# 137. 只出现一次的数字 II

## 核心思路

本题本质是：**如何在"其余元素出现 k 次"的约束下，提取出只出现 1 次的元素**。经典的 Single Number I 用异或（模 2 计数器）解决"出现 2 次"的情况，本题需要构造一个"模 3 计数器"。

## 思维链

1. **读完题第一反应**：用哈希表统计每个元素出现次数，找出次数为 1 的那个。简单直接，但空间是 O(n)。

2. **瓶颈在哪**：题目要求 O(1) 空间。哈希表不行，排序也需要 O(n) 额外空间（或 O(n log n) 时间）。必须用位运算。

3. **回忆 Single Number I**：`a ^ a = 0`，异或本质是"模 2 的加法"——同一个数出现 2 次就归零。那本题需要"模 3 的加法"——同一个数出现 3 次归零。

4. **逐位思考**：把所有数的第 i 位加起来，如果某个数出现 3 次，它在第 i 位的贡献是 3 的倍数。对总和取模 3，剩下的就是那个只出现 1 次的数在第 i 位的值。这就是**逐位统计法**。

5. **能否更优雅**：逐位统计需要 32 次循环。能否用类似异或的方式一次处理整个 int？用两个变量 `ones` 和 `twos` 分别记录"出现 1 次"和"出现 2 次"的位，模拟一个模 3 计数器。这就是**状态机法**。

6. **状态机的推导**：对每一位来说，计数状态有 3 种：`00 → 01 → 10 → 00`（二进制表示 0, 1, 2），用 `(twos, ones)` 两个变量的对应位来编码。每来一个新数，状态转移一次。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 哈希表计数 | 统计频次，找出现1次的 | O(n) | O(n) | 能说出即可 |
| 排序 | 排序后相邻比较 | O(n log n) | O(1) | 能说出即可 |
| 逐位统计 | 每一位求和对3取模 | O(32n) | O(1) | ⭐ 必须写出 |
| 状态机(有限自动机) | ones/twos 模3计数器 | O(n) | O(1) | 加分项 |

## 关键提示

1. **从位的视角看数字**：不要把数字当整体，把每个数看成 32 个独立的位。每一位上，所有数字的 0/1 值可以分别统计。

2. **模运算消除重复**：如果某个数出现了 3 次，它在任意一位的贡献 = 0 或 3，模 3 后都是 0。所以模 3 后剩下的就是目标数的贡献。

3. **状态机法的关键**：想清楚 `(twos, ones)` 的状态转移表：
   ```
   当前状态   输入bit   新状态
   (0, 0)      0       (0, 0)    ← 计数0，不变
   (0, 0)      1       (0, 1)    ← 计数0→1
   (0, 1)      0       (0, 1)    ← 计数1，不变
   (0, 1)      1       (1, 0)    ← 计数1→2
   (1, 0)      0       (1, 0)    ← 计数2，不变
   (1, 0)      1       (0, 0)    ← 计数2→0（模3归零）
   ```

4. **负数没问题**：逐位统计法对负数天然正确，因为符号位只是第 31 位，和其他位一样处理。

5. **从卡诺图推导公式**：状态机法不需要死记公式，可以用真值表+卡诺图（或直接观察）推导出 `ones` 和 `twos` 的更新表达式。

## 解法详解

### 解法1: 哈希表计数 — O(n) / O(n)

**思考过程**: 最直觉的做法。遍历数组，用哈希表记录每个元素出现次数，最后找次数为 1 的元素。

```cpp
class Solution {
public:
    int singleNumber(vector<int>& nums) {
        unordered_map<int, int> freq;
        for (int num : nums) {
            freq[num]++;
        }
        for (auto& [val, cnt] : freq) {
            if (cnt == 1) return val;
        }
        return -1; // 不会到达
    }
};
```

**关键点**: 空间 O(n)，不满足题目 O(1) 空间的要求，但面试中作为第一步展示理解是可以的。

---

### 解法2: 逐位统计 — O(32n) / O(1) ⭐ 面试首选

**从解法1优化**: 解法1的瓶颈是需要存储所有不同元素。位运算的思路是：**不存储元素，而是统计每一位上 1 的总数**。

**核心观察**：
```
// 例: nums = [2, 2, 3, 2]
// 二进制:
//   2 = 10
//   2 = 10
//   3 = 11
//   2 = 10
//
// 逐位统计(从低到高):
//   bit 0: 0 + 0 + 1 + 0 = 1, 1 % 3 = 1  ← 目标数第0位 = 1
//   bit 1: 1 + 1 + 1 + 1 = 4, 4 % 3 = 1  ← 目标数第1位 = 1
//   结果: 11(二进制) = 3 ✓
```

```cpp
class Solution {
public:
    int singleNumber(vector<int>& nums) {
        int result = 0;
        for (int i = 0; i < 32; i++) {
            int bitSum = 0;
            for (int num : nums) {
                // 统计所有数字第 i 位上 1 的个数
                bitSum += (num >> i) & 1;
            }
            // 模 3 后如果余 1，说明目标数第 i 位是 1
            if (bitSum % 3 != 0) {
                result |= (1 << i);
            }
        }
        return result;
    }
};
```

**为什么正确**：出现 3 次的数在每一位贡献 0 或 3 个 1，模 3 后归零。只出现 1 次的数在某一位如果是 1，模 3 后余 1；如果是 0，模 3 后余 0。所以模 3 的结果恰好就是目标数。

**关键点**: 
- `(num >> i) & 1` 提取第 i 位
- 负数的符号位（第31位）同样适用，不需要特殊处理
- 这个方法可以**推广到任意 k 次**：只需把 `% 3` 改成 `% k`

---

### 解法3: 状态机（有限自动机）— O(n) / O(1)

**从解法2优化**: 解法2 对每一位独立处理，需要 32 轮遍历。能否一次遍历处理所有位？

**核心思路**: 用两个整数 `ones` 和 `twos`，它们的第 i 位共同编码"第 i 位上 1 出现了几次（模 3）"。

```
// 状态编码: (twos的第i位, ones的第i位)
// (0, 0) = 出现0次
// (0, 1) = 出现1次  
// (1, 0) = 出现2次
// (1, 1) = 不存在（被清除）
//
// 状态转移（输入 bit b）:
// (0,0) --b=1--> (0,1)    (0,0) --b=0--> (0,0)
// (0,1) --b=1--> (1,0)    (0,1) --b=0--> (0,1)
// (1,0) --b=1--> (0,0)    (1,0) --b=0--> (1,0)
//
// 推导更新公式:
// 先更新 ones: ones' = (ones ^ num) & (~twos)
//   ones ^ num: 常规的异或计数
//   & (~twos): 如果 twos 对应位已经是1(状态10)，清除 ones
// 再更新 twos: twos' = (twos ^ num) & (~ones')
//   twos ^ num: 常规的异或计数  
//   & (~ones'): 如果 ones' 对应位已经是1(状态01)，清除 twos
```

```cpp
class Solution {
public:
    int singleNumber(vector<int>& nums) {
        int ones = 0, twos = 0;
        for (int num : nums) {
            // ones 记录"出现1次"的位，twos 记录"出现2次"的位
            // 出现3次时 ones 和 twos 同时归零
            ones = (ones ^ num) & (~twos);
            twos = (twos ^ num) & (~ones);
        }
        // 最终 ones 中存的就是只出现1次的数
        return ones;
    }
};
```

**手动模拟验证**:
```
// nums = [2, 2, 3, 2], 二进制: 10, 10, 11, 10
//
// 初始:   ones=00, twos=00
// num=10: ones = (00^10) & ~00 = 10 & 11 = 10
//         twos = (00^10) & ~10 = 10 & 01 = 00
//         → ones=10, twos=00  (2出现1次 ✓)
//
// num=10: ones = (10^10) & ~00 = 00 & 11 = 00
//         twos = (00^10) & ~00 = 10 & 11 = 10
//         → ones=00, twos=10  (2出现2次 ✓)
//
// num=11: ones = (00^11) & ~10 = 11 & 01 = 01
//         twos = (10^11) & ~01 = 01 & 10 = 00
//         → ones=01, twos=00  (bit0:3出现1次, bit1:2出现2次+3出现1次=3次→归零)
//         等等，让我重新跟踪...
//         bit1: 2出现2次(twos=1), 来了3的bit1=1, 
//               twos^num的bit1 = 1^1 = 0, &(~ones'的bit1) = &(~0)=&1 = 0
//               所以twos的bit1变0，ones的bit1也是0 → 状态(0,0)→计数归零后+1=...
//         实际上逐位分析更清晰，整体结果是对的
//
// num=10: ones = (01^10) & ~00 = 11 & 11 = 11  → 等等不对
//         让我重算: 上一轮 ones=01, twos=00
//         ones = (01^10) & ~00 = 11 & 11 = 11
//         twos = (00^10) & ~11 = 10 & 00 = 00
//         → ones=11=3, twos=00  
//         但这不对啊... 让我用十进制更仔细地跟踪:
//
// 其实结果 ones=3 是正确的！因为 3 就是只出现1次的数。
// (中间过程的位状态编码在处理完所有数后才有意义)
```

**关键点**: 这个公式不需要死记。面试时如果记不住，用解法2（逐位统计）完全足够拿满分。状态机法是加分项。

### 解法4: 数学法 — O(n) / O(n)

**思路**: `3 × (所有不同元素之和) - 数组总和 = 2 × 目标元素`

```cpp
class Solution {
public:
    int singleNumber(vector<int>& nums) {
        unordered_set<int> seen;
        long sumSet = 0, sumArray = 0;
        for (int num : nums) {
            if (seen.insert(num).second) {
                sumSet += num;
            }
            sumArray += num;
        }
        // 3 * sumSet - sumArray = 2 * answer
        return (int)((3 * sumSet - sumArray) / 2);
    }
};
```

**关键点**: 空间 O(n)，不满足要求，但思路巧妙。注意用 `long` 防溢出。

**面试策略**: 先说哈希表思路(10秒)，然后直接写逐位统计法。如果面试官追问能否更快，再讲状态机。

## 易错点

1. **位运算优先级**:
   - ✗ `num >> i & 1` → 实际是 `num >> (i & 1)`
   - ✓ `(num >> i) & 1` → 必须加括号

2. **状态机更新顺序**:
   - ✗ 先更新 twos 再更新 ones → 用了旧的 twos 但新的 ones 不匹配
   - ✓ 先更新 ones，再用更新后的 ones 更新 twos（或者反过来但公式不同）
   - 两个变量的更新是有依赖关系的，不能随意交换

3. **逐位统计法中 result 的构建**:
   - ✗ `result += (bitSum % 3) << i` → 当 i=31 时左移可能溢出
   - ✓ `result |= (bitSum % 3) << i` → 用 OR 更安全，且语义更准确

4. **负数处理**:
   - 逐位统计法天然处理负数（第31位就是符号位），不需要特殊处理
   - 但数学法中 `3*sumSet - sumArray` 可能溢出 int，必须用 long

## 面试追问

**Q1: 暴力解能过吗？瓶颈是什么？**
> 哈希表 O(n) 时间能过，但空间 O(n)。题目要求 O(1) 空间，所以需要位运算。

**Q2: 如果"其余元素出现 k 次"而不是 3 次，怎么改？**
> 逐位统计法：把 `% 3` 改成 `% k` 即可。状态机法需要 ⌈log₂k⌉ 个变量来编码状态。

**Q3: 如果有两个元素各出现 1 次，其余出现 3 次呢？**
> 逐位统计法中 `bitSum % 3` 的结果是两个目标数在该位的"异或"。此时需要额外信息来区分。可以参考 LeetCode 260 (Single Number III) 的分组异或思路结合本题。

**Q4: 状态机的公式怎么推导？不想死记。**
> 列出真值表（输入：当前 ones 位、当前 twos 位、新数的位；输出：新 ones 位、新 twos 位），然后用卡诺图化简。面试中如果时间紧，直接用逐位统计法即可。
