# 283. 移动零

## 核心思路
本质上是一个**数组分区问题**：把数组原地分成两段——前段是所有非零元素（保持原序），后段全是零。这和快排的 partition 操作是同一类问题。

## 思维链

1. **读完题第一反应**：开一个新数组，把非零元素按顺序拷进去，剩余位置填零。但题目要求原地操作，不能用额外数组。

2. **那就暴力模拟**：每遇到一个 0，就把它后面所有元素往前挪一位，最后补个零。这就像冒泡一样把零一个个"沉到底部"。但每次搬移是 O(n)，最坏 O(n²)。

3. **瓶颈在哪？** 每次遇到零就搬移整个后半段，大量重复搬移。能不能**一次遍历**就搞定？

4. **关键观察**：我们其实不需要"移动零"，而是**把非零元素往前放**，放完后剩下的位置自然全填零。这就转化成了：用一个慢指针 `slow` 标记"下一个非零元素该放的位置"，快指针 `fast` 扫描整个数组。

5. **进阶优化**：如果非零元素本来就在正确位置（如 `[1,2,3,0,0]`），上面的"覆盖+补零"方案还是会做多余的赋值操作。用**交换**代替覆盖——`swap(nums[slow], nums[fast])`，只在 `slow != fast` 时才交换，操作次数最少。

## 解法概览
| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力冒泡 | 每遇到0就把后面元素前移 | O(n²) | O(1) | 能说出即可 |
| 覆盖+补零 | 非零元素前移，末尾补零 | O(n) | O(1) | ⭐ 必须写出 |
| 交换法（最优） | 双指针交换，最少操作次数 | O(n) | O(1) | 加分项 |

## 关键提示

1. **不要想"怎么移动零"，而要想"怎么把非零元素归位"** — 换个角度，问题就简单了。

2. **慢指针的含义**：`slow` 左边（不含 `slow`）的所有元素都已经是非零且有序的。`slow` 就是"下一个非零元素应该放在哪"。

3. **覆盖 vs 交换**：覆盖法最后需要补零；交换法不需要补零，因为零被自然交换到后面了。

4. **进阶追问的关键**：当数组开头没有零时（如 `[1,2,0,3]`），交换法中 `slow == fast` 时不做交换，避免无意义的自我交换，从而最小化操作次数。

5. 想一想：这个双指针模式和 **LeetCode 27. 移除元素** 是不是完全一样？（把"移除的目标值"换成 0，再补零就行了）

```
// 双指针过程演示: nums = [0, 1, 0, 3, 12]
//
// 初始:    [0, 1, 0, 3, 12]
//           s
//           f
//
// f=0: nums[0]==0, 跳过
//          [0, 1, 0, 3, 12]
//           s  f
//
// f=1: nums[1]==1≠0, swap(nums[0], nums[1]), s++
//          [1, 0, 0, 3, 12]
//              s  f
//
// f=2: nums[2]==0, 跳过
//          [1, 0, 0, 3, 12]
//              s     f
//
// f=3: nums[3]==3≠0, swap(nums[1], nums[3]), s++
//          [1, 3, 0, 0, 12]
//                 s      f
//
// f=4: nums[4]==12≠0, swap(nums[2], nums[4]), s++
//          [1, 3, 12, 0, 0]
//                     s      f→结束
//
// 结果: [1, 3, 12, 0, 0] ✓
```

## 解法详解

### 解法1: 暴力冒泡 — O(n²) / O(1)

**思考过程**: 最直觉的想法——遇到一个 0，就把后面的元素整体往前搬一位，然后在末尾放个 0。这就像冒泡排序一样，把零一个个"沉到底"。

```cpp
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        int n = nums.size();
        for (int i = 0; i < n; i++) {
            if (nums[i] == 0) {
                // 找到当前0后面第一个非零元素
                int j = i + 1;
                while (j < n && nums[j] == 0) j++;
                if (j < n) {
                    swap(nums[i], nums[j]);
                }
            }
        }
    }
};
```

**关键点**: 这个方法正确但慢。对于 `[0,0,0,...,0,1]` 这种极端情况，内层 while 每次几乎扫完整个数组，总操作 O(n²)。

---

### 解法2: 覆盖 + 补零 — O(n) / O(1) ⭐ 面试首选

**从解法1优化**: 解法1的瓶颈是"每次遇到零都要搬移"。换个思路——我们不去移动零，而是**只关注非零元素**，把它们依次写到数组前面，最后把剩余位置填零。

```cpp
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        int slow = 0; // slow: 下一个非零元素应放的位置
        
        // 第一趟：把所有非零元素依次写到前面
        for (int fast = 0; fast < nums.size(); fast++) {
            if (nums[fast] != 0) {
                nums[slow] = nums[fast]; // 非零元素前移
                slow++;
            }
        }
        
        // 第二趟：slow 及之后的位置全部填零
        while (slow < nums.size()) {
            nums[slow] = 0;
            slow++;
        }
    }
};
```

**关键点**: 
- `slow` 的不变量：`nums[0..slow-1]` 始终是已经归位的非零元素。
- 两趟遍历，但总操作恰好 n 次赋值（每个位置被写一次），时间 O(n)。

---

### 解法3: 交换法（最少操作） — O(n) / O(1) — 进阶 Follow-up

**从解法2优化**: 解法2 的问题是：即使非零元素本来就在正确位置（如 `[1,2,3,0,0]`），前 3 个元素也会被"覆盖"成自己（多余操作）。交换法只在 `slow != fast` 时做交换，并且不需要第二趟补零。

```cpp
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        int slow = 0;
        for (int fast = 0; fast < nums.size(); fast++) {
            if (nums[fast] != 0) {
                if (fast != slow) {
                    // 只在 fast 和 slow 不同位置时才交换
                    // 避免元素自我交换的多余操作
                    swap(nums[slow], nums[fast]);
                }
                slow++;
            }
        }
        // 不需要补零！零已经被交换到后面了
    }
};
```

**为什么操作次数最少？**
- 如果数组没有零（如 `[1,2,3]`），`fast == slow` 始终成立，**零次交换**。
- 如果数组全是零（如 `[0,0,0]`），没有非零元素触发交换，也是**零次交换**。
- 一般情况下，每个非零元素最多被交换一次，总交换次数 = 非零元素个数（最坏情况）。

## 解法对比

| | 暴力冒泡 | 覆盖+补零 | 交换法 |
|---|---|---|---|
| 时间 | O(n²) | O(n) | O(n) |
| 空间 | O(1) | O(1) | O(1) |
| 写操作次数 | 最多 | 恰好 n 次 | ≤ 非零元素数 |
| 需要补零？ | 否 | 是 | 否 |
| 代码复杂度 | 简单 | 简单 | 简单 |

**选择建议**：面试中先写出解法2（清晰易懂），然后被追问 Follow-up 时优化到解法3。

## 易错点

1. **覆盖法忘记补零**
   - ✗ 只做第一趟覆盖，漏掉 `while (slow < n) nums[slow++] = 0;`
   - 结果：`[0,1,0,3,12]` → `[1,3,12,3,12]`（末尾残留旧值）
   - ✓ 必须第二趟把 `[slow, n)` 全部置零

2. **交换法漏掉 `fast != slow` 判断**
   - ✗ `if (nums[fast] != 0) swap(nums[slow], nums[fast]);`
   - 虽然不影响正确性，但违背了 Follow-up "最少操作次数"的要求
   - ✓ 加上 `if (fast != slow)` 条件，避免无意义的自我交换

3. **slow 指针初始化错误**
   - ✗ `int slow = 1;` — 跳过了 `nums[0]` 的检查
   - ✓ `int slow = 0;` — 从头开始

## 面试追问

**Q1（基础理解）**: 你的解法能保持非零元素的相对顺序吗？为什么？
> 能。因为 `fast` 从左到右顺序扫描，每次把非零元素按遇到的顺序放到 `slow` 位置，相对顺序不变。

**Q2（Follow-up）**: 能否最小化总操作次数？如果数组已经没有零呢？
> 用交换法 + `fast != slow` 判断。如果没有零，`fast` 和 `slow` 始终同步，不做任何交换，操作次数为 0。

**Q3（变体）**: 如果要把所有零移到数组**开头**怎么办？
> 从右往左扫描，用一个 `slow` 从末尾往前标记"下一个非零元素该放的位置"，逻辑完全对称。

**Q4（泛化）**: 如果不是移动零，而是移动任意指定值 `val` 呢？
> 这就是 LeetCode 27. 移除元素。把 `nums[fast] != 0` 改成 `nums[fast] != val`，逻辑完全相同。区别只是 283 要补零，27 不需要。
