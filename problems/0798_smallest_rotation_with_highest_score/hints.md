# 798. Smallest Rotation with Highest Score - 得分最高的最小轮调

## 核心思路

本题的暴力做法是枚举每个 k 值并计算得分，时间 O(n^2)。优化的关键在于 **差分数组**：对于每个元素 nums[i]，预先计算它在哪些 k 值下能得分，将这个 k 区间记录到差分数组中，最后通过前缀和还原每个 k 的总得分。

核心观察：每个元素得分的 k 值构成一个连续区间（可能回绕），差分数组可以 O(1) 标记区间，总时间降为 O(n)。

## 思维链

1. **理解轮调**：轮调 k 次意味着数组向左循环移位 k 位。原位置 i 的元素移动到新位置 `(i - k + n) % n`
2. **得分条件**：元素 nums[i] 在新位置 j 得分当且仅当 `nums[i] <= j`，即值不超过下标
3. **反向思考**：对于固定的元素 nums[i] 在原位置 i，哪些 k 能让它得分？
4. **推导得分区间**：新位置 j = (i-k+n)%n，得分条件 nums[i] <= j，解不等式得到 k 的区间
5. **差分数组标记**：每个元素贡献一个 k 区间，用差分数组 O(1) 标记
6. **前缀和还原**：差分数组求前缀和得到每个 k 的总得分，取最大值的最小 k

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 核心技巧 | 适用场景 |
|------|-----------|-----------|---------|---------|
| 差分数组 + 前缀和 | O(n) | O(n) | 区间更新转差分 | 最优解，面试必知 |
| 暴力枚举 | O(n^2) | O(1) | 直接模拟每个 k | 仅用于验证 |

## 关键提示

### 提示 1 - 暴力分析
暴力枚举每个 k (0 到 n-1)，对每个 k 遍历所有位置检查 nums[(i+k)%n] <= i。时间 O(n^2)，n=10^5 会 TLE。但暴力帮助理解问题本质。

### 提示 2 - 每个元素的得分区间
固定元素 nums[i] 在原位置 i，轮调 k 后到达新位置 `(i - k + n) % n`。得分条件是 `nums[i] <= (i - k + n) % n`。

关键推导：
- 当 k = 0 时，元素在位置 i，得分条件 nums[i] <= i
- 当 k = (i+1)%n 时，元素到达位置 n-1（最右），几乎一定得分（除非 nums[i] = n）
- 当 k = (i-nums[i]+n)%n 时，元素恰好在位置 nums[i]，刚好得分
- 当 k = (i-nums[i]+1+n)%n 时，元素在位置 nums[i]-1，不再得分

因此得分的 k 区间为 `[(i+1)%n, (i-nums[i]+n)%n]`。

### 提示 3 - 差分数组处理区间
对于每个元素的得分区间 [lo, hi]：
- 如果 lo <= hi：正常区间，`diff[lo]++, diff[hi+1]--`
- 如果 lo > hi：回绕区间，拆成 [lo, n-1] 和 [0, hi]，分别标记

特殊情况：当 nums[i] == 0 时，元素在任何位置都得分（值 0 <= 任何下标），k 区间覆盖全部。

### 提示 4 - 前缀和求最大值
对差分数组求前缀和，得到每个 k 对应的总得分。遍历一遍找到最大得分对应的最小 k。

## 解法详解

### 解法一：差分数组 + 前缀和（唯一最优解）

**核心推导**：

对于位置 i 的元素值 v = nums[i]：
- 轮调 k 后，它到达位置 j = (i - k + n) % n
- 得分条件：v <= j，即 j >= v
- j 的范围是 0 到 n-1，当 k 从 0 增大时 j 从 i 逐步减小（循环）

得分的 k 值区间：
- lo = (i + 1) % n：此时元素到达 n-1，开始得分
- hi = (i - v + n) % n：此时元素恰好在位置 v，刚好还得分
- k = (i - v + 1 + n) % n 时元素到位置 v-1，不再得分

特殊情况：如果 v == 0，元素永远得分（0 <= 任何非负下标），lo 到 hi 的区间覆盖 [0, n-1]。但算法不需要特判，因为 lo = (i+1)%n, hi = i%n = i，如果 lo > hi 会自动拆成回绕区间覆盖全部。

**差分数组操作**：
```
if lo <= hi:
    diff[lo]++, diff[hi+1]--
else:  // 回绕
    diff[lo]++, diff[n]--, diff[0]++, diff[hi+1]--
```

**前缀和还原**：
```
score = 0, 最大得分 = 0, 最佳 k = 0
for k in [0, n-1]:
    score += diff[k]
    if score > 最大得分: 更新
```

**举例**：nums = [2, 3, 1, 4, 0], n = 5

| i | nums[i] | lo=(i+1)%5 | hi=(i-nums[i]+5)%5 | 区间 | 类型 |
|---|---------|-----------|-------------------|------|------|
| 0 | 2 | 1 | 3 | [1,3] | 正常 |
| 1 | 3 | 2 | 3 | [2,3] | 正常 |
| 2 | 1 | 3 | 1 | [3,4]+[0,1] | 回绕 |
| 3 | 4 | 4 | 4 | [4,4] | 正常 |
| 4 | 0 | 0 | 4 | [0,4] | 正常 |

差分处理后求前缀和得到每个 k 的得分，取最大值的最小 k。

## 易错点

1. **区间边界推导错误**
   - 错误：lo = i % n（元素不动的情况）
   - 正确：lo = (i + 1) % n（k=i+1 时元素到位置 n-1）

2. **回绕区间处理遗漏**
   - 错误：只处理 lo <= hi 的情况
   - 正确：lo > hi 时必须拆成两段 [lo, n-1] 和 [0, hi]

3. **差分数组大小不够**
   - 错误：diff 数组大小为 n，但 diff[hi+1] 可能越界
   - 正确：diff 数组大小至少为 n+1

4. **nums[i] >= n 的情况**
   - 此时元素永远不得分（值大于任何合法下标）
   - 需要跳过或让区间为空。实际上 lo = (i+1)%n, hi = (i-nums[i]+n)%n，当 nums[i] >= n 时，得分区间实际为空，但差分标记可能产生错误。题目保证 0 <= nums[i] < n，所以不用担心。

5. **最大得分初始值设置不当**
   - 错误：maxScore = INT_MAX 或 -1
   - 正确：maxScore = 0（或 -1），从 k=0 开始累加时取第一个得分值

6. **前缀和循环范围**
   - 错误：循环到 n+1 或包含 diff[n]
   - 正确：只循环 k 从 0 到 n-1

## 面试追问

**Q1: 为什么得分区间是 [(i+1)%n, (i-nums[i]+n)%n]？**
轮调 k 后位置 j = (i-k+n)%n。k 从 (i+1)%n 开始时 j = n-1（最大位置），只要 nums[i] <= n-1 就得分。k 逐渐增大，j 逐渐减小。当 j 减小到 nums[i] 时仍满足条件，此时 k = (i-nums[i]+n)%n。再增大 k 则 j < nums[i]，不再得分。

**Q2: 差分数组的核心思想是什么？**
差分数组用于高效处理"区间加"操作。对区间 [l, r] 加 1，只需 diff[l]++ 和 diff[r+1]--，O(1) 完成。最后一次前缀和还原所有位置的值。本题中每个元素贡献一个区间，n 个元素 n 次 O(1) 操作，总 O(n)。

**Q3: 回绕区间怎么处理？**
当 lo > hi 时，区间跨越数组末尾回到开头。拆成 [lo, n-1] 和 [0, hi] 两个不回绕的子区间分别标记。或者等价地：diff[lo]++, diff[n]--, diff[0]++, diff[hi+1]--。

**Q4: 这个方法能推广到什么类型的问题？**
任何需要对大量区间做统一加减操作的场景都适用差分数组，例如：航班预订统计（LeetCode 1109）、公交站间距（LeetCode 1094）。核心模式是"区间更新 + 单点查询"转化为"单点更新 + 前缀和查询"。

**Q5: 如果允许得分条件改为 nums[i] == i（严格等于），还能用差分数组吗？**
可以。此时每个元素在特定 k 下才得分，k = (i - nums[i] + n) % n（恰好一个点而非区间），退化为对单点做 +1。差分数组仍然适用，但更简单的做法是直接用计数数组。
