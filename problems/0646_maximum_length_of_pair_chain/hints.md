# 646. 最长数对链 (Maximum Length of Pair Chain)

**难度**: Medium | **标签**: Greedy, Array, Dynamic Programming, Sorting

## 核心思路

本题本质上是一个**活动选择问题（Activity Selection Problem）**的变体。每个数对 [a, b] 可以看作一个"活动"，起始时间为 a，结束时间为 b。我们需要选择尽可能多的互不重叠的活动，使得链的长度最长。

关键洞察：**按照右端点排序后，贪心地选择结束最早的数对**，可以保证给后续数对留出最大的空间。这是贪心算法的经典应用。

## 思维链

1. **问题识别**：数对链 = 互不重叠的区间选择 = 活动选择问题
2. **排序策略**：按右端点升序排序（不是按左端点！）
3. **贪心选择**：维护当前链末尾的右端点 curEnd，扫描排序后的数对
4. **选择条件**：如果 pairs[i][0] > curEnd，则选择此数对，更新 curEnd = pairs[i][1]，链长度 +1
5. **正确性论证**：选结束最早的，不会错过更优解；如果跳过一个结束更早的去选结束更晚的，只会让后续选择空间更小

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 贪心（按右端点排序） | O(n log n) | O(1) | 最优解，思路清晰 |
| 动态规划 | O(n^2) | O(n) | 经典 LIS 变体，面试需掌握 |
| 动态规划 + 二分 | O(n log n) | O(n) | LIS 优化版 |

## 关键提示

1. **必须按右端点排序**：按左端点排序的贪心是错误的。例如 [[1,100],[2,3],[4,5]]，按左端点排序选 [1,100] 后就无法再选了，但正确答案是 [2,3]->[4,5]
2. **严格不等号**：链的条件是 b < c（严格小于），不是 b <= c
3. **数对链 vs LIS**：虽然都是"链"，但数对链的元素是二维的，需要排序预处理
4. **不需要用到所有数对**：这是本题和 LIS 的共同点
5. **贪心的直觉**：越早结束，给后面留的空间越大 -- 和"会议室安排"一模一样

## 解法详解

### 解法一：贪心（最优）

**核心思路**：按右端点排序后，贪心选择。

**步骤**：
1. 将 pairs 按右端点 (pairs[i][1]) 升序排序
2. 初始化 curEnd = INT_MIN, count = 0
3. 遍历排序后的数对：
   - 如果 pairs[i][0] > curEnd：选中，curEnd = pairs[i][1], count++
4. 返回 count

**正确性证明（交换论证）**：
假设贪心选择了集合 G = {g1, g2, ...}，最优解选择了集合 O = {o1, o2, ...}。
可以证明对每个 i，g_i 的右端点 <= o_i 的右端点。因此 |G| >= |O|。

### 解法二：动态规划

**核心思路**：按左端点排序后，类似 LIS。

**步骤**：
1. 将 pairs 按左端点升序排序
2. dp[i] = 以 pairs[i] 结尾的最长链长度
3. 转移：dp[i] = max(dp[j] + 1)，其中 j < i 且 pairs[j][1] < pairs[i][0]
4. 初始 dp[i] = 1
5. 返回 max(dp)

## 易错点

1. **排序维度错误**：必须按右端点排序做贪心，按左端点排序做 DP。混淆两种做法会导致错误
2. **严格小于条件**：b < c 不是 b <= c。[1,2] 和 [2,3] 不能组成链
3. **初始 curEnd 值**：设为 INT_MIN 或负无穷，确保第一个数对一定被选中
4. **DP 方向**：如果按左端点排序，dp[i] 需要往前扫所有 j < i 判断条件
5. **排序稳定性**：右端点相同时，左端点的排序不影响贪心正确性

## 面试追问

1. **Q: 为什么贪心按右端点排序而不是按左端点？**
   A: 反例 [[1,100],[2,3],[4,5]]。按左端点排序选 [1,100]，只能选 1 个。按右端点排序先选 [2,3]，再选 [4,5]，得到 2 个。右端点小意味着"结束得早"，给后面留更多空间。

2. **Q: 这道题和 LIS 有什么关系？**
   A: DP 解法本质就是 LIS 的变体。区别在于 LIS 的转移条件是 nums[j] < nums[i]，而本题是 pairs[j][1] < pairs[i][0]（二维比较）。

3. **Q: 如果条件从 b < c 改为 b <= c 会怎样？**
   A: 贪心逻辑改为 pairs[i][0] >= curEnd 即可，其余不变。

4. **Q: 如果要输出具体的链而不仅仅是长度？**
   A: 贪心法中记录选中的数对即可。DP 法需要额外记录 parent 数组回溯。

5. **Q: 时间复杂度能否优于 O(n log n)？**
   A: 不能，因为排序的下界就是 O(n log n)。贪心扫描本身是 O(n)。
