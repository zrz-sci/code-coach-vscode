# 774. 最小化去加油站的最大距离 (Minimize Max Distance to Gas Station)

**难度**: Hard | **标签**: Array, Binary Search

## 核心思路

这是一道经典的**二分答案**问题。我们不直接求解"如何放置 k 个加油站"，而是反过来问：**如果最大距离不超过 d，需要至少添加多少个加油站？** 然后对 d 进行二分搜索，找到满足条件的最小 d。

关键洞察：对于给定的最大允许距离 d，每个区间 gap 需要切分成 `ceil(gap/d)` 段，即需要添加 `ceil(gap/d) - 1` 个加油站。将所有区间需要的加油站数累加，若总数 <= k，则 d 可行。

## 思维链

1. **直觉分析**: 加油站放在最大间距处，但放置后间距会改变，贪心直接分配不容易做。
2. **逆向思维**: 不去决定放在哪里，而是假设一个最大距离 d，检查是否可行。
3. **可行性检验**: 对每个相邻加油站间距 gap，需要 `ceil(gap/d) - 1` 个新站使得每段 <= d。
4. **单调性**: d 越大，需要的加油站越少 -> 具备二分性质。
5. **二分搜索**: 在 [0, max_gap] 上二分 d，找到使 count <= k 的最小 d。
6. **精度控制**: 浮点二分，终止条件为 `right - left < 1e-6`。

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 适用场景 |
|------|-----------|-----------|---------|
| 二分答案 | O(n * log(M/eps)) | O(1) | 最优解法，首选 |
| 优先队列贪心 | O((n+k) * log n) | O(n) | k 较小时可用 |

> n = stations.length, M = max_gap, eps = 10^-6

## 关键提示

1. **二分的是答案（最大距离 d）**: 不是二分位置或加油站数量，而是最终答案本身。
2. **浮点二分**: left=0, right=max_gap，精度要求 10^-6。通常迭代 100 次足够。
3. **可行性检查的核心公式**: 区间 gap 被 d 切分需要 `ceil(gap/d) - 1` 个新站 = `(int)(gap/d)` 个新站（当 gap/d 恰好整除时少一个）。
4. **不需要实际放置**: 只需计算总共需要多少个新站，不需要确定它们的精确位置。
5. **gap 的计算**: `stations[i+1] - stations[i]`，stations 已排序。
6. **二分终止条件**: `right - left < 1e-6` 或固定迭代 100 次（每次缩小一半，2^100 > 10^30 精度足够）。

## 解法详解

### 解法一：二分答案 (最优解法)

**思路**: 
1. 计算所有相邻加油站的间距。
2. 二分搜索最大距离 d，范围 [0, max_gap]。
3. 对每个 mid 值，检查是否能用 k 个加油站使得所有相邻距离 <= mid：
   - 遍历每个间距 gap，计算需要 `(int)(gap / mid)` 个新站（如果 gap 恰好被 mid 整除，需要少一个）。
   - 累加所有区间需要的新站数，如果总数 <= k，则 mid 可行。
4. 可行则缩小 right，不可行则增大 left。

**详细步骤**:
```
left = 0, right = max(stations[i+1] - stations[i])
while right - left > 1e-6:
    mid = (left + right) / 2
    count = 0
    for each gap in intervals:
        count += (int)(gap / mid)  // 需要的新站数
    if count <= k:
        right = mid  // mid 可行，尝试更小的
    else:
        left = mid   // mid 不可行，需要更大的
return left
```

**注意**: `(int)(gap / mid)` 在 gap 恰好整除 mid 时会多算一个站。更精确的写法是 `ceil(gap / mid) - 1`，但由于浮点精度，通常 `(int)(gap / mid)` 在浮点二分中表现良好。

**复杂度**:
- 时间: O(n * log(M / eps))。n 个间距，二分约 log(10^8 / 10^-6) = 47 次。
- 空间: O(1)。只用常数额外空间。

### 解法二：优先队列贪心

**思路**:
1. 用优先队列维护当前最大间距。
2. 每次取出最大间距的区间，将其平均切分成更多段（增加一个切分点）。
3. 重复 k 次。

每个区间维护 (当前最大子段长度, 原始长度, 切分数)。取出后将切分数加 1，重新计算最大子段长度 = 原始长度 / (切分数+1)，放回队列。

**复杂度**:
- 时间: O((n + k) * log n)。k 可达 10^6，可能较慢。
- 空间: O(n)。优先队列存储 n-1 个区间。

## 易错点

1. **浮点精度**: 二分的终止条件不能用 `==`，要用 `right - left < 1e-6` 或固定迭代次数。
2. **整除边界**: 当 gap 恰好等于 mid 时，`gap / mid = 1.0`，实际不需要加站。要小心 `(int)(gap / mid)` 的行为。
3. **right 初始值**: 应为所有间距中的最大值，而非 `stations.back() - stations.front()`。
4. **k=0 的情况**: 不添加加油站，直接返回最大间距。
5. **返回值**: 返回 left 或 right 皆可（收敛后差异 < 1e-6）。

## 面试追问

1. **Q: 为什么不能用贪心（每次放在最大间距的中点）？**
   A: 贪心需要 O(k log n) 时间，k 可达 10^6，且优先队列常数开销大。二分答案只需 O(n * 47) 更高效。

2. **Q: 如何证明二分的单调性？**
   A: 最大距离 d 越大，每个区间需要的加油站越少。因此 need(d) 是关于 d 的单调递减函数，满足二分条件。

3. **Q: 如果加油站不一定在整数位置，这是否影响算法？**
   A: 不影响。算法本身不假设整数位置，浮点二分天然支持连续位置。

4. **Q: 固定迭代次数 vs 精度终止，哪个更好？**
   A: 固定 100 次迭代更稳健，避免浮点精度导致的无限循环风险。2^100 的分辨率远超 10^-6 要求。

5. **Q: 这道题和 LC 875 (Koko Eating Bananas) 有什么联系？**
   A: 都是"二分答案"模式——对答案空间二分，通过可行性检验找最优值。875 是整数二分，本题是浮点二分。
