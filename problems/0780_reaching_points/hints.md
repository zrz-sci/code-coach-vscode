# 780. 到达终点 (Reaching Points)

## 核心思路

本题的关键洞察是**逆向思维 + 取模加速**。正向从 `(sx, sy)` 搜索到 `(tx, ty)` 会产生指数级的搜索空间。但反过来，从 `(tx, ty)` 回溯到 `(sx, sy)` 时，每一步的操作是唯一确定的：如果 `tx > ty`，上一步只能是 `(tx - ty, ty)`；如果 `ty > tx`，上一步只能是 `(tx, ty - tx)`。再用取模替代重复减法，将时间从 O(max(tx, ty)) 优化到 O(log(max(tx, ty)))。

## 思维链

1. **正向分析**：从 `(x, y)` 可以到 `(x, x+y)` 或 `(x+y, y)`。由于 x, y 都是正整数，值只增不减，搜索树是二叉的。
2. **逆向分析**：从 `(tx, ty)` 反推。因为 `(tx, ty)` 只能来自 `(tx - ty, ty)`（若 `tx > ty`）或 `(tx, ty - tx)`（若 `ty > tx`）。每一步方向唯一（类似辗转相除法）。
3. **加速**：当 `tx >> ty` 时，会反复执行 `tx -= ty`，这等价于 `tx %= ty`。但必须小心不要减过头（不能减到小于 `sx` 或 `sy`）。
4. **终止条件**：
   - `tx == sx && ty == sy` -> true
   - `tx == sx` -> 检查 `(ty - sy) % tx == 0` 且 `ty >= sy`
   - `ty == sy` -> 检查 `(tx - sx) % ty == 0` 且 `tx >= sx`
   - `tx < sx || ty < sy` -> false

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 逆向 + 取模 | O(log(max(tx,ty))) | O(1) | 最优解，类似 GCD 的辗转相除 |
| 逆向 + 逐步减法 | O(max(tx,ty)) | O(1) | 直观但会 TLE |

## 关键提示

1. **逆向唯一性**：正向每步有两个选择（分裂），但逆向每步只有一个选择（收敛）
2. **取模替代减法**：`tx %= ty` 替代重复的 `tx -= ty`，但必须处理好边界
3. **特殊情况 tx == sx**：此时不能再用 tx 做取模，需要直接检查 ty 方向
4. **坐标都是正整数**：`1 <= sx, sy, tx, ty <= 10^9`，不会出现 0
5. **tx == ty 时**：只有 `sx == tx && sy == ty` 才返回 true（因为正向操作总使一个坐标增大）

## 解法详解

### 解法一：逆向 + 取模（推荐）

**核心思想**：从 `(tx, ty)` 逆向回溯。每次选择较大的坐标做减法（等价于取模），直到某个坐标等于对应的起点坐标或无法继续。

**算法步骤**：
1. 当 `tx > sx && ty > sy` 时循环：
   - 如果 `tx > ty`：`tx %= ty`
   - 否则：`ty %= tx`
2. 循环结束后检查：
   - `tx == sx && ty == sy` -> true
   - `tx == sx` -> `ty >= sy` 且 `(ty - sy) % tx == 0`
   - `ty == sy` -> `tx >= sx` 且 `(tx - sx) % ty == 0`
   - 否则 -> false

**关键细节**：取模可能使值变为 0（当一个是另一个的倍数时）。由于坐标要求 >= 1，需要处理。但实际上，当 `tx > sx` 且 `ty > sy` 时，取模不会使结果小于等于 0（因为 tx > ty > sy >= 1 保证 tx % ty >= 0，但可以等于 0——此时说明 tx 是 ty 的倍数，此时应停止循环换另一种终止检查）。

### 解法二：逆向逐步减法（理解用，不推荐提交）

**核心思想**：同上，但不用取模加速，每次只减一次。

**算法步骤**：
1. 当 `tx != sx || ty != sy` 时：
   - 如果 `tx > ty`：`tx -= ty`
   - 否则如果 `ty > tx`：`ty -= tx`
   - 否则（`tx == ty` 但 != `(sx, sy)`）：return false
   - 如果 `tx < sx || ty < sy`：return false
2. 最终 `tx == sx && ty == sy` -> true

## 易错点

1. **取模后值为 0**：当 `tx` 是 `ty` 的整数倍时 `tx % ty == 0`，需要在循环条件中处理（`tx > sx` 而非 `tx >= sx`）
2. **逆向终止时漏检**：循环结束后可能 `tx == sx` 但 `ty` 还没到位，此时需要单独检查 `(ty - sy) % sx == 0`
3. **整数溢出**：虽然坐标最大 10^9，但 int 范围足够，不会溢出
4. **tx == ty 的情况**：如果 `tx == ty` 且不等于 `(sx, sy)`，则无法继续回溯（取模会变 0），直接返回 false
5. **误用正向搜索**：正向搜索是指数级时间，最大坐标 10^9 绝对超时

## 面试追问

1. **为什么逆向操作是唯一的？**
   - 因为 `(tx, ty)` 的前驱要么是 `(tx - ty, ty)` 要么是 `(tx, ty - tx)`。由于所有坐标必须为正整数，`tx > ty` 时只能选前者（否则 `tx - ty` 会是负数或零——因为 ty 没变），`ty > tx` 时只能选后者。这保证了每一步的唯一性。

2. **这题和 GCD 有什么关系？**
   - 回溯过程和辗转相除法（求 GCD）完全同构。取模操作使得时间复杂度和 GCD 一样是 O(log(max(tx, ty)))。

3. **如果允许坐标为 0 呢？**
   - 问题会变复杂：`(x, 0)` 只能到 `(x, x)` 或 `(x, 0)`，有些路径会产生死循环。需要额外处理 0 的边界情况。

4. **能否用 BFS/DFS 正向搜索？**
   - 理论上可以，但由于坐标最大 10^9，正向搜索空间是指数级的，完全不可行。

5. **如果操作变成 `(x, y) -> (x, x*y)` 或 `(x*y, y)` 呢？**
   - 逆向时用除法代替减法，需要检查整除性。但搜索空间收缩更快（指数下降），复杂度更低。
