# 591. Tag Validator - 标签验证器

## 核心思路

本题要求实现一个简化版的 XML/HTML 标签验证器。核心数据结构是**栈**，用于匹配嵌套的开始/结束标签。解题的关键在于仔细解析字符串，正确处理三种情况：开始标签 `<TAG>`、结束标签 `</TAG>`、以及 CDATA 块 `<![CDATA[...]]>`。

难点在于规则众多、边界条件复杂，需要严格按规则逐字符解析，不能遗漏任何约束。

## 思维链

1. **整体结构**：代码必须被一个有效的闭合标签完全包裹
2. **逐字符扫描**：遇到 `<` 时判断是开始标签、结束标签还是 CDATA
3. **标签名验证**：只能是大写字母，长度 1-9
4. **标签匹配**：用栈存储开始标签名，遇到结束标签时与栈顶匹配
5. **CDATA 处理**：`<![CDATA[` 开头，找到第一个 `]]>` 结束，中间内容不做任何解析
6. **结束条件**：扫描完毕后栈为空，且整个字符串确实被最外层标签完全包裹

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 栈 + 逐字符解析 | O(n) | O(n) | 标准做法，面试唯一推荐方案 |

## 关键提示

1. **代码必须被最外层标签完全包裹**：不能是 `<A></A><B></B>` 这样的两个并列标签
2. **CDATA 只能出现在标签内部**：栈不为空时才能有 CDATA
3. **TAG_NAME 约束**：仅大写字母 A-Z，长度 [1, 9]
4. **遇到 `<` 时的分支**：
   - `<![CDATA[` -> CDATA 块
   - `</` -> 结束标签
   - `<` 后跟大写字母 -> 开始标签
   - 其他情况 -> 无效
5. **栈为空时不能有任何内容**：外层标签关闭后字符串必须结束

## 解法详解

### 栈 + 逐字符解析

**主循环逻辑**：

```
i = 0
while i < code.length:
    if i > 0 且 栈为空:
        return false  // 外层标签已关闭但还有内容

    if code[i] == '<':
        if code.substr(i, 9) == "<![CDATA[":
            if 栈为空: return false  // CDATA 不能在标签外
            找到 "]]>" 的位置, 如果找不到 return false
            跳到 "]]>" 之后

        else if code[i+1] == '/':
            // 结束标签
            找到 '>' 的位置
            提取 TAG_NAME = code.substr(i+2, j-i-2)
            验证 TAG_NAME 合法性
            与栈顶匹配, 不匹配则 return false
            弹栈

        else:
            // 开始标签
            找到 '>' 的位置
            提取 TAG_NAME = code.substr(i+1, j-i-1)
            验证 TAG_NAME 合法性
            压栈
    else:
        if 栈为空: return false  // 普通字符不能在标签外
        i++

return 栈为空
```

**TAG_NAME 验证函数**：
- 长度必须在 [1, 9] 范围内
- 每个字符必须是大写字母 A-Z
- `<>` 或 `<ABCDEFGHIJ>` 都是非法的

**关键细节**：
1. 处理开始标签时，找 `>` 的位置：`j = code.find('>', i)`，如果 `j == npos` 返回 false
2. CDATA 查找：`code.find("]]>", i+9)`，如果找不到返回 false
3. **外层标签关闭后检查**：当 `i > 0` 且栈为空时，说明最外层标签已经关闭但后面还有字符

**完整逻辑的测试用例分析**：
- `<A></A>` -> true：最简单的有效标签
- `<A></A>extra` -> false：外层标签关闭后还有字符
- `<A><B></B></A>` -> true：嵌套标签
- `<A><B></A></B>` -> false：交叉嵌套（B 未关闭就关 A）
- `<![CDATA[content]]>` -> false：CDATA 在标签外
- `<A><![CDATA[<B>]]></A>` -> true：CDATA 内的标签不解析
- `abc` -> false：没有被标签包裹
- `<a></a>` -> false：小写标签名
- `<ABCDEFGHIJ></ABCDEFGHIJ>` -> false：标签名长度超过9

## 易错点

1. **忘记检查外层标签关闭后是否还有字符**：`<A></A>x` 应该返回 false。关键是 `if (i > 0 && stk.empty()) return false;` 这个前置检查
2. **CDATA 在标签外**：`<![CDATA[...]]>` 必须在某个标签的内容中，栈为空时出现就无效
3. **标签名长度边界**：空标签名 `<>` 和超长标签名 `<ABCDEFGHIJ>` 都无效
4. **CDATA 前缀判断**：必须严格匹配 `<![CDATA[` 全部9个字符
5. **find 返回 npos**：找不到 `>` 或 `]]>` 时必须返回 false
6. **栈为空时遇到普通字符**：说明字符在最外层标签之外，无效
7. **空字符串或无标签**：没有被标签包裹的代码直接无效

## 面试追问

1. **这道题和括号匹配有什么关系？**
   - 本质都是栈匹配问题，标签名相当于"带标签的括号"
   - 区别在于需要额外处理 CDATA、标签名合法性、以及外层包裹约束
2. **如何扩展支持属性（如 `<div class="x">`）？**
   - 在解析开始标签时，找到第一个空格分隔标签名和属性
   - 属性解析需要处理引号内的特殊字符
3. **CDATA 存在的意义是什么？**
   - 在 XML 中，CDATA 用于包含不应被 XML 解析器解析的文本（如包含 `<>&` 的文本）
   - 避免了对特殊字符的转义需求
4. **时间复杂度为什么是 O(n)？**
   - 每个字符最多被访问常数次（主循环 + find 操作总共扫过一遍）
   - 栈操作和字符串比较都是常数时间（标签名最长9个字符）
5. **如果要返回详细的错误信息（第几行第几列出错），如何改造？**
   - 维护行号和列号计数器
   - 每个 return false 处记录当前位置和错误类型
6. **substr 的性能问题**：每次 `code.substr(i, 9)` 会创建新字符串，可以用 `code.compare(i, 9, "<![CDATA[")` 代替避免分配
