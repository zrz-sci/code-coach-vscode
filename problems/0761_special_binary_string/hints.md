# 761. 特殊的二进制字符串 (Special Binary String)

## 核心思路

本题是一个**递归 + 排序**问题，需要理解"特殊二进制字符串"与合法括号序列的类比关系。将 '1' 看作 '('，'0' 看作 ')'，那么特殊二进制字符串就是合法的括号序列。题目允许交换相邻的特殊子串以得到字典序最大的结果。解法是递归地将特殊字符串分解为最小的特殊子串，对它们的内部递归处理后降序排序拼接，即可得到字典序最大的结果。

## 思维链

1. **类比括号序列**：特殊二进制字符串的两个性质（0和1数量相等、每个前缀1的数量 >= 0的数量）恰好对应合法括号序列的性质
2. **分解为不可分割的特殊子串**：在最外层，找到所有"最小"的特殊子串（类似找顶层括号对），即每次 count 从0变为正再回到0的区间
3. **递归处理内部**：每个最小特殊子串形如 `1...0`，首尾的 1 和 0 是固定的，中间部分也是特殊二进制字符串，递归处理
4. **降序排序**：交换相邻特殊子串等价于对它们重新排列，要字典序最大就降序排序
5. **组装结果**：每个子串处理后外包 `1...0`，所有子串降序排列拼接

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 递归分解 + 排序 | O(n^2) | O(n) | 优雅的递归解法 |

## 关键提示

1. **1 对应 '('，0 对应 ')'**：这个类比是理解本题的关键。特殊二进制字符串 = 合法括号序列
2. **最小特殊子串**：用计数器 count，遇到 '1' 加1，遇到 '0' 减1。当 count 回到 0 时，就找到了一个最小的不可分割的特殊子串
3. **递归结构**：最小特殊子串 `s[i..j]` 的形式是 `1 + inner + 0`，其中 `inner = s[i+1..j-1]` 也是特殊二进制字符串
4. **排序方向**：降序排列所有处理后的子串。直觉是：较大的子串（以更多1开头）放前面，字典序更大
5. **交换操作的等价性**：题目说可以交换相邻的特殊子串任意次，这等价于可以对同一层的特殊子串做任意排列（因为任意排列可以通过若干次相邻交换达到）

## 解法详解

### 解法一：递归分解 + 排序（推荐）

**算法步骤**：
1. 定义递归函数 `makeLargestSpecial(s)`：
2. 用 `count = 0` 和 `start = 0` 遍历字符串 s：
   - 遇到 '1'：count++
   - 遇到 '0'：count--
   - 当 `count == 0` 时：
     - 找到一个最小特殊子串 `s[start..i]`
     - 递归处理其内部：`inner = makeLargestSpecial(s[start+1..i-1])`
     - 将 `"1" + inner + "0"` 加入子串列表
     - 更新 `start = i + 1`
3. 将收集到的所有子串降序排序
4. 将排序后的子串拼接返回

**示例 "11011000" 的递归过程**：
1. 外层扫描：count 变化为 1,2,1,2,1,0 -> 整个串是一个最小特殊子串
2. 去掉首尾 `1...0` 后内部是 `"101100"`
3. 递归处理 `"101100"`：
   - 扫描 count: 1,0 -> 子串 `"10"`（start=0, i=1）
   - 扫描 count: 1,2,1,0 -> 子串 `"1100"`（start=2, i=5）
   - `"10"` 内部为空，保持 `"10"`
   - `"1100"` 内部为 `"10"`，递归得 `"10"`，结果 `"1100"`
   - 子串列表：["10", "1100"]，降序排列：["1100", "10"]
   - 拼接："110010"
4. 外层结果：`"1" + "110010" + "0"` = `"11100100"`

**复杂度分析**：
- 时间复杂度：O(n^2)，每层递归需要 O(n) 扫描和排序，最坏递归深度 O(n)
- 空间复杂度：O(n)，递归栈和子串存储

### 为什么降序排列能得到字典序最大？

**证明直觉**：
- 每个子串都以 '1' 开头，以 '0' 结尾
- 较长的子串（如 "1100"）以 "11..." 开头，较短的（如 "10"）以 "10..." 开头
- 降序排列让 "11..." 排在 "10..." 前面，使得高位尽可能大
- 这本质上是字符串排序的贪心策略：逐位比较，高位优先放大字符

**严格来说**：同一层的特殊子串可以任意排列（通过相邻交换实现任意置换），字典序最大的排列就是降序排列。

## 易错点

1. **递归处理的是内部**：`s[start+1..i-1]` 而不是 `s[start..i]`，要去掉首尾的 1 和 0
2. **count 初始化**：每次调用递归函数时 count 从 0 开始，不要忘记重置
3. **start 更新时机**：在 count 回到 0 且收集完子串后，将 start 更新为 `i + 1`
4. **排序方向**：是降序（greater<string>()），不是升序。字典序最大 = 降序排列
5. **空字符串处理**：如果 s 为空，直接返回空字符串。递归基就是空串
6. **子串提取**：`s.substr(start + 1, i - start - 1)` 是内部部分，注意长度计算

## 面试追问

1. **Q: 为什么可以把交换相邻子串等价为任意排列？**
   - A: 冒泡排序的原理：任意排列都可以通过若干次相邻交换达到。题目允许无限次交换，所以等价于对同一层的子串做任意排列。

2. **Q: 特殊二进制字符串和 Dyck Path 有什么关系？**
   - A: 特殊二进制字符串对应 Dyck 路径：1 = 上升，0 = 下降，路径永不低于 x 轴。最小特殊子串对应从原点出发首次回到 x 轴的路径段。

3. **Q: 能否用迭代替代递归？**
   - A: 可以但复杂。用栈模拟递归，从内向外处理。递归版本更清晰，推荐面试中使用。

4. **Q: 时间复杂度能否优化到 O(n log n)？**
   - A: 理论上排序部分可以是 O(k log k)，但字符串比较是 O(n)，总体仍可能是 O(n^2)。对于 n <= 50 的约束，O(n^2) 完全足够。

5. **Q: 如果要求字典序最小而不是最大，如何修改？**
   - A: 只需将排序方向改为升序即可。递归结构完全不变。
