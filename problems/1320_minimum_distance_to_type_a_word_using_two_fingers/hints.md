# 1320. 二指输入的的最小距离

## 核心思路

本质上是一个**序列决策问题**：对于字符串中的每个字符，你必须决定用哪根手指去按它，目标是让两根手指的总移动距离最小。状态由"当前要按哪个字符"和"两根手指分别在哪里"决定。

## 思维链

1. **读完题第一反应**：每个字符要么用手指1按，要么用手指2按。暴力枚举所有分配方案？每个字符2种选择，n个字符就是 2^n 种方案 → 指数级，不可行。但这说明这是一个"每步做选择"的问题，很可能是 DP。

2. **定义状态**：要做决策，需要知道什么信息？ — 当前处理到第 i 个字符，两根手指分别在位置 f1 和 f2。所以状态是 `dp[i][f1][f2]`。但 f1、f2 各有 26 种可能 + "还没按过任何键"，加上 n 步，状态空间 O(n × 27 × 27)。

3. **关键观察降维**：当处理到第 i 个字符时，上一个字符 word[i-1] 一定是被某根手指按的。也就是说，两根手指中必有一根在 word[i-1] 上！我们不需要同时记录两根手指的位置 — 只需记录"另一根手指在哪里"。状态简化为 `dp[i][other]`，其中 other 是那根"没按上一个字符"的手指的位置。

4. **状态转移**：对于第 i 个字符 word[i]，有两种选择：
   - 用"在 word[i-1] 上的手指"继续按 → 另一根手指位置不变，代价 = dist(word[i-1], word[i])
   - 用"另一根手指（在 other 位置）"来按 → 现在 word[i-1] 变成了"另一根手指"的位置，代价 = dist(other, word[i])

5. **起始位置免费**：手指初始位置不计代价。用一个特殊值（如 26 或 -1）表示"还没用过"，从这个状态移动到任何字母的距离视为 0。

6. **空间优化**：`dp[i]` 只依赖 `dp[i-1]`，可以用滚动数组将 O(n × 27) 优化到 O(27)。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力记忆化搜索 | dp(i, f1, f2) 三维状态 | O(n × 27²) | O(n × 27²) | 能说出即可 |
| 优化DP (降维) | 利用"必有一指在word[i-1]"降为二维 | O(n × 27) | O(n × 27) | ⭐ 必须写出 |

## 关键提示

1. **键盘布局映射**：字母 c 在键盘上的坐标是 `(c / 6, c % 6)`（6列布局：ABCDEF / GHIJKL / ...）。曼哈顿距离直接用坐标差的绝对值之和计算。

2. **"免费起始"的处理**：手指初始不在任何位置。用一个哨兵值（比如 26）表示"未使用"，从这个状态到任何字母的距离定义为 0，自然处理了"首次放手指不计代价"。

3. **降维的关键洞察**：处理完第 i-1 个字符后，两根手指中必有一根就在 word[i-1] 上。所以只需记录另一根手指的位置，将 27×27 降为 27。

4. **DP填表过程示意**（word = "CAKE"，C=2, A=0, K=10, E=4）：
   ```
   i=0 (C): dp[0][other] — 第一个字符，必有一根手指放在C上，另一根在"未使用"(26)
   i=1 (A): 对每个possible other, 选用哪根手指按A
   i=2 (K): 同理
   i=3 (E): 同理，最后取 min(dp[3][all possible other])
   ```

5. **易忽略的点**：当 `other == 26`（未使用）时，用这根手指去按字母的代价是 0，不是从某个默认位置算距离。

## 解法详解

### 解法1: 三维DP记忆化搜索 — O(n × 27²) / O(n × 27²)

**思考过程**：最自然的状态定义：`dfs(i, f1, f2)` 表示"处理第 i 个字符，手指1在位置f1，手指2在位置f2时，从第i个字符到末尾的最小代价"。每步两种选择：用手指1按 或 用手指2按。

```cpp
class Solution {
public:
    int minimumDistance(string word) {
        int n = word.size();
        // 26 表示手指尚未使用（初始状态）
        // memo[i][f1][f2]: 从第i个字符开始，手指1在f1、手指2在f2的最小代价
        vector<vector<vector<int>>> memo(n, vector<vector<int>>(27, vector<int>(27, -1)));
        
        return dfs(0, 26, 26, word, memo);
    }
    
private:
    int dist(int a, int b) {
        // 26 代表"未使用"，从未使用位置移动到任何字母代价为0
        if (a == 26 || b == 26) return 0;
        int r1 = a / 6, c1 = a % 6;
        int r2 = b / 6, c2 = b % 6;
        return abs(r1 - r2) + abs(c1 - c2);
    }
    
    int dfs(int i, int f1, int f2, const string& word, 
            vector<vector<vector<int>>>& memo) {
        if (i == (int)word.size()) return 0;
        if (memo[i][f1][f2] != -1) return memo[i][f1][f2];
        
        int c = word[i] - 'A';
        // 选择1: 用手指1按第i个字符
        int use1 = dist(f1, c) + dfs(i + 1, c, f2, word, memo);
        // 选择2: 用手指2按第i个字符
        int use2 = dist(f2, c) + dfs(i + 1, f1, c, word, memo);
        
        return memo[i][f1][f2] = min(use1, use2);
    }
};
```

**关键点**：状态数 n × 27 × 27 ≈ 300 × 729 ≈ 218700，完全可以通过。但空间较大，且没有利用"必有一指在上一个字符"的性质。

### 解法2: 二维DP（降维优化）— O(n × 27) / O(n × 27) ⭐ 面试首选

**从解法1优化**：解法1中，当处理第 i 个字符时，上一个字符 word[i-1] 一定在某根手指上。所以两根手指的位置中有一个是确定的（就是 word[i-1]），只需记录"另一根手指在哪"。

定义 `dp[i][j]` = 已处理完前 i 个字符，"另一根手指"在位置 j 时的最小总代价。这里"另一根手指"指的是没按 word[i-1] 的那根。

```
状态转移（处理 word[i]，当前字符 c = word[i]，上一个字符 p = word[i-1]）：

情况1: 用"在p上的手指"按c → 另一根手指不动，仍在j
  dp[i+1][j] = min(dp[i+1][j], dp[i][j] + dist(p, c))

情况2: 用"在j上的另一根手指"按c → 按完后c是刚按的，p变成了"另一根手指"
  dp[i+1][p] = min(dp[i+1][p], dp[i][j] + dist(j, c))
```

```
// DP表填充示意 (word = "CAKE", C=2, A=0, K=10, E=4):
//
//   处理C(i=0): 第一个字符，一根手指放C，另一根在"未使用"(26)
//               dp[1][26] = 0
//
//   处理A(i=1): 从dp[1][26]=0出发
//     情况1: 用在C上的手指按A, 另一根仍在26 → dp[2][26] = 0+dist(C,A)=0+2=2
//     情况2: 用在26上的手指按A, C变成另一根 → dp[2][2] = 0+dist(26,A)=0+0=0
//
//   处理K(i=2): 
//     从dp[2][26]=2: 上一字符A
//       情况1: 用在A上的手指按K → dp[3][26] = 2+dist(A,K)=2+4=6
//       情况2: 用26的手指按K → dp[3][0] = 2+dist(26,K)=2+0=2
//     从dp[2][2]=0: 上一字符A
//       情况1: 用在A上的手指按K → dp[3][2] = 0+dist(A,K)=0+4=4
//       情况2: 用在C上的手指按K → dp[3][0] = min(2, 0+dist(C,K))=min(2,0+3)=2
//
//   处理E(i=3):
//     从dp[3][26]=6: 上一字符K → 用K的手指按E: 6+dist(K,E)=6+1=7
//     从dp[3][0]=2: 上一字符K → 用K的手指按E: 2+1=3 ✓ 
//                                 用A的手指按E: 2+dist(A,E)=2+2=4
//     从dp[3][2]=4: 上一字符K → 用K的手指按E: 4+1=5
//                                 用C的手指按E: 4+dist(C,E)=4+1=5
//
//   答案: min(dp[4][all j]) = 3 ✓
```

```cpp
class Solution {
public:
    int minimumDistance(string word) {
        int n = word.size();
        // dp[j]: 另一根手指在位置j时的最小代价
        // 27个位置: 0-25是字母, 26是"未使用"
        const int INF = 1e9;
        // dp[i][j]: 处理完前i个字符后，另一根手指在j
        vector<vector<int>> dp(n + 1, vector<int>(27, INF));
        
        // 初始: 第一个字符放下，另一根手指在26(未使用)，代价0
        dp[1][26] = 0;
        
        for (int i = 1; i < n; i++) {
            int c = word[i] - 'A';     // 当前要按的字符
            int p = word[i - 1] - 'A'; // 上一个字符（必有一指在此）
            
            for (int j = 0; j < 27; j++) {
                if (dp[i][j] == INF) continue;
                
                // 情况1: 用"在p上的手指"按c，另一根手指不动
                dp[i + 1][j] = min(dp[i + 1][j], dp[i][j] + cost(p, c));
                
                // 情况2: 用"在j上的另一根手指"按c，p变成另一根手指
                dp[i + 1][p] = min(dp[i + 1][p], dp[i][j] + cost(j, c));
            }
        }
        
        int ans = INF;
        for (int j = 0; j < 27; j++) {
            ans = min(ans, dp[n][j]);
        }
        return ans;
    }
    
private:
    int cost(int a, int b) {
        if (a == 26 || b == 26) return 0; // 未使用 → 免费
        return abs(a / 6 - b / 6) + abs(a % 6 - b % 6);
    }
};
```

**关键点**：
- 降维的关键是认识到"两根手指中必有一根在 word[i-1] 上"，这把状态从 27² 降到 27
- 初始化只有 `dp[1][26] = 0`（第一个字符放下后，另一根手指未使用）

### 解法3: 空间优化DP — O(n × 27) / O(27)

**从解法2优化**：`dp[i+1]` 只依赖 `dp[i]`，用两个一维数组滚动即可。

```cpp
class Solution {
public:
    int minimumDistance(string word) {
        int n = word.size();
        const int INF = 1e9;
        vector<int> dp(27, INF), ndp(27, INF);
        
        dp[26] = 0; // 第一个字符放下后，另一根手指未使用
        
        for (int i = 1; i < n; i++) {
            int c = word[i] - 'A';
            int p = word[i - 1] - 'A';
            fill(ndp.begin(), ndp.end(), INF);
            
            for (int j = 0; j < 27; j++) {
                if (dp[j] == INF) continue;
                // 用在p上的手指按c
                ndp[j] = min(ndp[j], dp[j] + cost(p, c));
                // 用在j上的手指按c
                ndp[p] = min(ndp[p], dp[j] + cost(j, c));
            }
            swap(dp, ndp);
        }
        
        return *min_element(dp.begin(), dp.end());
    }
    
private:
    int cost(int a, int b) {
        if (a == 26 || b == 26) return 0;
        return abs(a / 6 - b / 6) + abs(a % 6 - b % 6);
    }
};
```

## 解法对比

| | 解法1 三维记忆化 | 解法2 二维DP ⭐ | 解法3 空间优化 |
|---|---|---|---|
| 时间 | O(n × 27²) | O(n × 27) | O(n × 27) |
| 空间 | O(n × 27²) | O(n × 27) | O(27) |
| 核心思路 | 直接记录两根手指位置 | 利用"必有一指在word[i-1]"降维 | 滚动数组 |
| 面试推荐 | 能说出思路即可 | **首选写法** | 追问空间优化时给出 |

解法1到解法2的关键跳跃是发现冗余状态：两根手指的位置不是独立的，其中一个被上一个字符锁定了。

## 易错点

1. **忘记处理"未使用"状态的距离**
   - ✗ `dist(26, c)` 按正常坐标算 → 得到一个很大的错误距离
   - ✓ `if (a == 26 || b == 26) return 0;` → 未使用的手指第一次放下不计代价

2. **dp初始化错误**
   - ✗ `dp[1][word[0]-'A'] = 0` — 把另一根手指初始化在第一个字符上
   - ✓ `dp[1][26] = 0` — 另一根手指在"未使用"位置，因为一开始只有一根手指放了第一个字符

3. **键盘是6列不是5列**
   - ✗ `a / 5, a % 5` — 以为5列（ABCDE一行）
   - ✓ `a / 6, a % 6` — 键盘是6列（ABCDEF一行，共26个字母分布在5行6列中，最后一行只有2个）

4. **情况2的状态转移写反**
   - ✗ `dp[i+1][j] = ... + cost(j, c)` — 用j的手指按c后，另一根手指仍然写成j
   - ✓ `dp[i+1][p] = ... + cost(j, c)` — 用j的手指按c后，p变成了"另一根手指"

## 面试追问

**Q1: 为什么暴力是 2^n？能直接DP吗？状态怎么定义？**
每个字符有"用手指1"或"用手指2"两种选择，共 2^n 种。DP状态需要记录当前位置和两根手指的位置：`dp[i][f1][f2]`，O(n × 27²)。

**Q2: 能否把 27² 降到 27？为什么？**
关键洞察：处理完第i个字符后，必有一根手指在 word[i] 上，另一根在某个位置 j。所以只需记录 j。状态从三维降到二维 `dp[i][j]`。

**Q3: 如果键盘布局改变（比如不是6列矩形，而是任意位置），代码需要改哪里？**
只需要修改 `cost()` 函数中的坐标计算逻辑。可以用一个 `pos[26]` 数组存每个字母的 (x, y) 坐标，DP框架完全不变。这体现了将"距离计算"和"决策逻辑"解耦的好处。

**Q4: 如果不是两根手指，而是 k 根手指呢？**
需要记录 k-1 根"另外手指"的位置（因为必有一根在上一个字符上）。状态变成 `dp[i][j1][j2]...[jk-1]`，复杂度指数增长于 k。对于 k 较小的情况可以状态压缩，k 较大时需要其他近似方法。
