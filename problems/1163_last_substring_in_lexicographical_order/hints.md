# 1163. 按字典序排在最后的子串

## 核心思路

字典序最大的子串，**一定是从某个位置 `i` 开始到字符串末尾的后缀**。问题简化为：在所有后缀中找字典序最大的那个。关键是如何高效比较后缀。

## 思维链

1. **读完题第一反应**：枚举所有子串，排序取最大？子串数量是 O(n²)，排序每次比较是 O(n)，总共 O(n³ log n)，太慢了。

2. **关键观察——答案一定是某个后缀**：任何子串 `s[i..j]`，把它扩展到 `s[i..n-1]`（后缀），字典序只会 ≥ 原来。所以答案一定是从某个位置开始到末尾的后缀。这把问题从 O(n²) 个子串缩减到 O(n) 个后缀。

3. **暴力找最大后缀**：枚举每个起始位置 `i`，和当前最优的 `best` 逐字符比较。最坏 O(n²)（如 `"aaaa...a"`），还是太慢。

4. **瓶颈在哪**：暴力法中两个后缀比较时，如果前 k 个字符都相同，才发现谁大谁小，浪费了 k 步。能否利用"已经比过的信息"跳过一些候选？

5. **双指针优化（核心突破）**：维护两个候选位置 `i` 和 `j`，以及已匹配长度 `k`。当 `s[i+k] == s[j+k]` 时 `k++`；当不等时，较小的那个候选可以直接跳过 `k+1` 个位置，因为中间的位置都不可能更优。这保证总比较次数是 O(n)。

6. **为什么能跳 k+1 步**：如果 `s[i..i+k-1] == s[j..j+k-1]` 且 `s[i+k] < s[j+k]`，那么以 `i, i+1, ..., i+k` 为起点的后缀都不可能是最优的——因为对应地，`j, j+1, ..., j+k` 各自都更优或者等价。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力比较 | 枚举所有后缀，两两比较 | O(n²) | O(1) | 能说出即可 |
| 双指针 | 两个候选后缀 + 匹配长度跳跃 | O(n) | O(1) | ⭐ 必须写出 |
| 后缀数组 | 构建后缀数组取最大 | O(n) ~ O(n log n) | O(n) | 加分项 |

## 关键提示

1. **答案必为后缀**：想清楚为什么——任何子串 `s[i..j]` 扩展到 `s[i..n-1]` 字典序不减。
2. **双指针的跳跃逻辑**：当 `s[i+k] < s[j+k]` 时，`i` 要跳到 `i+k+1`。但注意跳完之后如果 `i == j`，还得再 `i++` 让两个指针不重合。
3. **匹配长度 k 的重置**：每次某个指针跳跃后，`k` 必须归零重新比较。
4. **想想为什么中间位置可以跳过**：如果 `s[i..i+k-1] == s[j..j+k-1]`，那么从 `i+1` 开始的后缀 vs 从 `j+1` 开始的后缀，前 `k-1` 个字符也相等，且 `j+1` 方向上第 `k` 个字符更大。

```
// 示例: s = "abab"
// 后缀: "abab", "bab", "ab", "b"
// 字典序: "ab" < "abab" < "b" < "bab"
// 答案: "bab" (从 index 1 开始的后缀)
//
// 双指针过程:
// i=0, j=1, k=0: s[0]='a' < s[1]='b' → i 跳到 0+0+1=1, i==j → i=2
// i=2, j=1, k=0: s[2]='a' < s[1]='b' → i 跳到 2+0+1=3
// i=3, j=1, k=0: s[3]='b' == s[1]='b' → k=1
// i=3, j=1, k=1: s[4] 越界, s[2]='a' → j 保持, i 越界 → 结束
// 答案: s[1..] = "bab"
```

## 解法详解

### 解法1: 暴力比较 — O(n²) / O(1)

**思考过程**: 最直接的想法：答案是某个后缀，就枚举所有起始位置，记录当前字典序最大的后缀的起始位置。

```cpp
class Solution {
public:
    string lastSubstring(string s) {
        int n = s.size();
        int best = 0; // 当前最优后缀的起始位置
        for (int i = 1; i < n; i++) {
            // 逐字符比较 s[i..] 和 s[best..]
            // 如果 s[i..] 更大，更新 best = i
            int j = 0;
            while (i + j < n && s[i + j] == s[best + j]) {
                j++;
            }
            if (i + j < n && s[i + j] > s[best + j]) {
                best = i;
            }
        }
        return s.substr(best);
    }
};
```

**关键点**: 对于 `"aaaa...ab"` 这种输入，每次比较都要走很多步才能分出胜负，最坏 O(n²)。n = 4×10⁵ 时会 TLE。

---

### 解法2: 双指针 — O(n) / O(1) ⭐ 面试首选

**从解法1优化**: 解法1的瓶颈是每次只淘汰一个候选，而且不利用之前比较过的信息。双指针法维护两个候选 `i` 和 `j`，加上已匹配长度 `k`，当分出胜负时，失败方不仅自己被淘汰，它后面的 `k` 个位置也一并淘汰。

**核心逻辑**：
- `i` 和 `j` 是两个候选后缀的起始位置，`k` 是当前已匹配的长度。
- 若 `s[i+k] == s[j+k]`：继续匹配，`k++`。
- 若 `s[i+k] < s[j+k]`：`i` 这边不如 `j`，`i` 跳到 `i+k+1`。
- 若 `s[i+k] > s[j+k]`：`j` 跳到 `j+k+1`。
- 跳完后如果 `i == j`，让重合的那个 `+1`。
- `k` 重置为 0。

**为什么跳 k+1 步是安全的**（以 `s[i+k] < s[j+k]` 为例）：
```
// s[i..i+k-1] == s[j..j+k-1], s[i+k] < s[j+k]
//
// 考虑以 i+t (0 ≤ t ≤ k) 开头的后缀:
//   s[i+t .. i+k-1] == s[j+t .. j+k-1]  (因为对应子串相等)
//   s[i+k] < s[j+k]
// 所以 suffix(i+t) < suffix(j+t) 对所有 0 ≤ t ≤ k 成立
// 因此 i, i+1, ..., i+k 都可以被淘汰，i 直接跳到 i+k+1
```

```cpp
class Solution {
public:
    string lastSubstring(string s) {
        int n = s.size();
        int i = 0, j = 1, k = 0;
        // i, j: 两个候选后缀的起始位置
        // k: 当前已匹配的字符数
        while (j + k < n) {
            if (s[i + k] == s[j + k]) {
                // 还没分出胜负，继续匹配
                k++;
            } else if (s[i + k] < s[j + k]) {
                // i 这边输了，跳过 i 到 i+k 这些位置
                i = i + k + 1;
                if (i == j) i++; // 两个候选不能重合
                k = 0;
            } else {
                // j 这边输了，跳过 j 到 j+k 这些位置
                j = j + k + 1;
                if (i == j) j++; // 两个候选不能重合
                k = 0;
            }
        }
        // 循环结束时 j+k >= n，说明 j 那边已经比完或越界
        // i 就是字典序最大后缀的起始位置
        return s.substr(i);
    }
};
```

**复杂度分析**：
- 每次循环，`j+k` 至少增 1（要么 k++，要么 j 跳到 j+k+1 使 j 增大）。`j+k` 从 1 增到 n-1，所以最多 O(n) 次循环。
- 注意 i 也在前进，且 i < j 始终成立（或者更准确地说 i 和 j 不重合），所以不会出现无限循环。

**关键点**: 循环终止后答案是 `i` 而不是 `min(i, j)`。因为当 `j+k >= n` 时，说明从 `j` 开始的后缀比 `i` 短且前缀与 `i` 相同，所以 `i` 更优（更长的那个字典序更大）。

---

### 解法3: 后缀数组（加分项）— O(n log n) 或 O(n) / O(n)

**思路**: 构建后缀数组（所有后缀按字典序排序后的起始位置数组），取最后一个元素对应的后缀。后缀数组是字符串算法中的经典数据结构，但实现复杂，面试中一般不要求手写，了解即可。

```cpp
class Solution {
public:
    string lastSubstring(string s) {
        // 使用简化版后缀数组 (SA-IS 或 倍增法)
        // 这里用 std::sort 的 O(n² log n) 简化版做示意
        // 实际面试中推荐解法2
        int n = s.size();
        vector<int> sa(n);
        iota(sa.begin(), sa.end(), 0);
        sort(sa.begin(), sa.end(), [&](int a, int b) {
            return s.compare(a, string::npos, s, b, string::npos) < 0;
        });
        return s.substr(sa.back());
    }
};
```

**注意**: 这个简化实现的排序是 O(n² log n)（每次比较 O(n)），比双指针慢。真正的 O(n) 后缀数组（如 SA-IS）实现非常复杂，不适合面试手写。

## 解法对比

| | 暴力比较 | 双指针 | 后缀数组 |
|---|---|---|---|
| 时间 | O(n²) | O(n) | O(n)~O(n²logn) |
| 空间 | O(1) | O(1) | O(n) |
| 代码量 | 简单 | 中等 | 复杂 |
| 面试 | 说思路即可 | ⭐ 首选 | 加分了解 |

**核心区别**: 暴力法每次只淘汰 1 个候选；双指针利用已比较的信息一次淘汰 k+1 个候选，因此是 O(n)。

## 易错点

1. **✗ 跳跃后忘记处理 `i == j`**
   ```cpp
   i = i + k + 1;
   k = 0;  // 漏掉 i==j 的检查
   ```
   **✓ 正确做法**: 跳完后如果 `i == j`，必须让一个再 +1，否则两个候选重合导致无限循环。

2. **✗ 循环条件写成 `j < n`**
   ```cpp
   while (j < n) { ... s[j+k] ... }  // j+k 可能越界!
   ```
   **✓ 正确做法**: 循环条件是 `j + k < n`，因为我们访问的是 `s[j+k]`。同时注意 `i+k < n` 在 `j+k < n` 且 `i < j` 时自动满足。

3. **✗ 认为答案起始位置是 `min(i, j)`**
   循环结束时 `j+k >= n`，此时 `j` 指向的后缀比 `i` 短（或已越界），`i` 才是答案。不要取 min。

4. **✗ 跳跃步长写成 `i = i + k` 而不是 `i = i + k + 1`**
   必须跳过 `i+k` 这个位置本身，因为以 `i+k` 为起点的后缀也被证明不如 `j+k` 为起点的后缀。

## 面试追问

**Q1: 为什么答案一定是某个后缀？**
→ 任何子串 `s[i..j]` 扩展到 `s[i..n-1]` 字典序 ≥ 原来（要么在第 j+1 位多出字符，要么相同前缀但更长）。所以字典序最大的子串一定从某个位置延伸到末尾，即后缀。

**Q2: 双指针跳跃为什么是对的？跳过的位置真的不可能是答案吗？**
→ 以 `s[i+k] < s[j+k]` 为例：对于任何 `0 ≤ t ≤ k`，`suffix(i+t)` 和 `suffix(j+t)` 的前 `k-t` 个字符相同（因为 `s[i..i+k-1] == s[j..j+k-1]`），而第 `k-t+1` 个字符处 `s[i+k] < s[j+k]`，所以 `suffix(i+t) < suffix(j+t)`。每个被跳过的位置都有对应的更优位置。

**Q3: 如果要求第 K 大的后缀呢？**
→ 需要构建后缀数组。可以用 O(n log²n) 的倍增法或 O(n) 的 SA-IS 算法。构建完直接取第 `n-K` 个位置。双指针法只能找最大，无法扩展到第 K 大。

**Q4: 这个双指针的思路还能用在哪里？**
→ 这本质上是"最大后缀"算法，也叫 **Booth's algorithm** 的变体。在求字符串的最小/最大循环旋转（最小表示法）中用到类似的双指针跳跃技巧。
