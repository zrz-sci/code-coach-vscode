# 720. Longest Word in Dictionary

## 核心思路

一个单词能被"逐字符构建"等价于它的每个前缀（长度 1 到 len-1）都出现在词典中。用 HashSet 或 Trie 验证所有前缀是否存在，追踪满足条件的最长（字典序最小）单词。

---

## 思维链

1. **理解"逐步构造"**：单词 "world" 可以逐步构造 ⟺ "w", "wo", "wor", "worl", "world" 全部在 words 中。
2. **暴力检查**：对每个单词，检查它所有长度的前缀是否都在词典中，但对每个单词逐个查前缀太慢。
3. **优化思路 A — 排序 + HashSet**：如果按长度排序，短单词先处理。当处理一个单词时，只需检查它去掉最后一个字符的前缀是否已经在"可构建集合"中。
4. **优化思路 B — Trie**：把所有单词插入 Trie，然后 DFS/BFS 遍历，只走 isEnd=true 的节点。能到达的最深叶子对应最长可构建单词。
5. **相同长度取字典序最小**：排序法自动保证（先按长度再按字典序）；Trie BFS 按 a-z 顺序遍历子节点也自动保证。

---

## 解法概览

| 解法 | 思路 | 时间复杂度 | 空间复杂度 | 推荐度 |
|------|------|-----------|-----------|--------|
| 排序 + HashSet | 排序后逐个验证前缀 | O(n log n + n * L) | O(n * L) | 首选 |
| Trie + BFS/DFS | 构建 Trie 后只走完整单词路径 | O(n * L) | O(n * L) | 备选 |
| 暴力检查 | 每个单词逐个查所有前缀 | O(n * L^2) | O(n * L) | 仅理解 |

L = 单词平均长度

## 关键提示

### 提示 1 — 什么条件下单词可构建？

一个单词 w 可逐步构建的**充要条件**是什么？

<details>
<summary>展开</summary>

w 的每一个前缀（长度 1, 2, ..., len(w)-1）都在 words 集合中。等价地说，w 去掉最后一个字符后的子串也是可构建的。这构成了一个递推关系：w 可构建 ⟺ w[0..len-2] 可构建 且 w[0..len-2] 在 words 中。

</details>

### 提示 2 — 排序方案中为什么先排序？

<details>
<summary>展开</summary>

按长度升序排序保证处理 w 时，w 的所有前缀（更短的单词）已经被处理过了。只需看 w 去掉最后一个字母后的前缀是否在 "已验证可构建" 的集合中。

排序规则：先按长度升序，长度相同按字典序。这样最后更新 result 时，同长度的单词中字典序更小的先被处理，但我们用 `>` 来更新 result 所以最终留下的是第一个最长的。

</details>

### 提示 3 — Trie 方案中如何剪枝？

<details>
<summary>展开</summary>

BFS/DFS 时，只沿着 isEnd == true 的子节点向下走。这确保了路径上每一步都对应一个在词典中存在的完整单词，即每个前缀都存在。

BFS 天然按层遍历（层 = 单词长度），在每层按 a-z 顺序处理子节点，自动满足"字典序最小"的要求。

</details>

### 提示 4 — 怎样处理字典序？

<details>
<summary>展开</summary>

**排序法**：排序时同长度按字典序。遍历时只在 w.size() > result.size() 时更新 result，这样同长度中只有第一个（字典序最小的）被选中。

**Trie 法**：BFS 遍历子节点时按 children[0] 到 children[25]（即 a 到 z）顺序，天然保证字典序优先。

</details>

## 解法详解

### 解法一：排序 + HashSet

**算法步骤**：

1. 将 words 排序（按长度升序，同长度按字典序）
2. 初始化 HashSet built = {""}，表示空串可构建
3. 初始化 result = ""
4. 遍历每个单词 w：
   - 取 prefix = w.substr(0, w.size()-1)
   - 如果 prefix 在 built 中，则 w 可构建
   - 将 w 加入 built
   - 如果 w.size() > result.size()，更新 result = w
5. 返回 result

**关键点**：空串 "" 放入 built 是为了处理长度为 1 的单词（它去掉最后一个字符后是空串）。

### 解法二：Trie + BFS

**算法步骤**：

1. 构建 Trie，将所有 words 插入
2. 从 root 开始 BFS
3. 对于每个节点，按 a-z 顺序检查子节点
4. 只将 isEnd == true 的子节点入队
5. 追踪 BFS 过程中遇到的最深（最长单词）节点
6. 由于 BFS 按层遍历 + 按字母序处理子节点，最后一个更新 result 的就是最长且字典序最小的单词

**Trie 节点**存储该节点对应的完整单词（或者通过路径重建），方便直接返回结果。

---

## 易错点

1. **忘记初始化空串**：HashSet 方案中必须先加入 ""，否则长度为 1 的单词无法被判定为可构建
2. **排序顺序搞反**：应先按长度升序，不是降序。降序的话前缀还没被验证就先处理了长单词
3. **更新 result 的条件**：用 `>` 不是 `>=`。用 `>=` 会在同长度中取字典序更大的那个
4. **Trie 中忘记标记 isEnd**：没有标记的话 BFS 会走到不存在的"伪前缀"上
5. **substr 的边界**：w.substr(0, w.size()-1) 在 w 为空时有问题，但题目保证 words 非空且单词长度 >= 1

## 面试追问

**Q1: 排序 + HashSet 和 Trie 各有什么优劣？**

排序+HashSet 实现简单，常数因子小，适合面试快速写出。Trie 方案更体现数据结构功底，不需要排序（O(n*L) vs O(n log n + n*L)），但代码量大、内存开销高。如果 n 很大且 L 很小，两者差异不大；如果面试官想考 Trie，就写 Trie。

**Q2: 如果有多个最长单词怎么办？**

题目要求返回字典序最小的。排序法通过排序保证同长度中字典序最小的先被处理；Trie BFS 通过 a-z 顺序遍历保证。两种方案都天然满足。

**Q3: 能否用 DFS 代替 BFS？**

可以。DFS 遍历 Trie 时也只沿 isEnd=true 节点走，记录最大深度对应的单词。但需要额外处理字典序（DFS 按 a-z 顺序递归，遇到更深的才更新 result）。BFS 更直观一些。

**Q4: 时间复杂度的 L 具体是什么？**

L 是单词的最大长度（或平均长度，取决于具体分析）。排序中比较两个字符串是 O(L)，排序 O(n * L * log n)。HashSet 中 substr 和 hash 计算都是 O(L)。Trie 中插入每个单词 O(L)。
