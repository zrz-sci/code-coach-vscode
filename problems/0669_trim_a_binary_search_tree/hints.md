# 669. 修剪二叉搜索树

## 核心思路

本质上在问：**利用 BST 的有序性，递归地判断每个节点是否在 [low, high] 范围内，不在范围的节点要被"替换"为它合适的子树**。关键洞察是——删除一个节点不意味着它的所有后代都要删除，BST 的性质保证了我们能精准地知道该往哪个子树找保留的节点。

## 思维链

1. **读完题第一反应**：遍历整棵树，对于不在 [low, high] 范围内的节点，把它们删掉。最朴素的做法是中序遍历收集所有合法节点值，然后重建一棵 BST —— 但这改变了树的结构，而且浪费。

2. **能不能原地修剪？** 考虑递归：对于当前节点 root：
   - 如果 `root->val < low`，说明 root 以及 root 的**整个左子树**都太小了（BST 性质！），答案只可能在右子树中。
   - 如果 `root->val > high`，同理，答案只可能在左子树中。
   - 如果 `low <= root->val <= high`，root 保留，但左右子树各自需要递归修剪。

3. **关键洞察：BST 性质让我们能剪掉整棵子树**。如果 root 值太小，它的左子树一定更小，全部不要，只需递归处理右子树。这比普通二叉树高效得多（普通二叉树不能利用这种偏序关系）。

4. **递归返回值的含义**：`trimBST(node, low, high)` 返回的是以 node 为根的子树修剪后的新根。这个"返回新根"的模式是树修改类题目的核心范式。

5. **迭代版思路**：先找到一个在 [low, high] 内的根节点（不断用 BST 性质跳转），然后分别修剪左子树和右子树中越界的节点。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 递归 | 利用 BST 性质递归修剪 | O(n) | O(h) | ⭐ 必须写出 |
| 迭代 | 先找合法根，再修剪左右越界节点 | O(n) | O(1) | 加分项 |

## 关键提示

1. **不要想成"删除节点"**，要想成"返回修剪后的子树根"。当一个节点不合法时，返回它合法的那棵子树即可。

2. **BST 性质是本题的核心**：当 `root->val < low` 时，root 的左子树中所有值都 `< root->val < low`，全部不合法，只需递归处理右子树。

3. 画出示例2理解过程：
```
//  原始树:              修剪 [1, 3]:
//       3                    3
//      / \                  /
//     0   4        →      2
//      \                 /
//       2               1
//      /
//     1
//
// 分析过程:
// root=3: 3 在 [1,3] → 保留，递归修剪左右子树
// root=4: 4 > 3 → 去右子树？右子树为空 → 返回 null
// root=0: 0 < 1 → 去右子树 root=2
// root=2: 2 在 [1,3] → 保留，递归修剪左右子树
// root=1: 1 在 [1,3] → 保留（叶子节点）
```

4. 递归终止条件别忘了空节点。

5. 迭代版的难点：修剪左子树时，需要不断把"左孩子值小于 low"的节点替换为其右孩子。

## 解法详解

### 解法1: 递归 — O(n) / O(h) ⭐ 面试首选

**思考过程**：树的修改类题目，最自然的递归框架是"返回修改后的子树根"。对于 BST 的修剪：
- 节点值太小 → 它和它的左子树全部无效，返回右子树的修剪结果
- 节点值太大 → 它和它的右子树全部无效，返回左子树的修剪结果
- 节点值合法 → 保留当前节点，左右子树各自递归修剪

```cpp
class Solution {
public:
    TreeNode* trimBST(TreeNode* root, int low, int high) {
        if (!root) return nullptr;
        
        // root 太小：root 和它的左子树全部 < low，答案在右子树
        if (root->val < low) {
            return trimBST(root->right, low, high);
        }
        // root 太大：root 和它的右子树全部 > high，答案在左子树
        if (root->val > high) {
            return trimBST(root->left, low, high);
        }
        
        // root 在 [low, high] 范围内，保留它
        // 但左右子树中可能有越界的节点，递归修剪
        root->left = trimBST(root->left, low, high);
        root->right = trimBST(root->right, low, high);
        return root;
    }
};
```

**关键点**：
- 递归返回值表示"修剪后这棵子树的根"，这样父节点可以直接接上。
- `root->left = trimBST(root->left, ...)` 这一行同时完成了"修剪"和"重新连接"两件事。

### 解法2: 迭代 — O(n) / O(1)

**从解法1到迭代**：递归的三种情况（太小跳右、太大跳左、合法则修剪左右），迭代需要分三步处理：

**Step 1**：找到一个值在 [low, high] 内的根节点（原 root 可能越界）
**Step 2**：修剪左子树 —— 如果某节点的左孩子值 < low，用左孩子的右子树替换它
**Step 3**：修剪右子树 —— 如果某节点的右孩子值 > high，用右孩子的左子树替换它

```cpp
class Solution {
public:
    TreeNode* trimBST(TreeNode* root, int low, int high) {
        // Step1: 找到在 [low, high] 内的根节点
        while (root && (root->val < low || root->val > high)) {
            if (root->val < low) root = root->right;
            else root = root->left;
        }
        if (!root) return nullptr;
        
        // Step2: 修剪左子树中 val < low 的节点
        // 此时 root->val >= low，但 root 的左子树中可能有 < low 的
        TreeNode* node = root;
        while (node->left) {
            if (node->left->val < low) {
                // 左孩子太小，它的左子树更小，全扔
                // 用左孩子的右子树替代左孩子
                node->left = node->left->right;
            } else {
                // 左孩子合法，继续往左深入检查
                node = node->left;
            }
        }
        
        // Step3: 修剪右子树中 val > high 的节点
        // 此时 root->val <= high，但 root 的右子树中可能有 > high 的
        node = root;
        while (node->right) {
            if (node->right->val > high) {
                // 右孩子太大，它的右子树更大，全扔
                // 用右孩子的左子树替代右孩子
                node->right = node->right->left;
            } else {
                // 右孩子合法，继续往右深入检查
                node = node->right;
            }
        }
        
        return root;
    }
};
```

**关键点**：
- Step2 中 `node->left = node->left->right` 这一步：左孩子太小被删掉，但左孩子的右子树可能有合法值（因为右子树值更大），所以用它替换。替换后不移动 node，因为新的左孩子可能还是太小，需要继续检查。
- Step3 对称处理。

## 解法对比

| | 递归 | 迭代 |
|---|---|---|
| 代码简洁度 | 极简，5行核心逻辑 | 较复杂，三段处理 |
| 空间 | O(h) 栈空间 | O(1) |
| 思维难度 | 低，自然递归 | 中，需要想清楚三步 |
| 面试推荐 | ⭐ 首选 | 追问"能否O(1)空间"时给出 |

**面试场景**：先写递归，面试官追问空间优化时再给迭代。

## 易错点

1. **递归时忘记处理空节点**
   - ✗ 没有 `if (!root) return nullptr;` 导致空指针异常
   - ✓ 递归函数第一行就判空

2. **以为 root->val < low 时直接返回 nullptr**
   - ✗ `if (root->val < low) return nullptr;` —— 这把右子树中的合法节点也丢了！
   - ✓ `if (root->val < low) return trimBST(root->right, low, high);` —— 右子树中可能有合法节点

3. **迭代版中替换后错误地移动了指针**
   - ✗ `node->left = node->left->right; node = node->left;` —— 替换后应该原地再检查
   - ✓ 替换后不移动 node，因为新接上来的节点可能仍然不合法

4. **混淆"删除BST节点"和"修剪BST"**
   - 删除节点（LeetCode 450）需要处理被删节点有两个孩子的情况（找后继/前驱）
   - 修剪更简单：越界节点直接用它的一棵子树替换，不需要找后继

## 面试追问

**Q1: 递归的时间复杂度为什么是 O(n) 而不是 O(n log n)？**
每个节点最多被访问一次。当 root->val < low 时，我们跳到右子树，跳过了 root 和整个左子树，不会重复访问。总共 n 个节点，每个最多访问一次，所以 O(n)。

**Q2: 能否不用递归，O(1) 空间完成？**
可以，就是迭代解法。三步走：先找合法根，再分别修剪左子树和右子树中的越界节点。关键是利用 BST 性质——左子树越界只可能是太小（用右孩子替换），右子树越界只可能是太大（用左孩子替换）。

**Q3: 如果不是 BST 而是普通二叉树，怎么修剪（删除值不在范围内的节点）？**
失去了 BST 性质，就不能"跳过整棵子树"。但仍然可以递归：合法节点保留并递归修剪左右子树，不合法节点需要想办法把它的左右子树中的合法节点"提上来"。这个问题更复杂，因为一个不合法节点可能左右子树都有合法节点，无法简单替换。一种做法：先递归修剪左右子树，然后如果当前节点不合法，需要合并两棵子树（类似合并两棵树）。

**Q4: 和 LeetCode 450"删除BST中的节点"有什么区别？**
450 只删除一个特定值的节点，需要处理"两个孩子"的情况（找中序后继）。本题删除一个连续范围外的所有节点，但因为 BST 性质，越界的节点和它的一侧子树一定全部越界，所以反而更简单——不需要找后继，直接用另一侧子树替换。
