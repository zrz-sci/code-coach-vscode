# 860. 柠檬水找零

## 核心思路

本质上是一个**模拟找零过程**的问题：你只需要跟踪手里有多少张 5 元和 10 元的钞票，遇到每个顾客时按贪心策略选择找零方式即可。

## 思维链

1. **读完题第一反应**：每来一个顾客，看他付了多少钱，需要找多少零。5 元不用找，10 元找 5，20 元找 15。直接模拟这个过程就行。

2. **需要记录什么状态？** 我们收到的钞票只有三种面值：5、10、20。找零只可能用到 5 元和 10 元（20 元永远不会被用来找零，因为没有需要找 20 或 25 的场景）。所以只需要两个计数器：`five` 和 `ten`。

3. **20 元找零有两种方式**：找 15 元 = 一张10 + 一张5，或者三张5。选哪个？这里有贪心的选择 —— **优先用 10 元 + 5 元**，因为 10 元钞票的用途很单一（只能在找 20 元时用），而 5 元钞票更万能（找 10 元和 20 元都需要它）。所以 5 元钞票更珍贵，应该尽量保留。

4. **为什么贪心是对的？** 10 元钞票只能在顾客付 20 元时派上用场，而 5 元钞票在付 10 元和 20 元时都需要。如果你在能用 10 元的时候不用，改用三张 5 元，白白浪费了更通用的资源，后面可能就不够用了。

5. **遍历一遍即可**：按顺序处理每个顾客，维护 `five` 和 `ten` 计数器，任何时刻如果找不出零钱就返回 false。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 贪心模拟 | 维护 5 元和 10 元计数器，20 元优先用 10+5 找零 | O(n) | O(1) | ⭐ 必须写出 |

> 这道 Easy 题只有一种正解思路（贪心模拟），没有"暴力 → 优化"的递进。但贪心策略的**正确性论证**是面试考察的重点。

## 关键提示

1. **20 元钞票永远不会被用来找零** — 想想为什么？这意味着你只需要跟踪 5 元和 10 元的数量。

2. **找零 15 元有两种方案**：10+5 或 5+5+5。哪种更优？想想哪种面值的钞票"更通用"。

3. **贪心直觉**：5 元钞票是"万能零钱"，能少用就少用。所以 20 元找零时，优先消耗 10 元钞票。

4. 模拟过程示意：
```
bills = [5, 5, 5, 10, 20]

顾客1: 付5元  → five=1, ten=0  (不用找零)
顾客2: 付5元  → five=2, ten=0
顾客3: 付5元  → five=3, ten=0
顾客4: 付10元 → 找5元 → five=2, ten=1
顾客5: 付20元 → 找15元 → 优先用10+5 → five=1, ten=0 ✓
```

## 解法详解

### 解法1: 贪心模拟 — O(n) / O(1) ⭐ 面试首选

**思考过程**：

每杯柠檬水 5 元，顾客付款只有三种情况：
- **付 5 元**：不用找零，直接收下。
- **付 10 元**：需要找 5 元，必须有 5 元钞票。
- **付 20 元**：需要找 15 元，有两种方案：
  - 方案A：10 + 5（优先选这个）
  - 方案B：5 + 5 + 5（方案A不行时用这个）

为什么方案 A 优先？因为 10 元钞票只在"顾客付 20 元"时有用，而 5 元钞票在"付 10 元"和"付 20 元"两种场景都需要。5 元钞票更灵活，应该尽量留着。

```cpp
class Solution {
public:
    bool lemonadeChange(vector<int>& bills) {
        int five = 0, ten = 0;
        
        for (int bill : bills) {
            if (bill == 5) {
                // 付5元：不用找零，收下这张5元
                five++;
            } else if (bill == 10) {
                // 付10元：必须找一张5元
                if (five == 0) return false;
                five--;
                ten++;
            } else {
                // 付20元：找15元，贪心优先用10+5
                if (ten > 0 && five > 0) {
                    ten--;
                    five--;
                } else if (five >= 3) {
                    five -= 3;
                } else {
                    return false;
                }
                // 注意：收到的20元不用记录，因为永远用不上
            }
        }
        
        return true;
    }
};
```

**关键点**：
- 20 元钞票的数量不需要跟踪，因为找零永远不会用到 20 元。
- 贪心的核心在 `bill == 20` 的分支：先尝试 10+5，不行再用 5+5+5。

## 解法对比

本题只有一种核心思路。如果面试官问"有没有其他方法"，可以提到：
- **不用贪心，暴力枚举找零方案？** 对于 20 元找零，只有两种方案，不存在组合爆炸，所以贪心和枚举差别不大。但贪心的正确性论证体现了你的思维深度。

## 易错点

1. **忘记收下顾客付的钱**：
   - ✗ 付 10 元时只写了 `five--`，忘了 `ten++`
   - ✓ 付 10 元：`five--; ten++;`（找出一张 5 元，收下一张 10 元）

2. **20 元找零的条件写错**：
   - ✗ `if (ten > 0) { ten--; five--; }` — 忘了检查 five 是否也 > 0
   - ✓ `if (ten > 0 && five > 0)` — 10+5 方案需要**同时**有 10 元和 5 元

3. **多余地跟踪 20 元**：
   - ✗ 用 `twenty` 计数器记录 20 元钞票数量，浪费了一个变量
   - ✓ 不需要跟踪 20 元，因为找零永远用不到它

4. **贪心顺序搞反**：
   - ✗ 20 元找零时先尝试 5+5+5，再尝试 10+5 — 会导致 5 元被过度消耗
   - ✓ 必须先尝试 10+5，保留尽可能多的 5 元钞票

## 面试追问

**Q1: 为什么贪心策略（优先用 10 元找零）是正确的？能否严格证明？**

> 5 元钞票能找 10 元和 20 元两种场景的零，而 10 元钞票只能在 20 元场景中使用。当我们能用 10+5 替代 5+5+5 时，净效果是少用了两张 5 元，多用了一张 10 元。10 元在未来的唯一用途就是配合 5 元找 20 元的零 — 如果不在当前用掉，它以后也只能在同样场景用（或者根本用不上）。所以提前用掉 10 元不会更差，反而保留了更灵活的 5 元。这是一个**交换论证（exchange argument）**：把任何"先用三张 5 元"的策略换成"用 10+5"，结果不会变差。

**Q2: 如果柠檬水涨价到 10 元，顾客可能付 10/20/50 元，怎么改？**

> 同样的贪心思路，但需要维护更多面值的计数器。找零时从大面值开始尝试（贪心地优先用大面值找零），因为大面值更"专用"，小面值更"通用"。

**Q3: 如果顾客可以用任意面值（不只是 5/10/20），怎么判断能否找零？**

> 这变成了一个一般性的"硬币找零可行性"问题。对于每个顾客，需要判断手头的零钱能否凑出找零金额。一般情况下可能需要动态规划或回溯。但如果面值有限且固定，贪心策略（优先用大面值）在很多场景下仍然有效。
