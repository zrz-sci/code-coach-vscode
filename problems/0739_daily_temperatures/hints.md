# 739. 每日温度

## 核心思路

本质上在问：**对于数组中每个元素，找到右边第一个比它大的元素的距离**。这是经典的"下一个更大元素"（Next Greater Element）问题。

## 思维链

1. **读完题第一反应**：对每一天，往右扫描找到第一个更高温度 → 暴力双循环 O(n²)。
2. **暴力解的瓶颈在哪？**：每个元素都要向右扫描，大量重复比较。比如 `[71, 69, 72]`，71 和 69 都在找右边更大的，但 72 出现时其实可以同时解决这两个的等待。
3. **关键观察**：如果我从左到右遍历，遇到一个较高温度时，它能"一次性结算"所有之前还没找到答案且比它小的天。哪些天在"等待"？就是那些温度递减排列的天——因为如果中间有更高的，早就被结算了。
4. **什么数据结构维护"等待队列"？**：需要后进先出（最近的未结算天先检查），且维护递减顺序 → **单调递减栈**。
5. **核心逻辑**：遍历每天，如果当前温度 > 栈顶温度，说明栈顶那天找到了答案，弹出并计算天数差；重复直到栈为空或栈顶更大；然后当前天入栈等待。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力双循环 | 每天向右扫描第一个更大值 | O(n²) | O(1) | 能说出即可 |
| 单调栈 | 维护递减栈，遇到更大值时结算 | O(n) | O(n) | ⭐ 必须写出 |
| 反向遍历+跳跃 | 利用已算好的 answer 跳跃 | O(n) | O(1)* | 加分项 |

> *反向跳跃法的辅助空间 O(1)（answer 数组不算额外空间），但思路不如单调栈直观。

## 关键提示

1. **想想栈里存什么**：存索引还是存温度值？存索引，因为你既需要温度值来比较，又需要索引来算距离。
2. **栈的单调性**：栈从底到顶是递减的。为什么？因为如果新来一个比栈顶大的，栈顶就该被结算弹出了。
3. **每个元素最多入栈出栈各一次**：所以总操作次数是 O(2n) = O(n)，不是嵌套的 O(n²)。
4. **ASCII 示意图 — 单调栈处理过程**：
```
temperatures: [73, 74, 75, 71, 69, 72, 76, 73]
索引:          0   1   2   3   4   5   6   7

Step0: 栈=[]，73 入栈 → 栈=[0(73)]
Step1: 74>73，弹出0，ans[0]=1-0=1 → 栈=[]，74入栈 → 栈=[1(74)]
Step2: 75>74，弹出1，ans[1]=2-1=1 → 栈=[]，75入栈 → 栈=[2(75)]
Step3: 71<75，入栈 → 栈=[2(75), 3(71)]
Step4: 69<71，入栈 → 栈=[2(75), 3(71), 4(69)]
Step5: 72>69，弹出4，ans[4]=5-4=1
       72>71，弹出3，ans[3]=5-3=2
       72<75，停。72入栈 → 栈=[2(75), 5(72)]
Step6: 76>72，弹出5，ans[5]=6-5=1
       76>75，弹出2，ans[2]=6-2=4
       栈空。76入栈 → 栈=[6(76)]
Step7: 73<76，入栈 → 栈=[6(76), 7(73)]
遍历结束，栈中剩余 [6,7] → ans[6]=0, ans[7]=0

结果: [1, 1, 4, 2, 1, 1, 0, 0] ✓
```

5. **遍历结束后栈中剩余的元素**：它们右边没有更大值，answer 保持初始值 0 即可。

## 解法详解

### 解法1: 暴力双循环 — O(n²) / O(1)

**思考过程**：最直觉的做法——对于每一天 i，从 i+1 开始向右扫描，找到第一个 `temperatures[j] > temperatures[i]` 就记录 `j - i`。

```cpp
class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& temperatures) {
        int n = temperatures.size();
        vector<int> answer(n, 0);
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                if (temperatures[j] > temperatures[i]) {
                    answer[i] = j - i;
                    break;  // 找到第一个就停
                }
            }
        }
        return answer;
    }
};
```

**关键点**：
- 最坏情况（递减数组如 `[100, 99, 98, ...]`），每个元素都要扫到末尾，O(n²)。
- 对于 n = 10⁵，约 10¹⁰ 次操作，会超时。
- 瓶颈：每个元素独立扫描，没有利用之前的比较结果。

### 解法2: 单调递减栈 — O(n) / O(n) ⭐ 面试首选

**从解法1优化**：暴力法的瓶颈是"每个元素重复向右扫描"。观察到：如果我们维护一个"还没找到答案"的等待列表，当遇到一个较高温度时，可以一次性结算所有比它小的等待天。这个等待列表天然是递减的（否则中间早被结算），用栈来维护。

```cpp
class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& temperatures) {
        int n = temperatures.size();
        vector<int> answer(n, 0);
        stack<int> stk;  // 存索引，栈底到栈顶对应温度递减
        
        for (int i = 0; i < n; i++) {
            // 当前温度比栈顶高 → 栈顶找到了答案
            while (!stk.empty() && temperatures[i] > temperatures[stk.top()]) {
                int prevDay = stk.top();
                stk.pop();
                answer[prevDay] = i - prevDay;  // 距离 = 当前索引 - 等待天的索引
            }
            stk.push(i);  // 当前天入栈，等待未来更高温度
        }
        // 栈中剩余元素的 answer 保持 0（没有更高温度）
        return answer;
    }
};
```

**为什么是 O(n)？** 虽然有 while 循环嵌套在 for 里，但每个元素最多入栈一次、出栈一次，总操作 ≤ 2n。

### 解法3: 反向遍历 + 跳跃优化 — O(n) / O(1)

**不同视角**：从右往左遍历。对于第 i 天，利用已经计算好的 answer 数组来"跳跃"寻找。如果第 i+1 天温度不够高，直接跳到第 `i+1+answer[i+1]` 天（因为 i+1 到那之间的温度都不比 i+1 高，自然也不比 i 高）。

```cpp
class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& temperatures) {
        int n = temperatures.size();
        vector<int> answer(n, 0);
        
        // 从倒数第二天开始，最后一天答案一定是 0
        for (int i = n - 2; i >= 0; i--) {
            int j = i + 1;
            while (j < n) {
                if (temperatures[j] > temperatures[i]) {
                    answer[i] = j - i;  // 找到了
                    break;
                } else if (answer[j] == 0) {
                    // j 右边没有更高温度了 → i 右边也没有
                    answer[i] = 0;
                    break;
                } else {
                    // 跳跃：j 到 j+answer[j] 之间没有比 j 更高的
                    // 既然 temperatures[j] <= temperatures[i]，
                    // 那这段区间也不可能比 i 高，直接跳过
                    j += answer[j];
                }
            }
        }
        return answer;
    }
};
```

**关键点**：时间复杂度分析较复杂，均摊 O(n)。空间上不需要栈，只用 answer 数组本身。但思路不如单调栈直观，面试中优先讲解法2。

## 解法对比

|  | 暴力双循环 | 单调栈 ⭐ | 反向跳跃 |
|--|-----------|----------|---------|
| 时间 | O(n²) | O(n) | O(n) 均摊 |
| 空间 | O(1) | O(n) | O(1)* |
| 直觉性 | ★★★ | ★★☆ | ★☆☆ |
| 面试推荐 | 开场说明理解 | **首选** | 追问时提及 |

> *answer 数组是返回值，不算额外空间。

- **暴力 → 单调栈**：关键优化是"用栈批量结算"代替"每个元素独立扫描"。
- **单调栈 vs 反向跳跃**：单调栈是正向思维（遇到更大的结算等待者），反向跳跃是反向思维（利用已有答案跳过无效区间）。

## 易错点

1. **栈里存值而不是索引**
   - ✗ `stk.push(temperatures[i])` → 算距离时没有索引信息
   - ✓ `stk.push(i)` → 通过 `temperatures[stk.top()]` 获取温度，通过 `i - stk.top()` 算距离

2. **比较条件用 >= 而不是 >**
   - ✗ `temperatures[i] >= temperatures[stk.top()]` → 相等温度不算"更高"，会错误结算
   - ✓ `temperatures[i] > temperatures[stk.top()]` → 严格大于才结算

3. **忘记处理栈中剩余元素**
   - 其实不需要额外处理，因为 `answer` 初始化为全 0，剩余元素天然就是 0。但如果初始化不是 0 就会出错。

4. **反向跳跃法中 `answer[j] == 0` 的判断遗漏**
   - ✗ 没有判断 `answer[j] == 0`，导致 `j += 0` 死循环
   - ✓ `answer[j] == 0` 意味着 j 右边没有更高的，此时 i 也找不到，直接 break

## 面试追问

**Q1（基础理解）**: "暴力法的时间复杂度是多少？瓶颈在哪？"
→ O(n²)，瓶颈在每个元素独立向右扫描，无法复用之前的比较结果。

**Q2（核心优化）**: "单调栈为什么能做到 O(n)？while 嵌套在 for 里不是 O(n²) 吗？"
→ 每个元素最多入栈一次出栈一次，总操作 ≤ 2n。这是**均摊分析**，不能看嵌套层数。

**Q3（变体追问）**: "如果要求的是右边第一个更小的温度呢？"
→ 改成单调递增栈（栈底到栈顶递增），当前温度 < 栈顶时结算。模板相同，只改比较方向。

**Q4（空间优化）**: "能否不用栈，O(1) 额外空间？"
→ 反向遍历 + 跳跃法（解法3），利用已计算的 answer 数组做跳跃，不需要栈。
