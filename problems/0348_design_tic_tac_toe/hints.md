# 348. 设计井字棋

## 核心思路

本质上是一个**增量计数问题**：每次落子后，不需要扫描整个棋盘来判断胜负，只需要检查落子所在的行、列、对角线是否已经被同一个玩家填满。关键洞察是——我们可以用计数器代替棋盘扫描。

## 思维链

1. **读完题第一反应**：每次 `move()` 后，检查整个棋盘，看是否有某行/某列/某对角线全是同一个玩家的棋子 → 暴力模拟。

2. **暴力解的瓶颈在哪？** 每次 `move()` 都要扫描整行（O(n)）、整列（O(n)）、两条对角线（O(n)），总共 O(n)。能不能更快？其实暴力扫描棋盘是 O(n²) 的（检查所有行列），优化到只检查落子所在的行/列/对角线就是 O(n) 了。但题目 Follow-up 问能不能比 O(n²) 更快——实际上能做到 O(1)！

3. **关键洞察**：判断一行是否全是玩家1的棋子，等价于判断"玩家1在该行放了n个棋子"。我们不需要每次重新数，只需要**维护一个计数器，每次落子时+1**，当计数器达到 n 时就赢了。

4. **两个玩家怎么处理？** 巧妙方法：玩家1落子时 +1，玩家2落子时 -1。当某个计数器的绝对值等于 n 时，说明有人赢了（+n 是玩家1赢，-n 是玩家2赢）。

5. **需要哪些计数器？** n 个行计数器 + n 个列计数器 + 1 个主对角线计数器 + 1 个副对角线计数器，共 2n+2 个。

6. **每次 move 只需 O(1)**：更新所在行的计数器、所在列的计数器，如果在对角线上再更新对角线计数器，然后检查是否等于 ±n。

## 解法概览

| 解法 | 思路 | move()时间 | 空间 | 面试 |
|------|------|------------|------|------|
| 暴力模拟 | 存储棋盘，每次扫描行/列/对角线 | O(n) | O(n²) | 能说出即可 |
| 计数器优化 | 行/列/对角线计数，+1/-1 技巧 | O(1) | O(n) | ⭐ 必须写出 |

## 关键提示

1. **你不需要存储整个棋盘**。想想：判断一行是否全是同一玩家的棋子，真的需要知道每个格子是什么吗？还是只需要知道"这一行有几个该玩家的棋子"？

2. **+1/-1 技巧**：两个玩家可以共用同一套计数器。玩家1加，玩家2减。计数器达到 +n 说明玩家1赢，达到 -n 说明玩家2赢。这样计数器数量减半。

3. **对角线的判断条件**：主对角线上的格子满足 `row == col`，副对角线上的格子满足 `row + col == n - 1`。不是每个格子都在对角线上，所以要加 if 判断。

4. 示意图——一个 3×3 棋盘上各计数器的作用范围：

```
         col0  col1  col2
          ↓     ↓     ↓
row0 →  [0,0] [0,1] [0,2]  ↘ diag(主对角线: row==col)
row1 →  [1,0] [1,1] [1,2]
row2 →  [2,0] [2,1] [2,2]  ↗ anti_diag(副对角线: row+col==n-1)

落子 (1,1): 更新 row[1], col[1], diag, anti_diag（因为1==1且1+1==2==n-1）
落子 (0,2): 更新 row[0], col[2], anti_diag（因为0+2==2==n-1，但0≠2所以不更新diag）
```

## 解法详解

### 解法1: 暴力模拟 — O(n) per move / O(n²) 空间

**思考过程**：最直觉的做法——把棋盘存下来，每次落子后检查该行、该列、两条对角线是否有 n 个连续相同棋子。

```cpp
class TicTacToe {
    vector<vector<int>> board;
    int n;
public:
    TicTacToe(int n) : board(n, vector<int>(n, 0)), n(n) {}
    
    int move(int row, int col, int player) {
        board[row][col] = player;
        
        // 检查第 row 行
        bool win = true;
        for (int j = 0; j < n; j++) {
            if (board[row][j] != player) { win = false; break; }
        }
        if (win) return player;
        
        // 检查第 col 列
        win = true;
        for (int i = 0; i < n; i++) {
            if (board[i][col] != player) { win = false; break; }
        }
        if (win) return player;
        
        // 检查主对角线 (仅当 row == col 时有必要)
        if (row == col) {
            win = true;
            for (int i = 0; i < n; i++) {
                if (board[i][i] != player) { win = false; break; }
            }
            if (win) return player;
        }
        
        // 检查副对角线 (仅当 row + col == n - 1 时有必要)
        if (row + col == n - 1) {
            win = true;
            for (int i = 0; i < n; i++) {
                if (board[i][n - 1 - i] != player) { win = false; break; }
            }
            if (win) return player;
        }
        
        return 0;
    }
};
```

**关键点**：虽然我们只检查落子相关的行/列/对角线（而不是全盘扫描），但每次仍需遍历长度为 n 的行/列，所以是 O(n)。

### 解法2: 行列对角线计数器 — O(1) per move / O(n) 空间 ⭐ 面试首选

**从解法1优化**：解法1的瓶颈是每次要遍历一整行/列来判断是否全是同一玩家。既然我们只关心"某行有几个该玩家的棋子"，那就直接维护计数器，每次 O(1) 更新和判断。

**+1/-1 技巧**：玩家1落子时给计数器 +1，玩家2落子时给计数器 -1。这样两个玩家共用一套计数器：
- 计数器 = +n → 玩家1在这条线上放满了 → 玩家1赢
- 计数器 = -n → 玩家2在这条线上放满了 → 玩家2赢
- 不可能出现 +n 或 -n 以外的"满"情况，因为一旦某行有两个不同玩家的棋子，计数器的绝对值就不可能达到 n

```cpp
class TicTacToe {
    vector<int> rows, cols;  // rows[i]: 第i行的计数, cols[j]: 第j列的计数
    int diag, anti_diag;     // 主对角线和副对角线的计数
    int n;
public:
    TicTacToe(int n) : rows(n, 0), cols(n, 0), diag(0), anti_diag(0), n(n) {}
    
    int move(int row, int col, int player) {
        // 玩家1 → +1, 玩家2 → -1
        int delta = (player == 1) ? 1 : -1;
        
        rows[row] += delta;
        cols[col] += delta;
        
        // 仅当落子在主对角线上时才更新
        if (row == col) diag += delta;
        
        // 仅当落子在副对角线上时才更新
        if (row + col == n - 1) anti_diag += delta;
        
        // 任一计数器绝对值达到 n → 有人赢了
        if (abs(rows[row]) == n || abs(cols[col]) == n ||
            abs(diag) == n || abs(anti_diag) == n) {
            return player;
        }
        
        return 0;
    }
};
```

**为什么 +1/-1 不会出错？** 因为题目保证每个格子只落一次子且两人交替，所以同一行不可能出现"玩家1放了n个"和"玩家2也放了n个"的矛盾。当计数器绝对值为n时，一定是某个玩家独占了这条线。

## 解法对比

| | 解法1: 暴力模拟 | 解法2: 计数器 |
|---|---|---|
| move() 时间 | O(n) | **O(1)** |
| 空间 | O(n²)（存棋盘） | **O(n)**（2n+2个计数器） |
| 代码复杂度 | 简单但冗长 | 简洁优雅 |
| 面试表现 | 说明理解题意 | 展示优化能力 |
| 适用场景 | 需要回溯/展示棋盘时 | 只需判断胜负 |

解法2 是面试必须给出的答案。面试官问 Follow-up "能否比 O(n) 更快" 时，直接切到解法2 的 O(1) 方案。

## 易错点

1. **对角线判断条件写反或遗漏**
   - ✗ 只写了 `if (row == col)` 而忘了副对角线 `if (row + col == n - 1)`
   - ✗ 把副对角线条件写成 `row - col == n - 1`
   - ✓ 主对角线：`row == col`；副对角线：`row + col == n - 1`

2. **中心格子同时在两条对角线上**
   - 当 n 为奇数时，中心格 (n/2, n/2) 满足 `row == col` 且 `row + col == n - 1`
   - ✗ 用 `else if` 连接两个对角线判断 → 只更新了一条
   - ✓ 两个 `if` 独立判断，不要用 `else if`

3. **+1/-1 方向搞反**
   - ✗ `int delta = player;`（玩家2的 delta 是 2 而不是 -1）
   - ✓ `int delta = (player == 1) ? 1 : -1;`

4. **返回值搞混**
   - ✗ 返回 1 或 -1 表示谁赢了
   - ✓ 返回 `player`（题目要求返回赢家编号 1 或 2）

## 面试追问

**Q1: 暴力解每次 move 的复杂度是多少？瓶颈在哪？**
→ O(n)，瓶颈在每次要遍历整行/整列/对角线来判断是否全部相同。但其实我们只需要"计数"。

**Q2: 怎么做到 O(1)？两个玩家怎么共用计数器？**
→ 用 +1/-1 技巧。玩家1加1、玩家2减1，计数器绝对值达到 n 就有赢家。两人的棋子会互相"抵消"，所以只有某人独占一条线时才能达到 ±n。

**Q3: 如果需要支持"撤销上一步"操作 (undo)，怎么改？**
→ 解法2 天然支持：记录上一步的 (row, col, player)，undo 时对 rows[row]、cols[col] 做反向操作（delta 取反）。如果需要支持多步撤销，用一个栈存历史操作。

**Q4: 如果棋盘不是 n×n 而是 m×n 矩形，获胜条件是连续 k 个，怎么做？**
→ 此时计数器方法不直接适用（因为不是"一整行都是同一玩家"），需要回到每次 O(k) 检查落子位置四个方向上的连续相同棋子数，类似五子棋判断逻辑。
