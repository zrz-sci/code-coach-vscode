# 26. 删除有序数组中的重复项

## 核心思路

数组已排序，所以相同元素一定相邻。本质上就是：**用一个慢指针标记"去重后数组的末尾"，用一个快指针扫描原数组，遇到新值就往前搬。**

## 思维链

1. **读完题第一反应**：要"原地"删除重复元素 → 不能新建数组，只能在原数组上操作。最朴素的想法：遇到重复就把后面的元素全部前移，但这样每次删除都要搬 O(n) 个元素。

2. **暴力解的瓶颈**：每发现一个重复元素就做一次数组搬移，最坏情况（如全是重复）搬移次数是 O(n²)。瓶颈在于"每次只前移一步"。

3. **关键观察**：数组是有序的！相同元素一定挨在一起。我们不需要"删除"重复元素，只需要**把不重复的元素"覆盖"到前面**就行了。后面的垃圾数据不用管。

4. **怎么做**：用两个指针 —— `slow` 指向去重后数组的最后一个有效位置，`fast` 往前扫描。当 `nums[fast] != nums[slow]` 时，说明遇到了新值，把它放到 `slow+1` 的位置。

5. **为什么正确**：`slow` 左边（含 `slow`）的部分始终是去重后的有序序列。`fast` 跳过的都是和 `nums[slow]` 相同的重复值。最终 `slow + 1` 就是去重后的长度。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力搬移 | 遇到重复就把后面元素全部前移 | O(n²) | O(1) | 能说出即可 |
| 快慢双指针 | slow 标记写入位置，fast 扫描新值 | O(n) | O(1) | ⭐ 必须写出 |

## 关键提示

1. **数组有序**意味着什么？ → 重复元素一定连续出现，不需要哈希表判重。
2. 不要真的"删除"元素 —— 想象你在**构建一个新数组**，只不过这个新数组和原数组共用同一片内存，写入位置由 `slow` 控制。
3. `slow` 指针有两种风格：指向"最后一个有效元素"或"下一个要写入的位置"，两种都行，但初始值和返回值不同，别搞混。
4. 边界情况：空数组？只有一个元素？全部相同？全部不同？ —— 双指针解法天然处理这些情况。

```
// 双指针运行示意 (nums = [0,0,1,1,1,2,2,3,3,4]):
//
// 初始:  s
//        [0, 0, 1, 1, 1, 2, 2, 3, 3, 4]
//         f
//
// f=1:   nums[1]=0 == nums[s]=0 → 跳过
//        s
//        [0, 0, 1, 1, 1, 2, 2, 3, 3, 4]
//            f
//
// f=2:   nums[2]=1 != nums[s]=0 → s++, 写入
//           s
//        [0, 1, 1, 1, 1, 2, 2, 3, 3, 4]
//               f
//
// f=3:   nums[3]=1 == nums[s]=1 → 跳过
// f=4:   nums[4]=1 == nums[s]=1 → 跳过
//
// f=5:   nums[5]=2 != nums[s]=1 → s++, 写入
//              s
//        [0, 1, 2, 1, 1, 2, 2, 3, 3, 4]
//                        f
//
// f=6:   跳过 (2==2)
// f=7:   nums[7]=3 != nums[s]=2 → s++, 写入
//                 s
//        [0, 1, 2, 3, 1, 2, 2, 3, 3, 4]
//                              f
//
// f=8:   跳过 (3==3)
// f=9:   nums[9]=4 != nums[s]=3 → s++, 写入
//                    s
//        [0, 1, 2, 3, 4, 2, 2, 3, 3, 4]
//                                    f
//
// 结束: 返回 s+1 = 5
// 前5个元素: [0, 1, 2, 3, 4] ✓
```

## 解法详解

### 解法1: 暴力搬移 — O(n²) / O(1)

**思考过程**：最直觉的做法 —— 从前往后扫描，一旦发现 `nums[i] == nums[i-1]`，就把 `i` 后面的所有元素前移一位，数组长度减1。重复直到没有相邻重复。

```cpp
class Solution {
public:
    int removeDuplicates(vector<int>& nums) {
        int n = nums.size();
        // 从第二个元素开始检查
        for (int i = 1; i < n; ) {
            if (nums[i] == nums[i - 1]) {
                // 把 i 后面的元素全部前移一位（模拟"删除"）
                for (int j = i; j < n - 1; j++) {
                    nums[j] = nums[j + 1];
                }
                n--;  // 有效长度减1
                // 注意：i 不动，因为新的 nums[i] 可能还是重复的
            } else {
                i++;
            }
        }
        return n;
    }
};
```

**关键点**：
- 删除后 `i` 不能 `i++`，因为前移后当前位置是新元素，可能还是重复的。
- 时间 O(n²)：最坏情况（如 [1,1,1,...,1]），每删一个都要搬 O(n) 个元素，总共删 n-1 次。
- 这个解法让你理解题目要求，但面试中不会用它。

### 解法2: 快慢双指针 — O(n) / O(1) ⭐ 面试首选

**从解法1优化**：暴力解的瓶颈是"每次删除都要搬移整个数组"。核心洞察：我们不需要"删除"重复元素，只需要**把不重复的元素依次覆盖到前面**。用 `slow` 记住写入位置，`fast` 负责找到下一个不同的值。

```cpp
class Solution {
public:
    int removeDuplicates(vector<int>& nums) {
        if (nums.empty()) return 0;
        
        // slow: 指向去重后数组的最后一个有效位置
        int slow = 0;
        
        // fast: 从第二个元素开始扫描
        for (int fast = 1; fast < (int)nums.size(); fast++) {
            // 发现新值（和 slow 位置的值不同）
            if (nums[fast] != nums[slow]) {
                slow++;                    // 写入位置后移
                nums[slow] = nums[fast];   // 把新值覆盖到 slow 位置
            }
            // 如果相同，fast 继续前进，slow 不动（跳过重复）
        }
        
        // slow 是最后一个有效元素的下标，长度 = slow + 1
        return slow + 1;
    }
};
```

**关键点**：
- `slow` 始终指向"已去重部分的最后一个元素"，所以写入时先 `slow++` 再赋值。
- 只需一次遍历，每个元素最多被读一次、写一次 → O(n)。
- `nums[fast] != nums[slow]` 利用了数组有序的性质：相同元素一定连续，所以只需和 `slow` 比较。

## 解法对比

| | 暴力搬移 | 快慢双指针 |
|---|---|---|
| 时间 | O(n²) | O(n) |
| 空间 | O(1) | O(1) |
| 核心思想 | 真的"删除"元素并搬移 | 用覆盖代替删除 |
| 适用场景 | 理解题意 | **面试和实战唯一选择** |

**本质区别**：暴力解在"删除"，双指针在"构建" —— 与其费力删掉不要的，不如只保留需要的。

## 易错点

1. **返回值搞错**：
   - ✗ `return slow;` — slow 是下标，不是长度
   - ✓ `return slow + 1;` — 下标从0开始，长度 = 最后下标 + 1

2. **空数组没处理**：
   - ✗ 直接 `int slow = 0; for (int fast = 1; ...)` — 如果 `nums` 为空，`slow + 1 = 1` 是错误的
   - ✓ 先判断 `if (nums.empty()) return 0;`
   - （注意：题目约束 `nums.length >= 1`，所以本题其实不会空，但好习惯要有）

3. **写入顺序错**：
   - ✗ `nums[slow] = nums[fast]; slow++;` — 先覆盖再移动，会覆盖掉 slow 位置本来的有效值
   - ✓ `slow++; nums[slow] = nums[fast];` — 先移动再覆盖
   - （当 slow 和 fast 相邻且值不同时，错误写法会导致 slow 位置被覆盖两次）

4. **和"下一个写入位置"风格搞混**：
   - 另一种写法 `slow` 从0开始代表"下一个要写入的位置"，此时用 `nums[slow++] = nums[fast]`，返回 `slow`。两种风格都正确，但别混用。

## 面试追问

**Q1: 这道题如果数组无序怎么办？**
→ 无序数组不能用双指针直接比较相邻元素。两种方案：
- 先排序 O(n log n)，再用本题的双指针。
- 用哈希集合 O(n) 空间记录已出现的值，但不保证顺序。
→ 具体选哪个取决于是否需要保持原始相对顺序。

**Q2: 如果要求每个元素最多出现两次呢？（LeetCode 80）**
→ 核心框架不变！只需把比较对象从 `nums[slow]` 改为 `nums[slow - 1]`（允许和前一个相同，但不允许和前两个相同）。具体见 LeetCode 80。

**Q3: 如果返回去重后的数组（新数组），允许用额外空间呢？**
→ 更简单：遍历原数组，遇到新值就 push_back 到结果数组。但这道题的考点就是原地操作，面试官问这个是想确认你理解"原地"的含义。
