# 841. 钥匙和房间 (Keys and Rooms)

## 难度: Medium | 标签: Depth-First Search, Breadth-First Search, Graph

---

## 题目理解

有 `n` 个房间，编号 0 到 n-1。除了 0 号房间，其余都**上锁**。
每个房间里有若干**钥匙**，钥匙上的数字表示能打开的房间号。
从 0 号出发，判断能否**访问所有房间**。

**本质**: 这是一个**有向图的可达性**问题。
- 节点 = 房间
- 边 = 钥匙 (从房间 i 指向 rooms[i] 中的每个房间)
- 问题: 从节点 0 出发，能否到达所有节点？

---

## 思维链 -- 从问题映射到图论

### Step 1: 建模为图

```
rooms = [[1],[2],[3],[]]

房间 0 有钥匙 [1]  ->  0 -> 1
房间 1 有钥匙 [2]  ->  1 -> 2
房间 2 有钥匙 [3]  ->  2 -> 3
房间 3 有钥匙 []   ->  (无出边)

有向图:  0 -> 1 -> 2 -> 3
```

从 0 出发能到达 {0, 1, 2, 3} = 全部 4 个房间 -> `true`

### Step 2: 选择遍历方式

既然是图的可达性，DFS 或 BFS 都行:
- **DFS**: 递归或用栈，深入探索每条路径
- **BFS**: 用队列，逐层扩展

两者都能遍历从 0 出发能到达的所有节点。

### Step 3: 判定条件

遍历结束后，统计已访问的房间数:
- 等于 n -> 返回 `true`
- 小于 n -> 返回 `false`

---

## DFS 过程详细演示

### 示例 1: `rooms = [[1],[2],[3],[]]` -> true

```
初始状态:
  visited = [T, F, F, F]  (0号房间已进入)
  手中钥匙: 从房间0获得 {1}

DFS调用栈演示:

dfs(0)
  visited[0] = true
  房间0的钥匙: [1]
  |
  +-- 钥匙1: visited[1]=false, 进入房间1
      dfs(1)
        visited[1] = true
        房间1的钥匙: [2]
        |
        +-- 钥匙2: visited[2]=false, 进入房间2
            dfs(2)
              visited[2] = true
              房间2的钥匙: [3]
              |
              +-- 钥匙3: visited[3]=false, 进入房间3
                  dfs(3)
                    visited[3] = true
                    房间3的钥匙: [] (空)
                    返回
              返回
        返回
  返回

最终 visited = [T, T, T, T]  ->  全部访问  ->  true
```

### 示例 2: `rooms = [[1,3],[3,0,1],[2],[0]]` -> false

```
图结构:
  0 -> 1, 3
  1 -> 3, 0, 1
  2 -> 2         (自环, 但谁来开门?)
  3 -> 0

观察: 没有任何从 {0,1,3} 到 2 的边!

DFS调用栈演示:

dfs(0)
  visited = [T, F, F, F]
  钥匙: [1, 3]
  |
  +-- 钥匙1: visited[1]=false
      dfs(1)
        visited = [T, T, F, F]
        钥匙: [3, 0, 1]
        |
        +-- 钥匙3: visited[3]=false
            dfs(3)
              visited = [T, T, F, T]
              钥匙: [0]
              |
              +-- 钥匙0: visited[0]=true, 跳过 (已访问!)
              返回
        +-- 钥匙0: visited[0]=true, 跳过
        +-- 钥匙1: visited[1]=true, 跳过
        返回
  +-- 钥匙3: visited[3]=true, 跳过
  返回

最终 visited = [T, T, F, T]
房间 2 未访问!  ->  false

原因: 钥匙 2 只在房间 2 里, 但进不了房间 2 -> 死锁!
```

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 推荐 |
|------|------|------|------|------|
| DFS (递归) | 深度优先遍历可达房间 | O(n + E) | O(n) 栈 | 最直观 |
| DFS (迭代栈) | 用显式栈替代递归 | O(n + E) | O(n) | 防栈溢出 |
| BFS (队列) | 广度优先遍历可达房间 | O(n + E) | O(n) | 经典 BFS |

其中 E = sum(rooms[i].length) <= 3000，即总钥匙数 (图的总边数)。

---

## 为什么 DFS/BFS 不会漏掉节点？

关键保证: **从 0 出发可达的节点 = DFS/BFS 遍历到的节点**。

这是图论的基本定理。只要:
1. 起点正确 (从 0 开始)
2. 每个节点的所有出边都被探索 (遍历 rooms[i] 的每把钥匙)
3. 不重复访问 (visited 数组)

就能找到从 0 可达的**全部**节点。

---

## 关键细节与易错点

### 1. 邻接表已经给好了
`rooms[i]` 就是节点 `i` 的邻居列表，不需要额外建图。

### 2. 钥匙可以重复使用
虽然题目说 "each key has a number on it"，但这不影响算法。
`visited` 数组保证每个房间只处理一次。

### 3. 自环无害
如果 rooms[i] 包含 i (有指向自己的钥匙)，visited 检查会跳过，不会死循环。

### 4. 统计方式
可以用 `count` 函数统计 visited 中 true 的个数:
```cpp
return count(visited.begin(), visited.end(), true) == n;
```
或者用一个计数器在 DFS/BFS 过程中累加。

### 5. 空间考虑
- DFS 递归: 最坏 O(n) 栈深度 (链状图)
- n <= 1000，不会栈溢出
- 但如果 n 很大，用迭代 DFS 或 BFS 更安全

---

## DFS vs BFS 的选择

| 维度 | DFS | BFS |
|------|-----|-----|
| 实现 | 递归 3 行 / 栈 | 队列 |
| 空间 | O(n) 栈深度 | O(n) 队列 |
| 顺序 | 深入一条路走到底 | 逐层扩展 |
| 适用 | 本题两者等价 | 本题两者等价 |
| 面试偏好 | 代码最短 | 更好控制 |

**本题两者完全等价**，因为我们只关心"能否到达全部节点"，不关心到达顺序或最短路径。

---

## 复杂度分析

- **时间**: O(n + E)
  - n = 房间数 (节点数)
  - E = 总钥匙数 (边数) = sum(rooms[i].length) <= 3000
  - 每个房间最多访问一次，每把钥匙最多检查一次

- **空间**: O(n)
  - visited 数组: O(n)
  - DFS 栈 / BFS 队列: 最坏 O(n)

## 图的可达性的本质

```
这道题的核心模型:

  有向图 + 单源可达性

  给定有向图 G 和起点 s, 判断从 s 出发能否到达所有节点。

  等价问题:
  - 从 s 出发的 DFS/BFS 连通分量是否等于整个图
  - 从 s 到每个节点是否存在有向路径
```

## 面试追问

1. **"DFS 和 BFS 哪个更好?"** → 本题两者完全等价，因为只关心"能否到达全部节点"，不关心顺序或最短路径。DFS 代码更短，BFS 更好控制层次。
2. **"如果问最少开门次数到达所有房间?"** → BFS 分层，层数 = 最远房间距离。若边权不同 (开门有代价)，需要 Dijkstra。
3. **"如何输出哪些房间不可达?"** → 遍历结束后，收集所有 `visited[i] == false` 的房间编号。
4. **"如果初始有多把钥匙?"** → 多个起点的 DFS/BFS (类似多源 BFS)，一开始就把所有初始可进入的房间入栈/入队。

## 变体问题联想

1. **如果初始有多把钥匙?** -> 多个起点的 DFS/BFS (类似多源 BFS)。
2. **如果要求最少步数到达所有房间?** -> BFS 分层 + 状态压缩 (像旅行商)。
3. **如果钥匙有数量限制?** -> 资源约束搜索，更复杂。
