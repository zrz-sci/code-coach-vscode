# 1200. 最小绝对差

## 核心思路

本题本质上在问：在数组中找到差值最小的所有"相邻元素对"——这里的"相邻"是指**排序后**的相邻。

## 思维链

1. **读完题第一反应**：要找所有绝对差最小的元素对。最朴素的做法是枚举所有两两配对，算绝对差，找最小值，再收集所有等于最小值的对。→ O(n²)

2. **暴力解的瓶颈**：枚举所有 C(n,2) 个对太多了。但思考一下——最小绝对差一定出现在"数值上最接近"的两个元素之间。随便举个例子：`[1, 5, 100]`，最小差一定是 `5-1=4`，不可能是 `100-1` 或 `100-5`。

3. **关键观察**：如果数组排好序，那么最小绝对差一定出现在**排序后相邻的两个元素**之间。为什么？因为对于任意 `arr[i] < arr[j] < arr[k]`，`arr[k] - arr[i] > arr[j] - arr[i]`，所以跨过中间元素的差一定更大。

4. **算法成型**：排序 → 遍历相邻对找最小差 → 再遍历一次收集所有等于最小差的对。甚至可以一次遍历搞定。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举所有 C(n,2) 对 | O(n²) | O(1) | 能说出即可 |
| 排序 + 两次遍历 | 排序后只看相邻对，先找最小差再收集 | O(n log n) | O(1)* | ⭐ 必须写出 |
| 排序 + 一次遍历 | 排序后一次遍历，边找最小差边收集 | O(n log n) | O(1)* | 加分项 |

> *不计输出空间

## 关键提示

1. **最小绝对差只可能出现在排序后相邻元素之间** — 这是最核心的观察。想想为什么"隔一个"的差一定 ≥ "相邻"的差？
2. 排序后只需要看 n-1 个相邻对，而不是 n(n-1)/2 个所有对。
3. 一次遍历的技巧：当发现更小的差时，**清空**之前收集的结果；当发现相同的差时，**追加**到结果。
4. 题目保证元素**互不相同**，所以最小差一定 > 0，不需要处理相等元素。

```
排序前: [3, 8, -10, 23, 19, -4, -14, 27]
排序后: [-14, -10, -4, 3, 8, 19, 23, 27]
相邻差:    4     6   7  5  11   4   4
                                ↑   ↑
最小差 = 4，出现在 (-14,-10), (19,23), (23,27)
```

## 解法详解

### 解法1: 暴力枚举 — O(n²) / O(1)

**思考过程**: 最直觉的做法——枚举所有两两配对。第一遍找最小差，第二遍收集所有等于最小差的对。

```cpp
class Solution {
public:
    vector<vector<int>> minimumAbsDifference(vector<int>& arr) {
        int n = arr.size();
        // 第一遍：找最小绝对差
        int minDiff = INT_MAX;
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                minDiff = min(minDiff, abs(arr[i] - arr[j]));
            }
        }
        // 第二遍：收集所有等于最小差的对（要求 a < b，升序输出）
        vector<vector<int>> result;
        // 先排序，这样收集时自然满足 a < b 且按升序
        sort(arr.begin(), arr.end());
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                if (arr[j] - arr[i] == minDiff) {
                    result.push_back({arr[i], arr[j]});
                }
            }
        }
        return result;
    }
};
```

**关键点**: 暴力解能通过但效率差。更重要的是，这个暴力解暗示了优化方向——既然最后还是要排序来保证输出顺序，为什么不一开始就排序，然后利用有序性减少比较次数？

---

### 解法2: 排序 + 两次遍历 — O(n log n) / O(1) ⭐ 面试首选

**从解法1优化**: 暴力解的瓶颈是枚举了 O(n²) 个对。但排序后，最小差一定在相邻元素之间产生（因为非相邻元素的差 ≥ 相邻元素的差），所以只需看 n-1 个相邻对。

```cpp
class Solution {
public:
    vector<vector<int>> minimumAbsDifference(vector<int>& arr) {
        // 排序：让"数值相近"的元素变成"位置相邻"
        sort(arr.begin(), arr.end());
        
        int n = arr.size();
        
        // 第一遍遍历：找排序后相邻元素的最小差
        int minDiff = INT_MAX;
        for (int i = 1; i < n; i++) {
            minDiff = min(minDiff, arr[i] - arr[i - 1]);
            // 排序后 arr[i] >= arr[i-1]，所以不需要 abs()
        }
        
        // 第二遍遍历：收集所有差等于 minDiff 的相邻对
        vector<vector<int>> result;
        for (int i = 1; i < n; i++) {
            if (arr[i] - arr[i - 1] == minDiff) {
                result.push_back({arr[i - 1], arr[i]});
            }
        }
        
        return result;
    }
};
```

**关键点**: 
- 排序后 `arr[i] - arr[i-1]` 一定 ≥ 0，不需要 `abs()`
- 结果自然按升序排列，因为我们从左到右遍历排序数组

---

### 解法3: 排序 + 一次遍历 — O(n log n) / O(1)

**从解法2优化**: 两次遍历其实可以合并成一次。核心技巧：遍历时维护当前已知最小差，如果遇到更小的差就清空结果重新收集。

```cpp
class Solution {
public:
    vector<vector<int>> minimumAbsDifference(vector<int>& arr) {
        sort(arr.begin(), arr.end());
        
        vector<vector<int>> result;
        int minDiff = INT_MAX;
        
        for (int i = 1; i < (int)arr.size(); i++) {
            int diff = arr[i] - arr[i - 1];
            
            if (diff < minDiff) {
                // 发现更小的差 → 之前收集的全作废
                minDiff = diff;
                result.clear();           // 关键：清空旧结果
                result.push_back({arr[i - 1], arr[i]});
            } else if (diff == minDiff) {
                // 差相同 → 追加
                result.push_back({arr[i - 1], arr[i]});
            }
            // diff > minDiff → 跳过
        }
        
        return result;
    }
};
```

**关键点**: `result.clear()` 是这个解法的灵魂——发现更小的差时，之前收集的对全都不是最小差了，必须清空。

## 解法对比

| | 解法1 暴力 | 解法2 排序+两遍 | 解法3 排序+一遍 |
|---|---|---|---|
| 时间 | O(n²) | O(n log n) | O(n log n) |
| 空间 | O(1) | O(1) | O(1) |
| 遍历次数 | O(n²) + O(n²) | 1遍找min + 1遍收集 | 1遍搞定 |
| 代码复杂度 | 简单但慢 | 清晰直观 | 最简洁 |
| 面试推荐 | ❌ | ✅ 首选 | ✅ 加分 |

**什么时候选哪个？** 面试中直接写解法2即可，逻辑最清晰不容易出错。如果面试官问"能否一次遍历？"再优化到解法3。三者的瓶颈都是排序的 O(n log n)。

## 易错点

1. **忘记排序后不需要 abs()**
   - ✗ `abs(arr[i] - arr[i-1])` — 多余操作，虽然结果正确但暴露对排序性质的不理解
   - ✓ `arr[i] - arr[i-1]` — 排序后后者一定 ≥ 前者

2. **一次遍历时忘记 clear()**
   - ✗ 发现更小差时只更新 `minDiff` 但不清空 `result`，导致旧的"非最小差"对混入结果
   - ✓ `minDiff = diff; result.clear(); result.push_back(...);`

3. **暴力解中收集结果时没排序**
   - ✗ 直接用原始数组顺序收集，输出可能不按升序
   - ✓ 先排序再收集，或者收集后排序

4. **用 `int` 做差时溢出**
   - 本题值域 [-10⁶, 10⁶]，差最大 2×10⁶，`int` 完全够用，不会溢出
   - 但如果值域更大（如 10⁹），`arr[i] - arr[i-1]` 可能溢出，需用 `long long`

## 面试追问

**Q1: 为什么最小绝对差一定在排序后相邻元素之间？能证明吗？**

> 反证法：假设最小差出现在排序后不相邻的 `arr[i]` 和 `arr[j]`（j > i+1），那么 `arr[i] ≤ arr[i+1] ≤ arr[j]`，所以 `arr[i+1] - arr[i] ≤ arr[j] - arr[i]`。也就是说相邻对 `(arr[i], arr[i+1])` 的差更小或相等，与假设矛盾。

**Q2: 如果数组可能有重复元素呢？**

> 最小差就是 0，所有相等的相邻元素对都要收集。代码逻辑不变，因为排序后相等元素相邻，差为 0 自然是最小的。

**Q3: 如果不允许排序（要求 O(n) 时间），能做到吗？**

> 可以用计数排序/桶排序思想。值域是 [-10⁶, 10⁶]，范围 2×10⁶，可以用布尔数组标记哪些值存在，然后线性扫描这个数组找相邻存在的值之间的最小差。时间 O(n + V)，V 是值域范围。
