# 15. 三数之和

## 核心思路

本质上是 **Two Sum 的升级版**：固定一个数 `nums[i]`，在剩余元素中找两个数使它们的和等于 `-nums[i]`。难点不在于找到三元组，而在于**如何高效地去重**。

## 思维链

1. **读完题第一反应**：三重循环枚举所有 `(i, j, k)` 组合，检查 `nums[i] + nums[j] + nums[k] == 0`。时间 O(n³)，n=3000 时约 2.7×10¹⁰ 次操作，太慢。而且去重很麻烦——用 set 存三元组？排序后再去重？

2. **暴力解的瓶颈**：三重循环的内两层本质上是在做 Two Sum。Two Sum 有 O(n) 的哈希表解法，所以可以降到 O(n²)。但哈希表方案的去重逻辑很烦。

3. **关键观察——排序的威力**：如果先排序，相同的元素会**挨在一起**，去重就变成了"跳过相邻重复元素"。同时，排序后的数组具有**单调性**，可以用双指针替代哈希表来完成 Two Sum。

4. **双指针怎么用？** 排序后固定 `nums[i]`，在 `[i+1, n-1]` 范围内用左右双指针：
   - `sum < 0`：说明太小了，左指针右移（让 sum 变大）
   - `sum > 0`：说明太大了，右指针左移（让 sum 变小）
   - `sum == 0`：找到一组！记录后，两个指针都跳过重复值

5. **去重三步走**：
   - 第一层循环：`nums[i] == nums[i-1]` 时跳过（固定数去重）
   - 找到答案后：左指针跳过重复值
   - 找到答案后：右指针跳过重复值

6. **提前终止**：排序后，如果 `nums[i] > 0`，三个正数不可能和为 0，直接 break。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力三重循环 | 枚举所有三元组 + set去重 | O(n³) | O(n) | 能说出即可 |
| 哈希表 | 固定一个数，哈希表做Two Sum | O(n²) | O(n) | 能说出即可 |
| **排序 + 双指针** | 排序后固定一个数，双指针找另外两个 | **O(n²)** | **O(1)** | ⭐ 必须写出 |

## 关键提示

1. **降维思想**：三数之和 → 固定一个数 → 两数之和。这是处理 kSum 问题的通用思路。

2. **为什么排序？** 两个好处：(a) 去重变简单——相同元素挨着，跳一下就行；(b) 双指针能用——有序性保证了"太小右移、太大左移"的正确性。

3. **去重的时机很关键**：
   - 第一层循环的去重是 `i > 0 && nums[i] == nums[i-1]`，不是 `nums[i] == nums[i+1]`！后者会**漏解**（比如 `[-1, -1, 2]` 会被跳过）。
   - 双指针的去重是在**找到答案之后**跳过重复，不是在移动过程中。

4. **提前剪枝**：`nums[i] > 0` 时直接 break（不是 continue），因为后面的数更大，不可能凑出 0。

5. **双指针移动的示意**（以 `[-4, -1, -1, 0, 1, 2]` 为例，固定 `i=1, nums[i]=-1`）：
   ```
   排序后: [-4, -1, -1, 0, 1, 2]
                  i   L        R     sum = -1+0+2 = 1 > 0, R左移
                  i   L     R        sum = -1+0+1 = 0 ✓ 找到!
                  i      L  R        sum = -1+1+1 = 1 > 0, R左移
                  i      LR          L >= R, 结束
   ```

## 解法详解

### 解法1: 暴力三重循环 — O(n³) / O(n)

**思考过程**：最直觉的方式——枚举所有可能的三元组，用 set 去重。

```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        int n = nums.size();
        set<vector<int>> resultSet;  // 用 set 自动去重
        sort(nums.begin(), nums.end());  // 排序后三元组有固定顺序，set 才能正确去重
        
        for (int i = 0; i < n - 2; i++) {
            for (int j = i + 1; j < n - 1; j++) {
                for (int k = j + 1; k < n; k++) {
                    if (nums[i] + nums[j] + nums[k] == 0) {
                        resultSet.insert({nums[i], nums[j], nums[k]});
                    }
                }
            }
        }
        
        return vector<vector<int>>(resultSet.begin(), resultSet.end());
    }
};
```

**关键点**：
- 必须先排序，否则 `{-1, 0, 1}` 和 `{0, -1, 1}` 在 set 中是不同的。
- O(n³) 在 n=3000 时会 TLE。
- set 的插入本身也有 O(log m) 的开销（m 是结果数）。

### 解法2: 排序 + 双指针 — O(n²) / O(1) ⭐ 面试首选

**从解法1优化**：暴力解的瓶颈在内两层循环做的是"在剩余数组中找两个数和为 target"——这就是 Two Sum！排序后用双指针可以 O(n) 完成，总体 O(n²)。

```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        vector<vector<int>> result;
        int n = nums.size();
        sort(nums.begin(), nums.end());  // 排序：为双指针和去重做准备
        
        for (int i = 0; i < n - 2; i++) {
            // 剪枝：最小的数已经 > 0，三数之和不可能 == 0
            if (nums[i] > 0) break;
            
            // 去重：跳过和前一个相同的 nums[i]
            // 为什么是 nums[i] == nums[i-1] 而不是 nums[i] == nums[i+1]？
            // 因为 nums[i+1] 可能和 nums[i] 配对使用（如 [-1,-1,2]）
            if (i > 0 && nums[i] == nums[i - 1]) continue;
            
            int left = i + 1, right = n - 1;
            int target = -nums[i];  // 转化为 Two Sum: 找两数之和 == -nums[i]
            
            while (left < right) {
                int sum = nums[left] + nums[right];
                
                if (sum < target) {
                    left++;   // 和太小，左指针右移让 sum 变大
                } else if (sum > target) {
                    right--;  // 和太大，右指针左移让 sum 变小
                } else {
                    // 找到一组！
                    result.push_back({nums[i], nums[left], nums[right]});
                    
                    // 去重：跳过 left 和 right 的重复值
                    // 必须在找到答案后才去重，否则可能漏解
                    while (left < right && nums[left] == nums[left + 1]) left++;
                    while (left < right && nums[right] == nums[right - 1]) right--;
                    
                    // 跳过重复值后，再各移一步到新的值
                    left++;
                    right--;
                }
            }
        }
        
        return result;
    }
};
```

**完整执行过程示意**：
```
输入: [-1, 0, 1, 2, -1, -4]
排序: [-4, -1, -1, 0, 1, 2]

i=0, nums[i]=-4, target=4:
  L=1, R=5: -1+2=1 < 4, L++
  L=2, R=5: -1+2=1 < 4, L++
  L=3, R=5: 0+2=2 < 4, L++
  L=4, R=5: 1+2=3 < 4, L++
  L=5 >= R=5, 结束

i=1, nums[i]=-1, target=1:
  L=2, R=5: -1+2=1 == target ✓ → 记录 [-1,-1,2]
    去重: L跳到3, R跳到4 → L=3, R=4
  L=3, R=4: 0+1=1 == target ✓ → 记录 [-1,0,1]
    去重: L跳到4 → L=4 >= R=4, 结束

i=2, nums[i]=-1, 与 nums[1] 相同 → 跳过

i=3, nums[i]=0 > 0? 不是（等于0不能break！）
  L=4, R=5: 1+2=3 > 0, R--
  L=4 >= R=4, 结束

i=4, nums[i]=1 > 0 → break

结果: [[-1,-1,2], [-1,0,1]]
```

## 解法对比

| | 暴力三重循环 | 排序 + 双指针 |
|---|---|---|
| 时间 | O(n³) | O(n²) |
| 空间 | O(n) set去重 | O(1) 原地去重 |
| 去重方式 | 依赖 set，逻辑简单但慢 | 排序后跳重复，O(1)空间 |
| 面试 | 只用于说明理解题意 | **必须写出** |
| 适用 | n ≤ 几百 | n ≤ 几千 |

## 易错点

1. **第一层去重方向写反**：
   - ✗ `if (nums[i] == nums[i+1]) continue;` — 会跳过 `[-1,-1,2]` 这种合法答案
   - ✓ `if (i > 0 && nums[i] == nums[i-1]) continue;` — 向前看，确保当前值之前已处理过

2. **剪枝条件写成 `>= 0` 而不是 `> 0`**：
   - ✗ `if (nums[i] >= 0) break;` — 会漏掉 `[0, 0, 0]`
   - ✓ `if (nums[i] > 0) break;` — `nums[i]=0` 时后面可能还有 0

3. **找到答案后忘记同时移动两个指针**：
   - ✗ 只写了去重的 while 循环，忘了最后的 `left++; right--;` — 导致死循环
   - ✓ 去重 while 循环**之后**，再各移一步

4. **去重 while 中缺少 `left < right` 的保护**：
   - ✗ `while (nums[left] == nums[left+1]) left++;` — left 可能越界
   - ✓ `while (left < right && nums[left] == nums[left+1]) left++;`

5. **排序忘了写**：
   - 没有排序，双指针的"太小右移、太大左移"逻辑不成立，去重也不work

## 面试追问

**Q1: 暴力解能过吗？瓶颈在哪？**
→ O(n³) 在 n=3000 时约 2.7×10¹⁰ 次操作，超时。瓶颈在内两层循环做的是 Two Sum，可以用双指针优化到 O(n)。

**Q2: 为什么排序不影响正确性？**
→ 题目要求返回值的组合（不是索引），排序只改变元素位置不改变元素值，所有合法三元组仍然存在。如果题目要求返回索引（像 Two Sum），就不能排序了。

**Q3: 如果要找四数之和（4Sum）呢？推广到 kSum 呢？**
→ 4Sum：外面再套一层循环，固定两个数后做 Two Sum。kSum：递归地将 kSum 转化为 (k-1)Sum，直到 k=2 时用双指针。时间 O(n^(k-1))。

**Q4: 能否用哈希表而不排序？**
→ 可以，固定 `nums[i]` 后用 unordered_set 做 Two Sum。但去重非常麻烦：需要对三元组排序后放入 set，或者用复杂的标记逻辑。排序 + 双指针方案更简洁、更不易出错。
