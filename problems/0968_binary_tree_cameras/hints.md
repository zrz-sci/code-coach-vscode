# 968. 监控二叉树

## 核心思路

本质上是一个**树上最小支配集**问题：在树的节点上放置最少的摄像头，使得每个节点要么自己有摄像头，要么被相邻节点（父/子）的摄像头覆盖。关键洞察是**自底向上贪心**：叶子节点不放摄像头，让其父节点放，这样每个摄像头能覆盖最多节点。

## 思维链

1. **读完题第一反应**：每个摄像头能覆盖自身、父节点、子节点。要覆盖所有节点，用最少摄像头 → 这是一个覆盖/支配问题。
2. **朴素想法**：能不能对每个节点尝试"放"或"不放"？这是暴力搜索，2^n 种组合，太慢。
3. **关键观察**：叶子节点放摄像头是"浪费"的——叶子没有子节点，覆盖范围小。如果在叶子的父节点放摄像头，既能覆盖叶子，还能覆盖叶子的兄弟和祖父，效率更高。
4. **贪心策略浮现**：自底向上，叶子节点不放 → 叶子的父节点被迫放 → 放了摄像头的节点的父节点已被覆盖，不需要放。这形成了一个**三状态传递**的模式。
5. **形式化为状态 DP**：每个节点有三种状态——(0)未被覆盖、(1)已被覆盖但没装摄像头、(2)装了摄像头。通过后序遍历，根据子节点状态决定当前节点状态。
6. **另一条路径——树形 DP**：对每个节点维护三个值（自己放、自己不放但被覆盖、自己不放且不被子覆盖），通过 min 操作精确计算最优解。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 贪心 + 后序遍历 | 自底向上三状态贪心 | O(n) | O(h) | ⭐ 必须写出 |
| 树形 DP（三状态） | 每个节点维护三种状态的最小值 | O(n) | O(h) | 加分项 |

2. **三状态是什么？** 想想一个节点回传给父节点的信息：
   - "我没被覆盖，你必须帮我"（状态 0）
   - "我已被覆盖了，你不用管我"（状态 1）
   - "我装了摄像头，我能帮你"（状态 2）

3. **ASCII 示意图——贪心过程**：
   ```

   //      / \          / \          / \
   //     0   0   →    0   0   →   📷  0(covered)
   //    / \          / \          / \
   //   0   0       叶子 叶子     ✓   ✓
   ```

4. **null 节点怎么处理？** 把 null 视为"已被覆盖"（状态 1），这样叶子节点的子节点不会触发"必须放摄像头"的条件，叶子本身变成"未覆盖"状态——正好推动父节点放摄像头。

## 解法详解

### 解法1: 贪心 + 后序遍历（三状态） — O(n) / O(h) ⭐ 面试首选

**思考过程**：

自底向上思考。叶子节点放摄像头"浪费"覆盖能力，所以让叶子的父节点放。这个贪心直觉引导我们用后序遍历（先处理子节点，再决定当前节点）。

定义三种状态：
- **0 = 未被覆盖**：该节点需要被父节点的摄像头覆盖
- **1 = 已被覆盖**：该节点安全了（被子节点的摄像头覆盖），但自己没装
- **2 = 有摄像头**：该节点装了摄像头

状态转移规则（后序遍历，拿到左右子状态后决定当前状态）：
- 如果**任一子节点未被覆盖（状态0）**→ 当前节点**必须**放摄像头（状态2）
- 如果**任一子节点有摄像头（状态2）**→ 当前节点已被覆盖（状态1）
- 否则（两个子节点都是已覆盖状态1）→ 当前节点未被覆盖（状态0），等父节点来覆盖

```
// 决策树（每个节点看子节点状态做决定）:
//
//  子状态有0(未覆盖)?  ──是──→ 当前放摄像头(2), cameras++
//         |
//        否
//         |
//  子状态有2(摄像头)?  ──是──→ 当前已被覆盖(1)
//         |
//        否
//         |
//  两子都是1(已覆盖)  ──────→ 当前未覆盖(0), 等父来救
```

```cpp
/**
 * Definition for a binary tree node.
 * struct TreeNode {
 *     int val;
 *     TreeNode *left;
 *     TreeNode *right;
 *     TreeNode() : val(0), left(nullptr), right(nullptr) {}
 *     TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
 *     TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
 * };
 */
class Solution {
public:
    int cameras = 0;
    
    // 返回值: 0=未覆盖, 1=已覆盖(无摄像头), 2=有摄像头
    int dfs(TreeNode* node) {
        if (!node) return 1; // null视为已覆盖，不触发父节点放摄像头
        
        int left = dfs(node->left);
        int right = dfs(node->right);
        
        // 规则1: 任一子节点未覆盖 → 必须在当前节点放摄像头
        if (left == 0 || right == 0) {
            cameras++;
            return 2;
        }
        // 规则2: 任一子节点有摄像头 → 当前节点已被覆盖
        if (left == 2 || right == 2) {
            return 1;
        }
        // 规则3: 两个子节点都是已覆盖(1) → 当前未覆盖，等父节点
        return 0;
    }
    
    int minCameraCover(TreeNode* root) {
        // 如果根节点最终未被覆盖，补一个摄像头
        if (dfs(root) == 0) cameras++;
        return cameras;
    }
};
```

**关键点**：
- null 返回 1（已覆盖）是整个贪心的基石——这保证了叶子节点返回 0（未覆盖），从而推动叶子的父放摄像头。
- 根节点特判：根节点没有父节点，如果它是状态 0，没人来救它，必须自己放。
- 判断顺序很重要：先检查状态 0（最紧急），再检查状态 2，最后才是状态 1。

### 解法2: 树形 DP（精确三状态） — O(n) / O(h)

**从解法1深化**：贪心解法简洁但需要正确性论证。树形 DP 用更严谨的方式定义状态，对每个节点返回三个值，通过 min 操作精确选择最优方案。

定义每个节点返回三个值 `(a, b, c)`：
- `a`：该节点**装摄像头**时，以该节点为根的子树所需的最小摄像头数
- `b`：该节点**不装摄像头但被子节点覆盖**时的最小摄像头数
- `c`：该节点**不装摄像头且未被子节点覆盖**（期望被父节点覆盖）时的最小摄像头数

状态转移：
- `a = 1 + min(la, lb, lc) + min(ra, rb, rc)`（自己放了摄像头，子节点怎样都行）
- `b = min(la + min(ra, rb), ra + min(la, lb))`（自己不放，至少一个子节点得放来覆盖自己）
- `c = lb + rb`（自己不放且不被覆盖，子节点各自被覆盖即可，不需要放摄像头）

```cpp
class Solution {
public:
    // 返回 {放摄像头, 不放但被子覆盖, 不放且未被覆盖}
    // 注意: 值为 INF 表示不可行的状态
    static constexpr int INF = 1e9;
    
    struct State {
        int cam;       // 自己放摄像头
        int covered;   // 自己不放,被子节点覆盖
        int uncovered; // 自己不放,未被覆盖
    };
    
    State dfs(TreeNode* node) {
        if (!node) {
            // null节点: 不能放摄像头(INF), 视为已覆盖(0), 不适用未覆盖(0)
            return {INF, 0, 0};
        }
        
        auto [la, lb, lc] = dfs(node->left);
        auto [ra, rb, rc] = dfs(node->right);
        
        // 自己放摄像头: 子节点任意状态都行
        int cam = 1 + min({la, lb, lc}) + min({ra, rb, rc});
        
        // 自己不放但要被覆盖: 至少一个子节点放了摄像头
        int covered = min(la + min(ra, rb), ra + min(la, lb));
        
        // 自己不放且未被覆盖: 两个子节点都不放但各自被覆盖
        int uncovered = lb + rb;
        
        return {cam, covered, uncovered};
    }
    
    int minCameraCover(TreeNode* root) {
        auto [cam, covered, uncovered] = dfs(root);
        // 根节点没有父节点,不能是uncovered状态(或者说uncovered也要算一个摄像头)
        return min(cam, covered);
    }
};
```

**关键点**：
- null 节点的 `cam = INF` 表示不可能在 null 上放摄像头。
- `covered` 的转移最复杂：要保证至少一个孩子放了摄像头来覆盖自己，用 `min(la + min(ra, rb), ra + min(la, lb))` 保证了这一点。
- 根节点的答案是 `min(cam, covered)`，不能取 `uncovered`，因为根没有父来覆盖它。

## 解法对比

| | 贪心（解法1） | 树形 DP（解法2） |
|---|---|---|
| 核心思想 | 自底向上三状态贪心 | 每个节点维护精确三值 |
| 代码量 | 少，~20行 | 多，状态转移较复杂 |
| 正确性 | 需要贪心证明（直觉上正确） | DP 天然保证最优 |
| 面试推荐 | ⭐ 首选：简洁易写 | 适合追问或严谨论证 |
| 适合场景 | 面试白板、竞赛快速AC | 想要深入理解/面试追问 |

## 易错点

1. **null 节点返回值搞错**
   - ✗ `if (!node) return 0;`（未覆盖）→ 会导致每个叶子的父放摄像头，进而叶子的祖父也不得不放，摄像头数过多
   - ✓ `if (!node) return 1;`（已覆盖）→ 叶子节点才能正确返回 0，触发父节点放摄像头

2. **忘记根节点特判**
   - ✗ 直接 `return cameras;`
   - ✓ `if (dfs(root) == 0) cameras++;` 根节点没有父节点，未覆盖时必须自己放

3. **判断顺序写反**
   - ✗ 先判断 `left == 2 || right == 2` 再判断 `left == 0 || right == 0`
   - ✓ **必须先判断 0**（未覆盖优先级最高），因为一个孩子有摄像头不代表另一个孩子被覆盖了——如果另一个孩子未覆盖，当前节点还是得放

4. **树形 DP 中 `covered` 的转移遗漏**
   - ✗ `covered = la + ra`（两个孩子都放）→ 这不是最小的，可能只需要一个放
   - ✓ `covered = min(la + min(ra, rb), ra + min(la, lb))`（至少一个放摄像头）

## 面试追问

**Q1: 为什么叶子不放摄像头是最优的？**
> 叶子没有子节点，放在叶子上只能覆盖自身和父节点（2个节点）。放在叶子的父上能覆盖父自身+所有子+祖父（最多4个节点）。覆盖效率更高，所以叶子不放。更严谨地说，可以证明任何包含叶子上摄像头的最优解，都能通过将摄像头上移到父节点而不增加总数。

**Q2: 这个贪心策略的正确性怎么证明？**
> 交换论证：假设最优解在某个叶子 L 放了摄像头，将其移到 L 的父节点 P。P 的摄像头覆盖了 P、P 的所有子节点（包括 L）、P 的父节点。如果 L 原来还负责覆盖自己（必然的），现在 P 也能覆盖 L，所以移动后覆盖不减少，摄像头数不增加。对所有叶子重复此操作，得到和贪心解等价的方案。

**Q3: 如果改成摄像头能覆盖距离 k 以内的所有节点（不只是距离 1），怎么办？**
> 这变成了**k-支配集**问题。贪心不再那么直接，需要树形 DP：每个节点维护 `dp[node][距离最近摄像头的距离]` 或 `dp[node][该节点的"需求距离"]`。状态数从 3 增加到 O(k)，总复杂度 O(nk)。

**Q4: 如果是一般图（不是树）呢？**
> 一般图上的最小支配集是 NP-hard 问题。树上之所以能贪心/DP 多项式解决，是因为树没有环，子问题之间独立。
