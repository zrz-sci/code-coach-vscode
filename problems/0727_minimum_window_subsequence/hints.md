# 727. 最小窗口子序列 (Minimum Window Subsequence)

**难度**: Hard | **标签**: String, Dynamic Programming, Sliding Window

## 核心思路

给定字符串 s1 和 s2，找到 s1 中最短的连续子串，使得 s2 是该子串的**子序列**。注意这里要求的是子序列（有序但不一定连续），而非子串。

核心方法是**前向匹配 + 后向收缩**的双指针技巧。先从左到右扫描找到一个包含 s2 所有字符（按序）的窗口终点，然后从该终点往回扫描收缩窗口找到最左起点。也可以使用 DP 方法，其中 `dp[i][j]` 表示 s1 前 i 个字符中包含 s2 前 j 个字符作为子序列的最晚起始位置。

## 思维链

1. **理解差异**: 与 LC 76 (Minimum Window Substring) 不同，本题要求的是子序列而非子集。s2 中字符必须在窗口中按序出现
2. **暴力思路**: 对 s1 中每个可能的起点，尝试匹配 s2 的所有字符。O(n^2 * m) 太慢
3. **优化方向一 - 双指针**: 先正向贪心匹配完 s2，确定窗口右端；再反向贪心收缩，确定窗口左端。这样每次找到一个候选窗口，取最小值
4. **优化方向二 - DP**: `dp[i][j]` 记录 s1[0..i] 中使得 s2[0..j] 是子序列的最大起始索引。最终在所有完成完整匹配的位置取最短窗口
5. **输出**: 返回最短窗口对应的子串；若无法完成匹配返回空串

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 前向匹配+后向收缩 | O(n * m) | O(1) | 双指针，直觉好，面试首选 |
| 动态规划 | O(n * m) | O(n * m) 或 O(n) | 标准 DP，逻辑清晰 |
| DP + 预计算 next 数组 | O(n * m) | O(n * 26) | 加速字符查找 |

其中 n = len(s1)，m = len(s2)。

## 关键提示

1. **前向匹配**: 用指针 j 遍历 s2，指针 i 遍历 s1，当 `s1[i] == s2[j]` 时 j++。j 到达 m 时表示找到一个包含 s2 的窗口，i 是右端点
2. **后向收缩**: 从匹配完成的右端点开始，反向扫描 s1 和 s2 以找到最靠右的左端点。这个左端点就是当前窗口的最优起始位置
3. **继续搜索**: 后向收缩找到左端点后，从左端点 +1 继续前向匹配，寻找下一个候选窗口
4. **DP 含义**: `dp[i][j]` = 使得 s2[0..j-1] 是 s1[start..i-1] 子序列的最大 start 值。值越大意味着窗口越短

## 解法详解

### 解法一：前向匹配 + 后向收缩（推荐）

**步骤**:
1. 用指针 `i` 扫描 s1，指针 `j` 扫描 s2
2. 正向阶段：当 `s1[i] == s2[j]` 时 `j++`。当 `j == m` 时，`right = i` 是窗口右端
3. 反向阶段：从 `right` 开始向左扫描，`j` 从 `m-1` 递减。当 `s1[i] == s2[j]` 时 `j--`。当 `j < 0` 时，`left = i` 是窗口左端
4. 更新答案：如果 `right - left + 1` 比当前最优更短，更新答案
5. 将 `i` 设为 `left + 1`，`j` 设为 `0`，继续正向匹配

**时间复杂度**: O(n * m)，最坏情况每次前向匹配 O(n) 后向收缩 O(m)  
**空间复杂度**: O(1)

### 解法二：动态规划

**状态定义**: `dp[i][j]` = 在 s1 的前 i 个字符中，使 s2 的前 j 个字符形成子序列的最大起始索引（0-indexed）。-1 表示不存在。

**转移方程**:
- 若 `s1[i-1] == s2[j-1]`:
  - 若 `j == 1`: `dp[i][j] = i - 1`（以 i-1 为起点）
  - 否则: `dp[i][j] = dp[i-1][j-1]`（继承之前的起始位置）
- 若 `s1[i-1] != s2[j-1]`: `dp[i][j] = dp[i-1][j]`（不用当前字符）

**答案提取**: 遍历所有 `dp[i][m]` != -1 的位置，取 `i - dp[i][m]` 最小的窗口。

**时间复杂度**: O(n * m)  
**空间复杂度**: O(n * m)，可优化至 O(n)

## 易错点

1. **子序列 vs 子串**: s2 是窗口的子序列，不是子串。字符必须按序出现但不必连续
2. **后向收缩的方向**: 反向扫描时 i 从 right 递减，j 从 m-1 递减，注意不要搞反
3. **起始位置更新**: 后向收缩找到 left 后，下次搜索应从 left+1 开始，而非 right+1，否则可能漏掉更优解
4. **左端点 vs 右端点**: 题目要求左端点最靠左的那个窗口（同长度时），后向收缩天然保证找到最靠右的左端点，所以按照找到顺序取最优即可
5. **DP 初始化**: `dp[i][0]` 应该全部初始化为有效值（或不需要，因为 j=0 表示空串）
6. **s2 中有 s1 不存在的字符**: 可能永远无法完成匹配，返回空串

## 面试追问

1. **本题与 LC 76 Minimum Window Substring 有什么区别？**
   - LC 76 要求窗口包含 t 中所有字符（集合/频率匹配），顺序无关；本题要求 s2 是窗口的子序列，顺序必须一致

2. **能否用滑动窗口（双指针缩放）解决？**
   - 不能直接用传统滑动窗口，因为子序列匹配不具备"右指针右移时左指针可以单调右移"的性质。需要前向+后向的两次扫描

3. **如何将 DP 的空间优化到 O(m)？**
   - 注意 `dp[i][j]` 只依赖 `dp[i-1][j-1]` 和 `dp[i-1][j]`，可以用滚动数组优化

4. **如果 s2 很长（接近 s1），有没有更快的方法？**
   - 可以预计算 `next[i][c]`：从位置 i 开始 s1 中字符 c 的下一个出现位置，实现 O(1) 跳转，但总复杂度仍为 O(n*m)

5. **如何处理多个相同长度的最短窗口？**
   - 题目要求返回左端点最小的，按照从左到右扫描的顺序，第一次遇到最短长度时记录即可
