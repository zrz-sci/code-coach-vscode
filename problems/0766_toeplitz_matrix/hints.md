# 766. 托普利茨矩阵 (Toeplitz Matrix)

## 核心思路

托普利茨矩阵的定义是：每条从左上到右下的对角线上的元素都相同。等价于：**对于每个元素 `matrix[r][c]`（r > 0 且 c > 0），检查它是否等于左上角的 `matrix[r-1][c-1]`**。如果所有位置都满足这个条件，则矩阵是托普利茨矩阵。这个观察将问题从"检查每条对角线"简化为"逐元素与左上角比较"。

## 思维链

1. **理解定义**：对角线 = 从左上到右下。同一条对角线上的元素满足 `r - c = 常数`
2. **逐对角线检查**？可以按 `r - c` 分组，但代码复杂
3. **更优观察**：如果 `matrix[r][c] != matrix[r-1][c-1]`，说明所在对角线不一致
4. **等价条件**：只需遍历矩阵，检查每个元素是否等于其**左上角邻居**即可
5. **跳过首行首列**：第一行和第一列没有左上角邻居，无需检查
6. **进阶思考**：如果内存受限，需要按行流式处理

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 逐元素比较左上角 | O(m*n) | O(1) | 最优解，代码极简 |
| 对角线分组比较 | O(m*n) | O(m+n) | 按对角线索引分组，用 map |
| 流式处理（进阶） | O(m*n) | O(n) | 只保留上一行，适合磁盘读取场景 |
| 首行首列定义法 | O(m*n) | O(1) | 追溯对角线起始元素 |
| 逐条对角线检查 | O(m*n) | O(1) | 显式遍历每条对角线 |

## 关键提示

1. **核心观察**：`matrix[r][c] == matrix[r-1][c-1]` 对所有 `r >= 1, c >= 1` 成立即可
2. **无需真正提取对角线**：逐元素比较左上角是最高效的方式
3. **对角线编号**：同一条对角线上 `r - c` 相同，这在分组方法中有用
4. **进阶一**：磁盘存储且每次只能读一行时，保存前一行即可逐行验证
5. **进阶二**：一次只能读部分行时，需要保留前一行对应部分的元素做对比
6. **矩阵不一定是方阵**：m 行 n 列，m 和 n 可以不同

## 解法详解

### 解法一：逐元素比较左上角（最优解）

**思路**：遍历矩阵中 `r >= 1, c >= 1` 的每个位置，检查 `matrix[r][c]` 是否等于 `matrix[r-1][c-1]`。如果有任何位置不相等，返回 false。

**步骤**：
1. 从第 1 行、第 1 列开始遍历（跳过第 0 行和第 0 列）
2. 比较当前元素与左上角元素
3. 不相等则立即返回 false
4. 全部通过返回 true

**时间复杂度**：O(m * n)  
**空间复杂度**：O(1)

### 解法二：对角线分组

**思路**：按 `r - c` 将元素分组到同一条对角线。每条对角线上的元素应该全部相同。可以用 HashMap 存储每条对角线上第一个见到的值，后续遇到相同对角线的元素进行比较。

**步骤**：
1. 遍历所有元素，计算对角线编号 `diag = r - c`
2. 用 map 记录每条对角线的第一个值
3. 后续元素与记录值比较，不同则返回 false

### 解法三：流式处理（进阶 Follow-up）

**思路**：针对"一次只能读取一行"的场景。保存前一行的数据，每读入新行时，比较 `curRow[c]` 与 `prevRow[c-1]`（c >= 1）。

**步骤**：
1. 读取第一行，保存为 `prevRow`
2. 对于后续每一行 `curRow`，检查 `curRow[c] == prevRow[c-1]`（c >= 1）
3. 更新 `prevRow = curRow`

**时间复杂度**：O(m * n)  
**空间复杂度**：O(n)，只需保留一行

### 解法四：首行首列定义法

**思路**：每个元素所在对角线的起始位置在第一行或第一列。验证每个元素等于其对角线起始元素。

### 解法五：逐条对角线检查

**思路**：显式枚举从第一列和第一行出发的所有对角线，检查每条对角线元素一致性。

## 易错点

1. **遍历范围**：从 `r=1, c=1` 开始，不是从 0 开始。第一行和第一列的元素没有左上角邻居
2. **矩阵可能是非方阵**：m x n 矩阵，行列数不同。循环边界用 `matrix.size()` 和 `matrix[0].size()`
3. **空矩阵或单元素**：1x1 矩阵天然是 Toeplitz 矩阵
4. **对角线方向搞混**：题目要求的是**左上到右下**的对角线（主对角线方向），不是副对角线
5. **进阶问题遗漏**：面试中很可能追问 follow-up，需要准备流式处理的思路
6. **比较方向**：可以比较 `(r,c)` vs `(r-1,c-1)`（左上角），也可以比较 `(r,c)` vs `(r+1,c+1)`（右下角），效果一样但循环边界不同

## 面试追问

1. **Q: 如果矩阵存在磁盘上，一次只能读一行，怎么办？**
   A: 保留前一行数据。读入新行后，比较 `newRow[c]` 与 `prevRow[c-1]`（c >= 1）。空间 O(n)

2. **Q: 如果一次只能读部分行（比如半行），怎么办？**
   A: 需要保留前一行的部分数据。每次读入当前行的一段 `[c1, c2]`，需要前一行 `[c1-1, c2-1]` 的数据。可以用两个长度为 blockSize 的缓冲区交替使用

3. **Q: 如何判断一个矩阵是否是反 Toeplitz 矩阵（副对角线方向）？**
   A: 检查 `matrix[r][c] == matrix[r-1][c+1]`，即右上角而非左上角

4. **Q: 能否用对角线编号 `r-c` 的思路做？有什么优劣？**
   A: 可以，用 HashMap 存储每条对角线的标准值。优点是容易推广到其他对角线模式，缺点是多了 O(m+n) 额外空间

5. **Q: 如何构造一个 m x n 的 Toeplitz 矩阵？**
   A: 只需要定义 m+n-1 个值，分别对应 `r-c` 从 `-(n-1)` 到 `(m-1)` 的每条对角线。第 (r,c) 位置的值为 `values[r - c + (n-1)]`
