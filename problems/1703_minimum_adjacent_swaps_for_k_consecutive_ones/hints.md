# 1703. 得到连续 K 个 1 的最少相邻交换次数

## 核心思路

本质上是：**从所有 1 的位置中选 k 个，把它们聚拢到一段连续区间，求最小移动总代价。** 这是经典的"中位数最优"问题的变体——选 k 个点聚到以中位数为中心的连续位置上，用前缀和 + 滑动窗口在 O(n) 时间内求解。

## 思维链

1. **读完题第一反应**：数组里只有 0 和 1，相邻交换等价于把 1 移动到目标位置，移动代价 = 移动的距离。暴力做法：枚举所有可能的连续 k 个位置的区间，对每个区间计算把最近的 k 个 1 搬过来的代价，取最小值。

2. **关键转化 — 只关注 1 的位置**：设所有 1 的下标存入数组 `pos[]`，问题变成：从 `pos[]` 中选连续 k 个元素（即一个滑动窗口），把它们移到某段连续位置上，求最小总移动距离。

3. **为什么是中位数？** 选定 k 个 1 后，它们要聚到连续的 k 个格子。经典结论：**将 k 个点聚到以中位数为中心的位置，总距离最小。** 但这里不是聚到同一点，而是聚到连续位置，所以需要做一步"坐标变换"：令 `pos[i] -= i`（减去在组内的相对偏移），把"聚到连续位置"转化为"聚到同一点"。

4. **前缀和 + 滑动窗口**：对变换后的数组，窗口大小 k，中位数是窗口中间元素。用前缀和 O(1) 计算窗口内所有点到中位数的距离之和。滑动窗口从左到右移动，O(m) 遍历（m = 1 的个数）。

5. **为什么 `pos[i] -= i` 是对的？** 假设选中的 k 个 1 最终占据位置 `[t, t+1, ..., t+k-1]`，第 j 个 1（在窗口内排第 j）需要移到 `t+j`。移动代价 = `|pos[j] - (t+j)| = |(pos[j]-j) - t|`。令 `g[j] = pos[j] - j`，问题变成：选一个 t，最小化 `Σ|g[j] - t|`，这就是经典的中位数问题。

6. **整体复杂度**：提取位置 O(n)，坐标变换 O(m)，前缀和 O(m)，滑动窗口 O(m)。总计 **O(n)**。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举每个窗口，直接计算移动代价 | O(m·k) | O(m) | 能说出即可 |
| 中位数 + 前缀和 + 滑动窗口 | 坐标变换后用中位数最优性 | O(n) | O(m) | ⭐ 必须写出 |

## 关键提示

1. **核心观察**：相邻交换移动一个 1，代价就是它移动的格数。所以总代价 = 所有被选中的 1 到它们目标位置的距离之和。

2. **坐标变换是关键一步**：`pos[i] -= i` 把"移到连续位置"问题变成"移到同一点"问题。想想为什么：如果 k 个 1 已经连续排列，变换后它们的值全相等。

3. **中位数最优性**：对于一组数，找一个点使得所有数到该点的绝对差之和最小，答案一定是中位数。

4. **前缀和加速求和**：窗口内左半部分都小于中位数，右半部分都大于中位数，分别用前缀和 O(1) 算出两侧的距离和。

5. **不要忘记 long long**：位置值和移动次数可能很大（n 到 10^5），累加后可能溢出 int。

```
示例可视化: nums = [1,0,0,0,0,0,1,1], k = 3

1 的位置: pos = [0, 6, 7]
坐标变换: pos[i] -= i → g = [0, 5, 5]

窗口 [0,5,5], 中位数 = 5
代价 = |0-5| + |5-5| + |5-5| = 5  ✓
```

## 解法详解

### 解法1: 暴力枚举 — O(m·k) / O(m)

**思考过程**：最直觉的做法。提取所有 1 的位置，枚举每个长度为 k 的窗口，对每个窗口计算把 k 个 1 聚拢到连续位置的最小代价。

```cpp
class Solution {
public:
    int minMoves(vector<int>& nums, int k) {
        // 提取所有 1 的位置
        vector<int> pos;
        for (int i = 0; i < (int)nums.size(); i++) {
            if (nums[i] == 1) pos.push_back(i);
        }
        int m = pos.size();
        
        // 坐标变换：聚到连续位置 → 聚到同一点
        for (int i = 0; i < m; i++) pos[i] -= i;
        
        long long ans = LLONG_MAX;
        // 枚举每个窗口 [i, i+k-1]
        for (int i = 0; i + k - 1 < m; i++) {
            int mid = i + k / 2;         // 中位数下标
            long long cost = 0;
            for (int j = i; j < i + k; j++) {
                cost += abs(pos[j] - pos[mid]);
            }
            ans = min(ans, cost);
        }
        return (int)ans;
    }
};
```

**关键点**：每个窗口内部 O(k) 计算，总共 O(m·k)，当 m 和 k 都接近 10^5 时会超时。但这个思路建立了正确的框架。

### 解法2: 中位数 + 前缀和 + 滑动窗口 — O(n) / O(m) ⭐ 面试首选

**从解法1优化**：解法1的瓶颈在于每个窗口都重新计算 O(k) 的距离和。用前缀和可以 O(1) 计算任意窗口内的距离和。

**核心数学推导**：

对于变换后的数组 `g[]`，窗口 `[i, i+k-1]`，中位数下标 `mid = i + k/2`，中位数值 `M = g[mid]`：

```
cost = Σ_{j=i}^{i+k-1} |g[j] - M|
     = (右半部分之和 - 右半元素个数 * M) + (左半元素个数 * M - 左半部分之和)
```

用前缀和 `pre[i] = g[0] + g[1] + ... + g[i-1]`，可以 O(1) 算出任意子数组之和。

```
// 窗口 [i, i+k-1] 中位数在 mid = i + k/2
//
// 变换后 g[] (已排序，因为原 pos 递增且减去递增的 i):
//   g = [g_i, g_{i+1}, ..., g_{mid}, ..., g_{i+k-1}]
//        |---- 左半 ----|  中位数  |---- 右半 ----|
//
// 左半: [i, mid-1] 共 mid-i 个, 每个 <= g[mid]
// 右半: [mid+1, i+k-1] 共 i+k-1-mid 个, 每个 >= g[mid]
//
// cost = M*(mid-i) - sum(左半) + sum(右半) - M*(i+k-1-mid)
```

```cpp
class Solution {
public:
    int minMoves(vector<int>& nums, int k) {
        // Step 1: 提取 1 的位置
        vector<long long> g;
        for (int i = 0; i < (int)nums.size(); i++) {
            if (nums[i] == 1) g.push_back(i);
        }
        int m = g.size();
        
        // Step 2: 坐标变换 — 消除"连续"约束
        // g[i] -= i 后，"移到连续位置"变成"移到同一点"
        for (int i = 0; i < m; i++) g[i] -= i;
        
        // Step 3: 前缀和
        // pre[i] = g[0] + g[1] + ... + g[i-1], pre[0] = 0
        vector<long long> pre(m + 1, 0);
        for (int i = 0; i < m; i++) {
            pre[i + 1] = pre[i] + g[i];
        }
        
        // Step 4: 滑动窗口，枚举每个 k-长窗口
        long long ans = LLONG_MAX;
        for (int i = 0; i + k <= m; i++) {
            int mid = i + k / 2;
            long long M = g[mid];
            
            // 右半: [mid, i+k-1] (包含中位数自身，自身贡献为0)
            // sum(右半) = pre[i+k] - pre[mid]
            long long rightSum = pre[i + k] - pre[mid];
            long long rightCount = i + k - mid; // = k - k/2
            
            // 左半: [i, mid-1]  (不包含中位数)
            // sum(左半) = pre[mid] - pre[i]
            long long leftSum = pre[mid] - pre[i];
            long long leftCount = mid - i;       // = k/2
            
            long long cost = (rightSum - rightCount * M)
                           + (leftCount * M - leftSum);
            ans = min(ans, cost);
        }
        return (int)ans;
    }
};
```

**为什么 g[] 变换后仍然是非递减的？**
原始 `pos[]` 严格递增（每个 1 的位置不同），即 `pos[i+1] > pos[i]`，所以 `pos[i+1] - (i+1) >= pos[i] - i`（因为 `pos[i+1] >= pos[i] + 1`）。因此 `g[]` 非递减，窗口内天然有序，中位数就在中间位置。

## 解法对比

| | 解法1 暴力 | 解法2 前缀和+滑动窗口 |
|---|---|---|
| 时间 | O(m·k) | O(n) |
| 空间 | O(m) | O(m) |
| 核心差异 | 每窗口暴力求和 | 前缀和 O(1) 求和 |
| 适用 | 理解思路 | 面试 & 竞赛 |

两个解法的核心框架完全相同（坐标变换 + 中位数），唯一区别是窗口内求和的效率。

## 易错点

1. **忘记坐标变换**：
   - ✗ 直接对 `pos[]` 求中位数距离和 → 这求的是"聚到同一点"的代价，不是"聚到连续位置"
   - ✓ `pos[i] -= i` 后再操作

2. **前缀和的区间边界**：
   - ✗ `rightSum = pre[i+k-1] - pre[mid]` → 漏掉了最后一个元素
   - ✓ `rightSum = pre[i+k] - pre[mid]`（前缀和多一位，`pre[j]` 表示前 j 个元素之和）

3. **整数溢出**：
   - ✗ 用 `int` 存前缀和和代价 → 当 n=10^5 时前缀和可达 ~10^9，乘法后溢出
   - ✓ 使用 `long long`

4. **中位数下标计算**：
   - ✗ `mid = i + (k-1)/2` vs `mid = i + k/2` → k 为偶数时两者不同，需要保持一致
   - ✓ 对于偶数 k，两个中位数都可以，但左右半区间的划分要跟中位数下标匹配

5. **变换后 g[] 可能有重复值**：
   - 这不影响正确性，但 `g[mid]` 不一定唯一。放心，中位数选谁都最优。

## 面试追问

**Q1: 为什么相邻交换的代价等于位置差的绝对值？**

相邻交换每次只移动一格，所以把一个 1 从位置 a 移到位置 b 至少需要 `|a-b|` 次交换。而且多个 1 的移动不会互相干扰（它们可以"穿过"彼此，等价于各自独立移动到目标位置）。更严谨地说：相邻交换排序的总次数 = 逆序对数 = 每个元素位移的绝对值之和（当所有移动方向一致或不交叉时）。

**Q2: 坐标变换 `pos[i] -= i` 的直觉是什么？**

想象 k 个 1 已经完美地连续排列在位置 `[t, t+1, ..., t+k-1]`，那么第 j 个 1 的目标是 `t+j`。变换后 `g[j] = pos[j] - j`，目标变成 `g[j] = t`，即所有人都要到同一个值 t。这就把"连续排列"问题化归为"聚到一点"问题。

**Q3: 如果不是相邻交换，而是可以任意交换，答案有什么变化？**

任意交换时，最小交换次数 = 目标排列相对于当前排列的"循环分解"中，每个长度为 L 的环需要 L-1 次交换。这比相邻交换代价低很多，且是完全不同的问题（置换环问题）。

**Q4: 能否不用坐标变换，直接在原位置上推导公式？**

可以，但公式更复杂。直接计算时，每个 1 到中位数的距离还要减去中间已有的 1 的个数（因为目标是连续位置，中间的 0 才是真正需要跨越的距离）。坐标变换的好处正是自动消除了这个修正项。
