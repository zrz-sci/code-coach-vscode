# 80. 删除有序数组中的重复项 II

## 核心思路

有序数组中原地删除多余的重复元素，使每个元素**最多出现两次**。这是一个经典的**双指针覆盖写**问题。

核心洞察：维护一个"写指针" `slow`，表示已处理部分的末尾。对于每个新元素，只需和 `nums[slow - 2]` 比较——如果不同，说明这个元素出现次数还不满 2 次，可以写入；如果相同，说明已经有 2 个了，跳过。

**通用模板**：如果允许最多 k 次重复，只需比较 `nums[i]` 和 `nums[slow - k]`。本题 k = 2。

## 思维链

1. **读完题第一反应** → 有序数组 + 原地删除 + O(1) 空间 = 双指针模式。用一个慢指针维护"有效部分"，快指针扫描所有元素。
2. **每个元素最多保留 2 个，怎么判断？** → 最直觉的做法：维护一个计数器，对连续相同元素计数，count <= 2 时保留，> 2 时跳过。
3. **有没有更优雅的方法？** → 因为数组有序，相同元素必然连续。如果当前元素 `num` 要写入位置 `slow`，只需看 `nums[slow - 2]`：如果 `num != nums[slow - 2]`，说明 `num` 在已写入部分中出现不到 2 次，可以写入。这就是**通用模板**。
4. **为什么比较 `nums[slow - 2]` 而不是 `nums[slow - 1]`？** → 因为允许 2 次重复。如果 `num == nums[slow - 1]` 但 `num != nums[slow - 2]`，说明 `num` 才出现了 1 次（`slow-1` 是第 1 个），可以再放一个。如果 `num == nums[slow - 2]`，说明 `nums[slow-2]` 和 `nums[slow-1]` 都等于 `num`，已经有 2 个了，不能再放。
5. **前 2 个元素怎么处理？** → `slow < 2` 时直接写入，因为前 2 个元素无论如何都应该保留（每个元素至少可以出现 2 次）。
6. **这个模板能推广吗？** → 当然！改成 k 就行：`slow < k || num != nums[slow - k]`。k=1 就是"删除所有重复"（LeetCode 26），k=3 就是"每个元素最多 3 次"。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 通用双指针模板 (k=2) | 比较 nums[slow-2] 判断是否写入 | O(n) | O(1) | ⭐ 必须掌握 |
| 显式计数法 | 维护 count 追踪连续重复次数 | O(n) | O(1) | 直觉更清晰 |
| for-each 简化写法 | 通用模板的简化形式 | O(n) | O(1) | 代码最短 |

## 关键提示

1. **通用模板的核心**：`if (slow < k || num != nums[slow - k])` 这一行包含了所有逻辑——前 k 个无条件接受，之后只接受与 `nums[slow-k]` 不同的值。
2. **为什么比较 slow-k 位置？** 因为 `nums[0..slow-1]` 是已经写好的有效部分。如果当前值等于 `nums[slow-k]`，说明从 `slow-k` 到 `slow-1` 这 k 个位置都是相同的值，已经够 k 个了。
3. **有序性是前提**：这个模板依赖数组有序（相同元素连续）。如果数组无序，需要先排序或用哈希表。
4. **写指针和读指针的角色**：`slow` 是写指针（下一个要写的位置），`num`（或 `fast`/`i`）是读指针（当前正在检查的元素）。写指针永远 <= 读指针。

## 解法详解

### 解法1: 通用双指针模板 (k=2) — O(n) / O(1) ⭐ 面试首选

**思考过程**: 利用有序性，已写入部分 `nums[0..slow-1]` 也是有序的。要判断当前元素是否可以写入，只需看往回数第 k 个位置。

```
示例: nums = [1,1,1,2,2,3], k = 2

slow=0: num=1, slow<2 → 直接写入. nums=[1,_,_,_,_,_], slow=1
slow=1: num=1, slow<2 → 直接写入. nums=[1,1,_,_,_,_], slow=2
slow=2: num=1, nums[slow-2]=nums[0]=1, num==nums[slow-2] → 跳过!
slow=2: num=2, nums[slow-2]=nums[0]=1, num!=nums[slow-2] → 写入. nums=[1,1,2,_,_,_], slow=3
slow=3: num=2, nums[slow-2]=nums[1]=1, num!=nums[slow-2] → 写入. nums=[1,1,2,2,_,_], slow=4
slow=4: num=3, nums[slow-2]=nums[2]=2, num!=nums[slow-2] → 写入. nums=[1,1,2,2,3,_], slow=5

返回 slow = 5. 有效部分: [1,1,2,2,3] ✓

为什么第三个1被跳过了？
  当 slow=2 时, nums[0]=1, nums[1]=1 (已经有2个1了)
  新的 num=1 == nums[slow-2]=nums[0]=1
  说明 [slow-2, slow-1] 这两个位置都是1, 已满, 不能再放
```

```cpp
class Solution {
public:
    int removeDuplicates(vector<int>& nums) {
        int slow = 0;
        for (int num : nums) {
            // 前 k 个直接放入；之后只有不等于 nums[slow-k] 才放入
            if (slow < 2 || num != nums[slow - 2]) {
                nums[slow++] = num;
            }
        }
        return slow;
    }
};
```

**通用化版本（任意 k）**:

```cpp
class Solution {
public:
    int removeDuplicates(vector<int>& nums, int k = 2) {
        int slow = 0;
        for (int num : nums) {
            if (slow < k || num != nums[slow - k]) {
                nums[slow++] = num;
            }
        }
        return slow;
    }
};
```

**关键点**:
- 整个算法的精华就一行：`if (slow < k || num != nums[slow - k])`。
- 不需要特殊处理空数组，因为空数组不进入循环，`slow = 0` 正确返回。
- `slow` 既表示"写入位置"也表示"当前有效长度"。
- k=1 就是 LeetCode 26（每个元素最多出现1次），k=2 就是本题。

### 解法2: 显式计数法 — O(n) / O(1)

**另一种思路**: 用一个变量 `count` 显式追踪当前连续重复的次数。遇到新值重置为 1，遇到重复值 count++。只有 count <= 2 时才写入。

```
示例: nums = [0,0,1,1,1,1,2,3,3]

i=0: slow=0, num=0 (初始化第一个元素)
i=1: num=0, 同前 → count=2 (<=2) → nums[1]=0, slow=1
i=2: num=1, 不同 → count=1 → nums[2]=1, slow=2
i=3: num=1, 同前 → count=2 (<=2) → nums[3]=1, slow=3
i=4: num=1, 同前 → count=3 (>2) → 跳过!
i=5: num=1, 同前 → count=4 (>2) → 跳过!
i=6: num=2, 不同 → count=1 → nums[4]=2, slow=4
i=7: num=3, 不同 → count=1 → nums[5]=3, slow=5
i=8: num=3, 同前 → count=2 (<=2) → nums[6]=3, slow=6

返回 slow+1 = 7. 有效部分: [0,0,1,1,2,3,3] ✓
```

```cpp
class Solution {
public:
    int removeDuplicates(vector<int>& nums) {
        if (nums.empty()) return 0;
        int slow = 0, count = 1; // slow 指向最后一个写入的位置
        for (int i = 1; i < (int)nums.size(); i++) {
            if (nums[i] == nums[i - 1]) {
                count++;
            } else {
                count = 1; // 新值，重置计数
            }
            if (count <= 2) {
                nums[++slow] = nums[i]; // 写入并前进
            }
        }
        return slow + 1; // slow 是最后写入的索引，长度 = slow + 1
    }
};
```

**关键点**:
- `slow` 在这个解法中指向"最后写入的位置"（而非"下一个写入位置"），所以返回 `slow + 1`。
- 需要单独处理空数组。
- `count` 是通过比较 `nums[i]` 和 `nums[i-1]` 来更新的，利用了数组有序的性质。
- 相比通用模板，逻辑更显式但代码更长。

---

### 解法3: 传统双指针写法 — O(n) / O(1)

**显式快慢指针**: 不用 for-each 语法，而是用传统的 fast/slow 指针形式。

```cpp
class Solution {
public:
    int removeDuplicates(vector<int>& nums) {
        int n = nums.size();
        if (n <= 2) return n; // 长度 <= 2 直接返回
        
        int slow = 2; // 前两个元素无条件保留
        for (int fast = 2; fast < n; fast++) {
            if (nums[fast] != nums[slow - 2]) {
                nums[slow] = nums[fast];
                slow++;
            }
        }
        return slow;
    }
};
```

**关键点**:
- `slow` 和 `fast` 都从 2 开始（前 2 个元素无条件保留）。
- 和解法1 本质相同，只是展开了 `slow < 2` 的边界条件。
- `slow` 表示"下一个写入位置"，最终值就是有效长度。

## 解法对比

|  | 通用模板 (k=2) | 显式计数法 | 传统双指针 |
|--|---------------|-----------|-----------|
| 代码量 | ⭐ 最短（6行） | ⭐⭐ 中等 | ⭐⭐ 中等 |
| 可读性 | 需要理解模板 | ⭐⭐⭐ 最直观 | ⭐⭐ 中等 |
| 通用性 | ⭐⭐⭐ 改 k 即可 | 需要改 count 阈值 | 改 k 即可 |
| 边界处理 | 自动处理 | 需特殊处理空数组 | 需特殊处理 n<=2 |

**面试选择**: 通用模板（解法1）是面试首选——代码最短、通用性最强、不需要特殊边界处理。如果面试官觉得你背了模板，可以切换到计数法（解法2）详细解释逻辑。

## 易错点

1. **通用模板中比较对象搞错**：
   - ✗ `num != nums[i - 2]` → 这是比较原始数组中的前两个位置，但那些位置可能已经被覆盖了
   - ✓ `num != nums[slow - 2]` → 比较的是已写入的有效部分

2. **slow 的含义不统一**：
   - 解法1中 `slow` = "下一个写入位置" = "有效长度"，直接 `return slow`
   - 解法2中 `slow` = "最后写入的索引"，需要 `return slow + 1`
   - 混淆两者会导致返回值差 1

3. **忘记 `slow < 2` 的边界条件**：
   - ✗ `if (num != nums[slow - 2])` → 当 slow=0 或 slow=1 时，`slow-2` 越界！
   - ✓ `if (slow < 2 || num != nums[slow - 2])` → 短路求值保护

4. **显式计数法中 count 重置时机错误**：
   - ✗ 先 `count = 1` 再判断 `nums[i] == nums[i-1]` → count 始终 >= 1，逻辑混乱
   - ✓ 先判断是否和前一个相同，相同则 count++，不同则 count = 1

5. **返回值包含了无效部分**：
   - ✗ `return nums.size()` → 没有修改原始大小
   - ✓ `return slow`（或 `slow + 1`，取决于 slow 的定义）

## 面试追问

**Q1: 如果改成"每个元素最多出现 k 次"呢？**
> 通用模板中把 2 替换成 k：`if (slow < k || num != nums[slow - k])`。这就是这个模板的威力——一行改动适配所有 k。

**Q2: 如果数组是无序的，怎么处理？**
> 两种方案：1) 先排序 O(n log n)，然后用本题的方法；2) 用 unordered_map 计数，如果某个元素已经出现了 k 次就跳过，O(n) 时间 O(n) 空间。面试中两种都提一下。

**Q3: 能否不修改原数组，返回一个新数组？**
> 可以，但需要 O(n) 额外空间。实际上这道题的难点就在于"原地操作 + O(1) 空间"。

**Q4: 这个模板为什么是正确的？能证明吗？**
> 归纳法：假设 `nums[0..slow-1]` 是有效的（每个值最多 k 次），新来的 `num` 等于 `nums[slow-k]` 意味着从 `slow-k` 到 `slow-1` 这 k 个位置全是同一个值（因为有序），已经满了。不等于则安全写入，保持不变量。

**Q5: 双指针写法和 STL 的 remove/unique 有什么关系？**
> `std::unique` 就是 k=1 的版本——它用一个读指针和一个写指针，只保留不同于前一个的元素。我们的通用模板是 `std::unique` 的泛化版本。
