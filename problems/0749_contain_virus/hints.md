# 749. 隔离病毒

## 核心思路

这是一道**模拟 + BFS/DFS + 贪心**的综合题。每天需要：
1. 用 BFS/DFS 找到所有独立的感染区域
2. 计算每个区域会威胁的**未感染邻居数量**（去重）
3. 对威胁最大的区域建墙隔离（标记为已隔离）
4. 剩余未隔离区域扩散到相邻未感染格子
5. 重复直到没有可扩散的区域或所有格子都被感染

关键洞察：这不是求最优策略，而是**贪心模拟**一个确定性的过程（每天隔离威胁最大的区域）。

## 思维链

1. **找连通区域**：用 BFS/DFS 找所有值为 1 的连通分量
2. **统计威胁**：对每个区域，找其相邻的值为 0 的格子（用 set 去重）
3. **统计墙数**：每个区域与未感染格子相邻的边数（不去重！一个 0 可能被同一区域的多个 1 相邻）
4. **贪心选择**：选择威胁最多未感染格子的区域
5. **隔离操作**：将该区域标记为已隔离（值设为 -1 或 2），墙数累加
6. **病毒扩散**：其他未隔离区域向相邻的 0 格子扩散（值变为 1）
7. **循环终止**：当没有活跃的感染区域，或所有区域都已隔离/扩散完毕

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| BFS 模拟 + 贪心 | O((m*n)^2) | O(m*n) | 标准做法，每轮 BFS 遍历全图 |
| DFS 模拟 + 贪心 | O((m*n)^2) | O(m*n) | 用 DFS 代替 BFS，递归实现 |

## 关键提示

1. **威胁数 vs 墙数的区别**：
   - **威胁数**（用于选择哪个区域隔离）：该区域能接触到多少个**不同的**未感染格子（set 去重）
   - **墙数**（用于计算答案）：该区域与未感染格子之间的**边数**（不去重！同一个 0 格子可能被多面墙围住）
2. **已隔离区域不参与后续**：被隔离的区域不再扩散，不参与后续计算
3. **扩散发生在隔离之后**：每天先隔离一个区域，然后其余区域扩散
4. **可能全部感染**：如果无法阻止所有病毒扩散，返回已安装的墙总数
5. **区域可能合并**：扩散后，原本独立的两个区域可能合并为一个

## 解法详解

### 解法一：BFS 模拟 + 贪心（推荐）

**每轮（每天）的操作**：

**步骤 1 - 找所有感染区域**：
- 遍历整个 grid，对每个未访问的值为 1 的格子，做 BFS
- 记录该区域的所有格子、威胁的未感染邻居（set 去重）、需要的墙数

**步骤 2 - 选择威胁最大的区域**：
- 比较所有区域的威胁邻居数量
- 选最大的那个

**步骤 3 - 隔离该区域**：
- 将该区域所有格子标记为 -1（表示已隔离，不再参与）
- 累加该区域的墙数到答案

**步骤 4 - 扩散其他区域**：
- 对所有**未被隔离**的区域，将其威胁的未感染邻居全部设为 1

**步骤 5 - 检查终止条件**：
- 如果本轮没有活跃区域（所有区域都被隔离或不存在），结束
- 如果只有一个区域且被隔离了，也结束

**数据结构设计**：
```
struct Region {
    vector<pair<int,int>> cells;      // 该区域的所有感染格子
    set<pair<int,int>> threatened;     // 威胁的未感染格子（去重）
    int wallCount;                     // 隔离需要的墙数
};
```

### 墙数计算详解

墙数 != 威胁的格子数。例如：
```
1 1
1 0
```
这里 0 被三个 1 包围，威胁格子数 = 1，但墙数 = 3（三条边）。

计算方法：BFS/DFS 时，每当从一个感染格子走到一个未感染格子，墙数 +1。

## 易错点

1. **墙数 vs 威胁数混淆**：选择区域用威胁数（set 去重），计算答案用墙数（不去重）。这是本题最核心的陷阱
2. **忘记标记已隔离区域**：已隔离的区域（值设为 -1 或特殊值）不应该在后续轮次中被重新统计
3. **扩散时序错误**：必须先完成隔离，再让其他区域扩散。不能边隔离边扩散
4. **扩散不应影响本轮**：扩散时新增的感染格子不应在当轮被其他区域当作扩散目标（但实际上用 set 记录后统一设置就没这个问题）
5. **visited 重置**：每轮的 visited 数组必须重新初始化
6. **终止条件不完整**：不仅要检查是否还有感染区域，还要检查是否还有可扩散的空间
7. **一个 0 被多个区域威胁**：同一个 0 格子可能被多个不同区域威胁，需要正确分配给各个区域的 threatened set

## 面试追问

1. **Q: 时间复杂度为什么是 O((m*n)^2)？**
   A: 每轮 BFS 是 O(m*n)。最多进行 O(m*n) 轮（最多 m*n/2 个独立区域被逐个隔离），所以总计 O((m*n)^2)。

2. **Q: 能否优化到比 O((m*n)^2) 更好？**
   A: 理论上可以用 Union-Find 增量维护连通分量，但实现复杂度极高且常数大，面试中不建议。

3. **Q: 如果允许每天隔离多个区域呢？**
   A: 那就变成了优化问题（类似背包），需要贪心或 DP 来决定每天隔离哪些区域。

4. **Q: 如何处理区域合并？**
   A: 每轮重新做 BFS 找连通分量，自动处理合并。不需要增量维护。

5. **Q: 墙是建在边上还是格子上？**
   A: 建在两个格子的**共享边界**上。一个格子最多有 4 面墙。墙只阻挡一条边。

6. **Q: 如果 grid 非常大（1000x1000），这个算法还适用吗？**
   A: O((m*n)^2) 在 10^6 规模下会超时。需要优化：例如只重新检查上一轮扩散影响到的区域，用增量式 BFS。
