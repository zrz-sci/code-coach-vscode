# 541. 反转字符串 II

## 核心思路

这道题本质上就是一个**模拟题**：按固定步长 `2k` 遍历字符串，在每个 `2k` 的窗口中只反转前 `k` 个字符。关键是把规则理清楚，正确处理末尾不足 `k` 或不足 `2k` 的边界情况。

## 思维链

1. **读完题第一反应**：每 `2k` 个字符为一组，反转每组的前 `k` 个。那我只要以步长 `2k` 遍历，对每个起点 `i` 反转 `[i, i+k-1]` 就行了。

2. **边界怎么处理？** 题目说了两种情况，但仔细想一下：
   - 剩余 `< k` 个：反转全部剩余 → 反转 `[i, n-1]`
   - 剩余 `>= k` 且 `< 2k`：反转前 `k` 个 → 反转 `[i, i+k-1]`
   
   这两种情况可以**统一**：反转的右端点是 `min(i + k - 1, n - 1)`，即"要么反转 k 个，要么反转到末尾"。

3. **反转操作本身**：就是经典的双指针交换，左指针从头、右指针从尾，向中间靠拢。也可以直接用 `std::reverse`。

4. **整合**：以 `2k` 为步长的 for 循环 + 每步一个反转操作，一共就几行代码。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 模拟（手写双指针反转） | 步长 2k 遍历 + 双指针反转 | O(n) | O(1) | ⭐ 必须写出 |
| 模拟（使用 std::reverse） | 步长 2k 遍历 + STL 反转 | O(n) | O(1) | 能说出即可 |

> 这道题没有"暴力→优化"的过程，因为模拟本身就是 O(n)。重点是代码写得简洁、边界处理正确。

## 关键提示

1. **步长是 `2k` 不是 `k`**：for 循环的增量是 `i += 2*k`，每一步只处理前 `k` 个的反转，后 `k` 个保持不变。

2. **边界统一处理**：反转区间的右端点用 `min(i + k - 1, n - 1)` 或 `min(i + k, n)`（取决于你用闭区间还是开区间），就不需要分三种情况讨论了。

3. **画图理解 `2k` 窗口**：
   ```
   s = "a b c d e f g",  k = 2
   
   窗口1: [a b | c d]   反转前2个 → "b a c d"
           ^^^   ~~~
           反转   保持
   
   窗口2: [e f | g]     反转前2个 → "f e g"
           ^^^   ~
           反转   保持（不足2k但>=k）
   
   结果: "b a c d f e g"
   ```

4. **如果 k 比字符串还长？** 那就反转整个字符串，`min` 操作自然处理了这个情况。

## 解法详解

### 解法1: 模拟 + 手写双指针反转 — O(n) / O(1) ⭐ 面试首选

**思考过程**：这道题的核心就是"按规则反转"，没有什么算法技巧。关键是把循环结构和边界处理写对。我们以 `2k` 为步长遍历，每次确定需要反转的区间 `[left, right]`，然后用双指针交换。

```cpp
class Solution {
public:
    string reverseStr(string s, int k) {
        int n = s.size();
        for (int i = 0; i < n; i += 2 * k) {
            // 确定反转区间：从 i 开始，最多反转 k 个字符
            // 如果剩余不足 k 个，就反转到末尾
            int left = i;
            int right = min(i + k - 1, n - 1);
            
            // 双指针反转 [left, right]
            while (left < right) {
                swap(s[left], s[right]);
                left++;
                right--;
            }
        }
        return s;
    }
};
```

**关键点**：
- `right = min(i + k - 1, n - 1)` 这一行是整个解法的精髓，统一处理了"剩余 < k"和"剩余 >= k"两种情况。
- 双指针反转是基本功，面试中要求手写不使用 STL。

### 解法2: 模拟 + std::reverse — O(n) / O(1)

**思路**：和解法1完全一样的循环结构，只是把手写反转换成 `std::reverse`。代码更简洁，但面试中可能被要求手写。

```cpp
class Solution {
public:
    string reverseStr(string s, int k) {
        int n = s.size();
        for (int i = 0; i < n; i += 2 * k) {
            // reverse 接受 [begin, end) 左闭右开区间
            // 反转从 i 开始的 min(k, n-i) 个字符
            reverse(s.begin() + i, s.begin() + min(i + k, n));
        }
        return s;
    }
};
```

**关键点**：
- `std::reverse` 用的是**左闭右开**区间 `[begin, end)`，所以右端点是 `min(i + k, n)` 而不是 `min(i + k - 1, n - 1)`。
- 注意：`i + k` 可能超过 `n`，所以必须取 `min`。

## 解法对比

| | 解法1（手写反转） | 解法2（STL reverse） |
|---|---|---|
| 时间复杂度 | O(n) | O(n) |
| 空间复杂度 | O(1) | O(1) |
| 代码量 | 稍多 | 最简洁 |
| 面试推荐 | ✅ 展示基本功 | ✅ 快速写完后可能被追问手写 |

> 实际面试建议：先用 STL 快速写出正确解法，如果面试官追问"不用 STL 怎么写"，再切换到手写双指针。

## 易错点

1. **步长写成 `k` 而不是 `2k`**：
   - ✗ `for (int i = 0; i < n; i += k)` → 每 k 个都反转了，后 k 个本该保持不变
   - ✓ `for (int i = 0; i < n; i += 2 * k)` → 每 2k 步才处理一次

2. **闭区间 vs 开区间搞混**：
   - ✗ `reverse(s.begin() + i, s.begin() + min(i + k - 1, n - 1))` → 少反转了一个字符（reverse 用左闭右开）
   - ✓ `reverse(s.begin() + i, s.begin() + min(i + k, n))` → 左闭右开

3. **手写反转时 `left < right` 写成 `left <= right`**：
   - 功能上没 bug（`left == right` 时 swap 自己无影响），但不够精确。习惯用 `<` 更清晰。

4. **忘记处理剩余不足 k 的情况**：
   - ✗ `int right = i + k - 1;` → 当最后一段不足 k 时，right 越界
   - ✓ `int right = min(i + k - 1, n - 1);`

## 面试追问

**Q1: 这道题的时间复杂度为什么是 O(n) 而不是 O(n/k × k)?**
→ O(n/k × k) 化简就是 O(n)。虽然外层循环 n/(2k) 次、内层反转最多 k 个字符，但每个字符最多被访问一次（被反转或被跳过），所以总共是 O(n)。

**Q2: 如果要求"每 2k 个字符反转后 k 个"而不是前 k 个呢？**
→ 只需把反转区间改为 `[i + k, min(i + 2k - 1, n - 1)]`，循环结构不变。

**Q3: 如果 k 为 0 怎么处理？**
→ 题目约束 `k >= 1` 所以不会出现，但如果面试中被问到，需要特判 `k == 0` 直接返回原字符串（否则 `i += 0` 会死循环）。

**Q4: 能否不修改原字符串，返回新字符串？**
→ 可以，但会多用 O(n) 空间。C++ 的 string 是值语义，参数如果不是引用传递，本身就是拷贝。当前解法是原地修改，空间最优。
