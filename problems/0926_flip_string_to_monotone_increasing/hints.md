# 926. 将字符串翻转到单调递增

## 核心思路

对于每个位置 `i`，想象在这里"切一刀"：左边全是 0，右边全是 1。左边原有的 1 需要翻转为 0，右边原有的 0 需要翻转为 1。**前缀和**可以 O(1) 计算任意切分点的翻转次数。或者用**动态规划**跟踪"到当前位置为止，以 0 结尾 / 以 1 结尾的最小翻转数"。

## 思维链

1. **读完题第一反应**：单调递增的二进制字符串 = 若干个 0 后面跟若干个 1（可能全 0 或全 1）。需要找到最优的"分界点"，使得翻转次数最少。

2. **暴力想法**：枚举分界点 `k`（0 <= k <= n），位置 [0, k-1] 全变 0，位置 [k, n-1] 全变 1。翻转次数 = [0, k-1] 中 1 的个数 + [k, n-1] 中 0 的个数。用前缀和 O(1) 计算每个切分点。

3. **前缀和方法**：设 `prefix[i]` = s[0..i-1] 中 1 的个数。则：
   - 左边 [0, k-1] 中 1 的个数 = prefix[k]
   - 右边 [k, n-1] 中 0 的个数 = (n - k) - (prefix[n] - prefix[k])
   - 总翻转 = prefix[k] + (n - k) - (prefix[n] - prefix[k]) = 2*prefix[k] - k + n - prefix[n]
   
   枚举 k 从 0 到 n，取最小值。

4. **DP 方法**：更优雅。定义：
   - `ones`：到当前位置为止已经遇到的 1 的个数
   - `flips`：到当前位置为止使字符串单调递增所需的最小翻转数
   
   遇到 '0' 时：要么把它翻成 1（flips + 1），要么保留它但把前面所有的 1 都翻成 0（ones 次翻转）→ `flips = min(flips + 1, ones)`
   遇到 '1' 时：直接保留，不需要翻转 → `ones++`

5. **为什么 DP 是对的？** `flips` 始终记录"让 s[0..i] 单调递增的最小翻转数"。每遇到一个 '0'，有两个选择：翻这个 0（代价 flips+1），或者把前面所有 1 翻掉让这个 0 合法（代价 ones）。取较小的那个。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 前缀和枚举分界点 | 枚举 0/1 分界位置，前缀和计算翻转数 | O(n) | O(n) 或 O(1) | 直觉解法 |
| DP (ones + flips) | 维护遇到的 1 数量和当前最小翻转数 | O(n) | O(1) | ⭐ 面试首选 |

> 两种解法时间复杂度相同，DP 更简洁且空间 O(1)。

## 关键提示

1. **"单调递增"等价于"0全在左，1全在右"** — 不需要想复杂，就是找一个分界点：左边全 0，右边全 1。

2. **DP 状态转移的直觉** — 遇到 '1' 不用管（它天然可以放在右边）。遇到 '0' 是矛盾点：要么翻这个 0（把它变成 1 融入右半边），要么把之前遇到的所有 1 翻掉（让它们变成 0，当前的 0 可以待在左半边）。

3. **ones 的含义** — 记录"到目前为止如果要把所有 1 都翻成 0 需要多少次"。它是"推倒重来"选项的成本。

4. DP 过程示意：
```
s = "010110"
        ones  flips
初始:   0     0
s[0]='0': min(0+1, 0) = 0  → flips=0, ones=0
s[1]='1': ones=1            → flips=0, ones=1
s[2]='0': min(0+1, 1) = 1  → flips=1, ones=1
s[3]='1': ones=2            → flips=1, ones=2
s[4]='1': ones=3            → flips=1, ones=3
s[5]='0': min(1+1, 3) = 2  → flips=2, ones=3

答案: flips = 2 ✓ (翻成 011111 或 000111)
```

## 解法详解

### 解法1: 前缀和枚举分界点 — O(n) / O(n)

**思考过程**：

枚举分界点 k：s[0..k-1] 全变 0，s[k..n-1] 全变 1。用前缀和快速计算每个 k 的翻转代价。

```cpp
class Solution {
public:
    int minFlipsMonoIncr(string s) {
        int n = s.size();
        // prefix[i] = s[0..i-1] 中 '1' 的个数
        vector<int> prefix(n + 1, 0);
        for (int i = 0; i < n; i++) {
            prefix[i + 1] = prefix[i] + (s[i] == '1');
        }
        
        int result = n; // 最坏情况: 全部翻转
        
        for (int k = 0; k <= n; k++) {
            // 左边 [0, k-1] 中 1 的个数 = prefix[k] → 需要翻成 0
            int leftOnes = prefix[k];
            // 右边 [k, n-1] 中 0 的个数 → 需要翻成 1
            int rightZeros = (n - k) - (prefix[n] - prefix[k]);
            result = min(result, leftOnes + rightZeros);
        }
        
        return result;
    }
};
```

**关键点**：
- k=0 表示全部变成 1（翻转所有 0）。
- k=n 表示全部变成 0（翻转所有 1）。
- 中间的 k 就是最优分界点。

### 解法2: DP (ones + flips) — O(n) / O(1) ⭐ 面试首选

**思考过程**：

维护两个变量：
- `ones`：到当前位置遇到的 1 的数量
- `flips`：使 s[0..i] 单调递增的最小翻转数

```cpp
class Solution {
public:
    int minFlipsMonoIncr(string s) {
        int ones = 0;   // 到目前为止遇到的 '1' 的数量
        int flips = 0;  // 到目前为止使字符串单调递增的最小翻转数
        
        for (char c : s) {
            if (c == '1') {
                // 遇到 '1': 它可以直接放在"1区间"
                // 不需要翻转，但要更新 ones 计数
                ones++;
            } else {
                // 遇到 '0': 两种选择
                // 选项A: 把这个 0 翻成 1 (代价: flips + 1)
                // 选项B: 保留这个 0，把前面所有 1 翻成 0 (代价: ones)
                flips = min(flips + 1, ones);
            }
        }
        
        return flips;
    }
};
```

**关键点**：
- 遇到 '1' 只增加 ones 计数，不增加 flips — 因为 1 放在右边是合法的。
- 遇到 '0' 时的 `min(flips+1, ones)` 是核心：要么延续之前的方案再多翻一个 0，要么"推倒重来"把所有已知的 1 翻掉。
- 最终 `flips` 就是答案。

## 解法对比

| 维度 | 前缀和 | DP (ones + flips) |
|------|--------|-------------------|
| 时间 | O(n) | O(n) |
| 空间 | O(n) 前缀数组 | O(1) |
| 遍历次数 | 两次（建前缀和 + 枚举） | 一次 |
| 代码长度 | 稍长 | 极短 |
| 直觉难度 | 容易理解（枚举分界点） | 需要理解状态含义 |

## 易错点

1. **前缀和中 k 的范围**：
   - ✗ k 从 1 到 n-1 → 漏了"全 0"和"全 1"的情况
   - ✓ k 从 0 到 n（包含两端）

2. **DP 中遇到 '1' 也更新 flips**：
   - ✗ `flips = min(flips, ones)` 在 c=='1' 时也执行 → 错误地减少了 flips
   - ✓ 遇到 '1' 只更新 ones，不动 flips

3. **min 的两个选项理解错误**：
   - ✗ `min(flips, ones + 1)` → ones+1 不是正确的"推倒重来"代价
   - ✓ `min(flips + 1, ones)` → flips+1 是"翻当前 0"，ones 是"翻前面所有 1"

4. **忘记 ones 是持续累加的**：
   - ✗ 每次遇到 '0' 重置 ones → 丢失了前面的 1 计数
   - ✓ ones 只在遇到 '1' 时增加，永远不减

## 面试追问

**Q1: DP 方法中 flips 的含义能更精确地描述吗？**

> `flips` 在处理完 s[0..i] 后，表示"使 s[0..i] 变成单调递增所需的最小翻转次数"。但注意，它隐含地包含了"最终字符串末尾可以是 0 或 1"这两种子状态的最优值。严格的二维 DP 会定义 dp[i][0] 和 dp[i][1]（以 0 结尾 / 以 1 结尾的最小翻转数），但本题可以压缩成一维：flips = min(dp[i][0], dp[i][1])。

**Q2: 能否用二维 DP 更清晰地解？**

> 定义 dp[i][0] = 使 s[0..i] 以 0 结尾且单调递增的最小翻转数，dp[i][1] = 以 1 结尾的最小翻转数。转移：
> - dp[i][0] = dp[i-1][0] + (s[i]=='1' ? 1 : 0)  // 只能从 0 转来
> - dp[i][1] = min(dp[i-1][0], dp[i-1][1]) + (s[i]=='0' ? 1 : 0)  // 从 0 或 1 都行
> 答案 = min(dp[n-1][0], dp[n-1][1])。ones+flips 方法是这个二维 DP 的压缩形式。

**Q3: 前缀和方法和 DP 方法本质上是否等价？**

> 是的。前缀和枚举分界点 k 时，`leftOnes = prefix[k]` 对应 DP 中"把前面 1 翻掉"的代价，`rightZeros` 对应"把后面 0 翻掉"的代价。DP 方法是从左到右逐步更新最优分界点，避免了存储完整前缀和数组。两者数学上等价，DP 更省空间。
