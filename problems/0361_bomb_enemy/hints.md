# 361. 轰炸敌人

## 题目理解

给定 `m x n` 矩阵，每个格子是墙 `'W'`、敌人 `'E'` 或空地 `'0'`。在一个空地放炸弹，能炸死同行同列的敌人（遇墙停止）。求一颗炸弹最多能杀多少敌人。

**本质**：这是"分段计数 + 行列分解"问题。炸弹的杀伤力被墙分隔成独立区段，关键是如何高效计算每个空格位置在行方向和列方向分别能炸到的敌人数。

```
示例: grid = [["0","E","0","0"],["E","0","W","E"],["0","E","0","0"]]
输出: 3
解释: 在 (1,1) 放炸弹，可炸死 (0,1)+(1,0)+(2,1) = 3个敌人
```

---

## 解法概览

| 解法 | 思路 | 时间复杂度 | 空间复杂度 | 推荐度 |
|------|------|-----------|-----------|--------|
| ⭐ 行列分段缓存 | 遇墙重算行/列敌人数 | O(m * n) | O(n) | 面试首选 |
| 预处理四方向 | 4个DP数组记录四方向敌人数 | O(m * n) | O(m * n) | 直观但费空间 |
| 暴力扩展 | 每个空格四方向扫描 | O(m * n * (m+n)) | O(1) | 不推荐 |

## 渐进提示

### 提示 1 -- 暴力思路

对每个空格 `'0'`，向上下左右四个方向扫描，遇到 `'E'` 计数，遇到 `'W'` 或边界停止。取所有空格的最大值。

<details>
<summary>展开</summary>

```
对于位置 (r, c) 且 grid[r][c] == '0':
  count = 0
  向左扫: c' = c-1, c-2, ... 直到 W 或边界，数 E
  向右扫: c' = c+1, c+2, ... 直到 W 或边界，数 E
  向上扫: r' = r-1, r-2, ... 直到 W 或边界，数 E
  向下扫: r' = r+1, r+2, ... 直到 W 或边界，数 E
```

时间 O(m * n * (m+n))，太慢。

**关键观察**：同一行中，两堵墙之间的空格共享相同的行方向敌人数！

</details>

### 提示 2 -- 行方向的分段思想

同一行中两堵墙之间构成一个"区段"，这个区段内所有空格的行方向敌人数是一样的。

<details>
<summary>展开</summary>

```
行: E 0 W E 0 0
    |-----|   |------|
    区段1     区段2

区段1: 有1个E，区段内任何位置行方向炸到1个敌人
区段2: 有1个E，区段内任何位置行方向炸到1个敌人
```

**什么时候需要重新计算行方向敌人数？**
- 当前位置在行的第一列（j == 0）
- 或者左边那个格子是墙（grid[i][j-1] == 'W'）

此时从当前位置向右扫描直到墙/边界，统计 E 的数量。之后同区段内的格子直接复用这个值。

</details>

### 提示 3 -- 列方向也类似

<details>
<summary>展开</summary>

列方向同理：同一列两堵墙之间的空格共享列方向敌人数。

**什么时候重新计算列方向敌人数？**
- 当前位置在第一行（i == 0）
- 或者上面那个格子是墙（grid[i-1][j] == 'W'）

需要为每一列维护一个 `colHits[j]`，记录当前区段的列方向敌人数。

```
遍历顺序: 逐行逐列 (i, j)

rowHits: 一个变量，当前行区段的敌人数
colHits[j]: 第j列当前区段的敌人数

if j==0 或 grid[i][j-1]=='W':
    rowHits = 从 (i,j) 向右数 E
if i==0 或 grid[i-1][j]=='W':
    colHits[j] = 从 (i,j) 向下数 E

if grid[i][j]=='0':
    ans = max(ans, rowHits + colHits[j])
```

</details>

### 提示 4 -- 完整算法与复杂度

<details>
<summary>展开</summary>

看似有嵌套循环（重算时要向右/下扫描），但每个格子在行方向最多被扫描2次（作为起点扫和作为被扫对象），列方向也一样。

**摊还分析**：每个格子在行方向的扫描次数 = 恰好被"重算"覆盖1次 + 扫描时经过1次 = O(1) 摊还。总时间 O(m * n)。

空间只需 O(n) 的 `colHits` 数组 + 一个 `rowHits` 变量。

</details>

## 关键思维模式

### 1. "分段缓存"模式

墙把行/列分成独立区段，同区段内共享结果。核心技巧：

```
if (需要重算的条件):
    hits = 从当前位置扫描统计
// 否则复用上次计算的 hits
```

### 2. "行列分解"模式

二维方向的计数 = 行方向 + 列方向。分别独立计算再合并。

### 3. 摊还复杂度分析

虽然有重算循环，但每个元素最多被扫描常数次，总体 O(mn)。

## 完整代码 (C++)

```cpp
class Solution {
public:
    int maxKilledEnemies(vector<vector<char>>& grid) {
        int m = grid.size(), n = grid[0].size();
        int ans = 0;
        int rowHits = 0;
        vector<int> colHits(n, 0);

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                // 行方向: 新区段起点 -> 重算
                if (j == 0 || grid[i][j - 1] == 'W') {
                    rowHits = 0;
                    for (int k = j; k < n && grid[i][k] != 'W'; k++) {
                        if (grid[i][k] == 'E') rowHits++;
                    }
                }
                // 列方向: 新区段起点 -> 重算
                if (i == 0 || grid[i - 1][j] == 'W') {
                    colHits[j] = 0;
                    for (int k = i; k < m && grid[k][j] != 'W'; k++) {
                        if (grid[k][j] == 'E') colHits[j]++;
                    }
                }
                // 空格: 统计能炸到的敌人总数
                if (grid[i][j] == '0') {
                    ans = max(ans, rowHits + colHits[j]);
                }
            }
        }
        return ans;
    }
};
```

## 算法图解

```
grid:  0  E  0  0        rowHits / colHits[j] 计算过程:
       E  0  W  E
       0  E  0  0

行方向 (按区段):
  行0: [0,E,0,0] -> 整行一个区段, rowHits=1(一个E)
  行1: [E,0] [W] [E] -> 区段1: rowHits=1, 区段2(墙后): rowHits=1
  行2: [0,E,0,0] -> 整行一个区段, rowHits=1

列方向 (按区段):
  列0: [0,E,0] -> 整列一个区段, colHits[0]=1
  列1: [E,0,E] -> 整列一个区段, colHits[1]=2
  列2: [0,W,0] -> 区段1: colHits[2]=0, 区段2(墙下): colHits[2]=0
  列3: [0,E,0] -> 整列一个区段, colHits[3]=1

位置(1,1): grid=='0', rowHits=1, colHits[1]=2
           total = 1 + 2 = 3 ★ 最大值!
```

## 常见错误

| 错误写法 | 正确写法 | 说明 |
|---------|---------|------|
| ✗ 每次都重新扫描行/列 | ✓ 只在区段起点重新计算 | 暴力 O(mn(m+n)) vs 优化 O(mn) |
| ✗ `if (j == 0 \|\| grid[i][j] == 'W')` | ✓ `if (j == 0 \|\| grid[i][j-1] == 'W')` | 条件是**前一个**是墙，不是当前 |
| ✗ 忘记在 `grid[i][j]=='0'` 时才统计 | ✓ 只在空格位置更新答案 | 炸弹只能放在空地 |
| ✗ colHits 在每行重新初始化 | ✓ colHits 跨行保持，只在列区段起点重算 | 列缓存需要跨行复用 |

## 面试追问

**Q1: 预处理四方向DP方法怎么做？**
> 建4个 m x n 矩阵 `left[i][j]`, `right[i][j]`, `up[i][j]`, `down[i][j]`，分别记录从四个方向到当前位置能炸到的敌人数。每个方向一次线性扫描。最后对每个空格取四方向之和。时间 O(mn)，空间 O(mn)。分段缓存法的优势是空间只需 O(n)。

**Q2: 如果有多颗炸弹呢？**
> 多颗炸弹且互不影响：贪心选 top-k 即可。如果炸弹能摧毁敌人改变格局：变成更复杂的搜索/DP 问题。面试一般不会追问这么深。

**Q3: 为什么摊还是 O(mn) 而不是 O(mn * max(m,n))？**
> 行方向：每行的每个元素在"重算"的内循环中最多被访问一次（从区段起点向右扫描，每个元素只属于一个区段）。列方向同理。因此行方向总扫描量 = O(mn)，列方向也是 O(mn)，总计 O(mn)。
