# 685. Redundant Connection II - 冗余连接 II

## 难度：Hard

## 标签：Union Find, Graph, DFS

---

## 核心思路

有向图中，一棵合法的有根树满足：(1) 恰好 n-1 条边，(2) 除根外每个节点恰好有一个父节点（入度为 1），(3) 无环。现在多了一条边，导致要么某个节点入度变为 2，要么出现有向环，要么两者兼有。通过**入度分析 + 并查集检测环**的组合策略，可以精确定位该删除哪条边。

---

## 思维链

1. 有根树中，根的入度为 0，其余节点入度为 1。多加一条边后，要么某个节点入度变为 2，要么形成了环（所有节点入度都为 1 但构成环路）。
2. 先扫描所有边，检查是否存在入度为 2 的节点。如果有，记录指向它的两条候选边。
3. 如果不存在入度为 2 的节点，则问题退化为无向图找环（同 LC 684），直接用并查集找到成环的那条边。
4. 如果存在入度为 2 的节点，先假设删除后出现的那条候选边（cand2），用并查集检测剩余图是否合法：
   - 合法 → cand2 就是答案
   - 仍有环 → 说明 cand1 在环上，cand1 才是答案
5. 这个"先试删 cand2"的贪心策略保证了在有多个合法答案时返回最后出现的边。

---

## 解法概览

| 解法 | 时间 | 空间 | 特点 |
|------|------|------|------|
| 并查集 + 入度分析 | O(n * α(n)) ≈ O(n) | O(n) | 经典做法，三种情况合一处理 |
| 拓扑排序 + 入度 | O(n) | O(n) | 先找环再分析入度，代码更长 |

## 关键提示

### 提示 1 - 与 LC 684 的本质区别
LC 684 是无向图，只需找成环的那条边。LC 685 是有向图，除了环还需要考虑"双父节点"问题。有向边 `u → v` 表示 u 是 v 的父节点。

### 提示 2 - 三种异常情况
多加一条边恰好对应三种互斥情况：
- **Case A**：有节点入度为 2，无环 → 删除指向该节点的两条边中后出现的
- **Case B**：有节点入度为 2，且有环 → 删除指向该节点的两条边中在环上的那条
- **Case C**：无节点入度为 2，但有环 → 用并查集找成环边

### 提示 3 - 为什么试删 cand2 能区分 Case A 和 Case B
如果删除 cand2 后，剩余的 n-1 条边能形成合法树（并查集无环），说明 cand2 就是多余的（Case A）。如果删除 cand2 后仍有环，说明 cand1 实际在环路上，必须删 cand1（Case B）。

### 提示 4 - 并查集处理有向边
虽然边是有向的，但并查集合并时忽略方向，仅用于检测是否成环。方向信息已经在入度分析阶段被利用了。

### 提示 5 - "最后出现"规则
题目要求有多个答案时返回数组中最后出现的。我们的策略天然满足：cand2 在 cand1 之后出现，优先尝试删 cand2；Case C 中并查集按顺序扫描，最后成环的边一定是序列中最后一条造成环的。

## 解法详解

### 并查集 + 入度分析

**第一步：扫描入度**
遍历所有边 `edges[i] = (u, v)`，记录每个节点 v 的入边索引。如果某个节点 v 已经有一条入边，说明 v 入度为 2，记录候选边 cand1（先出现的边）和 cand2（后出现的边）。

**第二步：并查集验证**
- 若存在 cand2：跳过 cand2，将剩余边逐条用并查集合并
  - 合并过程中发现环 → 返回 cand1
  - 全部合并无环 → 返回 cand2
- 若不存在 cand2：所有边依次用并查集合并，合并失败的那条边就是答案

**并查集实现要点：**
- 使用路径压缩 + 按秩合并
- `find(x)` 返回 x 的根，同时路径压缩
- `unite(x, y)` 返回是否成功（false 表示 x、y 已连通，即成环）

```
初始: parent[i] = i

对于每条边 (u, v):
  若 find(u) == find(v) → 成环
  否则 parent[find(v)] = find(u)
```

---

## 易错点

1. **cand1 和 cand2 的顺序不能搞反**：cand1 是先出现的边（inEdge 中已记录的），cand2 是后出现的。试删应该先试 cand2。
2. **并查集初始化范围**：节点编号从 1 到 n，不要遗漏边界。
3. **跳过 cand2 的时机**：在并查集合并阶段跳过，而不是在入度扫描阶段就删除它。
4. **仅入度为 2 的节点最多一个**：因为只多了一条边，所以最多只有一个节点入度为 2（不可能出现两个）。
5. **不要混淆有向和无向**：并查集检测的是"连通性意义上的环"，不是有向环。但由于有根树的特性，两者在此题中等价。

## 面试追问

1. **如果可以删除多条边使图变成有根树，如何返回所有合法方案？**
   → 需要枚举每条边删除后验证是否为合法有根树（检查连通性 + 入度 + 无环），时间 O(n^2)。

2. **如何验证一个有向图是否是合法的有根树？**
   → 恰好 n-1 条边 + 恰好一个入度为 0 的节点（根） + 其余节点入度为 1 + 从根可达所有节点。

3. **如果边有权重，要删除权重最小的冗余边，怎么做？**
   → 在 Case A 中比较两条候选边的权重取小；Case C 中需要找环路上权重最小的边，用 DFS/BFS 找到环后遍历取最小。

4. **并查集的路径压缩和按秩合并分别有什么作用？**
   → 路径压缩使后续查询接近 O(1)；按秩合并保持树的平衡。两者结合使得每次操作均摊 O(α(n))。

5. **能否用 DFS 代替并查集来检测环？**
   → 可以。用有向图的 DFS 检测环（维护访问状态：未访问/访问中/已完成），但代码更复杂且常数更大。
