# 202. 快乐数

## 核心思路

这道题本质上是**检测链表是否有环**的问题：不断对数字做"各位平方和"运算，会形成一条数字序列，这条序列要么最终到达 1（快乐数），要么进入一个不包含 1 的循环（非快乐数）。判断"是否有环"就是核心。

## 思维链

1. **读完题第一反应**：不断算各位平方和，直到变成 1 或者"无限循环"。怎么知道它会无限循环？如果某个数字重复出现了，就说明进入了循环。
2. **朴素做法**：用一个集合记录所有出现过的数字，每次算出新数字就检查是否已出现过。如果出现过且不是 1，就是循环。
3. **这个做法的瓶颈**：需要额外的哈希集合存储所有经过的数字，空间消耗不确定。能否不用额外空间？
4. **联想到快慢指针**：这和"链表判环"是一模一样的结构！数字序列就像链表，`next` 操作就是"算各位平方和"。快指针走两步、慢指针走一步，如果有环一定会相遇。
5. **相遇后判断**：如果相遇点的值是 1，就是快乐数；否则不是。
6. **还有一个数学小知识**：对于 32 位整数，各位平方和最大不超过 9²×10 = 810，所以序列一定会进入一个很小范围内的循环，不会无限增长。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 哈希集合 | 记录出现过的数字，检测重复 | O(log n) | O(log n) | 能说出即可 |
| 快慢指针 | Floyd 判环，无需额外存储 | O(log n) | O(1) | ⭐ 必须写出 |
| 数学硬编码 | 非快乐数一定经过 4，直接判断 | O(log n) | O(1) | 加分项 |

> **时间复杂度说明**：每次 `getNext` 操作是 O(log n)（n 的位数），而序列很快收敛到小范围（<810），后续操作都是常数级别，所以总体 O(log n)。

## 关键提示

1. **提示1**：如果一个数不是快乐数，反复计算各位平方和，序列会怎样？想想"有限集合上的映射一定产生循环"。
2. **提示2**：这个"序列是否进入循环"的问题，你还在哪道题见过类似的结构？（提示：链表）
3. **提示3**：32 位 int 最大约 21 亿（10位数），各位平方和最大 = 9²×10 = 810。这说明什么？序列值的范围是有限的！
4. **提示4**：快慢指针不需要找环的入口，只需要判断"环上是否包含 1"——更简单：如果快指针先到 1，就是快乐数。

```
数字序列可视化 (n = 2):
2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 → ... (循环!)
                                                  ↑______|

数字序列可视化 (n = 19):
19 → 82 → 68 → 100 → 1 → 1 → 1 → ... (到达1，停留)
```

## 解法详解

### 解法1: 哈希集合检测循环 — O(log n) / O(log n)

**思考过程**: 最直觉的想法——怎么判断"无限循环"？如果一个数字之前见过，就说明进入了环。用 HashSet 记录见过的数字即可。

```cpp
class Solution {
public:
    bool isHappy(int n) {
        unordered_set<int> seen;
        while (n != 1) {
            // 如果 n 之前出现过，说明进入了循环，永远不会到 1
            if (seen.count(n)) return false;
            seen.insert(n);
            n = getNext(n);
        }
        return true;
    }
    
private:
    int getNext(int n) {
        int sum = 0;
        while (n > 0) {
            int d = n % 10;     // 取最低位
            sum += d * d;       // 平方后累加
            n /= 10;            // 去掉最低位
        }
        return sum;
    }
};
```

**关键点**: `getNext` 函数是公共模块，所有解法都复用。注意 `n /= 10` 是整数除法，自动截断。

---

### 解法2: 快慢指针 (Floyd 判环) — O(log n) / O(1) ⭐ 面试首选

**从解法1优化**: 解法1 需要 O(log n) 空间存储 seen 集合。如果我们把"数字→下一个数字"看成链表的 `next` 指针，这就是经典的**链表判环问题**，用 Floyd 快慢指针可以 O(1) 空间解决。

```
// 类比链表判环:
// 链表:  node → node.next → node.next.next → ...
// 本题:  n    → getNext(n) → getNext(getNext(n)) → ...
//
// 快指针每次走两步 (算两次 getNext)
// 慢指针每次走一步 (算一次 getNext)
// 如果有环，快慢一定相遇
// 如果到达 1，1 → 1 是"自环"，也会相遇在 1
```

```cpp
class Solution {
public:
    bool isHappy(int n) {
        int slow = n;
        int fast = getNext(n);  // fast 先走一步
        
        // 当 fast 不是 1（还没到终点）且 slow != fast（还没相遇）
        while (fast != 1 && slow != fast) {
            slow = getNext(slow);           // 慢指针走一步
            fast = getNext(getNext(fast));   // 快指针走两步
        }
        
        // 相遇时：如果 fast == 1，说明序列能到达 1
        return fast == 1;
    }
    
private:
    int getNext(int n) {
        int sum = 0;
        while (n > 0) {
            int d = n % 10;
            sum += d * d;
            n /= 10;
        }
        return sum;
    }
};
```

**关键点**: 
- 为什么 `fast == 1` 就够了？因为 `getNext(1) = 1`，1 是一个"自环"。如果 fast 到达 1，它会一直停在 1，slow 最终也会追上来在 1 相遇。所以 `fast == 1` 等价于"序列中包含 1"。
- 初始化 `slow = n, fast = getNext(n)` 避免一开始就 `slow == fast` 导致直接退出循环。

---

### 解法3: 数学方法 — O(log n) / O(1)

**数学观察**: 通过枚举可以发现，所有非快乐数在迭代过程中一定会经过数字 **4**。这是因为 1~810 范围内的所有非快乐数最终都会进入同一个循环：`4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4`。

```cpp
class Solution {
public:
    bool isHappy(int n) {
        while (n != 1 && n != 4) {
            n = getNext(n);
        }
        return n == 1;
    }
    
private:
    int getNext(int n) {
        int sum = 0;
        while (n > 0) {
            int d = n % 10;
            sum += d * d;
            n /= 10;
        }
        return sum;
    }
};
```

**关键点**: 这个解法依赖数学结论（非快乐数必经过 4），面试中如果你能推导出这个结论是加分项，但一般面试官更看重解法2的快慢指针思路。

## 解法对比

| | 哈希集合 | 快慢指针 | 数学方法 |
|---|---|---|---|
| 空间 | O(log n) — 需要 set | **O(1)** — 只用两个变量 | **O(1)** |
| 代码量 | 最少，最直觉 | 稍多，需要理解判环 | 最少，但需要数学结论 |
| 面试推荐 | 作为第一个说的方案 | **追问优化时给出** | 知道即可 |
| 核心技能 | HashSet 使用 | Floyd 判环算法 | 数学分析 |

**选择建议**: 面试时先说哈希集合（30秒讲清楚），然后主动提出"可以用快慢指针优化到 O(1) 空间"。

## 易错点

1. **`getNext` 中忘记处理 n=0 的情况**
   - ✗ 其实不会出错，因为 `while (n > 0)` 对 n=0 直接返回 sum=0。但要意识到题目保证 n ≥ 1，且序列中也不会出现 0（最小是 1²=1）。

2. **快慢指针初始化错误**
   - ✗ `int slow = n, fast = n;` → while 条件 `slow != fast` 一开始就 false，直接退出
   - ✓ `int slow = n, fast = getNext(n);` → 让 fast 先走一步，避免初始相等

3. **快慢指针对 getNext(getNext(fast)) 的安全性**
   - 不用担心！因为 `getNext(1) = 1`，即使 fast 已经到达 1，再调用 getNext 也不会出问题。而且循环条件 `fast != 1` 会在下一轮开始时检查。

4. **误以为需要处理负数**
   - 题目约束 `1 <= n <= 2^31 - 1`，都是正整数，`n % 10` 和 `n / 10` 对正整数没有符号问题。

## 面试追问

**Q1: 为什么序列一定会进入循环，而不是无限增长？**
> 对于 32 位 int，最大 ~2×10⁹（10位数）。各位平方和最大 = 9²×10 = 810。所以第一步之后数字就 ≤ 810。810 以内最大平方和 = 8²+1²+0² = 65。很快就会收敛到一个很小的范围，由鸽巢原理，有限范围内一定产生循环。

**Q2: 能否不用哈希表实现 O(1) 空间？**
> 用 Floyd 快慢指针。把 `n → getNext(n)` 看成链表的 `node → next`，用慢指针走一步、快指针走两步，如果有环一定相遇。如果相遇在 1 就是快乐数。

**Q3: 如果要找出循环中的所有数字呢？**
> 先用快慢指针找到环上任意一点（相遇点），然后从该点出发，一直调用 getNext 直到回到该点，沿途的所有数字就是环上的元素。这和"找链表环的所有节点"是一样的。
