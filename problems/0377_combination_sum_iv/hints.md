# 377. 组合总和 Ⅳ

## 核心思路

这道题的名字叫"组合"，但本质上求的是**排列数**——因为不同顺序算不同方案。它等价于：从 `nums` 中**可重复选取**元素，排成一个序列使总和为 `target`，问有多少种不同序列？这其实是一个**完全背包的排列变体**。

## 思维链

1. **读完题第一反应**：每个数可以用无限次，要求总和为 target。想到用回溯暴力枚举所有可能的序列。
2. **暴力解的瓶颈**：回溯的决策树分支极多，target=1000 时指数级爆炸。但仔细一想——很多子问题是重复的！比如"凑出余额 3"这个子问题会被反复计算。
3. **发现重叠子问题 → DP**：定义 `f(remaining)` = 凑出 `remaining` 的排列数。每次可以选 `nums` 中任意一个 `num`（只要 `num <= remaining`），选完后剩余 `remaining - num`。这就是一个经典的递推关系。
4. **关键区分——排列 vs 组合**：如果是组合（不考虑顺序），外层遍历物品、内层遍历容量；如果是排列（考虑顺序），**外层遍历容量、内层遍历物品**。本题是排列，所以外层 `for i in [1..target]`，内层 `for num in nums`。
5. **状态转移方程**：`dp[i] = Σ dp[i - num]`，对所有 `num ∈ nums` 且 `num <= i`。
6. **初始化**：`dp[0] = 1`（凑出 0 有一种方案：什么都不选）。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 回溯暴力 | DFS 枚举所有序列 | O(指数级) | O(target) | 能说出即可 |
| 记忆化搜索 | 自顶向下 + memo | O(target × n) | O(target) | 能说出即可 |
| 动态规划（递推） | 外层遍历容量，内层遍历物品 | O(target × n) | O(target) | ⭐ 必须写出 |

## 关键提示

1. **顺序敏感 = 排列**：`(1,2,1)` 和 `(2,1,1)` 算两种方案。这意味着对于同一个"余额"，每次都可以从 `nums` 的任意元素重新选起，而不是只能从某个起点之后选。

2. **和完全背包的关系**：完全背包求组合数是"外物品内容量"，求排列数是"**外容量内物品**"。为什么？因为外层遍历容量时，对于每个容量值，所有物品都有机会作为"最后一个被选的"，这就隐含了顺序。

3. **递推方向**：`dp[i]` 依赖所有 `dp[i - num]`，而 `i - num < i`，所以从小到大遍历即可。

4. **溢出提示**：中间结果可能超过 int 范围（虽然最终答案保证在 32 位内），某些测试用例中 `dp[i-num]` 累加可能溢出。实际上 LeetCode 的测试数据保证不会，但严谨做法是在累加前检查。

5. **Follow-up 思考**：如果 `nums` 中有负数，比如 `{-1, 1}`，凑 target=0 可以有无穷多种排列（`-1,1,-1,1,...`）。必须加限制条件，如"序列长度不超过 k"。

## 解法详解

### 解法1: 回溯暴力 — O(指数级) / O(target)

**思考过程**: 最直觉的做法——从 target 出发，每次尝试选 nums 中的每一个数，递归地凑剩余部分。

```
// 决策树 (nums=[1,2,3], target=4):
//                    4
//              /     |     \
//           3(选1)  2(选2)  1(选3)
//          /|\      /|      |
//        2  1  0  1  0      0
//       /|  |    |
//      1  0 0    0
//      |
//      0
// 
// 每到 remaining=0 就找到一个合法序列
// 注意：remaining=1 这个子问题出现了多次！→ 重叠子问题
```

```cpp
class Solution {
public:
    int combinationSum4(vector<int>& nums, int target) {
        if (target == 0) return 1;
        int count = 0;
        for (int num : nums) {
            if (target >= num) {
                count += combinationSum4(nums, target - num);
            }
        }
        return count;
    }
};
```

**关键点**: 会超时（TLE），但帮助理解问题结构。注意 `target=0` 返回 1 而不是 0——这代表"已经恰好凑完"。

---

### 解法2: 记忆化搜索（自顶向下 DP） — O(target × n) / O(target)

**从解法1优化**: 解法1 中 `f(1)`、`f(2)` 等子问题被反复计算。加一个 memo 数组，算过的直接查表。

```cpp
class Solution {
public:
    int combinationSum4(vector<int>& nums, int target) {
        // memo[i] = -1 表示未计算，>= 0 表示已有结果
        vector<int> memo(target + 1, -1);
        return dfs(nums, target, memo);
    }
    
    int dfs(vector<int>& nums, int remaining, vector<int>& memo) {
        if (remaining == 0) return 1;       // 恰好凑完
        if (memo[remaining] != -1) return memo[remaining]; // 已算过
        
        int count = 0;
        for (int num : nums) {
            if (remaining >= num) {
                count += dfs(nums, remaining - num, memo);
            }
        }
        memo[remaining] = count;
        return count;
    }
};
```

**关键点**: memo 初始化为 -1 而不是 0，因为 0 本身是合法的结果值（某些余额可能确实凑不出，结果为 0）。

---

### 解法3: 动态规划（递推，自底向上） — O(target × n) / O(target) ⭐ 面试首选

**从解法2翻译**: 把递归改成 for 循环。`dp[i]` 表示凑出总和 `i` 的排列数。

```
// DP 填表过程 (nums=[1,2,3], target=4):
//
// dp[0] = 1  (base case: 空序列凑出0)
//
// dp[1]: 遍历 nums
//   num=1: dp[1-1]=dp[0]=1  ✓
//   num=2: 2>1 跳过
//   num=3: 3>1 跳过
//   dp[1] = 1               → {1}
//
// dp[2]: 
//   num=1: dp[2-1]=dp[1]=1  → {1,1}
//   num=2: dp[2-2]=dp[0]=1  → {2}
//   num=3: 3>2 跳过
//   dp[2] = 2
//
// dp[3]:
//   num=1: dp[3-1]=dp[2]=2  → {1,1,1}, {1,2} (在dp[2]的序列前加1? 不对——是在末尾加1)
//   num=2: dp[3-2]=dp[1]=1  → {2,1} (不是{1,2}!)
//   num=3: dp[3-3]=dp[0]=1  → {3}
//   dp[3] = 4
//
// dp[4]:
//   num=1: dp[4-1]=dp[3]=4
//   num=2: dp[4-2]=dp[2]=2
//   num=3: dp[4-3]=dp[1]=1
//   dp[4] = 7               ← 最终答案
//
// 填表方向: dp[0] → dp[1] → dp[2] → ... → dp[target]
//           ←───── 每个dp[i]依赖前面的值 ─────→
```

```cpp
class Solution {
public:
    int combinationSum4(vector<int>& nums, int target) {
        vector<int> dp(target + 1, 0);
        dp[0] = 1;  // 凑出0的方式：什么都不选，算1种
        
        // 外层遍历"容量"（排列的关键！）
        for (int i = 1; i <= target; i++) {
            // 内层遍历所有可选物品
            for (int num : nums) {
                if (i >= num) {
                    dp[i] += dp[i - num];
                }
            }
        }
        return dp[target];
    }
};
```

**关键点**:
- **外容量内物品 = 排列**。如果把两层循环反过来（外物品内容量），得到的是组合数——那就变成了 LeetCode 518（零钱兑换 II）。
- `dp[0] = 1` 是数学约定：空序列是凑出 0 的唯一方式。

## 解法对比

| | 回溯暴力 | 记忆化搜索 | 递推 DP |
|---|---|---|---|
| 时间 | 指数级 | O(target × n) | O(target × n) |
| 空间 | O(target) 递归栈 | O(target) memo | O(target) dp数组 |
| 优点 | 直觉、易理解 | 自顶向下，只算需要的子问题 | 无递归开销，代码简洁 |
| 缺点 | 超时 | 递归栈深度 | 需要计算所有 dp[0..target] |
| 面试 | 说思路即可 | 可作为过渡 | ⭐ 首选写法 |

**排列 vs 组合的循环顺序对比**（本题最核心的区分点）：

```
排列（本题 377）:            组合（518 零钱兑换II）:
for i in [1..target]:        for num in nums:
    for num in nums:             for i in [num..target]:
        dp[i] += dp[i-num]          dp[i] += dp[i-num]
```

## 易错点

1. **✗ `dp[0] = 0`** → **✓ `dp[0] = 1`**
   空序列凑出 0 算 1 种方案。如果初始化为 0，所有 dp 值都是 0。

2. **✗ 外层遍历物品，内层遍历容量** → **✓ 外层遍历容量，内层遍历物品**
   循环顺序反了就变成了求组合数（LeetCode 518），不是排列数（本题）。这是最常见的错误。

3. **✗ 忘记判断 `i >= num`** → **✓ 加上 `if (i >= num)`**
   不加判断会数组越界访问 `dp[负数]`。

4. **✗ 记忆化搜索中 memo 初始化为 0** → **✓ 初始化为 -1**
   0 是合法的计算结果（某些 remaining 确实凑不出），用 0 做"未计算"标记会导致重复计算。

## 面试追问

**Q1: 这道题和零钱兑换 II（LeetCode 518）有什么区别？**
→ 518 求的是组合数（不同顺序算同一种），本题求的是排列数（不同顺序算不同种）。区别**仅在循环顺序**：518 是外物品内容量，377 是外容量内物品。

**Q2: 为什么外层遍历容量就能得到排列数？**
→ 因为对于每个容量 `i`，我们遍历所有 `nums` 中的元素作为"序列的最后一个元素"。这意味着 `num=1` 后面可以跟 `num=2`（在 `dp[i-1]` 中已经考虑过 `num=2`），反过来 `num=2` 后面也可以跟 `num=1`。不同顺序自然被计入不同方案。

**Q3 (Follow-up): 如果数组中有负数会怎样？**
→ 如果存在正负数能互相抵消（如 `{-1, 1}`），就能构造出无穷多个序列凑出任意 target。为了使问题有有限解，必须加限制：**序列长度不超过某个上限 k**。此时 DP 需要加一维：`dp[i][j]` = 用恰好 j 个数凑出总和 i 的方案数，最后对 j ∈ [1..k] 求和。
