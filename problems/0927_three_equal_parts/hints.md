# 927. 三等分

[file://./solution.cpp](file://./solution.cpp)

## 核心思路

将一个只含 0 和 1 的数组分成三段，使得每段代表的二进制数值相等。关键洞察：**三段的二进制值相等意味着三段的"有效位模式"（从第一个1到末尾）必须完全相同**，而且三段末尾的0的个数由第三段决定（第三段末尾的0不可调整）。

## 思维链

1. **读完题第一反应** → 三段表示相同的二进制值，首先要搞清楚"相同值"意味着什么。比如 `[0,1,1]` 和 `[1,1]` 是相同的（前导零不影响值），但 `[1,1,0]` 和 `[1,1]` 不同（末尾的0是有效位）。
2. **关键观察：1的个数** → 如果数组中1的总数不能被3整除，直接返回 `[-1,-1]`。因为三段的二进制值相同，那三段中1的个数必须相同。
3. **特殊情况：全0** → 如果没有1，任意分割都有效，直接返回 `[0, 2]`。
4. **确定每段的1的位置** → 找到所有1的位置，将它们平均分成三组。第一组的1在第一段，第二组在第二段，第三组在第三段。
5. **比较位模式** → 从每段的第一个1开始，三段后续的位模式（0和1的排列）必须完全相同。
6. **处理末尾的0** → 第三段末尾的0的个数是固定的（从第三段最后一个1到数组末尾）。第一段和第二段必须有足够的空间容纳同样多的末尾0。这些0来自两段之间的间隔。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 计数1 + 模式匹配 | 按1的位置分段，比较位模式，对齐末尾0 | O(n) | O(1) | 必须掌握 |

## 关键提示

1. **1的总数必须被3整除**：这是最基本的判断条件。如果总数为0，任何分割都可以。
2. **三段的"有效二进制模式"由第三段决定**：因为第三段延伸到数组末尾，它的末尾0个数是固定的。第一段和第二段末尾也要有同样多的0。
3. **找到三段起始位置**：分别找到第 `1, count/3+1, 2*count/3+1` 个1的位置作为三段有效模式的起点。
4. **同步比较**：三个指针从各自段的第一个1开始同步往后走，比较每一位是否相同。
5. **调整分割点**：比较完后，利用第三段末尾0的数量来确定最终的分割索引 `i` 和 `j`。

## 解法详解

### 解法1: 计数1 + 模式匹配 — O(n) / O(1)

**思考过程**: 三段二进制值相等，意味着去掉前导零后的位模式完全相同。所以先统计1的个数，确定每段应该有多少个1，再逐位比较。

**步骤**:
1. 统计数组中1的总数 `totalOnes`。
2. 如果 `totalOnes % 3 != 0`，返回 `[-1,-1]`。
3. 如果 `totalOnes == 0`，返回 `[0, 2]`（全0任意分都行）。
4. 令 `k = totalOnes / 3`，找到第1个1、第k+1个1、第2k+1个1的位置，分别记为 `p1, p2, p3`。
5. 从 `p1, p2, p3` 开始同步向后比较，直到 `p3` 到达数组末尾。如果过程中有任何不匹配，返回 `[-1,-1]`。
6. 比较完成后，`p3` 在数组末尾位置，末尾0的个数 = `n - 1 - (第三段最后一个1的位置)`。利用此信息确定 `i = p1 - 1` 和 `j = p2`。

```
示例: arr = [1,0,1,0,1]
1的位置: [0, 2, 4], 总数=3, 每段1个1
p1=0(第1个1), p2=2(第2个1), p3=4(第3个1)
比较: arr[0]=1, arr[2]=1, arr[4]=1 → 匹配
p3到达末尾，比较结束
i = p1-1+末尾0数 = 0, j = p2+末尾0数 = 3 → [0, 3] 中间段的起始索引要+末尾0数
但具体看实现: 末尾0数 = 5-1-4 = 0
i = 0, j = 2+1 = 3 → 输出 [0, 3]

```

```cpp
class Solution {
public:
    vector<int> threeEqualParts(vector<int>& arr) {
        int n = arr.size();

        // 第一步：统计1的总数
        int totalOnes = 0;
        for (int x : arr) totalOnes += x;

        // 不能被3整除 → 无解
        if (totalOnes % 3 != 0) return {-1, -1};

        // 全0特殊情况
        if (totalOnes == 0) return {0, 2};

        int k = totalOnes / 3;

        // 第二步：找到每段第一个1的起始位置
        int p1 = -1, p2 = -1, p3 = -1;
        int count = 0;
        for (int i = 0; i < n; i++) {
            if (arr[i] == 1) {
                count++;
                if (count == 1) p1 = i;          // 第一段第一个1
                if (count == k + 1) p2 = i;      // 第二段第一个1
                if (count == 2 * k + 1) p3 = i;  // 第三段第一个1
            }
        }

        // 第三步：三段同步比较
        while (p3 < n) {
            if (arr[p1] != arr[p2] || arr[p1] != arr[p3]) {
                return {-1, -1};
            }
            p1++;
            p2++;
            p3++;
        }

        // p3到达n，说明比较成功
        // p1-1 是第一段的结束索引 i
        // p2 是第三段的起始索引 j
        return {p1 - 1, p2};
    }
};
```

**关键点**:
- 三个指针同步推进的过程中，`p3` 推到数组末尾时停止。此时 `p1` 和 `p2` 自然包含了末尾0的对齐。
- 分割点 `i = p1 - 1`（第一段包含 arr[0..i]），`j = p2`（第三段从 arr[j] 开始）。
- 这个做法巧妙地将"末尾0的对齐"融入了同步比较过程中，不需要单独处理。

## 易错点

1. **忘记全0特判**：
   - 全0时 `totalOnes = 0`，如果不特判，后面找第一个1的逻辑会出问题（找不到任何1）。
   - 全0数组任意分割都表示相同值0。

2. **末尾0没有对齐**：
   - 第三段的末尾0个数是固定的，第一段和第二段必须也补齐同样多的0。
   - 同步比较法自动处理了这个问题，因为 `p3` 会走过这些末尾0。

3. **分割索引理解错误**：
   - 第一段是 `arr[0..i]`，第二段是 `arr[i+1..j-1]`，第三段是 `arr[j..n-1]`。
   - 注意第二段的结束和第三段的开始之间的关系：`j` 是第三段的起始。

4. **1的计数起点搞混**：
   - 第 `k+1` 个1是第二段的开始（不是第 `k` 个），第 `2k+1` 个1是第三段的开始。

## 面试追问

**Q1: 为什么三段1的个数必须相等？**
> 二进制值相同意味着去掉前导零后的位模式相同，相同的位模式中1的数量自然相同。因此总的1的个数必须是3的倍数。

**Q2: 为什么从第三段开始反推？**
> 第三段延伸到数组末尾，其末尾0的个数是固定不变的。而第一段和第二段的末尾0可以通过调整分割点来增减（段间的0可以分给前一段作为末尾0）。所以第三段的结构决定了所有段的要求。

**Q3: 能否用哈希或直接计算二进制值来比较？**
> 数组长度可达 3*10^4，二进制值可能极大，无法用整数表示。必须用逐位比较的方式。

**Q4: 如果题目改为分成 K 等分呢？**
> 思路完全相同：1的总数必须是 K 的倍数，找到每段的起始1位置，以最后一段为基准同步比较。时间复杂度仍为 O(n)。
