# 311. 稀疏矩阵的乘法

## 核心思路

本质上就是矩阵乘法，但关键在于"稀疏"二字——矩阵中大量元素为 0，而任何数乘以 0 都是 0，所以我们应该**跳过所有涉及 0 的乘法运算**，只处理非零元素。

## 思维链

1. **读完题第一反应**：矩阵乘法公式 `result[i][j] = Σ mat1[i][p] * mat2[p][j]`，三重循环直接算。
2. **暴力解的瓶颈在哪？** 三重循环是 O(m·k·n)，但如果矩阵是稀疏的（大量 0），很多乘法是 `0 * something = 0`，完全白算了。
3. **怎么跳过 0？** 最简单的方式：在内层循环中加一个 `if (mat1[i][p] != 0)` 判断，跳过 mat1 中的零元素。更进一步，调换循环顺序，让我们可以提前跳过整行/整列的零。
4. **更进一步**：预处理出每行/每列的非零元素位置和值，只遍历非零元素。这就是稀疏矩阵的经典存储方式（CSR/CSC 格式的简化版）。
5. **面试追问方向**：如果矩阵非常大但极其稀疏（如 10000×10000 但只有 100 个非零元素），预处理方式的优势就非常明显了。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力三重循环 | 直接套矩阵乘法公式 | O(m·k·n) | O(1)* | 能说出即可 |
| 调换循环+跳零 | 交换 j/p 循环顺序，提前跳过 mat1 的零 | O(m·k·n) 最坏，实际远小于 | O(1)* | ⭐ 必须写出 |
| 预处理非零元素 | 提取每行非零(col, val)对，只做非零乘法 | O(m·a·b/k) 实际 | O(a+b) | 加分项 |

*注：输出矩阵 O(m·n) 空间是必须的，这里只算额外空间。a, b 分别是 mat1 和 mat2 的非零元素个数。

## 关键提示

1. **矩阵乘法公式回顾**：`C[i][j] = Σ(p=0..k-1) A[i][p] * B[p][j]`。标准三重循环是 i→j→p，但循环顺序可以任意调换。
2. **调换循环顺序的妙处**：如果用 i→p→j 的顺序，我们可以在进入 j 循环之前就检查 `mat1[i][p]` 是否为 0，如果是 0 就直接跳过整个 j 循环（省掉 n 次运算）。
3. **预处理思路**：把 mat1 的每一行用 `vector<pair<col, val>>` 存非零元素。这样遍历 mat1 第 i 行时，只会访问非零元素。
4. **可视化矩阵乘法**：
```
mat1 (2×3):          mat2 (3×3):          result (2×3):
[1  0  0]            [7  0  0]            [7  0  0]
[-1 0  3]     ×      [0  0  0]      =     [-7 0  3]
                      [0  0  1]
                      
result[1][2] = (-1)*0 + 0*0 + 3*1 = 3
                 ↑跳过    ↑跳过  ↑只有这个有效
```

5. **为什么"跳零"有效？** 如果稀疏度为 s（非零比例），暴力做 m·k·n 次乘法，跳零后大约只做 m·k·n·s 次，当 s 很小时提升巨大。

## 解法详解

### 解法1: 暴力三重循环 — O(m·k·n) / O(1)

**思考过程**: 矩阵乘法最直接的实现，三重循环 i→j→p。没有利用稀疏性，所有乘法都做，包括乘以 0 的无效运算。

```cpp
class Solution {
public:
    vector<vector<int>> multiply(vector<vector<int>>& mat1, vector<vector<int>>& mat2) {
        int m = mat1.size(), k = mat1[0].size(), n = mat2[0].size();
        vector<vector<int>> result(m, vector<int>(n, 0));
        
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                for (int p = 0; p < k; p++) {
                    result[i][j] += mat1[i][p] * mat2[p][j];
                }
            }
        }
        return result;
    }
};
```

**关键点**: 这个解法完全没利用"稀疏"这个条件。对于 100×100 的矩阵，即使只有 1 个非零元素，也要做 100^3 = 100万次乘法。

---

### 解法2: 调换循环顺序 + 跳零 — O(m·k·n) 最坏 / O(1) ⭐ 面试首选

**从解法1优化**: 解法1的瓶颈是不管 mat1[i][p] 是否为 0 都进入最内层循环。如果我们把循环顺序从 i→j→p 改为 **i→p→j**，就可以在进入 j 循环之前判断 `mat1[i][p] != 0`，一次跳过 n 次无效乘法。

**为什么 i→p→j 而不是 i→j→p？**
- i→j→p: 对每个 (i,j) 遍历所有 p，无法提前跳过
- i→p→j: 先固定 mat1 的一个元素 mat1[i][p]，如果它为 0，整个 j 循环都不用做

```
// 循环顺序对比：
// 
// 方式1: i→j→p (标准)           方式2: i→p→j (优化)
// for i:                         for i:
//   for j:                         for p:
//     for p:                         if mat1[i][p] == 0: continue  ← 跳过！
//       C[i][j] += A[i][p]*B[p][j]  for j:
//                                      C[i][j] += A[i][p]*B[p][j]
//
// 方式2中，一个 continue 就跳过了 n 次乘法！
```

```cpp
class Solution {
public:
    vector<vector<int>> multiply(vector<vector<int>>& mat1, vector<vector<int>>& mat2) {
        int m = mat1.size(), k = mat1[0].size(), n = mat2[0].size();
        vector<vector<int>> result(m, vector<int>(n, 0));
        
        for (int i = 0; i < m; i++) {
            for (int p = 0; p < k; p++) {
                // 核心优化：mat1[i][p] 为 0 时，跳过整个 j 循环
                // 因为 0 * mat2[p][j] = 0，对任何 j 都没有贡献
                if (mat1[i][p] == 0) continue;
                
                for (int j = 0; j < n; j++) {
                    // 额外优化：mat2[p][j] 为 0 也可以跳过这一次
                    if (mat2[p][j] == 0) continue;
                    result[i][j] += mat1[i][p] * mat2[p][j];
                }
            }
        }
        return result;
    }
};
```

**关键点**:
- 循环顺序调换不影响正确性，因为 `result[i][j]` 的累加顺序不影响最终结果。
- 如果 mat1 有 90% 的零，外层 continue 就省掉了 90% 的内层循环。

---

### 解法3: 预处理非零元素（稀疏表示） — 实际 O(m·a_avg·b_avg) / O(非零元素数)

**从解法2继续优化**: 解法2仍然需要遍历 mat1 的每一行的所有 k 个元素来找非零项。如果预处理把每行的非零元素提取出来，可以直接遍历非零元素，连 `if` 判断都省了。

**思路**: 把 mat1 转换为"每行的非零元素列表"：`sparseA[i] = [(col1, val1), (col2, val2), ...]`。这样遍历 mat1 第 i 行时，只访问非零元素。

```
// 预处理示例：
// mat1 = [[1, 0, 0],    →  sparseA[0] = [(0, 1)]
//         [-1, 0, 3]]       sparseA[1] = [(0, -1), (2, 3)]
//
// mat2 = [[7, 0, 0],    →  sparseB[0] = [(0, 7)]
//         [0, 0, 0],        sparseB[1] = []
//         [0, 0, 1]]        sparseB[2] = [(2, 1)]
//
// 计算 result[1][j]:
//   sparseA[1] 有 (0,-1) 和 (2,3)
//   对 (0,-1): 遍历 sparseB[0] = [(0,7)] → result[1][0] += -1*7 = -7
//   对 (2,3):  遍历 sparseB[2] = [(2,1)] → result[1][2] += 3*1 = 3
//   result[1] = [-7, 0, 3] ✓
```

```cpp
class Solution {
public:
    vector<vector<int>> multiply(vector<vector<int>>& mat1, vector<vector<int>>& mat2) {
        int m = mat1.size(), k = mat1[0].size(), n = mat2[0].size();
        vector<vector<int>> result(m, vector<int>(n, 0));
        
        // 预处理 mat1：提取每行的非零元素 (列号, 值)
        vector<vector<pair<int,int>>> sparseA(m);
        for (int i = 0; i < m; i++) {
            for (int p = 0; p < k; p++) {
                if (mat1[i][p] != 0) {
                    sparseA[i].emplace_back(p, mat1[i][p]);
                }
            }
        }
        
        // 预处理 mat2：提取每行的非零元素 (列号, 值)
        // mat2 的第 p 行在乘法中被 mat1 的第 p 列索引
        vector<vector<pair<int,int>>> sparseB(k);
        for (int p = 0; p < k; p++) {
            for (int j = 0; j < n; j++) {
                if (mat2[p][j] != 0) {
                    sparseB[p].emplace_back(j, mat2[p][j]);
                }
            }
        }
        
        // 只遍历非零元素做乘法
        for (int i = 0; i < m; i++) {
            for (auto& [p, valA] : sparseA[i]) {
                // valA = mat1[i][p]，已知非零
                for (auto& [j, valB] : sparseB[p]) {
                    // valB = mat2[p][j]，已知非零
                    result[i][j] += valA * valB;
                }
            }
        }
        return result;
    }
};
```

**关键点**:
- 预处理开销 O(m·k + k·n) 只是遍历一次矩阵。
- 乘法次数 = mat1 非零元素数 × mat2 对应行的平均非零元素数，极其稀疏时远小于 m·k·n。
- 这本质上是 CSR（Compressed Sparse Row）格式的简化版，是工业界处理稀疏矩阵的标准方式。

| | 解法1 暴力 | 解法2 调换循环+跳零 | 解法3 预处理非零 |
|---|---|---|---|
| 乘法次数 | m·k·n | 跳过 mat1 零行，实际更少 | 仅非零对非零 |
| 额外空间 | O(1) | O(1) | O(非零元素数) |
| 代码复杂度 | 最简单 | 简单 | 稍复杂 |
| 稀疏优势 | 无 | 中等 | 最大 |
| 面试推荐 | 开场展示理解 | ⭐ 首选，简洁有效 | 追问时展示 |

**什么时候选哪个？**
- 解法2 是面试的最佳平衡点：代码简洁、正确利用稀疏性、容易解释。
- 解法3 适合追问"如果矩阵非常大、非常稀疏怎么办？"时展示，体现对稀疏矩阵存储格式的理解。

## 易错点

1. **循环顺序调换后累加错误**
   - ✗ 以为换成 i→p→j 后 `result[i][j]` 被覆盖了：`result[i][j] = mat1[i][p] * mat2[p][j]`
   - ✓ 必须用 `+=` 累加：`result[i][j] += mat1[i][p] * mat2[p][j]`
   - 因为同一个 result[i][j] 会被不同的 p 值多次更新

2. **预处理时搞混行列**
   - ✗ mat2 也按列提取：对 mat2 的每一列存非零元素
   - ✓ mat2 应该按行提取（sparseB[p] = 第 p 行的非零元素），因为乘法是 mat1 的列索引对应 mat2 的行索引

3. **忘记初始化 result 为全零**
   - ✗ `vector<vector<int>> result(m, vector<int>(n));` — 部分编译器可能不保证初始化为 0
   - ✓ `vector<vector<int>> result(m, vector<int>(n, 0));` — 显式初始化（实际上 vector<int>(n) 默认为 0，但显式更安全清晰）

## 面试追问

**Q1 (基础理解)**: 普通矩阵乘法的时间复杂度是多少？这道题为什么可以优化？

> A: 普通矩阵乘法 O(m·k·n)。稀疏矩阵大量元素为 0，而 `0 * x = 0`，所以可以跳过所有涉及 0 的乘法。

**Q2 (优化细节)**: 为什么要把循环顺序从 i→j→p 改成 i→p→j？

> A: i→p→j 的顺序下，mat1[i][p] 在最外层（相对于 j），如果它为 0，可以一次性跳过整个 j 循环（n 次运算）。而 i→j→p 的顺序下，mat1[i][p] 在最内层，每次只能跳过 1 次运算。

**Q3 (进阶)**: 如果矩阵是 10000×10000 但只有 100 个非零元素，你会怎么处理？

> A: 用预处理方式（解法3），提取非零元素。这样乘法次数只和非零元素数量相关，而不是矩阵尺寸。甚至可以用哈希表 `map<pair<int,int>, int>` 存储非零元素，避免开 10000×10000 的数组。

**Q4 (变体)**: 如果需要多次查询不同的 mat1×mat2，但 mat1 固定不变，怎么优化？

> A: 预处理 mat1 为稀疏表示（一次性开销），之后每次新的 mat2 来时只需预处理 mat2 并做非零乘法。mat1 的预处理可以复用。
