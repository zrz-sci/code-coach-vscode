# 722. Remove Comments

## 核心思路

用状态机逐字符扫描源代码，维护一个 boolean 变量 inBlock 追踪当前是否在块注释 `/* ... */` 内部。根据状态决定：普通字符加入缓冲区、`//` 跳过行末、`/*` 进入块注释、`*/` 退出块注释。

---

## 思维链

1. **识别两种注释**：行注释 `//` 影响到行末，块注释 `/* ... */` 可跨行。
2. **优先级**：哪个先出现就先生效。`//` 在块注释中被忽略，`/*` 在行注释中也被忽略。所以只需逐字符扫描，先匹配到谁就按谁处理。
3. **状态机设计**：只需两个状态 —— inBlock=false（正常代码）和 inBlock=true（块注释内）。
4. **块注释跨行的关键**：进入块注释后，换行不会结束注释。块注释结束后，剩余内容要拼接到块注释开始前的那一行，不是新起一行。
5. **缓冲区管理**：用 newLine 字符串积累当前行的有效字符。行处理结束时，若不在块注释中且 newLine 非空，则输出该行。若在块注释中，行结束时不清空 newLine（下一行内容要拼接上来）。

---

## 解法概览

| 解法 | 思路 | 时间复杂度 | 空间复杂度 | 推荐度 |
|------|------|-----------|-----------|--------|
| 状态机 + 逐字符 | 两状态扫描 | O(N) | O(N) | 首选 |
| 正则表达式 | 用正则匹配注释模式 | O(N) | O(N) | 取巧但不适合面试 |

N = 所有源代码字符总数

## 关键提示

### 提示 1 — 为什么需要状态机？

两种注释模式互相排斥：在块注释内遇到 `//` 不作为行注释，在行注释内遇到 `/*` 不作为块注释起始。如何优雅处理？

<details>
<summary>展开</summary>

用一个 boolean 变量 inBlock 即可。当 inBlock=true 时，只关心 `*/`，其他一切字符（包括 `//`）都被忽略。当 inBlock=false 时，先检查 `//`（终止当前行），再检查 `/*`（进入块注释），否则字符正常加入输出。

</details>

### 提示 2 — 块注释跨行时缓冲区怎么处理？

<details>
<summary>展开</summary>

```
源代码:
"int a; /* comment"    ← 进入块注释, newLine = "int a; "
"still comment"        ← 整行被跳过, newLine 不变
"end */ int b;"        ← 退出块注释, newLine += "int b;"
```

关键：块注释跨行时，newLine 不清空。最终 "int a; " 和 " int b;" 拼接为一行 "int a;  int b;"。

只有在行处理完毕且 inBlock==false 时，才将 newLine 输出并清空。

</details>

### 提示 3 — 遇到 `//` 和 `/*` 时要跳过下一个字符吗？

<details>
<summary>展开</summary>

- 遇到 `//`：直接 break 跳出当前行循环，不需要 i++（剩余字符全部忽略）
- 遇到 `/*`：设 inBlock=true，然后 i++（跳过 `*`，否则下一轮可能把 `*` 和后面的 `/` 误判为 `*/`）
- 遇到 `*/`：设 inBlock=false，然后 i++（跳过 `/`）

</details>

### 提示 4 — 空行怎么处理？

<details>
<summary>展开</summary>

删除注释后，如果某行变为空（newLine 为空字符串），则不输出该行。这在行尾是 `/*` 块注释开始、下一行开头是 `*/` 块注释结束时会发生。判断条件：行处理完毕、inBlock==false、newLine.empty() → 不加入 result。

</details>

## 解法详解

### 解法一：状态机 + 逐字符扫描

**算法步骤**：

1. 初始化 inBlock = false，newLine = ""
2. 遍历每一行 source[j]：
   - 遍历行中每个字符 i：
     - **若 inBlock == true**：
       - 检查 line[i] == '*' && line[i+1] == '/'：退出块注释，i++
       - 否则跳过（块注释内容被丢弃）
     - **若 inBlock == false**：
       - 检查 line[i] == '/' && line[i+1] == '/'：行注释，break
       - 检查 line[i] == '/' && line[i+1] == '*'：进入块注释，i++
       - 否则：newLine += line[i]
   - 行遍历结束后：
     - 若 !inBlock && !newLine.empty()：result.push_back(newLine); newLine = ""
3. 返回 result

**状态转移图**：

```
                  遇到 /*
  正常代码 ──────────────────→ 块注释内
  (inBlock=false)              (inBlock=true)
      │                            │
      │ 遇到 //                    │ 遇到 */
      │ → break                    │
      ↓                            ↓
  忽略行末                    回到正常代码
```

**时间复杂度**：O(N)，每个字符最多被访问一次
**空间复杂度**：O(N)，存储结果

## 易错点

1. **块注释跨行时清空 newLine**：最常见的错误。块注释内换行时 newLine 不能清空，否则块注释前后的代码无法拼接到同一行
2. **`i+1 < n` 越界检查**：检查 `//`、`/*`、`*/` 时都要确保 i+1 不越界
3. **`/*` 和 `*/` 重叠**：例如 `/*/` 不应被解释为"打开再立即关闭"。进入块注释后 i++ 跳过了 `*`，所以 `/` 在下一轮不会和前面的 `*` 配对
4. **空行输出**：删除注释后为空的行不应该出现在结果中
5. **行注释后不输出空行**：如果一行只有 `// comment`，删除后 newLine 为空，不应输出
6. **块注释中遇到 `//`**：不应该 break，因为 `//` 在块注释内无意义
7. **字符串/字符字面量中的注释符号**：题目保证输入合法且不会出现在字符串字面量中，不用处理这种情况

## 面试追问

**Q1: 如果源代码中有字符串字面量包含 `//` 或 `/*`，怎么办？**

需要增加第三个状态 inString（或 inChar）。进入字符串后，所有注释符号都是普通字符。还要处理转义字符 `\"` 不终止字符串。本题简化了这个问题，但实际编译器前端需要处理。

**Q2: 这道题的本质是什么？有限状态自动机（FSA）？**

是的。本质是一个 2 状态的 FSA：{正常代码, 块注释内}。输入字符集为所有 ASCII 字符加上行末标记。状态转移由双字符序列 `/*`、`*/`、`//` 触发。行注释 `//` 不需要独立状态，因为它总是在当前行内结束。

**Q3: 能否用正则表达式一行搞定？**

理论上可以。将所有行合并为一个字符串（用特殊分隔符），然后用正则 `//.*?$|/\*[\s\S]*?\*/` 替换为空。但正则方案在面试中不被推荐：(1) 不展示算法思维 (2) 跨行匹配的正则语法各语言不同 (3) 边界情况难调试。

**Q4: 时间复杂度能否低于 O(N)？**

不能。必须扫描每个字符至少一次才能确定它是否在注释内。O(N) 是信息论下界。
