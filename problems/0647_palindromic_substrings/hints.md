# 647. 回文子串

## 核心思路
本质上在问：字符串 `s` 的所有子串中，有多少个是回文的？关键洞察是**每个回文串都有一个"中心"**，从中心向两边扩展是判断回文最自然的方式。

## 思维链

1. **读完题第一反应**：枚举所有子串 `s[i..j]`，逐一判断是否回文。子串有 O(n²) 个，判断每个需要 O(n)，总共 O(n³)。
2. **暴力解的瓶颈在哪？** 对每个子串都从头到尾检查一遍是否回文，很多检查是重复的。比如知道 `s[i+1..j-1]` 是回文后，只需看 `s[i]==s[j]` 就能判断 `s[i..j]`。
3. **怎么利用这个递推关系？** 两条路：
   - **DP 路线**：`dp[i][j]` 表示 `s[i..j]` 是否回文，从短子串填到长子串。
   - **中心扩展路线**：每个回文都以某个字符（奇数长度）或两个相邻字符（偶数长度）为中心，从中心向两边扩展，直到不匹配。
4. **中心扩展为什么更优？** 中心共 2n-1 个（n个单字符中心 + n-1个双字符中心），每次扩展最多 O(n)，总计 O(n²)，且空间只要 O(1)。
5. **还能更快吗？** Manacher 算法可以 O(n)，但面试中极少要求，属于加分项。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举所有子串，逐一检查 | O(n³) | O(1) | 能说出即可 |
| 动态规划 | dp[i][j] 表示 s[i..j] 是否回文 | O(n²) | O(n²) | 能说出即可 |
| 中心扩展 | 枚举每个中心，向两边扩展 | O(n²) | O(1) | ⭐ 必须写出 |
| Manacher | 利用已知回文信息跳过冗余扩展 | O(n) | O(n) | 加分项 |

## 关键提示

1. **回文的中心**：长度为奇数的回文中心是 1 个字符，偶数的中心是 2 个字符。一共有 `2n - 1` 个中心。
2. **DP 的填表方向**：`dp[i][j]` 依赖 `dp[i+1][j-1]`（内层子串），所以要么按长度从小到大填，要么 `i` 从大到小填。
3. **中心扩展的优势**：不需要额外空间，代码简洁，面试中是首选。
4. **别忘了单字符**：每个单独的字符本身就是回文，这是 base case。
5. **示例推演**：
```
s = "aaa"

中心扩展过程:
中心 'a'(0):  a → aa → aaa  → 3个回文
中心 'a'(1):  a → aa         → 2个回文 (注意 aaa 已经从中心0扩展得到)
中心 'a'(2):  a              → 1个回文
              等等...

奇数中心: i=0→"a","aaa"  i=1→"a"  i=2→"a"    = 4个
偶数中心: (0,1)→"aa"  (1,2)→"aa"             = 2个
总计: 6个 ✓
```

## 解法详解

### 解法1: 暴力枚举 — O(n³) / O(1)

**思考过程**：最直觉的方法——枚举所有可能的子串，判断每个是否回文。两层循环枚举起点和终点，一层循环检查回文。

```cpp
class Solution {
public:
    int countSubstrings(string s) {
        int n = s.size(), count = 0;
        for (int i = 0; i < n; i++) {
            for (int j = i; j < n; j++) {
                // 检查 s[i..j] 是否回文
                if (isPalindrome(s, i, j)) {
                    count++;
                }
            }
        }
        return count;
    }
    
    bool isPalindrome(const string& s, int left, int right) {
        while (left < right) {
            if (s[left] != s[right]) return false;
            left++;
            right--;
        }
        return true;
    }
};
```

**关键点**：这个解法的瓶颈在于对每个子串独立判断回文，没有利用子串之间的重叠关系。比如已知 `"aba"` 是回文，判断 `"xabax"` 时只需比较两端，但暴力法会重新扫一遍。

---

### 解法2: 动态规划 — O(n²) / O(n²)

**从解法1优化**：暴力法对每个子串独立检查，没有利用"子问题"。关键递推：`s[i..j]` 是回文 ⟺ `s[i] == s[j]` 且 `s[i+1..j-1]` 是回文。这就是 DP 的状态转移。

```
// dp 填表依赖关系:
//
// dp[i][j] 依赖 dp[i+1][j-1]（左下方的格子）
//
//       j →  0  1  2  3  4
//   i ↓
//   0        T  ?  ?  ?  ?
//   1           T  ?  ?  ?
//   2              T  ?  ?     dp[i][j] ← dp[i+1][j-1]
//   3                 T  ?              ↗
//   4                    T        这个格子
//
// 填表方向: 按子串长度从小到大（对角线方向），
// 或者 i 从大到小、j 从小到大
//
// 以 s = "aaa" 为例:
//       j=0  j=1  j=2
// i=0    T    T    T     "a"✓  "aa"✓  "aaa"✓
// i=1         T    T           "a"✓   "aa"✓
// i=2              T                  "a"✓
// 共 6 个 T → 答案为 6
```

```cpp
class Solution {
public:
    int countSubstrings(string s) {
        int n = s.size(), count = 0;
        // dp[i][j] = true 表示 s[i..j] 是回文
        vector<vector<bool>> dp(n, vector<bool>(n, false));
        
        // i 从大到小遍历，保证 dp[i+1][j-1] 在 dp[i][j] 之前已算出
        for (int i = n - 1; i >= 0; i--) {
            for (int j = i; j < n; j++) {
                if (s[i] == s[j]) {
                    // 长度 <= 3 时（如 "a", "aa", "aba"），只要两端相等就是回文
                    // 长度 > 3 时，还需要内层 s[i+1..j-1] 也是回文
                    if (j - i <= 2 || dp[i + 1][j - 1]) {
                        dp[i][j] = true;
                        count++;
                    }
                }
            }
        }
        return count;
    }
};
```

**关键点**：
- `j - i <= 2` 这个条件覆盖了三种 base case：单字符 (`j==i`)、双字符相等 (`j==i+1`)、三字符两端相等 (`j==i+2`)，不需要单独初始化。
- 遍历顺序必须保证 `dp[i+1][j-1]` 先于 `dp[i][j]` 被计算。

### 解法3: 中心扩展 — O(n²) / O(1) ⭐ 面试首选

**核心洞察**：换一个角度——不是枚举子串再判断，而是**枚举回文的中心，向两边扩展**。每个回文串一定有一个中心：
- 奇数长度回文：中心是 1 个字符，如 `"aba"` 中心是 `'b'`
- 偶数长度回文：中心是 2 个字符之间的间隙，如 `"abba"` 中心在两个 `'b'` 之间

中心总共有 `2n - 1` 个（n 个字符中心 + n-1 个间隙中心）。

```
// 中心扩展过程 (s = "aab"):
//
// 奇数中心:
//   center=0('a'): "a"✓ → 扩展"?a?" 越界 → 贡献1
//   center=1('a'): "a"✓ → 扩展"aab" s[0]='a'≠s[2]='b' → 贡献1
//   center=2('b'): "b"✓ → 扩展"?b?" 越界 → 贡献1
//
// 偶数中心:
//   center=(0,1): s[0]='a'==s[1]='a' → "aa"✓ → 扩展越界 → 贡献1
//   center=(1,2): s[1]='a'≠s[2]='b' → 贡献0
//
// 总计: 1+1+1+1+0 = 4 ✓
```

```cpp
class Solution {
public:
    int countSubstrings(string s) {
        int n = s.size(), count = 0;
        
        for (int i = 0; i < n; i++) {
            // 以 s[i] 为中心的奇数长度回文
            count += expandFromCenter(s, i, i);
            // 以 s[i] 和 s[i+1] 为中心的偶数长度回文
            count += expandFromCenter(s, i, i + 1);
        }
        
        return count;
    }
    
private:
    int expandFromCenter(const string& s, int left, int right) {
        int count = 0;
        // 从中心向两边扩展，只要两端相等就是一个新的回文
        while (left >= 0 && right < s.size() && s[left] == s[right]) {
            count++;   // 每次匹配都找到一个新的回文子串
            left--;    // 向左扩展
            right++;   // 向右扩展
        }
        return count;
    }
};
```

**关键点**：
- 每次扩展成功都意味着找到了一个新的回文子串，所以 `count++` 在 while 内部。
- 奇数和偶数回文统一用同一个函数处理，区别仅在初始的 `left` 和 `right`。

### 解法4: Manacher 算法 — O(n) / O(n)（加分项）

**动机**：中心扩展法中，很多扩展是重复的。比如已知 `"aba"` 是回文，那么它内部的回文信息可以被利用。Manacher 算法利用已知的回文右边界来跳过冗余扩展。

**核心思想**：
1. 在字符之间插入 `#`，统一奇偶（`"abc"` → `"#a#b#c#"`）。
2. 维护一个数组 `p[i]` 表示以位置 `i` 为中心的最长回文半径。
3. 维护当前已知的最远回文右边界 `maxRight` 和对应的中心 `center`。
4. 对于新位置 `i`，如果 `i < maxRight`，可以利用其关于 `center` 的镜像位置 `mirror = 2*center - i` 的信息来初始化 `p[i]`，避免从头扩展。

```cpp
class Solution {
public:
    int countSubstrings(string s) {
        // 预处理: 插入 '#' 统一奇偶
        // "abc" → "^#a#b#c#$"  (^和$是哨兵防越界)
        string t = "^#";
        for (char c : s) {
            t += c;
            t += '#';
        }
        t += '$';
        
        int n = t.size();
        vector<int> p(n, 0);  // p[i] = 以 t[i] 为中心的最长回文半径
        int center = 0, maxRight = 0;
        
        for (int i = 1; i < n - 1; i++) {
            int mirror = 2 * center - i;
            
            // 利用对称性初始化 p[i]
            if (i < maxRight) {
                p[i] = min(maxRight - i, p[mirror]);
            }
            
            // 尝试继续扩展
            while (t[i + p[i] + 1] == t[i - p[i] - 1]) {
                p[i]++;
            }
            
            // 更新最远右边界
            if (i + p[i] > maxRight) {
                center = i;
                maxRight = i + p[i];
            }
        }
        
        // 统计回文子串数: 对于变换后字符串中位置 i 的回文半径 p[i],
        // 对应原字符串中 (p[i] + 1) / 2 个回文子串（向上取整）
        // 原因: 半径 p[i] 包含了 '#'，每隔一个才是真实字符
        int count = 0;
        for (int i = 1; i < n - 1; i++) {
            // p[i] 在 '#' 位置代表偶数长度回文，在字符位置代表奇数长度回文
            // 无论哪种，贡献的回文子串数 = ceil(p[i] / 2)
            count += (p[i] + 1) / 2;
        }
        return count;
    }
};
```

**关键点**：
- Manacher 算法的精髓是"利用已知回文信息避免重复扩展"，使总扩展次数降到 O(n)。
- 统计回文数时 `(p[i] + 1) / 2` 的推导：半径为 `p[i]` 的回文中，去掉 `#` 后每个不同的半径长度（从 1 到 p[i]，每隔 2 一个真实字符步）对应一个不同长度的回文子串。

## 解法对比

| | 暴力枚举 | 动态规划 | 中心扩展 | Manacher |
|--|---------|---------|---------|----------|
| 时间 | O(n³) | O(n²) | O(n²) | O(n) |
| 空间 | O(1) | O(n²) | O(1) | O(n) |
| 代码量 | 中等 | 中等 | 最少 | 较多 |
| 面试推荐 | ✗ | 可以 | ⭐首选 | 锦上添花 |

**关键区别**：
- **DP vs 中心扩展**：两者时间复杂度相同，但中心扩展不需要额外空间，代码更简洁直觉。DP 的优势是如果后续还需要查询某个子串是否回文（如回文分割问题），dp 表可以复用。
- **中心扩展 vs Manacher**：Manacher 是中心扩展的加速版，利用对称性跳过冗余扩展。面试中除非面试官明确要求 O(n)，否则中心扩展足够。

## 易错点

1. **DP 遍历方向错误**：
   - ✗ `for(i=0;i<n;i++) for(j=i;j<n;j++)` — `dp[i][j]` 依赖 `dp[i+1][j-1]`，但 `i+1` 还没算！
   - ✓ `for(i=n-1;i>=0;i--) for(j=i;j<n;j++)` — 保证依赖的 `dp[i+1][j-1]` 已经填好

2. **DP 中漏掉短子串的 base case**：
   - ✗ 只写 `dp[i][j] = s[i]==s[j] && dp[i+1][j-1]` — 当 `j-i<=1` 时 `dp[i+1][j-1]` 越界！
   - ✓ 加条件 `j - i <= 2 || dp[i+1][j-1]`

3. **中心扩展忘记偶数中心**：
   - ✗ 只做 `expandFromCenter(s, i, i)` — 漏掉了所有偶数长度的回文（如 `"aa"`）
   - ✓ 必须同时做 `expandFromCenter(s, i, i)` 和 `expandFromCenter(s, i, i+1)`

4. **中心扩展的返回值理解错误**：
   - ✗ 认为 `expandFromCenter` 返回最长回文长度，然后只 +1
   - ✓ 每次扩展成功都是一个新回文，应该在 while 内部计数

## 面试追问

**Q1: 暴力法的复杂度是多少？瓶颈在哪？**
> O(n³)。瓶颈在于每个子串独立检查回文。`s[i..j]` 和 `s[i+1..j-1]` 的回文性有依赖关系，暴力法没有利用。

**Q2: DP 和中心扩展哪个更好？什么时候选 DP？**
> 面试一般选中心扩展，O(1) 空间更优。但如果题目需要多次查询"某个子串是否回文"（如 LeetCode 131 回文分割），DP 表可以复用，此时 DP 更合适。

**Q3: 能否做到 O(n)？**
> Manacher 算法。核心思想是维护当前已知的最远回文右边界，利用回文的对称性，对新位置的回文半径给出一个初始下界，避免从头扩展。总扩展次数是 O(n)。

**Q4: 如果不是统计数量，而是找最长回文子串（LeetCode 5），代码怎么改？**
> 中心扩展法几乎相同，只需把计数改成记录最长长度和对应的起始位置即可。
