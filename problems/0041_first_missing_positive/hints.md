# 41. 缺失的第一个正数

## 核心思路

本质上在问：从 1 开始数，1 在不在？2 在不在？3 在不在？……第一个"不在"的是谁？关键约束是 O(n) 时间 + O(1) 空间，这意味着不能排序、不能用额外哈希表，必须**把数组本身当哈希表**。

## 思维链

1. **读完题第一反应**：答案一定在 `[1, n+1]` 范围内（n 为数组长度）。为什么？最好的情况是数组恰好包含 `1,2,...,n`，答案就是 `n+1`；否则一定有某个 `[1,n]` 内的数缺失。
2. **暴力做法**：对每个正整数 k=1,2,3,...，遍历数组看 k 是否存在。第一个不存在的就是答案。时间 O(n²)。
3. **用哈希表优化查找**：先把所有元素扔进 HashSet，然后从 1 开始查。时间 O(n)，但空间 O(n)，不满足 O(1) 空间。
4. **瓶颈在哪**：空间。我们需要一个"标记某个数是否存在"的机制，但不能用额外空间。
5. **突破**：数组本身就有 n 个位置！如果能把值为 `k` 的元素放到索引 `k-1` 的位置（即 `nums[k-1] = k`），那最后扫一遍，第一个 `nums[i] != i+1` 的位置，`i+1` 就是答案。
6. **怎么放**：遍历数组，对每个位置不断 swap，直到当前元素归位或者不在 `[1,n]` 范围内。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 对 k=1,2,...逐个检查是否在数组中 | O(n²) | O(1) | 能说出即可 |
| 哈希表 | HashSet 记录所有数，从 1 开始查 | O(n) | O(n) | 能说出即可 |
| 原地哈希(置换法) | 把数组本身当哈希表，swap 归位 | O(n) | O(1) | ⭐ 必须写出 |
| 原地标记(正负号法) | 用正负号标记某个数是否出现 | O(n) | O(1) | 加分项 |

## 关键提示

1. **答案上界**：长度为 n 的数组，答案最大是 `n+1`。这极其关键——它限制了我们需要关心的数的范围。
2. **数组即哈希表**：索引 0 对应值 1，索引 1 对应值 2，...，索引 `i` 对应值 `i+1`。不在 `[1,n]` 范围的数直接忽略。
3. **置换法的循环终止**：swap 时，如果目标位置已经有正确的值了（`nums[nums[i]-1] == nums[i]`），必须停止，否则死循环。
4. **正负号法前置处理**：原数组可能有负数和零，要先统一处理成一个不影响判断的正值（比如 `n+1`），这样才能用正负号做标记。

```
// 置换法示例: nums = [3, 4, -1, 1], n=4
//
// 索引:    0  1  2  3     目标: nums[i] = i+1
// 初始:   [3, 4, -1, 1]
//
// i=0: nums[0]=3, 应放到索引2 → swap(nums[0], nums[2])
//      [−1, 4, 3, 1]
//      nums[0]=−1, 不在[1,4]范围, 跳过
//
// i=1: nums[1]=4, 应放到索引3 → swap(nums[1], nums[3])
//      [−1, 1, 3, 4]
//      nums[1]=1, 应放到索引0 → swap(nums[1], nums[0])
//      [1, −1, 3, 4]
//      nums[1]=−1, 不在范围, 跳过
//
// i=2: nums[2]=3, 应放到索引2, 已就位, 跳过
// i=3: nums[3]=4, 应放到索引3, 已就位, 跳过
//
// 最终: [1, −1, 3, 4]
//        ✓   ✗  ✓  ✓
//            ↑ 索引1处 nums[1]≠2, 答案=2
```

## 解法详解

### 解法1: 暴力枚举 — O(n²) / O(1)

**思考过程**: 最直觉的做法——答案从 1 开始，逐个检查。对每个候选值遍历整个数组看是否存在。

```cpp
class Solution {
public:
    int firstMissingPositive(vector<int>& nums) {
        int n = nums.size();
        for (int k = 1; k <= n + 1; k++) {
            bool found = false;
            for (int i = 0; i < n; i++) {
                if (nums[i] == k) {
                    found = true;
                    break;
                }
            }
            if (!found) return k;
        }
        return n + 1; // 理论上不会到这里
    }
};
```

**关键点**: 外层最多循环 `n+1` 次，内层每次 O(n)，总时间 O(n²)。面试中说出这个思路即可，不需要写代码。

---

### 解法2: 哈希表 — O(n) / O(n)

**从暴力优化**: 暴力的瓶颈在"检查 k 是否存在"需要 O(n)。用 HashSet 把查找降到 O(1)。

```cpp
class Solution {
public:
    int firstMissingPositive(vector<int>& nums) {
        unordered_set<int> s(nums.begin(), nums.end());
        int n = nums.size();
        for (int k = 1; k <= n + 1; k++) {
            if (s.find(k) == s.end()) return k;
        }
        return n + 1;
    }
};
```

**关键点**: 时间 O(n) 了，但空间也是 O(n)。题目要求 O(1) 额外空间，所以这还不够。但这个解法清晰展示了"需要快速判断某个数是否存在"的需求，为下一步"原地哈希"做铺垫。

---

### 解法3: 原地哈希 — 置换法 — O(n) / O(1) ⭐ 面试首选

**从解法2优化**: 解法2的瓶颈是额外 O(n) 空间存 HashSet。核心洞察：数组本身就有 n 个格子，可以把值 `k` 放到位置 `k-1`，数组自己就是哈希表！

**为什么每个元素最多被 swap 一次**: 每次 swap 都至少把一个元素放到正确位置，一个元素归位后不会再被移走，所以总 swap 次数 ≤ n。

```cpp
class Solution {
public:
    int firstMissingPositive(vector<int>& nums) {
        int n = nums.size();
        
        // 第一遍: 把每个在[1,n]范围内的数归位到 nums[k-1] = k
        for (int i = 0; i < n; i++) {
            // 用 while 不是 if: 当前位置换来的新数可能也需要归位
            while (nums[i] >= 1 && nums[i] <= n       // 值在有效范围
                   && nums[nums[i] - 1] != nums[i]) {  // 目标位置还没有正确的值
                swap(nums[i], nums[nums[i] - 1]);
            }
        }
        
        // 第二遍: 找第一个不满足 nums[i] == i+1 的位置
        for (int i = 0; i < n; i++) {
            if (nums[i] != i + 1) return i + 1;
        }
        
        // 所有 1~n 都在，答案是 n+1
        return n + 1;
    }
};
```

**关键点**: 
- **while 不是 if**: swap 之后当前位置来了一个新数，这个新数可能也需要归位，所以要持续 swap。
- **终止条件 `nums[nums[i]-1] != nums[i]`**: 如果目标位置已经有了正确的值（比如有重复元素），必须停止，否则两个相同的值互相 swap 导致死循环。

---

### 解法4: 原地标记 — 正负号法 — O(n) / O(1)

**不同视角**: 不移动元素，而是用"正负号"来标记。如果值 `k` 存在，就把索引 `k-1` 处的值变成负数。最后第一个正数的索引 `i` 意味着 `i+1` 不存在。

```cpp
class Solution {
public:
    int firstMissingPositive(vector<int>& nums) {
        int n = nums.size();
        
        // 第一步: 把所有 ≤0 的数改成 n+1 (一个超出范围的正数)
        // 目的: 让数组全是正数，这样才能用正负号做标记
        for (int i = 0; i < n; i++) {
            if (nums[i] <= 0) nums[i] = n + 1;
        }
        
        // 第二步: 对于每个在[1,n]范围内的值，把对应索引处的值变为负数
        for (int i = 0; i < n; i++) {
            int val = abs(nums[i]);  // 取绝对值，因为可能已经被标记为负
            if (val <= n) {
                nums[val - 1] = -abs(nums[val - 1]); // 标记为负(可能已经是负了，abs防止重复标记翻正)
            }
        }
        
        // 第三步: 第一个正数的索引+1 就是答案
        for (int i = 0; i < n; i++) {
            if (nums[i] > 0) return i + 1;
        }
        
        return n + 1;
    }
};
```

```
// 正负号法示例: nums = [3, 4, -1, 1], n=4
//
// Step1 - 替换非正数:  [3, 4, 5, 1]    (−1 → n+1=5)
//
// Step2 - 标记:
//   i=0: val=3, 标记索引2 → [3, 4, −5, 1]
//   i=1: val=4, 标记索引3 → [3, 4, −5, −1]
//   i=2: val=|−5|=5 > n, 跳过
//   i=3: val=|−1|=1, 标记索引0 → [−3, 4, −5, −1]
//
// Step3 - 扫描:
//   索引0: −3 < 0 ✓ (1存在)
//   索引1:  4 > 0 ✗ → 答案 = 2
```

**关键点**: 
- 第一步把 ≤0 改成 `n+1` 而不是其他值，因为 `n+1` 在第二步会被跳过，不会错误标记。
- 第二步标记时取 `abs`，因为这个位置的值可能已经被之前的标记翻成负数了。
- 标记时用 `-abs(...)` 而不是简单取反，防止同一位置被标记两次后翻回正数。

## 解法对比

| | 暴力 | 哈希表 | 置换法 ⭐ | 正负号法 |
|---|---|---|---|---|
| 时间 | O(n²) | O(n) | O(n) | O(n) |
| 空间 | O(1) | O(n) | O(1) | O(1) |
| 是否修改原数组 | 否 | 否 | 是 | 是 |
| 理解难度 | 低 | 低 | 中 | 中高 |
| 面试推荐 | 先说 | 过渡 | **首选** | 备选 |

**什么时候选哪个**：
- 面试首选**置换法**：逻辑最自然——"把 k 放到位置 k-1"，一句话就能解释。
- 正负号法思路更巧妙但解释成本高，如果面试官追问"还有别的方法吗"再给出。

## 易错点

1. **置换法用 `if` 而不是 `while`**
   - ✗ `if (nums[i] >= 1 && ...) swap(...);` — 只 swap 一次，换来的新数没有继续归位
   - ✓ `while (nums[i] >= 1 && ...) swap(...);` — 持续归位直到当前位置的数无需移动

2. **置换法缺少 `nums[nums[i]-1] != nums[i]` 的判断**
   - ✗ `while (nums[i] >= 1 && nums[i] <= n) swap(...)` — 对于重复元素（如 `[1,1]`）会死循环
   - ✓ 加上条件 `nums[nums[i]-1] != nums[i]`，目标位置已有正确值就停止

3. **正负号法标记时直接取反**
   - ✗ `nums[val-1] = -nums[val-1];` — 如果同一位置被标记两次，负负得正，等于没标记
   - ✓ `nums[val-1] = -abs(nums[val-1]);` — 无论标记几次都保持为负

4. **忘记答案可能是 `n+1`**
   - 当数组恰好是 `[1,2,...,n]` 的某个排列时，所有位置都正确，答案是 `n+1`
   - 循环结束后别忘了 `return n + 1;`

## 面试追问

**Q1: 为什么答案一定在 `[1, n+1]` 范围内？**
> 数组有 n 个位置。最好的情况是它们恰好放了 1 到 n，此时答案是 n+1。任何其他情况（有负数、有重复、有超出范围的值），都意味着 [1,n] 中至少有一个数缺失。所以答案 ≤ n+1。

**Q2: 置换法的 while 循环不会导致超过 O(n) 吗？**
> 不会。虽然看起来是嵌套循环（for + while），但每次 swap 都把一个元素放到正确位置，而一个元素归位后不再移动。所以整个过程的 swap 总次数 ≤ n，总时间仍是 O(n)。这是**均摊分析 (amortized analysis)** 的经典例子。

**Q3: 如果不允许修改原数组，O(n) 时间能做吗？**
> 如果不能修改原数组，O(1) 额外空间就做不到了（需要某种方式记录信息）。可以用 O(n) 空间的哈希表解法。或者先复制一份数组再原地操作，但这还是 O(n) 空间。在只读数组约束下，O(n) 时间 + O(1) 空间是不可能的。

**Q4: 如果数组很大放不进内存（外部排序场景），怎么办？**
> 分块思想：答案在 [1, n+1]，把这个范围分成若干块。第一遍扫描统计每块中出现了多少个数，找到不满的那一块。第二遍只关注那一块的具体值。类似桶排序/基数排序的思路。
