# 11. 盛最多水的容器

## 核心思路

本质上是在所有 `(i, j)` 对中，找到 `min(height[i], height[j]) * (j - i)` 的最大值。关键在于：如何利用"移动短板"的贪心策略，将 O(n²) 的枚举降到 O(n)。

## 思维链

1. **读完题第一反应**：选两根线，面积 = 宽度 × 两根线中较短的那根。暴力枚举所有配对就行。
2. **暴力解的瓶颈**：两层 for 循环枚举所有 `(i, j)` 对，O(n²)，n 最大 10⁵ 会超时。
3. **能不能少枚举一些？** 观察面积公式 `min(h[left], h[right]) * (right - left)`，如果从两端开始（宽度最大），每次只需向内移动。问题是：移谁？
4. **关键洞察**：移动较短的那根线！因为宽度减 1 是确定的损失，只有提高短板高度才可能弥补宽度减少带来的损失。移动较高的那根线，高度只可能不变或更差（短板还是那个短的），面积一定变小。
5. **所以**：左右指针从两端出发，每次移动较短的一侧，更新最大面积，直到两指针相遇。O(n) 搞定。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举所有 (i,j) 对 | O(n²) | O(1) | 能说出即可 |
| 双指针（贪心） | 左右夹逼，移动短板 | O(n) | O(1) | ⭐ 必须写出 |

## 关键提示

1. **面积公式**：`area = min(height[left], height[right]) * (right - left)`，面积受限于较短的那根线。
2. **为什么从两端开始？** 两端出发时宽度最大，接下来宽度只会减少，所以我们需要尽量让高度增加来弥补。
3. **为什么移动短板？** 如果移动长板：短板不变 → `min` 值不变或更小，宽度减 1 → 面积一定不增。所以移动长板一定不优，可以安全跳过。
4. **证明不漏解**：每次移动短板时，以当前短板为一侧的所有配对，面积都不可能超过当前值（因为宽度只会更窄，高度也不可能超过短板）。所以淘汰这些配对是安全的。

```
示例: height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
索引:           0  1  2  3  4  5  6  7  8

Step1: L=0, R=8  → min(1,7)*8 = 8   → 移动L(短板1)
Step2: L=1, R=8  → min(8,7)*7 = 49  → 移动R(短板7)
Step3: L=1, R=7  → min(8,3)*6 = 18  → 移动R(短板3)
Step4: L=1, R=6  → min(8,8)*5 = 40  → 移动任一(相等)
Step5: L=2, R=6  → min(6,8)*4 = 24  → 移动L(短板6)
Step6: L=3, R=6  → min(2,8)*3 = 6   → 移动L(短板2)
Step7: L=4, R=6  → min(5,8)*2 = 10  → 移动L(短板5)
Step8: L=5, R=6  → min(4,8)*1 = 4   → L>=R 结束

最大面积 = 49 (Step2, 选线1和线8)
```

## 解法详解

### 解法1: 暴力枚举 — O(n²) / O(1)

**思考过程**：最直接的想法——试遍所有两根线的组合，计算每对的面积，取最大值。

```cpp
class Solution {
public:
    int maxArea(vector<int>& height) {
        int n = height.size();
        int maxWater = 0;
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                // 面积 = 宽度 × 较短的线
                int area = min(height[i], height[j]) * (j - i);
                maxWater = max(maxWater, area);
            }
        }
        return maxWater;
    }
};
```

**关键点**：
- n = 10⁵ 时，10¹⁰ 次运算，铁定超时。
- 瓶颈：我们枚举了太多不必要的配对。能不能证明某些配对一定不是最优的，直接跳过？

---

### 解法2: 双指针（贪心）— O(n) / O(1) ⭐ 面试首选

**从解法1优化**：暴力解枚举了所有 O(n²) 个配对。双指针从两端出发，每步淘汰一批不可能是最优解的配对，最终只需 O(n) 步。

**核心论证（为什么移动短板是正确的）：**
- 假设 `height[left] < height[right]`，当前面积 = `height[left] * (right - left)`
- 如果保持 `left` 不动，向内移动 `right`：
  - 宽度减小
  - 高度 = `min(height[left], height[new_right])` ≤ `height[left]`（短板限制）
  - 所以面积一定 ≤ 当前面积
- 因此 `(left, right-1)`, `(left, right-2)`, ... `(left, left+1)` 这些配对全部可以淘汰
- 安全地移动 `left`，不会错过最优解

```cpp
class Solution {
public:
    int maxArea(vector<int>& height) {
        int left = 0, right = height.size() - 1;
        int maxWater = 0;
        
        while (left < right) {
            // 当前配对的面积
            int w = right - left;
            int h = min(height[left], height[right]);
            maxWater = max(maxWater, w * h);
            
            // 移动较短的那根线——贪心策略
            // 因为保留短板、移动长板，面积只会更差
            if (height[left] < height[right]) {
                left++;
            } else {
                right--;
            }
        }
        
        return maxWater;
    }
};
```

**关键点**：
- 当 `height[left] == height[right]` 时，移动哪边都行。因为此时 `(left, right)` 的面积已经被记录，无论移动哪边，剩余配对的面积都不可能超过当前值（高度不变或更小，宽度更小）。
- 整个过程 `left` 只增不减，`right` 只减不增，两个指针总共移动 n-1 步，所以 O(n)。

## 解法对比

| | 暴力枚举 | 双指针贪心 |
|---|---|---|
| 时间 | O(n²) | O(n) |
| 空间 | O(1) | O(1) |
| 核心思想 | 穷举所有配对 | 每步淘汰一批必定不优的配对 |
| 能否通过 | n ≤ 10⁵ 下超时 | ✅ |
| 面试 | 暖场用 | **必须写出** |

双指针解法唯一比暴力多想的一步就是：**理解"移动短板"的正确性**。这是面试官最想听到的分析。

## 易错点

1. **✗ 面积计算用 `height[left] * (right - left)`**
   **✓ 应该用 `min(height[left], height[right]) * (right - left)`**
   水量由较短的线决定，不是随便取一边。

2. **✗ `height[left] == height[right]` 时不知道移谁导致死循环**
   **✓ 移动任一边都正确（比如统一移动 `left`，或统一移动 `right`），只要 while 条件是 `left < right` 就不会死循环。**

3. **✗ 用 `left <= right` 作为循环条件**
   **✓ 应该用 `left < right`**。当 `left == right` 时只有一条线，无法构成容器，不需要也不应该计算。

4. **✗ 忘记在移动指针之前先计算面积**
   **✓ 必须先算当前面积再移动，否则漏掉初始的最宽配对。**

## 面试追问

**Q1: 暴力解的时间复杂度是多少？有什么瓶颈？**
→ O(n²)，瓶颈在于枚举了所有 n(n-1)/2 个配对。当 n = 10⁵ 时不可接受。

**Q2: 双指针为什么不会漏掉最优解？请严格证明。**
→ 每次移动短板时，以该短板为一侧的所有更窄配对，面积都 ≤ 当前面积（宽度更小且高度受短板限制）。所以这些配对全部被安全淘汰，不会漏掉最优解。形式化：当 `h[L] ≤ h[R]` 时，对任意 `r < R`，`min(h[L], h[r]) * (r-L) ≤ h[L] * (R-L) = 当前面积`。

**Q3: 如果要求返回组成最大面积的两条线的索引呢？**
→ 在更新 `maxWater` 的同时记录 `bestLeft` 和 `bestRight` 即可，不影响整体算法。

**Q4: 这道题和 42. 接雨水 (Trapping Rain Water) 有什么关系？**
→ 本题选两根线围成容器（只看两端），42 题是所有柱子之间的凹陷都要算。42 题也可以用双指针，但逻辑不同：42 题需要维护 `leftMax` 和 `rightMax`，按"短板决定水位"的思想逐格计算。

## 相关题型

- **42. 接雨水 (Trapping Rain Water)** — 同样使用双指针 + "短板原理"，区别在于本题只选两条线，42 题需要累加每个位置的储水量。双指针的移动策略可以直接复用。
- **15. 三数之和 (3Sum)** — 复用"排序后双指针夹逼"的框架，区别在于外层多一个循环固定第一个数。
- **167. 两数之和 II - 输入有序数组** — 复用"左右指针在有序数组上向中间逼近"的思想，但判断条件不同（本题是贪心移短板，167是比较 sum 和 target）。
