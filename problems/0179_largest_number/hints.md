# 179. 最大数

## 核心思路

本质上是一个**自定义排序**问题：给定一组数字，定义一种"谁放前面拼出来更大"的比较规则，然后按这个规则排序，拼接即为答案。

## 思维链

1. **读完题第一反应**：要把数字排成最大的数，那是不是大数字放前面？比如 `[9, 5, 3]` 排成 `953`。但 `[3, 30]` 呢？`330 > 303`，所以 `3` 应该在 `30` 前面 —— 不是简单的数值大小！

2. **暴力解的想法**：全排列所有数字的排列方式，拼接后比较。n 个数字有 n! 种排列，`n=100` 时完全不可行。

3. **关键观察**：我们不需要枚举所有排列。对于任意两个数 `a` 和 `b`，如果 `ab > ba`（拼接后），那么在最终结果中 `a` 一定在 `b` 前面。比如 `a=3, b=30`：`"330" > "303"`，所以 `3` 排在 `30` 前面。

4. **这个比较规则能排序吗？** 关键是要证明这个规则满足**传递性**（如果 `a` 排在 `b` 前面，`b` 排在 `c` 前面，那么 `a` 一定排在 `c` 前面）。答案是可以的 —— 字符串拼接比较满足传递性，因此可以作为排序的比较函数。

5. **实现**：把所有数字转成字符串，用自定义比较函数排序，然后拼接。注意特殊情况：全是 0 时结果是 `"0"` 不是 `"000..."`。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力全排列 | 枚举所有排列取最大 | O(n! × n) | O(n) | 能说出即可 |
| 自定义排序（贪心） | 定义 `ab > ba` 的比较规则排序 | O(n log n × k) | O(n × k) | ⭐ 必须写出 |

> 其中 `k` 是数字转字符串后的平均长度，最大约 10（因为 `nums[i] ≤ 10^9`）。

## 关键提示

1. **不要按数值大小排序**：`[3, 30, 34]` 中 `34 > 30 > 3`，但正确顺序是 `3, 34, 30`（拼成 `"34330"` 才最大）。想想为什么。

2. **两个数谁放前面？** 比较 `a+b` 和 `b+a`（字符串拼接），谁大谁在前面。这就是你需要的全部比较逻辑。

3. **传递性保证**：为什么逐对比较后排序的结果就是全局最优？因为如果 `a` 优于 `b`，`b` 优于 `c`，可以证明 `a` 也优于 `c`。

4. **特殊情况**：如果排序后第一个元素是 `"0"`，说明所有元素都是 0，结果应该是 `"0"` 而不是 `"00...0"`。

5. **贪心正确性**：这本质是一个比较排序问题，自定义的比较关系满足全序关系（自反性、反对称性、传递性），所以排序结果唯一且最优。

## 解法详解

### 解法1: 暴力全排列 — O(n! × n) / O(n)

**思考过程**: 最直接的想法 —— 枚举所有数字的排列顺序，拼接每种排列，取最大值。

```cpp
class Solution {
public:
    string largestNumber(vector<int>& nums) {
        vector<string> strs;
        for (int x : nums) strs.push_back(to_string(x));
        
        // 生成所有排列，找拼接后最大的
        sort(strs.begin(), strs.end()); // 先排序以使用 next_permutation
        string result = "";
        do {
            string candidate = "";
            for (auto& s : strs) candidate += s;
            if (candidate > result) result = candidate;
        } while (next_permutation(strs.begin(), strs.end()));
        
        return result;
    }
};
```

**关键点**: 这个解法 n ≤ 8 左右可以跑，`n=100` 完全不可行。但它帮我们理解了题目：在所有排列中找最大拼接结果。

**瓶颈**: n! 种排列太多。我们需要一种方法，不枚举所有排列就能确定最优顺序。

---

### 解法2: 自定义排序（贪心） — O(n log n × k) / O(n × k) ⭐ 面试首选

**从解法1优化**: 全排列的瓶颈在于我们不知道哪个数该排在前面。核心洞察是：对于任意两个数 `a` 和 `b`，我们可以通过比较 `ab` 和 `ba`（拼接后的字符串）直接判断谁在前面。这个比较规则满足传递性，所以用它排序就能得到全局最优。

```
// 为什么自定义比较是正确的？以 [3, 30, 34] 为例：
// 
// 比较 "3" 和 "30":  "330" vs "303"  →  "330" > "303"  →  3 排在 30 前
// 比较 "3" 和 "34":  "334" vs "343"  →  "343" > "334"  →  34 排在 3 前
// 比较 "34" 和 "30": "3430" vs "3034" → "3430" > "3034" → 34 排在 30 前
//
// 排序结果: ["9", "5", "34", "3", "30"]  →  "9534330"
```

```cpp
class Solution {
public:
    string largestNumber(vector<int>& nums) {
        // Step 1: 把数字转成字符串
        vector<string> strs;
        for (int x : nums) {
            strs.push_back(to_string(x));
        }
        
        // Step 2: 自定义排序 —— 核心就这一行比较逻辑
        // 如果 a+b > b+a（字符串拼接），那么 a 应该排在 b 前面
        sort(strs.begin(), strs.end(), [](const string& a, const string& b) {
            return a + b > b + a;
        });
        
        // Step 3: 特判全零的情况
        // 排序后最大的是 "0"，说明所有数都是 0
        if (strs[0] == "0") return "0";
        
        // Step 4: 拼接结果
        string result = "";
        for (auto& s : strs) {
            result += s;
        }
        return result;
    }
};
```

**关键点**:
- 比较函数的本质：`a + b > b + a` 这里的 `+` 是字符串拼接，不是数值加法
- 全零特判：`[0, 0, 0]` 排序后是 `["0", "0", "0"]`，拼接成 `"000"`，应该返回 `"0"`

## 解法对比

|  | 暴力全排列 | 自定义排序 |
|---|---|---|
| 时间复杂度 | O(n! × n) | O(n log n × k) |
| 空间复杂度 | O(n) | O(n × k) |
| 适用规模 | n ≤ 8 | n ≤ 10^5+ |
| 核心思想 | 穷举 | 贪心（局部比较 → 全局最优） |
| 面试推荐 | 仅作分析起点 | ⭐ 首选方案 |

## 易错点

1. **字符串拼接方向搞反**
   - ✗ `return a + b < b + a;`（这会排成最小数）
   - ✓ `return a + b > b + a;`（降序排列，大的在前）

2. **忘记全零特判**
   - ✗ 输入 `[0, 0]`，输出 `"00"`
   - ✓ 排序后检查 `strs[0] == "0"`，是的话直接返回 `"0"`

3. **用数值比较代替拼接比较**
   - ✗ `return stoi(a) > stoi(b);`（`3` 和 `30` 数值比较 `30 > 3`，但 `"330" > "303"` 所以 `3` 在前）
   - ✓ 必须用 `a + b > b + a` 拼接后比较

4. **拼接后溢出担忧**
   - 不用担心！我们比较的是字符串，不是数值。字符串字典序比较天然支持任意长度。

5. **比较函数不满足严格弱序**
   - 实际上 `a + b > b + a` 是满足的。但注意 lambda 里不要写 `>=`，C++ sort 要求严格弱序（不含等号）。
   - ✗ `return a + b >= b + a;` → 可能导致未定义行为
   - ✓ `return a + b > b + a;`

## 面试追问

**Q1: 为什么不能简单按数值大小排序？**
> 反例：`[3, 30]`。按数值 `30 > 3`，排成 `"303"`；但正确答案是 `"330"`。因为数字位数不同时，数值大小不能反映拼接后的优劣。

**Q2: 怎么证明这个自定义比较规则的正确性（传递性）？**
> 设字符串 `a` 代表数字 `A`，长度为 `la`。则 `ab` 代表的数值为 `A × 10^lb + B`。
> 如果 `ab > ba`，即 `A × 10^lb + B > B × 10^la + A`。
> 整理得：`A / (10^la - 1) > B / (10^lb - 1)`。
> 设 `f(X) = X / (10^lx - 1)`，则比较规则等价于比较 `f(A)` 和 `f(B)`，这显然具有传递性。

**Q3: 如果要求排成最小数呢？**
> 只需把比较函数反过来：`return a + b < b + a;`。其余完全一样。这就是 LeetCode 面试官常见的 follow-up。注意全零特判同样需要。

**Q4: 时间复杂度中的 k 是什么？能否优化掉？**
> k 是字符串平均长度（≤10）。每次比较要拼接两个字符串并比较，代价 O(k)。排序有 O(n log n) 次比较，总计 O(nk log n)。由于 k ≤ 10 是常数级别，实际就是 O(n log n)。
