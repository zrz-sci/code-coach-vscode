# 982. 按位与为零的三元组

[./solution.cpp)

## 核心思路

给定整数数组 nums，找出所有三元组 (i, j, k) 使得 nums[i] & nums[j] & nums[k] == 0。关键优化：**先枚举两两 AND 的结果并用哈希表计数，再枚举第三个数检查 AND 是否为零**。将 O(n^3) 降到 O(n^2 + n * 2^16)。

## 思维链

1. **读完题第一反应** -> 三重循环枚举所有 (i, j, k)，对每个三元组计算 `nums[i] & nums[j] & nums[k]`，等于 0 就计数。时间 O(n^3)。

2. **暴力的瓶颈** -> n <= 1000，O(n^3) = 10^9 级别，太慢。需要找到降维的方法。

3. **关键观察** -> `nums[i] & nums[j] & nums[k]` 可以拆成两步：先算 `x = nums[i] & nums[j]`，再检查 `x & nums[k] == 0`。如果我们预处理所有 `nums[i] & nums[j]` 的结果和频率，就可以把三重循环变成两步。

4. **降维** -> 第一步 O(n^2) 枚举所有 (i, j) 对，将 `nums[i] & nums[j]` 的结果存到哈希表 cnt 中。由于 `0 <= nums[i] < 2^16`，AND 的结果也在 [0, 2^16) 范围内，哈希表最多 2^16 个键。

5. **第二步** -> 遍历哈希表中的每个值 x 和对应计数 cnt[x]，再遍历 nums 中每个 nums[k]。如果 `x & nums[k] == 0`，答案加上 cnt[x]。这一步是 O(2^16 * n)。

6. **进阶优化（枚举子集）** -> 对于每个 nums[k]，我们需要找所有与它 AND 为 0 的 x。即 x 的每一位都不能和 nums[k] 冲突。换言之，x 必须是 ~nums[k]（取反后低 16 位）的子集。可以用子集枚举技巧在 O(2^popcount(~nums[k])) 内完成，总体 O(n^2 + n * 3^16 / n) 左右，但实际面试中哈希表法已足够。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力三重循环 | 枚举所有 (i,j,k) | O(n^3) | O(1) | 能说即可 |
| 哈希表预处理两两AND | 预处理 + 遍历 | O(n^2 + n * 2^16) | O(2^16) | 面试首选 |
| 子集枚举优化 | 预处理 + 枚举补集的子集 | O(n^2 + n * 2^16) 最坏相同 | O(2^16) | 加分项 |

## 关键提示

1. **为什么 AND 的结果范围有限？** 题目约束 `0 <= nums[i] < 2^16`，所以任何 AND 运算的结果也在 [0, 2^16 - 1] 内。这意味着哈希表最多 65536 个键，遍历成本可控。

2. **预处理两两AND的频率**：
```
nums = [2, 1, 3]
两两AND:
  2&2=2, 2&1=0, 2&3=2
  1&2=0, 1&1=1, 1&3=1
  3&2=2, 3&1=1, 3&3=3
cnt = {2:3, 0:2, 1:3, 3:1}
```

3. **第二步检查 x & nums[k] == 0**：对于 nums[k]=2 (二进制 10)，需要 x 的第1位为0。cnt 中满足条件的：x=0 贡献 2，x=1(01) 贡献 3，x=0 贡献已统计。逐一检查即可。

4. **子集枚举的技巧**：给定掩码 mask，枚举其所有子集可以用 `for (int sub = mask; sub; sub = (sub - 1) & mask)`，别忘了 sub=0 的情况。这个技巧是位运算的经典套路。

5. **i, j, k 可以相同**：注意题目说的是三元组的索引可以相同（0 <= i, j, k < n），不要求 i < j < k，所以 (0,0,0) 也是合法的。这就是为什么 nums=[0,0,0] 的答案是 27 = 3^3。

## 解法详解

### 解法1: 暴力三重循环 -- O(n^3) / O(1)

**思考过程**: 最直接的做法，三层循环枚举所有可能的三元组，检查三者 AND 是否为零。

```cpp
class Solution {
public:
    int countTriplets(vector<int>& nums) {
        int n = nums.size(), count = 0;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                for (int k = 0; k < n; k++) {
                    if ((nums[i] & nums[j] & nums[k]) == 0) {
                        count++;
                    }
                }
            }
        }
        return count;
    }
};
```

**关键点**: n <= 1000 时 O(n^3) = 10^9，LeetCode 通常要求 10^8 以内，这个方法几乎一定 TLE。但它帮助我们看清结构：可以把 `nums[i] & nums[j]` 先算出来。

---

### 解法2: 哈希表预处理 -- O(n^2 + n * 2^16) / O(2^16) -- 面试首选

**从解法1优化**: 将三重循环的前两层合并为预处理步骤。用哈希表记录所有 `nums[i] & nums[j]` 的出现次数，然后对每个 nums[k]，遍历哈希表检查哪些 AND 值与 nums[k] 进一步 AND 为 0。

```cpp
class Solution {
public:
    int countTriplets(vector<int>& nums) {
        int n = nums.size();
        // 第一步：预处理所有两两 AND 的频率
        unordered_map<int, int> cnt;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                cnt[nums[i] & nums[j]]++;
            }
        }
        
        // 第二步：对每个 nums[k]，检查哈希表
        int result = 0;
        for (int k = 0; k < n; k++) {
            for (auto& [val, freq] : cnt) {
                if ((val & nums[k]) == 0) {
                    result += freq;
                }
            }
        }
        return result;
    }
};
```

**关键点**:
- 预处理 O(n^2)，哈希表最多 2^16 个键。
- 第二步 O(n * min(n^2, 2^16))，由于 2^16 = 65536 且 n <= 1000，实际复杂度约 O(n * 2^16) = O(6.5 * 10^7)，可以通过。
- 也可以用数组 `int cnt[1 << 16]` 代替 unordered_map，常数更小。

---

### 解法3: 子集枚举优化 -- O(n^2 + n * 2^16) / O(2^16)

**思路**: 第二步不遍历整个哈希表，而是只枚举 `~nums[k]` 的子集。因为要 `val & nums[k] == 0`，val 的每个 1 位必须在 nums[k] 的 0 位上，即 val 是 `~nums[k] & 0xFFFF` 的子集。

```cpp
class Solution {
public:
    int countTriplets(vector<int>& nums) {
        int n = nums.size();
        // 用数组代替哈希表，下标即 AND 值
        vector<int> cnt(1 << 16, 0);
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                cnt[nums[i] & nums[j]]++;
            }
        }
        
        int result = 0;
        for (int k = 0; k < n; k++) {
            int mask = (~nums[k]) & 0xFFFF; // nums[k]的补集（低16位）
            // 枚举 mask 的所有子集
            for (int sub = mask; sub > 0; sub = (sub - 1) & mask) {
                result += cnt[sub];
            }
            result += cnt[0]; // sub=0 时 0 & anything == 0
        }
        return result;
    }
};
```

**关键点**: 枚举所有子集的总操作量为 sum of 2^popcount(mask_i)，最坏 O(3^16) 约 4.3*10^7。但因为外层还有 n 次循环，实际性能取决于数据分布。实际提交中这个优化效果显著。

| 空间 | O(1) | O(2^16) | O(2^16) |
| 代码量 | 少 | 中 | 中 |
| 思维难度 | 低 | 中 | 高（子集枚举技巧） |

**哈希表预处理法是最实用的**：思路清晰（两步拆分），代码简洁，复杂度可控。子集枚举是进阶优化，面试中如果时间充裕且面试官追问可以提及。

## 易错点

1. **忘记 i, j, k 可以相同**
   - 题目允许 i == j == k，所以 (0,0,0) 也算一个合法三元组。预处理时 i==j 的情况也要统计。

2. **AND 结果用 int 存储但忘记范围**
   - 0 <= nums[i] < 2^16，AND 结果也在这个范围内。如果用 unordered_map 没问题，但如果用数组，大小必须至少 2^16 = 65536。

3. **子集枚举漏掉 sub=0**
   - `for (sub = mask; sub > 0; sub = (sub-1) & mask)` 不包含 sub=0。必须在循环外单独加上 `result += cnt[0]`。

4. **取反时忘记 & 0xFFFF**
   - `~nums[k]` 在 32 位 int 上会得到高位全 1 的结果。必须 `& 0xFFFF` 截取低 16 位，否则子集枚举会遍历 2^32 个状态。

5. **预处理时用了 i < j 而不是 i, j 独立遍历**
   - 三元组的每个位置独立选取，预处理两两AND时也应该让 i 和 j 独立遍历（各从 0 到 n-1），不能用 i < j。

## 面试追问

**Q1: 暴力解的复杂度？能过吗？**
> O(n^3)，n=1000 时 10^9 次运算，肯定 TLE。但暴力是理解题意和发现优化切入点的起点。

**Q2: 为什么选择先合并前两个数的 AND？**
> 因为 a & b & c = (a & b) & c，AND 满足结合律。先算两两AND后，中间结果的值域被限制在 [0, 2^16)，哈希表大小可控。如果先算一个和第三个，本质相同。

**Q3: 子集枚举 `sub = (sub - 1) & mask` 为什么能遍历所有子集？**
> sub - 1 会翻转 sub 的最低位 1 以及更低位，& mask 确保结果仍然是 mask 的子集。每次操作严格减小 sub 的值，最终到达 0。这是一个经典的位运算枚举技巧，时间恰好是 2^popcount(mask)。

**Q4: 如果 nums[i] 的范围扩大到 2^20，解法还能用吗？**
> 哈希表法仍可用，但第二步变成 O(n * 2^20) ≈ 10^9（n=1000时），可能需要子集枚举优化。子集枚举总量是 O(3^20) ≈ 3.5*10^9，也很紧。更大范围可能需要 FWT（快速沃尔什变换）等高级技巧。
