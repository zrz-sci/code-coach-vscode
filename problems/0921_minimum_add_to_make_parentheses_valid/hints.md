# 921. 使括号有效的最少添加

## 核心思路

本质上在问：遍历完字符串后，有多少个左括号没被匹配 + 多少个右括号没被匹配？它们的总和就是需要添加的括号数。

## 思维链

1. **读完题第一反应**：这是一道括号匹配问题。括号匹配最经典的工具就是**栈**——遇到 `(` 入栈，遇到 `)` 看栈顶能否配对。
2. **用栈模拟匹配**：遍历结束后，栈里剩余的 `(` 就是没被匹配的左括号；过程中遇到 `)` 但栈为空，说明这个右括号也没被匹配。两者之和就是答案。
3. **瓶颈在哪？** 栈的思路已经是 O(n) 了，时间上没有瓶颈。但空间上我们用了一个栈，能否优化？
4. **观察关键点**：栈里其实只会存 `(`，我们根本不需要知道具体是哪些 `(`，只需要知道"有几个"。所以栈可以退化成一个**计数器**！
5. **贪心计数法**：用 `open` 记录未匹配的 `(` 数量，`close` 记录未匹配的 `)` 数量。遇到 `(` 就 `open++`；遇到 `)` 时如果 `open > 0` 就配对消掉（`open--`），否则 `close++`。最终答案 = `open + close`。
6. **为什么贪心是对的？** 每个 `)` 优先和前面最近的未匹配 `(` 配对，这是最优策略——因为延迟配对只会让后续更难匹配，不会更好。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 栈模拟 | 经典括号匹配，栈里存未匹配的 `(` | O(n) | O(n) | 能说出即可 |
| 贪心计数 | 两个计数器替代栈 | O(n) | O(1) | ⭐ 必须写出 |

## 关键提示

1. **不需要真的"添加"括号**：你不需要构造最终字符串，只需要数出有多少个无法匹配的括号。
2. **左右括号分别统计**：未匹配的左括号需要添加右括号来补，未匹配的右括号需要添加左括号来补，这两种情况是独立的。
3. **栈退化为计数器**：当栈里只存同一种元素时，栈可以用一个整数替代。
4. **遍历过程示意**：
   ```
   输入: "( ) )"
          ↑         open=1, close=0   — '(' 入栈/计数+1
            ↑       open=0, close=0   — ')' 配对成功，open-1
              ↑     open=0, close=1   — ')' 无法配对，close+1
   答案 = open + close = 0 + 1 = 1
   ```
5. **贪心的直觉**：每个 `)` 能配就配（贪心），不能配就记一笔。最后剩余的未配对 `(` 也记一笔。

## 解法详解

### 解法1: 栈模拟 — O(n) / O(n)

**思考过程**：括号匹配是栈的经典应用场景。遍历字符串，遇到 `(` 入栈，遇到 `)` 看栈是否非空且栈顶是 `(`。如果能配对就弹出，不能配对说明这个 `)` 是多余的。遍历结束后栈中剩余的 `(` 也是多余的。多余的总数就是需要添加的括号数。

```cpp
class Solution {
public:
    int minAddToMakeValid(string s) {
        stack<char> stk;
        int unmatchedClose = 0; // 无法配对的 ')' 数量
        
        for (char c : s) {
            if (c == '(') {
                stk.push(c);
            } else {
                // c == ')'
                if (!stk.empty()) {
                    stk.pop(); // 和栈顶的 '(' 配对成功
                } else {
                    unmatchedClose++; // 没有 '(' 可配，这个 ')' 多余
                }
            }
        }
        
        // 栈中剩余的 '(' 都是未匹配的
        return stk.size() + unmatchedClose;
    }
};
```

**关键点**：栈中只会有 `(`，因为 `)` 要么配对弹出了，要么计入 `unmatchedClose`。

### 解法2: 贪心计数 — O(n) / O(1) ⭐ 面试首选

**从解法1优化**：解法1的栈里只存 `(`，我们不关心具体是哪些 `(`，只关心有几个。所以用一个整数 `open` 替代栈，表示当前未匹配的 `(` 数量。

```
遍历 "())":
  字符  open  close  说明
  '('    1     0     左括号，open++
  ')'    0     0     有未匹配的左括号，配对! open--
  ')'    0     1     没有左括号可配，close++
                     答案 = 0 + 1 = 1

遍历 "(((":
  字符  open  close  说明
  '('    1     0     open++
  '('    2     0     open++
  '('    3     0     open++
                     答案 = 3 + 0 = 3
```

```cpp
class Solution {
public:
    int minAddToMakeValid(string s) {
        int open = 0;   // 未匹配的 '(' 数量（替代栈）
        int close = 0;  // 未匹配的 ')' 数量
        
        for (char c : s) {
            if (c == '(') {
                open++;
            } else {
                // c == ')'
                if (open > 0) {
                    open--;  // 贪心：优先和前面的 '(' 配对
                } else {
                    close++; // 无 '(' 可配，需要额外添加一个 '('
                }
            }
        }
        
        // open: 剩余未匹配的 '('，每个需要添加一个 ')'
        // close: 过程中无法匹配的 ')'，每个需要添加一个 '('
        return open + close;
    }
};
```

**关键点**：`open` 永远 >= 0，因为我们在 `open > 0` 时才做减法。这保证了不会出现负数（负数意味着多余的 `)` 被错误地"配对"了）。

## 解法对比

| | 栈模拟 | 贪心计数 |
|---|---|---|
| 时间 | O(n) | O(n) |
| 空间 | O(n) 栈 | O(1) 两个变量 |
| 代码量 | 略多（需要 stack） | 精简 |
| 面试推荐 | 作为思路起点 | ⭐ 最终答案 |
| 核心区别 | 用栈存未匹配的 `(` | 用整数计数替代栈 |

两种解法的逻辑完全一致，区别仅在于**栈退化为计数器**的优化。面试中建议先口述栈思路，再优化为计数器写代码。

## 易错点

1. **忘记统计未匹配的左括号**：
   - ✗ 只返回 `close`（只数了多余的 `)`，忘了遍历结束后栈里还有未匹配的 `(`）
   - ✓ 返回 `open + close`

2. **`open` 减到负数**：
   - ✗ 不判断 `open > 0` 直接 `open--`，导致 `open` 变负
   - ✓ `open > 0` 时才 `open--`，否则 `close++`
   - 负数的 `open` 没有物理含义，会导致最终答案错误（如 `"))("` 会算出 `open=-1+1=0, close=0`，答案错误地为 0）

3. **误以为答案是字符串长度减去最长有效括号长度**：
   - 虽然数学上可能等价，但这个思路复杂得多，容易出错。直接计数更简洁。

## 面试追问

**Q1: 能解释一下为什么贪心策略（每个 `)` 优先配对最近的 `(`）是最优的？**
> 如果一个 `)` 不和它前面的 `(` 配对，而是选择不配对等着被"添加一个 `(` 补上"，那前面那个 `(` 也需要被补上一个 `)`。这样总添加数 >= 2，而直接配对只需要 0 次添加。所以贪心配对一定不会更差。

**Q2: 如果括号类型扩展为 `()[]{}` 三种，怎么改？**
> 计数器不够用了，因为需要区分不同类型的左括号的顺序。必须回到栈方案：遇到左括号入栈，遇到右括号检查栈顶是否是对应的左括号。不匹配则需要添加。这就是 LeetCode 20 的扩展。

**Q3: 如果不是问"最少添加数"，而是问"最少删除数使括号有效"，答案一样吗？**
> 一样！每个未匹配的括号，无论是添加一个配对还是删除它自身，都是一次操作。所以最少添加数 = 最少删除数。
