# 810. 黑板异或游戏

## 核心思路

这是一道**博弈论 + 位运算**的脑筋急转弯题。结论非常简洁：**Alice 赢当且仅当 (1) 所有数的 XOR 为 0，或 (2) 数组长度为偶数**。关键在于理解为什么偶数长度时 Alice 必胜。

## 思维链

1. **读完题第一反应**：这是一个博弈问题，直觉上需要分析谁有必胜策略。暴力模拟所有可能的删除顺序是阶乘级别的，不可行。

2. **简单情况分析**：
   - 如果一开始 XOR = 0，Alice 直接赢（题目规定）。
   - 如果数组只有 1 个元素（且不为 0），Alice 必须删除它，之后 XOR = 0，Alice 输。

3. **关键洞察 -- 偶数长度时 Alice 必胜（假设初始 XOR != 0）**：
   - 假设 `xorAll = nums[0] ^ nums[1] ^ ... ^ nums[n-1] != 0`
   - Alice 需要删除一个元素 `nums[i]`，使得剩余元素的 XOR != 0
   - 反证法：如果对所有 i，删除 `nums[i]` 后 XOR 都 = 0，那么 `xorAll ^ nums[i] = 0` 对所有 i 成立，即 `nums[i] = xorAll` 对所有 i 成立
   - 但如果 n 是偶数，`xorAll = nums[0] ^ ... ^ nums[n-1] = xorAll ^ xorAll ^ ... = 0`（偶数个相同值 XOR = 0），矛盾！
   - 所以 n 为偶数时，Alice 总能找到一个安全的删除选择，不会使 XOR 变为 0

4. **递推论证**：Alice 安全删除后，轮到 Bob 面对奇数个元素（且 XOR != 0）。Bob 可能也能安全删除（不一定每次都输），但关键是这个"偶数方有安全删除"的论证可以不断递归 -- 每次轮到偶数方时都能安全操作，最终偶数方获胜。

5. **最终结论**：`return xorAll == 0 || n % 2 == 0`

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 数学结论 | XOR 为 0 或长度为偶数则 Alice 胜 | O(n) | O(1) | ⭐ 必须写出 |

> 本题的代码极短（3 行），面试重点完全在于**推导和证明**过程。需要能解释清楚为什么偶数长度时 Alice 必胜。

## 关键提示

1. **初始 XOR = 0 时 Alice 直接赢** -- 这是题目的直接规则，不要遗漏。

2. **反证法是核心** -- 假设 Alice 无论删哪个数，XOR 都变成 0。推出所有数都相同（= xorAll），但偶数个相同数的 XOR = 0，与 xorAll != 0 矛盾。

3. **偶数方永远有安全选择** -- 这个性质在博弈过程中不断保持：Alice 删一个（变奇数给 Bob），Bob 删一个（变偶数给 Alice），Alice 始终面对偶数个元素。

4. 实例验证：
```
nums = [1, 1, 2]  n=3(奇数), XOR = 1^1^2 = 2 != 0
→ 奇数且 XOR!=0 → Alice 输 → return false ✓

nums = [1, 2, 3]  n=3(奇数), XOR = 1^2^3 = 0
→ XOR=0 → Alice 直接赢 → return true ✓

nums = [0, 1]  n=2(偶数), XOR = 0^1 = 1 != 0
→ 偶数 → Alice 赢 → return true ✓
```

## 解法详解

### 解法1: 数学结论 -- O(n) / O(1) ⭐ 面试首选

**思考过程**：

通过反证法证明偶数长度时 Alice 总能找到安全删除，结合"初始 XOR = 0 直接赢"得出完整结论。

```cpp
class Solution {
public:
    bool xorGame(vector<int>& nums) {
        int xorAll = 0;
        for (int num : nums) xorAll ^= num;
        
        // Alice 赢: XOR 已经是 0 (直接赢) 或 长度是偶数 (必胜策略)
        return xorAll == 0 || nums.size() % 2 == 0;
    }
};
```

**证明过程（面试核心）**：

**命题**：当 n 为偶数且 XOR(全部) != 0 时，当前玩家总能删除一个元素使 XOR 不变为 0。

**反证**：假设删除任何 `nums[i]` 后 XOR 都 = 0。
- `XOR(全部) ^ nums[i] = 0` 对所有 i 成立
- 所以 `nums[i] = XOR(全部)` 对所有 i 成立（所有数相等）
- 但 n 为偶数时，偶数个相同数的 XOR = 0
- 这与 `XOR(全部) != 0` 矛盾，假设不成立。QED。

## 易错点

1. **忘记初始 XOR = 0 的情况**：
   - ✗ 只判断 `nums.size() % 2 == 0`
   - ✓ 还需要判断 `xorAll == 0`（例如 `[1,2,3]` 的 XOR = 0，Alice 直接赢）

2. **把偶数条件搞反**：
   - ✗ `nums.size() % 2 == 1`（奇数长度 Alice 赢）
   - ✓ `nums.size() % 2 == 0`（偶数长度 Alice 赢，因为 Alice 先手面对偶数个元素）

3. **尝试模拟博弈**：
   - ✗ 试图用 minimax/递归枚举所有可能 -> TLE
   - ✓ 直接用数学结论

4. **没有理解题意中"XOR of no elements is 0"**：
   - 当所有元素都被删除时 XOR = 0，删除最后一个元素的人输

## 面试追问

**Q1: 能否用更直观的方式解释为什么偶数长度时 Alice 必胜？**

> 可以这样想：n 为偶数时，Alice 每次面对偶数个元素，Bob 每次面对奇数个元素。由反证法，偶数个元素时总能找到安全删除（不让 XOR 变 0）。所以 Alice 永远不会被迫让 XOR 变 0，而 Bob 在某个时刻会被逼到无路可走。

**Q2: 如果改为"删除后 XOR = 0 则该玩家赢"（规则反转），结论怎么变？**

> 这时问题变成"谁能最先让 XOR = 0"。如果初始 XOR = 0，Alice 直接赢（不变）。如果初始 XOR != 0，需要找到一个 nums[i] = xorAll 的元素来删除。如果存在这样的元素且轮到你，你就赢。分析会更复杂。

**Q3: 这个结论能推广到 k 个玩家轮流删除的情况吗？**

> 关键性质是"当前玩家面对的元素个数模 k 的余数"。但推广后反证法不一定成立（偶数的 XOR 消除性质不再适用），需要更深入的组合博弈论分析（如 Sprague-Grundy 定理）。
