# 1570. 两个稀疏向量的点积

## 核心思路

本质上在问：如何**高效存储**一个大量元素为 0 的向量，并在计算点积时**跳过所有零元素的乘法**，只对两个向量都非零的位置做计算。

## 思维链

1. **读完题第一反应**：点积就是对应位置相乘再求和，直接遍历整个数组就行，O(n) 时间 → 但题目强调"稀疏"，说明大部分元素是 0，直接遍历会做大量 `0 * x = 0` 的无效计算。

2. **瓶颈在哪？** 如果一个长度 10^5 的向量只有 10 个非零元素，暴力遍历要做 10^5 次乘法，但其中 99990 次都是 0 × something = 0。核心浪费在"遍历了大量零"。

3. **怎么只存非零元素？** 用哈希表 `{index: value}` 只记录非零位置。计算点积时，遍历一个向量的非零位置，在另一个向量中查找同一位置是否也非零。这样计算量从 O(n) 降到 O(L1) 或 O(L2)，其中 L 是非零元素个数。

4. **能否更进一步？** 用有序数组 `[(index, value)]` 存储非零元素（按 index 排序），然后对两个有序列表用**双指针**归并扫描，只在 index 相同时做乘法。这避免了哈希表的常数开销。

5. **Follow-up 思考**：如果只有一个向量是稀疏的，应该遍历稀疏向量的非零元素，在稠密向量中直接按索引取值（O(1) 随机访问），不需要对稠密向量做特殊存储。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力 | 直接存完整数组，逐位相乘求和 | O(n) | O(n) | 能说出即可 |
| 哈希表 | 只存非零元素的 {index: value} | O(L1 + L2) | O(L) | ⭐ 必须写出 |
| 双指针 | 有序非零对 + 归并扫描 | O(L1 + L2) | O(L) | 加分项 |

> 其中 L1, L2 是两个向量各自的非零元素个数，L = max(L1, L2)

## 关键提示

1. **稀疏 = 大部分是零**：存储时只需记录"哪个位置有非零值"。想想有哪些数据结构天然适合存储"键值对"？

2. **点积只在两边都非零时才有贡献**：如果你遍历一个向量的非零位置，怎么快速判断另一个向量在同一位置是否也非零？

3. **如果两个非零列表都是按 index 排好序的**：这就变成了"两个有序数组找公共元素"的问题——经典的双指针场景。

4. **Follow-up：一个稀疏一个稠密**——遍历稀疏的那个，用 index 直接在稠密数组中 O(1) 取值即可。关键是选择遍历哪个。

5. **设计题的核心**：构造函数决定存储结构，计算函数决定算法。先想好"怎么存"再想"怎么算"。

## 解法详解

### 解法1: 暴力存储 — O(n) / O(n)

**思考过程**：最直接的做法——把整个数组存下来，计算点积时逐位置相乘累加。

```cpp
class SparseVector {
public:
    vector<int> nums;
    
    SparseVector(vector<int> &nums) : nums(nums) {}
    
    int dotProduct(SparseVector& vec) {
        int result = 0;
        for (int i = 0; i < nums.size(); i++) {
            result += nums[i] * vec.nums[i];
        }
        return result;
    }
};
```

**关键点**：这个方案完全没利用"稀疏"这个条件。对于长度 10^5 但只有几个非零元素的向量，存储和计算都在做大量无用功。面试官一定会追问优化。

---

### 解法2: 哈希表存储 — O(L1 + L2) / O(L) ⭐ 面试首选

**从解法1优化**：解法1的浪费在于存储和遍历了大量零元素。用哈希表只记录非零位置的 `{index → value}`，点积时遍历较小的那个哈希表，查另一个表中同位置是否存在。

```cpp
class SparseVector {
public:
    unordered_map<int, int> mp;  // index → value, 只存非零
    
    SparseVector(vector<int> &nums) {
        for (int i = 0; i < nums.size(); i++) {
            if (nums[i] != 0) {
                mp[i] = nums[i];
            }
        }
    }
    
    int dotProduct(SparseVector& vec) {
        // 优化：遍历非零元素少的那个，减少查找次数
        if (mp.size() > vec.mp.size()) {
            return vec.dotProduct(*this);
        }
        
        int result = 0;
        for (auto& [idx, val] : mp) {
            // 在对方的哈希表中查找同一index
            auto it = vec.mp.find(idx);
            if (it != vec.mp.end()) {
                result += val * it->second;
            }
        }
        return result;
    }
};
```

**关键点**：
- 遍历较小的哈希表是一个重要优化，面试官可能会追问。
- 哈希表查找平均 O(1)，所以总时间 O(min(L1, L2))，最坏 O(L1 + L2)。

---

### 解法3: 有序数组 + 双指针 — O(L1 + L2) / O(L) — 加分项

**思考过程**：哈希表有常数开销（哈希冲突、内存不连续）。如果我们把非零元素存成按 index 排序的 `vector<pair<int,int>>`，就可以用双指针归并扫描。这就像"合并两个有序数组"——两个指针各自前进，index 相同时相乘累加。

```
// 双指针归并过程示意:
// v1 的非零: [(0,1), (3,2), (4,3)]
// v2 的非零: [(1,3), (3,4)]
//             p1↑               p2↑
//
// Step1: p1.idx=0 < p2.idx=1  → p1++
// Step2: p1.idx=3 > p2.idx=1  → p2++
// Step3: p1.idx=3 == p2.idx=3 → result += 2*4=8, p1++, p2++
// Step4: p2 到头 → 结束
// result = 8
```

```cpp
class SparseVector {
public:
    vector<pair<int, int>> pairs;  // (index, value), 按index有序
    
    SparseVector(vector<int> &nums) {
        for (int i = 0; i < nums.size(); i++) {
            if (nums[i] != 0) {
                pairs.push_back({i, nums[i]});
            }
        }
        // 按遍历顺序构建，天然有序，无需排序
    }
    
    int dotProduct(SparseVector& vec) {
        int result = 0;
        int p1 = 0, p2 = 0;
        
        while (p1 < pairs.size() && p2 < vec.pairs.size()) {
            if (pairs[p1].first == vec.pairs[p2].first) {
                // 两个向量在同一位置都非零 → 贡献点积
                result += pairs[p1].second * vec.pairs[p2].second;
                p1++;
                p2++;
            } else if (pairs[p1].first < vec.pairs[p2].first) {
                // v1 的当前index更小，v2 在此位置为零，跳过
                p1++;
            } else {
                // v2 的当前index更小，v1 在此位置为零，跳过
                p2++;
            }
        }
        return result;
    }
};
```

**关键点**：
- 不需要额外排序！因为我们从左到右遍历 nums 构建 pairs，index 天然递增。
- 双指针的精髓：两个有序序列找"交集"，和归并排序的 merge 步骤同理。
- 对缓存更友好——连续内存访问比哈希表的随机访问快很多。

---

### Follow-up: 只有一个向量稀疏时

**场景**：v1 稀疏（几个非零），v2 稠密（大部分非零）。

**策略**：v1 用哈希表/有序数组存，v2 直接存完整数组。计算时遍历 v1 的非零位置，在 v2 中用索引直接访问。

```cpp
// 如果 v2 是稠密的，直接保留原数组:
// for (auto& [idx, val] : sparse.mp) {
//     result += val * dense.nums[idx];  // O(1) 随机访问
// }
// 时间: O(L_sparse)，只遍历稀疏向量的非零元素
```

如果两个都用有序数组存储，也可以对稀疏的那个遍历，对稠密的那个用**二分查找**找对应 index（当一个极稀疏、另一个非零元素很多时，二分的 O(L1 · log L2) 可能比双指针的 O(L1 + L2) 更优）。

## 解法对比

| | 暴力 | 哈希表 | 双指针 |
|---|---|---|---|
| 存储 | 完整数组 | 非零的 {idx: val} | 非零的 [(idx, val)] 有序 |
| 点积时间 | O(n) | O(min(L1,L2)) 平均 | O(L1 + L2) |
| 空间 | O(n) | O(L) | O(L) |
| 缓存友好 | 好 | 差 | 好 |
| 代码复杂度 | 最简单 | 中等 | 稍复杂 |
| 适用场景 | 稠密向量 | 通用稀疏 | 两个都稀疏 |

**面试选择**：先写哈希表解法（简洁直观），再提双指针优化（展示深度理解）。

## 易错点

1. **构造时忘记跳过零元素**
   - ✗ `for (int i = 0; i < nums.size(); i++) mp[i] = nums[i];` → 把零也存进去了，完全没利用稀疏性
   - ✓ 加上 `if (nums[i] != 0)` 才存

2. **双指针忘记同时递增**
   - ✗ index 相等时只 `p1++` 忘了 `p2++` → 同一对被重复计算
   - ✓ `pairs[p1].first == vec.pairs[p2].first` 时 `p1++; p2++;` 都要递增

3. **哈希表解法没有遍历较小的那个**
   - 不影响正确性，但如果一个有 10 个非零、另一个有 10000 个非零，遍历大的做了 10000 次查找（其中 9990 次查不到），遍历小的只做 10 次查找。面试官会追问这个优化。

4. **Follow-up 理解错误**
   - "只有一个稀疏"不是说另一个全非零，而是另一个非零元素很多。关键是选择遍历稀疏的那个，而非稠密的。

## 面试追问

**Q1（基础理解）**：为什么不能直接用原始数组？稀疏向量的特点是什么？
> 稀疏 = 大部分元素为零。直接存完整数组浪费空间，计算时大量乘以 0 浪费时间。只存非零元素可以同时优化存储和计算。

**Q2（优化追问）**：哈希表和有序数组+双指针各有什么优劣？什么时候选哪个？
> 哈希表：代码简单，单次查找 O(1) 但有常数开销和哈希冲突风险。有序数组+双指针：缓存友好，无哈希开销，但需要两个都有序。如果只需要查一次，性能差异不大；如果需要多次查询或对内存/缓存敏感，双指针更优。

**Q3（Follow-up 变体）**：如果一个极稀疏（10个非零）一个很稠密（10000个非零），双指针还是最优吗？
> 不一定。双指针是 O(L1 + L2) = O(10010)。但如果对稀疏的遍历，对稠密的用二分查找，是 O(L1 · log L2) = O(10 · 14) ≈ 140，远小于 10010。所以"一个极稀疏"时，二分查找更优。
