# 1002. 查找共用字符

## 核心思路

本质上就是求 **26 个字母在所有字符串中出现次数的"最小值"**。一个字符要出现在结果中 k 次，它必须在每个字符串中都至少出现 k 次，所以对每个字符取所有字符串中频次的最小值即可。

## 思维链

1. **读完题第一反应**：要找在"每个"字符串中都出现的字符，且包括重复。比如 `l` 在 "bella" 中出现 2 次，在 "label" 中出现 2 次，在 "roller" 中出现 2 次，所以结果包含 2 个 `l`。
2. **朴素想法**：对第一个字符串的每个字符，检查它是否在所有其他字符串中都存在。但 "包括重复" 让简单的存在性检查不够——需要计数。
3. **转化为计数问题**：如果我们统计每个字符串中每个字母出现的次数，那么某个字母能出现在答案中的次数 = 它在所有字符串中出现次数的**最小值**。
4. **具体做法**：用一个长度为 26 的数组 `minFreq` 记录全局最小频次，初始化为"无穷大"（或用第一个字符串的频次初始化）。遍历每个字符串，统计当前字符串的频次，然后对 26 个字母逐一取 `min`。
5. **构造结果**：遍历 26 个字母，`minFreq[c]` 是几就往结果数组里放几个该字母。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 频次取最小值 | 统计每个字符串的字母频次，逐个取 min | O(n·m) | O(1) | ⭐ 必须写出 |
| 逐字符串"交集"模拟 | 用 multiset 或列表逐步求交集 | O(n·m) | O(m) | 能说出即可 |

> n = 字符串个数，m = 字符串平均长度。空间上频次数组固定 26 长，算 O(1)。

## 关键提示

1. **"包含重复"是关键**：不是只判断字符存不存在，而是要统计出现了几次。比如 `l` 出现 2 次就要输出两个 `l`。
2. **取最小值的直觉**：字符 `a` 在字符串 A 中出现 3 次，在字符串 B 中出现 1 次，那结果中最多只能有 1 个 `a`（被 B "限制"住了），这就是 min 操作。
3. **初始化技巧**：`minFreq` 可以用第一个字符串的频次来初始化，避免用 INT_MAX 再多处理一步。
4. **只有 26 个小写字母**：这意味着频次数组大小固定，空间是 O(1)，操作也很快。

```
// 示例: words = ["bella", "label", "roller"]
//
// 频次统计:
//         a b e l
// bella:  1 1 1 2   (其余字母为0)
// label:  1 1 1 2
// roller: 0 0 1 2
//         --------
// min:    0 0 1 2   → 结果: ["e", "l", "l"]
```

## 解法详解

### 解法1: 频次取最小值 — O(n·m) / O(1) ⭐ 面试首选

**思考过程**: 字符出现在所有字符串中，等价于它的频次在每个字符串中都 ≥ 1。而且要包含重复，所以要取所有频次的最小值。26 个字母是固定集合，直接用数组统计。

```cpp
class Solution {
public:
    vector<string> commonChars(vector<string>& words) {
        // 用第一个字符串的频次初始化全局最小频次
        vector<int> minFreq(26, 0);
        for (char c : words[0]) {
            minFreq[c - 'a']++;
        }
        
        // 从第二个字符串开始，逐个取 min
        for (int i = 1; i < words.size(); i++) {
            vector<int> curFreq(26, 0);
            for (char c : words[i]) {
                curFreq[c - 'a']++;
            }
            // 对 26 个字母逐一取最小值
            for (int j = 0; j < 26; j++) {
                minFreq[j] = min(minFreq[j], curFreq[j]);
            }
        }
        
        // 根据最终的 minFreq 构造结果
        vector<string> result;
        for (int j = 0; j < 26; j++) {
            for (int k = 0; k < minFreq[j]; k++) {
                result.push_back(string(1, 'a' + j));
            }
        }
        return result;
    }
};
```

**关键点**: 用第一个字符串初始化 `minFreq`，这样后续只需要从第二个字符串开始遍历，比用 INT_MAX 初始化更自然。

### 解法2: multiset 交集模拟 — O(n·m) / O(m)

**思考过程**: 把每个字符串看成一个"字符多重集合"（multiset），求所有集合的交集。可以用类似归并的方式：将第一个字符串的字符放入 multiset，对后续每个字符串，只保留两者都有的字符（找到就从 multiset 中移除一个，防止重复计数）。

```cpp
class Solution {
public:
    vector<string> commonChars(vector<string>& words) {
        // 用第一个字符串初始化"候选字符池"
        vector<char> pool(words[0].begin(), words[0].end());
        
        for (int i = 1; i < words.size(); i++) {
            vector<char> nextPool;
            // 把当前字符串做成可消耗的 multiset
            unordered_map<char, int> available;
            for (char c : words[i]) {
                available[c]++;
            }
            // 遍历候选池，只保留当前字符串也有的字符
            for (char c : pool) {
                if (available[c] > 0) {
                    nextPool.push_back(c);
                    available[c]--;  // 消耗一个，防止重复
                }
            }
            pool = nextPool;
        }
        
        vector<string> result;
        for (char c : pool) {
            result.push_back(string(1, c));
        }
        return result;
    }
};
```

**关键点**: 每次从 available 中消耗匹配的字符（`available[c]--`），这就自然处理了重复问题。如果不消耗，`l` 出现 1 次也会匹配池中的 2 个 `l`。

## 解法对比

| | 解法1: 频次取 min | 解法2: multiset 交集 |
|---|---|---|
| 核心操作 | 26 长数组逐位取 min | 逐字符匹配+消耗 |
| 空间 | O(1)（固定 26） | O(m)（候选池大小） |
| 代码简洁度 | 更简洁，推荐 | 稍复杂但直觉性强 |
| 面试推荐 | ⭐ 首选 | 可作为初始思路讲述 |

两种解法时间复杂度相同，都是 O(n·m)。解法1更优雅，解法2更贴近"交集"的直觉。

## 易错点

1. **忘记处理重复**：
   - ✗ 用 `set` 只记录字符是否出现 → `l` 只会输出一次
   - ✓ 必须用频次计数或 multiset，才能正确处理 `["e","l","l"]` 这种重复结果

2. **构造结果字符串时的写法**：
   - ✗ `result.push_back('a' + j)` → 类型不匹配，push 的是 char 不是 string
   - ✓ `result.push_back(string(1, 'a' + j))` → 需要构造长度为 1 的 string

3. **minFreq 初始化为 0 而不是第一个字符串的频次**：
   - ✗ `vector<int> minFreq(26, 0)` 然后直接对所有字符串取 min → 结果全是 0
   - ✓ 先用第一个字符串的频次填充 minFreq，再从第二个字符串开始取 min
   - 或者初始化为 INT_MAX，这样 `min(INT_MAX, curFreq)` 也能得到正确结果

4. **解法2中忘记 `available[c]--`**：
   - ✗ 不消耗 → 池中有 3 个 `l`，当前字符串只有 1 个 `l`，结果会保留 3 个
   - ✓ 每匹配一个就消耗一个，保证不超过当前字符串的实际频次

## 面试追问

**Q1: 暴力解怎么做？复杂度是多少？**
> 对第一个字符串的每个字符，遍历所有其他字符串检查是否存在（且要处理重复消耗）。时间 O(n·m²)，不优雅但能 work。本题的关键观察是：只有 26 个字母，转化为频次问题就很简单。

**Q2: 如果字符集不是 26 个小写字母，而是 Unicode 全集怎么办？**
> 把 `vector<int>(26)` 换成 `unordered_map<char, int>`，逻辑完全一样。空间从 O(1) 变成 O(字符集大小)，但算法不变。

**Q3: 如果 words 数组非常长（百万级），但每个字符串很短，有什么优化空间？**
> 核心循环是 O(n·m + n·26)。如果 m 很小但 n 很大，瓶颈在 n·26 的取 min 步骤。可以考虑在取 min 时提前终止：如果 minFreq 已经全是 0，后续字符串不用再处理了。
