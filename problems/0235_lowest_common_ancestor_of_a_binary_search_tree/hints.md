# 235. 二叉搜索树的最近公共祖先

## 核心思路

这道题本质上是：利用 **BST 的有序性**，判断两个节点分别在当前节点的哪一侧——如果分叉了（一左一右），当前节点就是最近公共祖先。

## 思维链

1. **读完题第一反应**：这不就是 LCA（最近公共祖先）问题吗？如果是普通二叉树，需要后序遍历，自底向上查找。但这里是 **BST**，一定有更高效的方法。

2. **暴力解怎么做？** 不利用 BST 性质，把它当普通二叉树。用 LeetCode 236 的方法：后序遍历，左右子树分别找 p 和 q，如果左右各找到一个就是 LCA。这需要遍历整棵树 O(n)。

3. **BST 给了我们什么额外信息？** BST 的核心性质：左子树所有值 < 根 < 右子树所有值。这意味着给定一个节点值，我们能**立刻判断** p 和 q 分别在它的左边还是右边！

4. **什么时候"分叉"？** 如果 p 和 q 都比当前节点小 → 都在左子树，继续往左找。如果都比当前节点大 → 都在右子树，继续往右找。如果一个在左一个在右（或者其中一个就是当前节点）→ **当前节点就是 LCA**！

5. **为什么分叉点一定是 LCA？** 因为一旦 p、q 分到了不同子树，再往任何一边走都不可能同时是两者的祖先了。所以第一个分叉点就是**最深的**公共祖先。

6. **递归 vs 迭代？** 这个判断逻辑是单向的（每次只走一个方向），不需要回溯，所以可以直接用迭代（while循环），比递归更省栈空间。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 通用 LCA（不用 BST 性质） | 后序遍历，自底向上找分叉 | O(n) | O(n) | 能说出即可 |
| BST 递归 | 利用 BST 性质递归找分叉点 | O(h) | O(h) | 加分项 |
| BST 迭代 | 利用 BST 性质迭代找分叉点 | O(h) | O(1) | ⭐ 必须写出 |

> h 为树高，平衡 BST 中 h = O(log n)，最坏退化为 O(n)

## 关键提示

1. **BST 的"导航"能力**：给定一个值，你能立刻知道该往左走还是往右走。这道题的关键是：p 和 q 的值能帮你决定走向。

2. **分叉条件**：当 `p->val` 和 `q->val` 一个 ≤ root->val，一个 ≥ root->val 时，root 就是答案。

3. **画图理解分叉**：
```
//         6          p=2, q=8
//        / \
//       2   8        2 < 6 < 8 → 分叉! → LCA = 6
//      / \ / \
//     0  4 7  9
//
//         6          p=2, q=4
//        / \
//       2   8        2 < 6 且 4 < 6 → 都在左边 → 往左走
//      / \ / \
//     0  4 7  9      到节点2: 2 ≤ 2 且 4 ≥ 2 → 分叉! → LCA = 2
//       / \
//      3   5
```

4. **迭代解法为什么可行**：每一步只走一个方向（左或右），不需要回头，所以不需要栈来保存状态。

5. **和 LeetCode 236 的区别**：236 是普通二叉树，没有有序性，必须遍历所有节点。本题利用 BST 性质可以像二分查找一样只走一条路径。

## 解法详解

### 解法1: 通用 LCA（不用 BST 性质）— O(n) / O(n)

**思考过程**：先忘掉 BST，当普通二叉树处理。后序遍历，对于每个节点：左子树找 p/q，右子树找 p/q。如果左右各找到一个，当前节点就是 LCA。这是 LeetCode 236 的解法，能 work 但没有利用 BST 的优势。

```cpp
class Solution {
public:
    TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
        // 终止条件：空节点，或找到了 p 或 q
        if (!root || root == p || root == q) return root;
        
        // 后序遍历：先递归左右子树
        TreeNode* left = lowestCommonAncestor(root->left, p, q);
        TreeNode* right = lowestCommonAncestor(root->right, p, q);
        
        // 如果左右都找到了，说明 p 和 q 分居两侧，当前节点是 LCA
        if (left && right) return root;
        
        // 否则返回非空的那个（p 和 q 都在同一侧）
        return left ? left : right;
    }
};
```

**关键点**：这个解法对任何二叉树都适用，但它遍历了整棵树。对于 BST，我们可以做得更好。

### 解法2: BST 递归 — O(h) / O(h)

**从解法1优化**：解法1的问题是遍历了整棵树，但 BST 的有序性告诉我们 p 和 q 在哪一侧，每次只需要走一个方向。

```cpp
class Solution {
public:
    TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
        // p 和 q 都在左子树 → LCA 一定在左边
        if (p->val < root->val && q->val < root->val) {
            return lowestCommonAncestor(root->left, p, q);
        }
        // p 和 q 都在右子树 → LCA 一定在右边
        if (p->val > root->val && q->val > root->val) {
            return lowestCommonAncestor(root->right, p, q);
        }
        // 分叉了（一左一右，或其中一个就是 root）→ root 就是 LCA
        return root;
    }
};
```

**关键点**：递归是尾递归（每次只递归一个方向），天然可以改成迭代。

### 解法3: BST 迭代 — O(h) / O(1) ⭐ 面试首选

**从解法2优化**：解法2是尾递归，每次只往一个方向走，完全可以用 while 循环替代，省掉递归栈空间。

```cpp
class Solution {
public:
    TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
        TreeNode* cur = root;
        while (cur) {
            if (p->val < cur->val && q->val < cur->val) {
                // 两个都在左边，往左走
                cur = cur->left;
            } else if (p->val > cur->val && q->val > cur->val) {
                // 两个都在右边，往右走
                cur = cur->right;
            } else {
                // 分叉了：一左一右，或者 cur 就是 p 或 q
                // 这就是 LCA
                return cur;
            }
        }
        return nullptr; // 题目保证 p、q 存在，不会走到这里
    }
};
```

**关键点**：迭代版本是面试中最推荐的写法——代码简洁、空间最优、逻辑清晰。

## 解法对比

| | 解法1: 通用 LCA | 解法2: BST 递归 | 解法3: BST 迭代 |
|---|---|---|---|
| 时间 | O(n) 遍历整棵树 | O(h) 只走一条路径 | O(h) 只走一条路径 |
| 空间 | O(n) 递归栈 | O(h) 递归栈 | **O(1)** 无额外空间 |
| 适用范围 | 任何二叉树 | 仅 BST | 仅 BST |
| 面试推荐 | 当追问"如果不是BST呢" | 可以，但不如迭代 | **首选** |

**什么时候选哪个？**
- 面试先写解法3（迭代），然后说"如果不是 BST，就用解法1（通用 LCA）"
- 这样能展示你理解两者的区别

## 易错点

1. **忘记"节点是自己的祖先"这个条件**
   - ✗ 只处理一左一右的情况，漏掉 `cur == p` 或 `cur == q` 的情况
   - ✓ 分叉条件自然涵盖了这种情况：当 `p->val == cur->val` 时，既不满足"都在左"也不满足"都在右"，走到 else 分支，正确返回 cur

2. **比较时用了 `<=` 和 `>=` 导致混乱**
   - ✗ `if (p->val <= root->val && q->val <= root->val)` → 当 p 就是 root 时会错误地往左走
   - ✓ 用严格小于 `<` 和严格大于 `>`，等于的情况自然落入 else（分叉）分支

3. **通用 LCA 解法中忘记处理 root 本身就是 p 或 q 的终止条件**
   - ✗ `if (!root) return root;` — 少了 `root == p || root == q`
   - ✓ `if (!root || root == p || root == q) return root;`

## 面试追问

**Q1: 你的解法利用了 BST 的什么性质？如果是普通二叉树怎么办？**
> BST 的有序性让我们能判断 p、q 在 root 的哪一侧，每次只走一个方向，O(h) 时间。普通二叉树没有这个信息，必须用后序遍历左右都搜索，O(n) 时间。（就是 LeetCode 236）

**Q2: 如果 p 或 q 不一定存在于树中呢？**
> 需要先验证 p 和 q 是否在树中。可以先做一次查找确认两个节点都存在，然后再找 LCA。或者在通用 LCA 解法中修改：不提前返回，而是记录是否真正找到了两个节点。

**Q3: 如果需要多次查询不同的 (p, q) 对，怎么优化？**
> 可以预处理：用 Euler Tour + Sparse Table 做到 O(n) 预处理、O(1) 查询。或者对于 BST，每次查询本身就是 O(h)，如果树是平衡的已经是 O(log n)，通常足够了。
