# 674. 最长连续递增序列

## 核心思路

本质上就是在数组中找到**最长的一段连续子数组**，使得其中每个元素都严格小于下一个元素。关键词是"连续"——不需要跳着选，只需要找一段不断上升的区间。

## 思维链

1. **读完题第一反应**：枚举所有可能的连续子数组，检查每一个是否严格递增，取最长的。这是 O(n²) 的暴力做法。
2. **暴力解的瓶颈在哪？** 对于每个起点 l，我们往右扫到第一个"不递增"的位置 r，得到一段递增区间。但注意：如果 [l, r] 是递增的，那么以 l+1 为起点的递增区间一定不会更长（因为它是 [l, r] 的子段）。所以从 l+1 到 r-1 这些起点根本不需要重新扫！
3. **怎么突破瓶颈？** 只需要一次遍历：维护一个"当前连续递增段的长度"，如果 `nums[i] > nums[i-1]` 就延长当前段，否则重新开始计数。
4. **这就是贪心/滑动窗口/一次遍历的思路**：遇到递增就累加，遇到断点就重置，全程维护最大值即可。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举每个起点，向右扫到断点 | O(n²) 最坏 | O(1) | 能说出即可 |
| 一次遍历（贪心） | 维护当前段长度，断点重置 | O(n) | O(1) | ⭐ 必须写出 |
| DP（线性） | dp[i] = 以 i 结尾的最长连续递增长度 | O(n) | O(n)→O(1) | 加分项（理解 DP 建模） |

## 关键提示

1. **"连续"是关键约束**：不是最长递增子序列（LIS，可以跳着选，需要 O(n log n)），而是连续子数组，简单得多。
2. **想想什么时候"断"**：`nums[i] <= nums[i-1]` 的时候，当前递增段就结束了，新的段从 i 重新开始。
3. **只需要两个变量**：一个记录当前段长度 `cur`，一个记录全局最大 `ans`。
4. **边界**：数组长度为 1 时，答案就是 1（任何单个元素都算长度为 1 的递增序列）。
5. **DP 视角**：定义 `dp[i]` = 以 `nums[i]` 结尾的最长连续递增序列长度，转移方程 `dp[i] = nums[i] > nums[i-1] ? dp[i-1] + 1 : 1`。由于只依赖前一个状态，自然优化为一个变量。

```
示例 nums = [1, 3, 5, 4, 7]:

索引:  0  1  2  3  4
值:    1  3  5  4  7
cur:   1  2  3  1  2    ← 在索引3处断裂(4≤5)，重置为1
ans:   1  2  3  3  3    ← 最大值始终保持为3
```

## 解法详解

### 解法1: 暴力枚举 — O(n²) / O(1)

**思考过程**：最朴素的想法——对每个位置 l 作为起点，向右扩展直到不再递增，记录长度。

```cpp
class Solution {
public:
    int findLengthOfLCIS(vector<int>& nums) {
        int n = nums.size();
        int ans = 1;
        for (int l = 0; l < n; l++) {
            int r = l;
            // 从 l 出发，尽可能向右扩展
            while (r + 1 < n && nums[r + 1] > nums[r]) {
                r++;
            }
            ans = max(ans, r - l + 1);
            // 注意：这里没有跳过，所以 l 还是逐个递增，导致重复扫描
        }
        return ans;
    }
};
```

**关键点**：这个解法虽然能 AC（因为 n ≤ 10⁴），但做了大量重复工作。比如当 [0,4] 都是递增的，以 1、2、3 为起点的段一定更短，根本不需要再扫。

### 解法2: 一次遍历（贪心）— O(n) / O(1) ⭐ 面试首选

**从解法1优化**：解法1的瓶颈是"对每个起点都重新向右扫"。但我们发现：一段连续递增区间的信息可以通过一个计数器 `cur` 来维护。遇到递增就 +1，遇到断点就重置为 1。

```cpp
class Solution {
public:
    int findLengthOfLCIS(vector<int>& nums) {
        int ans = 1;   // 至少有一个元素，长度至少为1
        int cur = 1;   // 当前连续递增段的长度
        for (int i = 1; i < nums.size(); i++) {
            if (nums[i] > nums[i - 1]) {
                cur++;              // 递增，当前段延长
            } else {
                cur = 1;            // 断裂，重新开始
            }
            ans = max(ans, cur);    // 随时更新全局最大
        }
        return ans;
    }
};
```

**关键点**：`cur` 重置为 1（不是 0），因为断裂后当前元素本身就是新段的起点，长度为 1。

### 解法3: 动态规划 — O(n) / O(n) → 空间优化 O(1)

**DP 建模**：定义 `dp[i]` = 以 `nums[i]` **结尾**的最长连续递增序列长度。

```
转移方程：
  if nums[i] > nums[i-1]:  dp[i] = dp[i-1] + 1   (延续前一段)
  else:                     dp[i] = 1              (重新开始)

初始化：dp[0] = 1
答案：max(dp[0], dp[1], ..., dp[n-1])
```

```
// DP 填表示意 (nums = [1, 3, 5, 4, 7]):
// i:     0   1   2   3   4
// nums:  1   3   5   4   7
// dp:    1   2   3   1   2
//            ↑   ↑   ↑   ↑
//          3>1  5>3  4≤5  7>4
//         dp=2 dp=3 重置  dp=2
// 答案 = max(1,2,3,1,2) = 3
```

**完整 DP 数组版**：
```cpp
class Solution {
public:
    int findLengthOfLCIS(vector<int>& nums) {
        int n = nums.size();
        vector<int> dp(n, 1);  // 每个位置至少为1
        int ans = 1;
        for (int i = 1; i < n; i++) {
            if (nums[i] > nums[i - 1]) {
                dp[i] = dp[i - 1] + 1;
            }
            // else dp[i] 保持初始值 1
            ans = max(ans, dp[i]);
        }
        return ans;
    }
};
```

**空间优化版**（dp[i] 只依赖 dp[i-1]，用一个变量替代）：
```cpp
class Solution {
public:
    int findLengthOfLCIS(vector<int>& nums) {
        int ans = 1, prev = 1;  // prev = dp[i-1]
        for (int i = 1; i < (int)nums.size(); i++) {
            prev = (nums[i] > nums[i - 1]) ? prev + 1 : 1;
            ans = max(ans, prev);
        }
        return ans;
    }
};
```

> 空间优化后和解法2完全等价！这说明**贪心的一次遍历本质上就是空间优化后的线性 DP**。

## 解法对比

| | 暴力枚举 | 一次遍历（贪心） | DP + 空间优化 |
|---|---|---|---|
| 时间 | O(n²) 最坏 | O(n) | O(n) |
| 空间 | O(1) | O(1) | O(1) |
| 关键区别 | 每个起点重新扫 | 一个计数器搞定 | 和贪心等价 |
| 适用场景 | 理解题意 | 面试首选 | 理解 DP 建模 |

贪心和 DP 空间优化殊途同归——面试中写贪心版最清晰，但能解释 DP 角度说明理解更深。

## 易错点

1. **`cur` 重置为 0 而不是 1**：
   - ✗ `cur = 0;` — 断裂后当前元素被忽略了
   - ✓ `cur = 1;` — 当前元素本身就是新段的第一个元素

2. **用 `>=` 判断递增**：
   - ✗ `if (nums[i] >= nums[i-1])` — 题目要求**严格**递增，相等不算
   - ✓ `if (nums[i] > nums[i-1])`

3. **空数组未处理**：
   - 题目保证 `nums.length >= 1`，但如果你写 `int ans = 0` 然后从 i=1 开始循环，当数组只有一个元素时循环不执行，返回 0（错误）
   - ✓ 初始化 `ans = 1`，因为至少有一个元素

4. **DP 空间优化时忘记强转**：
   - 如果写 `i < nums.size()` 且 `nums.size()` 为 0，`size() - 1` 会下溢（unsigned）
   - ✓ 用 `(int)nums.size()` 或提前判空

## 面试追问

**Q1: 这道题和 LeetCode 300（最长递增子序列 LIS）有什么区别？**
→ 300 是**不要求连续**的递增子序列，需要 O(n²) DP 或 O(n log n) 贪心+二分。本题要求**连续**，所以只需要 O(n) 一次遍历。"连续"这个约束大大简化了问题。

**Q2: 如果改成"最长连续非递减序列"（允许相等）呢？**
→ 只需要把判断条件从 `nums[i] > nums[i-1]` 改成 `nums[i] >= nums[i-1]`，其他完全一样。

**Q3: 如果要返回最长连续递增子序列本身（不只是长度），怎么改？**
→ 额外记录最优段的起始位置 `start`。当 `cur > ans` 时更新 `ans` 并记录 `start = i - cur + 1`，最后用 `start` 和 `ans` 截取子数组。

**Q4: 如果数组非常大（10⁹ 级别），需要分布式处理怎么办？**
→ 将数组分成多个块，每个块独立计算内部最长连续递增段。然后检查相邻块的边界：如果前一块最后一个元素 < 后一块第一个元素，需要合并两个跨边界的段。类似 MapReduce 思路。

- **LeetCode 128 最长连续序列** — 不要求在原数组中连续，而是值连续（如 1,2,3,4）。需要哈希表 O(n)。

- **LeetCode 673 最长递增子序列的个数** — 300 的进阶版，不仅要长度还要计数。和本题编号相邻但难度差异很大。
