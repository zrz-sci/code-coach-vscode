# 641. 设计循环双端队列 (Design Circular Deque)

## 核心思路

用**固定大小数组 + front/rear 双指针 + 取模运算**实现循环双端队列。核心技巧是分配 `k+1` 大小的数组来区分"队空"和"队满"（不浪费这一格则两种状态都表现为 `front == rear`，无法区分）。`front` 指向队头元素，`rear` 指向队尾元素的下一个空位。所有 8 个操作均 O(1)。

## 思维链

1. **为什么不直接用 vector/list？** → 面试考的就是底层实现。用 STL 容器等于没答。

2. **为什么选数组不选链表？** → 数组连续存储、缓存友好、无额外指针开销。链表每节点多 2 个指针（prev/next），内存浪费大。数组是面试首选。

3. **普通数组的问题** → 头部插入/删除需要移动所有元素 O(n)。怎么做到 O(1)？

4. **循环数组！** → 把数组想象成一个圆环。front 和 rear 在圆环上移动，到末尾后"绕回"开头。用 `% cap` 实现循环。

5. **如何区分空和满？** → 如果 `cap == k`：空时 `front == rear`，满时 rear 绕一圈也追上 front，也是 `front == rear`！无法区分。
   - 方案 A：**多分配一格** `cap = k+1`，满的条件变为 `(rear+1)%cap == front`
   - 方案 B：**额外维护 size 变量**，空 = `size==0`，满 = `size==k`

6. **指针约定** → `front` 指向队头元素，`rear` 指向队尾的下一个空位。insertFront 先退 front 再写入；insertLast 先写入再进 rear。

## 解法概览

| 解法 | 区分空满的方式 | 数组大小 | 额外变量 | 面试推荐 |
|------|-------------|---------|---------|---------|
| 浪费一格法 | `(rear+1)%cap==front` | k+1 | 无 | ⭐ 首选 |
| size 计数法 | `size==0` / `size==k` | k | int size | 可选 |
| 双向链表 | `size==0` / `size==k` | 动态 | ListNode | 展示链表功底 |

## 关键提示

1. **为什么 `cap = k + 1`？** → 如果 `cap == k`，队满时 rear 绕一圈追上 front，此时 `front == rear`——和空队列一样！浪费一格后，满的条件变为"rear 的下一格是 front"，与空队列的"front == rear"不同，完美区分。

2. **C++ 负数取模陷阱**：`-1 % 4` 在 C++ 中结果可能是 `-1`（而非 3）。必须写 `(front - 1 + cap) % cap` 加 cap 确保非负。Python 无此问题（`-1 % 4 == 3`）。
   ```cpp
   // 正确: 加 cap 确保非负
   front = (front - 1 + cap) % cap;
   // 错误: C++ 中 (0 - 1) % 4 = -1
   front = (front - 1) % cap;
   ```

3. **insertFront 和 insertLast 的写入顺序相反**：
   - insertFront：**先移后写**。因为 front 指向当前头元素，要在它前面插入，必须先退一步腾出位置。
   - insertLast：**先写后移**。因为 rear 指向空位，直接写入后再前进到下一个空位。
   - **搞反会覆盖有效数据！**

4. **getRear 不是 `data[rear]`！** → rear 指向空位。队尾元素在 `data[(rear-1+cap)%cap]`。

5. **删除不需要清零**：deleteFront/deleteLast 只移动指针，不清除数据。被"逻辑删除"的位置在下次写入时会自然被覆盖。

## 解法详解

### 解法 1: 固定数组 + 浪费一格法 — O(1) / O(k)

**8 个操作的实现逻辑**：

| 操作 | 步骤 | 返回值 |
|------|------|--------|
| insertFront(val) | 检查满 → front 后退 → 写入 data[front] | bool |
| insertLast(val) | 检查满 → 写入 data[rear] → rear 前进 | bool |
| deleteFront() | 检查空 → front 前进 | bool |
| deleteLast() | 检查空 → rear 后退 | bool |
| getFront() | 检查空 → 返回 data[front] | int/-1 |
| getRear() | 检查空 → 返回 data[(rear-1+cap)%cap] | int/-1 |
| isEmpty() | front == rear | bool |
| isFull() | (rear+1)%cap == front | bool |

### 解法 2: 固定数组 + size 计数

不浪费空间，用 `size` 变量判断空满。数组大小就是 k。每次 insert 时 `size++`，delete 时 `size--`。

**优点**：不浪费一格空间。
**缺点**：每次操作多维护一个 size 变量。

### 解法 3: 双向链表

用 dummy head + dummy tail 哨兵节点简化边界。insertFront 在 head 后插入，insertLast 在 tail 前插入。

**优点**：概念清晰，无需取模运算。
**缺点**：每个节点多 2 指针（prev/next），内存开销大，缓存不友好。

## 与循环单端队列 (622) 的对比

| 特性 | 622 循环队列 | 641 循环双端队列 |
|------|-------------|-----------------|
| insertFront | 不支持 | 支持 |
| deleteLast | 不支持 | 支持 |
| 指针方向 | 只有前进 (++) | 前进 + 后退 (++/--) |
| 取模方向 | 只有 `(x+1)%cap` | `(x+1)%cap` 和 `(x-1+cap)%cap` |
| 实现难度 | 较低 | 稍高（多 2 个操作方向） |
| 面试频率 | 常见 | 中等 |

## 易错点

1. **C++ 负数取模**：`(front - 1) % cap` 可能为负。必须 `(front - 1 + cap) % cap`。

2. **insertFront 和 insertLast 写入顺序搞反**：
   - ✗ insertFront: 先写 data[front] 再移 front → 覆盖了当前头元素！
   - ✓ insertFront: 先移 front 再写 data[front]

3. **getRear 返回 `data[rear]`**：rear 是空位！正确是 `data[(rear-1+cap)%cap]`。

4. **忘记检查 isFull/isEmpty**：insert 前必须检查满，delete/get 前必须检查空。

5. **cap 初始化为 k 而非 k+1**：浪费一格法必须 k+1，否则空满无法区分。

## 面试追问

**Q1: 浪费一格法 vs size 计数法，哪个更好？**
> 浪费一格法无需额外变量、无原子性问题（多线程环境下 size 的读写需要加锁）。实际工程中多线程无锁队列常用浪费一格法。

**Q2: 如果要支持动态扩容怎么办？**
> 类似 vector 的 2 倍扩容策略：当 isFull 时，分配 2*cap 的新数组，从 front 开始按逻辑顺序复制到新数组，重置 front=0, rear=size。均摊 O(1)。

**Q3: 多线程安全的循环队列怎么设计？**
> 经典的 Lock-Free Ring Buffer：用原子变量存 front 和 rear，CAS 操作实现无锁并发。Linux 内核的 kfifo 就是这种设计。
