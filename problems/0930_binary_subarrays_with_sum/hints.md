# 930. 和相同的二元子数组

[file://./solution.cpp](file://./solution.cpp)

## 核心思路

计算二进制数组中和为 `goal` 的子数组个数。经典的**前缀和 + 哈希表**模式，或者可以用**滑动窗口**的技巧将"恰好等于 K"转化为"小于等于 K"减去"小于等于 K-1"。

## 思维链

1. **读完题第一反应** → 子数组之和问题，和 560 题（和为 K 的子数组）几乎一样。直接用前缀和 + 哈希表。
2. **前缀和的关键等式** → `sum(i..j) = prefix[j+1] - prefix[i]`。如果 `prefix[j+1] - prefix[i] == goal`，则 `prefix[i] == prefix[j+1] - goal`。所以对每个 `prefix[j+1]`，查哈希表中有多少个之前的前缀和等于 `prefix[j+1] - goal`。
3. **滑动窗口能不能用？** → 普通滑动窗口只能处理"小于等于"类型的条件。但巧妙的转化：`count(== goal) = count(<= goal) - count(<= goal-1)`。每个 `count(<= X)` 都可以用标准滑动窗口求解。
4. **为什么滑动窗口能处理"<= X"？** → 数组是二进制的（全非负），窗口内的和随右指针增大而增大，随左指针增大而减小，满足单调性。
5. **goal = 0 的特殊处理** → 前缀和方法天然处理了这个情况（prefix 中相等的值构成配对）。滑动窗口中，`count(<= -1) = 0`，所以也没问题。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 前缀和 + 哈希表 | 存前缀和频率，查找 prefix - goal | O(n) | O(n) | 必须掌握 |
| 滑动窗口 | count(<=goal) - count(<=goal-1) | O(n) | O(1) | 进阶加分 |

## 关键提示

1. **前缀和 + 哈希表是子数组求和的万能模板**：不管数组元素是什么（正、负、零），都适用。本题是 560 题的特殊情况（元素只有0和1）。
2. **初始化 `map[0] = 1`**：表示在遍历开始前，前缀和为0的情况出现过1次（空前缀）。这处理了"从数组开头到当前位置的子数组和恰好等于 goal"的情况。
3. **滑动窗口的技巧：将"恰好等于"转化为两个"小于等于"的差**：`atMost(goal) - atMost(goal - 1)`。这个技巧在很多子数组计数问题中通用。
4. **滑动窗口中 count 的含义**：当右指针在 `r` 位置时，满足条件的子数组右端点都是 `r`，左端点可以是 `left` 到 `r` 的任何位置，所以贡献 `r - left + 1` 个。
5. **goal = 0 时全0子数组的计数**：`[0,0,0,0,0]` goal=0 时答案是 15 = C(5+1,2) = 所有非空子数组都满足。

## 解法详解

### 解法1: 前缀和 + 哈希表 — O(n) / O(n)

**思考过程**: 子数组和问题的经典套路。`sum(i..j) == goal` 等价于 `prefix[j] - prefix[i-1] == goal`，即查找之前有多少个前缀和等于 `prefix[j] - goal`。

```
示例: nums = [1,0,1,0,1], goal = 2

prefix:     0  1  1  2  2  3
            ↑           ↑
            初始       遍历中

遍历过程 (prefix 边算边查):
j=0: prefix=1, 查 1-2=-1 → 0个      map={0:1, 1:1}
j=1: prefix=1, 查 1-2=-1 → 0个      map={0:1, 1:2}
j=2: prefix=2, 查 2-2=0  → 1个 ✓    map={0:1, 1:2, 2:1}
j=3: prefix=2, 查 2-2=0  → 1个 ✓    map={0:1, 1:2, 2:2}
j=4: prefix=3, 查 3-2=1  → 2个 ✓    map={0:1, 1:2, 2:2, 3:1}

总计: 0+0+1+1+2 = 4
```

```cpp
class Solution {
public:
    int numSubarraysWithSum(vector<int>& nums, int goal) {
        unordered_map<int, int> prefixCount;
        prefixCount[0] = 1; // 空前缀，前缀和为0

        int prefix = 0;
        int result = 0;

        for (int num : nums) {
            prefix += num;
            // 查找之前有多少个前缀和等于 prefix - goal
            if (prefixCount.count(prefix - goal)) {
                result += prefixCount[prefix - goal];
            }
            // 记录当前前缀和
            prefixCount[prefix]++;
        }

        return result;
    }
};
```

**关键点**:
- 与 560 题代码几乎一模一样，只是数组元素限定为0和1。
- 初始化 `prefixCount[0] = 1` 不能遗忘。
- 先查后存，和 Two Sum 的思路一致。

---

### 解法2: 滑动窗口 — O(n) / O(1)

**从另一个角度**: 利用元素非负的性质，滑动窗口可以高效计算"和 <= X 的子数组个数"。然后 `count(==goal) = atMost(goal) - atMost(goal-1)`。

```
atMost(goal) 的计算:
维护窗口 [left, right]，窗口和 <= goal
每当 right 扩展后窗口和 > goal，收缩 left
此时以 right 为右端点、左端点在 [left, right] 的子数组都满足
贡献 right - left + 1 个

示例: nums = [1,0,1,0,1], goal = 2
atMost(2):
  right=0: sum=1<=2, 贡献1  (子数组: [1])
  right=1: sum=1<=2, 贡献2  (子数组: [0], [1,0])
  right=2: sum=2<=2, 贡献3  (子数组: [1], [0,1], [1,0,1])
  right=3: sum=2<=2, 贡献4  (子数组: [0], [1,0], [0,1,0], [1,0,1,0])
  right=4: sum=3>2, left++ sum=2<=2, 贡献4
  total = 1+2+3+4+4 = 14

atMost(1):
  right=0: sum=1<=1, 贡献1
  right=1: sum=1<=1, 贡献2
  right=2: sum=2>1, left++ sum=1<=1, 贡献2
  right=3: sum=1<=1, 贡献3
  right=4: sum=2>1, left++ sum=1<=1, left++ sum=1<=1, 贡献2
  total = 1+2+2+3+2 = 10

result = 14 - 10 = 4 ✓
```

```cpp
class Solution {
public:
    int numSubarraysWithSum(vector<int>& nums, int goal) {
        return atMost(nums, goal) - atMost(nums, goal - 1);
    }

private:
    // 计算和 <= goal 的子数组个数
    int atMost(vector<int>& nums, int goal) {
        if (goal < 0) return 0;

        int left = 0, sum = 0, count = 0;
        for (int right = 0; right < (int)nums.size(); right++) {
            sum += nums[right];
            while (sum > goal) {
                sum -= nums[left];
                left++;
            }
            // 以 right 结尾、左端点在 [left, right] 的子数组都满足
            count += right - left + 1;
        }
        return count;
    }
};
```

**关键点**:
- `atMost(goal - 1)` 当 `goal = 0` 时变成 `atMost(-1)`，需要直接返回0。
- 窗口单调性保证：元素非负，右移 right 窗口和不减，右移 left 窗口和不增。
- O(1) 空间是这个解法相比前缀和方法的优势。

## 解法对比

|  | 前缀和+哈希表 | 滑动窗口 |
|--|--------------|---------|
| 时间 | O(n) | O(n) |
| 空间 | **O(n)** | **O(1)** |
| 通用性 | 适用于任何数组（含负数） | 仅适用于非负数组 |
| 代码复杂度 | 简单 | 需要封装 atMost 函数 |
| 适用范围 | 560题也能用 | 利用了二进制数组特性 |

**面试选择**: 前缀和方法更通用、更快写出。如果面试官问"能否 O(1) 空间"，再讲滑动窗口。

## 易错点

1. **忘记初始化 `prefixCount[0] = 1`**：
   - 如果子数组从第0个元素开始、和恰好等于 goal，此时需要 `prefix - goal == 0` 在表中有记录。
   - 不初始化会少算这些子数组。

2. **滑动窗口中 goal < 0 未特判**：
   - `atMost(-1)` 时数组元素全非负，不可能有和 <= -1 的子数组，应直接返回0。
   - 否则 while 循环可能导致 left > right 的异常情况。

3. **把前缀和方法中的"先查后存"写反**：
   - 先存后查可能导致自身配对（当 goal == 0 时，prefix - goal == prefix，会匹配自己刚存入的值）。
   - 必须先查再存。

4. **滑动窗口贡献量理解错误**：
   - 每次 right 固定时贡献 `right - left + 1`，不是 `1`。因为所有左端点在 `[left, right]` 范围内的子数组都以 right 结尾且和 <= goal。

## 面试追问

**Q1: 前缀和方法和 560 题有什么区别？**
> 本质上没区别。本题数组元素只有0和1，但解法完全相同。560 题数组元素可以是任意整数，前缀和+哈希表仍然适用。

**Q2: 滑动窗口为什么不能直接求"恰好等于 goal"？**
> 因为当窗口和等于 goal 时，收缩左指针可能仍然等于 goal（中间有0），无法确定左边界。"恰好等于"的窗口左边界不唯一。但"小于等于"有明确的最左左边界。

**Q3: 如果数组元素不只是0和1（含负数），滑动窗口还能用吗？**
> 不能。滑动窗口依赖窗口和的单调性（右移 left 一定使和减小），负数破坏了这个性质。此时只能用前缀和+哈希表。

**Q4: goal 非常大（接近 n）时有优化吗？**
> 没有本质优化。无论 goal 多大，两种方法都是 O(n)。但可以提前判断：如果 goal > 数组元素总和，直接返回0。

## 相关题型

- **560. 和为 K 的子数组** — 本题的通用版本，数组元素可以是任意整数。前缀和+哈希表是标准解法。本题是它的特殊情况。
- **992. K 个不同整数的子数组** — 同样使用 `atMost(K) - atMost(K-1)` 的滑动窗口技巧，但统计的是"不同整数个数"而非"和"。
- **1248. 统计「优美子数组」** — 统计恰好含 K 个奇数的子数组数量，与本题思路几乎相同（奇数看作1，偶数看作0）。
- **325. 和等于 k 的最长子数组长度** — 前缀和+哈希表，但目标是找最长而非计数。哈希表存的是首次出现的索引而非频率。
