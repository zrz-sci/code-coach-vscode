# 794. Valid Tic-Tac-Toe State - 有效的井字游戏

## 核心思路

本题要求判断一个 3x3 井字棋棋盘状态是否可能在合法游戏过程中出现。核心在于 **分类讨论 + 约束检查**：先验证棋子数量是否符合回合规则（X 先手），再验证获胜状态与回合数是否一致。这道题并不需要任何高级数据结构或算法，纯粹考察逻辑分析的严密性。

关键观察：合法状态必须同时满足数量约束和获胜约束，缺一不可。

## 思维链

1. **X 先手规则**：X 总是先下，因此任何合法状态中 X 的数量要么等于 O（O 刚下完），要么比 O 多一个（X 刚下完）
2. **获胜即终止**：一旦某方获胜，游戏立即结束，对手不能再落子
3. **互斥获胜**：在一步棋不可能同时让两方获胜的规则下，X 和 O 不能同时处于获胜状态
4. **回合数与获胜方的绑定**：如果 X 获胜，意味着最后一步是 X 下的，所以 countX = countO + 1；如果 O 获胜，最后一步是 O 下的，所以 countX = countO

逻辑推导链：数量检查 -> 获胜检查 -> 获胜与数量的一致性检查 -> 综合判定

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 核心技巧 | 适用场景 |
|------|-----------|-----------|---------|---------|
| 分类讨论法 | O(1) | O(1) | 独立 wins() 辅助函数 | 面试首选，逻辑清晰 |
| 行列累加值法 | O(1) | O(1) | X=+1, O=-1, 和为 +-3 判胜 | 代码紧凑，一次遍历 |

## 关键提示

### 提示 1 - 统计棋子数量
设 countX 和 countO 分别为 X 和 O 的数量。由于 X 先手，合法状态必须满足：
- `countX == countO`（轮到 X 下，或 O 刚下完且游戏未结束/O 赢了）
- `countX == countO + 1`（轮到 O 下，或 X 刚下完且游戏未结束/X 赢了）

任何其他情况（如 O 比 X 多、X 比 O 多两个以上）都不合法。

### 提示 2 - 编写获胜检查函数
获胜条件：某玩家在三行、三列、两条对角线中的任何一条上占满三个格子。
编写 `wins(board, player)` 函数，逐一检查 8 条线（3 行 + 3 列 + 2 对角线）。

### 提示 3 - 获胜后的约束
这是最容易遗漏的部分：
- 如果 X 赢了，此时必须 `countX == countO + 1`（因为获胜的那步是 X 下的）
- 如果 O 赢了，此时必须 `countX == countO`（因为获胜的那步是 O 下的）
- X 和 O 不能同时获胜（一方赢了游戏就停止了）

### 提示 4 - 累加值替代方案
用 +1 代表 X，-1 代表 O，分别对每行、每列、两条对角线求和。和为 3 表示 X 占满，和为 -3 表示 O 占满。这样可以在一次遍历中同时完成计数和获胜检查。

## 解法详解

### 解法一：分类讨论法（面试首选）

**核心思路**：分三步检查——数量约束、获胜检查、一致性验证。

**Step 1**：遍历棋盘，统计 countX 和 countO。如果不满足 `countX == countO` 或 `countX == countO + 1`，直接返回 false。

**Step 2**：编写辅助函数 `wins(board, player)` 检查某个玩家是否获胜。需要检查：
- 3 行：`board[i][0] == board[i][1] == board[i][2] == player`
- 3 列：`board[0][j] == board[1][j] == board[2][j] == player`
- 主对角线：`board[0][0] == board[1][1] == board[2][2] == player`
- 副对角线：`board[0][2] == board[1][1] == board[2][0] == player`

**Step 3**：综合约束检查：
- `xWin && oWin` -> false（不可能同时赢）
- `xWin && countX != countO + 1` -> false（X 赢但不是 X 刚下完）
- `oWin && countX != countO` -> false（O 赢但不是 O 刚下完）
- 其余情况 -> true

**举例分析**：
- `["XOX","O O","XOX"]`：countX=4, countO=3, 4==3+1 合法。X 没赢，O 没赢，返回 true
- `["XXX","OOX","OOX"]`：countX=5, countO=4, 5==4+1 合法。但 X 赢了且 O 也有 4 个子，说明 X 赢后 O 还下了两步，但检查发现 countX==countO+1 满足，O 没赢，所以... 等一下，countX=5 意味着总共 9 格填了 9 格，X 赢了（第一行全 X），O 没赢，countX=5==4+1 满足，返回 true。实际上此状态对应 X 在第 9 步下完后恰好第一行全 X。

### 解法二：行列累加值法

**核心思路**：用数值编码简化获胜检查。X 贡献 +1，O 贡献 -1。维护 rows[3]、cols[3]、diag、anti 四组累加值。

遍历棋盘时同步更新计数和累加值。遍历完成后：
- 某行/列/对角和为 3 表示 X 获胜
- 某行/列/对角和为 -3 表示 O 获胜

用 lambda 或内联函数 `checkWin(target)` 统一检查。其余逻辑与解法一相同。

优点：代码更紧凑，只需一次遍历。缺点：抽象程度较高，面试中不如解法一直观。

## 易错点

1. **忘记互斥获胜检查**
   - 错误：分别检查 xWin 和 oWin 但没有判断 `xWin && oWin` 的情况
   - 正确：必须先判断两者不能同时为 true

2. **获胜与回合数不匹配**
   - 错误：X 赢了但 countX == countO，说明 O 在 X 赢后又下了一步
   - 正确：X 赢时 countX 必须比 countO 多恰好 1；O 赢时两者必须相等

3. **只检查数量不检查获胜**
   - 错误：认为只要数量关系对就合法
   - 正确：`["XXX","   ","OOO"]` 数量 3:3 合法，但 X 和 O 同时赢，实际不合法

4. **对角线检查遗漏**
   - 错误：只检查主对角线，忘记副对角线
   - 正确：两条对角线都要检查（左上到右下，右上到左下）

5. **混淆先手后手**
   - 错误：假设 O 先手
   - 正确：题目规定 X 先手，因此 countX >= countO

## 面试追问

**Q1: 为什么 X 赢了的时候必须 countX == countO + 1？**
X 先手。X 获胜意味着 X 完成了某一行/列/对角线的第三个棋子。此时游戏立即结束，O 不能再下。因为 X 先手，每一轮结束后要么 countX == countO + 1（X 刚下完），要么 countX == countO（O 刚下完）。X 获胜的那步一定是 X 下的，所以 countX == countO + 1。

**Q2: 为什么 X 和 O 不能同时获胜？**
获胜意味着游戏终止。如果 X 先占满一条线，游戏已结束，O 不可能再下棋去占满另一条线。反之亦然。所以在任何合法游戏流程中，最多一方获胜。

**Q3: 如果棋盘扩展到 NxN 需要 N 连珠获胜，解法怎么推广？**
数量约束不变（countX == countO 或 countX == countO + 1）。获胜检查需要遍历所有 N 行、N 列和 2 条对角线，时间从 O(1) 变为 O(N^2)。累加值方法可以一次遍历完成：行和、列和通过索引映射，对角线和通过 i==j 和 i+j==N-1 判断。

**Q4: 能否用状态空间搜索来验证？**
可以。用 BFS/DFS 从空棋盘开始枚举所有合法状态，检查目标状态是否在合法集合中。但这会探索约 9! = 362880 种路径（实际因剪枝远少于此），对固定 3x3 可行但不如直接验证高效。面试中不推荐这种方法。

**Q5: 如果允许重叠放置（即同一格可以被覆盖），规则怎么变？**
此时数量约束变为 countX + countO <= 9 且 |countX - countO| <= 1，获胜状态的检查不变但需要考虑覆盖后的最终状态。这是一个开放问题，面试官可能希望你讨论覆盖顺序对合法性的影响。
