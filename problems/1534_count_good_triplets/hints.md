# 1534. 统计好三元组 (Count Good Triplets)

## 核心思路

在数组中找出所有满足三个绝对值差条件的**有序三元组** `(arr[i], arr[j], arr[k])`，其中 `i < j < k`。

数据范围极小（`n <= 100`），所以 **O(n^3) 暴力枚举** 就是正解。面试中更重要的是：如何在暴力基础上做**剪枝优化**和讨论**大数据量下的优化思路**。

## 思维链

1. **读完题第一反应** → 三元组且要求 `i < j < k`，最直观就是三层循环枚举所有可能的 `(i, j, k)` 组合。
2. **暴力可行吗？** → `n <= 100`，三层循环最多 `C(100,3) ≈ 16万` 次，完全没问题。
3. **有没有更快的？** → 可以利用条件之间的关系做剪枝：先固定 `i, j`，如果 `|arr[i] - arr[j]| > a` 就直接跳过内层循环。
4. **能否降到 O(n^2)？** → 固定 `j` 作为中间元素，分别用前缀计数数组统计左边满足条件的 `i` 的数量和右边满足条件的 `k` 的数量。但由于 n 很小，不需要这么复杂。
5. **关键数学观察** → 三个条件是**同时满足**（AND），所以任何一个不满足就可以提前跳过。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力三重循环 | 枚举所有 (i,j,k) 三元组 | O(n^3) | O(1) | 对本题足够 |
| 剪枝优化 | 先检查 (i,j) 条件再进内层 | O(n^3) 最坏，实际快很多 | O(1) | 推荐写出 |
| 枚举中间元素 + 前缀计数 | 固定 j，前后分别计数 | O(n * V) | O(V) | 讨论即可 |

其中 V 是值域大小（本题 V = 1001）。

## 关键提示

1. **绝对值不等式展开**：`|arr[i] - arr[j]| <= a` 等价于 `arr[j] - a <= arr[i] <= arr[j] + a`，这在优化时很有用。
2. **剪枝顺序**：三个条件中，`|arr[i] - arr[j]| <= a` 在最外两层就能检查，可以跳过大量无效的内层循环。
3. **三元组计数 vs 列举**：本题只需要**计数**，不需要列出所有三元组，所以可以用数学公式加速。
4. **边界注意**：`0 <= arr[i] <= 1000`，绝对值不会溢出 `int`。

## 解法详解

### 解法1: 暴力三重循环 — O(n^3) / O(1)

**思考过程**: 数据量 n <= 100 极小，直接三层 for 循环枚举所有 `i < j < k`，检查三个条件。

```
枚举过程 (arr = [3,0,1,1,9,7], a=7, b=2, c=3):

i=0, j=1, k=2: |3-0|=3<=7  |0-1|=1<=2  |3-1|=2<=3  -> count++  (3,0,1)
i=0, j=1, k=3: |3-0|=3<=7  |0-1|=1<=2  |3-1|=2<=3  -> count++  (3,0,1)
i=0, j=1, k=4: |3-0|=3<=7  |0-9|=9>2   -> skip
i=0, j=1, k=5: |3-0|=3<=7  |0-7|=7>2   -> skip
i=0, j=2, k=3: |3-1|=2<=7  |1-1|=0<=2  |3-1|=2<=3  -> count++  (3,1,1)
i=0, j=2, k=4: |3-1|=2<=7  |1-9|=8>2   -> skip
...
i=1, j=2, k=3: |0-1|=1<=7  |1-1|=0<=2  |0-1|=1<=3  -> count++  (0,1,1)
...

总计: 4 个好三元组
```

```cpp
class Solution {
public:
    int countGoodTriplets(vector<int>& arr, int a, int b, int c) {
        int n = arr.size();
        int count = 0;
        for (int i = 0; i < n - 2; i++) {
            for (int j = i + 1; j < n - 1; j++) {
                for (int k = j + 1; k < n; k++) {
                    if (abs(arr[i] - arr[j]) <= a &&
                        abs(arr[j] - arr[k]) <= b &&
                        abs(arr[i] - arr[k]) <= c) {
                        count++;
                    }
                }
            }
        }
        return count;
    }
};
```

**关键点**:
- `i < n-2, j < n-1, k < n` 确保三元组有三个不同位置。
- 三个条件用 `&&` 短路求值，前面的条件不满足就不检查后面的。
- 时间 O(n^3)，n=100 时约 16 万次，毫秒级。

---

### 解法2: 剪枝优化 — O(n^3) 最坏 / O(1) ⭐ 推荐

**从解法1优化**: 如果 `|arr[i] - arr[j]| > a`，那么对所有 `k` 都不可能形成好三元组，直接跳过整个内层循环。这是一个简单但非常有效的剪枝。

```
剪枝效果分析:

无剪枝: 枚举所有 (i,j,k) → C(n,3) 次
有剪枝: 只对满足 |arr[i]-arr[j]|<=a 的 (i,j) 对才进入 k 循环

当 a 很小时（比如 a=0），大量 (i,j) 对被跳过，
实际运行时间可能只有无剪枝的 1/10。
```

```cpp
class Solution {
public:
    int countGoodTriplets(vector<int>& arr, int a, int b, int c) {
        int n = arr.size();
        int count = 0;
        for (int i = 0; i < n - 2; i++) {
            for (int j = i + 1; j < n - 1; j++) {
                // 剪枝: 先检查 (i,j) 的条件，不满足直接跳过整个 k 循环
                if (abs(arr[i] - arr[j]) > a) continue;
                
                for (int k = j + 1; k < n; k++) {
                    if (abs(arr[j] - arr[k]) <= b &&
                        abs(arr[i] - arr[k]) <= c) {
                        count++;
                    }
                }
            }
        }
        return count;
    }
};
```

**关键点**:
- 剪枝前：n=100 时约 16 万次内层迭代。
- 剪枝后：当 `a` 较小时，大量 `(i,j)` 对被跳过，实际运行快数倍。
- 最坏情况（所有元素相等，a/b/c 极大）仍是 O(n^3)，但这种情况实际很少。
- `continue` 比嵌套 `if` 更清晰，减少缩进层级。

### 解法3: 枚举中间元素 + 值域计数 — O(n^2 + n*V) / O(V)

**适用于数据量更大的场景讨论**:

固定 `j` 作为中间元素。对于满足条件的三元组 `(i, j, k)`:
- `i < j`: 需要 `|arr[i] - arr[j]| <= a`，即 `arr[j]-a <= arr[i] <= arr[j]+a`
- `k > j`: 需要 `|arr[j] - arr[k]| <= b`，即 `arr[j]-b <= arr[k] <= arr[j]+b`
- 同时需要 `|arr[i] - arr[k]| <= c`

如果忽略第三个条件（或者把它融入范围），可以用前缀计数加速:
- 维护一个值域数组 `leftCnt[v]` 表示 j 左边值为 v 的元素个数
- 遍历 j 时，在值域 `[arr[j]-a, arr[j]+a]` 范围内求和

```
枚举中间元素的思路:

对于 j=2, arr[j]=1, a=7, b=2, c=3:

左边满足 |arr[i]-1| <= 7 的元素:
  arr[0]=3: |3-1|=2 <= 7  ✓
  arr[1]=0: |0-1|=1 <= 7  ✓
  leftCnt in [1-7, 1+7] = [-6, 8] → 2个

右边满足 |arr[k]-1| <= 2 的元素:
  arr[3]=1: |1-1|=0 <= 2  ✓
  arr[4]=9: |9-1|=8 > 2   ✗
  arr[5]=7: |7-1|=6 > 2   ✗
  rightCnt in [1-2, 1+2] = [-1, 3] → 1个

还需检查第三个条件 |arr[i]-arr[k]| <= c
```

> 注意: 由于第三个条件关联了 i 和 k，无法直接用乘法原理。完整的 O(n*V) 优化需要更精细的值域分析，面试中口述思路即可。

## 面试应对

### 面试官可能追问

**Q: 如果 n 扩大到 10^5，怎么办？**

A: O(n^3) 不可行。可以枚举中间元素 `j`，然后：
- 用前缀和数组维护左边满足条件的 `i` 的值域分布
- 对右边的 `k` 同理计数
- 但第三个条件 `|arr[i] - arr[k]| <= c` 让问题复杂化
- 可能需要 BIT/线段树，时间降到 O(n^2) 或 O(n * V * log V)

**Q: 能不能不用三重循环就把这题做出来？**

A: 对于 n <= 100，三重循环是最清晰正确的做法。过度优化反而增加了 bug 风险。面试时说明"当前数据量暴力足够，然后讨论优化方向"是加分的。

**Q: 如果只有两个条件（二元组），怎么做？**

A: 两层循环 O(n^2)，或排序后用滑动窗口/双指针 O(n log n)。

**Q: 三个条件是否有冗余？**

A: 不冗余。虽然 `|a-c| <= |a-b| + |b-c|`（三角不等式），但这只给出上界。三个独立阈值 a, b, c 意味着三个条件互不蕴含。

## 易错点

1. **循环边界**：`i < n-2, j < n-1` 或者 `i < n, j < n`（不影响正确性但影响效率）。
2. **绝对值**：别忘了用 `abs()`，减法可能为负。
3. **条件用 AND 连接**：三个条件必须**同时满足**。
4. **三元组是有序的**：`i < j < k` 意味着下标递增，不是值递增。
5. **重复值的处理**：`arr[2]=1` 和 `arr[3]=1` 是不同位置，可以分别参与三元组。

## Follow-up 思考

1. **如果要返回所有好三元组的列表而非计数？** → 直接在计数处改为 push_back 即可，注意输出格式。
2. **如果数组有负数？** → `abs()` 仍然有效，代码无需修改。
3. **如果条件改为 `arr[i] + arr[j] + arr[k] <= target`？** → 变成三数之和变体，排序+双指针可优化到 O(n^2)。
4. **如果只需要判断是否存在而非计数？** → 找到第一个就 return true，平均更快。
