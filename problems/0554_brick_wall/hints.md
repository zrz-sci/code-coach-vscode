# 554. 砖墙

## 核心思路

**穿过最少的砖块 = 经过最多的砖缝。** 把"求最少穿过"转化为"求最多经过边缘"，用哈希表统计每个位置有多少条砖缝，答案就是 `n - 最大砖缝数`。

## 思维链

1. **读完题第一反应**：垂线可以画在任何 x 坐标上，我需要检查每个可能的 x 位置，看穿过了多少块砖。
2. **暴力想法**：枚举每个整数 x 位置（从 1 到 wallWidth-1），对每一行检查这条线是否穿过某块砖。但是砖的宽度可以很大（最大 2^31-1），x 的范围太大了。
3. **关键观察**：线只有画在"砖缝"的位置才有意义！不在砖缝上的位置一定穿过那一行的某块砖。所以**有效位置只有砖缝出现的那些 x 坐标**，数量有限。
4. **逆向思考**：穿过的砖 = 总行数 - 该 x 位置上的砖缝数。要最小化穿过的砖，就要**最大化某个 x 位置上的砖缝数**。
5. **怎么统计砖缝？** 对每一行，算出每块砖的右边缘（前缀和），除了最后一块砖的右边缘（那是墙的右边界，题目不允许），其余都是砖缝位置。用**哈希表**统计每个砖缝位置出现了多少次。
6. **答案**：`n - max(哈希表中的值)`。如果哈希表为空（每行只有一块砖），答案就是 n。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举所有可能 x 位置，逐行判断 | O(W × n) | O(n) | 能说出即可 |
| 哈希表统计砖缝 | 前缀和找砖缝位置，哈希表计数取最大 | O(总砖块数) | O(总砖块数) | ⭐ 必须写出 |

> 其中 W 是墙的宽度，n 是行数。由于 W 可达 2^31，暴力不可行。

## 关键提示

1. **逆向思维**：不要想"线穿过了几块砖"，要想"线经过了几条砖缝"。穿过的砖 = 总行数 - 经过的砖缝数。

2. **前缀和就是砖缝位置**：一行砖 `[1, 2, 2, 1]`，前缀和是 `[1, 3, 5, 6]`。除了最后一个 6（墙的右边界），`{1, 3, 5}` 就是砖缝的 x 坐标。

3. **砖墙示意图**（以示例1为例）：
```
x坐标:  0  1  2  3  4  5  6
        |  |     |     |  |
Row 0:  |1 | 2   | 2   |1 |     砖缝在 x = 1, 3, 5
Row 1:  |  3     |1 | 2   |     砖缝在 x = 3, 4
Row 2:  |1 |  3     | 2   |     砖缝在 x = 1, 4
Row 3:  | 2   |  4         |     砖缝在 x = 2
Row 4:  |  3     |1 | 2   |     砖缝在 x = 3, 4
Row 5:  |1 |  3     |1 |1 |     砖缝在 x = 1, 4, 5
        
砖缝统计: x=1:3次, x=2:1次, x=3:3次, x=4:4次, x=5:2次
最大砖缝数 = 4 (在 x=4)
答案 = 6 - 4 = 2
```

4. **不要枚举 x 的值域**：砖的宽度可达 2^31，不能用数组。哈希表以前缀和为 key，自动只处理有效位置。

5. **排除右边界**：前缀和的最后一个值（墙的总宽度）不能算砖缝，题目明确说不能沿两侧垂直边缘画线。

## 解法详解

### 解法1: 暴力枚举（概念理解） — O(W × n) / O(n)

**思考过程**：最直接的想法——枚举每个整数 x 位置，对每一行检查这条线是否落在砖缝上。

```cpp
class Solution {
public:
    int leastBricks(vector<vector<int>>& wall) {
        int n = wall.size();
        // 先算出墙的总宽度
        int totalWidth = 0;
        for (int w : wall[0]) totalWidth += w;
        
        int minCross = n; // 最坏情况：穿过所有行
        
        // 枚举 x = 1 到 totalWidth-1
        for (int x = 1; x < totalWidth; x++) {
            int cross = 0;
            for (int i = 0; i < n; i++) {
                // 检查第 i 行在 x 位置是否有砖缝
                int pos = 0;
                bool hitEdge = false;
                for (int j = 0; j < (int)wall[i].size() - 1; j++) {
                    pos += wall[i][j];
                    if (pos == x) { hitEdge = true; break; }
                    if (pos > x) break;
                }
                if (!hitEdge) cross++;
            }
            minCross = min(minCross, cross);
        }
        return minCross;
    }
};
```

**关键点**：这个解法在 W 很大时（砖宽可达 2^31）完全不可行，但它帮助我们理解问题结构：**只有砖缝位置才是有效候选**。

---

### 解法2: 哈希表统计砖缝 — O(总砖块数) / O(总砖块数) ⭐ 面试首选

**从解法1优化**：解法1的瓶颈是枚举了所有 x 位置，但大部分位置没有砖缝。我们只需要关注砖缝出现的位置，用哈希表直接统计。

**核心转化**：`穿过的砖块数 = 总行数 - 该位置的砖缝数`。最小化穿过 = 最大化砖缝数。

```cpp
class Solution {
public:
    int leastBricks(vector<vector<int>>& wall) {
        unordered_map<int, int> edgeCount; // key: 砖缝x坐标, value: 出现次数
        
        for (const auto& row : wall) {
            int prefixSum = 0;
            // 遍历每行的砖，排除最后一块（右边界不算砖缝）
            for (int i = 0; i < (int)row.size() - 1; i++) {
                prefixSum += row[i];
                edgeCount[prefixSum]++;  // 这个位置有一条砖缝
            }
        }
        
        // 找到最大的砖缝数
        int maxEdges = 0;
        for (const auto& [pos, cnt] : edgeCount) {
            maxEdges = max(maxEdges, cnt);
        }
        
        // 穿过的砖 = 总行数 - 最大砖缝数
        return wall.size() - maxEdges;
    }
};
```

**为什么正确？**
- 每一行，砖的前缀和（不含最后一个）就是该行砖缝的 x 坐标
- 哈希表记录了每个 x 坐标上有多少行有砖缝
- 选砖缝最多的位置画线，穿过的砖最少

**关键点**：
- 循环到 `row.size() - 1` 而不是 `row.size()`，排除右边界
- 如果每行只有一块砖（无砖缝），`edgeCount` 为空，`maxEdges = 0`，答案就是 `n`

## 解法对比

| | 暴力枚举 | 哈希表统计砖缝 |
|---|---|---|
| 时间 | O(W × n) | O(总砖块数) |
| 空间 | O(1) | O(总砖块数) |
| 适用性 | W 小时可用 | 通用，面试首选 |
| 核心思想 | 逐位置检查 | 逆向思维 + 前缀和 + 计数 |

选择建议：面试直接用哈希表解法，但要能解释清楚"为什么统计砖缝"这个逆向思维。

## 易错点

1. **忘记排除右边界**
   - ✗ `for (int i = 0; i < row.size(); i++)` — 把墙的右边界也当成了砖缝，右边界处砖缝数 = n，答案变成 0
   - ✓ `for (int i = 0; i < (int)row.size() - 1; i++)` — 排除最后一块砖

2. **哈希表为空时返回错误**
   - ✗ 直接返回 `n - maxEdges` 没问题，但如果有人写成 `*max_element(...)` 会在空容器上崩溃
   - ✓ 初始化 `maxEdges = 0`，空表时自然返回 n

3. **前缀和溢出**
   - 题目说 `wall[i][j]` 可达 2^31-1，多块砖的前缀和可能溢出 int
   - ✓ 但题目约束 `sum(wall[i].length) <= 2*10^4`，说明砖块总数有限，实际不会有特别多块超大砖。不过严谨起见可以用 `long long`

4. **混淆"砖块数"和"砖缝数"**
   - 一行有 k 块砖，砖缝数是 k-1，不是 k

## 面试追问

**Q1: 暴力法的时间复杂度瓶颈在哪？**
> 瓶颈是枚举所有 x 位置，x 范围可达 2^31。但有效的砖缝位置数量 ≤ 总砖块数 ≤ 2×10^4，远小于 x 范围。所以应该只看砖缝位置。

**Q2: 为什么是"总行数 - 最大砖缝数"？能否直接统计穿过的砖？**
> 可以但更复杂。每行在某个位置要么有砖缝（不穿过），要么没有（穿过）。穿过数 = n - 砖缝数。最小化穿过 = 最大化砖缝，只需要一个 max 操作。

**Q3: 如果允许在墙的两侧画线，答案会怎么变？**
> 答案永远是 0，因为两侧的"砖缝数"等于 n（每行都有边界）。这就是为什么题目排除了这种情况。

**Q4: 如果要求返回最优线的具体 x 坐标呢？**
> 在遍历哈希表时记录 maxEdges 对应的 key 即可。如果有多个最优位置，可以全部收集。
