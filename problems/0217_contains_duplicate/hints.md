# 217. 存在重复元素

## 核心思路

本质上在问：**数组中是否存在两个相同的元素？** 也就是判断数组元素的唯一性。

## 思维链

1. **读完题第一反应**：对于每个元素，检查数组中后面是否还有跟它一样的 → 两层循环暴力枚举所有配对。
2. **暴力解的瓶颈**：两层循环 O(n²)，对每个元素都要线性扫描剩余部分，**"查找某个值是否已经出现过"这个操作花了 O(n)**。
3. **怎么突破瓶颈？**：有两条路：
   - **排序**：排序后相同元素一定相邻，只需检查相邻对 → O(n log n)
   - **哈希集合**：把"查找是否出现过"从 O(n) 降到 O(1) → O(n)
4. **哈希集合怎么用？**：一边遍历，一边把元素放入集合。放入之前先查一下，如果已经在集合里了，说明重复。
5. **还有一种思路**：如果排序后数组长度不变但相邻元素有相同的，就有重复。或者直接看 `set` 去重后大小是否变小。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 双重循环比较所有配对 | O(n²) | O(1) | 能说出即可 |
| 排序 | 排序后检查相邻元素 | O(n log n) | O(1)* | 加分项 |
| 哈希集合 | 边遍历边查集合 | O(n) | O(n) | ⭐ 必须写出 |

> *排序解法空间取决于排序算法，原地排序是 O(1)，但会修改原数组。

## 关键提示

1. **最暴力的做法**：拿每个元素去和其他所有元素比较 — 能通过吗？n 最大 10⁵，O(n²) = 10¹⁰，超时。
2. **排序的妙处**：排序后，重复元素一定挨在一起。你只需要比较 `nums[i]` 和 `nums[i+1]`。
3. **哈希集合的本质**：用空间换时间。`set.count(x)` 或 `set.find(x)` 是 O(1) 的，所以总体只需 O(n)。
4. **一个取巧判断**：如果 `set(nums).size() < nums.size()`，说明有重复。一行搞定，但本质和哈希集合一样。
5. **思考空间 vs 时间的取舍**：排序解法不需要额外空间但会改原数组；哈希解法不改原数组但需要 O(n) 空间。面试时可以主动提到这个 trade-off。

## 解法详解

### 解法1: 暴力枚举 — O(n²) / O(1)

**思考过程**：最直接的想法——对于每个元素 `nums[i]`，检查它后面的所有元素中有没有和它相同的。如果找到就返回 true。

```cpp
class Solution {
public:
    bool containsDuplicate(vector<int>& nums) {
        int n = nums.size();
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                if (nums[i] == nums[j]) {
                    return true;   // 找到一对相同的，直接返回
                }
            }
        }
        return false;  // 所有配对都不同
    }
};
```

**关键点**：n 最大 10⁵，O(n²) ≈ 10¹⁰ 次操作，**会超时**。但这是理解题目最好的起点，也是面试中展示"我理解了题意"的方式。

---

### 解法2: 排序 — O(n log n) / O(1)

**从解法1优化**：暴力法的瓶颈是"对每个元素，都要在无序数组中搜索是否有重复"。如果数组**有序**，相同元素一定相邻，只需检查相邻对即可。

```cpp
class Solution {
public:
    bool containsDuplicate(vector<int>& nums) {
        sort(nums.begin(), nums.end());  // 排序，使相同元素相邻
        for (int i = 1; i < (int)nums.size(); i++) {
            if (nums[i] == nums[i - 1]) {
                return true;   // 相邻元素相同 → 有重复
            }
        }
        return false;
    }
};
```

**关键点**：
- 排序会**修改原数组**。如果题目要求不能改原数组，需要先拷贝一份。
- 排序 O(n log n) + 一次遍历 O(n) = O(n log n)，比暴力快很多。

---

### 解法3: 哈希集合 — O(n) / O(n) ⭐ 面试首选

**从排序进一步优化**：排序的瓶颈是 O(n log n) 的排序步骤。我们真正需要的只是"快速判断一个元素是否出现过"。**哈希集合 (unordered_set) 的查找是 O(1)**，所以一次遍历即可。

```cpp
class Solution {
public:
    bool containsDuplicate(vector<int>& nums) {
        unordered_set<int> seen;       // 记录已经遍历过的元素
        for (int num : nums) {
            if (seen.count(num)) {     // O(1) 查找：num 之前出现过吗？
                return true;           // 出现过 → 有重复
            }
            seen.insert(num);          // 没出现过 → 记录下来
        }
        return false;                  // 遍历完都没重复
    }
};
```

**为什么边遍历边查就够了？** 当遍历到 `nums[i]` 时，集合中已经包含了 `nums[0..i-1]` 的所有元素。如果 `nums[i]` 在集合中，说明前面某个位置有相同的值。这样一次遍历就能覆盖所有配对情况。

**关键点**：
- `unordered_set` 平均 O(1) 查找/插入，最坏 O(n)（哈希冲突严重时），但实际几乎不会发生。
- 空间 O(n)，最坏情况下所有元素都不同，集合大小等于数组长度。

---

### 解法3b: 一行写法（利用集合大小）

```cpp
class Solution {
public:
    bool containsDuplicate(vector<int>& nums) {
        // set 会自动去重，如果去重后大小变小了，说明有重复
        return unordered_set<int>(nums.begin(), nums.end()).size() < nums.size();
    }
};
```

**注意**：这种写法简洁但会把**所有**元素都放入集合，无法提前终止。解法3在发现第一个重复时就返回，实际更快。

---

## 解法对比

| | 暴力枚举 | 排序 | 哈希集合 |
|------|------|------|------|
| 时间 | O(n²) | O(n log n) | O(n) |
| 空间 | O(1) | O(1)* | O(n) |
| 改原数组 | 否 | 是 | 否 |
| 能否提前终止 | 能 | 能 | 能 |
| 面试推荐 | ✗ | 作为过渡方案提及 | ✓ 首选 |

> 选择建议：**面试默认写哈希集合**。如果面试官追问"能否不用额外空间"，再给排序解法。

## 易错点

1. **排序解法忘了从 i=1 开始**：
   - ✗ `for (int i = 0; ...)` 然后比较 `nums[i] == nums[i-1]` → `i=0` 时 `nums[-1]` 越界！
   - ✓ `for (int i = 1; i < n; i++)` 比较 `nums[i] == nums[i-1]`

2. **哈希集合先插入再查找**：
   - ✗ 先 `seen.insert(num)` 再 `seen.count(num)` → 永远返回 true（自己跟自己比）
   - ✓ 先 `seen.count(num)` 查找，再 `seen.insert(num)` 插入

3. **一行写法用了 `set` 而不是 `unordered_set`**：
   - `set` 是红黑树，插入/查找 O(log n)，总体 O(n log n)
   - `unordered_set` 是哈希表，插入/查找 O(1)，总体 O(n)

## 面试追问

**Q1: 暴力法能通过吗？瓶颈在哪？**
> 不能。n = 10⁵，O(n²) = 10¹⁰ 超时。瓶颈在于对每个元素都要线性扫描判断是否出现过。

**Q2: 如果不允许使用额外空间，怎么做？**
> 排序后检查相邻元素，O(n log n) 时间、O(1) 空间（原地排序）。代价是修改了原数组。如果也不能改原数组，那 O(1) 空间做不到 O(n) 时间（理论下界），排序是最优的。

**Q3: 如果改成"判断是否存在两个元素之差的绝对值 ≤ t"呢？（LeetCode 220）**
> 这就是 "Contains Duplicate III"。不能简单用哈希集合判等了，需要用**有序集合** (`set` 红黑树) 维护滑动窗口，或者用**桶排序**的思想把元素映射到大小为 t+1 的桶中。

## 相关题型

- **220. 存在重复元素 III** — 增加约束"值差 ≤ t 且下标差 ≤ k"。从哈希集合升级为有序集合或桶排序。
- **1. 两数之和** — 同样是"边遍历边查哈希表"的经典模式，区别是查的不是自身而是 `target - num`。
