# 670. 最大交换

## 核心思路

本质上是在问：在一个数字的所有位中，找到一对位置 `(i, j)`（`i < j`），交换后使得数字最大。贪心策略是尽量让高位变大——从最高位开始，找到后面比它大的最大数字（如果有多个相同的取最靠右的），交换过来。

## 思维链

1. **读完题第一反应**：数字最多 9 位（≤10^8），暴力枚举所有可能的交换对数最多 C(9,2) = 36 种，完全可以接受。
2. **暴力能过，但能否更优雅？** 暴力虽然 O(n²) 但 n≤9 所以无所谓。但面试中需要展示贪心思维。
3. **贪心直觉**：要让数字最大，就应该让尽可能高的位上放尽可能大的数字。所以从最高位往右扫，找到第一个"不够大"的位。
4. **什么叫"不够大"？** 如果当前位的右侧存在比它更大的数字，就应该把那个更大的数字换过来。
5. **如果右侧有多个相同的最大数字，选哪个？** 选**最靠右的那个**，因为把低位的大数字换到高位，损失最小。
6. **具体做法**：预处理每个位置右侧（含自身）的最大数字及其最右出现位置，然后从高位往低位扫，找到第一个可以"变大"的位，交换即可。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举所有交换对，取最大值 | O(n²) | O(n) | 能说出即可 |
| 贪心（后缀最大值） | 从右往左记录最大数字最后出现位置 | O(n) | O(n) | ⭐ 必须写出 |
| 贪心（记录每个数字最后位置） | 用数组记录 0-9 每个数字最后出现的下标 | O(n) | O(1) | 加分项 |

## 关键提示

1. **先转字符串**：数字操作按位处理不方便，转成字符串（或字符数组）后按下标操作。
2. **为什么选最右的？** 考虑 `1993`：右侧最大数字是 9，有两个。应该选下标 3 的 9（最右），交换后得 `9913`；如果选下标 1 的 9，交换 `9` 和 `1` 得到 `9913`——嗯这个例子两个一样。换个例子 `98368`：8 出现在下标 1 和 4，从左扫到下标 2 时发现 3 < 8，应该拿下标 4 的 8 来换，得 `98863`。如果拿下标 1 的 8 来换就成了 `98368`（自己和自己换没意义）。
3. **只需要一次交换**：找到第一个可以变大的高位就立即交换并返回，不要继续找。
4. **已经是最大时**：如果从头到尾每一位都是右侧最大的，说明数字是非递增排列，不需要交换。

## 解法详解

### 解法1: 暴力枚举 — O(n²) / O(n)

**思考过程**：数字最多 9 位，枚举所有 (i, j) 对交换后取最大值。n 很小所以完全可行。

```cpp
class Solution {
public:
    int maximumSwap(int num) {
        string s = to_string(num);
        int n = s.size();
        int best = num;
        
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                swap(s[i], s[j]);
                best = max(best, stoi(s));
                swap(s[i], s[j]); // 撤销交换
            }
        }
        return best;
    }
};
```

**关键点**：交换后要撤销（回溯），否则后续枚举基于错误的状态。

---

### 解法2: 贪心（后缀最大值）— O(n) / O(n) ⭐ 面试首选

**从解法1优化**：暴力枚举了所有交换对，但实际上我们只需要找"从左往右第一个不是最大的位"，然后把右边那个最大值换过来。

**核心逻辑**：
```
数字: 2 7 3 6
      ↑
      从左扫，2 < 右侧最大值 7
      把最右的 7 换到位置 0 → 7236
```

```
数字: 9 9 7 3
      每一位都 >= 右侧最大值，无需交换
```

```cpp
class Solution {
public:
    int maximumSwap(int num) {
        string s = to_string(num);
        int n = s.size();
        
        // suffixMaxIdx[i] = 从位置 i 到末尾，最大数字的最右出现下标
        vector<int> suffixMaxIdx(n);
        suffixMaxIdx[n - 1] = n - 1;
        for (int i = n - 2; i >= 0; i--) {
            // 注意用 >= 保证取最右的（相同数字取靠右的位置）
            if (s[i] > s[suffixMaxIdx[i + 1]]) {
                suffixMaxIdx[i] = i;
            } else {
                suffixMaxIdx[i] = suffixMaxIdx[i + 1];
            }
        }
        
        // 从左往右扫，找第一个可以变大的位
        for (int i = 0; i < n; i++) {
            int j = suffixMaxIdx[i]; // 右侧（含自身）最大数字的最右位置
            if (s[j] > s[i]) {
                // 当前位不是右侧最大的，交换后数字变大
                swap(s[i], s[j]);
                return stoi(s);
            }
        }
        
        return num; // 已经是最大，无需交换
    }
};
```

**关键点**：`suffixMaxIdx` 的构建中，`s[i] > s[suffixMaxIdx[i+1]]` 用严格大于（`>`），这样当 `s[i] == s[右侧最大]` 时，保留右侧的下标（即更靠右的位置）。

---

### 解法3: 贪心（记录每个数字最后位置）— O(n) / O(1)

**换一个角度**：直接用长度为 10 的数组记录每个数字 0-9 最后出现的下标，然后从高位开始，看能否换上一个更大的数字。

```cpp
class Solution {
public:
    int maximumSwap(int num) {
        string s = to_string(num);
        int n = s.size();
        
        // last[d] = 数字 d 最后一次出现的下标
        int last[10] = {};
        for (int i = 0; i < n; i++) {
            last[s[i] - '0'] = i;
        }
        
        // 从高位到低位，尝试找一个更大的数字换过来
        for (int i = 0; i < n; i++) {
            // 从 9 到当前数字+1，看有没有比当前位更大的数字在右边
            for (int d = 9; d > s[i] - '0'; d--) {
                if (last[d] > i) {
                    // 数字 d 的最后出现位置在 i 的右边，交换
                    swap(s[i], s[last[d]]);
                    return stoi(s);
                }
            }
        }
        
        return num;
    }
};
```

**为什么从 9 往下尝试？** 因为我们想让高位尽可能大，所以优先看有没有 9 可以换过来，没有再看 8，以此类推。

**为什么用"最后出现位置"？** 同样的数字，选最靠右的来换，这样高位变大的同时低位的损失最小。

## 解法对比

| | 暴力枚举 | 后缀最大值 | 最后位置数组 |
|---|---|---|---|
| 时间 | O(n²) | O(n) | O(n)，内层最多循环 10 次 |
| 空间 | O(n) 字符串 | O(n) 后缀数组 | O(1) 固定 10 个元素 |
| 思路 | 无脑枚举 | 预处理后缀信息 | 记录每个数字位置 |
| 面试 | 说清楚即可 | ⭐ 推荐 | 代码最简洁 |

三种解法在这道题上性能差异极小（n ≤ 9），面试中推荐解法 2 或 3，能体现贪心思维。

## 易错点

1. **后缀最大值取最右位置时的比较方向**：
   - ✗ `if (s[i] >= s[suffixMaxIdx[i+1]])` → 当 `s[i]` 等于右侧最大值时，`suffixMaxIdx[i] = i`（取了靠左的位置）
   - ✓ `if (s[i] > s[suffixMaxIdx[i+1]])` → 相等时保留右侧更靠右的位置
   - 错误案例：`1993`，如果最大值 9 记录了下标 1 而非下标 2，交换 `s[0]` 和 `s[1]` 得 `9193`，而正确答案是 `9913`（交换 `s[0]` 和 `s[2]`）

2. **忘记"不需要交换"的情况**：
   - ✗ 一定要找一对交换
   - ✓ 如果遍历完都没有 `s[j] > s[i]`，直接返回原数

3. **stoi 溢出**：题目说 `num ≤ 10^8`，交换后最大 `99999999`，int 范围内安全。但如果题目范围更大要注意。

## 面试追问

**Q1: 暴力解能过吗？瓶颈在哪？**
A: 能过，因为数字最多 9 位，O(n²) = O(81)。但面试官期望贪心思路。

**Q2: 为什么贪心是正确的？能否严格证明？**
A: 要让数字最大，首先要让最高位尽可能大（因为高位的权重大于所有低位之和，如 1000 > 999）。所以从高位开始，找到第一个"可以变大"的位交换，就是全局最优。不需要继续看后面的位，因为高位的增益一定大于低位。

**Q3: 如果允许交换 K 次呢？**
A: 这变成了一个更复杂的贪心/DP 问题。可以用贪心：每次找到最高位可以提升的交换执行，重复 K 次。也可以用类似"从大到小排序，看最少需要多少次交换"的思路（类似排序问题的最少交换次数）。
