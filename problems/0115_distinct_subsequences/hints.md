# 115. 不同的子序列

## 核心思路

本质上是一个**子序列匹配计数问题**：在 s 中选若干字符（保持相对顺序），使之恰好等于 t，问有多少种选法。这是一个经典的二维 DP 问题，核心决策是"s 的每个字符用不用来匹配 t 的当前字符"。

## 思维链

1. **读完题第一反应**：穷举 s 的所有子序列，检查哪些等于 t。s 长度最大 1000，子序列数量是 2^1000 —— 完全不可行。
2. **换个角度穷举**：不要枚举子序列本身，而是考虑「逐字符匹配」。对 s 的第 i 个字符和 t 的第 j 个字符，如果它们相同，有两种选择：**用 s[i] 去匹配 t[j]**，或者**不用 s[i]（跳过它，去后面找别的字符匹配 t[j]）**。如果不同，只能跳过 s[i]。
3. **发现重叠子问题**：递归时 `(i, j)` 的组合会被反复计算 → 加记忆化 → 或者直接用 DP 递推。
4. **定义状态**：`dp[i][j]` = s 的前 i 个字符中，有多少个子序列等于 t 的前 j 个字符。
5. **状态转移**：
   - 若 `s[i-1] == t[j-1]`：`dp[i][j] = dp[i-1][j-1] + dp[i-1][j]`（匹配 + 不匹配两条路）
   - 若 `s[i-1] != t[j-1]`：`dp[i][j] = dp[i-1][j]`（只能跳过 s[i]）
6. **空间优化**：每行只依赖上一行 → 可以用一维滚动数组，但注意遍历方向必须**从右往左**，否则 `dp[j-1]` 会被提前覆盖。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力递归 | DFS 穷举所有匹配方式 | O(2^m) 指数级 | O(m) 栈深 | 能说出即可 |
| 记忆化搜索 | 递归 + memo | O(m×n) | O(m×n) | 能说出即可 |
| 二维 DP | 递推填表 | O(m×n) | O(m×n) | ⭐ 必须写出 |
| 一维 DP（空间优化） | 滚动数组 | O(m×n) | O(n) | 加分项 |

> m = len(s), n = len(t)

## 关键提示

1. **子序列 vs 子串**：子序列不要求连续，只要求保持相对顺序。所以这题不能用滑动窗口。
2. **核心决策只有一个**：当 `s[i] == t[j]` 时，选择"用"还是"不用"s[i] 来匹配 t[j]。两条路的方案数**相加**。
3. **初始化关键**：`dp[i][0] = 1`（s 的任意前缀都有 1 种方式匹配空串 t —— 什么都不选）；`dp[0][j] = 0`（j>0 时，空串 s 无法匹配非空 t）。
4. **空间优化的陷阱**：如果用一维数组，内层循环必须**从右到左**遍历，因为 `dp[j]` 依赖 `dp[j-1]`（上一行的值），从左到右会提前覆盖。

```
DP 填表方向示意（s="babgbag", t="bag"）:

       ""  b  a  g
  ""    1  0  0  0
  b     1  1  0  0
  a     1  1  1  0
  b     1  2  1  0
  g     1  2  1  1
  b     1  3  1  1
  a     1  3  4  1
  g     1  3  4  5  ← 答案

填表方向: 从上到下，从左到右
dp[i][j] 依赖 dp[i-1][j-1]（左上）和 dp[i-1][j]（正上）
```

## 解法详解

### 解法1: 暴力递归 — O(2^m) / O(m)

**思考过程**：最自然的想法是从 s 和 t 的末尾开始匹配。如果 s[i] == t[j]，有两个选择：用它匹配（i-1, j-1）或者不用（i-1, j）。如果不等，只能跳过（i-1, j）。递归到 j < 0 说明 t 匹配完了，返回 1；i < 0 但 j >= 0 说明 s 用完了但 t 还没匹配完，返回 0。

```cpp
class Solution {
public:
    int numDistinct(string s, string t) {
        return dfs(s, t, s.size() - 1, t.size() - 1);
    }
    
    int dfs(const string& s, const string& t, int i, int j) {
        if (j < 0) return 1;          // t 匹配完了，找到一种方案
        if (i < 0) return 0;          // s 用完了，t 还没匹配完
        
        // 不用 s[i]（跳过）
        int result = dfs(s, t, i - 1, j);
        
        // 用 s[i] 匹配 t[j]（仅当相等时）
        if (s[i] == t[j]) {
            result += dfs(s, t, i - 1, j - 1);
        }
        
        return result;
    }
};
```

**关键点**：指数级复杂度，只能用于理解思路，无法通过大数据。但这个递归框架是后续所有优化的基础。

---

### 解法2: 记忆化搜索 — O(m×n) / O(m×n)

**从解法1优化**：递归中 `(i, j)` 的组合只有 m×n 种，但存在大量重复计算。加一个 memo 数组缓存即可。

```cpp
class Solution {
public:
    int numDistinct(string s, string t) {
        int m = s.size(), n = t.size();
        // memo[i][j] = -1 表示未计算
        vector<vector<int>> memo(m, vector<int>(n, -1));
        return dfs(s, t, m - 1, n - 1, memo);
    }
    
    int dfs(const string& s, const string& t, int i, int j,
            vector<vector<int>>& memo) {
        if (j < 0) return 1;
        if (i < 0) return 0;
        if (memo[i][j] != -1) return memo[i][j];
        
        int result = dfs(s, t, i - 1, j, memo);  // 跳过 s[i]
        if (s[i] == t[j]) {
            result += dfs(s, t, i - 1, j - 1, memo);  // 用 s[i] 匹配 t[j]
        }
        
        return memo[i][j] = result;
    }
};
```

**关键点**：记忆化搜索是自顶向下的 DP，和递推（自底向上）本质相同。

---

### 解法3: 二维 DP（递推）— O(m×n) / O(m×n) ⭐ 面试首选

**从记忆化翻译成递推**：把递归参数 `(i, j)` 变成表格的行列。

**状态定义**：`dp[i][j]` = s 的前 i 个字符的子序列中，等于 t 的前 j 个字符的方案数。

**转移方程**：
- `s[i-1] == t[j-1]`：`dp[i][j] = dp[i-1][j-1] + dp[i-1][j]`
- `s[i-1] != t[j-1]`：`dp[i][j] = dp[i-1][j]`

**初始化**：`dp[i][0] = 1`（空 t 总有 1 种匹配方式），`dp[0][j>0] = 0`

```cpp
class Solution {
public:
    int numDistinct(string s, string t) {
        int m = s.size(), n = t.size();
        // 用 unsigned long long 防止中间加法溢出
        vector<vector<unsigned long long>> dp(m + 1, vector<unsigned long long>(n + 1, 0));
        
        // base case: 匹配空串 t 的方式只有 1 种（什么都不选）
        for (int i = 0; i <= m; i++) {
            dp[i][0] = 1;
        }
        
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                // 不用 s[i-1]，直接继承上一行
                dp[i][j] = dp[i - 1][j];
                // 用 s[i-1] 匹配 t[j-1]（仅当相等时）
                if (s[i - 1] == t[j - 1]) {
                    dp[i][j] += dp[i - 1][j - 1];
                }
            }
        }
        
        return (int)dp[m][n];
    }
};
```

**关键点**：
- 用 `unsigned long long` 而非 `int`：虽然题目保证最终结果在 32 位范围内，但中间累加可能溢出。
- `dp[i][j]` 只依赖 `dp[i-1][j-1]` 和 `dp[i-1][j]`，即上一行的"正上方"和"左上方"，这为空间优化奠定基础。

---

### 解法4: 一维 DP（空间优化）— O(m×n) / O(n) 加分项

**从解法3优化**：`dp[i][j]` 只依赖上一行，可以压缩到一维。关键：**内层循环必须从右到左**。

为什么从右到左？因为 `dp[j]` 更新时需要用到 `dp[j-1]`（代表上一行的 `dp[i-1][j-1]`）。如果从左到右遍历，`dp[j-1]` 已经被当前行覆盖了，就不是"上一行"的值了。

```
// 一维滚动过程 (s="babgbag", t="bag"):
//
// 初始 dp:  [1, 0, 0, 0]    （dp[0]=1 始终不变）
//                j=3  ←  j=1    ← 从右到左更新
//
// i=1 (s[0]='b'):  [1, 1, 0, 0]   dp[1] += dp[0] 因为 b==b
// i=2 (s[1]='a'):  [1, 1, 1, 0]   dp[2] += dp[1] 因为 a==a
// i=3 (s[2]='b'):  [1, 2, 1, 0]   dp[1] += dp[0] 因为 b==b
// i=4 (s[3]='g'):  [1, 2, 1, 1]   dp[3] += dp[2] 因为 g==g
// i=5 (s[4]='b'):  [1, 3, 1, 1]   dp[1] += dp[0] 因为 b==b
// i=6 (s[5]='a'):  [1, 3, 4, 1]   dp[2] += dp[1] 因为 a==a
// i=7 (s[6]='g'):  [1, 3, 4, 5]   dp[3] += dp[2] 因为 g==g
//                              ↑ 答案 = 5
```

```cpp
class Solution {
public:
    int numDistinct(string s, string t) {
        int m = s.size(), n = t.size();
        vector<unsigned long long> dp(n + 1, 0);
        dp[0] = 1;  // 匹配空 t 的方式 = 1
        
        for (int i = 1; i <= m; i++) {
            // 从右到左更新，保证 dp[j-1] 还是"上一行"的值
            for (int j = n; j >= 1; j--) {
                if (s[i - 1] == t[j - 1]) {
                    dp[j] += dp[j - 1];
                }
                // 不等时 dp[j] 保持不变，相当于 dp[i][j] = dp[i-1][j]
            }
        }
        
        return (int)dp[n];
    }
};
```

**关键点**：当 `s[i-1] != t[j-1]` 时，`dp[j]` 不需要更新，天然等于上一轮（上一行）的 `dp[j]`。这就是为什么代码里不需要 else 分支。

## 解法对比

| | 暴力递归 | 记忆化搜索 | 二维 DP | 一维 DP |
|---|---|---|---|---|
| 时间 | O(2^m) | O(m×n) | O(m×n) | O(m×n) |
| 空间 | O(m) 栈 | O(m×n) | O(m×n) | O(n) |
| 思维难度 | 低 | 低 | 中 | 中高 |
| 面试推荐 | 仅用于讲思路 | 可以先写这个 | ⭐ 首选 | 追问时给出 |

**选择建议**：面试时先写二维 DP（清晰易懂），面试官追问空间优化时再给一维版本。

## 易错点

1. **初始化 `dp[i][0]` 忘了设为 1**
   - ✗ `dp[i][0] = 0`（默认值）→ 所有状态都是 0
   - ✓ `dp[i][0] = 1`（空串 t 总有 1 种匹配方式 —— 不选任何字符）
   - **为什么**：这是 base case，没有它整张表无法正确填充

2. **一维 DP 内层循环方向写反**
   - ✗ `for (int j = 1; j <= n; j++)` → `dp[j-1]` 已被当前行覆盖，结果偏大
   - ✓ `for (int j = n; j >= 1; j--)` → `dp[j-1]` 还是上一行的值
   - **为什么**：和 0/1 背包空间优化同理，"用过就不能再用"对应从右到左

3. **中间结果溢出**
   - ✗ 用 `int` 做 dp 数组 → 中间累加可能超过 INT_MAX
   - ✓ 用 `unsigned long long` 或 `long long` → 最终结果再转 int
   - **为什么**：题目只保证最终答案在 32 位范围，不保证中间值

4. **下标搞混（0-indexed vs 1-indexed）**
   - ✗ `if (s[i] == t[j])` 在 1-indexed DP 中 → 越界
   - ✓ `if (s[i-1] == t[j-1])` → dp 数组多了一行一列用于 base case

## 面试追问

**Q1: 能否解释一下状态转移方程的含义？**
> 当 `s[i-1] == t[j-1]` 时，有两个选择：(1) 用 s[i-1] 匹配 t[j-1]，剩余问题变成 `dp[i-1][j-1]`；(2) 不用 s[i-1]，保留更多选择余地，方案数是 `dp[i-1][j]`。两种选择互斥，方案数相加。

**Q2: 为什么空间优化时内层循环要从右到左？**
> 因为 `dp[j]` 的更新依赖 `dp[j-1]`（上一行的值）。如果从左到右遍历，`dp[j-1]` 会被当前行提前覆盖。这和 0/1 背包的空间优化原理完全一致 —— 每个物品只能用一次，所以容量从大到小遍历。

**Q3: 这道题和编辑距离(LC 72)有什么关系？**
> 两者都是双字符串二维 DP，状态定义类似（`dp[i][j]` 基于两个字符串的前缀）。区别在于：编辑距离有插入/删除/替换三种操作取 min，而本题只有"选/不选"两种决策取 sum。它们共享相同的"二维 DP on 两个字符串"的建模框架。

**Q4: 如果 s 和 t 的长度极大（10^5），O(m×n) 还能接受吗？如何优化？**
> O(m×n) = 10^10 会超时。可以考虑：(1) 预处理 t 中每个字符在 s 中的出现位置，用记忆化 + 剪枝跳过大量不匹配的字符；(2) 如果 t 中某个字符在 s 中不存在，直接返回 0。不过这属于极端优化场景，一般面试不会追问到这里。
