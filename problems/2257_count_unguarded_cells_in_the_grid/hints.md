# 2257. 统计网格图中没有被保卫的格子数

## 核心思路

本质上就是一个**模拟题**：从每个警卫出发，沿上下左右四个方向"发射射线"，碰到墙或其他警卫就停止，标记沿途格子为"被保卫"。最后数一下既不是墙、也不是警卫、也没被保卫的格子有多少。

## 思维链

1. **读完题第一反应**：每个警卫能看到四个方向的所有格子（直到被墙或另一个警卫挡住）。最朴素的想法：对每个警卫，向四个方向逐格扩展，标记"被保卫"。

2. **这个暴力有多暴力？** 每个警卫最多扩展到整行和整列，即 O(m + n)。总共有 G 个警卫，所以总工作量是 O(G × (m + n))。考虑到 `m * n ≤ 10^5` 和 `G ≤ 5 × 10^4`，这个复杂度完全可以接受！

3. **关键发现**：这道题的"暴力"其实就是最优解。因为每个警卫必须沿四个方向走到头（碰到墙/警卫才停），你不可能比"走一遍"更快。唯一需要注意的是**用矩阵标记状态**来避免重复计数。

4. **实现细节**：用一个二维数组 `grid[m][n]` 来记录每个格子的状态：
   - `0` = 空闲（未被保卫）
   - `1` = 警卫
   - `2` = 墙
   - `3` = 被保卫

5. **最终**：遍历 grid，数值为 `0` 的格子就是答案。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 模拟（标记矩阵） | 从每个警卫四方向射线扩展 | O(m×n + G×(m+n)) | O(m×n) | ⭐ 必须写出 |
| BFS 变体 | 把警卫作为起点 BFS（本质相同） | O(m×n + G×(m+n)) | O(m×n) | 能说出即可 |

> 注：这道题本质上只有一种核心思路，区别仅在实现风格（直接模拟 vs BFS 框架）。

## 关键提示

1. **射线不是 BFS**：警卫的视线是直线的，不需要像 BFS 一样向四面八面扩散。每个方向就是一个 `while` 循环往一个方向走。

2. **警卫也能挡住视线**：题目说"被墙**或另一个警卫**挡住"。所以扩展时碰到警卫也要停！

3. **不要把"被保卫"和"警卫/墙"搞混**：被保卫的格子不能阻挡视线，只有警卫和墙能。所以碰到已经标记为"被保卫"的格子要继续走，不能停。

4. **矩阵示意图**（示例1）：
```
     0   1   2   3   4   5
  +---+---+---+---+---+---+
0 | G | W | g | g | g | g |    G=警卫, W=墙, g=被保卫, .=空闲
  +---+---+---+---+---+---+
1 | g | G | g | g | W |   |
  +---+---+---+---+---+---+
2 | g | g | W | G | g | g |
  +---+---+---+---+---+---+
3 | . | . | . | g | . | . |    7个"."就是答案
  +---+---+---+---+---+---+
```

5. **数据范围陷阱**：`m, n` 各自可达 `10^5`，但 `m * n ≤ 10^5`。所以矩阵不会很大，O(m×n) 空间没问题。

## 解法详解

### 解法1: 模拟射线标记 — O(m×n) / O(m×n) ⭐ 面试首选

**思考过程**：

最自然的想法：我需要知道每个格子是否被保卫。怎么判断？从每个警卫出发，沿四个方向走，走过的格子就是被保卫的。碰到墙或另一个警卫就停。

关键问题是怎么标记不同类型的格子：
- 需要区分"空闲"、"警卫"、"墙"和"被保卫"四种状态
- 因为扩展时碰到"被保卫"的格子要继续走（它不阻挡视线），但碰到"警卫"或"墙"要停

```cpp
class Solution {
public:
    int countUnguarded(int m, int n, vector<vector<int>>& guards, vector<vector<int>>& walls) {
        // 状态: 0=空闲, 1=警卫, 2=墙, 3=被保卫
        vector<vector<int>> grid(m, vector<int>(n, 0));
        
        // 先标记所有墙和警卫
        for (auto& w : walls) {
            grid[w[0]][w[1]] = 2;
        }
        for (auto& g : guards) {
            grid[g[0]][g[1]] = 1;
        }
        
        // 四个方向: 上、下、左、右
        int dirs[4][2] = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};
        
        // 从每个警卫出发，四方向射线扩展
        for (auto& g : guards) {
            for (auto& d : dirs) {
                int r = g[0] + d[0];
                int c = g[1] + d[1];
                // 沿一个方向一直走，碰到边界/墙/警卫才停
                while (r >= 0 && r < m && c >= 0 && c < n 
                       && grid[r][c] != 1 && grid[r][c] != 2) {
                    grid[r][c] = 3;  // 标记为被保卫
                    r += d[0];
                    c += d[1];
                }
            }
        }
        
        // 统计空闲格子（值为0的格子）
        int count = 0;
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == 0) count++;
            }
        }
        return count;
    }
};
```

**关键点**：
- `while` 循环的终止条件：碰到 `grid[r][c] == 1`（警卫）或 `grid[r][c] == 2`（墙）就停。碰到 `grid[r][c] == 3`（已被保卫）不停，继续走！
- 这意味着同一个格子可能被多个警卫"走过"，但由于标记为 3 后不影响逻辑，所以没问题。

**复杂度分析**：
- 时间：O(m×n) 初始化 + O(G × (m+n)) 射线扩展 + O(m×n) 统计 = **O(m×n + G×(m+n))**。由于 `m*n ≤ 10^5`，实际非常快。
- 空间：O(m×n) 存储网格状态。

### 解法2: 枚举优化思路（按行/列排序）— 了解即可

**思考过程**：

另一种角度：不从警卫出发扩展，而是**按行扫描**和**按列扫描**。

对于每一行，从左到右扫描，遇到警卫就开始标记右边的格子，直到碰到墙或另一个警卫；然后从右到左扫描处理左边。对每一列做同样的事（从上到下、从下到上）。

这本质上和解法1是等价的，但思维角度不同——从"行列扫描"而非"从警卫出发"。

```cpp
class Solution {
public:
    int countUnguarded(int m, int n, vector<vector<int>>& guards, vector<vector<int>>& walls) {
        vector<vector<int>> grid(m, vector<int>(n, 0));
        
        for (auto& w : walls) grid[w[0]][w[1]] = 2;
        for (auto& g : guards) grid[g[0]][g[1]] = 1;
        
        // 按行扫描：每行从左到右、从右到左
        for (int i = 0; i < m; i++) {
            // 从左到右：碰到警卫开始标记，碰到墙/警卫停止
            bool guarding = false;
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == 1) {
                    guarding = true;   // 遇到警卫，开始向右保卫
                } else if (grid[i][j] == 2) {
                    guarding = false;  // 遇到墙，保卫中断
                } else if (guarding) {
                    grid[i][j] = 3;    // 空闲格子被保卫
                }
            }
            // 从右到左
            guarding = false;
            for (int j = n - 1; j >= 0; j--) {
                if (grid[i][j] == 1) {
                    guarding = true;
                } else if (grid[i][j] == 2) {
                    guarding = false;
                } else if (guarding) {
                    grid[i][j] = 3;
                }
            }
        }
        
        // 按列扫描：每列从上到下、从下到上
        for (int j = 0; j < n; j++) {
            bool guarding = false;
            for (int i = 0; i < m; i++) {
                if (grid[i][j] == 1) {
                    guarding = true;
                } else if (grid[i][j] == 2) {
                    guarding = false;
                } else if (guarding) {
                    grid[i][j] = 3;
                }
            }
            guarding = false;
            for (int i = m - 1; i >= 0; i--) {
                if (grid[i][j] == 1) {
                    guarding = true;
                } else if (grid[i][j] == 2) {
                    guarding = false;
                } else if (guarding) {
                    grid[i][j] = 3;
                }
            }
        }
        
        int count = 0;
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                if (grid[i][j] == 0) count++;
        return count;
    }
};
```

**关键点**：
- 这种写法保证每个格子最多被访问**常数次**（每行两遍、每列两遍），所以严格 O(m×n)。
- 不需要遍历 guards 数组来逐个发射射线，而是在扫描过程中"顺便"处理。

**复杂度**：
- 时间：O(m×n)（严格，每个格子被扫 4 次）
- 空间：O(m×n)

## 解法对比

| | 解法1: 从警卫射线扩展 | 解法2: 行列扫描 |
|---|---|---|
| 思路 | 以每个警卫为中心，四方向发射 | 逐行逐列线性扫描 |
| 时间 | O(m×n + G×(m+n)) | O(m×n) |
| 空间 | O(m×n) | O(m×n) |
| 优势 | 直觉清晰，代码短 | 严格线性，无重复扫描 |
| 面试推荐 | ⭐ 首选（容易想到、不易出错） | 了解即可（优化幅度不大） |

**实际性能差异**：由于 `m*n ≤ 10^5`，两者在本题约束下几乎没有速度差异。解法1代码更短更直观，面试优先写解法1。

## 易错点

1. **✗ 碰到"被保卫"的格子就停止扩展**
   ```cpp
   // 错误：把 grid[r][c] == 3 也当作阻挡
   while (r >= 0 && r < m && c >= 0 && c < n && grid[r][c] == 0) {
   ```
   **✓ 只有墙和警卫能阻挡视线，被保卫的格子不能**
   ```cpp
   while (r >= 0 && r < m && c >= 0 && c < n 
          && grid[r][c] != 1 && grid[r][c] != 2) {
   ```
   > 为什么：一个格子已经被警卫A保卫，不代表警卫B的射线打不过去。视线只被物理障碍（墙/警卫）阻挡。

2. **✗ 忘记警卫本身也占据格子**
   ```cpp
   // 错误：最后统计时把警卫也算成"没被保卫"
   if (grid[i][j] != 3 && grid[i][j] != 2) count++;
   ```
   **✓ 警卫和墙都不是"空闲"格子，只有值为0的才算**
   ```cpp
   if (grid[i][j] == 0) count++;
   ```

3. **✗ 开辟 `m × n` 数组时 m 和 n 很大**
   > 注意约束：`m, n` 各自可达 `10^5`，但 `m * n ≤ 10^5`。所以实际矩阵不大。如果误以为 `m = n = 10^5` 就开 `10^10` 的数组就爆了。看清约束！

4. **✗ 解法2中，碰到警卫后忘记判断是否也碰到墙**
   ```cpp
   // 注意在行列扫描中，碰到警卫时设置 guarding = true
   // 碰到墙时设置 guarding = false
   // 两者不能混淆：一个格子只可能是其中一种
   ```

## 面试追问

**Q1: 你先用最简单的方式解决这道题？**
> 从每个警卫出发，四方向一直走，碰到墙/警卫停。用矩阵标记状态。时间 O(m×n + G×(m+n))，空间 O(m×n)。

**Q2: 如果同一个格子被多个警卫的射线经过，你的做法会不会重复计数？**
> 不会。我用 `grid[r][c] = 3` 标记被保卫，无论被几个警卫覆盖都只标一次。而且碰到已标记为 3 的格子不停止，因为它不阻挡视线。

**Q3: 能不能把时间做到严格 O(m×n)，不依赖 G？**
> 可以。用行列扫描法：逐行左右扫、逐列上下扫，用 boolean 变量记录"当前是否在某个警卫的视线中"。每个格子恰好被访问 4 次。

**Q4: 如果墙会动态添加/删除，怎么高效更新？**
> 这变成了动态问题。一种思路：对每行/每列用有序集合（如 `std::set`）维护墙和警卫的位置，查询某格子是否被保卫时用二分查找找最近的遮挡物。但实现复杂度较高，面试中说出思路即可。
