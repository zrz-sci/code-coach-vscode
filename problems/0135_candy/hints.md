# 135. 分发糖果 (Candy)

## 核心思路

这道题本质上是一个**约束满足问题**：每个孩子的糖果数同时受到左邻居和右邻居的约束，而这两个方向的约束可能冲突。关键洞察是**把双向约束拆解为两个单向约束，分别处理后取最大值合并**。

## 思维链

1. **读完题第一反应**：每个孩子至少1颗糖，评分更高的比邻居多。最朴素的做法？所有人先给1颗，然后反复扫描，发现不满足条件就调整，直到稳定。

2. **暴力解的问题**：调整一个人可能影响邻居，邻居又影响邻居的邻居... 最坏情况需要多次遍历才收敛，效率不可控。

3. **观察关键性质**：一个孩子需要同时满足"比左邻居关系"和"比右邻居关系"两个约束。能不能把它们拆开？

4. **拆解为两个单向问题**：
   - 从左到右扫描：只考虑"比左邻居评分高→糖果比左邻居多"
   - 从右到左扫描：只考虑"比右邻居评分高→糖果比右邻居多"
   - 每个位置取两次结果的**最大值**，就同时满足了两个方向的约束！

5. **为什么取 max 是对的**：取 max 保证两个方向的约束都满足（较大值一定 ≥ 较小值），同时因为每次单向扫描都是贪心给最少，所以合并后也是全局最少。

6. **能否进一步优化空间**：可以！通过观察评分的"上升-下降"序列（类似山峰），用常数个变量在一次遍历中计算出答案。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力迭代 | 反复扫描直到稳定 | O(n²) | O(n) | 能说出即可 |
| 两次遍历贪心 | 左→右 + 右→左，取max | O(n) | O(n) | ⭐ 必须写出 |
| 一次遍历（上坡下坡） | 统计递增递减序列长度 | O(n) | O(1) | 加分项 |

## 关键提示

1. **提示1**：先忘掉右邻居，只考虑左邻居约束：从左到右扫一遍，`ratings[i] > ratings[i-1]` 时 `candy[i] = candy[i-1] + 1`，否则给1。这一遍之后，所有"比左邻居强"的约束都满足了。

2. **提示2**：再忘掉左邻居，只考虑右邻居约束：从右到左扫一遍，`ratings[i] > ratings[i+1]` 时 `candy[i] = candy[i+1] + 1`，否则给1。

3. **提示3**：两个约束都要满足，取 `max` 即可。想想为什么 `max` 不会破坏任何一个方向的约束？

4. **提示4**：注意 `ratings[i] == ratings[i-1]` 时**不需要**满足"更多糖果"的条件——题目说的是"评分**更高**的"才需要更多。

5. **ASCII 示意图 — 两次遍历过程**：
```
ratings:    [1, 3, 5, 3, 2, 1, 4, 3]

左→右遍历:  [1, 2, 3, 1, 1, 1, 2, 1]
             ↑  ↑  ↑              ↑
            只处理上升，下降全给1   上升+1

右→左遍历:  [1, 1, 3, 2, 1, 1, 1, 1]  ← 注意 [2]=3 因为右边有3个递减
                   ↑

取 max:     [1, 2, 3, 2, 1, 1, 2, 1]
总计 = 13
```

## 解法详解

### 解法1: 暴力迭代 — O(n²) / O(n)

**思考过程**：最直觉的做法——所有人先给1颗糖，然后不断扫描，如果某人评分比邻居高却糖果不比邻居多，就把他的糖果调到 `邻居糖果 + 1`。重复直到一轮下来没有任何调整。

```cpp
class Solution {
public:
    int candy(vector<int>& ratings) {
        int n = ratings.size();
        vector<int> candies(n, 1);
        
        bool changed = true;
        while (changed) {
            changed = false;
            for (int i = 0; i < n; i++) {
                // 检查左邻居约束
                if (i > 0 && ratings[i] > ratings[i-1] 
                    && candies[i] <= candies[i-1]) {
                    candies[i] = candies[i-1] + 1;
                    changed = true;
                }
                // 检查右邻居约束
                if (i < n-1 && ratings[i] > ratings[i+1] 
                    && candies[i] <= candies[i+1]) {
                    candies[i] = candies[i+1] + 1;
                    changed = true;
                }
            }
        }
        
        int total = 0;
        for (int c : candies) total += c;
        return total;
    }
};
```

**关键点**：最坏情况（严格递减序列如 `[5,4,3,2,1]`）需要 O(n) 轮才能稳定，每轮 O(n)，所以总体 O(n²)。这也暴露了瓶颈：信息从右向左传播太慢，每轮只能传播一步。

---

### 解法2: 两次遍历贪心 — O(n) / O(n) ⭐ 面试首选

**从解法1优化**：暴力解的瓶颈是双向约束互相纠缠，导致需要多轮。解法2的核心洞察：**拆成两个独立的单向问题**。

- 第一遍（左→右）：只保证"比左邻居评分高 → 糖果比左邻居多"
- 第二遍（右→左）：只保证"比右邻居评分高 → 糖果比右邻居多"
- 合并：每个位置取两遍结果的 `max`

**为什么 max 是正确的？**
- 取 max 后一定 ≥ 左→右的值，所以左邻居约束仍然满足
- 取 max 后一定 ≥ 右→左的值，所以右邻居约束仍然满足
- 每次单向遍历都是给最少的糖，max 合并后也是最少的

```cpp
class Solution {
public:
    int candy(vector<int>& ratings) {
        int n = ratings.size();
        vector<int> candies(n, 1);
        
        // 第一遍：左→右，处理"比左邻居评分高"的约束
        for (int i = 1; i < n; i++) {
            if (ratings[i] > ratings[i-1]) {
                candies[i] = candies[i-1] + 1;
            }
            // ratings[i] <= ratings[i-1] 时保持1，不需要动
        }
        
        // 第二遍：右→左，处理"比右邻居评分高"的约束
        // 同时累加总数（省一次遍历）
        int total = candies[n-1]; // 最后一个元素直接加
        for (int i = n - 2; i >= 0; i--) {
            if (ratings[i] > ratings[i+1]) {
                // 取 max：不能破坏第一遍已建立的左邻居约束
                candies[i] = max(candies[i], candies[i+1] + 1);
            }
            total += candies[i];
        }
        
        return total;
    }
};
```

**关键点**：第二遍中 `candies[i] = max(candies[i], candies[i+1] + 1)` 这个 `max` 是精髓。如果直接赋值 `candies[i+1] + 1`，可能破坏第一遍建立的左邻居约束。

---

### 解法3: 一次遍历（上坡下坡法） — O(n) / O(1)

**进一步优化空间**：解法2用了 O(n) 的数组。能否用 O(1) 空间？

**核心观察**：评分序列可以看作一系列"山峰"。我们追踪三个变量：
- `up`：当前连续上升序列的长度
- `down`：当前连续下降序列的长度
- `peak`：最近一个峰值位置对应的上升长度

```
ratings:  1  3  5  3  2  1  4  3
          ↗  ↗  ↘  ↘  ↘  ↗  ↘
up:       1  2  3              2
down:              1  2  3        1
peak:           3  3  3  3
```

每遇到上升，当前孩子的糖果数就是 `up + 1`；每遇到下降，下降序列中每个人都要+1（包括可能把峰值顶上去）。

```cpp
class Solution {
public:
    int candy(vector<int>& ratings) {
        int n = ratings.size();
        if (n <= 1) return n;
        
        int total = 1; // 第一个孩子至少1颗
        int up = 0, down = 0, peak = 0;
        
        for (int i = 1; i < n; i++) {
            if (ratings[i] > ratings[i-1]) {
                // 上升：延续或开始上升序列
                up++;
                down = 0;
                peak = up; // 记录峰值高度
                total += up + 1; // 当前孩子得 up+1 颗
            } else if (ratings[i] < ratings[i-1]) {
                // 下降：延续或开始下降序列
                up = 0;
                down++;
                // down 颗给当前孩子，如果下降长度达到peak，峰值也要+1
                total += down + (down >= peak ? 1 : 0);
            } else {
                // 相等：重置，当前孩子给1颗
                up = 0;
                down = 0;
                peak = 0;
                total += 1;
            }
        }
        
        return total;
    }
};
```

**为什么 `down >= peak` 时要额外 +1？**

```
// 例: ratings = [1, 3, 5, 3, 2, 1]
//     上升序列: 1→3→5，peak = 3 (5得到3颗糖)
//     下降序列: 5→3→2→1
// 
// 如果下降长度 = 3，那下降序列的糖果是 3,2,1
// 但峰值(5)也在下降起点，它需要比下降序列第一个(3)多
// 峰值本来是3颗（从上升得来），下降序列第一个也需要3颗
// 所以峰值需要被顶到4颗 → 额外+1
```

**什么时候选哪个？**
- 面试先说解法1展示理解，然后写解法2，时间充裕再讲解法3的思路
- 解法2最好写、最不容易出错、时间最优，是面试标准答案
- 解法3空间更优但代码容易出错，适合追问"能否O(1)空间"时口述思路

## 易错点

1. **相等评分不需要更多糖果**
   - ✗ `if (ratings[i] >= ratings[i-1]) candies[i] = candies[i-1] + 1;`
   - ✓ `if (ratings[i] > ratings[i-1]) candies[i] = candies[i-1] + 1;`
   - 题目说"评分**更高**的"，相等时没有约束，给1颗即可（这样总数更少）

2. **第二遍忘记取 max**
   - ✗ `candies[i] = candies[i+1] + 1;`（直接覆盖）
   - ✓ `candies[i] = max(candies[i], candies[i+1] + 1);`
   - 直接覆盖会破坏第一遍建立的左邻居约束。例如 `ratings = [1,3,2]`，第一遍后 `candies = [1,2,1]`，第二遍处理 `i=1` 时如果直接赋值 `candies[1] = candies[2]+1 = 2`，正确；但如果是 `ratings = [1,5,3,2]`，第一遍 `[1,2,1,1]`，第二遍 `i=1` 需要 `max(2, 3) = 3`。

3. **解法3中 `down >= peak` 的边界**
   - 常见错误：写成 `down > peak`，少加了1，导致峰值和下降首位糖果相同
   - 正确条件是 `>=`，因为当 down 恰好等于 peak 时，下降序列的最高位和峰值糖果数相同，违反"评分更高要更多糖果"

## 面试追问

**Q1（基础理解）**：为什么不能只从左到右扫一遍就解决？
> 只从左到右扫，只保证了"比左邻居评分高→糖果更多"，但不能保证"比右邻居评分高→糖果更多"。例如 `[3,2,1]`，左→右扫完是 `[1,1,1]`，第一个孩子评分最高却只有1颗。

**Q2（优化）**：能否把两个数组优化为一个？
> 可以。第一遍结果存入数组，第二遍在同一个数组上原地取 max，不需要两个独立数组。解法2已经是这样做的。

**Q3（进阶）**：能否用 O(1) 空间？
> 可以，用上坡-下坡法（解法3）。核心思想是把评分序列看作连续的上升和下降段，利用等差数列求和公式直接计算每段的糖果总数，不需要存储每个人的糖果数。

**Q4（变体）**：如果约束改为"评分更高的比**两个**邻居都严格多"且"评分相同的邻居糖果也必须相同"呢？
> "评分相同也要相同"意味着相等时也要传播糖果数（不再重置为1）。修改两次遍历：`ratings[i] >= ratings[i-1]` 时也需要 `candies[i] = candies[i-1] + 1`（上升或相等都传播）。但要注意相等时是"相同"不是"更多"，所以应该是 `candies[i] = candies[i-1]`。
