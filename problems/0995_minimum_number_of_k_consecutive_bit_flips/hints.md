# 995. Minimum Number of K Consecutive Bit Flips

[file://solution.cpp](./solution.cpp)

## 核心思路

贪心 + 滑动窗口/差分数组。从左到右扫描数组，每当遇到当前位为 0（考虑之前翻转的累积效果后）时，必须在当前位置发起一次长度为 k 的翻转。贪心策略的正确性在于：如果某个位置最终需要翻转，越早翻转越好，因为翻转只会影响当前及之后的元素。关键优化是用差分数组或队列来 O(1) 追踪当前位置被翻转的次数，而非真正执行翻转操作。

## 思维链

1. **暴力思考**：每次遇到 0 就翻转 k 个元素，时间 O(nk)，太慢。
2. **关键观察**：翻转是自反的（翻两次等于没翻），所以每个位置要么翻 0 次要么翻 1 次。
3. **贪心方向**：从左到右扫描，如果当前位是 0（累计翻转后），必须在此处翻转。
4. **优化追踪**：不需要真正翻转数组，只需知道当前位置被翻转了几次（奇偶性）。
5. **差分技巧**：用一个 flipCount 变量记录当前有效翻转次数，当翻转窗口滑出时减一。
6. **边界判断**：如果需要翻转但 i + k > n，说明无解返回 -1。

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 暴力翻转 | O(nk) | O(1) | 直接修改数组 |
| 差分数组 | O(n) | O(n) | 用额外数组标记翻转边界 |
| 原地标记 | O(n) | O(1) | 利用 nums 数组本身做标记 |

## 关键提示

1. **差分数组核心**：在位置 i 翻转时，标记 diff[i+k] 表示翻转效果在 i+k 处结束。
2. **翻转奇偶性**：当前位的实际值 = nums[i] XOR (flipCount % 2)，即翻转偶数次不变，奇数次取反。
3. **原地标记技巧**：可以将 nums[i] 设为 2 来标记"此处发起过翻转"，避免额外空间。
4. **贪心正确性**：因为翻转区间是连续的且长度固定，左侧的 0 只能通过起始于该位置或更左侧的翻转来处理。

## 解法详解

### 解法一：差分数组（推荐）

**思路**：维护一个差分数组 `isFlipped`，`isFlipped[i]` 表示位置 i 是否是某次翻转的起点。用 `flipCount` 累计当前位置的有效翻转次数。

**步骤**：
1. 创建数组 `isFlipped[n]`，初始全 0。
2. 维护 `flipCount = 0`，表示当前位置被翻转的累计次数。
3. 遍历每个位置 i：
   - 如果 `i >= k`，则 `flipCount -= isFlipped[i - k]`（窗口滑出）。
   - 如果 `(nums[i] + flipCount) % 2 == 0`，当前位实际为 0，需要翻转：
     - 若 `i + k > n`，返回 -1。
     - `isFlipped[i] = 1`，`flipCount++`，`result++`。
4. 返回 result。

**复杂度**：时间 O(n)，空间 O(n)。

### 解法二：原地标记

**思路**：利用 nums 数组本身做标记，将发起翻转的位置标记为特殊值（如加 2），省去额外数组。

**步骤**：
1. 遍历时，检查 `i >= k` 时 `nums[i-k]` 是否 >= 2 来判断窗口滑出。
2. 当前位需要翻转时，`nums[i] += 2` 作标记。

**复杂度**：时间 O(n)，空间 O(1)。

### 解法三：队列法

**思路**：用队列存储所有翻转的起始位置，队列大小即当前有效翻转次数。当队首元素滑出窗口时弹出。

**复杂度**：时间 O(n)，空间 O(n)。

## 易错点

1. **边界检查遗漏**：忘记判断 `i + k > n` 时应返回 -1，导致数组越界。
2. **翻转效果计算错误**：混淆 `nums[i]` 的实际值与翻转后的值，应该用 `(nums[i] + flipCount) % 2` 判断。
3. **窗口滑出时机**：差分数组中，翻转在 `i` 处开始，在 `i + k` 处结束（不含），所以 `i >= k` 时才减去 `isFlipped[i-k]`。
4. **原地标记恢复**：如果面试官要求不修改原数组，原地标记法需要后续恢复，或改用差分数组法。

## 面试追问

1. **Q: 如果 k 不固定，每次可以选择不同的 k 值翻转，怎么办？**
   A: 这变成了一个更复杂的问题，可能需要 BFS/DP 来搜索最优翻转序列。

2. **Q: 如何证明贪心策略的最优性？**
   A: 考虑最左边的 0，它必须被某次起始于 <= 该位置的翻转覆盖。而起始位置越靠左，对右侧的影响越大。因此从左到右贪心是最优的。

3. **Q: 这道题与"灯泡开关"类问题有什么联系？**
   A: 都涉及翻转/开关操作的累积效应，核心都是追踪奇偶性而非真正执行操作。

4. **Q: 能否用位运算进一步优化？**
   A: 对于 k=1 的特殊情况，答案就是 0 的个数。对于一般 k，位运算帮助不大，瓶颈在于遍历。
