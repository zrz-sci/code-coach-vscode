# 1888. 使二进制字符串字符交替的最少反转次数

## 核心思路

类型 1 操作本质是把字符串的所有"旋转"都考虑一遍，问的是：在所有旋转中，哪个旋转变成交替串需要的翻转次数最少？用**滑动窗口**在拼接串 `s+s` 上模拟所有旋转，动态维护翻转代价。

## 思维链

1. **读完题的第一反应**：类型 1 操作就是把首字符移到末尾，做若干次后字符串变成某个"旋转版本"。对于长度为 n 的串，最多有 n 种不同的旋转。对每个旋转，计算变成交替串（`010101...` 或 `101010...`）需要翻转几个字符，取最小值。

2. **暴力做法**：枚举 n 种旋转 × 每种遍历 n 个字符计算不匹配数 = O(n²)，n = 10⁵ 会超时。

3. **突破瓶颈的关键观察**：旋转操作 = 把第一个字符扔到末尾。如果把字符串拼接成 `s + s`，那么原串的每个旋转恰好是 `s+s` 中一个长度为 n 的子串！这就把"旋转枚举"变成了"滑动窗口"。

4. **滑动窗口维护代价**：目标交替串只有两种（`010101...` 和 `101010...`）。对拼接串 `s+s`，用一个长度为 n 的窗口从左滑到右，窗口每向右移动一格（加入右端一个字符、踢出左端一个字符），O(1) 更新与两种目标不匹配的字符数。

5. **结果**：窗口滑动过程中，取两种目标的最小不匹配数的全局最小值即为答案。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举旋转 | 枚举 n 种旋转，逐个计算翻转数 | O(n²) | O(n) | 能说出即可 |
| 滑动窗口 (拼接串) | s+s 上长度 n 的窗口，动态维护不匹配数 | O(n) | O(n) | ⭐ 必须写出 |
| 滑动窗口 (取模优化) | 不真正拼接，用下标取模模拟 | O(n) | O(1) | 加分项 |

## 关键提示

1. **旋转 ↔ 子串**：把 `s` 拼接成 `s + s` 后，原串的第 k 次旋转 = `(s+s)[k..k+n-1]`。这个技巧在循环字符串/数组问题中非常常见。

2. **目标只有两种**：长度为 n 的交替串只有 `"010101..."` 和 `"101010..."`。而且它们的不匹配数之和恒等于 n，所以只需要维护一种目标的不匹配数 `diff0`，另一种自动为 `n - diff0`。

3. **窗口滑动时更新**：右端加入字符 → `diff` 可能 +1 或不变；左端移出字符 → `diff` 可能 -1 或不变。每次 O(1)。

4. **目标串的奇偶性**：对于拼接串位置 i，目标值 = `i % 2`（对于目标 `010101...`）。注意拼接后下标继续递增，不需要重置。

5. **易忽略**：答案取 `min(diff0, n - diff0)` 而不是只看一种目标，因为两种交替模式都合法。

## 解法详解

### 解法1: 暴力枚举旋转 — O(n²) / O(n)

**思考过程**：最直接的想法——旋转有 n 种可能，对每种旋转分别统计需要多少次翻转。

```cpp
class Solution {
public:
    int minFlips(string s) {
        int n = s.size();
        int ans = n; // 最坏情况翻转所有字符
        
        for (int rot = 0; rot < n; rot++) {
            // 第 rot 次旋转后的字符串
            string t = s.substr(rot) + s.substr(0, rot);
            int diff0 = 0, diff1 = 0;
            for (int i = 0; i < n; i++) {
                // 目标0: "010101..."  目标1: "101010..."
                if ((t[i] - '0') != (i % 2)) diff0++;
                if ((t[i] - '0') != ((i + 1) % 2)) diff1++;
            }
            ans = min(ans, min(diff0, diff1));
        }
        return ans;
    }
};
```

**关键点**：正确但 O(n²)，n=10⁵ 时超时。瓶颈在于每次旋转都重新遍历整个串。

---

### 解法2: 滑动窗口 (拼接串) — O(n) / O(n) ⭐ 面试首选

**从解法1优化**：解法1每次旋转重新算 n 个字符的不匹配数，但相邻两次旋转只差首尾各一个字符。用滑动窗口，每次 O(1) 增减。

```
拼接串 s+s = "111000111000"（以 s="111000" 为例）
目标 target0 = "010101010101"（下标 i 处值 = i%2）

窗口大小 = n = 6，从左到右滑动：
窗口0: "111000"  vs "010101" → diff0=4, diff1=2 → min=2
窗口1: "110001"  vs "101010" → diff0=?, diff1=?  （i%2 对应变了）
... 但实际上我们是和全局 target 比，所以 diff 可以增量更新
```

```cpp
class Solution {
public:
    int minFlips(string s) {
        int n = s.size();
        // 拼接: 所有旋转 = s+s 中长度 n 的子串
        string doubled = s + s;
        int len = doubled.size(); // 2n
        
        // diff0: 与目标 "010101..." 不匹配的字符数
        // 目标 "101010..." 的不匹配数 = 窗口大小 - diff0 = n - diff0
        int diff0 = 0;
        int ans = n;
        
        for (int i = 0; i < len; i++) {
            // 右端字符加入窗口
            // 目标0 在位置 i 的期望值 = i % 2
            if ((doubled[i] - '0') != (i % 2)) {
                diff0++;
            }
            
            // 左端字符移出窗口（窗口大小超过 n 时）
            if (i >= n) {
                int left = i - n;
                if ((doubled[left] - '0') != (left % 2)) {
                    diff0--;
                }
            }
            
            // 窗口大小恰好为 n 时，更新答案
            if (i >= n - 1) {
                ans = min(ans, min(diff0, n - diff0));
            }
        }
        return ans;
    }
};
```

**关键点**：
- `diff0` 是窗口内与 `"010101..."` 不匹配的数量
- 与 `"101010..."` 不匹配的数量 = `n - diff0`（因为每个位置要么匹配 pattern0 要么匹配 pattern1）
- 利用全局下标 `i % 2` 作为目标值，拼接后下标自然递增，不需要手动处理旋转偏移

---

### 解法3: 滑动窗口 (取模优化) — O(n) / O(1)

**进一步优化**：不真正拼接字符串，用下标取模 `i % n` 访问原串字符。

```cpp
class Solution {
public:
    int minFlips(string s) {
        int n = s.size();
        int diff0 = 0;
        int ans = n;
        
        for (int i = 0; i < 2 * n; i++) {
            // doubled[i] = s[i % n]
            // 目标0 在位置 i 的期望值 = i % 2
            if ((s[i % n] - '0') != (i % 2)) {
                diff0++;
            }
            
            if (i >= n) {
                int left = i - n;
                if ((s[left % n] - '0') != (left % 2)) {
                    diff0--;
                }
            }
            
            if (i >= n - 1) {
                ans = min(ans, min(diff0, n - diff0));
            }
        }
        return ans;
    }
};
```

**关键点**：空间从 O(n) 降到 O(1)，因为不再创建拼接串。

## 解法对比

| | 暴力 | 滑动窗口(拼接) | 滑动窗口(取模) |
|---|---|---|---|
| 时间 | O(n²) | O(n) | O(n) |
| 空间 | O(n) | O(n) | O(1) |
| 核心思想 | 枚举每种旋转 | 拼接+窗口 | 取模+窗口 |
| 面试推荐 | 说思路即可 | ⭐ 首选 | 追问时给出 |

**什么时候选哪个**：面试先说暴力思路建立共识，然后直接给解法2。如果面试官追问空间优化，给解法3。

## 易错点

1. **✗ 只算一种目标**：`ans = min(ans, diff0)` → **✓** `ans = min(ans, min(diff0, n - diff0))`
   - 交替串有两种（`010...` 和 `101...`），必须都考虑

2. **✗ 目标值用窗口内相对位置**：`(i - windowStart) % 2` → **✓** `i % 2`
   - 用全局下标 `i % 2` 作为目标，这样 `n - diff0` 自动就是另一种目标的不匹配数。如果用窗口内相对位置，两种目标就不互补了。

3. **✗ 窗口条件写错**：`if (i > n)` → **✓** `if (i >= n)`
   - 当 `i == n` 时窗口已经有 n+1 个元素，需要移出左端

4. **✗ 忘记 `- '0'`**：`s[i] != (i % 2)` → **✓** `(s[i] - '0') != (i % 2)`
   - `s[i]` 是 char 类型，值为 '0'(48) 或 '1'(49)，不是 0/1

## 面试追问

**Q1（基础理解）**：类型 1 操作能进行任意次，所以有多少种不同的旋转？
> 长度为 n 的串有 n 种旋转（包括原串，即旋转 0 次）。

**Q2（关键优化）**：怎么避免 O(n²) 地枚举所有旋转？
> 把 s 拼接成 s+s，原串的第 k 次旋转就是 s+s 的子串 `[k, k+n)`。用长度为 n 的滑动窗口在 s+s 上滑动，每次 O(1) 更新不匹配数。

**Q3（深入追问）**：为什么 `n - diff0` 就是另一种目标的不匹配数？
> 对于任意位置 i，目标 `010...` 和目标 `101...` 的期望值恰好相反。如果 `s[i]` 与目标 0 匹配，则它一定与目标 1 不匹配，反之亦然。所以 `diff0 + diff1 = n`（窗口大小），即 `diff1 = n - diff0`。

**Q4（变体）**：如果不允许类型 1 操作（不能旋转），答案是什么？
> 直接比较 s 与两种目标串的不匹配数，取较小值。这是最基础的版本，O(n) 一遍扫描。
