# 94. 二叉树的中序遍历

## 核心思路
中序遍历就是按"左→根→右"的顺序访问二叉树的每个节点。本题是二叉树遍历的基础题，核心在于理解递归天然匹配树结构，以及如何用栈手动模拟递归调用栈来实现迭代版本。

## 思维链
1. **读完题第一反应**：中序遍历 = 左子树 → 根节点 → 右子树，天然递归结构，递归三行代码就能搞定。
2. **递归的本质是什么？** 系统帮你维护了一个调用栈，每次递归进入左子树就是"压栈"，返回就是"弹栈"。
3. **题目 Follow-up 要求迭代**：既然递归本质是栈，那我们自己维护一个显式的栈，模拟"一路向左压栈 → 弹出处理 → 转右子树"的过程。
4. **还有更进阶的方式吗？** Morris 遍历利用叶子节点的空指针建立临时链接，实现 O(1) 空间遍历，不需要栈也不需要递归。
5. **三种方式的取舍**：面试中递归展示理解、迭代展示功底、Morris 是加分项。

## 解法概览
| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 递归 | 左→根→右，直接递归 | O(n) | O(h) | 能说出即可 |
| 迭代（显式栈） | 用栈模拟递归调用栈 | O(n) | O(h) | ⭐ 必须写出 |
| Morris 遍历 | 利用空指针建临时链接 | O(n) | O(1) | 加分项 |

> h 为树的高度，最坏 O(n)（退化为链表），平衡树为 O(log n)

## 关键提示

- **提示1**：中序遍历的顺序是"左→根→右"。想想对于任意一个节点，你要先处理完它的整个左子树，才轮到它自己。

- **提示2（迭代关键）**：从根出发，一路向左走到底，把沿途节点全部压栈。弹出栈顶时就是"该访问的节点"，访问后转向它的右子树，对右子树重复同样的过程。

- **提示3**：画出下面这棵树的栈变化过程，你就理解迭代版了：
```
//       1
//        \
//         2
//        /
//       3
//
// 中序结果: [1, 3, 2]
//
// 栈的变化:
// Step1: curr=1, 无左 → 压栈[1]
//        实际: 一路向左: push(1), curr=null
// Step2: 弹出1, 访问1, 转右 curr=2
// Step3: 一路向左: push(2), curr=3, push(3), curr=null
// Step4: 弹出3, 访问3, 转右 curr=null
// Step5: 弹出2, 访问2, 转右 curr=null
// Step6: 栈空 & curr=null → 结束
// 结果: [1, 3, 2] ✓
```

- **提示4（Morris）**：如果一个节点有左子树，它的前驱（左子树的最右节点）的右指针本来是 null，可以临时指向当前节点，这样遍历完左子树后能"免费"回到当前节点。

- **提示5**：前序、中序、后序三种遍历的迭代写法中，中序的迭代最经典，理解了中序，其他两种很容易类推。

## 解法详解

### 解法1: 递归 — O(n) / O(h)

**思考过程**：树的定义本身就是递归的（左子树也是树，右子树也是树），所以中序遍历"左→根→右"天然对应递归：先递归左子树，处理当前节点，再递归右子树。

```
//  示例树:
//         1
//        / \
//       2   3
//      / \   \
//     4   5   8
//        / \ /
//       6  7 9
//
//  中序遍历过程 (左→根→右):
//  递归(1) → 递归(2) → 递归(4) → 访问4
//            ← 回到2 → 访问2
//            → 递归(5) → 递归(6) → 访问6
//                        ← 回到5 → 访问5
//                        → 递归(7) → 访问7
//            ← 回到1 → 访问1
//            → 递归(3) → 访问3
//                      → 递归(8) → 递归(9) → 访问9
//                                  ← 回到8 → 访问8
//  结果: [4, 2, 6, 5, 7, 1, 3, 9, 8]
```

```cpp
class Solution {
public:
    vector<int> inorderTraversal(TreeNode* root) {
        vector<int> result;
        dfs(root, result);
        return result;
    }
    
    void dfs(TreeNode* node, vector<int>& result) {
        if (!node) return;          // 终止条件：空节点
        dfs(node->left, result);    // 递归左子树
        result.push_back(node->val); // 处理当前节点（中序 = 在"中间"处理）
        dfs(node->right, result);   // 递归右子树
    }
};
```

**关键点**：
- 递归三要素：①返回值 void（结果通过引用参数收集）②终止条件 `!node` ③单层逻辑 左→根→右
- 空间复杂度是 O(h) 不是 O(n)，因为递归栈的深度等于树的高度

### 解法2: 迭代（显式栈） — O(n) / O(h) ⭐ 面试首选

**从解法1优化**：递归之所以能工作，是因为系统帮你维护了一个调用栈。我们自己用一个 `stack` 来模拟这个过程。核心模式是：

> **一路向左压栈 → 弹出访问 → 转向右子树 → 重复**

为什么这样就是中序？因为一路向左到底保证了"左子树先处理完"，弹出时处理当前节点就是"根"，然后转右就是"右子树"。

```
//  以示例1 [1,null,2,3] 为例:
//       1
//        \
//         2
//        /
//       3
//
//  步骤     栈(底→顶)    curr     动作            result
//  ────────────────────────────────────────────────────
//  init     []           1        开始
//  Step1    [1]          null     一路向左: push(1)
//  Step2    []           2        弹出1, 访问1, 转右=2   [1]
//  Step3    [2]          3        一路向左: push(2), curr=3
//  Step4    [2,3]        null     继续向左: push(3)
//  Step5    [2]          null     弹出3, 访问3, 转右=null [1,3]
//  Step6    []           null     弹出2, 访问2, 转右=null [1,3,2]
//  Step7    栈空&curr=null        结束 → [1,3,2] ✓
```

```cpp
class Solution {
public:
    vector<int> inorderTraversal(TreeNode* root) {
        vector<int> result;
        stack<TreeNode*> stk;
        TreeNode* curr = root;
        
        // 循环条件: curr非空(还有节点要向左探) 或 栈非空(还有节点待处理)
        while (curr || !stk.empty()) {
            // 阶段1: 一路向左，把沿途节点全部压栈
            while (curr) {
                stk.push(curr);
                curr = curr->left;
            }
            // 阶段2: 弹出栈顶 = 当前最左的未处理节点
            curr = stk.top();
            stk.pop();
            result.push_back(curr->val);  // 访问（中序位置）
            // 阶段3: 转向右子树，对右子树重复同样的过程
            curr = curr->right;
        }
        
        return result;
    }
};
```

**关键点**：
- 外层 `while` 的条件是 `curr || !stk.empty()`，两个都为假才结束
- 内层 `while` 把当前节点到最左叶子的路径全部入栈
- 弹出后 `curr = curr->right` 是关键：即使右子树为 null 也没关系，下一轮会直接跳过内层 while 继续弹栈

### 解法3: Morris 遍历 — O(n) / O(1) 加分项

**从解法2优化**：迭代用栈还是需要 O(h) 空间。Morris 遍历的核心想法是：利用叶子节点本来就是 null 的右指针，临时建立一条回到父节点的链接（"线索"），这样遍历完左子树后可以沿着这条链接回到父节点，不需要栈。

**Morris 中序遍历的规则**：
1. 如果 `curr` 没有左子树 → 直接访问 `curr`，然后 `curr = curr->right`
2. 如果 `curr` 有左子树 → 找到左子树的最右节点（即 curr 的前驱 predecessor）
   - 如果前驱的右指针是 null → 建立线索：`predecessor->right = curr`，然后 `curr = curr->left`
   - 如果前驱的右指针已经指向 curr → 说明左子树已遍历完，断开线索，访问 curr，`curr = curr->right`

```
//  Morris 过程示例 [1,null,2,3]:
//       1               1的左子树为空
//        \              → 访问1, curr=2
//         2             2有左子树(3)
//        /              → 3的右指针指向2(建线索), curr=3
//       3               3无左子树
//                       → 访问3, curr=3->right=2(沿线索回去)
//                       2有左子树, 但前驱3的右指针已指向2
//                       → 断开线索, 访问2, curr=2->right=null
//                       结束 → [1, 3, 2] ✓
```

```cpp
class Solution {
public:
    vector<int> inorderTraversal(TreeNode* root) {
        vector<int> result;
        TreeNode* curr = root;
        
        while (curr) {
            if (!curr->left) {
                // 没有左子树：直接访问，转向右子树
                result.push_back(curr->val);
                curr = curr->right;
            } else {
                // 有左子树：找前驱节点（左子树的最右节点）
                TreeNode* predecessor = curr->left;
                while (predecessor->right && predecessor->right != curr) {
                    predecessor = predecessor->right;
                }
                
                if (!predecessor->right) {
                    // 前驱右指针为空：建立线索，进入左子树
                    predecessor->right = curr;
                    curr = curr->left;
                } else {
                    // 前驱右指针指向curr：左子树已遍历完
                    predecessor->right = nullptr;  // 恢复树结构
                    result.push_back(curr->val);   // 访问当前节点
                    curr = curr->right;
                }
            }
        }
        
        return result;
    }
};
```

**关键点**：
- 时间 O(n)：虽然每个节点可能被访问多次（找前驱），但每条边最多被遍历 2 次，总共 O(n)
- 空间 O(1)：不用栈，不用递归，利用树本身的空指针
- **会临时修改树结构**，遍历结束后恢复原状。面试时需要提到这个 trade-off

## 解法对比

| | 递归 | 迭代（栈） | Morris |
|---|---|---|---|
| 时间 | O(n) | O(n) | O(n) |
| 空间 | O(h) 调用栈 | O(h) 显式栈 | O(1) |
| 代码复杂度 | 最简单（3行核心） | 中等 | 较高 |
| 修改树结构 | 否 | 否 | 是（临时修改） |
| 面试场景 | 热身/基础确认 | **主要考点** | 追问加分 |
| 适用 | 任何场景 | 栈深度受限时 | 严格要求O(1)空间 |

**什么时候选哪个？**
- 日常刷题/快速写出来 → 递归
- 面试被问"能否迭代" → 显式栈（这是本题 Follow-up 的核心）
- 面试追问"能否 O(1) 空间" → Morris

## 易错点

1. **迭代版外层循环条件漏了 `curr`**
   - ✗ `while (!stk.empty())` — 初始时栈为空，直接跳过循环，返回空结果
   - ✓ `while (curr || !stk.empty())` — `curr` 非空说明还有节点需要向左探索

2. **迭代版忘记 `curr = curr->right`**
   - ✗ 弹出后不转右子树 → 死循环，同一个节点反复被弹出
   - ✓ 弹出访问后必须 `curr = curr->right`，即使 right 为 null

3. **Morris 遍历忘记恢复树结构**
   - ✗ 建立线索后不断开 → 树结构被永久修改，后续操作出错
   - ✓ 第二次发现前驱指向自己时，`predecessor->right = nullptr` 恢复

4. **Morris 找前驱时死循环**
   - ✗ `while (predecessor->right)` — 如果线索已建立，会无限循环回到 curr
   - ✓ `while (predecessor->right && predecessor->right != curr)` — 遇到指向 curr 的线索要停下

## 面试追问

**Q1: 递归的时间和空间复杂度分别是多少？最坏情况是什么？**
> 时间 O(n)，每个节点恰好访问一次。空间 O(h)，h 为树高。最坏情况：树退化为链表（如只有右子树），h = n，空间 O(n)。

**Q2: 能否用迭代实现？迭代版的栈在模拟什么？**
> 栈模拟的是递归调用栈。"一路向左压栈"对应递归不断进入左子树，"弹出"对应递归返回到当前节点，"转右"对应递归进入右子树。

**Q3: 能否做到 O(1) 空间？如果不允许修改树结构呢？**
> O(1) 空间可以用 Morris 遍历，但会临时修改树的指针。如果不允许修改树结构，则无法做到 O(1)，最优是 O(h) 的显式栈。

**Q4: 如果改成前序/后序遍历，迭代版代码需要怎么改？**
> 前序：把 `result.push_back` 移到内层 while（压栈之前），即入栈时就访问。后序：最简单的方式是按"根→右→左"遍历（前序的镜像），最后反转结果。
