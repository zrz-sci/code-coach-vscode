# 907. 子数组的最小值之和

## 核心思路

本题本质上不是要你枚举每个子数组再求最小值，而是**反向思考**：对于每个元素 `arr[i]`，它作为最小值能"统治"多少个子数组？把每个元素的 `arr[i] × 统治的子数组个数` 累加起来就是答案。找到"统治范围"的高效工具就是**单调栈**。

## 思维链

1. **读完题第一反应**：枚举所有子数组 `[l, r]`，对每个子数组求最小值，全部加起来。暴力 O(n²) 或 O(n³)。
2. **暴力解的瓶颈**：子数组有 O(n²) 个，每个还要求 min。即使用 DP 维护区间最小值也是 O(n²)。n=3×10⁴ 时 O(n²) 有点勉强。
3. **换个角度思考**：不枚举子数组，而是枚举每个元素。问：`arr[i]` 在多少个子数组中充当最小值？如果知道这个"贡献次数"，答案就是 `Σ arr[i] × count[i]`。
4. **如何算贡献次数**：对于 `arr[i]`，找到它左边第一个比它**严格更小**的位置 `left[i]`，和右边第一个**小于等于**它的位置 `right[i]`。那么 `arr[i]` 作为最小值的子数组个数 = `(i - left[i]) × (right[i] - i)`。
5. **为什么一边严格一边非严格**：如果两边都用严格小于，当存在相等元素时同一个子数组会被重复计算。一边严格、一边非严格恰好保证每个子数组的最小值只被"归属"给一个位置。
6. **用什么数据结构高效求 left/right**：**单调递增栈**，一次遍历 O(n) 就能求出所有位置的 left 和 right。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举所有子数组，维护区间 min | O(n²) | O(1) | 能说出即可 |
| 单调栈 + 贡献法 | 对每个元素算它"统治"多少子数组 | O(n) | O(n) | ⭐ 必须写出 |
| DP + 单调栈 | dp[i] = 以 arr[i] 结尾的所有子数组的 min 之和 | O(n) | O(n) | 加分项 |

## 关键提示

1. **反向思考贡献**：不要枚举子数组，而是对每个 `arr[i]` 问"它在多少个子数组中是最小值"。
2. **左右边界**：`arr[i]` 能作为最小值的子数组范围，由左边第一个更小元素和右边第一个更小元素决定。
3. **处理相等元素**：如果 `arr[i] == arr[j]`（i < j），为避免重复计算，约定左边用"严格小于"，右边用"小于等于"（或反过来，但必须一边严格一边非严格）。
4. **单调栈方向**：维护一个**单调递增栈**（栈底到栈顶递增），遇到更小的元素时弹出。
5. **乘法原理**：左边有 `L` 种起点选择、右边有 `R` 种终点选择，总贡献 = `arr[i] × L × R`。

```
arr = [3, 1, 2, 4]，分析 arr[1]=1 的贡献：

索引:  0  1  2  3
值:    3  1  2  4

left[1] = -1 (左边没有比1更小的)
right[1] = 4 (右边没有≤1的)

左边可选起点: 0, 1 → 共 (1 - (-1)) = 2 种
右边可选终点: 1, 2, 3 → 共 (4 - 1) = 3 种
贡献 = 1 × 2 × 3 = 6

对应子数组: [3,1], [1], [3,1,2], [1,2], [3,1,2,4], [1,2,4]
它们的 min 都是 1，确实是 6 个 ✓
```

## 解法详解

### 解法1: 暴力枚举 — O(n²) / O(1)

**思考过程**: 最直觉的做法——枚举左端点 `l`，从 `l` 向右扩展右端点 `r`，同时维护当前区间的最小值。

```cpp
class Solution {
public:
    int sumSubarrayMins(vector<int>& arr) {
        const int MOD = 1e9 + 7;
        int n = arr.size();
        long long ans = 0;
        for (int l = 0; l < n; l++) {
            int curMin = arr[l];
            for (int r = l; r < n; r++) {
                curMin = min(curMin, arr[r]);
                ans = (ans + curMin) % MOD;
            }
        }
        return ans;
    }
};
```

**关键点**:
- 时间 O(n²)，n=3×10⁴ 时约 4.5×10⁸ 次操作，可能超时（取决于评测机和常数）。
- 这个解法的价值在于：让你看到"每次向右扩展一格，min 只会不变或减小"这个单调性——这就是后续优化的基础。

### 解法2: 单调栈 + 贡献法 — O(n) / O(n) ⭐ 面试首选

**从解法1优化**: 暴力枚举了 O(n²) 个子数组。但如果我们换个角度——对每个元素，直接算它作为最小值的贡献——就能用单调栈在 O(n) 内完成。

**核心思想**:

对于 `arr[i]`，找到：
- `left[i]`：左边第一个**严格小于** `arr[i]` 的位置（找不到则为 -1）
- `right[i]`：右边第一个**小于等于** `arr[i]` 的位置（找不到则为 n）

贡献 = `arr[i] × (i - left[i]) × (right[i] - i)`

```
为什么一边严格、一边非严格？

考虑 arr = [1, 2, 1]:

子数组 [1,2,1] 的 min = 1，出现在 index=0 和 index=2。
如果两边都用严格小于：
  - arr[0]=1: left=-1, right=3 → 贡献=1×1×3=3
  - arr[2]=1: left=-1, right=3 → 贡献=1×3×1=3
  子数组[1,2,1]被算了两次！

改成左严格、右非严格（≤）：
  - arr[0]=1: left=-1, right=2 (arr[2]=1 ≤ arr[0]) → 贡献=1×1×2=2
  - arr[2]=1: left=-1, right=3 → 贡献=1×3×1=3
  总贡献=2+3=5，不重复 ✓
```

**单调栈求 left[] 和 right[] 的过程**:

```
arr = [3, 1, 2, 4]

求 left[]（严格小于，从左往右遍历，维护递增栈）：
  i=0: 栈空 → left[0]=-1，push 0。 栈: [0]
  i=1: arr[1]=1 < arr[0]=3 → pop 0。栈空 → left[1]=-1，push 1。栈: [1]
  i=2: arr[2]=2 > arr[1]=1 → left[2]=1，push 2。栈: [1,2]
  i=3: arr[3]=4 > arr[2]=2 → left[3]=2，push 3。栈: [1,2,3]

  left = [-1, -1, 1, 2]

求 right[]（小于等于，从右往左遍历，维护递增栈）：
  i=3: 栈空 → right[3]=4，push 3。 栈: [3]
  i=2: arr[2]=2 < arr[3]=4 → right[2]=3... 不对，2≤4不弹。
  
  （实际操作：弹出栈中 ≥ arr[i] 的元素）
  i=3: 栈空 → right[3]=4，push 3。栈: [3]
  i=2: arr[3]=4 ≥ arr[2]=2? 是 → pop 3。栈空 → right[2]=4，push 2。栈: [2]
  i=1: arr[2]=2 ≥ arr[1]=1? 是 → pop 2。栈空 → right[1]=4，push 1。栈: [1]
  i=0: arr[1]=1 ≥ arr[0]=3? 否 → right[0]=1，push 0。栈: [0,1]

  right = [1, 4, 4, 4]

贡献计算：
  i=0: 3 × (0-(-1)) × (1-0) = 3×1×1 = 3
  i=1: 1 × (1-(-1)) × (4-1) = 1×2×3 = 6
  i=2: 2 × (2-1) × (4-2)    = 2×1×2 = 4
  i=3: 4 × (3-2) × (4-3)    = 4×1×1 = 4
  
  总和 = 3+6+4+4 = 17 ✓
```

```cpp
class Solution {
public:
    int sumSubarrayMins(vector<int>& arr) {
        const int MOD = 1e9 + 7;
        int n = arr.size();
        vector<int> left(n), right(n);
        stack<int> stk;
        
        // 求 left[i]: 左边第一个严格小于 arr[i] 的位置
        for (int i = 0; i < n; i++) {
            // 弹出所有 >= arr[i] 的（因为我们要找严格小于的）
            while (!stk.empty() && arr[stk.top()] >= arr[i]) {
                stk.pop();
            }
            left[i] = stk.empty() ? -1 : stk.top();
            stk.push(i);
        }
        
        // 清空栈，复用
        while (!stk.empty()) stk.pop();
        
        // 求 right[i]: 右边第一个小于等于 arr[i] 的位置
        for (int i = n - 1; i >= 0; i--) {
            // 弹出所有 > arr[i] 的（因为我们要找 ≤ 的，即保留 ≤ 的）
            while (!stk.empty() && arr[stk.top()] > arr[i]) {
                stk.pop();
            }
            right[i] = stk.empty() ? n : stk.top();
            stk.push(i);
        }
        
        // 累加每个元素的贡献
        long long ans = 0;
        for (int i = 0; i < n; i++) {
            long long cnt = (long long)(i - left[i]) * (right[i] - i);
            ans = (ans + (long long)arr[i] % MOD * (cnt % MOD)) % MOD;
        }
        return (int)ans;
    }
};
```

**关键点**:
- 单调栈弹出条件的不同（`>=` vs `>`）对应左严格/右非严格的处理，是避免重复计算的核心。
- 乘法时注意 `long long` 防溢出。

### 解法3: DP + 单调栈 — O(n) / O(n)

**不同视角**: 定义 `dp[i]` = 所有以 `arr[i]` 结尾的子数组的最小值之和。最终答案 = `Σ dp[i]`。

**状态转移推导**:

以 `arr[i]` 结尾的子数组有：`[i], [i-1,i], [i-2,i], ..., [0,i]`。

设 `j` 是左边第一个严格小于 `arr[i]` 的位置。那么：
- 子数组 `[k..i]`，当 `j < k ≤ i` 时，最小值都是 `arr[i]`（因为 `arr[i]` 是这个范围内最小的）
- 子数组 `[k..i]`，当 `k ≤ j` 时，最小值和 `[k..j]` 的最小值相同（因为 `arr[j] < arr[i]`）

所以：`dp[i] = arr[i] × (i - j) + dp[j]`

```
arr = [3, 1, 2, 4]

dp[0]: j=-1 → dp[0] = 3×(0-(-1)) + 0 = 3
  (子数组: [3], min之和=3)

dp[1]: j=-1 → dp[1] = 1×(1-(-1)) + 0 = 2
  (子数组: [1],[3,1], min之和=1+1=2)

dp[2]: j=1 (arr[1]=1<arr[2]=2) → dp[2] = 2×(2-1) + dp[1] = 2+2 = 4
  (子数组: [2],[1,2],[3,1,2], min之和=2+1+1=4)

dp[3]: j=2? arr[2]=2<arr[3]=4 → dp[3] = 4×(3-2) + dp[2] = 4+4 = 8
  (子数组: [4],[2,4],[1,2,4],[3,1,2,4], min之和=4+2+1+1=8)

ans = 3+2+4+8 = 17 ✓
```

```cpp
class Solution {
public:
    int sumSubarrayMins(vector<int>& arr) {
        const int MOD = 1e9 + 7;
        int n = arr.size();
        // 单调栈找左边第一个严格小于 arr[i] 的位置
        // 这里我们边遍历边维护栈和 dp
        stack<int> stk;  // 单调递增栈（存索引）
        vector<long long> dp(n);
        long long ans = 0;
        
        for (int i = 0; i < n; i++) {
            // 弹出所有 >= arr[i] 的元素
            while (!stk.empty() && arr[stk.top()] >= arr[i]) {
                stk.pop();
            }
            int j = stk.empty() ? -1 : stk.top();
            // dp[i] = arr[i] × (i - j) + dp[j]（j=-1时dp[j]=0）
            dp[i] = (long long)arr[i] * (i - j);
            if (j >= 0) dp[i] += dp[j];
            dp[i] %= MOD;
            
            ans = (ans + dp[i]) % MOD;
            stk.push(i);
        }
        return (int)ans;
    }
};
```

**关键点**:
- 这个解法只需要一次遍历，一个栈，代码最简洁。
- `dp[i]` 的含义非常清晰：以 `i` 结尾的所有子数组 min 之和。
- 不需要单独求 right 数组，因为我们是按"结尾位置"来组织 dp 的。

## 解法对比

| | 解法1: 暴力 | 解法2: 单调栈+贡献 | 解法3: DP+单调栈 |
|---|---|---|---|
| 时间 | O(n²) | O(n) | O(n) |
| 空间 | O(1) | O(n) | O(n) |
| 遍历次数 | 双重循环 | 三次遍历(左+右+累加) | 一次遍历 |
| 思维方式 | 枚举子数组 | 枚举元素的贡献 | 递推：以 i 结尾的子数组 |
| 代码难度 | 简单 | 中等（需处理左右边界） | 中等偏简 |
| 面试推荐 | 作为起点 | ⭐ 最经典，必须掌握 | 加分项，代码更简洁 |

解法2 和解法3 本质相同：都是用单调栈找"最近更小元素"。区别在于：
- 解法2 先求完 left/right 数组，再用乘法原理一次算出贡献
- 解法3 边遍历边递推，不需要 right 数组

## 易错点

1. **重复计算相等元素**:
   - ✗ 左右都用严格小于 (`<`)：相等元素会导致同一子数组被多个位置重复计算
   - ✓ 一边严格小于 (`<`)，一边小于等于 (`<=`)：保证每个子数组的 min 只归属于一个位置

2. **单调栈弹出条件搞反**:
   - ✗ 求 left 时 `while (arr[stk.top()] > arr[i])`（应该是 `>=`）
   - ✓ 求 left 时 `while (arr[stk.top()] >= arr[i])`，求 right 时 `while (arr[stk.top()] > arr[i])`
   - 原因：left 用 `>=` 弹出，意味着相等元素不做左边界→配合 right 用 `>` 保留相等元素做右边界

3. **long long 溢出**:
   - ✗ `ans += arr[i] * (i - left[i]) * (right[i] - i)`（三个 int 相乘可能溢出）
   - ✓ `ans += (long long)arr[i] * (i - left[i]) % MOD * (right[i] - i) % MOD`，或者分步取模

4. **DP 解法中忘记 j=-1 的情况**:
   - ✗ `dp[i] = arr[i] * (i - j) + dp[j]`（当 j=-1 时 dp[-1] 越界）
   - ✓ 先判断 `j >= 0` 再加 `dp[j]`

## 面试追问

**Q1: 暴力解的时间复杂度？能通过吗？**
> O(n²)，n=3×10⁴ 时约 10⁹ 次操作，在多数 OJ 上会超时。但可以用来验证优化解法的正确性。

**Q2: 你提到对每个元素算贡献，怎么保证不重不漏？**
> 关键是"一边严格、一边非严格"。这相当于对于有相同最小值的多个位置，约定"最右边那个"负责统计。每个子数组的最小值恰好被一个位置"认领"。

**Q3: 如果题目改成求所有子数组的最大值之和呢？**
> 完全对称：把单调递增栈改成单调递减栈，找左边第一个严格大于和右边第一个大于等于的位置。代码结构完全一样，只需翻转比较符号。

**Q4: 如果同时需要 min 之和和 max 之和怎么办？**
> 各做一遍即可，时间仍然是 O(n)。实际上 LeetCode 2104 "子数组范围和" 就需要 max 之和减去 min 之和。
