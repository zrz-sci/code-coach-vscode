# 717. 1-bit and 2-bit Characters / 1 比特与 2 比特字符

## 核心思路

本题有两种字符编码：1 比特字符 `0`，和 2 比特字符 `10` 或 `11`。给定一个以 `0` 结尾的二进制数组，判断最后一个字符是否**一定**是 1 比特字符。

核心洞察：从左到右**贪心解码**。遇到 `1` 时，它必定是 2 比特字符的开头（因为 `1` 不能单独成为字符），所以跳过 2 位；遇到 `0` 时，它是 1 比特字符，跳过 1 位。如果指针最终恰好停在最后一位（index = n-1），说明最后一个字符是 1 比特字符（即那个 `0`）。如果指针跳过了最后一位，说明最后一个 `0` 是前一个 2 比特字符的一部分。

另一个等价的思路：只需关注倒数第二个 `0` 到数组末尾之间有多少个 `1`。如果 `1` 的数量是偶数，则最后一个字符是 1 比特字符；奇数则不是。

## 思维链

1. **字符规则分析**：`0` -> 1比特字符；`10` 或 `11` -> 2比特字符。关键：以 `1` 开头的一定是 2 比特。
2. **贪心解码**：从左到右扫描，`bits[i] == 0` 时 `i += 1`，`bits[i] == 1` 时 `i += 2`
3. **终止判断**：循环条件 `i < n - 1`（不处理最后一位）。循环结束后，若 `i == n - 1`，说明最后一位 `0` 是单独的 1 比特字符
4. **为什么贪心正确？** 解码是唯一确定的——`0` 只能是 1 比特，`1` 只能是 2 比特的开头，没有歧义

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 贪心线性扫描 | O(n) | O(1) | 最直观的解法 |
| 末尾连续 1 计数 | O(n) | O(1) | 只看末尾部分 |
| 从右往左计数 | O(n) 最坏 | O(1) | 更快的平均情况 |

## 关键提示

1. **解码无歧义**：这套编码系统是**前缀码（prefix code）**——没有任何字符是另一个字符的前缀。`0` 不是 `10` 或 `11` 的前缀（因为后者以 `1` 开头）。所以从左到右解码是唯一确定的。
2. **只需扫到倒数第二位**：最后一位已知是 `0`（题目保证），我们只需判断它是否被前面的 `1` "吃掉"了。
3. **连续 1 的奇偶性**：从右向左看（跳过末尾的 0），数连续 `1` 的个数。偶数个 `1` 意味着它们两两配对成 2 比特字符，最后的 `0` 独立；奇数个则最后的 `0` 被前面的 `1` 绑定。
4. **数组只有一个元素时**：`bits = [0]`，最后一个字符一定是 1 比特字符，返回 true。

## 解法详解

### 解法一：贪心线性扫描（推荐）

从左到右扫描数组，模拟解码过程：
- `i = 0` 开始
- 如果 `bits[i] == 1`，这是 2 比特字符的开头，`i += 2`
- 如果 `bits[i] == 0`，这是 1 比特字符，`i += 1`
- 循环条件：`i < n - 1`（不处理最后一位）
- 循环结束后，`i == n - 1` 说明最后一位独立，返回 true

**为什么不能 i < n？** 因为如果最后一位 `0` 是 2 比特字符 `10` 的一部分，`i` 会在倒数第二位时直接跳到 `n`（跳过最后一位），此时 `i == n != n-1`，返回 false。

### 解法二：末尾连续 1 计数

从倒数第二位（index = n-2）向左数连续 `1` 的个数：
- 遇到 `0` 就停止
- 如果连续 `1` 的个数是偶数（包括 0），返回 true
- 如果是奇数，返回 false

**原理**：连续的 `1` 会两两配对成 `11` 字符。偶数个 `1` 全部配对，末尾 `0` 独立。奇数个 `1` 中最后一个 `1` 必须和末尾 `0` 组成 `10`。

### 解法三：动态规划（过度设计但正确）

- `dp[i]` 表示从位置 i 开始解码，最后一个字符是否为 1 比特
- 从右向左递推
- 对于本题来说过于复杂，不推荐

## 易错点

1. **循环条件写错**：应该是 `i < n - 1` 而非 `i < n`。如果写 `i < n`，当 i 指向最后一位时会把它当作 1 比特字符处理，但这恰好是我们要判断的，逻辑自相矛盾。
2. **忘记数组只有一个元素的情况**：`bits = [0]`，循环不执行，`i == 0 == n - 1`，返回 true，正确。
3. **解法二中方向搞反**：应该从 `n-2` 往左数，不是从 `0` 往右数。
4. **误以为有多种解码方式**：这套编码是前缀码，解码唯一确定，不存在歧义。
5. **将 `1` 当作 1 比特字符**：`1` 单独出现不是合法字符，它必须和下一位组成 `10` 或 `11`。

## 面试追问

1. **Q: 这套编码和霍夫曼编码有什么关系？**
   A: 两者都是前缀码（prefix-free code），即没有任何码字是另一个码字的前缀。本题的编码是固定的（0, 10, 11），霍夫曼编码根据频率动态构建。

2. **Q: 如果编码规则变成 `0`、`10`、`110`、`1110`...（变长前缀码），怎么解？**
   A: 同样的贪心策略依然有效——遇到 `0` 就结束当前字符。因为 `0` 始终是每个字符的终止符。

3. **Q: 如果数组不以 `0` 结尾呢？**
   A: 如果末尾是 `1`，最后一个字符一定是 2 比特字符（以 `1` 开头必须有下一位），题目保证不会出现这种无效输入。

4. **Q: 能否用正则表达式解？**
   A: 可以。匹配模式 `(1.|0)*0` 即可判断最后一个字符是否为单独的 `0`。但面试中不推荐这种方式。

5. **Q: 时间复杂度能否优于 O(n)？**
   A: 使用解法二（从末尾向前数连续 1）在最好情况下是 O(1)（如 `...0, 0`），但最坏仍是 O(n)（全是 1 后跟一个 0）。无法避免 O(n) 最坏情况。
