# 189. 轮转数组

## 核心思路

本质上是把数组的**后 k 个元素**搬到**前面**来。关键在于：能否不用额外数组，O(1) 空间原地完成？

## 思维链

1. **读完题第一反应**：每次把最后一个元素放到最前面，重复 k 次 → 暴力模拟轮转。
2. **暴力的瓶颈**：每次移动需要整个数组后移 O(n)，做 k 次就是 O(n×k)，当 k 和 n 都是 10⁵ 时会超时。
3. **换个角度观察**：把结果和原数组对比，轮转 k 步后的结果是 `[后k个 | 前n-k个]`，这不就是两段的拼接吗？
4. **用额外数组**：直接计算每个元素的新位置 `(i+k) % n`，放到新数组里，O(n) 时间 O(n) 空间。
5. **能否 O(1) 空间？** 观察一个神奇的性质：`[1,2,3,4 | 5,6,7]` → 全翻 `[7,6,5 | 4,3,2,1]` → 前 k 个翻 `[5,6,7 | 4,3,2,1]` → 后 n-k 个翻 `[5,6,7 | 1,2,3,4]`，三次翻转搞定！
6. **为什么三次翻转是对的？** 翻转 = 逆序。全翻相当于把两段都逆了且交换了位置，再各自翻转恢复各段内部顺序。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力模拟 | 逐步右移 k 次 | O(n×k) | O(1) | 能说出即可 |
| 额外数组 | 计算新位置直接放 | O(n) | O(n) | 能说出即可 |
| 三次翻转 | 全翻 + 分段翻 | O(n) | O(1) | ⭐ 必须写出 |
| 环状替换 | 沿环逐个归位 | O(n) | O(1) | 加分项 |

## 关键提示

1. **k 可能大于 n**！先做 `k %= n`，轮转 n 次等于没转。
2. 观察结果结构：`nums[0..n-1]` 轮转 k 步 → `nums[n-k..n-1] + nums[0..n-k-1]`，两段互换位置。
3. 翻转一个数组很简单（双指针交换），三次翻转就能原地完成两段互换——这个技巧在字符串左旋、循环移位等场景都能复用。
4. 环状替换的关键：一共需要搬 n 次，但一条环可能回到起点还没搬完所有元素。需要搬的环数 = `gcd(n, k)`。

```
原数组:   [1, 2, 3, 4, 5, 6, 7]    k=3, n=7

解法3 (三次翻转) 过程:
Step1 全翻转:  [7, 6, 5, 4, 3, 2, 1]
                ←———————————————→
Step2 翻前k个: [5, 6, 7, 4, 3, 2, 1]
                ←——→
Step3 翻后n-k: [5, 6, 7, 1, 2, 3, 4]  ✓
                         ←———————→
```

## 解法详解

### 解法1: 暴力模拟 — O(n×k) / O(1)

**思考过程**: 最直觉的方式，每次把最后一个元素拿出来，所有元素右移一位，再把拿出的元素放到开头。重复 k 次。

```cpp
class Solution {
public:
    void rotate(vector<int>& nums, int k) {
        int n = nums.size();
        k %= n; // k可能大于n，取模消除多余整圈
        for (int step = 0; step < k; step++) {
            int last = nums[n - 1]; // 保存末尾元素
            // 所有元素右移一位
            for (int i = n - 1; i > 0; i--) {
                nums[i] = nums[i - 1];
            }
            nums[0] = last; // 末尾元素放到开头
        }
    }
};
```

**关键点**: 内层循环必须从后往前移（从前往后会覆盖数据）。此解法在 k 接近 n 时 O(n²) 会 TLE。

---

### 解法2: 额外数组 — O(n) / O(n)

**从解法1优化**: 解法1的瓶颈是"一步一步搬"，其实每个元素的最终位置可以直接算出来：元素 `nums[i]` 的新位置是 `(i + k) % n`。

```cpp
class Solution {
public:
    void rotate(vector<int>& nums, int k) {
        int n = nums.size();
        k %= n;
        vector<int> temp(n);
        for (int i = 0; i < n; i++) {
            temp[(i + k) % n] = nums[i]; // 直接放到目标位置
        }
        nums = temp; // 拷贝回原数组
    }
};
```

**关键点**: `(i + k) % n` 就是轮转的数学公式。这个方法简单直观，但用了 O(n) 额外空间，面试官大概率会追问"能否 O(1) 空间"。

---

### 解法3: 三次翻转法 — O(n) / O(1) ⭐ 面试首选

**从解法2优化**: 解法2用额外数组是因为"原地搬会覆盖"。三次翻转法的核心洞察：

> 轮转 k 步 = 把数组分成 `[前n-k个 | 后k个]`，然后两段交换位置。

怎么原地交换两段？**全部翻转 → 前k翻转 → 后n-k翻转**。

```
为什么三次翻转能实现两段互换？

设数组为 [A | B]，要变成 [B | A]

Step1: 翻转全部 → [A^r | B^r]^r = [B^r | A^r]
  (翻转后，B和A的位置互换了，但各自内部是反的)
Step2: 翻转前半段 → [B | A^r]
Step3: 翻转后半段 → [B | A]  ✓
```

```cpp
class Solution {
public:
    void rotate(vector<int>& nums, int k) {
        int n = nums.size();
        k %= n; // 关键：k可能>=n
        if (k == 0) return; // 不需要轮转
        
        // 三次翻转
        reverse(nums.begin(), nums.end());            // 翻转整个数组
        reverse(nums.begin(), nums.begin() + k);      // 翻转前k个
        reverse(nums.begin() + k, nums.end());         // 翻转后n-k个
    }
};
```

**不用 STL 的版本**（面试可能要求手写 reverse）：

```cpp
class Solution {
public:
    void rotate(vector<int>& nums, int k) {
        int n = nums.size();
        k %= n;
        if (k == 0) return;
        
        auto rev = [&](int left, int right) {
            while (left < right) {
                swap(nums[left++], nums[right--]);
            }
        };
        
        rev(0, n - 1);     // 全翻
        rev(0, k - 1);     // 前k个翻
        rev(k, n - 1);     // 后n-k个翻
    }
};
```

**关键点**: 
- `k %= n` 必须在最前面，否则 `nums.begin() + k` 可能越界。
- 手写 reverse 时，`rev(0, k-1)` 的右边界是 `k-1` 不是 `k`（闭区间）。

---

### 解法4: 环状替换 — O(n) / O(1)

**完全不同的思路**: 把每个元素直接放到它应该去的位置。元素 i 去位置 (i+k)%n，被顶掉的元素继续往下放，形成一条"链"。

```
环状替换过程 (nums=[1,2,3,4,5,6], k=2):

从位置0出发:
0 → 2 → 4 → 0 (回到起点，一条环走完)
移动过程: 1→pos2, 5→pos0 中间经过 3→pos4, 然后 5→pos0

环1: 0→2→4→0  处理了 nums[0], nums[2], nums[4]
环2: 1→3→5→1  处理了 nums[1], nums[3], nums[5]

一共 gcd(6,2)=2 条环，每条环 6/2=3 个元素
```

```cpp
class Solution {
public:
    void rotate(vector<int>& nums, int k) {
        int n = nums.size();
        k %= n;
        if (k == 0) return;
        
        int count = 0; // 已归位的元素数
        for (int start = 0; count < n; start++) {
            int cur = start;
            int prev_val = nums[start];
            do {
                int next = (cur + k) % n;      // 目标位置
                int temp = nums[next];          // 保存被覆盖的值
                nums[next] = prev_val;          // 放入
                prev_val = temp;                // 被覆盖的值继续往下放
                cur = next;
                count++;                        // 又一个元素归位
            } while (cur != start);             // 回到起点说明这条环走完
        }
    }
};
```

**关键点**: 
- 环的数量 = `gcd(n, k)`，每条环长度 = `n / gcd(n, k)`
- 外层 `for` 循环最多执行 `gcd(n, k)` 次（但我们用 `count < n` 来控制更简洁）
- 必须用 `do-while` 而不是 `while`，否则第一次 `cur == start` 就退出了

## 解法对比

| | 暴力模拟 | 额外数组 | 三次翻转 ⭐ | 环状替换 |
|---|---------|---------|-----------|---------|
| 时间 | O(n×k) | O(n) | O(n) | O(n) |
| 空间 | O(1) | O(n) | O(1) | O(1) |
| 代码量 | 少 | 少 | 最少 | 中等 |
| 思维难度 | 低 | 低 | 中 | 高 |
| 面试推荐 | ✗ | 过渡 | ✓ 首选 | 加分 |

**面试推荐路线**: 先说额外数组确保正确性 → 提出三次翻转优化空间 → 如果面试官继续追问可以讲环状替换。

## 易错点

1. **忘记 `k %= n`**
   - ✗ 直接用 k → 当 k ≥ n 时，`nums.begin() + k` 越界，或计算出错
   - ✓ `k %= n;` 放在函数最开始

2. **手写 reverse 的边界**
   - ✗ `rev(0, k)` — 多翻了一个元素
   - ✓ `rev(0, k-1)` — 闭区间 [0, k-1]

3. **环状替换用 `while` 而非 `do-while`**
   - ✗ `while (cur != start) { ... }` — 循环体一次都不执行（初始 cur == start）
   - ✓ `do { ... } while (cur != start);` — 至少执行一次

4. **k == 0 的特殊情况**
   - 虽然 `k %= n` 后 k 可能变成 0（如 n=3, k=6），此时不需要任何操作
   - ✗ 不检查 → 三次翻转仍然正确但多做无用功；环状替换可能死循环
   - ✓ `if (k == 0) return;`

## 面试追问

**Q1: 暴力解的时间复杂度是多少？能通过本题吗？**
> O(n×k)，n 和 k 最大 10⁵，最坏 10¹⁰ 次操作，会 TLE。

**Q2: 用额外数组能 O(n) 解决，但能否 O(1) 空间？**
> 可以。三次翻转法：全翻 → 前 k 翻 → 后 n-k 翻。每次翻转是 O(n) 原地操作，总共 O(n) 时间 O(1) 空间。

**Q3: 为什么三次翻转是正确的？能证明吗？**
> 数组看成 [A|B]，要变成 [B|A]。翻转全部得到 (AB)^r = B^r A^r（翻转会反转拼接顺序），再分别翻转 B^r→B 和 A^r→A，得到 [B|A]。

**Q4: 如果是左旋 k 步呢？**
> 左旋 k 步 = 右旋 n-k 步。或者三次翻转的顺序调整：先翻前 k 个 → 再翻后 n-k 个 → 最后全翻。

**Q5: 环状替换法中，一共有几条环？**
> `gcd(n, k)` 条环，每条环长 `n / gcd(n, k)`。所以总共恰好移动 n 个元素。
