# 817. 链表组件

## 核心思路

把 `nums` 中的值放入哈希集合，然后遍历链表。每当从"不在集合中"的节点转移到"在集合中"的节点时，就意味着进入了一个新的连通分量。统计这种**进入边界**的次数即可。

## 思维链

1. **读完题第一反应** → 连通分量？听起来像图论的 Union-Find 或 BFS/DFS。但仔细看，"连通"的定义是**链表中相邻**，不是值相邻。
2. **简化问题** → 链表是线性结构，相邻关系是确定的。所以问题变成：在链表这条线上，把 `nums` 中的值标记出来，问有几段**连续的标记区域**？
3. **类比** → 就像数组 `[1,0,1,1,0,1]` 中数 "连续1的段数" 一样简单。
4. **怎么数段数？** → 遍历链表，看当前节点是否在集合中且是某段的起点（前一个不在集合中或不存在）。每当发现一个段的起点，计数+1。
5. **优化查找** → 判断节点值是否在 `nums` 中用哈希集合，O(1) 查找。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 哈希集合 + 线性扫描 | 遍历链表，统计连续段数 | O(n) | O(m) | 必须写出 |
| Union-Find | 对相邻且都在集合中的节点合并 | O(n * α(n)) | O(n) | 杀鸡用牛刀，不推荐 |

其中 n 是链表长度，m 是 `nums` 的大小。

## 关键提示

1. **转换视角**：不要被"连通分量"吓到，链表是线性的，问题退化为"数连续段"。
2. **段起点判定**：当前节点在集合中，且前一个节点不在集合中（或当前是头节点），就是一个新段的起点。
3. **等价简化**：也可以换个角度——当前节点在集合中，且下一个节点**不在**集合中（或不存在），说明当前段**结束**了，计数+1。两种方式等价。
4. **哈希集合而非哈希表**：只需要判断存在性，不需要映射值，用 `unordered_set` 足够。
5. **不需要真的构造子链表**：不需要把连通分量"提取"出来，只需要计数。

## 解法详解

### 解法1: 哈希集合 + 线性扫描 — O(n) / O(m)

**思考过程**: 链表是线性结构，"连通"意味着链表中相邻且都在 `nums` 中。所以遍历链表，找到每段连续属于 `nums` 的节点段，统计段数即可。

```
示例: head = [0,1,2,3,4], nums = [0,3,1,4]
集合 = {0, 1, 3, 4}

遍历链表:
0 → 在集合中, 前面无节点 → 新段起点, count=1
1 → 在集合中, 前面0也在集合中 → 同一段, 不加
2 → 不在集合中 → 段中断
3 → 在集合中, 前面2不在集合中 → 新段起点, count=2
4 → 在集合中, 前面3也在集合中 → 同一段, 不加

结果: 2 个连通分量 [0,1] 和 [3,4]
```

```cpp
class Solution {
public:
    int numComponents(ListNode* head, vector<int>& nums) {
        unordered_set<int> setG(nums.begin(), nums.end());
        int count = 0;
        bool inComponent = false;
        
        ListNode* curr = head;
        while (curr) {
            if (setG.count(curr->val)) {
                if (!inComponent) {
                    count++;          // 新段的起点
                    inComponent = true;
                }
            } else {
                inComponent = false;  // 段中断
            }
            curr = curr->next;
        }
        return count;
    }
};
```

**关键点**:
- `inComponent` 标记当前是否在一个连续段内，避免重复计数。
- 也可以不用 flag，改用"看下一个节点"的方式判断段结束。

---

### 解法1 变体: 统计段结束点

**不同角度**: 不统计段起点，而是统计段**结束点**。当前节点在集合中，且下一个节点不在集合中（或 next 为 null），说明一段结束。

```cpp
class Solution {
public:
    int numComponents(ListNode* head, vector<int>& nums) {
        unordered_set<int> setG(nums.begin(), nums.end());
        int count = 0;
        
        ListNode* curr = head;
        while (curr) {
            if (setG.count(curr->val) && 
                (!curr->next || !setG.count(curr->next->val))) {
                count++;  // 段结束
            }
            curr = curr->next;
        }
        return count;
    }
};
```

**关键点**:
- 这种写法更简洁，不需要额外的 `inComponent` 标记。
- 逻辑等价：段起点数 == 段结束点数。

## 易错点

1. **用数组线性查找而非哈希集合**：
   - 错误做法：每次用 `find(nums.begin(), nums.end(), val)` 查找，复杂度 O(m)，总体 O(n*m)
   - 正确做法：预先建立 `unordered_set`，O(1) 查找

2. **忘记处理链表尾部**：
   - 如果最后一段一直延伸到链表末尾，统计段起点的方式不受影响；但如果用其他方式（如统计"从在集合到不在集合的跳变"），可能遗漏最后一段

3. **误解"连通"的含义**：
   - 错误理解：值相邻（差为1）即连通。例如 [1,3] 中 1 和 3 差为 2 不连通
   - 正确理解：在**链表中**物理相邻且都在 `nums` 中才算连通

4. **修改链表**：
   - 不需要也不应该修改原始链表的结构

## 面试追问

**Q1: 时间和空间复杂度分析？**
> 时间 O(n + m)：建集合 O(m)，遍历链表 O(n)。空间 O(m)：哈希集合存储。

**Q2: 如果 nums 非常大（接近 n），有优化空间吗？**
> 此时哈希集合大小接近 n，可以考虑用位图（bitset）代替哈希集合，空间常数更小。由于 Node.val < n，位图大小也是 O(n)。

**Q3: 如果链表有环怎么办？**
> 需要先用快慢指针检测环，或者用 visited 集合记录已访问节点。但本题保证无环。

**Q4: 能否用 Union-Find 解？**
> 可以，但过于复杂。对相邻且都在集合中的节点对做 union 操作，最后数不同的连通分量。时间 O(n * alpha(n))，空间 O(n)。对于线性链表来说是杀鸡用牛刀。
