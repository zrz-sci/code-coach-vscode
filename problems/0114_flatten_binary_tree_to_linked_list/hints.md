# 114. 二叉树展开为链表 (Flatten Binary Tree to Linked List)

## 核心思路

给定一棵二叉树的根节点 `root`，将其原地展开为一个"链表"：展开后的链表应该使用 `TreeNode`，其中 `right` 指针指向下一个节点，`left` 指针始终为 `nullptr`。展开顺序与**前序遍历**一致。

本质上就是一个**树结构重排**问题：按前序遍历的顺序，把二叉树改造为只有右子节点的"链表"。

## ASCII 图解

```
原始二叉树:              展开后（前序链表）:
      1                   1
     / \                   \
    2   5                   2
   / \   \                   \
  3   4   6                   3
                               \
                                4
                                 \
                                  5
                                   \
                                    6

前序遍历顺序: 1 → 2 → 3 → 4 → 5 → 6
展开后就是按这个顺序串成右链。
```

## 思维链

1. **读完题第一反应** → 先前序遍历得到节点列表，然后按顺序重新连接。但这需要 O(n) 额外空间。
2. **能否原地完成？** → 需要在遍历的同时改造树结构，关键是"处理当前节点时，不能丢失右子树"。
3. **方法1: 反向后序递归** → 如果按 "右 → 左 → 根" 的顺序处理（前序的逆序），用一个 `prev` 指针记录上一个处理的节点，当前节点的 `right` 指向 `prev`。从后往前构建链表。
4. **方法2: 前序迭代 + 栈** → 用栈模拟前序遍历。弹出节点时，将其 `right` 指向栈顶（下一个要访问的节点）。
5. **方法3: Morris 式 O(1) 空间** → 对每个有左子树的节点：找到左子树的最右节点，把当前节点的右子树挂到那里，然后把左子树移到右边。这样不需要额外空间。

```
Morris 式图解（处理节点1的左子树）:

Step 1: 找到左子树(2)的最右节点 → 是4
      1                      1
     / \                    / \
    2   5      →           2   5
   / \   \               / \   \
  3   4   6             3   4   6
                             \
                              5 ← 把1的右子树接到4后面
                               \
                                6

Step 2: 左子树移到右边，左边置空
      1
       \
        2
       / \
      3   4
           \
            5
             \
              6

Step 3: 继续处理节点2（同样的操作）...
```

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 前序遍历 + 重连 | 先遍历存列表再连接 | O(n) | O(n) | 能说出即可 |
| 反向后序递归 | 右左根顺序，prev 串联 | O(n) | O(n) 栈 | ⭐ 代码最短 |
| 前序迭代 + 栈 | 栈模拟前序遍历 | O(n) | O(n) | ⭐ 最直观 |
| Morris 式 O(1) 空间 | 左子树最右节点接右子树 | O(n) | O(1) | ⭐⭐ 最优 |

## 关键提示

1. **前序遍历顺序**：根 → 左 → 右。展开后的链表就是这个顺序。
2. **原地修改的难点**：处理根节点时，如果直接把 left 接到 right，原来的 right 子树就丢了。三种解法分别用不同策略解决这个问题：
   - 反向后序：从后往前构建，不存在"丢失右子树"的问题。
   - 栈：先把右子节点压栈保存，不会丢。
   - Morris：把右子树提前挂到左子树的最右节点上，再移动。
3. **`left` 全部置 `nullptr`**：展开后每个节点的 left 必须为空，容易漏掉。
4. **反向后序的关键洞察**：前序是"根左右"，反过来是"右左根"。按这个顺序处理，每个节点处理时，它前序中后面的所有节点都已经被串好了（存在 `prev` 中）。

## 解法详解

### 解法1: 前序遍历 + 重新连接 — O(n) / O(n)

**思考过程**: 最直接的两步走：先前序遍历收集所有节点，再按顺序重新连接。

```cpp
class Solution {
public:
    void flatten(TreeNode* root) {
        vector<TreeNode*> nodes;
        preorder(root, nodes);
        for (int i = 0; i < (int)nodes.size() - 1; i++) {
            nodes[i]->left = nullptr;
            nodes[i]->right = nodes[i + 1];
        }
    }
private:
    void preorder(TreeNode* node, vector<TreeNode*>& nodes) {
        if (!node) return;
        nodes.push_back(node);
        preorder(node->left, nodes);
        preorder(node->right, nodes);
    }
};
```

**关键点**:
- 简单直接，两步操作分离，不易出错。
- 需要 O(n) 额外空间存节点列表。面试官会追问"能否 O(1) 空间？"

---

### 解法2: 反向后序递归（右 → 左 → 根） — O(n) / O(n) ⭐

**核心思想**: 前序是 "根 → 左 → 右"，如果我们按其逆序 "右 → 左 → 根" 处理，那么每个节点被处理时，它在前序中所有后续节点都已经被串成链表了（存在 `prev` 中）。

```
处理顺序: 6 → 5 → 4 → 3 → 2 → 1 （前序的逆序）

处理6: prev = null     → 6.right = null, prev = 6
处理5: prev = 6        → 5.right = 6,    prev = 5
处理4: prev = 5→6      → 4.right = 5,    prev = 4
处理3: prev = 4→5→6    → 3.right = 4,    prev = 3
处理2: prev = 3→4→5→6  → 2.right = 3,    prev = 2
处理1: prev = 2→...→6  → 1.right = 2,    prev = 1

最终: 1→2→3→4→5→6 ✓
```

```cpp
class Solution {
public:
    TreeNode* prev = nullptr;
    
    void flatten(TreeNode* root) {
        if (!root) return;
        flatten(root->right);  // 先处理右子树
        flatten(root->left);   // 再处理左子树
        root->right = prev;    // 当前节点的 right 指向上一个处理的节点
        root->left = nullptr;  // left 置空
        prev = root;           // 更新 prev
    }
};
```

**关键点**:
- 代码极其简洁，只有 6 行核心逻辑。
- 递归顺序是 "右 → 左 → 根"，不是标准的后序 "左 → 右 → 根"。
- `prev` 是类成员变量（或引用参数），用来跨递归调用传递信息。
- 空间 O(n)：递归栈深度最坏 O(n)（退化为链表时）。

---

### 解法3: 前序迭代 + 栈 — O(n) / O(n)

**思路**: 用栈模拟前序遍历。弹出节点时，将其 `right` 指向栈顶（即前序中的下一个节点）。

```
栈模拟过程:
初始: 栈 = [1]

弹出1: 压入 right=5, left=2 → 栈 = [5, 2]
  1.right = 栈顶2, 1.left = null

弹出2: 压入 right=4, left=3 → 栈 = [5, 4, 3]
  2.right = 栈顶3, 2.left = null

弹出3: 无子节点 → 栈 = [5, 4]
  3.right = 栈顶4, 3.left = null

弹出4: 无子节点 → 栈 = [5]
  4.right = 栈顶5, 4.left = null

弹出5: 压入 right=6 → 栈 = [6]
  5.right = 栈顶6, 5.left = null

弹出6: 栈空
  6.right = null, 6.left = null

结果: 1→2→3→4→5→6 ✓
```

```cpp
class Solution {
public:
    void flatten(TreeNode* root) {
        if (!root) return;
        stack<TreeNode*> stk;
        stk.push(root);
        
        while (!stk.empty()) {
            TreeNode* node = stk.top();
            stk.pop();
            
            // 先压右再压左，这样左先弹出（前序：根左右）
            if (node->right) stk.push(node->right);
            if (node->left) stk.push(node->left);
            
            // 当前节点的 right 指向下一个要访问的节点（栈顶）
            if (!stk.empty()) {
                node->right = stk.top();
            }
            node->left = nullptr;
        }
    }
};
```

**关键点**:
- 最直观的前序遍历模拟，容易理解和编写。
- 先压右再压左，保证左子节点先弹出。
- `node->right = stk.top()` 直接把当前节点连到下一个前序节点。

---

### 解法4: Morris 式 O(1) 空间 — O(n) / O(1) ⭐⭐

**核心思想**: 对于每个有左子树的节点，找到左子树的最右节点（即前序遍历中左子树的最后一个节点），把当前节点的右子树挂到那个最右节点的右边。然后把左子树整体移到右边。

```
为什么挂到"左子树的最右节点"？
因为前序遍历中，左子树的最右节点是左子树中最后被访问的。
它的下一个就是当前节点的右子树。

详细步骤:
原始:        Step1(处理1):   Step2(处理2):   Step3(处理3):
    1            1              1              1
   / \            \              \              \
  2   5            2              2              2
 / \   \          / \              \              \
3   4   6        3   4              3              3
                      \              \              \
                       5              4              4
                        \              \              \
                         6              5              5
                                        \              \
                                         6              6
                                                  完成! ✓
```

```cpp
class Solution {
public:
    void flatten(TreeNode* root) {
        TreeNode* curr = root;
        while (curr) {
            if (curr->left) {
                // 找到左子树的最右节点
                TreeNode* rightmost = curr->left;
                while (rightmost->right) {
                    rightmost = rightmost->right;
                }
                // 把当前节点的右子树挂到左子树的最右节点后面
                rightmost->right = curr->right;
                // 左子树移到右边
                curr->right = curr->left;
                curr->left = nullptr;
            }
            // 移动到下一个节点（右子节点）
            curr = curr->right;
        }
    }
};
```

**关键点**:
- **O(1) 空间**，不需要栈或递归。
- 每个节点最多被访问两次（一次作为 curr，一次在找最右节点时被经过），所以时间仍是 O(n)。
- 这个技巧类似 Morris 遍历中的"线索化"思想（利用空指针建立临时链接），但这里是永久修改。

## 解法对比

|  | 前序+重连 | 反向后序递归 | 前序迭代+栈 | Morris式 |
|--|----------|------------|-----------|---------|
| 时间 | O(n) | O(n) | O(n) | **O(n)** |
| 空间 | O(n) | O(n) | O(n) | **O(1)** |
| 代码量 | 中 | **最少** | 中 | 少 |
| 直观度 | 高 | 需要理解反向 | 高 | 需要理解技巧 |
| 面试推荐 | 起点 | ⭐ 巧妙 | ⭐ 易写 | ⭐⭐ 最优 |

**面试策略**: 先说前序遍历+重连的思路，然后根据面试官偏好写递归或迭代。如果追问 O(1) 空间，讲 Morris 式解法。

## 易错点

1. **反向后序递归顺序搞错**：
   - ✗ `flatten(left); flatten(right); root->right = prev;` → 标准后序"左右根"，会打乱顺序
   - ✓ `flatten(right); flatten(left); root->right = prev;` → "右左根"（前序的逆序）

2. **忘记置空 left**：
   - ✗ 只设置了 `right`，没有设置 `left = nullptr`
   - ✓ 每个节点处理后都要 `node->left = nullptr`

3. **Morris 式找最右节点时进入右子树**：
   - ✗ 从 `curr` 开始找最右 → 可能会回到 curr 自己（如果之前已经被修改）
   - ✓ 从 `curr->left` 开始找最右，且只沿 `right` 走

4. **栈解法中压入顺序**：
   - ✗ 先压左再压右 → 右先弹出，变成"根右左"
   - ✓ 先压右再压左 → 左先弹出，正确的前序"根左右"

5. **递归解法中 prev 作用域**：
   - ✗ `prev` 定义为局部变量 → 递归调用之间不共享
   - ✓ `prev` 定义为类成员变量或引用参数

## 面试追问

**Q1: 三种解法的取舍？**
> 如果面试要求 O(1) 空间 → Morris 式。如果追求代码简洁 → 反向后序递归。如果要最直观 → 前序迭代+栈。

**Q2: 如果要按中序遍历展开呢？**
> 反向后序递归法：改为按中序的逆序处理（右 → 根 → 左）。Morris 式：改用标准 Morris 中序遍历的思路。

**Q3: 如果不能修改树的结构，只需要返回前序遍历结果？**
> 直接前序遍历收集结果即可，O(n) 时间 O(n) 空间。

**Q4: Morris 式的时间复杂度为什么是 O(n) 而不是 O(n^2)？**
> 虽然每个节点可能在"找最右节点"时被经过，但每条边最多被走两次（一次向下，一次在找最右时经过）。总共 n-1 条边，所以总操作数 <= 2(n-1) + n = O(n)。

**Q5: 能否用 Morris 遍历真正的 O(1) 空间来做前序遍历？**
> 可以，但 Morris 前序遍历和本题的 Morris 式解法思路不同。Morris 前序遍历用线索二叉树的思想，找到前驱节点后建立临时链接，遍历完后恢复。本题不需要恢复（永久修改），所以代码更简单。
