# 853. 车队 (Car Fleet)

## 核心思路

本题本质上是：**按位置从远到近排序后，判断后方的车能否在到达终点前追上前方的车**。如果后方的车到达终点所需时间 ≤ 前方的车，说明它会被前方的车"挡住"，合并为一个车队；否则它自成一个车队。

## 思维链

1. **读完题的第一反应**：每辆车有位置和速度，不能超车。后面的快车追上前面的慢车后会"合并"成一个车队，以慢车速度行驶。问最终有几个车队到达终点。

2. **关键观察 — 谁挡谁？** 一辆车只会被它**前面最近**的车挡住。所以我们应该**从最靠近终点的车开始，向后逐个考察**。

3. **怎么判断"追上"？** 如果没有前车阻挡，每辆车独立到达终点的时间是 `(target - position) / speed`。如果后方的车到达时间 ≤ 前方的车，说明后方会追上前方（或恰好在终点追上），它们合并为一个车队。

4. **从后往前扫描**：把车按位置从大到小排序。维护当前车队的"到达时间"（即当前车队最前面那辆车的时间）。如果下一辆车的独立到达时间 > 当前车队时间，它无法追上，自成新车队。

5. **这就是单调栈的思想**：维护一个"到达时间"的单调递减栈（从栈底到栈顶时间递减），每辆车的到达时间如果 ≤ 栈顶，被吞并；如果 > 栈顶，入栈，代表新车队。最终栈的大小就是车队数。

6. **其实不需要显式栈**：只需要一个变量记录当前最大到达时间即可，因为我们是从前到后线性扫描。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 排序 + 线性扫描 | 按位置降序排序，比较到达时间 | O(n log n) | O(n) | ⭐ 必须写出 |
| 排序 + 单调栈 | 显式用栈维护车队的到达时间 | O(n log n) | O(n) | 能说出即可 |

## 关键提示

1. **先排序**：按位置从大到小排序，这样从最靠近终点的车开始考察，模拟"前车挡后车"的物理过程。

2. **到达时间是关键**：每辆车独立到达终点的时间 = `(target - pos) / speed`（用 `double`）。如果后方车时间 ≤ 前方车时间，后方车一定能追上（或被挡住变慢）。

3. **合并的本质**：被前车挡住的车，最终到达时间等于前车的到达时间。所以我们只需要关注每个车队的"领头车"的时间。

4. **ASCII 示意图 — 示例1的排序和扫描过程**：
```
target = 12
排序后（按位置降序）:
位置:  10   8   5   3   0
速度:   2   4   1   3   1
时间:  1.0  1.0 7.0 3.0 12.0

扫描过程 (从左到右 = 从最近终点到最远):
  车@10: 时间=1.0, 无前车 → 新车队 ✓  (fleets=1, maxTime=1.0)
  车@8:  时间=1.0, 1.0 ≤ 1.0 → 合并到前车队 (fleets=1, maxTime=1.0)
  车@5:  时间=7.0, 7.0 > 1.0 → 新车队 ✓  (fleets=2, maxTime=7.0)
  车@3:  时间=3.0, 3.0 ≤ 7.0 → 合并到前车队 (fleets=2, maxTime=7.0)
  车@0:  时间=12.0, 12.0 > 7.0 → 新车队 ✓ (fleets=3, maxTime=12.0)
结果: 3 个车队
```

5. **浮点数精度**：用 `double` 做除法即可，不需要特殊处理精度（因为只是比较大小关系）。

## 解法详解

### 解法1: 排序 + 线性扫描 — O(n log n) / O(n) ⭐ 面试首选

**思考过程**：

核心洞察：**一辆车能否独立到达终点，取决于它前面有没有更慢的车挡着它**。

如果我们从最靠近终点的车开始向后扫描，维护"当前最慢车队的到达时间"：
- 后方车的独立到达时间 ≤ 当前最大时间 → 它会被前方车队吞并
- 后方车的独立到达时间 > 当前最大时间 → 它追不上前方车队，自成新车队

这样只需要一次线性扫描。

```cpp
class Solution {
public:
    int carFleet(int target, vector<int>& position, vector<int>& speed) {
        int n = position.size();
        // 将 (position, speed) 配对，按位置降序排序
        vector<pair<int,int>> cars(n);
        for (int i = 0; i < n; i++) {
            cars[i] = {position[i], speed[i]};
        }
        // 按位置从大到小排序 → 从最靠近终点的车开始
        sort(cars.begin(), cars.end(), [](const pair<int,int>& a, const pair<int,int>& b) {
            return a.first > b.first;
        });
        
        int fleets = 0;
        double maxTime = 0; // 当前车队到达终点的最大时间
        
        for (auto& [pos, spd] : cars) {
            // 这辆车独立到达终点需要多长时间
            double time = (double)(target - pos) / spd;
            
            if (time > maxTime) {
                // 追不上前面的车队 → 自成新车队
                fleets++;
                maxTime = time; // 更新最大时间
            }
            // else: 能追上前面的车队 → 被吞并，不产生新车队
        }
        
        return fleets;
    }
};
```

**关键点**：
- 排序方向是按位置**降序**（从终点往回看），不是升序
- `maxTime` 只会单调递增（因为只在 `time > maxTime` 时更新），这保证了正确性
- 不需要显式栈，一个变量就够了

### 解法2: 排序 + 单调栈 — O(n log n) / O(n)

**从解法1的角度看**：解法1 中 `maxTime` 本质上就是"栈顶"。我们可以用显式的栈来存储每个车队的到达时间，更直观地展示"车队合并"的过程。

**栈的含义**：栈中每个元素代表一个独立车队的到达时间。新车如果到达时间 ≤ 栈顶，就被栈顶车队吞并；否则入栈成为新车队。

```cpp
class Solution {
public:
    int carFleet(int target, vector<int>& position, vector<int>& speed) {
        int n = position.size();
        vector<pair<int,int>> cars(n);
        for (int i = 0; i < n; i++) {
            cars[i] = {position[i], speed[i]};
        }
        sort(cars.begin(), cars.end(), [](const pair<int,int>& a, const pair<int,int>& b) {
            return a.first > b.first;
        });
        
        // 栈存储每个独立车队的到达时间（从栈底到栈顶单调递增）
        stack<double> st;
        
        for (auto& [pos, spd] : cars) {
            double time = (double)(target - pos) / spd;
            
            // 如果栈空 或 当前车的到达时间 > 栈顶（前方车队的时间）
            // → 追不上，自成新车队
            if (st.empty() || time > st.top()) {
                st.push(time);
            }
            // else: 追得上前方车队，被吞并，不入栈
        }
        
        return st.size(); // 栈中元素个数 = 车队数
    }
};
```

**关键点**：
- 栈从底到顶是**单调递增**的（后面的车队到达时间一定越来越大）
- 这个栈其实没有"弹出"操作，所以严格来说不算经典单调栈，更像是一个过滤器
- 但理解单调栈的思想对后续题目（如 Car Fleet II）有帮助

## 解法对比

| | 解法1: 线性扫描 | 解法2: 单调栈 |
|---|---|---|
| 时间 | O(n log n) | O(n log n) |
| 空间 | O(n) 排序 | O(n) 排序+栈 |
| 代码量 | 更简洁 | 稍多 |
| 面试推荐 | ⭐ 首选 | 适合讲单调栈思想 |
| 本质 | maxTime 变量 = 隐式栈顶 | 显式栈 |

两种解法的瓶颈都在排序 O(n log n)。解法1更简洁，面试首选。解法2的价值在于它让"栈"的概念显式化，有助于理解 Car Fleet II 等需要真正用单调栈的进阶题。

## 易错点

1. **✗ 排序方向搞反**：按位置升序排序后从前往后扫描
   **✓ 按位置降序排序**（从终点往回看），因为我们需要知道"前方车队的时间"来判断后方车能否追上

2. **✗ 用整数除法算时间**：`int time = (target - pos) / spd;`
   **✓ 用浮点除法**：`double time = (double)(target - pos) / spd;`，否则 `(12-10)/2 = 1` 但 `(12-8)/4 = 1`，精度丢失可能导致本该不同的时间变成相同

3. **✗ 判断条件用 `>=` 而不是 `>`**：
   ```cpp
   // 错误：time >= maxTime 会把恰好等于的情况也算成新车队
   // 正确：time > maxTime 才算新车队
   // 因为"恰好追上"也算同一个车队（题目明确说 "at the mile target" 也算）
   ```

4. **✗ 忘记把 position 和 speed 配对后再排序**：单独排序 position 会打乱和 speed 的对应关系

## 面试追问

**Q1: 为什么按位置排序而不是按速度或到达时间排序？**
→ 因为"不能超车"是基于物理位置的约束。位置靠前的车是"挡路"的车，后面的车只能被它阻挡。按位置排序后，才能从前到后（或从后到前）正确模拟这个过程。如果按时间排序，你无法知道两辆车之间的空间关系。

**Q2: 如果要求返回每个车队包含哪些车呢？**
→ 在扫描时维护一个当前车队的列表。每当 `time > maxTime`，说明新车队开始，把之前的车队存起来，开始新一组。

**Q3: 如果车可以超车呢？（即没有阻挡约束）**
→ 那每辆车都独立到达终点，答案就是 n。"不能超车"是本题的核心约束，正是它导致了车队合并。

**Q4 (进阶): Car Fleet II (LeetCode 1776) 怎么做？**
→ 那道题问的是每辆车被前车追上的时间，需要用**真正的单调栈**。本题只是计数，不需要弹栈；1776 需要弹栈来处理"前车被更前的车吞并后，当前车的碰撞对象变了"的情况。

## 相关题型

- **1776. Car Fleet II** — 本题的进阶版。本题只数车队个数（不需要弹栈），1776 要求每辆车的碰撞时间（需要**真正的单调栈 + 弹栈逻辑**）。掌握本题的"按位置排序 + 到达时间比较"是 1776 的前置知识。

- **735. 小行星碰撞 (Asteroid Collision)** — 同样是栈 + 碰撞/合并的思想。区别：小行星有方向，碰撞规则不同；本题所有车同向，合并规则基于速度。复用"用栈维护存活元素"的框架。

- **739. 每日温度 (Daily Temperatures)** — 经典单调栈题。复用"从后往前扫描，用栈维护待处理元素"的模式。区别：739 找下一个更大值，本题找下一个更慢的车队。
