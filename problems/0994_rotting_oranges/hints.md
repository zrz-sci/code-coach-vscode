# 994. 腐烂的橘子

## 核心思路

这道题本质上是一个**多源 BFS 求最短传播时间**的问题：所有腐烂橘子同时向外扩散，问扩散到所有新鲜橘子需要多少轮（分钟）。

## 思维链

1. **读完题第一反应**：腐烂橘子每分钟感染四周的新鲜橘子，这就像"病毒传播"或"森林火灾"——从多个起火点同时向外蔓延，问多久烧完。最朴素的做法是每分钟遍历整个网格，把腐烂橘子旁边的新鲜橘子变腐烂，直到没有变化为止。

2. **暴力解的瓶颈**：每一轮都要扫描整个网格找腐烂橘子，但大部分位置其实不需要检查（只有"刚刚腐烂"的橘子才可能感染新邻居）。如果网格很大，重复扫描浪费大量时间。

3. **怎么突破瓶颈？** 我们只需要关注"这一轮刚腐烂的橘子"，让它们去感染邻居。这正是 **BFS 的层级扩展**思想——每一层就是"这一分钟新腐烂的橘子"。

4. **关键洞察：多源 BFS**。这题不是从一个起点出发，而是所有初始腐烂橘子同时开始扩散。做法是把所有初始腐烂橘子一起放入队列作为第 0 层，然后逐层 BFS。每扩展一层，时间 +1。

5. **终止判断**：BFS 结束后，如果还有新鲜橘子剩余，说明有橘子永远无法被感染到（被空格隔开），返回 -1。

6. **细节**：如果一开始就没有新鲜橘子，直接返回 0（不需要任何时间）。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力模拟 | 每分钟遍历整个网格，感染邻居 | O(m·n·max(m,n)) | O(1) 原地 | 能说出即可 |
| 多源 BFS | 所有腐烂橘子入队，逐层扩展 | O(m·n) | O(m·n) | ⭐ 必须写出 |

## 关键提示

1. **为什么是 BFS 而不是 DFS？** BFS 天然按"距离层级"扩展，每扩一层就是 1 分钟。DFS 只能找到"能否到达"，但不能高效求最短传播时间。

2. **多源 vs 单源**：如果只有一个腐烂橘子，就是标准 BFS。多个腐烂橘子同时扩散，就是把所有起点一起放入队列——效果等价于添加一个"超级源点"连接所有初始腐烂橘子。

3. **时间怎么计算？** 不是每次出队 +1，而是每处理完一整层 +1。用 `queue.size()` 控制层级。

4. **别忘了检查"不可能"的情况**：BFS 结束后扫一遍网格，看有没有值为 1 的新鲜橘子残留。

5. **ASCII 示意图**（示例 1）：

```
初始状态:           第1分钟:            第2分钟:            第3分钟:            第4分钟:
2  1  1            2  2  1            2  2  2            2  2  2            2  2  2
1  1  0            2  1  0            2  2  0            2  2  0            2  2  0
0  1  1            0  1  1            0  1  1            0  2  1            0  2  2
                   ↑(0,0)感染          ↑(0,1)和(1,0)      ↑(1,1)和(2,1)      ↑(2,1)感染
                   (1,0)和(0,1)        感染邻居             感染邻居            (2,2)
```

## 解法详解

### 解法1: 暴力模拟 — O(m·n·max(m,n)) / O(1)

**思考过程**：最直觉的做法——模拟每一分钟发生的事。每轮遍历整个网格，找到所有腐烂橘子，把它们四周的新鲜橘子标记为腐烂。重复直到某一轮没有新的橘子腐烂。

```cpp
class Solution {
public:
    int orangesRotting(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        int minutes = 0;
        
        while (true) {
            // 记录这一轮新感染的位置（不能边遍历边修改，否则"这分钟新腐烂的"会立刻感染别人）
            vector<pair<int,int>> newRotten;
            int dx[] = {0, 0, 1, -1};
            int dy[] = {1, -1, 0, 0};
            
            for (int i = 0; i < m; i++) {
                for (int j = 0; j < n; j++) {
                    if (grid[i][j] == 2) {
                        for (int d = 0; d < 4; d++) {
                            int ni = i + dx[d], nj = j + dy[d];
                            if (ni >= 0 && ni < m && nj >= 0 && nj < n && grid[ni][nj] == 1) {
                                newRotten.push_back({ni, nj});
                            }
                        }
                    }
                }
            }
            
            // 如果没有新橘子腐烂，停止
            if (newRotten.empty()) break;
            
            // 将新腐烂的橘子标记为2
            for (auto& [r, c] : newRotten) {
                grid[r][c] = 2;
            }
            minutes++;
        }
        
        // 检查是否还有新鲜橘子
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                if (grid[i][j] == 1) return -1;
        
        return minutes;
    }
};
```

**关键点**：
- **不能边遍历边修改**！如果直接把 `grid[ni][nj]` 改成 2，那这个"刚腐烂的"橘子在同一轮循环中就会被当作"已腐烂"去感染更远的邻居，导致一分钟内传播了多步。必须先收集，再统一修改。
- 暴力解的瓶颈：每一轮都要遍历整个 m×n 网格，而绝大多数格子不是"刚腐烂的"，做了大量无用工作。

### 解法2: 多源 BFS — O(m·n) / O(m·n) ⭐ 面试首选

**从解法1优化**：解法1每轮扫描整个网格找腐烂橘子，瓶颈在于重复扫描。BFS 直接维护"待扩散"队列，每个橘子最多入队一次，总时间 O(m·n)。

**核心思想**：
1. 预扫描网格：所有初始腐烂橘子入队，同时统计新鲜橘子总数 `freshCount`。
2. BFS 逐层扩展：每一层代表 1 分钟，该层所有腐烂橘子同时感染四周。
3. 每感染一个新鲜橘子，`freshCount--`。
4. BFS 结束后，`freshCount == 0` 则返回总分钟数，否则返回 -1。

```
// BFS 层级扩展示意 (示例1):
// 
// 初始队列 (第0层): [(0,0)]     freshCount = 6
//
// 第1层: (0,0) 感染 (0,1) 和 (1,0)
//   队列: [(0,1), (1,0)]       freshCount = 4
//   minutes = 1
//
// 第2层: (0,1)→(0,2), (1,0)→(1,1)
//   队列: [(0,2), (1,1)]       freshCount = 2
//   minutes = 2
//
// 第3层: (1,1)→(2,1)
//   队列: [(2,1)]              freshCount = 1
//   minutes = 3
//
// 第4层: (2,1)→(2,2)
//   队列: [(2,2)]              freshCount = 0
//   minutes = 4
//
// 队列空, freshCount=0 → 返回 4
```

```cpp
class Solution {
public:
    int orangesRotting(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        queue<pair<int,int>> q;
        int freshCount = 0;
        
        // 第一步：收集所有初始腐烂橘子，统计新鲜橘子数量
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == 2) {
                    q.push({i, j});        // 多源：所有腐烂橘子都是起点
                } else if (grid[i][j] == 1) {
                    freshCount++;
                }
            }
        }
        
        // 特判：如果没有新鲜橘子，0分钟就完成了
        if (freshCount == 0) return 0;
        
        int minutes = 0;
        int dx[] = {0, 0, 1, -1};
        int dy[] = {1, -1, 0, 0};
        
        // 第二步：BFS 逐层扩展
        while (!q.empty()) {
            int size = q.size();  // 当前层的节点数（这一分钟同时扩散的橘子数）
            
            for (int i = 0; i < size; i++) {
                auto [r, c] = q.front();
                q.pop();
                
                for (int d = 0; d < 4; d++) {
                    int nr = r + dx[d], nc = c + dy[d];
                    // 只感染范围内的新鲜橘子
                    if (nr >= 0 && nr < m && nc >= 0 && nc < n && grid[nr][nc] == 1) {
                        grid[nr][nc] = 2;   // 标记为腐烂（同时充当 visited 标记）
                        freshCount--;
                        q.push({nr, nc});
                    }
                }
            }
            
            minutes++;  // 处理完一整层，时间 +1
        }
        
        // 第三步：检查结果
        // minutes-1 是因为最后一层处理完后还多加了一次
        // 或者用 freshCount 判断
        return freshCount == 0 ? minutes - 1 : -1;
    }
};
```

**关键点**：
- 用 `grid[nr][nc] = 2` 既标记腐烂又充当 visited，不需要额外的 visited 数组。
- `minutes - 1`：最后一层节点扩展时发现没有新邻居，但循环末尾仍然执行了 `minutes++`，所以要减 1。

| | 暴力模拟 | 多源 BFS |
|---|---|---|
| 时间复杂度 | O(m·n·max(m,n))，最坏每轮扫全图 | O(m·n)，每个格子最多入队一次 |
| 空间复杂度 | O(m·n) 收集新腐烂的位置 | O(m·n) 队列最坏存所有格子 |
| 核心区别 | 每轮盲目扫描全图 | 只关注"刚腐烂"的前线 |
| 代码难度 | 简单直接 | 需要理解多源 BFS 模板 |
| 面试推荐 | 展示理解后快速过渡到 BFS | ⭐ 必须掌握 |

## 易错点

1. **✗ 忘记 `minutes - 1`**：BFS 循环结束时，最后一层处理完毕但没有新感染，`minutes` 仍然多加了 1。
   - ✓ 返回 `minutes - 1`；或者改成"只有本轮确实感染了新橘子才 `minutes++`"。

2. **✗ 暴力解中边遍历边修改 grid**：
   ```cpp
   // 错误：同一分钟内，刚被感染的橘子又去感染更远的邻居
   if (grid[i][j] == 2) {
       if (grid[i+1][j] == 1) grid[i+1][j] = 2; // 这个橘子马上又被当成源
   }
   ```
   ✓ 先收集所有要修改的位置，循环结束后统一修改。BFS 天然解决这个问题（出队的是上一层）。

3. **✗ 没有特判"初始就没有新鲜橘子"的情况**：
   ```cpp
   // 如果 freshCount == 0，但队列中有腐烂橘子，BFS 仍会运行一层
   // 导致返回 0 而不是正确的 0... 其实这里恰好是 0，但逻辑不清晰
   ```
   ✓ 在 BFS 开始前特判 `if (freshCount == 0) return 0;`

4. **✗ 忘记检查是否有不可达的新鲜橘子**：BFS 结束后必须检查 `freshCount` 是否为 0，否则遗漏返回 -1 的情况。

## 面试追问

**Q1: 这道题为什么用 BFS 而不是 DFS？**
> BFS 按层扩展，天然对应"每分钟扩散一圈"。DFS 是深入一条路径到底再回溯，无法高效模拟"同时扩散"。DFS 可以做但需要额外记录距离信息，不如 BFS 自然。

**Q2: 如果不修改原始 grid，怎么做？**
> 额外用一个 `visited` 二维数组标记已访问。或者用一个 `set/map` 记录已腐烂的坐标。时间不变，空间多 O(m·n)。

**Q3: 如果网格非常大（比如 10000×10000），但只有少量橘子，怎么优化？**
> BFS 只处理有橘子的格子，所以实际时间取决于橘子数量而非网格大小。可以用哈希集合存储新鲜橘子的位置，避免最后 O(m·n) 的扫描。

**Q4: 如果腐烂橘子的传播速度不同（比如某些腐烂橘子2分钟才感染一圈），怎么改？**
> 这就变成了**带权最短路径**问题。可以用优先队列（Dijkstra）替代普通 BFS 队列，按"腐烂时间"排序。
