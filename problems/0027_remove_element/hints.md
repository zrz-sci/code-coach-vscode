# 27. 移除元素

## 核心思路

本质上就是**数组的原地分区**：把所有不等于 `val` 的元素"搬"到数组前部，返回前部的长度。不需要真正"删除"，只需要用不等于 `val` 的元素覆盖掉等于 `val` 的位置。

## 思维链

1. **读完题第一反应**：遍历数组，遇到等于 `val` 的元素就"删掉"它。但数组删除元素需要后面所有元素前移，代价是 O(n)，如果每次都移，最坏 O(n²)。

2. **暴力解的瓶颈**：每删一个元素，后面所有元素都要移动一格。如果有很多 `val`，大量重复搬移。

3. **突破瓶颈的关键观察**：题目说"元素的顺序可以改变"、"前 k 个元素正确即可"。这意味着我们**不需要保持后面元素的正确性**，只需要把"好的"元素收集到前面。

4. **快慢指针（双指针同向）**：用一个慢指针 `slow` 标记"下一个该放元素的位置"，快指针 `fast` 遍历所有元素。遇到不等于 `val` 的，就放到 `slow` 位置，`slow++`。

5. **进一步优化（首尾双指针）**：如果要删除的元素很少，快慢指针会做很多"自己赋值给自己"的无用操作。可以用首尾双指针：遇到等于 `val` 的就用数组末尾元素覆盖，末尾指针左移。这样赋值次数 = 等于 `val` 的元素个数。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力移位 | 遇到 val 就后面整体前移 | O(n²) | O(1) | 能说出即可 |
| 快慢双指针 | slow 收集非 val 元素 | O(n) | O(1) | ⭐ 必须写出 |
| 首尾双指针 | val 元素用末尾元素覆盖 | O(n) | O(1) | 加分项 |

## 关键提示

1. **"原地"的含义**：不能创建新数组，必须在 `nums` 上直接操作。但可以改变元素顺序。

2. **快慢指针的不变量**：`nums[0..slow-1]` 始终存放着已确认的非 `val` 元素。想清楚这个不变量，代码自然就对了。

3. **首尾双指针适用场景**：当 `val` 出现次数很少时（比如 1000 个元素只有 2 个是 `val`），快慢指针要赋值 998 次，而首尾双指针只赋值 2 次。

4. **数组操作的通用模式**：这道题和 [26. 删除有序数组中的重复项] 几乎是同一个模板，区别仅在判断条件。

```
// 快慢双指针过程示意 (nums = [3,2,2,3], val = 3):
//
// 初始:  [3, 2, 2, 3]    slow=0, fast=0
//         f
//         s
//
// fast=0: nums[0]=3 == val, 跳过
//         [3, 2, 2, 3]    slow=0, fast=1
//            f
//         s
//
// fast=1: nums[1]=2 != val, nums[0]=2, slow++
//         [2, 2, 2, 3]    slow=1, fast=2
//               f
//            s
//
// fast=2: nums[2]=2 != val, nums[1]=2, slow++
//         [2, 2, 2, 3]    slow=2, fast=3
//                  f
//               s
//
// fast=3: nums[3]=3 == val, 跳过
//         [2, 2, 2, 3]    slow=2
//
// 返回 slow=2，前2个元素 [2, 2] 就是答案
```

## 解法详解

### 解法1: 暴力移位 — O(n²) / O(1)

**思考过程**：最直觉的想法——遍历数组，遇到等于 `val` 的元素，就把后面所有元素往前移一位，数组长度减一。相当于模拟"真正的删除"。

```cpp
class Solution {
public:
    int removeElement(vector<int>& nums, int val) {
        int n = nums.size();
        for (int i = 0; i < n; ) {
            if (nums[i] == val) {
                // 后面所有元素前移一位 — 这就是 O(n) 的瓶颈
                for (int j = i; j < n - 1; j++) {
                    nums[j] = nums[j + 1];
                }
                n--;  // 有效长度减一
                // 注意：i 不动，因为新的 nums[i] 还没检查
            } else {
                i++;
            }
        }
        return n;
    }
};
```

**关键点**：删除后 `i` 不能自增，因为后面的元素移上来了，当前位置是新元素，还需要检查。

---

### 解法2: 快慢双指针（同向） — O(n) / O(1) ⭐ 面试首选

**从解法1优化**：解法1的瓶颈是每次删除都要移动后面所有元素。但我们其实不需要"删除"——只需要把非 `val` 的元素收集到前面即可。

用两个指针：
- `fast`：遍历每个元素（"探路者"）
- `slow`：指向下一个要放置非 `val` 元素的位置（"收集者"）

```cpp
class Solution {
public:
    int removeElement(vector<int>& nums, int val) {
        int slow = 0;
        for (int fast = 0; fast < nums.size(); fast++) {
            if (nums[fast] != val) {
                // 非 val 元素放到 slow 位置，slow 前进
                nums[slow] = nums[fast];
                slow++;
            }
            // 等于 val 的元素直接跳过，不做任何操作
        }
        // slow 就是非 val 元素的个数
        return slow;
    }
};
```

**不变量**：循环过程中 `nums[0..slow-1]` 始终是已经确认的非 `val` 元素。

---

### 解法3: 首尾双指针（相向） — O(n) / O(1)

**从解法2优化**：解法2中，如果数组是 `[1,2,3,4,5]`、`val=6`（没有要删的），fast 和 slow 走得一模一样，每个元素都"自己赋值给自己"，做了 n 次无意义的赋值。

**优化思路**：题目说顺序可以改变！那么遇到等于 `val` 的元素，直接用数组**最后一个元素**覆盖它，然后缩短数组长度。这样赋值次数 = 等于 `val` 的元素个数。

```cpp
class Solution {
public:
    int removeElement(vector<int>& nums, int val) {
        int left = 0, right = nums.size();
        while (left < right) {
            if (nums[left] == val) {
                // 用最后一个元素覆盖当前元素，缩短有效长度
                nums[left] = nums[right - 1];
                right--;
                // left 不动，因为换过来的元素还没检查
            } else {
                left++;
            }
        }
        return left;
    }
};
```

**关键点**：`right` 用的是开区间（初始为 `nums.size()` 而非 `nums.size()-1`），这样空数组不需要特判。

## 解法对比

| | 暴力移位 | 快慢双指针 | 首尾双指针 |
|---|---|---|---|
| 时间 | O(n²) | O(n) | O(n) |
| 赋值次数 | 最多 O(n²) | 恰好 n-k 次（k=val个数） | 恰好 k 次 |
| 保持相对顺序 | ✅ 是 | ✅ 是 | ❌ 否 |
| 适用场景 | 理解题意 | **通用首选** | val 出现少时更优 |

**面试选择**：默认写快慢双指针（解法2），如果面试官追问"能否减少赋值次数"或"顺序无关怎么优化"，给出首尾双指针（解法3）。

## 易错点

1. **暴力解中删除后 i 不能自增**
   - ✗ `for(int i=0; i<n; i++) { if(nums[i]==val) { 移位; n--; } }` → 会跳过紧接着的下一个元素
   - ✓ 只在 `nums[i] != val` 时才 `i++`

2. **首尾双指针的 right 初始值**
   - ✗ `right = nums.size() - 1` → 空数组时 `right = -1`（无符号溢出！）
   - ✓ `right = nums.size()`，用开区间，空数组时 `left=0, right=0`，直接不进循环

3. **首尾双指针中覆盖后不要移动 left**
   - ✗ `nums[left] = nums[right-1]; right--; left++;` → 换过来的元素可能也是 `val`，被跳过了
   - ✓ 覆盖后 `left` 不动，下一轮循环会重新检查这个位置

## 面试追问

**Q1: 暴力解的时间复杂度是多少？瓶颈在哪？**
> O(n²)。瓶颈是每次"删除"一个元素时，后面所有元素都要前移 O(n)。如果有 k 个 val，最坏移动 k×n 次。

**Q2: 快慢双指针为什么是 O(n)？赋值了多少次？**
> fast 遍历一轮 O(n)。赋值次数 = 非 val 元素的个数（每个非 val 元素恰好被赋值一次到 slow 位置）。

**Q3: 如果 val 出现非常少（比如 10⁶ 个元素中只有 1 个是 val），有没有更优的做法？**
> 用首尾双指针。快慢指针会做约 10⁶ 次赋值（几乎每个元素自己赋给自己），首尾双指针只做 1 次赋值（用末尾元素覆盖那个 val）。代价是不保持相对顺序。

**Q4: 如果要求保持相对顺序呢？**
> 只能用快慢双指针（解法2），首尾双指针会打乱顺序。
