# 503. 下一个更大元素 II

## 核心思路

本质上就是经典的「下一个更大元素」问题（LeetCode 496），但数组变成了**循环数组**。核心难点是：如何处理"绕一圈回来"的情况？答案是**将数组逻辑上拼接一份**，遍历 `2n` 次，用 `i % n` 映射回原数组索引。

## 思维链

1. **读完题第一反应**：对每个元素，往后扫描找到第一个比它大的。如果到末尾没找到，就绕回开头继续找。→ 暴力法：对每个元素最多扫 n-1 个位置，O(n²)。
2. **暴力解的瓶颈**：每个元素都要独立地线性扫描后续元素，大量重复比较。比如 `[5,4,3,2,1,6]`，前5个元素各自都要一路扫到6，做了很多重复工作。
3. **怎么突破？回忆 "下一个更大元素" 的经典手法**：单调栈。当我们遇到一个大数时，它能一次性"解决"栈里所有比它小的元素。栈里维护的是"还没找到答案的元素"。
4. **循环怎么办？**：不需要真的拼接数组，只需要遍历索引从 0 到 `2n-1`，用 `i % n` 得到实际元素。第二圈遍历时，栈里剩余的"还没找到答案"的元素就有机会在绕回来时找到答案了。
5. **栈里存什么？**：存**索引**而非值，因为我们需要通过索引写回结果数组。比较时用 `nums[stk.top()]` 取值。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力模拟 | 每个元素向后扫一圈 | O(n²) | O(1) | 能说出即可 |
| 单调栈 + 循环展开 | 遍历2n，单调递减栈 | O(n) | O(n) | ⭐ 必须写出 |

## 关键提示

1. **循环数组的经典处理方式**：不需要真正复制数组，遍历 `2n` 次并用取模运算 `i % n` 即可"模拟"循环。
2. **单调栈的方向**：从左到右遍历，维护一个**单调递减栈**（栈底到栈顶递减），当遇到比栈顶大的元素时，栈顶元素的"下一个更大元素"就找到了。
3. **第二圈遍历只出栈不入栈**：可以选择第二圈也入栈（不影响正确性），但为了避免重复写入结果，常见做法是第二圈也正常入栈，因为结果数组只在出栈时写入，每个索引只会被出栈一次。
4. **结果数组初始化为 -1**：这样如果某元素遍历完2圈都没被弹出（说明它是最大值），自然保持 -1。

```
单调栈过程 (nums = [1, 2, 1]):

遍历 2n = 6 次, 索引 i: 0,1,2,3,4,5
实际索引 i%3:             0,1,2,0,1,2

i=0, val=1: 栈空，入栈          栈: [0]
i=1, val=2: 2>nums[0]=1 → 弹0   res[0]=2    栈: [1]
i=2, val=1: 1<nums[1]=2 → 入栈  栈: [1, 2]
i=3, val=1: 1<nums[2]=1 → 不弹  栈: [1, 2]  (第二圈可入栈也可不入)
i=4, val=2: 2>nums[2]=1 → 弹2   res[2]=2    栈: [1]
             2=nums[1]=2 → 不弹
i=5, val=1: 不弹

结果: res = [2, -1, 2] ✓
```

## 解法详解

### 解法1: 暴力模拟 — O(n²) / O(1)

**思考过程**：最直觉的做法——对每个元素，从它的下一个位置开始，最多看 n-1 个元素（绕一圈），找到第一个比它大的就记录，找不到就是 -1。

```cpp
class Solution {
public:
    vector<int> nextGreaterElements(vector<int>& nums) {
        int n = nums.size();
        vector<int> res(n, -1);
        for (int i = 0; i < n; i++) {
            for (int j = 1; j < n; j++) {  // 最多往后看 n-1 个
                int idx = (i + j) % n;     // 循环索引
                if (nums[idx] > nums[i]) {
                    res[i] = nums[idx];
                    break;
                }
            }
        }
        return res;
    }
};
```

**关键点**：
- 内层循环 `j` 从 1 开始（跳过自身），最多到 `n-1`。
- `(i + j) % n` 实现循环。
- 时间 O(n²)，对于 n=10⁴ 可以通过但不优雅。

### 解法2: 单调栈 + 循环展开 — O(n) / O(n) ⭐ 面试首选

**从解法1优化**：暴力法中，每个元素独立扫描后续元素，做了大量重复比较。单调栈的核心思想是：**批量处理**——当一个大数出现时，它能一次性回答栈里所有比它小的元素的问题。

**为什么是单调递减栈？**
- 栈维护"还没找到下一个更大元素"的索引。
- 如果栈顶 a < 当前值 b，说明 b 就是 a 的答案，弹出 a。
- 如果栈顶 a >= b，b 还需要继续等待，入栈。
- 所以栈从底到顶是递减的（大的在下面还在等，小的在上面会先被弹出）。

**为什么遍历 2n 次？**
- 第一圈（i: 0 ~ n-1）：正常建栈 + 弹栈。
- 第二圈（i: n ~ 2n-1）：让第一圈末尾那些"还没找到答案"的元素有机会看到前面的更大值。

```cpp
class Solution {
public:
    vector<int> nextGreaterElements(vector<int>& nums) {
        int n = nums.size();
        vector<int> res(n, -1);  // 初始化 -1：找不到更大元素的默认值
        stack<int> stk;          // 存索引，不存值
        
        // 遍历 2n 次模拟循环数组
        for (int i = 0; i < 2 * n; i++) {
            int cur = nums[i % n];
            // 当前值比栈顶大 → 栈顶的"下一个更大元素"就是当前值
            while (!stk.empty() && nums[stk.top()] < cur) {
                res[stk.top()] = cur;  // 记录答案
                stk.pop();
            }
            // 只在第一圈入栈（避免同一索引重复入栈）
            if (i < n) {
                stk.push(i);
            }
        }
        return res;
    }
};
```

**也可以两圈都入栈**（写法更简洁，但栈可能稍大一点）：

```cpp
class Solution {
public:
    vector<int> nextGreaterElements(vector<int>& nums) {
        int n = nums.size();
        vector<int> res(n, -1);
        stack<int> stk;
        
        for (int i = 0; i < 2 * n; i++) {
            while (!stk.empty() && nums[stk.top()] < nums[i % n]) {
                res[stk.top()] = nums[i % n];
                stk.pop();
            }
            stk.push(i % n);  // 两圈都入栈，更简洁
        }
        return res;
    }
};
```

**关键点**：
- 结果数组初始化为 -1，这样栈中最终没被弹出的元素（全局最大值）自动是 -1。
- 栈存索引不存值：因为 `res[index] = value` 需要知道索引。
- `i % n` 是循环数组的万能公式。

## 解法对比

| | 暴力模拟 | 单调栈 |
|------|------|------|
| 时间 | O(n²) | O(n)（每个元素最多入栈出栈各一次） |
| 空间 | O(1)（不算结果） | O(n)（栈空间） |
| 思路难度 | 简单直觉 | 需要理解单调栈 |
| 面试 | 作为起点 | 面试官期望解法 |

**什么时候选哪个？** 面试中先说暴力思路展示理解，然后分析瓶颈引出单调栈。

## 易错点

1. **栈中存值而不是存索引**
   - ✗ `stk.push(nums[i])` → 无法知道该更新 `res` 的哪个位置
   - ✓ `stk.push(i)` → 通过 `nums[stk.top()]` 取值，通过 `res[stk.top()]` 写结果

2. **比较时用 `<=` 而不是 `<`**
   - ✗ `nums[stk.top()] <= cur` → 相等时也弹出，但相等不算"更大"，会导致某些元素提前被弹出且答案错误
   - ✓ `nums[stk.top()] < cur` → 严格大于才弹出

3. **忘记遍历 2n 次**
   - ✗ `for (int i = 0; i < n; i++)` → 无法处理循环，末尾元素的答案可能在数组前面
   - ✓ `for (int i = 0; i < 2 * n; i++)` → 模拟完整循环

4. **结果数组没初始化为 -1**
   - ✗ `vector<int> res(n, 0)` → 全局最大值应该返回 -1 而不是 0
   - ✓ `vector<int> res(n, -1)`

## 面试追问

**Q1: 如果不是循环数组呢？（就是普通数组求下一个更大元素）**
→ 只遍历一次 `n` 就够了，不需要 `2n`，其余逻辑完全相同。这就是 LeetCode 496 的核心。

**Q2: 为什么单调栈是 O(n)？看起来有 while 循环在 for 里面，不是 O(n²) 吗？**
→ 均摊分析：每个索引最多入栈一次、出栈一次。2n 次遍历中，入栈操作最多 2n 次，出栈操作也最多 2n 次。总操作 O(n)。

**Q3: 如果要求"下一个更小元素"怎么改？**
→ 把 `nums[stk.top()] < cur` 改成 `nums[stk.top()] > cur`，即维护单调递增栈。栈顶遇到更小的值就弹出记录。

**Q4: 如果数组长度是 10⁸，O(n) 空间的栈也太大了，能不能 O(1) 额外空间？**
→ 对于循环数组，O(n) 额外空间（栈+结果数组）基本是下界，结果数组本身就需要 O(n)。栈最坏 O(n) 但平均远小于 n。
