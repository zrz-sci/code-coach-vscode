# 1094. 拼车

## 核心思路

本质上就是一个**区间叠加问题**：每段行程在 `[from, to)` 区间内增加若干乘客，问在任意时刻车上的乘客总数是否超过 `capacity`。

## 思维链

1. **读完题第一反应**：车沿一个方向行驶，每次在 `from` 上客、`to` 下客。我需要知道**每个位置上车里有多少人**，只要任一位置超过 capacity 就返回 false。

2. **最朴素的做法**：对每一段行程 `[from, to)`，把这个区间内每个位置的乘客数都加上 `numPassengers`，最后扫描所有位置看有没有超标。这相当于直接模拟，对每段行程做区间内逐点累加。

3. **暴力的瓶颈**：每段行程要遍历 `to - from` 个位置去累加，如果行程很长就很慢。本质上是"区间批量加"操作太慢。

4. **突破瓶颈 — 差分数组**：差分数组可以把**区间加操作从 O(L) 降到 O(1)**！在 `from` 处 `+num`，在 `to` 处 `-num`，最后做一次前缀和就能还原每个位置的乘客数。

5. **还有别的方法吗？— 事件排序法**：把每段行程拆成两个事件（上车、下车），按位置排序后扫描，维护当前车上人数。这和差分的本质是一样的，只是实现方式不同。

6. **位置范围很小 (≤1000)**：可以直接开长度 1001 的数组，不需要哈希表或离散化。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力模拟 | 对每段行程逐位置累加 | O(n·L) | O(L) | 能说出即可 |
| 差分数组 | from处+num, to处-num, 前缀和还原 | O(n + L) | O(L) | ⭐ 必须写出 |
| 事件排序(扫描线) | 拆上下车事件, 排序后扫描 | O(n log n) | O(n) | 加分项 |

> 其中 n = trips.length, L = 位置上界(≤1000)

## 关键提示

1. **乘客在 `to` 位置下车**：也就是说 `to` 这个位置乘客已经不在车上了，区间是 `[from, to)` 左闭右开。
2. **位置范围只有 0~1000**：暗示你可以开一个固定大小的数组，不需要复杂的数据结构。
3. **差分数组的核心**：对区间 `[a, b)` 加 val，等价于 `diff[a] += val; diff[b] -= val`。做前缀和后就能得到每个位置的实际值。
4. **事件排序法与差分是同一思想的两种表达**：差分利用位置范围小直接开数组；事件排序更通用，位置范围大时也能用。

```
位置:    0    1    2    3    4    5    6    7
行程1:        +2   +2   +2   +2              (2人, 1→5)
行程2:                  +3   +3   +3   +3    (3人, 3→7)
总人数:  0    2    2    5    5    3    3    0

差分:    0   +2    0   +3    0   -2    0   -3
前缀和:  0    2    2    5    5    3    3    0  ← 一样的结果！
```

## 解法详解

### 解法1: 暴力模拟 — O(n·L) / O(L)

**思考过程**: 最直觉的想法——开一个数组代表每个位置上车里有多少人，对每段行程把区间内的每个位置都加上乘客数，最后检查有没有超标。

```cpp
class Solution {
public:
    bool carPooling(vector<vector<int>>& trips, int capacity) {
        vector<int> passengers(1001, 0);
        
        for (auto& trip : trips) {
            int num = trip[0], from = trip[1], to = trip[2];
            // 在 [from, to) 的每个位置都加上乘客数
            for (int i = from; i < to; i++) {
                passengers[i] += num;
                if (passengers[i] > capacity) return false;
            }
        }
        return true;
    }
};
```

**关键点**: 注意是 `i < to` 不是 `i <= to`，因为乘客在 `to` 处已经下车了。

---

### 解法2: 差分数组 — O(n + L) / O(L) ⭐ 面试首选

**从解法1优化**: 解法1的瓶颈是对每段行程要遍历整个区间逐点累加。差分数组把这个"区间加"操作压缩为**两次端点操作 O(1)**，最后一次前缀和还原。

**为什么差分能 work**: 差分数组 `diff[i]` 记录的是位置 i 相对于位置 i-1 的变化量。在 `from` 处 +num 表示"从这里开始多了 num 人"，在 `to` 处 -num 表示"到这里这些人下车了"。对差分做前缀和就还原了每个位置的实际乘客数。

```cpp
class Solution {
public:
    bool carPooling(vector<vector<int>>& trips, int capacity) {
        // diff[i] 表示位置 i 相对于 i-1 的乘客变化量
        vector<int> diff(1001, 0);
        
        for (auto& trip : trips) {
            int num = trip[0], from = trip[1], to = trip[2];
            diff[from] += num;  // from 处上车
            diff[to] -= num;    // to 处下车（左闭右开）
        }
        
        // 前缀和还原每个位置的实际乘客数
        int current = 0;
        for (int i = 0; i <= 1000; i++) {
            current += diff[i];
            if (current > capacity) return false;
        }
        return true;
    }
};
```

**关键点**: `diff[to] -= num` 而不是 `diff[to+1]`，因为乘客在 `to` 处已下车，区间是 `[from, to)` 左闭右开。

---

### 解法3: 事件排序（扫描线）— O(n log n) / O(n)

**不同角度**: 把每段行程拆成两个"事件"——上车事件和下车事件。按位置排序，同一位置先处理下车再处理上车（这样能腾出座位）。扫描所有事件，维护当前车上人数。

**什么时候用这个方法**: 当位置范围非常大（比如到 10^9）时，差分数组开不了那么大，但事件排序只需要 O(n) 空间。

```cpp
class Solution {
public:
    bool carPooling(vector<vector<int>>& trips, int capacity) {
        // 用 map 自动按位置排序，同一位置的变化量直接累加
        // 这等价于事件排序，但更简洁
        map<int, int> events;
        
        for (auto& trip : trips) {
            int num = trip[0], from = trip[1], to = trip[2];
            events[from] += num;   // 上车
            events[to] -= num;     // 下车
        }
        
        int current = 0;
        for (auto& [pos, change] : events) {
            current += change;
            if (current > capacity) return false;
        }
        return true;
    }
};
```

**关键点**: 用 `map` 而不是 `unordered_map`，因为我们需要按位置从小到大遍历。`map` 天然有序。

---

## 解法对比

| | 暴力模拟 | 差分数组 | 事件排序 |
|---|---|---|---|
| 时间 | O(n·L) | O(n + L) | O(n log n) |
| 空间 | O(L) | O(L) | O(n) |
| 位置范围大时 | 空间爆炸 | 空间爆炸 | ✅ 只存事件 |
| 位置范围小时 | 最慢 | ✅ 最快最简洁 | 排序有额外开销 |
| 核心操作 | 区间逐点加 | 两端点 O(1) 操作 | 排序 + 扫描 |

**面试推荐**: 本题位置范围 ≤1000，差分数组是最优选择。如果面试官追问"位置范围到 10^9 怎么办"，切换到事件排序。

## 易错点

1. **左闭右开搞错**：
   - ✗ `diff[to+1] -= num`（多算了一个位置，`to` 处乘客还在车上）
   - ✓ `diff[to] -= num`（乘客在 `to` 处下车，`to` 位置不占座）

2. **差分数组大小不够**：
   - ✗ `vector<int> diff(1000, 0)`（`to` 最大为 1000，需要 `diff[1000]`）
   - ✓ `vector<int> diff(1001, 0)`

3. **暴力解中提前返回的逻辑**：
   - 暴力解中可以边加边判断提前返回 false，但差分数组**不能在构建差分时判断**，必须做完前缀和后才能判断（差分值本身没有意义，前缀和才是实际乘客数）。

4. **事件排序中同一位置的处理顺序**：
   - 用 `map` 直接累加变化量就不需要担心顺序问题，因为同一位置的上下车变化量已经合并了。
   - 如果用 `vector<pair>` 手动排序，需要确保同一位置先下车后上车（即变化量小的排前面）。

## 面试追问

**Q1: 暴力解的复杂度是多少？瓶颈在哪？**
> 时间 O(n·L)，瓶颈在"区间加"操作需要逐点遍历。差分数组把区间加压缩为 O(1)。

**Q2: 如果位置范围不是 1000 而是 10^9，怎么办？**
> 差分数组开不了那么大。改用事件排序法：把上下车拆成事件存到 map 或 vector 中，排序后扫描，空间 O(n)，时间 O(n log n)。

**Q3: 如果要支持动态添加行程并实时查询是否超载（在线场景），怎么设计？**
> 可以用**线段树**支持区间加和区间最大值查询。每次添加行程是 O(log L) 的区间加操作，查询全局最大值是 O(log L)。如果位置范围大，需要动态开点线段树或离散化。
