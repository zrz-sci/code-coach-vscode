# 407. 接雨水 II

## 核心思路

这道题是经典"接雨水"（LeetCode 42）从一维到二维的推广。本质问题：对于矩阵中的每个格子，它能存住多少水取决于它四周"围墙"的最短板——即**木桶效应在二维上的体现**。水从最矮的围墙溢出，所以我们应该从最矮的边界开始，由外向内"灌水"。

## 思维链

1. **读完题第一反应**：这是 42 题"接雨水"的 2D 版本。1D 版本中，每个柱子能接的水 = `min(左边最高, 右边最高) - 自身高度`。能不能推广到 2D？

2. **2D 暴力想法**：对矩阵中每个格子，找它到矩阵边界的所有路径，取每条路径上最高点的最小值（即"最容易溢出"的方向），再减去自身高度。这相当于对每个格子做一次 BFS/DFS 搜索所有出路，时间复杂度爆炸 — O(m²n² × mn)。

3. **瓶颈分析**：暴力的问题是"从每个格子向外找边界"太重复了。能不能反过来？**从边界向内推**——水一定从边界溢出，所以边界就是天然的"围墙"。

4. **木桶效应的关键洞察**：水面高度取决于围墙的最短板。我们应该**每次处理围墙中最矮的那个格子**——因为水只会从最矮处溢出。处理完后，它的邻居可能被"淹没"，此时邻居的水位就确定了，邻居加入围墙。

5. **数据结构选择**：我们需要反复取"围墙中最矮的格子"→ **最小堆（优先队列）**！把边界全部入堆，然后每次弹出最矮的，向内扩展，计算蓄水量，更新围墙。

6. **算法流程**：初始化边界入堆 → 弹出堆顶（最矮围墙）→ 检查四邻 → 如果邻居更矮，差值就是蓄水量 → 邻居以 `max(自身高度, 当前水位)` 入堆作为新围墙 → 重复直到堆空。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力 BFS | 对每个格子 BFS 找最低溢出路径 | O(m²n² · mn) | O(mn) | 能说出即可 |
| 最小堆 BFS（由外向内） | 边界入堆，每次弹最矮围墙向内灌水 | O(mn log(mn)) | O(mn) | ⭐ 必须写出 |

## 关键提示

1. **从 1D 到 2D 的类比**：1D 中，每个位置的水位取决于 `min(leftMax, rightMax)`。2D 中，每个格子的水位取决于"围住它的一圈围墙中最矮的那个"。

2. **为什么从边界开始？** 边界格子不可能存水（水会流出去），它们天然就是围墙。

3. **为什么用最小堆？** 水从最矮处溢出 — 木桶效应。我们必须先处理最矮的围墙，因为它决定了内部能存多少水。

4. **每个格子只处理一次**：一旦被弹出堆（即被"灌水处理过"），就不再重新计算。用 visited 数组标记。

5. **灌水示意图（示例2）**：

## 解法详解

### 解法1: 暴力思路（概念理解，不写代码）— O(m²n²·mn) / O(mn)

**思考过程**：对每个内部格子 (i,j)，我们想知道水最多能到多高。水会沿着任意路径流向边界，所以水位取决于"到边界所有路径上，最高点的最小值"。这等价于：从 (i,j) 出发，找到达边界的路径中，路径最高点最小的那条路径，其最高点就是水面。

这相当于对每个格子跑一次变形的最短路/BFS，复杂度太高，不实用。但**理解这个思路很重要**——它解释了为什么"水位取决于围墙最短板"。

### 解法2: 最小堆 BFS（由外向内灌水）— O(mn log(mn)) / O(mn) ⭐ 面试首选

**从暴力的瓶颈出发**：暴力是"从内向外"找每个格子的水位，重复计算严重。反转思路——**从外向内**：边界是天然的围墙，从最矮的围墙开始向内"灌水"。

**核心算法**：
1. 把矩阵四条边上所有格子放入最小堆（按高度排序），标记 visited
2. 弹出堆顶（高度最小的围墙格子），检查它的四个邻居
3. 对于每个未访问的邻居：
   - 如果邻居比当前水位矮，差值就是蓄水量
   - 邻居以 `max(邻居自身高度, 当前水位)` 入堆（成为新围墙）
   - 标记邻居为 visited
4. 重复直到堆空

**为什么这是对的？** 因为我们总是从最矮的围墙向内处理，保证了每个格子被处理时，它的"有效围墙高度"已经确定了——不会有更矮的路径让水溢出。

```
// 算法执行过程示意（示例1的局部）:
//
// 原始矩阵:
//   1 4 3 1 3 2
//   3 2 1 3 2 4
//   2 3 3 2 3 1
//
// Step1: 边界入堆(按高度排序)
//   堆: [(1,(0,0)), (1,(0,3)), (1,(2,5)), (2,(0,5)), (2,(2,0)), ...]
//   visited: 所有边界格子
//
// Step2: 弹出 (1,(0,0)), 检查邻居:
//   (1,0)=3 已是边界visited → 跳过
//   (0,1)=4 已是边界visited → 跳过
//
// Step3: 弹出 (1,(0,3)), 检查邻居:
//   (1,3)=3 未访问, max(3,1)=3 入堆, 蓄水0
//   ...
//
// Step4: 弹出 (1,(2,5)), 检查邻居:
//   (1,5)=4 已visited → 跳过
//   (1,4) 未访问 → 处理...
//
// ... 当处理到 (1,2)=1 时:
//   它被围墙高度>=2包围, 蓄水 2-1=1
//   以高度 max(1,2)=2 入堆作为新围墙
```

```cpp
class Solution {
public:
    int trapRainWater(vector<vector<int>>& heightMap) {
        int m = heightMap.size(), n = heightMap[0].size();
        if (m <= 2 || n <= 2) return 0;  // 至少3x3才可能存水
        
        // 最小堆: (高度, 行, 列)
        priority_queue<tuple<int,int,int>, 
                       vector<tuple<int,int,int>>, 
                       greater<tuple<int,int,int>>> pq;
        
        vector<vector<bool>> visited(m, vector<bool>(n, false));
        
        // Step1: 边界入堆
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (i == 0 || i == m-1 || j == 0 || j == n-1) {
                    pq.push({heightMap[i][j], i, j});
                    visited[i][j] = true;
                }
            }
        }
        
        int water = 0;
        int dirs[4][2] = {{0,1},{0,-1},{1,0},{-1,0}};
        
        // Step2: 每次弹出最矮围墙，向内灌水
        while (!pq.empty()) {
            auto [h, x, y] = pq.top();
            pq.pop();
            
            for (auto& d : dirs) {
                int nx = x + d[0], ny = y + d[1];
                if (nx < 0 || nx >= m || ny < 0 || ny >= n || visited[nx][ny])
                    continue;
                
                visited[nx][ny] = true;
                
                // 如果邻居比当前水位矮，能蓄水
                if (heightMap[nx][ny] < h) {
                    water += h - heightMap[nx][ny];
                }
                
                // 邻居成为新围墙，高度取 max(自身, 当前水位)
                // 因为如果邻居更矮，水已经把它填到了 h 的高度
                pq.push({max(h, heightMap[nx][ny]), nx, ny});
            }
        }
        
        return water;
    }
};
```

**关键点**：
- `pq.push({max(h, heightMap[nx][ny]), nx, ny})` 这行是精髓：邻居入堆的高度不是它自身高度，而是 `max(自身高度, 当前水位)`，因为如果它被水淹了，它对更内部格子而言的"围墙高度"就是水面高度。
- 每个格子只入堆一次、出堆一次，所以时间复杂度 O(mn log(mn))。

## 解法对比

|  | 暴力 | 最小堆 BFS |
|--|------|-----------|
| 方向 | 从内向外（每个点找出路） | 从外向内（围墙向内灌水） |
| 时间 | O(m²n² · mn) | O(mn log(mn)) |
| 核心思想 | 逐点计算 | 木桶效应 + 贪心 |
| 实用性 | 不可行 | ⭐ 面试标准解法 |

## 易错点

1. **忘记 `m <= 2 || n <= 2` 的边界**：
   - ✗ 直接处理，可能边界循环逻辑出错
   - ✓ 矩阵至少 3×3 才可能蓄水，否则直接返回 0

2. **邻居入堆时用自身高度而非 max**：
   - ✗ `pq.push({heightMap[nx][ny], nx, ny})`
   - ✓ `pq.push({max(h, heightMap[nx][ny]), nx, ny})`
   - 为什么：如果邻居被水淹了（自身高度<h），它作为围墙的有效高度是水面高度 h，不是自身高度

3. **边界入堆时忘记标记 visited**：
   - ✗ 只在弹出时标记
   - ✓ 入堆时立刻标记，否则同一个边界格子可能被重复加入堆

4. **蓄水量计算不用 max(0, ...)**：
   - 看起来需要 `max(0, h - heightMap[nx][ny])`，但其实因为我们用了最小堆（总是先处理矮的），当 `heightMap[nx][ny] >= h` 时差值自然 ≤ 0，此时可以用 if 判断代替 max，两种写法都对

## 面试追问

**Q1: 这道题和 LeetCode 42（一维接雨水）有什么联系？**
A: 1D 版本中每个位置的水位 = min(leftMax, rightMax)，本质是左右两堵"墙"的较矮者。2D 版本推广为"围住这个格子的整圈围墙中最矮的那个"决定水位。1D 可以用双指针（从两端向内夹逼），2D 因为边界是一圈而非两个端点，所以用最小堆来模拟"从最矮处向内灌"。

**Q2: 为什么最小堆保证正确性？能不能用最大堆？**
A: 木桶效应——水从最矮的围墙溢出。最小堆保证我们先处理最矮的围墙，这样当一个内部格子被处理时，决定它水位的"最短板"一定已经被处理过了。如果用最大堆（先处理最高的），我们无法确定内部格子的水位，因为可能还有更矮的出口没处理。

**Q3: 如果矩阵非常大（如 1000×1000），有没有更快的方法？**
A: 最小堆 BFS 的 O(mn log(mn)) 对 1000×1000 来说约 10^6 × 20 ≈ 2×10^7，完全可行。理论上可以用类似 1D 的"逐行/逐列扫描"方法做到 O(mn)（不需要堆），但实现极其复杂，面试中不会要求。提及即可展示深度理解。

**Q4: 能否用并查集/Union-Find 解决这道题？**
A: 可以。思路：把所有格子按高度从小到大排序，依次"填入"。每填入一个格子时，它和已填入的邻居合并。如果某个连通分量接触到边界，水会流出；否则这个分量能蓄水到当前高度。时间 O(mn · α(mn)) ≈ O(mn)，但实现较复杂。
