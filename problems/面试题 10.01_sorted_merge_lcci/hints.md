# 面试题 10.01. 合并排序的数组

## 核心思路

给定两个有序数组 A 和 B，A 的末尾有足够的缓冲空间容纳 B，要求将 B 合并到 A 中并保持有序。核心技巧是**从后往前填充**（逆向双指针），这样可以直接利用 A 末尾的空位，避免覆盖 A 中未处理的有效元素。

## 思维链

1. **读完题第一反应**：两个有序数组合并 — 经典的归并排序的 merge 步骤。最简单的想法是开一个新数组，用双指针从前往后合并，然后拷贝回 A。但这需要 O(m+n) 额外空间。

2. **能不能原地合并？** 如果从前往后填充 A，A[0] 位置放入的新值会覆盖 A 本身的有效数据。比如 A=[1,2,3,0,0,0], B=[0,0,6]，如果从前往后放，A[0] 被覆盖成 0，原来的 1 就丢了。

3. **关键洞察**：A 的末尾有空位（那些 0 是占位符）！如果我们**从后往前**填充，先把最大的元素放到 A 的最后面，就不会覆盖任何还需要处理的有效元素。因为 A[m..m+n-1] 全是空位。

4. **三指针的设计**：
   - `i = m - 1`：指向 A 有效部分的末尾
   - `j = n - 1`：指向 B 的末尾
   - `k = m + n - 1`：指向 A 总空间的末尾（填充位置）
   每次比较 A[i] 和 B[j]，把较大的放到 A[k]，然后移动对应的指针。

5. **收尾处理**：当 A 或 B 其中一个先用完时：
   - 如果 B 先用完（j < 0）：A 中剩余的元素已经在正确位置，不需要移动
   - 如果 A 先用完（i < 0）：B 中剩余的元素需要填入 A 的前面

6. **面试最佳策略**：直接说"从后往前"的思路，解释为什么这样不会覆盖数据，然后写三指针代码。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 额外数组合并 | 新建数组，从前往后合并，拷贝回 A | O(m+n) | O(m+n) | 能说出即可 |
| 逆向双指针 | 从后往前填充，大的先放 | O(m+n) | O(1) | ⭐ 必须写出 |
| 直接排序 | 把 B 拷贝到 A 末尾，整体排序 | O((m+n)log(m+n)) | O(1) | 不推荐 |

## 关键提示

1. **为什么从后往前不会覆盖？** A 的有效元素在 A[0..m-1]，空位在 A[m..m+n-1]。从后往前填充时，k 从 m+n-1 开始，先写入空位区域。当 k 追上 i 时，A[i] 要么已经被处理过（已经移到更后面），要么 i 和 k 指向同一位置（不需要移动）。

2. **B 剩余必须处理，A 剩余不需要**：如果 A 先用完（i < 0），B 还有剩余元素，它们比 A 中所有元素都小，需要填入 A 的最前面。如果 B 先用完（j < 0），A 的剩余元素已经在正确位置上。

3. **和 LeetCode 88 完全相同**：面试题 10.01 就是 LeetCode 88 "Merge Sorted Array" 的翻版。

4. **指针比较用 >=**：注意不是 >，因为 A[0] 和 B[0] 也需要被处理。

5. **等号归谁**：当 A[i] == B[j] 时，放谁都行，结果都正确。但放 B[j] 更好（保持稳定性，即相等元素的相对顺序不变）。

## 解法详解

### 解法1: 额外数组合并 — O(m+n) / O(m+n)

**思考过程**：最直觉的做法 — 新建一个数组 temp，用两个指针从前往后归并，然后把结果拷贝回 A。

```
示例: A = [1,2,3,0,0,0], m=3, B = [2,5,6], n=3

temp = []
i=0,j=0: A[0]=1 < B[0]=2 → temp=[1], i=1
i=1,j=0: A[1]=2 == B[0]=2 → temp=[1,2], i=2 (或 j=1)
i=2,j=0: A[2]=3 > B[0]=2 → temp=[1,2,2], j=1
i=2,j=1: A[2]=3 < B[1]=5 → temp=[1,2,2,3], i=3
j=1,2: B剩余 → temp=[1,2,2,3,5,6]
拷贝回A
```

```cpp
class Solution {
public:
    void merge(vector<int>& A, int m, vector<int>& B, int n) {
        vector<int> temp(m + n);
        int i = 0, j = 0, k = 0;
        
        while (i < m && j < n) {
            if (A[i] <= B[j]) {
                temp[k++] = A[i++];
            } else {
                temp[k++] = B[j++];
            }
        }
        while (i < m) temp[k++] = A[i++];
        while (j < n) temp[k++] = B[j++];
        
        // 拷贝回 A
        for (int p = 0; p < m + n; p++) {
            A[p] = temp[p];
        }
    }
};
```

### 解法2: 逆向双指针（从后往前）— O(m+n) / O(1)

**思考过程**：解法1 需要额外空间，而 A 的末尾已经有空位了。如果从后往前填充，先放大的元素，就不会覆盖 A 中还没处理的有效元素。

**关键决策**：三指针 — `i` 指 A 有效末尾，`j` 指 B 末尾，`k` 指 A 总末尾。每次比较 A[i] 和 B[j]，较大的放到 A[k]。

```
示例: A = [1,2,3,0,0,0], m=3, B = [2,5,6], n=3

初始: i=2, j=2, k=5
step1: A[2]=3 < B[2]=6 → A[5]=6, j=1, k=4    → A=[1,2,3,0,0,6]
step2: A[2]=3 < B[1]=5 → A[4]=5, j=0, k=3    → A=[1,2,3,0,5,6]
step3: A[2]=3 > B[0]=2 → A[3]=3, i=1, k=2    → A=[1,2,3,3,5,6]
step4: A[1]=2 == B[0]=2 → A[2]=2, j=-1, k=1  → A=[1,2,2,3,5,6]
j<0, 循环结束。A中剩余[1,2]已在正确位置。

结果: A = [1,2,2,3,5,6] ✓
```

```cpp
class Solution {
public:
    void merge(vector<int>& A, int m, vector<int>& B, int n) {
        int i = m - 1;      // A 有效部分的末尾
        int j = n - 1;      // B 的末尾
        int k = m + n - 1;  // A 总空间的末尾（填充位置）
        
        // 从后往前，每次选较大的放入 A[k]
        while (i >= 0 && j >= 0) {
            if (A[i] > B[j]) {
                A[k--] = A[i--];
            } else {
                A[k--] = B[j--];  // 等于时放B，保持稳定性
            }
        }
        
        // B 中剩余元素填入 A（A 的剩余已在正确位置）
        while (j >= 0) {
            A[k--] = B[j--];
        }
        // 注意: 不需要处理 i >= 0 的情况！
        // 因为 A 剩余的元素本来就在 A 的前面，位置正确
    }
};
```

**自检**：
- m=0 (A为空)？i=-1, 跳过第一个循环，第二个循环把B全部拷入 ✓
- n=0 (B为空)？j=-1, 两个循环都跳过，A不变 ✓
- A=[1,2,3,0,0,0], B=[2,5,6]？上面手动模拟已验证 ✓

### 解法3: 直接拼接排序 — O((m+n)log(m+n)) / O(1)

**思考过程**：最"偷懒"的做法 — 把 B 的元素拷贝到 A 的空位处，然后对整个 A 排序。

```cpp
class Solution {
public:
    void merge(vector<int>& A, int m, vector<int>& B, int n) {
        for (int i = 0; i < n; i++) {
            A[m + i] = B[i];  // 把 B 拷贝到 A 的末尾
        }
        sort(A.begin(), A.end());  // 整体排序
    }
};
```

**为什么不推荐**：时间复杂度 O((m+n)log(m+n))，没有利用两个数组已有序的条件。面试中写这个等于没有解决核心问题。

## 解法对比

| 解法 | 时间 | 空间 | 是否利用有序 | 面试推荐 |
|------|------|------|------------|---------|
| 额外数组 | O(m+n) | O(m+n) | 是 | 说出思路 |
| 逆向双指针 | O(m+n) | O(1) | 是 | ⭐⭐⭐ |
| 直接排序 | O((m+n)log) | O(1) | 否 | ❌ |

**从解法1到解法2的演进逻辑**：
- 解法1 需要额外空间，因为正向合并会覆盖 A 的有效数据
- 关键洞察：A 末尾有空位 → 逆向填充就不会覆盖 → 解法2

## 易错点

1. **忘记处理 B 剩余**：
   ```cpp
   // ✗ 错误：只有一个 while 循环，B 剩余没处理
   while (i >= 0 && j >= 0) {
       // ... 合并逻辑
   }
   // B 中还有更小的元素没放入 A！
   
   // ✓ 正确：加上 B 的收尾
   while (j >= 0) A[k--] = B[j--];
   ```

2. **多处理了 A 的剩余**：
   ```cpp
   // ✗ 不必要：A 的剩余已经在正确位置
   while (i >= 0) A[k--] = A[i--];  // 浪费时间但不出错
   
   // ✓ 正确：只需处理 B 的剩余
   while (j >= 0) A[k--] = B[j--];
   ```

3. **指针初始值搞错**：
   ```cpp
   // ✗ 错误：k 应该是 m+n-1 不是 m+n
   int k = m + n;  // 越界！
   
   // ✓ 正确
   int k = m + n - 1;
   ```

4. **正向合并覆盖数据**：
   ```cpp
   // ✗ 严重错误：从前往后填 A 会覆盖有效元素
   int i = 0, j = 0, k = 0;
   while (...) A[k++] = ...;  // A[0] 被覆盖，原数据丢失
   
   // ✓ 正确：从后往前填
   int i = m-1, j = n-1, k = m+n-1;
   ```

## 面试追问

**Q1: 为什么从后往前不会覆盖数据？能证明吗？**
A1: 归纳证明 — 当 k 位置被写入时，A[k] 要么是空位（k >= m），要么 A[k] 已经被移到更后面（因为 i <= k 始终成立，且 A[i] 已被处理意味着 A[i] 被移到了 i 之后的某个位置）。更直觉的说法：写指针 k 的移动速度等于读指针 i 和 j 移动速度之和，所以 k 永远领先于 i。

**Q2: 如果两个数组都没有预留空间，怎么原地合并？**
A2: 不可能在 O(m+n) 时间内原地完成。可以用 O(m+n) 额外空间的经典归并，或者用就地归并（gap-based merge）做到 O((m+n)log(m+n)) 时间 O(1) 空间。

**Q3: 这题的思路能推广到 K 个有序数组合并吗？**
A3: K 路归并用最小堆（priority queue），每次从堆中取最小元素，放入结果数组。时间 O(N log K)，N 是总元素数。参考 LC 23 "Merge K Sorted Lists"。

**Q4: 如果 A 和 B 都是链表呢？**
A4: 链表合并更简单，因为不存在覆盖问题 — 只需要调整指针。参考 LC 21 "Merge Two Sorted Lists"。正向遍历即可，不需要逆向。

**Q5: 这个技巧在归并排序中怎么用？**
A5: 归并排序的 merge 步骤通常需要额外空间。但如果在 bottom-up 归并中预先分配好缓冲区，可以交替使用原数组和缓冲区来避免重复分配。本题的逆向技巧在归并排序中不直接适用，因为归并排序的两个子数组没有预留空间。
