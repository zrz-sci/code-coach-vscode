# 679. 24 点游戏

## 核心思路

本质上是一个**穷举搜索**问题：从 4 个数中任选 2 个，用 4 种运算符之一合并成 1 个新数，然后在剩下的数（变成 3 个）中继续选 2 个合并……直到只剩 1 个数，看它是否等于 24。这是一个规模极小的回溯问题（4 张牌最多只有几千种组合），不需要优化，暴力即可。

## 思维链

1. **读完题第一反应**：4 个数字，3 个运算符位置，还有括号决定运算顺序……排列组合好复杂。能不能暴力穷举？
2. **括号怎么处理？** 括号本质上决定了**哪两个数先运算**。与其枚举括号位置，不如换一种方式：每次从当前数字列表中**选 2 个数**，用某种运算合并成 1 个数，放回列表。这样括号的效果就自然涵盖了！
3. **搜索规模有多大？** 4 个数选 2 个：C(4,2)=6 种选法 × 4 种运算符（注意 a-b 和 b-a 不同，a/b 和 b/a 不同，所以实际是 6 对有序选法） → 第一步最多 6×2×4=48 种；第二步 3 个数选 2 个…… 总共不超过 **48 × 24 × 8 ≈ 9216** 种。完全可以暴力。
4. **具体怎么实现？** 用一个 `vector<double>` 存当前可用数字，递归地：选 2 个 → 4 种运算各试一遍 → 结果放回列表 → 递归到列表只剩 1 个数时判断是否为 24。
5. **浮点精度问题**：实数除法会引入精度误差，判断是否等于 24 要用 `fabs(x - 24.0) < 1e-6`。
6. **除零问题**：除法时除数可能为 0（某次运算结果为 0），需要跳过。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 回溯穷举 | 每次选2个数合并，递归到1个数 | O(1) 常数级 | O(1) | ⭐ 必须写出 |
| 枚举所有表达式树结构 | 枚举5种二叉树形态+排列+运算符 | O(1) 常数级 | O(1) | 能说出即可 |

> 注：由于输入固定为 4 个数，搜索空间是有限常数，所以时间空间都是 O(1)。

## 关键提示

1. **不要试图枚举括号**。括号的本质是决定运算顺序，而"每次从列表中选 2 个数合并"天然覆盖了所有可能的运算顺序（即所有可能的表达式树形态）。

2. **减法和除法不满足交换律**。选了数 a 和 b 后，要分别尝试 `a-b` 和 `b-a`、`a/b` 和 `b/a`。一种简洁写法：遍历所有**有序对** (i, j) 其中 i ≠ j。

3. **浮点比较**：最终判断不能用 `==`，要用 `fabs(result - 24.0) < 1e-6`。

4. **决策树可视化**（以 [4, 1, 8, 7] 为例的一条成功路径）：
   ```
   [4, 1, 8, 7]
       ↓ 选 8 和 4，做 8-4=4
   [1, 7, 4]
       ↓ 选 7 和 1，做 7-1=6
   [4, 6]
       ↓ 选 4 和 6，做 4*6=24
   [24] → ✓ 等于 24！
   ```

5. **除零保护**：当某次运算的第二个操作数为 0 时（通过浮点判断 `fabs(b) < 1e-6`），跳过除法。

## 解法详解

### 解法1: 回溯穷举（选2合1递归） — O(1) / O(1) ⭐ 面试首选

**思考过程**：

这道题的难点不在算法优化，而在于**如何不遗漏地枚举所有可能的表达式**。

关键洞察：任何一个由 4 个数和 3 个二元运算符组成的表达式，都可以用以下过程生成：
- 从 4 个数中选 2 个，用 1 个运算符合并 → 得到 3 个数
- 从 3 个数中选 2 个，用 1 个运算符合并 → 得到 2 个数
- 从 2 个数中选 2 个，用 1 个运算符合并 → 得到 1 个数

这个过程天然覆盖了所有可能的表达式树结构（包括不同的括号方案），因为**选择哪两个数先合并**就决定了运算的优先级。

```cpp
class Solution {
public:
    static constexpr double EPS = 1e-6;
    
    bool judgePoint24(vector<int>& cards) {
        vector<double> nums(cards.begin(), cards.end());
        return backtrack(nums);
    }
    
    bool backtrack(vector<double>& nums) {
        int n = nums.size();
        // 只剩1个数，判断是否为24
        if (n == 1) {
            return fabs(nums[0] - 24.0) < EPS;
        }
        
        // 从当前列表中选两个数 nums[i] 和 nums[j]
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                if (i == j) continue; // 必须选不同位置的两个数
                
                // 构建去掉 i, j 后的新列表
                vector<double> next;
                for (int k = 0; k < n; k++) {
                    if (k != i && k != j) {
                        next.push_back(nums[k]);
                    }
                }
                
                // 尝试4种运算，把结果放入新列表末尾
                double a = nums[i], b = nums[j];
                // 遍历有序对(i,j)已经处理了 a-b vs b-a，a/b vs b/a
                vector<double> results;
                results.push_back(a + b);
                results.push_back(a - b);
                results.push_back(a * b);
                if (fabs(b) > EPS) { // 除零保护
                    results.push_back(a / b);
                }
                
                for (double res : results) {
                    next.push_back(res);
                    if (backtrack(next)) return true;
                    next.pop_back(); // 回溯
                }
            }
        }
        return false;
    }
};
```

**关键点**：
- 遍历所有有序对 `(i, j)` 而非无序对，是为了覆盖 `a-b` 和 `b-a`、`a/b` 和 `b/a`。加法和乘法虽然有交换律会重复计算，但不影响正确性，且总量很小。
- `next` 列表先放入"除了 i, j 之外的所有数"，再把运算结果追加到末尾，这样递归下去就是"3个数的子问题"。

### 解法2: 枚举表达式树结构 — O(1) / O(1)

**思考过程**：

另一种思路是直接分析：4 个数 3 次运算，所有可能的**表达式树形态**有哪些？

```
形态1: ((a○b)○c)○d     — 左结合链式
形态2: (a○(b○c))○d     
形态3: (a○b)○(c○d)     — 两两配对
形态4: a○((b○c)○d)     
形态5: a○(b○(c○d))     — 右结合链式
```

对每种形态，枚举 4! = 24 种数字排列 × 4³ = 64 种运算符选择 = 1536 种。5 种形态共 7680 种。

这种方法更"暴力枚举式"，但实现较繁琐，面试中不如解法1简洁。解法1的"选2合1递归"天然覆盖了所有5种形态。

```cpp
class Solution {
public:
    static constexpr double EPS = 1e-6;
    
    // 对两个数执行运算，返回所有可能结果
    vector<double> compute(double a, double b) {
        vector<double> res = {a + b, a - b, a * b};
        if (fabs(b) > EPS) res.push_back(a / b);
        return res;
    }
    
    bool judgePoint24(vector<int>& cards) {
        vector<double> nums(cards.begin(), cards.end());
        // 枚举4个数的全排列
        sort(nums.begin(), nums.end());
        do {
            double a = nums[0], b = nums[1], c = nums[2], d = nums[3];
            // 枚举所有表达式树形态
            for (double ab : compute(a, b)) {
                for (double abc : compute(ab, c)) {
                    for (double abcd : compute(abc, d)) {
                        if (fabs(abcd - 24.0) < EPS) return true; // ((a○b)○c)○d
                    }
                }
                for (double cd : compute(c, d)) {
                    for (double abcd : compute(ab, cd)) {
                        if (fabs(abcd - 24.0) < EPS) return true; // (a○b)○(c○d)
                    }
                }
            }
            for (double bc : compute(b, c)) {
                for (double abc : compute(a, bc)) {
                    for (double abcd : compute(abc, d)) {
                        if (fabs(abcd - 24.0) < EPS) return true; // (a○(b○c))○d
                    }
                }
                for (double bcd : compute(bc, d)) {
                    for (double abcd : compute(a, bcd)) {
                        if (fabs(abcd - 24.0) < EPS) return true; // a○((b○c)○d)
                    }
                }
            }
            for (double cd : compute(c, d)) {
                for (double bcd : compute(b, cd)) {
                    for (double abcd : compute(a, bcd)) {
                        if (fabs(abcd - 24.0) < EPS) return true; // a○(b○(c○d))
                    }
                }
            }
        } while (next_permutation(nums.begin(), nums.end()));
        return false;
    }
};
```

**关键点**：需要确保覆盖了所有 5 种表达式树形态，漏掉任何一种都会 WA。

## 解法对比

| | 解法1: 选2合1回溯 | 解法2: 枚举表达式树 |
|---|---|---|
| **核心思想** | 每次选2个数合并，递归缩减问题规模 | 枚举所有树形态 + 排列 + 运算符 |
| **代码量** | 短，~30行 | 长，需要手写5种结构 |
| **正确性保证** | 天然覆盖所有结构，不怕遗漏 | 需要确保5种形态全列出 |
| **面试推荐** | ⭐ 首选 | 了解即可 |
| **可扩展性** | 易推广到N个数的情况 | N增大后形态数爆炸 |

## 易错点

1. **只枚举无序对导致漏解**
   - ✗ `for (int j = i+1; j < n; j++)` 然后只算 `a+b, a-b, a*b, a/b`
   - ✓ 要么枚举有序对 `(i,j)` 其中 `i≠j`，要么枚举无序对但对减法和除法分别算 `a-b, b-a, a/b, b/a`
   - **为什么**：`a-b ≠ b-a`，`a/b ≠ b/a`，漏掉就会 miss 正确表达式

2. **浮点比较用 `==`**
   - ✗ `return nums[0] == 24.0;`
   - ✓ `return fabs(nums[0] - 24.0) < 1e-6;`
   - **为什么**：`8.0 / 3.0 * 9.0` 在浮点运算中可能不精确等于 24.0

3. **忘记除零保护**
   - ✗ 直接 `a / b` 不检查 b 是否为 0
   - ✓ `if (fabs(b) > EPS) results.push_back(a / b);`
   - **为什么**：中间运算可能产生 0（如 `1-1=0`），后续除以 0 会得到 inf/nan

4. **回溯时忘记 pop_back**
   - ✗ 把结果 push 进 next 后递归，但没有 pop 就继续下一个运算
   - ✓ 每次 push 后递归完必须 pop_back

## 面试追问

**Q1: 为什么"每次选2个数合并"能覆盖所有括号方案？**

任何合法的表达式都对应一棵**二叉表达式树**，叶子是4个数，内部节点是3个运算符。这棵树从叶子到根的构建过程就是"每次选2个子树合并成1个"。我们的回溯过程恰好在枚举所有可能的合并顺序，因此覆盖了所有树形态。

**Q2: 搜索空间到底有多大？能精确算出来吗？**

- 第一步：4个数选有序对 = 4×3 = 12 种选法 × 4种运算 = 48
- 第二步：3个数选有序对 = 3×2 = 6 × 4 = 24
- 第三步：2个数选有序对 = 2×1 = 2 × 4 = 8
- 总计：48 × 24 × 8 = 9216（上界，含重复计算如加法交换律）

**Q3: 如果扩展到 N 个数字，能得到目标值 T，怎么做？**

同样的"选2合1"回溯框架可以直接推广。但搜索空间为 `N! × (N-1)! × ... × 4^(N-1)`，指数级增长。对于较大 N（如 6-8），可以考虑：
- **剪枝**：如果当前数字集合中最大可能乘积远小于T，提前剪枝
- **记忆化**：对数字集合（排序后）做哈希记忆，避免重复子问题
- **双向搜索**：把N个数分成两半，分别枚举所有可能结果，再在中间 meet-in-the-middle
