# 659. Split Array into Consecutive Subsequences

## 核心思路

贪心策略：对于排序数组中的每个数字，优先将它追加到一个已有的、以前一个数字结尾的连续子序列后面（延长已有序列），而不是用它去开启一个新的长度为3的子序列。只有在无法追加时，才尝试开始新序列（需要后续两个连续数字存在）。如果既不能追加也不能开始新序列，则返回 false。

## 思维链

1. 数组已排序，所以相同的数字是连续出现的
2. 对每个数字 x，有两种选择：(a) 追加到以 x-1 结尾的子序列 (b) 以 x 开头创建新子序列 [x, x+1, x+2]
3. 为什么优先追加？因为追加不会消耗额外的数字，而开新序列需要额外消耗 x+1 和 x+2
4. 需要两个哈希表：freq 记录剩余可用数量，need 记录以某个值结尾的子序列期望的下一个值的数量
5. 遍历数组，对每个 x：先检查 freq[x]>0（还能用），再优先检查 need[x]>0（能追加），否则检查能否开新序列
6. 如果都不行，直接返回 false

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 贪心 + 双哈希表 | O(n) | O(n) | 经典做法，一次遍历 |
| 贪心 + 最小堆 | O(n log n) | O(n) | 用堆追踪每个子序列长度 |

## 关键提示

1. 使用两个 map：`freq` 统计每个数字剩余频次，`need` 统计"以某个值结尾的子序列需要的下一个值"的个数
2. 优先追加到现有子序列（need[x] > 0），再考虑开新序列
3. 开新序列时必须确保 x+1 和 x+2 都有剩余频次
4. 数组已排序是前提条件，保证了从左到右的贪心顺序正确性
5. 最小堆做法：维护 map<int, min_heap>，key 是子序列末尾值，堆中存子序列长度，每次取最短的序列来追加

## 解法详解

### 解法一：贪心 + 双哈希表（推荐）

**思路**：维护 freq（每个数字的剩余出现次数）和 need（需要某个数字来延续子序列的次数）。对于每个数字 x：
- 若 freq[x] == 0，已被使用，跳过
- 若 need[x] > 0，追加到已有子序列，need[x]--，need[x+1]++
- 否则若 freq[x+1] > 0 && freq[x+2] > 0，开新序列 [x, x+1, x+2]
- 否则返回 false

**关键实现细节**：
- freq 在扫描前统计好所有频次
- 每次使用一个数字时，freq[x]-- 必须执行
- need 的含义是"有多少个子序列正在等待数字 x 来续接"

### 解法二：贪心 + 最小堆

**思路**：用 unordered_map<int, priority_queue<int, vector<int>, greater<int>>> 来管理子序列，key 是子序列末尾元素，value 是一个最小堆，存储所有以该 key 结尾的子序列的长度。

对于每个数字 x：
- 如果 map[x-1] 非空，从中取出最短的子序列（贪心：优先延长最短的），长度+1，放入 map[x]
- 否则在 map[x] 中插入新序列，长度为 1

最终检查所有子序列长度是否都 >= 3。

## 易错点

1. **忘记检查 freq[x] == 0 的跳过逻辑**：如果数字已经在之前被"预支"用于开新序列，当前遍历到它时应该跳过
2. **开新序列时没有同步减少 freq[x+1] 和 freq[x+2]**：这是最常见的 bug，会导致后续重复使用已被占用的数字
3. **need 的更新方向搞反**：追加到以 x-1 结尾的序列后，应该是 need[x]--, need[x+1]++，不是 need[x]++
4. **边界条件：所有数字相同**：例如 [1,1,1]，每个数字都无法与任何其他数字形成连续序列，应返回 false
5. **混淆"子序列"和"子数组"**：本题的子序列不要求连续下标，但要求值连续递增（差为1）

## 面试追问

1. **如果不是排序数组怎么办？** 先排序，时间变为 O(n log n)，核心逻辑不变
2. **如何输出具体的分割方案？** 在堆解法中，维护每个子序列的完整列表而不仅是长度
3. **如果要求子序列长度至少为 k 而不是 3？** 只需修改开新序列时的检查和最终长度判断为 >= k
4. **能否用动态规划？** 可以但不必要，贪心已经是最优解，DP 会更复杂
5. **时间和空间能否进一步优化？** 时间已是 O(n) 最优；空间上如果值域有限可用数组代替哈希表
