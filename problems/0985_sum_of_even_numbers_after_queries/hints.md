# 985. 查询后的偶数和

[./solution.cpp)

## 核心思路

给定数组 nums 和一系列查询 queries[i] = [val, index]，每次将 val 加到 nums[index] 上，然后求数组中所有偶数的和。**关键优化：维护一个全局偶数和，每次查询只更新受影响的那一个元素对偶数和的贡献变化，O(1) 处理每个查询。**

## 思维链

1. **读完题第一反应** -> 对于每个查询，先修改 nums[index]，然后遍历整个数组求偶数和。每次查询 O(n)，总共 O(n * q)。

2. **暴力的瓶颈** -> n 和 q 都可以到 10^4，O(n * q) = 10^8，有点紧。而且这题的核心观察是：每次查询只改了一个元素，不需要重新扫整个数组。

3. **关键观察** -> 每次查询只影响 nums[index] 这一个元素。偶数和的变化可以通过分析这个元素修改前后的奇偶性来 O(1) 计算。

4. **分类讨论** -> 设修改前 nums[index] = old，修改后 = old + val = new。
   - 如果 old 是偶数：old 之前贡献了 old 给偶数和，先减去 old。
   - 如果 old 是奇数：old 之前不贡献偶数和，不需要减。
   - 修改后，如果 new 是偶数：加上 new。
   - 修改后，如果 new 是奇数：不加。

5. **实现** -> 预先计算初始偶数和。每次查询：(1) 如果旧值是偶数，从偶数和中减去旧值；(2) 加上 val 更新 nums[index]；(3) 如果新值是偶数，把新值加到偶数和中。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力模拟 | 每次查询后遍历数组求偶数和 | O(n * q) | O(q) | 能说即可 |
| 增量维护偶数和 | 只更新被修改元素的贡献 | O(n + q) | O(q) | 面试首选 |

## 关键提示

1. **偶数判断用 x % 2 == 0**：注意 C++ 中负数 % 2 可能是 -1 或 0。更安全的写法是 `(x & 1) == 0` 来判断偶数，或者 `x % 2 == 0`（负偶数 % 2 == 0 是成立的）。

2. **增量更新的四种情况**：
```
修改前   val    修改后   偶数和变化
偶数old  偶val  偶new    - old + new = + val
偶数old  奇val  奇new    - old
奇数old  偶val  奇new    无变化（奇+偶=奇）
奇数old  奇val  偶new    + new
```

3. **具体演示**：
```
nums = [1, 2, 3, 4], 初始偶数和 = 2 + 4 = 6

查询1: [1, 0] → nums[0] = 1+1 = 2
  old=1(奇) → 不减
  new=2(偶) → 偶数和 += 2 → 偶数和 = 8
  答案: 8 ✓

查询2: [-3, 1] → nums[1] = 2+(-3) = -1
  old=2(偶) → 偶数和 -= 2 → 偶数和 = 6
  new=-1(奇) → 不加
  答案: 6 ✓

查询3: [-4, 0] → nums[0] = 2+(-4) = -2
  old=2(偶) → 偶数和 -= 2 → 偶数和 = 4
  new=-2(偶) → 偶数和 += (-2) → 偶数和 = 2
  答案: 2 ✓

查询4: [2, 3] → nums[3] = 4+2 = 6
  old=4(偶) → 偶数和 -= 4 → 偶数和 = -2
  new=6(偶) → 偶数和 += 6 → 偶数和 = 4
  答案: 4 ✓
```

4. **不要忘记实际修改 nums[index]**：计算完偶数和变化后，nums[index] 必须真的更新为新值，因为后续查询依赖最新的数组状态。

5. **初始偶数和的计算**：遍历一次 nums 累加所有偶数值。这是 O(n) 的一次性开销。

## 解法详解

### 解法1: 暴力模拟 -- O(n * q) / O(q)

**思考过程**: 最直接的做法。每次查询后遍历整个数组，累加所有偶数。

```cpp
class Solution {
public:
    vector<int> sumEvenAfterQueries(vector<int>& nums, vector<vector<int>>& queries) {
        vector<int> answer;
        for (auto& q : queries) {
            nums[q[1]] += q[0]; // 修改数组
            int evenSum = 0;
            for (int x : nums) {
                if (x % 2 == 0) evenSum += x;
            }
            answer.push_back(evenSum);
        }
        return answer;
    }
};
```

**关键点**: 简单直接但效率低。n = q = 10^4 时约 10^8 次操作，可能刚好卡过或 TLE。面试中应直接跳到优化解法。

---

### 解法2: 增量维护偶数和 -- O(n + q) / O(q) -- 面试首选

**从解法1优化**: 既然每次只改一个元素，偶数和的变化只取决于这一个元素修改前后的奇偶性。预计算初始偶数和，每次 O(1) 更新。

```cpp
class Solution {
public:
    vector<int> sumEvenAfterQueries(vector<int>& nums, vector<vector<int>>& queries) {
        // 预计算初始偶数和
        int evenSum = 0;
        for (int x : nums) {
            if (x % 2 == 0) evenSum += x;
        }
        
        vector<int> answer;
        for (auto& q : queries) {
            int val = q[0], index = q[1];
            int oldVal = nums[index];
            int newVal = oldVal + val;
            
            // 如果旧值是偶数，从偶数和中移除
            if (oldVal % 2 == 0) {
                evenSum -= oldVal;
            }
            
            // 更新数组
            nums[index] = newVal;
            
            // 如果新值是偶数，加入偶数和
            if (newVal % 2 == 0) {
                evenSum += newVal;
            }
            
            answer.push_back(evenSum);
        }
        return answer;
    }
};
```

**关键点**:
- 预处理 O(n)，每个查询 O(1)，总共 O(n + q)。
- 顺序很重要：先减旧值的贡献，再更新数组，再加新值的贡献。
- 不需要分四种情况写 if-else，上面的代码自然覆盖了所有情况。

## 解法对比

| | 暴力模拟 | 增量维护 |
|---|---|---|
| 时间 | O(n * q) | O(n + q) |
| 空间 | O(q) | O(q) |
| 代码量 | 少 | 中 |
| 思维难度 | 低 | 低 |
| 面试推荐 | 说思路 | 面试首选 |

**增量维护是典型的"维护全局状态 + 增量更新"模式**，在很多查询类题目中非常常见。

## 易错点

1. **先更新数组再判断偶数性**
   - 如果先 `nums[index] += val` 再去判断旧值奇偶，旧值已经丢失了。
   - 必须先保存 oldVal 或先处理旧值的偶数和贡献，再修改数组。

2. **负数的偶数判断**
   - C++ 中 `-3 % 2 == -1`（不是 1），但 `-3 % 2 != 0` 仍然正确（-3 是奇数）。
   - `-4 % 2 == 0` 也正确（-4 是偶数）。
   - 所以 `x % 2 == 0` 对负数也能正确判断偶数。

3. **忘记更新 nums[index]**
   - 偶数和虽然维护正确了，但如果不更新 nums[index]，下一个查询中 oldVal 会是错的。

4. **queries 的格式**
   - queries[i] = [val, index]，不是 [index, val]。注意顺序：`val = q[0], index = q[1]`。

5. **偶数和可以是负数**
   - nums 中可以有负数（-10^4 <= nums[i] <= 10^4），偶数和也可以是负数。不要用 unsigned 类型。

## 面试追问

**Q1: 暴力解的时间复杂度？能过吗？**
> O(n * q)，n = q = 10^4 时约 10^8。LeetCode 上 C++ 可能刚好过，但 Java/Python 肯定 TLE。面试中应该直接给出 O(n + q) 的解法。

**Q2: 如果查询不是加一个值，而是改成一个值呢？**
> 思路完全相同：先移除 oldVal 对偶数和的贡献，设 newVal = 查询指定的值，再加入 newVal 的贡献。O(1) 处理每个查询。

**Q3: 如果要同时维护奇数和呢？**
> 同样的增量更新。或者利用 奇数和 = 总和 - 偶数和。总和在每次 +val 后 O(1) 更新。所以只需要维护一个偶数和就够了。

**Q4: 如果每次查询是区间加而不是单点加呢？**
> 单点加变成区间加后，每次影响多个元素，不能 O(1) 更新。需要更复杂的数据结构如线段树（维护区间偶数和）或差分数组 + 后处理。
