# 709. 转换成小写字母

## 核心思路

将字符串中所有大写字母转为对应的小写字母，其他字符保持不变。核心知识点是 **ASCII 码表**中大小写字母的关系：`'A'(65)` 到 `'a'(97)` 相差 32，而这个 32 恰好是 `2^5`，所以可以用**位运算**来完成转换。

## 思维链

1. **读完题第一反应** → 很简单，遍历字符串，遇到大写字母就转成小写。但面试官出这题不是考你会不会调 `tolower()`，而是考**底层原理**。
2. **大小写的本质是什么？** → ASCII 码表。大写 `A-Z` 的编码是 65-90，小写 `a-z` 是 97-122。差值恒为 32。
3. **方法1：加 32** → 如果字符在 `'A'` 到 `'Z'` 范围内，加 32 即可。
4. **方法2：位运算** → 32 = `0x20` = `0b00100000`，恰好是 ASCII 码第 5 位。大写字母的第 5 位是 0，小写字母的第 5 位是 1。所以 `c |= 0x20` 可以把大写转小写，且对已经是小写的字母无影响。
5. **方法3：利用字符范围** → `c - 'A' + 'a'` 这种写法更具可读性，不依赖具体的 ASCII 值。
6. **面试深度**：这道 Easy 题在面试中往往是一个起点，面试官会追问 ASCII 原理、位运算、Unicode 扩展等。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 判断 + 加 32 | 检查 A-Z 范围，加 32 | O(n) | O(1) | ⭐ 基础写法 |
| 位运算 OR 0x20 | 利用 ASCII 第5位特性 | O(n) | O(1) | ⭐⭐ 加分写法 |
| 字符差值法 | c - 'A' + 'a' | O(n) | O(1) | 可读性好 |

## 关键提示

1. **ASCII 码关键知识**：

   ```
   ASCII 码表（大小写字母部分）:
   
   字符   十进制   二进制
   'A'    65      0100 0001
   'B'    66      0100 0010
   ...
   'Z'    90      0101 1010
   
   'a'    97      0110 0001    ← 比 'A' 多了 0010 0000 (=32)
   'b'    98      0110 0010
   ...
   'z'    122     0111 1010
   
   观察: 大小写字母只有第 5 位不同!
     'A' = 0100 0001
     'a' = 0110 0001
              ^
              第5位: 0→大写, 1→小写
   
   所以 c | 0x20 (0010 0000) 可以将大写转小写:
     'A' | 0x20 = 0100 0001 | 0010 0000 = 0110 0001 = 'a' ✓
     'a' | 0x20 = 0110 0001 | 0010 0000 = 0110 0001 = 'a' ✓ (不变)
   ```

2. **位运算只对字母安全，对其他字符不安全**：
   - `'0'(48)` | `0x20` = `48 | 32` = `80` = `'P'` 错！
   - 所以如果字符串包含非字母字符（题目说"printable ASCII"），必须先判断是否是大写字母。
   - 安全写法：`if (c >= 'A' && c <= 'Z') c |= 0x20;`

3. **三种判断方式**：
   - `c >= 'A' && c <= 'Z'` — 最清晰
   - `isupper(c)` — 标准库函数
   - `c >= 65 && c <= 90` — 避免使用（魔法数字，不可读）

4. **面试中可以展示的进阶知识**：
   - 大小写互转：`c ^= 0x20`（XOR 翻转第5位）
   - 小写转大写：`c &= ~0x20`（清除第5位）
   - 大写转小写：`c |= 0x20`（设置第5位）

## 解法详解

### 解法1: 判断 + 加 32 — O(n) / O(1) ⭐ 基础写法

**思考过程**: 最直接的方法，检测到大写就加 32。

```cpp
class Solution {
public:
    string toLowerCase(string s) {
        for (char& c : s) {
            if (c >= 'A' && c <= 'Z') {
                c += 32;  // 或 c += ('a' - 'A');
            }
        }
        return s;
    }
};
```

**关键点**:
- `char& c` 用引用直接修改原字符串，避免额外空间。
- 只对 `A-Z` 范围的字符操作，数字、空格、标点等保持不变。
- `c += 32` 和 `c += ('a' - 'A')` 等价，后者可读性更好。

---

### 解法2: 位运算 OR 0x20 — O(n) / O(1) ⭐⭐ 加分写法

**思考过程**: 利用 ASCII 编码中大小写字母仅第5位不同的特性。

```cpp
class Solution {
public:
    string toLowerCase(string s) {
        for (char& c : s) {
            if (c >= 'A' && c <= 'Z') {
                c |= 0x20;  // 设置第5位：大写→小写
            }
        }
        return s;
    }
};
```

**关键点**:
- `0x20` = 32 = `0b00100000`，恰好是 ASCII 码第 5 位。
- `c |= 0x20` 对大写字母：设置第5位 → 变成小写。
- 必须先判断 `c >= 'A' && c <= 'Z'`，因为对非字母字符 `|= 0x20` 会产生错误结果。

---

### 解法3: 字符差值法 — O(n) / O(1)

**思考过程**: 不依赖 ASCII 具体值，用 `'a' - 'A'` 的差值。

```cpp
class Solution {
public:
    string toLowerCase(string s) {
        for (char& c : s) {
            if (c >= 'A' && c <= 'Z') {
                c = c - 'A' + 'a';  // 先映射到 0-25，再映射到 a-z
            }
        }
        return s;
    }
};
```

**关键点**:
- `c - 'A'` 得到 0-25 的偏移量，`+ 'a'` 映射到小写。
- 这种写法在非 ASCII 编码（如 EBCDIC）中也能正确工作（虽然现实中几乎不会遇到）。

---

### 解法4: 标准库函数 — O(n) / O(1)

```cpp
class Solution {
public:
    string toLowerCase(string s) {
        for (char& c : s) {
            c = tolower(c);  // C 标准库函数
        }
        return s;
    }
};
```

**关键点**:
- `tolower()` 对非大写字符返回原值，不需要额外判断。
- 面试中通常不推荐直接用库函数（除非面试官说可以），因为考察的就是底层原理。

## 易错点

1. **位运算不判断范围**：
   - ✗ `c |= 0x20` 对所有字符 → `'0'|0x20 = 'P'`，数字变成字母
   - ✓ `if (c >= 'A' && c <= 'Z') c |= 0x20;`

2. **忘记用引用修改**：
   - ✗ `for (char c : s) c += 32;` → c 是副本，s 不变
   - ✓ `for (char& c : s) c += 32;` → 引用修改原字符串

3. **硬编码 ASCII 值**：
   - ✗ `if (c >= 65 && c <= 90) c += 32;` → 魔法数字，不可读
   - ✓ `if (c >= 'A' && c <= 'Z') c += ('a' - 'A');` → 自解释

4. **返回值忘记**：
   - ✗ 只修改不返回 → 编译错误或返回未修改的字符串
   - ✓ 修改后 `return s;`

## 面试追问

**Q1: 为什么 32 恰好等于 2^5？这是巧合吗？**
> 不是巧合。ASCII 码设计时故意让大小写字母只差一个位（第5位），方便硬件用简单的位操作进行转换。这是 1960 年代 ASCII 委员会的设计决策。

**Q2: 如果要处理 Unicode 字符（如中文、德语 ß→SS）怎么办？**
> Unicode 的大小写转换比 ASCII 复杂得多：不是简单加 32。需要用 ICU 库或语言内置的 Unicode 大小写转换函数。某些字符转换后长度会改变（如德语 `'ß'.toUpperCase() = "SS"`），所以不能原地转换。

**Q3: XOR 0x20 可以做大小写互转，你能想到什么应用场景？**
> 1. 大小写不敏感的字符比较：`(a ^ 0x20) == (b ^ 0x20)` 可以将大小写统一后比较。
> 2. 字母大小写切换（toggle case）：每个字符 XOR 0x20 就行。
> 3. 密码学中简单的字母替换（当然不安全）。

**Q4: tolower() 在多线程环境下安全吗？**
> C 标准的 `tolower()` 依赖 locale 设置。如果在多线程中修改 locale，可能有线程安全问题。C++ 的 `std::tolower` 接受 locale 参数的版本是线程安全的。对于纯 ASCII 的手动转换（`c += 32`）完全无此问题。

**Q5: 如果字符串是 const（不可修改），怎么做？**
> 创建一个新字符串作为结果。时间不变 O(n)，空间 O(n)。代码改为 `string result = s; for (char& c : result) ...`
