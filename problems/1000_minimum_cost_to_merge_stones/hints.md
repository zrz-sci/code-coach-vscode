# 1000. 合并石头的最低成本

[./solution.cpp)

## 核心思路

n 堆石头排成一行，每次操作合并连续 k 堆为一堆，代价等于这 k 堆石头总数。求将所有石头合并为一堆的最小总代价。**区间 DP：dp[i][j] 表示将 stones[i..j] 合并到不能再合并的最小代价。当 (j - i) % (k - 1) == 0 时可以合并为一堆，额外加上 sum(i, j)。**

## 思维链

1. **读完题第一反应** -> 类似经典的"石子合并"问题，但每次必须合并恰好 k 堆而不是 2 堆。这增加了约束。

2. **先判断可行性** -> 每次合并 k 堆变 1 堆，减少 k-1 堆。从 n 堆减到 1 堆需要减少 n-1 堆。因此 (n-1) 必须是 (k-1) 的倍数，即 `(n-1) % (k-1) == 0`。否则返回 -1。

3. **经典 k=2 的回顾** -> 当 k=2 时，dp[i][j] = min(dp[i][m] + dp[m+1][j]) + sum(i,j)，其中 i <= m < j。这是标准的区间 DP。

4. **推广到 k > 2** -> 关键难点：如何划分区间。将 stones[i..j] 合并为一堆需要先分成 k 个子区间，每个子区间先合并为一堆，然后再合并这 k 堆。

5. **DP 定义** -> dp[i][j] = 将 stones[i..j] 尽可能合并的最小代价。具体来说，能合并成多少堆取决于 (j - i) 和 (k - 1) 的关系。`(j - i) % (k - 1)` 个堆到 `(j - i) % (k - 1) + 1` 堆... 不对，让我重新想。

6. **更清晰的定义** -> dp[i][j] = 将 stones[i..j] 合并到不能再合并的最小代价。区间内的堆数为 j - i + 1。每次合并减少 k - 1 堆，最终剩余 `(j - i) % (k - 1) + 1` 堆。当 `(j - i) % (k - 1) == 0` 时恰好能合并成 1 堆，需要额外付出 sum(i, j) 的代价。

7. **转移方程** -> dp[i][j] = min(dp[i][m] + dp[m+1][j])，其中 m 从 i 开始以 k-1 为步长枚举（保证左半部分能合并为一堆）。如果 (j - i) % (k - 1) == 0，再加上 prefix[j+1] - prefix[i]。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 区间 DP（二维） | dp[i][j] + 前缀和 | O(n^3 / k) | O(n^2) | 面试首选 |
| 区间 DP（三维） | dp[i][j][p] = 合并成 p 堆 | O(n^3 * k) | O(n^2 * k) | 更直观但空间大 |

## 关键提示

1. **可行性判断**：`(n - 1) % (k - 1) != 0` 时返回 -1。直觉：每次操作将 k 堆变 1 堆，净减少 k-1。总共需要净减少 n-1 堆，所以 (n-1) 必须是 (k-1) 的倍数。

2. **二维 DP 的核心思想**：
```
dp[i][j] = 把 stones[i..j] 尽可能合并的最小代价

转移: 枚举分割点 m，把 [i..j] 分成 [i..m] 和 [m+1..j]
      dp[i][j] = min(dp[i][m] + dp[m+1][j])
      
      m 的步长是 k-1（确保左半 [i..m] 能合并为 1 堆）
      
如果 (j-i) % (k-1) == 0:
      [i..j] 刚好能合并成 1 堆
      dp[i][j] += sum(i, j)   // 最后一次合并的代价
```

3. **为什么 m 以 k-1 为步长？** 左半区间 [i..m] 的长度为 m - i + 1，要求它能合并成 1 堆，即 (m - i) % (k - 1) == 0。m = i 满足条件（长度 1，不需要合并），下一个满足条件的 m = i + (k-1)，再下一个 m = i + 2*(k-1)，以此类推。

4. **具体演示**：
```
stones = [3, 2, 4, 1], k = 2
前缀和: [0, 3, 5, 9, 10]

dp 填表 (从小区间到大区间):
  dp[0][0]=0, dp[1][1]=0, dp[2][2]=0, dp[3][3]=0

  len=2 (k-1=1, (1)%1==0 → 可合并):
    dp[0][1] = dp[0][0]+dp[1][1] + sum(0,1) = 0+0+5 = 5
    dp[1][2] = 0+0+6 = 6
    dp[2][3] = 0+0+5 = 5

  len=3 ((2)%1==0 → 可合并):
    dp[0][2] = min(dp[0][0]+dp[1][2], dp[0][1]+dp[2][2]) + sum(0,2)
             = min(0+6, 5+0) + 9 = 5 + 9 = 14
    dp[1][3] = min(dp[1][1]+dp[2][3], dp[1][2]+dp[3][3]) + sum(1,3)
             = min(0+5, 6+0) + 7 = 5 + 7 = 12

  len=4 ((3)%1==0 → 可合并):
    dp[0][3] = min(dp[0][0]+dp[1][3], dp[0][1]+dp[2][3], dp[0][2]+dp[3][3]) + sum(0,3)
             = min(0+12, 5+5, 14+0) + 10 = 10 + 10 = 20

  答案: dp[0][3] = 20 ✓
```

5. **三维 DP 解法的定义**：dp[i][j][p] = 将 stones[i..j] 合并成 p 堆的最小代价。转移：dp[i][j][p] = min(dp[i][m][1] + dp[m+1][j][p-1])。dp[i][j][1] = dp[i][j][k] + sum(i,j)。但空间更大，面试中二维更优。

## 解法详解

### 解法1: 区间 DP（二维） -- O(n^3 / k) / O(n^2) -- 面试首选

**思考过程**: 经典区间 DP 的推广。关键是分割点 m 的步长和"最后一次合并"的时机。

```cpp
class Solution {
public:
    int mergeStones(vector<int>& stones, int k) {
        int n = stones.size();
        // 可行性判断
        if ((n - 1) % (k - 1) != 0) return -1;
        
        // 前缀和
        vector<int> prefix(n + 1, 0);
        for (int i = 0; i < n; i++) {
            prefix[i + 1] = prefix[i] + stones[i];
        }
        
        // dp[i][j] = 将 stones[i..j] 尽可能合并的最小代价
        vector<vector<int>> dp(n, vector<int>(n, 0));
        
        // 按区间长度从小到大填表
        for (int len = k; len <= n; len++) {
            for (int i = 0; i + len - 1 < n; i++) {
                int j = i + len - 1;
                dp[i][j] = INT_MAX;
                
                // 枚举分割点 m，步长 k-1
                for (int m = i; m < j; m += k - 1) {
                    dp[i][j] = min(dp[i][j], dp[i][m] + dp[m + 1][j]);
                }
                
                // 如果 [i..j] 恰好能合并成一堆，加上最后一次合并的代价
                if ((j - i) % (k - 1) == 0) {
                    dp[i][j] += prefix[j + 1] - prefix[i];
                }
            }
        }
        
        return dp[0][n - 1];
    }
};
```

**关键点**:
- m 的步长是 k-1 而不是 1，这是因为左半区间 [i..m] 必须能合并为一堆。
- `(j - i) % (k - 1) == 0` 判断区间是否恰好能合并为一堆。
- 前缀和 O(1) 查询区间和。
- 时间 O(n^3 / (k-1))：三层循环，最内层步长 k-1。

### 解法2: 区间 DP（三维） -- O(n^3 * k) / O(n^2 * k) -- 更直观

**思路**: 增加第三维 p，dp[i][j][p] 表示将 [i..j] 合并为 p 堆的最小代价。

```cpp
class Solution {
public:
    int mergeStones(vector<int>& stones, int k) {
        int n = stones.size();
        if ((n - 1) % (k - 1) != 0) return -1;
        
        vector<int> prefix(n + 1, 0);
        for (int i = 0; i < n; i++) {
            prefix[i + 1] = prefix[i] + stones[i];
        }
        
        // dp[i][j][p] = 将 [i..j] 合并成 p 堆的最小代价
        // 初始化为 INT_MAX 表示不可达
        vector<vector<vector<int>>> dp(n, vector<vector<int>>(n, vector<int>(k + 1, INT_MAX)));
        
        // 基础情况: 单个石头堆本身就是 1 堆，代价 0
        for (int i = 0; i < n; i++) {
            dp[i][i][1] = 0;
        }
        
        for (int len = 2; len <= n; len++) {
            for (int i = 0; i + len - 1 < n; i++) {
                int j = i + len - 1;
                
                // 合并成 p 堆 (p >= 2)
                for (int p = 2; p <= min(len, k); p++) {
                    for (int m = i; m < j; m++) {
                        if (dp[i][m][1] != INT_MAX && dp[m + 1][j][p - 1] != INT_MAX) {
                            dp[i][j][p] = min(dp[i][j][p],
                                              dp[i][m][1] + dp[m + 1][j][p - 1]);
                        }
                    }
                }
                
                // 合并成 1 堆: 先合并成 k 堆，再合并这 k 堆
                if (dp[i][j][k] != INT_MAX) {
                    dp[i][j][1] = dp[i][j][k] + prefix[j + 1] - prefix[i];
                }
            }
        }
        
        return dp[0][n - 1][1];
    }
};
```

**关键点**: dp[i][j][1] = dp[i][j][k] + sum(i,j)。即合并成 1 堆的代价 = 先分成 k 堆的代价 + 最后一步合并的代价。三维更直观但空间 O(n^2 * k)。

## 解法对比

| | 二维区间 DP | 三维区间 DP |
|---|---|---|
| 时间 | O(n^3 / k) | O(n^3 * k) |
| 空间 | O(n^2) | O(n^2 * k) |
| 代码量 | 中 | 多 |
| 思维难度 | 高（m的步长需要推导） | 中（第三维意义清晰） |
| 面试推荐 | 首选（效率高） | 如果推导不出二维可以先写三维 |

## 易错点

1. **忘记可行性判断**
   - `(n - 1) % (k - 1) != 0` 时无法合并为一堆，必须返回 -1。
   - 例：stones = [3,2,4,1], k = 3，n=4，(4-1)%(3-1) = 3%2 = 1 != 0 → 返回 -1。

2. **分割点 m 的步长用了 1 而不是 k-1**
   - 步长为 1 时也能得到正确答案（因为 dp 值包含了不可行状态），但时间多出 k-1 倍。
   - 步长 k-1 是优化的关键，保证左半区间能合并为恰好一堆。

3. **最后一次合并代价加错位置**
   - 应该在转移之后、且 `(j-i) % (k-1) == 0` 时才加 sum(i,j)。
   - 不能在转移的 min 里面就加，否则中间状态的代价会被错误计算。

4. **初始化错误**
   - dp[i][i] = 0（单堆不需要合并）。
   - len < k 的区间无法合并（除了 len=1），dp 保持 0（没有合并操作发生）。

5. **前缀和下标偏移**
   - sum(i, j) = prefix[j+1] - prefix[i]，注意 +1 的偏移。

## 面试追问

**Q1: 为什么 (n-1) % (k-1) != 0 就无解？**
> 每次合并 k 堆变 1 堆，减少 k-1 堆。设经过 t 次合并后剩 1 堆，则 n - t*(k-1) = 1，即 t = (n-1)/(k-1)。如果不能整除，则不存在整数 t，无法合并为一堆。

**Q2: k=2 时退化成什么？**
> 经典石子合并问题。dp[i][j] = min(dp[i][m] + dp[m+1][j]) + sum(i,j)，分割点 m 步长为 1。这就是 O(n^3) 的标准区间 DP。

**Q3: 能否用贪心（每次选代价最小的 k 堆合并）？**
> 不能。贪心在 k=2 时就不是最优的（考虑经典反例）。必须用 DP 保证全局最优。

**Q4: 如果不要求连续 k 堆，而是任意 k 堆？**
> 那就变成了完全不同的问题（类似哈夫曼编码的推广）。此时贪心可能有效：每次选最小的 k 堆合并。需要注意最后一步可能不足 k 堆的处理。
