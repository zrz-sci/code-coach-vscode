# LCR 023. 相交链表 (同主站 160. Intersection of Two Linked Lists)

## 题目理解

给定两个单链表的头节点 headA 和 headB，找出两个链表的相交起始节点。
如果没有交点，返回 null。

**相交的定义**：两个链表在某个节点之后共享所有后续节点（是同一个节点对象，不只是值相等）。

```
链表 A:     4 → 1 ─┐
                     ↘
                      8 → 4 → 5
                     ↗
链表 B: 5 → 6 → 1 ─┘

交点: 节点 8
```

**进阶要求**：O(m+n) 时间、O(1) 空间。

---

## 解法一：双指针法（最优解，推荐）

### 核心思想

让两个指针 pA 和 pB 分别从 headA 和 headB 出发。当某个指针走到链表末尾时，
切换到另一条链表的头部继续走。这样两个指针走过的总距离相等，会在交点相遇。

### 数学证明

设链表 A 的独有部分长度为 a，链表 B 的独有部分长度为 b，公共部分长度为 c。

```
链表 A: [---a---][---c---]
链表 B: [--b--][---c---]
```

- pA 走的路径：a + c + b = a + b + c
- pB 走的路径：b + c + a = a + b + c

两者总路程相同！所以它们会同时到达交点。

### 指针移动图解

```
链表 A: a1 → a2 → c1 → c2 → c3
                   ↑ 交点
链表 B: b1 → b2 → b3 → c1 → c2 → c3

═══════════════════════════════════════════════

第1轮: pA 遍历链表 A, pB 遍历链表 B

  pA: a1 → a2 → c1 → c2 → c3 → null
  pB: b1 → b2 → b3 → c1 → c2 → c3 → null

pA 先到 null (A 较短), 切换到 headB
pB 后到 null (B 较长), 切换到 headA

═══════════════════════════════════════════════

第2轮: pA 遍历链表 B, pB 遍历链表 A

  pA (从 headB 开始): b1 → b2 → b3 → [c1] ← 到达交点!
  pB (从 headA 开始): a1 → a2       → [c1] ← 到达交点!

  pA 走了: a1,a2,c1,c2,c3 | b1,b2,b3,[c1] = 2 + 3 + 3 + 1 = 路程 a+c+b
  pB 走了: b1,b2,b3,c1,c2,c3 | a1,a2,[c1]  = 3 + 3 + 2 + 1 = 路程 b+c+a

两者在 c1 相遇! ✓
```

### 无交点的情况

```
链表 A: a1 → a2 → a3         (长度 3)
链表 B: b1 → b2              (长度 2)

无交点, c = 0

pA 路径: a1,a2,a3,null → b1,b2,null    走了 3 + 2 + 2(null) 步
pB 路径: b1,b2,null → a1,a2,a3,null    走了 2 + 3 + 2(null) 步

两者同时到达 null, 返回 null ✓

关键: a 走到 null 后切换, b 走到 null 后切换, 最终同时到 null
       因为 pA 总共走 a + b 步到 null
       pB 总共走 b + a 步到 null
       a + b == b + a, 所以同时到达!
```

### 逐步 trace（带指针图）

以 A=[4,1,8,4,5], B=[5,6,1,8,4,5], 交点在节点8 为例：

```
初始:
A: [4] → [1] → [8] → [4] → [5] → null
                 ↑ 交点
B: [5] → [6] → [1] → [8] → [4] → [5] → null

pA=4, pB=5

Step 1: pA=1, pB=6
Step 2: pA=8, pB=1
Step 3: pA=4, pB=8(交点)  // pA 和 pB 在不同位置
Step 4: pA=5, pB=4
Step 5: pA=null, pB=5
Step 6: pA→headB=5, pB=null
Step 7: pA=6, pB→headA=4
Step 8: pA=1, pB=1
Step 9: pA=8(交点), pB=8(交点)  → pA == pB, 返回 8!

验证:
  pA 走了: 4,1,8,4,5,null,5,6,1,[8] = lenA + (lenB - c) 步
  pB 走了: 5,6,1,8,4,5,null,4,1,[8] = lenB + (lenA - c) 步
  lenA + lenB - c == lenB + lenA - c  ✓
```

## 解法二：哈希集合法

### 思路

1. 遍历链表 A，把所有节点存入哈希集合
2. 遍历链表 B，找第一个在集合中出现的节点

```
链表 A: [4] → [1] → [8] → [4] → [5]
HashSet: {节点4, 节点1, 节点8, 节点4', 节点5}

链表 B: [5] → [6] → [1] → [8] → ...
                              ↑ 在 HashSet 中找到了! 返回节点8
```

时间 O(m+n)，空间 O(m)——不满足 O(1) 空间要求。

## 解法三：长度差法

### 思路

1. 先分别遍历两条链表，求出各自的长度 lenA 和 lenB
2. 让较长的链表先走 |lenA - lenB| 步
3. 然后两个指针同时走，第一个相同的节点就是交点

```
A: [4] → [1] → [8] → [4] → [5]      lenA = 5
B: [5] → [6] → [1] → [8] → [4] → [5]  lenB = 6

差值 = 6 - 5 = 1, 让 pB 先走 1 步

pB 先走: [5] → [6]     (现在 pB 指向 [6])
                 ↓
         pA:[4]  pB:[6]
         pA:[1]  pB:[1]
         pA:[8]  pB:[8]  ← 相遇! (同一个节点对象)
```

时间 O(m+n)，空间 O(1)。逻辑正确但代码比双指针法长。

## 常见错误与陷阱

### 1. 比较的是节点对象，不是值

```cpp
// 错误: 比较值
if (pA->val == pB->val) return pA;  // ✗ 值相同不一定是同一节点

// 正确: 比较指针 (节点地址)
if (pA == pB) return pA;  // ✓
```

### 2. 双指针切换逻辑的边界

```cpp
// 错误写法 (会跳过 null 的比较):
a = a->next ? a->next : headB;  // ✗ 当 a 在最后一个节点时直接跳到 headB

// 正确写法 (先到 null, 下一步再切换):
a = a ? a->next : headB;  // ✓ 当 a == null 时切换到 headB
```

区别在于：正确写法让 pA 经过 null 节点（相当于走到链表"尾巴后面一步"），
然后下一步才切换。这保证了无交点时两个指针同时到达 null。

### 3. 链表完全不相交时的死循环

双指针法不会死循环。证明：无论是否有交点，两个指针各自走 lenA + lenB 步后
必然同时到达 null（无交点）或同一节点（有交点），所以 while(a != b) 必然终止。

| 哈希集合 | O(m+n) | O(m) | 否 |
| 长度差 | O(m+n) | O(1) | 否 |

## 为什么双指针法如此优雅？

这个算法有一个诗意的比喻：

> "你走过我来时的路，我走过你来时的路，
>  当我们走过的路程一样长时，我们就在交点相遇了。"

pA 走完 A 再走 B，pB 走完 B 再走 A，两人走过的总路程相同（a+b+c），
所以一定会在交点（或者在无交点时的 null）相遇。

## Follow-up 拓展

**Q: 如果链表有环怎么办？**
→ 需要先用 Floyd 判环，然后分情况讨论。如果两个链表的环是同一个环，
则相交；否则不相交。这是一道非常复杂的面试追问。

**Q: 如何在不改变链表的情况下判断交点？**
→ 双指针法和哈希法都不修改链表。但如果允许修改，还可以把 A 的末尾连到 A 的头，
然后问题变成"在 B 中找环的入口"（LC 142），不过这会修改链表结构。

**Q: 如果两条链表都很长（百万节点），如何优化？**
→ O(m+n) 已经是最优时间复杂度。空间上双指针法 O(1) 也是最优。
实际优化可以考虑缓存友好性和链表节点的内存布局。
