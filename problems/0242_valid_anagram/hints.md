# 242. 有效的字母异位词

## 核心思路

字母异位词 = 两个字符串用到的每个字母的次数完全相同。本质上就是**比较两个字符串的字符频率是否一致**。

## 思维链

1. **读完题第一反应**：字母异位词意味着两个字符串包含的字符种类和数量完全相同，只是排列顺序不同。最朴素的想法——把两个字符串都排序，排序后相同就是异位词。

2. **排序解法的瓶颈**：排序的时间复杂度是 O(n log n)，能不能更快？

3. **换个角度思考**：既然只关心"每个字母出现几次"，那我们只需要**统计频率**。用什么来统计？数组或哈希表！

4. **具体怎么做**：遍历字符串 s 时对每个字母计数 +1，遍历字符串 t 时 -1。最终如果所有计数都是 0，说明字符频率完全一致。

5. **进一步思考 Follow-up**：如果字符不局限于 26 个小写字母而是 Unicode 怎么办？固定大小的数组不够用了，换成哈希表（`unordered_map`）即可。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 排序比较 | 排序后直接比较字符串 | O(n log n) | O(1)~O(n) | 能说出即可 |
| 数组计数 | 长度26的数组统计频率 | O(n) | O(1) | ⭐ 必须写出 |
| 哈希表计数 | unordered_map统计频率 | O(n) | O(k) | 加分项（Follow-up） |

## 关键提示

1. **长度不同直接返回 false**：如果 `s.length() != t.length()`，不可能是异位词，这是最简单的剪枝。

2. **一个数组就够了**：不需要两个计数数组再比较。用一个数组，s 的字符 +1、t 的字符 -1，最后全 0 即为异位词。

3. **字符映射到下标**：`s[i] - 'a'` 把小写字母映射到 0~25，正好对应数组下标。

4. **Follow-up 的关键**：Unicode 字符集很大且不连续，固定大小数组行不通，用哈希表替代。

## 解法详解

### 解法1: 排序比较 — O(n log n) / O(n)

**思考过程**：异位词 = 字母相同、顺序不同。那把顺序统一（排序）后比较，相同就是异位词。这是最直觉的想法。

```cpp
class Solution {
public:
    bool isAnagram(string s, string t) {
        // 长度不同不可能是异位词
        if (s.size() != t.size()) return false;
        
        // 排序后，异位词会变成完全相同的字符串
        // "nagaram" → "aaagmnr", "anagram" → "aaagmnr"
        sort(s.begin(), s.end());
        sort(t.begin(), t.end());
        
        return s == t;
    }
};
```

**关键点**：排序会修改原字符串。如果题目要求不能修改输入，需要先拷贝。C++ 中参数按值传递已经是拷贝了，所以没问题。

---

### 解法2: 数组计数 — O(n) / O(1) ⭐ 面试首选

**从解法1优化**：排序解法的瓶颈在 O(n log n) 的排序。但我们其实不关心字符的顺序，只关心**每个字符出现几次**。用一个长度为 26 的数组统计频率即可，时间降到 O(n)。

```
// 示例: s = "anagram", t = "nagaram"
//
// 遍历 s (加):  a:3  n:1  g:1  r:1  m:1
// 遍历 t (减):  a:3-3=0  n:1-1=0  g:1-1=0  r:1-1=0  m:1-1=0
// 全部为 0 → true
//
// 示例: s = "rat", t = "car"
//
// 遍历 s (加):  r:1  a:1  t:1
// 遍历 t (减):  c:-1  a:1-1=0  r:1-1=0    t 仍为 1
// 不全为 0 → false
```

```cpp
class Solution {
public:
    bool isAnagram(string s, string t) {
        if (s.size() != t.size()) return false;
        
        // 26个字母的频率计数器，初始全0
        int count[26] = {0};
        
        // 一次遍历：s的字符+1，t的字符-1
        // 因为长度相同，可以在同一个循环里处理
        for (int i = 0; i < s.size(); i++) {
            count[s[i] - 'a']++;  // s中出现的字母 +1
            count[t[i] - 'a']--;  // t中出现的字母 -1
        }
        
        // 如果是异位词，所有计数应该回到0
        for (int i = 0; i < 26; i++) {
            if (count[i] != 0) return false;
        }
        
        return true;
    }
};
```

**关键点**：空间是 O(1) 而不是 O(n)，因为数组大小固定为 26，与输入规模无关。

---

### 解法3: 哈希表计数 — O(n) / O(k)（Follow-up: Unicode 支持）

**为什么需要这个解法**：解法2 用固定大小的数组，依赖"只有26个小写字母"的前提。如果字符是 Unicode（可能有上百万种字符），数组下标映射不现实。用哈希表就没有这个限制。

```cpp
class Solution {
public:
    bool isAnagram(string s, string t) {
        if (s.size() != t.size()) return false;
        
        // 用哈希表代替固定数组，适应任意字符集
        unordered_map<char, int> count;
        
        for (char c : s) count[c]++;
        for (char c : t) count[c]--;
        
        // 检查所有计数是否为0
        for (auto& [ch, cnt] : count) {
            if (cnt != 0) return false;
        }
        
        return true;
    }
};
```

**关键点**：哈希表的常数开销比数组大，但适用范围更广。面试中如果被问 Follow-up，这就是答案。

## 解法对比

| | 排序比较 | 数组计数 | 哈希表计数 |
|---|---|---|---|
| 时间 | O(n log n) | O(n) | O(n) |
| 空间 | O(1)~O(n) 取决于排序实现 | O(1) 固定26 | O(k) k为字符种类数 |
| 适用字符集 | 任意 | 仅已知有限字符集 | 任意（Unicode） |
| 代码复杂度 | 最简单 | 简单 | 稍多 |
| **面试推荐** | 作为暴力提及 | **首选** | Follow-up 时给出 |

选择建议：面试中直接写解法2（数组计数），被追问 Unicode 时切换到解法3（哈希表）。

## 易错点

1. **忘记判断长度**：
   - ✗ 直接开始计数，`s="ab"` 和 `t="a"` 会在遍历时下标越界（如果用同一循环）
   - ✓ 先判 `if (s.size() != t.size()) return false;`

2. **字符映射写反**：
   - ✗ `count[s[i] - 'A']` — 题目说的是小写字母，用 `'A'` 会得到错误下标
   - ✓ `count[s[i] - 'a']`

3. **数组未初始化**：
   - ✗ `int count[26];` — C++ 中局部数组不会自动初始化为0，可能包含垃圾值
   - ✓ `int count[26] = {0};` 或 `int count[26] = {};`

4. **最终检查遗漏**：
   - ✗ 只检查 `count` 中是否有负数（忘了检查正数也不行）
   - ✓ 检查所有 `count[i] != 0`（不过如果已判断长度相等，有正必有负，但逻辑上还是检查 `!= 0` 更准确）

## 面试追问

**Q1: 暴力解能过吗？瓶颈在哪？**
> 排序解法 O(n log n) 肯定能过（n ≤ 5×10⁴），瓶颈在排序。但本题只需统计频率，不需要排序这么"重"的操作。

**Q2: 能否只用一个计数数组，一次遍历搞定？**
> 可以。因为两个字符串等长，在同一个 for 循环里 s 的字符 +1、t 的字符 -1。最后检查全 0。

**Q3 (Follow-up): 如果输入包含 Unicode 字符怎么办？**
> 固定大小数组不适用（Unicode 有超过 14 万个字符）。改用 `unordered_map<char, int>`（或 `unordered_map<int, int>` 对应 code point），逻辑完全一样，只是存储结构变了。

**Q4: 如果要判断两个字符串是否是"排列关系"（permutation），和异位词有什么区别？**
> 完全等价。异位词 = 排列 = 字符频率相同。代码一模一样。
