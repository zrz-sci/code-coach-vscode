# 2235. 两整数相加

## 核心思路（1句话）
直接返回两数之和；但本题的面试价值在于：如果不允许使用 `+` 运算符，如何用位运算模拟加法。

## 思维链（4-6步）

1. **第一反应**：这题不就是 `return num1 + num2` 吗？一行代码搞定。
2. **质疑简单性**：面试中如果遇到这种题，面试官一定会追问"不用加法运算符怎么做"，所以需要准备位运算解法。
3. **位运算思路**：回忆计算机底层如何做加法——用异或 (XOR) 计算"无进位和"，用与 (AND) + 左移计算"进位"。
4. **迭代 vs 递归**：位运算加法可以写成循环形式（while carry != 0），也可以写成递归形式。
5. **边界考虑**：负数在补码表示下，位运算同样成立，无需特殊处理。但在 Python 中需注意整数无限精度导致的负数循环问题（C++ 无此问题）。
6. **最终决策**：面试时先给出一行解法展示"快速解题"能力，再主动给出位运算解法展示"底层理解"。

## 解法概览

|------|-----------|-----------|------|

## 关键提示

1. **位运算加法的核心公式**：`a + b = (a ^ b) + ((a & b) << 1)`，其中 `a ^ b` 是无进位和，`(a & b) << 1` 是进位。这个过程不断重复直到进位为 0。

2. **为什么 XOR 是无进位和**：
   - `0 + 0 = 0`，`0 XOR 0 = 0`
   - `0 + 1 = 1`，`0 XOR 1 = 1`
   - `1 + 0 = 1`，`1 XOR 0 = 1`
   - `1 + 1 = 10`（进位），`1 XOR 1 = 0`（只看当前位，不管进位）

3. **为什么 AND + 左移 是进位**：只有两个位都是 1 时才产生进位（AND = 1），进位要加到高一位（左移 1）。

4. **C++ 中负数的位运算**：C++ 中 int 使用补码表示，位运算在补码上天然正确，无需额外处理负数情况。但注意：C++20 之前，有符号整数左移溢出是未定义行为。题目约束 `-100 <= num <= 100`，不会溢出。

5. **面试策略**：先写 `return num1 + num2;` 展示快速解题能力，然后主动说"如果不允许用加法运算符，我可以用位运算实现"，展示深度理解。

## 解法详解

### 解法1: 直接相加 — O(1)/O(1) ⭐面试首选

**思考过程**: 题目要求返回两数之和，最直接的方式就是使用 `+` 运算符。这是面试中首先应该给出的答案，展示快速理解和解决问题的能力。

```cpp
class Solution {
public:
    int sum(int num1, int num2) {
        // 直接返回两数之和
        return num1 + num2;
    }
};
```

**关键点**: 
- 不要过度思考，面试中先给出最简洁的正确解法
- 注意数据范围 `-100 <= num1, num2 <= 100`，和的范围是 `[-200, 200]`，int 完全够用，无需考虑溢出

### 解法2: 位运算迭代 — O(log(max_val))/O(1)

**从解法1优化**: 如果面试官要求不使用 `+` 运算符，我们需要从计算机底层的加法器原理出发。CPU 的加法器就是通过异或和与运算实现的。

**位运算加法原理（以 5 + 3 为例）**：
```
第一轮:
  num1 = 5  = 0101
  num2 = 3  = 0011
  无进位和 = 0101 ^ 0011 = 0110 (6)
  进位     = (0101 & 0011) << 1 = (0001) << 1 = 0010 (2)

第二轮:
  num1 = 6  = 0110
  num2 = 2  = 0010
  无进位和 = 0110 ^ 0010 = 0100 (4)
  进位     = (0110 & 0010) << 1 = (0010) << 1 = 0100 (4)

第三轮:
  num1 = 4  = 0100
  num2 = 4  = 0100
  无进位和 = 0100 ^ 0100 = 0000 (0)
  进位     = (0100 & 0100) << 1 = (0100) << 1 = 1000 (8)

第四轮:
  num1 = 0  = 0000
  num2 = 8  = 1000
  无进位和 = 0000 ^ 1000 = 1000 (8)
  进位     = (0000 & 1000) << 1 = 0000 (0)

进位为0，结束! 结果 = 8 = 5 + 3
```

```cpp
class Solution {
public:
    int sum(int num1, int num2) {
        // 位运算模拟加法：不使用 + 运算符
        while (num2 != 0) {
            // 计算进位：两位都为1时产生进位
            int carry = (num1 & num2) << 1;
            // 计算无进位和：异或得到不考虑进位的结果
            num1 = num1 ^ num2;
            // 将进位赋给 num2，下一轮继续处理
            num2 = carry;
        }
        return num1;
    }
};
```

**关键点**: 
- 循环终止条件是 `num2 == 0`（即没有进位了）
- 每次循环，进位至少左移一位，所以最多循环 32 次（int 的位数）
- 必须先计算 carry 再更新 num1，否则 num1 被修改后 carry 计算就错了

### 解法3: 递归位运算 — O(log(max_val))/O(log(max_val))

**从解法2优化**: 将迭代逻辑改为递归，代码更加简洁优雅。

```cpp
class Solution {
public:
    int sum(int num1, int num2) {
        // 递归终止：没有进位时，num1 就是最终结果
        if (num2 == 0) return num1;
        // 递归：无进位和 与 进位 继续相加
        return sum(num1 ^ num2, (num1 & num2) << 1);
    }
};
```

**关键点**: 
- 递归的 base case 是 `num2 == 0`
- 递归调用栈深度等于进位传播的轮数，最坏 O(32) = O(1)（对固定位宽是常数）
- 面试中递归写法更简洁，但要注意解释清楚递归逻辑

## 易错点

1. **位运算顺序错误**
   ```cpp
   // ✗ 错误：先修改了 num1，导致 carry 计算使用了修改后的值
   num1 = num1 ^ num2;
   int carry = (num1 & num2) << 1;  // 这里的 num1 已经不是原值了！
   num2 = carry;

   // ✓ 正确：先计算 carry，再修改 num1
   int carry = (num1 & num2) << 1;
   num1 = num1 ^ num2;
   num2 = carry;
   ```
   **原因**：carry 的计算依赖于原始的 num1，如果先做了 XOR，num1 就变了。这和"交换两个变量需要临时变量"是同一类问题。

2. **Python 中负数位运算的陷阱**（C++ 无此问题，但面试可能问到）
   ```python
   # ✗ 错误：Python 整数无限精度，负数的补码有无限个前导1，循环不会终止
   while num2 != 0:
       carry = (num1 & num2) << 1
       num1 = num1 ^ num2
       num2 = carry  # 如果有负数，carry 永远不为 0

   # ✓ 正确：需要用 mask 限制为 32 位
   MASK = 0xFFFFFFFF
   MAX_INT = 0x7FFFFFFF
   while num2 & MASK:
       carry = ((num1 & num2) << 1) & MASK
       num1 = (num1 ^ num2) & MASK
       num2 = carry
   # 最后处理负数：如果结果超过 MAX_INT，转回负数
   return num1 if num1 <= MAX_INT else ~(num1 ^ MASK)
   ```
   **原因**：C++ 的 int 天然是 32 位补码，溢出自动截断；Python 的整数是任意精度的，需要手动模拟 32 位。

3. **忘记处理溢出（本题不需要，但通用场景需注意）**
   ```cpp
   // ✗ 如果 num1 和 num2 范围很大，(num1 & num2) << 1 可能有符号溢出 (UB)
   int carry = (num1 & num2) << 1;  // C++20前，有符号左移溢出是 UB

   // ✓ 通用安全写法（使用 unsigned 避免有符号左移未定义行为）
   unsigned int carry = (unsigned int)(num1 & num2) << 1;
   ```
   **原因**：本题约束 `-100 <= num <= 100`，不会触发溢出，但在更大范围的场景下需要注意。

## 面试追问

### Q1: 如果不允许使用 `+` `-` `*` `/` 四则运算，如何实现加法？
**回答**：使用位运算。核心思想来自计算机加法器的原理：
- **异或 (XOR)**：计算每一位的"无进位和"。因为 `0+0=0, 0+1=1, 1+0=1` 与 XOR 结果一致，`1+1=0`（进位到高位）XOR 也为 0。
- **与 (AND) + 左移**：计算进位。只有 `1+1` 才产生进位（AND=1），进位影响高一位（左移 1 位）。
- 重复以上过程，直到进位为 0。这就是所谓的"半加器"链。

完整实现：
```cpp
int add(int a, int b) {
    while (b != 0) {
        int carry = (a & b) << 1;
        a = a ^ b;
        b = carry;
    }
    return a;
}
```

### Q2: 位运算加法的循环一定会终止吗？为什么？
**回答**：在 C++ 中一定会终止。证明如下：
- 每次循环，`carry = (a & b) << 1`
- carry 的最低位 (bit 0) 一定是 0（因为左移了一位）
- 更关键的是：carry 中 1 的位置一定比原来 `a & b` 中 1 的位置高至少一位
- 在 32 位 int 中，1 最多向高位移动 31 次就会移出边界变成 0
- 所以循环最多执行 O(32) = O(1) 次

但在 Python 中（整数无限精度），如果操作数是负数，补码表示有无限个前导 1，进位可能无限传播，需要手动 mask 为 32 位。

### Q3: 如何用位运算实现减法 `a - b`？
**回答**：减法 = 加上相反数。`a - b = a + (-b)`。在补码表示中，`-b = ~b + 1`（取反加一）。所以：
```cpp
int subtract(int a, int b) {
    // -b 的补码 = ~b + 1
    // 而 +1 可以用我们的位运算加法 add(~b, 1)
    return add(a, add(~b, 1));
}
```
进一步拓展：
- **乘法**：可以用"位移 + 加法"实现（类似手算竖式乘法，逐位乘再相加）
- **除法**：可以用"位移 + 减法"实现（类似长除法，从最高位开始逐位试商）
- 这些都是 CPU ALU 中的基本运算原理

### Q4: 这道题虽然简单，但你能说说 CPU 中的全加器是怎么工作的吗？
**回答**：CPU 的全加器 (Full Adder) 处理三个输入：两个操作数位 A、B，和来自低位的进位 Cin：
- **Sum = A XOR B XOR Cin**（三个输入的异或）
- **Cout = (A AND B) OR (Cin AND (A XOR B))**（任意两个及以上为 1 就产生进位）

多个全加器串联形成**行波进位加法器** (Ripple Carry Adder)，从低位到高位逐级传递进位。缺点是进位传播慢（O(n) 延迟，n 是位数）。

改进方案：**超前进位加法器** (Carry Lookahead Adder)，通过预计算每一位的"生成"和"传播"信号，将进位延迟降到 O(log n)。我们的位运算迭代方法本质上就是在软件层面模拟行波进位加法器——每轮处理一层进位传播。
