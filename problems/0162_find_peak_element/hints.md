# 162. 寻找峰值

## 核心思路

这道题本质上是：**在一个两端为负无穷、相邻元素不等的数组中，找到任意一个"山顶"**。关键洞察是——既然两端是负无穷，数组一定存在峰值；而如果某侧"更高"，那一侧一定存在峰值，这就给了我们二分的依据。

## 思维链

1. **读完题第一反应**：遍历一遍数组，逐个检查每个元素是否比左右邻居都大，找到就返回。这是 O(n) 的线性扫描。

2. **题目要求 O(log n)**：看到 O(log n) 第一反应是二分查找。但数组又没有排序，怎么二分？

3. **关键洞察 — 为什么能二分？** 想象你站在数组的某个位置 `mid`：
   - 如果 `nums[mid] < nums[mid+1]`，说明右边在"上坡"。因为数组最右端是 `-∞`，上坡之后迟早要下来，所以**右半边一定有峰值**。
   - 如果 `nums[mid] > nums[mid+1]`，同理**左半边（含 mid）一定有峰值**。
   - 这就像爬山：朝着更高的方向走，一定能走到某个山顶。

4. **每次排除一半**：无论 mid 在哪，我们都能确定其中一半一定包含峰值，另一半可以安全丢弃。这就是二分的本质——不需要数组有序，只需要能可靠地排除一半搜索空间。

5. **收缩到一个点**：当 `left == right` 时，该点就是峰值。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 线性扫描 | 遍历找第一个"下坡起点" | O(n) | O(1) | 能说出即可 |
| 二分查找 | 朝更高的方向收缩搜索区间 | O(log n) | O(1) | ⭐ 必须写出 |

## 关键提示

1. **为什么一定存在峰值？** `nums[-1] = nums[n] = -∞`，意味着从左端点出发如果一直上升，到右端点之前一定会下降（因为右端点是 `-∞`）。所以数组中一定有峰值。

2. **二分不需要有序，只需要"每次能排除一半"。** 这道题的排除依据是：如果 mid 处在上坡（`nums[mid] < nums[mid+1]`），右边一定有峰值。

3. **比较 `nums[mid]` 和 `nums[mid+1]` 就够了**，不需要同时比较左右两侧。因为我们是在收缩区间，最终区间长度为 1 时自然是峰值。

4. **线性扫描的简化**：不需要同时检查左右邻居。只要找到第一个 `nums[i] > nums[i+1]` 的位置，`i` 就是峰值。（为什么？因为 `nums[-1] = -∞`，从左到右要么一开始就下降，要么一直上升后首次下降的那个点就是峰。）

5. **搜索空间收缩过程示意**：
```
nums = [1, 2, 1, 3, 5, 6, 4]
         0  1  2  3  4  5  6

Round1: left=0, right=6, mid=3
        nums[3]=3 < nums[4]=5 → 右边更高 → left=4
        搜索空间: [4, 5, 6]

Round2: left=4, right=6, mid=5
        nums[5]=6 > nums[6]=4 → 左边更高(含mid) → right=5
        搜索空间: [4, 5]

Round3: left=4, right=5, mid=4
        nums[4]=5 < nums[5]=6 → 右边更高 → left=5
        搜索空间: [5]

left == right == 5 → 返回 5 (nums[5]=6 是峰值)
```

## 解法详解

### 解法1: 线性扫描 — O(n) / O(1)

**思考过程**：最直觉的做法。因为 `nums[-1] = -∞`，数组从左端起步是"上升"的（或者第一个元素本身就是峰值）。我们只需要找到第一个"开始下降"的位置，即 `nums[i] > nums[i+1]`，这个 `i` 就是峰值。

为什么？因为在 `i` 之前，序列一直在上升（否则更早就找到了），所以 `nums[i-1] < nums[i]`；而 `nums[i] > nums[i+1]`，满足峰值定义。如果遍历完都没找到，说明数组一直上升，最后一个元素就是峰值。

```cpp
class Solution {
public:
    int findPeakElement(vector<int>& nums) {
        int n = nums.size();
        for (int i = 0; i < n - 1; i++) {
            // 找到第一个"下降"的位置，它就是峰值
            // 因为从左端(-∞)到 i 一直在上升，i 处首次下降
            if (nums[i] > nums[i + 1]) {
                return i;
            }
        }
        // 整个数组单调递增，最后一个元素是峰值（右端是-∞）
        return n - 1;
    }
};
```

**关键点**：不需要同时检查左右邻居，只检查 `nums[i] > nums[i+1]` 就够了。

---

### 解法2: 二分查找 — O(log n) / O(1) ⭐ 面试首选

**从解法1优化**：线性扫描是 O(n)，题目要求 O(log n)。二分的核心不是数组有序，而是"每次能确定性地排除一半"。

**为什么能二分？** 站在 mid 处：
- `nums[mid] < nums[mid+1]`：mid 到 mid+1 在上坡，而右端是 `-∞`，上坡之后一定会下来 → **右半边一定有峰值** → `left = mid + 1`
- `nums[mid] > nums[mid+1]`：mid 到 mid+1 在下坡，而左端是 `-∞`，类似地 → **左半边（含 mid）一定有峰值** → `right = mid`

```cpp
class Solution {
public:
    int findPeakElement(vector<int>& nums) {
        int left = 0, right = nums.size() - 1;
        
        while (left < right) {
            int mid = left + (right - left) / 2;
            
            if (nums[mid] < nums[mid + 1]) {
                // mid 处在"上坡"，峰值一定在 mid 右侧
                // mid 自己不可能是峰值（因为右邻居比它大）
                left = mid + 1;
            } else {
                // mid 处在"下坡"或是顶点，峰值在 mid 或 mid 左侧
                // mid 可能是峰值，不能排除，所以 right = mid 而不是 mid-1
                right = mid;
            }
        }
        
        // left == right，区间收缩为一个点，就是峰值
        return left;
    }
};
```

**为什么用 `left < right` 而不是 `left <= right`？**
- 我们要找的是一个位置，不是确切值匹配。用 `left < right` 可以让区间自然收缩到一个点。
- 如果用 `left <= right`，当 `left == right` 时还会进入循环，需要额外的终止逻辑。

## 解法对比

| | 线性扫描 | 二分查找 |
|---|---|---|
| 时间复杂度 | O(n) | O(log n) |
| 空间复杂度 | O(1) | O(1) |
| 核心思想 | 找第一个下降点 | 朝更高方向收缩 |
| 面试价值 | 展示理解题意 | 展示二分思维 |
| 适用场景 | 无特殊要求 | 题目要求 O(log n) |

**选择建议**：面试中先说线性扫描证明自己理解了题意，然后主动说"但题目要求 O(log n)，可以用二分"，展示递进思维。

## 易错点

1. **✗ `right = mid - 1`** → **✓ `right = mid`**
   - 当 `nums[mid] > nums[mid+1]` 时，mid 本身可能就是峰值，不能跳过它。如果写成 `right = mid - 1`，可能错过答案。

2. **✗ 比较 `nums[mid]` 和 `nums[mid-1]`** → **✓ 比较 `nums[mid]` 和 `nums[mid+1]`**
   - 比较 `mid` 和 `mid-1` 时，当 `mid=0` 会越界。比较 `mid` 和 `mid+1` 时，因为 `left < right` 保证了 `mid < right`，所以 `mid+1` 不会越界。

3. **✗ 循环条件用 `left <= right`** → **✓ 用 `left < right`**
   - `left <= right` 在 `left == right` 时访问 `nums[mid+1]` 可能越界（如果 `mid == n-1`），而且逻辑上区间只剩一个元素时就该结束了。

4. **✗ 忘记处理数组只有一个元素的情况**
   - 其实不需要特判。`left = 0, right = 0`，直接不进入循环，返回 0，是正确的。

## 面试追问

**Q1: 为什么这道题的数组没有排序，却可以用二分？**
> 二分的本质不是"数组有序"，而是"每次能确定性地排除一半搜索空间"。这里的排除依据是：上坡方向一定存在峰值（因为边界是 `-∞`）。只要有这种二分性质，就能用二分。

**Q2: 如果相邻元素可以相等（去掉 `nums[i] != nums[i+1]` 的限制），还能 O(log n) 吗？**
> 不能。如果允许相等，当 `nums[mid] == nums[mid+1]` 时，无法判断峰值在哪一侧，最坏情况退化为 O(n)。类似于在含重复元素的旋转数组中搜索（LC 81）。

**Q3: 如果要找所有峰值呢？**
> 必须 O(n) 线性扫描，因为峰值可能有 O(n) 个（如锯齿数组 [1,3,1,3,1,3,1]），输出本身就是 O(n)。

**Q4: 能否用这个二分思路解决"旋转有序数组找最小值"（LC 153）？**
> 是的！思路非常相似。LC 153 中，`nums[mid] > nums[right]` 说明最小值在右半边，`nums[mid] < nums[right]` 说明最小值在左半边（含 mid）。核心都是"每次排除一半"。
