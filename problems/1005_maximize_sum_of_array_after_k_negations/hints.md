# 1005. K 次取反后最大化的数组和

## 核心思路

本质上是一个贪心问题：每次取反操作应该让数组总和增加最多（或减少最少），因此优先翻转最小的数（负数中绝对值最大的），用完负数后如果 k 还有剩余，反复翻转绝对值最小的数来消耗 k。

## 思维链

1. **读完题第一反应**：每次可以选一个数取反，做恰好 k 次，要总和最大。朴素想法——每次都挑"取反后收益最大"的数来翻转。
2. **什么数取反收益最大？** 取反一个负数变正数，总和增加 `2 * |nums[i]|`；取反一个正数变负数，总和减少 `2 * nums[i]`。所以应该**优先翻转负数，且从绝对值最大的负数开始翻**。
3. **负数翻完了 k 还有剩余怎么办？** 剩余的 k 次只能翻正数，每次都让总和变小。为了损失最少，应该**反复翻绝对值最小的那个数**。如果剩余 k 是偶数，正负正负抵消，等于没翻；如果是奇数，总和减少 `2 * min_abs`。
4. **实现策略**：排序后从小到大遍历，遇到负数就翻转并消耗一次 k。遍历完后如果 k 还有剩，找当前数组绝对值最小的元素，判断 k 的奇偶即可。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 排序 + 贪心 | 排序后优先翻负数，剩余 k 处理最小绝对值 | O(n log n) | O(1) | ⭐ 必须写出 |
| 最小堆贪心 | 每次弹出最小值取反再放回 | O(k log n) | O(n) | 能说出即可 |
| 计数排序优化 | 利用值域 [-100,100] 做桶排序 | O(n + C) | O(C) | 加分项 |

## 关键提示

1. **为什么优先翻负数？** 翻转一个负数，总和增加 2|x|；翻转一个正数，总和减少 2x。所以翻负数是赚的，翻正数是亏的。
2. **负数要按什么顺序翻？** 绝对值最大的负数最先翻（即排序后最小的数），因为收益 = 2|x|，绝对值越大收益越高。
3. **k 用不完怎么办？** 关键观察：对同一个数翻两次等于没翻。所以剩余 k 如果是偶数就不用管，奇数才需要翻一次——翻当前绝对值最小的数损失最小。
4. **数组中有 0 怎么处理？** 0 取反还是 0，相当于白消耗 k，所以有 0 的话剩余 k 都不用担心。
5. **注意排序后翻转负数的过程中，要动态跟踪绝对值最小的元素**（可能是刚翻转过的负数变成的正数）。

## 解法详解

### 解法1: 排序 + 贪心 — O(n log n) / O(1) ⭐ 面试首选

**思考过程**：

要让总和最大，每次取反应该让总和增量最大。排序后从最小（最负）的数开始翻转，这样收益最高。翻完所有负数后，如果 k 还有剩余，就看奇偶性：偶数无影响，奇数就把当前绝对值最小的数翻一次。

```
排序前: [2, -3, -1, 5, -4],  k = 2
排序后: [-4, -3, -1, 2, 5]

Step1: 翻 -4 → [4, -3, -1, 2, 5], k=1
Step2: 翻 -3 → [4, 3, -1, 2, 5],  k=0
k=0, 停止。总和 = 4+3+(-1)+2+5 = 13
```

```cpp
class Solution {
public:
    int largestSumAfterKNegations(vector<int>& nums, int k) {
        sort(nums.begin(), nums.end());
        
        // 第一步：贪心翻转负数（从最小/最负的开始）
        for (int i = 0; i < nums.size() && k > 0 && nums[i] < 0; i++, k--) {
            nums[i] = -nums[i];
        }
        
        // 第二步：如果 k 还有剩余且为奇数，翻转当前绝对值最小的元素
        // 找当前数组中的最小值（所有负数已翻正，但翻转后的值可能不有序）
        int minVal = *min_element(nums.begin(), nums.end());
        
        int sum = 0;
        for (int x : nums) sum += x;
        
        // k 为偶数：翻两次抵消，无影响
        // k 为奇数：必须翻一次最小值，总和减少 2 * minVal
        if (k % 2 == 1) {
            sum -= 2 * minVal;
        }
        
        return sum;
    }
};
```

**关键点**：翻转负数后数组不再有序，所以不能直接用 `nums[0]` 当最小值，必须用 `min_element` 重新找。

### 解法2: 最小堆贪心 — O(k log n) / O(n)

**思考过程**：

最直觉的贪心——每次取反时，翻转当前最小的数。用最小堆可以 O(log n) 取到最小值。这个方法不需要分析负数/正数/奇偶的各种情况，逻辑最简单。

```
堆: [-4, -3, -1, 2, 5], k=2
Step1: 弹出 -4, 放入 4 → 堆: [-3, -1, 2, 4, 5], k=1
Step2: 弹出 -3, 放入 3 → 堆: [-1, 2, 3, 4, 5], k=0
总和 = -1+2+3+4+5 = 13
```

```cpp
class Solution {
public:
    int largestSumAfterKNegations(vector<int>& nums, int k) {
        // 建小顶堆
        priority_queue<int, vector<int>, greater<int>> pq(nums.begin(), nums.end());
        
        // 每次取出最小值，取反后放回
        while (k-- > 0) {
            int smallest = pq.top();
            pq.pop();
            pq.push(-smallest);
        }
        
        // 求和
        int sum = 0;
        while (!pq.empty()) {
            sum += pq.top();
            pq.pop();
        }
        return sum;
    }
};
```

**关键点**：当 k 很大时（如 10^4），这个方法的时间是 O(k log n)。题目约束下 k ≤ 10^4, n ≤ 10^4，完全够用。但如果 k 极大（如 10^9），这个方法就不行了，必须用解法1 的奇偶分析。

### 解法3: 计数排序优化 — O(n + C) / O(C)，C = 201

**从解法1优化**：值域只有 [-100, 100]，总共 201 个可能值。用计数数组（桶排序思想）可以 O(1) 找到最小值并模拟翻转过程，避免 O(n log n) 的排序。

```cpp
class Solution {
public:
    int largestSumAfterKNegations(vector<int>& nums, int k) {
        // cnt[i+100] 记录值 i 出现的次数，i ∈ [-100, 100]
        int cnt[201] = {};
        for (int x : nums) cnt[x + 100]++;
        
        // 从 -100 到 -1，贪心翻转负数
        for (int val = -100; val < 0 && k > 0; val++) {
            if (cnt[val + 100] > 0) {
                // 能翻转的次数 = min(该值的个数, 剩余k)
                int flip = min(cnt[val + 100], k);
                cnt[val + 100] -= flip;
                cnt[-val + 100] += flip;  // val 取反变 -val
                k -= flip;
            }
        }
        
        // k 还有剩余且为奇数：翻转绝对值最小的数
        if (k % 2 == 1) {
            // 找当前最小的非零绝对值
            for (int val = 0; val <= 100; val++) {
                if (cnt[val + 100] > 0) {
                    cnt[val + 100]--;
                    cnt[-val + 100]++;
                    break;
                }
            }
        }
        
        // 统计总和
        int sum = 0;
        for (int val = -100; val <= 100; val++) {
            sum += val * cnt[val + 100];
        }
        return sum;
    }
};
```

**关键点**：这是利用"值域有限"的性质做的优化。面试中如果面试官问"能否做到 O(n)？"可以给出这个解法。

## 解法对比

| | 排序+贪心 | 最小堆 | 计数排序 |
|---|---|---|---|
| 时间 | O(n log n) | O(k log n) | O(n + C) |
| 空间 | O(1)（原地排序） | O(n) | O(C)，C=201 |
| 代码量 | 中等 | 最少 | 较多 |
| 适用性 | 通用 | k 不太大时 | 值域有限时 |
| 面试推荐 | ⭐ 首选 | 作为思路说明 | 追问优化时给出 |

**排序+贪心**是面试最佳选择：逻辑清晰，空间最优，时间对 Easy 题绰绰有余。

## 易错点

1. **翻转负数后忘记重新找最小值**
   - ✗ `sum -= 2 * nums[0];` — 翻转后数组已不有序，`nums[0]` 不一定最小
   - ✓ `sum -= 2 * *min_element(nums.begin(), nums.end());`

2. **循环条件遗漏 `nums[i] < 0`**
   - ✗ `for (int i = 0; i < n && k > 0; i++) nums[i] = -nums[i];` — 会把已经变正的数又翻回负数
   - ✓ `for (int i = 0; i < n && k > 0 && nums[i] < 0; i++)` — 只翻负数

3. **忘记处理 k 的奇偶性**
   - 把所有负数翻完后还剩 k=5，直接不处理 → 错！剩余奇数次必须翻一次最小值

4. **计数排序解法中 `val=0` 时翻转自己**
   - 0 取反还是 0，所以 `cnt[0+100]--; cnt[0+100]++;` 等于没变，需要从 0 开始找而不是跳过 0（找到 0 时 break 即可，因为翻 0 没损失）

## 面试追问

**Q1: 为什么贪心策略是正确的？能否证明？**
> 翻转负数使总和增加 2|x|，所以翻转绝对值最大的负数收益最高。翻完负数后只剩正数，翻转任何正数都让总和减少，所以翻绝对值最小的损失最低。偶数次翻转同一个数抵消。这三条合起来就是贪心的正确性证明。

**Q2: 如果 k 可以高达 10^9，解法2（最小堆）还能用吗？**
> 不能，O(k log n) 会超时。但解法1 和解法3 不受影响，因为它们把 k 用完负数后只看奇偶，不需要真的执行 k 次操作。

**Q3: 如果数组的值域不是 [-100, 100] 而是 [-10^9, 10^9]，解法3 还能用吗？**
> 不能，计数数组太大。此时解法1（排序+贪心）是最佳方案，O(n log n) 时间，O(1) 空间。

**Q4: 能否用一次排序解决而不需要 `min_element`？**
> 可以。排序后遍历翻负数时，同时维护一个变量 `minAbs` 记录遇到的最小绝对值（包括刚翻转后的值）。这样可以省掉一次 O(n) 扫描，但总时间仍是 O(n log n)。
