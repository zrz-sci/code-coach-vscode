# 2193. 得到回文串的最少操作次数

## 核心思路

本质上是：给定一个字符串，只能相邻交换，求将其变为回文串的最少交换次数。这等价于求**逆序对数**的一种变体——贪心地从两端向中间配对，每次把匹配字符交换到对称位置，累计交换次数。

## 思维链

1. **读完题第一反应**：回文串要求 `s[i] == s[n-1-i]`，我们需要通过相邻交换使所有对称位置配对。相邻交换的最少次数让人联想到"冒泡排序"——冒泡排序的交换次数 = 逆序对数。

2. **暴力思路**：可以尝试所有可能的回文排列，对每种排列计算相邻交换次数（即逆序对数），取最小值。但回文排列数量可能是指数级的，行不通。

3. **关键观察——贪心**：我们不需要枚举所有排列。考虑**从两端向内**处理：固定左指针 `l`，在剩余字符中找到与 `s[l]` 相同的最右边字符 `r`，把 `s[r]` 一步步交换到位置 `n-1-l`。为什么最右边？因为它离目标位置最近，交换次数最少。

4. **特殊情况**：如果 `s[l]` 在剩余区间内没有配对（说明它是奇数次出现的唯一字符），先把它交换到中间附近，最后再处理。或者更简洁地：遇到无配对字符时，先标记，计算它到中间的距离，最后加上。

5. **实现方式 1（双指针模拟）**：直接在字符串上操作，每次从右往左找配对，执行交换，O(n²)。

6. **实现方式 2（BIT 优化）**：用树状数组维护当前可用位置，快速计算交换次数，可以做到 O(n log n)，但对 n ≤ 2000 不是必须的。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 贪心 + 双指针模拟 | 从两端向内，每次找配对并交换到位 | O(n²) | O(n) | ⭐ 必须写出 |
| 贪心 + BIT | 用树状数组优化交换次数计算 | O(n log n) | O(n) | 加分项 |

## 关键提示

1. **贪心方向**：想象左右两个指针从两端向内收缩。对于左端字符 `s[left]`，在 `[left+1, right]` 中**从右往左**找第一个与之匹配的字符，这样配对的代价最小。

2. **奇数字符处理**：如果某个字符只出现奇数次（最多一个），它最终要放在正中间。处理技巧：遇到无配对时，先把该字符换到紧邻位置（swap 一次到中间方向），后续再自然归位——或者更优雅地：遇到无配对时，记录它需要到中间的距离，最后加上。

3. **为什么贪心是最优的？** 关键引理：从两端向内贪心配对，不同字符的配对操作**不会互相干扰**（不存在"先处理 a 导致 b 多交换"的情况），因为我们总是在缩小的窗口内操作。

4. **可视化示例 `"letelt"`**：
```
初始: l e t e l t
      ↑         ↑
      L         R

Step1: s[L]='l', 从R往左找'l' → s[4]='l'
       把s[4]交换到s[5]: l e t e t l  (1次交换)
       ↑       ↑
       L 收缩  R 收缩

Step2: s[L]='e', 从R往左找'e' → s[3]='e'
       把s[3]交换到s[4]: l e t t e l  (1次交换)

总计: 2次
```

5. **和逆序对的关系**：相邻交换次数 = 从原始排列到目标排列的逆序对数。贪心过程本质上是在构造一个目标排列，使得逆序对数最小。

## 解法详解

### 解法1: 贪心 + 双指针模拟 — O(n²) / O(n) ⭐ 面试首选

**思考过程**：回文串要求首尾对称。我用双指针 `left` 和 `right` 从两端开始：
- 对于 `s[left]`，在 `[left+1, right]` 中从右向左找第一个相同字符 `k`
- 如果找到了（`k != left`），把 `s[k]` 通过相邻交换移到 `right` 位置，累计 `right - k` 次交换，然后 `left++, right--`
- 如果没找到（`k == left`，说明这个字符是奇数次的），把它往右换一步（`swap(s[left], s[left+1])`），`moves++`，`left` 不动重新处理

```cpp
class Solution {
public:
    int minMovesToMakePalindrome(string s) {
        int n = s.size();
        int moves = 0;
        int left = 0, right = n - 1;
        
        while (left < right) {
            // 从右往左找与 s[left] 匹配的字符
            int k = right;
            while (k > left && s[k] != s[left]) {
                k--;
            }
            
            if (k == left) {
                // 没找到配对 → 这是奇数次字符，先交换一步往中间推
                swap(s[left], s[left + 1]);
                moves++;
                // 不移动 left，下一轮重新处理
            } else {
                // 找到配对，把 s[k] 交换到 right 位置
                while (k < right) {
                    swap(s[k], s[k + 1]);
                    k++;
                    moves++;
                }
                left++;
                right--;
            }
        }
        
        return moves;
    }
};
```

**关键点**：
- 奇数字符的处理：不直接计算到中间的距离，而是"推一步"让它自然归位，这样后续处理中它会被逐步推到中间。
- 为什么 `k == left` 时只交换一步？因为我们不知道最终中间位置在哪（随着其他交换会变化），每次推一步是最安全的贪心选择。

### 解法2: 贪心 + BIT (树状数组) — O(n log n) / O(n)

**从解法1优化**：解法1每次配对后要真的执行 O(n) 次交换来移动字符，导致总共 O(n²)。能不能只**计算**需要多少次交换，而不真的移动？

核心思路：
1. 预处理每个字符出现的所有位置（用队列存储）
2. 从两端贪心决定配对关系，得到一个"目标排列"
3. 用树状数组计算从原排列到目标排列的逆序对数（即最少相邻交换次数）

```cpp
class Solution {
public:
    // 树状数组
    vector<int> bit;
    int n;
    
    void update(int i, int val) {
        for (; i <= n; i += i & (-i))
            bit[i] += val;
    }
    
    int query(int i) {
        int s = 0;
        for (; i > 0; i -= i & (-i))
            s += bit[i];
        return s;
    }
    
    int minMovesToMakePalindrome(string s) {
        n = s.size();
        
        // 为每个字符记录出现的索引（从后往前入队，这样队头是最右边的）
        deque<int> pos[26];
        for (int i = 0; i < n; i++) {
            pos[s[i] - 'a'].push_back(i);
        }
        
        // 贪心构造目标排列：target[i] = 原始位置 i 的字符应该去的目标位置
        vector<int> target(n, -1);
        int lo = 0, hi = n - 1;
        
        // 从两端向内配对
        // 使用一个标记数组表示哪些位置已经被配对
        vector<bool> used(n, false);
        int midPos = -1; // 奇数字符放中间
        
        // 换一种思路：直接从两端贪心配对构造排列映射
        // 用 left/right 指针模拟，但不真正交换
        // 这个方法比较复杂，我们用更直观的方式：
        
        // 方法：用贪心确定配对关系，然后计算逆序对
        // 对于每对 (i, j) 配对 → 位置 i 去 left_slot, 位置 j 去 right_slot
        
        vector<int> perm(n);
        int leftSlot = 0, rightSlot = n - 1;
        
        // 重新用队列方式处理
        deque<int> indices[26];
        for (int i = 0; i < n; i++) {
            indices[s[i] - 'a'].push_back(i);
        }
        
        used.assign(n, false);
        int oddChar = -1;
        
        // 从左往右扫描，遇到未配对的字符，找它的配对
        vector<pair<int,int>> pairs; // (pos1, pos2) 配对
        
        for (int c = 0; c < 26; c++) {
            auto& dq = indices[c];
            while (dq.size() >= 2) {
                int front = dq.front(); dq.pop_front();
                int back = dq.back(); dq.pop_back();
                pairs.push_back({front, back});
            }
            if (!dq.empty()) {
                midPos = dq.front(); dq.pop_front();
            }
        }
        
        // 按照 front 排序 → 这些配对从外到内排
        sort(pairs.begin(), pairs.end());
        
        // 分配目标位置
        leftSlot = 0; rightSlot = n - 1;
        for (auto& [a, b] : pairs) {
            // a 去 leftSlot, b 去 rightSlot
            perm[a] = leftSlot++;
            perm[b] = rightSlot--;
        }
        if (midPos != -1) {
            perm[midPos] = n / 2;
        }
        
        // 计算 perm 的逆序对数 = 最少相邻交换次数
        bit.assign(n + 2, 0);
        long long moves = 0;
        for (int i = n - 1; i >= 0; i--) {
            moves += query(perm[i]); // 在 perm[i] 之前有多少个比它小的已插入
            update(perm[i] + 1, 1); // BIT 是 1-indexed
        }
        
        return (int)moves;
    }
};
```

**注意**：这个 BIT 解法的核心难点在于正确构造配对关系和目标排列。面试中通常解法1的 O(n²) 就足够了（n ≤ 2000）。

## 易错点

1. **奇数字符处理遗漏**：
   - ✗ 遇到 `k == left` 时直接 `left++`（跳过了）→ 结果错误
   - ✓ 遇到 `k == left` 时 `swap(s[left], s[left+1]); moves++;` 不移动 left

2. **内层循环方向搞反**：
   - ✗ 从 `left+1` 向右找配对 → 可能找到离 `right` 更远的，导致交换次数不是最少
   - ✓ 从 `right` 向左找配对 → 找到的字符离目标位置最近

3. **交换后忘记更新双指针**：
   - ✗ 配对成功后只 `right--` 忘了 `left++`
   - ✓ 配对成功后 `left++; right--` 都要移动

4. **字符串长度为1**：
   - 直接返回 0，循环条件 `left < right` 已经处理

## 面试追问

**Q1: 为什么贪心策略是最优的？每次从右找最近的配对，不会影响后续的最优选择吗？**

> 关键引理：对于"相邻交换使之回文"问题，贪心地从外向内配对是最优的。直觉：外层字符不管怎么排都要到两端，先处理它们不会增加内层字符的移动距离。形式化证明可以用交换论证（exchange argument）：如果存在更优方案不先配对外层，可以证明调整为先配对外层不会更差。

**Q2: 如果 n 非常大（比如 10⁶），O(n²) 过不了，怎么优化？**

> 用 BIT（树状数组）。先贪心确定配对关系，构造一个目标排列，然后计算原排列到目标排列的逆序对数（用归并排序或树状数组都行），就是最少交换次数。总复杂度 O(n log n)。

**Q3: 如果不保证输入能构成回文，如何判断并处理？**

> 统计字符频次。如果奇数频次的字符 > 1（偶数长度时要求全部偶数频次），则无法构成回文。判断后，剩余逻辑不变。
