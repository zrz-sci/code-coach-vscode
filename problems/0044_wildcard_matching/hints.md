# 44. 通配符匹配

## 核心思路

本质上是一个**双序列匹配问题**：两个字符串 `s` 和 `p` 从左到右逐步匹配，难点在于 `*` 可以匹配任意长度的序列——这意味着遇到 `*` 时我们不知道它该"吃掉"多少字符，需要尝试所有可能。

## 思维链

1. **读完题第一反应**：逐字符匹配，`?` 简单（匹配任意一个），`*` 麻烦（匹配 0 到多个）。遇到 `*` 时，可以递归尝试"匹配 0 个字符"、"匹配 1 个字符"、"匹配 2 个字符"……→ 暴力递归。

2. **暴力递归的瓶颈**：一个 `*` 可能尝试匹配 0~n 个字符，多个 `*` 组合起来分支爆炸。但仔细看递归参数只有 `(i, j)` 两个指针，状态空间只有 O(m×n)，说明有大量重叠子问题 → 可以记忆化。

3. **记忆化 → 递推 DP**：定义 `dp[i][j]` = "s 的前 i 个字符能否被 p 的前 j 个字符匹配"。状态转移清晰：
   - `p[j-1]` 是普通字符或 `?`：看 `dp[i-1][j-1]`
   - `p[j-1]` 是 `*`：要么 `*` 匹配空（`dp[i][j-1]`），要么 `*` 至少匹配一个（`dp[i-1][j]`）

4. **空间优化**：DP 表每行只依赖上一行和当前行左边 → 可以压缩到一维滚动数组。

5. **还有更快的方法吗？** 贪心 + 双指针：遇到 `*` 时记住位置，先假设匹配 0 个字符继续走；如果后面匹配失败，回到 `*` 的位置让它多匹配一个字符。这个方法 O(m×n) 最坏但实际非常快，且 O(1) 空间。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力递归 | 遇到 `*` 枚举匹配长度 | O(2^(m+n)) 最坏 | O(m+n) 栈 | 能说出即可 |
| 记忆化搜索 | 递归 + memo | O(m×n) | O(m×n) | 能说出即可 |
| 二维 DP | 填 dp 表 | O(m×n) | O(m×n) | ⭐ 必须写出 |
| 一维 DP (空间优化) | 滚动数组 | O(m×n) | O(n) | 加分项 |
| 贪心双指针 | `*` 回溯 | O(m×n) 最坏 | O(1) | 加分项 |

> m = len(s), n = len(p)

## 关键提示

1. **`*` 的转移是关键**：`*` 匹配空序列 = "跳过这个 `*`"（看 `dp[i][j-1]`）；`*` 至少匹配一个字符 = "消耗 s 的一个字符但 `*` 还在"（看 `dp[i-1][j]`）。不需要枚举 `*` 匹配了多少个，这两种情况就覆盖了所有可能。

2. **初始化陷阱**：`dp[0][j]` 表示空串 s 能否被 p 的前 j 个字符匹配。只有当 p 的前 j 个字符全是 `*` 时才为 true。

3. **贪心双指针的核心**：只需记住最后一个 `*` 的位置。匹配失败时回溯到这个 `*`，让它多吃一个字符。

4. **和 LeetCode 10（正则匹配）的区别**：10 中 `*` 修饰前一个字符（`a*` = 0 或多个 a），这里 `*` 是独立的通配符。转移方程不同！

5. **DP 填表方向示意**：
```
      ""  *  a  *  b
  ""   T  T  F  F  F
  a    F  T  T  T  F
  d    F  T  F  T  F
  c    F  T  F  T  F
  e    F  T  F  T  F
  b    F  T  F  T  T
       ↑
  dp[i][j] 依赖 dp[i-1][j-1]（左上）、dp[i][j-1]（左）、dp[i-1][j]（上）
```

## 解法详解

### 解法1: 暴力递归 — O(2^(m+n)) / O(m+n)

**思考过程**：最直觉的方式——用两个指针 i、j 分别指向 s 和 p，逐字符匹配。遇到 `*` 时，递归尝试让 `*` 匹配 0 个字符（j+1）或至少匹配 1 个字符（i+1）。

```cpp
class Solution {
public:
    bool isMatch(string s, string p) {
        return dfs(s, p, 0, 0);
    }

private:
    bool dfs(const string& s, const string& p, int i, int j) {
        // 两个都走完了，匹配成功
        if (j == (int)p.size()) return i == (int)s.size();
        
        if (p[j] == '*') {
            // * 匹配空序列: 跳过 *
            // * 至少匹配一个: 消耗 s[i]，* 还在
            return dfs(s, p, i, j + 1) || 
                   (i < (int)s.size() && dfs(s, p, i + 1, j));
        }
        
        // 普通字符或 ?
        if (i < (int)s.size() && (p[j] == '?' || s[i] == p[j])) {
            return dfs(s, p, i + 1, j + 1);
        }
        return false;
    }
};
```

**关键点**：这个解法在多个连续 `*` 的情况下会指数爆炸。但它清晰展示了问题的递归结构，是后续优化的基础。

### 解法2: 记忆化搜索 — O(m×n) / O(m×n)

**从解法1优化**：递归参数只有 `(i, j)`，范围分别是 `[0, m]` 和 `[0, n]`，最多 (m+1)×(n+1) 个状态。加一个 memo 数组消除重复计算。

```cpp
class Solution {
public:
    bool isMatch(string s, string p) {
        int m = s.size(), n = p.size();
        // 0 = 未计算, 1 = true, -1 = false
        vector<vector<int>> memo(m + 1, vector<int>(n + 1, 0));
        return dfs(s, p, 0, 0, memo);
    }

private:
    bool dfs(const string& s, const string& p, int i, int j, 
             vector<vector<int>>& memo) {
        if (memo[i][j] != 0) return memo[i][j] == 1;
        
        bool res;
        if (j == (int)p.size()) {
            res = (i == (int)s.size());
        } else if (p[j] == '*') {
            res = dfs(s, p, i, j + 1, memo) || 
                  (i < (int)s.size() && dfs(s, p, i + 1, j, memo));
        } else if (i < (int)s.size() && (p[j] == '?' || s[i] == p[j])) {
            res = dfs(s, p, i + 1, j + 1, memo);
        } else {
            res = false;
        }
        
        memo[i][j] = res ? 1 : -1;
        return res;
    }
};
```

**关键点**：memo 用 int 而不是 bool，因为需要区分"未计算"和"计算结果为 false"。

### 解法3: 二维 DP — O(m×n) / O(m×n) ⭐ 面试首选

**从记忆化翻译成递推**：把递归自顶向下改成循环自底向上。

**状态定义**：`dp[i][j]` = s 的前 i 个字符能否被 p 的前 j 个字符完全匹配。

**状态转移**：
- `p[j-1]` 是字母或 `?`：`dp[i][j] = dp[i-1][j-1] && (p[j-1]=='?' || s[i-1]==p[j-1])`
- `p[j-1]` 是 `*`：`dp[i][j] = dp[i][j-1] || dp[i-1][j]`
  - `dp[i][j-1]`：`*` 匹配空序列
  - `dp[i-1][j]`：`*` 至少吃掉 s 的一个字符（`*` 还保留继续吃）

```
// DP 填表示例: s = "adceb", p = "*a*b"
//
//        ""   *    a    *    b
//   ""  [ T] [ T] [ F] [ F] [ F]
//    a  [ F] [ T] [ T] [ T] [ F]
//    d  [ F] [ T] [ F] [ T] [ F]
//    c  [ F] [ T] [ F] [ T] [ F]
//    e  [ F] [ T] [ F] [ T] [ F]
//    b  [ F] [ T] [ F] [ T] [ T] ← 答案
//
// 填表方向: 从左到右，从上到下
// dp[i][j] 依赖: 左上 dp[i-1][j-1], 上 dp[i-1][j], 左 dp[i][j-1]
```

```cpp
class Solution {
public:
    bool isMatch(string s, string p) {
        int m = s.size(), n = p.size();
        // dp[i][j]: s的前i个 vs p的前j个 是否匹配
        vector<vector<bool>> dp(m + 1, vector<bool>(n + 1, false));
        
        // base case: 空串 vs 空模式
        dp[0][0] = true;
        
        // base case: 空串 vs p的前j个（只有全是*才能匹配空串）
        for (int j = 1; j <= n; j++) {
            dp[0][j] = (p[j - 1] == '*') && dp[0][j - 1];
        }
        
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                if (p[j - 1] == '*') {
                    // * 匹配空 || * 至少吃一个字符
                    dp[i][j] = dp[i][j - 1] || dp[i - 1][j];
                } else {
                    // 普通字符或 ? 必须当前字符匹配，且前缀也匹配
                    dp[i][j] = dp[i - 1][j - 1] && 
                               (p[j - 1] == '?' || s[i - 1] == p[j - 1]);
                }
            }
        }
        
        return dp[m][n];
    }
};
```

**关键点**：初始化 `dp[0][j]` 时，连续的 `*` 都为 true，一旦遇到非 `*` 就全部为 false。

### 解法4: 一维 DP (空间优化) — O(m×n) / O(n)

**从解法3优化**：`dp[i][j]` 只依赖上一行 `dp[i-1][...]` 和当前行左边 `dp[i][j-1]`，因此可以用一维数组滚动。

```cpp
class Solution {
public:
    bool isMatch(string s, string p) {
        int m = s.size(), n = p.size();
        vector<bool> dp(n + 1, false);
        dp[0] = true;
        
        // 初始化第0行: 空串 vs p 的前j个
        for (int j = 1; j <= n; j++) {
            dp[j] = (p[j - 1] == '*') && dp[j - 1];
        }
        
        for (int i = 1; i <= m; i++) {
            // prev 保存的是 dp[i-1][j-1]，即"左上角"
            bool prev = dp[0];
            dp[0] = false;  // 非空串 vs 空模式 = false
            
            for (int j = 1; j <= n; j++) {
                bool temp = dp[j]; // 保存旧的 dp[j]（即上一行的 dp[i-1][j]）
                if (p[j - 1] == '*') {
                    // dp[i][j-1] = dp[j-1]（当前行左边，已更新）
                    // dp[i-1][j] = dp[j]（上一行，尚未更新，就是 temp）
                    dp[j] = dp[j - 1] || temp;
                } else {
                    // dp[i-1][j-1] = prev
                    dp[j] = prev && (p[j - 1] == '?' || s[i - 1] == p[j - 1]);
                }
                prev = temp; // 为下一轮准备"左上角"
            }
        }
        
        return dp[n];
    }
};
```

**关键点**：`prev` 变量保存的是更新前的 `dp[j]`，也就是二维版本中的 `dp[i-1][j-1]`。每次进入内层循环前要先保存，更新后要传递。

### 解法5: 贪心双指针 — O(m×n) 最坏 / O(1)

**完全不同的思路**：不用 DP，用两个指针 i、j 分别扫描 s 和 p。遇到 `*` 时，记住这个 `*` 的位置和 s 当前位置，先假设 `*` 匹配 0 个字符继续走。如果后面匹配失败，回溯到上次的 `*` 位置，让它多匹配一个字符。

**为什么贪心是对的？** 关键洞察：我们只需要记住**最后一个** `*` 的位置。如果有多个 `*`，前面的 `*` 匹配多少字符已经在前面的尝试中确定了，匹配失败时只需要调整最后一个 `*` 的匹配长度。

```
// 贪心过程示例: s = "adceb", p = "*a*b"
//
// i=0,j=0: p[j]='*' → 记录 starJ=0, matchI=0, j=1
// i=0,j=1: p[j]='a', s[i]='a' → 匹配! i=1, j=2
// i=1,j=2: p[j]='*' → 记录 starJ=2, matchI=1, j=3
// i=1,j=3: p[j]='b', s[i]='d' → 不匹配! 回溯: matchI=2, i=2, j=3
// i=2,j=3: p[j]='b', s[i]='c' → 不匹配! 回溯: matchI=3, i=3, j=3
// i=3,j=3: p[j]='b', s[i]='e' → 不匹配! 回溯: matchI=4, i=4, j=3
// i=4,j=3: p[j]='b', s[i]='b' → 匹配! i=5, j=4
// i=5: s 扫完, 检查 p 剩余是否全是 * → j=4=n, 全部匹配完 → true
```

```cpp
class Solution {
public:
    bool isMatch(string s, string p) {
        int m = s.size(), n = p.size();
        int i = 0, j = 0;
        int starJ = -1;   // 最后一个 * 在 p 中的位置
        int matchI = -1;   // 遇到该 * 时 s 的位置
        
        while (i < m) {
            if (j < n && (p[j] == '?' || s[i] == p[j])) {
                // 普通匹配：两个指针都前进
                i++;
                j++;
            } else if (j < n && p[j] == '*') {
                // 遇到 *：记录位置，先假设匹配 0 个字符
                starJ = j;
                matchI = i;
                j++;  // 跳过 *，i 不动（* 匹配 0 个）
            } else if (starJ != -1) {
                // 匹配失败但之前有 *：让 * 多吃一个字符
                matchI++;
                i = matchI;
                j = starJ + 1;  // 从 * 后面重新开始匹配
            } else {
                // 无法匹配且没有 * 可以回溯
                return false;
            }
        }
        
        // s 扫完了，p 剩下的必须全是 *
        while (j < n && p[j] == '*') j++;
        return j == n;
    }
};
```

**关键点**：
- `starJ` 和 `matchI` 只记录**最后一个** `*` 的信息，每次遇到新 `*` 就覆盖。
- 回溯时 `j = starJ + 1` 而不是 `starJ`，因为 `*` 本身不需要重新处理。
- 最后要检查 p 的剩余部分是否全为 `*`。

## 易错点

1. **`dp[0][j]` 初始化遗漏**
   - ✗ 只设 `dp[0][0] = true`，其他默认 false → `p = "***"` 匹配空串 s 会返回 false
   - ✓ 遍历 p，只要前缀全是 `*` 就设为 true：`dp[0][j] = (p[j-1]=='*') && dp[0][j-1]`

2. **`*` 转移方程写错**
   - ✗ `dp[i][j] = dp[i-1][j-1]`（把 `*` 当成 `?` 了，只匹配一个字符）
   - ✓ `dp[i][j] = dp[i][j-1] || dp[i-1][j]`（空匹配 or 至少吃一个）

3. **一维 DP 忘记更新 `dp[0]`**
   - ✗ 忘记在每行开头设 `dp[0] = false` → 从第二行开始 `dp[0]` 还是 true
   - ✓ 每行 `dp[0] = false`（非空串不可能被空模式匹配）

4. **贪心解法忘记最后检查 p 的尾部**
   - ✗ s 扫完直接返回 true → `s="a"`, `p="a*b"` 会返回 true
   - ✓ 还需检查 p 剩余部分是否全为 `*`

5. **混淆本题 `*` 和 LeetCode 10 正则 `*`**
   - 本题 `*` 独立匹配任意序列，10 中 `*` 是量词修饰前一个字符
   - 转移方程完全不同！

## 面试追问

**Q1: 你能先写一个暴力解吗？瓶颈在哪？**
→ 暴力递归，遇到 `*` 分两支。瓶颈：多个 `*` 导致指数级分支。但状态空间只有 O(mn)，说明有大量重叠子问题。

**Q2: DP 方程中 `*` 为什么只需要两种情况就覆盖了所有匹配长度？**
→ `dp[i-1][j]` 表示 `*` 至少吃一个字符。由于 `*` 还保留在模式中，下一行还能继续通过 `dp[i-1][j]` 再吃一个。数学归纳：`dp[i][j]` 为 true 当且仅当存在某个 k (0≤k≤i) 使得 `dp[i-k][j-1]` 为 true。

**Q3: 能否 O(1) 空间？**
→ 贪心双指针。核心思想是只需记住最后一个 `*` 的位置，匹配失败时回溯让 `*` 多吃一个。正确性：如果存在匹配方案，贪心策略一定能找到（因为 `*` 匹配越少字符越好，失败时再贪心增加）。

**Q4: 和 LeetCode 10 (Regular Expression Matching) 有什么区别？**
→ 10 的 `*` 是量词（修饰前一个字符），本题的 `*` 是独立通配符。10 中 `a*` 匹配 0 或多个 `a`，本题 `*` 直接匹配任意序列。DP 转移不同：10 的 `*` 转移涉及 `dp[i][j-2]`（跳过字符+量词），本题是 `dp[i][j-1]` 和 `dp[i-1][j]`。

## 相关题型

- **LeetCode 10 正则表达式匹配** — 同样是双序列 DP 匹配框架，但 `*` 语义不同。本题 `*` 的转移是 `dp[i][j-1] || dp[i-1][j]`，10 的 `.` `*` 转移涉及 `dp[i][j-2]`。搞清楚两者区别后都不难。
- **LeetCode 72 编辑距离** — 同样的二维 DP 框架（两个字符串，dp[i][j] 依赖左上/上/左），可以复用填表和空间优化的技巧。
- **LeetCode 1143 最长公共子序列** — 双序列 DP 的基础题，建议先做这个建立 dp[i][j] 二维匹配的直觉。
- **LeetCode 115 不同的子序列** — 同为双序列匹配 DP，dp[i][j] 定义和转移思路类似。
