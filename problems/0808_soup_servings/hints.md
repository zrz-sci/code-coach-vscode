# 808. 分汤

## 核心思路

这是一道**概率 DP + 数学剪枝**题。把汤量除以 25 简化为单位操作，用记忆化搜索计算 `f(a, b)` 表示"A 剩 a 份、B 剩 b 份时，A 先用完的概率 + 0.5 * 同时用完的概率"。关键剪枝：当 n 足够大（>= 4800），答案无限趋近于 1，直接返回 1.0。

## 思维链

1. **读完题第一反应**：四种操作每次等概率选一种，每种从 A 倒出的量分别是 100/75/50/25，从 B 倒出的是 0/25/50/75。A 平均每次倒 62.5mL，B 平均每次倒 37.5mL，所以 A 用完的概率天然大于 B。

2. **简化单位**：所有操作量都是 25 的倍数，可以除以 25 转换为 (4,0), (3,1), (2,2), (1,3) 四种操作。这样 n 变小，DP 状态数减少。

3. **DP 定义**：`f(a, b)` = A 剩 a 份、B 剩 b 份时的目标概率。递推关系：
   ```
   f(a, b) = 0.25 * [f(a-4, b) + f(a-3, b-1) + f(a-2, b-2) + f(a-1, b-3)]
   ```
   
4. **边界条件**：
   - `a <= 0 && b <= 0`：同时用完，返回 0.5
   - `a <= 0 && b > 0`：A 先用完，返回 1.0
   - `a > 0 && b <= 0`：B 先用完，返回 0.0

5. **大 n 剪枝**：n 最大可达 10^9，直接 DP 不可行。但当 n >= 4800（即 192 份），A 先用完的概率已经大于 1 - 10^-5，直接返回 1.0 即可满足精度要求。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 记忆化搜索 + 剪枝 | 除以 25 简化状态，大 n 直接返回 1.0 | O(k^2) k=n/25 | O(k^2) | ⭐ 必须写出 |
| 自底向上 DP | 同上思路的迭代版本 | O(k^2) | O(k^2) | 可选 |

> 面试重点在于：(1) 识别出除以 25 简化状态的技巧；(2) 意识到大 n 时需要剪枝并解释为什么概率趋近 1。

## 关键提示

1. **所有操作量都是 25 的倍数** -- 除以 25 是简化问题的关键步骤。注意要向上取整：`n = ceil(n / 25.0)` 或 `n = (n + 24) / 25`。

2. **A 平均消耗更快** -- 四种操作中 A 的消耗量 (4,3,2,1) 平均为 2.5，B 的消耗量 (0,1,2,3) 平均为 1.5。这解释了为什么 A 先用完的概率更大。

3. **n 很大时概率趋近 1** -- 由于 A 消耗速度的统计优势，n 越大这个优势越明显。经计算 n >= 4800 时精度已满足。

4. 小例子验证：
```
n = 50, 即 2 份
f(2,2) = 0.25 * [f(-2,2) + f(-1,1) + f(0,0) + f(1,-1)]
       = 0.25 * [  1.0    +   1.0   +  0.5   +   0.0  ]
       = 0.625 ✓
```

## 解法详解

### 解法1: 记忆化搜索 + 大 n 剪枝 -- O(k^2) / O(k^2) ⭐ 面试首选

**思考过程**：

将 n 除以 25 转换为"份数"后，用记忆化搜索计算概率。当 n >= 4800 时直接返回 1.0（数学剪枝）。

```cpp
class Solution {
public:
    unordered_map<int, double> memo;
    
    double soupServings(int n) {
        // 大 n 剪枝：概率已非常接近 1
        if (n >= 4800) return 1.0;
        
        // 除以 25，向上取整
        n = (n + 24) / 25;
        return dfs(n, n);
    }
    
    double dfs(int a, int b) {
        // 边界条件
        if (a <= 0 && b <= 0) return 0.5; // 同时用完
        if (a <= 0) return 1.0;            // A 先用完
        if (b <= 0) return 0.0;            // B 先用完
        
        int key = a * 200 + b; // 编码状态
        if (memo.count(key)) return memo[key];
        
        // 四种操作等概率
        memo[key] = 0.25 * (
            dfs(a - 4, b) +      // 操作1: A倒100, B倒0
            dfs(a - 3, b - 1) +  // 操作2: A倒75,  B倒25
            dfs(a - 2, b - 2) +  // 操作3: A倒50,  B倒50
            dfs(a - 1, b - 3)    // 操作4: A倒25,  B倒75
        );
        
        return memo[key];
    }
};
```

**关键点**：
- `(n + 24) / 25` 是整数向上取整除法的技巧。
- 状态编码 `a * 200 + b`，因为 4800/25 = 192 < 200，所以不会冲突。
- 剪枝阈值 4800 是经验值，可以通过二分查找精确确定。

## 易错点

1. **忘记大 n 剪枝导致 TLE/MLE**：
   - ✗ 直接对 n = 10^9 建 DP 表
   - ✓ n >= 4800 时直接返回 1.0

2. **向上取整写错**：
   - ✗ `n = n / 25`（向下取整，50mL 变成 2 份，但应该考虑不能整除的情况）
   - ✓ `n = (n + 24) / 25`（向上取整）

3. **边界条件顺序错误**：
   - ✗ 先判断 `a <= 0` 再判断 `a <= 0 && b <= 0`（同时用完的情况被抢先匹配）
   - ✓ 先判断同时用完（`a <= 0 && b <= 0`），再分别判断

4. **状态编码冲突**：
   - ✗ 用 `a * 100 + b` 编码（当 b >= 100 时与更大的 a 冲突）
   - ✓ 用 `a * 200 + b` 或 `pair<int,int>` 避免冲突

## 面试追问

**Q1: 为什么选 4800 作为剪枝阈值？能否严格推导？**

> 当 n = 4800 时，份数为 192。由于 A 每轮平均消耗 2.5 份而 B 只消耗 1.5 份，经过足够多轮次后，A 先用完的概率按照中心极限定理会趋近于 1。具体地，可以二分查找满足 `f(k,k) >= 1 - 1e-5` 的最小 k，实测大约在 k=179 即 n=4475。取 4800 留有余量。

**Q2: 如果操作不是等概率而是有不同权重，怎么改？**

> 将 `0.25 * (...)` 改为各操作概率的加权求和 `p1*f(a-4,b) + p2*f(a-3,b-1) + ...`。剪枝阈值需要重新计算，取决于 A 和 B 消耗量的期望差异。如果 A 和 B 期望消耗相同，则概率趋近于 0.5，不能剪枝。

**Q3: 能否用自底向上 DP 替代记忆化搜索？有什么注意点？**

> 可以。用二维数组 `dp[a][b]` 从边界开始填表。注意 a-4 可能为负，需要用 `max(0, a-4)` 而非直接下标访问。自底向上避免了递归开销，但代码稍复杂一些。
