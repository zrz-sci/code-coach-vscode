# 75. 颜色分类

## 核心思路

本质上是对一个只包含 3 种值（0, 1, 2）的数组进行原地排序。因为值域极小（只有 3 种），我们不需要通用排序算法，可以利用值域有限这个特性，用远比 O(n log n) 更高效的方式完成。

## 思维链

1. **读完题第一反应**：这不就是排序吗？直接调 sort 就行 —— 但题目说了不能用库函数。那自己写个排序？O(n log n)。但等等，值只有 0、1、2 三种，通用排序是不是杀鸡用牛刀了？

2. **利用值域有限**：只有 3 种值，那我先数一下有多少个 0、多少个 1、多少个 2，然后直接按数量覆盖回数组不就行了？这就是**计数排序**的思路，两趟扫描（一趟计数，一趟填充），O(n) 时间。

3. **能不能只扫描一趟？** Follow-up 要求一趟扫描 + O(1) 空间。想象三个区域：左边全放 0，中间放 1，右边放 2。如果我们能在一趟遍历中把每个元素"归位"到正确区域，就实现了一趟排序。

4. **三指针分区（荷兰国旗问题）**：用三个指针 `lo`、`mid`、`hi` 分别维护 0 区域的右边界、当前遍历位置、2 区域的左边界。遍历时：遇到 0 往左边换，遇到 2 往右边换，遇到 1 跳过。这就是 Dijkstra 提出的经典**荷兰国旗算法**。

5. **为什么三指针不会漏？** `mid` 从左到右扫描，每次操作后要么 `mid` 前进，要么 `hi` 后退，所以 `[mid, hi]` 这个"未处理区间"在不断缩小，当 `mid > hi` 时所有元素都已归位。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 计数排序 | 两趟扫描：先计数再填充 | O(n) | O(1) | 能说出即可 |
| 两趟双指针 | 第一趟把 0 移到前面，第二趟把 1 移到前面 | O(n) | O(1) | 能说出即可 |
| 荷兰国旗（三指针） | 一趟扫描，三路分区 | O(n) | O(1) | ⭐ 必须写出 |

## 关键提示

1. **值域极小是关键信息**：只有 3 种值，意味着我们可以做到比 O(n log n) 更好。思考：如果值有 k 种，你会怎么做？

2. **三指针的不变量**：任何时刻，`[0, lo)` 全是 0，`[lo, mid)` 全是 1，`(hi, n-1]` 全是 2，`[mid, hi]` 是未处理区间。画出来！

3. **遇到 2 换过来的元素还没看过**：从 `hi` 换过来的值可能是 0、1 或 2，所以换完 `mid` 不能前进！但遇到 0 从 `lo` 换过来的值一定是 1（因为 `lo` 到 `mid` 之间只有 1），所以 `mid` 可以前进。

4. **ASCII 示意图 — 三指针分区**：
```
数组状态的不变量:
[0 0 0 | 1 1 1 | ? ? ? | 2 2 2]
       ↑       ↑       ↑
      lo      mid      hi

lo 左边全是 0
lo~mid 之间全是 1
mid~hi 之间是未处理
hi 右边全是 2
```

5. **与快排 partition 的关系**：荷兰国旗本质是三路快排的 partition 步骤（以 1 为 pivot 做三路分区）。学会这题，快排的三路分区你也就会了。

## 解法详解

### 解法1: 计数排序 — O(n) / O(1)

**思考过程**：值只有 0、1、2 三种。最朴素的利用方式：数一下各有多少个，然后直接按数量覆盖。这是"计数排序"的核心思想。

```cpp
class Solution {
public:
    void sortColors(vector<int>& nums) {
        int count[3] = {0, 0, 0};
        
        // 第一趟：统计每种颜色的数量
        for (int num : nums) {
            count[num]++;
        }
        
        // 第二趟：按顺序覆盖
        int idx = 0;
        for (int color = 0; color < 3; color++) {
            for (int i = 0; i < count[color]; i++) {
                nums[idx++] = color;
            }
        }
    }
};
```

**关键点**：
- 需要两趟扫描，不满足 Follow-up 的一趟要求
- 但代码最简单，面试中可以作为第一版快速给出

### 解法2: 两趟双指针 — O(n) / O(1)

**思考过程**：换个角度，第一趟把所有 0 交换到数组前部，第二趟把所有 1 交换到 0 后面。每趟就是一个简单的 partition 操作。

```cpp
class Solution {
public:
    void sortColors(vector<int>& nums) {
        int n = nums.size();
        int ptr = 0;
        
        // 第一趟：把所有 0 移到前面
        for (int i = 0; i < n; i++) {
            if (nums[i] == 0) {
                swap(nums[i], nums[ptr]);
                ptr++;
            }
        }
        
        // 第二趟：从 ptr 开始，把所有 1 移到 0 后面
        // （此时 ptr 指向第一个非 0 的位置）
        for (int i = ptr; i < n; i++) {
            if (nums[i] == 1) {
                swap(nums[i], nums[ptr]);
                ptr++;
            }
        }
    }
};
```

**关键点**：
- 本质是做了两次"把特定值移到前面"的操作
- 还是两趟，但思路为解法3铺垫——如果能同时维护两个边界，就能一趟完成

### 解法3: 荷兰国旗（三指针） — O(n) / O(1) ⭐ 面试首选

**从解法2优化**：解法2分别处理 0 和 1 需要两趟。能不能一趟同时处理？用三个指针：`lo` 维护 0 的右边界，`hi` 维护 2 的左边界，`mid` 扫描未处理元素。

```
// 以 nums = [2, 0, 2, 1, 1, 0] 为例，详细演示：
//
// 初始: lo=0, mid=0, hi=5
// [2, 0, 2, 1, 1, 0]
//  ↑                ↑
//  lo,mid           hi
//
// Step1: nums[mid]=2, 与 hi 交换, hi--
// [0, 0, 2, 1, 1, 2]    mid 不动! 换过来的 0 还没检查
//  ↑              ↑
//  lo,mid         hi
//
// Step2: nums[mid]=0, 与 lo 交换(自己和自己), lo++, mid++
// [0, 0, 2, 1, 1, 2]
//     ↑           ↑
//     lo,mid      hi
//
// Step3: nums[mid]=0, 与 lo 交换(自己和自己), lo++, mid++
// [0, 0, 2, 1, 1, 2]
//        ↑        ↑
//        lo,mid   hi
//
// Step4: nums[mid]=2, 与 hi 交换, hi--
// [0, 0, 1, 1, 2, 2]    mid 不动!
//        ↑     ↑
//        lo,mid hi
//
// Step5: nums[mid]=1, 跳过, mid++
// [0, 0, 1, 1, 2, 2]
//        ↑  ↑  ↑
//        lo mid hi
//
// Step6: nums[mid]=1, 跳过, mid++
// [0, 0, 1, 1, 2, 2]
//        ↑     ↑
//        lo   mid,hi  → mid > hi? 不，mid == hi+1? 
//                        mid=4 > hi=3 → 结束!
//
// 最终: [0, 0, 1, 1, 2, 2] ✓
```

```cpp
class Solution {
public:
    void sortColors(vector<int>& nums) {
        int lo = 0, mid = 0, hi = nums.size() - 1;
        
        // 循环不变量:
        // [0, lo)       → 全是 0
        // [lo, mid)     → 全是 1
        // [mid, hi]     → 未处理
        // (hi, n-1]     → 全是 2
        while (mid <= hi) {
            if (nums[mid] == 0) {
                // 把 0 换到左边 0 区域
                // lo 位置的值一定是 1（因为 [lo,mid) 都是 1）
                // 所以换过来的是 1，mid 可以安全前进
                swap(nums[lo], nums[mid]);
                lo++;
                mid++;
            } else if (nums[mid] == 2) {
                // 把 2 换到右边 2 区域
                // hi 位置的值未知（可能是 0/1/2）
                // 所以换过来后 mid 不能前进，下一轮还要检查
                swap(nums[mid], nums[hi]);
                hi--;
                // 注意：mid 不动！
            } else {
                // nums[mid] == 1，已在正确区域，直接跳过
                mid++;
            }
        }
    }
};
```

**关键点**：
- 遇到 0 交换后 `mid++`（因为从 lo 换来的一定是 1），遇到 2 交换后 `mid` 不动（因为从 hi 换来的值未知）
- 循环条件是 `mid <= hi`，不是 `mid < hi`，因为 `mid == hi` 时那个元素还未处理

## 解法对比

| | 计数排序 | 两趟双指针 | 荷兰国旗 |
|--|---------|-----------|---------|
| 扫描次数 | 2 趟 | 2 趟 | 1 趟 |
| 空间 | O(1) | O(1) | O(1) |
| 代码难度 | 简单 | 简单 | 中等 |
| 面试价值 | 作为初始答案 | 过渡思路 | Follow-up 必须给出 |
| 扩展性 | 值域 k 种 → O(k) 空间 | 只适合少量类别 | 经典三路分区，快排可复用 |

**面试策略**：先快速给出计数排序，然后说"但这需要两趟扫描，我们可以用三指针做到一趟"，展示你的优化能力。

## 易错点

1. **遇到 2 交换后 mid 前进了**
   - ✗ `swap(nums[mid], nums[hi]); hi--; mid++;` — 从 hi 换来的可能是 0，直接跳过就丢失了
   - ✓ `swap(nums[mid], nums[hi]); hi--;` — mid 不动，下一轮重新检查

2. **循环条件写成 `mid < hi`**
   - ✗ `while (mid < hi)` — 当 mid == hi 时那个元素没处理，可能是 0 或 2 没归位
   - ✓ `while (mid <= hi)` — 必须包含等号

3. **lo 和 mid 的初始值搞混**
   - ✗ `lo = 0, mid = 1` — mid 应该从 0 开始，因为第一个元素也需要处理
   - ✓ `lo = 0, mid = 0`

4. **遇到 0 交换后忘记 mid++**
   - ✗ `swap(nums[lo], nums[mid]); lo++;` — mid 不前进会导致死循环（如果 lo 和 mid 指向同一位置，无限交换自己）
   - ✓ `swap(nums[lo], nums[mid]); lo++; mid++;`

## 面试追问

**Q1: 为什么遇到 0 换完 mid 可以前进，遇到 2 换完就不行？**
> 因为 `lo` 到 `mid` 之间的元素已经被扫描过，只可能是 1。所以从 `lo` 换过来的一定是 1，不需要再检查。但 `hi` 指向的是未处理区域，换过来的可能是 0、1、2 中的任何一个，必须再检查。

**Q2: 如果颜色不是 3 种而是 k 种怎么办？**
> 三指针只适用于 3 种值。k 种值的情况下：
> - 计数排序：O(n+k) 时间，O(k) 空间，最通用
> - 如果 k 很小，可以递归地做：先把最小和最大值分到两端（类似荷兰国旗），然后递归处理中间部分。但代码复杂度大幅增加，一般直接用计数排序。

**Q3: 这个三路分区和快排什么关系？**
> 荷兰国旗算法就是快排的三路分区（three-way partition）。在快排中，选一个 pivot，把数组分成 < pivot、== pivot、> pivot 三部分。这里 pivot 就是 1。三路快排对有大量重复元素的数组特别高效，能避免传统快排退化到 O(n²)。

**Q4: 能否用其他 O(n) 排序算法？**
> 可以用基数排序（radix sort），但对这道题来说杀鸡用牛刀。计数排序是最自然的选择，因为值域只有 {0, 1, 2}。
