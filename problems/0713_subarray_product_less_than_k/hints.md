# 713. 乘积小于 K 的子数组

## 核心思路

本质上是在问：在一个正整数数组中，有多少个**连续子数组**的元素乘积严格小于 k？因为所有元素都 ≥ 1，乘积随着窗口扩大单调不减，这种**单调性**是用滑动窗口的前提条件。

## 思维链

1. **读完题第一反应**：枚举所有子数组，计算每个子数组的乘积，判断是否 < k。这是 O(n²) 甚至 O(n³) 的暴力法。

2. **暴力解的瓶颈**：对每个起点 i，都要向右扩展计算乘积。但注意——所有 nums[i] ≥ 1，所以乘积是**单调不减**的！一旦某个子数组 [i..j] 的乘积 ≥ k，那 [i..j+1], [i..j+2]... 也一定 ≥ k，不需要继续扩展。

3. **怎么利用单调性？** 这正是**滑动窗口**的典型场景：维护一个窗口 [left, right]，right 右移扩大窗口，当乘积 ≥ k 时 left 右移缩小窗口。

4. **核心难点：怎么数子数组个数？** 当右指针在 right 位置时，窗口 [left, right] 内乘积 < k，那么**以 right 结尾**的合法子数组有 `right - left + 1` 个（分别是 [left..right], [left+1..right], ..., [right..right]）。

5. **特殊情况**：如果 k ≤ 1，因为所有元素 ≥ 1，任何子数组乘积都 ≥ 1，所以答案直接为 0。

6. **进阶思路**：取对数后乘积变成求和，可以用前缀和 + 二分查找，但实际不如滑动窗口简洁高效。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举所有子数组，累乘判断 | O(n²) | O(1) | 能说出即可 |
| 滑动窗口 | 利用乘积单调性，双指针维护窗口 | O(n) | O(1) | ⭐ 必须写出 |
| 对数前缀和 + 二分 | 取 log 转化为求和，前缀和+二分 | O(n log n) | O(n) | 加分项 |

## 关键提示

1. **单调性观察**：所有元素 ≥ 1，窗口越大乘积越大（或不变）。这决定了可以用滑动窗口。

2. **计数技巧**：不要试图一次数出所有子数组。每次 right 右移一步，只数"以 right 结尾"的新增子数组个数 = `right - left + 1`。

3. **边界陷阱**：k = 0 或 k = 1 时要特判。nums[i] ≥ 1，所以任何子数组乘积 ≥ 1，当 k ≤ 1 时答案一定为 0。

4. **滑动窗口过程可视化**（以 nums=[10,5,2,6], k=100 为例）：
```
right=0: [10]        prod=10  < 100  → count += 1 (子数组: [10])
right=1: [10,5]      prod=50  < 100  → count += 2 ([5], [10,5])
right=2: [10,5,2]    prod=100 ≥ 100  → 收缩! left=1
         [5,2]       prod=10  < 100  → count += 2 ([2], [5,2])
right=3: [5,2,6]     prod=60  < 100  → count += 3 ([6], [2,6], [5,2,6])
                                       总计: 1+2+2+3 = 8 ✓
```

5. **对数转化思路**：log(a×b×c) = log(a)+log(b)+log(c)，乘积 < k 变成求和 < log(k)，就变成了"子数组和小于目标值"的问题，可以用前缀和 + 二分。

## 解法详解

### 解法1: 暴力枚举 — O(n²) / O(1)

**思考过程**：最直接的想法，固定左端点 i，右端点 j 从 i 开始向右扩展，累乘。一旦乘积 ≥ k 就 break（因为再往右只会更大）。

```cpp
class Solution {
public:
    int numSubarrayProductLessThanK(vector<int>& nums, int k) {
        if (k <= 1) return 0;
        int n = nums.size(), count = 0;
        for (int i = 0; i < n; i++) {
            int prod = 1;
            for (int j = i; j < n; j++) {
                prod *= nums[j];
                if (prod < k) {
                    count++;
                } else {
                    break; // 乘积只增不减，后面不可能 < k
                }
            }
        }
        return count;
    }
};
```

**关键点**：利用了 nums[i] ≥ 1 所以乘积单调不减，可以提前 break。但每个起点仍然可能扫到末尾，最坏 O(n²)。

### 解法2: 滑动窗口 — O(n) / O(1) ⭐ 面试首选

**从解法1优化**：解法1中，当起点从 i 移到 i+1 时，很多乘积是重复计算的。滑动窗口的核心思想是：right 每次右移一步，prod 乘上新元素；如果 prod ≥ k，就 left 右移，prod 除掉离开的元素。这样 left 和 right 各最多移动 n 次，总共 O(n)。

```cpp
class Solution {
public:
    int numSubarrayProductLessThanK(vector<int>& nums, int k) {
        if (k <= 1) return 0; // 所有元素≥1，乘积≥1，不可能<1或<0
        
        int left = 0, prod = 1, count = 0;
        for (int right = 0; right < (int)nums.size(); right++) {
            prod *= nums[right];           // 扩展窗口
            while (prod >= k) {
                prod /= nums[left++];      // 收缩窗口
            }
            // 此时 [left, right] 的乘积 < k
            // 以 right 结尾的合法子数组: [left..right], [left+1..right], ..., [right..right]
            count += right - left + 1;
        }
        return count;
    }
};
```

**关键点**：
- **计数公式 `right - left + 1`**：这不是窗口大小的巧合，而是精确地数出"以当前 right 结尾"的所有合法子数组个数，避免重复计数。
- **为什么不会漏数？** 每个子数组恰好在其右端点处被计数一次。

### 解法3: 对数前缀和 + 二分 — O(n log n) / O(n)

**不同角度**：取对数把乘积变加法。prefix[i] = log(nums[0]) + ... + log(nums[i-1])，那么子数组 [i, j] 的乘积 < k 等价于 prefix[j+1] - prefix[i] < log(k)。固定 j，找最小的 i 使得 prefix[i] > prefix[j+1] - log(k)，用二分查找。

```cpp
class Solution {
public:
    int numSubarrayProductLessThanK(vector<int>& nums, int k) {
        if (k <= 1) return 0;
        int n = nums.size();
        vector<double> prefix(n + 1, 0.0);
        for (int i = 0; i < n; i++) {
            prefix[i + 1] = prefix[i] + log(nums[i]);
        }
        
        double logK = log(k);
        int count = 0;
        for (int j = 0; j < n; j++) {
            // 找最小的 i 使得 prefix[j+1] - prefix[i] < logK
            // 即 prefix[i] > prefix[j+1] - logK
            double target = prefix[j + 1] - logK + 1e-9; // 加 eps 处理浮点误差
            int lo = 0, hi = j + 1;
            while (lo < hi) {
                int mid = lo + (hi - lo) / 2;
                if (prefix[mid] >= target) {
                    hi = mid;
                } else {
                    lo = mid + 1;
                }
            }
            count += j - lo + 1;
        }
        return count;
    }
};
```

**关键点**：浮点精度是这种方法的天然弱点。加 `1e-9` 的 epsilon 是为了让严格小于变成 ≤ 的比较，但在极端情况下仍可能出错。面试中提到这个思路即可，**实际推荐滑动窗口**。

## 解法对比

| | 暴力 O(n²) | 滑动窗口 O(n) | 对数+二分 O(n log n) |
|---|---|---|---|
| 核心思想 | 枚举所有起点 | 双指针利用单调性 | 乘法变加法 |
| 空间 | O(1) | O(1) | O(n) |
| 精度问题 | 无 | 无 | 浮点误差 |
| 面试推荐 | 展示理解 | **首选** | 展示知识面 |

滑动窗口之所以能 O(n)，是因为 left 和 right 都只向右移动，永不回退，总共最多各移动 n 次。

## 易错点

1. **漏掉 k ≤ 1 的特判**
   - ✗ 直接进入滑动窗口，当 k=0 时 while 循环中 left 会越界
   - ✓ 开头 `if (k <= 1) return 0;`，因为所有元素 ≥ 1，乘积永远 ≥ 1

2. **计数公式写成窗口大小而不是增量**
   - ✗ `count = right - left + 1`（赋值，覆盖了之前的计数）
   - ✓ `count += right - left + 1`（累加）

3. **while 条件写成 prod > k 而不是 prod >= k**
   - ✗ `while (prod > k)` — 漏掉了 prod == k 的情况（题目要求**严格小于**）
   - ✓ `while (prod >= k)`

4. **整数溢出**
   - nums[i] 最大 1000，数组长度最大 3×10⁴，乘积可能极大。但因为我们在 prod ≥ k 时就会收缩，而 k ≤ 10⁶，所以 prod 在收缩前最多是 k × 1000 = 10⁹，在 int 范围内。**不会溢出**，但面试中提到这个分析是加分项。

## 面试追问

**Q1（基础理解）**：暴力法的复杂度是多少？能不能比 O(n²) 更差？
> O(n²)。因为所有元素 ≥ 1，乘积单调不减，对每个起点最多走到乘积 ≥ k 就停了。但最坏情况（如全是 1 且 k 很大）每个起点都要走到末尾，所以是 O(n²)。

**Q2（核心优化）**：滑动窗口为什么不会漏数子数组？
> 每个合法子数组恰好在其右端点被计数一次。当 right 固定时，[left..right] 是以 right 结尾的最长合法子数组，[left..right], [left+1..right], ..., [right..right] 共 right-left+1 个全部合法，且更短的子数组乘积更小一定也合法。

**Q3（变体）**：如果数组中可能有 0 怎么办？
> 0 会使乘积变成 0，破坏了"除法收缩"的逻辑（不能除以 0）。需要特殊处理：遇到 0 时，如果 k > 0，那么包含 0 的子数组乘积为 0 < k 一定合法；同时需要将 left 跳到 0 之后重新开始窗口。

**Q4（Follow-up）**：如果要求乘积**恰好等于** k 的子数组个数呢？
> 滑动窗口不直接适用（恰好等于没有单调性可利用）。可以用哈希表存前缀积（类似 Two Sum / 560. 和为 K 的子数组），但要注意乘积为 0 和溢出问题。
