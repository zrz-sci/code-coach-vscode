# 455. 分发饼干

## 核心思路

本质上是一个**匹配问题**：在"孩子胃口"和"饼干尺寸"两个集合之间，找到最大数量的合法配对（饼干尺寸 ≥ 孩子胃口），且每个孩子和每块饼干只能用一次。贪心策略是：**用尽量小的饼干去满足胃口最小的孩子，把大饼干留给胃口大的孩子**。

## 思维链

1. **读完题第一反应**：每个孩子需要一块足够大的饼干，每块饼干只能给一个孩子。暴力想法 —— 尝试所有可能的分配方案，取满足最多孩子的那个。这是排列/组合穷举，复杂度爆炸。

2. **换个角度想**：不需要穷举所有方案。直觉告诉我们，**小饼干给小胃口的孩子更划算**。为什么？如果一块小饼干能同时满足胃口小的孩子 A 和胃口大的孩子 B，把它给 A 显然更优 —— 因为 B 需要更大的饼干，而 A 不需要那么大的。把小饼干给了 B 是"浪费"。

3. **贪心策略成型**：两边都排序。从胃口最小的孩子开始，用能满足他的最小饼干去喂他。如果当前最小的饼干都不能满足当前胃口最小的孩子，那这块饼干就没用了（它满足不了任何还没被满足的孩子），跳过它。

4. **实现方式**：排序后用双指针，一个指向孩子，一个指向饼干，同时向右扫描。匹配成功两个指针都右移，匹配失败只移饼干指针。

5. **为什么贪心是正确的？** 反证法：假设最优解中，一块大饼干 S 给了小胃口孩子 A，而小饼干 s 给了大胃口孩子 B（s ≥ g_B）。那交换一下（S 给 B，s 给 A），只要 s ≥ g_A 就行。因为 g_A ≤ g_B ≤ s，交换后依然合法，满足的孩子数不变。所以"小饼干优先给小胃口"不会比任何方案差。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力穷举 | 尝试所有分配组合 | O(n! 或 2^n) | O(n) | 能说出即可 |
| 排序 + 贪心双指针 | 小饼干优先喂小胃口 | O(n log n + m log m) | O(1) | ⭐ 必须写出 |

> 注：n = g.length, m = s.length。本题最优解就是排序+贪心，没有更低时间复杂度的做法（排序本身是瓶颈）。

## 关键提示

1. **排序是关键前提**：贪心依赖有序性。不排序就无法保证"用最小的饼干去匹配最小的胃口"。

2. **双指针的移动规则**：
   - 匹配成功（`s[j] >= g[i]`）：两个指针都前进，配对完成
   - 匹配失败（`s[j] < g[i]`）：只移动饼干指针，这块饼干太小，对谁都没用了

3. **s 可能为空**：题目约束 `0 <= s.length`，饼干数组可能为空，结果直接返回 0。

4. **不要想复杂了**：这道题不需要 DP、不需要回溯，贪心 + 排序是最自然也是最优的思路。

5. **ASCII 示意图 — 双指针过程**：
```
排序后: g = [1, 2, 3],  s = [1, 1]
                 
Round 1: g[i]=1, s[j]=1  → 1 >= 1 ✓ 匹配! i++, j++, count=1
         i→         j→

Round 2: g[i]=2, s[j]=1  → 1 < 2  ✗ 饼干太小，跳过! j++
            i→         j→

j 已越界，结束。答案 = 1
```

## 解法详解

### 解法1: 暴力思路（概念分析） — 指数级 / O(n)

**思考过程**：最直觉的想法是穷举所有可能的"孩子-饼干"配对方案。比如用回溯法，对每块饼干决定给哪个孩子（或不给），找出满足最多孩子的方案。

但仔细想想：n 和 m 都可以到 3×10⁴，穷举方案数是指数级的，完全不可行。我们需要贪心策略来避免穷举。

**这个解法不需要写代码**，它的价值在于让我们认识到：必须找到一种"不回头"的策略（贪心），而不是尝试所有可能。

### 解法2: 排序 + 贪心双指针 — O(n log n + m log m) / O(1) ⭐ 面试首选

**从暴力到贪心**：暴力的瓶颈是"不知道该把哪块饼干给哪个孩子"。排序后，这个决策变得简单：**从小到大扫描，能匹配就匹配，不能就跳过饼干**。

**贪心正确性**：对于当前胃口最小的未满足孩子，用能满足他的最小饼干。这样不会浪费大饼干，留给后面胃口更大的孩子。

```cpp
class Solution {
public:
    int findContentChildren(vector<int>& g, vector<int>& s) {
        // 排序：贪心的前提，让我们能从小到大匹配
        sort(g.begin(), g.end());
        sort(s.begin(), s.end());
        
        int i = 0; // 指向当前待满足的孩子（胃口最小的那个）
        int j = 0; // 指向当前考虑的饼干（尺寸最小的那个）
        int count = 0;
        
        while (i < (int)g.size() && j < (int)s.size()) {
            if (s[j] >= g[i]) {
                // 这块饼干能满足这个孩子 → 匹配成功
                count++;
                i++; // 这个孩子已满足，看下一个
                j++; // 这块饼干已用掉，看下一块
            } else {
                // 这块饼干太小，连当前胃口最小的孩子都满足不了
                // 那它也满足不了后面任何孩子（因为后面胃口更大）
                // 所以直接丢弃这块饼干
                j++;
            }
        }
        
        return count;
    }
};
```

**关键点**：
- `s[j] < g[i]` 时只移动 j 不移动 i，因为这块饼干对所有剩余孩子都无用
- `s[j] >= g[i]` 时 i 和 j 都移动，一对一匹配消耗掉
- 循环终止条件：任一指针越界就停止（孩子都看完了，或饼干用完了）

### 解法2 变体: 从大到小的贪心

**换个方向**：也可以从胃口最大的孩子开始，用最大的饼干尝试满足他。

```cpp
class Solution {
public:
    int findContentChildren(vector<int>& g, vector<int>& s) {
        sort(g.begin(), g.end());
        sort(s.begin(), s.end());
        
        int i = g.size() - 1; // 从胃口最大的孩子开始
        int j = s.size() - 1; // 从最大的饼干开始
        int count = 0;
        
        while (i >= 0 && j >= 0) {
            if (s[j] >= g[i]) {
                // 最大的饼干能满足当前最贪心的孩子
                count++;
                i--;
                j--;
            } else {
                // 最大的饼干都满足不了这个孩子，放弃这个孩子
                i--;
            }
        }
        
        return count;
    }
};
```

**与正向贪心的区别**：匹配失败时，正向跳过饼干（饼干太小没用），反向跳过孩子（孩子太贪心满足不了）。两种方向得到的结果相同。

## 解法对比

| | 正向贪心（小→大） | 反向贪心（大→小） |
|---|---|---|
| 匹配失败时 | 跳过饼干（太小没用） | 跳过孩子（满足不了） |
| 直觉 | 小饼干优先给小胃口 | 大饼干优先给大胃口 |
| 结果 | 相同 | 相同 |
| 面试推荐 | ⭐ 更直觉 | 也可以 |

两者本质相同，都是排序后贪心匹配。面试中写哪个都行，但正向（从小到大）的逻辑更好解释。

## 易错点

1. **忘记排序就开始双指针**：
   - ✗ 不排序直接扫描 → 无法保证贪心正确性
   - ✓ 两个数组**都要排序**

2. **匹配失败时移错了指针**：
   - ✗ `s[j] < g[i]` 时写了 `i++`（跳过孩子） → 这个孩子可能被后面更大的饼干满足
   - ✓ `s[j] < g[i]` 时应该 `j++`（跳过饼干）

3. **忘记处理 s 为空的情况**：
   - 题目允许 `s.length = 0`，此时 while 循环直接不进入，返回 0，代码天然处理了
   - 但如果用 `s.size() - 1` 做反向遍历的起点，`s.size()` 是 unsigned，`0 - 1` 会溢出！
   - ✗ `int j = s.size() - 1;` 当 s 为空时 j 变成巨大正数
   - ✓ 先判断 `if (s.empty()) return 0;` 或用 `(int)s.size() - 1`

4. **用 count 变量计数但忘记同时移动 i**：
   - ✗ 匹配成功只写了 `count++; j++;` 忘了 `i++` → 同一个孩子被重复匹配
   - ✓ 匹配成功时 `count++; i++; j++;` 三步都要有

## 面试追问

**Q1（基础理解）**：为什么贪心策略是正确的？能证明吗？
> 反证/交换论证：假设最优解中存在"大饼干给了小胃口，小饼干给了大胃口"的情况，交换它们不会减少满足的孩子数（因为小饼干够大才能满足大胃口，交换后小饼干给小胃口一定也够）。所以"小饼干优先给小胃口"的策略不会比任何方案差。

**Q2（变体）**：如果每个孩子可以拿多块饼干（饼干尺寸可以累加），怎么做？
> 这就不是简单的贪心了。变成了一个**分组/背包**问题：把饼干分成若干组，每组的总和要 ≥ 对应孩子的胃口，最大化满足的孩子数。贪心思路：排序后从胃口最小的孩子开始，尽量用小饼干凑够他的胃口。

**Q3（扩展）**：如果不是求最大数量，而是求"满足所有孩子的最少饼干数"（每个孩子可以拿多块），怎么做？
> 对每个孩子，贪心地从大到小选饼干直到满足胃口，这样用的饼干块数最少。整体需要更复杂的策略，类似背包问题。
