# 693. Binary Number with Alternating Bits

## 核心思路

判断一个正整数的二进制表示中，相邻位是否总是不同（交替出现 0 和 1）。核心技巧是利用**位运算**：将 n 右移一位后与 n 异或，如果结果是全 1（形如 0...0111...1），则说明 n 具有交替位模式。验证全 1 可以用 `x & (x+1) == 0` 来判断。

## 思维链

1. 交替位数字的二进制形式：101、1010、10101 等
2. 观察：如果 n 是交替位，n 右移 1 位后得到的数与 n 没有任何一位相同
3. n ^ (n >> 1) 对于交替位数字一定是全 1 的形式（如 111、1111）
4. 判断一个数是否是全 1：x & (x + 1) == 0
5. 也可以逐位检查，但位运算解法更优雅，O(1)
6. 注意边界：n >= 1，所以不需要处理 0 的情况

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 位运算一行解 | O(1) | O(1) | 最优雅，利用异或+全1判断 |
| 逐位检查 | O(log n) | O(1) | 直观，逐位比较相邻位 |
| 正则/字符串 | O(log n) | O(log n) | 转字符串后模式匹配 |
| 除法检查 | O(log n) | O(1) | 反复除以2检查余数交替 |

## 关键提示

1. **异或的本质**：两个不同的位异或结果为 1。如果 n 的每对相邻位都不同，那么 n ^ (n >> 1) 的每一位都是 1。
2. **全 1 判断技巧**：一个二进制数全部为 1 当且仅当 x & (x + 1) == 0。这是因为全 1 数加 1 后进位变成 10...0，与原数没有公共位。
3. **逐位检查的思路**：取最低位 prev = n & 1，然后不断右移 n，比较当前最低位与 prev 是否不同，若相同则返回 false。
4. **不需要特殊处理前导零**：二进制表示不含前导零，最高位一定是 1，所以只需从最低位开始检查到最高位即可。

## 解法详解

### 解法一：位运算一行解（推荐）

**思路**：
- 计算 x = n ^ (n >> 1)
- 对于交替位数字，x 一定是全 1（连续的 1）
- 判断 x 是否为全 1：x & (x + 1) == 0

**示例**：
```
n = 5:     101
n >> 1:    010
XOR:       111   -> 全1，x & (x+1) = 111 & 1000 = 0 -> true

n = 7:     111
n >> 1:    011
XOR:       100   -> 不是全1 -> false

n = 10:   1010
n >> 1:   0101
XOR:      1111   -> 全1 -> true
```

**复杂度**：时间 O(1)，空间 O(1)

### 解法二：逐位检查

**思路**：
- 取出最低位 prev = n & 1
- 反复右移 n，取当前最低位 curr = n & 1
- 如果 curr == prev，说明相邻位相同，返回 false
- 更新 prev = curr，继续检查

**步骤**：
1. prev = n & 1, n >>= 1
2. while n > 0: curr = n & 1; if curr == prev return false; prev = curr; n >>= 1
3. 循环结束返回 true

**复杂度**：时间 O(log n)，空间 O(1)

### 解法三：除法模拟

**思路**：
- 依次取 n % 2 得到每一位
- 检查连续两次的余数是否不同
- n /= 2 进入下一位

本质与逐位检查相同，只是不用位运算而用除法和取模。

## 易错点

1. **忘记处理 n >> 1 的溢出**：在 C++ 中，如果 n 是 int 类型，对负数右移是算术右移（保持符号位）。但题目保证 n >= 1，所以不会出现负数。
2. **误用 n ^ (n << 1)**：左移会多出一位，导致结果不正确。必须用右移 n >> 1。
3. **全 1 判断错误**：不要用 x == (1 << k) - 1 来判断全 1，因为需要额外计算 k。用 x & (x+1) == 0 更简洁且无需知道位数。
4. **逐位检查时方向混乱**：从最低位向最高位检查（右移）是最自然的方式，不要试图从最高位开始。

## 面试追问

1. **如何生成所有 32 位以内的交替位数字？**
   - 交替位数字只有两种模式：010101... 和 101010...。可以从 1 开始，交替左移加 0/1 来生成。32 位以内只有约 64 个这样的数。

2. **如何扩展到 64 位整数？**
   - 解法完全相同，只需注意使用 long long 类型，位运算操作不变。

3. **O(1) 解法为什么正确？请严格证明。**
   - 如果 n 有交替位，则 n 的每一位与其右邻位都不同，n ^ (n>>1) 每一位都是 1。反之，如果 n 有两个相邻相同位，对应位置异或为 0，结果不是全 1。

4. **能否用 n & (n >> 2) == 0 来判断？**
   - 不行。n & (n >> 2) == 0 只能说明间隔一位没有公共 1，不能排除相邻位相同的情况。例如 n = 3 (11)，3 & (3>>2) = 3 & 0 = 0，但 3 不是交替位。

5. **这题的思路能用在哪些其他位运算问题中？**
   - n ^ (n >> 1) 是 Gray Code 的核心操作；全 1 判断 (x & (x+1) == 0) 可用于 Power of Two 相关问题的变体。
