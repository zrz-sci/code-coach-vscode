# 169. 多数元素

## 核心思路

找出数组中出现次数超过 `⌊n/2⌋` 的元素。本质上是利用"多数元素的数量比其他所有元素加起来还多"这个压倒性优势。

## 思维链

1. **读完题第一反应**：统计每个元素出现次数，返回次数最多的那个 → 用哈希表计数，O(n) 时间 O(n) 空间。
2. **能不能不用额外空间？** 题目的 Follow-up 要求 O(1) 空间。哈希表的瓶颈在于它需要 O(n) 空间来存储计数。
3. **换个角度思考**：如果排序呢？多数元素出现超过 n/2 次，排序后中间位置 `nums[n/2]` 一定是它。O(n log n) 时间 O(1) 空间（原地排序）。
4. **还能更快吗？** 关键洞察：多数元素的数量 > 所有其他元素数量之和。想象一个投票场景 — 多数元素当候选人，遇到相同的+1，不同的-1，计数归零就换人。因为多数元素"人多势众"，最后一定活到最后。这就是 **Boyer-Moore 投票算法**，O(n) 时间 O(1) 空间。
5. **分治思路**：也可以递归地把数组一分为二，左半部分的多数元素和右半部分的多数元素，整体的多数一定是其中之一。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 哈希表计数 | 统计每个元素出现次数 | O(n) | O(n) | 能说出即可 |
| 排序取中 | 排序后中间元素即多数 | O(n log n) | O(1) | 能说出即可 |
| Boyer-Moore 投票 | 抵消思想，候选人存活 | O(n) | O(1) | ⭐ 必须写出 |
| 分治 | 左右各取多数，验证 | O(n log n) | O(log n) | 加分项 |

## 关键提示

1. **多数元素出现超过 n/2 次** — 这意味着它比其他所有元素加起来还多。这个"压倒性数量优势"是 O(1) 空间解法的根基。
2. **排序后想想中间位置**：不管多数元素是最小值、最大值还是中间值，排序后它一定覆盖了 `nums[n/2]` 这个位置。画个图试试。
3. **投票算法的直觉**：想象多数派和少数派打架，一换一（互相抵消），多数派人多，最后一定还有人站着。
4. **分治的合并**：左右子数组各自的多数元素最多两个候选，全局多数一定是其中之一，线性验证即可。

## 解法详解

### 解法1: 哈希表计数 — O(n) / O(n)

**思考过程**: 最直觉的做法 — 遍历数组，记录每个数出现几次，谁超过 n/2 就返回谁。

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        unordered_map<int, int> count;
        int n = nums.size();
        for (int num : nums) {
            count[num]++;
            // 一旦某个数的计数超过 n/2，直接返回，不用遍历完
            if (count[num] > n / 2) return num;
        }
        return -1; // 题目保证一定存在，不会走到这里
    }
};
```

**关键点**: 边统计边判断可以提前返回，不需要遍历完再找最大计数。空间瓶颈在哈希表最坏需要存 O(n) 个不同元素。

---

### 解法2: 排序取中位数 — O(n log n) / O(1)

**思考过程**: 多数元素出现超过 n/2 次。排序后，无论多数元素是什么值，它一定会"跨过"数组中间位置。

```
// 为什么排序后 nums[n/2] 一定是多数元素？
// 
// 假设多数元素是 x，出现 k 次 (k > n/2)
// 排序后 x 占据连续 k 个位置
// 
// 最极端情况1: x 全在左边      最极端情况2: x 全在右边
// [x x x x x _ _ _ _]          [_ _ _ _ x x x x x]
//          ↑ n/2 被覆盖                  ↑ n/2 被覆盖
// 
// 不管怎么放，k > n/2 保证 x 一定覆盖 index n/2
```

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        // 多数元素一定覆盖中间位置
        return nums[nums.size() / 2];
    }
};
```

**关键点**: 这个解法利用了"出现超过 n/2 次"这个条件的几何意义。如果题目改成"出现最多的元素"（不保证超过 n/2），这个方法就不成立了。

---

### 解法3: Boyer-Moore 投票算法 — O(n) / O(1) ⭐ 面试首选

**从解法1优化**: 解法1的瓶颈是哈希表的 O(n) 空间。我们需要一种不记录所有元素计数、只用常量空间就能找到多数元素的方法。

**核心直觉**: 多数元素的数量比其他所有元素加起来还多。想象一个"对战抵消"过程：

```
// Boyer-Moore 投票算法示意 — nums = [2,2,1,1,1,2,2]
//
// 遍历过程:
//   元素:     2    2    1    1    1    2    2
//   候选:     2    2    2    1    1    1    2
//   计数:     1    2    1    0    1    0    1
//                       ↑         ↑         ↑
//                     遇到不同    归零      归零后
//                     计数-1     换候选    换候选
//
// 最终候选: 2 ✓
//
// 直觉：多数派(2出现4次) vs 少数派(1出现3次)
// 一对一抵消后，多数派一定还有人"站着"
```

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        int candidate = 0;
        int count = 0;
        
        for (int num : nums) {
            // 计数为0时，选当前元素作为新候选人
            if (count == 0) {
                candidate = num;
            }
            // 相同则+1(支持)，不同则-1(抵消)
            count += (num == candidate) ? 1 : -1;
        }
        
        // 题目保证多数元素一定存在，所以 candidate 就是答案
        return candidate;
    }
};
```

**为什么正确？**
- 多数元素出现次数 > n/2，其他所有元素出现次数之和 < n/2
- 每次"抵消"消耗一个多数元素和一个非多数元素
- 多数元素"人数"更多，抵消完后一定还剩余，最终候选人一定是多数元素

**关键点**: 如果题目**不保证**多数元素一定存在，算法第一遍找到候选人后，还需要**第二遍遍历**验证它的计数是否真的超过 n/2。

---

### 解法4: 分治 — O(n log n) / O(log n)

**思考过程**: 全局的多数元素，在左半或右半中至少有一半也是多数元素。否则它不可能在全局超过 n/2 次。

```
// 分治过程 — nums = [2,2,1,1,1,2,2]
//
//              [2,2,1,1,1,2,2]
//             /               \
//        [2,2,1]           [1,1,2,2]
//        /    \            /       \
//     [2]   [2,1]      [1,1]    [2,2]
//            / \        / \      / \
//          [2] [1]    [1] [1]  [2] [2]
//
// 自底向上合并:
// [2] vs [1] → 2出现1次, 1出现1次 → 返回2(左边多数)
// [2,2,1] → 左多数=2, 计数2次 > 3/2 → 返回2
// [1] vs [1] → 都是1 → 返回1
// [1,1] → 返回1
// [2] vs [2] → 都是2 → 返回2
// [2,2] → 返回2
// [1,1,2,2] → 左多数=1(计数2), 右多数=2(计数2) → 返回2(或1,平手时取任一)
// 最终 [2,2,1,1,1,2,2] → 左多数=2(计数4), 右多数=2 → 返回2 ✓
```

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        return majority(nums, 0, nums.size() - 1);
    }
    
private:
    int majority(vector<int>& nums, int lo, int hi) {
        // base case: 只有一个元素，它就是多数
        if (lo == hi) return nums[lo];
        
        int mid = lo + (hi - lo) / 2;
        int leftMaj = majority(nums, lo, mid);
        int rightMaj = majority(nums, mid + 1, hi);
        
        // 左右多数相同，不用验证
        if (leftMaj == rightMaj) return leftMaj;
        
        // 不同则线性扫描验证谁在 [lo, hi] 中出现更多
        int leftCount = count(nums.begin() + lo, nums.begin() + hi + 1, leftMaj);
        int rightCount = count(nums.begin() + lo, nums.begin() + hi + 1, rightMaj);
        
        return leftCount > rightCount ? leftMaj : rightMaj;
    }
};
```

**关键点**: 合并时需要 O(n) 线性验证，总共 O(log n) 层，每层总扫描量 O(n)，所以总时间 O(n log n)。

## 解法对比

| | 哈希表 | 排序 | Boyer-Moore | 分治 |
|---|---|---|---|---|
| 时间 | O(n) | O(n log n) | O(n) | O(n log n) |
| 空间 | O(n) | O(1)* | O(1) | O(log n) |
| 修改原数组 | 否 | 是 | 否 | 否 |
| 是否需要保证多数存在 | 否 | 是 | 是(否则需二次验证) | 否 |
| 适用场景 | 通用计数 | 简单直接 | 面试首选 | 展示分治思维 |

> *排序的 O(1) 空间指原地排序（如堆排序），若用 std::sort 通常是 O(log n)。

**面试场景选择**：
- 先说哈希表（展示基本思路），然后主动优化到 Boyer-Moore（展示 O(1) 空间能力）
- 如果面试官问分治，说明你对递归和合并有理解

## 易错点

1. **Boyer-Moore 忘记 count == 0 时更换候选人**
   - ✗ `if (num == candidate) count++; else count--;`（缺少更换逻辑）
   - ✓ `if (count == 0) candidate = num; count += (num == candidate) ? 1 : -1;`
   - 必须先判断 count == 0 再判断相等，顺序不能反

2. **不保证多数存在时直接返回候选人**
   - ✗ 直接返回 `candidate`
   - ✓ 第二遍遍历验证 `count(candidate) > n/2` 后再返回
   - 本题保证存在所以可以省略，但面试时要主动提这个点

3. **排序法取错索引**
   - ✗ `return nums[(n-1)/2];`（偶数长度时位置不对）
   - ✓ `return nums[n/2];`（对于 n 为偶数和奇数都正确）

4. **分治法合并时只比较 leftMaj 和 rightMaj 的大小**
   - ✗ `return max(leftMaj, rightMaj);`（多数元素不是最大值）
   - ✓ 应该分别计数 leftMaj 和 rightMaj 在整个区间的出现次数

## 面试追问

**Q1: 你能想到几种解法？各自的时间空间复杂度？**
→ 哈希表 O(n)/O(n)、排序 O(n log n)/O(1)、Boyer-Moore O(n)/O(1)、分治 O(n log n)/O(log n)。展示你对多种方法的掌握。

**Q2: Follow-up — 能否 O(n) 时间 O(1) 空间？**
→ Boyer-Moore 投票算法。核心思想是"多数元素和非多数元素一对一抵消，多数元素一定剩余"。

**Q3: 如果不保证多数元素一定存在怎么办？**
→ Boyer-Moore 第一遍找候选人，第二遍验证它出现次数是否真的 > n/2。如果不是则不存在多数元素。

**Q4: 如果要找出现次数超过 ⌊n/3⌋ 的所有元素呢？（LeetCode 229）**
→ 扩展 Boyer-Moore：维护两个候选人和两个计数器。出现超过 n/3 的元素最多两个。最后验证两个候选人的实际计数。
