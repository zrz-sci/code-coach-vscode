# 350. 两个数组的交集 II

## 核心思路

本质上是一个**带计数的匹配**问题：结果中每个元素出现的次数 = 该元素在两个数组中各出现次数的**较小值**。核心操作是"统计频率 + 匹配消耗"。

## 思维链

1. **读完题第一反应** → 交集但要保留重复！和 349 题不同，`[2,2]` 和 `[2,2]` 的交集是 `[2,2]` 而不是 `[2]`。所以不能用 set，需要用计数器。
2. **暴力怎么做？** → 遍历 nums1 的每个元素，在 nums2 中线性查找，找到就放入结果并从 nums2 中"移除"（标记已用）。时间 O(m*n)。
3. **暴力的瓶颈在哪？** → "在 nums2 中查找"这个操作是 O(n)，如果能用哈希表预处理 nums2 的频率，查找就是 O(1)。
4. **哈希表法** → 先对一个数组做频率统计（`{值: 出现次数}`），然后遍历另一个数组，每找到一个匹配就加入结果并将计数减 1。计数减到 0 后不再匹配。
5. **能不能不用额外空间？** → 如果两个数组都排好序，可以用双指针。两个指针同步推进：相等就收集并同时右移，否则值小的那个指针右移。
6. **哪个数组建哈希表？** → 应该对**较小的**数组建表，这样哈希表占用空间更少。如果 nums1 大小远小于 nums2，这个选择很关键。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 哈希表计数 | 小数组建频率表，大数组遍历匹配 | O(m+n) | O(min(m,n)) | ⭐ 面试首选 |
| 排序 + 双指针 | 排序后同步推进 | O(m log m + n log n) | O(1)* | 进阶/Follow-up |
| 暴力匹配 | 双循环逐个查找 | O(m*n) | O(1) | 仅口述 |

*排序解法的空间取决于排序算法本身，如果允许修改原数组则额外空间 O(1)，否则 O(m+n)。

## 关键提示

1. **区分 349 和 350**：349 返回的是集合（去重），用 `set` 就够了；350 返回的带重复次数，必须用计数（`map` 或 `counter`）。
2. **在较小数组上建哈希表**：如果 `nums1.size() > nums2.size()`，交换一下再处理。这样哈希表最大只有 `min(m, n)` 条目。
3. **计数递减到 0 后停止匹配**：`freq[x] > 0` 时才匹配，匹配后 `freq[x]--`，保证结果中的每个元素不超过两数组中的最小出现次数。
4. **排序解法中双指针的移动规则**：值相等 → 两个指针同时右移；不等 → 值小的指针右移（因为排序后，值小的那边不可能在后面找到更大的匹配了）。
5. **Follow-up 三问的回答策略**：这三个 Follow-up 是面试中必问的，需要准备好。

## 解法详解

### 解法1: 哈希表计数 — O(m+n) / O(min(m,n)) ⭐ 面试首选

**思考过程**: 结果中每个元素的出现次数 = `min(在nums1中的次数, 在nums2中的次数)`。用哈希表统计一个数组的频率，然后遍历另一个数组来"消耗"频率。

```
示例: nums1 = [4,9,5], nums2 = [9,4,9,8,4]

Step 1: 对 nums1 建频率表（nums1更小）
  freq = {4:1, 9:1, 5:1}

Step 2: 遍历 nums2，匹配并消耗
  9 → freq[9]=1 > 0 → 收集9, freq[9]-- → freq={4:1, 9:0, 5:1}
  4 → freq[4]=1 > 0 → 收集4, freq[4]-- → freq={4:0, 9:0, 5:1}
  9 → freq[9]=0, 跳过（nums1中只有一个9）
  8 → freq中无8, 跳过
  4 → freq[4]=0, 跳过（nums1中只有一个4）

结果: [9, 4] ✓ （顺序不限）
```

```cpp
class Solution {
public:
    vector<int> intersect(vector<int>& nums1, vector<int>& nums2) {
        // 确保在较小数组上建哈希表，优化空间
        if (nums1.size() > nums2.size()) return intersect(nums2, nums1);

        unordered_map<int, int> freq;
        for (int x : nums1) freq[x]++;

        vector<int> res;
        for (int x : nums2) {
            if (freq[x] > 0) {
                res.push_back(x);
                freq[x]--;
            }
        }
        return res;
    }
};
```

**关键点**:
- `if (nums1.size() > nums2.size()) return intersect(nums2, nums1);` 这一行保证总是在较小数组上建表。递归调用交换参数后直接返回。
- `freq[x] > 0` 而不是 `freq.count(x)`: 因为 `count` 只检查键是否存在，不考虑计数是否已减到 0。而 `freq[x] > 0` 同时检查了存在性和剩余可用次数。
- 时间 O(m+n)：遍历两个数组各一次。空间 O(min(m,n))：哈希表大小等于较小数组的去重元素数。

---

### 解法2: 排序 + 双指针 — O(m log m + n log n) / O(1)

**从不同角度思考**: 如果两个数组都排好序，交集问题就变成了"归并两个有序数组中的公共元素"，和归并排序的合并步骤非常相似。

```
示例: nums1 = [1,2,2,1], nums2 = [2,2]

排序后: nums1 = [1,1,2,2], nums2 = [2,2]

双指针过程:
  i=0, j=0: nums1[0]=1 < nums2[0]=2 → i++
  i=1, j=0: nums1[1]=1 < nums2[0]=2 → i++
  i=2, j=0: nums1[2]=2 == nums2[0]=2 → 收集2, i++, j++
  i=3, j=1: nums1[3]=2 == nums2[1]=2 → 收集2, i++, j++
  i=4: 越界，结束

结果: [2, 2] ✓
```

```
为什么双指针不会漏掉公共元素？
- 两个指针都只往右移，每个元素最多被访问一次
- 当 nums1[i] < nums2[j]: nums1[i] 不可能和 nums2[j] 及之后的元素匹配（有序递增），所以安全跳过
- 当 nums1[i] > nums2[j]: 同理，nums2[j] 不可能和 nums1[i] 及之后的匹配
- 当 nums1[i] == nums2[j]: 匹配成功，两个都右移，消耗各一个
```

```cpp
class Solution {
public:
    vector<int> intersect(vector<int>& nums1, vector<int>& nums2) {
        sort(nums1.begin(), nums1.end());
        sort(nums2.begin(), nums2.end());

        vector<int> res;
        int i = 0, j = 0;
        while (i < (int)nums1.size() && j < (int)nums2.size()) {
            if (nums1[i] < nums2[j]) {
                i++;        // nums1 当前值太小，右移追赶
            } else if (nums1[i] > nums2[j]) {
                j++;        // nums2 当前值太小，右移追赶
            } else {
                res.push_back(nums1[i]);  // 相等 → 收集
                i++;
                j++;
            }
        }
        return res;
    }
};
```

**关键点**:
- 此解法修改了原数组（排序）。如果不允许修改，需要先拷贝再排序，空间 O(m+n)。
- 双指针本身的逻辑只有 O(m+n)，瓶颈在排序的 O(m log m + n log n)。
- 这个解法在 **Follow-up 1**（数组已排序）场景下特别有优势：无需排序，直接双指针，O(m+n) 时间 O(1) 空间。

## 解法对比

|  | 哈希表计数 | 排序+双指针 |
|--|-----------|------------|
| 时间 | **O(m+n)** | O(m log m + n log n) |
| 空间 | O(min(m,n)) | **O(1)** (修改原数组) |
| 数组已排序时 | O(m+n), O(min(m,n)) | **O(m+n), O(1)** |
| nums1 远小于 nums2 | **O(m+n), O(m)** | O(m log m + n log n) |
| nums2 在磁盘上 | **可分块处理** | 需外排序 |

**面试选择**: 默认写哈希表解法。Follow-up 问到"已排序"时，切换到双指针。

## 易错点

1. **用 `set` 代替 `map` — 丢失重复次数**：
   - ✗ `unordered_set<int> s(nums1.begin(), nums1.end());` → `[2,2] ∩ [2,2]` 只返回 `[2]`
   - ✓ 必须用 `unordered_map<int, int>` 记录频率

2. **忘记检查计数是否>0**：
   - ✗ `if (freq.count(x)) { res.push_back(x); freq[x]--; }` → 计数减到负数，多匹配
   - ✓ `if (freq[x] > 0) { res.push_back(x); freq[x]--; }`

3. **双指针中相等时只移动一个指针**：
   - ✗ `if (nums1[i] == nums2[j]) { res.push_back(nums1[i]); i++; }` → j 没动，下次还会匹配同一个 nums2[j]
   - ✓ 相等时 `i++; j++;` 两个都要移动

4. **没有在较小数组上建哈希表**：
   - 功能上不影响正确性，但空间可能从 O(min(m,n)) 退化到 O(max(m,n))
   - 面试中这个优化值得主动提到

## 面试追问 — Follow-up 三连

**Q1: 如果给定的数组已经排好序了呢？你将如何优化你的算法？**
> **排序 + 双指针**最优：跳过排序步骤，直接双指针扫描，O(m+n) 时间 O(1) 空间。比哈希表省了 O(min(m,n)) 的空间。

**Q2: 如果 nums1 的大小比 nums2 小很多，哪种方法更优？**
> **哈希表法更优**。在 nums1（小数组）上建哈希表，空间 O(m)（m 很小）。然后遍历 nums2，总时间 O(m+n)。
> 如果用排序+双指针，排序 nums2 的代价 O(n log n) 可能更大。
> 进一步优化：对小数组排序后，对大数组的每个元素用**二分查找**在小数组中定位，时间 O(n log m)。当 m << n 时可能比 O(m+n) 的哈希表法更优（因为省了哈希表的常数开销和空间）。

**Q3: 如果 nums2 的元素存储在磁盘上，内存有限，不能一次性加载所有元素到内存中，怎么办？**
> 1. **哈希表法（推荐）**：把 nums1 加载到内存中建哈希表（假设 nums1 能放下），然后分块读取 nums2 的数据进行匹配。
> 2. 如果两个数组都太大：**外排序 + 双指针**。先用外排序将两个数组各自排好序，然后用两个读指针分块读取进行归并比较。
> 3. 如果内存极度有限，只能放下极少量数据：用 **MapReduce** 思想，按哈希值将两个数组的元素分桶，相同桶号的元素必定有相同的值，逐桶在内存中做交集。
