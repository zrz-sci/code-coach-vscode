# 408. 有效单词缩写

## 核心思路

本质上就是**模式匹配**：用两个指针分别扫描原词 `word` 和缩写 `abbr`，遇到字母就逐个比对，遇到数字就把 `word` 的指针往前跳对应步数，最终看两个指针是否同时到达末尾。

## 思维链

1. **读完题第一反应**：缩写是由字母和数字交替组成的，数字代表"跳过原词中多少个字符"。我需要"展开"缩写，看展开后是否和原词一致。
2. **怎么"展开"？** 最直觉的想法：遍历 `abbr`，遇到字母就和 `word` 当前位置比对，遇到数字就累加成完整数值然后让 `word` 指针跳过对应长度。
3. **有什么坑？** 数字可能是多位的（如 `12`），需要连续读取所有数字字符拼成完整数值。另外前导零（如 `01`）和零本身（如 `0`）是非法的。
4. **怎么判结束？** 两个指针必须**同时**到达各自字符串末尾，缺一不可——如果 `word` 还有剩余或者 `abbr` 还有剩余，都说明不匹配。
5. **复杂度如何？** 一次遍历，每个字符只看一次，O(n) 时间 O(1) 空间，已经是最优了。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 双指针模拟 | 两个指针同步扫描，遇数字跳指针，遇字母逐个比 | O(n) | O(1) | ⭐ 必须写出 |

> 这道 Easy 题只有一种核心解法，关键在于写对细节（前导零、多位数字、边界）。

## 关键提示

1. **前导零陷阱**：当你遇到数字字符 `'0'` 时，如果它是数字序列的第一个字符，说明缩写非法（`"s010n"` 中的 `010`），直接返回 `false`。
2. **多位数字拼接**：`abbr` 中的数字可能不止一位，例如 `"i12iz4n"` 中的 `12`。遇到数字要用 `num = num * 10 + (ch - '0')` 持续累加。
3. **同时到达末尾**：最终检查条件不是 `i == word.size()` 也不是 `j == abbr.size()`，而是两者**同时**成立。
4. **模拟过程示意**：

```
word:  i n t e r n a t i o n a l i z a t i o n
       ↑                         ↑       ↑   ↑
abbr:  i 1 2                     i z 4   n
       ↑ ↑←——12个字符——→         ↑ ↑ ↑←4→↑

匹配过程:
  i=0, j=0: 'i' == 'i' ✓ → i=1, j=1
  i=1, j=1: abbr[j]='1', 继续读 '2' → num=12 → i跳到13, j=3
  i=13, j=3: 'i' == 'i' ✓ → i=14, j=4
  i=14, j=4: 'z' == 'z' ✓ → i=15, j=5
  i=15, j=5: abbr[j]='4' → num=4 → i跳到19, j=6
  i=19, j=6: 'n' == 'n' ✓ → i=20, j=7
  i=20, j=7: 两个都到末尾 → true!
```

## 解法详解

### 解法1: 双指针同步扫描 — O(n) / O(1) ⭐ 面试首选

**思考过程**：缩写就像一个"压缩格式"——字母是原样保留的锚点，数字是"跳过N个字符"的指令。我们只需要一个指针 `i` 跟踪 `word` 的当前位置，一个指针 `j` 跟踪 `abbr` 的当前位置，然后按规则同步推进即可。

```cpp
class Solution {
public:
    bool validWordAbbreviation(string word, string abbr) {
        int i = 0, j = 0;
        int m = word.size(), n = abbr.size();
        
        while (i < m && j < n) {
            if (isdigit(abbr[j])) {
                // 前导零非法：缩写中数字不能以 '0' 开头
                if (abbr[j] == '0') return false;
                
                // 连续读取所有数字字符，拼成完整数值
                int num = 0;
                while (j < n && isdigit(abbr[j])) {
                    num = num * 10 + (abbr[j] - '0');
                    j++;
                }
                // word 指针跳过 num 个字符
                i += num;
            } else {
                // 字母：必须逐个匹配
                if (word[i] != abbr[j]) return false;
                i++;
                j++;
            }
        }
        
        // 两个指针必须同时到达末尾
        return i == m && j == n;
    }
};
```

**关键点**：
- 前导零检测必须在累加数字**之前**做，否则 `num=0` 和 `num=01` 分不清。
- `i += num` 后 `i` 可能超过 `m`，这没关系——循环条件 `i < m` 会终止循环，最后 `i == m` 检查会判断是否恰好用完。

## 解法对比

本题只有一种核心思路（双指针模拟），没有暴力 vs 优化的演进。区别主要在实现细节的写法上：
- 有些人会先把 abbr "展开"成完整字符串再比较——这浪费 O(n) 空间且没必要。
- 双指针原地比对是最简洁、最优的方式。

## 易错点

1. **✗ 忘记检测前导零**：
   ```cpp
   // 错误：直接累加数字，"s010n" 会被当成合法的 10
   int num = 0;
   while (j < n && isdigit(abbr[j])) {
       num = num * 10 + (abbr[j] - '0');
       j++;
   }
   ```
   **✓ 正确：在进入数字累加前检查第一个字符是否为 '0'**
   ```cpp
   if (abbr[j] == '0') return false;  // 前导零直接非法
   int num = 0;
   while (j < n && isdigit(abbr[j])) { ... }
   ```

2. **✗ 最终只检查一个指针**：
   ```cpp
   return i == m;  // 错误：abbr 可能还没用完
   ```
   **✓ 正确：两个都必须到末尾**
   ```cpp
   return i == m && j == n;
   ```

3. **✗ 数字累加后忘记 i 可能越界**：
   ```cpp
   i += num;
   if (word[i] != abbr[j]) ...  // i 可能已经 >= m，越界访问！
   ```
   **✓ 正确：跳转后回到 while 循环头部重新检查 `i < m`**

4. **✗ 把 `"s0ubstitution"` 当合法（数字0代表替换0个字符）**：
   题目明确说缩写替换的是"非空子串"，所以数字不能为 0。前导零检测恰好也覆盖了这个 case（`'0'` 作为数字序列开头直接返回 false）。

## 面试追问

**Q1: 为什么不能先把 abbr 展开成完整字符串再比较？**
> 可以这么做，但浪费 O(n) 空间。双指针原地比对是 O(1) 空间，更优。面试官可能会追问能否不用额外空间。

**Q2: 如果 abbr 中的数字非常大（比如 `"999999999"`），会不会有问题？**
> 题目说数字在 32-bit 整数范围内，所以用 `int` 就够了。但实际上 `word.length <= 20`，所以如果 num > 20 直接可以返回 false（可以加这个剪枝，但不是必须的）。

**Q3: 如果要你生成一个单词的所有合法缩写呢？（LeetCode 320）**
> 那就变成了回溯问题——对 word 的每个位置，选择保留字母或替换成数字，注意不相邻的约束。本题的匹配逻辑可以用来验证生成结果的正确性。
