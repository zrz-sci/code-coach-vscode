# 268. 丢失的数字

## 核心思路

`[0, n]` 共 `n+1` 个数，数组里有 `n` 个，恰好缺一个。本质上是**找出完整集合与当前集合的"差异"**。

## 思维链

1. **读完题第一反应**：有 `n` 个数，范围是 `[0, n]`，缺了一个。最朴素的做法？对每个 `0` 到 `n` 的数，去数组里查一遍是否存在，不存在的就是答案。→ 暴力 O(n²)。

2. **暴力解的瓶颈在哪？** 对每个候选数字，都要线性扫描整个数组来判断"是否存在"，查找操作是 O(n)。

3. **怎么加速查找？** 用哈希表（HashSet）存所有出现过的数，查找从 O(n) → O(1)。→ O(n) 时间，O(n) 空间。

4. **能否不用额外空间？** 想想数学：`[0, n]` 的总和是 `n*(n+1)/2`，减去数组实际的和，差值就是缺失的数。→ O(n) 时间，O(1) 空间。

5. **还有别的 O(1) 空间方案吗？** 位运算：异或的性质 `a ^ a = 0, a ^ 0 = a`。把 `0~n` 和数组所有元素全部异或，成对的数字互相抵消，剩下的就是缺失的那个。→ O(n) 时间，O(1) 空间，且没有溢出风险。

6. **排序也行**：排序后 `nums[i]` 应该等于 `i`，第一个不等的位置就是答案。→ O(n log n) 时间，但思路最直觉。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 排序 | 排序后找第一个 `nums[i] != i` | O(n log n) | O(1) | 能说出即可 |
| 哈希表 | 集合查存在性 | O(n) | O(n) | 能说出即可 |
| 数学（求和） | 期望总和 - 实际总和 | O(n) | O(1) | ⭐ 必须写出 |
| 位运算（异或） | 全部异或，成对抵消 | O(n) | O(1) | 加分项 |

## 关键提示

1. **数学角度**：如果 `[0, n]` 所有数都在，总和是多少？现在缺了一个，总和差了多少？
2. **异或角度**：回忆 "Single Number"（136 题），同一个数异或两次等于没有。这里能否构造出"每个数恰好出现两次，只有缺失的数出现一次"的效果？
3. **排序角度**：排序后数组应该长什么样？`[0, 1, 2, ..., n]` 少了一个，第一个"不对劲"的位置在哪？
4. **溢出陷阱**：求和法中 `n*(n+1)/2` 在 `n` 很大时可能溢出 `int`，但本题 `n ≤ 10⁴`，不会溢出。面试中要主动提到这个意识。
5. **进阶要求**：题目 Follow-up 要求 O(n) 时间 + O(1) 空间，求和法和异或法都满足。

## 解法详解

### 解法1: 排序 — O(n log n) / O(1)

**思考过程**: 最直觉的想法——排序后，位置 `i` 应该放数字 `i`。找到第一个 `nums[i] != i` 的位置即可。如果所有位置都对，说明缺的是最后一个数 `n`。

```cpp
class Solution {
public:
    int missingNumber(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int n = nums.size();
        for (int i = 0; i < n; i++) {
            if (nums[i] != i) return i;
        }
        // 0 ~ n-1 都在，缺的是 n
        return n;
    }
};
```

**关键点**: 别忘了循环结束后 `return n` 的情况（如 `nums = [0, 1]`，缺的是 `2`）。

---

### 解法2: 哈希表 — O(n) / O(n)

**从解法1优化**: 排序的 O(n log n) 是为了让"查找某个数是否存在"变快。哈希表可以 O(1) 查找，不需要排序。

```cpp
class Solution {
public:
    int missingNumber(vector<int>& nums) {
        unordered_set<int> s(nums.begin(), nums.end());
        int n = nums.size();
        for (int i = 0; i <= n; i++) {
            if (s.find(i) == s.end()) return i;
        }
        return -1; // 不会到达
    }
};
```

**关键点**: 遍历范围是 `[0, n]`（包含 `n`），不是 `[0, n-1]`。

---

### 解法3: 数学（求和） — O(n) / O(1) ⭐ 面试首选

**核心观察**: 完整的 `[0, n]` 总和是 `n*(n+1)/2`。数组的和缺了一个数，差值就是答案。

```
期望: 0 + 1 + 2 + 3 = 6  (n=3)
实际: 3 + 0 + 1     = 4
差值: 6 - 4 = 2 ← 缺失的数
```

```cpp
class Solution {
public:
    int missingNumber(vector<int>& nums) {
        int n = nums.size();
        // 等差数列求和公式，得到 [0,n] 的完整总和
        int expectedSum = n * (n + 1) / 2;
        int actualSum = 0;
        for (int x : nums) {
            actualSum += x;
        }
        // 差值就是缺失的那个数
        return expectedSum - actualSum;
    }
};
```

**关键点**: 面试时主动说"如果 n 很大，`n*(n+1)/2` 可能溢出 int"。本题 n ≤ 10⁴ 没问题，但如果 n 到 10⁹ 级别，需要用 `long long` 或者改用异或法来避免溢出。

---

### 解法4: 位运算（异或） — O(n) / O(1) 加分项

**核心思想**: 异或的性质 — `a ^ a = 0`，`a ^ 0 = a`。把索引 `0, 1, ..., n` 和数组所有元素全部异或在一起，存在的数字会出现两次（一次在索引里，一次在数组值里），异或后抵消为 0，只剩下缺失的那个数。

```
索引:  0  1  2  3      (n = 3)
数组:  3  0  1

全部异或: (0^1^2^3) ^ (3^0^1)
        = 0^0 ^ 1^1 ^ 2 ^ 3^3
        = 0   ^ 0   ^ 2 ^ 0
        = 2  ← 缺失的数
```

```cpp
class Solution {
public:
    int missingNumber(vector<int>& nums) {
        int n = nums.size();
        int xorAll = 0;
        // 异或上所有索引 0~n
        for (int i = 0; i <= n; i++) {
            xorAll ^= i;
        }
        // 异或上数组中所有值
        for (int x : nums) {
            xorAll ^= x;
        }
        // 成对的数抵消，剩下的就是缺失的数
        return xorAll;
    }
};
```

也可以合并成一个循环（更简洁）：

```cpp
class Solution {
public:
    int missingNumber(vector<int>& nums) {
        int n = nums.size();
        int xorAll = n; // 先异或上 n（因为循环只到 n-1）
        for (int i = 0; i < n; i++) {
            xorAll ^= i ^ nums[i]; // 同时异或索引和值
        }
        return xorAll;
    }
};
```

**关键点**: 为什么初始化 `xorAll = n`？因为循环 `i` 从 `0` 到 `n-1`，覆盖了索引 `0~n-1`，但我们需要 `0~n` 的异或，所以提前把 `n` 异或进去。

## 解法对比

| | 排序 | 哈希表 | 求和 | 异或 |
|--|------|--------|------|------|
| 时间 | O(n log n) | O(n) | O(n) | O(n) |
| 空间 | O(1)* | O(n) | O(1) | O(1) |
| 溢出风险 | 无 | 无 | n 大时有 | 无 |
| 面试推荐度 | 低 | 中 | **高** | 高 |

> *排序看实现，原地排序 O(1)，否则 O(n)

- **求和法**最适合面试首选：直觉、简洁、O(1) 空间，且容易解释。
- **异或法**是加分项：展示位运算功底，且无溢出风险。
- **哈希表**是最自然的"降低查找复杂度"思路，适合作为引出求和/异或之前的过渡。

## 易错点

1. **遍历范围错误**
   - ✗ `for (int i = 0; i < n; i++)` 然后遍历候选数字 — 漏掉了 `n` 本身
   - ✓ `for (int i = 0; i <= n; i++)` — 范围是 `[0, n]`，共 `n+1` 个候选

2. **排序法忘记 return n**
   - ✗ 循环结束后没有返回值 — 当 `nums = [0, 1, 2]` 时缺的是 `3(=n)`
   - ✓ 循环后 `return n;`

3. **异或法初始值错误**
   - ✗ 合并循环时 `xorAll = 0`，循环 `i` 只到 `n-1` — 漏掉了 `n`
   - ✓ `xorAll = n`，因为循环只覆盖 `0` 到 `n-1`

4. **求和溢出（面试意识）**
   - 本题 `n ≤ 10⁴`，`n*(n+1)/2 ≤ 5×10⁷`，int 够用
   - 但面试要主动说：如果 `n` 到 `10⁹` 级别，需要 `long long` 或改用异或

## 面试追问

**Q1（基础理解）**: "暴力怎么做？复杂度多少？"
→ 对每个 `0~n`，线性扫描数组看是否存在。O(n²) 时间，O(1) 空间。

**Q2（优化）**: "能否 O(n) 时间？"
→ 哈希表 O(n)/O(n)，或者求和法 O(n)/O(1)。

**Q3（进阶 Follow-up）**: "能否 O(n) 时间 + O(1) 空间？"
→ 求和法或异或法。两者都 O(n)/O(1)，异或法没有溢出风险。

**Q4（变体）**: "如果数组范围是 `[1, n]` 而不是 `[0, n]` 呢？"
→ 完全一样的方法，只是期望总和变成 `n*(n+1)/2`（从 1 加到 n），数组也少了一个。

**Q5（扩展）**: "如果缺了两个数呢？"
→ 单纯异或只能得到两个缺失数的异或值，需要额外技巧（按某一位分组，分别异或）。参见 LeetCode 260。
