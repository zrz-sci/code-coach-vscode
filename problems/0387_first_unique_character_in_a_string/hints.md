# 387. 字符串中的第一个唯一字符

## 核心思路
本质上在问：**统计每个字符的出现次数，然后按原始顺序找到第一个次数为1的字符**。关键在于"第一个"要求我们保持原始顺序。

## 思维链

1. **读完题第一反应**：对每个字符，检查它在整个字符串中是否只出现了一次。最朴素的做法——对每个位置 i，扫描整个字符串看有没有另一个位置 j 和它相同。
2. **暴力解的瓶颈**：双重循环 O(n²)，对每个字符都要扫一遍全串，查找操作太慢。
3. **怎么突破瓶颈**？字符串只包含小写字母（26种），完全可以先用一个计数数组/哈希表一次遍历统计所有字符的频次，查频次就是 O(1)。
4. **具体做法**：第一遍遍历统计频次，第二遍遍历找第一个频次为 1 的位置。两次 O(n) 遍历，总体 O(n)。
5. **进阶思考**：如果是数据流场景（字符一个个到来，随时查询第一个唯一字符），可以用队列 + 哈希表来做。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力双循环 | 对每个字符扫全串检查唯一性 | O(n²) | O(1) | 能说出即可 |
| 计数数组（两遍遍历） | 统计频次 + 顺序查找 | O(n) | O(1)* | ⭐ 必须写出 |
| 队列 + 哈希表（流式） | 维护候选唯一字符队列 | O(n) | O(1)* | 加分项 |

> *空间 O(1) 是因为字符集固定为 26 个小写字母，哈希表/数组大小为常数。

## 关键提示

1. **字符集有限**：只有 26 个小写字母，这意味着计数数组的大小是常数，不随 n 增长。
2. **两遍遍历的顺序很重要**：第一遍统计频次，第二遍按**原始顺序**遍历——这样第一个找到的频次为 1 的就是答案。如果遍历哈希表，顺序不保证！
3. **队列解法的关键**：队列天然维护"先进先出"的顺序，配合频次表可以弹出已经不唯一的字符。
4. **想一想**：为什么不能只遍历一次就得到答案？因为后面可能出现和前面相同的字符，第一次遍历时无法确定某字符是否唯一。

## 解法详解

### 解法1: 暴力双循环 — O(n²) / O(1)

**思考过程**：最直觉的方法——对字符串中的每个位置 i，检查是否存在另一个位置 j (j≠i) 使得 s[j] == s[i]。如果不存在，i 就是答案。

```cpp
class Solution {
public:
    int firstUniqChar(string s) {
        int n = s.size();
        for (int i = 0; i < n; i++) {
            bool unique = true;
            for (int j = 0; j < n; j++) {
                if (i != j && s[i] == s[j]) {
                    unique = false;
                    break;    // 发现重复，无需继续
                }
            }
            if (unique) return i;  // 第一个没有重复的
        }
        return -1;
    }
};
```

**关键点**：内层循环发现重复后要 `break`，否则白白浪费时间。这个解法对 n=10⁵ 太慢。

---

### 解法2: 计数数组（两遍遍历） — O(n) / O(1) ⭐ 面试首选

**从解法1优化**：解法1的瓶颈是"对每个字符都要 O(n) 扫全串判断是否唯一"。如果我们**先用一遍遍历统计每个字符出现了多少次**，之后判断唯一性就是 O(1) 查表。

```
// 示例: s = "loveleetcode"
//
// 第一遍统计频次:
// l:1  o:2  v:1  e:4  l→变2  t:1  c:1  d:1
// count = {l:2, o:2, v:1, e:4, t:1, c:1, d:1}
//
// 第二遍按原始顺序查找:
// index 0: 'l' → count=2, 跳过
// index 1: 'o' → count=2, 跳过
// index 2: 'v' → count=1, ✅ 返回 2
```

```cpp
class Solution {
public:
    int firstUniqChar(string s) {
        // 只有26个小写字母，用数组比 unordered_map 更快
        int count[26] = {0};
        
        // 第一遍：统计每个字符的出现次数
        for (char c : s) {
            count[c - 'a']++;
        }
        
        // 第二遍：按原始顺序找第一个次数为1的
        for (int i = 0; i < s.size(); i++) {
            if (count[s[i] - 'a'] == 1) {
                return i;
            }
        }
        
        return -1;
    }
};
```

**关键点**：
- 第二遍必须遍历原字符串（而不是遍历 count 数组），因为我们要的是**第一个**唯一字符的**索引**。
- 用 `int count[26]` 而不是 `unordered_map`，常数因子更小。

---

### 解法3: 队列 + 哈希表（流式处理） — O(n) / O(1)

**适用场景**：如果字符是流式到来的（Follow-up: 数据流场景），我们需要随时查询当前的第一个唯一字符。队列维护"候选唯一字符"的顺序，频次表用于判断是否仍然唯一。

```
// 模拟 s = "leetcode" 的流式处理:
//
// 读入 'l': queue=[l]  count={l:1}         → 队首 'l' 是唯一的
// 读入 'e': queue=[l,e] count={l:1,e:1}    → 队首 'l' 是唯一的
// 读入 'e': queue=[l,e,e] count={e:2}      → 队首 'l' 仍是唯一的
//   清理队首: 'l' count=1 → 不弹出         → 第一个唯一: 'l'
// 读入 't': queue=[l,e,e,t] count={t:1}    → 队首 'l' 是唯一的
// ...
// 如果后来又读入 'l': count={l:2}
//   查询时弹出队首 'l'(count=2 不唯一), 弹出 'e'(count=2), 弹出 'e'...
//   直到找到 count=1 的队首
```

```cpp
class Solution {
public:
    int firstUniqChar(string s) {
        int count[26] = {0};
        queue<int> q;  // 存索引，维护候选唯一字符的顺序
        
        for (int i = 0; i < s.size(); i++) {
            count[s[i] - 'a']++;
            q.push(i);
            
            // 弹出队首已经不唯一的字符（延迟删除）
            while (!q.empty() && count[s[q.front()] - 'a'] > 1) {
                q.pop();
            }
        }
        
        return q.empty() ? -1 : q.front();
    }
};
```

**关键点**：
- 队列中的元素可能随着后续字符的加入变得"不唯一"，所以每次都要检查队首。
- 每个索引最多入队一次、出队一次，所以总的时间仍是 O(n)。

## 易错点

1. **✗ 遍历计数数组找最小索引**：
   ```cpp
   // 错误：遍历 count 数组找 count==1 的字符，然后用 s.find() 找索引
   for (int i = 0; i < 26; i++) {
       if (count[i] == 1) return s.find('a' + i);
   }
   ```
   这样找到的是**字母序最小的唯一字符**，不是**第一个出现的唯一字符**。比如 `"dc"` 应该返回 0（'d'），但上面代码会返回 1（'c'）。
   
   **✓ 正确做法**：第二遍遍历原字符串，保持原始顺序。

2. **✗ 用 `unordered_map` 遍历找结果**：
   ```cpp
   for (auto& [c, cnt] : mp) { if (cnt == 1) ... }
   ```
   `unordered_map` 遍历顺序不确定，无法保证找到"第一个"。必须遍历原字符串。

3. **✗ 忘记处理全部重复的情况**：函数末尾忘记 `return -1`。

## 面试追问

**Q1: 基础理解** — 为什么需要两遍遍历，一遍行不行？
> 不行。第一遍遍历时，当前字符是否唯一取决于**后面**是否还会出现相同字符，这在一遍遍历中无法确定。（除非用队列做延迟判断，但本质上也是"回头检查"。）

**Q2: 优化** — 如果字符串非常长但字符集很小（比如只有小写字母），有什么好处？
> 计数数组大小固定为 26，空间是 O(|Σ|) = O(1)。第二遍遍历虽然是 O(n)，但可以提前终止（找到第一个就返回）。最坏情况仍然是 O(n)。

**Q3: 变体/Follow-up** — 如果字符是流式到来的，每来一个字符就要能查询"当前第一个唯一字符"，怎么做？
> 用解法3的队列方案。维护一个候选队列和频次表，每次新字符到来时更新频次、入队、弹出队首中已不唯一的元素。队首就是答案。每次查询 O(1) 摊还。

**Q4: 延伸** — 如果不限于小写字母，而是任意 Unicode 字符呢？
> 把 `int count[26]` 换成 `unordered_map<char, int>`，逻辑不变，空间变为 O(|Σ|)。
