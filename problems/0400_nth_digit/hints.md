# 400. 第 N 位数字

## 核心思路

这道题本质上是一个**数学分段定位**问题：将自然数序列 1,2,3,...拼成一个无穷字符串"123456789101112..."，给定位置 n，找到该位置上的数字。关键在于：自然数按位数分段（1位数、2位数、3位数...），每段的数字个数和总位数都有确定的公式，利用这些公式逐段减去即可精确定位。

## 思维链

1. **读完题第一反应**：序列"123456789101112131415..."是自然数拼在一起，第 n 位是这个大字符串里的某个字符。直觉是暴力拼接字符串然后取第 n 位，但 n 最大到 2^31-1（约 21 亿），暴力不可行。

2. **寻找规律 — 按位数分段**：
   - 1 位数：1~9，共 9 个数，占 9 x 1 = 9 位
   - 2 位数：10~99，共 90 个数，占 90 x 2 = 180 位
   - 3 位数：100~999，共 900 个数，占 900 x 3 = 2700 位
   - d 位数：共 `9 * 10^(d-1)` 个数，占 `d * 9 * 10^(d-1)` 位
   
   这个结构很整齐，可以逐段减去，直到 n 落在某个段内。

3. **三步定位法**：
   - **第一步：确定位数 d** — 逐段减去 `d * 9 * 10^(d-1)` 直到 n 无法再减。
   - **第二步：确定是哪个数** — 当前段的起始数是 `start = 10^(d-1)`，目标数 = `start + (n-1) / d`。
   - **第三步：确定是该数的第几位** — 位内偏移 = `(n-1) % d`，将数转为字符串取对应位。

4. **溢出风险**：d 位数的总位数 `d * 9 * 10^(d-1)` 在 d=9 时约为 81 亿，超过 int 范围，必须用 long。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力拼接 | 逐个数拼成字符串取第 n 位 | O(n) | O(n) | 会超时 |
| 数学分段定位 | 按位数分段定位到具体数字 | O(log n) | O(1) | ⭐ 必须写出 |

## 关键提示

1. **为什么用 (n-1)/d 而不是 n/d？** — 因为 n 是 1-based 的。例如 n=1 应该对应段内第 0 个偏移（即 start 本身），`(1-1)/d = 0` 正确；如果用 `n/d`，n=d 时得到 1 就错位了。

2. **为什么用 (n-1)%d？** — 同理，1-based 转 0-based 索引。n=1 对应第 0 位（最高位），n=d 对应第 d-1 位（最低位）。

3. **必须用 long** — `digits * count` 可能溢出 int。例如 d=10 时，`count = 9*10^9`，`digits*count` 约 90 亿。

4. **和二分查找的关系** — 虽然标签里有"二分查找"，但直接用分段减法更直观。如果用二分，可以二分搜索 n 落在哪个位数段中，但没有必要。

5. **面试高频追问**：给定 n 能否快速知道它属于几位数？答案就是第一步的逐段减法，最多循环 9 次（因为 int 最多 10 位数）。

```
完整手算示例: n = 187

第一步: 确定位数段
  n = 187
  d=1: 1位数占 9 位, 187 > 9 → n = 187 - 9 = 178
  d=2: 2位数占 180 位, 178 < 180 → n落在2位数段

第二步: 确定是哪个数
  start = 10 (2位数起始)
  num = 10 + (178 - 1) / 2 = 10 + 88 = 98

第三步: 确定是该数的第几位
  idx = (178 - 1) % 2 = 1  (第1位，0-based)
  "98" → 第1位 = '8'
  
答案: 8

验证: 1~9 占 9 位, 10~98 占 89*2 = 178 位
  总计 9 + 178 = 187 位
  第 187 位是 98 的最后一位 = 8 ✓
```

## 解法详解

### 解法1: 暴力拼接（会超时）— O(n) / O(n)

**思考过程**: 最直觉的方式——逐个把自然数转成字符串拼接起来，然后取第 n 位。简单但当 n 极大时不可行。

```cpp
class Solution {
public:
    int findNthDigit(int n) {
        // 暴力：逐个拼接（会超时/超内存）
        string s;
        for (int num = 1; s.size() < (size_t)n; num++) {
            s += to_string(num);
        }
        return s[n - 1] - '0';
    }
};
```

**关键点**: 这个解法在 n 小时可以工作，但 n 最大到 2^31-1，会超时超内存。它的价值在于帮助理解问题——我们需要的是这个巨大字符串中的某个字符。

### 解法2: 数学分段定位 — O(log n) / O(1)

**思考过程**: 不需要真的拼接字符串。利用位数段的规律，三步定位：(1) 确定落在几位数段 → (2) 确定是该段第几个数 → (3) 确定是该数的第几位。

```cpp
class Solution {
public:
    int findNthDigit(int n) {
        long digits = 1;  // 当前位数
        long count = 9;   // 当前段有多少个数
        long start = 1;   // 当前段的起始数字

        // 第一步：确定 n 落在几位数段
        while (n > digits * count) {
            n -= digits * count;
            digits++;
            count *= 10;
            start *= 10;
        }
        // 第二步：确定是该段的第几个数
        long num = start + (n - 1) / digits;
        // 第三步：确定是该数的第几位
        int idx = (n - 1) % digits;
        string s = to_string(num);
        return s[idx] - '0';
    }
};
```

**关键点**:
- while 循环最多执行 9 次（int 范围内最多 10 位数），所以是 O(1) 或 O(log n)。
- `digits`, `count`, `start` 必须是 long 类型，否则 `digits * count` 会溢出。
- `(n-1)/digits` 和 `(n-1)%digits` 配合使用实现 1-based 到 0-based 的转换。

## 易错点

1. **整数溢出**：`digits * count` 在 d 较大时会超过 int 范围。即使 n 本身是 int，中间计算也必须用 long。

2. **1-based vs 0-based 混淆**：n 是 1-based 的，`(n-1)/d` 得到的是 0-based 的偏移量。写成 `n/d` 会导致边界错误。

3. **start 的初始值**：1 位数段的 start 是 1（不是 0），2 位数段是 10，3 位数段是 100。

4. **to_string 后的索引**：`s[idx]` 返回的是 char，需要减去 '0' 转为 int。

## 面试追问

### 追问1: 能否用二分查找？

可以。二分搜索目标数字 num，check(num) 函数计算从 1 到 num 总共占多少位，与 n 比较。这等价于用前缀和思想替代逐段减法，但实现更复杂，面试中通常不必要。

### 追问2: 如果要求从 0 开始（序列为 0,1,2,3,...），怎么改？

只需处理 0 这个特例：如果 n=1，直接返回 0。否则 n 减 1 后按原逻辑处理。或者更优雅地，将 start 改为 0，count 改为 10（0~9 有 10 个 1 位数）。

### 追问3: 如果序列不是十进制而是 k 进制呢？

将公式中的 10 替换为 k 即可：d 位数有 `(k-1) * k^(d-1)` 个（d=1 时特殊处理为 k 个），其余逻辑完全相同。
