# 771. 宝石与石头 (Jewels and Stones)

**难度**: Easy | **标签**: Hash Table, String

## 核心思路

将宝石类型存入哈希集合（HashSet），然后遍历石头字符串，统计属于宝石类型的石头数量。本质上是一个**集合查找**问题：对 stones 中的每个字符，查询它是否在 jewels 集合中。

## 思维链

1. **问题简化**: jewels 中每个字符代表一种宝石类型（唯一），stones 中每个字符代表一颗石头。统计 stones 中有多少字符出现在 jewels 中。
2. **暴力思路**: 双层循环 O(J*S) -- 对每颗石头遍历所有宝石类型，效率低。
3. **优化思路**: 将 jewels 存入 HashSet，查找 O(1)，总体 O(J+S)。
4. **极致优化**: 由于字符集有限（52 个英文字母），可以用位运算或数组代替 HashSet。

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 适用场景 |
|------|-----------|-----------|---------|
| 哈希集合 | O(J + S) | O(J) | 通用解法，面试首选 |
| 数组标记 (128) | O(J + S) | O(1) | 字符集有限时最优 |
| 位运算标记 | O(J + S) | O(1) | 仅小写或仅大写时 |
| 暴力双循环 | O(J * S) | O(1) | 不推荐 |

> J = jewels.length, S = stones.length

## 关键提示

1. **大小写敏感**: `'a'` 和 `'A'` 是不同的宝石类型，不要忽略大小写。
2. **jewels 字符唯一**: 题目保证 jewels 中无重复字符，可以直接用集合或布尔数组。
3. **字符集范围**: 只包含英文字母（52种），可用固定大小数组替代哈希表。
4. **一次遍历**: 先建立 jewels 集合（O(J)），再遍历 stones 计数（O(S)），两步分离清晰。

## 解法详解

### 解法一：哈希集合 (推荐)

**思路**:
1. 将 jewels 中所有字符加入一个 `unordered_set<char>`。
2. 遍历 stones 中的每个字符，若在集合中则计数器加一。
3. 返回计数器。

**为什么推荐**: 代码简洁、逻辑清晰、扩展性好（字符集变大也没问题），是面试中的标准答法。

**复杂度**:
- 时间: O(J + S)。建立集合 O(J)，遍历 stones O(S)。
- 空间: O(J)。集合存储宝石类型。

### 解法二：数组标记

**思路**:
1. 创建布尔数组 `seen[128]`（ASCII 范围）初始化为 false。
2. 遍历 jewels，将 `seen[c] = true`。
3. 遍历 stones，对每个字符 c，若 `seen[c]` 为 true 则计数。

**优势**: 避免哈希表的常数开销，在字符集有限的场景下更快。

**复杂度**:
- 时间: O(J + S)。
- 空间: O(1)。数组大小固定为 128，与输入无关。

### 解法三：位运算标记

**思路**:
如果只处理小写字母（26个），可以用一个 32 位整数的各位来标记是否为宝石。
但本题包含大小写共 52 种字符，需要用 64 位整数（long long）。

**核心操作**:
- 标记宝石: `mask |= (1LL << (c - 'A'))`
- 检查石头: `if (mask & (1LL << (c - 'A')))`

这是极致的空间优化，但可读性较差，面试中不作为首选。

**复杂度**:
- 时间: O(J + S)。
- 空间: O(1)。仅用一个 64 位整数。

## 易错点

1. **忘记大小写敏感**: `'a'` 和 `'A'` 是不同类型，不要用 `tolower()` 统一化。
2. **数组大小不足**: 如果用数组标记，大小至少为 128（ASCII范围），不是 26。因为包含大小写字母。
3. **返回值类型**: 返回的是计数 int，不是布尔值或字符串列表。
4. **空 jewels**: 虽然题目约束 length >= 1，但代码应自然处理空字符串的情况。

## 面试追问

1. **Q: 如果 jewels 可能有重复字符怎么办？**
   A: 用 set 自动去重，逻辑不变。如果用数组标记，重复标记同一位也无影响。

2. **Q: 如果字符集是 Unicode 而非 ASCII？**
   A: 数组标记法不适用（Unicode 范围太大），应使用 HashSet。哈希集合的方法具有更好的通用性。

3. **Q: 如果 stones 非常大（数亿字符），如何优化？**
   A: 可以并行处理 stones 的不同分段，各段分别计数再汇总。jewels 集合足够小可以放入每个线程的缓存。

4. **Q: 能否一次遍历完成？**
   A: 不行。必须先建立 jewels 集合，否则遇到 stones 中的字符时不知道它是否是宝石。除非 jewels 预先排序用二分查找（O(S log J)）。

5. **Q: 这道题的实际应用场景是什么？**
   A: 典型的集合成员查询问题。实际中如：过滤器（白名单/黑名单检查）、标签匹配、权限验证等。
