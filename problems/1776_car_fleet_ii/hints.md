# 1776. 车队 II

## 核心思路

本质上是：对每辆车，找到它**最终会追上的那辆前方车**（不是简单地追上紧邻的下一辆，因为下一辆可能在被追上之前已经和更前面的车合并了）。这是一个**从右往左处理、维护"有效前车"的单调栈问题**。

## 思维链

1. **读完题第一反应**：每辆车只可能追上前方（右边）比它慢的车。如果前车更快，永远追不上。最朴素的做法：对每辆车 `i`，向右扫描所有前车，计算追上时间。

2. **暴力解的瓶颈**：对车 `i`，不能简单地只看紧邻的下一辆车 `i+1`。因为 `i+1` 可能在 `i` 追上它之前，已经和 `i+2` 合并变慢了。我们需要考虑"级联合并"效应，暴力模拟是 O(n²)。

3. **关键观察 — 从右往左思考**：最右边的车永远不会追上任何车（答案为 -1）。从右往左处理时，如果我们维护一个"还没被合并掉的前车"的栈，就能快速找到每辆车真正会追上的对象。

4. **什么时候栈顶该弹出？** 两种情况弹出栈顶车 `j`：
   - 车 `i` 比车 `j` 慢或一样快 → `i` 永远追不上 `j`，但 `j` 也不是 `i` 要追的对象，`j` 对 `i` 没用（错误！`j` 慢的话 `i` 可能追上它）。实际上：如果 `speed[i] <= speed[j]`，`i` 追不上 `j`，弹出 `j` 继续看更前面的车。
   - 车 `i` 能追上车 `j`，但在追上之前 `j` 已经和更前面的车合并了（`j` 的碰撞时间 < i追上j的时间），那么 `j` 已经"不存在了"，弹出 `j`。

5. **栈中维护的是什么？** 从右到左，一个单调递减速度的栈（栈底最慢，栈顶可能更快）。不对——实际上栈中存的是**车的索引**，关键判断逻辑是上述两个弹出条件。

6. **计算追上时间**：车 `i` 追上车 `j` 的时间 = `(pos[j] - pos[i]) / (speed[i] - speed[j])`，前提是 `speed[i] > speed[j]`。

## 关键提示

1. **从右往左处理**：最右边的车不会追上任何车，是天然的"基准"。从右往左，每辆车只需要关心右边"还存活的车"。

2. **栈中弹出的两个条件缺一不可**：
   - 条件A：`speed[i] <= speed[stack.top()]` — 我追不上你，你对我没用
   - 条件B：`speed[i] > speed[stack.top()]` 但我追上你的时间 > 你自己碰撞消失的时间 — 你在我到之前已经没了

3. **条件B是最难想到的**：追上时间 `t_catch = (pos[j]-pos[i])/(speed[i]-speed[j])`，如果 `answer[j] > 0`（`j` 会碰撞消失）且 `t_catch > answer[j]`，那么 `j` 对 `i` 来说无效，弹出。

4. **为什么是 O(n)？** 每辆车最多入栈一次、出栈一次，总操作 2n。

## 解法详解

### 解法1: 暴力模拟 — O(n²) / O(n)

**思考过程**：最自然的想法是模拟整个过程。找出最先发生的碰撞，合并车队，重复直到没有碰撞。但每次碰撞后车队的速度改变，会影响其他车的碰撞时间，需要重新计算。

这个思路用堆可以实现：计算所有相邻车对的碰撞时间，取最小的，合并，更新受影响的相邻对。但实现复杂且时间 O(n log n) 到 O(n²)，不是面试首选。

### 解法2: 单调栈（从右往左） — O(n) / O(n) ⭐ 面试首选

**从暴力到最优的跳跃**：与其按时间顺序模拟，不如按位置从右往左逐车确定答案。关键洞察：车 `i` 最终追上的一定是右边某辆"在 `i` 追到之前还活着"的车。

```cpp
class Solution {
public:
    vector<double> getCollisionTimes(vector<vector<int>>& cars) {
        int n = cars.size();
        vector<double> ans(n, -1.0);
        stack<int> stk; // 存车的索引，从右往左处理
        
        for (int i = n - 1; i >= 0; i--) {
            // 弹出对当前车i无效的栈顶
            while (!stk.empty()) {
                int j = stk.top();
                // 条件A：i比j慢或等速，永远追不上j
                if (cars[i][1] <= cars[j][1]) {
                    stk.pop();
                }
                // 条件B：i能追上j，但j在被追上之前已经合并消失了
                else if (ans[j] > 0 && 
                         getTime(cars, i, j) > ans[j]) {
                    stk.pop();
                }
                else {
                    break; // 栈顶j是有效目标
                }
            }
            
            if (!stk.empty()) {
                ans[i] = getTime(cars, i, stk.top());
            }
            stk.push(i);
        }
        return ans;
    }
    
private:
    // 车i追上车j需要的时间
    double getTime(vector<vector<int>>& cars, int i, int j) {
        return (double)(cars[j][0] - cars[i][0]) / 
               (cars[i][1] - cars[j][1]);
    }
};
```

**关键点**：
- 条件B的判断 `ans[j] > 0 && getTime(i,j) > ans[j]` 必须同时满足两个子条件
- `ans[j] == -1` 表示 `j` 永远不会消失，此时只要 `i` 比 `j` 快就一定能追上
- 每个元素最多入栈出栈各一次，所以是 O(n)

## 解法对比

| | 暴力模拟 | 单调栈 |
|---|---|---|
| 时间 | O(n² 或 n log n) | O(n) |
| 空间 | O(n) | O(n) |
| 思维难度 | 中（模拟直觉） | 高（需要想清楚弹出条件） |
| 面试推荐 | 口述思路即可 | ⭐ 必须能写出 |

选择建议：面试直接讲单调栈思路，暴力模拟只在"先说一个朴素方法"时提一句。

## 易错点

1. **忘记条件B，只检查速度**：
   - ✗ `while (!stk.empty() && cars[i][1] <= cars[stk.top()][1]) stk.pop();`
   - ✓ 还需要检查 `ans[j] > 0 && getTime(i,j) > ans[j]` 才弹出
   - 只检查速度会导致追上一辆"已经不存在的车"

2. **条件B中漏掉 `ans[j] > 0` 的检查**：
   - ✗ `getTime(i,j) > ans[j]` — 当 `ans[j]==-1` 时，这个比较会错误地弹出永远不会消失的车
   - ✓ `ans[j] > 0 && getTime(i,j) > ans[j]`

3. **整数除法导致精度丢失**：
   - ✗ `(cars[j][0] - cars[i][0]) / (cars[i][1] - cars[j][1])` — 整数除整数
   - ✓ 加 `(double)` 强制转换

4. **弹出条件写成 if-else 而非 while**：必须是 while 循环持续弹出，不是只弹一次

## 面试追问

**Q1: 为什么从右往左处理？从左往右行不行？**
> 从左往右时，车 `i` 的碰撞目标在右边，但右边的车还没处理，不知道它们会不会消失。从右往左时，右边的车已经确定了碰撞时间（`ans[j]` 已知），所以可以判断 `j` 是否在被追上前消失。

**Q2: 为什么每辆车最多入栈出栈各一次？有没有可能一辆车被反复 push/pop？**
> 每辆车只在遍历到自己时 push 一次，被 pop 后就不会再 push。所以 while 循环中所有 pop 操作的总次数 ≤ n，整体 O(n)。

**Q3: 如果题目改成"碰撞后车队速度取最快的"，怎么改？**
> 如果取最快速度，那么碰撞后车队变快，可能追上更前面的车。此时碰撞链的传播方向反了——一个碰撞可能触发更多碰撞。单调栈的弹出逻辑需要重新设计，核心区别在于：原题合并后变慢（稳定），新题合并后变快（不稳定，可能触发级联）。

**Q4: 这题和 853. Car Fleet（车队 I）有什么关系？**
> 853 只问"最终有几个车队"，不关心碰撞时间，且是从终点看。本题要求每辆车的具体碰撞时间，复杂度更高。853 可以排序后贪心，本题需要单调栈处理"级联消失"。

- **853. Car Fleet** — 同样是车队合并，但只问最终车队数量。排序后从右往左扫描即可，不需要栈。本题的核心技巧（从右往左 + 考虑合并效应）是 853 的升级版。
