# 17. 电话号码的字母组合

## 核心思路

本质是一个**多层嵌套循环**问题：每个数字对应若干字母，要求从每一层（每个数字）中各选一个字母，输出所有可能的组合。当"层数"不固定时，嵌套循环写不出来，就需要用**回溯（递归）** 来模拟。

## 思维链

1. **读完题第一反应**：每个数字映射几个字母，要把每个数字选一个字母排列出来。比如 "23"，数字2有"abc"，数字3有"def"，要把每种搭配列出来 → 这不就是笛卡尔积吗？
2. **尝试暴力**：如果只有2个数字，两层 for 循环搞定。3个数字就3层。但数字个数是输入决定的（最多4个），写死循环不通用 → **嵌套层数不确定时，用递归来模拟多层循环**。
3. **递归怎么设计？** 每一层递归处理一个数字：从当前数字对应的字母中逐个选择，拼到当前路径上，然后递归处理下一个数字。处理完所有数字（递归到底）就收获一个结果。
4. **有没有另一种思路？** 可以用迭代的 BFS 方式：维护一个"已有组合"列表，每遇到新数字，就把列表中每个已有组合分别追加新数字的每个字母，生成新列表。
5. **复杂度能优化吗？** 结果总量就是各数字字母数的乘积（最多 4^4 = 256），必须全部输出，没有优化空间。所有解法的时间复杂度本质相同。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 回溯（DFS） | 每层递归处理一个数字，选一个字母后递归下一层 | O(4^n · n) | O(n) 递归栈 | ⭐ 必须写出 |
| 迭代（BFS 式逐层扩展） | 维护组合列表，每个数字扩展一轮 | O(4^n · n) | O(4^n · n) 存中间结果 | 能说出即可 |

> n 为 digits 长度（最多4），4 是单个数字最多映射的字母数（7和9对应4个字母）。

## 关键提示

1. **映射表怎么建？** 用一个字符串数组或 map，把 '2'-'9' 映射到对应的字母字符串。注意 7 对应 "pqrs"（4个），8 对应 "tuv"（3个），9 对应 "wxyz"（4个）。
2. **递归的参数是什么？** 你需要知道"当前处理到第几个数字"和"已经拼好的路径"。当处理完所有数字时，路径就是一个完整的结果。
3. **需要"撤销选择"吗？** 如果用字符串拼接传值，不需要显式撤销；如果用引用，选择后要 pop_back。
4. **空字符串输入？** 题目说 `1 <= digits.length`，但面试中建议处理空串返回空列表的边界。
5. **迭代思路的关键**：想象你手里有一摞卡片，每张写着已有的组合。新来一个数字，你把每张卡片复制若干份，分别追加新数字的每个字母。

```
// 决策树（digits = "23"）:
//                     ""
//                /    |    \
//              "a"   "b"   "c"        ← 数字'2' → "abc"
//             /|\   /|\   /|\
//           ad ae af bd be bf cd ce cf  ← 数字'3' → "def"
//           ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑
//           9个叶子 = 9个结果
```

## 解法详解

### 解法1: 回溯（DFS） — O(4^n · n) / O(n) ⭐ 面试首选

**思考过程**：每个数字对应的字母就是"选择列表"，数字的顺序就是"递归层数"。经典回溯模板：对当前层的每个选择，做选择 → 递归下一层 → 撤销选择。

```cpp
class Solution {
public:
    // 数字到字母的映射（下标对应数字，0和1为空占位）
    const string mapping[10] = {
        "", "", "abc", "def", "ghi", "jkl",
        "mno", "pqrs", "tuv", "wxyz"
    };
    
    vector<string> result;
    
    vector<string> letterCombinations(string digits) {
        if (digits.empty()) return {};  // 边界：空串
        string path;
        backtrack(digits, 0, path);
        return result;
    }
    
    // index: 当前处理到 digits 的第几个数字
    // path: 已经拼好的字母组合（当前路径）
    void backtrack(const string& digits, int index, string& path) {
        // 终止条件：所有数字都处理完了，收获结果
        if (index == digits.size()) {
            result.push_back(path);
            return;
        }
        
        // 当前数字对应的字母集
        const string& letters = mapping[digits[index] - '0'];
        
        for (char ch : letters) {
            path.push_back(ch);          // 做选择
            backtrack(digits, index + 1, path);  // 递归下一个数字
            path.pop_back();             // 撤销选择
        }
    }
};
```

**关键点**：
- `index` 控制递归层数，每层处理 digits 的一个数字
- `path` 用引用传递 + push_back/pop_back，避免每层创建新字符串的开销
- 终止条件是 `index == digits.size()`，此时 path 长度恰好等于 digits 长度

### 解法2: 迭代（BFS 式逐层扩展） — O(4^n · n) / O(4^n · n)

**从另一个角度思考**：不用递归，而是像 BFS 一样逐层扩展。初始列表只有一个空串 `""`，每处理一个数字，就把列表中的每个字符串分别追加该数字的每个字母。

```
// 迭代过程（digits = "23"）:
// 初始:    [""]
// 处理'2': ["a", "b", "c"]           ← "" + 'a', "" + 'b', "" + 'c'
// 处理'3': ["ad","ae","af",           ← "a" + 'd'/'e'/'f'
//           "bd","be","bf",           ← "b" + 'd'/'e'/'f'
//           "cd","ce","cf"]           ← "c" + 'd'/'e'/'f'
```

```cpp
class Solution {
public:
    vector<string> letterCombinations(string digits) {
        if (digits.empty()) return {};
        
        const string mapping[10] = {
            "", "", "abc", "def", "ghi", "jkl",
            "mno", "pqrs", "tuv", "wxyz"
        };
        
        vector<string> result = {""};  // 初始：一个空串
        
        for (char digit : digits) {
            vector<string> newResult;
            const string& letters = mapping[digit - '0'];
            // 把已有的每个组合，分别追加当前数字的每个字母
            for (const string& combo : result) {
                for (char ch : letters) {
                    newResult.push_back(combo + ch);
                }
            }
            result = move(newResult);  // 用新列表替换旧列表
        }
        
        return result;
    }
};
```

**关键点**：
- 初始化 `result = {""}` 而不是 `result = {}`，因为空串是所有组合的起点
- `move(newResult)` 避免不必要的拷贝
- 这种方法不用递归，逻辑更线性，但需要存储所有中间结果

## 解法对比

| | 回溯（DFS） | 迭代（BFS 式） |
|---|---|---|
| **实现** | 递归，天然适合组合/排列问题 | 循环嵌套，逻辑更直观 |
| **额外空间** | O(n) 递归栈（不算结果） | O(4^n · n) 中间结果列表 |
| **扩展性** | 容易加剪枝条件 | 剪枝不方便 |
| **面试推荐** | ⭐ 首选，展示回溯功底 | 可作为第二种思路补充 |

## 易错点

1. **忘记处理空串输入**
   - ✗ 不判断直接递归 → 输出 `[""]`（一个空串）
   - ✓ `if (digits.empty()) return {};` → 返回空列表

2. **映射表下标错位**
   - ✗ `mapping[0] = "abc"` → 数字2取到了错误的字母
   - ✓ 数组下标对齐数字：`mapping[2] = "abc"`，0和1留空

3. **回溯忘记撤销选择**
   - ✗ 只 push_back 不 pop_back → path 越来越长，结果全错
   - ✓ 每次 push_back 之后、递归返回之后，必须 pop_back

4. **迭代法初始化为空列表**
   - ✗ `result = {}` → 内层循环不执行，结果永远为空
   - ✓ `result = {""}` → 空串是组合的种子

## 面试追问

**Q1（基础理解）**：这道题的结果总共有多少个？
> 每个数字映射3或4个字母，总结果数 = 各数字字母数的乘积。最坏情况（全是7或9）：4^4 = 256 个。

**Q2（回溯模板）**：回溯和普通 DFS 有什么区别？
> 回溯在 DFS 的基础上加了"撤销选择"这一步。DFS 往深处走，回溯在返回时恢复状态，从而能探索其他分支。本题中 `pop_back()` 就是撤销。

**Q3（变体）**：如果某些数字组合对应的字母组合是"有效单词"，要求只输出有效单词，怎么改？
> 在回溯中加剪枝：维护一个 Trie（前缀树），每选一个字母就在 Trie 上走一步，如果当前前缀不是任何单词的前缀就剪枝。这就把本题和 Trie + 回溯结合了起来。

**Q4（扩展）**：如果 digits 长度可以很长（比如100），还能用回溯吗？
> 可以用回溯生成，但结果数量是指数级的（最多4^100），无法全部存储。此时应该改用迭代器/生成器模式，按需生成下一个组合，而不是一次性存储所有结果。
