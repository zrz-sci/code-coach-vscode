# 128. 最长连续序列

## 核心思路

本质上在问：在一堆散乱的数字中，找到最长的"连续递增1"的链条有多长。关键不是排序，而是**如何高效判断一个数的下一个数是否存在**。

## 思维链

1. **读完题第一反应**：把数组排序，然后扫一遍就能找连续序列。排序是 O(n log n)，但题目要求 O(n)，排序方案不够。
2. **暴力解怎么做？** 对每个数 x，不断查找 x+1, x+2, x+3... 是否存在。如果存在性查找用线性扫描，最坏 O(n) 查一次，总共 O(n²) 甚至 O(n³)。
3. **瓶颈在哪？** 两个：① 查找"某个数是否存在"太慢 → 用哈希集合 O(1) 查找；② 每个数都尝试向后延伸，大量重复工作。
4. **关键洞察**：一条连续序列只需要从**起点**开始延伸一次就够了！怎么判断起点？如果 `x-1` 不在集合中，说明 `x` 就是某条连续序列的起点。
5. **复杂度为什么是 O(n)？** 每个数最多被访问两次：一次判断是否是起点，一次在某条链中被延伸到。总共 O(n)。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 排序扫描 | 排序后线性扫描连续段 | O(n log n) | O(1)~O(n) | 能说出即可 |
| 哈希集合 + 起点判断 | 只从序列起点开始延伸 | O(n) | O(n) | ⭐ 必须写出 |
| 并查集 | 相邻数字合并连通分量 | O(n·α(n)) ≈ O(n) | O(n) | 加分项 |

## 关键提示

1. **想想排序后的数组长什么样**：`[1,2,3,4,100,200]`，连续段一目了然。但排序花 O(n log n)，能不能不排序也达到同样效果？
2. **哈希集合让"存在性检查"变成 O(1)**：把所有数扔进 set，查 `x+1` 是否存在就是 O(1)。
3. **避免重复延伸是关键**：不要对每个数都向后找。思考：如果 `x-1` 存在，说明 `x` 一定会被从 `x-1`（或更早）开始的链条覆盖到，`x` 自己不需要作为起点。
4. **注意重复元素**：`[1,0,1,2]` 中有两个 1，用 set 天然去重。排序解法需要跳过重复。
5. 可视化示例 `[100, 4, 200, 1, 3, 2]`：
```
哈希集合: {100, 4, 200, 1, 3, 2}

检查每个数是否是起点 (x-1 不存在):
  100: 99不在 → 起点! 延伸: 100→101? 不在. 长度=1
    4: 3在   → 跳过
  200: 199不在 → 起点! 延伸: 200→201? 不在. 长度=1
    1: 0不在 → 起点! 延伸: 1→2✓→3✓→4✓→5? 不在. 长度=4 ★
    3: 2在   → 跳过
    2: 1在   → 跳过

答案: 4
```

## 解法详解

### 解法1: 排序 + 线性扫描 — O(n log n) / O(1)

**思考过程**：最直觉的想法——排完序后连续的数字会挨在一起，只需线性扫描一遍，维护当前连续段长度即可。虽然不满足 O(n) 的要求，但作为面试的起手式展示理解没问题。

```cpp
class Solution {
public:
    int longestConsecutive(vector<int>& nums) {
        if (nums.empty()) return 0;
        
        sort(nums.begin(), nums.end());
        
        int maxLen = 1, curLen = 1;
        for (int i = 1; i < nums.size(); i++) {
            if (nums[i] == nums[i-1]) {
                // 重复元素，跳过（不算断开也不算延伸）
                continue;
            }
            if (nums[i] == nums[i-1] + 1) {
                // 连续，延伸当前段
                curLen++;
            } else {
                // 断开，重新开始
                curLen = 1;
            }
            maxLen = max(maxLen, curLen);
        }
        return maxLen;
    }
};
```

**关键点**：重复元素的处理。`[1,1,2]` 答案是 2 不是 1，遇到 `nums[i]==nums[i-1]` 要 `continue` 而不是重置 `curLen`。

---

### 解法2: 哈希集合 + 起点判断 — O(n) / O(n) ⭐ 面试首选

**从解法1优化**：排序的 O(n log n) 是瓶颈。其实我们不需要全局有序，只需要快速回答"某个数存不存在"。用哈希集合做 O(1) 查找，并且只从每条连续序列的**起点**开始延伸，避免重复工作。

```cpp
class Solution {
public:
    int longestConsecutive(vector<int>& nums) {
        // 1. 把所有数字放入哈希集合，顺便去重
        unordered_set<int> numSet(nums.begin(), nums.end());
        
        int maxLen = 0;
        for (int num : numSet) {
            // 2. 只有当 num 是某条连续序列的起点时才开始延伸
            //    起点的判据：num-1 不在集合中
            if (numSet.count(num - 1)) continue;
            
            // 3. num 是起点，向后延伸
            int curNum = num;
            int curLen = 1;
            while (numSet.count(curNum + 1)) {
                curNum++;
                curLen++;
            }
            
            maxLen = max(maxLen, curLen);
        }
        return maxLen;
    }
};
```

**为什么是 O(n)？** 虽然有嵌套循环（for + while），但每个元素最多被 while 访问一次（只有起点才进入 while，而每个元素最多是一条链的成员）。总访问次数 ≤ 2n。

**关键点**：遍历 `numSet` 而不是 `nums`，避免重复元素多次触发。

---

### 解法3: 并查集 — O(n·α(n)) / O(n)

**不同视角**：把每个数看作图中的节点，如果 `x` 和 `x+1` 都存在，就连一条边。问题变成"求最大连通分量的大小"，这是并查集的经典应用。

```cpp
class Solution {
public:
    unordered_map<int, int> parent, rank_, size_;
    
    int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]); // 路径压缩
        }
        return parent[x];
    }
    
    void unite(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return;
        // 按秩合并
        if (rank_[px] < rank_[py]) swap(px, py);
        parent[py] = px;
        size_[px] += size_[py];
        if (rank_[px] == rank_[py]) rank_[px]++;
    }
    
    int longestConsecutive(vector<int>& nums) {
        if (nums.empty()) return 0;
        
        // 初始化：每个数是自己的父节点，大小为1
        for (int num : nums) {
            parent[num] = num;
            rank_[num] = 0;
            size_[num] = 1;
        }
        
        // 对每个数，尝试与 num+1 合并（如果存在）
        for (int num : nums) {
            if (parent.count(num + 1)) {
                unite(num, num + 1);
            }
        }
        
        // 找最大连通分量
        int maxLen = 0;
        for (auto& [num, p] : parent) {
            if (find(num) == num) { // 只看根节点
                maxLen = max(maxLen, size_[num]);
            }
        }
        return maxLen;
    }
};
```

**适用场景**：当问题有更复杂的"合并"操作时（如动态添加元素），并查集更灵活。但本题哈希集合解法更简洁。

| | 排序扫描 | 哈希集合 ⭐ | 并查集 |
|---|---|---|---|
| 时间 | O(n log n) | O(n) | O(n·α(n)) ≈ O(n) |
| 空间 | O(1)~O(n) | O(n) | O(n) |
| 代码量 | 最少 | 适中 | 较多 |
| 理解难度 | 最低 | 中等 | 较高 |
| 满足题目要求 | ✗ (O(n log n)) | ✓ | ✓ |
| 面试推荐 | 起手式 | **首选** | 追问时说 |

## 易错点

1. **重复元素导致答案错误（排序解法）**
   - ✗ `if (nums[i] != nums[i-1] + 1) curLen = 1;` — 遇到重复会重置长度
   - ✓ 先判断 `nums[i] == nums[i-1]` 时 `continue`，跳过重复再判断连续

2. **遍历 nums 而不是 numSet（哈希解法）**
   - ✗ `for (int num : nums)` — 如果 nums 有大量重复，同一个起点会被多次延伸
   - ✓ `for (int num : numSet)` — 去重后遍历，保证每个值只处理一次

3. **忘记空数组判断**
   - ✗ 排序解法不判空直接访问 `nums[0]`
   - ✓ 开头 `if (nums.empty()) return 0;`

4. **起点判断条件写反**
   - ✗ `if (numSet.count(num + 1))` — 这判断的是"能往后延伸"，不是"是起点"
   - ✓ `if (!numSet.count(num - 1))` — 前驱不存在才是起点

## 面试追问

**Q1: 暴力解怎么做？瓶颈在哪？**
对每个数 x 向后找 x+1, x+2...，用线性查找是 O(n²)。瓶颈：① 查找是否存在太慢 ② 每个数都做延伸有重复。

**Q2: 你说 O(n)，但代码有嵌套循环，怎么证明？**
外层 for 遍历 n 个数，但只有起点（num-1 不存在）才进入 while。每个数最多被 while 访问一次（作为某条链的成员）。把所有 while 的迭代次数加起来 ≤ n，所以总复杂度是 O(n) + O(n) = O(n)。这是**均摊分析**。

**Q3: 如果数据流式到达（不断有新数字加入），怎么动态维护最长连续序列？**
用并查集。每来一个新数字 x，创建节点，然后尝试与 x-1 和 x+1 合并。维护一个全局 maxLen。每次合并后更新 maxLen。插入操作均摊 O(α(n)) ≈ O(1)。

**Q4: 能否用 O(1) 额外空间？**
如果允许修改原数组，可以用排序解法 O(n log n)。严格 O(n) 时间 + O(1) 空间是不可能的——你需要某种方式记住哪些数存在，这至少需要 O(n) 空间。
