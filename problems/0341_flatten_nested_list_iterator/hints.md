# 341. 扁平化嵌套列表迭代器

## 核心思路

这道题本质上是**对一棵多叉树进行先序遍历**，只不过叶子节点存的是整数，非叶子节点存的是子列表。你要设计一个迭代器，按照从左到右的顺序逐个吐出所有叶子节点的值。

## 思维链

1. **读完题第一反应**：嵌套列表就像文件系统——文件夹里套文件夹，最终里面是文件。我想把所有文件按顺序列出来。最直觉的做法：**递归 DFS 一次性展平到一个数组里**，然后用下标迭代。

2. **这个暴力解有什么问题？** 功能上完全正确，但它在构造函数里就把**所有元素**都展开了。如果嵌套列表很大但调用者只取前几个元素（提前 break），我们白做了大量工作。面试官会追问：能不能**惰性求值（lazy evaluation）**？

3. **怎么实现惰性求值？** 关键观察：DFS 递归本质上是用调用栈来记住"我遍历到哪了"。如果我们**用一个显式栈来模拟这个递归过程**，就可以在每次 `hasNext()` 时只展开到下一个整数为止，不多做。

4. **栈里存什么？** 不能只存 `NestedInteger` 对象——那样我们不知道一个列表遍历到第几个元素了。正确做法：**栈里存迭代器对（begin, end）**，每对代表"某个列表中还没遍历的部分"。

5. **`hasNext()` 的核心逻辑**：不断检查栈顶迭代器指向的元素——如果是整数，说明下一个值准备好了；如果是列表，就把这个列表的迭代器范围压栈（向下展开），继续检查。如果栈顶迭代器已耗尽，弹栈回到上一层。

6. **为什么放在 `hasNext()` 而不是 `next()` 里？** 因为调用者的模式是 `while(hasNext()) next()`，`hasNext()` 保证下一个整数就绪后，`next()` 只需取出并前进即可。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 预处理展平 | 构造时递归 DFS 把所有整数放入数组 | 构造 O(n)，next/hasNext O(1) | O(n) | 能说出即可 |
| 栈模拟迭代器（惰性求值） | 栈存迭代器对，hasNext 中按需展开 | 均摊 O(1) | O(d)，d 为嵌套深度 | ⭐ 必须写出 |

## 关键提示

1. **把嵌套列表画成树**：每个列表是一个内部节点，每个整数是叶子节点。"扁平化"就是先序遍历所有叶子。

```
nestedList = [[1,1],2,[1,1]]

          root
        /   |   \
      [1,1]  2  [1,1]
      / \        / \
     1   1      1   1

先序遍历叶子: 1, 1, 2, 1, 1
```

2. **惰性展开的关键**：`hasNext()` 负责"把栈顶调整到一个整数"，`next()` 只负责"取出这个整数"。所有展开逻辑集中在 `hasNext()`。

3. **栈里存什么？** 不是存 `NestedInteger` 本身，而是存**指向列表元素的迭代器**（一对 begin/end），这样才能记住"这个列表遍历到第几个了"。

4. **空列表要小心**：`[[], [1, []], 2]` 这种情况，展开 `[]` 后发现是空的，要继续弹栈找下一个，不能返回 true。

5. **解法1 虽然简单但不要小看**：面试中如果时间紧，先写出解法1拿到正确性分，然后口述解法2的思路也是好策略。

## 解法详解

### 解法1: 预处理展平 — 构造 O(n)，next/hasNext O(1)

**思考过程**：最直觉的想法——递归遍历嵌套结构，把所有整数按顺序塞进一个数组。之后 `next()` 和 `hasNext()` 就是数组的下标操作。

```cpp
class NestedIterator {
    vector<int> vals;
    int idx;
    
    void flatten(vector<NestedInteger>& list) {
        for (auto& ni : list) {
            if (ni.isInteger()) {
                vals.push_back(ni.getInteger());
            } else {
                flatten(ni.getList());
            }
        }
    }
    
public:
    NestedIterator(vector<NestedInteger>& nestedList) : idx(0) {
        flatten(nestedList);
    }
    
    int next() {
        return vals[idx++];
    }
    
    bool hasNext() {
        return idx < (int)vals.size();
    }
};
```

**关键点**：
- 简单正确，但构造时就展开了全部元素，无法惰性求值
- 空间 O(n)，n 为所有整数的总数

### 解法2: 栈模拟迭代器（惰性求值） — 均摊 O(1) ⭐ 面试首选

**从解法1优化**：解法1的问题是"一口气全展开"。如果调用者只要前几个元素就停了呢？我们希望**按需展开**。

核心思想：用栈模拟递归 DFS。栈中每一层存一对迭代器 `(cur, end)`，代表某个列表中"当前位置"和"结束位置"。

```
调用 hasNext() 时的展开过程 (以 [1,[4,[6]]] 为例):

栈状态变化:
初始: stack = [(iter→[1,[4,[6]]])]
                  ↑cur指向第0个元素

hasNext(): 栈顶cur指向 1 (整数) → 返回true
next():    取出 1, cur前进

hasNext(): 栈顶cur指向 [4,[6]] (列表) 
           → 压入 [4,[6]] 的迭代器
           → 新栈顶cur指向 4 (整数) → 返回true
next():    取出 4, cur前进

hasNext(): 新栈顶cur指向 [6] (列表)
           → 压入 [6] 的迭代器
           → 新栈顶cur指向 6 (整数) → 返回true
next():    取出 6, cur前进

hasNext(): 栈顶迭代器耗尽 → 弹栈
           → 上一层也耗尽 → 弹栈
           → 最外层也耗尽 → 弹栈
           → 栈空 → 返回false
```

```cpp
class NestedIterator {
    // 栈中存: (当前位置迭代器, 结束位置迭代器)
    using Iter = vector<NestedInteger>::iterator;
    stack<pair<Iter, Iter>> stk;
    
public:
    NestedIterator(vector<NestedInteger>& nestedList) {
        stk.push({nestedList.begin(), nestedList.end()});
    }
    
    int next() {
        // hasNext() 已保证栈顶 cur 指向一个整数
        int val = stk.top().first->getInteger();
        stk.top().first++;  // 前进到下一个元素
        return val;
    }
    
    bool hasNext() {
        // 核心: 不断调整栈顶，直到 cur 指向整数 或 栈空
        while (!stk.empty()) {
            auto& [cur, end] = stk.top();
            if (cur == end) {
                // 当前层遍历完了，回到上一层
                stk.pop();
                continue;
            }
            if (cur->isInteger()) {
                // 找到了一个整数，准备好了
                return true;
            }
            // cur 指向一个子列表，需要展开
            auto& subList = cur->getList();
            cur++;  // 先前进（下次回到这层时跳过这个子列表）
            stk.push({subList.begin(), subList.end()});
        }
        return false;
    }
};
```

**关键点**：
- `hasNext()` 中的 while 循环确保处理空列表和多层嵌套
- `cur++` 必须在压栈**之前**，否则回到这层时会重复展开同一个子列表
- 空间 O(d)，d 为嵌套最大深度（不是元素总数！）

## 解法对比

| | 预处理展平 | 栈迭代器 |
|---|---|---|
| 展开时机 | 构造时全部展开 | 按需惰性展开 |
| 空间 | O(n) 存所有整数 | O(d) 只存栈帧 |
| 实现难度 | 简单 | 中等 |
| 适用场景 | 数据量小/需要随机访问 | 数据量大/可能提前终止 |
| 面试价值 | 保底拿分 | 展示设计能力 |

## 易错点

1. **`cur++` 的时机**：
   - ✗ 先压栈再 `cur++` → 如果子列表为空，弹栈后 cur 没前进，死循环
   - ✓ 先 `cur++` 再压子列表的迭代器

2. **`hasNext()` 里漏了 while 循环**：
   - ✗ 只用 if 判断一次 → 遇到 `[[], 1]` 这种嵌套空列表会出错
   - ✓ 用 while 循环持续展开，直到找到整数或栈空

3. **`next()` 里忘了前进迭代器**：
   - ✗ 只取值不 `cur++` → 每次 next 返回同一个值
   - ✓ 取值后 `stk.top().first++`

4. **引用失效**：在 C++ 中，`auto& [cur, end] = stk.top()` 用引用绑定。如果在循环中 pop 了栈顶后再访问 cur/end，就是悬垂引用。解法中 pop 后直接 continue，不再访问，是安全的。

## 面试追问

**Q1: 解法1有什么缺点？什么场景下不理想？**
> 构造时就展开全部，如果嵌套列表有上百万个元素但只取前10个，浪费大量时间和空间。惰性求值（解法2）只展开需要的部分。

**Q2: 解法2的 `hasNext()` 时间复杂度到底是多少？看起来有 while 循环。**
> 单次调用可能 O(d)（d 为深度），但**均摊**来看，每个 NestedInteger 对象最多被压栈和弹栈各一次，所以遍历所有 n 个整数的总操作是 O(n)，均摊每次 O(1)。

**Q3: 如果 `NestedInteger` 不提供 `getList()` 返回引用，而是返回拷贝，解法2还能用吗？**
> 如果返回拷贝，栈里存的迭代器会失效（指向临时对象）。这时要么改为预处理展平（解法1），要么栈里存 `NestedInteger` 对象本身而不是迭代器，在 `hasNext()` 中手动展开栈顶列表。

**Q4: 能否把这个迭代器设计成支持 `reset()` 重新遍历？**
> 解法1 天然支持（idx 置 0）。解法2 需要保存原始 nestedList 的引用，reset 时重新初始化栈。
