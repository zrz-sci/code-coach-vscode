# 296. 最佳的碰头地点

## 核心思路

曼哈顿距离可以**分解为行距离和列距离的独立求和**，每一维上的最优碰头点就是所有朋友坐标的**中位数**。

## 思维链

1. **读完题第一反应**：枚举网格中每个点作为碰头地点，计算所有朋友到它的曼哈顿距离之和，取最小值 → 暴力 O(m²n²·k)。

2. **关键观察 — 维度可分离**：曼哈顿距离 `|r1-r| + |c1-c|` 中，行和列是独立的！总距离 = Σ|ri - r| + Σ|ci - c|，两部分互不影响，可以**分别在行维度和列维度上求最优点**。

3. **降维后的子问题**：在一维数组上，找一个点 p 使得 Σ|xi - p| 最小 — 这是经典的数学问题，**答案是中位数**。
   - 直觉：中位数两侧的点数相同，往任一方向移动 p，一边距离减少的量等于另一边增加的量（当两侧不平衡时才有净减少，所以中位数是平衡点）。

4. **怎么收集坐标**：遍历网格，把所有 `1` 的行坐标收集到 `rows[]`，列坐标收集到 `cols[]`。行坐标按行遍历自然有序，列坐标按列遍历才有序（或收集后排序）。

5. **计算最小距离和**：取 `rows` 的中位数和 `cols` 的中位数，分别计算各维度的距离和，相加即为答案。甚至不需要真的找中位数 — 用双指针首尾配对求距离和更简洁。

6. **复杂度跳跃**：从 O(m²n²·k) 直接优化到 O(mn)，核心是两个数学洞察 — 维度分离 + 中位数最优性。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举每个格子作为碰头点 | O(m·n·k)，k为朋友数 | O(k) | 能说出即可 |
| 排序 + 中位数 | 维度分离，各维排序取中位数 | O(mn + k·log k) | O(k) | ⭐ 必须写出 |
| 收集有序 + 双指针 | 巧妙遍历顺序使坐标天然有序 | O(mn) | O(k) | 加分项 |

## 关键提示

- **提示1**：曼哈顿距离的公式 `|Δx| + |Δy|`，x 和 y 之间没有耦合。你能把二维问题拆成两个一维问题吗？

- **提示2**：在一维上，使 `Σ|xi - p|` 最小的 p 是什么？想想三个点 {1, 3, 7} 放在数轴上，p 在哪里最好？

- **提示3**：你不需要真正"找到"中位数的值 — 用首尾配对的方式，`distance = x[n-1]-x[0] + x[n-2]-x[1] + ...`，每一对的距离之和就是答案。

- **提示4**：行坐标按行遍历天然有序（先遍历 row=0，再 row=1...），但列坐标不是！你需要单独按列遍历或者排序。

```
  网格示例:
  (0,0)=1  .  .  .  (0,4)=1
    .      .  .  .    .
    .      . (2,2)=1  .

  行坐标: rows = [0, 0, 2]  ← 按行遍历自然有序
  列坐标: cols = [0, 2, 4]  ← 需要按列遍历或排序

  行中位数 = 0, 列中位数 = 2 → 碰头点 (0, 2)
  距离和 = |0-0|+|0-0|+|2-0| + |0-2|+|4-2|+|2-2| = 0+0+2 + 2+2+0 = 6
```

## 解法详解

### 解法1: 暴力枚举 — O(m·n·k) / O(k)

**思考过程**：最直接的想法 — 碰头点可以是网格中任意一个格子，对每个候选点计算所有朋友到它的距离之和，取最小值。

```cpp
class Solution {
public:
    int minTotalDistance(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        // 先收集所有朋友的位置
        vector<pair<int,int>> friends;
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                if (grid[i][j] == 1)
                    friends.push_back({i, j});
        
        int minDist = INT_MAX;
        // 枚举每个格子作为碰头点
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                int dist = 0;
                for (auto& [r, c] : friends)
                    dist += abs(r - i) + abs(c - j);
                minDist = min(minDist, dist);
            }
        }
        return minDist;
    }
};
```

**关键点**：
- 碰头点不一定在某个朋友的位置上，但一维中位数的性质保证了最优点一定在某个朋友的坐标上（或其间任意位置），所以其实只需枚举朋友坐标的组合，但这里为了简单枚举了所有格子。
- 时间复杂度 O(m·n·k)，对 200×200 网格最坏约 200×200×40000 = 不可接受，需要优化。

### 解法2: 排序 + 中位数 — O(mn + k·log k) / O(k) ⭐ 面试首选

**从解法1优化**：暴力的瓶颈是对每个候选点都要遍历所有朋友。核心洞察是曼哈顿距离可以分维度独立计算，每一维上中位数是最优的。

```
  一维证明直觉 (3个点: 1, 3, 7):
  
  p=1: |1-1|+|3-1|+|7-1| = 0+2+6 = 8
  p=3: |1-3|+|3-3|+|7-3| = 2+0+4 = 6  ← 中位数，最优
  p=7: |1-7|+|3-7|+|7-7| = 6+4+0 = 10
  
  p 从中位数向右移1: 左边2个点各+1，右边1个点-1，净增 +1
  所以中位数是平衡点，偏离必然增大总距离。
```

```cpp
class Solution {
public:
    int minTotalDistance(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        vector<int> rows, cols;
        
        // 收集所有朋友的行坐标和列坐标
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                if (grid[i][j] == 1) {
                    rows.push_back(i);
                    cols.push_back(j);
                }
        
        // rows 按行遍历天然有序，cols 需要排序
        sort(cols.begin(), cols.end());
        
        // 取中位数，计算各维度距离和
        int medianRow = rows[rows.size() / 2];
        int medianCol = cols[cols.size() / 2];
        
        int dist = 0;
        for (int r : rows) dist += abs(r - medianRow);
        for (int c : cols) dist += abs(c - medianCol);
        
        return dist;
    }
};
```

**关键点**：
- `rows` 按行遍历已经有序（行号从小到大），但 `cols` 不是 — 必须排序！
- 中位数取 `size/2` 位置，偶数个时取中间任一个都行（距离和相同）。

### 解法3: 有序收集 + 双指针 — O(mn) / O(k) 加分项

**进一步优化**：解法2中 cols 的排序是 O(k·log k)。如果我们按列优先遍历网格来收集列坐标，就天然有序了，省去排序。同时用双指针首尾配对求距离和，甚至不需要找中位数。

```
  双指针配对求距离和:
  排序后坐标: [1, 3, 5, 7]
  
  配对: (1,7) 距离=6, (3,5) 距离=2 → 总和=8
  
  为什么等价于中位数法?
  首尾配对的距离 = 最外层两点必须覆盖的距离
  无论碰头点在哪，(1,7) 这对至少贡献 6 的距离
  所以总和 = Σ(外层对的距离)，与中位数位置无关!
```

```cpp
class Solution {
public:
    int minTotalDistance(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        vector<int> rows, cols;
        
        // 按行遍历收集行坐标 — 天然有序
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                if (grid[i][j] == 1)
                    rows.push_back(i);
        
        // 按列遍历收集列坐标 — 天然有序！
        for (int j = 0; j < n; j++)
            for (int i = 0; i < m; i++)
                if (grid[i][j] == 1)
                    cols.push_back(j);
        
        return minDist1D(rows) + minDist1D(cols);
    }

private:
    // 双指针首尾配对，求一维最小距离和
    int minDist1D(vector<int>& points) {
        int dist = 0;
        int lo = 0, hi = points.size() - 1;
        while (lo < hi) {
            dist += points[hi] - points[lo];
            lo++;
            hi--;
        }
        return dist;
    }
};
```

**关键点**：
- 按列遍历（外层 j，内层 i）收集的列坐标天然按列号递增，无需排序。
- 双指针法的正确性：首尾配对的距离和 = 中位数法的距离和。这是因为无论碰头点选在 `[lo, hi]` 之间的哪个位置，这一对点至少贡献 `hi - lo` 的距离。

| | 解法1 暴力 | 解法2 排序+中位数 | 解法3 有序收集+双指针 |
|---|---|---|---|
| 时间 | O(m·n·k) | O(mn + k·log k) | O(mn) |
| 空间 | O(k) | O(k) | O(k) |
| 核心思想 | 枚举所有候选点 | 维度分离 + 中位数 | 同左 + 避免排序 |
| 面试建议 | 开场说明 | ⭐ 主力解法 | 追问优化时给出 |

- 解法2 → 解法3 的改进只在常数级别（省了一次排序），**面试中解法2足够**。
- 关键思维跳跃在**解法1 → 解法2**：维度分离 + 中位数性质。

## 易错点

- ✗ **列坐标忘记排序**：按行遍历时 `cols` 的收集顺序是 `(0,0),(0,4),(2,2)` → cols = `[0,4,2]`，不是有序的！中位数取错。
  ✓ 要么对 `cols` 排序，要么按列优先遍历收集。

- ✗ **以为碰头点必须在朋友位置上**：虽然最优解恰好等价于中位数坐标，但在暴力法中只枚举朋友位置是不完备的（虽然结果碰巧对，但思维有误）。正确理解：一维中位数性质保证了最优点在中位数处，不需要额外假设。

- ✗ **用平均值代替中位数**：`mean` 最小化的是 Σ(xi - p)²（平方和），不是 Σ|xi - p|（绝对值和）。本题是曼哈顿距离，要用**中位数**。

- ✗ **双指针漏掉奇数个点的中间点**：奇数个时中间点到自身距离为 0，`lo < hi` 的循环自然跳过，无需特殊处理 — 这是对的，但要理解为什么。

## 面试追问

**Q1: 为什么可以把行和列分开独立处理？**
→ 曼哈顿距离 `|Δr| + |Δc|` 中行差和列差互不影响。选择碰头点的行坐标只影响行距离总和，列坐标只影响列距离总和。两个一维问题的最优解组合就是二维问题的最优解。

**Q2: 为什么一维上中位数使得绝对值距离和最小？**
→ 设 p 在中位数位置，左边有 L 个点、右边有 R 个点。若 p 右移 1 单位：左边 L 个点距离各+1，右边 R 个点距离各-1，净变化 = L-R。当 L=R（中位数）时净变化为 0（局部最小）。若 L>R 则右移使总距离增加，左移减少 — 但那时 p 已不在中位数左边了。

**Q3: 如果距离改为欧氏距离 (L2)，还能这样做吗？**
→ 不能。欧氏距离 `√(Δr² + Δc²)` 中行和列不能分离。需要用 Weiszfeld 算法（迭代加权中位数）来求几何中位数，且没有闭式解。这也是本题巧妙之处 — 曼哈顿距离的可分解性是关键。

**Q4: 如果网格特别大（10⁶×10⁶）但朋友很少（k≤100），怎么优化？**
→ 直接收集 k 个朋友坐标（不遍历整个网格），排序 O(k log k)，双指针 O(k)。总复杂度 O(k log k)，与网格大小无关。
