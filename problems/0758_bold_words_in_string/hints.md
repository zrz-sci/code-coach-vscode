# 758. 字符串中的加粗单词 (Bold Words in String)

## 核心思路

本题需要找到字符串中所有被关键词覆盖的位置，然后用 `<b></b>` 标签包裹这些位置。核心方法是：用一个布尔数组标记字符串中每个字符是否需要加粗，然后扫描布尔数组合并连续的加粗区域，插入最少数量的标签。关键词匹配可以用暴力匹配、Trie树或KMP等方式完成。

## 思维链

1. **标记阶段**：创建布尔数组 `bold[i]`，表示 `s[i]` 是否需要加粗
2. **关键词匹配**：对字符串中的每个起始位置，检查是否有某个关键词从此处开始匹配。若匹配成功，将对应范围标记为 true
3. **区间合并优化**：维护一个 `end` 变量表示当前匹配能覆盖到的最远位置，避免重复标记
4. **标签插入**：扫描布尔数组，在加粗区域的开头插入 `<b>`，结尾插入 `</b>`
5. **相邻/重叠合并**：布尔数组天然处理了重叠和相邻的情况，连续的 true 区域只需一对标签

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 暴力匹配 + 布尔标记 | O(n * m * L) | O(n) | 简洁直观，适合面试 |
| Trie树匹配 + 布尔标记 | O(n * L + m * L) | O(m * L) | 多模式匹配更高效 |
| 区间合并法 | O(n * m * L) | O(n) | 先收集区间再合并 |

其中 n = s.length, m = words.length, L = 最大单词长度

## 关键提示

1. **布尔数组是核心**：`bold[i] = true` 表示 `s[i]` 需要被加粗标签包裹。这是处理重叠和相邻匹配的最简洁方式
2. **匹配覆盖**：对于起始位置 i 匹配到单词 w，需要将 `bold[i] ~ bold[i + w.length() - 1]` 全部设为 true
3. **标签位置判定**：
   - 插入 `<b>`：`bold[i] == true` 且 `(i == 0 || bold[i-1] == false)`
   - 插入 `</b>`：`bold[i] == true` 且 `(i == n-1 || bold[i+1] == false)`
4. **此题与 LC 616 完全相同**：Add Bold Tag in String，两题可以用同一套代码

## 解法详解

### 解法一：暴力匹配 + 布尔标记（推荐）

**算法步骤**：
1. 创建布尔数组 `bold`，长度为 `s.size()`，初始全 false
2. 对每个起始位置 `i`（0 到 n-1）：
   - 对每个关键词 `word`：
     - 检查 `s.substr(i, word.size()) == word`
     - 若匹配，将 `bold[i]` 到 `bold[i + word.size() - 1]` 设为 true
3. 构建结果字符串：
   - 遍历每个位置 `i`：
     - 如果 `bold[i]` 且前一个不是 bold，插入 `<b>`
     - 追加 `s[i]`
     - 如果 `bold[i]` 且下一个不是 bold，插入 `</b>`
4. 返回结果

**优化**：用 `end` 变量追踪当前能覆盖到的最远位置，避免对已覆盖位置重复标记。

**复杂度分析**：
- 时间复杂度：O(n * m * L)，n 个起始位置，m 个单词，每个单词匹配 O(L)
- 空间复杂度：O(n)，布尔数组

### 解法二：Trie 树优化匹配

**核心改进**：将所有关键词插入 Trie 树，对字符串每个起始位置在 Trie 中走一遍，可以同时匹配所有前缀匹配的关键词。

**优势**：
- 多个关键词共享前缀时效率更高
- 匹配一个位置的时间从 O(m * L) 降为 O(L)

**步骤**：
1. 将所有 words 插入 Trie
2. 对每个起始位置 i，在 Trie 中从 s[i] 开始走
3. 每走到一个 Trie 叶节点（表示完整匹配某个单词），标记对应范围
4. 后续步骤同解法一

### 解法三：区间合并法

**思路**：
1. 对每个匹配位置记录区间 `[start, end)`
2. 收集所有区间后排序
3. 合并重叠和相邻的区间
4. 根据合并后的区间插入标签

## 易错点

1. **子串匹配位置**：`s.substr(i, word.size())` 不要越界，需要 `i + word.size() <= s.size()`
2. **重叠处理**：两个匹配区域如 `[1,3]` 和 `[2,5]` 应合并为一个加粗区域 `[1,5]`，只用一对 `<b></b>` 标签
3. **相邻处理**：`[1,3]` 和 `[3,5]`（共享字符 s[3]）也应合并。布尔数组方法天然处理这种情况
4. **空 words 列表**：如果没有关键词，直接返回原字符串
5. **标签嵌套**：题目要求不能有嵌套的标签（如 `<b>a<b>b</b>c</b>`），布尔数组方法保证不会产生嵌套
6. **单词可能是另一个的子串**：如 words=["a","ab"]，需要正确标记所有匹配

## 面试追问

1. **Q: 如果关键词非常多（比如10万个），如何优化？**
   - A: 使用 Trie 树或 Aho-Corasick 自动机进行多模式匹配。Aho-Corasick 可以在 O(n + m*L + matches) 时间内完成所有匹配。

2. **Q: 布尔数组方法和区间合并方法哪个更好？**
   - A: 布尔数组方法更简洁，不需要额外的区间排序和合并步骤。当 n 不大时（本题 n<=500），布尔数组方法是最佳选择。

3. **Q: 如何处理大小写不敏感的匹配？**
   - A: 在匹配前将 s 和 words 全部转为小写再比较，但在构建结果时使用原始字符串中的字符。

4. **Q: 如果需要支持正则表达式的关键词，如何修改？**
   - A: 需要用正则引擎替代简单的子串匹配，但整体框架（标记 + 合并 + 插入标签）不变。

5. **Q: 这道题和 LC 616 有什么区别？**
   - A: 完全相同的问题，只是参数顺序不同。616 是 `addBoldTag(s, words)`，758 是 `boldWords(words, s)`。
