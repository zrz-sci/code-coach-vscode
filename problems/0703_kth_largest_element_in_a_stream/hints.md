# 703. Kth Largest Element in a Stream / 数据流中的第 K 大元素

## 核心思路

本题要求设计一个数据结构，在持续接收新元素的数据流中，实时返回第 K 大的元素。核心思路是**维护一个大小为 K 的最小堆（min-heap）**。

关键洞察：如果我们只保留最大的 K 个元素，那么这 K 个元素中最小的那个就是第 K 大的元素。最小堆的堆顶正好就是最小值，因此堆顶就是答案。每次新元素到来时，如果比堆顶大，就替换堆顶并重新调整堆；如果比堆顶小，说明它不在前 K 大中，忽略即可。

## 思维链

1. **暴力思路**：每次 add 后排序取第 K 大 => O(n log n) 太慢
2. **优化方向**：不需要维护所有元素的完整排序，只关心"前 K 大"
3. **数据结构选择**：最小堆天然适合——堆大小固定为 K，堆顶是第 K 大
4. **初始化**：将所有初始元素加入堆，但只保留最大的 K 个
5. **add 操作**：
   - 将 val 加入堆
   - 如果堆大小 > K，弹出堆顶（最小元素）
   - 返回堆顶（即为第 K 大）
6. **边界情况**：初始时 nums.size() 可能 < K，此时堆不满，继续加入即可

## 解法概览

| 解法 | 初始化复杂度 | add 复杂度 | 空间复杂度 | 特点 |
|------|-------------|-----------|-----------|------|
| 最小堆 | O(n log K) | O(log K) | O(K) | 最优解 |
| 有序数组 | O(n log n) | O(K) 插入 | O(n) | 简单但慢 |
| BST (平衡) | O(n log n) | O(log n) | O(n) | 过度设计 |

## 关键提示

1. **为什么用最小堆而非最大堆？** 最小堆大小为 K，堆顶是这 K 个最大元素中的最小值，即第 K 大。最大堆无法高效维护这个性质。
2. **堆大小的维护**：堆中最多保留 K 个元素。超过 K 个时弹出堆顶，被弹出的元素一定不在前 K 大中。
3. **初始数组可能不足 K 个**：题目保证 `1 <= k <= nums.length + 1`，所以初始时堆可能不满 K 个，直到足够的 add 调用。
4. **C++ 的 priority_queue 默认是最大堆**：需要用 `priority_queue<int, vector<int>, greater<int>>` 来创建最小堆。
5. **不要保留所有元素**：只保留 K 个即可，这是空间优化的关键。

## 解法详解

### 解法一：最小堆（推荐）

**构造函数 KthLargest(k, nums)**：
- 保存 K 值
- 将 nums 中的元素逐个加入最小堆
- 如果堆大小超过 K，弹出堆顶
- 最终堆中最多保留 K 个最大元素

**add(val) 操作**：
- 将 val 推入堆
- 如果堆大小 > K，弹出堆顶
- 返回堆顶元素（即第 K 大）

**正确性论证**：
- 堆中始终保留数据流中最大的 K 个元素
- 堆顶是这 K 个中最小的 = 全局第 K 大
- 新元素若小于堆顶，加入后会被弹出，不影响结果
- 新元素若大于堆顶，加入后堆顶被弹出（它不再是前 K 大），新的堆顶是正确的第 K 大

### 解法二：有序数组 + 二分插入

- 维护一个始终有序的数组
- add 时用二分查找找到插入位置，插入新元素
- 返回倒数第 K 个元素
- 插入操作 O(K)（需要移动元素），不如堆高效

### 解法三：multiset（平衡 BST）

- 使用 C++ 的 multiset，自动排序，支持重复元素
- 保持 multiset 大小为 K
- 堆顶等价物是 `*mset.begin()`（最小元素）
- 插入删除都是 O(log K)

## 易错点

1. **用了最大堆而非最小堆**：最大堆堆顶是最大值，无法直接获取第 K 大。
2. **堆大小不做限制**：如果不限制堆大小为 K，add 操作仍然是 O(log n) 而非 O(log K)，且空间为 O(n)。
3. **初始化时忘记控制堆大小**：构造时将所有元素加入后必须弹出多余元素，保持堆大小 <= K。
4. **k > nums.size() 时的处理**：此时堆中元素不足 K 个，add 时只需 push 不需 pop，直到堆大小达到 K。
5. **C++ greater<int> 写反**：`priority_queue<int, vector<int>, greater<int>>` 是最小堆，`less<int>` 才是最大堆（默认）。

## 面试追问

1. **Q: 如果要求第 K 小而非第 K 大，如何修改？**
   A: 使用大小为 K 的最大堆。堆顶是前 K 小元素中最大的 = 第 K 小。

2. **Q: 如果 K 会动态变化（有时查第 3 大，有时查第 5 大），怎么办？**
   A: 可以用平衡 BST（如 C++ 的 `std::multiset`）或者两个堆的方案，支持动态调整 K。

3. **Q: 如果数据流非常大（十亿级别），K 也很大（百万级），如何优化？**
   A: 堆的方案依然适用，O(K) 空间。如果 K 非常大，可以考虑分布式堆或 reservoir sampling 的变体。

4. **Q: 能否不用堆，用快速选择（QuickSelect）？**
   A: QuickSelect 是单次查询 O(n) 平均，但数据流场景下每次 add 都要重新选择，总体不如堆高效。

5. **Q: 这道题和 LeetCode 295（数据流中位数）有什么关系？**
   A: 295 是本题的推广。295 用两个堆（最大堆 + 最小堆）维护中位数，相当于 K = n/2 的情况。
