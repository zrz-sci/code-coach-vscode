# 656. 成本最小路径 (Coin Path)

**难度**: Hard | **标签**: Array, Dynamic Programming

## 核心思路

从终点**反向 DP**：定义 `dp[i]` 为从位置 i 到终点 n 的最小代价。从右往左遍历，对每个位置 i 尝试跳到 `i+1` 到 `i+maxJump` 的所有可达位置，取最小代价。同时用 `next[i]` 记录最优的下一跳位置，最后从位置 1 沿 next 指针构建路径。

**为什么反向 DP**：反向 DP 天然产生字典序最小的路径。当存在多条等代价路径时，反向遍历从右到左更新，使得在同一代价下优先选择较小的下一跳索引。

## 思维链

1. **识别题型**：最小代价路径 + 字典序最小 -> DP + 路径记录
2. **状态定义**：`dp[i]` = 从位置 i 跳到位置 n 的最小总代价
3. **方向选择**：
   - 正向 DP：`dp[i]` = 从 1 到 i 的最小代价，需要额外处理字典序（更复杂）
   - 反向 DP：`dp[i]` = 从 i 到 n 的最小代价，天然满足字典序最小（推荐）
4. **转移方程**：`dp[i] = coins[i] + min(dp[i+1], dp[i+2], ..., dp[i+maxJump])`
5. **路径构建**：维护 `next[i]` 记录最优下一步，从位置 1 沿链构建结果
6. **不可达判断**：如果 `dp[0] == INF`（位置 1 不可达终点），返回空数组

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 反向 DP | O(n * maxJump) | O(n) | 推荐，天然字典序最小 |
| 正向 DP + 路径比较 | O(n * maxJump) | O(n) | 可行但路径处理更复杂 |
| BFS/Dijkstra | O(n * maxJump) | O(n) | 不如 DP 直接 |

## 关键提示

1. **1-indexed vs 0-indexed**：题目说数组 1-indexed，但代码中数组是 0-indexed。转换关系：题目中位置 i 对应代码中下标 i-1。结果中的位置要 +1
2. **反向 DP 保证字典序**：从右向左遍历时，对于相同代价，从右到左扫描跳跃目标，使用 `<=`（而非 `<`）来更新最优值，这样字典序较小的路径会被保留
3. **-1 表示不可达**：`coins[i] == -1` 的位置不能停留，DP 中设为 INF
4. **起点终点必须可达**：`coins[0] != -1`（题目保证），但 `coins[n-1]` 可能是 -1，此时无解
5. **maxJump 可能大于 n**：不影响正确性，循环中自然处理越界

## 解法详解

### 解法一：反向 DP（推荐）

**思路**：从终点反向计算每个位置到终点的最小代价。

**状态**：`dp[i]` = 从位置 i 到位置 n-1（终点）的最小代价

**初始化**：
- `dp[n-1] = coins[n-1]`（如果 coins[n-1] != -1，否则无解）
- 其余 `dp[i] = INF`

**转移**（从 i = n-2 到 0）：
- 如果 `coins[i] == -1`，跳过
- 对于 j = i+1 到 min(i+maxJump, n-1)：
  - 如果 `dp[j] < dp[next[i]]`（或者 next[i] 未设置）：
    - 更新 `next[i] = j`
  - `dp[i] = coins[i] + dp[next[i]]`

**路径构建**：
- 从 i = 0 开始，沿 `next[i]` 链走到终点
- 每个位置 +1 转为 1-indexed

**字典序保证**：
- 反向遍历时，对于相同 dp 值的跳跃目标，选择 index 较小的。由于从 i+1 开始向右扫描，遇到相等的 dp 值时不更新（用 `<` 而非 `<=`），自然保留了字典序最小的下一步。

### 解法二：正向 DP

**思路**：`dp[i]` = 从位置 0 到位置 i 的最小代价，配合路径比较。

**转移**：对每个位置 i，检查所有能跳到 i 的位置 j（j 在 [i-maxJump, i-1] 范围内），取 `dp[j] + coins[i]` 的最小值。

**字典序处理**：当 dp 值相同时，需要比较完整路径的字典序，或用 `next` 指针从正确方向记录。这种方式实现更复杂。

## 易错点

1. **1-indexed 和 0-indexed 混淆**：题目描述用 1-indexed，代码中用 0-indexed，最终结果需要 +1 转回 1-indexed
2. **字典序处理错误**：正向 DP 需要额外逻辑处理字典序，反向 DP 天然正确，但更新条件（`<` vs `<=`）必须精确
3. **终点不可达**：如果 `coins[n-1] == -1`，直接返回空数组。有些实现忘记这个 early return
4. **起点代价也要算**：`dp[0] = coins[0] + min(dp[1..maxJump])`，起点本身的 coins[0] 也是代价的一部分
5. **INF 溢出**：用 `INT_MAX` 做 INF 时，`coins[i] + dp[j]` 可能溢出。建议用一个足够大但不溢出的值如 `1e9`
6. **next 指针初始化**：`next[i] = -1`，循环结束后需要检查 `next[i]` 是否被更新过

## 面试追问

1. **Q: 为什么反向 DP 天然保证字典序最小？**
   - A: 反向 DP 中 `next[i]` 记录下一跳。当我们从 j = i+1 向右扫描并用严格 `<` 更新 dp 最小值时，对于相同代价的跳跃目标，保留了最左边（最小索引）的目标。这意味着在位置 i 的决策中，优先选择了字典序较小的路径。

2. **Q: 如果要求返回所有最优路径怎么办？**
   - A: 修改 `next[i]` 为一个列表 `nexts[i]`，记录所有等代价的下一步。然后从位置 0 出发做 DFS/BFS 枚举所有路径。

3. **Q: 能否用贪心代替 DP？**
   - A: 不能。贪心只看当前步代价最小，无法保证全局最优。例如当前步代价略大但后续步代价很小的路径，贪心会错过。

4. **Q: 时间复杂度能否优化到 O(n log maxJump)？**
   - A: 可以。用单调队列（滑动窗口最小值）优化内层循环，将 O(maxJump) 降为 O(1) 均摊。但对于 n, maxJump <= 1000 的约束，O(n * maxJump) 已经足够。

5. **Q: 这道题和 Jump Game II (45) 的区别？**
   - A: Jump Game II 求最少跳跃次数，每个位置的跳跃范围是 nums[i]。本题求最小代价总和，跳跃范围固定为 maxJump，且有不可达位置（-1）。
