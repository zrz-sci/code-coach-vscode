# 300. 最长递增子序列

## 核心思路

本质上是：在一个序列中，选出尽可能多的元素，使得它们**保持原始相对顺序**且**严格递增**。这是一个经典的"最优子结构"问题——每个元素面临"选/不选"的决策，且选择受前面已选元素的约束。

## 思维链

1. **读完题第一反应**：子序列不要求连续，所以不能用滑动窗口。最朴素的想法——枚举所有子序列（2^n 个），检查哪个是递增的且最长。这是指数级的，肯定不行。

2. **能不能用 DP？** 子序列问题天然有"选/不选"的结构，而且"以第 i 个元素结尾的 LIS 长度"只依赖于前面的元素——这就是最优子结构 + 重叠子问题，DP 可行！

3. **状态怎么定义？** `dp[i]` = 以 `nums[i]` 结尾的最长递增子序列长度。关键词是"结尾"——这样每个位置才能明确地和前面的位置建立转移关系。

4. **转移方程是什么？** 对于每个 `i`，遍历所有 `j < i`，如果 `nums[j] < nums[i]`，那么 `nums[i]` 可以接在以 `nums[j]` 结尾的 LIS 后面：`dp[i] = max(dp[j] + 1)`。这是 O(n²)。

5. **O(n²) 的瓶颈在哪？** 对每个 `i`，我们遍历了所有 `j < i` 来找最优的前驱。如果我们能快速找到"比 nums[i] 小的元素中，LIS 最长的那个"，就能优化。

6. **怎么突破？用贪心 + 二分！** 维护一个数组 `tails`，`tails[k]` 表示"长度为 k+1 的递增子序列的最小末尾元素"。每来一个新元素，用二分查找它应该放的位置。这样每个元素只需 O(log n)，总共 O(n log n)。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力 DP | dp[i] = 以 nums[i] 结尾的 LIS 长度 | O(n²) | O(n) | ⭐ 必须写出 |

## 关键提示

1. **状态定义的选择**：为什么定义"以 nums[i] 结尾"而不是"前 i 个元素中的 LIS"？因为后者的转移需要知道子序列的末尾值才能判断能否接上，信息不够。"结尾"的定义天然携带了末尾值信息。

2. **dp 初始化**：每个 `dp[i]` 至少为 1——每个元素自身就是长度为 1 的递增子序列。

3. **答案不是 dp[n-1]**：最长递增子序列不一定以最后一个元素结尾！答案是 `max(dp[0], dp[1], ..., dp[n-1])`。

4. **贪心的直觉**：如果两个递增子序列长度相同，末尾元素越小越好——因为给后续元素留了更大的"接上去"的空间。

5. **tails 数组是有序的**：这是二分查找能用的前提。想一想为什么它一定是严格递增的？

```
// DP 填表过程 (nums = [10, 9, 2, 5, 3, 7, 101, 18]):
//
// i=0: nums[0]=10  dp=[1]                       → 无前驱
// i=1: nums[1]=9   dp=[1,1]                     → 9 < 10, 无法接
// i=2: nums[2]=2   dp=[1,1,1]                   → 2 < 10,9, 无法接
// i=3: nums[3]=5   dp=[1,1,1,2]                 → 5>2, dp[3]=dp[2]+1=2
// i=4: nums[4]=3   dp=[1,1,1,2,2]               → 3>2, dp[4]=dp[2]+1=2
// i=5: nums[5]=7   dp=[1,1,1,2,2,3]             → 7>5, dp[5]=dp[3]+1=3
//                                                  7>3, dp[5]=max(3,dp[4]+1)=3
// i=6: nums[6]=101 dp=[1,1,1,2,2,3,4]           → 101>7, dp[6]=dp[5]+1=4
// i=7: nums[7]=18  dp=[1,1,1,2,2,3,4,4]         → 18>7, dp[7]=dp[5]+1=4
//
// 答案 = max(dp) = 4
```

## 解法详解

### 解法1: 动态规划 — O(n²) / O(n) ⭐ 面试首选

**思考过程**：子序列问题 → 选/不选决策 → DP。定义 `dp[i]` 为以 `nums[i]` 结尾的 LIS 长度。对每个 `i`，看前面所有 `j` 中哪些能作为前驱（`nums[j] < nums[i]`），取最大的 `dp[j] + 1`。

```cpp
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        int n = nums.size();
        // dp[i]: 以 nums[i] 结尾的最长递增子序列长度
        vector<int> dp(n, 1);  // 每个元素自身就是长度1的子序列
        
        int ans = 1;
        for (int i = 1; i < n; i++) {
            for (int j = 0; j < i; j++) {
                // nums[j] 能作为 nums[i] 的前驱吗？
                if (nums[j] < nums[i]) {
                    dp[i] = max(dp[i], dp[j] + 1);
                }
            }
            ans = max(ans, dp[i]);  // 答案是所有 dp[i] 的最大值
        }
        return ans;
    }
};
```

**关键点**：
- `dp[i]` 初始化为 1 而非 0——自身就是一个长度为 1 的子序列
- 答案取 `max(dp[i])`，不是 `dp[n-1]`
- 严格递增：条件是 `nums[j] < nums[i]`，不是 `<=`

### 解法2: 贪心 + 二分查找 — O(n log n) / O(n)

**从解法1优化**：解法1对每个 `i` 要遍历前面所有 `j`，这是 O(n) 的。能不能更快地找到"nums[i] 应该接在哪里"？

**核心贪心思想**：维护数组 `tails`，其中 `tails[k]` = 所有长度为 `k+1` 的递增子序列中，末尾元素的最小值。

- 为什么要最小？因为末尾越小，后面能接上的元素越多，给未来留更多可能。
- `tails` 一定是严格递增的——如果长度更长的子序列末尾反而更小，那截取一段就能得到更短但末尾更小的序列，和"最小"矛盾。

**对每个新元素 `nums[i]`**：
- 如果 `nums[i]` > `tails` 末尾：直接追加，LIS 长度 +1
- 否则：用二分找到 `tails` 中第一个 >= `nums[i]` 的位置，替换它（维护"最小末尾"的性质）

```cpp
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        // tails[k]: 长度为 k+1 的递增子序列的最小末尾
        vector<int> tails;
        
        for (int num : nums) {
            // 二分找 tails 中第一个 >= num 的位置
            auto it = lower_bound(tails.begin(), tails.end(), num);
            
            if (it == tails.end()) {
                // num 比所有末尾都大，可以延伸最长的子序列
                tails.push_back(num);
            } else {
                // 替换，用更小的末尾维护贪心性质
                *it = num;
            }
        }
        
        return tails.size();
    }
};
```

**关键点**：
- `tails` 数组的含义不是一个实际的 LIS！它只是辅助求长度的工具
- `lower_bound` 找的是 `>= num` 的第一个位置（严格递增，所以用 `>=`）
- 如果题目改成"非递减"，应该用 `upper_bound`

## 解法对比

| | DP O(n²) | 贪心+二分 O(n log n) |
|---|---|---|
| 思维难度 | 低，经典 DP 模板 | 高，贪心正确性不直观 |
| 编码难度 | 低 | 中（二分细节） |
| 面试推荐 | 先写这个，展示 DP 基本功 | 被追问 Follow-up 时写 |
| 能否还原 LIS | 容易（回溯 dp 数组） | 不能直接还原（tails 不是真正的 LIS） |

## 易错点

1. **答案取错位置**
   - ✗ `return dp[n-1];` — LIS 不一定以最后一个元素结尾
   - ✓ `return *max_element(dp.begin(), dp.end());` 或在循环中维护 `ans`

2. **dp 初始化为 0**
   - ✗ `vector<int> dp(n, 0);` — 当没有前驱时 dp[i] 应该为 1
   - ✓ `vector<int> dp(n, 1);` — 每个元素自身就是长度为 1 的子序列

3. **混淆严格递增和非递减**
   - ✗ `if (nums[j] <= nums[i])` — 这允许相等元素，变成了"非递减子序列"
   - ✓ `if (nums[j] < nums[i])` — 严格递增

4. **tails 数组误以为是答案序列**
   - 以 `[10,9,2,5,3,7,101,18]` 为例，最终 `tails = [2,3,7,18]`
   - 但实际 LIS 是 `[2,3,7,101]` 或 `[2,5,7,101]`
   - `tails` 只能用来求长度，不能直接作为 LIS 输出

## 面试追问

**Q1（基础理解）**：dp[i] 为什么定义为"以 nums[i] 结尾"而不是"前 i 个元素的 LIS 长度"？
> 如果定义为"前 i 个元素的 LIS 长度"，转移时不知道子序列末尾是什么值，无法判断新元素能否接上去。"结尾"的定义让转移条件（`nums[j] < nums[i]`）变得明确。

**Q2（Follow-up 优化）**：能否将时间复杂度降到 O(n log n)？
> 用贪心 + 二分。维护 tails 数组记录各长度子序列的最小末尾，利用 tails 的有序性做二分查找。核心贪心：末尾越小，未来越容易延伸。

**Q3（变体）**：如果要输出一个实际的最长递增子序列（不只是长度），怎么做？
> DP 解法：额外维护 `prev[i]` 记录 dp[i] 是从哪个 j 转移来的，最后从最大 dp 值的位置回溯。贪心+二分解法：需要额外记录每个位置在 tails 中的索引，然后反向构建。

**Q4（变体）**：如果是二维的 LIS（信封嵌套问题，LeetCode 354）？
> 先按第一维排序（升序），第一维相同时按第二维降序（防止同一维度内互相嵌套），然后对第二维求 LIS。
