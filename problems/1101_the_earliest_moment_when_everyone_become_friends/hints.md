# 1101. 彼此熟识的最早时间

## 核心思路

本质上问的是：**按时间顺序处理"连边"操作，何时所有 n 个人第一次属于同一个连通分量？** 这是一个经典的动态连通性问题。

## 思维链

1. **读完题第一反应**：每条日志把两个人连起来，"认识"具有传递性 → 这不就是图的连通分量吗？所有人都认识 = 整张图只有一个连通分量。

2. **最朴素做法**：每处理一条日志，就用 BFS/DFS 检查整个图是否连通。但每次检查都要 O(n + E)，处理 m 条日志总共 O(m × (n + m))，太慢。

3. **瓶颈在哪？** 每次加一条边后都要从头检查连通性，浪费了之前已知的连通信息。

4. **什么数据结构能"增量维护"连通性？** → **并查集（Union-Find）**！它能在近 O(1) 时间内完成"合并两个集合"和"查询两个元素是否同集合"。

5. **核心逻辑**：先按时间排序日志，然后逐条处理。每次 union 成功（两人原本不在同一集合），连通分量数减 1。当分量数降到 1 时，当前时间就是答案。

6. **为什么要排序？** 我们要找"最早时间"，所以必须按时间从小到大处理，第一次全连通的时刻就是答案。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力 BFS/DFS | 每加一条边后 BFS 检查连通性 | O(m × (n+m)) | O(n+m) | 能说出即可 |
| 排序 + 并查集 | 按时间排序，Union-Find 维护连通分量 | O(m log m + m α(n)) | O(n) | ⭐ 必须写出 |

> 其中 m = logs.length，α(n) 是反阿克曼函数，实际可视为常数。

## 关键提示

1. **"认识"有传递性** → 认识关系形成连通分量，不是简单的直接朋友关系。
2. **日志可能不按时间排序**，题目没保证有序，所以第一步必须排序。
3. **不需要真的建图**：并查集只需要一个 parent 数组，不需要邻接表。
4. **提前终止**：连通分量数降到 1 就立刻返回，不用处理剩余日志。
5. 如果处理完所有日志分量数仍 > 1，返回 -1。

```
// 示例1的合并过程可视化：
// 
// 初始: {0} {1} {2} {3} {4} {5}   分量数=6
//
// t=20190101: union(0,1)
//   {0,1} {2} {3} {4} {5}         分量数=5
//
// t=20190104: union(3,4)
//   {0,1} {2} {3,4} {5}           分量数=4
//
// t=20190107: union(2,3)
//   {0,1} {2,3,4} {5}             分量数=3
//
// t=20190211: union(1,5)
//   {0,1,5} {2,3,4}               分量数=2
//
// t=20190224: union(2,4) → 已在同一集合，跳过
//   {0,1,5} {2,3,4}               分量数=2
//
// t=20190301: union(0,3)
//   {0,1,2,3,4,5}                 分量数=1 → 返回 20190301!
```

## 解法详解

### 解法1: 暴力 BFS — O(m × (n+m)) / O(n+m)

**思考过程**: 最直觉的做法——把所有日志按时间排序，逐条加边到邻接表里，每加一条边后用 BFS 从节点 0 出发看能否访问所有 n 个节点。

```cpp
class Solution {
public:
    int earliestAcq(vector<vector<int>>& logs, int n) {
        // 按时间排序
        sort(logs.begin(), logs.end());
        
        // 邻接表
        vector<vector<int>> adj(n);
        
        for (auto& log : logs) {
            int t = log[0], x = log[1], y = log[2];
            adj[x].push_back(y);
            adj[y].push_back(x);
            
            // BFS 检查是否全连通
            vector<bool> visited(n, false);
            queue<int> q;
            q.push(0);
            visited[0] = true;
            int count = 1;
            
            while (!q.empty()) {
                int cur = q.front(); q.pop();
                for (int nei : adj[cur]) {
                    if (!visited[nei]) {
                        visited[nei] = true;
                        count++;
                        q.push(nei);
                    }
                }
            }
            
            if (count == n) return t;
        }
        
        return -1;
    }
};
```

**关键点**: 每加一条边就做一次完整 BFS，明显有大量重复工作。但这是最容易理解的思路，面试中可以先说这个，再引出并查集优化。

---

### 解法2: 排序 + 并查集 — O(m log m + m α(n)) / O(n) ⭐ 面试首选

**从解法1优化**: 解法1的瓶颈是每次加边后都要 O(n+m) 检查连通性。并查集可以 O(α(n))≈O(1) 完成合并和查询，且天然维护连通分量数——每次成功 union 分量数减 1，减到 1 就是答案。

```cpp
class Solution {
public:
    int earliestAcq(vector<vector<int>>& logs, int n) {
        // 第一步：按时间排序，保证按时间顺序处理
        sort(logs.begin(), logs.end());
        
        // 初始化并查集
        vector<int> parent(n), rank_(n, 0);
        for (int i = 0; i < n; i++) parent[i] = i;
        
        int components = n; // 初始每人一个分量
        
        for (auto& log : logs) {
            int t = log[0], x = log[1], y = log[2];
            
            // 尝试合并 x 和 y
            int rx = find(parent, x);
            int ry = find(parent, y);
            
            if (rx != ry) {
                // 按秩合并：矮树挂到高树上，保持树平衡
                if (rank_[rx] < rank_[ry]) swap(rx, ry);
                parent[ry] = rx;
                if (rank_[rx] == rank_[ry]) rank_[rx]++;
                
                components--;
                
                // 提前终止：所有人已在同一集合
                if (components == 1) return t;
            }
        }
        
        return -1; // 处理完所有日志仍未全连通
    }
    
private:
    // 路径压缩：让查找路径上的所有节点直接指向根
    int find(vector<int>& parent, int x) {
        if (parent[x] != x) {
            parent[x] = find(parent, parent[x]);
        }
        return parent[x];
    }
};
```

**关键点**:
- 排序是 O(m log m)，后续处理是 O(m × α(n))，总体由排序主导。
- 路径压缩 + 按秩合并使得每次 find/union 几乎 O(1)。
- `components` 计数器避免了每次都要遍历检查是否全连通。

## 解法对比

| | 暴力 BFS | 排序 + 并查集 |
|---|---|---|
| 时间 | O(m × (n+m)) | O(m log m) |
| 空间 | O(n+m) 邻接表 | O(n) parent数组 |
| 连通性检查 | 每次从头 BFS | 增量维护，近 O(1) |
| 代码复杂度 | 简单但效率低 | 需要会写并查集模板 |
| 面试推荐 | 说思路即可 | **必须能写出来** |

核心区别：并查集是"增量维护"连通性的利器，避免了暴力法的重复计算。

## 易错点

1. **忘记排序**：
   - ✗ 直接按 logs 原始顺序处理 → 可能先处理了时间晚的日志
   - ✓ `sort(logs.begin(), logs.end())` — vector 默认按首元素排序，正好是时间戳

2. **find 函数没做路径压缩**：
   - ✗ `return parent[x] == x ? x : find(parent, parent[x]);` — 没压缩，退化成 O(n)
   - ✓ `parent[x] = find(parent, parent[x]); return parent[x];` — 路径压缩

3. **判断全连通的方式错误**：
   - ✗ 遍历 parent 数组检查是否所有人的 root 相同 → 每次 O(n)
   - ✓ 维护 `components` 计数器，减到 1 就返回 → O(1)

4. **union 时忘记检查是否已在同一集合**：
   - ✗ 直接 `parent[ry] = rx; components--;` → 已经同集合时多减了
   - ✓ 先检查 `rx != ry`，只有不同集合才合并并减计数

## 面试追问

**Q1: 为什么用并查集而不是 BFS/DFS？**
> 每条日志只是加一条边，并查集可以增量维护连通性（O(α(n)) per operation），而 BFS/DFS 每次都要从头检查（O(n+E)）。动态加边场景是并查集的经典应用。

**Q2: 如果 logs 已经按时间排序了，时间复杂度变成多少？**
> O(m × α(n)) ≈ O(m)，因为省去了排序的 O(m log m)。实际上排序通常是瓶颈。

**Q3: 如果不只是加边，还可能删边（取消友谊），该怎么处理？**
> 标准并查集不支持删除操作。可以用"离线处理 + 反向并查集"：先确定最终状态，从后往前加边（删除变成添加）。或者用更复杂的 Link-Cut Tree 支持在线删除。

**Q4: 如果同一时间戳可能有多条日志怎么办？**
> 本题保证所有时间戳不同。如果允许相同时间戳，处理逻辑不变——同一时间戳的所有边处理完后检查 components 即可，因为排序稳定性不影响结果。
