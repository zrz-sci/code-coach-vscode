# 1512. 好数对的数目 (Number of Good Pairs)

## 核心思路

给定一个整数数组 `nums`，好数对 `(i, j)` 定义为 `nums[i] == nums[j]` 且 `i < j`。返回好数对的数目。

本质上就是一个**计数问题**：对于每个值 v，如果出现了 c 次，能组成多少对 `(i, j)`？答案是组合数 C(c, 2) = c * (c-1) / 2。

## 思维链

1. **读完题第一反应** → 暴力双循环，枚举所有 `(i, j)` 对检查是否相等。O(n^2)。
2. **暴力的瓶颈** → 对于 n <= 100 的约束，O(n^2) 绰绰有余，但有没有更优雅的做法？
3. **换个角度想** → 与其枚举所有对，不如统计每个值出现的次数。如果值 v 出现了 c 次，它对答案的贡献就是从 c 个位置中选 2 个 = C(c, 2)。
4. **更巧妙的做法** → 遍历到 `nums[i]` 时，之前已经出现了 `count[nums[i]]` 个相同的值，当前元素能和每一个之前的组成好数对。所以直接 `res += count[nums[i]]`，然后 `count[nums[i]]++`。
5. **数学验证** → 如果值 v 出现 3 次（位置 a, b, c）：
   - 遍历到 a：count=0，贡献 0
   - 遍历到 b：count=1，贡献 1（和 a 配对）
   - 遍历到 c：count=2，贡献 2（和 a、b 分别配对）
   - 总计 0+1+2 = 3 = C(3,2) ✓

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力双循环 | 枚举所有 (i,j) 对 | O(n^2) | O(1) | 能说出即可 |
| 边遍历边计数 | 哈希表在线计数 | O(n) | O(n) | ⭐ 推荐 |
| 后处理组合数 | 先统计频率再求和 C(c,2) | O(n) | O(n) | 等价写法 |
| 数组计数 | 值域有限用数组代替哈希表 | O(n) | O(maxVal) | 常数更小 |

## 关键提示

1. **"边遍历边计数"是核心技巧**：遍历到 `nums[i]` 时，之前已经出现了 `count[nums[i]]` 个相同值，每一个都能和当前构成好数对。这个技巧在很多计数题中反复出现（如 Two Sum、Subarray Sum Equals K）。
2. **组合数等价**：0+1+2+...+(c-1) = c*(c-1)/2 = C(c,2)。两种写法本质相同。
3. **值域提示**：题目说 `1 <= nums[i] <= 100`，所以可以用 `int count[101] = {0}` 代替 `unordered_map`，避免哈希开销。
4. **i < j 不需要特别处理**：边遍历边计数天然保证了 i < j（因为 count 里只存之前的元素）。
5. **这道题是更复杂题目的基础模式**：相同的"边遍历边查表"思路用于 Two Sum、逆序对等问题。

## 解法详解

### 解法1: 暴力双循环 — O(n^2) / O(1)

**思考过程**: 最直接的想法，枚举所有可能的 (i, j) 对，检查 nums[i] == nums[j]。

```cpp
class Solution {
public:
    int numIdenticalPairs(vector<int>& nums) {
        int res = 0;
        int n = nums.size();
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                if (nums[i] == nums[j]) {
                    res++;
                }
            }
        }
        return res;
    }
};
```

**关键点**:
- n <= 100，O(n^2) = 10000 次操作，完全能过。
- 这是理解题意的基础，面试中可以快速说出。

---

### 解法2: 边遍历边计数（哈希表） — O(n) / O(n) ⭐ 推荐

**从暴力优化**: 不需要回头看之前的元素，只需要知道"之前出现了多少个相同值"。

```
示例: nums = [1,2,3,1,1,3]

遍历过程:
i=0, nums[0]=1: count={}, res += 0 → count={1:1}
i=1, nums[1]=2: count={1:1}, res += 0 → count={1:1, 2:1}
i=2, nums[2]=3: count={1:1, 2:1}, res += 0 → count={1:1, 2:1, 3:1}
i=3, nums[3]=1: count={1:1,...}, res += 1 → count={1:2, 2:1, 3:1}
                  ↑ 之前有1个1，能组成1个好数对
i=4, nums[4]=1: count={1:2,...}, res += 2 → count={1:3, 2:1, 3:1}
                  ↑ 之前有2个1，能组成2个好数对
i=5, nums[5]=3: count={...,3:1}, res += 1 → count={1:3, 2:1, 3:2}
                  ↑ 之前有1个3，能组成1个好数对

总计: 0+0+0+1+2+1 = 4 ✓
```

```cpp
class Solution {
public:
    int numIdenticalPairs(vector<int>& nums) {
        unordered_map<int, int> count;
        int res = 0;
        for (int x : nums) {
            res += count[x]; // 当前 x 能和之前的 count[x] 个 x 组成好数对
            count[x]++;
        }
        return res;
    }
};
```

**关键点**:
- `count[x]` 在加之前就是"之前出现了多少个 x"，用 `unordered_map` 的 `[]` 操作符，不存在的 key 默认返回 0，这里正好合适。
- 时间 O(n)，空间 O(n)（哈希表最多存 n 个不同的值）。
- 这个"边遍历边更新"的模式是解决很多配对/计数问题的通用套路。

---

### 解法3: 后处理组合数 — O(n) / O(n)

**不同视角**: 先统计每个值出现的频率，再用组合数公式求总数。

```
示例: nums = [1,2,3,1,1,3]
频率: {1:3, 2:1, 3:2}
好数对: C(3,2) + C(1,2) + C(2,2)
      = 3 + 0 + 1
      = 4 ✓
```

```cpp
class Solution {
public:
    int numIdenticalPairs(vector<int>& nums) {
        unordered_map<int, int> freq;
        for (int x : nums) freq[x]++;
        
        int res = 0;
        for (auto& [val, cnt] : freq) {
            res += cnt * (cnt - 1) / 2; // C(cnt, 2)
        }
        return res;
    }
};
```

**关键点**:
- 数学上完全等价于解法2：0+1+2+...+(c-1) = c*(c-1)/2。
- 需要两次遍历（统计频率 + 计算组合数），而解法2只需要一次遍历。

---

### 解法4: 数组计数（利用值域有限） — O(n) / O(100)

**利用约束优化**: 题目说 `1 <= nums[i] <= 100`，可以用固定大小数组代替哈希表，避免哈希开销。

```cpp
class Solution {
public:
    int numIdenticalPairs(vector<int>& nums) {
        int count[101] = {0}; // 值域 [1, 100]
        int res = 0;
        for (int x : nums) {
            res += count[x];
            count[x]++;
        }
        return res;
    }
};
```

**关键点**:
- 数组访问是 O(1) 且常数极小，比 `unordered_map` 快。
- 空间 O(101) = O(1)，比哈希表更省。
- 当值域有限且不大时，数组计数是比哈希表更好的选择。

## 解法对比

|  | 暴力 | 边遍历边计数 | 后处理组合数 | 数组计数 |
|--|------|------------|------------|---------|
| 时间 | O(n^2) | **O(n)** | O(n) | O(n) |
| 空间 | **O(1)** | O(n) | O(n) | O(1) |
| 遍历次数 | 1 | 1 | 2 | 1 |
| 常数 | 大 | 中 | 中 | **小** |
| 面试推荐 | 起点 | ⭐ 推荐 | 等价 | 最优 |

## 易错点

1. **`unordered_map` 的 `[]` 自动插入**：
   - 在解法2中，`count[x]` 不存在时返回 0 并自动创建，这里恰好是我们想要的行为。
   - 但在其他场景（如 Two Sum），用 `[]` 可能污染哈希表，需要用 `count()` 或 `find()`。

2. **组合数公式的整数溢出**：
   - `cnt * (cnt - 1)` 当 cnt 很大时可能溢出 int。
   - 本题 n <= 100，所以 cnt <= 100，cnt*(cnt-1) <= 9900，完全安全。
   - 更一般的场景下用 `(long long)cnt * (cnt - 1) / 2`。

3. **i < j 的约束**：
   - 暴力解法中内层循环从 `j = i + 1` 开始，自然保证 i < j。
   - 边遍历边计数中，count 只存之前的元素，也天然保证 i < j。
   - 组合数法中，C(c, 2) 本身就是无序对的数量，也没问题。

## 面试追问

**Q1: 暴力能过吗？这道题的真正考点是什么？**
> n <= 100，暴力 O(n^2) 轻松过。但考点是"能否想到 O(n) 的计数优化"。面试中即使暴力能过，也应该展示更优解法。

**Q2: 如果数组非常大（n = 10^7）且值域也很大，怎么办？**
> 用 `unordered_map` 计数，O(n) 时间 O(k) 空间（k = 不同值的数量）。如果值域有限且不大，用数组更快。

**Q3: 如果问"好三元组" (i,j,k) 满足 nums[i]==nums[j]==nums[k] 且 i<j<k 呢？**
> 同样统计频率，每个值 v 出现 c 次的贡献是 C(c, 3) = c*(c-1)*(c-2)/6。或者边遍历时用两层计数。

**Q4: "边遍历边计数"还能用在什么题目上？**
> Two Sum（查找 target - nums[i]）、560. 和为K的子数组（前缀和差值）、逆序对（结合归并排序或 BIT），都是相同的"遍历时查历史状态"模式。

## 相关题型

- **1. 两数之和 (Two Sum)** — 同样的"边遍历边查表"模式，只是查找条件不同（值相等 vs 和为 target）。
- **560. 和为 K 的子数组** — 前缀和 + 哈希表计数，"边遍历边查表"的进阶版。
- **2001. 可互换矩形的组数** — 类似的配对计数：将矩形的宽高比作为 key，统计相同比例的矩形对数。
- **2506. 统计相似字符串对的数目** — 同样的 C(c,2) 计数思路，key 变成了字符集的 bitmask。
