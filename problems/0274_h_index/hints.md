# 274. H 指数 (H-Index)

## 核心思路

找到最大的 h，使得至少有 h 篇论文被引用了至少 h 次。关键洞察：**h 的范围只能是 [0, n]**（因为最多 n 篇论文），而且引用次数超过 n 的论文和引用次数恰好为 n 的论文对 h-index 的贡献一样（因为 h 最大就是 n）。这让我们可以用**计数排序**把时间从 O(n log n) 降到 O(n)。

## 思维链

1. **读完题第一反应**：h-index 的定义有点绕——"至少 h 篇论文引用 >= h 次"。先用一个具体例子理解：`[3,0,6,1,5]`，排序后 `[0,1,3,5,6]`，从大到小看：第1大=6>=1, 第2大=5>=2, 第3大=3>=3, 第4大=1<4 → h=3。

2. **直觉做法**：排序后从后往前数，数到第 i 篇论文（从1开始）的引用次数 < i 时停下，h = i-1。

3. **排序解法的瓶颈**：时间 O(n log n)。能否做到 O(n)？

4. **突破口**：h 最大只能是 n。引用次数为 100 和引用次数为 n 的论文，对 h-index 的贡献完全一样（都是"引用 >= h 次"的论文之一）。所以可以把引用次数 cap 到 n。

5. **计数排序**：创建 `count[0..n]`，`count[i]` = 恰好被引用 i 次的论文数（引用 >= n 的归入 `count[n]`）。从 `count[n]` 到 `count[0]` 累加，当累计论文数 `total >= i` 时，i 就是 h-index。

6. **为什么从后往前？** 因为我们要找**最大的** h。从大到小遍历，第一个满足条件的 i 就是答案。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 排序 + 扫描 | 排序后从大到小检查 | O(n log n) | O(1) | 能写出 |
| 计数排序 | 桶计数 + 后缀累加 | O(n) | O(n) | ⭐ 最优解 |
| 二分查找 | 排序后二分找 h | O(n log n) | O(1) | 变体 |

## 关键提示

1. **h-index 的直觉理解**：把论文按引用次数从大到小排，从第1篇开始往后数，只要"第 k 篇的引用次数 >= k"就继续。停下来的位置 k-1 就是 h-index。想象成"引用次数曲线和 y=x 直线的交点"。

2. **h 的范围是 [0, n]**：这是关键洞察。不可能有 n+1 篇论文（只有 n 篇），所以 h <= n。引用次数大于 n 和恰好等于 n 对 h-index 完全等价。

3. **计数排序的原理图**（以 citations = [3,0,6,1,5] 为例）：
```
// n = 5, 引用次数 cap 到 5
//
// 引用次数:    0   1   2   3   4   5(包含>=5)
// count[]:    [1,  1,  0,  1,  0,  2]
//              ↑0次 ↑1次     ↑3次     ↑5次和6次
//
// 从后往前累加（total = 引用 >= i 的论文数）:
// i=5: total = 0+2 = 2,  2 >= 5? No
// i=4: total = 2+0 = 2,  2 >= 4? No
// i=3: total = 2+1 = 3,  3 >= 3? Yes! → h = 3
```

4. **排序解法的直觉**：排序后 `citations[n-1]` 是最大值，`citations[n-1-i]` 是第 i+1 大的引用次数。`citations[n-1-i] >= i+1` 意味着"第 i+1 大的引用 >= i+1"。第一个不满足的位置就是 h 的上界。

5. **计数排序 vs 普通排序**：普通排序是基于比较的，下界 O(n log n)。计数排序利用了"值域有限"（0 到 n）的特点，用 O(n) 时间 + O(n) 空间完成排序效果。

## 解法详解

### 解法1: 排序 + 线性扫描 — O(n log n) / O(1)

**思考过程**：排序后引用次数从小到大排列。从后往前看，`citations[n-1-i]` 是第 i+1 大的引用次数。如果 `citations[n-1-i] >= i+1`，说明至少有 i+1 篇论文引用 >= i+1 次。找最大的这样的 i+1。

```cpp
class Solution {
public:
    int hIndex(vector<int>& citations) {
        sort(citations.begin(), citations.end());
        int n = citations.size();
        
        for (int i = 0; i < n; i++) {
            // citations[n-1-i] 是第 i+1 大的引用次数
            // 如果第 i+1 大的引用 < i+1，说明不可能有 i+1 篇论文引用 >= i+1
            if (citations[n - 1 - i] < i + 1) {
                return i;  // h-index 是 i（上一个满足的位置）
            }
        }
        
        return n;  // 所有论文引用都 >= n
    }
};
```

**逐步模拟**（citations = [3,0,6,1,5]）：
```
排序后: [0, 1, 3, 5, 6]

i=0: citations[4] = 6 >= 1? Yes → 至少 1 篇引用 >= 1
i=1: citations[3] = 5 >= 2? Yes → 至少 2 篇引用 >= 2
i=2: citations[2] = 3 >= 3? Yes → 至少 3 篇引用 >= 3
i=3: citations[1] = 1 >= 4? No  → 不到 4 篇引用 >= 4
→ 返回 i = 3

答案: h = 3 ✓
```

### 解法2: 计数排序 — O(n) / O(n) ⭐ 面试最优

**从解法1优化**：排序的 O(n log n) 能否降到 O(n)？可以！因为 h <= n，我们不关心引用次数的具体大小，只关心"引用 >= h 的论文有多少篇"。

**核心操作**：
1. 创建计数桶 `count[0..n]`
2. 遍历 citations，将每篇论文计入对应的桶（引用 >= n 的归入 `count[n]`）
3. 从 `count[n]` 开始累加 total，`total` 表示"引用 >= i 的论文数"
4. 第一个 `total >= i` 的 i 就是 h-index

```cpp
class Solution {
public:
    int hIndex(vector<int>& citations) {
        int n = citations.size();
        
        // Step 1: 计数桶
        // count[i] = 引用次数恰好为 i 的论文数
        // 引用次数 >= n 的全部归入 count[n]（因为 h 最大就是 n）
        vector<int> count(n + 1, 0);
        for (int c : citations) {
            count[min(c, n)]++;
        }
        
        // Step 2: 从后往前累加
        // total = 引用次数 >= i 的论文总数
        int total = 0;
        for (int i = n; i >= 0; i--) {
            total += count[i];
            // 至少有 total 篇论文引用 >= i 次
            // 如果 total >= i，那 h-index 至少为 i
            // 因为从大到小遍历，第一个满足的 i 就是最大的 h
            if (total >= i) {
                return i;
            }
        }
        
        return 0;  // 所有论文引用为 0
    }
};
```

**逐步模拟**（citations = [3,0,6,1,5], n=5）：
```
Step 1 - 建桶:
  c=3: count[3]++  → count = [0,0,0,1,0,0]
  c=0: count[0]++  → count = [1,0,0,1,0,0]
  c=6: count[5]++  → count = [1,0,0,1,0,1] (6 >= 5, 归入 count[5])
  c=1: count[1]++  → count = [1,1,0,1,0,1]
  c=5: count[5]++  → count = [1,1,0,1,0,2]

Step 2 - 后缀累加:
  i=5: total = 0+2 = 2,  2 >= 5? No
  i=4: total = 2+0 = 2,  2 >= 4? No
  i=3: total = 2+1 = 3,  3 >= 3? Yes! → 返回 3

答案: h = 3 ✓
```

### 解法3: 排序 + 二分查找 — O(n log n) / O(1)

**另一种思路**：排序后，利用有序性用二分查找找到 h-index。

**二分目标**：找最大的 h，使得 `citations[n - h] >= h`（即从后数第 h 个位置的值 >= h）。

```cpp
class Solution {
public:
    int hIndex(vector<int>& citations) {
        sort(citations.begin(), citations.end());
        int n = citations.size();
        
        int lo = 0, hi = n;
        while (lo < hi) {
            int mid = lo + (hi - lo + 1) / 2;  // 上取整，避免死循环
            // 检查是否至少有 mid 篇论文引用 >= mid
            if (citations[n - mid] >= mid) {
                lo = mid;       // mid 可行，尝试更大的
            } else {
                hi = mid - 1;   // mid 不可行，缩小范围
            }
        }
        
        return lo;
    }
};
```

## 解法对比

|  | 解法1: 排序+扫描 | 解法2: 计数排序 | 解法3: 排序+二分 |
|---|---|---|---|
| 时间 | O(n log n) | O(n) ⭐ | O(n log n) |
| 空间 | O(1)* | O(n) | O(1)* |
| 核心技巧 | 从大到小线性扫描 | 桶计数 + 后缀累加 | 有序性 + 二分 |
| 面试推荐 | 能写出 | ⭐ 最优解 | 展示二分技巧 |
| 代码难度 | 简单 | 简单 | 中等（二分边界） |

*注：排序方法标注 O(1) 空间不计排序本身的空间。

**什么时候选哪个？**
- 面试第一轮：写解法1（排序+扫描），简单直觉。
- 面试追问"能否 O(n)"：给解法2（计数排序），展示关键洞察"h <= n"。
- 面试追问"还有什么方法"：提解法3（二分），展示二分查找的应用。

## 易错点

1. **h-index 搞混了"论文数"和"引用数"**
   ```cpp
   // ✗ 错误：返回引用次数而不是论文数量
   // h-index 是"论文数量"——"至少 h 篇论文引用 >= h 次"
   
   // ✓ 正确理解：h 是一个数量，不是某篇论文的引用次数
   ```

2. **计数排序忘记将 >= n 的归入 count[n]**
   ```cpp
   // ✗ 错误：引用次数为 1000 时访问 count[1000] → 越界
   count[c]++;
   
   // ✓ 正确：cap 到 n
   count[min(c, n)]++;
   ```

3. **排序解法的方向搞反**
   ```cpp
   // ✗ 错误：从小到大扫描，找的不是最大的 h
   for (int i = 0; i < n; i++) {
       if (citations[i] >= n - i) return n - i;  // 逻辑对但返回时机不对
   }
   
   // ✓ 正确：从最大的引用开始检查，找第一个不满足的位置
   for (int i = 0; i < n; i++) {
       if (citations[n - 1 - i] < i + 1) return i;
   }
   return n;
   ```

4. **所有论文引用为 0 的边界**
   ```cpp
   // citations = [0, 0, 0]
   // 排序后: [0, 0, 0]
   // i=0: citations[2] = 0 >= 1? No → 返回 0
   // 正确！h-index = 0
   ```

5. **二分查找中的上取整问题**
   ```cpp
   // ✗ 可能死循环：lo=0, hi=1 时 mid = 0，lo = mid = 0，永远不变
   int mid = lo + (hi - lo) / 2;  // 下取整
   
   // ✓ 当 lo = mid 时需要上取整
   int mid = lo + (hi - lo + 1) / 2;  // 上取整
   ```

6. **计数排序从后往前遍历遗漏 i=0**
   ```cpp
   // ✗ 遗漏了 i=0 的情况
   for (int i = n; i >= 1; i--) { ... }
   
   // ✓ 包含 i=0
   for (int i = n; i >= 0; i--) { ... }
   // 虽然 h=0 意味着"没有论文被引用"，但逻辑上需要覆盖
   ```

## 面试追问

**Q1（基础理解）**：为什么 h-index 最大只能是 n？
> 因为总共只有 n 篇论文。"至少 h 篇论文引用 >= h 次"中的 h 不可能超过论文总数。即使每篇论文都被引用 1000 次，h 也只能是 n。

**Q2（优化追问）**：排序解法是 O(n log n)，能否做到 O(n)？
> 可以，用计数排序。关键观察：h <= n，所以引用次数 > n 的论文和引用 = n 的论文等价。建立 `count[0..n]` 桶后，从后往前累加找到第一个 `total >= i` 的位置就是答案。这是用 O(n) 空间换 O(n) 时间。

**Q3（变体）**：如果 citations 已经排好序了呢？（→ LeetCode 275）
> 排序已完成，可以用二分查找。在有序数组中二分找最大的 h 使得 `citations[n-h] >= h`。时间 O(log n)，这就是 LeetCode 275 的最优解。

**Q4（深入理解）**：计数排序中为什么 `total >= i` 就是答案？
> `total` 是"引用次数 >= i 的论文总数"。h-index 的定义是"至少 h 篇论文引用 >= h"。所以当 total >= i 时，i 满足 h-index 的定义。因为我们从大到小遍历，第一个满足的 i 就是最大的 h。

**Q5（拓展思考）**：如果论文数量很大（百万级）且引用次数也很大，哪种方法最好？
> 如果引用次数范围很大但论文数 n 是有限的，计数排序仍然是 O(n)（因为桶大小只有 n+1）。如果 n 本身很大，计数排序的 O(n) 空间可能成问题，此时可以用排序+扫描 O(n log n) / O(1)，或者用更高级的数据结构（如 order-statistic tree）。
