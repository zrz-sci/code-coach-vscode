# 面试题 01.06. 字符串压缩

## 核心思路

本质上在问：遍历字符串，统计连续相同字符的个数，构造 "字符+出现次数" 的压缩串，若压缩后更短则返回压缩串，否则返回原串。核心难点不在算法本身，而在细节处理（边界、数字转字符串、最终长度比较）。

## 思维链

1. **读完题第一反应**：用一个指针遍历字符串，遇到连续相同的字符就计数，遇到不同字符时把 "字符+计数" 拼接到结果串里。最后比较长度决定返回哪个。

2. **暴力解需要注意什么？** 其实这题没有"暴力 vs 优化"的区分 — 任何解法都是 O(n) 的一次遍历。核心考察的是：
   - 你能不能一次遍历把所有连续段统计完？
   - 边界情况：空串、只有一个字符、最后一段连续字符如何处理？
   - 数字可能是多位数（比如 "aaa...a" 出现 100 次，计数是 "100" 而不是 "1"、"0"、"0"）

3. **用双指针还是单指针？** 两种写法都可以：
   - **单指针 + 计数器**：逐字符遍历，当前字符和前一个不同时输出一段
   - **双指针**：`i` 指向段首，`j` 向前跑到段尾，段长为 `j - i`
   双指针写法更清晰，不容易搞混边界。

4. **能不能提前判断？** 在实际构造压缩串之前，可以先遍历一遍统计压缩后的长度，如果不会变短就直接返回原串。但这不是必要优化，面试中一次遍历直接构造即可。

5. **面试最佳策略**：双指针一次遍历，代码简洁清晰。注意把 "最后一段" 的处理融入循环或在循环后额外处理。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 双指针一次遍历 | i 指向段首，j 找段尾，拼接 char+count | O(n) | O(n) | ⭐ 必须写出 |
| 单指针 + 计数器 | 逐字符遍历，遇到不同字符时输出 | O(n) | O(n) | 也可以 |
| 预计算长度 | 先算长度再决定是否构造 | O(n) | O(1)/O(n) | 优化版 |

## 关键提示

1. **最后一段的处理**：最常见的 bug 是循环结束后忘记把最后一段写入结果。双指针写法中，外层 `while(i < n)` 天然包含了最后一段；单指针写法中，循环结束后需要额外处理。

2. **数字转字符串**：计数值不一定是个位数！如果连续字符有 100 个，压缩后是 "a100" 而不是 "a1"。用 `to_string(count)` 来转换。

3. **长度比较**：压缩串可能比原串更长（如 "abc" → "a1b1c1"）。最终要比较 `compressed.size()` 和 `S.size()`。

4. **空串**：空串直接返回空串。这个 edge case 别漏。

5. **每个字符出现次数至少是 1**：即使字符只出现一次，压缩后也是 "a1"（2个字符），所以如果原串中每个字符都不同，压缩后长度一定是原来的两倍。

## 解法详解

### 解法1: 双指针一次遍历 — O(n) / O(n)

**思考过程**：最清晰的写法。用两个指针 `i` 和 `j`，`i` 始终指向当前连续段的起点，`j` 向前移动找到当前段的终点（即第一个和 `s[i]` 不同的位置）。段长为 `j - i`。

**关键决策**：为什么用双指针而不是单指针？因为双指针可以直接用 `j - i` 得到段长，不需要维护额外的计数变量，而且循环结构天然覆盖最后一段。

```
示例: S = "aabcccccaaa"

i=0, j→2:  段 "aa"    → "a2"
i=2, j→3:  段 "b"     → "b1"
i=3, j→8:  段 "ccccc" → "c5"
i=8, j→11: 段 "aaa"   → "a3"

结果: "a2b1c5a3" (长度8 < 原串长度11) → 返回压缩串
```

```cpp
class Solution {
public:
    string compressString(string S) {
        int n = S.size();
        if (n == 0) return S;  // 边界: 空串
        
        string compressed;
        int i = 0;
        while (i < n) {
            int j = i;
            // j 向前跑，直到遇到不同字符
            while (j < n && S[j] == S[i]) {
                j++;
            }
            // S[i..j-1] 是一个连续段，字符为 S[i]，长度为 j-i
            compressed += S[i];
            compressed += to_string(j - i);
            i = j;  // 跳到下一段
        }
        
        // 比较长度，返回较短的那个
        return compressed.size() < S.size() ? compressed : S;
    }
};
```

**自检**：
- 空串？`n == 0` 直接返回 ✓
- 单字符 "a"？i=0, j=1, 压缩 "a1"(2) >= "a"(1), 返回原串 ✓
- "aabcccccaaa"？压缩 "a2b1c5a3"(8) < 11, 返回压缩串 ✓

### 解法2: 单指针 + 计数器 — O(n) / O(n)

**思考过程**：另一种常见写法，维护一个计数器 `count`，遍历时比较当前字符和前一个字符。

**关键决策**：每次发现 `S[i] != S[i-1]` 时，输出前一段。循环结束后还需要输出最后一段 — 这就是为什么双指针更推荐的原因。

**技巧**：让循环条件为 `i <= n`（注意 <= 不是 <），当 `i == n` 时自然触发"最后一段输出"的逻辑，避免循环外的重复代码。

```cpp
class Solution {
public:
    string compressString(string S) {
        int n = S.size();
        if (n == 0) return S;
        
        string compressed;
        int count = 1;
        
        for (int i = 1; i <= n; i++) {
            // i==n 或 当前字符与前一个不同 → 输出一段
            if (i == n || S[i] != S[i - 1]) {
                compressed += S[i - 1];
                compressed += to_string(count);
                count = 1;
            } else {
                count++;
            }
        }
        
        return compressed.size() < S.size() ? compressed : S;
    }
};
```

### 解法3: 预计算长度（优化版）— O(n) / O(n)

**思考过程**：如果压缩后注定不会更短，我们可以提前返回原串，避免构造压缩串的开销。先遍历一遍计算压缩后的长度，长度 >= 原串时直接返回。

```cpp
class Solution {
public:
    string compressString(string S) {
        int n = S.size();
        if (n == 0) return S;
        
        // 第一遍：计算压缩后的长度
        int compressedLen = 0;
        int i = 0;
        while (i < n) {
            int j = i;
            while (j < n && S[j] == S[i]) j++;
            // 1个字符 + 数字的位数
            compressedLen += 1 + (int)to_string(j - i).size();
            i = j;
        }
        
        // 提前判断：压缩后不会更短
        if (compressedLen >= n) return S;
        
        // 第二遍：构造压缩串
        string compressed;
        compressed.reserve(compressedLen);  // 预分配精确空间
        i = 0;
        while (i < n) {
            int j = i;
            while (j < n && S[j] == S[i]) j++;
            compressed += S[i];
            compressed += to_string(j - i);
            i = j;
        }
        
        return compressed;
    }
};
```

## 解法对比

| 解法 | 时间 | 空间 | 优势 | 劣势 |
|------|------|------|------|------|
| 双指针 | O(n) | O(n) | 代码最简洁，无遗漏边界 | - |
| 单指针 | O(n) | O(n) | 直觉自然 | 容易忘记最后一段 |
| 预计算 | O(n) | O(n) | 避免不必要的构造 | 两遍遍历，代码稍长 |

**从解法1到解法3的演进逻辑**：
- 解法1和解法2本质相同，只是遍历风格不同（双指针 vs 计数器）
- 解法3是对"不必要构造"的优化：先算长度，不够短就别费力构造了

**面试策略**：直接写解法1（双指针）。如果面试官问"能不能优化"，提一下预计算长度的思路。

## 易错点

1. **忘记最后一段（单指针写法）**：
   ```cpp
   // ✗ 错误：循环结束后没有输出最后一段
   for (int i = 1; i < n; i++) {
       if (S[i] != S[i-1]) {
           compressed += S[i-1];
           compressed += to_string(count);
           count = 1;
       } else count++;
   }
   // 最后一段 "aaa" 被遗漏！
   
   // ✓ 正确：循环后补上
   compressed += S[n-1];
   compressed += to_string(count);
   ```

2. **长度比较用 ≤ 还是 <**：
   ```cpp
   // 题目说"压缩后没有变短则返回原串"，等长时也返回原串
   return compressed.size() < S.size() ? compressed : S;  // ✓ 用 <
   // 不能用 <=，因为等长时也应该返回原串
   ```

3. **计数直接用 char 拼接**：
   ```cpp
   // ✗ 错误：count可能>9，直接加 '0'+count 会溢出
   compressed += (char)('0' + count);  // 当 count=100 时变成乱码！
   
   // ✓ 正确：用 to_string
   compressed += to_string(count);
   ```

4. **空串未处理**：
   ```cpp
   // ✗ 错误：S为空时 S[0] 越界
   char curr = S[0];
   
   // ✓ 正确：先判空
   if (S.empty()) return S;
   ```

## 面试追问

**Q1: 时间和空间复杂度分析？**
A1: 时间 O(n)，一次遍历。空间 O(n)，压缩串最坏情况也是 O(n)（实际最坏是 2n，每个字符各不同时）。

**Q2: 如果字符串非常长（比如 1GB），怎么处理？**
A2: 流式处理（streaming）。不需要一次性加载整个字符串，用一个字符一个字符读入的方式，维护当前字符和计数器即可。输出也是流式的，不需要在内存中保存完整的压缩串。这是经典的 "大数据处理" 面试追问。

**Q3: 如果要支持解压（从压缩串还原原串）怎么做？**
A3: 遍历压缩串，交替读取字符和后面的数字（数字可能是多位），然后把字符重复相应次数。注意数字解析需要处理多位数的情况。参考 LC 394 (Decode String)。

**Q4: 如果字符串中除了字母还包含数字，压缩格式可能有歧义（"a1b2" 中的 1 是计数还是字符？），怎么设计编码？**
A4: 需要引入分隔符或转义字符。例如用固定宽度的计数（4位数 "a0001b0002"），或者在字符和计数之间加分隔符（"a:1:b:2"），或者只压缩连续重复超过一定阈值的段。这考察编码设计能力。

**Q5: 这题和 LeetCode 443 (String Compression) 有什么区别？**
A5: LC 443 要求原地压缩（in-place），不能用额外字符串，且计数为 1 时不写数字。那题更难，需要双指针 + 原地写入。本题允许创建新字符串，且计数为 1 也要写。
