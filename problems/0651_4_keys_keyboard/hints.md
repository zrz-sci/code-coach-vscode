# 651. 四个键的键盘 (4 Keys Keyboard)

**难度**: Medium | **标签**: Math, Dynamic Programming

## 核心思路

本题的关键在于发现**操作的最优结构**：在某个时刻，我们应该停止打 'A'，转而使用 Ctrl-A + Ctrl-C + 若干次 Ctrl-V 来倍增屏幕上的字符数。一次 Ctrl-A + Ctrl-C + (j-1) 次 Ctrl-V 会将字符数乘以 j 倍（总共消耗 j+1 步）。

核心 DP：dp[i] = 用 i 步最多能得到的 'A' 的数量。对于每一步 i，要么直接打 'A'（dp[i] = dp[i-1] + 1），要么在之前某个步骤 j 之后做 Ctrl-A + Ctrl-C + 连续 Ctrl-V。

## 思维链

1. **分析操作序列**：最优序列一定是"打若干 A" + 若干段"Ctrl-A, Ctrl-C, Ctrl-V, Ctrl-V, ..."
2. **关键洞察**：一段"Ctrl-A + Ctrl-C + k 次 Ctrl-V"消耗 k+2 步，将字符数变为原来的 (k+1) 倍
3. **DP 定义**：dp[i] = 用 i 次按键最多能产生的 'A' 数量
4. **DP 转移**：对于 dp[i]，要么是 dp[i-1] + 1（直接打 A），要么是 dp[j] * (i-j-1)（在第 j 步后做 Ctrl-A, Ctrl-C, 然后 i-j-2 次 Ctrl-V）
5. **倍增因子**：从步骤 j 到步骤 i，做一次复制粘贴操作，倍增因子 = i - j - 1
6. **最优倍增因子**：数学上可以证明，最优的乘法因子不超过 5（实际上 3 和 4 最好）

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| DP (通用) | O(n^2) | O(n) | 标准解法 |
| 数学优化 DP | O(n) | O(n) | 利用最优因子只有 3/4/5 |
| 纯数学 | O(1) | O(1) | 仅限特定分析 |

## 关键提示

1. **Ctrl-A + Ctrl-C 消耗 2 步**：这两步不产生新的 'A'，但为后续 Ctrl-V 做准备
2. **Ctrl-V 追加而非覆盖**：每次 Ctrl-V 都是在已有内容后追加 buffer 内容
3. **多次 Ctrl-V 的效果**：如果屏幕有 x 个 A，执行 Ctrl-A + Ctrl-C + k 次 Ctrl-V，结果是 x * (k+1) 个 A（注意不是 x + k*x，因为 Ctrl-V 是追加 buffer，buffer = x，执行 k 次 V 得到 x + k*x = x*(k+1)）
4. **没有"覆盖"buffer 的问题**：buffer 一旦 Ctrl-C 就固定，直到下一次 Ctrl-C
5. **dp 转移的理解**：dp[j] * (i - j - 1) 中，i - j - 1 就是乘法因子。因为步骤 j+1 是 Ctrl-A，j+2 是 Ctrl-C，j+3 到 i 都是 Ctrl-V，共 i-j-2 次 Ctrl-V，倍增因子 = i-j-2+1 = i-j-1

## 解法详解

### 解法一：DP

**状态定义**：dp[i] = 用 i 次按键操作，屏幕上最多有多少个 'A'

**初始状态**：dp[i] = i（全部打 'A'，不做任何复制粘贴）

**状态转移**：
对于 j 从 i-3 到 1（倒序扫描更直观）:
  - 在第 j 步时决定开始复制
  - j+1: Ctrl-A
  - j+2: Ctrl-C
  - j+3 到 i: 执行 i-j-2 次 Ctrl-V
  - 倍增因子 = i - j - 1
  - dp[i] = max(dp[i], dp[j] * (i - j - 1))

**为什么 j 从 i-3 开始？**
- 至少需要 Ctrl-A + Ctrl-C + 一次 Ctrl-V = 3 步才有意义
- 如果只做 Ctrl-A + Ctrl-C 不做 Ctrl-V，相当于浪费 2 步

### 解法二：数学优化

**观察**：对于足够大的 n，最优策略是交替使用乘以 3 和乘以 4 的操作段。

- 乘以 2（消耗 3 步）：每步产出 2^(1/3) 约 1.26
- 乘以 3（消耗 4 步）：每步产出 3^(1/4) 约 1.316
- 乘以 4（消耗 5 步）：每步产出 4^(1/5) 约 1.32
- 乘以 5（消耗 6 步）：每步产出 5^(1/6) 约 1.308

因此乘以 4（5步）和乘以 3（4步）效率最高，乘以 5 以上效率下降。

## 易错点

1. **Ctrl-V 的语义理解错误**：Ctrl-V 是追加 buffer 到屏幕末尾，不是替换屏幕内容。如果屏幕有 "AAA" 且 buffer 是 "AAA"，按一次 V 得到 "AAAAAA"（6个），不是 "AAA"（3个）
2. **倍增因子计算**：在步骤 j 到 i 之间，消耗 2 步做 Ctrl-A + Ctrl-C，剩余 i-j-2 次 Ctrl-V，产生 dp[j] * (i-j-2+1) = dp[j] * (i-j-1) 个字符
3. **初始化遗漏**：dp[i] = i 是 base case（全部按 A），不能忘记
4. **n 较小时**：n <= 6 时，直接打 A 可能是最优的（n=6 时打 3 个 A 然后 Ctrl-A+C+V 也是 6 个）
5. **buffer 不随 Ctrl-V 更新**：连续按 V 每次都追加同一个 buffer 内容

## 面试追问

1. **Q: 为什么不需要在 DP 中建模 buffer 的状态？**
   A: 因为最优策略中，每次 Ctrl-C 之后紧接着的所有 Ctrl-V 都使用同一个 buffer。不存在"多次 Ctrl-C 再 Ctrl-V"的更优方案（额外的 Ctrl-C 浪费了一步）。因此只需要记录屏幕上的 A 数量。

2. **Q: 时间复杂度能优化到 O(n) 吗？**
   A: 可以。观察到最优倍增因子只可能是 3、4 或 5（偶尔 2），因此 j 只需从 i-5 扫描到 i-3，常数次比较即可。

3. **Q: 如果 n 非常大（比如 10^9），怎么办？**
   A: 用数学分析：最优策略约为将 n 分成若干段，每段 4-5 步（乘以 3 或 4）。结果约为 3^(n/4) 或 4^(n/5)。可以 O(1) 计算。

4. **Q: Ctrl-A 选择全部 vs 选择部分？**
   A: 题目中 Ctrl-A 只能选择全屏。如果能选择部分，问题会更复杂。

5. **Q: 如果增加一个 Ctrl-X（剪切）操作呢？**
   A: Ctrl-X = Ctrl-C + 清空屏幕。由于 Ctrl-V 会追加，先 X 再 V 效果和原来一样但多了清空步骤，所以不会比现有策略更好。
