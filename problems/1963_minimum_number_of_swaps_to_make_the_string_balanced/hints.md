# 1963. 使字符串平衡的最小交换次数

## 核心思路

给定一个由等数量的 `[` 和 `]` 组成的字符串，可以交换任意两个位置的括号。求使字符串变成**平衡括号串**所需的**最少交换次数**。

关键洞察：先消掉所有已经匹配的括号对，剩下的一定是 `]]]...[[[...` 形式（前面全是 `]`，后面全是 `[`）。设未匹配的 `]` 数量为 k，则答案是 `ceil(k/2)` = `(k+1)/2`。

## 思维链

1. **读完题第一反应**：平衡括号串 = 合法的括号序列。可以交换任意两个位置。求最少交换次数。

2. **先简化问题**：扫一遍字符串，用一个计数器消掉能匹配的括号对。遇到 `[` 就 `open++`，遇到 `]` 时如果 `open > 0` 就消掉一对 (`open--`)，否则这个 `]` 没有配对 (`close++`)。

3. **消掉后剩什么？**：剩下 `close` 个未匹配的 `]` 和 `close` 个未匹配的 `[`（因为总数相等）。这些未匹配的一定形如 `]]]...[[[...`。

4. **一次交换能修多少？**：
   - 如果剩 `][`，交换这两个变成 `[]`，修掉了 2 个未匹配括号
   - 如果剩 `]][[`，交换中间两个 → `[]][` → 不对。交换首尾 → `[]][` 也不对。交换第一个 `]` 和最后一个 `[` → `[][]` → 修掉了全部 4 个！所以 2 对未匹配需要 1 次交换。
   - 等等，`]][[` 交换首尾: `[` 和 `]` → `[]][`? 不对。让我重新想...
   - `]][[`: 交换 index 0 (`]`) 和 index 3 (`[`) → `[]][` → 只修了一对。需要再交换 index 1 和 index 2 → `[[]]` → OK，2次交换修了4个。不对？
   - 实际上 `]][[` → 交换 index 0 和 index 2: `[]]['` 不行。
   - 交换 index 0 (`]`) 和 index 3 (`[`): `[]]['`... 我来手动算:
     ```
     ]  ]  [  [
     0  1  2  3
     交换 s[0] 和 s[3]: [  ]  [  ] → 不是 "][[]" ... 
     等等: 原始 ]][[, 交换第0个]和第3个[:
     s = [, ], [, ] → "[][]" → 平衡了! 只需1次交换!
     ```
   - 所以 4 个未匹配（2个`]` + 2个`[`），只需 1 次交换！

5. **更一般的情况**：
   - 2 个未匹配 (`][`) → 1 次交换
   - 4 个未匹配 (`]][[`) → 1 次交换? 等等那上面的 `]]][[[ `(6个未匹配) 需要2次。
   - k 个未匹配的 `]` → 每次交换修掉 2 个 → 需要 `ceil(k/2)` = `(k+1)/2` 次

6. **验证**：
   ```
   "][" → close=1 → (1+1)/2 = 1 ✓
   "][][" → 扫描: ]→close=1, [→open=1, ]→消掉open, [→open=1
     剩余: close=1 → (1+1)/2 = 1 ✓
   "]]][[[" → close=3 → (3+1)/2 = 2 ✓
   "[]" → close=0 → 0 ✓
   ```

## 关键提示

1. **贪心的正确性**：交换时，最优策略是拿一个最左边的未匹配 `]` 和一个最右边的未匹配 `[` 交换。一次交换修掉 2 个未匹配。特殊情况：如果 k 是奇数，最后一次交换只修 1 个（实际上修 2 个，因为一个 `][` 变成 `[]` 修了 2 个）。

2. **为什么 close == open（未匹配数）？**：总的 `[` 和 `]` 数量各占 n/2。已匹配的每配对消耗一个 `[` 和一个 `]`。剩余的未匹配 `[` 数 = 剩余的未匹配 `]` 数。

3. **不需要用栈**：虽然括号匹配经典思路是用栈，但本题只需要一个计数器。用 `open` 跟踪未匹配的 `[` 数量就够了。

4. **交换的可视化**：
   ```
   "][" (close=1):
     ] [  →  交换0和1  →  [ ]  → 平衡!
     1次交换
   
   "][][" (close=1, 中间一对已匹配):
     ] [ ] [
     先消掉第1和第2个: ][  (close=1)
     交换: [] → 平衡!
     1次交换
   
   "]]][[[" (close=3):
     ] ] ] [ [ [
     交换0和5: [ ] ] [ [ ]  → "[]]["["...]"
     再简化: [] ][ [] → 中间 ][ 需要1次交换
     共2次  → ceil(3/2) = 2 ✓
   ```

5. **示例完整推演**：
   ```
   s = "]]][[["
   
   扫描过程:
     s[0] = ']': open=0, 无法匹配 → close=1
     s[1] = ']': open=0, 无法匹配 → close=2
     s[2] = ']': open=0, 无法匹配 → close=3
     s[3] = '[': open=1
     s[4] = '[': open=2
     s[5] = '[': open=3
   
   close = 3, open = 3
   答案 = (3 + 1) / 2 = 2 ✓
   ```

|------|------|------|------|------|

## 解法详解

### 解法1: 贪心计数 -- O(n) / O(1) 推荐

**思路**：一次遍历统计未匹配的 `]` 数量 `close`。答案 = `(close + 1) / 2`。

```cpp
class Solution {
public:
    int minSwaps(string s) {
        int open = 0;   // 未匹配的 '[' 数量
        int close = 0;  // 未匹配的 ']' 数量
        for (char c : s) {
            if (c == '[') {
                open++;
            } else {  // c == ']'
                if (open > 0) {
                    open--;  // 和最近的 '[' 配对消掉
                } else {
                    close++; // 无法配对，记录
                }
            }
        }
        return (close + 1) / 2;  // 每次交换修 2 个
    }
};
```

**正确性证明**：
- 消掉已匹配对后，剩余形如 `]]]...[[[...`（close 个 `]` + close 个 `[`）
- 交换一对（最左 `]` 和最右 `[`）可以修掉 2 个未匹配
- 共需 `ceil(close / 2)` 次

---

### 解法1b: 更简洁的写法 -- 只用一个变量

**观察**：我们甚至不需要 `close`，只需要跟踪 `open` 的最小值（最大负值）。

```cpp
class Solution {
public:
    int minSwaps(string s) {
        int balance = 0;  // 当前未匹配的 '[' 数量（负值表示 ']' 多出来了）
        int maxClose = 0; // 过程中 ']' 多出来的最大数量
        for (char c : s) {
            if (c == '[') balance++;
            else balance--;
            maxClose = max(maxClose, -balance);
        }
        // 不对，这个思路更复杂了。还是用解法1更清晰。
        // 实际上更简洁的写法是:
        int open = 0;
        for (char c : s) {
            if (c == '[') open++;
            else if (open > 0) open--;
        }
        // open = 遍历完后剩余的未匹配 '[' 数 = close 数
        return (open + 1) / 2;
    }
};
```

**注意**：遍历完后 `open` = 剩余未匹配的 `[` 数 = 未匹配的 `]` 数 = `close`。所以也可以返回 `(open + 1) / 2`。

---

### 解法2: 栈模拟 -- O(n) / O(n)

**思路**：用栈消掉所有匹配的括号对，栈中剩余的就是未匹配的。

```cpp
class Solution {
public:
    int minSwaps(string s) {
        stack<char> st;
        for (char c : s) {
            if (c == '[') {
                st.push(c);
            } else {
                if (!st.empty() && st.top() == '[') {
                    st.pop();  // 配对消掉
                } else {
                    st.push(c);
                }
            }
        }
        // 栈中剩余: ']]]...[[[...'
        // 总数 = 2 * close, close = st.size() / 2
        return (st.size() / 2 + 1) / 2;
    }
};
```

**缺点**：用了 O(n) 额外空间存栈，实际上不需要。

---

### 解法3: 双指针（模拟交换）-- O(n) / O(1)

**思路**：左指针找第一个未匹配的 `]`，右指针找最后一个未匹配的 `[`，交换它们。

```cpp
class Solution {
public:
    int minSwaps(string s) {
        int n = s.size();
        int l = 0, r = n - 1;
        int swaps = 0;
        int open = 0;
        
        while (l < r) {
            // 从左找第一个未匹配的 ']'
            while (l < r) {
                if (s[l] == '[') open++;
                else {
                    if (open > 0) open--;
                    else break;  // 找到未匹配的 ']'
                }
                l++;
            }
            // 从右找第一个未匹配的 '['
            // (简化: 直接从右端找 '[')
            while (l < r && s[r] != '[') r--;
            
            if (l < r) {
                swap(s[l], s[r]);
                swaps++;
                l++;
                r--;
            }
        }
        return swaps;
    }
};
```

**这个思路虽然直觉上正确但实现复杂**，不如贪心计数简洁。面试中不推荐。

## 数学公式推导

```
已知: 字符串有 n/2 个 '[' 和 n/2 个 ']'

Step 1: 贪心消掉已匹配对
  遍历时，每个 ']' 尝试和最近的未匹配 '[' 配对。
  设消掉了 m 对。

Step 2: 剩余分析
  剩余 '[' 数 = n/2 - m
  剩余 ']' 数 = n/2 - m
  设 k = n/2 - m (两者相等)

Step 3: 最优交换
  剩余形如 ']^k [^k'
  每次交换一对 (最左']', 最右'['):
  ']^k [^k' → '[' ']^(k-1)' '[^(k-1)]' ']' 
  这修掉了 2 个未匹配的
  
  偶数 k: 需要 k/2 次
  奇数 k: 需要 (k+1)/2 次 = ceil(k/2)
  
  统一: (k + 1) / 2 (整数除法)
```

## 易错点

1. **`open` 和 `close` 的含义搞混**：
   - `open` = 当前**已存在但未被消掉**的 `[` 的数量
   - `close` = 遇到 `]` 时无法消掉的次数
   - 遍历完后 `open == close`

2. **答案公式写错**：
   ```cpp
   // 错误: close / 2 + close % 2 → 等价于 (close+1)/2 但容易写错
   // 也错误: (close + 1) >> 1 → 对负数不安全 (虽然 close >= 0)
   ```
   **推荐**：`(close + 1) / 2`，最清晰。

3. **栈解法中 size() 的类型**：`st.size()` 是 `size_t`（无符号），`st.size() / 2` 如果 size 为奇数会截断。不过本题保证 size 一定是偶数（close 个 `]` + close 个 `[`）。

4. **忘记处理已经平衡的情况**：`close = 0` 时答案是 0。`(0+1)/2 = 0`，公式自动处理了。

## 面试追问

**Q1（基础）**：为什么消掉已匹配对后，剩余一定是 `]]]...[[[...` 形式？
> 从左到右扫描，每个 `]` 要么被消掉（和左边的 `[` 配对），要么无法消掉（左边没有 `[`）。无法消掉的 `]` 一定在所有未匹配的 `[` 的左边，因为如果右边有 `]`，它会去配左边的 `[`。

**Q2（证明）**：为什么 `ceil(k/2)` 是最优的？能否更少？
> 每次交换最多修掉 2 个未匹配的括号。有 k 对未匹配需要修，至少需要 `ceil(k/2)` 次。上面的贪心策略恰好达到了这个下界。

**Q3（变体）**：如果括号是 `(` 和 `)` 而不是 `[` 和 `]`，有区别吗？
> 没有本质区别，只是换了字符。算法完全一样。

**Q4（进阶）**：如果不是交换任意两个，而是只能相邻交换？
> 那就变成了不同的问题。需要用贪心或BFS计算最少的相邻交换次数，答案会更大。
