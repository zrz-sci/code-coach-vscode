# 877. 石子游戏

## 核心思路

Alice 和 Bob 轮流从两端取石子，Alice 先手。看似需要博弈搜索，但本题有两个层次的解法：(1) **数学解法**：Alice 总是赢（先手必胜），直接返回 true；(2) **区间 DP**：dp[i][j] 表示面对 piles[i..j] 时先手能获得的最大分差，这是通用的博弈 DP 框架。

## 思维链

1. **读完题第一反应** → 这是一个博弈问题，两个玩家都最优决策。经典的 Minimax 博弈。
2. **先想暴力** → 递归搜索所有可能的选择。每一步有两个选择（取左/取右），树的深度是 n，时间 O(2^n)。用记忆化搜索优化到 O(n^2)。
3. **区间 DP** → dp[i][j] = 面对 piles[i..j] 时，当前玩家能获得的"比对手多的分数"。选左：piles[i] - dp[i+1][j]；选右：piles[j] - dp[i][j-1]。取 max。
4. **发现数学规律** → 偶数堆石子，总数为奇数。Alice 可以选择只拿奇数位置的石子或只拿偶数位置的石子（因为偶数个堆，先手可以控制策略）。奇数位和偶数位的和不可能相等（总和为奇数），Alice 选较大的那组就赢了。
5. **面试策略** → 先讲 DP 解法展示算法能力，再提数学解法展示洞察力。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 数学 | 先手必胜，return true | O(1) | O(1) | 加分项（需证明） |
| 区间 DP | dp[i][j] = 先手分差 | O(n^2) | O(n^2) | 首选（通用框架） |
| 记忆化搜索 | 同DP，自顶向下 | O(n^2) | O(n^2) | 等价，看个人习惯 |

## 关键提示

1. **"分差"状态设计**：dp[i][j] 不存"先手总分"而存"先手比后手多的分数"。这样转移时不需要区分是 Alice 还是 Bob 在操作——对当前玩家来说，选左得 piles[i] 但让对手在 [i+1,j] 上先手（对手的分差就是 dp[i+1][j]），所以自己的分差是 piles[i] - dp[i+1][j]。
2. **转移方程**：`dp[i][j] = max(piles[i] - dp[i+1][j], piles[j] - dp[i][j-1])`。取 max 因为当前玩家会选最优的。
3. **基准情况**：`dp[i][i] = piles[i]`（只剩一堆，先手全拿）。
4. **数学证明**：将堆编号为 1,2,...,n（n 为偶数）。奇数堆和偶数堆的总和不同（因为总和为奇数）。Alice 先手，她可以选择始终拿奇数位或偶数位的石子——因为当奇数位在两端时她拿奇数位，之后偶数位就暴露在两端给 Bob；反之亦然。
5. **遍历顺序**：DP 按区间长度从小到大填表。len=1 先填 dp[i][i]，然后 len=2, len=3, ...

## 解法详解

### 解法1: 数学 — O(1) / O(1)

**思考过程**: Alice 先手必胜。

```
证明（直觉版）:
堆: p1, p2, p3, p4, ..., pn  (n为偶数)

把堆分成两组:
  奇数组: p1, p3, p5, ...
  偶数组: p2, p4, p6, ...

两组和不等（总和为奇数）。Alice 可以选择只拿较大组:
  - 如果奇数组较大: Alice 先拿 p1（左端），无论 Bob 拿什么，
    暴露出来的都是奇数组的下一个，Alice 继续拿。
  - 如果偶数组较大: Alice 先拿 pn（右端），同理。

所以 Alice 总是能拿到较大组的所有石子 → Alice 必胜。
```

```cpp
class Solution {
public:
    bool stoneGame(vector<int>& piles) {
        return true; // Alice 先手必胜
    }
};
```

**关键点**: 这个解法虽然代码只有一行，但面试中必须能证明为什么先手必胜。

### 解法2: 区间 DP — O(n^2) / O(n^2)

**通用博弈框架**: dp[i][j] = 面对 piles[i..j] 时，当前先手玩家比后手多得的分数。

```
示例: piles = [5, 3, 4, 5]

dp 表填充 (对角线开始):

len=1: dp[0][0]=5, dp[1][1]=3, dp[2][2]=4, dp[3][3]=5

len=2: dp[0][1] = max(5-3, 3-5) = max(2, -2) = 2
       dp[1][2] = max(3-4, 4-3) = max(-1, 1) = 1
       dp[2][3] = max(4-5, 5-4) = max(-1, 1) = 1

len=3: dp[0][2] = max(5-dp[1][2], 4-dp[0][1]) = max(5-1, 4-2) = max(4, 2) = 4
       dp[1][3] = max(3-dp[2][3], 5-dp[1][2]) = max(3-1, 5-1) = max(2, 4) = 4

len=4: dp[0][3] = max(5-dp[1][3], 5-dp[0][2]) = max(5-4, 5-4) = 1

dp[0][3] = 1 > 0 → Alice 先手多 1 分 → Alice 赢
```

```cpp
class Solution {
public:
    bool stoneGame(vector<int>& piles) {
        int n = piles.size();
        // dp[i][j] = 当前先手面对 piles[i..j] 时能比后手多得的分数
        vector<vector<int>> dp(n, vector<int>(n, 0));
        
        // 基准: 只有一堆时先手全拿
        for (int i = 0; i < n; i++) dp[i][i] = piles[i];
        
        // 按区间长度从小到大填
        for (int len = 2; len <= n; len++) {
            for (int i = 0; i <= n - len; i++) {
                int j = i + len - 1;
                dp[i][j] = max(piles[i] - dp[i+1][j],
                               piles[j] - dp[i][j-1]);
            }
        }
        
        return dp[0][n-1] > 0;
    }
};
```

### 解法3: 区间 DP 空间优化 — O(n^2) / O(n)

```cpp
class Solution {
public:
    bool stoneGame(vector<int>& piles) {
        int n = piles.size();
        vector<int> dp(piles.begin(), piles.end());
        
        for (int len = 2; len <= n; len++) {
            for (int i = 0; i <= n - len; i++) {
                int j = i + len - 1;
                dp[i] = max(piles[i] - dp[i+1], piles[j] - dp[i]);
            }
        }
        return dp[0] > 0;
    }
};
```

## 易错点

1. **转移方程中的减号**：
   - dp[i][j] = max(piles[i] **-** dp[i+1][j], piles[j] **-** dp[i][j-1])
   - 是减号不是加号！因为选了一端后，对手在剩余区间是先手，对手的分差就是你的劣势。

2. **dp 含义混淆**：
   - dp[i][j] 不是"Alice 的总分"，而是"当前先手比后手多的分数"。这个定义让转移方程不需要区分是谁在操作。

3. **遍历顺序错误**：
   - 必须按区间长度从小到大遍历。如果直接用两层 for(i) for(j) 遍历，dp[i+1][j] 可能还没算出来。

4. **数学解法在面试中不够**：
   - 面试官大概率会要求你写出 DP 解法。先说数学结论容易被认为是"背题"而不是"理解算法"。

## 面试追问

**Q1: 为什么 Alice 先手必胜？能严格证明吗？**
> 偶数堆石子分为奇数位和偶数位两组，总和为奇数所以两组和不同。Alice 先手可以选择始终取奇数位或偶数位（通过选取左端或右端来控制给 Bob 暴露哪一组），所以 Alice 一定能拿到较大组，必胜。

**Q2: 如果堆数是奇数怎么办？数学结论还成立吗？**
> 不一定成立了。奇数堆时先手不能保证只拿奇数位或偶数位，必须用 DP 来解。

**Q3: 区间 DP 能否优化空间到 O(n)？**
> 可以。注意到 dp[i][j] 只依赖 dp[i+1][j] 和 dp[i][j-1]，可以用一维数组滚动。具体地，外层按区间长度遍历，内层从左到右更新 dp[i]。

**Q4: 这个区间 DP 框架能解决哪些类似问题？**
> 所有"两人轮流从两端取"的博弈问题，如 Predict the Winner (486)、Stone Game II/III/IV 系列。核心框架完全一样，只是取的规则不同。
