# 7. 整数反转

## 核心思路

这道题本质上是**逐位提取数字并重新组装**，核心难点不在反转本身，而在于**如何在不使用 64 位整数的前提下检测 32 位溢出**。

## 思维链

1. **读完题第一反应** → 把整数转成字符串，反转字符串，再转回整数？可以，但字符串转换要处理符号和前导零，且溢出检测不方便。
2. **更数学的做法** → 用 `x % 10` 提取末位，`x / 10` 去掉末位，逐步构建反转结果 `result = result * 10 + digit`。这是反转数字的经典数学模板。
3. **瓶颈在哪？** → 反转逻辑很简单，但 `result * 10 + digit` 可能溢出 32 位！题目明确说不能用 64 位整数。
4. **怎么在溢出前检测？** → 在做 `result * 10 + digit` **之前**判断：如果 `result > INT_MAX / 10`，必然溢出；如果 `result == INT_MAX / 10`，还要看 `digit > 7`（因为 INT_MAX = 2147483647，末位是 7）。负数同理。
5. **负数怎么处理？** → C++ 中 `%` 对负数取模结果也是负数（如 `-123 % 10 = -3`），所以正负数可以用**完全相同的循环逻辑**，只是溢出判断的边界不同。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 数学逐位反转（提前溢出检测） | 每次取末位，乘10累加，在乘之前判断是否会溢出 | O(log x) | O(1) | ⭐ 必须写出 |
| 字符串反转 | 转字符串→反转→转回整数 | O(log x) | O(log x) | 能说出即可 |
| 用 long long 偷懒检测 | 用 64 位存中间结果，最后检查范围 | O(log x) | O(1) | 违反题意，不推荐 |

## 关键提示

1. **你真的需要处理符号吗？** C++ 的 `%` 和 `/` 对负数的行为：`-123 % 10 = -3`，`-123 / 10 = -12`。这意味着负数可以和正数用同一套逻辑。
2. **溢出检测的时机**：不是在 `result * 10 + digit` 之后检查（已经溢出了，未定义行为！），而是在**做乘法之前**检查。
3. **INT_MAX = 2147483647, INT_MIN = -2147483648**。正数溢出边界的末位是 7，负数是 -8。但实际上，由于输入本身在 int 范围内，反转后末位不可能超过 2（因为输入最高位最大是 2），所以末位检测其实永远不会触发——但面试中必须写出来展示你理解溢出。
4. **为什么 `x = 0` 和末尾有零的情况自动处理了？** `120 % 10 = 0`，第一次循环 `result = 0 * 10 + 0 = 0`，前导零自然消失。

## 解法详解

### 解法1: 数学逐位反转（提前溢出检测） — O(log x) / O(1) ⭐ 面试首选

**思考过程**: 反转一个整数的数字，最自然的数学方法就是不断取末位、累积到新数上。就像你手动反转 321：取 1 → 取 2 → 取 3，拼成 123。关键挑战是溢出检测。

```
反转 x = 123 的过程:
┌────────┬───────┬───────────────────────┬────────┐
│  步骤  │ digit │        计算           │ result │
├────────┼───────┼───────────────────────┼────────┤
│ x=123  │   3   │ 0 * 10 + 3 = 3       │   3    │
│ x=12   │   2   │ 3 * 10 + 2 = 32      │   32   │
│ x=1    │   1   │ 32 * 10 + 1 = 321    │  321   │
│ x=0    │  end  │                       │  321   │
└────────┴───────┴───────────────────────┴────────┘

溢出检测逻辑 (在 result * 10 + digit 之前):
  INT_MAX = 2147483647
  如果 result > 214748364 (即 INT_MAX/10)   → 必溢出, 返回 0
  如果 result == 214748364 且 digit > 7     → 溢出, 返回 0
  负数同理:
  如果 result < -214748364 (即 INT_MIN/10)  → 必溢出, 返回 0
  如果 result == -214748364 且 digit < -8   → 溢出, 返回 0
```

```cpp
class Solution {
public:
    int reverse(int x) {
        int result = 0;
        while (x != 0) {
            int digit = x % 10;  // 负数取模结果也是负数，如 -123%10=-3
            x /= 10;
            
            // 正数溢出检测：result*10+digit > INT_MAX
            // 等价于在乘之前检查 result > INT_MAX/10
            if (result > INT_MAX / 10 || 
                (result == INT_MAX / 10 && digit > 7)) {
                return 0;
            }
            // 负数溢出检测：result*10+digit < INT_MIN
            if (result < INT_MIN / 10 || 
                (result == INT_MIN / 10 && digit < -8)) {
                return 0;
            }
            
            result = result * 10 + digit;
        }
        return result;
    }
};
```

**关键点**:
- 溢出检测必须在 `result * 10 + digit` **之前**做，否则已经是未定义行为
- C++ 中负数 `%` 和 `/` 的行为保证了正负数统一处理

### 解法2: 字符串反转法 — O(log x) / O(log x)

**思考过程**: 最直觉的方法——把数字当字符串处理。但要注意符号和溢出。

```cpp
class Solution {
public:
    int reverse(int x) {
        // 特殊情况：INT_MIN 取绝对值会溢出
        if (x == INT_MIN) return 0;
        
        int sign = (x < 0) ? -1 : 1;
        string s = to_string(abs(x));
        std::reverse(s.begin(), s.end());
        
        // stol 用 long 接收，检测溢出
        // 注意：题目说不能用64位，这里仅作为思路展示
        long val = stol(s);
        if (val > INT_MAX) return 0;
        
        return sign * (int)val;
    }
};
```

**关键点**: 这种方法简单但依赖了 `long`（64位），严格来说违反题目约束。面试中可以提到这种思路，但要主动说明其局限性，然后过渡到解法1。

### 解法3: 用 long long 简化溢出检测 — O(log x) / O(1)

**从解法1简化**: 如果面试官允许用 64 位（或作为过渡理解），可以先用 long long 存中间结果，最后检查范围。

```cpp
class Solution {
public:
    int reverse(int x) {
        long long result = 0;  // 用64位暂存，避免溢出
        while (x != 0) {
            result = result * 10 + x % 10;
            x /= 10;
        }
        // 最后检查是否在32位范围内
        if (result > INT_MAX || result < INT_MIN) return 0;
        return (int)result;
    }
};
```

**关键点**: 代码简洁，但违反"不允许存储64位整数"的约束。面试中写完这个后，面试官一定会追问"如果不能用 long long 呢？"——这时过渡到解法1。

## 解法对比

| | 解法1: 提前溢出检测 | 解法2: 字符串 | 解法3: long long |
|---|---|---|---|
| 时间 | O(log x) | O(log x) | O(log x) |
| 空间 | O(1) | O(log x) | O(1) |
| 符合题意 | ✅ 完全符合 | ❌ 依赖long | ❌ 用了64位 |
| 代码复杂度 | 中等（溢出判断） | 简单 | 最简单 |
| 面试推荐 | ⭐ 首选 | 可作思路铺垫 | 可作中间步骤 |

核心区别：三种方法的反转逻辑完全相同（取末位、累积），唯一区别在于**如何处理溢出**。解法1是唯一完全符合题目约束的方案。

## 易错点

1. **✗ 在乘法之后检测溢出**
   ```cpp
   result = result * 10 + digit;     // ← 已经溢出了！未定义行为！
   if (result > INT_MAX) return 0;   // ← 检测无效
   ```
   **✓ 在乘法之前检测**
   ```cpp
   if (result > INT_MAX / 10) return 0;  // ← 提前拦截
   result = result * 10 + digit;
   ```

2. **✗ 对负数单独取绝对值处理**
   ```cpp
   if (x < 0) x = -x;  // ← 当 x = INT_MIN 时，-x 溢出！
   ```
   **✓ 利用 C++ 负数取模的特性，正负统一处理**，不需要取绝对值。

3. **✗ 只检测正数溢出，忘记负数**
   ```cpp
   if (result > INT_MAX / 10) return 0;  // ← 负数呢？
   ```
   **✓ 正负两个方向都要检查**，虽然实际上 INT_MIN 的末位检测 `digit < -8` 对合法输入永远不会触发（因为输入最高位最多是 -2），但面试中写完整更好。

4. **✗ 循环条件写成 `while (x > 0)`**
   ```cpp
   while (x > 0) { ... }  // ← 负数直接跳过了！
   ```
   **✓ 写成 `while (x != 0)`**，正负数都能处理。

## 面试追问

**Q1: 为什么不能用 `long long`？如果面试官问"假设可以用64位呢"？**
→ 先用 long long 写一版简洁的（解法3），展示你理解核心逻辑。然后主动说"如果不允许用64位"，切换到解法1的提前检测方案。这个过渡本身就展示了你的工程思维。

**Q2: 溢出检测中 `digit > 7` 和 `digit < -8` 这个边界判断真的有可能触发吗？**
→ 不会。因为输入 x 本身在 `[-2^31, 2^31-1]` 范围内，最多10位数字，最高位只能是 1 或 2。反转后这个 1 或 2 变成末位 digit，不可能超过 7。但写出来表示你理解了完整的溢出逻辑，面试中这是加分项。

**Q3: 如果题目改成反转后保留前导零怎么办？比如 100 → "001"？**
→ 如果要保留前导零，返回值就不能是 int 了，需要返回字符串。反转逻辑改为字符串反转，不需要数学方法。这本质上变成了一道字符串题。

**Q4: 如果输入是 64 位整数，反转后也要在 64 位范围内，怎么改？**
→ 同样的思路，把 `INT_MAX` / `INT_MIN` 换成 `LLONG_MAX` / `LLONG_MIN`，溢出检测逻辑完全一样。但不能再用更大的类型了，所以必须用提前检测法。

## 相关题型

- **8. 字符串转换整数 (atoi)** — 复用同样的"提前溢出检测"模板（`result > INT_MAX/10` 的判断逻辑几乎一模一样），区别是输入从数字变成了字符串，需要额外处理空格、符号、非数字字符。
- **9. 回文数** — 可以复用本题的"反转一半数字"技巧：只反转后半部分，和前半部分比较，避免溢出且只需 O(1) 空间。
- **190. 颠倒二进制位** — 同样的"逐位提取并重新组装"思想，从十进制换成二进制，用位运算 (`& 1`, `>> 1`, `<< 1`) 代替 (`% 10`, `/ 10`, `* 10`)。
