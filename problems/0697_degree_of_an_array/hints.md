# 697. Degree of an Array

## 核心思路

本题要求找到与原数组具有相同"度"的最短连续子数组。数组的"度"定义为出现频率最高的元素的频率。核心思路是**哈希表一次遍历**：对每个元素记录其出现次数、首次出现位置和末次出现位置。然后在所有达到最大频率的元素中，选择末次 - 首次位置差最小的那个。

## 思维链

1. "度"= 数组中出现频率最大的元素的频率
2. 子数组要与原数组同度 -> 子数组必须包含某个最高频元素的所有出现
3. 最短这样的子数组 = 从该元素第一次出现到最后一次出现的区间
4. 如果有多个元素达到最高频率，取区间最短的那个
5. 一次遍历即可收集 count、firstIndex、lastIndex 三个信息
6. 时间 O(N)，空间 O(N)

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 三哈希表一次遍历 | O(N) | O(N) | 最优解，一次遍历收集所有信息 |
| 两次遍历 | O(N) | O(N) | 先统计频率找度，再找最短区间 |
| 滑动窗口（非最优） | O(N * K) | O(N) | 对每个最高频元素做窗口，K=最高频元素数 |

## 关键提示

1. **三个哈希表**：count 记录频率，first 记录首次出现位置，last 记录末次出现位置。实际上 first 只需在元素第一次出现时记录，后续不更新；last 每次都更新。
2. **同时追踪度和最短长度**：可以在遍历过程中同时维护最大频率 maxFreq 和对应的最短区间长度 minLen，避免第二次遍历。
3. **区间长度计算**：last[x] - first[x] + 1 即为包含元素 x 所有出现的最短子数组长度。
4. **度相同时取更短**：如果多个元素频率相同（都等于度），选择区间最短的。如果频率更大，则直接更新。

## 解法详解

### 解法一：三哈希表一次遍历（推荐）

**思路**：
用三个哈希表分别记录每个元素的频率、首次出现位置、末次出现位置。遍历数组时同步更新这些信息，并动态维护最大频率和最短长度。

**步骤**：
1. 遍历数组 nums，对于 nums[i]：
   - count[nums[i]]++
   - 如果是首次出现，记录 first[nums[i]] = i
   - 更新 last[nums[i]] = i
2. 检查 count[nums[i]] 与当前 maxFreq 的关系：
   - 如果 count > maxFreq：更新 maxFreq，minLen = last - first + 1
   - 如果 count == maxFreq：minLen = min(minLen, last - first + 1)
3. 返回 minLen

**复杂度**：时间 O(N)，空间 O(N)

### 解法二：分两步走

**步骤**：
1. 第一遍遍历：统计每个元素的频率，找出最大频率（度）
2. 第二遍遍历或使用哈希表：对所有达到最大频率的元素，计算 last - first + 1，取最小值

**复杂度**：时间 O(N)，空间 O(N)

### 解法三：结构体合并

**思路**：
用一个 unordered_map<int, tuple<int,int,int>> 把 count、first、last 合并到一个映射中，减少哈希表数量。

**步骤**：
1. 遍历时维护 map[nums[i]] = {count, first, last}
2. 遍历完后扫描 map，找度最大且区间最短的

## 易错点

1. **长度计算 off-by-one**：最短子数组长度是 last - first + 1，不是 last - first。这是包含两端的区间长度。
2. **忘记处理多个元素同度**：如果 1 和 2 都出现了 3 次，需要比较两者的区间长度，取更短的。
3. **误以为度只有一个元素**：可能有多个元素都达到最大频率，必须全部检查。
4. **first 被覆盖**：首次出现位置只能在元素第一次出现时记录，后续出现不能覆盖。要用 `if (first.find(x) == first.end()) first[x] = i;` 或等价逻辑。
5. **空数组处理**：题目保证 nums 非空，但编码时仍需注意初始化 minLen 不能为 0。

## 面试追问

1. **能否只用一个哈希表完成？**
   - 可以，将 count、first、last 打包为结构体或 tuple，存入一个 map。但本质上还是存了三个信息。

2. **如果数组是流式输入（不知道总长度），怎么处理？**
   - 一次遍历解法天然支持流式处理。每读入一个元素就更新 count 和 last，并检查是否需要更新答案。

3. **如果要求返回最短子数组本身而不只是长度？**
   - 在更新 minLen 时同时记录对应的 first 和 last 值，最后返回 nums[first..last]。

4. **如果数组可以有负数怎么办？**
   - 解法完全不变，哈希表的 key 支持负数。

5. **时间复杂度能否低于 O(N)？**
   - 不能，因为必须读取每个元素才能确定度。
