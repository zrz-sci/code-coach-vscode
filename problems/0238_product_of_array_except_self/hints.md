# 238. 除了自身以外数组的乘积

## 核心思路

**本质上是在问：** 对于每个位置 i，如何高效地计算它左边所有元素的乘积 × 右边所有元素的乘积？这就是"前缀积"和"后缀积"的思想——与前缀和类似，只不过把加法换成了乘法。

## 思维链

1. **读完题第一反应**：最简单的办法——对每个位置 i，遍历数组把除了 `nums[i]` 以外的元素乘起来。O(n²)，能 work 但太慢。

2. **能不能用除法？** 先算全部乘积 total，然后 `answer[i] = total / nums[i]`？题目明确说**不允许用除法**，而且如果有 0 会出问题。此路不通。

3. **暴力的瓶颈在哪？** 对于每个 i，都在重新算一遍乘积，大量重复计算。能不能把乘积"预处理"好，查询时直接用？

4. **关键洞察：拆分！** `answer[i] = (nums[0] × ... × nums[i-1]) × (nums[i+1] × ... × nums[n-1])`，也就是**左边的乘积 × 右边的乘积**。左边的乘积可以从左往右累乘得到，右边的乘积可以从右往左累乘得到。

5. **两趟扫描**：第一趟从左到右，算出每个位置的"前缀积"；第二趟从右到左，算出每个位置的"后缀积"。两者相乘就是答案。O(n) 时间，O(n) 空间。

6. **进阶优化**：第一趟结果直接存进 answer 数组（前缀积），第二趟用一个滚动变量 `suffix` 从右到左累乘，边乘边更新 answer。空间从 O(n) 降到 O(1)（answer 数组不算额外空间）。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力 | 对每个 i，遍历其他所有元素求积 | O(n²) | O(1) | 能说出即可 |
| 前缀积 + 后缀积（两个数组） | 预处理左右两个乘积数组 | O(n) | O(n) | ⭐ 必须写出 |
| 前缀积 + 滚动变量（空间优化） | 用 answer 存前缀积，滚动变量存后缀积 | O(n) | O(1) | 加分项（Follow-up） |

## 关键提示

1. **拆分思想**：`answer[i]` 可以拆成"i 左边所有元素的乘积" 和 "i 右边所有元素的乘积" 两部分，分别预处理。

2. **前缀积类比前缀和**：前缀和是 `prefix[i] = prefix[i-1] + nums[i]`，前缀积就是 `prefix[i] = prefix[i-1] * nums[i]`。区别是乘法的"空元素"基准值是 1 而不是 0。

3. **空间优化关键**：第二趟扫描时不需要真正存一个后缀积数组，用一个变量 `suffix` 滚动累乘就够了，因为我们是从右到左顺序访问的。

4. **含 0 的情况**：不需要特殊处理！前缀积和后缀积的方式天然正确处理了 0 的情况。

5. 可视化示例 `nums = [1, 2, 3, 4]`：

```
索引:          0    1    2    3
nums:         [1,   2,   3,   4]

前缀积 L[i] = nums[0..i-1] 的乘积:
              [1,   1,   2,   6]
               ↑    ↑    ↑    ↑
              空   1   1×2  1×2×3

后缀积 R[i] = nums[i+1..n-1] 的乘积:
              [24,  12,  4,   1]
               ↑    ↑    ↑    ↑
             2×3×4 3×4   4   空

answer[i] = L[i] × R[i]:
              [24,  12,  8,   6]
```

## 解法详解

### 解法1: 暴力 — O(n²) / O(1)

**思考过程**：最朴素——对每个位置 i，遍历整个数组，跳过 i，把其余元素乘起来。

```cpp
class Solution {
public:
    vector<int> productExceptSelf(vector<int>& nums) {
        int n = nums.size();
        vector<int> answer(n, 1);
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                if (j != i) {
                    answer[i] *= nums[j];
                }
            }
        }
        return answer;
    }
};
```

**关键点**：
- O(n²) 在 n = 10⁵ 时会超时（10¹⁰ 次操作）。
- 大量重复计算——`answer[0]` 和 `answer[1]` 的计算中，大部分乘法是重叠的。

### 解法2: 前缀积 + 后缀积（两个数组） — O(n) / O(n) ⭐ 面试首选

**从解法1优化**：暴力的瓶颈是对每个位置重复计算乘积。我们把 `answer[i]` 拆成"左边的积 × 右边的积"，各只算一次。

```cpp
class Solution {
public:
    vector<int> productExceptSelf(vector<int>& nums) {
        int n = nums.size();
        vector<int> L(n), R(n), answer(n);
        
        // L[i] = nums[0] * nums[1] * ... * nums[i-1]
        // 即 i 左边所有元素的乘积，L[0] = 1（左边没有元素）
        L[0] = 1;
        for (int i = 1; i < n; i++) {
            L[i] = L[i - 1] * nums[i - 1];
        }
        
        // R[i] = nums[i+1] * nums[i+2] * ... * nums[n-1]
        // 即 i 右边所有元素的乘积，R[n-1] = 1（右边没有元素）
        R[n - 1] = 1;
        for (int i = n - 2; i >= 0; i--) {
            R[i] = R[i + 1] * nums[i + 1];
        }
        
        // answer[i] = 左边的积 × 右边的积
        for (int i = 0; i < n; i++) {
            answer[i] = L[i] * R[i];
        }
        
        return answer;
    }
};
```

**关键点**：
- 边界初始化：`L[0] = 1`（0 左边没有元素，乘积为 1），`R[n-1] = 1`（n-1 右边没有元素，乘积为 1）。
- 这里的 1 是乘法的"单位元"——乘以 1 不改变结果。

### 解法3: 空间优化 — O(n) / O(1)（Follow-up 最优）

**从解法2优化**：解法2用了两个额外数组 L 和 R。观察到：
- L 数组可以直接存到 answer 中（第一趟扫描）。
- R 数组只需要一个滚动变量 `suffix`，从右到左边算边乘到 answer 中。

```cpp
class Solution {
public:
    vector<int> productExceptSelf(vector<int>& nums) {
        int n = nums.size();
        vector<int> answer(n);
        
        // 第一趟：从左到右，answer[i] 存的是 i 左边所有元素的乘积
        answer[0] = 1;
        for (int i = 1; i < n; i++) {
            answer[i] = answer[i - 1] * nums[i - 1];
        }
        
        // 第二趟：从右到左，用 suffix 滚动累乘右边的积
        // 然后 answer[i] *= suffix 就得到最终结果
        int suffix = 1;
        for (int i = n - 1; i >= 0; i--) {
            answer[i] *= suffix;   // answer[i] = 左边积 × 右边积
            suffix *= nums[i];     // 更新 suffix，为下一个位置（i-1）准备
        }
        
        return answer;
    }
};
```

**逐步演示** `nums = [1, 2, 3, 4]`：

```
第一趟（从左到右，存前缀积到 answer）:
  answer[0] = 1
  answer[1] = answer[0] * nums[0] = 1 * 1 = 1
  answer[2] = answer[1] * nums[1] = 1 * 2 = 2
  answer[3] = answer[2] * nums[2] = 2 * 3 = 6
  → answer = [1, 1, 2, 6]

第二趟（从右到左，suffix 滚动累乘）:
  i=3: answer[3] = 6 * suffix(1) = 6,   suffix = 1 * 4 = 4
  i=2: answer[2] = 2 * suffix(4) = 8,   suffix = 4 * 3 = 12
  i=1: answer[1] = 1 * suffix(12) = 12, suffix = 12 * 2 = 24
  i=0: answer[0] = 1 * suffix(24) = 24, suffix = 24 * 1 = 24
  → answer = [24, 12, 8, 6] ✓
```

**关键点**：
- `suffix` 在处理位置 i 时，存的恰好是 `nums[i+1] * nums[i+2] * ... * nums[n-1]`。
- 先用 `suffix` 乘到 `answer[i]`，再更新 `suffix`（顺序不能反！）。

## 解法对比

|  | 暴力 | 前缀积+后缀积 | 空间优化 |
|--|------|--------------|---------|
| 时间 | O(n²) | O(n) | O(n) |
| 额外空间 | O(1) | O(n) — L 和 R 数组 | O(1) — 只用一个变量 |
| 遍历次数 | n² 次 | 3 趟 | 2 趟 |
| 代码复杂度 | 最简单 | 容易理解 | 稍需技巧 |
| 面试推荐 | 只用于说思路 | ⭐ 主力解法 | Follow-up 加分 |

**核心区别**：解法2和3的算法思路完全相同（左积×右积），区别只在于空间使用——解法3把 L 复用为 answer，R 缩减为一个变量。

## 易错点

1. **前缀积初始化用 0 而不是 1**：
   - ✗ `L[0] = 0;` → 所有结果都变成 0
   - ✓ `L[0] = 1;` — 乘法的单位元是 1，不是 0

2. **空间优化版中，第二趟更新顺序颠倒**：
   - ✗ 先 `suffix *= nums[i]`，再 `answer[i] *= suffix` → suffix 包含了 nums[i] 自身
   - ✓ 先 `answer[i] *= suffix`，再 `suffix *= nums[i]` — suffix 必须只包含 i 右边的元素

3. **第一趟前缀积的下标搞错**：
   - ✗ `answer[i] = answer[i-1] * nums[i]` → 前缀积包含了 nums[i] 自身
   - ✓ `answer[i] = answer[i-1] * nums[i-1]` — 前缀积只包含 i 左边的元素（不含 i）

4. **误用除法**：
   - ✗ `total / nums[i]` — 题目禁止用除法，而且 nums[i] = 0 时会除以零
   - ✓ 用前缀积 × 后缀积的方式完全避开除法

## 面试追问

**Q1（基础理解）**：暴力法 O(n²) 的瓶颈是什么？
> 对每个位置 i 都重新遍历整个数组做 n-1 次乘法，总共 n×(n-1) 次。瓶颈是大量重复计算——相邻位置的乘积只差一个元素，却完全重新算。

**Q2（核心优化）**：为什么不能用"总乘积÷自身"？
> 题目禁止使用除法。即使允许，也有两个问题：(1) nums[i]=0 时除以零；(2) 有多个 0 时需要分情况讨论（1个0、2个0以上），逻辑复杂易出错。前缀积×后缀积的方式更干净。

**Q3（Follow-up）**：如何做到 O(1) 额外空间？
> 第一趟把前缀积直接写入 answer 数组，第二趟用一个滚动变量 suffix 从右到左累乘，边乘边更新 answer[i]。answer 数组既当前缀积的存储，又当最终结果的输出。

**Q4（变体）**：如果允许用除法，怎么处理数组中有 0 的情况？
> 统计 0 的个数：(1) 0个：answer[i] = totalProduct / nums[i]；(2) 1个：只有那个 0 的位置有非零结果（等于其余元素的积），其他位置结果都是 0；(3) 2个以上：所有位置结果都是 0。
