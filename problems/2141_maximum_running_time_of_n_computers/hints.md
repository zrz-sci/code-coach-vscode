# 2141. 同时运行 N 台电脑的最长时间

## 核心思路

本质上是一个**二分答案**问题：猜一个运行时间 T，然后判断所有电池的总可用电量能否支撑 n 台电脑同时运行 T 分钟。关键洞察是：每块电池对目标时间 T 的贡献最多为 T（因为一块电池同一时刻只能给一台电脑用）。

## 思维链

1. **读完题第一反应**：电池可以随时换，这意味着电池的电量可以在不同电脑之间"流动"。问题的核心不是"谁用哪块电池"，而是"总电量够不够"。

2. **直觉尝试**：如果我猜一个时间 T，n 台电脑同时运行 T 分钟需要总共 `n * T` 的电量。那是不是只要 `sum(batteries) >= n * T` 就行？——**不完全对**！因为单块电池在 T 时间内最多只能贡献 T 分钟（同一时刻只能插在一台电脑上）。

3. **关键约束**：对于一块电量为 `b` 的电池：
   - 如果 `b >= T`，它最多贡献 T（多余的浪费了，或者说它可以独占一台电脑 T 分钟）
   - 如果 `b < T`，它贡献全部 b（需要和别的电池轮换着用）

4. **可行性判断**：猜时间 T，总可用电量 = `sum(min(b, T) for b in batteries)`，如果 `>= n * T` 则可行。

5. **二分搜索**：答案具有单调性——如果时间 T 可行，那 T-1 也可行。所以可以二分找最大的可行 T。

6. **搜索范围**：下界 1，上界 `sum(batteries) / n`（最理想情况，所有电量均匀分配）。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 二分答案 | 二分时间 T + 贪心验证 | O(m·log(sum/n)) | O(1) | ⭐ 必须写出 |
| 排序+贪心 | 排序后从大到小决定哪些电池独占 | O(m·log m) | O(1) | 加分项 |

其中 m = batteries.length，sum = sum(batteries)。

## 关键提示

1. **电池可以随时换** → 电量可以"共享"。问题的关键不是分配方案，而是总电量是否充足。

2. **单块电池有上限**：一块电池在 T 分钟内最多贡献 T 分钟。想想为什么？因为同一时刻它只能给一台电脑供电。

3. **二分的判断条件**：`sum(min(batteries[i], T)) >= n * T`。这个条件为什么是充分的？（提示：小电池可以轮流填补空缺，就像水流填满容器）

4. **注意溢出**：batteries[i] 最大 10^9，n 最大 10^5，sum 可能达到 10^14，需要用 `long long`。

5. **排序+贪心解法的核心观察**：如果一块电池的电量 >= T，它可以独占一台电脑。从大到小排序，大电池逐个"绑定"电脑，剩余电池的总电量分摊给剩余电脑。

## 解法详解

### 解法1: 二分答案 + 贪心验证 — O(m·log(sum/n)) / O(1) ⭐ 面试首选

**思考过程**：

答案是一个具体的时间值 T，而且 T 越大越难满足，越小越容易满足——这就是经典的**二分答案**模式。

关键在于 `check(T)` 函数怎么写：
- n 台电脑运行 T 分钟，总共需要 `n * T` 分钟的电量
- 每块电池 b 最多贡献 `min(b, T)` 分钟（因为一块电池同一时刻只给一台电脑用）
- 只要总贡献 >= 总需求，就可行

为什么这个贪心判断是**充分**的？直觉上：小电池（< T）可以在不同电脑之间轮换使用，像水一样"流动"填满每台电脑的 T 分钟时间槽。大电池（>= T）绑定一台电脑就够了。可以用数学归纳法严格证明，但面试中给出直觉即可。

```
// 二分搜索空间收缩示例:
// n=2, batteries=[3,3,3], sum=9, 上界=9/2=4
//
// Round1: lo=1, hi=4, mid=2 → 贡献=min(3,2)+min(3,2)+min(3,2)=6 >= 2*2=4 ✓ → lo=3
// Round2: lo=3, hi=4, mid=3 → 贡献=min(3,3)+min(3,3)+min(3,3)=9 >= 2*3=6 ✓ → lo=4
// Round3: lo=4, hi=4, mid=4 → 贡献=min(3,4)+min(3,4)+min(3,4)=9 >= 2*4=8 ✓ → lo=5
// lo > hi → 退出, 答案=4
```

```cpp
class Solution {
public:
    long long maxRunTime(int n, vector<int>& batteries) {
        long long sum = 0;
        for (int b : batteries) sum += b;
        
        long long lo = 1, hi = sum / n;
        while (lo <= hi) {
            long long mid = lo + (hi - lo) / 2;
            // 计算所有电池对目标时间 mid 的总贡献
            long long total = 0;
            for (int b : batteries) {
                total += min((long long)b, mid); // 每块电池最多贡献 mid
            }
            if (total >= (long long)n * mid) {
                lo = mid + 1; // mid 可行，尝试更大的时间
            } else {
                hi = mid - 1; // mid 不可行，缩小时间
            }
        }
        return hi; // hi 是最后一个可行的时间
    }
};
```

**关键点**：
- 二分的上界是 `sum/n` 而不是 `max(batteries)`，因为理论上所有电量平均分配时达到上限
- `total` 必须用 `long long`，否则累加过程会溢出
- 返回 `hi`（最后一个使 check 成功的值）

### 解法2: 排序 + 贪心 — O(m·log m) / O(1)

**从另一个角度思考**：

先把电池从大到小排序。考虑最大的电池：
- 如果它的电量足够"独占"一台电脑（即 >= 当前目标时间 T），那就让它绑定一台电脑，问题规模从 n 台变成 n-1 台
- 剩下的电池总电量分摊给剩余电脑

具体做法：从大到小排序后，扫描电池。假设还剩 k 台电脑需要分配：
- 如果当前电池电量 `batteries[i] > remaining_sum / k`，说明它电量太大，多余部分浪费了，它独占一台电脑，k 减 1
- 否则，剩下所有电池（包括当前这块）的总电量均匀分给 k 台电脑，答案就是 `remaining_sum / k`

```cpp
class Solution {
public:
    long long maxRunTime(int n, vector<int>& batteries) {
        sort(batteries.begin(), batteries.end());
        
        long long sum = 0;
        for (int b : batteries) sum += b;
        
        int m = batteries.size();
        // 从最大的电池开始看
        // 如果最大电池 > 平均值，它独占一台电脑
        for (int i = m - 1; i >= 0; i--) {
            if (batteries[i] > sum / n) {
                // 这块电池独占一台电脑，只用 sum/n 的电量（但实际上我们
                // 是减少一台电脑和这块电池的全部电量）
                sum -= batteries[i];
                n--;
            } else {
                // 从这块电池开始，所有电池都 <= 平均值
                // 它们可以完美地填满 n 台电脑
                break;
            }
        }
        return sum / n;
    }
};
```

**为什么这样是对的？**

关键洞察：如果一块电池的电量 > `sum/n`（当前平均值），那它的电量超过了目标运行时间，多余部分不可能被利用（一块电池同一时刻只给一台电脑）。所以它只能独占一台电脑，用掉目标时间 T 的电量。

但我们不知道 T 是多少！技巧在于：我们不需要知道 T，只需要知道"谁超过了平均值"。超过平均值的电池独占电脑后，剩余电池的平均值自然就是答案。

## 解法对比

| | 二分答案 | 排序+贪心 |
|---|---|---|
| 时间复杂度 | O(m·log(sum/n)) | O(m·log m) |
| 空间复杂度 | O(1) | O(1)（原地排序）|
| 思维难度 | 中（二分模板+贡献上限） | 高（需要证明贪心正确性） |
| 面试推荐 | ⭐ 首选，容易解释 | 加分项，更优雅 |
| 适用场景 | "最大化最小值"/"最小化最大值"类问题通用 | 本题特有的结构 |

二分答案的思维模式更通用（"猜答案+验证"），面试中更容易想到和解释。排序+贪心更巧妙但需要更强的直觉。

## 易错点

1. **溢出问题**：
   - ✗ `int total = 0; for(int b : batteries) total += min(b, (int)mid);` → 累加溢出
   - ✓ `long long total = 0; ... total += min((long long)b, mid);`
   - batteries 总和可达 10^5 × 10^9 = 10^14，远超 int 范围

2. **二分上界设错**：
   - ✗ `hi = *max_element(batteries.begin(), batteries.end())` → 上界太小！多块电池可以轮换，总时间可能超过单块最大值
   - ✓ `hi = sum / n` → 所有电量均匀分配的理论上限

3. **贪心解法中的整数除法**：
   - `sum / n` 向下取整是正确的，因为时间是整数分钟
   - 但要确保 `n` 不会减到 0（题目保证 n >= 1 且 batteries.length >= n）

4. **二分答案 lo/hi 返回值搞混**：
   - 使用 `lo <= hi` 模板时，循环结束后 `hi` 是最后一个满足条件的值
   - ✗ 返回 `lo` → 这是第一个不满足条件的值
   - ✓ 返回 `hi`

## 面试追问

**Q1: 为什么 `min(b, T)` 的总和 >= n*T 就一定能实现？（证明充分性）**

> 直觉：把 n 台电脑运行 T 分钟想象成 n×T 的网格。大电池（>= T）填满一整列（一台电脑）。小电池（< T）的总电量可以像水一样"流动"填满剩余空位。因为小电池每块 < T，所以可以在不同电脑之间切换而不违反"同一时刻一块电池只给一台电脑"的约束。严格证明可以用构造法：按时间片轮流分配小电池。

**Q2: 如果电池不能在使用过程中切换（一旦插入就不能拔出），答案会变成什么？**

> 这变成了一个完全不同的问题：每台电脑选一块电池，运行时间取决于所选 n 块电池中的最小值。排序后选最大的 n 块，答案就是其中最小的那块。（变成了简单的排序+选择问题）

**Q3: 如果要求返回具体的分配方案（哪个时刻哪块电池给哪台电脑），怎么做？**

> 先用二分得到最优时间 T。然后构造方案：大电池（>= T）各绑定一台电脑。小电池按轮转方式分配给剩余电脑——按时间片（每分钟）依次轮换。这是一个构造问题，关键是证明小电池可以无冲突地轮换。
