# 83. 删除排序链表中的重复元素

## 核心思路

链表已经**有序**，相同值的节点一定相邻。只需要遍历一遍，遇到当前节点和下一个节点值相同时，跳过下一个节点即可。

## 思维链

1. **读完题第一反应**：链表是有序的，所以重复元素一定是连续挨在一起的——不需要哈希表记录"见没见过"。
2. **最朴素的做法**：遍历链表，逐个比较当前节点和下一个节点。如果值相同，删掉下一个节点；如果不同，指针前进。
3. **有没有更优的？** 本题已经是 O(n) 了，没有比遍历一次更快的方法。但我们可以换一种"视角"——递归：把问题分解为"处理好后面的链表，再看头节点是否重复"。
4. **总结**：这道题的核心不在优化复杂度，而在于**正确处理指针操作**——什么时候移动 `curr`、什么时候只修改 `next`。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 迭代（单指针） | 逐个比较当前和下一个，相同则跳过 | O(n) | O(1) | ⭐ 必须写出 |
| 递归 | 递归处理子链表，回来判断头节点是否重复 | O(n) | O(n) 栈 | 能说出即可 |

## 关键提示

1. **链表有序是最大的线索**：重复值一定相邻，不需要额外数据结构记录"是否出现过"。
2. **删除 vs 移动指针**：当 `curr->val == curr->next->val` 时，不要移动 `curr`，而是让 `curr->next = curr->next->next` 跳过重复节点。因为新的 `next` 可能还是重复的！
3. **什么时候才移动 curr？** 只有确认 `curr->val != curr->next->val` 时，才 `curr = curr->next`。
4. **头节点会被删除吗？** 不会——我们保留每组重复元素的**第一个**，所以头节点一定保留，不需要 dummy 节点。

```
// 示例: 1→1→2→3→3→NULL
//
// Step1: curr=1, next=1, 值相同 → 跳过: 1→2→3→3→NULL, curr仍在1
// Step2: curr=1, next=2, 值不同 → 前进: curr移到2
// Step3: curr=2, next=3, 值不同 → 前进: curr移到3
// Step4: curr=3, next=3, 值相同 → 跳过: 1→2→3→NULL, curr仍在3
// Step5: curr=3, next=NULL → 结束
//
// 结果: 1→2→3→NULL
```

## 解法详解

### 解法1: 迭代（单指针）— O(n) / O(1) ⭐ 面试首选

**思考过程**：链表有序 → 重复元素连续 → 一个指针从头走到尾，遇到重复就"跳线"。关键是：**跳线后不移动指针**（因为新的 next 可能还重复），只有不重复时才前进。

```cpp
class Solution {
public:
    ListNode* deleteDuplicates(ListNode* head) {
        ListNode* curr = head;
        while (curr && curr->next) {
            if (curr->val == curr->next->val) {
                // 跳过重复节点，但 curr 不动（新 next 可能还重复）
                curr->next = curr->next->next;
            } else {
                // 值不同才前进
                curr = curr->next;
            }
        }
        return head;
    }
};
```

**关键点**：`if` 分支中 curr 不前进，`else` 分支中才前进。很多人写成不论是否删除都 `curr = curr->next`，导致漏删。

### 解法2: 递归 — O(n) / O(n)

**思考过程**：链表天然适合递归——"如果后面的子链表已经去重了，我只需要看头节点和子链表的头是否重复"。

```cpp
class Solution {
public:
    ListNode* deleteDuplicates(ListNode* head) {
        // 终止条件：空链表或只有一个节点，不可能重复
        if (!head || !head->next) return head;
        
        // 递归处理后面的链表（已去重）
        head->next = deleteDuplicates(head->next);
        
        // 当前头节点和去重后的下一个节点值相同 → 跳过自己
        // 值不同 → 保留自己
        return (head->val == head->next->val) ? head->next : head;
    }
};
```

**关键点**：递归返回的是"去重后子链表的头"。如果当前节点和它重复，就返回子链表的头（跳过当前节点）。

```
// 递归展开过程 (1→1→2):
//   deleteDup(1→1→2)
//     head->next = deleteDup(1→2)
//       head->next = deleteDup(2)
//         head->next = deleteDup(NULL)
//           return NULL          ← 终止
//         2->next = NULL, 2≠NULL's val → return 2
//       1->next = 2, 1≠2 → return 1→2
//     1->next = 1→2, 1==1 → return 1→2 (跳过当前的1)
//   结果: 1→2
```

## 解法对比

| | 迭代 | 递归 |
|---|---|---|
| 时间 | O(n) | O(n) |
| 空间 | O(1) | O(n) 递归栈 |
| 代码量 | 更短 | 更优雅 |
| 面试推荐 | ⭐ 首选 | 展示递归思维 |
| 适用场景 | 链表很长时不会栈溢出 | 链表短时代码简洁 |

**面试建议**：先写迭代解法，如果面试官问"能否用递归实现"，再给出递归版本。

## 易错点

1. **删除后仍移动指针，导致漏删连续重复**：
   - ✗ `curr->next = curr->next->next; curr = curr->next;` — 如果有 1→1→1，跳过一个1后 curr 就跑到第三个1了，第二和第三个1的重复没处理
   - ✓ 删除后 curr 不动，循环再次检查新的 `curr->next`

2. **忘记判断 `curr->next` 是否为空**：
   - ✗ `while (curr)` 然后直接访问 `curr->next->val` — 当 curr 是最后一个节点时 NPE
   - ✓ `while (curr && curr->next)` 保证 `curr->next` 存在

3. **认为需要 dummy 节点**：
   - 本题保留第一个出现的元素，头节点永远保留，不需要 dummy
   - 对比 LeetCode 82（删除所有重复节点），那道题头节点可能被删，才需要 dummy

## 面试追问

**Q1: 这道题需要 dummy 节点吗？为什么？**
不需要。因为我们保留每组重复的第一个节点，头节点一定被保留。只有当头节点本身可能被删除时（如第 82 题）才需要 dummy。

**Q2: 如果要求删除所有出现过重复的节点（一个都不保留），怎么改？**
这就是 LeetCode 82。需要 dummy 节点（头可能被删），并且用 `prev` 指针记录"上一个确认不重复的节点"。当发现重复时，`prev->next` 直接跳过整组重复节点。

**Q3: 如果链表无序呢？**
方法一：先排序（归并排序 O(n log n)），再用本题方法。
方法二：用哈希表记录出现过的值，一次遍历去重，时间 O(n)、空间 O(n)。

**Q4: 内存泄漏怎么处理？**
在 C++ 中，被跳过的节点没有 `delete`，会造成内存泄漏。面试中可以加 `ListNode* toDelete = curr->next; curr->next = toDelete->next; delete toDelete;`。
