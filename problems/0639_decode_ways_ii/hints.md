# 639. Decode Ways II

## 核心思路

在经典 Decode Ways（LC 91）基础上引入通配符 `'*'`（代表 1-9 中的任意数字）。使用**线性 DP**，状态 `dp[i]` 表示前 i 个字符的解码方案数。关键在于分类讨论当前字符和前一个字符的所有组合（数字/数字、数字/\*、\*/数字、\*/\*），精确计算单字符解码和双字符解码的贡献。

## 思维链

1. **回顾 LC 91**：dp[i] = dp[i-1] (单字符解码) + dp[i-2] (双字符解码)
2. **引入通配符**：`'*'` 代表 1-9，需要枚举它可能代表的每个值，累加贡献
3. **单字符贡献 ways1(c)**：
   - c 是数字 0：不能单独解码，贡献 0
   - c 是数字 1-9：贡献 1
   - c 是 `'*'`：代表 1-9，贡献 9
4. **双字符贡献 ways2(c1, c2)**：两字符组成 10-26 的方案数
   - 需要分类讨论所有 (c1, c2) 组合
5. **状态转移**：`dp[i] = ways1(s[i]) * dp[i-1] + ways2(s[i-1], s[i]) * dp[i-2]`
6. **空间优化**：只需 dp[i-1] 和 dp[i-2]

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 推荐度 |
|------|-----------|-----------|--------|
| 线性 DP + 空间优化 | O(n) | O(1) | ⭐⭐⭐⭐⭐ |
| 线性 DP 数组 | O(n) | O(n) | ⭐⭐⭐⭐ |

## 关键提示

1. **ways2 的分类讨论是核心难点**，共 9 种情况（3x3: 数字1/数字2/\* x 数字/0/\*）
2. **`'*'` 不包含 0**：这是与一般通配符的关键区别
3. **取模时机**：每步乘法/加法后立即取模，避免 long long 溢出
4. **边界处理**：s[0] 为 '0' 时直接返回 0；s[0] 为 '*' 时 dp[0] = 9
5. **双字符组合表**（最重要的记忆点）：

| c1 \ c2 | 0 | 1-6 | 7-9 | * |
|---------|---|-----|-----|---|
| 1 | 1 (10) | 1 (11-16) | 1 (17-19) | 9 (11-19) |
| 2 | 1 (20) | 1 (21-26) | 0 | 6 (21-26) |
| 3-9 | 0 | 0 | 0 | 0 |
| * | 2 (10,20) | 2 (1x,2x) | 1 (仅1x) | 15 (11-19 + 21-26) |

## 解法详解

### 解法一：线性 DP + 空间优化（推荐）

**核心函数**：

**ways1(c)** - 单字符解码方案数：
- c == '0' -> 0 （0不能单独解码）
- c == '*' -> 9 （代表1-9）
- c 是 '1'-'9' -> 1

**ways2(c1, c2)** - 双字符解码方案数（组成 10-26）：
- c1=='1', c2=='*' -> 9 （11-19都合法）
- c1=='2', c2=='*' -> 6 （21-26合法）
- c1=='*', c2=='*' -> 15 （11-19有9种 + 21-26有6种）
- c1=='*', c2是数字 -> 看c2:
  - c2 in '0'-'6' -> 2（1x和2x都合法）
  - c2 in '7'-'9' -> 1（只有1x合法）
- c1是数字, c2是数字 -> 看组合值是否在10-26
- c1=='0' 或 c1>='3' -> 0

**转移方程**：
```
dp[i] = ways1(s[i]) * dp[i-1] + ways2(s[i-1], s[i]) * dp[i-2]
```

**时间 O(n)，空间 O(1)**

### 解法二：DP 数组

与解法一逻辑完全相同，只是用 `dp[]` 数组存储所有状态。
优点是代码更直观，方便调试。

**时间 O(n)，空间 O(n)**

## 易错点

1. **`'*'` 不代表 0**：这是最常见的错误！`'*'` 只能是 1-9，如果误认为包含 0，ways1 和 ways2 的计算全部出错
2. **双字符分类遗漏**：9 种 (c1, c2) 组合必须全部覆盖，漏掉任何一种都会 WA
3. **`'*'` + `'*'` 的双字符方案数是 15 不是 81**：只有 11-19(9种) 和 21-26(6种) 共 15 种合法双字符
4. **取模遗漏**：字符串长度可达 10^5，不取模会溢出
5. **前导零处理**：`s = "0..."` 应该返回 0
6. **ways2 中 c1='*', c2='0' 的情况**：答案是 2（代表 10 和 20）
7. **乘法溢出**：`ways2 * dp[i-2]` 中 ways2 最大为 15，dp[i-2] 可达 10^9，乘积可达 1.5 * 10^10，需要 long long

## 面试追问

**Q1: 请列出 ways2 的完整分类讨论表。**

```
ways2(c1, c2):
  c1 == '*' && c2 == '*' -> 15  (11-19: 9种, 21-26: 6种)
  c1 == '*' && c2 == '0' -> 2   (10, 20)
  c1 == '*' && '1' <= c2 <= '6' -> 2  (1x, 2x 都合法)
  c1 == '*' && '7' <= c2 <= '9' -> 1  (仅 1x 合法)
  c1 == '1' && c2 == '*' -> 9   (11-19)
  c1 == '2' && c2 == '*' -> 6   (21-26)
  c1 >= '3' && c2 == '*' -> 0
  c1 == '0' -> 0  (0x 不是合法编码)
  否则: 10*digit(c1) + digit(c2) 在 [10,26] 内 -> 1, 否则 -> 0
```

**Q2: 如果 `'*'` 还可以代表 0（即 0-9），转移方程如何修改？**

- ways1('*') 变为 9（0 不能单独解码，所以还是 9）
- ways2 的变化：
  - `'*'` + `'*'`：10-19(10种) + 20-26(7种) = 17
  - `'1'` + `'*'`：10-19 = 10
  - `'2'` + `'*'`：20-26 = 7
  - `'*'` + 数字d：看 1d 和 2d 是否在 10-26 范围内（与之前相同）
  - `'*'` + `'0'`：10, 20 = 2（不变，因为 00 不合法）

关键影响在双 `'*'` 的情况多了 10, 20（因为第二个 * 可以是 0 了）。

**Q3: 能否用矩阵快速幂优化到 O(log n)？**

理论上，如果所有字符都是 `'*'`（或都是同一种字符），转移矩阵是固定的，可以用矩阵快速幂。但本题字符串中的字符各不相同，每步的转移系数 (ways1, ways2) 都可能不同，矩阵快速幂不适用。O(n) 已经是最优时间复杂度。
