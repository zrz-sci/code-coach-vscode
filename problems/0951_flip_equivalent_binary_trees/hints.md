# 951. Flip Equivalent Binary Trees

## 核心思路

判断两棵二叉树是否"翻转等价"——即通过任意次交换某节点的左右子树，能否使两棵树相同。核心方法是**递归比较**：对于两个节点，如果值相同，那么它们的子树要么直接匹配（左对左、右对右），要么交叉匹配（左对右、右对左）。递归地检查这两种情况中是否有一种成立即可。这是一个经典的树形递归判断问题，每个节点最多被访问常数次。

## 思维链

1. **Base case 分析**：两个节点都为 null 则等价；只有一个为 null 则不等价
2. **值比较**：两个节点都非 null 但值不同，则不等价
3. **递归拆解**：值相同时，子树有两种可能的对应关系
4. **不翻转情况**：左对左且右对右 —— `flip(r1->left, r2->left) && flip(r1->right, r2->right)`
5. **翻转情况**：左对右且右对左 —— `flip(r1->left, r2->right) && flip(r1->right, r2->left)`
6. **任一成立即可**：两种情况取 OR

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 递归DFS | O(n) | O(h) | 最直观，代码最简洁 |
| 迭代BFS（规范化） | O(n) | O(n) | 将两棵树规范化后逐层比较 |
| 序列化比较 | O(n) | O(n) | 规范化序列化后字符串比较 |

## 关键提示

1. **两种对应关系取 OR**：不需要确定哪些节点翻转了，只要递归检查两种可能
2. **递归终止条件要完整**：null-null、null-非null、非null-null、值不等四种情况
3. **与"相同树"的区别**：LC 100 只检查"不翻转"情况，本题多了"翻转"分支
4. **与"对称树"的区别**：LC 101 固定检查镜像关系，本题是可选翻转
5. **节点值唯一**：题目保证值唯一，所以值相同就代表是"同一个"节点

## 解法详解

### 解法一：递归DFS（推荐）

**思路**：自顶向下递归。对每对节点，先处理 base case，然后检查值是否相同，最后递归检查子树是否在"不翻转"或"翻转"的情况下等价。

**步骤**：
1. 如果 root1 和 root2 都为 null，返回 true
2. 如果只有一个为 null，或者两者的值不同，返回 false
3. 递归检查两种情况：
   - 不翻转：`flipEquiv(root1->left, root2->left) && flipEquiv(root1->right, root2->right)`
   - 翻转：`flipEquiv(root1->left, root2->right) && flipEquiv(root1->right, root2->left)`
4. 返回两种情况的 OR

**复杂度分析**：
- 时间 O(n)：每个节点最多被访问常数次。虽然看似有两个递归分支可能导致指数，但由于节点值唯一且匹配是确定性的，实际每个节点只走一条有效路径。
- 空间 O(h)：递归栈深度等于树高，最坏 O(n)。

### 解法二：规范化后比较

**思路**：对两棵树各自进行"规范化"——对每个节点，如果左子节点的值大于右子节点的值，就交换左右子树。规范化后，两棵翻转等价的树会变成完全相同的树，直接用"相同树判断"（LC 100）即可。

**步骤**：
1. 对 root1 递归规范化：若 left->val > right->val，swap(left, right)
2. 对 root2 递归规范化
3. 用标准的 isSameTree 比较两棵规范化后的树

**复杂度**：时间 O(n)，空间 O(h)（递归栈）。

## 易错点

1. **忘记处理一个为 null 的情况**：只判断了"都为 null"和"值不等"，遗漏了一 null 一非 null
2. **递归分支写错**：翻转情况是 left-right 和 right-left 交叉，不是 left-left 和 right-right 都翻转
3. **误认为复杂度是指数级**：实际上每层递归中，只有一条分支能真正匹配（因为值唯一），所以是线性的
4. **规范化时忘记处理 null 子节点**：比较 left->val 和 right->val 前要检查是否为 null
5. **混淆对称树和翻转等价**：对称树是固定镜像，翻转等价是每个节点可独立选择是否翻转

## 面试追问

1. **Q: 如何证明时间复杂度是 O(n) 而不是 O(n^2) 或指数级？**
   A: 因为节点值唯一，在值匹配后，子树的对应关系最多有两种可能。一旦某个分支返回 false，另一个分支才会被尝试。总的比较次数与节点数成正比。更严格地说，每个节点对最多被比较 O(1) 次。

2. **Q: 如果节点值不唯一，算法还正确吗？复杂度会变吗？**
   A: 算法逻辑仍然正确，但复杂度可能退化。最坏情况下，每层都有两种匹配可能，复杂度变为 O(2^h)。可以用记忆化优化。

3. **Q: 能否用迭代方式实现？**
   A: 可以用栈或队列模拟递归。每次从栈中取出一对节点，检查后将子节点对按"不翻转"或"翻转"方式压入栈中。

4. **Q: 这个思想在哪些实际场景中有应用？**
   A: 分子结构匹配（手性分子）、电路等价判断、XML/JSON 结构比较（属性顺序不定）等。
