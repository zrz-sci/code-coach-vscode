# 207. 课程表

## 核心思路

这道题本质上是：**给定一个有向图，判断图中是否存在环。** 课程是节点，先修关系是有向边，如果有环就意味着存在循环依赖，不可能完成所有课程。

## 思维链

1. **读完题第一反应**：课程之间有先后关系，这就是一个依赖关系。把每门课看作节点，先修关系 `[a, b]` 表示 `b → a`（先修 b 才能学 a），构成一个有向图。

2. **什么情况下不能完成？** 当存在循环依赖时。比如 A 依赖 B，B 依赖 A，谁都没法先学。这就是有向图中的「环」！

3. **所以问题转化为**：有向图是否有环？这是经典的图论问题，有两种标准方法：
   - **BFS（Kahn 算法 / 拓扑排序）**：不断移除入度为 0 的节点，如果最终所有节点都被移除，说明无环。
   - **DFS（三色标记法）**：通过 DFS 遍历，标记节点状态（未访问/访问中/已完成），如果遇到"访问中"的节点，说明有环。

4. **BFS 思路**：先统计每个节点的入度，入度为 0 的节点没有前置依赖可以直接学。学完后把它指向的节点入度减 1，如果减到 0 就加入队列。最后看是否所有课程都学了。

5. **DFS 思路**：对每个节点做 DFS，用三种颜色区分状态——白色（未访问）、灰色（正在当前 DFS 路径上）、黑色（已处理完毕）。DFS 中遇到灰色节点 = 遇到了回边 = 有环。

6. **直觉验证**：拓扑排序能排完 = 无环 = 能完成所有课程。这两种方法一个从"能学什么"出发（BFS），一个从"是否有环"出发（DFS），殊途同归。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| BFS 拓扑排序 (Kahn) | 不断删除入度为 0 的节点 | O(V+E) | O(V+E) | ⭐ 必须写出 |
| DFS 三色标记 | 检测有向图中的环 | O(V+E) | O(V+E) | ⭐ 必须写出 |

> V = numCourses（节点数），E = prerequisites.length（边数）

## 关键提示

1. **建图方向想清楚**：`[a, b]` 表示 b 是 a 的先修，边是 `b → a`。BFS 中入度加在 `a` 上（a 被依赖），DFS 中从 `b` 出发能到达 `a`。

2. **BFS 核心直觉**：入度为 0 = 没有前置依赖 = 可以直接学。学完一门课就"解锁"它后续的课程（入度减 1）。

3. **DFS 为什么要三种状态？** 仅用 visited（是否访问过）不够！因为在有向图中，从不同路径到达同一节点不代表有环。只有在 **当前递归路径** 上再次遇到才是环，所以要区分「正在路径上」和「已完成处理」。

4. **ASCII 示意图 — 有环 vs 无环**：
```
无环（可以完成）:          有环（不可以完成）:
  0 → 1 → 3               0 → 1
       ↓                   ↑   ↓
       2                   3 ← 2

拓扑排序: 0, 1, 2, 3      入度永远不会全变0
```

5. **终止判断**：BFS 数已学课程数是否等于总课程数；DFS 看是否所有节点都能标记为"已完成"。

## 解法详解

### 解法1: BFS 拓扑排序 (Kahn 算法) — O(V+E) / O(V+E) ⭐ 面试首选

**思考过程**：如果一门课没有先修要求（入度为 0），我们可以直接学它。学完之后，依赖它的课程少了一个前置条件（入度减 1）。重复这个过程，如果最终所有课程都能被学到，说明没有循环依赖。

这就是 **Kahn 算法**（BFS 拓扑排序）：逐层剥离入度为 0 的节点。

```
// BFS 拓扑排序过程示例:
// numCourses=4, prerequisites=[[1,0],[2,0],[3,1],[3,2]]
//
// 建图:  0 → 1, 0 → 2, 1 → 3, 2 → 3
// 入度:  0:0  1:1  2:1  3:2
//
// 初始队列: [0]（入度为0）
//
// Step1: 弹出0, 处理邻居1和2
//   1的入度: 1→0 → 入队   2的入度: 1→0 → 入队
//   已学: [0], 队列: [1, 2]
//
// Step2: 弹出1, 处理邻居3
//   3的入度: 2→1
//   已学: [0, 1], 队列: [2]
//
// Step3: 弹出2, 处理邻居3
//   3的入度: 1→0 → 入队
//   已学: [0, 1, 2], 队列: [3]
//
// Step4: 弹出3, 无邻居
//   已学: [0, 1, 2, 3], 队列: 空
//
// 已学4门 == numCourses=4 → 返回 true
```

```cpp
class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        // 1. 建图 + 统计入度
        vector<vector<int>> graph(numCourses);
        vector<int> indegree(numCourses, 0);
        
        for (auto& pre : prerequisites) {
            // pre[1] → pre[0]：先修 pre[1] 才能学 pre[0]
            graph[pre[1]].push_back(pre[0]);
            indegree[pre[0]]++;
        }
        
        // 2. 将所有入度为 0 的节点加入队列（没有先修要求，可以直接学）
        queue<int> q;
        for (int i = 0; i < numCourses; i++) {
            if (indegree[i] == 0) {
                q.push(i);
            }
        }
        
        // 3. BFS：逐层"学习"课程
        int learnedCount = 0;
        while (!q.empty()) {
            int course = q.front();
            q.pop();
            learnedCount++;
            
            // 学完 course 后，它指向的课程入度减 1
            for (int next : graph[course]) {
                indegree[next]--;
                // 入度变 0 说明前置课程全学完了，可以学这门课了
                if (indegree[next] == 0) {
                    q.push(next);
                }
            }
        }
        
        // 4. 如果所有课程都学了，说明无环
        return learnedCount == numCourses;
    }
};
```

**关键点**：
- 入度数组是核心数据结构，记录每个节点还有几个未满足的前置依赖
- 最终 `learnedCount < numCourses` 意味着有些节点的入度永远无法降为 0，即存在环

### 解法2: DFS 三色标记法 — O(V+E) / O(V+E) ⭐ 面试必会

**思考过程**：换一个角度——直接检测有向图中是否有环。DFS 时，如果沿着一条路径走，又回到了路径上的某个节点，说明有环。

关键在于区分三种状态：
- **0（白色/未访问）**：还没开始处理
- **1（灰色/访问中）**：正在当前 DFS 路径上，还没处理完
- **2（黑色/已完成）**：该节点及其所有后续都处理完毕，确认无环

为什么不能只用 `visited` 布尔值？看这个例子：
```
// 0 → 1 → 2
// 0 → 2
//
// 从 0 出发 DFS: 0→1→2（标记2为visited）
// 回到 0，走另一条路 0→2，发现 2 已 visited
// 但这不是环！只是两条路径到达同一节点
//
// 三色标记：走完 0→1→2 后，2 标为黑色（已完成）
// 走 0→2 时，发现 2 是黑色 → 安全，不是环
// 只有遇到灰色（当前路径上的节点）才是环
```

```cpp
class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        // 1. 建图
        vector<vector<int>> graph(numCourses);
        for (auto& pre : prerequisites) {
            graph[pre[1]].push_back(pre[0]);
        }
        
        // 2. 三色标记：0=未访问, 1=访问中(在当前路径上), 2=已完成
        vector<int> color(numCourses, 0);
        
        // 3. 对每个未访问的节点发起 DFS
        for (int i = 0; i < numCourses; i++) {
            if (color[i] == 0) {
                if (hasCycle(graph, color, i)) {
                    return false;  // 发现环，不能完成
                }
            }
        }
        return true;  // 无环
    }
    
private:
    bool hasCycle(vector<vector<int>>& graph, vector<int>& color, int node) {
        color[node] = 1;  // 标记为"访问中"（灰色）
        
        for (int next : graph[node]) {
            if (color[next] == 1) {
                // 遇到灰色节点 = 在当前路径上又遇到了 = 环！
                return true;
            }
            if (color[next] == 0) {
                // 白色节点，继续 DFS
                if (hasCycle(graph, color, next)) {
                    return true;
                }
            }
            // color[next] == 2（黑色）：已处理完毕，跳过
        }
        
        color[node] = 2;  // 该节点所有后续都无环，标记为"已完成"（黑色）
        return false;
    }
};
```

**关键点**：
- 灰色 = 当前递归调用栈上的节点 = 当前 DFS 路径
- 遇到灰色就是回边（back edge），回边 = 有环
- 黑色节点已确认安全，不需要重复检查（这也是剪枝，避免重复工作）

## 解法对比

| | BFS 拓扑排序 | DFS 三色标记 |
|---|---|---|
| 核心思想 | "能学什么就先学什么"，逐层剥离 | "走一条路到底，看能不能走回来" |
| 判断标准 | 学完的课程数 == 总课程数 | 没有遇到灰色节点（无回边） |
| 实现难度 | 简单直观，不易出错 | 需要理解三色标记，容易忘记状态转换 |
| 扩展性 | 直接输出拓扑排序序列（LC 210） | 也可以输出，但需要额外记录 |
| 面试推荐 | ⭐ 首选，逻辑清晰好解释 | ⭐ 也要会，面试官可能要求两种都写 |

**总结**：两种方法时间空间复杂度完全相同，都是 O(V+E)。BFS 更直觉，DFS 更"图论味"。面试时先写 BFS，如果面试官追问就补 DFS。

## 易错点

1. **建图方向搞反**：
   - ✗ `graph[pre[0]].push_back(pre[1])` — 方向反了！
   - ✓ `graph[pre[1]].push_back(pre[0])` — `[a, b]` 表示 b 是 a 的前置，边是 b→a
   - 如果方向反了，BFS 的入度统计也全错，但代码不会报错，只是结果不对

2. **DFS 只用 visited 布尔值而不是三色标记**：
   - ✗ `if (visited[next]) return true;` — 会把"从不同路径到达同一节点"误判为环
   - ✓ 用三色：只有 `color[next] == 1`（灰色/当前路径上）才说明有环

3. **DFS 忘记将节点标为黑色**：
   - ✗ 函数末尾少了 `color[node] = 2;`
   - ✓ 必须在所有邻居处理完后标记为黑色，否则每次都会重复处理，时间退化为指数级

4. **忽略孤立节点（没有任何边的课程）**：
   - 孤立节点入度为 0，BFS 中会直接入队并计数，不影响正确性
   - DFS 中颜色为白色，DFS 后直接变黑色，也不影响
   - 但如果建图时只处理了有边的节点，忘记考虑孤立节点，可能在某些实现中出错

## 面试追问

**Q1: 这道题本质是什么图论问题？为什么？**
→ 有向图判环。课程是节点，先修关系是有向边。存在环 = 循环依赖 = 不可能完成所有课程。等价地，能完成所有课程 ⟺ 图的拓扑排序存在 ⟺ 图是 DAG（有向无环图）。

**Q2: BFS 和 DFS 两种方法你都能写吗？各自的核心数据结构是什么？**
→ BFS 核心是 **入度数组 + 队列**；DFS 核心是 **颜色/状态数组 + 递归栈**。BFS 从"可以学什么"出发正向推进，DFS 从"是否存在环"出发反向检测。

**Q3: 如果不只是判断能否完成，还要输出一个合法的学习顺序呢？（LeetCode 210）**
→ BFS 方法只需记录出队顺序，出队顺序就是拓扑排序。DFS 方法在节点标记为黑色时加入结果栈，最后反转即可。核心代码改动极小：BFS 加一个 `vector<int> order`，每次 `pop` 时 `order.push_back(course)`。

**Q4: 如果课程数量非常大但边很少（稀疏图），你的实现有什么需要注意的？**
→ 邻接表的选择是正确的（而不是邻接矩阵），因为邻接矩阵 O(V²) 空间在稀疏图上浪费。当前实现已经是 O(V+E)，是最优的。
