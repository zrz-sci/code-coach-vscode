# 773. 滑动谜题

## 核心思路

经典的**BFS 状态空间搜索**。将 2x3 棋盘展平为字符串作为"状态"，每个状态下 0 可以和相邻位置交换生成新状态。BFS 搜索从初始状态到目标状态 `"123450"` 的最短路径。状态空间极小（最多 6! = 720 种），BFS 完全可行。

## 思维链

1. **读完题第一反应** → 华容道/15-puzzle 的简化版。要求最少步数 → 想到 BFS（BFS 天然找最短路径）。
2. **状态怎么表示？** → 2x3 棋盘有 6 个格子，状态空间是 6 个数字的排列。展平成字符串 `"412503"` 就是一个状态。用字符串作为 BFS 中的"节点"。
3. **状态转移怎么做？** → 找到 0 的位置，把 0 和相邻位置（上下左右）交换，得到新状态。
4. **邻居表预计算** → 2x3 棋盘中每个位置的邻居是固定的。位置编号 0-5：
   ```
   0 1 2
   3 4 5
   ```
   邻居表：`{1,3}, {0,2,4}, {1,5}, {0,4}, {1,3,5}, {2,4}`
5. **搜索空间有多大？** → 6 个不同数字的排列 = 6! = 720。BFS 最多访问 720 个状态，完全可接受。
6. **无解怎么判断？** → BFS 队列清空但没有找到目标状态，返回 -1。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| BFS | 字符串状态 + 邻居表 | O(6! * 6) | O(6!) | ⭐ 面试首选 |
| 双向 BFS | 从起点和终点同时搜索 | O(6! * 6) | O(6!) | 进阶优化 |
| A* 搜索 | 曼哈顿距离启发式 | O(6! * 6) | O(6!) | 进阶加分 |

## 关键提示

1. **展平方式**：`board[i][j]` → `s[i*3 + j]`。即 `board[0][0..2]` 对应 `s[0..2]`，`board[1][0..2]` 对应 `s[3..5]`。
2. **邻居表是关键**：在 2x3 棋盘上，每个位置的邻居位置是固定的，提前硬编码比运行时计算上下左右更简洁。
3. **visited 去重**：用 `unordered_set<string>` 存已访问状态，避免重复搜索。
4. **BFS 层序遍历**：每层代表一步。队列处理完一层后 `steps++`。找到目标时返回的 `steps` 就是最少移动次数。
5. **起点特判**：如果初始状态就是目标，直接返回 0。

## 解法详解

### 解法1: BFS 状态空间搜索 — O(6! * 6) / O(6!) ⭐ 面试首选

**思考过程**: 最短路径 → BFS。状态 = 棋盘展平的字符串。转移 = 0 与相邻位置交换。

```cpp
class Solution {
public:
    int slidingPuzzle(vector<vector<int>>& board) {
        // Step 1: 展平棋盘为字符串
        string start;
        for (auto& row : board)
            for (int x : row) start += to_string(x);

        string target = "123450";
        if (start == target) return 0;  // 特判：已经是目标

        // Step 2: 预定义邻居表
        vector<vector<int>> neighbors = {
            {1, 3}, {0, 2, 4}, {1, 5}, {0, 4}, {1, 3, 5}, {2, 4}
        };

        // Step 3: BFS
        unordered_set<string> visited;
        queue<string> q;
        q.push(start);
        visited.insert(start);
        int steps = 0;

        while (!q.empty()) {
            steps++;
            int sz = q.size();  // 当前层的大小
            while (sz--) {
                string curr = q.front(); q.pop();
                int zeroPos = curr.find('0');  // 找到0的位置

                for (int nb : neighbors[zeroPos]) {
                    string next = curr;
                    swap(next[zeroPos], next[nb]);  // 交换0和邻居
                    if (next == target) return steps;
                    if (!visited.count(next)) {
                        visited.insert(next);
                        q.push(next);
                    }
                }
            }
        }
        return -1;  // BFS 穷尽所有状态仍未到达目标
    }
};
```

**关键点**:
- **层序遍历**：外层 `while (!q.empty())` + 内层 `while (sz--)` 确保每层代表一步。`steps` 在每层开始时递增。
- **先检查目标再入队**：`if (next == target) return steps;` 在生成新状态时立即检查，比出队时检查更快（少一层）。
- **字符串作为状态**：`string` 可以直接放入 `unordered_set`，方便去重。也可以用 `int` 编码（如 hash = 各位数字加权），但字符串更直观。
- **时间复杂度**：最多 6! = 720 个状态，每个状态最多生成 4 个邻居，每个状态操作 O(6)（字符串操作），总计 O(720 * 4 * 6) ≈ O(17280)，极快。

### 解法2: 双向 BFS — 进阶优化

**优化思路**: 从起点和终点同时搜索。当两端的搜索"相遇"时，路径就找到了。对于状态空间大的问题可以显著减少搜索量，但本题状态空间很小，优化效果不明显。

```cpp
class Solution {
public:
    int slidingPuzzle(vector<vector<int>>& board) {
        string start;
        for (auto& row : board)
            for (int x : row) start += to_string(x);

        string target = "123450";
        if (start == target) return 0;

        vector<vector<int>> neighbors = {
            {1, 3}, {0, 2, 4}, {1, 5}, {0, 4}, {1, 3, 5}, {2, 4}
        };

        // 两个方向各自维护一个集合
        unordered_set<string> frontSet = {start};
        unordered_set<string> backSet = {target};
        unordered_set<string> visited = {start, target};
        int steps = 0;

        while (!frontSet.empty() && !backSet.empty()) {
            steps++;
            // 总是扩展较小的一端（优化）
            if (frontSet.size() > backSet.size()) {
                swap(frontSet, backSet);
            }

            unordered_set<string> nextSet;
            for (const string& curr : frontSet) {
                int zeroPos = curr.find('0');
                for (int nb : neighbors[zeroPos]) {
                    string next = curr;
                    swap(next[zeroPos], next[nb]);

                    // 检查是否和另一端相遇
                    if (backSet.count(next)) return steps;

                    if (!visited.count(next)) {
                        visited.insert(next);
                        nextSet.insert(next);
                    }
                }
            }
            frontSet = nextSet;
        }
        return -1;
    }
};
```

**关键点**:
- 每次选择较小的集合来扩展（`if (frontSet.size() > backSet.size()) swap(...);`），保证搜索均衡。
- 当一端生成的新状态在另一端的集合中出现，说明两端相遇，路径长度就是当前 `steps`。

## 解法对比

|  | BFS | 双向 BFS | A* |
|--|-----|---------|-----|
| 时间 | O(6! * 6) | O(6! * 6) 更少常数 | O(6! * 6) 更少搜索 |
| 空间 | O(6!) | O(6!) | O(6!) |
| 实现难度 | 简单 | 中等 | 较难 |
| 面试推荐 | ⭐ 首选 | 追问时提 | 追问时提 |

本题状态空间极小（720），三种方法差异不大。面试默认写 BFS。

## 易错点

1. **邻居表写错**：
   - 最常见错误：位置 4 的邻居漏掉或多写。正确是 `{1, 3, 5}`（上、左、右）。
   - 调试方法：画出 2x3 网格，手动列出每个位置的上下左右邻居。

2. **字符串状态操作的副作用**：
   - ✗ 直接在 `curr` 上 swap → 修改了当前状态，后续邻居的探索会出错
   - ✓ 每次 `string next = curr;` 拷贝后再 swap

3. **steps 计数时机错误**：
   - ✗ 在出队时才 `steps++` → 同一层的节点 steps 不一致
   - ✓ 每层开始时统一 `steps++`（层序遍历模板）

4. **忘记起点特判**：
   - ✗ 起点就是目标但 BFS 至少走一步才检查 → 返回 1 而不是 0
   - ✓ `if (start == target) return 0;` 在 BFS 开始前特判

5. **find('0') 返回值类型**：
   - `string::find` 返回 `size_t`（无符号），如果赋给 `int` 通常没问题（因为 0 一定存在）。但要确保 0 存在于字符串中。

## 面试追问

**Q1: 为什么用 BFS 而不是 DFS？**
> BFS 天然找最短路径。DFS 能找到解但不保证是最短的（除非遍历所有路径取最小值，效率低）。

**Q2: 状态空间有多大？能否穷举所有状态？**
> 6 个不同数字的排列 = 6! = 720。其中约一半（360）是可达的（奇偶排列性质），另一半不可达。BFS 最多访问 360 个状态，极快。

**Q3: 如果棋盘是 3x3（8-puzzle）呢？**
> 状态空间 9! = 362880。BFS 仍然可行但较慢。可以用 A* 搜索 + 曼哈顿距离启发函数来加速。实际 8-puzzle 的最大最优解是 31 步。

**Q4: 如何判断是否有解？**
> 通过**逆序数的奇偶性**判断。将棋盘展平（去掉0），计算逆序数（前面比后面大的对数）。对于 2x3 棋盘，起始状态和目标状态的逆序数奇偶性必须相同才有解。这比 BFS 快（O(n^2) 直接判断），但面试中 BFS 搜不到返回 -1 就够了。

**Q5: 能否用 A* 启发式搜索？**
> 可以。启发函数用**曼哈顿距离**：每个数字当前位置到目标位置的曼哈顿距离之和。A* = BFS + 优先队列（按 `steps + heuristic` 排序）。本题状态空间太小，A* 优势不明显，但在 3x3 或更大棋盘上效果显著。
