# 791. Custom Sort String (自定义字符串排序)

## 核心思路

根据 order 定义的字符优先级对字符串 s 进行排序。核心方法有两种：(1) 计数排列法——先统计 s 中每个字符的频次，然后按 order 的顺序依次输出，最后追加 order 中未出现的字符；(2) 自定义比较函数排序——为每个字符赋予 order 中的权重，然后用标准排序。

## 思维链

1. **理解约束**：order 中字符唯一且仅小写字母（最多 26 个）；s 长度最多 200。
2. **方法一思路（计数排列）**：统计 s 中每个字符出现的次数。遍历 order 中的每个字符 c，将 c 重复 count[c] 次放入结果，然后清零。最后将 s 中未在 order 中出现的字符追加到结果。
3. **方法二思路（自定义排序）**：给 order 中每个字符一个优先级编号（例如 order[0]->0, order[1]->1, ...），不在 order 中的字符给一个统一的大值（如 26）。然后对 s 用该优先级作为比较函数进行排序。
4. **方法一更优**：计数排列法是 O(|s| + |order|)，而自定义排序是 O(|s| log |s|)。虽然 |s| <= 200 差距不大，但面试中展示线性解法更加分。

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 计数排列 (桶排序思想) | O(N + M) | O(26) | 线性时间，最优 |
| 自定义比较排序 | O(N log N) | O(26) | 代码简洁 |
| 原地双指针交换 | O(N * M) | O(1) | 空间最优，无额外分配 |

其中 N = |s|, M = |order|。

## 关键提示

1. **order 中字符唯一**：无重复，可以直接用下标作为优先级。
2. **s 中可能有 order 中没有的字符**：这些字符的相对顺序无所谓，放在任何位置都合法。
3. **s 中可能有重复字符**：需要正确统计频次。
4. **order 中可能有 s 中没有的字符**：跳过即可，不影响结果。
5. **返回任意合法排列**：不要求唯一解，只要满足 order 定义的相对顺序即可。

## 解法详解

### 解法一：计数排列法（推荐面试首选）

**步骤**：
1. 用数组 `count[26]` 统计 s 中每个字符的出现次数。
2. 遍历 order 中的每个字符 c：将 c 重复 `count[c]` 次追加到结果字符串，然后 `count[c] = 0`。
3. 遍历 26 个字母，对于 count 仍 > 0 的字符（即不在 order 中的），追加到结果。

**为什么正确**：order 中的字符按顺序输出，天然满足排序要求。不在 order 中的字符放在最后（或任何位置），题目允许任意放置。

**复杂度**：O(N + M + 26) 时间，O(26) 空间。

### 解法二：自定义比较函数排序

**步骤**：
1. 构建优先级映射 `priority[c] = 在 order 中的下标`。不在 order 中的字符给默认值（如 order.size()）。
2. 对 s 进行 sort，比较函数为 `priority[a] < priority[b]`。

**注意**：这种方法排序不保证稳定性（相同优先级的字符相对顺序可能变），但题目允许任意合法排列，所以无影响。

**复杂度**：O(N log N) 时间，O(26) 空间。

### 解法三：原地双指针交换

**步骤**：遍历 order 中的每个字符 c，用一个 writePos 指针，将 s 中所有等于 c 的字符交换到 writePos 开始的位置。类似选择排序。

**复杂度**：O(N * M) 时间，O(1) 额外空间（原地修改 s）。

## 易错点

1. **忘记处理 order 中没有的字符**：如果只输出 order 中的字符，会丢失 s 中其他字符。
2. **count 清零**：计数排列法中，输出后必须清零，否则第 3 步会重复输出。
3. **自定义排序中未在 order 中的字符优先级不一致**：如果都给 INT_MAX 或 26，排序后它们会被推到末尾——这是合法的。但如果给 -1 等负值，它们会被拉到开头，也是合法的。
4. **混淆 order 和 s 的角色**：order 定义排序规则，s 是被排序的对象。不要搞反。
5. **string 拼接效率**：如果用 `result += c` 在循环中拼接，C++ 中可能触发多次拷贝。可以先 `reserve` 或用 `string(count, c)` / `append(count, c)` 一次性追加。

## 面试追问

1. **Q: 如果 s 很长（10^6），哪种方法更优？** A: 计数排列法，O(N) vs O(N log N)。差距在大数据量时显著。
2. **Q: 如果要求稳定排序（相同优先级字符保持原始顺序），怎么做？** A: 计数排列法天然不稳定（按字母聚合）。自定义排序用 stable_sort 可以保持相同优先级字符的原始顺序。
3. **Q: 如果 order 也可能有重复字符呢？** A: 取第一次出现的下标作为优先级，后续忽略。或者先去重再处理。
4. **Q: 如何扩展到 Unicode 字符集？** A: 将固定大小数组 count[26] 替换为 unordered_map<char, int>。逻辑不变。
5. **Q: 如果不在 order 中的字符也有特定排序要求（比如按 ASCII 排序）？** A: 修改第 3 步，从 'a' 到 'z' 遍历输出（而非无序追加），或在自定义比较函数中对无优先级字符按字典序比较。
