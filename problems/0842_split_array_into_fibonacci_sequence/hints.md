# 842. Split Array into Fibonacci Sequence - 提示与解析

## 核心思路

给定一个数字字符串，将其拆分为一个类斐波那契序列（长度 >= 3，每个数 < 2^31，相邻两数之和等于下一个数）。本质是一个回溯搜索问题：一旦确定前两个数，后续所有数都是唯一确定的。因此只需枚举前两个数的所有可能分割方式，然后贪心地验证剩余部分是否匹配。

## 思维链

1. **问题转化**：确定前两个数 f[0] 和 f[1] 后，整个序列就被唯一确定了（f[k] = f[k-1] + f[k-2]）。
2. **枚举策略**：双层循环枚举 f[0] 和 f[1] 的结束位置。f[0] 长度范围 [1, n/2]，f[1] 长度范围 [1, n/2]。
3. **前导零处理**：如果一个数长度 > 1 且以 '0' 开头，则非法（数字 "0" 本身合法）。
4. **溢出检查**：每个数必须 < 2^31，即 fit in int32。用 long 做中间计算。
5. **贪心验证**：知道前两个数后，计算它们的和，检查字符串剩余部分是否以这个和的字符串表示开头。反复执行直到字符串耗尽。
6. **成功条件**：字符串完全被消耗，且序列长度 >= 3。

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 推荐度 | 特点 |
|------|-----------|-----------|--------|------|
| 回溯 + 剪枝 | O(n^2 * n) | O(n) | ⭐⭐⭐⭐⭐ | 枚举前两个数，贪心验证 |
| 纯回溯 DFS | O(n * 2^n) | O(n) | ⭐⭐⭐ | 通用回溯框架，但较慢 |
| 迭代确定性验证 | O(n^2 * n) | O(n) | ⭐⭐⭐⭐ | 枚举前两个数后迭代检查 |

## 关键提示

1. **前两个数决定一切**：类斐波那契序列的特性是，一旦知道 f[0] 和 f[1]，后续所有数唯一确定。
2. **前导零约束**：数字 "0" 合法，但 "01"、"00" 等不合法。发现前导零立刻剪枝。
3. **32 位溢出**：题目要求每个数 < 2^31。当字符串转换出的数超过 INT_MAX 时需要终止。
4. **第一个数和第二个数的长度限制**：每个数最多占字符串一半长度，否则剩余部分不够形成第三个数。
5. **字符串匹配代替数字比较**：验证时可以把 sum 转回字符串，与字符串的下一段做前缀匹配，避免反复解析。

## 解法详解

### 解法一：枚举前两个数 + 贪心验证（推荐）

**思路**：
用双层循环枚举第一个数和第二个数的长度。对每种组合，将它们转为整数后，反复计算 sum = prev1 + prev2，将 sum 转为字符串，检查剩余字符串是否以该字符串开头。若匹配则移动指针继续，不匹配则尝试下一种组合。

**关键步骤**：
- 外层循环 i: f[0] 的结束位置
- 内层循环 j: f[1] 的结束位置
- 内部 while 循环：贪心匹配后续数字

**复杂度分析**：
- 时间：O(n^2 * n)，枚举 O(n^2) 种组合，每种验证 O(n)
- 空间：O(n)，存储结果序列

### 解法二：标准回溯 DFS

**思路**：
使用通用的回溯框架。每一步决定下一个数取多长，然后递归。当序列长度 >= 3 且当前位置到达字符串末尾时返回成功。

**复杂度分析**：
- 时间：最坏 O(n * 2^n)，但剪枝后远快于此
- 空间：O(n)，递归深度和结果存储

### 解法三：迭代确定性验证

**思路**：
与解法一类似但使用纯迭代（无递归）。枚举前两个数后用 while 循环验证。代码更简洁，逻辑更清晰。

## 易错点

1. **忘记前导零检查**：数字 "0" 合法但 "01" 不合法。很多人忽略这个条件导致 WA。
2. **溢出处理不当**：字符串可能很长，转数字时超出 int 范围。应使用 long long 中间计算并检查是否 > INT_MAX。
3. **序列长度 < 3**：仅拆成两个数时不满足要求，必须 >= 3 个数。
4. **第一个数取太长**：第一个数的长度不应超过 n/2，否则不可能有第三个数。
5. **sum 本身溢出**：两个接近 INT_MAX 的 int 相加可能溢出 int，必须用 long long。

## 面试追问

1. **Q: 为什么枚举前两个数就够了？**
   A: 类斐波那契序列的递推关系 f[k] = f[k-1] + f[k-2] 使得 f[0] 和 f[1] 唯一确定整个序列。

2. **Q: 如何优化到更快？**
   A: 关键剪枝：(1) 前导零直接跳过 (2) 数字超过 INT_MAX 直接 break (3) 第一个和第二个数长度限制为 n/2。

3. **Q: 如果允许负数呢？**
   A: 需要处理负号，枚举时增加一个字符位用于负号。递推关系不变，但分割更复杂。

4. **Q: 如果要求返回所有合法拆分呢？**
   A: 不需要找到一个就返回，而是收集所有解。不过实际上合法拆分极少，复杂度变化不大。
