# 540. 有序数组中的单一元素

## 核心思路

本质上：有序数组中每对相同元素"成对排列"，单一元素打破了这种奇偶对齐规律。利用这个规律，可以用二分查找在 O(log n) 内定位断裂点。

## 思维链

1. **读完题第一反应**：异或所有元素，成对的会抵消，剩下的就是答案。但这是 O(n)，题目要求 O(log n)。
2. **O(log n) + 有序数组 → 二分查找**：但这不是普通的"找一个目标值"，二分的判断条件是什么？
3. **关键观察 — 奇偶配对规律**：
   - 在单一元素**之前**，每对元素的第一个在偶数下标，第二个在奇数下标：`(0,1), (2,3), (4,5)...`
   - 在单一元素**之后**，这种配对被打乱：第一个在奇数下标，第二个在偶数下标
4. **二分判断条件**：取 mid，看 mid 和它的"配对元素"是否符合"单一元素之前"的规律。如果符合，说明单一元素在右边；不符合，说明在左边（或就是 mid）。
5. **技巧**：用 `mid ^ 1` 可以快速得到配对下标（偶数→偶数+1，奇数→奇数-1），这比分类讨论更简洁。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 异或法 | XOR 所有元素 | O(n) | O(1) | 能说出即可 |
| 二分查找（奇偶配对） | 利用配对规律二分 | O(log n) | O(1) | ⭐ 必须写出 |
| 二分查找（仅偶数下标） | 只在偶数下标上二分 | O(log n) | O(1) | 加分项 |

## 关键提示

1. **画一下下标**：在单一元素出现之前，相同元素对总是从偶数下标开始。单一元素出现后，这个规律被反转。
   ```
   下标:  0  1  2  3  4  5  6  7  8
   值:    1  1  2  3  3  4  4  8  8
               ↑ 单一元素在这里
   之前: (1,1) 在 (0,1) — 偶数开头 ✓
   之后: (3,3) 在 (3,4) — 奇数开头 ✗（规律被打破）
   ```

2. **`mid ^ 1` 的妙用**：偶数下标 `^1` 得到它的右邻居，奇数下标 `^1` 得到它的左邻居。这恰好就是"配对元素"的下标。

3. **搜索空间**：二分的是下标范围 `[0, n-1]`，不是值的范围。

4. **另一种思路**：只看偶数下标。如果 `nums[mid] == nums[mid+1]`，说明这一对完整，单一元素在后面；否则在前面（包括 mid）。

5. **数组长度一定是奇数**（每对2个 + 单一1个），所以不用担心越界问题吗？不一定，`mid+1` 可能越界，需要处理。

## 解法详解

### 解法1: 异或法 — O(n) / O(1)

**思考过程**: 这是"找唯一出现一次的元素"的经典做法。`a ^ a = 0`，所有成对元素异或后消失，剩下的就是答案。但这完全没利用"有序"这个条件，时间是 O(n)，不满足题目要求。

```cpp
class Solution {
public:
    int singleNonDuplicate(vector<int>& nums) {
        int result = 0;
        for (int num : nums) {
            result ^= num;
        }
        return result;
    }
};
```

**关键点**: 这个解法正确但不够优，面试中可以作为"先给个暴力解"的起步，然后再优化。

### 解法2: 二分查找（奇偶配对） — O(log n) / O(1) ⭐ 面试首选

**从解法1优化**: 解法1的瓶颈是逐个遍历，没有利用"有序"。有序 + O(log n) = 二分查找。关键洞察：单一元素把数组分成"配对正常区"和"配对错位区"，我们要找这个分界点。

```
// 搜索空间收缩过程（示例1: [1,1,2,3,3,4,4,8,8]）:
//
// 下标:  0  1  2  3  4  5  6  7  8
// 值:    1  1  2  3  3  4  4  8  8
//
// Round1: left=0, right=8, mid=4
//   mid=4(偶数), mid^1=5, nums[4]=3, nums[5]=4, 不相等
//   → 配对已错位，单一元素在左半边（含mid） → right=4
//
// Round2: left=0, right=4, mid=2
//   mid=2(偶数), mid^1=3, nums[2]=2, nums[3]=3, 不相等
//   → 配对已错位，单一元素在左半边（含mid） → right=2
//
// Round3: left=0, right=2, mid=1
//   mid=1(奇数), mid^1=0, nums[1]=1, nums[0]=1, 相等
//   → 配对正常，单一元素在右半边 → left=2
//
// left==right==2 → 返回 nums[2]=2 ✓
```

```cpp
class Solution {
public:
    int singleNonDuplicate(vector<int>& nums) {
        int left = 0, right = nums.size() - 1;
        while (left < right) {
            int mid = left + (right - left) / 2;
            // mid^1: 偶数→偶数+1, 奇数→奇数-1 — 找到配对下标
            if (nums[mid] == nums[mid ^ 1]) {
                // 配对正常 → 单一元素在 mid 右边
                left = mid + 1;
            } else {
                // 配对异常 → 单一元素在 mid 或 mid 左边
                right = mid;
            }
        }
        return nums[left];
    }
};
```

**为什么 `mid ^ 1` 有效？**
- 如果 mid = 4（二进制 100），4 ^ 1 = 5（二进制 101）→ 偶数的下一个
- 如果 mid = 5（二进制 101），5 ^ 1 = 4（二进制 100）→ 奇数的前一个
- 这恰好就是"正常配对"时，当前元素的另一半所在的下标

### 解法3: 二分查找（仅偶数下标） — O(log n) / O(1)

**另一个角度**: 单一元素一定在偶数下标上（因为它前面有偶数个元素）。只在偶数下标上二分，逻辑更直观。

```
// 思路图解:
// 下标:  0  1  2  3  4  5  6  7  8
// 值:    1  1  2  3  3  4  4  8  8
//        ↑     ↑     ↑     ↑     ↑   ← 偶数下标: 0,2,4,6,8
//
// 检查偶数下标 mid，看 nums[mid] == nums[mid+1]?
//   下标0: nums[0]=1 == nums[1]=1 → 配对完好，答案在右边
//   下标2: nums[2]=2 != nums[3]=3 → 配对断裂，答案在左边（含2）
//   → 答案是下标2，值=2 ✓
```

```cpp
class Solution {
public:
    int singleNonDuplicate(vector<int>& nums) {
        int left = 0, right = nums.size() - 1;
        while (left < right) {
            int mid = left + (right - left) / 2;
            // 确保 mid 是偶数（如果是奇数就左移一位）
            if (mid % 2 == 1) mid--;
            
            if (nums[mid] == nums[mid + 1]) {
                // 当前对完整，单一元素在右边
                left = mid + 2;  // 跳过这一对
            } else {
                // 当前对不完整，单一元素就是 mid 或在更左
                right = mid;
            }
        }
        return nums[left];
    }
};
```

**关键点**: `left = mid + 2` 而不是 `mid + 1`，因为 mid 和 mid+1 是一对完整配对，要跳过整对。

## 解法对比

|  | 异或法 | 二分(奇偶配对) | 二分(偶数下标) |
|--|--------|---------------|---------------|
| 时间 | O(n) | O(log n) | O(log n) |
| 空间 | O(1) | O(1) | O(1) |
| 利用有序性 | ✗ | ✓ | ✓ |
| 代码简洁度 | 最简单 | 简洁但需理解 ^1 | 直观好理解 |
| 面试推荐 | 开场热身 | ⭐ 首选 | 备选/讲解用 |

- **解法2 vs 解法3**: 解法2用 `^1` 统一处理奇偶，代码更短；解法3强制 mid 为偶数，逻辑更易理解。本质相同。

## 易错点

1. **✗ 用 `left <= right`** → **✓ 用 `left < right`**
   - 本题是"找边界"而非"找确切值"，用 `left < right` 模板，最终 `left == right` 就是答案。如果用 `<=` 会死循环。

2. **✗ 解法3中 `left = mid + 1`** → **✓ `left = mid + 2`**
   - mid 和 mid+1 是一对完好的配对，如果只跳到 mid+1，下次循环 mid 落在奇数位置，逻辑全错。

3. **✗ 没处理 mid 的奇偶** → **✓ 解法3要确保 mid 是偶数**
   - 如果 mid 是奇数，`nums[mid] == nums[mid+1]` 的含义完全不同（变成检查错误的配对方向）。

4. **✗ 担心 `mid+1` 越界** → **✓ `right = n-1` 且 `left < right` 保证 `mid < right`，所以 `mid+1 <= right` 始终安全**
   - 当 `left < right` 时，`mid = left + (right-left)/2 < right`，所以 `mid+1` 不会越界。

## 面试追问

**Q1 (基础理解)**: "如果不要求 O(log n)，你会怎么做？"
→ 异或法 O(n)，或者逐对检查 `nums[i] != nums[i+1]` 就找到了。

**Q2 (核心追问)**: "有序 + O(log n) 暗示什么？二分的判断条件是什么？"
→ 二分查找。判断条件：单一元素之前，偶数下标的元素等于其下一个；之后则不等。这就是二分的"单调性"。

**Q3 (变体)**: "如果数组不是有序的，但每个元素出现两次只有一个出现一次，怎么 O(n)/O(1)？如果有两个出现一次呢？"
→ 一个出现一次：异或所有元素。两个出现一次（LeetCode 260）：异或得到 `a^b`，取任一不同位把数组分两组，分别异或。
