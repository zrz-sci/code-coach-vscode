# 1980. 找出不同的二进制字符串

## 核心思路

本质上是一个**鸽巢原理**问题：n 个长度为 n 的二进制字符串，总共有 2ⁿ 种可能，而只给了 n 个，所以一定存在缺失的。关键是如何高效找到一个不在给定集合中的字符串。

## 思维链

1. **读完题第一反应**：枚举所有长度为 n 的二进制字符串（共 2ⁿ 个），逐个检查是否在 nums 中出现过，找到没出现的就返回。
2. **暴力解的瓶颈**：需要枚举 2ⁿ 个候选，每次检查需要 O(n) 对比。虽然 n ≤ 16 时 2¹⁶ = 65536 完全能过，但有没有更聪明的方法？
3. **关键观察 — 对角线论证 (Cantor's Diagonal Argument)**：如果我构造一个字符串，它的第 i 位和 `nums[i]` 的第 i 位不同，那它一定和 `nums[i]` 不同（因为第 i 位就不一样）。对每个 i 都这样做，结果就和所有 n 个字符串都不同！
4. **这就是康托尔对角线法**：只需 O(n) 时间，逐位构造即可。每个位置只看一个字符串的一个字符，极其优雅。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举所有 2ⁿ 个二进制串，查 HashSet | O(2ⁿ · n) | O(n²) | 能说出即可 |
| 整数映射 + 查找 | 将字符串转整数，找缺失 | O(n²) | O(n) | 能说出即可 |
| 对角线法 (Cantor) | 第 i 位取 nums[i][i] 的反 | O(n) | O(n) | ⭐ 必须写出 |

## 关键提示

1. **数量关系**：n 个字符串，每个长度 n，总共 2ⁿ 种可能但只有 n 个，缺失的远多于存在的。
2. **想想对角线**：如果你只需要和每个字符串"至少有一位不同"，你需要看多少位？只需要看 n 位就够了 — 每个字符串看一位。
3. **Cantor 对角线法**：构造结果的第 i 位 = `nums[i][i]` 取反。这保证了结果和 `nums[i]` 在第 i 位不同，因此和每个 nums 中的字符串都不同。
4. **为什么一定有效**：因为你构造的字符串和 `nums[0]` 的第 0 位不同，和 `nums[1]` 的第 1 位不同...和 `nums[n-1]` 的第 n-1 位不同。所以它不等于任何一个 nums 中的字符串。

```
对角线法示意 (nums = ["111", "011", "001"]):

       位0  位1  位2
nums[0]: [1]  1    1     ← 取第0位 '1'，取反得 '0'
nums[1]:  0  [1]   1     ← 取第1位 '1'，取反得 '0'
nums[2]:  0   0   [1]    ← 取第2位 '1'，取反得 '0'
                           ↓
构造结果:  1    0    0   → "100"

验证: "100" ≠ "111"(位0不同), ≠ "011"(位1不同), ≠ "001"(位2不同) ✓
```

## 解法详解

### 解法1: 暴力枚举 + HashSet — O(2ⁿ · n) / O(n²)

**思考过程**: 最直觉的做法 — 把 nums 放进集合，然后从 0 到 2ⁿ-1 枚举每个数，转成二进制字符串检查是否在集合中。

```cpp
class Solution {
public:
    string findDifferentBinaryString(vector<string>& nums) {
        int n = nums.size();
        unordered_set<string> seen(nums.begin(), nums.end());
        
        // 枚举 0 到 2^n - 1 的所有数
        for (int i = 0; i < (1 << n); i++) {
            string candidate = "";
            for (int j = n - 1; j >= 0; j--) {
                candidate = (char)('0' + ((i >> j) & 1)) + candidate;
            }
            if (seen.find(candidate) == seen.end()) {
                return candidate;
            }
        }
        return ""; // 不会到这里，因为 2^n > n
    }
};
```

**关键点**: n ≤ 16 时 2¹⁶ = 65536，完全可以通过。但面试中这不是最佳答案。

### 解法2: 整数映射 — O(n²) / O(n)

**从解法1优化**: 不需要枚举所有 2ⁿ 个候选，只需要把 nums 转成整数集合，然后从 0 开始找第一个不在集合中的整数。因为集合只有 n 个元素，最多查 n+1 次就能找到。

```cpp
class Solution {
public:
    string findDifferentBinaryString(vector<string>& nums) {
        int n = nums.size();
        unordered_set<int> seen;
        
        // 把每个二进制字符串转成整数
        for (const string& s : nums) {
            seen.insert(stoi(s, nullptr, 2));
        }
        
        // 从 0 开始找第一个缺失的整数
        for (int i = 0; i <= n; i++) {  // 最多查 n+1 个
            if (seen.find(i) == seen.end()) {
                // 整数转回长度为 n 的二进制字符串
                string result(n, '0');
                for (int j = n - 1; j >= 0 && i > 0; j--) {
                    result[j] = '0' + (i & 1);
                    i >>= 1;
                }
                return result;
            }
        }
        return "";
    }
};
```

**关键点**: 鸽巢原理保证 0 到 n 中至少有一个不在 seen 中（seen 只有 n 个元素）。

### 解法3: 对角线法 (Cantor's Diagonal) — O(n) / O(n) ⭐ 面试首选

**核心洞察**: 我们不需要和所有 2ⁿ 个字符串比较。只需要保证和给定的 n 个字符串都不同。利用对角线法：让结果的第 i 位和 `nums[i]` 的第 i 位不同，就能保证结果和每个 nums[i] 都至少有一位不同。

```cpp
class Solution {
public:
    string findDifferentBinaryString(vector<string>& nums) {
        int n = nums.size();
        string result(n, '0');
        
        for (int i = 0; i < n; i++) {
            // 第 i 位取 nums[i][i] 的反：保证 result ≠ nums[i]
            result[i] = (nums[i][i] == '0') ? '1' : '0';
        }
        
        return result;
    }
};
```

**为什么这么优雅**：
- 和 `nums[0]` 不同：因为 result[0] ≠ nums[0][0]
- 和 `nums[1]` 不同：因为 result[1] ≠ nums[1][1]
- ...
- 和 `nums[n-1]` 不同：因为 result[n-1] ≠ nums[n-1][n-1]

一共只看了 n 个字符，构造了一个保证不在集合中的字符串。

## 解法对比

| | 暴力枚举 | 整数映射 | 对角线法 |
|---|---|---|---|
| 时间 | O(2ⁿ · n) | O(n²) | O(n) |
| 空间 | O(n²) | O(n) | O(n) (结果本身) |
| 思维难度 | 低 | 中 | 需要知道对角线论证 |
| 面试推荐 | ✗ | ✓ | ⭐⭐⭐ |

**什么时候选哪个**：面试直接上对角线法，代码极短且体现数学思维。如果一时想不到，整数映射也完全可以接受。

## 易错点

1. **对角线翻转写错**：
   - ✗ `result[i] = nums[i][i] == '0' ? '0' : '1';`（没取反，构造出来可能就是某个 nums[i]）
   - ✓ `result[i] = nums[i][i] == '0' ? '1' : '0';`（必须取反）

2. **整数转字符串时长度不足 n**：
   - ✗ 直接用 `bitset<16>` 然后截取，可能 n 不是 16
   - ✓ 手动构造长度恰好为 n 的字符串，高位补 '0'

3. **混淆行和列**：对角线法取的是 `nums[i][i]`（第 i 个字符串的第 i 个字符），不是 `nums[0][i]` 或 `nums[i][0]`

## 面试追问

**Q1: 暴力解能过吗？瓶颈在哪？**
> n ≤ 16 时暴力完全能过（2¹⁶ = 65536），但瓶颈是枚举量是指数级的。面试官想看你能不能做到线性。

**Q2: 对角线法为什么一定能构造出合法答案？会不会构造出来的字符串恰好等于某个 nums[j]？**
> 不会。对于任意 j，result[j] ≠ nums[j][j]，所以 result 和 nums[j] 至少在第 j 位不同。这就是 Cantor 对角线论证的核心 — 通过"对角线上逐位取反"来保证和所有已知元素都不同。

**Q3: 如果 nums 中有 2ⁿ - 1 个字符串（只缺一个），你能 O(n) 找到缺失的那个吗？**
> 可以。把所有字符串转成整数后异或，同时和 0 到 2ⁿ-1 的所有整数异或，利用 XOR 的性质（a ⊕ a = 0），最终剩下的就是缺失的。类似于"缺失数字"那道题。不过这里 n ≤ 16，对角线法仍然适用且更简单。
