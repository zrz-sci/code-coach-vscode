# 354. 俄罗斯套娃信封问题

## 核心思路

这道题本质上是一个**二维最长递增子序列（LIS）问题**：在宽度和高度都严格递增的约束下，找最长的嵌套链。关键突破口是通过巧妙排序将二维问题降为一维 LIS。

## 思维链

1. **读完题第一反应**：每个信封有两个维度（宽、高），要找最长的严格递增链。这不就是二维版的 LIS 吗？暴力做法：先排序，然后用经典的 O(n²) DP 求 LIS。

2. **暴力 DP 的瓶颈**：n 可达 10⁵，O(n²) 的 DP 会超时。一维 LIS 有经典的 O(n log n) 解法（patience sorting + 二分查找），能否把这道二维题转化为一维 LIS？

3. **关键观察**：如果先按宽度排序，宽度方向就天然有序了，只需要在高度方向上求 LIS。但有一个陷阱——**宽度相同的信封不能嵌套**（题目要求严格大于）。例如 `[6,4]` 和 `[6,7]` 宽度相同，不能互套。

4. **破解陷阱**：排序时，宽度升序，**宽度相同时高度降序**。这样宽度相同的信封中，高度是递减的，在后续求 LIS 时不可能同时选中两个宽度相同的信封（因为 LIS 要求严格递增，而降序排列的高度不可能同时出现在递增子序列中）。

5. **降维成功**：排序后，只对高度数组求一维 LIS，用 O(n log n) 的二分查找方法即可。

6. **总结**：排序（宽度升序 + 同宽高度降序）→ 提取高度数组 → 一维 LIS（二分查找）。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 排序 + DP (LIS) | 按宽度排序后，O(n²) DP 求高度的 LIS | O(n²) | O(n) | 能说出即可 |
| 排序 + 二分 LIS | 按宽度排序后，O(n log n) patience sorting 求 LIS | O(n log n) | O(n) | ⭐ 必须写出 |

## 关键提示

1. **排序是第一步**：先按宽度升序排。但只排宽度够吗？想想宽度相同时会发生什么。

2. **同宽度的陷阱**：`[3,4]` 和 `[3,5]` 宽度相同，不能嵌套。如果高度也是升序，求 LIS 时会把它们都选进去。怎么阻止？

3. **高度降序的妙用**：宽度相同时高度降序排列，这样 LIS 算法自然不会同时选中同宽度的两个信封。

4. **一维 LIS 的 O(n log n) 解法**：维护一个 `tails` 数组，`tails[i]` 表示长度为 `i+1` 的递增子序列的最小末尾元素。遇到新元素时，用二分查找替换第一个 `≥` 它的位置。

5. **示例排序过程**：
```
原始: [5,4] [6,4] [6,7] [2,3]
排序后(宽度升序, 同宽高度降序):
      [2,3] [5,4] [6,7] [6,4]
                        ↑ 注意 6 的高度是 7→4 降序
提取高度: [3, 4, 7, 4]
LIS:      [3, 4, 7]  → 长度 3
```

## 解法详解

### 解法1: 排序 + O(n²) DP — O(n²) / O(n)

**思考过程**：这是最直接的思路。排序后，对每个信封 i，检查所有 j < i，如果 j 能装进 i，则 `dp[i] = max(dp[i], dp[j] + 1)`。这就是经典 LIS 的 DP 解法，只不过判断条件是两个维度都严格小于。

```cpp
class Solution {
public:
    int maxEnvelopes(vector<vector<int>>& envelopes) {
        int n = envelopes.size();
        // 按宽度升序，宽度相同按高度升序（这里不需要降序，因为 DP 会逐个比较两个维度）
        sort(envelopes.begin(), envelopes.end());
        
        // dp[i] = 以 envelopes[i] 结尾的最长嵌套链长度
        vector<int> dp(n, 1);
        int ans = 1;
        
        for (int i = 1; i < n; i++) {
            for (int j = 0; j < i; j++) {
                // 两个维度都严格小于才能嵌套
                if (envelopes[j][0] < envelopes[i][0] &&
                    envelopes[j][1] < envelopes[i][1]) {
                    dp[i] = max(dp[i], dp[j] + 1);
                }
            }
            ans = max(ans, dp[i]);
        }
        return ans;
    }
};
```

**关键点**：这个解法 n = 10⁵ 时 O(n²) = 10¹⁰，会超时。但它帮助理解问题本质：排序后求 LIS。

### 解法2: 排序 + 二分 LIS — O(n log n) / O(n) ⭐ 面试首选

**从解法1优化**：解法1的瓶颈是 O(n²) 的 LIS DP。一维 LIS 有经典的 O(n log n) 解法（patience sorting），关键是通过巧妙排序把二维问题降成一维。

**核心排序策略**：
- 宽度升序：保证后面的宽度 ≥ 前面
- **同宽度时高度降序**：阻止同宽度的信封同时出现在 LIS 中

```
// 为什么同宽高度降序？
// 
// 假设有 [6,4] [6,7]
// 如果高度升序排列: [6,4] [6,7] → 高度 [4,7] → LIS 会选 4,7 → 错！宽度相同不能嵌套
// 如果高度降序排列: [6,7] [6,4] → 高度 [7,4] → LIS 不会同时选 7 和 4 → 正确！
//
// patience sorting 过程 (示例 [2,3] [5,4] [6,7] [6,4]):
// 高度序列: [3, 4, 7, 4]
//
// 处理 3: tails = [3]           ← 新建一堆
// 处理 4: tails = [3, 4]        ← 4 > 3, 新建一堆
// 处理 7: tails = [3, 4, 7]     ← 7 > 4, 新建一堆
// 处理 4: tails = [3, 4, 4]     ← 4 替换第一个 >= 4 的位置(索引1处的4→4，或索引2处的7→4)
//                                   实际是替换 7 → tails = [3, 4, 4]
//
// 等等，让我更仔细地走一遍二分:
// 处理 4: 在 tails=[3,4,7] 中找第一个 >= 4 的位置 → 索引1(值4)
//         替换: tails = [3, 4, 7]  (4替换4，没变)
// 
// 嗯，再试: lower_bound 找 >= 4 → 索引1
// tails[1] = 4，替换为 4，不变。
// 最终 tails 长度 = 3 → 答案 3 ✓
```

```cpp
class Solution {
public:
    int maxEnvelopes(vector<vector<int>>& envelopes) {
        // 排序: 宽度升序, 同宽度时高度降序
        sort(envelopes.begin(), envelopes.end(), [](const vector<int>& a, const vector<int>& b) {
            return a[0] < b[0] || (a[0] == b[0] && a[1] > b[1]);
        });
        
        // 对高度求一维 LIS (patience sorting)
        // tails[i] = 长度为 i+1 的递增子序列的最小末尾元素
        vector<int> tails;
        
        for (auto& env : envelopes) {
            int h = env[1];
            // 二分查找: 找 tails 中第一个 >= h 的位置
            auto it = lower_bound(tails.begin(), tails.end(), h);
            
            if (it == tails.end()) {
                // h 比所有末尾都大, 可以延伸最长子序列
                tails.push_back(h);
            } else {
                // 替换, 让末尾尽可能小, 为后续留更多空间
                *it = h;
            }
        }
        
        // tails 的长度就是 LIS 的长度
        return tails.size();
    }
};
```

**关键点**：
- `lower_bound` 找的是第一个 **≥ h** 的位置（严格递增，所以不能用 `upper_bound`）
- `tails` 数组本身**不是**LIS 序列，它的**长度**才是 LIS 的长度

## 解法对比

| | 解法1: 排序 + O(n²) DP | 解法2: 排序 + 二分 LIS |
|---|---|---|
| 时间 | O(n²) | O(n log n) |
| 空间 | O(n) | O(n) |
| 排序要求 | 宽度升序即可 | **必须**同宽高度降序 |
| 本质 | 经典 LIS DP，直接比较两个维度 | 巧妙降维，只需比较一个维度 |
| 面试 | 展示思路，但 n=10⁵ 会 TLE | 必须掌握 |

**什么时候选哪个**：面试时先说解法1展示理解，再优化到解法2。如果数据范围 n ≤ 5000，解法1就够了。n 到 10⁵ 必须解法2。

## 易错点

1. **✗ 宽度相同时高度也升序** → **✓ 宽度相同时高度降序**
   ```cpp
   // 错误: 只按宽度升序
   sort(env.begin(), env.end());
   // 正确: 同宽度时高度降序
   sort(env.begin(), env.end(), [](auto& a, auto& b) {
       return a[0] < b[0] || (a[0] == b[0] && a[1] > b[1]);
   });
   ```
   不降序的话，`[3,3][3,4]` 高度 3,4 会被选为 LIS，但它们宽度相同不能嵌套。

2. **✗ 用 `upper_bound`** → **✓ 用 `lower_bound`**
   ```cpp
   // 错误: upper_bound 允许相等元素，导致非严格递增
   auto it = upper_bound(tails.begin(), tails.end(), h);
   // 正确: lower_bound 保证严格递增
   auto it = lower_bound(tails.begin(), tails.end(), h);
   ```
   LIS 要求**严格**递增，必须替换掉相等的元素。

3. **✗ 误以为 tails 数组就是 LIS 序列** → **✓ tails 的长度是 LIS 长度，但内容不一定是实际的 LIS**
   tails 中的元素在替换过程中可能来自不同的子序列，不能直接输出。

4. **✗ 忘记处理只有一个信封的情况** → 其实代码天然处理了，tails 最终长度为 1。

## 面试追问

**Q1: 为什么排序后只需要对高度求 LIS？宽度不需要管了吗？**
> 排序保证了宽度非递减。LIS 中相邻元素的高度严格递增，再加上同宽高度降序的排序策略，保证了同宽度最多选一个。而不同宽度之间，排序已保证前面的宽度 ≤ 后面的宽度，又因为同宽最多选一个，所以实际选出的元素宽度严格递增。

**Q2: 如果题目改成"宽度和高度可以相等也算能嵌套"（非严格），怎么改？**
> 两处修改：(1) 排序时同宽度的高度不需要降序了，升序即可。(2) LIS 中用 `upper_bound` 代替 `lower_bound`，因为允许等于。

**Q3: 如果扩展到三维（宽、高、深），还能用这个方法吗？**
> 不能直接用。两维可以排序+LIS，但三维无法简单降维。需要用 O(n²) DP 或者更高级的数据结构（如 BIT/CDQ分治）。这是一个经典的偏序问题。

**Q4: 能否输出具体的嵌套方案（而不只是长度）？**
> O(n²) DP 版本可以通过记录 `prev[i]` 回溯路径。O(n log n) 二分版本需要额外记录每个元素被放在哪一"堆"，然后从最后一堆反向追踪。
