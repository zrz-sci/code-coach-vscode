# 395. 至少有 K 个重复字符的最长子串

## 核心思路

找最长子串，要求子串内**每个字符**的出现次数都 >= k。关键洞察：出现次数 < k 的字符**绝不可能**出现在任何合法子串中，因此可以把它们作为"分割点"递归处理。

## 思维链

1. **读完题第一反应** → 暴力枚举所有子串，检查每个子串是否所有字符频率 >= k。O(n^2) 枚举子串，每次 O(n) 统计 → O(n^3)，太慢。
2. **能不能用滑动窗口？** → 常规滑动窗口需要一个明确的"收缩条件"。这题的合法性定义是"所有字符频率 >= k"，没有简单的"窗口何时该收缩"的判据。直接用不了。
3. **换个角度：什么字符一定不在答案里？** → 统计整个字符串的字符频率，频率 < k 的字符不可能属于任何合法子串！因为即使把整个字符串算上，它的频率都不够 k。
4. **分割思路诞生** → 以频率 < k 的字符为"毒药"，把字符串切成若干段，对每段递归求解，取最大值。
5. **递归一定会终止吗？** → 是的！每次递归至少淘汰一种"坏"字符（频率 < k 的），字符集最多 26 个字母，所以递归深度最多 26 层。
6. **滑动窗口能不能用？** → 可以！但需要一个巧妙变体：枚举"窗口内恰好有 t 种不同字符"（t = 1 到 26），对每个 t 用滑动窗口。这样就有了明确的收缩条件。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 分治递归 | 以频率 < k 的字符为分割点递归 | O(26n) | O(26) 递归栈 | ⭐ 面试首选 |
| 滑动窗口变体 | 枚举窗口内不同字符数 t=1..26 | O(26n) | O(1) | 加分项 |

## 关键提示

1. **分治的核心洞察**：如果字符 c 在整个字符串中出现次数 < k，那么 c 不可能出现在任何合法子串中。所以把 c 作为分隔符，把字符串切成几段，分别求解。

   ```
   示例: s = "ababbc", k = 2
   
   统计频率: a:2, b:3, c:1
   c 的频率 1 < k=2，c 是"坏"字符
   
   以 c 为分割点: "ababb" | "c" | (末尾)
   
   递归处理 "ababb":
   统计频率: a:2, b:3
   所有字符频率都 >= 2 → "ababb" 本身就是合法子串
   长度 = 5 → 答案
   ```

2. **递归终止条件**：
   - `end - start < k` → 子串长度不够 k，不可能满足条件
   - 所有字符频率都 >= k → 当前子串就是答案

3. **递归复杂度分析**：每层递归至少消除一种"坏"字符。字母表大小 26，所以最多递归 26 层。每层扫描 O(n)，总体 O(26n) = O(n)。

4. **滑动窗口的巧妙之处**：直接对"所有字符频率 >= k"做滑窗不行，因为没有单调性。但如果限定"窗口内恰好有 t 种不同字符"，就有了明确的扩展/收缩条件：
   - 不同字符数 > t → 收缩左边界
   - 不同字符数 <= t 且所有字符频率 >= k → 更新答案

## 解法详解

### 解法1: 分治递归 — O(26n) / O(26) ⭐ 面试首选

**思考过程**: 不能在答案子串中出现的字符，恰好是天然的分割点。

```
详细递归过程: s = "ababbc", k = 2

第1层: helper("ababbc", 0, 6)
  频率: a:2, b:3, c:1
  c 的频率 < 2, c 在位置 5
  → 分割: helper("ababb", 0, 5) 和 helper("", 6, 6)
  
  第2层: helper("ababb", 0, 5)
    频率: a:2, b:3
    所有频率 >= 2 → 返回长度 5 ✓
  
  第2层: helper("", 6, 6)
    6 - 6 = 0 < 2 → 返回 0
  
  max(5, 0) = 5 → 返回 5
```

```cpp
class Solution {
public:
    int longestSubstring(string s, int k) {
        return helper(s, 0, s.size(), k);
    }
    
    int helper(const string& s, int start, int end, int k) {
        // 子串长度 < k，不可能满足条件
        if (end - start < k) return 0;
        
        // 统计当前子串的字符频率
        int freq[26] = {};
        for (int i = start; i < end; i++) {
            freq[s[i] - 'a']++;
        }
        
        // 找第一个频率 < k 的字符作为分割点
        for (int i = start; i < end; i++) {
            if (freq[s[i] - 'a'] < k) {
                // 跳过连续的"坏"字符
                int j = i + 1;
                while (j < end && freq[s[j] - 'a'] < k) j++;
                // 递归处理分割后的左右两段
                return max(helper(s, start, i, k),
                           helper(s, j, end, k));
            }
        }
        
        // 所有字符频率都 >= k，当前子串就是答案
        return end - start;
    }
};
```

**关键点**:
- 跳过连续的坏字符：`while (j < end && freq[s[j] - 'a'] < k) j++;` 这一步很重要，避免对单个坏字符创建无效的空递归。
- 只需要找**第一个**坏字符分割。因为左半部分递归时，如果还有坏字符，会继续分割。
- 递归深度有限：每层至少消除一种坏字符，最多 26 层。

### 解法2: 滑动窗口变体 — O(26n) / O(1)

**思考过程**: 标准滑窗不可行（缺少收缩条件）。关键创新：枚举"窗口内恰好有 t 种不同字符"（t = 1, 2, ..., 26）。对于固定的 t，可以用标准滑窗。

**为什么固定不同字符数后滑窗就可行了？**
- 维护两个计数：`unique`（窗口内不同字符总数）、`atLeastK`（频率 >= k 的字符数）
- **扩展右边界**：right 右移，更新 unique 和 atLeastK
- **收缩条件**：`unique > t` 时收缩左边界
- **合法窗口**：`unique == t && atLeastK == t`（恰好 t 种不同字符，且每种频率都 >= k）

```
示例: s = "ababbc", k = 2, t = 2

right=0 (a): unique=1, atLeastK=0 → 继续扩展
right=1 (b): unique=2, atLeastK=0 → 继续扩展
right=2 (a): unique=2, atLeastK=1 (a:2>=2) → 继续扩展
right=3 (b): unique=2, atLeastK=2 (a:2,b:2) → 合法！长度=4
right=4 (b): unique=2, atLeastK=2 (a:2,b:3) → 合法！长度=5
right=5 (c): unique=3 > t=2 → 收缩
  left=0→1: 去掉 a, a:1<2, atLeastK=1, unique=3
  left=1→2: 去掉 b, b:2, unique=2 → 停止收缩
  unique=2, atLeastK=1 → 不合法
  
t=2 的最大长度 = 5
```

```cpp
class Solution {
public:
    int longestSubstring(string s, int k) {
        int n = s.size();
        int result = 0;
        
        // 枚举窗口内不同字符的数量 t
        for (int t = 1; t <= 26; t++) {
            int freq[26] = {};
            int left = 0;
            int unique = 0;     // 窗口内不同字符数
            int atLeastK = 0;   // 窗口内频率 >= k 的字符数
            
            for (int right = 0; right < n; right++) {
                int idx = s[right] - 'a';
                if (freq[idx] == 0) unique++;
                freq[idx]++;
                if (freq[idx] == k) atLeastK++;
                
                // 收缩：当不同字符数超过 t 时
                while (unique > t) {
                    int lidx = s[left] - 'a';
                    if (freq[lidx] == k) atLeastK--;
                    freq[lidx]--;
                    if (freq[lidx] == 0) unique--;
                    left++;
                }
                
                // 检查当前窗口是否合法
                if (unique == t && atLeastK == t) {
                    result = max(result, right - left + 1);
                }
            }
        }
        
        return result;
    }
};
```

**关键点**:
- 外层 `t` 从 1 到 26（最多 26 种小写字母），每次内层滑窗 O(n)，总共 O(26n)。
- 双计数维护：`unique` 追踪不同字符总数，`atLeastK` 追踪满足条件的字符数。当两者相等且都等于 t，说明窗口内所有字符频率都 >= k。
- `freq[idx] == k` 和 `freq[lidx] == k` 是关键的边界判断——恰好到达或离开 k 时更新 `atLeastK`。

## 解法对比

|  | 分治递归 | 滑动窗口变体 |
|--|---------|-------------|
| 时间 | O(26n) | O(26n) |
| 空间 | O(26) 递归栈 | O(1) |
| 代码复杂度 | 简单直觉 | 中等（需要理解枚举 t 的技巧） |
| 面试推荐 | ⭐ 首选 | 作为 follow-up 或加分项 |

## 易错点

1. **分治时忘记跳过连续坏字符**：
   - ✗ 直接对每个坏字符位置都递归 → 产生大量空段，虽然结果正确但效率差
   - ✓ `while (j < end && freq[s[j] - 'a'] < k) j++;` 跳过连续坏字符

2. **递归边界搞混**：
   - ✗ `helper(s, start, i - 1, k)` → 如果用闭区间，容易出错
   - ✓ 统一用左闭右开 `[start, end)` → `helper(s, start, i, k)` 和 `helper(s, j, end, k)`

3. **滑窗中 atLeastK 的更新时机**：
   - ✗ 在 `freq[idx]++` 之前检查 `freq[idx] == k` → 逻辑错误
   - ✓ 先 `freq[idx]++`，然后检查 `freq[idx] == k`（刚好到达 k）

4. **滑窗中 unique 的更新顺序**：
   - 扩展时：先检查 `freq[idx] == 0`（还没出现过），再 `freq[idx]++`
   - 收缩时：先 `freq[lidx]--`，再检查 `freq[lidx] == 0`（消失了）

5. **特殊情况 k = 1**：
   - 任何非空字符串的所有字符频率都 >= 1 → 答案就是整个字符串长度
   - 分治解法自动处理（没有坏字符，直接返回全长）

## 面试追问

**Q1: 分治的时间复杂度怎么严格证明是 O(26n)？**
> 每层递归扫描当前子串 O(len)，且至少淘汰一种字符。最多 26 种字符，所以最多 26 层。每层所有递归分支的子串长度总和 <= n。总复杂度 26 * n = O(n)。

**Q2: 为什么不能直接用标准滑动窗口？**
> 标准滑窗需要单调性：窗口扩大时某个量单调变化，或者有明确的收缩条件。"所有字符频率 >= k"没有这种单调性——加入一个新字符可能让某些字符频率达标但降低另一些。固定不同字符数 t 后就有了单调性。

**Q3: 如果字符集不是26个字母而是任意 Unicode，复杂度怎么变？**
> 分治：递归深度变成 O(|charset|)，总复杂度 O(|charset| * n)。滑窗：外层枚举变成 O(|charset|)，总复杂度相同。对于大字符集，分治通常更好（实际递归深度取决于字符串中出现的不同字符数，不是字符集大小）。

**Q4: 能否用前缀和或者其他数据结构优化？**
> 前缀和可以在 O(1) 内查询子串内每个字符的频率，但枚举子串本身是 O(n^2)。不如分治/滑窗。可以用前缀和配合二分搜索做一些优化，但复杂度不会低于 O(n log n)，不如分治。
