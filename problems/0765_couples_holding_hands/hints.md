# 765. 情侣牵手 (Couples Holding Hands)

## 难度: Hard | 标签: Greedy, Union Find, Graph

---

## 核心思路

n 对情侣坐在 2n 个座位上，每对情侣的编号为 `(2k, 2k+1)`。我们需要用**最少的交换次数**让每对情侣都坐在相邻的一对座位上（即位置 0-1、2-3、4-5...）。

关键洞察：**每次交换修复一对座位**。从左到右扫描每对座位 `(0,1), (2,3), ...`，如果当前这对座位上的两个人不是情侣，就把正确的伴侣交换过来。这个贪心策略可以证明是最优的。

## 思维链

1. **读完题第一反应** → 这是一个排列/交换最小化的问题。可能涉及贪心或图论（置换环）。
2. **情侣编号的数学规律** → 编号 `x` 的伴侣是 `x ^ 1`（异或 1）。偶数找奇数、奇数找偶数：`0↔1, 2↔3, 4↔5, ...`。这个异或技巧是核心。
3. **贪心思路** → 从左到右，两个座位两个座位地检查。如果 `row[0]` 和 `row[1]` 不是情侣，就找到 `row[0]` 的伴侣在哪个位置，交换到 `row[1]`。修复一对后继续看下一对。
4. **为什么贪心是最优的？** → 每次交换至少修复了当前这一对座位，并且不会破坏任何已经修复的座位（因为我们是从左到右处理的，被交换走的人来自右边尚未处理的座位）。一对不匹配的座位至少需要一次交换，所以贪心给出的就是最小次数。
5. **并查集视角** → 把每对座位看作一个"位置节点"，把每对情侣看作一个"关系边"。如果一个连通分量包含 k 对座位，那么需要 k-1 次交换来解开（类似置换环，环长 k 需要 k-1 次交换）。总交换次数 = n - 连通分量数。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 贪心交换 | 逐对修复，O(1) 找伴侣 | O(n) | O(n) | ⭐ 面试首选，直觉简单 |
| 并查集 | 环/连通分量建模 | O(n * alpha) | O(n) | 进阶讨论，展示图论思维 |

## 关键提示

1. **伴侣编号规则**：编号 `x` 的伴侣是 `x ^ 1`（异或 1）。这利用了情侣编号为 `(0,1), (2,3), (4,5)...` 的特性——偶数异或 1 得到下一个奇数，奇数异或 1 得到上一个偶数。
2. **用位置数组加速查找**：`pos[person] = seat_index`，这样查找伴侣的位置只需要 O(1)，避免了每次线性扫描。
3. **交换时更新位置数组**：交换两个人的座位后，别忘了同步更新 `pos` 数组。这是容易出错的地方。
4. **贪心的正确性证明**：修复当前一对座位时，被换走的人去了右边（尚未处理的区域），所以不会破坏已修复的对。而且每次交换刚好修复一对，最优。
5. **并查集建模方式**：初始化 n 个连通分量（每对座位一个）。对于位置 `2i` 和 `2i+1` 上的两个人 `a` 和 `b`，他们的"情侣组"分别是 `a/2` 和 `b/2`，执行 `union(a/2, b/2)`。最终答案 = n - 连通分量数。

## 解法详解

### 解法1: 贪心交换 — O(n) / O(n) ⭐ 面试首选

**思考过程**: 每次只关注当前的一对座位，把不对的伴侣换过来。

```
示例: row = [0, 2, 1, 3]

  座位:   [0] [1] [2] [3]
  人ID:    0   2   1   3

  检查座位 0-1: 人0的伴侣是 0^1=1, 但座位1上是2 (不是1)
    → 找到人1在座位2, 交换 row[1] 和 row[2]
    → row 变为 [0, 1, 2, 3]
    → swaps = 1

  检查座位 2-3: 人2的伴侣是 2^1=3, 座位3上是3 ✓
    → 不需要交换

  结果: 1 次交换
```

```cpp
class Solution {
public:
    int minSwapsCouples(vector<int>& row) {
        int n = row.size();
        vector<int> pos(n);
        for (int i = 0; i < n; i++) pos[row[i]] = i;

        int swaps = 0;
        for (int i = 0; i < n; i += 2) {
            int partner = row[i] ^ 1;
            if (row[i + 1] != partner) {
                int j = pos[partner];
                pos[row[i + 1]] = j;
                pos[partner] = i + 1;
                swap(row[i + 1], row[j]);
                swaps++;
            }
        }
        return swaps;
    }
};
```

**关键点**:
- `pos` 数组建立"人 → 座位"的映射，支持 O(1) 找人。
- 交换时同时更新 `pos` 和 `row`，保持两者一致。
- 时间复杂度 O(n)：虽然外层循环是 n/2 次，每次交换也是 O(1)。

---

### 解法2: 并查集 — O(n * alpha) / O(n)

**思考过程**: 将问题建模为图论。每对座位形成一个"位置组"，每对情侣形成一个"关系"。如果两对不同的情侣混在一起，它们形成一个"环"，需要环长-1次交换来解开。

```
示例: row = [0, 2, 1, 3]

  座位 0-1 上: 人0 (情侣组0) 和 人2 (情侣组1)
    → union(0, 1)  // 情侣组0 和 情侣组1 被连在一起

  座位 2-3 上: 人1 (情侣组0) 和 人3 (情侣组1)
    → union(0, 1)  // 已经在同一组

  连通分量数 = 1 (只有一个大组 {0,1})
  n = 2 对
  答案 = 2 - 1 = 1 ✓
```

```
更复杂的示例: row = [5, 4, 2, 6, 3, 1, 0, 7]
  4对情侣: (0,1) (2,3) (4,5) (6,7)
  
  座位 0-1: 人5(组2) 和 人4(组2) → union(2,2) → 已是情侣，不增加交换
  座位 2-3: 人2(组1) 和 人6(组3) → union(1,3)
  座位 4-5: 人3(组1) 和 人1(组0) → union(1,0) → 现在 {0,1,3} 在一起
  座位 6-7: 人0(组0) 和 人7(组3) → union(0,3) → 已在同一组

  连通分量: {2} 和 {0,1,3} → 共 2 个
  答案 = 4 - 2 = 2
```

---

## 易错点

1. **异或技巧忘记了**：`x ^ 1` 才是伴侣，不是 `x + 1` 或 `x - 1`。比如人 3 的伴侣是 `3^1=2`，不是 4。
2. **pos 数组更新遗漏**：交换 `row[i+1]` 和 `row[j]` 后，必须同时更新 `pos[row[i+1]]` 和 `pos[partner]`。漏掉任何一个都会导致后续查找错误。
3. **并查集的建模方式**：是对"情侣组"（即 `person/2`）做并查集，不是对人或座位做并查集。初始有 n 个连通分量（n = row.size()/2）。
4. **边界情况**：当 row 只有 2 个元素时，只需检查这一对。

## 面试追问递进链

1. **"请证明贪心是最优的"** → 每对不匹配的座位至少需要一次交换。贪心每次交换恰好修复一对且不破坏已修复的，所以恰好是最小次数。
2. **"用并查集怎么解释？"** → 置换环理论：k 个元素的环需要 k-1 次交换来归位。总交换 = 总对数 - 连通分量数。
3. **"如果座位不是连续的而是任意配对呢？"** → 贪心思路不变，但需要额外的映射来确定哪些座位是一对。
4. **"如果要输出交换序列呢？"** → 贪心法中记录每次交换的 `(i+1, j)` 即可。

## 复杂度分析

| 解法 | 时间 | 空间 | 说明 |
|------|------|------|------|
| 贪心交换 | O(n) | O(n) | n = row.size()，一次建表 + 一次扫描 |
| 并查集 | O(n * alpha(n)) | O(n) | alpha 是反 Ackermann，几乎 O(1) |
