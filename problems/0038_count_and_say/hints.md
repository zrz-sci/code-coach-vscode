# 38. 外观数列 (Count and Say)

## 核心思路

这道题本质上就是**模拟**：从 `"1"` 开始，重复执行"行程长度编码 (RLE)"操作 `n-1` 次，每次把当前字符串中**连续相同的字符**压缩成"计数+字符"的形式，得到下一个字符串。

## 思维链

1. **读完题第一反应**：这是一个递推序列，第 n 项由第 n-1 项通过某种变换得到。最直觉的做法就是按定义模拟——先算出第 1 项，再算第 2 项，一直算到第 n 项。

2. **核心操作是什么？** 每一步的核心操作是"行程长度编码"——遍历字符串，把连续相同字符分组，每组输出"个数+字符"。

3. **有没有更高效的做法？** 由于第 n 项**必须**依赖第 n-1 项的完整内容，无法跳步计算（数学上没有已知的封闭公式），所以只能逐步模拟。优化空间有限，重点在于**如何高效地写出 RLE 的一次操作**。

4. **递归 vs 迭代**：递归写法更贴合定义 `countAndSay(n) = RLE(countAndSay(n-1))`；迭代写法用循环从第 1 项推到第 n 项，省去递归栈开销。两者本质相同。

5. **RLE 的实现要点**：双指针扫描连续相同字符——用一个指针 `i` 标记当前组起点，另一个指针 `j` 向右找到第一个不同字符，则这组长度为 `j - i`，字符为 `s[i]`。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 递归模拟 | 按定义递归，base case 返回 "1" | O(n × L) | O(n × L)（递归栈+字符串） | 能说出即可 |
| 迭代模拟 | 循环 n-1 次，每次做一遍 RLE | O(n × L) | O(L) | ⭐ 必须写出 |

> 其中 L 是第 n 项字符串的长度。n ≤ 30 时 L 最大约 5000+，不会超时。

## 关键提示

1. **先手动推几项**，确保理解规则：
   ```
   n=1: "1"
   n=2: "11"       ← 1个1
   n=3: "21"       ← 2个1
   n=4: "1211"     ← 1个2, 1个1
   n=5: "111221"   ← 1个1, 1个2, 2个1
   n=6: "312211"   ← 3个1, 2个2, 1个1
   ```

2. **RLE 的关键**：用双指针找出每组连续相同字符的起止位置，组长度 = `j - i`。

3. **递归 vs 迭代**：递归更直观，但题目 Follow-up 问能否迭代——用一个 for 循环从 1 推到 n 即可。

4. **字符串拼接效率**：C++ 中 `string += ...` 的均摊复杂度是 O(1)，不需要额外优化。如果用 Java/Python 考虑 StringBuilder。

5. **边界**：`n = 1` 时直接返回 `"1"`，不需要做任何 RLE 操作。

## 解法详解

### 解法1: 递归模拟 — O(n × L) / O(n × L)

**思考过程**：题目定义就是递归的——`countAndSay(n) = RLE(countAndSay(n-1))`，最自然的写法就是按定义递归。

```cpp
class Solution {
public:
    string countAndSay(int n) {
        // base case: 第1项就是 "1"
        if (n == 1) return "1";
        
        // 先递归拿到第 n-1 项
        string prev = countAndSay(n - 1);
        
        // 对 prev 做一次行程长度编码
        string result;
        int i = 0;
        while (i < prev.size()) {
            int j = i;
            // j 向右扫描，找到第一个和 prev[i] 不同的位置
            while (j < prev.size() && prev[j] == prev[i]) {
                j++;
            }
            // 这组有 (j - i) 个 prev[i]
            result += to_string(j - i);  // 计数
            result += prev[i];            // 字符
            i = j;  // 跳到下一组
        }
        return result;
    }
};
```

**关键点**：
- 递归深度为 n（最多 30），不会栈溢出。
- 每层递归都会创建新字符串，空间是 O(n × L)。

---

### 解法2: 迭代模拟 — O(n × L) / O(L) ⭐ 面试首选

**从解法1优化**：递归的 n 层调用栈可以用一个 for 循环替代。我们只需要维护"当前项"的字符串，每次原地更新为下一项。

```
迭代过程（n=5）：
Step1: curr = "1"
Step2: RLE("1")    → "11"       (1个1)
Step3: RLE("11")   → "21"       (2个1)  
Step4: RLE("21")   → "1211"     (1个2, 1个1)
Step5: RLE("1211") → "111221"   (1个1, 1个2, 2个1)
返回 "111221"
```

```cpp
class Solution {
public:
    string countAndSay(int n) {
        string curr = "1";  // 第1项
        
        // 从第2项推到第n项，共做 n-1 次 RLE
        for (int step = 2; step <= n; step++) {
            string next;
            int i = 0;
            while (i < curr.size()) {
                int j = i;
                // 找连续相同字符的右边界
                while (j < curr.size() && curr[j] == curr[i]) {
                    j++;
                }
                // 拼接: "计数" + "字符"
                next += to_string(j - i);
                next += curr[i];
                i = j;
            }
            curr = next;  // 更新为下一项
        }
        
        return curr;
    }
};
```

**关键点**：
- 只需保存"当前项"和"下一项"两个字符串，空间 O(L)。
- 循环从 `step = 2` 开始，因为第 1 项已经初始化好了。

## 解法对比

| | 递归 | 迭代 |
|---|---|---|
| 代码风格 | 更贴合数学定义，易理解 | 更工程化，省栈空间 |
| 空间 | O(n × L)（递归栈） | O(L)（只保留当前项） |
| 面试推荐 | 先讲思路时用 | 写代码时用 |
| 本质 | 完全相同，都是做 n-1 次 RLE |  |

## 易错点

1. **循环次数写错**：
   - ✗ `for (int step = 1; step <= n; step++)` — 多做了一次，第 1 项不需要 RLE
   - ✓ `for (int step = 2; step <= n; step++)` — 从第 2 项开始，共 n-1 次

2. **RLE 中忘记移动 i**：
   - ✗ 内层 while 结束后没有 `i = j`，导致死循环
   - ✓ 每次处理完一组后 `i = j` 跳到下一组起点

3. **计数和字符的顺序搞反**：
   - ✗ `next += curr[i]; next += to_string(j - i);` — 先字符后计数
   - ✓ `next += to_string(j - i); next += curr[i];` — 先计数后字符（"2个1" → "21"）

4. **n = 1 时未特殊处理**（迭代版其实不需要，因为循环不会执行；但递归版需要 base case）

## 面试追问

**Q1: 请描述这道题的核心操作是什么？**
→ 行程长度编码 (RLE)：遍历字符串，将连续相同字符压缩为"计数+字符"。整道题就是从 "1" 开始重复做 n-1 次 RLE。

**Q2: 能否用迭代替代递归？有什么好处？**（题目 Follow-up）
→ 可以。用 for 循环从第 1 项推到第 n 项。好处是省去 O(n) 的递归栈空间，且代码更清晰，不用担心栈溢出（虽然 n ≤ 30 不会溢出）。

**Q3: 第 n 项的长度增长有什么规律？n 很大时会不会超时？**
→ 外观数列的长度增长率趋近于常数 λ ≈ 1.303577...(Conway 常数)。即第 n 项长度约为 λ^n。n = 30 时长度约 5000+，完全可以接受。但如果 n 无限制增长，字符串会指数级增长。

**Q4: 如果要优化字符串拼接的性能，怎么做？**
→ C++ 中 `string +=` 已经足够高效（均摊 O(1)）。在 Java 中用 `StringBuilder`，Python 中用列表 `append` 后 `''.join()`，避免频繁创建新字符串对象。
