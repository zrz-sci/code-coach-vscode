# 406. 根据身高重建队列

## 核心思路

本题本质上是一个**排序+贪心插入**问题：通过精心设计处理顺序（先高后矮），让每个人插入时只需关注 `k` 值，因为后续插入的矮个子不会影响高个子的 `k` 值。

## 思维链

1. **读完题第一反应**：每个人有两个属性 `[h, k]`，需要找到一种排列使得每个人前面恰好有 `k` 个身高 ≥ h 的人。暴力做法：全排列然后验证？n! 太爆炸了。

2. **换个角度想**：能不能一个一个地把人放到正确位置？关键问题是"按什么顺序放"——如果先放矮的人，后面放高个子时会打乱矮个子的 `k` 值；**如果先放高的人呢？** 矮个子后来插入时，对高个子来说"不可见"（矮的人不会被高的人计入 `k`），所以高个子的位置不会被影响！

3. **贪心策略成型**：按身高从高到矮排序。对于同身高的人，`k` 小的排前面（因为 k 小的要求前面更少的高个子）。然后依次把每个人插入到结果数组的第 `k` 个位置。

4. **为什么这样是对的？** 当我们插入 `[h, k]` 时，结果数组中已有的人身高都 ≥ h，所以插入到位置 `k` 恰好保证前面有 `k` 个身高 ≥ h 的人。后续插入的人身高 ≤ h，不会影响已插入人的 `k` 值。

5. **瓶颈在哪？** 每次 `insert` 到 vector 中间是 O(n)，总共 O(n²)。能否用更高效的数据结构？可以用**树状数组/线段树**维护空位，实现 O(n log n)。

6. **另一个思路**：反过来，按身高从矮到高处理。矮个子先占位，`k` 值代表"前面要留多少空位给后来的高个子"。用线段树/树状数组找第 `(k+1)` 个空位，直接放入。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 贪心插入（高→矮） | 按身高降序排序，依次插入第 k 位 | O(n²) | O(n) | ⭐ 必须写出 |
| 贪心占位（矮→高） | 按身高升序排序，用空位计数放置 | O(n²) | O(n) | 能说出即可 |
| 树状数组/线段树优化 | 矮→高 + 二分找第 k 个空位 | O(n log n) | O(n) | 加分项 |

## 关键提示

1. **想一想处理顺序**：如果我们先安排最高的人，后来插入的矮个子会影响他们的 `k` 值吗？为什么不会？

2. **排序的细节**：身高相同时，`k` 的排序顺序在"高→矮"和"矮→高"两种策略中是**相反**的，想想为什么。

3. **插入位置的含义**：在"高→矮"策略中，结果数组中已有的全是比当前人高（或同高）的人，所以位置 `k` 就是最终位置。

4. **可视化排序后的处理过程**：
```
排序后: [7,0] [7,1] [6,1] [5,0] [5,2] [4,4]

Step1: 插入[7,0]到位置0 → [[7,0]]
Step2: 插入[7,1]到位置1 → [[7,0],[7,1]]
Step3: 插入[6,1]到位置1 → [[7,0],[6,1],[7,1]]
Step4: 插入[5,0]到位置0 → [[5,0],[7,0],[6,1],[7,1]]
Step5: 插入[5,2]到位置2 → [[5,0],[7,0],[5,2],[6,1],[7,1]]
Step6: 插入[4,4]到位置4 → [[5,0],[7,0],[5,2],[6,1],[4,4],[7,1]] ✓
```

5. **"矮→高"策略的思路**：对于矮个子来说，他不知道后面会来谁（都比他高），但他知道前面要留 `k` 个空位。所以找到第 `(k+1)` 个空位放入即可。

## 解法详解

### 解法1: 贪心插入（高→矮排序） — O(n²) / O(n) ⭐ 面试首选

**思考过程**：

核心洞察：**矮个子对高个子是"透明"的**。一个身高为 7 的人只关心前面有几个 ≥7 的人，身高为 4 或 5 的人对他来说"不存在"。所以如果我们先把高个子排好，后续插入矮个子不会破坏高个子的有效性。

排序规则：
- 身高**降序**：先处理高的
- 身高相同时 k 值**升序**：k 小的先插，因为 k 大的后插到更后面不会影响 k 小的

```cpp
class Solution {
public:
    vector<vector<int>> reconstructQueue(vector<vector<int>>& people) {
        // 排序：身高降序，同身高 k 升序
        sort(people.begin(), people.end(), [](const vector<int>& a, const vector<int>& b) {
            return a[0] > b[0] || (a[0] == b[0] && a[1] < b[1]);
        });
        
        vector<vector<int>> result;
        for (auto& p : people) {
            // 插入到位置 p[1]
            // 此时 result 中所有人身高 >= p[0]，所以位置 k 就是正确位置
            result.insert(result.begin() + p[1], p);
        }
        return result;
    }
};
```

**关键点**：
- `insert` 的位置就是 `k` 值，因为此时数组里全是 ≥ 当前身高的人
- 同身高 k 升序保证 `[7,0]` 先于 `[7,1]` 插入，否则 `[7,1]` 会被挤到位置 2

### 解法2: 贪心占位（矮→高排序） — O(n²) / O(n)

**从另一个方向思考**：矮个子先选位置。对于 `[h, k]`，他知道后面还会来一些比他高的人，这些人会占据他前面的某些位置。所以他需要前面有 `k` 个空位（留给未来的高个子），自己占据第 `(k+1)` 个空位。

排序规则（与解法1相反）：
- 身高**升序**：先处理矮的
- 身高相同时 k 值**降序**：同身高中 k 大的先放（放到更后面的空位），不影响 k 小的

```cpp
class Solution {
public:
    vector<vector<int>> reconstructQueue(vector<vector<int>>& people) {
        // 排序：身高升序，同身高 k 降序
        sort(people.begin(), people.end(), [](const vector<int>& a, const vector<int>& b) {
            return a[0] < b[0] || (a[0] == b[0] && a[1] > b[1]);
        });
        
        int n = people.size();
        vector<vector<int>> result(n);
        
        for (auto& p : people) {
            // 找到第 (p[1]+1) 个空位
            int spaces = 0;
            for (int i = 0; i < n; i++) {
                if (result[i].empty()) {
                    spaces++;
                    if (spaces == p[1] + 1) {
                        // 这就是当前人的位置
                        // 前面有 p[1] 个空位会被后续更高的人填充
                        result[i] = p;
                        break;
                    }
                }
            }
        }
        return result;
    }
};
```

**为什么 k 代表空位数？** 当前人身高最矮（或之一），后续所有人都 ≥ 他。这些后来者会填入空位。所以前面留 `k` 个空位 = 最终前面会有 `k` 个 ≥ h 的人。

### 解法3: 树状数组优化（矮→高 + 二分查找空位） — O(n log² n) / O(n)

**从解法2的瓶颈出发**：解法2中"找第 k+1 个空位"需要线性扫描 O(n)，总体 O(n²)。如果用**树状数组**维护前缀空位数，就能用**二分查找**在 O(log²n) 内找到第 k+1 个空位。

树状数组维护的是：每个位置是否为空（1=空，0=已占）。前缀和 `query(i)` = 位置 0~i 中空位的数量。要找前缀和 = k+1 的最小 i，用二分搜索。

```cpp
class Solution {
public:
    vector<int> tree;
    int n;
    
    void update(int i, int val) {
        for (i++; i <= n; i += i & (-i))
            tree[i] += val;
    }
    
    int query(int i) {
        int sum = 0;
        for (i++; i > 0; i -= i & (-i))
            sum += tree[i];
        return sum;
    }
    
    // 二分查找：前缀和 >= target 的最小下标
    int findKth(int target) {
        int lo = 0, hi = n - 1;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (query(mid) >= target)
                hi = mid;
            else
                lo = mid + 1;
        }
        return lo;
    }
    
    vector<vector<int>> reconstructQueue(vector<vector<int>>& people) {
        n = people.size();
        tree.assign(n + 1, 0);
        
        // 初始化：所有位置为空 (值=1)
        for (int i = 0; i < n; i++)
            update(i, 1);
        
        // 身高升序，同身高 k 降序
        sort(people.begin(), people.end(), [](const vector<int>& a, const vector<int>& b) {
            return a[0] < b[0] || (a[0] == b[0] && a[1] > b[1]);
        });
        
        vector<vector<int>> result(n);
        for (auto& p : people) {
            // 找第 (k+1) 个空位
            int pos = findKth(p[1] + 1);
            result[pos] = p;
            update(pos, -1);  // 标记为已占
        }
        return result;
    }
};
```

**进一步优化**：可以在树状数组上直接做"树上二分"避免外层二分，达到 O(n log n)。但面试中 O(n log²n) 已经足够。

| | 解法1: 高→矮插入 | 解法2: 矮→高占位 | 解法3: 树状数组 |
|---|---|---|---|
| 排序方向 | 身高降序，k升序 | 身高升序，k降序 | 同解法2 |
| 核心操作 | vector::insert | 线性找空位 | 二分找空位 |
| 时间 | O(n²) | O(n²) | O(n log²n) |
| 空间 | O(n) | O(n) | O(n) |
| 代码量 | 最少，8行核心 | 中等 | 较多 |
| 面试推荐 | ⭐ 首选 | 理解即可 | 追问优化时给 |

**什么时候选哪个？**
- 面试：解法1，代码短、思路清晰、好解释
- 追问 O(n log n)：解法3
- 解法2 的价值：展示"同一问题可以从两个方向思考"的能力

## 易错点

1. **同身高排序方向搞反**
   - ✗ 高→矮策略中同身高按 k **降序**：`[7,1]` 先插入位置1，`[7,0]` 再插入位置0 → `[[7,0],[7,1]]` 看起来对，但如果有更多同高的就会出错
   - ✓ 高→矮策略中同身高按 k **升序**：先插 `[7,0]`，再插 `[7,1]`，`[7,1]` 插入位置1时前面恰好有1个≥7的人
   - 原因：同身高互相"可见"（≥ h 不是 > h），k 小的必须先占位

2. **两种策略的排序规则混淆**
   - ✗ 矮→高策略中同身高按 k **升序**：`[5,0]` 先放到第1个空位，`[5,2]` 再放到第3个空位。但 `[5,0]` 占了一个位，`[5,2]` 前面只剩1个空位 + `[5,0]` 本身 = 2，看似正确？实际上同身高应该**降序**，让 k 大的先放（不会影响 k 小的）
   - ✓ 矮→高策略中同身高按 k **降序**

3. **vector::insert 的位置理解错误**
   - `result.insert(result.begin() + k, person)` 是在位置 k **之前**插入，插入后该元素位于下标 k

4. **树状数组下标从0还是从1**
   - 树状数组内部通常 1-indexed，但对外接口可以是 0-indexed，注意 `i++` 的转换

## 面试追问

**Q1: 解释一下你的贪心策略为什么是正确的？**
> 按身高降序插入时，每次插入的人是当前最矮的（或之一）。已在数组中的人身高都 ≥ 当前人，所以当前人插入到位置 k 时，前面恰好有 k 个 ≥ h 的人。后续插入的人身高 ≤ 当前人，虽然会改变数组元素的位置，但对于已插入的人来说，后续矮个子"不被计入" k（因为 k 统计的是 ≥ h 的人），所以不影响正确性。

**Q2: 当前解法是 O(n²)，能优化到 O(n log n) 吗？**
> 瓶颈在 `vector::insert` 是 O(n)。可以用解法2的"矮→高"思路，将"找第 k 个空位"用树状数组+二分优化到 O(log²n)。或者用链表优化插入为 O(1)，但查找位置仍需 O(n)。真正的 O(n log n) 需要树状数组上直接做树上二分。

**Q3: 如果改为"前面恰好有 k 个身高**严格大于** h 的人"，排序规则需要怎么改？**
> 高→矮策略中，同身高的人互相"不可见"了（严格大于才计入 k）。此时同身高应该按 k **降序**（与原题相反），因为 k 大的要在更后面，而同身高之间不互相影响，先插 k 大的不会干扰 k 小的。
