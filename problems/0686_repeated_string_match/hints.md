# 686. Repeated String Match - 重复叠加字符串匹配

## 难度：Medium

## 标签：String, String Matching, KMP, Rabin-Karp

---

## 核心思路

将字符串 a 不断重复拼接，直到总长度足以"容纳" b 作为子串。关键观察是：b 最多横跨 `ceil(len(b)/len(a))` 个完整的 a，加上首尾各可能横跨一个 a 的边界，因此最多需要 `ceil(len(b)/len(a)) + 1` 次重复。超过这个上界仍找不到就返回 -1。进阶可用 KMP 或 Rabin-Karp 在虚拟的无限重复串上做线性匹配。

---

## 思维链

1. b 要成为 a 重复后的子串，b 的每个字符都必须能在 a 中找到对应 → 先做字符集检查可以提前返回 -1。
2. 假设 b 的长度为 m，a 的长度为 n。b 作为子串出现在 `a...a` 中时，b 的起始位置在某个 a 的中间，结束位置在另一个 a 的中间。
3. b 中间完整跨越的 a 的个数约为 `(m - n) / n`（可能为 0），加上首尾两个不完整的 a，总共约 `ceil(m/n) + 1` 个 a 就够了。
4. 所以算法是：先重复 a 到总长 >= m，检查 b 是否为子串；若不是，再多拼一个 a 再检查。
5. 进阶：不真正构造重复字符串，而是在"虚拟无限重复的 a"上用 KMP/Rabin-Karp 做匹配，通过 `index % n` 访问字符。

---

## 解法概览

| 解法 | 时间 | 空间 | 特点 |
|------|------|------|------|
| 暴力重复 + find | O((n+m) * m) 最坏 | O(n * ceil(m/n)) | 最简单直观 |
| KMP 在虚拟串上匹配 | O(n + m) | O(m) | 线性时间，不构造重复串 |
| Rabin-Karp 滚动哈希 | O(n + m) 期望 | O(1) 额外 | 哈希冲突可能退化 |

---

## 关键提示

### 提示 1 - 确定重复次数的上下界
最少需要重复 `ceil(m/n)` 次才能让总长度 >= m。最多再加 1 次处理 b 跨越 a 边界的情况。因此答案要么在 `[ceil(m/n), ceil(m/n)+1]` 范围内，要么不存在。

### 提示 2 - 字符集剪枝
如果 b 中存在 a 中没有的字符，无论重复多少次都不可能包含 b，直接返回 -1。这个 O(n+m) 的预检查在大量测试用例中能显著加速。

### 提示 3 - 为什么最多多加一次
考虑 b 在重复串中的位置：b 的开头最多"吃掉"一个 a 的尾部，b 的结尾最多"吃掉"一个 a 的头部，中间是完整的 a 的重复。所以 `ceil(m/n)` 个 a 覆盖中间部分，再加 1 个 a 覆盖边界跨越。

### 提示 4 - KMP 虚拟匹配
不需要真正拼接字符串。在 KMP 匹配过程中，文本串的第 i 个字符用 `a[i % n]` 获取。文本串的搜索长度上限为 `n * (ceil(m/n) + 1)`，匹配成功时根据匹配结束位置计算需要多少次重复。

### 提示 5 - Rabin-Karp 的哈希碰撞处理
使用滚动哈希时，当窗口哈希与目标哈希相等时需要逐字符验证。用双模数可以将碰撞概率降到极低。

---

## 解法详解

### 解法一：暴力重复 + 子串查找

1. 计算 `minRepeats = ceil(m / n) = (m + n - 1) / n`
2. 将 a 重复 minRepeats 次得到 `repeated`
3. 在 `repeated` 中查找 b：
   - 找到 → 返回 minRepeats
   - 没找到 → 再拼接一个 a，再查找
     - 找到 → 返回 minRepeats + 1
     - 没找到 → 返回 -1

### 解法二：KMP 线性匹配

1. 对 b 构建 KMP 的 failure/next 数组（部分匹配表）
2. 在虚拟的无限重复 a 上做 KMP 匹配：
   - 文本字符：`text[i] = a[i % n]`
   - 搜索范围：`i` 从 0 到 `n * (ceil(m/n) + 1) - 1`
3. 匹配成功时，b 的结束位置为 i，起始位置为 `i - m + 1`
4. 需要的重复次数为 `i / n + 1`

### 解法三：Rabin-Karp 滚动哈希

1. 预计算 b 的哈希值 hashB
2. 在虚拟重复串上维护长度为 m 的滑动窗口哈希
3. 窗口哈希等于 hashB 时逐字符验证
4. 验证通过则根据窗口结束位置计算重复次数

---

## 易错点

1. **整数除法上取整**：`ceil(m/n)` 应写成 `(m + n - 1) / n`，不要用浮点除法再 ceil，可能有精度问题。
2. **只加一次不够？多加两次？**：数学上最多只需要多加 1 次。如果加了 2 次仍未找到则必然不存在。有些人为了保险多加，但只会浪费时间。
3. **空字符串边界**：题目保证 a 和 b 非空，但面试中要确认这一点。
4. **Rabin-Karp 的取模溢出**：使用 `long long` 且每步取模。减法可能产生负数，需要加 MOD 再取模。
5. **KMP next 数组构建**：注意 next[0] = -1 或 0 的定义差异，与主循环的写法要配套。
6. **返回的是重复次数，不是子串位置**：匹配成功后要正确转换为需要的重复次数。

## 面试追问

1. **如果 a 和 b 都很长（10^6 级别），哪种方法最好？**
   → KMP 或 Rabin-Karp，时间 O(n+m)，不需要构造重复字符串，空间也更优。

2. **能否不预构造重复串就用 string::find？**
   → 不行，`string::find` 需要实际的连续内存。但可以用 KMP 在虚拟串上匹配来避免。

3. **如果改成找 b 在无限重复 a 中的所有出现位置？**
   → 用 KMP 在长度为 `n * (ceil(m/n) + 1)` 的虚拟串上匹配，收集所有匹配位置。由于 a 是周期性的，超过这个范围的匹配也是周期性的。

4. **时间复杂度 O((n+m)*m) 中的两个 m 分别来自哪里？**
   → 第一个 m：`repeated` 的长度约为 n+m 量级。第二个 m：`string::find` 最坏情况每个位置匹配 m 个字符。

5. **Rabin-Karp 最坏情况下会退化吗？**
   → 会。如果所有窗口哈希都碰撞，退化到 O((n+m)*m)。实践中用大质数模数或双哈希可以避免。
