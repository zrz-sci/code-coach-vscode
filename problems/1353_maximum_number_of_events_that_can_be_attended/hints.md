# 1353. 最多可以参加的会议数目 (Maximum Number of Events That Can Be Attended)

[LeetCode 链接](https://leetcode.com/problems/maximum-number-of-events-that-can-be-attended/)

## 题目理解

有 `n` 个会议，每个会议 `events[i] = [startDay, endDay]`，你可以在 `[startDay, endDay]` 之间的**任意一天**参加该会议。每天最多参加**一个**会议。求最多能参加多少个会议。

```
示例: events = [[1,2],[2,3],[3,4],[1,2]]

时间轴:
Day:   1      2      3      4
       |      |      |      |
会议A: [======]                    startDay=1, endDay=2
会议B:        [======]             startDay=2, endDay=3
会议C:               [======]     startDay=3, endDay=4
会议D: [======]                    startDay=1, endDay=2

最优安排:
Day 1: 参加 A (或 D)
Day 2: 参加 D (或 A) ← 今天是它的最后机会!
Day 3: 参加 B
Day 4: 参加 C
→ 全部 4 个都能参加!
```

**关键约束**：
- 每个会议只需**参加一天**即可（不是占满整个区间）
- 每天只能参加**一个**会议
- `1 <= startDay <= endDay <= 10^5`

---

## 第一步提示：什么样的贪心策略是正确的？

<details>
<summary>展开提示</summary>

**最早截止时间优先**（Earliest Deadline First, EDF）：

```
直觉: 你有一堆 deadline 不同的任务

  任务A: deadline Day 2  ← 快过期了! 先做这个!
  任务B: deadline Day 5  ← 还有时间, 可以等
  任务C: deadline Day 3  ← 也快了, 排第二

  优先做快到期的 → 留更多选择给未来
```

**每天从当前可参加的会议中，选截止日期最早的那个参加。**

**为什么正确？**（交换论证）

假设最优解在 Day d 选了截止较晚的会议 B（endDay=5），而我们选了截止最早的 A（endDay=2）：
- A 如果 Day d 不参加，很快就过期了
- B 截止时间晚（endDay=5），以后还有机会参加
- 交换 A 和 B 的参加时间，不会减少总参加数

所以贪心不差于最优解。

</details>

## 第二步提示：为什么不能简单地按 endDay 排序？

<details>
<summary>展开提示</summary>

**错误想法**：按 endDay 排序，逐个安排到最早的空闲天。

这种方法太慢！如果会议区间很大（如 [1, 100000]），找"最早空闲天"需要额外的数据结构（如并查集），代码复杂。

**正确思路**：**按天枚举**，配合**小顶堆**。

```
为什么按天枚举?

Day 1: 哪些会议已经开始? → startDay <= 1 的
       选一个截止最早的参加

Day 2: 新增了哪些会议? → startDay == 2 的
       加上之前剩下的会议
       选一个截止最早的参加

Day 3: ... 依此类推

按天枚举保证:
  1. 每天最多选一个会议
  2. 新会议按 startDay 自然加入
  3. 过期会议自然淘汰
```

</details>

## 第三步提示：算法三步曲 -- 排序 + 指针 + 小顶堆

<details>
<summary>展开提示</summary>

```
算法框架:

1. 按 startDay 排序所有会议
2. 维护指针 ptr 和小顶堆 minHeap (按 endDay)
3. 逐天 day = 1, 2, 3, ...

每天三步操作:
  ┌─ (a) 入堆: startDay == day 的会议, push(endDay)
  │
  ├─ (b) 清除: endDay < day 的过期会议, pop
  │
  └─ (c) 参加: 堆不空 → pop 堆顶 (endDay 最小), count++
```

**数据结构选择**：

| 操作 | 需求 | 工具 |
|------|------|------|
| 找最早截止的会议 | 取最小 endDay | 小顶堆 (min-heap) |
| 逐步加入新会议 | startDay 递增 | 排序 + 指针 |
| 淘汰过期会议 | endDay < day | 堆顶判断 + pop |

</details>

## 第四步提示：完整贪心过程可视化

<details>
<summary>展开提示</summary>

```
示例: events = [[1,2],[2,3],[3,4],[1,2]]

排序后 (按 startDay): [[1,2],[1,2],[2,3],[3,4]]
                       会议A  会议D  会议B  会议C

==================================================================
Day 1:
==================================================================

  (a) 入堆: startDay=1 → 会议A(end=2), 会议D(end=2)

      小顶堆 minHeap (按 endDay 升序):
      ┌──────────────┐
      │  endDay = 2   │  ← 堆顶 (最紧急)
      ├──────────────┤
      │  endDay = 2   │
      └──────────────┘

  (b) 清除过期: 堆顶 endDay=2 >= day=1, 无需清除

  (c) 参加堆顶: pop endDay=2, count=1
      (参加了会议A, 今天是它倒数第二天)

==================================================================
Day 2:
==================================================================

  (a) 入堆: startDay=2 → 会议B(end=3)

      小顶堆:
      ┌──────────────┐
      │  endDay = 2   │  ← 堆顶 (会议D, 今天是最后机会!)
      ├──────────────┤
      │  endDay = 3   │    (会议B)
      └──────────────┘

  (b) 清除过期: 堆顶 endDay=2 >= day=2, 无需清除

  (c) 参加堆顶: pop endDay=2, count=2
      (参加了会议D, 今天不参加就过期了!)

==================================================================
Day 3:
==================================================================

  (a) 入堆: startDay=3 → 会议C(end=4)

      小顶堆:
      ┌──────────────┐
      │  endDay = 3   │  ← 堆顶 (会议B, 今天到期!)
      ├──────────────┤
      │  endDay = 4   │    (会议C)
      └──────────────┘

  (b) 清除过期: 无
  (c) 参加堆顶: pop endDay=3, count=3

==================================================================
Day 4:
==================================================================

  (a) 入堆: 无新会议 (ptr=4, 超出范围)

      小顶堆:
      ┌──────────────┐
      │  endDay = 4   │  ← 堆顶 (会议C)
      └──────────────┘

  (b) 清除过期: 无
  (c) 参加堆顶: pop endDay=4, count=4

  ptr >= n && 堆空 → break!

==================================================================
结果: count = 4 (全部参加!)
==================================================================
```

**关键观察**：Day 2 时堆顶是 endDay=2 的会议D（而非 endDay=3 的会议B），因为小顶堆保证最紧急的在上面。如果 Day 2 选了会议B，会议D就永远过期了。

</details>

## 第五步提示：优化 -- 跳过空闲天

<details>
<summary>展开提示</summary>

如果会议分布稀疏（比如只有 [1,1] 和 [99999,100000]），按天枚举会空转大量天数。

**优化**：当堆为空且还有未处理的会议时，直接跳到下一个会议的 `startDay`。

```
原始: day = 1, 2, 3, ..., 99999, 100000  (10^5 次循环)
优化: day = 1, (跳过 2~99998), 99999, 100000  (3 次循环)
```

```cpp
// 优化版: 跳过空闲天
if (minHeap.empty() && ptr < n) {
    day = max(day, events[ptr][0]);  // 跳到下一个会议的开始日
}
```

优化后时间从 O(n log n + D) 降为 O(n log n)。

</details>

## 思维链总结

```
输入: events[i] = [startDay, endDay]

Step 1: 按 startDay 排序
Step 2: 初始化小顶堆 minHeap, 指针 ptr=0, count=0
Step 3: 逐天 day = 1, 2, ...
  ┌─ (a) 入堆: startDay[ptr] == day → push(endDay)
  ├─ (b) 清除过期: while 堆顶 < day → pop
  ├─ (c) 参加: 堆不空 → pop 堆顶, count++
  └─ (d) 终止: ptr >= n && 堆空 → break
Step 4: 返回 count
```

## 完整代码

```cpp
class Solution {
public:
    int maxEvents(vector<vector<int>>& events) {
        int n = events.size();

        // 按 startDay 排序
        sort(events.begin(), events.end());

        // 小顶堆: 按 endDay 升序, 堆顶是截止最早的
        priority_queue<int, vector<int>, greater<int>> minHeap;
        int ptr = 0;
        int count = 0;

        for (int day = 1; day <= 100000; day++) {
            // (a) 将 startDay == day 的会议入堆
            while (ptr < n && events[ptr][0] == day) {
                minHeap.push(events[ptr][1]);
                ptr++;
            }

            // (b) 清除过期会议 (endDay < day)
            while (!minHeap.empty() && minHeap.top() < day) {
                minHeap.pop();
            }

            // (c) 参加截止最早的会议
            if (!minHeap.empty()) {
                minHeap.pop();
                count++;
            }

            // (d) 提前终止
            if (ptr >= n && minHeap.empty()) break;
        }

        return count;
    }
};
```

## 解法对比

| 解法 | 时间 | 空间 | 说明 |
|------|------|------|------|
| 排序 + 小顶堆 (按天枚举) | O(n log n + D) | O(n) | 主解法, D=max(endDay) |
| 排序 + 小顶堆 (跳过空闲天) | O(n log n) | O(n) | 优化版, 跳过无会议的天 |
| 按 endDay 排序 + 并查集找空天 | O(n log n * alpha) | O(D) | 复杂但高效 |

## 复杂度分析

**排序 + 小顶堆**：
- 排序：O(n log n)
- 每个会议入堆一次 O(log n)、出堆一次 O(log n)
- 枚举天数：O(D)，其中 D = max(endDay) <= 10^5
- 总时间：O(n log n + D)
- 空间：O(n) -- 堆

## 常见错误

1. **只按 endDay 排序不按天枚举**：无法处理同一天多个可选会议的情况
2. **用大顶堆代替小顶堆**：应该选截止最早的（最小 endDay），不是最晚的
3. **忘记清除过期会议**：堆中残留 endDay < day 的会议会导致错误参加
4. **枚举范围到 n 而非 maxDay**：天数范围是 [1, max(endDay)]，与 n 无关
5. **入堆条件用 `<=` 而非 `==`**：因为按 startDay 排序且 ptr 单向递增，用 `==` 即可；用 `<=` 也正确但在优化版中更常用

## 模式识别

**「按天/时间点枚举 + 小顶堆调度」** -- 区间任务分配的经典模式：
- 外层按时间点推进
- 内层用堆维护活跃任务，按优先级选取
- 惰性删除过期任务
