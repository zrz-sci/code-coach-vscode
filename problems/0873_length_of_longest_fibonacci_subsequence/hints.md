# 873. 最长的斐波那契子序列的长度

## 核心思路

在一个**严格递增**的数组中，找到最长的类斐波那契子序列。关键观察：斐波那契序列中任意两个相邻元素就能决定整条链的走向，因此用 **dp[i][j] 表示以 arr[i], arr[j] 结尾的斐波那契子序列长度**，然后向前查找 arr[j] - arr[i] 是否存在。

## 思维链

1. **读完题第一反应** → 暴力枚举所有子序列？2^n 不可能。但斐波那契的特性是"知道最后两个数就能推导下一个"，所以只需要枚举最后两个数。
2. **暴力想法** → 枚举所有 (i, j) 对作为序列的起始两个元素，然后不断查找 arr[i]+arr[j] 是否在数组中。用 HashSet 可以 O(1) 查找。最坏 O(n^2 * log(max_val))。
3. **能否用 DP 优化？** → 定义 dp[j][k] = 以 arr[j], arr[k] 结尾的最长斐波那契子序列长度。转移：如果存在 i 使得 arr[i] = arr[k] - arr[j] 且 i < j，则 dp[j][k] = dp[i][j] + 1。
4. **如何快速找 i？** → 用 unordered_map 存 "值→索引" 的映射，O(1) 查找 arr[k] - arr[j] 对应的索引。
5. **遍历顺序** → 固定 k，枚举 j (j < k)，对每个 (j, k) 查找前驱 i。初始状态 dp[j][k] = 2（只有两个元素）。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 + HashSet | 枚举起始两数，不断查下一个 | O(n^2 log M) | O(n) | 能说出即可 |
| DP + HashMap | dp[j][k] 表示以 j,k 结尾的链长 | O(n^2) | O(n^2) | 首选 |

## 关键提示

1. **状态设计**：dp 的 key 必须是两个索引 (j, k)，因为斐波那契序列需要"最后两个数"才能确定下一个数。单个索引不够。
2. **值到索引的映射**：数组严格递增，每个值唯一，所以可以直接用 unordered_map<int, int> 做值到索引的映射。
3. **前驱条件**：对于 dp[j][k]，前驱 val = arr[k] - arr[j] 必须满足 val < arr[j]（因为数组严格递增，前一个元素必须更小），且 val 必须在数组中。
4. **初始值**：任意两个数都能组成长度 2 的序列，所以 dp[j][k] 的最小值是 2。答案只在 >= 3 时有效。
5. **最终答案**：遍历所有 dp[j][k]，取最大值。如果最大值 < 3，返回 0（不存在长度 >= 3 的斐波那契子序列）。

## 解法详解

### 解法1: 暴力枚举 + HashSet — O(n^2 log M) / O(n)

**思考过程**: 枚举所有可能的起始两个数 (arr[i], arr[j])，然后用 HashSet 查找后续数是否存在。

```cpp
class Solution {
public:
    int lenLongestFibSubseq(vector<int>& arr) {
        unordered_set<int> s(arr.begin(), arr.end());
        int n = arr.size(), ans = 0;
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                int a = arr[i], b = arr[j];
                int len = 2;
                while (s.count(a + b)) {
                    int c = a + b;
                    a = b;
                    b = c;
                    len++;
                }
                ans = max(ans, len);
            }
        }
        return ans >= 3 ? ans : 0;
    }
};
```

**关键点**:
- while 循环最多执行 O(log(max_val)) 次，因为斐波那契数列增长极快（指数级）。
- 时间复杂度 O(n^2 * log M)，其中 M 是数组最大值。
- 代码简洁直观，面试中可以先讲这个思路。

---

### 解法2: DP + HashMap — O(n^2) / O(n^2)

**从解法1优化**: 解法1中很多子序列被重复计算。用 DP 记忆化：dp[j][k] 表示以 arr[j], arr[k] 结尾的最长斐波那契子序列长度。

```
示例: arr = [1, 2, 3, 4, 5, 6, 7, 8]

索引映射: {1:0, 2:1, 3:2, 4:3, 5:4, 6:5, 7:6, 8:7}

k=2 (arr[k]=3):
  j=1 (arr[j]=2): 前驱 val=3-2=1, 找到 i=0 → dp[1][2] = dp[0][1]+1 = 3
  j=0 (arr[j]=1): 前驱 val=3-1=2, 但 2 > 1 不满足 val < arr[j]? 
    实际上 val=2 > arr[j]=1，前驱要求 val < arr[j]，所以不更新

k=4 (arr[k]=5):
  j=2 (arr[j]=3): 前驱 val=5-3=2, 找到 i=1 → dp[2][4] = dp[1][2]+1 = 4
  j=3 (arr[j]=4): 前驱 val=5-4=1, 找到 i=0 → dp[3][4] = dp[0][3]+1 = 3

最终链: 1→2→3→5→8, 长度5
```

```cpp
class Solution {
public:
    int lenLongestFibSubseq(vector<int>& arr) {
        int n = arr.size(), ans = 0;
        unordered_map<int, int> idx;
        for (int i = 0; i < n; i++) idx[arr[i]] = i;
        
        // dp[j][k]: 以 arr[j], arr[k] 结尾的斐波那契子序列长度
        vector<vector<int>> dp(n, vector<int>(n, 2));
        
        for (int k = 2; k < n; k++) {
            for (int j = 1; j < k; j++) {
                int val = arr[k] - arr[j]; // 前驱值
                if (val < arr[j] && idx.count(val)) {
                    int i = idx[val];
                    dp[j][k] = dp[i][j] + 1;
                    ans = max(ans, dp[j][k]);
                }
            }
        }
        return ans >= 3 ? ans : 0;
    }
};
```

**关键点**:
- `val < arr[j]` 这个条件保证前驱严格在 arr[j] 前面（因为数组严格递增）。
- dp 初始值全部设为 2，表示任何两个数天然形成长度 2 的序列。
- 只有转移成功（找到前驱）时才更新 ans，确保 ans >= 3 才有效。

## 易错点

1. **忘记检查 val < arr[j]**：
   - 如果不检查，val 可能等于或大于 arr[j]，此时 "前驱" 实际在 j 后面，链无效。
   - 数组严格递增保证了：如果 val < arr[j]，则 val 对应的索引一定 < j。

2. **答案 < 3 时返回 0**：
   - 斐波那契子序列最少 3 个元素。如果找不到长度 >= 3 的序列，必须返回 0，不是 2。

3. **dp 数组初始值不是 0 而是 2**：
   - 任意两个元素都可以形成长度为 2 的"准斐波那契序列"。转移时 dp[i][j]+1 才有意义。

4. **用 unordered_map 而非遍历查找前驱**：
   - 如果对每个 (j,k) 线性查找 val，退化为 O(n^3)。必须用哈希表做到 O(1) 查找。

## 面试追问

**Q1: 暴力和 DP 解法的核心区别是什么？**
> 暴力解法对每一对起始元素独立地向后搜索，不同起始对之间的中间结果无法复用。DP 解法通过状态 dp[j][k] 记录了"以 arr[j], arr[k] 结尾"的最优结果，后续以 arr[k] 开头的延伸可以直接复用 dp[j][k]，避免重复计算。

**Q2: 为什么状态需要两个维度 (j, k) 而不是一个维度 k？**
> 斐波那契序列的特性是"下一个数 = 前两个数之和"，所以仅知道最后一个数不够，必须知道最后两个数才能唯一确定序列的延伸方向。用单维度 dp[k] 无法区分"到达 arr[k] 的不同路径"。

**Q3: 时间复杂度能否优于 O(n^2)？**
> 很难。因为答案可能由数组中任意两个数开始，枚举起始对本身就是 O(n^2)。在某些特殊情况（如数组元素范围很小）可以做优化，但一般情况下 O(n^2) 已经是最优。

**Q4: 如果数组不是严格递增的怎么办？**
> 需要先去重或用 multimap 处理重复值。同时 val < arr[j] 的条件变为 val <= arr[j]，需要更细致地处理索引关系。
