# 13. 罗马数字转整数

## 核心思路

罗马数字的规则本质上就一条：**如果当前字符代表的值比下一个字符小，就减去当前值；否则加上当前值**。整道题的关键在于发现这个规律。

## 思维链

1. **读完题第一反应**：罗马数字有 7 个基本符号，每个对应一个数值。直觉上就是把每个字符的值加起来？但有"减法规则"（IV=4, IX=9 等），所以不能无脑加。

2. **最朴素的想法**：把所有可能的组合（包括 IV, IX, XL, XC, CD, CM 这 6 种双字符组合）都枚举出来。先检查两个字符的组合，匹配不上再看单字符。这样一定能得到正确结果。

3. **有没有更简洁的做法？** 观察减法规则的共性：IV(4)=V(5)-I(1)、IX(9)=X(10)-I(1)、XL(40)=L(50)-X(10)... **规律：当小值出现在大值左边时，小值要被减去**。

4. **核心规律提炼**：从左到右遍历，对于位置 i：
   - 如果 `value[s[i]] < value[s[i+1]]`，说明这是减法组合 → 减去 `value[s[i]]`
   - 否则 → 加上 `value[s[i]]`

5. **验证**：`MCMXCIV` → M(1000加) + C(100,下一个M更大,减) + M(1000加) + X(10,下一个C更大,减) + C(100加) + I(1,下一个V更大,减) + V(5加) = 1000 - 100 + 1000 - 10 + 100 - 1 + 5 = **1994** ✓

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 双字符优先匹配 | 先看两字符组合，再看单字符 | O(n) | O(1) | 能说出即可 |
| 左右比较法 | 小值在大值左边就减，否则加 | O(n) | O(1) | ⭐ 必须写出 |
| 从右往左累加 | 反向遍历，维护当前最大值 | O(n) | O(1) | 加分项 |

## 关键提示

1. **建立映射**：先用哈希表（或 switch）把 7 个字符映射到数值，这是所有解法的基础设施。

2. **发现减法规律**：不要试图穷举所有 6 种特殊组合。观察 IV、IX、XL、XC、CD、CM，它们的共性是什么？——**左边的值比右边的小**。

3. **最后一个字符**：最后一个字符没有"下一个"可以比较，它永远是被加上的。想想为什么？

4. **验证思路**：拿 `MCMXCIV`(1994) 手动走一遍你的算法，确认每一步的加/减是否正确：
   ```
   M(1000) C(100) M(1000) X(10) C(100) I(1) V(5)
     +        -      +       -     +      -    +
   = 1000 - 100 + 1000 - 10 + 100 - 1 + 5 = 1994 ✓
   ```

5. **不需要担心非法输入**：题目保证输入是合法的罗马数字，范围 [1, 3999]。

## 解法详解

### 解法1: 双字符优先匹配 — O(n) / O(1)

**思考过程**：最直觉的做法——既然有 6 种双字符的特殊组合，我就先看当前位置和下一个位置是否构成这些组合。如果是，加上组合的值，跳两步；否则加上单字符的值，跳一步。

```cpp
class Solution {
public:
    int romanToInt(string s) {
        // 把 7 个单字符 + 6 个双字符组合都放进 map
        unordered_map<string, int> mp = {
            {"I", 1}, {"V", 5}, {"X", 10}, {"L", 50},
            {"C", 100}, {"D", 500}, {"M", 1000},
            {"IV", 4}, {"IX", 9}, {"XL", 40}, {"XC", 90},
            {"CD", 400}, {"CM", 900}
        };
        
        int result = 0;
        int i = 0;
        while (i < s.size()) {
            // 优先尝试匹配两个字符的组合
            if (i + 1 < s.size() && mp.count(s.substr(i, 2))) {
                result += mp[s.substr(i, 2)];
                i += 2;  // 匹配到双字符，跳两步
            } else {
                result += mp[s.substr(i, 1)];
                i += 1;  // 单字符，跳一步
            }
        }
        return result;
    }
};
```

**关键点**：
- 必须**优先**检查双字符组合。如果先匹配单字符，遇到 "IV" 会先加 1 再加 5 得到 6，而不是 4。
- `substr(i, 2)` 在 i 是最后一个位置时会越界，所以要先检查 `i + 1 < s.size()`。

---

### 解法2: 左右比较法 — O(n) / O(1) ⭐ 面试首选

**从解法1优化**：解法1虽然正确，但需要维护 13 个映射项，还要做字符串截取。观察减法规则的本质——**当前字符的值 < 下一个字符的值时，当前值应该被减去**。这样只需要 7 个基本映射，逻辑更简洁。

```
// 以 MCMXCIV = 1994 为例，展示左右比较过程：
// 
// 位置:  0    1    2    3    4    5    6
// 字符:  M    C    M    X    C    I    V
// 值:   1000  100  1000  10   100   1    5
// 比较:  1000>100 100<1000 1000>10 10<100 100>1  1<5  (最后一个直接加)
// 操作:  +1000  -100   +1000  -10   +100   -1   +5
// 累计:  1000   900    1900   1890  1990  1989  1994 ✓
```

```cpp
class Solution {
public:
    int romanToInt(string s) {
        // 只需要 7 个基本字符的映射
        unordered_map<char, int> mp = {
            {'I', 1}, {'V', 5}, {'X', 10}, {'L', 50},
            {'C', 100}, {'D', 500}, {'M', 1000}
        };
        
        int result = 0;
        for (int i = 0; i < s.size(); i++) {
            // 核心规律：当前值 < 下一个值 → 减去当前值（减法组合的前半部分）
            if (i + 1 < s.size() && mp[s[i]] < mp[s[i + 1]]) {
                result -= mp[s[i]];
            } else {
                result += mp[s[i]];
            }
        }
        return result;
    }
};
```

**为什么这是正确的？**
以 IV(=4) 为例：遍历到 I 时，发现 I(1) < V(5)，所以减去 1；遍历到 V 时，没有下一个更大的，加上 5。结果 = -1 + 5 = 4。等价于直接计算 5 - 1 = 4。

对于正常的"大→小"排列（如 VI=6）：遍历到 V(5)，5 > 1，加 5；遍历到 I(1)，没有下一个，加 1。结果 = 5 + 1 = 6。完全正确。

**关键点**：最后一个字符永远是加上的，因为 `i + 1 < s.size()` 不成立，走 else 分支。

---

### 解法3: 从右往左累加 — O(n) / O(1)

**另一个视角**：从右往左遍历。维护一个"已经见过的最大值"。如果当前值 ≥ 这个最大值，就加上（并更新最大值）；如果当前值 < 最大值，说明它是某个减法组合的"小值"部分，减去它。

```cpp
class Solution {
public:
    int romanToInt(string s) {
        unordered_map<char, int> mp = {
            {'I', 1}, {'V', 5}, {'X', 10}, {'L', 50},
            {'C', 100}, {'D', 500}, {'M', 1000}
        };
        
        int result = 0;
        int prev = 0;  // 右边（已处理的）字符的值
        
        // 从右往左遍历
        for (int i = s.size() - 1; i >= 0; i--) {
            int curr = mp[s[i]];
            // 如果当前值比右边的小，说明是减法组合
            if (curr < prev) {
                result -= curr;
            } else {
                result += curr;
            }
            prev = curr;
        }
        return result;
    }
};
```

**思考过程**：从右往左看 `MCMXCIV`：
```
// V(5)+  I(1,<5,减)  C(100)+  X(10,<100,减)  M(1000)+  C(100,<1000,减)  M(1000)+
// = 5 - 1 + 100 - 10 + 1000 - 100 + 1000 = 1994 ✓
```

这种写法的好处是不需要检查 `i+1` 是否越界，因为从右往左走，用 `prev` 记录已处理的值即可。

## 解法对比

| | 解法1: 双字符优先 | 解法2: 左右比较 ⭐ | 解法3: 从右往左 |
|---|---|---|---|
| 映射数量 | 13个（7单+6双） | 7个 | 7个 |
| 遍历方向 | 从左到右，变步长 | 从左到右，步长1 | 从右到左，步长1 |
| 代码简洁度 | 中等 | 最简洁 | 简洁 |
| 面试推荐 | 不推荐（啰嗦） | **首选** | 备选 |

**面试选哪个？** 解法2（左右比较法）。原因：代码最短、规律最优美、面试官一眼看出你理解了减法规则的本质。

## 易错点

1. **✗ 忘记处理最后一个字符的边界**：
   ```cpp
   // 错误：i + 1 没有检查越界
   if (mp[s[i]] < mp[s[i + 1]]) {  // 当 i = s.size()-1 时越界！
   ```
   **✓ 正确写法**：先检查 `i + 1 < s.size()` 再访问 `s[i + 1]`。

2. **✗ 把 char 映射写成 string 映射**（解法2/3）：
   ```cpp
   unordered_map<string, int> mp = {{"I", 1}, ...};
   mp[s[i]];  // 编译错误！s[i] 是 char，不是 string
   ```
   **✓ 正确写法**：用 `unordered_map<char, int>` 或用 `mp[string(1, s[i])]` 转换。

3. **✗ 解法1中先匹配单字符再匹配双字符**：
   ```cpp
   // 错误逻辑：先加了 I(1)，再发现应该是 IV(4)，但已经过了
   ```
   **✓ 必须优先匹配双字符组合**。

## 面试追问

**Q1: 你能说说罗马数字减法规则的本质吗？**
> 当小值字符出现在大值字符的左边时，小值要被减去而不是加上。这只发生在 6 种固定组合中（IV, IX, XL, XC, CD, CM），但不需要逐个枚举，只需要一个"当前值 < 下一个值则减"的判断。

**Q2: 如果不用哈希表，能不能做？**
> 可以，用 switch-case 或 if-else 直接映射。哈希表在这里并不是为了优化时间复杂度（只有 7 个映射），而是为了代码简洁。面试中用 switch 写也完全可以，甚至更快（避免哈希表的常数开销）。

**Q3: 反过来呢？整数转罗马数字（LeetCode 12）怎么做？**
> 整数转罗马数字用贪心法：把所有可能的值（包括 900, 400, 90, 40, 9, 4 这些组合值）从大到小排列，每次尽可能减去最大的值并拼接对应的罗马字符。这是本题（13）的逆操作。
