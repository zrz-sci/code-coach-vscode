# 560. 和为 K 的子数组

## 核心思路

本题本质上在问：**数组中有多少个连续子数组，其元素之和恰好等于 k？** 关键洞察是将"子数组之和"转化为"两个前缀和之差"，从而把问题从"枚举区间求和"转变为"查找差值配对"。

## 思维链

1. **读完题第一反应**：枚举所有子数组 `[i, j]`，对每个子数组计算元素和，如果等于 k 就计数。这需要两层循环枚举 i 和 j，再一层循环求和，O(n³)。
2. **第一次优化**：求和可以用前缀和优化。令 `prefix[0] = 0`，`prefix[i] = nums[0] + ... + nums[i-1]`，则子数组 `[i, j)` 的和 = `prefix[j] - prefix[i]`。这样枚举 i, j 就够了，O(n²)。
3. **发现瓶颈**：O(n²) 的瓶颈在于——对每个 j，我们要遍历所有 i < j 找满足 `prefix[j] - prefix[i] == k` 的 i。也就是说，我们在找 `prefix[i] == prefix[j] - k`。
4. **突破瓶颈**：「对每个新值，查找之前是否出现过某个特定值」——这就是 **Two Sum 的模式**！用哈希表记录每个前缀和出现的次数，一边遍历一边查。
5. **最终方案**：遍历数组维护当前前缀和 `currSum`，同时用 `unordered_map` 记录之前每个前缀和出现过多少次。每到一个位置，查 `map[currSum - k]` 就是以当前位置结尾的、和为 k 的子数组个数。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 两层循环枚举所有子数组 + 前缀和求区间和 | O(n²) | O(1) | 能说出即可 |
| 前缀和 + 哈希表 | 一边算前缀和，一边用哈希表查找配对 | O(n) | O(n) | ⭐ 必须写出 |

## 关键提示

1. **不能用滑动窗口！** 因为数组元素可以是负数，窗口扩大时和不一定增大，缩小时和不一定减小，单调性被破坏。这是本题最常见的误区。
2. 子数组 `[i+1, j]` 的和 = `prefix[j] - prefix[i]`。如果这个差等于 k，说明 `prefix[i] = prefix[j] - k`。能否快速查"之前有多少个前缀和等于某个值"？
3. 哈希表初始化时要放入 `{0: 1}`。想想为什么——如果某个前缀和本身就等于 k，那 `currSum - k = 0`，需要匹配到"空前缀"。
4. 这道题的模式和 Two Sum 非常像：Two Sum 找 `target - nums[i]`，本题找 `currSum - k`。

```
前缀和示意 (nums = [1, 2, 3], k = 3):

index:      0     1     2     3
prefix:   [ 0,    1,    3,    6 ]
              ↑         ↑
              prefix[1]=1  prefix[2]=3
              
子数组[0,1]: prefix[2] - prefix[0] = 3 - 0 = 3 ✓
子数组[2,2]: prefix[3] - prefix[2] = 6 - 3 = 3 ✓
答案 = 2
```

## 解法详解

### 解法1: 暴力枚举（前缀和优化求和） — O(n²) / O(1)

**思考过程**: 最直接的想法就是枚举所有子数组的起止位置。对每个起始位置 i，从 i 开始累加，每加一个元素就检查当前和是否等于 k。这避免了 O(n³) 的朴素方法（不需要单独求和），利用了"上一次的和 + 当前元素"的递推关系。

```cpp
class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        int n = nums.size();
        int count = 0;
        // 枚举每个起始位置 i
        for (int i = 0; i < n; i++) {
            int sum = 0;
            // 从 i 开始向右累加
            for (int j = i; j < n; j++) {
                sum += nums[j];
                if (sum == k) {
                    count++;
                }
                // 注意：即使 sum == k 也不能 break
                // 因为后面的元素可能有正有负，sum 可能再次回到 k
            }
        }
        return count;
    }
};
```

**关键点**: 
- 找到一个和为 k 的子数组后不能停止内层循环，因为元素有负数，后面可能再次凑成 k。
- 虽然是 O(n²)，对于 n ≤ 2×10⁴ 大约 4×10⁸ 次操作，在 LeetCode 上可能超时或刚好通过。

### 解法2: 前缀和 + 哈希表 — O(n) / O(n) ⭐ 面试首选

**从解法1优化**: 解法1的瓶颈是"对每个终点 j，要遍历所有起点 i 来找和为 k 的子数组"。核心观察是：子数组 `[i+1, j]` 的和 = `prefix[j] - prefix[i]`，要等于 k 就需要 `prefix[i] = prefix[j] - k`。所以对每个 j，我们要查"之前有多少个前缀和等于 `prefix[j] - k`"——这就是哈希表的经典用法。

```
哈希表工作过程 (nums = [1, 1, 1], k = 2):

步骤    currSum    查找 currSum-k    map中次数    count    更新map
初始    —          —                 {0:1}        0        —
i=0     1          1-2=-1            0次          0        {0:1, 1:1}
i=1     2          2-2=0             1次          1        {0:1, 1:1, 2:1}
i=2     3          3-2=1             1次          2        {0:1, 1:1, 2:1, 3:1}

结果 count = 2，对应子数组 [1,1](前两个) 和 [1,1](后两个)
```

```cpp
class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        // key: 前缀和的值, value: 该前缀和出现的次数
        unordered_map<int, int> prefixCount;
        
        // 初始化：空前缀的和为0，出现1次
        // 这处理了"从数组开头到当前位置的和恰好等于k"的情况
        prefixCount[0] = 1;
        
        int currSum = 0;  // 当前前缀和
        int count = 0;    // 满足条件的子数组个数
        
        for (int num : nums) {
            currSum += num;
            
            // currSum - prefix[i] == k  ⟹  prefix[i] == currSum - k
            // 查找之前有多少个前缀和等于 currSum - k
            if (prefixCount.count(currSum - k)) {
                count += prefixCount[currSum - k];
            }
            
            // 把当前前缀和加入哈希表（注意：先查再加，保证只查"之前"的）
            prefixCount[currSum]++;
        }
        
        return count;
    }
};
```

**关键点**:
- **先查后加**：必须先查 `currSum - k` 在 map 中的次数，再把 `currSum` 加入 map。顺序不能反，否则会把当前位置也算进去（自己配对自己）。
- **初始化 `{0: 1}`**：如果不初始化，当某个前缀和本身等于 k 时（即从第一个元素到当前元素的和为 k），`currSum - k = 0` 在 map 中找不到，就漏掉了这种情况。

## 解法对比

| | 暴力枚举 | 前缀和 + 哈希表 |
|---|---|---|
| 时间 | O(n²) | O(n) |
| 空间 | O(1) | O(n) |
| 核心操作 | 双重循环枚举区间 | 哈希表查找配对 |
| 本质 | 逐个检查每个子数组 | 把"区间和"转化为"两值之差"，用 Two Sum 思路 |
| 适用场景 | 面试中快速写出展示理解 | 面试最终答案，最优解 |

## 易错点

1. **忘记初始化 `prefixCount[0] = 1`**
   - ✗ 漏掉 `prefixCount[0] = 1` → 当整个前缀和恰好等于 k 时，`currSum - k = 0` 找不到匹配，结果偏小
   - ✓ 必须初始化 `prefixCount[0] = 1`，代表"空前缀"存在一次

2. **先加后查导致错误**
   - ✗ `prefixCount[currSum]++; count += prefixCount[currSum - k];` → 当 k=0 时，自己和自己配对，多计数
   - ✓ `count += prefixCount[currSum - k]; prefixCount[currSum]++;` → 先查再加

3. **误用滑动窗口**
   - ✗ 因为看到"子数组"就用滑动窗口 → 元素有负数时，窗口单调性不成立，会漏解
   - ✓ 只有在所有元素非负的情况下，才能用滑动窗口解此类题

4. **用 `int` 存前缀和可能溢出**
   - 对于本题约束（n ≤ 2×10⁴，|nums[i]| ≤ 1000），最大前缀和约 2×10⁷，`int` 够用
   - 但如果数据范围更大，需要用 `long long`

## 面试追问

**Q1: 为什么这道题不能用滑动窗口？**
→ 滑动窗口需要窗口满足单调性：扩大窗口时和变大，缩小时和变小。但本题元素可以为负数，扩大窗口和可能反而减小，无法确定该扩还是该缩。如果题目保证 `nums[i] >= 0`，就可以用滑动窗口。

**Q2: `prefixCount[0] = 1` 的含义是什么？去掉会怎样？**
→ 它代表"空前缀和为0出现1次"。比如 nums=[3], k=3 时，currSum=3，查找 3-3=0，如果 map 中没有 0，就漏掉了 [3] 这个子数组。本质上是 prefix[0]=0 对应下标 0 之前的空前缀。

**Q3: 如果要返回所有和为 k 的子数组的起止索引，怎么改？**
→ 把 `unordered_map<int, int>` 改成 `unordered_map<int, vector<int>>`，value 存的不是次数，而是所有出现该前缀和的下标列表。找到配对时，从列表中取出每个起始下标，和当前下标配成区间。

**Q4: 如果数组非常长（10⁸ 级别），哈希表占内存太大，有什么思路？**
→ 如果元素全部非负，可以用滑动窗口 O(1) 空间。如果有负数，可以考虑分块处理或离线算法，但通常面试不会追问到这一步。核心是识别"全非负 → 滑动窗口可行"这个条件。

## 相关题型

- **1. Two Sum** — 本题是 Two Sum 的推广。Two Sum 找 `target - nums[i]`，本题找 `currSum - k`。核心都是"边遍历边用哈希表查配对"。
- **523. 连续的子数组和 (Continuous Subarray Sum)** — 同样的前缀和 + 哈希表框架，区别是判断条件从 `prefix[j] - prefix[i] == k` 变成 `(prefix[j] - prefix[i]) % k == 0`，所以哈希表存的是 `prefix % k`。
- **974. 和可被 K 整除的子数组 (Subarray Sums Divisible by K)** — 和 523 类似，前缀和取模后用哈希表配对，但要处理负数取模的问题（`((prefix % k) + k) % k`）。
- **325. 和等于 K 的最长子数组长度** — 同样前缀和 + 哈希表，但不是计数而是找最长，所以哈希表只存第一次出现的下标（贪心：越早出现的前缀和，能配出越长的子数组）。
