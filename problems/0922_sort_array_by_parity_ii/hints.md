# 922. 按奇偶排序数组 II

## 核心思路

本题的关键观察：数组一半是偶数一半是奇数，需要让偶数索引放偶数、奇数索引放奇数。最优解法是用**双指针**分别扫描偶数位和奇数位，找到"放错位置"的元素进行交换，实现 O(n) 时间 O(1) 空间的原地排序。

## 思维链

1. **读完题第一反应**：把偶数放到偶数下标，奇数放到奇数下标。最直接的想法是开一个新数组，用两个指针分别指向偶数位(0,2,4...)和奇数位(1,3,5...)，遍历原数组时按奇偶性分别填入。

2. **能不能原地做？** 题目 Follow Up 要求原地操作。想想如果偶数位上放了一个奇数，那说明某个奇数位上一定放了一个偶数（因为总数是匹配的）。所以我们可以找到这两个"错位"的元素直接交换。

3. **双指针策略**：用指针 `i` 扫描偶数下标(0,2,4...)，`j` 扫描奇数下标(1,3,5...)。当 `i` 指向一个奇数（放错了），同时 `j` 指向一个偶数（也放错了），交换它们即可。

4. **为什么双指针一定能匹配到？** 偶数位上每多一个奇数，奇数位上就必然多一个偶数。所以"偶数位上的错误"和"奇数位上的错误"数量一定相等，双指针一定能成对消除。

5. **遍历完成的条件**：当 `i` 或 `j` 越界时，所有错位都已修正。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 双通道填充 | 新数组 + 偶数位/奇数位各一个指针 | O(n) | O(n) | 基础解法 |
| 双指针原地交换 | 偶数位指针和奇数位指针配对交换错位元素 | O(n) | O(1) | ⭐ 面试首选 |

> 两种解法时间复杂度相同，但原地版本空间优化到 O(1)，是面试官期待的 Follow Up 答案。

## 关键提示

1. **偶数位和奇数位是独立的子问题** — 偶数位上如果有奇数，那一定有对应的奇数位上放了偶数。数量守恒！

2. **判断奇偶用位运算** — `nums[i] & 1` 比 `nums[i] % 2` 更快。`& 1` 为 0 表示偶数，为 1 表示奇数。

3. **指针步长是 2 而不是 1** — 偶数指针从 0 开始每次加 2，奇数指针从 1 开始每次加 2。这是本题双指针的特殊之处。

4. 双指针过程示意：
```
nums = [4, 2, 5, 7]
         i     j

i=0: nums[0]=4 偶数 ✓ → i=2
i=2: nums[2]=5 奇数 ✗ → 找 j
j=1: nums[1]=2 偶数 ✗ → swap(nums[2], nums[1])
nums = [4, 5, 2, 7]  ✓ 全部就位
```

## 解法详解

### 解法1: 双通道填充 — O(n) / O(n) 基础解法

**思考过程**：

最直觉的方法：创建结果数组，维护两个写入指针 `evenIdx = 0` 和 `oddIdx = 1`。遍历原数组，偶数写到 `evenIdx` 然后 `evenIdx += 2`，奇数写到 `oddIdx` 然后 `oddIdx += 2`。

```cpp
class Solution {
public:
    vector<int> sortArrayByParityII(vector<int>& nums) {
        int n = nums.size();
        vector<int> result(n);
        int evenIdx = 0, oddIdx = 1;
        
        for (int num : nums) {
            if (num % 2 == 0) {
                // 偶数放到偶数下标
                result[evenIdx] = num;
                evenIdx += 2;
            } else {
                // 奇数放到奇数下标
                result[oddIdx] = num;
                oddIdx += 2;
            }
        }
        
        return result;
    }
};
```

**关键点**：
- 两个指针独立运行，不会冲突（一个只访问偶数位，一个只访问奇数位）。
- 不需要排序，只需要"分类"到正确的位置。

### 解法2: 双指针原地交换 — O(n) / O(1) ⭐ 面试首选

**思考过程**：

偶数位指针 `i` 从 0 开始步长 2，找到偶数位上的奇数（违规元素）。奇数位指针 `j` 从 1 开始步长 2，找到奇数位上的偶数（违规元素）。两个违规元素交换后都归位。

```cpp
class Solution {
public:
    vector<int> sortArrayByParityII(vector<int>& nums) {
        int n = nums.size();
        int j = 1;  // 奇数位指针
        
        for (int i = 0; i < n; i += 2) {
            // i 扫描偶数位
            if (nums[i] % 2 == 1) {
                // 偶数位上放了奇数！需要交换
                // 在奇数位找一个偶数来交换
                while (nums[j] % 2 == 1) {
                    j += 2;  // 跳过奇数位上正确的奇数
                }
                // nums[j] 是奇数位上的偶数（违规），交换
                swap(nums[i], nums[j]);
            }
        }
        
        return nums;
    }
};
```

**关键点**：
- `j` 不需要每次从头开始扫描 — 因为之前扫过的奇数位要么已经正确(奇数)，要么已经被交换过。
- 外层循环 `i` 只看偶数位，内层 `j` 只看奇数位，总共访问每个元素常数次，时间仍是 O(n)。
- 返回的是修改后的原数组引用，空间 O(1)。

| 维度 | 双通道填充 | 双指针原地交换 |
|------|-----------|--------------|
| 时间 | O(n) | O(n) |
| 空间 | O(n) 新数组 | O(1) 原地 |
| 代码难度 | 简单直白 | 稍需思考 |
| 面试推荐 | 作为思路起点 | Follow Up 答案 |

## 易错点

1. **指针步长写成 1**：
   - ✗ `i++` / `j++` — 会访问"不属于自己"的下标
   - ✓ `i += 2` / `j += 2` — 偶数位和奇数位各走各的

2. **奇偶判断搞反**：
   - ✗ 偶数位要求奇数 → 逻辑完全反了
   - ✓ 偶数位(i=0,2,4...)要求偶数，奇数位(j=1,3,5...)要求奇数

3. **原地交换时 j 每次从 1 重新开始**：
   - ✗ 每次找违规奇数位都从 `j=1` 开始 → O(n^2)
   - ✓ `j` 保持上次位置继续向前 → O(n) 摊还

4. **忘记返回修改后的数组**：
   - ✗ 原地修改了 nums 但忘了 `return nums`
   - ✓ 函数签名要求返回 `vector<int>`，原地修改后仍需 return

## 面试追问

**Q1: 为什么双指针的时间复杂度是 O(n) 而不是 O(n^2)？**

> 虽然有嵌套循环，但 `i` 和 `j` 都只向前移动，不回退。`i` 最多从 0 走到 n-1（步长2），`j` 也最多从 1 走到 n-1（步长2）。两个指针合计最多各走 n/2 步，总操作 O(n)。这是经典的**摊还分析**。

**Q2: 如果不是一半偶数一半奇数，而是要求偶数在前、奇数在后（LeetCode 905），怎么做？**

> 经典的 partition 问题。用两个指针 left 和 right，left 从左找奇数，right 从右找偶数，交换。类似快速排序的 partition 步骤。区别在于本题(922)的指针步长是 2（分别扫描奇偶位），而 905 的指针步长是 1（从两端向中间）。

**Q3: 能否用排序来解？时间复杂度会变吗？**

> 可以先排序再按奇偶分配，但排序是 O(n log n)，不如 O(n) 的双指针。面试中应该指出"不需要排序，只需要分类"，展示你能识别问题的本质需求。
