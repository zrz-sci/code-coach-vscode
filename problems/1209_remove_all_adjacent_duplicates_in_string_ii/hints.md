# 1209. 删除字符串中的所有相邻重复项 II

## 核心思路

本题本质上是 **LeetCode 1047（删除相邻重复项，k=2 的特例）的泛化版**：你需要持续消除连续 k 个相同字符，消除后两侧拼接可能产生新的 k 连续，继续消除直到稳定。关键在于如何高效地**追踪每个字符的连续出现次数**，并在删除后快速接上之前的计数。

## 思维链

1. **读完题第一反应**：模拟！每轮扫描字符串，找到 k 个连续相同字符就删除，重复直到没有可删的。但这可能需要多轮扫描。
2. **暴力解的瓶颈**：每轮删除后字符串变短，要重新扫描。最坏情况每轮只删 k 个字符，需要 O(n/k) 轮，每轮 O(n)，总共 O(n²/k)。
3. **观察关键性质**：删除 k 个相同字符后，左右两侧会"拼接"起来。这就像括号匹配 —— 新来的字符需要和"之前留下的字符"比较。**栈天然适合这种"新元素和最近的旧元素配对"的场景**。
4. **栈的设计**：栈里不能只存字符，还要存**当前字符的连续计数**。每次新字符进来，如果和栈顶相同就计数+1，不同就压入新元素（计数=1）。计数达到 k 就弹出（相当于删除）。
5. **一次遍历搞定**：因为弹出后栈顶自动变成之前的字符，新字符又可以和它比较，完美处理了"删除后两侧拼接"的情况。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力模拟 | 反复扫描删除直到稳定 | O(n²/k) | O(n) | 能说出即可 |
| 栈 + 计数 | 栈存 (字符, 计数)，计数达 k 弹出 | O(n) | O(n) | ⭐ 必须写出 |
| 双指针（原地模拟栈） | 用数组模拟栈，指针做栈顶 | O(n) | O(n) | 加分项 |

## 关键提示

1. **和 1047 题（k=2）的对比**：k=2 时只需要栈存字符（出现2次就弹），k 任意时栈需要额外存**计数**。想想为什么？
2. **栈里存什么**：不是存单个字符，而是存 `(字符, 连续出现次数)` 这个 pair。这是本题最核心的设计决策。
3. **删除后的拼接效果**：删除 "eee" 后 "d_d" 拼接变成 "dd"，栈自然处理了这个拼接 —— 弹出 'e' 后栈顶就是之前的 'd'。
4. **最终结果的构建**：栈里剩下的就是结果，但要注意每个元素可能有多个字符（计数>1），需要逐个展开。

```
模拟示例: s = "deeedbbcccbdaa", k = 3

```

## 解法详解

### 解法1: 暴力模拟 — O(n²/k) / O(n)

**思考过程**：最直觉的做法 —— 反复扫描字符串，每次找到连续 k 个相同字符就删掉，直到一轮扫描下来没有任何删除。

```cpp
class Solution {
public:
    string removeDuplicates(string s, int k) {
        bool changed = true;
        while (changed) {
            changed = false;
            string next;
            int i = 0;
            while (i < s.size()) {
                int j = i;
                // 找到以 s[i] 开头的连续相同字符段
                while (j < s.size() && s[j] == s[i]) j++;
                int count = j - i;
                if (count >= k) {
                    // 删掉 k 的整数倍个字符，保留余数
                    int remain = count % k;
                    next.append(remain, s[i]);
                    changed = true;
                } else {
                    next.append(count, s[i]);
                }
                i = j;
            }
            s = next;
        }
        return s;
    }
};
```

**关键点**：
- 每轮不只删一组 k 个，而是把每段连续相同字符中 k 的倍数部分都删掉（保留 `count % k` 个），这样更高效。
- 但删除后的拼接仍可能产生新的连续段，所以需要多轮。
- 最坏情况：如 "aabbaa" k=2，第一轮删 bb → "aaaa"，第二轮删 aaaa → ""，需要多轮。

### 解法2: 栈 + 计数 — O(n) / O(n) ⭐ 面试首选

**从解法1优化**：暴力解的瓶颈是"删除后拼接可能产生新的可删段，需要重新扫描"。栈天然解决了这个问题 —— 弹出后栈顶就是之前的元素，新字符可以直接和它比较。

```cpp
class Solution {
public:
    string removeDuplicates(string s, int k) {
        // 栈存 (字符, 当前连续计数)
        vector<pair<char, int>> stk;
        
        for (char c : s) {
            if (!stk.empty() && stk.back().first == c) {
                // 和栈顶相同字符，计数+1
                stk.back().second++;
                // 计数达到 k，弹出（等价于删除 k 个连续字符）
                if (stk.back().second == k) {
                    stk.pop_back();
                }
            } else {
                // 不同字符，新压入栈
                stk.push_back({c, 1});
            }
        }
        
        // 从栈构建结果字符串
        string result;
        for (auto& [ch, cnt] : stk) {
            result.append(cnt, ch);
        }
        return result;
    }
};
```

**关键点**：
- 栈里存的是 `(字符, 计数)` 对，不是每个字符单独入栈。
- 删除操作就是 `pop_back()`，删除后栈顶自动变成之前的字符段，新字符会继续和它比较。
- 一次遍历 O(n)，每个字符最多入栈一次出栈一次。

### 解法3: 双指针（原地模拟栈）— O(n) / O(n)

**思路**：用字符串本身（或字符数组）当作"栈"，用一个慢指针 `j` 表示栈顶位置，配合一个额外的计数数组。这样避免了最后从栈构建字符串的过程。

```cpp
class Solution {
public:
    string removeDuplicates(string s, int k) {
        int n = s.size();
        vector<int> count(n, 0); // count[j] = s[j] 位置的连续计数
        
        int j = 0; // j 是"栈顶指针"，指向下一个要写入的位置
        for (int i = 0; i < n; i++) {
            s[j] = s[i]; // 将当前字符写到"栈顶"
            
            if (j > 0 && s[j] == s[j - 1]) {
                count[j] = count[j - 1] + 1; // 和前一个相同，计数延续
            } else {
                count[j] = 1; // 新字符，计数重置为 1
            }
            
            if (count[j] == k) {
                j -= k; // 弹出 k 个字符（栈顶后退 k 步）
            }
            j++;
        }
        
        return s.substr(0, j);
    }
};
```

**关键点**：
- `s[0..j-1]` 就是当前的"栈内容"，`count[i]` 记录位置 i 处字符的连续计数。
- 当 `count[j] == k` 时，`j -= k` 相当于弹出 k 个字符。
- 最后 `s.substr(0, j)` 就是结果，无需额外构建。

## 解法对比

| | 暴力模拟 | 栈+计数 | 双指针模拟栈 |
|---|---|---|---|
| 时间 | O(n²/k) 多轮扫描 | O(n) 一次遍历 | O(n) 一次遍历 |
| 空间 | O(n) 新字符串 | O(n) 栈 | O(n) count数组 |
| 代码复杂度 | 简单但多轮逻辑 | 清晰直观 | 技巧性强 |
| 面试推荐 | 说思路即可 | ⭐ 首选 | 追问时展示 |

**选择建议**：面试中首选解法2（栈+计数），思路清晰、代码简洁。如果面试官追问"能否不用额外的栈结构"，可以展示解法3。

## 易错点

1. **栈里只存字符，忘记存计数**
   - ✗ `stack<char> stk;` 然后数栈顶连续相同的个数 → 需要反复 pop 再 push 回去，复杂且易错
   - ✓ `vector<pair<char,int>> stk;` 把计数和字符绑定在一起

2. **构建结果时只取一个字符**
   - ✗ `for (auto& p : stk) result += p.first;` → 每个栈元素可能代表多个字符
   - ✓ `for (auto& [ch, cnt] : stk) result.append(cnt, ch);` → 按计数展开

3. **解法3中 `j -= k` 之后忘记 `j++`**
   - 弹出 k 个后，j 指向的是被弹出位置的开头，下一个字符应该写到新的 j 位置，循环末尾的 `j++` 不能漏。

4. **解法3中 count 数组边界**
   - 当 `j == 0` 时访问 `s[j-1]` 会越界，要先判断 `j > 0`。

## 面试追问

**Q1: 这道题和 1047 题（k=2 的简单版）有什么区别？代码上改了什么？**
> 1047 题（k=2）栈里只存字符，栈顶和当前相同就弹出。本题 k 任意，所以栈里需要额外存一个计数，计数达到 k 才弹出。核心差异就是从 `stack<char>` 变成 `stack<pair<char,int>>`。

**Q2: 如果 k 很大（比如 k=10000），对性能有影响吗？**
> 对栈解法没有影响 —— 计数存在 pair 里，不管 k 多大，每个字符仍然只入栈出栈一次，O(n) 不变。对暴力解影响也不大，反而每次删除更多字符，轮数更少。

**Q3: 如果要求返回删除过程中所有中间状态怎么办？**
> 暴力模拟更容易输出中间态。栈解法是"一步到位"的，不容易还原中间态。可以修改暴力法，每轮删除后记录当前字符串。

**Q4: 能否用递归解？**
> 可以。每轮删除所有 k 连续段后递归处理，直到字符串不再变化。本质就是暴力法的递归版。但时间复杂度不如栈解法。
