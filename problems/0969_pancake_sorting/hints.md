# LeetCode 969 - Pancake Sorting

## 核心思路

贪心策略：从最大的元素开始，逐个将每个元素"翻"到正确位置。对于当前需要放置的最大未排序元素 target：先翻转一次使它到达数组首部，再翻转一次使它落到目标位置。每个元素最多需要两次翻转，总翻转次数不超过 2n，满足题目 10n 的限制。

## 思维链

1. **理解翻转操作** - pancake flip(k) 翻转 arr[0..k-1]。只能翻转从头开始的前缀。
2. **选择排序策略** - 观察到：如果能把最大元素翻到最后，问题规模就缩小 1。类似选择排序。
3. **两步翻转法** - 要将位置 i 的元素放到位置 j（末尾）：
   - 第一步：flip(i+1) 把它翻到最前面
   - 第二步：flip(j+1) 把它从最前面翻到位置 j
4. **从大到小处理** - 先放最大的到最后，然后放次大的到倒数第二...每轮处理一个元素，问题规模减 1。
5. **特殊情况** - 如果元素已经在正确位置，跳过不需要翻转。如果元素已经在首位，只需一次翻转。
6. **验证** - 每轮最多 2 次翻转，n 个元素最多 2n 次，远小于 10n。

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 翻转次数 | 特点 |
|------|----------|----------|---------|------|
| 贪心（从大到小） | O(n^2) | O(1) 额外 | 最多 2n | 推荐，最直观 |
| 贪心（从小到大） | O(n^2) | O(1) 额外 | 最多 2n | 可行但不如从大到小直观 |
| 优化贪心 | O(n^2) | O(1) | 可能更少 | 跳过已在位的元素 |

## 关键提示

1. 翻转 flip(k) 是翻转 arr[0..k-1]（0-indexed），返回的 k 值是 1-indexed 的长度。
2. arr 是 1 到 n 的排列，所以目标位置就是 arr[i] = i + 1。
3. 从最大值 n 开始向下到 1 处理：每次找到当前值的位置，两次翻转送到目标位。
4. 如果当前值已经在目标位，无需翻转，跳过即可。
5. 如果当前值恰好在位置 0，只需一次翻转（直接翻到目标位）。
6. 翻转操作用 reverse(arr.begin(), arr.begin() + k) 实现。

## 解法详解

### 解法一：贪心从大到小排列（推荐）

**算法**：
```
对于 target 从 n 下降到 1：
    1. 找到 target 在数组中的位置 idx
    2. 如果 idx == target - 1，已经在位，跳过
    3. 如果 idx != 0：
       - flip(idx + 1) 把 target 翻到位置 0
       - 记录操作 idx + 1
    4. flip(target) 把 target 从位置 0 翻到位置 target - 1
       - 记录操作 target
```

**执行示例**（arr = [3,2,4,1]）：
- target = 4: idx = 2, flip(3) -> [4,2,3,1], flip(4) -> [1,3,2,4]
- target = 3: idx = 1, flip(2) -> [3,1,2,4], flip(3) -> [2,1,3,4]
- target = 2: idx = 0, 已在首位, flip(2) -> [1,2,3,4]
- target = 1: idx = 0 == target-1, 已在位, 跳过

结果操作序列：[3, 4, 2, 3, 2]

**为什么正确？** 每次将当前最大未排序元素放到正确位置后，它永远不会再被移动（因为后续操作的翻转范围更小，不会影响到它）。

### 解法二：查找位置的优化

可以维护一个值到位置的映射 pos[val] = idx，避免每次线性查找。但由于每次 flip 会改变多个元素的位置，更新映射的开销也是 O(n)，总复杂度仍然 O(n^2)。

### 操作数分析

- 最坏情况：每个元素需要 2 次翻转，共 2n 次
- 最好情况：数组已排序，0 次翻转
- 平均情况：约 1.5n 次（部分元素已在位或在首位，节省翻转）

题目允许 10n 次翻转，我们的方案远低于此限制。

### 翻转操作的实现

```cpp
void flip(vector<int>& arr, int k) {
    reverse(arr.begin(), arr.begin() + k);
}
```

注意：`reverse` 是原地操作，不需要额外空间。

## 易错点

1. **k 的含义** - flip(k) 翻转前 k 个元素 arr[0..k-1]，k 是从 1 开始的。容易和 0-indexed 混淆。
2. **找位置后忘记先翻到首位** - 必须先把目标元素翻到 arr[0]，才能再翻到目标位置。
3. **元素已在首位的情况** - 如果 target 已经在 idx=0，只需一次 flip(target) 就够了，不需要先 flip(1)。
4. **元素已在目标位** - 如果 target 已经在 idx = target - 1，不需要任何操作。不检查会浪费多余翻转。
5. **翻转顺序记录** - 每次 flip 都要把 k 加入结果数组。先加 idx+1，再加 target。
6. **原地修改数组** - flip 操作会真的改变 arr，后续查找必须基于修改后的数组。

## 面试追问

1. **能否做到少于 2n 次翻转？** - 理论最优下界约 (18/11)n，但实际算法很复杂。面试中 2n 足够。
2. **pancake sorting 和普通排序的关系？** - pancake sorting 是一种受限排序，只能做前缀翻转。它和 "前缀翻转排序网络" 相关，是组合数学中经典的问题。
3. **如何验证给出的操作序列是否正确？** - 按序模拟每次翻转，最终检查数组是否有序。
4. **如果允许从任意位置开始翻转（不仅是前缀），会更容易吗？** - 是的，那就变成了冒泡排序的变体，可以直接交换相邻元素。
5. **burnt pancake sorting 是什么？** - 每个煎饼有正反面，不仅要排序还要保证正面朝上。需要最多 2n 次翻转。
