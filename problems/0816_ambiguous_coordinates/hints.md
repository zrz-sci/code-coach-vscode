# 816. Ambiguous Coordinates - 提示与解析

## 核心思路

本题给定一个去掉了逗号、空格和小数点的坐标字符串（如 "(123)"），要求恢复所有合法的原始坐标。核心方法是**两层枚举**：外层枚举逗号位置（将数字串分成左右两部分），内层对每一部分枚举小数点位置。关键在于判断一个数字字符串（可能带小数点）是否合法：不能有前导零（除了单独的"0"和"0.xxx"形式），小数部分不能以零结尾（否则是多余的零）。

## 思维链

1. **解析输入**：去掉括号，得到纯数字字符串
2. **枚举逗号位置**：将数字串分为左右两部分，每部分至少1个字符
3. **对每部分枚举小数点位置**：生成所有合法的数字表示
4. **合法性判断**：
   - 整数部分：不能有前导零（除了单独的 "0"）
   - 小数部分：不能以零结尾
5. **组合结果**：左右两部分的合法表示做笛卡尔积
6. **格式化输出**：`"(left, right)"`

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 适用场景 |
|------|-----------|-----------|---------|
| 枚举 + 合法性判断 | O(n^3) | O(n^3) | 唯一解法 |

说明：n 为字符串长度，外层 O(n) 枚举逗号，内层 O(n) 枚举小数点，每次生成字符串 O(n)，总 O(n^3)。输出最多 O(n^2) 个坐标，每个长度 O(n)。

## 关键提示

1. **合法数字的规则**（最核心的判断）：
   - 纯整数 "XYZ"：不能有前导零。"0" 合法，"01" 不合法
   - 小数 "X.YZ"：整数部分不能有前导零（"0.5" 合法，"01.5" 不合法），小数部分不能以0结尾（"1.50" 不合法）
2. **特殊情况 "0"**：只能表示整数 "0" 或 "0.xxx" 形式
3. **单字符**：只能是整数本身，不能加小数点
4. **全零串 "000"**：只能表示 "0.00"... 不行（末尾0），所以 "000" 只能是 "0" 但长度不对——实际上无合法表示
5. **辅助函数 generate(s)**：返回字符串 s 的所有合法数字表示列表

## 解法详解

### 枚举 + 合法性判断（唯一解法）

**Step 1: 枚举逗号位置**
```
s = 去掉括号后的数字串（如 "123"）
对于 i = 1 to len(s)-1:
    left = s[0..i-1]   // 左部分
    right = s[i..end]   // 右部分
```

**Step 2: 生成合法数字表示**
```
generate(s):
    results = []
    // 情况1：不加小数点（纯整数）
    if s == "0" or s[0] != '0':  // 没有前导零
        results.add(s)
    
    // 情况2：加小数点
    for dot_pos = 1 to len(s)-1:
        integer_part = s[0..dot_pos-1]
        decimal_part = s[dot_pos..end]
        if (integer_part == "0" or integer_part[0] != '0')  // 整数部分无前导零
           and decimal_part.back() != '0':  // 小数部分不以零结尾
            results.add(integer_part + "." + decimal_part)
    
    return results
```

**Step 3: 笛卡尔积**
```
对每个逗号位置的 (left_candidates, right_candidates):
    对每个 (l, r) in left_candidates x right_candidates:
        result.add("(" + l + ", " + r + ")")
```

### 合法性判断汇总表

| 字符串 | 纯整数 | 可加小数点 | 合法表示 |
|--------|--------|-----------|---------|
| "1" | YES | NO（太短） | ["1"] |
| "0" | YES | NO（太短） | ["0"] |
| "12" | YES | YES: "1.2" | ["12", "1.2"] |
| "00" | NO | NO（"0.0"末尾0） | [] |
| "10" | YES | NO（"1.0"末尾0） | ["10"] |
| "01" | NO | YES: "0.1" | ["0.1"] |
| "012" | NO | YES: "0.12" | ["0.12"] |
| "100" | YES | NO（末尾0） | ["100"] |
| "001" | NO | NO（前导0+末尾0） | [] (wait: "0.01" is valid!) |

注意 "001"：整数 "001" 不合法；"0.01" -> 整数部分 "0" 合法，小数部分 "01" 以1结尾合法 -> 合法！所以 "001" -> ["0.01"]。

## 易错点

1. **忘记 "0" 是合法整数**：特判 s == "0" 时直接加入结果
2. **前导零判断不完整**：只检查 s[0] == '0' 而没有排除 s == "0" 的情况，导致 "0" 被错误过滤
3. **小数末尾零判断遗漏**：如 "1.0", "1.20" 都不合法，必须检查 decimal_part.back() != '0'
4. **边界：单字符部分**：长度为1的字符串不能加小数点，只能作为整数
5. **去括号时下标错误**：s = s.substr(1, s.size()-2)，注意 substr 的参数
6. **笛卡尔积为空**：如果某一侧没有合法表示，该逗号位置直接跳过

## 面试追问

1. **Q: 时间复杂度的详细分析？**
   A: 外层 O(n) 枚举逗号，每侧 O(n) 枚举小数点，生成字符串 O(n)。总的生成过程 O(n^3)。但实际输出量通常远小于此。

2. **Q: 如何优化？**
   A: 可以提前判断一侧是否有合法表示来剪枝。例如，全零串只有特殊情况才合法，提前判断可以跳过不必要的枚举。

3. **Q: 如果输入可能包含负号怎么办？**
   A: 在枚举时需要额外考虑负号的位置。负号只能出现在数字最前面，且不能是 "-0"（除非后面有小数部分）。

4. **Q: 如果坐标是三维的 (x, y, z) 怎么办？**
   A: 需要两层逗号枚举：第一刀分出 x，第二刀分出 y 和 z。时间复杂度变为 O(n^4)。

5. **Q: 如何验证结果正确性？**
   A: 对每个输出的坐标，去掉逗号、空格和小数点后应该等于原始输入。可以用这个性质做单元测试。
