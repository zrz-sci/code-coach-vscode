# 88. 合并两个有序数组

## 核心思路

本质上就是**归并排序的 merge 步骤**：把两个已排序数组合并成一个有序数组。关键约束是必须**原地**合并到 `nums1` 中，而 `nums1` 尾部预留了足够空间。

## 思维链

1. **读完题第一反应**：两个有序数组合并？最简单的做法是把 `nums2` 的元素塞进 `nums1`，然后整体排序。简单粗暴，能过。
2. **暴力解的瓶颈**：排序的时间复杂度是 O((m+n) log(m+n))，没有利用"两个数组已经各自有序"这个条件。
3. **经典合并思路**：归并排序的 merge 操作！两个指针分别指向两个数组头部，每次取较小的放入结果。但问题是——如果从前往后合并到 `nums1`，会**覆盖** `nums1` 还没比较的元素。
4. **突破覆盖问题**：`nums1` 的**尾部**是空的（都是 0 占位符）！如果**从后往前**填充，每次取两个数组中较大的放到 `nums1` 末尾，就不会覆盖任何有效元素。
5. **为什么不会覆盖**：写入位置 `k` 从 `m+n-1` 开始递减，读取位置 `i` 从 `m-1` 开始递减。因为 `k >= i` 始终成立（每次写入至多消耗一个 nums1 的元素），所以写指针永远不会追上读指针。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 合并后排序 | 拼接 + sort | O((m+n)log(m+n)) | O(1) | 能说出即可 |
| 正向双指针 + 额外数组 | 经典归并，用临时数组 | O(m+n) | O(m) | 能说出即可 |
| **逆向双指针** | 从后往前填充 nums1 | O(m+n) | O(1) | ⭐ 必须写出 |

## 关键提示

1. **利用尾部空间**：`nums1` 后面 `n` 个位置是空的，这不是浪费，而是提示你**从后往前填**。
2. **从后往前 = 不覆盖**：想想为什么从前往后会覆盖——因为写入的位置可能还有没读的数据。从后往前就没这个问题。
3. **谁先耗尽？**：如果 `nums2` 先耗尽，`nums1` 剩余元素已经在正确位置，不用动；如果 `nums1` 先耗尽，需要把 `nums2` 剩余元素全部拷贝过来。
4. **边界**：`m=0` 时 `nums1` 没有有效元素，直接把 `nums2` 全部拷过去就行。

```
// 逆向双指针过程演示:
// nums1 = [1, 2, 3, 0, 0, 0]   m=3
// nums2 = [2, 5, 6]             n=3
//
// i=2, j=2, k=5:  nums1[2]=3 < nums2[2]=6  → nums1[5]=6, j--
// [1, 2, 3, 0, 0, 6]
//
// i=2, j=1, k=4:  nums1[2]=3 < nums2[1]=5  → nums1[4]=5, j--
// [1, 2, 3, 0, 5, 6]
//
// i=2, j=0, k=3:  nums1[2]=3 > nums2[0]=2  → nums1[3]=3, i--
// [1, 2, 3, 3, 5, 6]
//
// i=1, j=0, k=2:  nums1[1]=2 == nums2[0]=2 → nums1[2]=2, i--
// [1, 2, 2, 3, 5, 6]
//
// i=0, j=0, k=1:  nums1[0]=1 < nums2[0]=2  → nums1[1]=2, j--
// [1, 2, 2, 3, 5, 6]
//
// j<0, 循环结束。nums1 剩余部分已在正确位置 ✓
```

## 解法详解

### 解法1: 合并后排序 — O((m+n)log(m+n)) / O(1)

**思考过程**：最直觉的做法——不管什么有序不有序，先把 `nums2` 全部拷到 `nums1` 后面，然后排序。简单，但浪费了"已有序"的信息。

```cpp
class Solution {
public:
    void merge(vector<int>& nums1, int m, vector<int>& nums2, int n) {
        // 把 nums2 的元素放到 nums1 的后半段
        for (int i = 0; i < n; i++) {
            nums1[m + i] = nums2[i];
        }
        // 整体排序
        sort(nums1.begin(), nums1.end());
    }
};
```

**关键点**：这里完全没利用两个数组已排序的性质，所以时间不是最优的。但作为面试的"第一反应"说出来是可以的。

---

### 解法2: 正向双指针 + 额外数组 — O(m+n) / O(m)

**思考过程**：经典归并操作——两个指针从头开始，每次取较小的放入结果数组。但直接往 `nums1` 里写会覆盖还没比较的元素，所以先把 `nums1` 的前 `m` 个元素拷贝出来。

```cpp
class Solution {
public:
    void merge(vector<int>& nums1, int m, vector<int>& nums2, int n) {
        // 拷贝 nums1 的有效部分，避免被覆盖
        vector<int> nums1_copy(nums1.begin(), nums1.begin() + m);
        
        int i = 0, j = 0, k = 0;
        // 标准归并：每次取两者中较小的
        while (i < m && j < n) {
            if (nums1_copy[i] <= nums2[j]) {
                nums1[k++] = nums1_copy[i++];
            } else {
                nums1[k++] = nums2[j++];
            }
        }
        // 处理剩余元素
        while (i < m) nums1[k++] = nums1_copy[i++];
        while (j < n) nums1[k++] = nums2[j++];
    }
};
```

**关键点**：用了 O(m) 额外空间。这正是解法3要消除的瓶颈。

---

### 解法3: 逆向双指针 — O(m+n) / O(1) ⭐ 面试首选

**从解法2优化**：解法2需要额外空间是因为"从前往后写会覆盖"。但 `nums1` 尾部有空位！**从后往前写**，每次取两者中**较大的**放到 `nums1` 末尾，写指针永远不会追上读指针，所以不需要额外空间。

```cpp
class Solution {
public:
    void merge(vector<int>& nums1, int m, vector<int>& nums2, int n) {
        int i = m - 1;      // nums1 有效部分的尾指针
        int j = n - 1;      // nums2 的尾指针
        int k = m + n - 1;  // 写入位置，从 nums1 最后一个位置开始
        
        // 从后往前，每次取较大的放到 k 位置
        while (i >= 0 && j >= 0) {
            if (nums1[i] > nums2[j]) {
                nums1[k--] = nums1[i--];
            } else {
                nums1[k--] = nums2[j--];
            }
        }
        
        // 如果 nums2 还有剩余，拷贝过来
        // （如果 nums1 有剩余，它们已经在正确位置，不用动）
        while (j >= 0) {
            nums1[k--] = nums2[j--];
        }
    }
};
```

**为什么不会覆盖**：每次循环，`k` 减 1，同时 `i` 或 `j` 中恰好有一个减 1。如果是 `i` 减 1，那 `i` 和 `k` 同步移动，间距不变；如果是 `j` 减 1，`k` 向左走但 `i` 没动，间距反而增大。因此 `k` 始终 ≥ `i`，永远不会覆盖 `nums1` 未读的元素。

**为什么 nums1 剩余不用处理**：如果 `i >= 0` 但 `j < 0`，说明 `nums2` 已全部放完，`nums1` 前面剩下的元素本来就在 `nums1` 中且有序，位置正确。

## 解法对比

| | 解法1：合并后排序 | 解法2：正向双指针 | 解法3：逆向双指针 |
|---|---|---|---|
| 时间 | O((m+n)log(m+n)) | O(m+n) | O(m+n) |
| 空间 | O(1)（原地排序时） | O(m) | **O(1)** |
| 利用有序性 | ✗ 完全没利用 | ✓ 归并 | ✓ 归并 |
| 核心技巧 | 无 | 拷贝避免覆盖 | **逆向填充避免覆盖** |
| 面试推荐 | 作为起点讨论 | 展示归并思想 | **⭐ 最终答案** |

## 易错点

1. **循环结束后忘记处理 `nums2` 剩余元素**
   - ✗ 只写了 `while (i >= 0 && j >= 0)` 的主循环就结束了
   - ✓ 还需要 `while (j >= 0) nums1[k--] = nums2[j--];` 把 `nums2` 剩余部分拷过来
   - 为什么：如果 `nums2` 的元素都比 `nums1` 小，主循环会因 `i < 0` 退出，此时 `nums2` 还有元素没放进去

2. **误以为 `nums1` 剩余也需要处理**
   - ✗ 多写了 `while (i >= 0) nums1[k--] = nums1[i--];`
   - ✓ 不需要！`nums1` 剩余元素已经在正确位置
   - 虽然多写不会出错（只是自己拷贝到自己），但说明没理解为什么不需要

3. **比较时用 `>=` 还是 `>`**
   - `nums1[i] > nums2[j]` 时取 `nums1[i]`，否则取 `nums2[j]`
   - 用 `>=` 也行，只是影响相等时取哪个，不影响正确性
   - 但如果要保持**稳定性**（相等元素保持原顺序），应该用 `>`（先取 `nums1` 中靠后的）

4. **`m=0` 的边界**
   - `i = m - 1 = -1`，主循环不进入，直接走 `while (j >= 0)` 把 `nums2` 全部拷贝——逻辑自洽，无需特判

## 面试追问

**Q1: 暴力解能过吗？瓶颈在哪？**
合并后排序 O((m+n)log(m+n)) 能过（数据量小），但没利用已排序的条件。面试官会追问"能否更快"。

**Q2: 经典归并为什么需要额外空间？怎么消除？**
从前往后写会覆盖 `nums1` 的有效元素。消除方法：利用 `nums1` 尾部的空位，**从后往前**填充——这就是逆向双指针。

**Q3: 能否证明逆向填充不会覆盖？**
每次写入位置 `k` 和读取位置 `i` 的关系：`k - i = (剩余的 nums2 元素个数) >= 0`。因为每次从 `nums2` 取元素时 `k` 前进但 `i` 不动，差值减小但不会变负。

**Q4: 如果两个数组都不允许修改，要返回新数组呢？**
直接用解法2的正向双指针归并，O(m+n) 时间 + O(m+n) 空间，最优且最自然。

**Q5: 如果不是两个而是 K 个有序数组呢？**
→ 引出 LeetCode 23「合并K个升序链表」，用最小堆/分治，时间 O(N log K)。
