# 2841. 几乎唯一子数组的最大和

## 核心思路

**固定长度滑动窗口 + 哈希表计数**：维护一个长度恰好为 k 的窗口在数组上滑动，用哈希表实时统计窗口内不同元素的个数。当不同元素数 >= m 时（满足"几乎唯一"条件），用窗口和更新答案。

## 思维链

1. **读完题第一反应** → 需要找长度为 k 的子数组中，含有至少 m 个不同元素的，和最大的那个。暴力做法：枚举所有长度为 k 的子数组，对每个用 set 统计不同元素数。O(nk) 太慢。
2. **暴力的瓶颈？** → 每个窗口都重新算 sum 和 distinct count，大量重复计算。相邻窗口只差一个左端和一个右端。
3. **怎么优化？** → 滑动窗口！窗口右移一格时：加入右端新元素，移除左端旧元素。用哈希表 freq 维护频率，freq.size() 就是不同元素数。
4. **窗口和怎么维护？** → 也用增量更新：`sum += nums[right]`，移除时 `sum -= nums[left]`。
5. **什么时候更新答案？** → 窗口大小达到 k 且 freq.size() >= m 时。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举每个长度 k 子数组，set 计数 | O(nk) | O(k) | 能说出但不够 |
| 滑动窗口 + 哈希表 | 固定窗口大小 k，增量维护 | O(n) | O(k) | ⭐ 必须写出 |

## 关键提示

1. **这是"固定长度"滑动窗口**：窗口大小始终为 k，不伸不缩。区别于"可变长度"滑动窗口（如最长无重复子串）。
2. **`freq.size()` 直接给出不同元素数**：不需要额外变量。当某个元素频率降为 0 时，必须 `erase` 它，否则 size 不准确。
3. **返回值是 `long long`**：nums[i] 最大 10^9，k 最大 2*10^4，窗口和最大 2*10^13，超出 int 范围。
4. **res 初始化为 0**：如果不存在满足条件的子数组（所有窗口的不同元素都 < m），返回 0。
5. **窗口建立阶段**：前 k-1 个元素只做加入操作，不需要移除左端。当 `i >= k` 时才开始移除。
6. **频率降为 0 时必须 erase**：如果只做 `freq[left]--` 而不 erase，freq.size() 会包含频率为 0 的"幽灵键"，导致不同元素数虚高。

## 解法详解

### 解法1: 滑动窗口 + 哈希表 — O(n) / O(k) ⭐ 面试首选

**思考过程**: 固定窗口大小为 k，用哈希表 freq 维护窗口内每个元素的出现次数。窗口每右移一步：右端加入、左端移除。freq.size() 就是当前窗口的不同元素数。

```cpp
class Solution {
public:
    long long maxSum(vector<int>& nums, int m, int k) {
        int n = nums.size();
        unordered_map<int, int> freq;  // 值 → 出现次数
        long long sum = 0, res = 0;

        for (int i = 0; i < n; i++) {
            // 1. 右端元素加入窗口
            freq[nums[i]]++;
            sum += nums[i];

            // 2. 窗口大小超过 k 时，移除左端
            if (i >= k) {
                int left = nums[i - k];
                freq[left]--;
                if (freq[left] == 0) freq.erase(left);  // 关键！频率为0要删除
                sum -= left;
            }

            // 3. 窗口大小恰好为 k 时判断
            if (i >= k - 1 && (int)freq.size() >= m) {
                res = max(res, sum);
            }
        }
        return res;
    }
};
```

**关键点**:
- **erase 操作不能省**：`freq[left]--` 后如果为 0，必须 `freq.erase(left)`。否则 `freq.size()` 会把频率为 0 的键也算进去，导致 distinct count 虚高。
- **long long**：sum 和 res 必须用 `long long`，因为 k * max(nums[i]) = 2*10^4 * 10^9 = 2*10^13 超过 int。
- **判断时机**：`i >= k - 1` 表示窗口已经填满 k 个元素（索引从 0 到 k-1）。

### 解法1-变体: 两阶段写法 — 先建窗口后滑动

有些同学觉得上面的统一写法不太直观，可以分成两个阶段：

```cpp
class Solution {
public:
    long long maxSum(vector<int>& nums, int m, int k) {
        int n = nums.size();
        unordered_map<int, int> freq;
        long long sum = 0, res = 0;

        // 阶段1: 建立初始窗口 [0, k-1]
        for (int i = 0; i < k; i++) {
            freq[nums[i]]++;
            sum += nums[i];
        }
        if ((int)freq.size() >= m) res = sum;

        // 阶段2: 窗口右移，每次加入右端、移除左端
        for (int i = k; i < n; i++) {
            // 加入右端 nums[i]
            freq[nums[i]]++;
            sum += nums[i];

            // 移除左端 nums[i-k]
            int left = nums[i - k];
            freq[left]--;
            if (freq[left] == 0) freq.erase(left);
            sum -= left;

            // 判断
            if ((int)freq.size() >= m) {
                res = max(res, sum);
            }
        }
        return res;
    }
};
```

**两种写法等价**，选择哪种看个人偏好。统一写法更简洁，两阶段写法逻辑更清晰。

## 滑动窗口模板总结

本题是**固定长度滑动窗口**的经典模板：

```
for (int i = 0; i < n; i++) {
    // 1. 加入右端元素
    window.add(nums[i]);
    
    // 2. 窗口超出大小时移除左端
    if (i >= k) {
        window.remove(nums[i - k]);
    }
    
    // 3. 窗口大小达到 k 时判断/更新答案
    if (i >= k - 1) {
        update_answer();
    }
}
```

核心思想：**相邻窗口只差一个元素**，避免重复计算。

## 易错点

1. **频率为 0 时不 erase**：
   - ✗ `freq[left]--;` 后不管 → `freq.size()` 仍然包含该键，distinct 数虚高
   - ✓ `if (freq[left] == 0) freq.erase(left);`

2. **sum 用 int 导致溢出**：
   - ✗ `int sum = 0;` → k=20000, nums[i]=10^9 时 sum 可达 2*10^13
   - ✓ `long long sum = 0;`

3. **判断时机搞错**：
   - ✗ `if (i >= k)` 才判断 → 漏掉了第一个窗口（i=k-1 时）
   - ✓ `if (i >= k - 1)` → 窗口刚填满时就要判断

4. **移除左端索引算错**：
   - ✗ `nums[i - k + 1]` → 这是当前窗口的左端点，不是要移除的元素
   - ✓ `nums[i - k]` → 这是窗口外刚被移出的元素

5. **忘记检查 freq.size() 的类型**：
   - ✗ `freq.size() >= m` 可能有符号/无符号比较警告
   - ✓ `(int)freq.size() >= m` 强转后比较

## 面试追问

**Q1: 为什么用 unordered_map 而不是 map？**
> unordered_map 的插入/查找/删除平均 O(1)，map 是 O(log k)。总时间从 O(n) 变成 O(n log k)。对于 k 可达 2*10^4 的场景，unordered_map 更快。

**Q2: 能不能不用 erase，用一个额外变量 distinctCount 来维护？**
> 可以。加入元素时如果 `freq[x]` 从 0 变成 1，distinctCount++；移除元素时如果 `freq[x]` 从 1 变成 0，distinctCount--。这样不需要 erase，但代码略复杂。

**Q3: 如果窗口大小不固定（找长度 >= k 且不同元素 >= m 的最大和），怎么做？**
> 这就变成了可变长度滑动窗口问题。需要用前缀和 + 单调队列等更复杂的数据结构。

**Q4: 时间复杂度为什么是 O(n)？**
> 每个元素最多被加入窗口一次、移出窗口一次。哈希表每次操作 O(1)。总计 O(n) 次操作。
