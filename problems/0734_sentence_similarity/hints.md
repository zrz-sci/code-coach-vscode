# 734. 句子相似性 (Sentence Similarity)

**难度**: Easy | **标签**: Array, Hash Table, String

## 核心思路

判断两个句子是否"相似"：两个句子长度相同，且对应位置的单词要么相同，要么出现在给定的相似词对列表中。注意相似关系**不具有传递性**（a~b, b~c 不能推出 a~c），这与 LC 737（句子相似性 II）形成对比。

解法非常直接：用 HashSet 存储所有相似词对，然后逐位置比较两个句子。核心在于如何高效地查找一对单词是否在相似列表中 -- 将词对编码为字符串（如 `"word1#word2"`）存入 set，查询时正反两个方向都查一次。

## 思维链

1. **长度检查**: 若两句子长度不同，直接返回 false
2. **构建查找结构**: 将 `similarPairs` 中的每对 `(a, b)` 存入 HashSet，key 为 `a#b` 和 `b#a`（双向存储）
3. **逐位比较**: 对每个位置 i，检查 `sentence1[i]` 和 `sentence2[i]`:
   - 若相同 => 继续
   - 若 set 中存在该词对 => 继续
   - 否则 => 返回 false
4. **全部通过**: 返回 true

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| HashSet 存词对 | O(n + p) | O(p) | 最推荐，O(1) 查找 |
| HashMap<string, set<string>> | O(n + p) | O(p) | 邻接表思路，略冗余 |
| 暴力遍历 similarPairs | O(n * p) | O(1) | 无需预处理，但慢 |

其中 n 为句子长度，p 为 similarPairs 的数量。

## 关键提示

1. **长度不等直接返回 false**: 这是最容易忘记的边界条件
2. **相似关系是双向的**: `["great","fine"]` 意味着 great~fine 且 fine~great，存入 set 时要存两个方向
3. **相似关系不可传递**: a~b 且 b~c 不能推出 a~c，所以不需要并查集（那是 LC 737 的考点）
4. **单词与自身相似**: 题目明确说"a word is always similar to itself"，所以 `sentence1[i] == sentence2[i]` 时直接通过
5. **拼接字符串做 key**: 使用分隔符（如 `#`）拼接两个单词，避免 `"ab"+"c"` 和 `"a"+"bc"` 的歧义

## 解法详解

### 解法一：HashSet 存储词对（推荐）

**步骤**:
1. 检查 `sentence1.size() != sentence2.size()`，若不等返回 false
2. 创建 `unordered_set<string> pairSet`
3. 遍历 `similarPairs`，对每对 `[a, b]`，将 `a + "#" + b` 和 `b + "#" + a` 加入 set
4. 遍历每个位置 i：
   - 若 `sentence1[i] == sentence2[i]`，继续
   - 若 `pairSet.count(sentence1[i] + "#" + sentence2[i])`，继续
   - 否则返回 false
5. 循环结束返回 true

**时间复杂度**: O(n + p)，n 为句子长度，p 为相似词对数  
**空间复杂度**: O(p)

### 解法二：HashMap 邻接表

**步骤**:
1. 构建 `unordered_map<string, unordered_set<string>> adj`
2. 对每对 `[a, b]`：`adj[a].insert(b)` 和 `adj[b].insert(a)`
3. 逐位比较时查 `adj[w1].count(w2)` 或 `w1 == w2`

这种方法等效于解法一，但用邻接表结构更直观地表达了"相似关系图"。

**时间复杂度**: O(n + p)  
**空间复杂度**: O(p)

### 解法三：暴力遍历

对每个位置，若两个单词不同，则遍历整个 `similarPairs` 查找是否存在匹配。

**时间复杂度**: O(n * p)  
**空间复杂度**: O(1)

不推荐，但在 p 很小时是最简单的实现。

## 易错点

1. **忘记长度检查**: 两个句子长度不同时必须返回 false，这是第一步
2. **相似关系只存一个方向**: `["great","fine"]` 查询时可能查 `"fine#great"`，如果只存了 `"great#fine"` 会漏判。必须双向存储
3. **字符串拼接无分隔符**: 如果不用 `#` 或其他分隔符，`"a"+"bc"` 和 `"ab"+"c"` 会碰撞。虽然在本题约束下可能不会出问题，但最好加分隔符
4. **认为相似关系可以传递**: 这是 LC 737 的考点，本题明确说不可传递
5. **大小写敏感**: 题目中单词由英文字母组成，比较时直接用 `==` 即可，无需特殊处理大小写
6. **空 similarPairs**: similarPairs 可以为空，此时只有相同的单词才算相似

## 面试追问

1. **如果相似关系是传递的，你会怎么做？**
   - 使用并查集（Union-Find）将所有传递相连的单词归为同一组，然后检查对应位置的单词是否在同一组。这正是 LC 737 的解法

2. **如果 similarPairs 非常大（百万级），如何优化？**
   - HashSet/HashMap 的构建是 O(p)，查询是 O(1)，已经是最优。可以考虑对 key 用更高效的 hash 函数

3. **如何扩展到支持"同义词链"（有限长度传递）？**
   - BFS/DFS 在相似关系图上做限定深度的搜索，判断两个单词是否在 k 步以内可达

4. **如果要找出两个句子中所有不相似的位置，怎么改？**
   - 将 `return false` 改为记录位置索引到结果列表，最后返回列表

5. **这道题和图的关系是什么？**
   - 相似关系构成无向图，每对 `(a, b)` 是一条边。本题只要求判断边的存在性（O(1) 查表），LC 737 要求判断连通性（并查集）
