# 134. 加油站

## 核心思路

本质上是在环形数组上找一个起点，使得从该点出发，沿途**累计净油量（加油 - 耗油）始终非负**。关键洞察：如果总油量 ≥ 总消耗，则一定存在解；而找起点的过程可以通过一次遍历中"净油量最低点"来确定。

## 思维链

1. **读完题第一反应**：环形路线，n 个起点都试一遍？对每个起点模拟绕一圈，看油箱是否始终 ≥ 0 → 暴力 O(n²)。

2. **暴力解的瓶颈**：对每个起点都要模拟走 n 步，n 个起点共 n² 步。能否避免重复模拟？

3. **关键观察**：定义 `diff[i] = gas[i] - cost[i]`，从某起点出发，油箱变化就是 diff 的前缀和。如果在某个位置油箱变负了，说明从这个起点到该位置之间的**任何一个点**都不可能是合法起点（因为它们到达该位置时油只会更少）。

4. **贪心跳跃**：如果从 start 出发，在位置 j 第一次油箱变负，那么 start ~ j 之间的所有点都不行，直接把 start 跳到 j+1。这样一次遍历就能找到唯一答案。

5. **判断无解**：如果 `sum(gas) < sum(cost)`，总油量不够，无论从哪出发都不行，返回 -1。

6. **另一种理解**：把累计净油量看成一条折线图，找到折线图最低点，最低点的下一个位置就是起点——因为从那里出发，折线图被"抬"到最高。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力模拟 | 每个起点模拟绕一圈 | O(n²) | O(1) | 能说出即可 |
| 贪心（跳跃式） | 累计为负则重置起点 | O(n) | O(1) | ⭐ 必须写出 |
| 最低点法 | 找累计净油量最低点 | O(n) | O(1) | 加分项 |

## 关键提示

1. **先想"有没有解"**：`sum(gas) >= sum(cost)` 是有解的充要条件。题目保证解唯一，所以总量够 → 一定有解。

2. **净油量思维**：每站的净油量 `diff[i] = gas[i] - cost[i]`。问题转化为：在环形 diff 数组上找起点，使前缀和始终 ≥ 0。

3. **为什么能跳过？**：如果从 A 出发到 B 油箱变负，A 到 B 之间的任何点 C 出发到 B 时油只会更少（因为从 A 到 C 的累计是正的，少了这段"正贡献"）。

4. **画个折线图帮助理解**：
```
// gas  = [1, 2, 3, 4, 5]
// cost = [3, 4, 5, 1, 2]
// diff = [-2,-2,-2, 3, 3]
//
// 累计前缀和（从 index 0 开始）:
// index:  0   1   2   3   4
// sum:   -2  -4  -6  -3   0
//              ↑
//         折线图从 index 0 开始越来越低
//         最低点在 index 2（值 = -6）
//         所以起点 = index 3（最低点的下一个）
//
// 验证：从 index 3 出发的累计:
// index:  3   4   0   1   2
// sum:    3   6   4   2   0  ← 始终 ≥ 0 ✓
```

5. **环形不需要真的走两圈**：总量够的前提下，一次线性扫描即可确定起点。

## 解法详解

### 解法1: 暴力模拟 — O(n²) / O(1)

**思考过程**: 最直觉的做法——尝试每个加油站作为起点，模拟跑一圈，看油箱是否始终非负。

```cpp
class Solution {
public:
    int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        int n = gas.size();
        for (int start = 0; start < n; start++) {
            int tank = 0;
            bool ok = true;
            for (int step = 0; step < n; step++) {
                int i = (start + step) % n;
                tank += gas[i] - cost[i];
                if (tank < 0) {     // 油箱变负，此起点不行
                    ok = false;
                    break;
                }
            }
            if (ok) return start;
        }
        return -1;
    }
};
```

**关键点**: 
- 用 `(start + step) % n` 处理环形索引。
- 一旦 `tank < 0` 立即 break，不必走完全程。
- n = 10⁵ 时 O(n²) 会超时，需要优化。

---

### 解法2: 贪心（一次遍历 + 跳跃重置） — O(n) / O(1) ⭐ 面试首选

**从解法1优化**: 暴力解中，从 start 出发到 j 失败后，我们傻傻地只把 start 移到 start+1。但其实 start+1 到 j 之间的所有点都不行，可以直接跳到 j+1。

**为什么能跳？**
```
// 假设从 A 出发，经过 B、C、... 到 D 时油箱首次变负
// A → B → C → ... → D (tank < 0)
//
// 从 A 到 B 的累计净油量 ≥ 0（否则 D 不是"首次"变负的位置）
// 所以从 B 出发到 D，比从 A 出发到 D 少了 A→B 这段正贡献
// 油箱只会更少，更不可能走完。C、D 同理。
// 结论：下一个候选起点是 D+1。
```

```cpp
class Solution {
public:
    int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        int n = gas.size();
        int totalSum = 0;   // 全程净油量总和，判断有没有解
        int curSum = 0;     // 从当前 start 出发的累计净油量
        int start = 0;      // 候选起点
        
        for (int i = 0; i < n; i++) {
            int diff = gas[i] - cost[i];
            totalSum += diff;
            curSum += diff;
            
            if (curSum < 0) {
                // 从 start 到 i 走不通，start~i 之间的都不行
                // 跳到 i+1 作为新起点
                start = i + 1;
                curSum = 0;     // 从新起点重新累计
            }
        }
        
        // 总油量不够，无解
        return totalSum >= 0 ? start : -1;
    }
};
```

**关键点**:
- `totalSum` 和 `curSum` 各司其职：`totalSum` 判断全局可行性，`curSum` 寻找起点。
- 最终 `start` 可能等于 n 吗？不会。因为 `totalSum >= 0` 保证了至少有一个合法起点在 [0, n-1] 内。

---

### 解法3: 最低点法 — O(n) / O(1)

**另一种视角**: 不"重置"，而是维护全局的累计净油量。找到累计净油量最小的那个位置 minIdx，起点就是 `(minIdx + 1) % n`。

**直觉**：折线图最低点之后，折线开始"爬升"，从那里出发等于把折线整体抬高，使得全程都不会低于 0。

```
// gas  = [1, 2, 3, 4, 5]
// cost = [3, 4, 5, 1, 2]
// diff = [-2,-2,-2, 3, 3]
//
// 累计:  -2, -4, -6, -3, 0
//                  ↑ 最低点 minIdx=2
// 起点 = (2+1) % 5 = 3 ✓
```

```cpp
class Solution {
public:
    int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        int n = gas.size();
        int totalSum = 0;
        int minSum = INT_MAX;
        int minIdx = 0;
        
        for (int i = 0; i < n; i++) {
            totalSum += gas[i] - cost[i];
            if (totalSum < minSum) {
                minSum = totalSum;
                minIdx = i;         // 记录最低点位置
            }
        }
        
        if (totalSum < 0) return -1;    // 总油量不够
        
        // 最低点的下一个位置就是起点
        return (minIdx + 1) % n;
    }
};
```

**关键点**:
- 这种解法不需要"重置"逻辑，思路更直观（画折线图一目了然）。
- 当最低点恰好在最后一个位置（minIdx = n-1）时，`(n-1+1) % n = 0`，起点是 0，正确。

## 解法对比

| | 暴力模拟 | 贪心跳跃⭐ | 最低点法 |
|---|---|---|---|
| 时间 | O(n²) | O(n) | O(n) |
| 空间 | O(1) | O(1) | O(1) |
| 核心思想 | 枚举+验证 | 失败则跳到下一个候选 | 找全局最低点 |
| 代码复杂度 | 简单 | 简单 | 最简单 |
| 面试推荐 | 先说后优化 | **首选** | 能讲清加分 |

**选择建议**：面试时先口述暴力 O(n²)，然后用"跳跃"逻辑优化到 O(n)。如果面试官问"有没有其他理解方式"，给出最低点法，展示不同角度的思维。

## 易错点

1. **✗ 忘记判 totalSum < 0**：
   ```cpp
   // 错误：直接返回 start，没判断是否真的有解
   return start;
   ```
   **✓ 正确**：必须加 `totalSum >= 0` 判断，否则无解时也会返回一个起点。

2. **✗ curSum < 0 时只跳到 i 而不是 i+1**：
   ```cpp
   if (curSum < 0) {
       start = i;      // 错！i 本身就是让油箱变负的位置
       curSum = 0;
   }
   ```
   **✓ 正确**：`start = i + 1`，因为 i 这站的净油量已经包含在让 curSum 变负的过程中了。

3. **✗ 最低点法中忘记取模**：
   ```cpp
   return minIdx + 1;     // 当 minIdx = n-1 时返回 n，越界！
   ```
   **✓ 正确**：`return (minIdx + 1) % n;`

4. **✗ 混淆"当前站加油量"和"到达当前站时的油量"**：
   - 到达 i 站时先加油（tank += gas[i]），然后消耗油到 i+1 站（tank -= cost[i]）。
   - 合并写成 `tank += gas[i] - cost[i]` 更不容易出错。

## 面试追问

**Q1: 暴力解为什么不行？瓶颈在哪？**
> 暴力对每个起点模拟 n 步，O(n²)。瓶颈在于：从 start 出发失败后，start+1 ~ j 之间的起点被重复验证了。

**Q2: 为什么从 start 出发在 j 失败后，start 到 j 之间的所有点都不行？请严格证明。**
> 设从 start 到位置 k（start < k ≤ j）的累计净油量为 S(start, k)。因为 j 是**第一个**让油箱变负的位置，所以对于 start < k ≤ j，S(start, k-1) ≥ 0。从 k 出发到 j 的累计 = S(start, j) - S(start, k-1)。因为 S(start, j) < 0 且 S(start, k-1) ≥ 0，所以 S(k, j) = S(start, j) - S(start, k-1) < 0。即从 k 出发也走不到 j。

**Q3: 如果题目不保证解唯一，需要返回所有合法起点，怎么改？**
> 最低点法不适用了。可以用 O(n) 的方法：用两个指针模拟环形遍历，或者对每个候选起点用"跳跃"策略跳过不可能的区间，总复杂度仍是 O(n)（每个站最多被访问 2 次）。

**Q4: 你的贪心解法只遍历了一次 [0, n-1]，但起点 start 右边还有一段没验证（start 到 n-1 走完后，0 到 start-1 这段），怎么保证正确？**
> 因为 totalSum ≥ 0 保证了全程总油量够。从 start 到 n-1 累计的正余量，加上 totalSum ≥ 0 的全局保证，意味着 0 到 start-1 这段一定能走完。
