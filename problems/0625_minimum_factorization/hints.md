# 625. 最小因式分解 (Minimum Factorization)

## 核心思路

将一个正整数 num 分解为若干个 1-9 的因子，使得这些因子组成的十进制数最小。**贪心策略**：从大到小（9 到 2）尝试分解因子，大因子放在低位（后添加），小因子自然排在高位。最终将因子从小到大排列组成最小数。特别注意 **32 位溢出**检测。

## 思维链

1. **问题转化**：找最小的数 x，使 x 的每一位数字之积 == num
2. **因子范围**：每一位数字只能是 1-9，所以只需考虑 2-9 的因子（1 不会减少 num）
3. **贪心顺序**：从 9 到 2 逐个尝试整除。为什么从大到小？因为大因子"吸收"更多乘积，产生更少位数 -> 数更小
4. **位数优先**：位数少的数一定更小，所以优先使用大因子来减少总位数
5. **同位数时**：小因子放高位（左边），大因子放低位（右边），数字更小。恰好从 9 到 2 的提取顺序自然实现这一点
6. **组装结果**：提取出的因子从小到大排列，组成十进制数
7. **溢出检测**：结果可能超过 INT_MAX (2^31 - 1)，需要检测

## 解法概览

| 解法 | 思路 | 时间复杂度 | 空间复杂度 | 推荐 |
|------|------|-----------|-----------|------|
| 贪心分解 + vector | 从 9 到 2 提取因子，反转组装 | O(log num) | O(log num) | ⭐ |
| 贪心分解 + 直接构建 | 从 9 到 2 提取，大因子放低位 | O(log num) | O(1) | ⭐ |

## 关键提示

1. **num == 1 特殊处理**：返回 1（1 的位数之积 = 1）
2. **无解判断**：如果分解后 num > 1，说明有大于 9 的质因子（如 11、13），无法用单位数字表示
3. **从大到小分解**：9->8->7->...->2，贪心确保位数最少
4. **组装技巧**：用 vector 收集因子，排序后组成数字；或用 long 直接计算
5. **溢出检测**：结果用 long 存储，最后检查是否 <= INT_MAX

## 解法详解

### 解法一：贪心分解 + vector 收集（推荐）

```cpp
class Solution {
public:
    int smallestFactorization(int num) {
        if (num == 1) return 1;

        vector<int> digits;

        // 从 9 到 2 贪心提取因子
        for (int d = 9; d >= 2; d--) {
            while (num % d == 0) {
                digits.push_back(d);
                num /= d;
            }
        }

        // 无法完全分解 (含有 > 9 的质因子)
        if (num > 1) return 0;

        // 将因子从小到大排列, 组成最小数
        // digits 当前是从大到小的顺序, 需要反转
        long result = 0;
        for (int i = digits.size() - 1; i >= 0; i--) {
            result = result * 10 + digits[i];
            // 溢出检测
            if (result > INT_MAX) return 0;
        }

        return (int)result;
    }
};
```

**复杂度**：时间 O(log num)（每次至少除以 2），空间 O(log num)（存储位数）

### 解法二：贪心分解 + 直接构建（O(1) 空间）

```cpp
class Solution {
public:
    int smallestFactorization(int num) {
        if (num == 1) return 1;

        long result = 0;
        long multiplier = 1;  // 当前位的权重: 1, 10, 100, ...

        // 从 9 到 2: 大因子放低位, 小因子放高位
        for (int d = 9; d >= 2; d--) {
            while (num % d == 0) {
                num /= d;
                result += d * multiplier;
                multiplier *= 10;
                if (result > INT_MAX) return 0;
            }
        }

        // num > 1 说明含有大于 9 的质因子
        return num > 1 ? 0 : (int)result;
    }
};
```

**说明**：这种写法从 9 到 2 提取因子，大因子先进入低位（multiplier 较小），小因子后进入高位（multiplier 较大），自然得到最小排列。

## 易错点

| 错误写法 | 正确写法 | 说明 |
|---------|---------|------|
| ✗ 忘记 `num == 1` 特殊处理 | ✓ `if (num == 1) return 1` | 1 是有效答案，直接返回 |
| ✗ 从 2 到 9 贪心 | ✓ 从 9 到 2 贪心 | 先用大因子减少位数，大因子放低位 |
| ✗ 用 int 存储结果 | ✓ 用 long 存储并检查溢出 | 结果可能超过 2^31-1 |
| ✗ `if (num != 0)` 判断无解 | ✓ `if (num > 1)` 判断无解 | 分解后 num 应该等于 1 才算成功 |
| ✗ 不排序直接组合因子 | ✓ 因子从小到大排列组成最小数 | 如 48 = 6*8, 应输出 68 而非 86 |

## 面试追问

**Q1: 为什么从 9 到 2 的贪心顺序是正确的？**

A: 关键原理是**位数越少数字越小**。大因子（如 9）能更快减小 num，产生更少的位数。例如 num=8 时用一个 8（一位数 "8"）比用三个 2（三位数 "222"）更优。在位数相同时，从 9 到 2 的提取顺序使大因子先进入低位，小因子后进入高位，形成升序排列，这也是最小的数字排列。可以证明：对于任何合法分解，9-to-2 的贪心方案要么位数更少，要么位数相同但字典序更小。

**Q2: num 含有大于 9 的质因子（如 11, 13）时为什么无解？**

A: 因为结果的每一位只能是 0-9，数字 0 和 1 不贡献乘积（0 会让整个乘积为 0，1 不改变乘积但增加位数）。所以有效位数只能是 2-9。如果 num 包含大于 9 的质因子（如 11），它无法用 2-9 的乘积表示。具体来说 2-9 的质因子分解只包含 2, 3, 5, 7，所以 num 的质因子只能来自 {2, 3, 5, 7} 才有解。

**Q3: 如果把 32 位限制改为 64 位或无限制，复杂度会变化吗？**

A: 时间复杂度依然是 O(log num)，因为每次操作至少将 num 除以 2，最多执行 log2(num) 次。对于 32 位输入 num <= 2^31-1，最多约 31 次除法。如果改为 64 位，最多约 63 次。结果的位数也是 O(log num)，因为每次至少除以 2，最多产生 log2(num) 个位数。真正变化的是溢出检测逻辑——64 位需要用 __int128 或字符串来检测。
