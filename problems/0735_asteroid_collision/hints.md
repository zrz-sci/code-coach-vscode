# 735. 小行星碰撞

## 核心思路

本质上是一个**模拟碰撞消除**的过程：从左到右扫描小行星，只有"栈顶向右（正）+ 新来向左（负）"时才会发生碰撞，用**栈**来维护当前存活的小行星，逐个处理碰撞结果。

## 思维链

1. **读完题第一反应**：小行星按位置排列，正数向右飞，负数向左飞。只有"右飞的"和"左飞的"相遇才会碰撞。那我能不能模拟这个过程？

2. **什么时候会碰撞？** 仔细分析四种相邻组合：
   - `→ →`（正正）：同向，不碰
   - `← ←`（负负）：同向，不碰
   - `← →`（负正）：背对背飞走，不碰
   - `→ ←`（正负）：**面对面，唯一碰撞情况！**

3. **暴力模拟的困难**：一颗大的负数小行星可能连续撞毁多颗正数小行星（如示例4中 `-6` 撞毁了 `3` 和 `5`）。每次碰撞后数组会变化，重新扫描效率低。

4. **栈的天然适配**：从左到右遍历，把小行星压入栈。当新来一个负数小行星时，它只可能和栈顶的**正数**小行星碰撞。用栈顶不断和它比较——这正是栈"后进先出"的优势！撞毁一个弹出一个，直到碰撞结束。

5. **碰撞的三种结果**：
   - 栈顶更大 → 新小行星被毁，不入栈
   - 新小行星更大 → 栈顶被毁，弹出，继续碰撞
   - 一样大 → 同归于尽，弹出栈顶，新的也不入栈

6. **最终栈中的元素**就是所有存活的小行星。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 栈模拟 | 遍历数组，用栈处理碰撞 | O(n) | O(n) | ⭐ 必须写出 |
| 原地模拟（双指针） | 用数组本身当栈，指针模拟栈顶 | O(n) | O(1)额外 | 加分项 |

## 关键提示

1. **碰撞条件**：不是所有"正遇到负"都碰撞，只有**栈顶为正、新来为负**才碰撞。如果栈顶也为负，说明两颗都向左飞，不会碰。

2. **一颗小行星可能连续碰撞多次**：`[5, 10, -15]` 中 `-15` 先撞毁 `10`，再撞毁 `5`。所以需要一个 **while 循环**，不是一次 if 判断。

3. **用一个 `alive` 标记**追踪当前新小行星是否还存活，避免逻辑混乱。

4. **碰撞过程的可视化**（以 `[3, 5, -6, 2, -1, 4]` 为例）：
   ```
   处理 3:  栈 = [3]           ← 正数直接入栈
   处理 5:  栈 = [3, 5]        ← 正数直接入栈
   处理 -6: 
     碰 5:  |5| < |-6|, 弹出5  → 栈 = [3]
     碰 3:  |3| < |-6|, 弹出3  → 栈 = []
     入栈:  栈 = [-6]          ← -6 存活
   处理 2:  栈 = [-6, 2]       ← 栈顶为负，不碰
   处理 -1:
     碰 2:  |2| > |-1|, -1被毁 → 栈 = [-6, 2]
   处理 4:  栈 = [-6, 2, 4]    ← 正数直接入栈
   结果: [-6, 2, 4] ✓
   ```

5. **等大碰撞别忘了**：`[8, -8]` 要同归于尽，弹出栈顶后新小行星也不入栈。

## 解法详解

### 解法1: 栈模拟 — O(n) / O(n) ⭐ 面试首选

**思考过程**：从左到右遍历小行星。每颗小行星要么安全入栈，要么和栈顶碰撞。碰撞只发生在"栈顶为正、新来为负"的情况下。碰撞可能连续发生（while循环），直到：新小行星被毁、或栈空、或栈顶不再是正数。

```cpp
class Solution {
public:
    vector<int> asteroidCollision(vector<int>& asteroids) {
        vector<int> stk; // 用 vector 当栈，方便最后直接返回
        
        for (int ast : asteroids) {
            bool alive = true; // 当前小行星是否存活
            
            // 碰撞条件：栈顶向右(>0) 且 当前向左(<0)
            while (alive && !stk.empty() && stk.back() > 0 && ast < 0) {
                if (stk.back() < -ast) {
                    // 栈顶更小，栈顶被毁，弹出，继续检查下一个栈顶
                    stk.pop_back();
                } else if (stk.back() == -ast) {
                    // 一样大，同归于尽
                    stk.pop_back();
                    alive = false;
                } else {
                    // 栈顶更大，当前小行星被毁
                    alive = false;
                }
            }
            
            if (alive) {
                stk.push_back(ast);
            }
        }
        
        return stk;
    }
};
```

**关键点**：
- `while` 而不是 `if`：一颗大的负数小行星可能连续撞毁多颗正数小行星
- 碰撞条件的四个部分缺一不可：`alive`、`!stk.empty()`、`stk.back() > 0`、`ast < 0`
- 用 `vector` 而非 `stack`：避免最后还要倒序输出

### 解法2: 原地模拟（双指针）— O(n) / O(1) 额外空间

**从解法1优化**：解法1用了额外的栈空间。观察到我们可以直接在原数组上操作，用一个指针 `top` 模拟栈顶位置，把原数组当作栈使用。

```cpp
class Solution {
public:
    vector<int> asteroidCollision(vector<int>& asteroids) {
        int top = -1; // 栈顶指针，-1表示栈空
        
        for (int i = 0; i < (int)asteroids.size(); i++) {
            int ast = asteroids[i];
            bool alive = true;
            
            while (alive && top >= 0 && asteroids[top] > 0 && ast < 0) {
                if (asteroids[top] < -ast) {
                    top--;
                } else if (asteroids[top] == -ast) {
                    top--;
                    alive = false;
                } else {
                    alive = false;
                }
            }
            
            if (alive) {
                asteroids[++top] = ast;
            }
        }
        
        // 只保留栈中的元素
        asteroids.resize(top + 1);
        return asteroids;
    }
};
```

**关键点**：直接在输入数组上原地操作，`top` 指针就是栈顶。逻辑和解法1完全一致，只是用 `asteroids[top]` 代替 `stk.back()`。

## 解法对比

| | 解法1: 栈模拟 | 解法2: 原地模拟 |
|---|---|---|
| 时间 | O(n) | O(n) |
| 额外空间 | O(n) | O(1) |
| 代码清晰度 | 更直观，推荐面试用 | 稍复杂，修改了输入 |
| 适用场景 | 通用 | 允许修改输入时 |

两种解法核心逻辑完全一致，每颗小行星最多入栈一次、出栈一次，所以时间都是 O(n)。面试中推荐解法1，代码更清晰不易出错。

## 易错点

1. **用 `if` 代替 `while` 处理碰撞**：
   - ✗ `if (!stk.empty() && stk.back() > 0 && ast < 0)` — 只处理一次碰撞
   - ✓ `while (alive && !stk.empty() && stk.back() > 0 && ast < 0)` — 连续碰撞
   - 为什么：`[5, 10, -15]` 中 `-15` 要先毁 `10` 再毁 `5`

2. **忘记 `alive` 标记导致同归于尽后仍入栈**：
   - ✗ 等大碰撞时只 `pop_back()` 但没设 `alive = false`，导致被毁的小行星仍被 push
   - ✓ 同归于尽时必须 `alive = false`

3. **碰撞条件写反**：
   - ✗ `stk.back() < 0 && ast > 0` — 这是"栈顶向左，新来向右"，两个背对背飞，不碰！
   - ✓ `stk.back() > 0 && ast < 0` — 栈顶向右，新来向左，面对面碰撞

4. **比较大小时忘记取绝对值**：
   - ✗ `stk.back() < ast` — 正数和负数直接比，逻辑全乱
   - ✓ `stk.back() < -ast` — 拿栈顶正数和新小行星的绝对值比

## 面试追问

**Q1: 碰撞只发生在什么情况下？其他三种方向组合为什么不碰？**
> A: 只有"栈顶正（向右）+ 新来负（向左）"才碰。正正/负负同向不碰，负正是背对背越飞越远不碰。

**Q2: 为什么用栈？能不能用队列？**
> A: 碰撞总是发生在"最近放入的"和"新来的"之间，这是后进先出的特性。用队列的话无法高效访问最后放入的元素。

**Q3: 这个算法每颗小行星会被处理多少次？时间复杂度怎么证明是 O(n)？**
> A: 每颗小行星最多入栈一次、出栈一次，所以虽然内层有 while 循环，总操作次数不超过 2n，均摊 O(n)。这是经典的**均摊分析**。

**Q4: 如果要求返回每颗小行星的"存活时间"（经历了多少次碰撞后被毁），怎么改？**
> A: 给每颗小行星维护一个计数器，每次碰撞时更新。栈中存 `{value, collision_count}` 的 pair。
