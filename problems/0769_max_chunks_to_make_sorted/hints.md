# 769. 最多能完成排序的块 (Max Chunks To Make Sorted)

## 核心思路

数组是 `[0, n-1]` 的一个排列，排序后的目标就是 `[0, 1, 2, ..., n-1]`。核心观察：**如果 `max(arr[0..i]) == i`，则位置 i 是一个合法分割点**。这是因为 `arr[0..i]` 排序后必须等于 `[0, 1, ..., i]`，而这等价于这 `i+1` 个元素的最大值恰好为 `i`（因为它们是 `{0, 1, ..., i}` 的排列）。只需维护前缀最大值，每次 `max == i` 时块数加 1。

## 思维链

1. **目标明确**：排序后就是 `[0, 1, 2, ..., n-1]`
2. **分块条件**：在位置 i 处分块，意味着 `arr[0..i]` 排序后恰好是 `[0, 1, ..., i]`
3. **等价条件推导**：`arr[0..i]` 是 `{0, 1, ..., i}` 的排列 iff `max(arr[0..i]) == i`
   - 因为数组是 `[0, n-1]` 的排列，每个值恰好出现一次
   - 如果前 i+1 个元素中最大值为 i，由鸽巢原理它们必然恰好是 `{0, ..., i}`
4. **一次遍历**：维护前缀 max，每次 `max == i` 时计数加 1
5. **贪心正确性**：每个合法分割点都独立贡献一个块，不会互相矛盾

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 前缀最大值 | O(n) | O(1) | 最优解，一次遍历 |
| 单调栈 | O(n) | O(n) | 通用方法，与 768 题一致 |
| 前缀 max + 后缀 min | O(n) | O(n) | 通用分块判定方法 |
| 排序对比法（前缀和） | O(n log n) | O(n) | 利用排列特性简化 |
| 位运算验证法 | O(n) | O(1) | 异或辅助验证 |

## 关键提示

1. **核心公式**：`max(arr[0..i]) == i` 是分割点的充要条件
2. **为什么成立**：数组是 `[0, n-1]` 排列，前 i+1 个元素的最大值为 i，则它们一定恰好是 `{0, 1, ..., i}`（鸽巢原理）
3. **与 768 题对比**：768 题有重复元素，不能用这个简单条件，必须用栈或前缀 max/后缀 min
4. **贪心**：每个满足条件的位置都尽早分割，这样能得到最多的块
5. **n 很小**：约束 `n <= 10`，任何方法都可以通过，但面试中要给出 O(n) 解法并解释原理

## 解法详解

### 解法一：前缀最大值（最优解）

**思路**：维护一个变量 `curMax` 表示 `arr[0..i]` 的最大值。当 `curMax == i` 时，前 `i+1` 个元素恰好是 `{0, 1, ..., i}` 的排列，可以形成独立的一块。

**步骤**：
1. 初始化 `curMax = 0, chunks = 0`
2. 遍历数组，`curMax = max(curMax, arr[i])`
3. 如果 `curMax == i`，则 `chunks++`
4. 返回 `chunks`

**正确性证明**：
- 因为数组是 `[0, n-1]` 的排列，每个值恰好出现一次
- `max(arr[0..i]) == i` 意味着 0 到 i 的所有值都在前 i+1 个位置中
- 所以 `arr[0..i]` 排序后就是 `[0, 1, ..., i]`，可以独立排序

**时间复杂度**：O(n)  
**空间复杂度**：O(1)

### 解法二：单调栈

**思路**：与 768 题完全相同的方法。维护单调递增栈，每个栈元素代表一个块的最大值。由于本题是排列，结果等价于前缀最大值方法，但代码更通用。

**步骤**：
1. 遍历数组，对每个元素维护单调递增栈
2. 遇到更小元素时弹栈合并块，保留合并后最大值
3. 栈大小就是答案

### 解法三：前缀 max + 后缀 min

**思路**：通用方法。位置 i 是分割点当且仅当 `max(arr[0..i]) <= min(arr[i+1..n-1])`。

### 解法四：排序对比法（前缀和）

**思路**：利用排列的特性。排序后目标为 `[0,1,...,n-1]`，前缀和为 `0, 1, 3, 6, ...`。由于是排列（无重复），前缀和相等等价于前缀元素集合相等。

### 解法五：位运算验证法

**思路**：利用异或性质作为辅助验证。`arr[0]^...^arr[i] == 0^1^...^i` 是前缀元素集合相同的必要条件。结合 `max == i` 使用可以增强正确性。

## 易错点

1. **条件是 `max == i` 不是 `max == arr[i]`**：是前缀最大值等于当前**索引** i，不是当前元素值
2. **从 0 开始**：数组值域是 `[0, n-1]`，索引也从 0 开始，两者对应
3. **混淆 768 和 769**：769 是排列（无重复），768 是通用数组（有重复），解法不同
4. **忘记更新 curMax**：必须在判断前更新 `curMax = max(curMax, arr[i])`
5. **n <= 10 的误解**：虽然约束很小，但面试中期望 O(n) 解法并解释原理
6. **初始化错误**：`curMax` 可以初始化为 0（因为 arr[i] >= 0）或 INT_MIN

## 面试追问

1. **Q: 为什么 `max(arr[0..i]) == i` 就能保证分块正确？**
   A: 因为数组是 `[0, n-1]` 的排列。如果前 i+1 个元素的最大值为 i，由鸽巢原理，这 i+1 个元素必然恰好是 `{0, 1, ..., i}`，排序后就是正确位置

2. **Q: 如果数组不是排列（有重复元素），这个方法还能用吗？**
   A: 不能，需要用 768 题的通用方法（单调栈或前缀 max/后缀 min）

3. **Q: 分块最少是多少？最多是多少？**
   A: 最少 1（如 `[n-1, n-2, ..., 0]`，整个数组是一块），最多 n（数组已经有序 `[0,1,2,...,n-1]` 时每个元素独立一块）

4. **Q: 能否用 O(1) 空间完成？**
   A: 前缀最大值方法已经是 O(1) 额外空间。只需要一个变量 curMax 和一个计数器

5. **Q: 如何输出具体的分块方案，而不是只输出块数？**
   A: 记录每个满足 `max == i` 的位置 i，这些位置就是分割点。分块为 `[0..i1], [i1+1..i2], ...`

6. **Q: 前缀和方法在排列场景下为什么可行？**
   A: 排列中每个数只出现一次，如果前 i+1 个数的和等于 `0+1+...+i = i*(i+1)/2`，则这些数一定是 `{0,...,i}`。但对于非排列数组（有重复），前缀和相等不保证元素集合相同
