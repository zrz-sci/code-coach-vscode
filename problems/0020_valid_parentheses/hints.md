# 20. 有效的括号

## 核心思路

这道题本质上是：**最近的左括号必须最先被匹配**——这是一个典型的"后进先出"(LIFO)模式，天然对应栈这种数据结构。

## 思维链

1. **读完题的第一反应**：每个右括号都要和一个左括号配对，而且必须是"最近的、同类型的"左括号。能不能简单计数？
2. **为什么计数不行？** 如果只有一种括号 `()`，计数确实够了。但三种括号混在一起，`([)]` 计数上每种都配对了，但顺序错了。所以**不仅要类型匹配，还要顺序正确**。
3. **什么叫"顺序正确"？** 观察 `({[]})` —— 最后打开的 `[` 必须最先关闭。这就是**后进先出**，也就是栈！
4. **怎么用栈？** 遇到左括号就压栈，遇到右括号就看栈顶是不是对应的左括号。如果是就弹出配对，不是就说明不合法。
5. **最终检查**：遍历完后栈必须为空，否则说明有多余的左括号没配对。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力替换 | 反复删除 `()` `[]` `{}` 直到无法删除 | O(n²) | O(n) | 能说出即可 |
| 栈匹配 | 左括号入栈，右括号检查栈顶 | O(n) | O(n) | ⭐ 必须写出 |
| 栈匹配(变体) | 遇到左括号压入对应右括号，简化判断 | O(n) | O(n) | 加分项 |

## 关键提示

1. **想想为什么"最近"这个概念很重要？** `([])`能匹配但`([)]`不能，区别在于`]`应该先和最近的`[`配对。哪种数据结构天然维护"最近"？
2. **遇到右括号时，你需要做什么？** 需要检查"最近一个还没配对的左括号"是否与它匹配。如果栈为空说明什么？
3. **遍历结束后还要检查什么？** 所有右括号都匹配了，但左括号可能有剩余，比如 `((`。
4. **有个小技巧**：遇到左括号时不压左括号本身，而是压入它对应的右括号。这样遇到右括号时直接比较 `==` 就行，不用再写映射逻辑。

```
// 栈匹配过程演示: s = "({[]})"
//
// 字符  操作            栈状态(底→顶)
//  (    左括号, 入栈     [ ( ]
//  {    左括号, 入栈     [ (, { ]
//  [    左括号, 入栈     [ (, {, [ ]
//  ]    右括号, 栈顶=[匹配! 弹出  [ (, { ]
//  }    右括号, 栈顶={匹配! 弹出  [ ( ]
//  )    右括号, 栈顶=(匹配! 弹出  [ ]  ← 空栈
//
// 遍历结束, 栈为空 → 返回 true

// 失败案例: s = "([)]"
//
// 字符  操作            栈状态(底→顶)
//  (    左括号, 入栈     [ ( ]
//  [    左括号, 入栈     [ (, [ ]
//  )    右括号, 栈顶=[ ≠ ) → 不匹配! 返回 false
```

## 解法详解

### 解法1: 暴力替换 — O(n²) / O(n)

**思考过程**: 最直觉的想法——既然配对的括号可以"消除"，那就反复在字符串中找 `()`、`[]`、`{}`，找到就删除，直到没法再删。如果最终字符串为空就合法。

```cpp
class Solution {
public:
    bool isValid(string s) {
        // 反复扫描，每次删除相邻的配对括号
        string prev;
        do {
            prev = s;
            // 用 string::find 和 erase 删除所有相邻配对
            size_t pos;
            while ((pos = s.find("()")) != string::npos) s.erase(pos, 2);
            while ((pos = s.find("[]")) != string::npos) s.erase(pos, 2);
            while ((pos = s.find("{}")) != string::npos) s.erase(pos, 2);
        } while (s != prev); // 直到没有变化
        
        return s.empty();
    }
};
```

**关键点**：
- 每次 `erase` 操作是 O(n)，最多需要 n/2 轮，所以总体 O(n²)。
- 这个解法直觉上好理解，但效率太低，面试中只作为"说说暴力思路"即可。
- **瓶颈**：每次删除后要重新扫描整个字符串，大量重复工作。

### 解法2: 栈匹配 — O(n) / O(n) ⭐ 面试首选

**从解法1优化**: 暴力法的瓶颈是"反复扫描和删除"。我们观察到，括号配对本质是**后进先出**——最后遇到的左括号必须最先配对。用栈就能一次遍历搞定，不需要反复扫描。

```cpp
class Solution {
public:
    bool isValid(string s) {
        stack<char> stk;
        
        for (char c : s) {
            if (c == '(' || c == '[' || c == '{') {
                // 左括号：压入栈，等待配对
                stk.push(c);
            } else {
                // 右括号：检查栈顶是否是对应的左括号
                // 栈为空说明没有左括号可以配对
                if (stk.empty()) return false;
                
                char top = stk.top();
                // 类型必须匹配
                if ((c == ')' && top != '(') ||
                    (c == ']' && top != '[') ||
                    (c == '}' && top != '{')) {
                    return false;
                }
                stk.pop(); // 配对成功，弹出
            }
        }
        
        // 遍历结束后栈必须为空（没有多余的左括号）
        return stk.empty();
    }
};
```

**关键点**: 
- 三个返回 `false` 的场景：①右括号多了（栈空时遇到右括号）②类型不匹配 ③左括号多了（遍历结束栈非空）
- 用 `unordered_map` 可以替代 if-else 判断，代码更简洁（见解法3）

### 解法3: 栈匹配(压入期望值) — O(n) / O(n) — 加分写法

**优化思路**: 解法2中判断匹配需要写三个 `||` 条件。一个技巧是：遇到左括号时**压入对应的右括号**。这样遇到右括号时只需要 `==` 比较，代码更优雅。

```cpp
class Solution {
public:
    bool isValid(string s) {
        stack<char> stk;
        
        for (char c : s) {
            // 遇到左括号，压入它"期望的"右括号
            if (c == '(')      stk.push(')');
            else if (c == '[') stk.push(']');
            else if (c == '{') stk.push('}');
            else {
                // 遇到右括号，检查栈顶的"期望值"是否等于当前字符
                // stk.empty(): 没有左括号可配对
                // stk.top() != c: 类型不匹配
                if (stk.empty() || stk.top() != c) return false;
                stk.pop();
            }
        }
        
        return stk.empty();
    }
};
```

**关键点**: 这个技巧在面试中展示，说明你对栈的使用很灵活。核心思想是"把判断逻辑前移到入栈时"。

## 解法对比

| | 解法1 暴力替换 | 解法2 栈匹配 | 解法3 压入期望值 |
|---|---|---|---|
| 时间 | O(n²) | O(n) | O(n) |
| 空间 | O(n) | O(n) | O(n) |
| 核心思想 | 反复消除配对 | 后进先出匹配 | 同解法2，入栈时预处理 |
| 代码简洁度 | 差 | 中 | 好 |
| 面试推荐 | 仅口述 | ⭐ 首选 | 加分 |

解法2和3本质相同，只是编码技巧不同。面试中写解法2即可，如果时间充裕可以优化为解法3展示代码能力。

## 易错点

1. **✗ 忘记检查 `stk.empty()`**：遇到右括号时直接 `stk.top()`，如果栈为空会 runtime error。
   ```cpp
   // ✗ 错误：没检查栈空
   char top = stk.top();  // 当 s = ")" 时，栈为空，崩溃！
   // ✓ 正确：先检查
   if (stk.empty()) return false;
   char top = stk.top();
   ```

2. **✗ 遍历结束后直接返回 `true`**：忘记检查栈是否为空，导致 `"((("` 返回 true。
   ```cpp
   // ✗ 错误
   return true;
   // ✓ 正确
   return stk.empty();
   ```

3. **✗ 匹配方向搞反**：写成 `c == '(' && top != ')'`，逻辑反了。当前字符是右括号，栈顶应该是对应的左括号。

## 面试追问

**Q1 (基础理解)**: 为什么不能只用三个计数器分别记录三种括号的数量？
> **A**: 计数器只能保证数量匹配，不能保证顺序。比如 `([)]`，每种括号数量都对，但顺序不合法。栈能记录"打开顺序"，保证最近的左括号最先配对。

**Q2 (优化追问)**: 有没有 O(1) 空间的做法？
> **A**: 如果字符串可以修改，可以用字符串本身当栈（用一个指针 `top` 标记栈顶位置）。但严格来说空间还是 O(n)，因为字符串本身占空间。如果字符串不可修改，O(1) 空间无法实现——需要记录历史信息。

**Q3 (变体追问)**: 如果括号类型不固定，比如有自定义的括号对 `<>` 或更多类型，怎么扩展？
> **A**: 用 `unordered_map<char, char>` 存储右括号→左括号的映射，判断逻辑不变。遇到不在 map 中的字符就是左括号，入栈；在 map 中的就是右括号，检查栈顶。
