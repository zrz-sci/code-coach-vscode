# 1758. 生成交替二进制字符串的最少操作数

## 核心思路

交替二进制字符串只有两种可能的形态：`"010101..."` 或 `"101010..."`。我们的任务是找到把原字符串变成这两种目标中哪一种所需的修改次数更少。关键观察：这两种目标互补 —— 某个位置需要为目标 A 修改，当且仅当它不需要为目标 B 修改。因此只需计算一种即可推出另一种。

## 思维链

1. **读完题第一反应**：交替字符串是什么？就是相邻字符不同。对于只有 `'0'` 和 `'1'` 的字符串，交替字符串长这样：`"0101..."` 或 `"1010..."`。也就是说，目标字符串是完全确定的，只有两种可能。

2. **暴力方法**：分别构造两个目标字符串 pattern1 = `"0101..."` 和 pattern2 = `"1010..."`，然后逐位比较原字符串与这两个目标的差异，取较小值。时间 O(n)，空间 O(n)（因为要构造目标字符串）。

3. **优化观察 - 不需要真的构造目标字符串**：对于位置 `i`，pattern1 期望的字符就是 `i % 2`（偶数位 `'0'`，奇数位 `'1'`）。所以不需要真的创建一个字符串，只需要对每个位置判断 `s[i]` 是否等于期望值。

4. **关键的互补性质**：设 cost1 是变成 pattern1 的代价（不匹配的位数），cost2 是变成 pattern2 的代价。因为在每个位置上，pattern1 和 pattern2 的期望值恰好相反，所以如果某位置不匹配 pattern1，就一定匹配 pattern2，反之亦然。这意味着 `cost1 + cost2 = n`（字符串长度）。所以 `cost2 = n - cost1`，答案就是 `min(cost1, n - cost1)`。

5. **最终方案**：一次遍历，只计算与 pattern1 不匹配的个数 cost1，返回 `min(cost1, n - cost1)`。时间 O(n)，空间 O(1)。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 推荐 |
|------|------|------|------|------|
| 一次遍历 | 比较每个位置与 "0101..." 的差异，利用互补性 | O(n) | O(1) | 面试唯一解 |

## 关键提示

1. **只有两种目标**：交替二进制字符串只有 `"0101..."` 和 `"1010..."` 两种。不需要搜索或枚举，直接比较即可。

2. **位置决定期望值**：对于目标 `"0101..."`，位置 `i` 的期望字符为 `'0' + (i % 2)`，即偶数位为 `'0'`，奇数位为 `'1'`。

3. **互补关系是核心**：两种目标的不匹配计数之和恰好等于字符串长度 n。这使得只算一次就够了：`min(cost1, n - cost1)`。

4. **不需要特判**：空字符串（n=0）时 cost1=0，返回 min(0, 0)=0，自然正确。n=1 时也无需特殊处理。

5. **如何思考这道题的本质**：这道题的关键不是"怎么操作"，而是"目标是什么"。一旦意识到目标只有两种可能且互补，问题就变成了简单的计数。

## 解法详解

### 一次遍历 — O(n) / O(1)

**思考过程**：把问题分解为"比较"和"计数"两步。

```
示例: s = "0100"

与 pattern1 = "0101" 比较:
  位置 0: s[0]='0', 期望='0', 匹配 ✓
  位置 1: s[1]='1', 期望='1', 匹配 ✓
  位置 2: s[2]='0', 期望='0', 匹配 ✓
  位置 3: s[3]='0', 期望='1', 不匹配 ✗  → cost1 = 1

与 pattern2 = "1010" 比较:
  cost2 = n - cost1 = 4 - 1 = 3

答案 = min(1, 3) = 1
```

```
示例: s = "1111"

与 pattern1 = "0101" 比较:
  位置 0: '1' vs '0' ✗
  位置 1: '1' vs '1' ✓
  位置 2: '1' vs '0' ✗
  位置 3: '1' vs '1' ✓  → cost1 = 2

cost2 = 4 - 2 = 2

答案 = min(2, 2) = 2
```

**为什么互补**：在每个位置 i，pattern1 期望的字符和 pattern2 期望的字符恰好相反。所以对于 s[i]，它要么匹配 pattern1（此时不匹配 pattern2），要么匹配 pattern2（此时不匹配 pattern1），二者必居其一。因此所有位置的不匹配数之和 = n。

```cpp
class Solution {
public:
    int minOperations(string s) {
        int n = s.size();
        int cost1 = 0; // 变成 "0101..." 需要修改的次数
        for (int i = 0; i < n; i++) {
            // pattern1 期望: 偶数位 '0'，奇数位 '1'
            char expected = '0' + (i % 2);
            if (s[i] != expected) cost1++;
        }
        // pattern2 的修改次数 = n - cost1（互补）
        return min(cost1, n - cost1);
    }
};
```

### 变体写法：利用异或

```cpp
class Solution {
public:
    int minOperations(string s) {
        int n = s.size(), cost1 = 0;
        for (int i = 0; i < n; i++) {
            // (s[i] - '0') 是实际值 (0 或 1)
            // (i % 2) 是 pattern1 的期望值
            // 异或: 相同为0，不同为1 —— 正好是"是否需要修改"
            cost1 += (s[i] - '0') ^ (i % 2);
        }
        return min(cost1, n - cost1);
    }
};
```

## 解法对比

| | 标准写法 | 异或写法 |
|---|---|---|
| 可读性 | 高 | 中 |
| 代码量 | 略长 | 更短 |
| 性能 | O(n) / O(1) | O(n) / O(1) |
| 推荐 | 面试首选 | 竞赛技巧 |

## 易错点

1. **忘记两种 pattern 互补，多算了一遍**：
   - ✗ 分别遍历一遍算 cost1 和 cost2（两次遍历，时间翻倍）
   - ✓ 只算一种，另一种用 `n - cost1` 推导
   - 虽然两次遍历也能 AC（时间复杂度不变），但说明没有理解互补性质。

2. **混淆偶数位/奇数位的期望值**：
   - ✗ `char expected = (i % 2 == 0) ? '1' : '0';`（把 pattern1 和 pattern2 搞反了）
   - ✓ 无论选哪种作为 pattern1 都可以，关键是保持一致，然后取 min。
   - 实际上选哪种作为 pattern1 不影响结果，因为最终取 `min(cost1, n - cost1)`。

3. **没有取 min，只返回了 cost1**：
   - ✗ `return cost1;`
   - ✓ `return min(cost1, n - cost1);`
   - cost1 可能大于 n/2，此时另一种模式更优。

4. **对期望值使用整数而非字符比较**：
   - ✗ `if (s[i] != i % 2)` — `s[i]` 是 `'0'` 或 `'1'`（ASCII 48 或 49），`i % 2` 是 0 或 1
   - ✓ `if (s[i] != '0' + i % 2)` 或 `if ((s[i] - '0') != i % 2)`

## 面试追问

**Q1: 为什么两种 pattern 的代价之和恰好是 n？能不能严格证明？**
对于每个位置 i，pattern1[i] 和 pattern2[i] 恰好相反（一个是 '0' 一个是 '1'）。所以 s[i] 要么等于 pattern1[i]（此时不等于 pattern2[i]，cost2 这一位 +1），要么不等于 pattern1[i]（此时一定等于 pattern2[i]，cost1 这一位 +1）。每个位置恰好贡献给 cost1 或 cost2 中的一个，所以 cost1 + cost2 = n。

**Q2: 如果字符串包含的不是 '0' 和 '1'，而是任意两种字符（比如 'a' 和 'b'），代码怎么改？**
先确定两种字符分别是什么（遍历或直接用前两个不同的字符），然后用同样的逻辑：偶数位期望第一种字符，奇数位期望第二种。互补性质依然成立。

**Q3: 如果要求返回修改后的字符串而不是修改次数，怎么做？**
先判断 cost1 和 cost2 哪个更小，然后按对应的 pattern 构造结果字符串。如果 cost1 <= cost2，就把每个不匹配 pattern1 的位置改成 pattern1 的期望值。

**Q4: 如果允许交换操作（交换两个位置的字符）而不是单独修改，最少需要多少次交换？**
这是一个更复杂的问题。需要分析哪些位置需要从 0 变 1、哪些从 1 变 0，如果数量匹配可以配对交换（一次交换解决两个错位），否则需要额外的单独修改。
