# 949. Largest Time for Given Digits

## 核心思路

给定4个数字，找出能组成的最大合法24小时制时间。核心方法是**枚举所有排列**：4个数字的全排列最多只有 4! = 24 种，对每种排列检查是否构成合法时间（HH:MM，其中 HH 在 [0,23]，MM 在 [0,59]），在所有合法时间中取最大值。由于搜索空间极小（常数级），暴力枚举是最优且最清晰的策略。

## 思维链

1. **观察搜索空间**：4个数字的排列只有24种，完全可以暴力枚举
2. **确定合法性判断**：将4位排列视为 `d[0]d[1]:d[2]d[3]`，合法条件为 `d[0]*10+d[1] <= 23` 且 `d[2]*10+d[3] <= 59`
3. **选择最大值**：将时间转为分钟数 `hours*60 + minutes` 进行比较，维护最大值
4. **处理无解情况**：如果没有任何合法排列，返回空字符串
5. **格式化输出**：将最大值转回 `"HH:MM"` 格式，注意前导零

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 全排列枚举 | O(1) | O(1) | 最直观，24种排列逐一检查 |
| 四重循环枚举 | O(1) | O(1) | 不用排列API，手动枚举4个位置 |
| 从23:59倒推 | O(1) | O(1) | 从最大时间往下试，但实现较复杂 |

## 关键提示

1. **排列数极小**：4! = 24，暴力就是最优解，不需要任何优化
2. **注意前导零**：输出 "09:30" 而不是 "9:30"
3. **用分钟总数比较大小**：`h * 60 + m` 统一比较
4. **next_permutation 用法**：先排序数组，然后循环调用 `next_permutation`
5. **无解判断**：初始化最大值为 -1，最终检查是否仍为 -1

## 解法详解

### 解法一：全排列枚举（推荐）

**思路**：将输入数组排序后，利用 `next_permutation` 遍历所有排列。对每个排列，将前两位作为小时、后两位作为分钟，检查合法性并维护最大时间值。

**步骤**：
1. 对 arr 排序（`next_permutation` 要求从最小排列开始才能遍历完整）
2. 使用 do-while 循环配合 `next_permutation` 遍历所有24种排列
3. 对每个排列计算 `hours = arr[0]*10 + arr[1]`，`minutes = arr[2]*10 + arr[3]`
4. 如果 `hours <= 23 && minutes <= 59`，用 `hours*60 + minutes` 更新最大值
5. 遍历结束后，将最大值转回字符串格式

**复杂度**：时间 O(1)，空间 O(1)，因为排列数和数组大小都是常数。

### 解法二：四重循环枚举

**思路**：用4层嵌套循环分别枚举4个位置的数字（确保每个数字恰好用一次），省去排列库的使用。

**步骤**：
1. 外层循环选第一位 i，内层选第二位 j（j != i），再选第三位 k（k != i,j），第四位 l 自动确定
2. 计算 hours 和 minutes，检查合法性
3. 维护最大值

**复杂度**：时间 O(1)（4*3*2*1 = 24次），空间 O(1)。

## 易错点

1. **忘记排序**：使用 `next_permutation` 前必须排序，否则不能遍历所有排列
2. **前导零丢失**：格式化输出时必须保证两位数格式，如 "08:05"
3. **边界值23:59**：小时最大23（不是24），分钟最大59
4. **空字符串返回**：当所有排列都不合法时（如 [5,5,5,5]），必须返回 `""`
5. **混淆12/24小时制**：题目明确是24小时制，小时范围是 0-23

## 面试追问

1. **Q: 如果数字个数不是4而是更多，怎么从中选4个组成最大时间？**
   A: 使用组合 C(n,4) 选出4个数字，再对每组做全排列检查。复杂度 O(C(n,4) * 24)。

2. **Q: 如果要求最小合法时间呢？**
   A: 同样枚举所有排列，维护最小值即可。初始值设为 INT_MAX。

3. **Q: 如何扩展到支持秒数的格式 HH:MM:SS？需要6个数字。**
   A: 6! = 720 种排列，仍然是常数级。增加秒数合法性检查（0-59）即可。

4. **Q: 这道题的解法能否推广到更通用的"给定数字组成满足约束的最大数"问题？**
   A: 是的，核心模式是"小规模排列枚举 + 约束检查 + 最优值维护"。适用于数字个数有限（<=8）的场景。
