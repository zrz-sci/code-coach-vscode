# 799. Champagne Tower - 香槟塔

## 核心思路

本题模拟香槟从金字塔顶部向下流动的过程。不要试图用数学公式直接算出某个杯子的液面量，而是 **自顶向下模拟溢出过程**：每个杯子最多盛 1 杯，超出部分平分流向左下和右下两个杯子。这是一个典型的 **模拟 DP** 问题，状态转移就是物理流体的溢出规则。

核心观察：每个杯子"收到"的液体可能远超 1 杯，但实际盛放最多 1 杯，多余的均匀溢出到下一行。

## 思维链

1. **建模**：dp[r][c] 表示第 r 行第 c 个杯子"收到"的液体总量（可能超过 1）
2. **初始条件**：dp[0][0] = poured（全部倒入顶部）
3. **状态转移**：如果 dp[r][c] > 1，溢出量 = dp[r][c] - 1，一半流向 dp[r+1][c]，一半流向 dp[r+1][c+1]
4. **答案**：min(1.0, dp[query_row][query_glass])
5. **优化**：只需模拟到 query_row 行，且可用滚动数组优化空间

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 核心技巧 | 适用场景 |
|------|-----------|-----------|---------|---------|
| 二维 DP 模拟 | O(R^2) | O(R^2) | 自顶向下溢出 | 逻辑最清晰 |
| 滚动数组优化 | O(R^2) | O(R) | 一维数组复用 | 空间最优 |

其中 R = query_row。

## 关键提示

### 提示 1 - 不要用数学公式
这道题看似可以用组合数学（每条路径流量为 1/2^depth），但实际上杯子有容量限制（最多 1 杯），溢出量取决于中间层的累积情况，不能简单用路径概率计算。必须逐层模拟。

### 提示 2 - 收到量 vs 实际盛放量
关键区别：dp[r][c] 记录的是杯子"收到"的总液体量，可以远大于 1。实际盛放量 = min(1.0, dp[r][c])。溢出量 = max(0.0, dp[r][c] - 1.0)。

### 提示 3 - 溢出分配规则
对于杯子 (r, c)，如果 dp[r][c] > 1.0：
- overflow = dp[r][c] - 1.0
- dp[r+1][c] += overflow / 2.0（流向左下）
- dp[r+1][c+1] += overflow / 2.0（流向右下）

每个杯子只有两个出口，各分一半。

### 提示 4 - 只需模拟到目标行
不需要模拟整个 100 行金字塔。只需从第 0 行模拟到第 query_row 行即可。如果 poured 很小而 query_row 很大，中间很多杯子的收到量为 0，自然不会溢出。

### 提示 5 - 滚动数组优化
第 r+1 行只依赖第 r 行的数据。可以用两个一维数组交替使用，将空间从 O(R^2) 降到 O(R)。注意新行必须清零后再累加溢出量。

## 解法详解

### 解法一：二维 DP 模拟（面试首选）

**建模**：
- dp[r][c] = 第 r 行第 c 个杯子收到的液体总量
- 第 r 行有 r+1 个杯子（c 从 0 到 r）

**初始化**：dp[0][0] = poured

**转移**：从上往下，从左往右扫描每个杯子：
```
for r in [0, query_row):
    for c in [0, r]:
        if dp[r][c] > 1.0:
            overflow = dp[r][c] - 1.0
            dp[r+1][c] += overflow / 2.0
            dp[r+1][c+1] += overflow / 2.0
```

**答案**：min(1.0, dp[query_row][query_glass])

**举例**：poured = 2, query_row = 1, query_glass = 1

第 0 行：dp[0][0] = 2 > 1，溢出 1，各 0.5 流向 dp[1][0] 和 dp[1][1]
第 1 行：dp[1][0] = 0.5, dp[1][1] = 0.5
答案：min(1.0, 0.5) = 0.5

**举例**：poured = 100000009, query_row = 33, query_glass = 17

大量液体从顶部涌入，每层分流。到第 33 行时液体分布近似正态分布，中间位置(17)收到最多。由于杯子容量限制为 1，答案为 1.0。

### 解法二：滚动数组优化

**核心变化**：用一维数组 cur[] 代替二维数组。每处理一行，创建新数组 next[]，将溢出量累加到 next 中，然后 cur = next。

**注意事项**：
- next 数组大小为 r+2（第 r+1 行有 r+2 个杯子）
- 每次创建 next 时必须初始化为 0
- 处理完所有行后，cur[query_glass] 就是答案

## 易错点

1. **混淆收到量和实际盛放量**
   - 错误：dp[r][c] = min(overflow/2, 1.0)（在累加时就截断）
   - 正确：先累加所有收到的液体（可能超过 1），溢出时再减去 1

2. **整数除法代替浮点除法**
   - 错误：overflow / 2（C++ 中整数除法截断小数）
   - 正确：overflow / 2.0（确保浮点运算）

3. **忘记 min(1.0, ...) 截断最终答案**
   - 错误：直接返回 dp[query_row][query_glass]（可能 > 1）
   - 正确：return min(1.0, dp[query_row][query_glass])

4. **数组大小分配错误**
   - 错误：每行分配 query_row 个元素
   - 正确：第 r 行有 r+1 个杯子，但考虑溢出到 r+1 行需要 r+2 个位置

5. **poured 为 0 的边界情况**
   - poured = 0 时所有杯子为空，直接返回 0.0
   - 算法自然处理，dp[0][0] = 0，无溢出，答案 min(1.0, 0) = 0

6. **溢出量计算时机**
   - 错误：在一个杯子溢出后立即更新自身为 1.0
   - 正确：自身的值不需要修改（下一行只看溢出量），但如果是滚动数组方案，则无所谓

## 面试追问

**Q1: 为什么不能用数学公式直接计算？**
如果没有容量限制，从顶到 (r,c) 有 C(r,c) 条路径，每条路径流量为 poured/2^r，总流量为 poured * C(r,c)/2^r。但容量限制 1 杯会改变溢出分配——某个满了的杯子会向下游多分流，破坏了均匀分配假设。所以必须逐层模拟。

**Q2: 如果杯子容量不是 1 而是任意值 cap[r][c]，怎么改？**
把 dp[r][c] > 1.0 改为 dp[r][c] > cap[r][c]，溢出量改为 dp[r][c] - cap[r][c]。其余逻辑不变。

**Q3: 如果金字塔的分流比例不是 1:1 而是任意比例 a:b 呢？**
左下分流 overflow * a/(a+b)，右下分流 overflow * b/(a+b)。比例可以不同甚至每个杯子不一样。

**Q4: 时间复杂度 O(R^2) 还能优化吗？**
不能。第 r 行有 r+1 个杯子都需要处理，总计 1+2+...+(R+1) = O(R^2)。这是问题的固有复杂度。

**Q5: 如果 query_row 很大但 poured 很小（比如 poured=1, query_row=99），还需要模拟那么多行吗？**
poured=1 时顶部杯子恰好满，无溢出，所有下面的杯子为 0。可以提前终止。一般化：如果某一行所有杯子都 <= 1 且没有溢出，后续行全为 0。可以加一个 early termination 检查来优化实际运行时间。

**Q6: 这个问题和 Pascal 三角形有什么关系？**
如果没有容量限制（cap = infinity），流量分布恰好是 Pascal 三角形的每个系数乘以 poured/2^r。容量限制打破了这个优美的数学结构，使问题变成必须模拟的 DP。
