# 680. 验证回文串 II

## 核心思路

本质上在问：一个字符串最多删除一个字符后，能否变成回文串？关键洞察是**双指针从两端向中间收缩，遇到不匹配时只有两种选择——删左或删右，分别尝试即可**。

## 思维链

1. **读完题第一反应**：最朴素的做法——枚举删除哪个字符（或不删），然后判断剩下的字符串是否是回文。每次判断 O(n)，枚举 n+1 种情况，总共 O(n²)。

2. **暴力解的瓶颈在哪？**：我们对每个位置都生成了一个新字符串再判断回文，其实大部分位置根本不需要尝试删除。**瓶颈在于盲目枚举删除位置**。

3. **关键观察**：回文串的特征是两端对称。如果我们用双指针从两端向中间走，`s[left] == s[right]` 时两端一定不需要删除。**只有 `s[left] != s[right]` 时，才需要考虑删除**。

4. **突破瓶颈**：当 `s[left] != s[right]` 时，只有两种选择：
   - 删除左边字符：判断 `s[left+1 ... right]` 是否是回文
   - 删除右边字符：判断 `s[left ... right-1]` 是否是回文
   - 任一成功就返回 true

5. **为什么只需检查一次不匹配？** 因为题目说"最多删一个字符"，所以遇到第一个不匹配时用掉唯一的删除机会，之后的子串必须是严格回文。

6. **复杂度**：双指针走一遍 O(n)，遇到不匹配最多再检查两个子串（每个也是 O(n)），总共 O(n)。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举删除每个位置，逐一判断回文 | O(n²) | O(n) | 能说出即可 |
| 双指针贪心 | 两端收缩，不匹配时尝试删左/删右 | O(n) | O(1) | ⭐ 必须写出 |

## 关键提示

1. **回文判断的核心**：双指针从两端向中间移动，配对字符必须相等。回忆 LeetCode 125（验证回文串 I）。

2. **不匹配时只有两条路**：遇到 `s[left] != s[right]`，要么删 `s[left]`（跳过左边），要么删 `s[right]`（跳过右边），不需要尝试其他位置。

3. **为什么不会有第二次不匹配还能修复的情况？** 因为题目限制"最多删一个"，第一次不匹配用掉了删除机会，之后必须严格回文。

4. **图解 "abca" 的判断过程**：
   ```
   a b c a
   ↑     ↑   s[0]='a' == s[3]='a' ✓ → 收缩
     b c
     ↑ ↑     s[1]='b' != s[2]='c' ✗
             → 尝试1: 删左, 检查 "c" → 回文 ✓ → 返回 true
             → 尝试2: 删右, 检查 "b" → 回文 ✓
   ```

5. **易忽略的点**：如果从头到尾都没有不匹配，说明原串本身就是回文，不需要删除，直接返回 true。

## 解法详解

### 解法1: 暴力枚举 — O(n²) / O(n)

**思考过程**：最直觉的方法——既然可以删一个字符，那就枚举删除每个位置（以及不删），对每种情况判断是否回文。

```cpp
class Solution {
public:
    bool validPalindrome(string s) {
        int n = s.size();
        // 先检查不删的情况
        if (isPalindrome(s, 0, n - 1)) return true;
        // 枚举删除第 i 个字符
        for (int i = 0; i < n; i++) {
            // 构造删除 s[i] 后的字符串
            string t = s.substr(0, i) + s.substr(i + 1);
            if (isPalindrome(t, 0, t.size() - 1)) return true;
        }
        return false;
    }
    
    bool isPalindrome(const string& s, int left, int right) {
        while (left < right) {
            if (s[left] != s[right]) return false;
            left++;
            right--;
        }
        return true;
    }
};
```

**关键点**：
- 每次 `substr` 创建新字符串，产生 O(n) 的额外开销
- 总共 n 次枚举 × 每次 O(n) 判断 = O(n²)，对 n=10⁵ 可能超时
- 这个方法的价值在于帮助理解题意，面试中可以作为暴力解提出

### 解法2: 双指针贪心 — O(n) / O(1) ⭐ 面试首选

**从解法1优化**：暴力解的瓶颈是"盲目枚举删除位置"。其实大部分字符根本不需要删。用双指针从两端收缩，只有在不匹配时才需要尝试删除，而且只需尝试两种情况。

```
// 图解完整流程 (s = "abcbka"):
// 
//   a b c b k a
//   ↑         ↑   s[0]='a' == s[5]='a' ✓ → left++, right--
//     b c b k
//     ↑     ↑     s[1]='b' != s[4]='k' ✗
//                  → 尝试删左: 检查 s[2..4] = "cbk" → 回文? c≠k → false
//                  → 尝试删右: 检查 s[1..3] = "bcb" → 回文? b==b, c中间 → true!
//   结果: true
```

```cpp
class Solution {
public:
    bool validPalindrome(string s) {
        int left = 0, right = s.size() - 1;
        while (left < right) {
            if (s[left] != s[right]) {
                // 不匹配！用掉唯一的删除机会
                // 删左边(left+1..right) 或 删右边(left..right-1)
                return isPalindrome(s, left + 1, right) 
                    || isPalindrome(s, left, right - 1);
            }
            left++;
            right--;
        }
        // 全程匹配，原串就是回文
        return true;
    }
    
    bool isPalindrome(const string& s, int left, int right) {
        while (left < right) {
            if (s[left] != s[right]) return false;
            left++;
            right--;
        }
        return true;
    }
};
```

**关键点**：
- `isPalindrome` 传的是引用 + 索引，不创建新字符串，O(1) 空间
- 主函数最多走 n/2 步，遇到不匹配后 `isPalindrome` 最多再走 n/2 步，总共 O(n)
- 短路求值 `||`：如果删左边成功就不会再检查删右边

## 解法对比

| | 暴力枚举 | 双指针贪心 |
|---|---|---|
| 时间 | O(n²) | O(n) |
| 空间 | O(n) 每次创建新串 | O(1) 只用索引 |
| 核心思想 | 枚举所有可能 | 精准定位需要删除的位置 |
| 面试推荐 | 口述即可 | ⭐ 必须实现 |

**双指针之所以高效**：两端相等的字符一定不需要删除（因为它们已经满足回文的对称要求），只有不等时才需要尝试。这把"搜索空间"从 n 个位置缩小到了 1 个位置（第一个不匹配处）。

## 易错点

1. **忘记处理"原串就是回文"的情况**：
   - ✗ 认为一定会遇到不匹配 → 死循环或返回错误
   - ✓ while 循环正常结束时返回 true，说明从未遇到不匹配

2. **只尝试删一边**：
   - ✗ `return isPalindrome(s, left+1, right);` 只尝试删左边
   - ✓ `return isPalindrome(s, left+1, right) || isPalindrome(s, left, right-1);`
   - 反例：`s = "lcupucu"`，第一次不匹配在 `l` vs `u`，删左边 `cupucu` 是回文，但如果换个例子只有删右边才行

3. **isPalindrome 的范围搞错**：
   - ✗ `isPalindrome(s, left, right)` — 没有跳过不匹配的字符
   - ✓ `isPalindrome(s, left+1, right)` 或 `isPalindrome(s, left, right-1)`

4. **在暴力解中用 substr 导致 TLE**：
   - 当 n=10⁵ 时，O(n²) 在 LeetCode 上大概率超时

## 面试追问

**Q1: 如果不允许删除任何字符，怎么判断回文？(基础)**
→ 就是 LeetCode 125 的核心逻辑：双指针从两端向中间走，所有对应位置都相等。这是本题的基础组件 `isPalindrome`。

**Q2: 如果允许删除最多 k 个字符呢？(进阶)**
→ 这就变成了经典问题"编辑距离"的变体。不能再用 O(n) 的贪心了，因为每次不匹配都有两种选择，且可以选 k 次。可以用：
- **递归 + 记忆化**：`solve(left, right, k)` 表示 `s[left..right]` 删除最多 k 个能否回文
- **DP**：类似最长回文子序列，如果 `len(s) - LPS(s) <= k` 则可以
- 时间 O(n²)

**Q3: 能否返回需要删除的那个字符的索引？**
→ 在遇到 `s[left] != s[right]` 时，分别检查删左和删右。如果删左（`isPalindrome(s, left+1, right)`）成功，删除的索引是 `left`；如果删右成功，索引是 `right`。如果两者都不成功，返回 -1。

**Q4: 如果字符串很长（10⁸），需要优化常数怎么办？**
→ 避免函数调用开销，可以内联 isPalindrome；用 `const char*` 直接操作字符数组而非 `string`；考虑缓存友好性（顺序访问 vs 随机访问，这里本身就是顺序的）。
