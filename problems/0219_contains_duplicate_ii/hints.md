# 219. 存在重复元素 II

## 核心思路

这道题本质上在问：**在一个大小为 k+1 的滑动窗口内，是否存在重复元素？** 把"距离约束"转化为"窗口约束"是关键的思维跳跃。

## 思维链

1. **读完题第一反应**：对于每个元素，我需要检查它前面（距离不超过 k 的范围内）有没有和它相同的值。最朴素的做法？对每个 `i`，往回扫 `k` 个位置看有没有相同的 → 双重循环暴力。

2. **暴力解的瓶颈在哪？** 对每个元素都要回头看 k 个元素，总体 O(n·k)。当 n 和 k 都很大时会超时。瓶颈在于**每次查找"窗口内是否存在某个值"**需要 O(k) 时间。

3. **怎么突破瓶颈？** 有两个方向：
   - **哈希表记录最近出现位置**：遍历时记录每个值最后出现的索引，遇到重复值直接比较索引差。查找从 O(k) → O(1)。
   - **滑动窗口 + 哈希集合**：维护一个大小不超过 k 的窗口（用 set），窗口内查重复是 O(1)。

4. **哈希表法核心逻辑**：用 `map<int, int>` 存 `{值 → 最近索引}`。遇到一个值时：如果 map 里已有这个值且索引差 ≤ k，返回 true；否则更新索引。

5. **滑动窗口法核心逻辑**：用 `set<int>` 维护当前窗口（最近 k 个元素）。每次加入新元素前先查 set，如果已存在则返回 true；如果窗口超过 k，移除最左边的元素。

6. **两种方法的权衡**：哈希表法更直觉、代码更短；滑动窗口法空间严格控制在 O(min(n,k))，体现了"窗口"这个核心思想。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力双循环 | 对每个 i 向前扫 k 个 | O(n·k) | O(1) | 能说出即可 |
| 哈希表记录最近索引 | map 存值→最近索引 | O(n) | O(n) | ⭐ 必须写出 |
| 滑动窗口 + 哈希集合 | set 维护窗口内元素 | O(n) | O(min(n,k)) | 加分项 |

## 关键提示

- **提示1**：如果同一个值出现了 3 次以上，你只需要关心"最近"的那次出现。为什么？因为如果最近一次都不满足距离 ≤ k，更早的那次距离只会更大。

- **提示2**：`abs(i - j) <= k` 等价于说 i 和 j 处于一个大小为 k+1 的窗口内。你能否维护这样一个窗口？

- **提示3**：滑动窗口法中，窗口大小最多为 k（不是 k+1），因为当处理索引 i 时，窗口存的是 `[i-k, i-1]` 范围的元素，新元素 i 是在查完之后才加入的。

- **提示4**：想想 LeetCode 217（存在重复元素 I）是怎么做的？那道题是全局查重，这道题加了距离约束，本质是把"全局"缩小为"窗口"。

```
示例: nums = [1,2,3,1,2,3], k = 2

暴力法对每个元素回看2个:
  i=0: 无前驱
  i=1: 看[1] → 无重复
  i=2: 看[1,2] → 无重复
  i=3(val=1): 看[2,3] → 无重复 (1在索引0,距离3>k)
  i=4(val=2): 看[3,1] → 无重复
  i=5(val=3): 看[1,2] → 无重复
  → 返回 false

哈希表法:
  i=0: map={1:0}
  i=1: map={1:0, 2:1}
  i=2: map={1:0, 2:1, 3:2}
  i=3(val=1): 已有1→索引0, |3-0|=3 > k=2, 更新 map={1:3, 2:1, 3:2}
  i=4(val=2): 已有2→索引1, |4-1|=3 > k=2, 更新 map={1:3, 2:4, 3:2}
  i=5(val=3): 已有3→索引2, |5-2|=3 > k=2, 更新
  → 返回 false
```

## 解法详解

### 解法1: 暴力双循环 — O(n·k) / O(1)

**思考过程**: 最直接的思路，对每个元素 `nums[i]`，向前检查最多 k 个元素，看是否有相同值。

```cpp
class Solution {
public:
    bool containsNearbyDuplicate(vector<int>& nums, int k) {
        int n = nums.size();
        for (int i = 0; i < n; i++) {
            // 只需向前看 k 个（而不是向后），避免重复检查
            for (int j = i + 1; j <= min(i + k, n - 1); j++) {
                if (nums[i] == nums[j]) {
                    return true;
                }
            }
        }
        return false;
    }
};
```

**关键点**: 内层循环的上界是 `min(i + k, n - 1)`，不要写成 `i + k` 否则数组越界。这个解法在 k 很大时退化为 O(n²)，LeetCode 上会 TLE。

---

### 解法2: 哈希表记录最近索引 — O(n) / O(n) ⭐ 面试首选

**从解法1优化**: 暴力法的瓶颈是"对每个元素要线性扫描窗口查重"。如果我们用哈希表记录每个值**最近一次出现的索引**，查找就变成 O(1)。

核心洞察：**如果同一个值出现多次，只有最近的那次出现才有可能满足距离 ≤ k。** 所以我们只需要存最近索引，每次更新即可。

```cpp
class Solution {
public:
    bool containsNearbyDuplicate(vector<int>& nums, int k) {
        unordered_map<int, int> lastIndex; // 值 → 最近出现的索引
        
        for (int i = 0; i < nums.size(); i++) {
            auto it = lastIndex.find(nums[i]);
            // 如果之前出现过，且距离 ≤ k，找到了
            if (it != lastIndex.end() && i - it->second <= k) {
                return true;
            }
            // 无论是否出现过，都更新为最新索引
            lastIndex[nums[i]] = i;
        }
        return false;
    }
};
```

**关键点**: 
- 不需要在 map 中删除旧条目，直接覆盖更新为最新索引。
- `i - it->second` 一定 ≥ 0（因为 i 单调递增），不需要用 `abs()`。

---

### 解法3: 滑动窗口 + 哈希集合 — O(n) / O(min(n,k))

**换个角度**: 把问题理解为"是否存在一个大小 ≤ k+1 的窗口包含重复元素"。我们维护一个最多 k 个元素的集合，代表当前窗口。

```
窗口滑动过程: nums = [1,2,3,1], k = 3
  i=0: set={}      → 查1不在 → 加入 → set={1}
  i=1: set={1}     → 查2不在 → 加入 → set={1,2}
  i=2: set={1,2}   → 查3不在 → 加入 → set={1,2,3}  (size=3=k, 满了)
  i=3: set={1,2,3} → 查1在!  → 返回true
```

```cpp
class Solution {
public:
    bool containsNearbyDuplicate(vector<int>& nums, int k) {
        unordered_set<int> window; // 维护当前窗口内的元素
        
        for (int i = 0; i < nums.size(); i++) {
            // 窗口满了，移除最左边的元素
            if (i > k) {
                window.erase(nums[i - k - 1]);
            }
            // 如果当前元素已在窗口中，说明有距离 ≤ k 的重复
            if (!window.insert(nums[i]).second) {
                return true; // insert 失败说明已存在
            }
        }
        return false;
    }
};
```

**关键点**:
- `window.insert(nums[i]).second` 返回 false 表示插入失败（元素已存在），这是一个巧妙的"查+插"合一写法。
- 移除条件是 `i > k`（不是 `i >= k`），因为窗口最多可以容纳 k 个历史元素（加上当前的就是 k+1 个索引范围）。
- 空间是 O(min(n,k))：如果 k ≥ n，窗口永远不需要删除，最多 n 个元素。

## 解法对比

| | 暴力双循环 | 哈希表 (最近索引) | 滑动窗口 (集合) |
|---|---|---|---|
| 时间 | O(n·k) | O(n) | O(n) |
| 空间 | O(1) | O(n) | O(min(n,k)) |
| 核心思想 | 线性扫描 | 空间换时间 | 窗口约束 |
| 代码难度 | 简单 | 简单 | 中等 |
| 面试推荐 | ✗ | ✓ 首选 | ✓ 展示窗口思维 |

- **哈希表法** 代码最短、最好写，面试时首选。
- **滑动窗口法** 空间更优，且体现了"距离约束 = 窗口约束"这个重要思想，如果面试官追问空间优化可以给出。
- 实际上两者运行时间差不多，差异在空间：哈希表存所有不同值，滑动窗口只存窗口内的值。

## 易错点

1. **滑动窗口删除时机错误**
   - ✗ `if (i >= k) window.erase(nums[i-k]);` → 窗口大小变成 k 而不是 k+1，会漏掉恰好距离为 k 的合法配对
   - ✓ `if (i > k) window.erase(nums[i-k-1]);` → 先删除窗口外的，再插入新的

2. **哈希表法忘记更新索引**
   - ✗ 找到重复但距离 > k 时，不更新索引就 `continue` → 后续更近的重复可能被忽略
   - ✓ 无论是否满足距离条件，每次都更新 `lastIndex[nums[i]] = i`

3. **暴力法内层循环越界**
   - ✗ `for (int j = i+1; j <= i+k; j++)` → 当 i+k ≥ n 时越界
   - ✓ `for (int j = i+1; j <= min(i+k, n-1); j++)`

4. **k = 0 的边界情况**
   - k = 0 意味着 i 和 j 必须相同，但题目要求"不同的索引"，所以 k = 0 时一定返回 false
   - 三种解法都能自然处理这个 case（暴力法内层循环不执行，哈希表法距离至少为 1 不可能 ≤ 0，滑动窗口 set 为空）

## 面试追问

**Q1（基础理解）**: 暴力法能通过吗？瓶颈在哪？
> 不能，O(n·k) 最坏 O(n²)，n=10⁵ 时约 10¹⁰ 次操作。瓶颈在于每次都要线性扫描窗口查找重复。

**Q2（优化思路）**: 你用了哈希表，空间是 O(n)。能否进一步优化空间？
> 可以。既然只关心距离 ≤ k 的范围，我们只需要维护大小为 k 的窗口，用 `unordered_set` 存窗口内元素，空间 O(min(n,k))。

**Q3（变体）**: 如果改成 `abs(nums[i] - nums[j]) <= t` 且 `abs(i - j) <= k`（LeetCode 220），怎么做？
> 这就是"存在重复元素 III"。不能用普通哈希集合了（因为不是精确匹配而是范围查找）。可以用 `std::set`（有序集合）在 O(log k) 时间内查找 `[nums[i]-t, nums[i]+t]` 范围内是否有元素；或者用桶排序思想，以 t+1 为桶大小，只需查相邻桶。

**Q4（思维扩展）**: 如果查询是多次的，即多次给不同的 k 值，如何预处理？
> 预处理每个值出现的所有索引（sorted），查询时对任意 k，遍历每个值的索引列表，检查相邻索引差是否 ≤ k。预处理 O(n)，每次查询 O(n)。
