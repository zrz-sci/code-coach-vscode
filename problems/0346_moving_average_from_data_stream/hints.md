# 346. 数据流中的移动平均值

## 核心思路

本质上是维护一个**固定大小的滑动窗口**，每次新元素进来时，如果窗口已满就淘汰最老的元素，然后返回窗口内所有元素的平均值。关键在于选择什么数据结构来高效地"先进先出"淘汰旧元素。

## 思维链

1. **读完题第一反应**：每次 `next` 被调用时，我需要知道最近 `size` 个数的平均值。最朴素的做法？把所有数存起来，每次取最后 `size` 个求和再除。

2. **暴力解的瓶颈在哪？**：每次调用 `next` 都要遍历最后 `size` 个元素求和，时间 O(size)。数据量大时每次都重新求和太浪费了——因为相邻两次调用之间，窗口只变化了一个元素（加了一个新的，可能淘汰了一个旧的）。

3. **怎么突破瓶颈？**：既然每次只变化一个元素，我可以**维护一个 running sum**（累计和）。新元素进来时 sum += val，如果窗口满了还要 sum -= 被淘汰的元素。这样每次 `next` 就是 O(1)。

4. **淘汰谁？**：需要淘汰"最早进入窗口的元素"。这正是**队列（FIFO）**的特性！用一个队列存储窗口内的元素，满了就 `pop` 队首。

5. **最终方案**：队列 + 累计和。队列负责维护窗口内容（知道该淘汰谁），累计和负责 O(1) 算平均值。

## 解法概览

| 解法 | 思路 | 时间（每次 next） | 空间 | 面试 |
|------|------|------|------|------|
| 暴力数组 | 存所有值，每次取最后 size 个求和 | O(size) | O(n) | 能说出即可 |
| 队列 + 累计和 | 队列维护窗口，sum 增量更新 | O(1) | O(size) | ⭐ 必须写出 |
| 循环数组 + 累计和 | 用固定大小数组替代队列 | O(1) | O(size) | 加分项 |

## 关键提示

1. **FIFO 思维**：窗口满了要淘汰"最老的"元素，什么数据结构天然支持"先进先出"？
2. **增量更新**：相邻两次 `next` 调用之间，窗口只变化了一个元素（+1 -1），不需要每次都重新遍历求和。
3. **窗口未满时的处理**：刚开始元素不足 `size` 个，除数应该是当前元素个数而不是 `size`。
4. **循环数组技巧**：如果不想用 queue，可以用 `index % size` 实现循环覆盖，这在嵌入式等不方便用 STL 的场景很有用。

```
窗口大小 size=3 的过程示意:

next(1):  窗口 [1]         sum=1   avg=1/1=1.0
next(10): 窗口 [1,10]      sum=11  avg=11/2=5.5
next(3):  窗口 [1,10,3]    sum=14  avg=14/3=4.667  ← 窗口刚好满
next(5):  窗口 [10,3,5]    sum=18  avg=18/3=6.0    ← 淘汰1, 加入5
                ↑ 淘汰队首(1), sum-=1, sum+=5
```

## 解法详解

### 解法1: 暴力数组 — O(size) / O(n)

**思考过程**: 最直觉的做法，把所有历史数据都存起来，每次需要平均值时，取最后 `min(count, size)` 个元素求和。简单但每次 `next` 都要遍历。

```cpp
class MovingAverage {
public:
    int windowSize;
    vector<int> data;
    
    MovingAverage(int size) {
        windowSize = size;
    }
    
    double next(int val) {
        data.push_back(val);
        // 取最后 windowSize 个元素（不足则取全部）
        int count = min((int)data.size(), windowSize);
        double sum = 0;
        for (int i = data.size() - count; i < data.size(); i++) {
            sum += data[i];
        }
        return sum / count;
    }
};
```

**关键点**: 
- 每次都重新遍历窗口内元素求和，浪费了"上次已经算过大部分"的信息。
- 空间会随着调用次数无限增长（存了所有历史数据），但实际只需要最近 `size` 个。

### 解法2: 队列 + 累计和 — O(1) / O(size) ⭐ 面试首选

**从解法1优化**: 解法1的瓶颈是"每次遍历窗口求和"。观察到窗口每次只变化一个元素，所以用 **增量更新 sum** 代替重新计算。用**队列**维护窗口内容，当窗口满时弹出队首（最老元素）。

```cpp
class MovingAverage {
public:
    queue<int> window;   // 维护当前窗口内的元素
    int windowSize;
    double sum;          // 窗口内元素的累计和
    
    MovingAverage(int size) {
        windowSize = size;
        sum = 0;
    }
    
    double next(int val) {
        // 如果窗口已满，淘汰最老的元素
        if ((int)window.size() == windowSize) {
            sum -= window.front();  // 累计和减去被淘汰的值
            window.pop();
        }
        // 新元素入队
        window.push(val);
        sum += val;
        // 除数是当前窗口实际元素个数（可能还没填满）
        return sum / window.size();
    }
};
```

**关键点**: 
- `sum` 的增量更新是核心——每次只做一次加法和可能一次减法，O(1)。
- 队列的 `front()` 正好是最老的元素，完美匹配"滑动窗口淘汰最老"的需求。

### 解法3: 循环数组 + 累计和 — O(1) / O(size)

**换一个思路**: 不用 queue，而是用一个固定大小的数组，通过 `index % size` 实现循环覆盖。新元素直接覆盖最老元素的位置。这种方式在某些语言/场景中比队列更高效（无动态内存分配）。

```cpp
class MovingAverage {
public:
    vector<int> window;  // 固定大小的循环数组
    int windowSize;
    int count;           // 已插入的元素总数
    double sum;
    
    MovingAverage(int size) {
        windowSize = size;
        window.resize(size, 0);  // 预分配固定大小
        count = 0;
        sum = 0;
    }
    
    double next(int val) {
        int idx = count % windowSize;  // 循环索引：新值要写入的位置
        // 如果窗口已满，被覆盖位置的旧值就是要淘汰的
        sum -= window[idx];  // 窗口未满时 window[idx]=0，减去也没关系
        window[idx] = val;
        sum += val;
        count++;
        // 实际窗口内元素个数
        return sum / min(count, windowSize);
    }
};
```

**关键点**:
- `count % windowSize` 让数组像一个环一样循环使用，无需移动元素。
- 初始化数组全为 0，所以窗口未满时 `sum -= window[idx]` 减去的是 0，逻辑统一无需 if 判断。

```
循环数组示意 (size=3):

count=0: idx=0  window=[0,0,0]  写入1  → [1,0,0]  sum=1
count=1: idx=1  window=[1,0,0]  写入10 → [1,10,0] sum=11
count=2: idx=2  window=[1,10,0] 写入3  → [1,10,3] sum=14
count=3: idx=0  window=[1,10,3] 淘汰1,写入5 → [5,10,3] sum=18
                 ↑ 回到位置0，覆盖最老的1
count=4: idx=1  window=[5,10,3] 淘汰10,写入2 → [5,2,3] sum=10
                    ↑ 覆盖位置1的10
```

## 解法对比

| | 解法1: 暴力数组 | 解法2: 队列+累计和 | 解法3: 循环数组 |
|---|---|---|---|
| 每次 next 时间 | O(size) 遍历求和 | O(1) 增量更新 | O(1) 增量更新 |
| 空间 | O(n) 无限增长 | O(size) 固定 | O(size) 固定 |
| 实现难度 | 最简单 | 简单 | 稍需理解取模 |
| 适用场景 | 数据量小 | 面试通用首选 | 嵌入式/无STL |

**核心区别**：解法2和3都是 O(1) 时间，区别在于数据结构的选择。队列更直观，循环数组更底层高效（少一层封装，无动态内存操作）。

## 易错点

1. **除数用 size 而不是实际元素个数**
   - ✗ `return sum / windowSize;` — 窗口未满时除数太大，结果偏小
   - ✓ `return sum / window.size();`（队列）或 `return sum / min(count, windowSize);`（循环数组）
   - 原因：前几次调用时元素不足 size 个，应该除以实际个数

2. **循环数组忘记减去旧值**
   - ✗ 只做 `sum += val` 不做 `sum -= window[idx]`
   - ✓ 先减旧值再覆盖：`sum -= window[idx]; window[idx] = val; sum += val;`
   - 原因：覆盖位置上有旧值（窗口满时）需要从 sum 中去掉

3. **sum 用 int 导致精度问题**
   - ✗ `int sum;` 然后 `return sum / count;` — 整数除法丢失小数
   - ✓ `double sum;` 或者 `return (double)sum / count;`

## 面试追问

**Q1（基础理解）**: 为什么用队列而不是栈？
> 因为需要淘汰**最早进入**的元素（FIFO），栈是 LIFO 只能访问最新元素。滑动窗口的"滑出"操作天然对应队列的 dequeue。

**Q2（优化）**: 如果 size 非常大（比如 10^9），但实际数据流很短（比如 10^4 次调用），你的循环数组方案有什么问题？怎么改？
> 循环数组会预分配 size 大小的空间造成浪费。此时应该用队列方案（解法2），队列最多存 min(调用次数, size) 个元素，按需分配。

**Q3（变体）**: 如果要同时支持"移动平均值"和"移动中位数"，数据结构怎么改？
> 中位数不能只靠 sum 增量更新，需要维护有序结构。可以用两个堆（大顶堆+小顶堆）维护滑动窗口的中位数，配合哈希表延迟删除（参考 LeetCode 480）。
