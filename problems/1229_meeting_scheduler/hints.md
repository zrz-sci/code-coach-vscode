# 1229. 安排会议日程

## 核心思路

本质上是一道**两个有序区间列表求交集**的问题：找到两人空闲时间的最早重叠区间，使得重叠长度 ≥ duration。

## 思维链

1. **读完题第一反应**：两个人各有若干空闲时段，我需要找到它们的重叠部分，且重叠长度 ≥ duration。最朴素的做法？把 slots1 的每个区间和 slots2 的每个区间都配对比较，看重叠部分够不够长。

2. **暴力解的瓶颈**：O(m×n) 的双重遍历，每对都要算交集。当 m、n 各有 10⁴ 时是 10⁸，偏慢。更关键的是——很多配对根本不可能有交集（一个在时间轴很前面，另一个在很后面），白白浪费比较。

3. **怎么突破？** 如果两个列表都按开始时间排序，就可以用**双指针**：两个指针分别扫描两个列表，每次只比较当前指向的两个区间。结束时间较早的那个区间不可能再和后面的区间有更好的交集，所以直接推进那个指针。这和"合并两个有序数组"的思路一模一样。

4. **两个区间怎么求交集？** 交集的开始 = max(start1, start2)，交集的结束 = min(end1, end2)。如果 交集结束 - 交集开始 ≥ duration，就找到了答案。

5. **谁先移动？** 谁的结束时间更早，谁就移动。因为结束时间早的区间已经"用完了"，不可能和对方后面的区间有交集。

6. **要求最早**：因为两个列表排序后双指针从前往后扫，第一个满足条件的交集天然就是最早的。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 双重循环检查所有配对 | O(mn) | O(1) | 能说出即可 |
| 排序 + 双指针 | 排序后用双指针线性扫描求交集 | O(m log m + n log n) | O(1) | ⭐ 必须写出 |
| 堆（优先队列） | 合并所有区间放入最小堆 | O((m+n) log(m+n)) | O(m+n) | 加分项 |

## 关键提示

1. **两个区间的交集公式**：overlap_start = max(s1, s2)，overlap_end = min(e1, e2)。如果 overlap_start < overlap_end，说明有交集。

2. **双指针移动规则**：结束时间小的先移动。想想为什么——如果 end1 < end2，那 slots1[i] 不可能和 slots2[j+1], slots2[j+2]... 有交集（因为后面的 start 更大，而 end1 已经小于当前 start2 了）。

3. **题目没说输入已排序**！虽然示例看起来是有序的，但题目只保证"同一个人的空闲时间不重叠"，没说已排序。必须先排序。

4. **返回的是 [overlap_start, overlap_start + duration]**，不是 [overlap_start, overlap_end]。我们要的是恰好 duration 长度的最早时段。

5. **预过滤优化**：可以在排序前先过滤掉长度 < duration 的区间，因为即使这个区间完全被包含在对方的区间里，交集也不够长。

```
时间轴示意（示例1）:
slots1:  [---10---50---]  [---60----------120---]  [---140--------210---]
slots2:  [0---15]                [60--70]

重叠区间:  [10,15] 长度5    [60,70] 长度10
                              ↑
                          10 >= 8 ✓ → 返回 [60, 68]
```

## 解法详解

### 解法1: 暴力枚举 — O(mn) / O(1)

**思考过程**：最直接的想法——枚举所有 (slots1[i], slots2[j]) 的配对，计算每对的交集长度，找到第一个 ≥ duration 的。为了保证"最早"，需要先排序，然后按交集开始时间记录最早的。

```cpp
class Solution {
public:
    vector<int> minAvailableDuration(vector<vector<int>>& slots1, 
                                      vector<vector<int>>& slots2, 
                                      int duration) {
        // 先排序保证从早到晚处理
        sort(slots1.begin(), slots1.end());
        sort(slots2.begin(), slots2.end());
        
        vector<int> best;  // 记录最早的合法交集
        
        for (auto& s1 : slots1) {
            for (auto& s2 : slots2) {
                // 计算两个区间的交集
                int lo = max(s1[0], s2[0]);
                int hi = min(s1[1], s2[1]);
                
                if (hi - lo >= duration) {
                    // 返回恰好 duration 长度的时段
                    vector<int> candidate = {lo, lo + duration};
                    if (best.empty() || candidate[0] < best[0]) {
                        best = candidate;
                    }
                }
            }
        }
        return best;
    }
};
```

**关键点**：排序后其实可以提前 break（当 s2 的开始时间 > s1 的结束时间时，后面的 s2 都不可能和 s1 有交集了），但整体思路仍是 O(mn)。

---

### 解法2: 排序 + 双指针 — O(m log m + n log n) / O(1) ⭐ 面试首选

**从解法1优化**：暴力法对每个 s1 遍历所有 s2，但排序后两个列表都是有序的。利用双指针，每次只比较当前的一对，用完一个就推进，线性扫描即可。

```
// 双指针工作过程（示例1，duration=8）:
//
// i=0, j=0: slots1=[10,50] vs slots2=[0,15]
//   交集 = [max(10,0), min(50,15)] = [10,15], 长度5 < 8
//   end2=15 < end1=50 → j++
//
// i=0, j=1: slots1=[10,50] vs slots2=[60,70]
//   交集 = [max(10,60), min(50,70)] = [60,50], 60>50 无交集
//   end1=50 < end2=70 → i++
//
// i=1, j=1: slots1=[60,120] vs slots2=[60,70]
//   交集 = [max(60,60), min(120,70)] = [60,70], 长度10 >= 8 ✓
//   返回 [60, 68]
```

```cpp
class Solution {
public:
    vector<int> minAvailableDuration(vector<vector<int>>& slots1, 
                                      vector<vector<int>>& slots2, 
                                      int duration) {
        // 必须先排序！题目没保证输入有序
        sort(slots1.begin(), slots1.end());
        sort(slots2.begin(), slots2.end());
        
        int i = 0, j = 0;
        while (i < slots1.size() && j < slots2.size()) {
            // 计算当前两个区间的交集
            int lo = max(slots1[i][0], slots2[j][0]);
            int hi = min(slots1[i][1], slots2[j][1]);
            
            // 交集长度 >= duration，找到答案
            if (hi - lo >= duration) {
                return {lo, lo + duration};
            }
            
            // 结束时间早的区间已经"用完"，推进它的指针
            // 为什么？因为结束早的不可能和对方后面的区间有交集
            if (slots1[i][1] < slots2[j][1]) {
                i++;
            } else {
                j++;
            }
        }
        
        return {};  // 没找到
    }
};
```

**关键点**：
- 移动结束时间小的指针，而不是开始时间小的。这是因为结束时间小的区间已经没有"剩余空间"可以和对方后续区间匹配了。
- 第一个找到的就是最早的，因为双指针从前往后扫。

---

### 解法3: 最小堆 — O((m+n) log(m+n)) / O(m+n)

**不同角度**：把两个人的所有区间混在一起，按开始时间排入最小堆。每次弹出堆顶，看堆顶和堆中下一个元素是否有足够的重叠。

**为什么可行？** 如果堆中连续弹出的两个区间有重叠（前一个的 end ≥ 后一个的 start），且重叠 ≥ duration，那它们一定分属两个不同的人（同一个人的区间不重叠），所以就是合法答案。

```cpp
class Solution {
public:
    vector<int> minAvailableDuration(vector<vector<int>>& slots1, 
                                      vector<vector<int>>& slots2, 
                                      int duration) {
        // 最小堆，按 start 时间排序
        // 预过滤：区间自身长度 < duration 的直接丢弃
        priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;
        
        for (auto& s : slots1) {
            if (s[1] - s[0] >= duration) {
                pq.push({s[0], s[1]});
            }
        }
        for (auto& s : slots2) {
            if (s[1] - s[0] >= duration) {
                pq.push({s[0], s[1]});
            }
        }
        
        while (pq.size() > 1) {
            auto [s1, e1] = pq.top(); pq.pop();
            auto [s2, e2] = pq.top();  // 不弹出，只 peek
            
            // 如果前一个区间的结束时间 - 后一个区间的开始时间 >= duration
            // 则找到合法重叠
            if (e1 - s2 >= duration) {
                return {s2, s2 + duration};
            }
            // 否则继续弹出下一个
        }
        
        return {};
    }
};
```

**关键点**：
- 预过滤掉太短的区间是一个重要优化。
- 这种方法的巧妙之处在于：不需要区分区间来自哪个人，因为同一个人的区间不重叠，所以如果两个相邻区间有交集，它们一定来自不同人。

## 解法对比

| | 暴力枚举 | 排序+双指针 | 最小堆 |
|---|---|---|---|
| 时间 | O(mn) | O(m log m + n log n) | O((m+n) log(m+n)) |
| 空间 | O(1) | O(1)（排序就地） | O(m+n) |
| 代码量 | 最多 | 最简洁 | 中等 |
| 核心技巧 | 无 | 双指针 + 区间交集 | 堆 + 预过滤 |
| 面试推荐 | 只作为起点 | ⭐ 首选 | 如果面试官追问其他思路 |

**选择建议**：面试中直接写解法2（排序+双指针），思路清晰、代码简洁、效率最优。解法3 可以作为"还有其他思路吗？"的回答。

## 易错点

1. **忘记排序**：
   - ✗ 直接用双指针扫描未排序的输入 → 会漏掉/错过最早的交集
   - ✓ 先 `sort(slots1.begin(), slots1.end())` 再双指针

2. **返回 [lo, hi] 而不是 [lo, lo+duration]**：
   - ✗ `return {lo, hi};` → 返回了整个交集，而不是恰好 duration 长度
   - ✓ `return {lo, lo + duration};` → 题目要求的是恰好 duration 的最早时段

3. **指针移动条件写反**：
   - ✗ 移动 start 较小的指针 → 可能跳过有效的重叠
   - ✓ 移动 end 较小的指针 → end 小的已经没有剩余可利用空间

4. **堆解法忘记预过滤**：
   - ✗ 不过滤短区间 → 可能误判同一个人的两个相邻区间为合法答案
   - ✓ 过滤掉 `end - start < duration` 的区间（虽然不过滤逻辑也对，但预过滤能避免一些边界case的混淆）

## 面试追问

**Q1（基础理解）：为什么双指针移动 end 较小的那个，而不是 start 较小的？**

> 因为 end 较小的区间已经"结束"了，它不可能和对方列表中更靠后的区间有交集（后面的 start 只会更大）。而 start 较小不代表这个区间已经用完——它的 end 可能很大，还能和对方后续区间匹配。

**Q2（优化）：如果两个列表已经排好序，复杂度是多少？**

> 那排序的 O(m log m + n log n) 就省了，只剩双指针的 O(m + n)。这就是为什么解法瓶颈在排序而不在扫描。

**Q3（变体）：如果有 K 个人的空闲时间表，找所有 K 个人都空闲的最早时段？**

> 可以用最小堆维护 K 个指针（每人一个当前区间），每次弹出 start 最小的，计算 K 个当前区间的交集。交集 = [max of all starts, min of all ends]。或者两两合并，类似合并 K 个有序链表的思路。
