# 55. 跳跃游戏

## 核心思路

这道题本质上在问：从位置 0 出发，每一步能跳 1 到 `nums[i]` 格，能否有一条路径到达终点？**关键观察：我们不需要知道具体怎么跳，只需要知道能到达的最远位置是否覆盖了终点。**

## 思维链

1. **读完题第一反应**：这是一个"能否到达"的问题，最朴素的想法是从位置 0 开始，尝试所有可能的跳跃路径（DFS/BFS），看能否到终点。
2. **暴力解的瓶颈**：DFS/BFS 在最坏情况下会探索指数级的路径。比如 `[5,4,3,2,1,0,0]`，从位置 0 可以跳 1~5 步，每个位置又有多种选择，分支爆炸。
3. **加入记忆化**：可以用 DP，`dp[i]` 表示能否从位置 i 到达终点。从后向前填表，每个位置尝试所有跳跃距离。但这仍然是 O(n²)。
4. **关键洞察**：我们其实不关心"从哪跳到哪"，只关心**能到达的最远位置**。如果遍历过程中某个位置 i 在最远可达范围内（`i <= maxReach`），那它就是可达的，可达后就用 `i + nums[i]` 更新 maxReach。
5. **贪心结论**：从左到右扫一遍，维护 `maxReach`。如果 `maxReach >= n-1`，返回 true；如果走到某个位置发现 `i > maxReach`，说明有"断层"，返回 false。
6. **一次遍历 O(n)**：这就是最优解，不需要任何额外数据结构。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力回溯 | DFS 尝试所有跳法 | O(2ⁿ) | O(n) | 能说出即可 |
| DP（自底向上） | dp[i] 表示能否到终点 | O(n²) | O(n) | 能说出即可 |
| 贪心（最远可达） | 维护能跳到的最远位置 | O(n) | O(1) | ⭐ 必须写出 |

## 关键提示

1. **不要纠结具体的跳跃路径**，只需要关注"最远能到哪"。想象你在走一条路，每到一个位置就更新你的"视野范围"。

2. **什么时候确定到不了？** 当你走到位置 i，发现 i 已经超出了之前所有位置能到达的最远距离 `maxReach`，这意味着存在一个"断层"，你根本走不到 i。

3. **示例可视化**：
   ```
   nums = [2, 3, 1, 1, 4]
   索引:   0  1  2  3  4
   
   i=0: maxReach = max(0, 0+2) = 2   能覆盖到索引2
   i=1: maxReach = max(2, 1+3) = 4   能覆盖到索引4 >= 4 ✓ 到达终点!
   
   nums = [3, 2, 1, 0, 4]
   索引:   0  1  2  3  4
   
   i=0: maxReach = max(0, 0+3) = 3   能覆盖到索引3
   i=1: maxReach = max(3, 1+2) = 3   不变
   i=2: maxReach = max(3, 2+1) = 3   不变
   i=3: maxReach = max(3, 3+0) = 3   不变, 3 < 4
   i=4: i=4 > maxReach=3 → 到不了索引4! ✗
   ```

4. **为什么贪心是对的？** 如果位置 i 可达，那么 0 到 i 之间所有位置也都可达（因为到达 i 的路径必然经过中间位置）。所以"最远可达位置"单调不减，不存在"跳过某个位置后面又能回来"的情况。

5. **系列题联系**：本题是 Jump Game 系列第一题，问"能不能到"。第 45 题 Jump Game II 问"最少几步到"，需要在贪心基础上增加跳跃计数。

## 解法详解

### 解法1: 动态规划 — O(n²) / O(n)

**思考过程**：把问题分解——如果我知道从位置 i+1 到终点能不能到，那从位置 i 能不能到就取决于：从 i 能跳到的所有位置中，有没有至少一个能到终点的。

定义 `dp[i]` 表示从位置 i 能否到达最后一个位置。从右向左填表：
- `dp[n-1] = true`（已经在终点）
- `dp[i] = true` 当且仅当存在某个 j ∈ [i+1, i+nums[i]]，使得 `dp[j] = true`

```
// dp 填表方向 (从右往左):
// nums:  [2, 3, 1, 1, 4]
// 索引:   0  1  2  3  4
// dp:     ?  ?  ?  ?  T    ← 初始化 dp[4]=true
// i=3:   dp[3]=dp[4]=T     ← nums[3]=1, 检查 j=4
// i=2:   dp[2]=dp[3]=T     ← nums[2]=1, 检查 j=3
// i=1:   dp[1]=dp[2]=T     ← nums[1]=3, 检查 j=2 就够了
// i=0:   dp[0]=dp[1]=T     ← nums[0]=2, 检查 j=1 就够了
// 结果:   T  T  T  T  T
```

```cpp
class Solution {
public:
    bool canJump(vector<int>& nums) {
        int n = nums.size();
        vector<bool> dp(n, false);
        dp[n - 1] = true; // 终点自身可达
        
        for (int i = n - 2; i >= 0; i--) {
            // 从位置 i 最远能跳到 min(i + nums[i], n-1)
            int farthest = min(i + nums[i], n - 1);
            for (int j = i + 1; j <= farthest; j++) {
                if (dp[j]) {
                    dp[i] = true;
                    break; // 找到一个可达的就够了，不用继续
                }
            }
        }
        return dp[0];
    }
};
```

**关键点**：内层循环找到第一个 `dp[j]=true` 就 break，这是一个重要的剪枝。但最坏情况仍然是 O(n²)，比如 `[1,1,1,...,1,0]`。

---

### 解法2: 贪心 — O(n) / O(1) ⭐ 面试首选

**从解法1优化**：解法1的瓶颈是对每个位置 i，要遍历它能跳到的所有位置检查 dp 值。但如果我们换个视角——**不关心"从 i 能不能到终点"，只关心"从起点能到达的最远位置"**——问题就大大简化了。

核心逻辑：
- 维护变量 `maxReach`，表示从位置 0 出发，当前能到达的最远索引
- 从左到右遍历每个位置 i：
  - 如果 `i > maxReach`：位置 i 不可达，直接返回 false
  - 否则：用 `i + nums[i]` 尝试更新 `maxReach`
- 遍历完成（或 `maxReach >= n-1`）则返回 true

**为什么贪心正确？** 可达性具有"连续性"：如果从 0 能到达位置 k，那么 0~k 之间的所有位置也都可达。所以 `maxReach` 是一个连续可达区间的右端点，不会出现"跳过一段再回来"的情况。

```
// 贪心过程可视化:
//
// nums = [2, 3, 1, 1, 4]
// 索引:   0  1  2  3  4
//         ^              maxReach=0
// i=0:    [====]         maxReach = max(0, 0+2) = 2
// i=1:    [==========]   maxReach = max(2, 1+3) = 4 >= 4 → true!
//
// nums = [3, 2, 1, 0, 4]
// 索引:   0  1  2  3  4
// i=0:    [========]     maxReach = max(0, 0+3) = 3
// i=1:    [========]     maxReach = max(3, 1+2) = 3 (不变)
// i=2:    [========]     maxReach = max(3, 2+1) = 3 (不变)
// i=3:    [========]     maxReach = max(3, 3+0) = 3 (不变)
// i=4:    i=4 > maxReach=3 → 不可达! return false
```

```cpp
class Solution {
public:
    bool canJump(vector<int>& nums) {
        int maxReach = 0;
        for (int i = 0; i < nums.size(); i++) {
            // 如果当前位置已经超出了最远可达范围，说明有断层
            if (i > maxReach) return false;
            // 用当前位置能跳到的最远距离更新 maxReach
            maxReach = max(maxReach, i + nums[i]);
            // 提前终止：已经能覆盖终点
            if (maxReach >= (int)nums.size() - 1) return true;
        }
        return true;
    }
};
```

**关键点**：`if (i > maxReach) return false` 这一行是整个算法的灵魂——它判断的是"当前位置是否可达"。

---

### 解法3: 贪心（反向，追踪最近可达位置） — O(n) / O(1)

**换个角度**：从终点反向思考。维护变量 `lastGood`，表示"最靠左的、确定能到达终点的位置"。从右往左扫描，如果位置 i 能跳到 `lastGood`（即 `i + nums[i] >= lastGood`），那么 i 也是"好位置"，更新 `lastGood = i`。

```cpp
class Solution {
public:
    bool canJump(vector<int>& nums) {
        int lastGood = nums.size() - 1; // 从终点开始
        for (int i = nums.size() - 2; i >= 0; i--) {
            // 如果从位置 i 能跳到 lastGood，那 i 就是新的"最近好位置"
            if (i + nums[i] >= lastGood) {
                lastGood = i;
            }
        }
        // 如果 lastGood 被推到了起点 0，说明从 0 可达终点
        return lastGood == 0;
    }
};
```

**与解法2的关系**：解法2 正向扫描维护"最远可达"，解法3 反向扫描维护"最近好位置"。两者本质都是贪心，只是方向不同。

## 解法对比

| | DP (解法1) | 贪心正向 (解法2) | 贪心反向 (解法3) |
|---|---|---|---|
| 时间 | O(n²) | O(n) | O(n) |
| 空间 | O(n) | O(1) | O(1) |
| 思维难度 | 低（标准 DP） | 中（需要贪心直觉） | 中 |
| 面试推荐 | 展示 DP 思维 | ⭐ 首选 | 加分项 |
| 关键区别 | 逐个位置检查 | 维护可达区间右端点 | 维护最近好位置 |

**什么时候选哪个？**
- 面试优先写解法2（正向贪心），代码最短最直观
- 如果面试官问"能不能用 DP？"，切换到解法1
- 解法3 作为补充视角，体现你的多角度思考能力

## 易错点

1. **漏掉不可达判断导致越界访问**
   - ✗ 直接遍历更新 `maxReach = max(maxReach, i + nums[i])`，不检查 `i > maxReach`
   - ✓ 在更新之前先判断 `if (i > maxReach) return false`
   - 为什么：如果位置 i 根本不可达，`i + nums[i]` 没有意义，用它更新 maxReach 是错误的

2. **整数溢出（虽然本题数据范围小，但好习惯要有）**
   - ✗ `i + nums[i]` 在极端情况下可能溢出 int
   - ✓ 本题 n ≤ 10⁴ 且 nums[i] ≤ 10⁵，不会溢出。但如果面试官加大数据范围，注意用 long long

3. **数组长度为 1 时的边界**
   - ✗ 忘记处理 `nums = [0]` 的情况
   - ✓ 长度为 1 时已经在终点，应返回 true。解法2 中 `maxReach=0 >= n-1=0` 自然返回 true，没问题

4. **DP 解法中内层循环上界越界**
   - ✗ `for (int j = i+1; j <= i + nums[i]; j++)` 没有限制 j < n
   - ✓ `int farthest = min(i + nums[i], n - 1);`

## 面试追问

**Q1: 暴力 DFS 的时间复杂度是多少？为什么不能接受？**
→ 最坏 O(2ⁿ)。比如 `[n-1, n-2, ..., 1, 0]`，从位置 0 可以跳到任意位置，每个位置又有多种选择，路径数指数级增长。

**Q2: DP 解法能优化到 O(n) 吗？**
→ 可以！DP 解法中 `dp[i]` 为 true 的位置形成一个连续的后缀（从终点往左），所以只需要记录"最左的 true 位置"（即 `lastGood`），这就退化成了贪心解法3。

**Q3: 如果题目改成"最少跳几次到达终点"（Jump Game II, LeetCode 45），怎么改？**
→ 贪心思路不变，但需要额外维护"当前跳跃能到达的边界"和"步数"。每次走到当前边界时，步数 +1，边界更新为这一步范围内能到的最远位置。从 O(1) 变量变成需要维护两个：`curEnd` 和 `maxReach`。

**Q4: 如果要输出一条具体的跳跃路径呢？**
→ 贪心只能判断可达性，无法回溯路径。需要改用 DP 并记录每个位置是从哪里跳来的（`parent[i]`），最后从终点沿 parent 链回溯出路径。
