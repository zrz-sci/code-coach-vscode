# 1944. 队列中可以看到的人数

## 核心思路

本质上是：对于每个人 i，向右找到所有满足"中间无人遮挡"的可见人数。这是一个经典的**单调栈**问题——从右往左维护一个递减栈，栈中被弹出的元素就是当前人能看到的"比自己矮的人"，而栈顶剩余的第一个更高的人也能被看到。

## 思维链

1. **读完题第一反应**：对每个人 i，向右扫描，判断每个人 j 是否可见（中间所有人都比 min(h[i], h[j]) 矮）。暴力做法是 O(n²) 甚至 O(n³)。

2. **暴力解的瓶颈**：对每个 i，向右找可见的人时，需要不断检查中间的最大值。能不能跳过那些"不可能被看到"的人？

3. **关键观察——谁会遮挡谁？** 假设从右往左处理。如果 j 右边有个 k 且 h[k] > h[j]，那么对于任何 i < j 且 h[i] > h[j] 的人来说，j 虽然能被 i 看到（因为 j 是中间递增序列的一部分），但 j 不会遮挡 k。关键是：**一旦遇到比自己高的人，自己就再也不会被更左边的人看到了**（被遮挡了）。这正是单调栈的"淘汰"机制！

4. **单调栈的直觉**：从右往左遍历，维护一个**从栈底到栈顶递减**的栈。对于当前人 i：
   - 弹出所有比 h[i] 矮的栈顶元素——它们都是 i 能看到的人（递增排列，不会互相遮挡）
   - 弹完后，如果栈非空，栈顶是第一个比 i 高的人——i 也能看到这个人
   - 把 i 压入栈

5. **为什么弹出的人不会再被左边更远的人看到？** 因为 h[i] 比它们都高，i 挡住了它们。它们的"历史使命"已经完成。

6. **总结**：每个元素最多入栈一次、出栈一次，总时间 O(n)。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 对每个 i 向右扫描所有可见的 j | O(n²) | O(1) | 能说出即可 |
| 单调栈（从右往左） | 维护递减栈，弹出的就是能看到的 | O(n) | O(n) | ⭐ 必须写出 |

## 关键提示

1. **可见性的本质**：人 i 向右看，能看到的是一段"严格递增"序列（每个都比前面的高才不被挡），再加上最后一个比 i 高的"墙"（如果存在）。

2. **从右往左遍历**：想想为什么从右往左更自然？因为右边的信息已经被栈总结了。

3. **栈里维护什么？** 栈里存的是"还有可能被左边某个人看到"的人的高度。一旦被更高的人遮挡（弹出），就永远不会再被看到。

4. **answer[i] = 弹出个数 + (栈非空 ? 1 : 0)**：弹出的是比 i 矮的可见人，栈顶残留的是第一个比 i 高的可见人。

5. **用示例验证**：
```
heights = [10, 6, 8, 5, 11, 9]
索引:       0  1  2  3   4  5

从右往左处理：
i=5: 栈空, push 9.            栈:[9]       ans[5]=0
i=4: 弹9(比11矮), 栈空.       栈:[11]      ans[4]=1(弹了1个)
i=3: 栈顶11>5, 不弹.          栈:[11,5]    ans[3]=0+1=1(看到11?不对...)
```
等等——这里需要仔细理解：5 能看到 11 吗？5 和 11 之间没人，当然能看到。ans[3]=1 ✓

## 解法详解

### 解法1: 暴力枚举 — O(n²) / O(1)

**思考过程**：最直觉的做法——对每个人 i，向右扫描，维护一个"当前最大高度"变量。如果 h[j] 大于这个最大值，说明 j 没被遮挡，i 能看到 j。然后更新最大值。当遇到比 h[i] 高的人时，停止（后面的全被挡住了）。

```cpp
class Solution {
public:
    vector<int> canSeePersonsCount(vector<int>& heights) {
        int n = heights.size();
        vector<int> answer(n, 0);
        
        for (int i = 0; i < n; i++) {
            int maxBetween = 0; // i+1 到 j-1 之间的最大高度
            for (int j = i + 1; j < n; j++) {
                // 可见条件: min(h[i], h[j]) > maxBetween
                if (min(heights[i], heights[j]) > maxBetween) {
                    answer[i]++;
                }
                maxBetween = max(maxBetween, heights[j]);
                // 如果遇到比 i 高的人，后面全被挡住，可以提前退出
                if (heights[j] >= heights[i]) break;
            }
        }
        
        return answer;
    }
};
```

**关键点**：
- 提前退出优化：遇到 h[j] >= h[i] 后 break，因为后面的人对 i 来说全被 j 挡住了。
- 虽然有 break，最坏情况仍然 O(n²)（递减序列时每个人要扫到最右边）。

---

### 解法2: 单调栈（从右往左） — O(n) / O(n) ⭐ 面试首选

**从解法1优化**：暴力解的瓶颈是每个人都要向右逐个扫描。单调栈把右边的信息预处理成一个递减序列，使得每个人的计算都是摊还 O(1)。

**核心逻辑**：

```
从右往左遍历。栈维护的是一个"从底到顶严格递减"的高度序列。
对于当前人 i：
  - 不断弹出栈顶比 h[i] 矮的人 → 这些人都是 i 能看到的（它们构成递增序列）
  - 弹完后如果栈非空 → 栈顶也是 i 能看到的（第一个比 i 高的人）
  - 把 h[i] 压入栈

为什么弹出的人是可见的？
因为栈是递减的，弹出的顺序是从矮到高，它们之间没有更高的人遮挡。
```

**可视化栈的变化**（示例 `[10,6,8,5,11,9]`）：

```
从右往左遍历:

i=5, h=9:  栈: []
           弹出: 无
           栈非空? 否
           ans[5] = 0 + 0 = 0
           push 9 → 栈: [9]

i=4, h=11: 栈: [9]
           弹出: 9 (9 < 11)   → count=1
           栈非空? 否
           ans[4] = 1 + 0 = 1
           push 11 → 栈: [11]

i=3, h=5:  栈: [11]
           弹出: 无 (11 > 5)
           栈非空? 是            → +1
           ans[3] = 0 + 1 = 1
           push 5 → 栈: [11, 5]

i=2, h=8:  栈: [11, 5]
           弹出: 5 (5 < 8)     → count=1
           栈非空? 是 (栈顶=11) → +1
           ans[2] = 1 + 1 = 2
           push 8 → 栈: [11, 8]

i=1, h=6:  栈: [11, 8]
           弹出: 无 (8 > 6)
           栈非空? 是            → +1
           ans[1] = 0 + 1 = 1
           push 6 → 栈: [11, 8, 6]

i=0, h=10: 栈: [11, 8, 6]
           弹出: 6 (6<10), 8 (8<10)  → count=2
           栈非空? 是 (栈顶=11)       → +1
           ans[0] = 2 + 1 = 3
           push 10 → 栈: [11, 10]

结果: [3, 1, 2, 1, 1, 0] ✓
```

```cpp
class Solution {
public:
    vector<int> canSeePersonsCount(vector<int>& heights) {
        int n = heights.size();
        vector<int> answer(n, 0);
        stack<int> stk; // 存高度值，从底到顶严格递减
        
        // 从右往左遍历
        for (int i = n - 1; i >= 0; i--) {
            int count = 0;
            
            // 弹出所有比当前人矮的 → 它们都是 i 能看到的
            while (!stk.empty() && stk.top() < heights[i]) {
                stk.pop();
                count++;
            }
            
            // 如果栈非空，栈顶是第一个比 i 高的人，i 也能看到
            if (!stk.empty()) {
                count++;
            }
            
            answer[i] = count;
            stk.push(heights[i]);
        }
        
        return answer;
    }
};
```

**为什么每个元素只入栈出栈一次？**
- 每个高度最多 push 一次、pop 一次
- while 循环总共执行次数 ≤ n（所有元素总共被弹出 n 次）
- 所以总时间 O(n)，虽然有嵌套循环，但摊还分析是线性的

**关键点**：
- 栈存的是高度值（也可以存索引，本题只需要计数所以存高度更简洁）
- `stk.top() < heights[i]` 用严格小于，因为题目说高度互不相同
- 弹出的是"比我矮的能看到的人"，栈顶剩下的是"比我高的第一个人"

## 解法对比

| | 暴力枚举 | 单调栈 |
|---|---|---|
| 时间 | O(n²) 最坏 | O(n) 摊还 |
| 空间 | O(1) 额外 | O(n) 栈空间 |
| 代码复杂度 | 简单直接 | 需要理解单调栈模型 |
| 面试 | 暖场用 | 面试官期望的答案 |

**核心区别**：暴力解每个人独立扫描右边，大量重复工作。单调栈把"右边还能被看到的人"维护成一个精简的递减序列，每个人的信息只处理一次。

## 易错点

1. **忘记加上栈顶的那个更高的人**
   - ✗ `answer[i] = count;`（只算了弹出的矮个子）
   - ✓ `if (!stk.empty()) count++;`（栈顶比 i 高的那个人也能看到！）
   - 原因：弹出的是比 i 矮的可见人，但 i 还能看到右边第一个比自己高的人

2. **遍历方向搞反**
   - ✗ 从左往右遍历，栈维护左边信息
   - ✓ 从右往左遍历，栈维护右边"待被看到"的人
   - 原因：每个人是向右看的，我们需要右边的信息已经在栈里

3. **判断条件用 <= 而不是 <**
   - 本题高度互不相同，所以 `<` 和 `<=` 在本题等价
   - 但如果高度可以相同，需要仔细考虑相等情况，这是常见变体

4. **栈里存索引 vs 存值混淆**
   - 如果存索引，比较时要写 `heights[stk.top()] < heights[i]`
   - 如果存值，弹出时无法知道是哪个位置的人（本题只需计数，存值够用）

## 面试追问

**Q1: 暴力解怎么做？时间复杂度是多少？有没有简单的剪枝？**

对每个 i 向右扫描，维护中间最大值判断可见性。O(n²) 最坏。剪枝：遇到比 h[i] 高的人就 break，因为后面全被挡住。但最坏（递减序列）仍 O(n²)。

**Q2: 为什么单调栈能做到 O(n)？摊还分析怎么说？**

每个元素最多入栈 1 次、出栈 1 次，所有 pop 操作总共 ≤ n 次。虽然单次循环的 while 可能弹出多个元素，但"借"的是其他迭代不弹出的次数。总操作 2n，即 O(n)。

**Q3: 如果高度可以重复，代码需要怎么改？**

需要考虑相等的情况。两个相同高度的人之间：矮的人看不到后面那个同高的人（因为 min(h[i], h[j]) 不严格大于中间最大值——等于时不满足条件）。这时候 while 条件应该用 `<=` 还是 `<` 需要根据题意仔细分析。一般来说，相同高度互相遮挡，while 应改为 `stk.top() <= heights[i]`。

**Q4: 如果改成"每个人向左能看到几个人"，怎么改？**

从左往右遍历，维护同样的递减栈即可。逻辑完全对称。
