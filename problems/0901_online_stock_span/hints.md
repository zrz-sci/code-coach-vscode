# 901. 在线股票跨度 (Online Stock Span)

## 核心思路

本题本质上是：**对于每个新价格，找到往左看连续 <= 当前价格的天数**。这是经典的**单调栈**应用 -- 维护一个价格递减栈，当新价格 >= 栈顶时不断弹栈，累加跨度。

## 思维链

1. **读完题的第一反应**：每次调用 `next(price)` 时，需要找到从当天往回数，连续多少天的价格 <= 今天的价格。暴力法每次都往回扫描，最坏 O(n^2)。

2. **关键观察 -- "跳跃合并"**：如果第 i 天的跨度是 3，说明第 i-1, i-2 天的价格都 <= price[i]。当第 j 天 (j > i) 的价格 >= price[i] 时，我们可以直接跳过 i 的整个跨度区间，不需要逐天比较。

3. **单调栈的自然应用**：维护一个**严格递减**的栈（从底到顶价格递减），栈中每个元素存 `(price, span)`。当新价格 >= 栈顶价格时，弹出栈顶并将其跨度累加到当前跨度中。

4. **均摊分析**：每个价格最多入栈一次、出栈一次。n 次 `next` 调用总共最多 2n 次栈操作，所以均摊 O(1) 每次调用。

5. **设计模式**：这是一个**数据流 + 单调栈**的设计题。初始化一个空栈，每次 `next` 调用执行一轮"弹栈 + 入栈"。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 单调递减栈 | 栈存(price,span)，弹栈累加跨度 | 均摊 O(1) | O(n) | ⭐ 必须写出 |
| 暴力回溯 | 每次从当前往回逐个比较 | O(n) 每次 | O(n) | 仅说思路 |

## 关键提示

1. **栈中存什么？** 存 `pair<int,int>`，即 `(price, span)`。span 不只是 1，而是该价格"吞并"掉的所有之前连续 <= 它的天数总和。

2. **弹栈条件**：当 `stack.top().price <= currentPrice` 时弹出。注意是 `<=` 不是 `<`，因为题目定义跨度包含"小于或等于"。

3. **ASCII 示意图 -- 示例的栈变化**：
```
next(100): 栈空 → push(100,1), return 1
           栈: [(100,1)]

next(80):  80 < 100, 不弹 → push(80,1), return 1
           栈: [(100,1), (80,1)]

next(60):  60 < 80, 不弹 → push(60,1), return 1
           栈: [(100,1), (80,1), (60,1)]

next(70):  70 >= 60, 弹(60,1), span=1+1=2
           70 < 80, 停止 → push(70,2), return 2
           栈: [(100,1), (80,1), (70,2)]

next(60):  60 < 70, 不弹 → push(60,1), return 1
           栈: [(100,1), (80,1), (70,2), (60,1)]

next(75):  75 >= 60, 弹(60,1), span=1+1=2
           75 >= 70, 弹(70,2), span=2+2=4
           75 < 80, 停止 → push(75,4), return 4
           栈: [(100,1), (80,1), (75,4)]

next(85):  85 >= 75, 弹(75,4), span=1+4=5
           85 >= 80, 弹(80,1), span=5+1=6
           85 < 100, 停止 → push(85,6), return 6
           栈: [(100,1), (85,6)]
```

4. **初始跨度为 1**：当前天本身就算 1 天的跨度，所以初始 span = 1，然后累加弹出的跨度。

5. **空间优化无必要**：栈最多存 n 个元素，已经是最优空间。

## 解法详解

### 解法1: 单调递减栈 -- 均摊 O(1) / O(n) ⭐ 面试首选

**思考过程**：

核心洞察：**当一个价格被更高的价格"吞并"后，它永远不会再被访问**。因此我们可以安全地从栈中移除它，并把它的跨度转移给新价格。

这正是单调栈的经典特性 -- 维护有用信息，丢弃已被"支配"的元素。

```cpp
class StockSpanner {
    // 栈存储 (价格, 跨度) 对
    // 从栈底到栈顶，价格严格递减
    stack<pair<int,int>> st;
    
public:
    StockSpanner() {
        // 构造函数无需特殊操作，栈初始为空
    }
    
    int next(int price) {
        int span = 1; // 当前天本身占 1 天跨度
        
        // 当栈非空且栈顶价格 <= 当前价格时
        // 弹出栈顶，将其跨度累加到当前跨度
        while (!st.empty() && st.top().first <= price) {
            span += st.top().second;
            st.pop();
        }
        
        // 将 (当前价格, 累积跨度) 入栈
        st.push({price, span});
        
        return span;
    }
};
```

**关键点**：
- 栈中每个元素 `(price, span)` 的 span 代表从该天往左看，连续 <= price 的天数（含自身）
- 弹栈时把旧元素的 span 累加到新元素上，信息不丢失
- 均摊 O(1)：每个元素最多入栈出栈各一次

### 解法2: 暴力法 -- O(n) 每次调用 / O(n)

**从最直观的角度**：把所有历史价格存起来，每次 `next` 从最后一个开始往前数。

```cpp
class StockSpanner {
    vector<int> prices;
    
public:
    StockSpanner() {}
    
    int next(int price) {
        prices.push_back(price);
        int span = 1;
        int i = prices.size() - 2; // 从前一天开始往回看
        
        // 逐天回溯，直到找到价格更大的那天或走到头
        while (i >= 0 && prices[i] <= price) {
            span++;
            i--;
        }
        
        return span;
    }
};
```

**关键点**：
- 简单直观但效率低，最坏情况（价格单调递增）每次都要扫描全部历史
- 面试中作为暴力基线说明即可，然后优化到单调栈

## 易错点

1. **✗ 弹栈条件写成 `<` 而非 `<=`**：
   ```cpp
   // 错误：while (!st.empty() && st.top().first < price)
   // 正确：while (!st.empty() && st.top().first <= price)
   // 题意是"小于或等于"都算跨度内
   ```

2. **✗ 忘记初始 span = 1**：当前天自身也是跨度的一部分，弹栈前 span 应从 1 开始，不是 0。

3. **✗ 栈中只存价格不存跨度**：如果只存价格，弹栈后无法知道被弹元素代表了多少天，就退化成了暴力法。必须存 `(price, span)` 对。

4. **✗ 在构造函数中 push 哨兵节点但处理不当**：有些写法会 push `(INT_MAX, 0)` 作为哨兵，但容易搞混逻辑。直接判断 `st.empty()` 更清晰。

## 面试追问

**Q1: 时间复杂度是 O(1) 还是 O(n)？为什么？**
→ 均摊 O(1)。虽然单次 `next` 可能弹出 O(n) 个元素，但每个元素最多入栈一次、出栈一次。n 次调用总操作不超过 2n 次，均摊每次 O(1)。

**Q2: 如果要求支持撤销最后一次 next 操作怎么办？**
→ 单调栈不支持高效撤销（被弹出的元素已丢失）。需要额外维护一个"操作日志"，记录每次 next 弹出了哪些元素，撤销时把它们重新压回栈中。或者用持久化栈。

**Q3: 如果要查询任意历史某天的跨度（不只是最新一天），怎么优化？**
→ 离线场景下可以预处理所有价格：用单调栈一次遍历，对每个位置找到左边第一个严格更大的元素，跨度就是 `i - leftGreater[i]`。这是 O(n) 的。在线场景下，每次 next 的返回值就是答案，存起来即可。
