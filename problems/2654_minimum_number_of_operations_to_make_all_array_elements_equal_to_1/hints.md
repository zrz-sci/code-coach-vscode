# 2654. 使数组所有元素变成 1 的最少操作次数

## 题目理解

给定正整数数组 `nums`，每次操作可选相邻两元素，将其中一个替换为它们的 GCD。问最少多少次操作能让所有元素变成 1？不可能则返回 -1。

**核心约束**：
- 只能操作**相邻**元素（不是任意两个）
- 替换的是**其中一个**，不是两个都替换
- 数组长度 <= 50，值 <= 10^6 -- 暗示 O(n^2) 或 O(n^2 log V) 可行

```
示例 1: nums = [2, 6, 3, 4] -> 4
示例 2: nums = [2, 10, 6, 14] -> -1 (全局 GCD = 2，永远无法产生 1)
```

---

## 解法概览

| 解法 | 思路 | 时间复杂度 | 空间复杂度 | 推荐度 |
|------|------|-----------|-----------|--------|
| 枚举子数组 GCD | 找最短 GCD=1 的连续子数组 | O(n^2 log V) | O(1) | 面试首选 |
| O(n log V) 优化 | 维护不同 GCD 值集合 | O(n log^2 V) | O(log V) | 进阶加分 |

## 渐进提示

### 提示 1 -- GCD 操作的本质是什么？

GCD 操作能产生什么值？它和原始数组元素有什么数学关系？

<details>
<summary>展开</summary>

**GCD 只能产生原始元素的因子**。

- `gcd(a, b)` 一定整除 a 和 b
- 对结果再做 GCD，仍然只能产生更小的因子
- GCD 操作永远不会引入新的质因数

**结论**：如果所有元素的 GCD > 1，说明它们共享某个质因子 p，无论怎么操作，结果都是 p 的倍数，永远无法得到 1。

```
例: [2, 10, 6, 14]
  全局 GCD = gcd(2, 10, 6, 14) = 2
  所有操作结果都是 2 的倍数，无法产生 1
  -> 返回 -1
```

**判定条件**：`gcd(全数组) > 1` 则返回 -1。

</details>

### 提示 2 -- 如果数组中已经存在 1 呢？

假设数组中有若干个 1，需要多少操作让所有元素变 1？

<details>
<summary>展开</summary>

1 是 GCD 操作的"万能钥匙"：`gcd(x, 1) = 1` 对任何正整数 x 成立。

设数组中已有 `cnt` 个 1：
- 每个 1 可以通过一次相邻操作把旁边的非 1 元素"感染"成 1
- 需要 `n - cnt` 次操作

```
例: [1, 5, 1, 7]   cnt=2, n=4
  操作1: gcd(1, 5) = 1 -> [1, 1, 1, 7]
  操作2: gcd(1, 7) = 1 -> [1, 1, 1, 1]
  共 4 - 2 = 2 次
```

**关键洞察**：有了 1 之后，传播是线性的，每次恰好消灭一个非 1 元素。

</details>

### 提示 3 -- 没有 1 时，如何"制造"第一个 1？

为什么必须是**连续子数组**而不是子序列？需要多少操作？

<details>
<summary>展开</summary>

因为每次操作只能选**相邻**元素。要让某个位置变成 1，必须用一段连续元素的 GCD 逐步"推"过去。

对一段连续子数组 `nums[l..r]`，如果 `gcd(nums[l], ..., nums[r]) = 1`：
- 可以通过 `r - l` 次相邻 GCD 操作把某个位置变成 1
- 这就是 `len - 1` 次操作（len = r - l + 1）

**为什么是 len - 1 次？** 看操作链条：

```
子数组 [a, b, c]，gcd(a, b, c) = 1

操作 1: 选 (a, b)，把 b 替换为 gcd(a, b)
        -> [a, gcd(a,b), c]

操作 2: 选 (gcd(a,b), c)，把 gcd(a,b) 替换为 gcd(gcd(a,b), c) = gcd(a,b,c) = 1
        -> [a, 1, c]

共 2 = 3 - 1 次操作产生了第一个 1。
```

**目标**：找到最短的连续子数组，使其 GCD = 1。设最短长度为 `minLen`，则产生第一个 1 需要 `minLen - 1` 次操作。

</details>

### 提示 4 -- 完整公式的推导

将"制造 1"和"传播 1"两个阶段合并，写出最终答案。

<details>
<summary>展开</summary>

设 `cnt_ones` = 数组中已有的 1 的个数。

**Case 1**：`cnt_ones > 0`
- 不需要制造 1，直接传播
- 答案 = `n - cnt_ones`

**Case 2**：`cnt_ones == 0`
- **Phase 1（制造）**：找最短子数组使 GCD = 1，设长度 `minLen`
  - 需要 `minLen - 1` 次操作产生第一个 1
- **Phase 2（传播）**：有了一个 1，感染其余 `n - 1` 个元素
  - 需要 `n - 1` 次操作
- 答案 = `(minLen - 1) + (n - 1)`

**Case 3**：全局 GCD > 1
- 无法产生 1
- 答案 = -1

```
例: nums = [2, 6, 3, 4], n = 4

全局 gcd = gcd(2,6,3,4) = 1 -> 有解
cnt_ones = 0 -> 需要制造

枚举子数组找最短 GCD=1:
  [3, 4]: gcd = 1, 长度 = 2 -> minLen = 2

答案 = (2-1) + (4-1) = 1 + 3 = 4
```

</details>

### 提示 5 -- 如何高效枚举？

枚举所有子数组 GCD 的策略，以及如何剪枝。

<details>
<summary>展开</summary>

**核心性质**：GCD 随子数组扩展**单调不增**。

```
gcd(a)               = a
gcd(a, b)            <= a
gcd(a, b, c)         <= gcd(a, b)
...
```

这意味着：
1. 固定左端点 `l`，GCD 只会越来越小
2. 一旦 GCD 达到 1，继续扩展不会更优（长度只会更大）
3. 可以 `break` 跳到下一个左端点

```
l=0: g=2, g=gcd(2,6)=2, g=gcd(2,3)=1 -> 长度3
l=1: g=6, g=gcd(6,3)=3, g=gcd(3,4)=1 -> 长度3
l=2: g=3, g=gcd(3,4)=1 -> 长度2 ★最短
l=3: g=4 -> 只有一个元素，不为1
```

**进阶优化 O(n log V)**：

利用性质"以右端点 j 结尾的所有子数组 GCD，最多只有 O(log V) 个不同值"（因为每次 GCD 变小时至少减半），可以用一个集合维护不同 GCD 值及其对应的最早左端点。

</details>

## 关键思维模式

### 1. "GCD 只减不增"性质

对一组数做 GCD 操作，结果单调递减或不变。这是因为 GCD 的结果一定整除之前所有参与运算的数，新加入的数只可能让 GCD 变小（引入新的限制）。

这个性质保证了：
- 全局 GCD > 1 时一定无解
- 全局 GCD = 1 时一定存在某段子数组 GCD = 1
- 枚举时可以提前 break

### 2. "两阶段分解"策略

很多"将数组变成统一状态"的问题可以分为：
1. **从无到有**：产生第一个目标值（通常是最难的部分）
2. **传播扩散**：用已有的目标值去转化其他元素（通常是线性的）

这种分解让复杂问题变得结构化。

### 3. "枚举子数组 GCD"模式

固定左端点 l，逐步扩展右端点 r，维护 `gcd(nums[l..r])`。配合 GCD 单调性剪枝。

```
l=0: gcd = nums[0]
     gcd = gcd(prev, nums[1])     <- 如果==1, 记录长度, break
     gcd = gcd(prev, nums[2])     <- 如果==1, 记录长度, break
     ...
l=1: gcd = nums[1]
     ...
```

### 4. 裴蜀定理（Bezout's Identity）

整个数组的 GCD = 1 等价于存在整数线性组合 `a1*x1 + a2*x2 + ... + an*xn = 1`。虽然本题不直接用到这个定理，但它提供了"为什么 GCD=1 时一定能产生 1"的数学保证。

## 完整代码 (C++)

```cpp
class Solution {
public:
    int minOperations(vector<int>& nums) {
        int n = nums.size();

        // 特判: 数组中已有 1
        int cntOnes = count(nums.begin(), nums.end(), 1);
        if (cntOnes > 0) return n - cntOnes;

        // Phase 1: 找最短子数组使 GCD = 1
        int minLen = INT_MAX;
        for (int i = 0; i < n; i++) {
            int g = 0;  // gcd(0, x) = x，方便初始化
            for (int j = i; j < n; j++) {
                g = __gcd(g, nums[j]);
                if (g == 1) {
                    minLen = min(minLen, j - i + 1);
                    break;  // GCD 单调不增，继续扩展不会更短
                }
            }
        }

        // 无法产生 1（全局 GCD > 1）
        if (minLen == INT_MAX) return -1;

        // Phase 1 + Phase 2
        return (minLen - 1) + (n - 1);
    }
};
```

---

## 复杂度分析

**时间复杂度**：O(n^2 * log(max_val))
- 枚举子数组左端点 O(n)
- 扩展右端点 O(n)
- 每次 GCD 计算 O(log(max_val))
- 对于 n <= 50，约 2500 * 20 = 50000 次操作

**空间复杂度**：O(1)，只需常数额外空间

## 过程可视化

```
nums = [2, 6, 3, 4], n = 4

Step 1: 检查已有 1 → cnt_ones = 0，无

Step 2: 枚举子数组

  l=0: g=2       -> [2]         GCD=2
       g=gcd(2,6)=2 -> [2,6]   GCD=2
       g=gcd(2,3)=1 -> [2,6,3] GCD=1 ★ 长度3

  l=1: g=6       -> [6]         GCD=6
       g=gcd(6,3)=3 -> [6,3]   GCD=3
       g=gcd(3,4)=1 -> [6,3,4] GCD=1 ★ 长度3

  l=2: g=3       -> [3]         GCD=3
       g=gcd(3,4)=1 -> [3,4]   GCD=1 ★ 长度2 <- 最短!

  l=3: g=4       -> [4]         GCD=4 (无法为1)

  minLen = 2

Step 3: 答案 = (2-1) + (4-1) = 1 + 3 = 4

具体操作序列:
  [2, 6, 3, 4]
    -> 选 i=2: nums[2]=gcd(3,4)=1 -> [2, 6, 1, 4]    (Phase 1完成)
    -> 选 i=1: nums[1]=gcd(6,1)=1 -> [2, 1, 1, 4]    (Phase 2)
    -> 选 i=0: nums[0]=gcd(2,1)=1 -> [1, 1, 1, 4]    (Phase 2)
    -> 选 i=2: nums[3]=gcd(1,4)=1 -> [1, 1, 1, 1]    (Phase 2)
  共 4 次 ✓
```

## 常见错误

1. **忘记特判已有的 1**：如果数组中已有 1，不需要 Phase 1，直接 `n - cnt_ones`
2. **公式记错**：Phase 1 是 `minLen - 1`（不是 minLen），Phase 2 是 `n - 1`（不是 n - cntOnes）
3. **判断无解条件**：不是看有没有 1，而是看全局 GCD 是否为 1
4. **子数组 vs 子序列**：因为只能操作相邻元素，所以必须是连续子数组
5. **忘记剪枝**：GCD 到 1 后继续扩展没有意义，应 break

## 面试追问

**Q1: 如果 n 很大（如 10^5），如何优化？**
> 利用"以右端点 j 结尾的不同 GCD 值最多 O(log V) 个"的性质。维护一个 (gcd_value, leftmost_index) 的集合，每加入 nums[j] 时与所有已有 GCD 值合并并去重。总时间 O(n log^2 V)。

**Q2: 如果能操作任意两个元素（不限相邻）呢？**
> 那就不需要"连续子数组"了。只要全局 GCD = 1，就能在某些元素对上做 GCD 产生 1，然后用 1 感染全部。但最优策略的分析会更复杂。

**Q3: 为什么 Phase 2 一定需要 n-1 步，不能更快？**
> 每次操作最多让一个位置从非 1 变成 1（因为 gcd(x, 1) = 1 只改变一个元素）。有 n-1 个非 1 元素，所以至少需要 n-1 步。
