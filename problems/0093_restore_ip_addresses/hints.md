# 93. 复原 IP 地址

## 核心思路

本质上是一个**分割问题**：把一个纯数字字符串切成恰好 4 段，每段都是合法的 IP 段（0-255，无前导零）。这是经典的回溯/枚举分割点问题。

## 思维链

1. **读完题第一反应**：需要在字符串中插入 3 个点，把它分成 4 段。最朴素的想法——用三重循环枚举 3 个切割位置，然后验证每段是否合法。

2. **暴力三重循环可行吗？** 字符串长度最多 20，每段长度 1-3，三重循环的搜索空间大约 20³ = 8000，完全可以接受。但代码写起来边界处理麻烦，且不够通用。

3. **更通用的视角**：把问题看成"从左到右依次确定每一段"。第 1 段可以取 1/2/3 个字符，确定后剩余部分继续切——这就是**回溯**的经典模式！

4. **回溯框架**：维护当前切到第几段（segId）和当前起始位置（start），每次尝试取 1/2/3 个字符作为当前段，验证合法后递归处理下一段。当 4 段都确定且恰好用完所有字符时，收集结果。

5. **剪枝优化**：剩余字符太少或太多时可以提前终止（每段至少 1 个字符、最多 3 个字符）。

6. **三重循环解法**：作为一种暴力但直观的方法，直接枚举 3 个切点位置，验证 4 段。代码简单但扩展性差（如果不是 4 段而是 k 段就不行了）。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 回溯（逐段选择） | 每段尝试取1/2/3个字符，递归4段 | O(3⁴·n) ≈ O(n) | O(n) | ⭐ 必须写出 |
| 三重循环暴力枚举 | 枚举3个切点，验证4段 | O(n³) | O(n) | 能说出即可 |

> 注：由于 IP 只有 4 段、每段最多 3 位，回溯分支因子为 3、深度为 4，决策空间固定为 3⁴=81，所以两种方法的实际复杂度都很低。

## 关键提示

1. **合法 IP 段的三个条件**：① 数值在 [0, 255]；② 不能有前导零（"01"、"00" 非法，但 "0" 合法）；③ 段不能为空。

2. **前导零判断技巧**：如果段的长度 > 1 且第一个字符是 '0'，直接判定为非法。

3. **回溯的终止条件**：已经选了 4 段 **且** 刚好用完了所有字符。两个条件缺一不可——选满 4 段但没用完字符也是非法的。

4. **决策树（前 2-3 层）**：
```
以 s = "25525511135" 为例：

                              (seg=0, start=0)
                         /         |          \
                   取"2"         取"25"       取"255"
               (seg=1,s=1)   (seg=1,s=2)   (seg=1,s=3)
              /    |    \      /   |   \      /   |   \
          取"5" "55" "552"  "5" "52" "525"  "2" "25" "255"
          ...    ...   ...  ...  ...   ...  ...  ...   ...
```

5. **剪枝**：在回溯开始时检查剩余字符数。剩余字符数必须满足：`(4-segId) <= remaining <= 3*(4-segId)`，否则不可能分成合法的段。

## 解法详解

### 解法1: 回溯（逐段选择）— O(3⁴·n) / O(n) ⭐ 面试首选

**思考过程**：这是一个"分割"问题，我们需要把字符串分成恰好 4 段。每一步我们决定当前段取多少个字符（1、2 或 3 个），然后递归处理剩余部分。这就是标准的回溯框架——做选择 → 递归 → 撤销选择。

```cpp
class Solution {
public:
    vector<string> restoreIpAddresses(string s) {
        vector<string> result;
        vector<string> segments;  // 存放当前选择的各段
        backtrack(s, 0, segments, result);
        return result;
    }
    
private:
    void backtrack(const string& s, int start, 
                   vector<string>& segments, vector<string>& result) {
        // 终止条件：已经选了4段
        if (segments.size() == 4) {
            // 必须刚好用完所有字符
            if (start == s.size()) {
                result.push_back(segments[0] + "." + segments[1] + "." 
                                 + segments[2] + "." + segments[3]);
            }
            return;  // 无论是否用完，4段已满就不再递归
        }
        
        // 剪枝：剩余字符数检查
        int remaining = s.size() - start;
        int needSegs = 4 - segments.size();
        if (remaining < needSegs || remaining > needSegs * 3) return;
        
        // 每段尝试取 1、2、3 个字符
        for (int len = 1; len <= 3 && start + len <= s.size(); len++) {
            string seg = s.substr(start, len);
            
            // 验证合法性：无前导零 + 值 <= 255
            if (seg.size() > 1 && seg[0] == '0') break;  // 前导零，更长的也一定有前导零，直接break
            if (stoi(seg) > 255) break;  // 超过255，更长的值更大，直接break
            
            // 做选择
            segments.push_back(seg);
            // 递归
            backtrack(s, start + len, segments, result);
            // 撤销选择
            segments.pop_back();
        }
    }
};
```

**关键点**：
- 前导零检查用 `break` 而不是 `continue`：如果 "01" 有前导零，那 "012" 也一定有，无需继续尝试更长的。
- 值 > 255 也用 `break`：长度增加，值只会更大。
- 终止时两个条件都要检查：`segments.size() == 4` 且 `start == s.size()`。

### 解法2: 三重循环暴力枚举 — O(n³) / O(n)

**思考过程**：IP 恰好有 4 段，我们只需要确定 3 个切点的位置。直接用三重循环枚举即可，然后对每种切法验证 4 段是否都合法。

```cpp
class Solution {
public:
    vector<string> restoreIpAddresses(string s) {
        vector<string> result;
        int n = s.size();
        
        // i, j, k 分别是第1、2、3个切点（即第2、3、4段的起始位置）
        for (int i = 1; i <= 3 && i < n; i++) {
            for (int j = i + 1; j <= i + 3 && j < n; j++) {
                for (int k = j + 1; k <= j + 3 && k < n; k++) {
                    // 第4段长度检查
                    if (n - k > 3) continue;
                    
                    string s1 = s.substr(0, i);
                    string s2 = s.substr(i, j - i);
                    string s3 = s.substr(j, k - j);
                    string s4 = s.substr(k);
                    
                    if (isValid(s1) && isValid(s2) && isValid(s3) && isValid(s4)) {
                        result.push_back(s1 + "." + s2 + "." + s3 + "." + s4);
                    }
                }
            }
        }
        return result;
    }
    
private:
    bool isValid(const string& seg) {
        if (seg.empty() || seg.size() > 3) return false;
        if (seg.size() > 1 && seg[0] == '0') return false;  // 前导零
        if (stoi(seg) > 255) return false;
        return true;
    }
};
```

**关键点**：
- 循环上界要同时限制 `<= prev + 3`（每段最多 3 字符）和 `< n`（不能越界，且至少留一个字符给后面的段）。
- 第 4 段不需要循环，由 k 的位置自动确定。

## 解法对比

| | 回溯 | 三重循环 |
|---|---|---|
| 代码风格 | 通用模板，适用于 k 段分割 | 专用于 4 段，简单粗暴 |
| 扩展性 | 改 `4` 为 `k` 即可处理 k 段分割 | k 段需 k-1 重循环，不实际 |
| 面试推荐 | ⭐ 展示回溯思维，面试首选 | 可以先提思路，再实现回溯版 |
| 剪枝 | 自然嵌入递归中 | 需要额外的 continue/break |

## 易错点

1. **✗ 忘记 start == s.size() 的检查**：
   ```cpp
   // 错误：4段选满就加入结果
   if (segments.size() == 4) {
       result.push_back(...);  // 可能还有字符没用完！
       return;
   }
   ```
   **✓ 必须同时检查字符用完：**
   ```cpp
   if (segments.size() == 4) {
       if (start == s.size()) result.push_back(...);
       return;
   }
   ```

2. **✗ 前导零判断只判了 "0x" 忘了 "00"**：
   ```cpp
   // 错误：只检查 seg != "0" && seg[0] == '0' 
   // 实际上 "0" 是合法的，"00" "01" "001" 都不合法
   ```
   **✓ 正确判断：长度 > 1 且首字符为 '0' 就非法**
   ```cpp
   if (seg.size() > 1 && seg[0] == '0') break;
   ```

3. **✗ 用 `continue` 而不是 `break` 跳过前导零**：
   ```cpp
   if (seg[0] == '0' && seg.size() > 1) continue;  // 还会尝试更长的，浪费
   ```
   **✓ 用 `break`**：前导零和超过 255 一旦出现，更长的段只会更差。

4. **✗ stoi 溢出**：虽然本题每段最多 3 位不会溢出，但如果扩展到更长字符串，`stoi` 可能抛异常。更安全的写法是手动转换并限制长度。

## 面试追问

**Q1: 暴力解的思路是什么？为什么可行？**
→ 三重循环枚举 3 个切点。因为 IP 固定 4 段、每段 1-3 字符，搜索空间极小（最多 3³=27 种组合），暴力完全可行。

**Q2: 如果不是 4 段而是 k 段呢？三重循环还行吗？**
→ 不行，k-1 重循环代码不可维护。应该用回溯：递归深度为 k，每层分支因子为 3，复杂度 O(3^k · n)。

**Q3: 如果输入可能包含非数字字符，怎么处理？**
→ 预处理阶段检查：如果包含非数字字符直接返回空。或者在 `isValid` 中额外检查每个字符是否为数字。

**Q4: 能不能不用 substr，优化字符串拼接？**
→ 可以。用一个固定长度 4 的数组存放每段的起始和长度（或直接存数值），最后统一拼接。也可以在原字符串上直接插入 '.' 再删除，但可读性差。回溯中用 `start` 和 `len` 索引即可避免 substr。
