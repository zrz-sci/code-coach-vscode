# 1502. 判断能否形成等差数列

## 核心思路
本质上在问：给定一组数，能否将它们排成一行，使得相邻两项之差恒定？等差数列排序后是均匀分布的，所以关键在于**排序后检查相邻差是否一致**。

## 思维链

1. **读完题第一反应**：等差数列的定义是相邻差相等。题目允许重新排列，所以顺序不固定。最朴素的想法——排序后检查。

2. **为什么排序有效？** 等差数列排序后一定是单调递增或递减的（公差≥0 递增，公差<0 递减）。排序后相邻元素的差应该全部相等。

3. **排序的代价可以接受吗？** O(n log n) 排序 + O(n) 遍历检查，对于 n ≤ 1000 绰绰有余。

4. **能否不排序？** 等差数列的每个元素可以由 `min + i * d` 确定（d = 公差）。如果我们知道 min 和 max，就能算出 d = (max - min) / (n - 1)。然后用哈希集合验证每个应该出现的值是否都在数组中。这是 O(n) 时间 O(n) 空间的做法。

5. **还有更省空间的方法吗？** 可以利用"桶排序"的思想：把每个元素放到它在等差数列中"应该在"的位置上（原地交换），然后检查是否每个位置都对。这是 O(n) 时间 O(1) 空间。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 排序 + 遍历 | 排序后检查相邻差 | O(n log n) | O(1) | ⭐ 必须写出 |
| 哈希集合 | 算出公差，验证每个期望值 | O(n) | O(n) | 能说出即可 |
| 原地交换（桶思想） | 把元素放到正确位置 | O(n) | O(1) | 加分项 |

## 关键提示

1. **等差数列排序后的性质**：`arr[i] - arr[i-1]` 对所有 i 都相同，等于 `(max - min) / (n - 1)`。

2. **特殊情况**：如果所有元素相同（公差为 0），直接就是等差数列。数组长度为 2 时，任何两个数都能构成等差数列。

3. **哈希解法的关键判断**：如果 `(max - min)` 不能被 `(n - 1)` 整除，直接返回 false。

4. **原地交换的核心**：每个元素 `arr[i]` 在等差数列中的目标位置是 `(arr[i] - min) / d`，反复交换直到当前位置正确。

5. **去重问题**：如果公差不为 0 但有重复元素，一定不是等差数列。

## 解法详解

### 解法1: 排序 + 遍历 — O(n log n) / O(1) ⭐ 面试首选

**思考过程**: 等差数列的核心性质是"相邻差恒定"。但题目允许重新排列，我们不知道原始顺序。最自然的想法是：排序后，等差数列就变成了有序的等差数列，此时只需遍历一遍检查相邻差是否全相等。

```
// 示例: arr = [3, 5, 1]
// 排序后: [1, 3, 5]
// 差值:    2  2     ← 全相等 → true
//
// 示例: arr = [1, 2, 4]
// 排序后: [1, 2, 4]
// 差值:    1  2     ← 不相等 → false
```

```cpp
class Solution {
public:
    bool canMakeArithmeticProgression(vector<int>& arr) {
        sort(arr.begin(), arr.end());
        
        // 排序后，等差数列的相邻差应该全部相等
        int diff = arr[1] - arr[0];
        for (int i = 2; i < arr.size(); i++) {
            if (arr[i] - arr[i - 1] != diff) {
                return false;
            }
        }
        return true;
    }
};
```

**关键点**: 这个解法几乎没有坑，代码简洁。唯一要注意的是题目保证 `arr.length >= 2`，所以 `arr[1] - arr[0]` 不会越界。

### 解法2: 哈希集合 — O(n) / O(n)

**从解法1优化**: 排序的 O(n log n) 是瓶颈。我们能否不排序就判断？

**核心观察**: 等差数列由 min、max、n 完全确定。公差 `d = (max - min) / (n - 1)`，期望的元素是 `min, min+d, min+2d, ..., max`。只需验证数组中的每个元素是否都在这个期望集合中。

```
// arr = [3, 5, 1]
// min=1, max=5, n=3, d=(5-1)/(3-1)=2
// 期望值: {1, 3, 5}
// 实际值: {3, 5, 1} → 放入集合 {1, 3, 5} → 和期望完全匹配 → true
```

```cpp
class Solution {
public:
    bool canMakeArithmeticProgression(vector<int>& arr) {
        int n = arr.size();
        int minVal = *min_element(arr.begin(), arr.end());
        int maxVal = *max_element(arr.begin(), arr.end());
        
        // 特殊情况: 所有元素相同，公差为0
        if (maxVal == minVal) return true;
        
        // 公差必须是整数，否则不可能是等差数列
        if ((maxVal - minVal) % (n - 1) != 0) return false;
        
        int d = (maxVal - minVal) / (n - 1);
        
        unordered_set<int> seen;
        for (int x : arr) {
            // 每个元素减去 min 后必须是 d 的整数倍
            if ((x - minVal) % d != 0) return false;
            // 检查重复: 等差数列（公差≠0时）不应有重复元素
            if (!seen.insert(x).second) return false;
        }
        return true;
    }
};
```

**关键点**: 有三个提前返回条件——(1) 全部相同直接 true；(2) 差值不整除直接 false；(3) 有重复元素直接 false。漏掉任一个都会出错。

### 解法3: 原地交换（桶排序思想）— O(n) / O(1)

**从解法2优化**: 哈希集合用了 O(n) 空间。能否 O(1) 空间？

**核心思想**: 算出公差 d 后，元素 `arr[i]` 在等差数列中应该排在位置 `(arr[i] - min) / d`。我们直接把每个元素交换到它"该去的位置"，如果最终每个位置都放了正确的值，就是等差数列。

```
// arr = [3, 5, 1], min=1, d=2
// 
// i=0: arr[0]=3, 目标位置=(3-1)/2=1, swap(arr[0], arr[1])
//      arr = [5, 3, 1]
//      arr[0]=5, 目标位置=(5-1)/2=2, swap(arr[0], arr[2])
//      arr = [1, 3, 5]
//      arr[0]=1, 目标位置=(1-1)/2=0, 已就位!
// i=1: arr[1]=3, 目标位置=1, 已就位!
// i=2: arr[2]=5, 目标位置=2, 已就位!
// 全部就位 → true
```

```cpp
class Solution {
public:
    bool canMakeArithmeticProgression(vector<int>& arr) {
        int n = arr.size();
        int minVal = *min_element(arr.begin(), arr.end());
        int maxVal = *max_element(arr.begin(), arr.end());
        
        if (maxVal == minVal) return true;
        if ((maxVal - minVal) % (n - 1) != 0) return false;
        
        int d = (maxVal - minVal) / (n - 1);
        
        // 原地交换: 把每个元素放到它该在的位置
        for (int i = 0; i < n; ) {
            int targetIdx = (arr[i] - minVal) / d;
            
            // 当前值减去 min 不是 d 的倍数 → 不合法
            if ((arr[i] - minVal) % d != 0) return false;
            // 目标位置越界 → 不合法
            if (targetIdx < 0 || targetIdx >= n) return false;
            
            if (targetIdx == i) {
                // 已在正确位置
                i++;
            } else if (arr[targetIdx] == arr[i]) {
                // 目标位置已经有相同值 → 重复元素
                return false;
            } else {
                swap(arr[i], arr[targetIdx]);
                // 不递增 i，继续处理交换过来的新元素
            }
        }
        return true;
    }
};
```

**关键点**: 
- `i` 只在当前位置正确时才递增，确保交换来的新元素也会被处理。
- 判断 `arr[targetIdx] == arr[i]` 来检测重复，防止无限交换。

## 解法对比

| | 排序 + 遍历 | 哈希集合 | 原地交换 |
|---|---|---|---|
| 时间 | O(n log n) | O(n) | O(n) |
| 空间 | O(1)* | O(n) | O(1) |
| 代码复杂度 | 极简 | 中等 | 较高 |
| 修改原数组 | 是（排序） | 否 | 是（交换） |
| 面试推荐 | ⭐ 首选 | 说思路 | 加分项 |

*注：排序的 O(1) 空间指的是不额外分配，但修改了原数组。严格说 sort 内部可能用 O(log n) 栈空间。

**什么时候选哪个？**
- 面试中先写排序解法（30秒写完，不出错），再口述 O(n) 思路。
- 如果面试官追问"不排序怎么做"，给哈希解法。
- 如果追问"O(1) 空间"，给原地交换。

## 易错点

1. **哈希解法忘记判断整除性**
   - ✗ 直接算 `d = (max - min) / (n - 1)` → 整数除法截断导致错误
   - ✓ 先判断 `(max - min) % (n - 1) != 0` 则直接返回 false

2. **哈希解法忘记处理公差为0的情况**
   - ✗ `d = 0` 时，`(x - minVal) % d` 除零错误！
   - ✓ 先特判 `maxVal == minVal` 直接返回 true

3. **原地交换忘记检测重复导致死循环**
   - ✗ 两个相同值不断互相交换，永远到不了正确位置
   - ✓ 加 `arr[targetIdx] == arr[i]` 的重复检测

4. **排序解法从 i=1 开始循环但差值用 i=0 算**
   - ✗ `for(int i=1; ...) if(arr[i]-arr[i-1] != arr[1]-arr[0])` 但循环从1开始所以 i=1 时比自己和自己，永远相等，漏检
   - ✓ 先算好 `diff = arr[1] - arr[0]`，循环从 `i = 2` 开始

## 面试追问

**Q1（基础理解）**: 等差数列有什么数学性质可以利用？
> 排序后相邻差恒定；由 min, max, n 可唯一确定公差 d = (max-min)/(n-1)；每个元素满足 `a_i = min + i * d`。

**Q2（优化）**: 排序是 O(n log n)，能否 O(n) 解决？
> 用哈希集合。算出公差后，验证每个元素是否是 min + k*d 形式，同时检查无重复。O(n) 时间 O(n) 空间。

**Q3（进阶）**: 能否 O(n) 时间 O(1) 空间？
> 原地交换：算出每个元素的目标位置 (arr[i]-min)/d，像桶排序一样把元素交换到正确位置。关键要处理重复检测避免死循环。

**Q4（变体）**: 如果不允许修改原数组，且要求 O(n) 时间，怎么做？
> 只能用 O(n) 空间的哈希方法。不修改原数组 + O(1) 空间 + O(n) 时间三者不可兼得。
