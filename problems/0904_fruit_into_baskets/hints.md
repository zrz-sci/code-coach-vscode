# 904. 水果成篮

## 核心思路

**本质：在整数数组中，找包含最多两种不同值的最长连续子数组的长度。** 把"水果种类"和"篮子"的故事外壳剥掉，这就是经典的"最多 K 种字符的最长子串"问题，其中 K=2。

## 思维链

1. **读完题第一反应**：需要找一段连续子数组，其中最多出现 2 种水果，且长度最大。最朴素的做法？枚举所有子数组，检查每个子数组里有几种水果。

2. **暴力解的瓶颈**：枚举起点 O(n)，对每个起点向右扩展并统计种类数 O(n)，总共 O(n²)。n 高达 10⁵，勉强能过但不够优雅。瓶颈在于：**左端点每次回退都从头开始扩展，之前的信息全部丢失**。

3. **怎么突破瓶颈？** 观察关键性质：当右指针固定时，如果 [left, right] 包含的种类 ≤ 2，那 left 右移只会让种类更少或不变——**窗口满足单调性**！这正是**滑动窗口**的适用条件。左指针只需要向右移动，永远不回退。

4. **具体怎么用滑动窗口？** 维护一个哈希表记录窗口内每种水果的出现次数。右指针扩展时加入新水果；如果种类超过 2，就不断收缩左指针（从哈希表中减少计数，计数归零时删除该种类），直到种类 ≤ 2。每步更新最大窗口长度。

5. **为什么正确？** 左指针只向右移动，右指针也只向右移动，每个元素最多被加入和移出各一次，所以总时间 O(n)。由于我们尝试了所有合法的右端点，且对每个右端点都找到了尽可能靠左的左端点，所以不会漏掉最优解。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举每个起点，向右扩展直到超过2种 | O(n²) | O(1) | 能说出即可 |
| 滑动窗口 + 哈希表 | 双指针维护最多含2种水果的窗口 | O(n) | O(1) | ⭐ 必须写出 |
| 滑动窗口 + 精简变量 | 只记录最后出现的两种水果及其位置 | O(n) | O(1) | 加分项 |

## 关键提示

1. **翻译题意**：把故事翻译成算法语言 —— "最多包含 2 种不同元素的最长连续子数组"。一旦这么想，就能联想到滑动窗口。

2. **窗口何时收缩？** 当窗口内的水果种类 > 2 时，必须收缩左边界。用哈希表 `count[fruit]` 追踪每种水果的数量，当某种水果计数降为 0 时，从表中删除它。

3. **哈希表大小是常数**：虽然用了哈希表，但任意时刻表中最多 3 个 key（刚加入第 3 种、还没来得及删除），所以空间是 O(1)。

4. **滑动窗口可视化**：
```
fruits = [3, 3, 3, 1, 2, 1, 1, 2, 3, 3, 4]
                       
窗口滑动过程 (window 内最多2种):
Step1: [3]                    → 种类:{3:1}     len=1
Step2: [3,3]                  → 种类:{3:2}     len=2
Step3: [3,3,3]                → 种类:{3:3}     len=3
Step4: [3,3,3,1]              → 种类:{3:3,1:1} len=4
Step5: [3,3,3,1,2] 种类=3! 收缩左边→
       → [3,3,1,2] 种类=3! 继续→
       → [3,1,2] 种类=3! 继续→
       → [1,2]                → 种类:{1:1,2:1} len=2
Step6: [1,2,1]                → 种类:{1:2,2:1} len=3
Step7: [1,2,1,1]              → 种类:{1:3,2:1} len=4
Step8: [1,2,1,1,2]            → 种类:{1:3,2:2} len=5 ← 最大!
Step9: [1,2,1,1,2,3] 种类=3! 收缩→
       ...→ [2,3]
...
答案 = 5
```

5. **精简变量版**：如果面试官追问能否不用哈希表，可以只记录"上一种水果"和"上上种水果"以及"上一种水果连续出现的起始位置"，但代码更复杂，建议先写哈希表版。

## 解法详解

### 解法1: 暴力枚举 — O(n²) / O(1)

**思考过程**：最直觉的方法 —— 对每个起点 i，向右走直到遇到第 3 种水果为止，记录长度。

```cpp
class Solution {
public:
    int totalFruit(vector<int>& fruits) {
        int n = fruits.size(), maxLen = 0;
        for (int i = 0; i < n; i++) {
            unordered_set<int> types;
            int j = i;
            while (j < n) {
                types.insert(fruits[j]);
                if (types.size() > 2) break; // 超过2种，停止
                j++;
            }
            maxLen = max(maxLen, j - i);
        }
        return maxLen;
    }
};
```

**关键点**：每次 i 右移时，j 又从 i 开始重新扫描，大量重复工作。这正是滑动窗口要解决的问题。

---

### 解法2: 滑动窗口 + 哈希表 — O(n) / O(1) ⭐ 面试首选

**从解法1优化**：解法1的瓶颈是左端点每次移动后，右端点从头扩展。观察到：当左端点右移一步，窗口只是少了一个元素，右端点不需要回退。这就是滑动窗口：**左右指针都只向右移动**。

```cpp
class Solution {
public:
    int totalFruit(vector<int>& fruits) {
        unordered_map<int, int> count; // 水果种类 → 窗口内出现次数
        int left = 0, maxLen = 0;
        
        for (int right = 0; right < (int)fruits.size(); right++) {
            count[fruits[right]]++;  // 右指针扩展，加入新水果
            
            // 种类超过2时，收缩左边界
            while (count.size() > 2) {
                count[fruits[left]]--;
                if (count[fruits[left]] == 0) {
                    count.erase(fruits[left]); // 计数归零 → 删除该种类
                }
                left++;
            }
            
            // 此时窗口 [left, right] 合法，更新答案
            maxLen = max(maxLen, right - left + 1);
        }
        
        return maxLen;
    }
};
```

**关键点**：
- `count.size()` 始终 ≤ 3（最多刚加入第3种还没删除），所以哈希表操作是 O(1)
- 左右指针各遍历数组一次，总时间严格 O(n)

---

### 解法3: 滑动窗口 — 精简变量版 — O(n) / O(1)

**进一步优化思路**：当窗口内出现第 3 种水果时，我们需要把左边界跳到"只保留最近两种水果"的位置。关键观察：**新的左边界 = 上一种不同水果最后连续出现的起始位置**。

举例：`[1,2,1,1,2,3]`，当 right 指向 3 时，窗口内有 1、2、3。我们需要丢弃所有最早的那种水果，新左边界应该从 `fruits[right-1]` 这种水果最后一段连续出现的起点开始。

```cpp
class Solution {
public:
    int totalFruit(vector<int>& fruits) {
        int n = fruits.size();
        int maxLen = 0;
        // lastSeen: 上一种水果连续段的起始位置
        // typeA, typeB: 当前窗口内的两种水果
        int left = 0;
        int typeA = -1, typeB = -1;
        int lastTypeChangePos = 0; // 最近一次水果种类变化的位置
        
        for (int right = 0; right < n; right++) {
            if (fruits[right] != typeA && fruits[right] != typeB) {
                // 出现第3种水果，左边界跳到最近连续段的起始
                left = lastTypeChangePos;
                typeA = fruits[right - 1]; // 保留 right 左边紧邻的种类
                typeB = fruits[right];     // 和新种类
            }
            // 更新"最近一次种类变化"的位置
            if (right > 0 && fruits[right] != fruits[right - 1]) {
                lastTypeChangePos = right;
            }
            maxLen = max(maxLen, right - left + 1);
        }
        
        return maxLen;
    }
};
```

**关键点**：这个版本不用哈希表，常数因子更小，但逻辑更复杂，面试中不推荐作为首选。理解滑动窗口+哈希表版即可。

## 解法对比

| | 暴力枚举 | 滑动窗口+哈希表 | 精简变量版 |
|---|---|---|---|
| 时间 | O(n²) | O(n) | O(n) |
| 空间 | O(1) | O(1)（哈希表最多3项） | O(1) |
| 代码难度 | 简单 | 中等 | 较高 |
| 面试推荐 | 说思路即可 | ⭐ **首选** | 追问时提及 |
| 通用性 | 低 | **高**（K种直接改2为K） | 低（只适用于K=2） |

**关键区别**：哈希表版天然支持 K 种水果的推广（改 `count.size() > 2` 为 `> K`），而精简变量版只能处理 K=2。

## 易错点

1. **忘记在计数归零时删除 key**
   - ✗ `count[fruits[left]]--;` 然后直接 `left++;`（此时 size() 仍然是 3）
   - ✓ 必须在 `count[fruits[left]] == 0` 时执行 `count.erase(fruits[left])`，否则 `count.size()` 永远不会减小

2. **用 `if` 代替 `while` 收缩窗口**
   - ✗ `if (count.size() > 2) { ... left++; }` — 一次可能不够
   - ✓ `while (count.size() > 2) { ... left++; }` — 可能需要连续收缩多步

3. **窗口长度计算 off-by-one**
   - ✗ `right - left`
   - ✓ `right - left + 1`（闭区间 [left, right] 的长度）

4. **精简变量版：处理数组只有一种水果的边界**
   - 当 `typeB == -1` 时要特殊处理，否则 `fruits[right] != typeB` 会误触发第3种水果的逻辑

## 面试追问

**Q1: 暴力解能过吗？瓶颈在哪？**
> 暴力 O(n²)，n=10⁵ 约 10¹⁰ 次操作，会 TLE。瓶颈在于每次左端点移动后，右端点从头扫描，大量重复。

**Q2: 如果篮子数从 2 变成 K 呢？（即最多 K 种水果）**
> 滑动窗口+哈希表版代码几乎不变：把 `count.size() > 2` 改成 `count.size() > k`。这就是 LeetCode 340 (Longest Substring with At Most K Distinct Characters) 的原题。时间仍然 O(n)，空间 O(K)。

**Q3: 如果数据流源源不断进来（不是给定数组），怎么处理？**
> 滑动窗口天然支持流式处理：右指针每次读入一个新元素，按同样的逻辑收缩左指针。不需要存储整个数组，只需要维护窗口内的哈希表和左指针位置。但左指针之前的元素需要能访问到（可以用队列缓存窗口内的元素）。
