# 253. 会议室 II

## 核心思路

本质上是在问：**在任意时刻，最多有多少个会议同时进行？** 这个最大重叠数就是所需的最少会议室数量。

## 思维链

1. **读完题第一反应**：每个会议占用一个时间段，如果两个会议时间重叠就需要不同的会议室。最朴素的想法——模拟每个时刻有多少会议在进行？但时间范围到 10⁶，逐时刻扫描不够优雅。

2. **换个角度想**：不需要逐时刻扫描，只需要关注**事件发生的时刻**。每个会议产生两个事件：开始时 +1（需要一间房），结束时 -1（释放一间房）。把所有事件按时间排序，扫描一遍就能知道任意时刻的并发数。

3. **事件排序有个细节**：如果一个会议在时刻 10 结束，另一个在时刻 10 开始，它们可以共用一间房吗？题目 `[start, end)` 是左闭右开，所以**结束优先于开始处理**——先释放再分配，这样不会多算。

4. **另一个经典思路——最小堆**：按开始时间排序会议，逐个分配房间。用最小堆维护"每间房最早何时空闲"。新会议来了，看堆顶（最早结束的房间）能否复用；不能就开新房间。

5. **还有更简洁的做法——分离排序**：把所有开始时间和结束时间分别排序，用双指针扫描，类似归并。开始指针走一步 = 需要一间房，结束指针走一步 = 释放一间房。

6. **总结**：三种解法本质都是在计算"最大并发数"，只是实现角度不同——差分事件线扫描、最小堆模拟分配、双指针归并扫描。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 排序+双指针 | 开始/结束分离排序，双指针扫描 | O(n log n) | O(n) | ⭐ 必须写出 |
| 最小堆 | 按开始排序，堆维护最早结束时间 | O(n log n) | O(n) | ⭐ 必须写出 |
| 差分/扫描线 | 事件 +1/-1，排序后累加求最大值 | O(n log n) | O(n) | 加分项 |

## 关键提示

1. **想一想**：如果把每个会议画在时间轴上，答案就是"竖着切一刀，最多切到几条线段"——这就是最大重叠数。

2. **事件拆分**：每个区间 `[s, e)` 可以拆成两个事件：时刻 s 发生 `+1`，时刻 e 发生 `-1`。排序后做前缀和，最大值就是答案。

3. **双指针的直觉**：开始时间和结束时间分别排序后，如果当前最早的开始 < 当前最早的结束，说明又多了一个并发会议；否则说明有一间房已经空了。

4. **堆的直觉**：贪心地把新会议分配给"最早结束的房间"。如果最早结束的房间都不能复用，那就只能开新房间。

5. **边界**：时刻相同时，结束事件应该排在开始事件之前（一个会议 10 结束，另一个 10 开始，可以复用同一间房）。

```
时间轴示意 (示例1):
0    5    10   15   20   25   30
|============================|     会议[0,30)
     |====|                        会议[5,10)
               |====|              会议[15,20)

时刻5~10 有2个会议重叠 → 需要2间会议室
```

## 解法详解

### 解法1: 排序 + 双指针 — O(n log n) / O(n) ⭐ 面试首选

**思考过程**：

把问题简化——我们不关心哪个开始对应哪个结束，只关心在任意时刻有多少"已开始但未结束"的会议。把开始时间和结束时间分别排序，用两个指针模拟时间推进：

- 遇到一个开始事件：`rooms++`
- 遇到一个结束事件：`rooms--`
- 每次取时间较小的先处理（结束优先）

```
// 双指针扫描过程 (示例1):
// starts: [0, 5, 15]    ends: [10, 20, 30]
//          ↑s                  ↑e
// 
// s=0 < e=10 → rooms=1, s++
// s=5 < e=10 → rooms=2, s++     ← 最大值=2
// s=15 >= e=10 → rooms=1, e++
// s=15 < e=20 → rooms=2, e++
// s用完 → 结束，答案=2
```

```cpp
class Solution {
public:
    int minMeetingRooms(vector<vector<int>>& intervals) {
        int n = intervals.size();
        vector<int> starts(n), ends(n);
        for (int i = 0; i < n; i++) {
            starts[i] = intervals[i][0];
            ends[i] = intervals[i][1];
        }
        sort(starts.begin(), starts.end());
        sort(ends.begin(), ends.end());
        
        int rooms = 0, maxRooms = 0;
        int s = 0, e = 0;
        while (s < n) {
            if (starts[s] < ends[e]) {
                // 新会议开始，还没有任何会议结束能释放房间
                rooms++;
                maxRooms = max(maxRooms, rooms);
                s++;
            } else {
                // 有会议已经结束，释放一间房间
                rooms--;
                e++;
            }
        }
        return maxRooms;
    }
};
```

**关键点**：
- `starts[s] < ends[e]` 用 `<` 而不是 `<=`，因为一个会议在时刻 t 结束、另一个在时刻 t 开始时，可以复用同一间房。
- 不需要遍历完 ends 数组，starts 遍历完时答案已经确定了。

### 解法2: 最小堆 — O(n log n) / O(n)

**思考过程**：

模拟真实分配过程。按开始时间排序后，逐个安排会议。用一个最小堆记录每间会议室当前的"结束时间"。来了一个新会议：
- 看堆顶（最早结束的房间），如果它已经结束了（`堆顶 <= 新会议开始`），就复用它（弹出旧结束时间，压入新结束时间）
- 否则，开一间新房间（直接压入新结束时间）
- 堆的大小就是当前在用的房间数

```
// 最小堆过程 (示例1):
// 排序后: [0,30], [5,10], [15,20]
//
// 处理[0,30]: 堆空 → 开新房间 → 堆={30}      rooms=1
// 处理[5,10]: 堆顶30 > 5 → 开新房间 → 堆={10,30}  rooms=2
// 处理[15,20]: 堆顶10 <= 15 → 复用！弹出10，压入20 → 堆={20,30}  rooms=2
// 答案 = 堆最大size = 2
```

```cpp
class Solution {
public:
    int minMeetingRooms(vector<vector<int>>& intervals) {
        // 按开始时间排序
        sort(intervals.begin(), intervals.end());
        
        // 最小堆：存储每间会议室的结束时间
        priority_queue<int, vector<int>, greater<int>> pq;
        
        for (auto& interval : intervals) {
            // 最早结束的房间已经空了，可以复用
            if (!pq.empty() && pq.top() <= interval[0]) {
                pq.pop();
            }
            // 无论复用还是新开，都要压入当前会议的结束时间
            pq.push(interval[1]);
        }
        
        // 堆的大小 = 同时需要的最大房间数
        return pq.size();
    }
};
```

**关键点**：
- `pq.top() <= interval[0]`：`<=` 表示结束时刻 == 开始时刻时可以复用。
- 每次只弹出一个堆顶（最多释放一间房给当前会议）——不能贪心地释放多间，因为当前会议只能用一间。

### 解法3: 差分/扫描线 — O(n log n) / O(n)

**思考过程**：

最直接地翻译"最大并发数"。每个会议产生两个事件：
- 时刻 `start`：需要 +1 间房
- 时刻 `end`：释放 -1 间房

把所有事件按时间排序（时间相同时，-1 排在 +1 前面），然后做前缀和，最大值就是答案。

```cpp
class Solution {
public:
    int minMeetingRooms(vector<vector<int>>& intervals) {
        // 每个会议产生两个事件：(时刻, +1/-1)
        vector<pair<int, int>> events;
        for (auto& iv : intervals) {
            events.push_back({iv[0], 1});   // 开始：+1
            events.push_back({iv[1], -1});  // 结束：-1
        }
        
        // 排序：时间相同时，-1 排在 +1 前面（先释放再分配）
        sort(events.begin(), events.end(), [](auto& a, auto& b) {
            if (a.first != b.first) return a.first < b.first;
            return a.second < b.second;  // -1 < 1，所以结束排前面
        });
        
        int rooms = 0, maxRooms = 0;
        for (auto& [time, delta] : events) {
            rooms += delta;
            maxRooms = max(maxRooms, rooms);
        }
        return maxRooms;
    }
};
```

**关键点**：
- 排序时，同一时刻的结束事件（-1）必须排在开始事件（+1）前面，否则会多算一间房。
- 这个思路可以推广到任何"区间最大重叠数"问题，非常通用。

## 解法对比

| | 排序+双指针 | 最小堆 | 差分/扫描线 |
|---|---|---|---|
| **核心操作** | 两个有序数组归并比较 | 贪心复用最早结束的房间 | 事件排序 + 前缀和 |
| **代码量** | 最少 | 中等 | 中等 |
| **直觉** | 需要理解"分离排序仍然正确" | 最直觉（模拟真实分配） | 最数学化 |
| **扩展性** | 仅适用于求数量 | 可以追踪每间房的具体分配 | 可推广到加权重叠 |
| **面试推荐** | ⭐ 首选（简洁高效） | ⭐ 必须掌握（追问最多） | 加分（展示算法功底） |

## 易错点

1. **双指针判断条件用 `<=` 导致少算房间**
   - ✗ `if (starts[s] <= ends[e])` — 相等时不该开新房间（应该先释放）
   - ✓ `if (starts[s] < ends[e])` — 严格小于才开新房间
   - 原因：会议 `[5,10]` 和 `[10,15]`，10 结束的房间可以给 10 开始的用

2. **最小堆判断复用条件写反**
   - ✗ `pq.top() < interval[0]` — 漏掉了 `==` 的情况
   - ✓ `pq.top() <= interval[0]` — 结束时刻等于开始时刻时可以复用

3. **差分排序忘记处理同时刻事件顺序**
   - ✗ 只按时间排序，不管 +1/-1 的顺序 → 同一时刻先 +1 后 -1 会多算
   - ✓ 时间相同时，-1（结束）排在 +1（开始）前面

4. **最小堆解法中忘记排序**
   - ✗ 不按开始时间排序直接处理 → 可能把后开始的会议先分配
   - ✓ 必须先按 `start` 排序，模拟时间推进

## 面试追问

**Q1: 暴力解怎么做？瓶颈在哪？**
> 暴力：对每个时刻 t 遍历所有会议，统计包含 t 的会议数。时间 O(T × n)，T 是时间范围最大值。瓶颈在于遍历了大量无事件发生的时刻。优化方向：只关注有事件发生的时刻。

**Q2: 如果面试官追问"这两个解法的本质区别是什么"？**
> 双指针/扫描线是"全局统计"视角——在所有事件中找最大并发。最小堆是"模拟分配"视角——逐个分配房间，贪心复用。前者更适合纯计数，后者可以扩展到追踪每间房的具体使用情况。

**Q3: 如果要返回每个会议分配到哪间房间怎么办？**
> 最小堆解法最适合扩展。堆中存 `{结束时间, 房间编号}`，复用时弹出的房间编号就是分配结果；开新房间时分配新编号。双指针和扫描线解法因为丢失了会议的对应关系，不容易追踪分配。

**Q4: 如果 intervals 数量极大（10⁸），有什么优化思路？**
> 如果时间范围较小（如 0~10⁶），可以用差分数组 `diff[t]`，直接 O(1) 标记每个区间，最后 O(T) 扫一遍求前缀最大值，避免排序的 O(n log n)。总体 O(n + T)。
