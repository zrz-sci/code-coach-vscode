# 984. 不含 AAA 或 BBB 的字符串

[./solution.cpp)

## 核心思路

给定整数 a 和 b，构造一个长度为 a+b 的字符串，包含恰好 a 个 'a' 和 b 个 'b'，且不包含 "aaa" 或 "bbb"。**贪心策略：每次优先放剩余数量更多的那个字符，放两个后切换到另一个字符放一个，防止连续三个。**

## 思维链

1. **读完题第一反应** -> 需要构造一个合法字符串。这是一个构造题，不是计数题。关键约束是不能有三个连续相同字符。

2. **朴素思路** -> 轮流放 a 和 b？比如 "ababab..."。但如果 a 远大于 b（如 a=4, b=1），轮流放会用完 b 后剩下大量 a 无法处理。

3. **观察规律** -> 当一种字符远多于另一种时，需要连续放两个多的那种，再穿插一个少的。例如 a=4, b=1: "aabaa"。核心：**多的放两个，少的放一个**。

4. **贪心策略** -> 每一步看谁剩余多。如果 a > b，放 "aa" 再放 "b"（如果 b > 0）；如果 b > a，放 "bb" 再放 "a"（如果 a > 0）；如果 a == b，放 "ab" 或 "ba" 都行。

5. **另一种贪心思路** -> 逐字符构造：每次决定放 'a' 还是 'b'。如果末尾已经有两个连续 'a'，必须放 'b'；如果末尾已经有两个连续 'b'，必须放 'a'；否则优先放剩余多的那个。

6. **正确性保证** -> 题目说保证有解。只要 a 和 b 的差不超过某个范围（实际上任意 0<=a,b<=100 都有解），贪心就能构造出来。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 贪心（块构造） | 多的放两个，少的放一个 | O(a+b) | O(a+b) | 面试首选 |
| 贪心（逐字符） | 每步检查末尾，优先放多的 | O(a+b) | O(a+b) | 同样优秀 |

## 关键提示

1. **为什么优先放多的？** 如果不优先消耗多的字符，到后面多的字符会堆积，被迫连续三个以上。优先放多的可以尽早平衡两者的数量。

2. **块构造的模式**：
```
a=5, b=2:
  a > b → 放 "aa"，a=3, b=2 → 放 "b"，a=3, b=1
  a > b → 放 "aa"，a=1, b=1 → 放 "b"，a=1, b=0
  a > b → 放 "a"，a=0, b=0
  结果: "aab" + "aab" + "a" = "aababa"... 等等让我重算
  
  实际过程: while循环每轮
  轮1: a=5>b=2 → append "aa", a=3; b>0 → append "b", b=1
  轮2: a=3>b=1 → append "aa", a=1; b>0 → append "b", b=0
  轮3: a=1>b=0 → append "a", a=0 (只放一个因为差距不大了)
  不对，让我用逐字符版展示更清楚:
```

3. **逐字符构造的演示**：
```
a=4, b=1, result=""
  末尾无连续 → a>b → 放'a', a=3, result="a"
  末尾1个a → a>b → 放'a', a=2, result="aa"
  末尾2个a → 必须放'b', b=0, result="aab"
  末尾1个b → a>b → 放'a', a=1, result="aaba"
  末尾1个a → a>0 → 放'a', a=0, result="aabaa"
  完成！result = "aabaa" ✓
```

4. **边界情况**：a=0 或 b=0 时，直接返回全 'b' 或全 'a'（因为 0 <= a,b <= 100 且题目保证有解，所以全相同字符时长度 ≤ 2 也是合法的... 不对，a 可以到 100，但此时 b 也应该足够大。实际上如果 a=100,b=0，那字符串就是 100 个 'a'，包含 "aaa"。但题目说保证有解，所以不会出现 a=100,b=0 的情况。）

5. **a == b 时怎么办？** 交替放即可："ababab..."。更一般地，差值 <= 1 时交替放就不会出现三连。

## 解法详解

### 解法1: 贪心（块构造） -- O(a+b) / O(a+b) -- 面试首选

**思考过程**: 每轮循环处理一个"块"：多的字符放两个（或一个），少的字符放一个。循环直到两个字符都用完。

```cpp
class Solution {
public:
    string strWithout3a3b(int a, int b) {
        string result;
        while (a > 0 || b > 0) {
            if (a > b) {
                // a 多：放 2 个 a（如果够的话），再放 1 个 b
                int takeA = min(2, a);
                result += string(takeA, 'a');
                a -= takeA;
                if (b > 0) {
                    result += 'b';
                    b--;
                }
            } else if (b > a) {
                // b 多：放 2 个 b，再放 1 个 a
                int takeB = min(2, b);
                result += string(takeB, 'b');
                b -= takeB;
                if (a > 0) {
                    result += 'a';
                    a--;
                }
            } else {
                // a == b：各放一个
                if (a > 0) { result += 'a'; a--; }
                if (b > 0) { result += 'b'; b--; }
            }
        }
        return result;
    }
};
```

**关键点**: 当 a > b 时放两个 'a' 一个 'b'，消耗速度 a 比 b 快，逐渐趋于平衡。a == b 时交替放，不会出现三连。

---

### 解法2: 贪心（逐字符构造） -- O(a+b) / O(a+b)

**思路**: 每次只放一个字符。判断条件：(1) 如果末尾已有两个连续 'a'，必须放 'b'；(2) 如果末尾已有两个连续 'b'，必须放 'a'；(3) 否则优先放剩余多的。

```cpp
class Solution {
public:
    string strWithout3a3b(int a, int b) {
        string result;
        while (a > 0 || b > 0) {
            int n = result.size();
            bool lastTwoA = (n >= 2 && result[n-1] == 'a' && result[n-2] == 'a');
            bool lastTwoB = (n >= 2 && result[n-1] == 'b' && result[n-2] == 'b');
            
            if (lastTwoA) {
                // 必须放 'b'
                result += 'b';
                b--;
            } else if (lastTwoB) {
                // 必须放 'a'
                result += 'a';
                a--;
            } else if (a >= b) {
                // 优先放剩余多的
                result += 'a';
                a--;
            } else {
                result += 'b';
                b--;
            }
        }
        return result;
    }
};
```

**关键点**: 这种方式更直观——每步决策只看末尾两个字符和剩余计数。正确性依赖于"优先放多的"这一贪心选择能保证不会走进死胡同。

## 解法对比

| | 块构造 | 逐字符构造 |
|---|---|---|
| 时间 | O(a+b) | O(a+b) |
| 空间 | O(a+b) | O(a+b) |
| 代码量 | 中 | 中 |
| 思维难度 | 低 | 低 |
| 面试推荐 | 首选（模式清晰） | 同样优秀（逻辑直观） |

两种方法本质相同，都是贪心策略。块构造更容易正确性论证，逐字符更灵活。

## 易错点

1. **忘记处理 a==b 的情况**
   - 如果 a==b 时仍然按 a>b 或 b>a 的逻辑走，可能多放了两个 'a' 然后 b 不够穿插。
   - 块构造中 a==b 时每次各放一个就够了。

2. **块构造中多的字符只放了一个而不是两个**
   - 当 a 远大于 b 时，如果每次只放一个 'a' 一个 'b'，'a' 消耗得太慢，最后会剩很多 'a'。
   - 多的那个应该放两个，少的放一个。

3. **逐字符构造中没有检查末尾两字符**
   - 单纯 "优先放多的" 而不检查末尾，可能在 a 远大于 b 时连续放三个 'a'。
   - 必须先检查末尾是否已有两个连续相同字符。

4. **a 或 b 为 0 时的处理**
   - 当一个字符已经用完（如 b=0），不能再放 'b'。块构造中的 `if (b > 0)` 判断不能省略。

5. **字符串拼接效率**
   - 在循环中用 `result += string(2, 'a')` 或 `result += 'a'` 是 O(1) 均摊的（C++ string 有预分配）。但如果用 `result = result + "aa"` 可能每次创建新对象，效率差。

## 面试追问

**Q1: 如何证明贪心策略一定能构造出合法字符串？**
> 题目保证有解（a, b ∈ [0, 100]）。贪心策略每轮至少消耗 1 个字符，且永远不会产生三连：多的放两个后立刻切换到少的，少的放一个后再回到多的。交替进行保证了任何位置最多连续两个相同字符。

**Q2: 什么条件下无解？**
> 永远有解（前提是 a, b >= 0）。即使 a=100, b=0，输出 100 个 'a' 包含 "aaa"，但题目说 "保证有解"，意味着这种输入不会出现。实际上 |a - b| <= max(a, b) 时都有解。更精确地说，只要不需要连续放 3 个以上相同字符就有解。

**Q3: 如果扩展到不能有连续 k 个相同字符呢？**
> 同样的贪心策略：多的放 k-1 个，少的放 1 个。或者逐字符构造时检查末尾 k-1 个字符。时间复杂度不变。

**Q4: 如果有三种字符 a, b, c 呢？**
> 每次优先放剩余最多的字符（但要检查末尾约束）。可以用最大堆维护剩余计数，每次取堆顶。这就变成了 LC 358/767 "重组字符串" 的变体。
