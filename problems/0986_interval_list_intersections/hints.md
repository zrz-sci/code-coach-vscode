# 986. 区间列表的交集

## 核心思路
两个**已排序且不重叠**的区间列表，求所有交集区间。本质就是"两个有序序列的归并"——用双指针同步扫描，每次判断当前两个区间有没有重叠，有则取交集，然后淘汰先结束的那个区间。

## 思维链

1. **读完题第一反应**：两个列表各取一个区间，判断是否有交集，有就记录。暴力做法是双重循环检查所有 `(i, j)` 对，O(m×n)。

2. **暴力解的瓶颈在哪？**：其实大部分 `(i, j)` 对根本不可能相交——如果 `A[i]` 完全在 `B[j]` 左边，那 `A[i]` 也不可能和 `B[j+1], B[j+2]...` 之前的区间相交（等等，反了，是和 `B[j]` 之前的相交更不可能）。关键在于：**两个列表都是有序的**，这意味着可以像归并排序一样用双指针。

3. **怎么突破？**：想象两个指针 `i` 和 `j` 分别指向两个列表。当前区间 `A[i]` 和 `B[j]` 要么有交集要么没有。判断完之后，**谁的结束时间更早，谁就该前进**——因为结束早的区间不可能再和对方的下一个区间相交了。

4. **两个区间怎么求交集？**：交集的起点 = `max(a_start, b_start)`，交集的终点 = `min(a_end, b_end)`。如果起点 ≤ 终点，说明有交集。

5. **谁前进？**：`end` 小的那个指针前进。因为 `end` 小的区间已经"用完"了，不可能和对方列表的后续区间再有交集。

6. **什么时候停？**：任一指针走到末尾就停。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力双循环 | 每对 (i,j) 都检查 | O(m×n) | O(1) | 能说出即可 |
| 双指针归并 | 有序列表同步扫描 | O(m+n) | O(1) | ⭐ 必须写出 |
| 扫描线 | 事件排序 | O((m+n)log(m+n)) | O(m+n) | 加分项（通用性更强） |

## 关键提示

1. **两个区间什么时候有交集？** 交集起点 = `max(两个起点)`，交集终点 = `min(两个终点)`。如果起点 > 终点则无交集。

2. **指针怎么移动？** 不是"谁起点小谁移"，而是**谁终点小谁移**。想一想为什么——终点小的区间已经完全"过期"了。

3. **会不会漏掉交集？** 不会。因为终点大的区间还可能和对方列表的下一个区间继续相交，所以它留下来等。

4. **ASCII 图示两个区间的 4 种位置关系：**
```
情况1: 不相交        情况2: 不相交
A: [----]            A:          [----]
B:        [----]     B: [----]

情况3: 部分重叠      情况4: 包含
A: [--------]        A: [------------]
B:     [--------]    B:    [----]
交集:  [----]        交集:  [----]
```

5. **边界：** 交集可以是单点，如 `[5,5]`，这也是合法的闭区间。

## 解法详解

### 解法1: 暴力双循环 — O(m×n) / O(1)

**思考过程**：最直觉的做法——遍历所有 `(i, j)` 组合，检查每对区间是否有交集。

```cpp
class Solution {
public:
    vector<vector<int>> intervalIntersection(vector<vector<int>>& firstList, 
                                              vector<vector<int>>& secondList) {
        vector<vector<int>> result;
        for (int i = 0; i < firstList.size(); i++) {
            for (int j = 0; j < secondList.size(); j++) {
                int lo = max(firstList[i][0], secondList[j][0]);
                int hi = min(firstList[i][1], secondList[j][1]);
                if (lo <= hi) {
                    result.push_back({lo, hi});
                }
            }
        }
        return result;
    }
};
```

**关键点**：虽然正确，但完全没有利用"已排序"这个条件。当 `firstList[i]` 的终点 < `secondList[j]` 的起点时，后面的 `j` 也不可能相交了，可以提前 break，但本质复杂度仍然不如双指针。

### 解法2: 双指针归并 — O(m+n) / O(1) ⭐ 面试首选

**从解法1优化**：解法1的瓶颈是遍历了大量不可能相交的组合。利用两个列表都已排序的性质，用两个指针从头开始同步扫描，每次只看当前的一对区间，检查完后淘汰先结束的那个。

```
// 可视化示例1的双指针过程:
// A: [0,2]  [5,10]  [13,23]  [24,25]
//     i→
// B: [1,5]  [8,12]  [15,24]  [25,26]
//     j→
//
// Step1: A[0]=[0,2], B[0]=[1,5] → 交集=[1,2], A结束早(2<5), i++
// Step2: A[1]=[5,10], B[0]=[1,5] → 交集=[5,5], B结束早(5<10), j++
// Step3: A[1]=[5,10], B[1]=[8,12] → 交集=[8,10], A结束早(10<12), i++
// Step4: A[2]=[13,23], B[1]=[8,12] → 无交集(13>12), B结束早, j++
// Step5: A[2]=[13,23], B[2]=[15,24] → 交集=[15,23], A结束早(23<24), i++
// Step6: A[3]=[24,25], B[2]=[15,24] → 交集=[24,24], B结束早(24<25), j++
// Step7: A[3]=[24,25], B[3]=[25,26] → 交集=[25,25], A结束早(25<26), i++
// i越界，结束。结果: [[1,2],[5,5],[8,10],[15,23],[24,24],[25,25]]
```

```cpp
class Solution {
public:
    vector<vector<int>> intervalIntersection(vector<vector<int>>& firstList, 
                                              vector<vector<int>>& secondList) {
        vector<vector<int>> result;
        int i = 0, j = 0;
        
        while (i < firstList.size() && j < secondList.size()) {
            // 求两个区间的交集
            int lo = max(firstList[i][0], secondList[j][0]);
            int hi = min(firstList[i][1], secondList[j][1]);
            
            if (lo <= hi) {
                result.push_back({lo, hi});
            }
            
            // 终点小的区间已经"用完"，不可能再和对方后续区间有交集
            if (firstList[i][1] < secondList[j][1]) {
                i++;
            } else {
                j++;
            }
        }
        
        return result;
    }
};
```

**关键点**：
- 指针移动条件是比较**终点**，不是起点
- `lo <= hi` 包含了单点交集 `[x, x]` 的情况
- 当两个区间终点相等时，移动哪个都行（代码中移动 j），因为两个都"用完"了

### 解法3: 扫描线 — O((m+n)log(m+n)) / O(m+n)

**不同视角**：把所有区间的端点拆成"事件"——起点是 +1（进入区间），终点是 -1（离开区间）。排序后扫描，当计数器 = 2 时说明两个区间重叠。这是处理多个区间列表交集的通用方法。

```cpp
class Solution {
public:
    vector<vector<int>> intervalIntersection(vector<vector<int>>& firstList, 
                                              vector<vector<int>>& secondList) {
        // 每个端点是一个事件: (坐标, 类型)
        // 类型: 0=起点(进入), 1=终点(离开)
        // 排序时: 同坐标先处理起点（保证 [5,5] 这样的单点交集不被遗漏）
        vector<pair<int,int>> events;
        for (auto& a : firstList) {
            events.push_back({a[0], 0}); // 进入
            events.push_back({a[1], 1}); // 离开
        }
        for (auto& b : secondList) {
            events.push_back({b[0], 0});
            events.push_back({b[1], 1});
        }
        
        // 排序: 坐标升序；坐标相同时，起点(0)在终点(1)前面
        sort(events.begin(), events.end());
        
        vector<vector<int>> result;
        int count = 0;
        int start = -1;
        
        for (auto& [pos, type] : events) {
            if (type == 0) { // 进入
                count++;
                if (count == 2) {
                    start = pos; // 两个区间开始重叠
                }
            } else { // 离开
                if (count == 2) {
                    result.push_back({start, pos}); // 重叠结束
                }
                count--;
            }
        }
        
        return result;
    }
};
```

**关键点**：扫描线方法的通用性更强——如果有 K 个区间列表要求交集，双指针需要用优先队列扩展为 K 路归并，而扫描线只需把 `count == 2` 改成 `count == K` 即可。但对于本题两个列表的情况，双指针更简洁高效。

## 解法对比

| | 暴力双循环 | 双指针归并 ⭐ | 扫描线 |
|---|---|---|---|
| 时间 | O(m×n) | O(m+n) | O((m+n)log(m+n)) |
| 空间 | O(1) | O(1) | O(m+n) |
| 利用排序性 | 否 | 是 | 否（自己排序） |
| 可扩展性 | 差 | K路需改造 | 天然支持K路 |
| 面试推荐 | ✗ | ✓ | 追问时提及 |

**面试中首选双指针**：时间最优、空间最优、代码最短、思路最清晰。

## 易错点

1. **✗ 用起点判断指针移动**：
   ```cpp
   // 错误：按起点移动
   if (firstList[i][0] < secondList[j][0]) i++;
   ```
   → **✓ 应该按终点移动**：终点小的区间才是真正"用完"的。反例：`A=[1,10], B=[2,3]`，A 起点更小但 A 还可能和 B 的下一个相交。

2. **✗ 交集判断用 `<` 而非 `<=`**：
   ```cpp
   if (lo < hi)  // 漏掉了单点交集 [5,5]
   ```
   → **✓ 应该用 `lo <= hi`**：闭区间 `[5,5]` 包含一个点，是有效交集。

3. **✗ 忘记处理空列表**：
   双指针解法天然处理了——`while` 条件中有 `i < size && j < size`，空列表时直接不进循环。

4. **✗ 终点相等时两个指针都不动导致死循环**：
   ```cpp
   if (firstList[i][1] < secondList[j][1]) i++;
   else if (firstList[i][1] > secondList[j][1]) j++;
   // 相等时忘了处理！
   ```
   → **✓ 用 `else` 兜底**（移动任意一个即可），或者同时 `i++, j++` 也正确。

## 面试追问

**Q1: 为什么双指针不会漏掉任何交集？**
> 因为每次我们淘汰的是终点更小的区间。该区间已经完全"过去"了，它不可能与对方列表中还没看到的区间（起点更大）有交集。而终点更大的区间被保留，继续与对方的下一个区间比较。这是一个贪心的正确性保证。

**Q2: 如果有 K 个已排序区间列表求交集怎么办？**
> 方法1：双指针扩展为 K 路归并——用最小堆维护 K 个指针，每次取终点最小的区间。O((总区间数) × log K)。
> 方法2：扫描线天然支持，把 `count == 2` 改成 `count == K`。

**Q3: 如果区间列表没有排序呢？**
> 先排序，O(n log n)，然后用同样的双指针。或者直接用扫描线方法（它本身包含排序步骤）。

**Q4: 如果不是求交集，而是求并集（合并两个区间列表）？**
> 这是 LeetCode 56 (Merge Intervals) 的变体。归并两个有序列表后，按照合并区间的方式处理重叠。
