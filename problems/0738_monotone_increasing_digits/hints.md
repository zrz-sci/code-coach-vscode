# 738. 单调递增的数字

## 核心思路

本质上在问：给定一个数 n，找到 ≤ n 的最大整数，使得其每一位数字从左到右**非递减**。关键是找到**第一个"下降"的位置**，然后用贪心策略在该位置前减 1，后面全部填 9。

## 思维链

1. **读完题第一反应**：最暴力的做法是从 n 开始往下逐个检查每个数是否"单调递增"，找到第一个满足的就返回。但 n 最大到 10^9，最坏可能要检查很多数。

2. **暴力解的瓶颈**：对每个候选数，检查是否单调递增是 O(d)（d 为位数），但候选数可能极多。比如 n = 1000000000，答案是 999999999，需要检查 10^9 次——不可接受。

3. **观察关键规律**：如果 n 本身就是单调递增的，直接返回 n。如果不是，从左到右找到**第一个"下降"**的地方（即 `digits[i] > digits[i+1]`），在这个位置需要"退一步"。

4. **贪心核心**：在下降位置把 `digits[i]` 减 1，然后把 i 后面所有位都填 9，这样既保证 ≤ n，又最大化了结果。

5. **连锁退位**：减 1 之后可能导致 `digits[i-1] > digits[i]`，需要继续向前退位。所以要**从右向左扫描**，找到最左边需要减 1 的位置。

6. **最终算法**：把 n 转成字符串，从右向左扫描找最左边的"退位点"，退位后后面全填 9。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 从 n 往下逐个检查 | O(n × d) | O(d) | 能说出即可 |
| 贪心（从右向左扫描） | 找最左退位点，后面填 9 | O(d) | O(d) | ⭐ 必须写出 |

其中 d 为数字的位数，最多 10 位。

## 关键提示

1. **把数字转成字符串/数组**来逐位操作，远比用数学取模方便。

2. **不是只退一次位**：例如 `332`，第一个下降在 `3→2`，把第二个 3 减到 2 后变成 `322`，此时 `3→2` 又下降了！所以需要连锁退位到 `299`。

3. **从右向左扫描**的好处：每次遇到 `s[i] > s[i+1]`，记录 `mark = i`，表示"从 i 后面都要填 9"。继续向左检查是否需要更多退位。扫描完成后一次性操作。

4. 关键不变量：`mark` 始终记录的是**最左边**需要减 1 的位置。

5. 边界：n = 0 时直接返回 0；n 本身单调递增时直接返回 n。

## 解法详解

### 解法1: 暴力枚举 — O(n × d) / O(d)

**思考过程**：最直觉的想法——从 n 开始递减，每次检查当前数是否单调递增，找到就返回。

```cpp
class Solution {
public:
    int monotoneIncreasingDigits(int n) {
        for (int i = n; i >= 0; i--) {
            if (isMonotone(i)) return i;
        }
        return 0;
    }
private:
    bool isMonotone(int num) {
        int prev = 9; // 从个位开始，初始"上一位"设为9
        while (num > 0) {
            int digit = num % 10;
            if (digit > prev) return false; // 高位 > 低位，不单调
            prev = digit;
            num /= 10;
        }
        return true;
    }
};
```

**关键点**：
- 这里从个位往高位检查，所以 `digit > prev` 表示高位大于低位，违反单调递增。
- n = 10^9 时直接超时，无法通过。但这个解法帮我们理解了题意。

### 解法2: 贪心（从右向左扫描） — O(d) / O(d) ⭐ 面试首选

**从解法1优化**：暴力法的瓶颈是"不知道该减到哪里"。贪心法直接定位到需要修改的位置。

**详细推导过程**：

以 `n = 332` 为例：
```
原始数字: 3 3 2
               ↑
          s[1]=3 > s[2]=2，下降了！
          
方案: 把 s[1] 减1 → 2，后面填9 → 3 2 9
但等等! s[0]=3 > s[1]=2，又下降了！

继续退位: 把 s[0] 减1 → 2，后面填9 → 2 9 9 ✓
```

以 `n = 1332` 为例：
```
原始数字: 1 3 3 2
                 ↑
扫描(从右到左):
  i=2: s[2]=3 > s[3]=2 → mark=2
  i=1: s[1]=3 > s[2]=3? 不是(3==3), 但注意 s[2] 将被减1 → 实际比较 s[1]=3 > s[2]=3
  等等，这里有个微妙点...
  
正确做法: 
  i=2: s[2]=3 > s[3]=2 → mark=2, s[2]减1变2
  i=1: s[1]=3 > s[2]=2 → mark=1, s[1]减1变2  
  i=0: s[0]=1 ≤ s[1]=2 → 停止
  
  从 mark=1 后面全填9 → 1 2 9 9 ✓
```

```cpp
class Solution {
public:
    int monotoneIncreasingDigits(int n) {
        string s = to_string(n);
        int mark = s.size(); // mark: 从这里开始全填9，初始为末尾之后（不需要填9）
        
        // 从右向左扫描，寻找最左边的退位点
        for (int i = s.size() - 2; i >= 0; i--) {
            if (s[i] > s[i + 1]) {
                // s[i] 比右边大，违反单调递增
                // 贪心策略：s[i] 减 1，后面全填 9
                s[i]--;         // 当前位减 1
                mark = i + 1;   // 记录从 i+1 开始要填 9
            }
        }
        
        // 从 mark 位置开始，后面全部填 9
        for (int i = mark; i < s.size(); i++) {
            s[i] = '9';
        }
        
        return stoi(s);
    }
};
```

**为什么从右向左扫描？**
- 如果从左向右，当 `s[i]` 减 1 后可能导致 `s[i-1] > s[i]`，需要回头处理。
- 从右向左扫描，每次遇到违规就退位，`mark` 自然记录了最左的退位点，不需要回头。

**为什么这个贪心是正确的？**
- 退位后 `s[mark-1]` 变小了，`mark` 后面全是 9，这是在"不超过 n"前提下能取到的最大值。
- 越靠左的位权越大，所以只在必要时才退左边的位，尽量保持高位不变。

## 解法对比

| | 暴力枚举 | 贪心扫描 |
|---|---|---|
| 时间 | O(n × d)，最坏 10^10 | O(d)，最多 10 次 |
| 空间 | O(d) | O(d) |
| 核心操作 | 逐个试 | 精确定位退位点 |
| 面试可用 | ✗ 超时 | ✓ 首选 |

## 易错点

1. **mark 初始值设错**：
   - ✗ `int mark = s.size() - 1;` → 即使 n 本身单调递增，也会把最后一位填成 9
   - ✓ `int mark = s.size();` → 初始表示"不需要填 9"，只在发现违规时更新

2. **忘记连锁退位**：
   - ✗ 只找第一个下降位置就停止，`332` 会得到 `329` 而不是 `299`
   - ✓ 从右向左完整扫描，每次退位都更新 mark

3. **比较方向搞反**：
   - ✗ `if (s[i] < s[i+1])` → 这是递增，不需要处理
   - ✓ `if (s[i] > s[i+1])` → 这才是违反单调递增

4. **循环范围错误**：
   - ✗ `for (int i = s.size() - 1; i >= 0; i--)` → 会访问 `s[i+1]` 越界
   - ✓ `for (int i = s.size() - 2; i >= 0; i--)` → 从倒数第二位开始

## 面试追问

**Q1: 暴力怎么做？为什么不行？**
从 n 往下逐个检查，时间复杂度 O(n×d)，n 到 10^9 时超时。但说明你理解了题意。

**Q2: 贪心策略的正确性怎么论证？**
核心论证：当 `s[i] > s[i+1]` 时，要保证结果 ≤ n，`s[i]` 必须减小（至少减 1）。减 1 后，从 `i+1` 往后放最大数字 9 来最大化结果。从右向左扫描保证了所有需要退位的地方都被处理，且 mark 记录了最左退位点。

**Q3: 如果要求"严格递增"（每一位都大于前一位）呢？**
把 `s[i] > s[i+1]` 改为 `s[i] >= s[i+1]`。但填 9 不再正确——严格递增的最大尾巴不是全 9，而是 `...6789` 这样的递增序列。需要从 mark 位置开始，倒着填 `9, 8, 7, ...`，如果不够填就继续退位。

**Q4: 时间/空间能进一步优化吗？**
时间已经是 O(d) 了，不能更优。空间上可以不转字符串，直接用数学取位和拼位操作，但代码会复杂很多，字符串做法更清晰。
