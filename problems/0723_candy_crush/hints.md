# 723. 粉碎糖果 (Candy Crush)

## 核心思路

这道题本质上是一个**模拟题**：反复执行「标记→粉碎→下落」三步操作，直到棋盘稳定。没有复杂的算法，关键在于正确实现每一步的细节，尤其是**同时标记所有需要粉碎的糖果**（不能边粉碎边检测）和**重力下落**的模拟。

## 思维链

1. **读完题第一反应**：这就是一个循环模拟 — 每轮先找出所有要消除的糖果，消除后让剩余糖果下落，重复直到没有可消除的。
2. **怎么找需要粉碎的糖果？** 扫描每一行和每一列，找到**连续3个及以上相同**的区间，标记它们。关键：必须先**全部标记**再统一粉碎，因为同一个格子可能同时参与水平和垂直的消除。
3. **怎么标记？** 可以用额外的布尔矩阵，也可以直接**取负值**标记（因为值都是正整数，取负表示"待粉碎"，比较时用绝对值）。取负值的技巧省去了额外空间。
4. **怎么模拟下落？** 每一列独立处理。从下往上扫描，用一个写指针指向当前列的底部空位，把非零元素依次"落"到写指针位置，剩余位置填0。这就是**双指针（压缩）**的思路。
5. **什么时候终止？** 如果某一轮扫描后没有任何格子被标记，说明已稳定，返回结果。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 模拟（额外标记矩阵） | 用 bool 矩阵标记，粉碎后双指针下落 | O(m·n·(m+n)·T) | O(m·n) | 能说出即可 |
| 模拟（取负值标记）⭐ | 用负值原地标记，省去额外空间 | O(m·n·(m+n)·T) | O(1) | ⭐ 必须写出 |

> T = 循环轮次，最坏情况下 T = O(m·n)，但实际中很小。每轮扫描 O(m·n·(m+n)) 可简化理解为每轮 O(m·n)。

## 关键提示

1. **同时粉碎**：不能发现一组就立刻清零。如果一个糖果同时参与水平和垂直消除，必须在同一轮都检测到后才清零。
2. **取负值标记技巧**：`board[i][j]` 取负表示"待粉碎"，扫描时用 `abs(board[i][j])` 比较，这样已标记的格子不影响后续比较。
3. **下落 = 每列独立压缩**：想象每一列是一个独立的一维数组，把所有非零元素"沉"到底部，上面补零。
4. **循环终止条件**：设一个 `found` 标志，某轮扫描后 `found == false` 就退出。

## 解法详解

### 解法1: 模拟（额外标记矩阵）— O(m·n·T) / O(m·n)

**思考过程**: 最直觉的做法——用一个和 board 同样大小的 `bool crush[][]` 矩阵来记录哪些位置需要粉碎。

```cpp
class Solution {
public:
    vector<vector<int>> candyCrush(vector<vector<int>>& board) {
        int m = board.size(), n = board[0].size();
        
        while (true) {
            // 标记矩阵
            vector<vector<bool>> crush(m, vector<bool>(n, false));
            bool found = false;
            
            // 检查水平方向：每行找连续>=3个相同的
            for (int i = 0; i < m; i++) {
                for (int j = 0; j + 2 < n; j++) {
                    int v = board[i][j];
                    if (v != 0 && v == board[i][j+1] && v == board[i][j+2]) {
                        crush[i][j] = crush[i][j+1] = crush[i][j+2] = true;
                        found = true;
                    }
                }
            }
            
            // 检查垂直方向：每列找连续>=3个相同的
            for (int j = 0; j < n; j++) {
                for (int i = 0; i + 2 < m; i++) {
                    int v = board[i][j];
                    if (v != 0 && v == board[i+1][j] && v == board[i+2][j]) {
                        crush[i][j] = crush[i+1][j] = crush[i+2][j] = true;
                        found = true;
                    }
                }
            }
            
            if (!found) break; // 稳定了，退出
            
            // 粉碎：将标记位置清零
            for (int i = 0; i < m; i++)
                for (int j = 0; j < n; j++)
                    if (crush[i][j]) board[i][j] = 0;
            
            // 下落：每列独立处理，双指针压缩
            for (int j = 0; j < n; j++) {
                int write = m - 1; // 写指针从底部开始
                for (int read = m - 1; read >= 0; read--) {
                    if (board[read][j] != 0) {
                        board[write][j] = board[read][j];
                        write--;
                    }
                }
                // 上方填零
                while (write >= 0) {
                    board[write][j] = 0;
                    write--;
                }
            }
        }
        
        return board;
    }
};
```

**关键点**: 这个解法最清晰易懂，缺点是每轮都要创建 O(m·n) 的标记矩阵。

---

### 解法2: 模拟（取负值原地标记）— O(m·n·T) / O(1) ⭐ 面试首选

**从解法1优化**: 解法1的额外空间来自标记矩阵。观察到 `board[i][j]` 都是正整数，我们可以**用负值表示"待粉碎"**，比较时取绝对值。这样不需要额外空间。

```cpp
class Solution {
public:
    vector<vector<int>> candyCrush(vector<vector<int>>& board) {
        int m = board.size(), n = board[0].size();
        
        while (true) {
            bool found = false;
            
            // === 第一步：标记 ===
            // 水平方向：连续3个及以上相同 → 取负
            for (int i = 0; i < m; i++) {
                for (int j = 0; j + 2 < n; j++) {
                    int v = abs(board[i][j]);
                    if (v != 0 && v == abs(board[i][j+1]) && v == abs(board[i][j+2])) {
                        // 取负标记，已经是负的就不管
                        board[i][j] = -v;
                        board[i][j+1] = -v;
                        board[i][j+2] = -v;
                        found = true;
                    }
                }
            }
            
            // 垂直方向：连续3个及以上相同 → 取负
            for (int j = 0; j < n; j++) {
                for (int i = 0; i + 2 < m; i++) {
                    int v = abs(board[i][j]);
                    if (v != 0 && v == abs(board[i+1][j]) && v == abs(board[i+2][j])) {
                        board[i][j] = -v;
                        board[i+1][j] = -v;
                        board[i+2][j] = -v;
                        found = true;
                    }
                }
            }
            
            if (!found) break;
            
            // === 第二步：粉碎（负值清零）+ 下落 ===
            for (int j = 0; j < n; j++) {
                int write = m - 1; // 写指针从底部开始
                // 从底向上扫描，把正值（存活的糖果）沉到底部
                for (int read = m - 1; read >= 0; read--) {
                    if (board[read][j] > 0) {
                        board[write][j] = board[read][j];
                        write--;
                    }
                }
                // 上方全部填零
                while (write >= 0) {
                    board[write][j] = 0;
                    write--;
                }
            }
        }
        
        return board;
    }
};
```

**关键点**:
- 取负值后，`abs()` 保证后续扫描能正确比较同一轮中已标记的格子
- 下落时判断 `> 0`（正值才是存活糖果），负值和零都跳过
- 粉碎和下落可以合并在一步完成（下落时自然忽略负值）

## 解法对比

| | 解法1 (额外标记) | 解法2 (取负值) |
|---|---|---|
| 额外空间 | O(m·n) 的 bool 矩阵 | O(1)，原地标记 |
| 代码清晰度 | 更直观，标记和比较分离 | 稍需理解"取负"技巧 |
| 面试推荐 | 思路清晰，可先说这个 | 优化版，面试官期望最终写出 |

两种解法时间复杂度相同。面试中建议先口头说解法1思路，直接写解法2代码。

## 易错点

1. **✗ 扫描时不取绝对值**:
   ```cpp
   // 错误：已标记为负的格子无法正确比较
   if (v != 0 && v == board[i][j+1] && v == board[i][j+2])
   ```
   **✓ 正确**:
   ```cpp
   if (v != 0 && v == abs(board[i][j+1]) && v == abs(board[i][j+2]))
   ```
   **原因**: 同一轮中，某个格子可能先被水平标记为负，但它也参与垂直消除。如果不取绝对值，垂直扫描时会比较失败。

2. **✗ 只检查恰好3个连续，漏掉4个及以上**:
   ```cpp
   // 错误：只检查 j, j+1, j+2 三个位置完全匹配
   // 如果有 5,5,5,5 四连，只标记了前三个
   ```
   **✓ 正确**: 上面的代码没有这个问题！因为窗口 `[j, j+1, j+2]` 滑动时会覆盖所有情况：`j=0` 标记前三个，`j=1` 标记第2~4个，全部都会被标记。

3. **✗ 下落时 write 和 read 方向搞反**:
   ```cpp
   // 错误：从上往下扫描，写指针从顶部开始 → 糖果"飞"上去了
   for (int read = 0; read < m; read++)
   ```
   **✓ 正确**: 必须从**底部**往上扫描，写指针从**底部**开始，模拟重力下落。

4. **✗ 边粉碎边检测**: 如果发现三连就立刻清零，会影响同一轮后续的检测（某个格子被清零后，原本参与的另一组三连就检测不到了）。必须先全部标记，再统一粉碎。

## 面试追问

**Q1: 为什么不能发现一组就立刻粉碎？**
> 因为一个糖果可能同时参与水平和垂直两组消除（如 T 形、L 形交叉点）。如果立刻粉碎第一组，第二组就检测不到了。必须先全部标记，再统一粉碎。

**Q2: 取负值标记有什么前提条件？如果值本身可以是负数怎么办？**
> 前提是原始值都是正整数（题目保证 `1 <= board[i][j] <= 2000`）。如果值可以是负数，就只能用额外的标记矩阵（解法1）。面试中先确认值域再选方案。

**Q3: 下落部分的双指针本质上是什么操作？**
> 本质就是 LeetCode 27 "移除元素" 的变体——在每一列上把所有零元素"移除"，非零元素保持相对顺序沉到底部。用读写双指针，从底部开始，读指针扫描非零值，写指针写入。

**Q4: 时间复杂度怎么分析？最坏情况循环多少轮？**
> 每轮至少粉碎3个糖果，总共最多 m·n 个糖果，所以最多循环 O(m·n/3) ≈ O(m·n) 轮。每轮扫描 O(m·n)，所以最坏总时间 O((m·n)²)。但实际中轮数很少。
