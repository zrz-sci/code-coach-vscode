# 21. 合并两个有序链表

## 核心思路

本质就是**归并排序的 merge 步骤**：两个已排好序的序列，用双指针逐一比较、取较小的接到结果链表后面。

## 思维链

1. **读完题第一反应**：两个有序链表要合并成一个有序链表，最直觉的做法就是每次从两个链表头部选一个较小的节点，接到结果链表后面。
2. **具体怎么选？** 两个指针分别指向两个链表当前位置，比较值大小，取小的那个接上去，然后该指针往后走一步。
3. **什么时候结束？** 其中一个链表走完了，另一个直接接到后面（因为剩余部分本身就是有序的）。
4. **实现上的问题**：结果链表的"头节点"还不确定（取决于第一次比较），怎么处理？→ 用 **dummy 虚拟头节点**，最后返回 `dummy.next`。
5. **还有别的做法吗？** 递归！合并两个有序链表本身就有递归结构：取较小的头节点，然后递归合并"剩余部分"和另一个链表。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 迭代 (dummy + 双指针) | 逐一比较，取较小的接上 | O(m+n) | O(1) | ⭐ 必须写出 |
| 递归 | 取较小头，递归合并剩余 | O(m+n) | O(m+n) 栈空间 | 加分项 |

## 关键提示

- **提示1**：如果不确定头节点是谁，用 dummy 节点可以统一处理，避免大量 if-else。
- **提示2**：循环结束后，两个链表中最多只有一个还有剩余，直接接上即可，不需要再逐个处理。
- **提示3**：递归写法只需 5 行。想一想：`mergeTwoLists(l1, l2)` 的含义是"返回合并后链表的头"，那 base case 是什么？递归怎么缩小问题规模？
- **提示4（ASCII 示意图）**：

```
  l1: 1 → 2 → 4
  l2: 1 → 3 → 4

  dummy → ?

  Step1: 比较 1 vs 1，取 l1 的 1 → dummy → 1
  Step2: 比较 2 vs 1，取 l2 的 1 → dummy → 1 → 1
  Step3: 比较 2 vs 3，取 l1 的 2 → dummy → 1 → 1 → 2
  Step4: 比较 4 vs 3，取 l2 的 3 → dummy → 1 → 1 → 2 → 3
  Step5: 比较 4 vs 4，取 l1 的 4 → dummy → 1 → 1 → 2 → 3 → 4
  Step6: l1 用完，接上 l2 剩余  → dummy → 1 → 1 → 2 → 3 → 4 → 4
  
  返回 dummy.next = 1 → 1 → 2 → 3 → 4 → 4
```

## 解法详解

### 解法1: 迭代 (Dummy + 双指针) — O(m+n) / O(1) ⭐ 面试首选

**思考过程**：这就是"合并两个有序数组"的链表版本。用两个指针分别遍历，每次取较小的接到结果链表末尾。关键技巧是使用 dummy 头节点，避免处理"第一个节点"的特殊情况。

```cpp
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* list1, ListNode* list2) {
        // dummy 节点：避免讨论头节点是谁的麻烦
        ListNode dummy(0);
        ListNode* tail = &dummy; // tail 始终指向结果链表的末尾
        
        // 两个链表都还有节点时，逐一比较
        while (list1 && list2) {
            if (list1->val <= list2->val) {
                tail->next = list1;     // 取 list1 的当前节点
                list1 = list1->next;    // list1 指针前进
            } else {
                tail->next = list2;     // 取 list2 的当前节点
                list2 = list2->next;    // list2 指针前进
            }
            tail = tail->next;          // 结果链表尾指针前进
        }
        
        // 其中一个链表用完了，另一个直接接上
        // 为什么不用逐个接？因为剩余部分本身有序且都比已合并部分大
        tail->next = list1 ? list1 : list2;
        
        return dummy.next;
    }
};
```

**关键点**：
- `tail` 指针必须每次更新，否则永远接在同一个位置。
- 循环结束后 `tail->next = list1 ? list1 : list2` 一行搞定剩余，不需要再循环。

---

### 解法2: 递归 — O(m+n) / O(m+n)

**思考过程**：合并两个有序链表具有天然的递归结构。`mergeTwoLists(l1, l2)` 的含义是"返回 l1 和 l2 合并后的有序链表头节点"。那么：
- **Base case**：如果 l1 为空，返回 l2；如果 l2 为空，返回 l1。
- **递归**：比较 l1 和 l2 的头节点，取较小的那个作为合并链表的头，它的 next 指向"剩余部分的合并结果"。

```
  递归展开示意 (l1=[1,2,4], l2=[1,3,4]):

  merge([1,2,4], [1,3,4])
    1->val <= 1->val, 取 l1 的 1
    1.next = merge([2,4], [1,3,4])
               1->val < 2->val, 取 l2 的 1
               1.next = merge([2,4], [3,4])
                          2->val < 3->val, 取 l1 的 2
                          2.next = merge([4], [3,4])
                                     3->val < 4->val, 取 l2 的 3
                                     3.next = merge([4], [4])
                                                4->val <= 4->val, 取 l1 的 4
                                                4.next = merge([], [4])
                                                           l1 空 → 返回 [4]
                                                返回 4→4
                                     返回 3→4→4
                          返回 2→3→4→4
               返回 1→2→3→4→4
    返回 1→1→2→3→4→4
```

```cpp
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* list1, ListNode* list2) {
        // Base case: 一方为空，直接返回另一方
        if (!list1) return list2;
        if (!list2) return list1;
        
        // 取较小的作为头，递归处理剩余
        if (list1->val <= list2->val) {
            list1->next = mergeTwoLists(list1->next, list2);
            return list1;
        } else {
            list2->next = mergeTwoLists(list1, list2->next);
            return list2;
        }
    }
};
```

**关键点**：
- 递归深度最大为 m+n（最坏情况两个链表交替取），所以栈空间 O(m+n)。
- 递归版代码极其简洁，但面试中要能说清楚空间复杂度不是 O(1)。

## 解法对比

| | 迭代 (Dummy + 双指针) | 递归 |
|---|---|---|
| 时间 | O(m+n) | O(m+n) |
| 空间 | O(1) 只用了几个指针 | O(m+n) 递归栈 |
| 代码量 | ~15 行 | ~8 行 |
| 直觉性 | 像归并排序的 merge 步骤 | 像数学归纳法 |
| 面试推荐 | ⭐ 首选：空间 O(1)，逻辑清晰 | 加分项：能展示递归思维 |

**什么时候选哪个？**
- 面试默认写迭代版，空间 O(1) 更优，且不会栈溢出。
- 面试官追问"能否递归实现？"时给出递归版，展示你对两种范式都熟悉。

## 易错点

1. **忘记更新 tail 指针**
   - ✗ `tail->next = list1; list1 = list1->next;`（漏了 `tail = tail->next`）
   - ✓ `tail->next = list1; list1 = list1->next; tail = tail->next;`
   - 后果：所有节点都接在 dummy 后面的同一个位置，最终只保留最后一个节点。

2. **dummy 用指针 new 出来但忘记释放（或用栈上变量更安全）**
   - ✗ `ListNode* dummy = new ListNode(0); ... return dummy->next;`（内存泄漏）
   - ✓ `ListNode dummy(0); ... return dummy.next;`（栈上分配，自动释放）

3. **递归版把两个分支的逻辑写反**
   - ✗ `list1->next = mergeTwoLists(list1, list2->next);`（应该是 `list1->next`，传 `list1->next` 而不是 `list1`）
   - ✓ `list1->next = mergeTwoLists(list1->next, list2);`
   - 后果：死递归，栈溢出。

4. **循环条件写成 `||` 而不是 `&&`**
   - ✗ `while (list1 || list2)` 然后循环内没有 null 检查 → 空指针崩溃
   - ✓ `while (list1 && list2)` 循环外处理剩余

## 面试追问

**Q1（基础理解）**：为什么需要 dummy 节点？不用行不行？
> 不用 dummy 也行，但需要额外判断结果链表是否为空（第一次接节点时要特殊处理头节点），代码更繁琐。dummy 统一了"第一次操作"和"后续操作"的逻辑。

**Q2（空间复杂度）**：递归解法的空间复杂度是多少？能否优化？
> 递归栈深度 O(m+n)，不能优化（因为每次递归只减少一个节点）。如果要 O(1) 空间就必须用迭代。

**Q3（变体/进阶）**：如果是 K 个有序链表合并呢？（LeetCode 23）
> 方法一：两两合并，像归并排序一样分治，O(N log K)。方法二：用最小堆维护 K 个链表头，每次取最小的，O(N log K)。本题的双链表合并是 K 路合并的基础子操作。

**Q4（追问细节）**：这道题是原地修改节点的 next 指针，还是创建新节点？
> 原地修改。我们并没有 new 新节点，只是改变了已有节点之间的连接关系。这也是为什么空间是 O(1)（迭代版）。
