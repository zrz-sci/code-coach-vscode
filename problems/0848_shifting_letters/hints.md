# 848. Shifting Letters - 提示与解析

## 核心思路

给定字符串 `s` 和移位数组 `shifts`，其中 `shifts[i]` 表示将 s 的前 i+1 个字符各右移 shifts[i] 位。直接模拟会导致 O(n^2) 的时间复杂度。关键优化是使用后缀和：第 i 个字符的总移位量 = shifts[i] + shifts[i+1] + ... + shifts[n-1]，即 shifts 数组从 i 到末尾的后缀和。从后往前累加即可在 O(n) 时间内计算所有移位量。

## 思维链

1. **理解操作**：shifts[i] = x 表示把 s[0..i] 这 i+1 个字符各右移 x 位。
2. **分析累积效果**：s[0] 被所有 shifts[0..n-1] 影响，s[1] 被 shifts[1..n-1] 影响，...，s[n-1] 只被 shifts[n-1] 影响。
3. **后缀和转化**：第 i 个字符的总移位量 = sum(shifts[i..n-1])。
4. **从后往前计算**：维护一个累加变量 total，从 n-1 到 0 遍历，每步 total += shifts[i]。
5. **取模处理**：由于字母是循环的（26 个），每个移位量对 26 取模。注意 shifts[i] 可达 10^9，累加可能溢出 int，需用 long long。

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 推荐度 | 特点 |
|------|-----------|-----------|--------|------|
| 后缀和（从后往前） | O(n) | O(1) | ⭐⭐⭐⭐⭐ | 最优解，原地修改 |
| 前缀和数组 | O(n) | O(n) | ⭐⭐⭐⭐ | 先构建后缀和数组再遍历 |
| 暴力模拟 | O(n^2) | O(1) | ⭐⭐ | 直接模拟每次移位，超时 |

## 关键提示

1. **后缀和而非前缀和**：第 i 个字符的总移位量是 shifts 从 i 到末尾的和，这是后缀和。
2. **从后往前遍历**：从最后一个字符开始，维护累计移位量，每次加上 shifts[i]。这样不需要额外数组。
3. **取模防溢出**：shifts[i] 最大 10^9，n 最大 10^5，总和可达 10^14，超出 int 范围。使用 long long 并适时取模 26。
4. **字符循环移位公式**：`new_char = 'a' + (s[i] - 'a' + shift_amount) % 26`。
5. **shift_amount 必须非负**：由于 shifts[i] >= 0 且我们只做加法，不会出现负数情况。

## 解法详解

### 解法一：后缀和从后往前（推荐）

**思路**：
从字符串末尾开始，维护一个变量 `total` 记录当前累积的移位量。对于位置 i，先将 shifts[i] 加入 total，然后将 s[i] 右移 total % 26 位。

**关键步骤**：
- 初始化 total = 0
- 从 i = n-1 到 0：
  - total += shifts[i]
  - s[i] = 'a' + (s[i] - 'a' + total % 26) % 26
- 返回修改后的 s

**复杂度分析**：
- 时间：O(n)，一次遍历
- 空间：O(1)，原地修改

### 解法二：构建后缀和数组

**思路**：
先将 shifts 数组转化为后缀和数组（从后往前累加），然后遍历字符串，按后缀和数组对每个字符进行移位。

**复杂度分析**：
- 时间：O(n)
- 空间：O(n)，后缀和数组（也可用原 shifts 数组原地修改为 O(1)）

### 解法三：暴力模拟

**思路**：
按题意直接模拟：对每个 shifts[i]，将 s[0..i] 各右移 shifts[i] 位。

**复杂度分析**：
- 时间：O(n^2)，n 最大 10^5，会超时
- 空间：O(1)

## 易错点

1. **整数溢出**：shifts[i] 最大 10^9，累加后可能超过 int 范围。必须使用 long long。
2. **忘记取模 26**：累加后的移位量可能非常大，但字母是 26 个循环的，必须取模。
3. **取模时机错误**：在累加过程中应该 total = (total + shifts[i]) % 26，而不是最后一次性取模（虽然结果一样，但中间不取模可能溢出 long long 也未必，但取模更安全）。
4. **字符运算错误**：`(s[i] - 'a' + shift) % 26 + 'a'` 中，如果 shift 为负数会出错（本题不会但要注意）。
5. **方向搞反**：从前往后累加是前缀和，得到的是错误的移位量。应该从后往前。

## 面试追问

1. **Q: 如果 shifts 中有负数（左移）怎么办？**
   A: 需要处理负数取模：`((s[i] - 'a' + shift) % 26 + 26) % 26 + 'a'`。

2. **Q: 如果要支持在线查询（每次给一个 shifts[i] 就立刻返回当前字符串）？**
   A: 维护一个全局偏移量数组或差分数组。每次查询时用后缀和计算当前偏移。

3. **Q: 为什么不用前缀和？**
   A: 也可以。先计算 total = sum(shifts)，然后从前往后，每处理一个字符后 total -= shifts[i]。效果等价。

4. **Q: 如果字符集不是 26 个小写字母而是 Unicode 呢？**
   A: 将 26 替换为字符集大小。逻辑完全相同。

5. **Q: LeetCode 848 II（Shifting Letters II）有什么不同？**
   A: 848 II 允许区间移位（每个操作可以是 [l, r, direction]），需要用差分数组而非简单的后缀和。
