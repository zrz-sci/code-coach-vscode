# 640. Solve the Equation

## 核心思路

**字符串解析 + 一元一次方程求解**。将等号两侧的表达式分别解析为 `coeff * x + constant` 的形式，然后移项合并：将所有 x 项移到左边，常数项移到右边，最后判断是否有唯一解、无解或无穷解。

## 思维链

1. **拆分等式**：按 `'='` 分成左右两个表达式
2. **解析表达式**：提取每个表达式中的 x 系数总和与常数总和
3. **解析策略**：按 `+` 和 `-` 分割出各项（token），每项要么是 `ax` 形式，要么是纯数字
4. **合并方程**：`leftCoeff * x + leftConst = rightCoeff * x + rightConst`
   - 移项：`(leftCoeff - rightCoeff) * x = rightConst - leftConst`
5. **判断结果**：
   - 系数 != 0：唯一解 `x = (rightConst - leftConst) / (leftCoeff - rightCoeff)`
   - 系数 == 0 且常数 == 0：无穷解
   - 系数 == 0 且常数 != 0：无解

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 推荐度 |
|------|-----------|-----------|--------|
| 统一解析（逐字符，过等号翻转） | O(n) | O(1) | ⭐⭐⭐⭐⭐ |
| 左右分别解析 | O(n) | O(1) | ⭐⭐⭐⭐ |
| 正则表达式分割 | O(n) | O(n) | ⭐⭐⭐ |

## 关键提示

1. **系数为 1 的情况**：`x` 前面没有数字时系数为 1（不是 0），`-x` 系数为 -1
2. **符号处理**：`+` 和 `-` 既是分隔符又是符号，需要保留符号信息
3. **纯 `x` 和 `0x` 的区别**：`"x"` 的系数是 1，`"0x"` 的系数是 0
4. **整数除法**：题目保证唯一解时 x 是整数，所以不需要考虑浮点
5. **空系数**：当 token 是 `"+x"` 或 `"-x"` 或 `"x"` 时，系数分别为 1、-1、1

## 解法详解

### 解法一：统一解析（推荐）

**思路**：遍历整个等式字符串，遇到 `'='` 后将后续所有项的符号翻转（乘以 -1），等价于移项。最终得到 `totalCoeff * x + totalConst = 0`，即 `x = -totalConst / totalCoeff`。

**解析算法**：
1. 维护 `side`（左侧 +1，右侧 -1）和当前项符号 `sign`
2. 维护当前数字 `num` 和是否读到数字的标志 `hasNum`
3. 遇到 `'x'`：将 `sign * side * num` 加到 coeff（若未读到数字则 num=1）
4. 遇到 `'+'/'-'/'='`：将 `sign * side * num` 加到 constant，重置状态
5. 末尾处理：循环结束后加一个虚拟 `+` 触发最后一项的处理

**示例**：
```
parse("x+5-3+x=6+x-2"):
  x(+1) -> coeff += 1
  5(+1) -> const += 5
  3(-1) -> const -= 3
  x(+1) -> coeff += 1
  = (side翻转为-1)
  6(+1*-1) -> const -= 6
  x(+1*-1) -> coeff -= 1
  2(-1*-1) -> const += 2
  
  coeff=1, const=-2 -> x = -(-2)/1 = 2
```

### 解法二：左右分别解析

**思路**：
1. 按 `'='` 分割成左右两个字符串
2. 编写 `parse(expr)` 函数，返回 `{coeff, constant}` 对
3. 合并：`(lCoeff - rCoeff) * x = rConst - lConst`

### 解法三：正则 + token 解析

**思路**：用正则或手动在每个 `+/-` 前插入分隔符，分割出各 token，逐个判断是 x 项还是常数项。C++ 中 regex 性能较差，不推荐用于面试。

## 易错点

1. **`"x"` 的系数是 1 不是 0**：这是最常见的 bug，`"x"` 等价于 `"1x"`
2. **`"-x"` 的系数是 -1**：不能简单地把 `-` 后面的空字符串转为 0
3. **`"0x"` 的系数是 0**：与 `"x"` 不同，`"0x"` 的系数确实是 0（hasNum=true, num=0）
4. **连续符号**：输入保证不会出现 `"+-"` 或 `"--"`，但 `"="` 后面可以紧跟 `-`
5. **大数处理**：系数和常数范围 [0, 100]，中间计算不会溢出 int
6. **输出格式**：必须是 `"x=#value"`，不是 `"x = #value"`（无空格）
7. **遍历结束后忘记处理最后一个 token**：逐字符扫描时，循环结束后还有一个未处理的数字需要加入

## 面试追问

**Q1: 如果方程中有乘法和除法，如何扩展？**

这就变成了一般的数学表达式求解问题：
- **语法解析**：需要处理运算符优先级（+ - 低于 * /）
- **数据结构**：构建表达式树或使用逆波兰表达式
- **求解**：对于一元一次方程，所有操作最终还是 coeff*x + const 形式（前提是 x 不出现在除数中）
- 如果 x 出现在除数或乘法的两侧（如 `x*x`），就变成高次方程，不能用简单移项求解

**Q2: 如果方程有多个变量（如 x 和 y），怎么处理？**

- 单个方程有两个未知数，一般有无穷多解
- 需要两个独立方程组成方程组
- 可以用**高斯消元法**求解：将方程组化为行最简阶梯形
- 数据结构：用 `{coeff_x, coeff_y, constant}` 表示每个方程

**Q3: 字符串解析有哪些常见的工程化做法？**

- **有限状态机 (FSM)**：定义状态（读数字、读符号、读变量），按字符转移
- **词法分析 + 语法分析**：先 tokenize（拆分成 NUMBER、VARIABLE、OPERATOR），再 parse
- **正则表达式**：用 regex 提取所有 token，如 `([+-]?\d*x?|[+-]?\d+)`
- 面试中推荐 FSM 或逐字符扫描，代码量适中且展示编码能力
