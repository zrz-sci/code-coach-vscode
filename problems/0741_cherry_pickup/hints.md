# 741. Cherry Pickup - 摘樱桃

## 难度: Hard

## 标签: Array, Dynamic Programming, Matrix

## 核心思路

本题的核心在于**问题转化**：不要把问题看作"去一趟再回来"（贪心两趟是错误的），而是等价转化为**两个人同时从 (0,0) 出发走到 (n-1,n-1)**。每人每步只能向右或向下，若两人经过同一个格子则樱桃只算一次。利用两人走的步数相同（`r1+c1 = r2+c2 = t`）来压缩状态为 `dp[t][r1][r2]`，实现 O(n^3) 的动态规划。

## 思维链

1. **直觉陷阱**: 先贪心走一趟取最多，再走第二趟取剩余 -> 错误！第一趟可能"堵住"第二趟的最优路径
2. **等价转化**: "去一趟 + 回一趟" 等价于 "两个人同时从 (0,0) 走到 (n-1,n-1)"
3. **同步步数**: 两个人同时走，第 t 步两人分别在 (r1, t-r1) 和 (r2, t-r2)
4. **状态压缩**: 因为 c = t - r，所以只需 `dp[t][r1][r2]` 三维即可，c1 和 c2 由 t 和 r 推导
5. **转移来源**: 每人前一步来自上方（r不变）或左方（r-1），共 2x2 = 4 种组合
6. **重复计数**: 若 r1 == r2（同一格子），樱桃只加一次
7. **不可达处理**: 荆棘格子（值为-1）对应 dp 值设为负无穷

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 3D DP (t, r1, r2) | O(n^3) | O(n^3) | 最清晰的标准写法 |
| 2D 滚动数组优化 | O(n^3) | O(n^2) | 空间优化，只保留前一步的状态 |
| 记忆化搜索 | O(n^3) | O(n^3) | 自顶向下，代码更直观 |

## 关键提示

1. **为什么贪心两趟不行**: 考虑一个 W 形的樱桃分布，贪心第一趟走中间会导致第二趟无法取到两侧樱桃
2. **t 的范围**: t 从 0 到 2*(n-1)，共 2n-1 步
3. **r 的范围**: 在第 t 步，r 的有效范围是 `[max(0, t-(n-1)), min(t, n-1)]`
4. **INT_MIN 作标志**: 用 INT_MIN 表示不可达状态，注意加法前检查避免溢出
5. **最终答案**: `max(0, dp[2*(n-1)][n-1][n-1])`，取 max(0,...) 是因为可能完全不可达

## 解法详解

### 解法一：三维 DP（推荐）

**状态定义**: `dp[t][r1][r2]` = 两个人分别走了 t 步，第一人在第 r1 行、第二人在第 r2 行时，能收集的最大樱桃数。

**转移方程**:
```
cherries = grid[r1][c1] + (r1 != r2 ? grid[r2][c2] : 0)
dp[t][r1][r2] = max(
    dp[t-1][r1][r2],       // 两人都从上方来
    dp[t-1][r1-1][r2],     // 人1从左方，人2从上方
    dp[t-1][r1][r2-1],     // 人1从上方，人2从左方
    dp[t-1][r1-1][r2-1]    // 两人都从左方来
) + cherries
```

**初始化**: `dp[0][0][0] = grid[0][0]`，其余为 INT_MIN

**时间复杂度**: O(n^3) - 三层循环 t, r1, r2

**空间复杂度**: O(n^3)

### 解法二：滚动数组空间优化

**思路**: 因为 dp[t] 只依赖 dp[t-1]，所以可以用两个 2D 数组交替使用。

**注意事项**: r1 和 r2 需要从大到小遍历（或使用两个数组），避免覆盖还需要的旧值。

**时间复杂度**: O(n^3)

**空间复杂度**: O(n^2)

### 解法三：记忆化搜索

**思路**: 定义 `dfs(r1, c1, r2)` 表示从当前状态走到终点能收集的最大樱桃数。c2 由 r1+c1-r2 推导。

**优势**: 自顶向下更直观，不需要考虑遍历顺序

**时间复杂度**: O(n^3)

**空间复杂度**: O(n^3)

## 易错点

1. **贪心错误**: 这是最常见的错误思路。先走一趟取最多再走一趟，结果可能不是全局最优
2. **忘记同格子去重**: 当 r1 == r2（即 c1 == c2）时，两人在同一格子，樱桃只能算一次
3. **INT_MIN 溢出**: 做 `INT_MIN + cherries` 会溢出，必须在加法前先检查前驱状态是否为 INT_MIN
4. **r 的范围计算错误**: 第 t 步 r 的有效范围是 `[max(0, t-n+1), min(t, n-1)]`，写成 `[0, t]` 会越界
5. **荆棘处理**: 遇到 grid 值为 -1 时要设 dp 为 INT_MIN 而非 -1，否则会被误判为有效路径
6. **最终取 max(0, ...)**: 如果 dp[2n-2][n-1][n-1] 仍为 INT_MIN，说明不存在有效路径，应返回 0

## 面试追问

1. **为什么"两人同时走"等价于"一去一回"?** 回程从 (n-1,n-1) 到 (0,0) 走左/上，等价于另一个人从 (0,0) 到 (n-1,n-1) 走右/下。两趟路径可以一一对应
2. **能否用网络流解?** 可以。建立最小费用最大流模型，每个格子拆成两个节点（入/出），容量1（或2），费用为负的樱桃数。但实现复杂度远高于 DP
3. **如果是三趟而非两趟呢?** 扩展为三个人同时走，状态变为 `dp[t][r1][r2][r3]`，复杂度 O(n^4)
4. **Cherry Pickup II (1463) 有什么不同?** 1463 是两人从第一行不同位置走到最后一行，只能向下/左下/右下，且起点不同
5. **空间如何进一步优化?** 由对称性 dp[t][r1][r2] == dp[t][r2][r1]，可以只存 r1 <= r2 的部分，再省一半空间
