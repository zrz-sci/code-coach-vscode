# 12. 整数转罗马数字

## 核心思路

这道题本质上是一个**贪心问题**：从大到小枚举所有可能的罗马数字面值（包括减法形式的 4/9），每次尽可能多地使用当前最大面值，直到 num 被减到 0。

## 思维链

1. **读完题第一反应**：罗马数字有 7 个基本符号，但还有 6 个减法组合（IV, IX, XL, XC, CD, CM），总共 13 个"单元"。能不能把这 13 个单元全列出来，然后逐个匹配？

2. **关键观察**：罗马数字是从大到小排列的。3749 = 1000+1000+1000+500+100+100+40+9，就是贪心地从最大面值开始减。这和我们用纸币找零是一样的道理——先用大面额，再用小面额。

3. **减法形式怎么处理？** 4 和 9 是特殊的，但如果我们把 IV(4)、IX(9)、XL(40)、XC(90)、CD(400)、CM(900) 也当作"面额"加入表中，那它们就不特殊了——统一用贪心处理即可。

4. **最终方案**：建一个从大到小的映射表（13 个条目），遍历每个条目，num 能减多少次就减多少次，每减一次就拼接对应的罗马字符串。

5. **另一种思路**：也可以按"个十百千"四个数位分别处理，每个数位 0-9 对应的罗马写法是有规律的（硬编码查表法）。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 贪心映射表 | 13个面值从大到小逐个匹配 | O(1) | O(1) | ⭐ 必须写出 |
| 逐位查表 | 千/百/十/个 各位硬编码 | O(1) | O(1) | 能说出即可 |
| 暴力拼接 | 按规则 if-else 逐段处理 | O(1) | O(1) | 不推荐 |

> 注：因为 num ≤ 3999，输出长度有上界（最长 15 字符 "MMMCMXCIX" 是 3999 → 实际最长约 15），所以所有解法的时间和空间都是 O(1)。但贪心映射表的思维方式最通用、最优雅。

## 关键提示

1. **把减法形式也当作基本面值**：不要试图在代码里用 if-else 特判 4 和 9。把 900、400、90、40、9、4 直接加入面值表，和 1000、500、100、50、10、5、1 并列，从大到小排好，统一用贪心。

2. **贪心为什么正确？** 因为罗马数字的规则本身就是贪心的——每个数位独立转换，且同一面值最多用 3 次（由减法形式保证不会出现 IIII）。面值表从大到小排列后，每次减去最大可用面值一定是正确的。

3. **循环次数不会超过 3 次**：对于基本符号 I/X/C/M 最多减 3 次，对于 V/L/D 和减法形式最多减 1 次，所以内层 while 执行次数是常数。

4. **另一种思路的线索**：每个数位（千位、百位、十位、个位）的 0-9 转换是独立的，且模式相同（只是用的字母不同）。比如个位用 I/V/X，十位用 X/L/C，百位用 C/D/M。

## 解法详解

### 解法1: 贪心映射表 — O(1) / O(1) ⭐ 面试首选

**思考过程**：罗马数字本质上是一种"找零"问题。我们手上有 13 种"面额"：1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4, 1。从最大面额开始，能用几次就用几次。

```
贪心过程示例 (num = 3749):

面值表: [1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4, 1]

num=3749, 面值1000: 3749÷1000=3次 → "MMM",   剩余749
num=749,  面值900:  749<900 跳过
num=749,  面值500:  749÷500=1次  → "D",      剩余249
num=249,  面值400:  249<400 跳过
num=249,  面值100:  249÷100=2次  → "CC",     剩余49
num=49,   面值90:   49<90 跳过
num=49,   面值50:   49<50 跳过
num=49,   面值40:   49÷40=1次   → "XL",     剩余9
num=9,    面值10:   9<10 跳过
num=9,    面值9:    9÷9=1次     → "IX",     剩余0
结果: "MMMDCCXLIX" ✓
```

```cpp
class Solution {
public:
    string intToRoman(int num) {
        // 13个面值从大到小排列（包含6个减法形式）
        int values[] =  {1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4, 1};
        string syms[] = {"M","CM","D","CD","C","XC","L","XL","X","IX","V","IV","I"};
        
        string result;
        for (int i = 0; i < 13; i++) {
            // 贪心：当前面值能用几次就用几次
            while (num >= values[i]) {
                result += syms[i];
                num -= values[i];
            }
        }
        return result;
    }
};
```

**关键点**：
- 面值表**必须从大到小排列**，否则贪心不正确（比如先用 1 会一直用 1）。
- 把 while 换成 `int count = num / values[i]; num %= values[i];` 加循环 count 次拼接也可以，效果一样。

---

### 解法2: 逐位查表（硬编码） — O(1) / O(1)

**思考过程**：num ≤ 3999，最多 4 位数。每个数位（千/百/十/个）的 0-9 对应的罗马写法是固定的，直接建四张表查表拼接。

```
每个数位的规律（以个位为例，用 I/V/X）:
 0: ""     1: "I"    2: "II"   3: "III"
 4: "IV"   5: "V"    6: "VI"   7: "VII"
 8: "VIII" 9: "IX"

十位用 X/L/C，百位用 C/D/M，千位只到3用 M/MM/MMM
```

```cpp
class Solution {
public:
    string intToRoman(int num) {
        // 千位: 0~3
        string thousands[] = {"", "M", "MM", "MMM"};
        // 百位: 0~9
        string hundreds[]  = {"", "C", "CC", "CCC", "CD", "D", "DC", "DCC", "DCCC", "CM"};
        // 十位: 0~9
        string tens[]      = {"", "X", "XX", "XXX", "XL", "L", "LX", "LXX", "LXXX", "XC"};
        // 个位: 0~9
        string ones[]      = {"", "I", "II", "III", "IV", "V", "VI", "VII", "VIII", "IX"};
        
        return thousands[num / 1000] 
             + hundreds[(num % 1000) / 100] 
             + tens[(num % 100) / 10] 
             + ones[num % 10];
    }
};
```

**关键点**：
- 这种方法代码极短、速度极快，但硬编码不够优雅，面试中可能被追问"如果范围扩大到几万怎么办？"（答：罗马数字本身最大3999，所以不会扩大）。
- 好处是完全没有循环，纯查表 O(1)。

## 解法对比

| | 贪心映射表 | 逐位查表 |
|---|---|---|
| **核心思想** | 贪心找零 | 每位独立查表 |
| **代码量** | ~10行 | ~8行（但表很长） |
| **可扩展性** | 高（加面值即可） | 低（需要重写表） |
| **面试推荐度** | ⭐⭐⭐ 优先 | ⭐⭐ 作为变体展示 |
| **思维难度** | 需要想到"把减法形式加入面值表" | 直觉简单，但有点"背诵感" |

**什么时候选哪个？**
- 面试中首选贪心映射表，因为它体现了分析问题和贪心策略的能力。
- 如果面试官追问"最快的写法"，可以提逐位查表。

## 易错点

1. **✗ 面值表顺序写反了**：
   ```cpp
   int values[] = {1, 4, 5, 9, 10, ...}; // 从小到大 → 错！
   ```
   → **✓ 必须从大到小**，否则贪心会先消耗小面值，结果全是 I。

2. **✗ 遗漏减法形式的面值**：
   ```cpp
   int values[] = {1000, 500, 100, 50, 10, 5, 1}; // 只有7个基本符号
   ```
   → **✓ 必须包含 900, 400, 90, 40, 9, 4 这6个减法面值**，否则无法正确处理 4/9 开头的数。

3. **✗ 逐位查表时取位数写错**：
   ```cpp
   hundreds[num / 100]   // 当 num=3749 时，3749/100=37，越界！
   ```
   → **✓ 正确写法是 `hundreds[(num % 1000) / 100]`**，先取模去掉高位。

4. **✗ string 拼接用 `push_back` 单字符**：
   ```cpp
   result.push_back(syms[i]); // syms[i] 是 string，不是 char
   ```
   → **✓ 用 `result += syms[i]` 或 `result.append(syms[i])`**。

## 面试追问

**Q1: 为什么贪心策略在这道题上是正确的？不会漏掉某些组合吗？**
> 罗马数字的规则本身就是贪心的——每个数位独立转换，且面值之间的关系保证了大面值优先不会导致"凑不出"的情况。类比：用 1、5、10、25 美分找零，贪心总是最优的（因为面额关系特殊）。而如果面额是 1、3、4 找零 6，贪心 4+1+1 不如 3+3，但罗马数字不会出现这种情况。

**Q2: 如果要反过来——罗马数字转整数（LeetCode 13），思路怎么变？**
> 从左到右扫描，如果当前符号比右边的小（如 I 在 V 前面），就减去当前值；否则加上当前值。关键是判断"减法形式"的方向变了：整数转罗马是贪心减法，罗马转整数是逐字符加减法。

**Q3: 如果范围扩大到百万级别，罗马数字怎么表示？**
> 传统罗马数字最大只到 3999。扩展的罗马数字用上划线表示 ×1000（如 V̅ = 5000），但这超出了本题范围。如果面试官问，可以说"在面值表中增加新的面额和符号即可，贪心框架不变"。
