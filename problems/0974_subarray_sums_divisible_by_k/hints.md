# 974. 和可被 K 整除的子数组

## 核心思路

本质上是"统计有多少个连续子数组的和能被 K 整除"。关键洞察：**子数组和 = 两个前缀和的差**，而"差能被 K 整除"等价于"两个前缀和对 K 取余相同"。所以问题转化为：在前缀和的余数序列中，找有多少对相同余数。

## 思维链

1. **读完题第一反应** → 枚举所有子数组，算每个子数组的和，检查是否能被 K 整除。双重循环枚举起点终点，O(n²) 或 O(n³)。
2. **暴力解的瓶颈** → 枚举了 O(n²) 个子数组，每个还要算和（如果不用前缀和就是 O(n³)，用前缀和可以 O(n²)），但 n=3×10⁴ 时 O(n²) ≈ 9×10⁸，还是太慢。
3. **关键数学观察** → 子数组 `nums[i..j]` 的和 = `prefix[j+1] - prefix[i]`。要求这个差能被 K 整除，即 `(prefix[j+1] - prefix[i]) % K == 0`，等价于 `prefix[j+1] % K == prefix[i] % K`。问题变成了：**在前缀和数组中，找有多少对索引的前缀和 mod K 相同**。
4. **用哈希表计数** → 遍历前缀和，用哈希表记录每个余数出现的次数。当前余数为 r 时，之前已有 `count[r]` 个前缀和的余数也是 r，它们都能和当前位置配对形成合法子数组。
5. **处理负数余数** → C++ 中负数取余结果可能为负（如 `-1 % 5 = -1`），需要 `((prefix % k) + k) % k` 修正为非负。
6. **初始化** → 空前缀（和为0）的余数是0，所以 `count[0] = 1`，代表"从数组开头到当前位置"这种子数组也能被统计到。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举所有子数组求和判断 | O(n²) | O(1) | 能说出即可 |
| 前缀和 + 哈希表 | 余数相同的前缀和配对计数 | O(n) | O(K) | ⭐ 必须写出 |
| 前缀和 + 余数数组 | 用固定大小数组代替哈希表 | O(n) | O(K) | 加分项 |

## 关键提示

- **提示1**：子数组和问题，先想前缀和。`sum(i,j) = prefix[j+1] - prefix[i]`，把区间和转化为两个端点的差。
- **提示2**：`(a - b) % K == 0` 等价于 `a % K == b % K`。这是整除问题的经典数论性质。
- **提示3**：如果有 m 个前缀和的余数都是 r，那么它们两两配对能形成 `C(m, 2) = m*(m-1)/2` 个合法子数组。但实际代码中不需要最后算组合数，边遍历边累加更简洁。
- **提示4**：C++ 中 `-1 % 5` 的结果是 `-1` 而不是 `4`！负数取余要特殊处理。
- **提示5**：别忘了初始化 `count[0] = 1`，代表空前缀。否则从索引 0 开始的子数组会漏掉。

```
前缀和与余数示例: nums = [4,5,0,-2,-3,1], k = 5

index:      0    1    2    3    4    5    6
prefix:  0    4    9    9    7    4    5
prefix%5: 0    4    4    4    2    4    0

余数分组:
  余数0: 出现在位置 {0, 6}  → C(2,2) = 1 对
  余数4: 出现在位置 {1, 2, 3, 5} → C(4,2) = 6 对
  余数2: 出现在位置 {4}  → C(1,2) = 0 对
  总计: 1 + 6 + 0 = 7 ✓
```

## 解法详解

### 解法1: 暴力枚举 + 前缀和 — O(n²) / O(n)

**思考过程**: 最直觉的方法就是算出前缀和数组，然后双重循环枚举所有 `(i, j)` 对，检查 `(prefix[j+1] - prefix[i]) % k == 0`。

```cpp
class Solution {
public:
    int subarraysDivByK(vector<int>& nums, int k) {
        int n = nums.size();
        // 构建前缀和数组
        vector<long long> prefix(n + 1, 0);
        for (int i = 0; i < n; i++) {
            prefix[i + 1] = prefix[i] + nums[i];
        }
        
        int count = 0;
        // 枚举所有 (i, j) 对，i < j
        for (int i = 0; i < n + 1; i++) {
            for (int j = i + 1; j < n + 1; j++) {
                // 子数组 nums[i..j-1] 的和 = prefix[j] - prefix[i]
                if ((prefix[j] - prefix[i]) % k == 0) {
                    count++;
                }
            }
        }
        return count;
    }
};
```

**关键点**: n = 3×10⁴ 时 O(n²) ≈ 9×10⁸，会 TLE。瓶颈在于需要枚举所有配对。

### 解法2: 前缀和 + 哈希表 — O(n) / O(K) ⭐ 面试首选

**从解法1优化**: 解法1枚举所有配对 O(n²)。我们发现 `(prefix[j] - prefix[i]) % k == 0` 等价于两者 mod k 相同。那只需要统计"之前有多少个前缀和和我余数相同"就行了，用哈希表 O(1) 查询。

```cpp
class Solution {
public:
    int subarraysDivByK(vector<int>& nums, int k) {
        // count[r] = 到目前为止，前缀和 mod k == r 的个数
        unordered_map<int, int> count;
        count[0] = 1;  // 空前缀的和为0，mod k = 0
        
        int prefix = 0;
        int result = 0;
        
        for (int num : nums) {
            prefix += num;
            // 处理负数余数：C++ 中 -1 % 5 = -1，需要修正为 4
            int r = ((prefix % k) + k) % k;
            
            // 之前有 count[r] 个前缀和的余数也是 r
            // 它们每一个都能和当前位置配对，形成合法子数组
            result += count[r];
            count[r]++;
        }
        
        return result;
    }
};
```

**关键点**: `((prefix % k) + k) % k` 是处理负数余数的标准写法。

### 解法3: 前缀和 + 余数数组 — O(n) / O(K)

**和解法2思路一致**，但因为余数范围是 `[0, k-1]`，可以用固定大小的数组代替哈希表，常数更小。

```cpp
class Solution {
public:
    int subarraysDivByK(vector<int>& nums, int k) {
        // 余数只有 0 ~ k-1 共 k 种，用数组比哈希表快
        vector<int> count(k, 0);
        count[0] = 1;
        
        int prefix = 0;
        int result = 0;
        
        for (int num : nums) {
            prefix += num;
            int r = ((prefix % k) + k) % k;
            result += count[r];
            count[r]++;
        }
        
        return result;
    }
};
```

**关键点**: 当 K 较小时（本题 K ≤ 10⁴），数组版本的常数更优。

## 解法对比

| | 暴力枚举 | 前缀和+哈希表 | 前缀和+余数数组 |
|---|---|---|---|
| 时间 | O(n²) | O(n) | O(n) |
| 空间 | O(n) | O(min(n, K)) | O(K) |
| 核心操作 | 枚举所有配对 | 哈希表计数配对 | 数组计数配对 |
| 是否通过 | ✗ TLE | ✓ | ✓ 最快 |

暴力到最优的关键跳跃：把"枚举配对"变成"计数配对"。只需知道"之前有多少个同余数的前缀和"，不需要知道它们具体在哪。

## 易错点

1. **负数取余**
   - ✗ `int r = prefix % k;` → 当 prefix 为负时 r 可能为负，如 `-1 % 5 = -1`
   - ✓ `int r = ((prefix % k) + k) % k;` → 保证 r ∈ [0, k-1]
   - 为什么：C++ 规定取余的符号和被除数一致，`-1 % 5 = -1` 而非 `4`

2. **忘记初始化 count[0] = 1**
   - ✗ 不初始化 → 漏掉从数组开头开始且和能被 K 整除的子数组
   - ✓ `count[0] = 1` → 空前缀和为0，mod K 余0，作为配对的左端点
   - 例如 `nums = [5], k = 5`：prefix = 5, r = 0。如果 count[0] 没初始化为1，result 不会 +1，输出 0 而非正确答案 1

3. **前缀和溢出**
   - n = 3×10⁴，每个元素最大 10⁴，前缀和最大 3×10⁸，int 够用
   - 但如果用 long long 更安全。注意取余操作在 int 范围内是安全的

4. **先查询再更新 vs 先更新再查询**
   - ✗ 先 `count[r]++` 再 `result += count[r]` → 自己和自己配对了（多算了）
   - ✓ 先 `result += count[r]` 再 `count[r]++` → 只和之前的配对

## 面试追问

**Q1（基础理解）: 暴力法的时间复杂度是多少？瓶颈在哪？**
→ O(n²) 或 O(n³)。用前缀和可以 O(1) 求子数组和，但还是要枚举 O(n²) 个子数组。瓶颈在"枚举所有配对"。

**Q2（核心优化）: 为什么 `prefix[j] % k == prefix[i] % k` 就能保证子数组和可被 K 整除？**
→ 因为 `(prefix[j] - prefix[i]) % k = (prefix[j] % k - prefix[i] % k) % k`。余数相同则差的余数为0，即差能被 K 整除。这是模运算的基本性质。

**Q3（变体）: 如果题目改为"子数组和恰好等于 K 的倍数的最长长度"呢？**
→ 哈希表存的不是 count 而是**每个余数第一次出现的索引**。当再次遇到相同余数时，用当前索引减去第一次出现的索引就是子数组长度，取最大值。类似 LeetCode 525 的思路。

**Q4（拓展）: 这道题和 LeetCode 523 (Continuous Subarray Sum) 有什么关系？**
→ 523 问"是否存在长度至少为2的子数组和是 K 的倍数"，用的是完全一样的余数+哈希表框架，区别在于 523 需要额外检查长度 ≥ 2（存储余数首次出现的索引来判断距离）。

## 相关题型

- **LeetCode 560 (和为 K 的子数组)** — 同样的"前缀和 + 哈希表"框架，区别：560 是精确匹配 `prefix[j] - prefix[i] == k`，本题是余数匹配 `prefix[j] % k == prefix[i] % k`
- **LeetCode 523 (连续的子数组和)** — 复用完全相同的余数思路，区别：523 问存在性且要求长度 ≥ 2，所以哈希表存首次出现索引而非计数
- **LeetCode 525 (连续数组)** — 复用"前缀和 + 哈希表存首次出现索引求最长"的模板，把 0 视为 -1 后转化为和为 0 的问题
- **LeetCode 1 (两数之和)** — 最基础的"边遍历边查哈希表找配对"模式，本题是这个模式在前缀和+取余上的推广
