# 1539. 第 k 个缺失的正整数

## 核心思路

本质上在问：正整数序列 1,2,3,4,... 中，去掉 arr 里出现的数后，剩下的序列的第 k 个是谁？关键洞察是——**arr[i] 前面缺失了多少个正整数，可以用公式 `arr[i] - (i+1)` 直接算出来**，不需要真的枚举。

## 思维链

1. **读完题第一反应**：从 1 开始一个个数正整数，遇到在 arr 里的就跳过，数到第 k 个不在 arr 里的就是答案。→ 线性扫描 O(n+k)。
2. **暴力解的瓶颈**：需要逐个遍历，当 k 很大或数组很长时不够快。能否跳着走？
3. **关键观察**：如果数组没有缺失，arr[i] 应该等于 i+1。实际的 arr[i] 比 i+1 大多少，就说明 arr[i] 前面缺失了多少个正整数。即 `missing(i) = arr[i] - (i + 1)`。
4. **联想到二分**：`missing(i)` 是单调不减的！我们可以**二分查找**第一个 `missing(i) >= k` 的位置，从而定位答案在哪两个 arr 元素之间。
5. **计算答案**：找到位置后，用简单的偏移公式算出第 k 个缺失的数。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力遍历 | 逐个正整数检查是否在 arr 中 | O(n + k) | O(1) | 能说出即可 |
| 二分查找 | 利用 `arr[i]-(i+1)` 的单调性二分 | O(log n) | O(1) | ⭐ 必须写出 |

## 关键提示

1. **核心公式**：对于索引 i，`arr[i]` 之前（含之前的间隙）一共缺失了 `arr[i] - (i + 1)` 个正整数。想想为什么？如果 0~i 这些位置全部不缺，arr[i] 应该恰好是 i+1。
2. **单调性**：`arr[i] - (i+1)` 随 i 增大而不减（数组严格递增，每往右一步 arr 至少 +1，而 i+1 恰好 +1）。有了单调性就能二分。
3. **二分找什么**：找最后一个 `missing(i) < k` 的位置，即"在 arr 中，最右边的那个还不够缺 k 个的元素"。答案就在这个元素的右侧。
4. **答案公式**：如果二分结束后 `left` 指向第一个 `missing >= k` 的位置，那答案 = `k + left`。理解这个公式：arr 中有 `left` 个元素 ≤ 答案，答案本身是第 k 个缺失的，所以答案 = k + left。

```
// arr = [2, 3, 4, 7, 11], k = 5
//
// 索引i:     0    1    2    3    4
// arr[i]:    2    3    4    7    11
// 期望值:    1    2    3    4    5     (如果无缺失)
// 缺失数:    1    1    1    3    6     = arr[i] - (i+1)
//                                ↑
//                         missing=3<5  missing=6>=5
//                         → 答案在 arr[3]=7 和 arr[4]=11 之间
//                         → 答案 = k + left = 5 + 4 = 9 ✓
```

5. **边界**：如果所有缺失数都在 arr 最后一个元素之后（如 arr=[1,2,3,4], k=2），二分结束时 left = n，答案 = k + n。

## 解法详解

### 解法1: 暴力遍历 — O(n + k) / O(1)

**思考过程**：最直觉的方式——从正整数 1 开始往上数，每个数检查它是否在 arr 中（用一个指针跟踪 arr）。不在就计数，计到第 k 个就返回。

```cpp
class Solution {
public:
    int findKthPositive(vector<int>& arr, int k) {
        int idx = 0;       // 指向 arr 中当前比较的位置
        int current = 0;   // 当前正在检查的正整数
        
        while (k > 0) {
            current++;
            // 如果 current 等于 arr[idx]，说明 current 没有缺失，跳过
            if (idx < arr.size() && arr[idx] == current) {
                idx++;
            } else {
                // current 是缺失的，消耗一次 k
                k--;
            }
        }
        return current;
    }
};
```

**关键点**：这里用 idx 指针避免了每次都在 arr 中查找，利用了 arr 有序的性质。如果用 HashSet 查找也可以，但多了 O(n) 空间。

---

### 解法2: 二分查找 — O(log n) / O(1) ⭐ 面试首选

**从解法1优化**：解法1逐个遍历，O(n+k) 在最坏情况下不够快。核心洞察：**arr[i] 之前缺失的正整数个数 = arr[i] - (i+1)**，这个值单调不减，可以二分。

我们要找：**最后一个满足 `arr[mid] - (mid+1) < k` 的位置**。二分结束后 `left` 就是第一个 `缺失数 >= k` 的索引，答案 = `k + left`。

```
// 二分过程 (arr = [2,3,4,7,11], k = 5):
//
// 搜索空间: [0, 4]
//
// Round1: left=0, right=4, mid=2
//         missing(2) = arr[2]-(2+1) = 4-3 = 1 < 5 → left = 3
//
// Round2: left=3, right=4, mid=3
//         missing(3) = arr[3]-(3+1) = 7-4 = 3 < 5 → left = 4
//
// Round3: left=4, right=4, mid=4
//         missing(4) = arr[4]-(4+1) = 11-5 = 6 >= 5 → right = 3
//
// 结束: left=4 > right=3
// 答案 = k + left = 5 + 4 = 9 ✓
```

```cpp
class Solution {
public:
    int findKthPositive(vector<int>& arr, int k) {
        int left = 0, right = arr.size() - 1;
        
        while (left <= right) {
            int mid = left + (right - left) / 2;
            // arr[mid] 之前缺失了多少个正整数
            int missing = arr[mid] - (mid + 1);
            
            if (missing < k) {
                // 缺失数还不够 k 个，答案在右边
                left = mid + 1;
            } else {
                // 缺失数已经 >= k，答案可能在左边
                right = mid - 1;
            }
        }
        
        // left = 第一个 missing >= k 的索引
        // 等价于：arr 中有 left 个元素 <= 答案
        // 答案 = k + left (k个缺失 + left个存在的 = 答案的绝对位置)
        return k + left;
    }
};
```

**为什么答案是 `k + left`？** 
- 二分结束后，`left` 表示 arr 中有多少个元素出现在答案之前（或等于答案位置之前）
- 在正整数序列中，答案之前有 `left` 个"存在的"和 `k-1` 个"缺失的"，加上答案本身，答案 = left + k

## 易错点

1. **缺失数公式搞错**：
   - ✗ `missing = arr[mid] - mid`（忘了索引从 0 开始，正整数从 1 开始）
   - ✓ `missing = arr[mid] - (mid + 1)`

2. **二分条件用错**：
   - ✗ `if (missing <= k)` — 当 missing 刚好等于 k 时，答案不是 arr[mid]，而是 arr[mid] 前面的那个缺失数。应该让 right 继续收缩。
   - ✓ `if (missing < k)` — 严格小于时才移动 left

3. **答案公式理解错**：
   - ✗ `return arr[right] + (k - missing_at_right)` — 容易在 right 越界时出错
   - ✓ `return k + left` — 简洁且不需要特判边界

4. **暴力法中忘记 idx 边界检查**：
   - ✗ `if (arr[idx] == current)` — idx 可能越界
   - ✓ `if (idx < arr.size() && arr[idx] == current)`

## 面试追问

**Q1: 暴力解时间复杂度是多少？瓶颈在哪？**
→ O(n+k)，当 k 远大于 n 时主要受 k 控制。瓶颈在于逐个遍历正整数。

**Q2: 能否做到 O(log n)？关键观察是什么？**
→ `arr[i] - (i+1)` 给出 arr[i] 之前有多少个缺失数，这个值单调不减，可以二分。

**Q3: 如果 arr 不是严格递增（可能有重复），怎么办？**
→ 先去重，或者公式需要调整：缺失数 = arr[i] - (i+1) 在有重复时不再单调，需要改用其他策略（如用 set 去重后二分，或回退到线性方法）。

**Q4: 如果要返回前 k 个缺失的正整数（不是第 k 个），怎么做？**
→ 用暴力遍历法收集所有缺失数即可，O(n+k)。或者用二分找到第 k 个的位置后，反推前面的。
