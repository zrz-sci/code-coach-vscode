# 756. 金字塔转换矩阵 (Pyramid Transition Matrix)

## 核心思路

本题本质是一个**回溯 + 哈希映射**问题。给定金字塔底层字符串和允许的三角形模式，需要判断能否从底层逐层向上构建直到只剩一个字符。关键在于：对底层相邻两个字符，查找所有允许放置在其上方的字符，然后通过回溯尝试所有可能的组合来构建上一层。每层构建完成后递归处理新的一层，直到层长为1。

## 思维链

1. **问题建模**：将 allowed 列表转化为映射关系 `(left, right) -> [top1, top2, ...]`，表示底部两个字符上方可以放置哪些字符
2. **逐层构建**：从底层开始，对每对相邻字符查找可选顶部字符，如果某对相邻字符没有可选项，当前路径不可行
3. **组合爆炸**：每个位置可能有多个候选字符，需要回溯枚举所有组合
4. **递归终止**：当某层只有1个字符时，金字塔构建成功
5. **剪枝优化**：字符集只有 A-F（6个字符），底层最长6个字符，搜索空间有限

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 回溯 + 哈希映射 | O(6^(n*(n-1)/2)) | O(n^2) | 经典解法，直观易懂 |
| 位运算优化回溯 | O(6^(n*(n-1)/2)) | O(n^2) | 用位掩码存储可选字符 |

## 关键提示

1. **映射构建**：用 `unordered_map<string, vector<char>>` 存储两个底部字符到可选顶部字符的映射，key 是底部两字符拼接的字符串
2. **回溯框架**：对当前层从左到右逐位确定上层字符，每确定一位就递归确定下一位
3. **层间递归**：上层完整构建后，以上层作为新的底层继续递归
4. **搜索空间**：虽然最坏情况指数级，但字符集大小(6)和底层长度(<=6)限制了实际搜索量
5. **字符串拼接**：取相邻字符 `bottom[i]` 和 `bottom[i+1]` 作为 key 查表

## 解法详解

### 解法一：回溯 + 哈希映射（推荐）

**算法步骤**：
1. 预处理 `allowed` 数组，构建映射 `map[left+right] = {top1, top2, ...}`
2. 从底层开始，调用递归函数 `build(bottom, nextRow, index, map)`
3. 在递归中：
   - 如果 `bottom.size() == 1`，返回 true
   - 如果 `index == bottom.size() - 1`，说明上层构建完成，递归处理新层 `build(nextRow, "", 0, map)`
   - 否则取 `key = bottom[index..index+1]`，查找所有可选顶部字符
   - 对每个可选字符，将其追加到 `nextRow`，递归尝试 `index + 1`
   - 如果某条路径成功返回 true，整体返回 true
4. 所有路径都失败则返回 false

**复杂度分析**：
- 时间复杂度：最坏情况下每个位置有6种选择，总层数为 n-1，总位置数为 n*(n-1)/2
- 空间复杂度：O(n^2) 递归栈深度加上存储中间层的空间

### 解法二：位运算优化

**核心改进**：用 6 位的位掩码表示每对底部字符的可选顶部字符集合，加速查表和判空操作。

**优化点**：
- `map[left][right]` 存储一个整数位掩码，第 k 位为1表示字符 'A'+k 可选
- 判断某对字符是否有可选项只需检查掩码是否为0
- 遍历可选字符时用位运算提取每一位

## 易错点

1. **映射 key 的构造**：必须用 `bottom[i]` 和 `bottom[i+1]`（相邻两个字符）而不是间隔字符
2. **递归终止条件**：`bottom.size() == 1` 表示成功，不要误写成 `bottom.size() == 0`
3. **回溯恢复状态**：如果使用引用传递 nextRow，在回溯时需要弹出末尾字符（pop_back）
4. **空映射处理**：某些字符对可能没有任何允许的顶部字符，此时应立即返回 false
5. **层间转换**：构建完上一层后，nextRow 变成新的 bottom，要重新开始 index=0 和空的 nextRow
6. **allowed 可能为空**：如果 bottom 长度为1则直接返回 true，否则若 allowed 为空则返回 false

## 面试追问

1. **Q: 如果字符集从 6 个扩展到 26 个，算法还能工作吗？**
   - A: 理论上可以，但搜索空间急剧增大。需要加入记忆化搜索（对每一层的状态做缓存）或使用位运算压缩状态来剪枝。

2. **Q: 如何对搜索进行剪枝优化？**
   - A: (1) 在构建上层前先检查每对字符是否都有可选项，若有任何一对为空则直接剪掉；(2) 可以用记忆化存储已知不可行的中间层状态避免重复计算。

3. **Q: 能否用 BFS 代替 DFS？**
   - A: 可以，将每一层的所有可能字符串作为状态放入队列，逐层构建。但状态数可能很大（6^n），DFS+回溯在空间上更优。

4. **Q: 时间复杂度能否优化到多项式？**
   - A: 本题本质是 NP 问题的一个特例，在一般情况下无法优化到多项式。但由于约束条件限制（底层最长6，字符仅6种），实际运行时间是可控的。

5. **Q: 如果需要输出具体的金字塔方案而不只是判断可行性，如何修改？**
   - A: 在回溯过程中记录每一层的构建结果，成功时将所有层收集起来返回即可。
