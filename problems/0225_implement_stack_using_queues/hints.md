# 225. 用队列实现栈

## 核心思路

队列是 FIFO（先进先出），栈是 LIFO（后进先出），本质上是要**在 FIFO 的约束下模拟 LIFO 的行为**。关键在于：每次需要访问"最后进来的元素"，但队列只能访问"最先进来的元素"，所以要想办法把最新元素挪到队列头部。

## 思维链

1. **读完题第一反应**：栈和队列的出入顺序恰好相反。队列只能从前面取，栈要从后面取。所以每次 pop/top 时，需要把前面的元素都"搬走"，才能拿到最后那个。
2. **两个队列怎么配合？** 把 q1 前面的元素一个个搬到 q2 里，搬到只剩一个就是"栈顶"。用完后再把 q2 换回来当主队列。这样 push 是 O(1)，但 pop 是 O(n)。
3. **能不能反过来？** 如果 push 的时候就把新元素调整到队列最前面，那 pop/top 就是 O(1) 了。怎么做？push 新元素到 q2，然后把 q1 的所有元素搬到 q2 后面，再交换 q1 和 q2。这样 q1 的队头永远是"栈顶"。
4. **进阶：只用一个队列？** push 新元素到队尾后，把它前面的所有元素依次出队再入队，相当于"旋转"队列，让新元素跑到队头。这就是一个队列的解法。
5. **选哪种取决于使用场景**：push 多就选"push O(1)"方案，pop/top 多就选"push O(n)"方案。面试中一般给出"push O(n)"的单队列解法最简洁优雅。

## 解法概览

| 解法 | 思路 | push | pop | top | 空间 | 面试 |
|------|------|------|-----|-----|------|------|
| 两个队列 (push O(1)) | pop 时搬元素 | O(1) | O(n) | O(n) | O(n) | 能说出即可 |
| 两个队列 (push O(n)) | push 时调整顺序 | O(n) | O(1) | O(1) | O(n) | ⭐ 必须写出 |
| 一个队列 (Follow-up) | push 时自旋转 | O(n) | O(1) | O(1) | O(n) | 加分项 |

## 关键提示

1. **队列只有四个操作**：push_back、pop_front（front）、size、empty。不能用下标访问或从后面取。
2. **想想 push 的时候做工作 vs pop 的时候做工作**：两种策略都能实现，但代码复杂度不同。
3. **一个队列的关键**：push(x) 后，把队列里原有的 n-1 个元素依次出队再入队，x 就"旋转"到了队头。
4. **ASCII 示意（push 时调整）**：
```
push(1): q = [1]           ← 1 就在队头，它是栈顶
push(2): q = [2]  暂时     ← 先把2入队
         把旧的1搬到2后面  
         q = [2, 1]        ← 现在2在队头，是栈顶 ✓
push(3): q = [3]  暂时
         把旧的2,1搬到3后面
         q = [3, 2, 1]     ← 3在队头，是栈顶 ✓
pop():   q.front() = 3 ✓   ← 直接从队头取就是栈顶
```

## 解法详解

### 解法1: 两个队列（push O(1), pop O(n)）

**思考过程**：最直觉的想法——push 时直接入队很快，pop 时再想办法把最后一个元素找出来。怎么找？把前面的 n-1 个元素搬到另一个队列，剩下的那个就是要 pop 的。

```cpp
class MyStack {
    queue<int> q1, q2;
public:
    MyStack() {}
    
    void push(int x) {
        q1.push(x);  // 直接入主队列
    }
    
    int pop() {
        // 把 q1 的前 n-1 个元素搬到 q2
        while (q1.size() > 1) {
            q2.push(q1.front());
            q1.pop();
        }
        // q1 剩下的最后一个就是"栈顶"
        int top = q1.front();
        q1.pop();
        // 交换 q1 和 q2，让 q1 重新成为主队列
        swap(q1, q2);
        return top;
    }
    
    int top() {
        // 和 pop 一样，但取完之后还要放回去
        while (q1.size() > 1) {
            q2.push(q1.front());
            q1.pop();
        }
        int top = q1.front();
        q2.push(q1.front());  // 放回 q2
        q1.pop();
        swap(q1, q2);
        return top;
    }
    
    bool empty() {
        return q1.empty();
    }
};
```

**关键点**：swap(q1, q2) 是 O(1) 操作（只交换内部指针），不是 O(n) 的逐元素搬运。top() 要记得把那个元素也放到 q2 里，否则丢了。

### 解法2: 两个队列（push O(n), pop/top O(1)）⭐ 面试首选

**从解法1优化**：解法1 的 pop/top 每次都要搬 n-1 个元素，如果 pop/top 调用频繁就很慢。**反过来想**：push 时就把新元素放到队头位置，这样 pop/top 直接取队头就行。

**怎么做到？** push(x) 时，先把 x 放进空的 q2，然后把 q1 的所有元素搬到 q2 后面。现在 q2 的队头就是 x（最新元素=栈顶）。最后交换 q1 和 q2。

```cpp
class MyStack {
    queue<int> q1, q2;
public:
    MyStack() {}
    
    void push(int x) {
        q2.push(x);  // 新元素先进 q2（此时 q2 是空的）
        // 把 q1 所有旧元素搬到 q2 的后面
        while (!q1.empty()) {
            q2.push(q1.front());
            q1.pop();
        }
        // 交换：q1 永远是"调整好顺序"的主队列
        swap(q1, q2);
    }
    
    int pop() {
        int top = q1.front();
        q1.pop();
        return top;
    }
    
    int top() {
        return q1.front();
    }
    
    bool empty() {
        return q1.empty();
    }
};
```

**过程可视化**：
```
push(1): q2=[1], q1=[] → 搬q1到q2 → q2=[1] → swap → q1=[1]
push(2): q2=[2], q1=[1] → 搬q1到q2 → q2=[2,1] → swap → q1=[2,1]
push(3): q2=[3], q1=[2,1] → 搬q1到q2 → q2=[3,2,1] → swap → q1=[3,2,1]
pop(): q1.front()=3 ✓, q1=[2,1]
top(): q1.front()=2 ✓
```

### 解法3: 一个队列（Follow-up）⭐ 加分项

**关键观察**：其实不需要第二个队列！push(x) 后，把队列里**原有的** n-1 个元素依次出队再入队到自己后面，新元素就自然"旋转"到了队头。

```cpp
class MyStack {
    queue<int> q;
public:
    MyStack() {}
    
    void push(int x) {
        int n = q.size();  // 记录 push 前有多少个旧元素
        q.push(x);
        // 把 x 前面的 n 个旧元素依次移到 x 后面
        for (int i = 0; i < n; i++) {
            q.push(q.front());
            q.pop();
        }
        // 现在 x 在队头
    }
    
    int pop() {
        int top = q.front();
        q.pop();
        return top;
    }
    
    int top() {
        return q.front();
    }
    
    bool empty() {
        return q.empty();
    }
};
```

**过程可视化**：
```
push(1): q=[1], n=0, 不旋转 → q=[1]
push(2): q=[1,2], n=1, 旋转1次: 取1放到2后面 → q=[2,1]
push(3): q=[2,1,3], n=2, 旋转2次:
         取2放后面 → q=[1,3,2]
         取1放后面 → q=[3,2,1]  ← 3在队头 ✓
pop():   front=3, q=[2,1]
```

## 解法对比

| | 解法1 (push O(1)) | 解法2 (push O(n)) | 解法3 (一个队列) |
|---|---|---|---|
| push | O(1) | O(n) | O(n) |
| pop | O(n) | O(1) | O(1) |
| 队列数 | 2 | 2 | 1 |
| 代码量 | pop/top 逻辑复杂 | push 逻辑稍复杂 | 最简洁 |
| 适用场景 | push 远多于 pop | pop/top 频繁 | 面试加分 |

**面试首选**：解法3（一个队列），代码最短，思路最巧，且是 Follow-up 的答案。

## 易错点

1. **解法1 的 top() 忘记把元素放回去**
   - ✗ `int top = q1.front(); q1.pop(); swap(q1, q2); return top;` — 元素丢了！
   - ✓ 取出后要 `q2.push(top)` 再 swap

2. **解法3 旋转次数搞错**
   - ✗ `for (int i = 0; i < q.size(); i++)` — q.size() 在循环中变化！而且应该旋转 n 次（push 前的元素数），不是 n+1 次
   - ✓ 先 `int n = q.size()` 保存，push 后再 `for (int i = 0; i < n; i++)`

3. **swap 之后忘了 q2 的状态**
   - swap 后 q2 应该是空的（q1 原来的元素已经全搬走了）。如果代码逻辑不对导致 q2 不空，后续 push 会出错。

## 面试追问

**Q1：为什么不能直接用一个 vector 模拟栈？**
> 题目约束只能用队列的标准操作（push_back、pop_front、front、size、empty），不能用下标访问或 pop_back。这道题考察的是在 FIFO 约束下实现 LIFO。

**Q2：两种策略（push 做工作 vs pop 做工作），面试该选哪个？**
> 取决于使用场景。如果不确定，选 push O(n) 的方案（pop/top O(1)），因为：1) 更直觉——队列始终保持"栈序"，pop/top 直接取；2) Follow-up 要求一个队列时，这个思路可以自然延伸。

**Q3：能否让 push 和 pop 都是 O(1)？**
> 不能。用队列模拟栈，**至少有一个操作是 O(n)**。直觉上，队列和栈的顺序是反的，总要付出"翻转"的代价，只是把代价分配给 push 还是 pop。这和信息论中的"顺序转换不可能免费"本质相同。
