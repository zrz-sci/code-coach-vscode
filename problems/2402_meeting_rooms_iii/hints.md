# 2402. 会议室 III

## 核心思路

本质是一个**事件驱动的模拟题**：按会议开始时间排序后，依次为每场会议分配房间。核心操作是"快速找到编号最小的空闲房间"和"快速找到最早结束的占用房间"——这两个操作天然适合用**两个优先队列（堆）**来维护。

## 思维链

1. **读完题第一反应**：会议按开始时间排序后逐个处理，每次分配编号最小的空闲房间。如果没有空闲房间，就等到最早结束的那间腾出来。→ 这是一个模拟过程。

2. **暴力怎么做？** 对每场会议，遍历所有 n 个房间，看哪个空闲且编号最小。如果都不空闲，找最早结束的。每场会议 O(n)，总共 O(m·n)。n ≤ 100, m ≤ 10^5，大约 10^7，勉强能过但不优雅。

3. **瓶颈在哪？** 每次都要扫描所有房间来找"编号最小的空闲房间"和"最早结束的占用房间"。

4. **怎么突破？** 用两个堆：
   - **空闲房间小顶堆**（按房间号排序）：O(log n) 取出编号最小的空闲房间
   - **占用房间小顶堆**（按结束时间排序，结束时间相同按房间号）：O(log n) 取出最早结束的房间

5. **核心逻辑**：处理每场会议时，先把所有结束时间 ≤ 当前会议开始时间的房间从"占用堆"移到"空闲堆"。然后：
   - 如果空闲堆非空，取编号最小的房间
   - 如果空闲堆为空，取占用堆中最早结束的房间，会议延期到那个时间点

6. **统计结果**：维护每个房间的使用次数数组，最后找最大值对应的最小编号。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力模拟 | 每次扫描所有房间 | O(m·n) | O(n) | 能说出即可 |
| 双堆模拟 | 空闲堆 + 占用堆 | O(m log n) | O(n) | ⭐ 必须写出 |

## 关键提示

1. **排序是前提**：会议必须按开始时间排序，因为"原开始时间更早的会议优先获得房间"。

2. **两个堆的职责分工**：空闲堆管"哪个房间号最小可用"，占用堆管"哪个房间最早结束"。每个房间在任何时刻只在其中一个堆里。

3. **延期会议的处理**：延期不改变持续时间。如果会议原本 [2, 7) 持续 5 个时间单位，延期到时间 10 开始，则变成 [10, 15)。

4. **结束时间可能很大**：多次延期后结束时间会远超 5×10^5，需要用 `long long`！

5. **模拟流程（示例1可视化）**：
```
n=2, meetings sorted: [0,10], [1,5], [2,7], [3,4]

时间线:
Room 0: |=====[0,10)=====|     |=[10,11)|
Room 1: |=[1,5)=|  |=[5,10)=====|

会议分配过程:
Meeting[0,10) → 空闲堆{0,1} → 取Room 0 → 占用堆{(10,0)}
Meeting[1,5)  → 释放: 无    → 空闲堆{1} → 取Room 1 → 占用堆{(5,1),(10,0)}
Meeting[2,7)  → 释放: 无    → 空闲堆{} → 延期! 取占用堆top(5,1) → Room 1在t=5空闲
              → 会议变[5,10) → 占用堆{(10,0),(10,1)}
Meeting[3,4)  → 释放: 无    → 空闲堆{} → 延期! 取占用堆top(10,0) → Room 0在t=10空闲
              → 会议变[10,11) → 占用堆{(10,1),(11,0)}

count = [2, 2] → 返回 0 (编号最小)
```

## 解法详解

### 解法1: 暴力模拟 — O(m·n) / O(n)

**思考过程**：最直觉的做法——对每场会议，维护每个房间的结束时间，扫描所有房间找最优分配。

```cpp
class Solution {
public:
    int mostBooked(int n, vector<vector<int>>& meetings) {
        sort(meetings.begin(), meetings.end()); // 按开始时间排序
        
        vector<long long> roomEnd(n, 0);  // 每个房间的结束时间
        vector<int> count(n, 0);          // 每个房间举办会议次数
        
        for (auto& m : meetings) {
            long long start = m[0], dur = m[1] - m[0];
            
            // 找最早结束的房间（如果有多个，取编号最小的）
            long long earliest = LLONG_MAX;
            int chosen = -1;
            
            // 优先找空闲房间（结束时间 <= start 的编号最小的房间）
            for (int i = 0; i < n; i++) {
                if (roomEnd[i] <= start) {
                    // 空闲房间，直接选编号最小的
                    chosen = i;
                    break; // 编号从小到大遍历，第一个空闲的就是编号最小的
                }
            }
            
            if (chosen == -1) {
                // 没有空闲房间，找最早结束的（结束时间相同取编号小的）
                for (int i = 0; i < n; i++) {
                    if (roomEnd[i] < earliest) {
                        earliest = roomEnd[i];
                        chosen = i;
                    }
                }
                // 延期：从 earliest 时间开始
                roomEnd[chosen] = earliest + dur;
            } else {
                // 正常安排
                roomEnd[chosen] = start + dur;
            }
            
            count[chosen]++;
        }
        
        // 找举办最多会议的最小编号房间
        return max_element(count.begin(), count.end()) - count.begin();
    }
};
```

**关键点**：
- 暴力法的好处是逻辑清晰、不容易出错，适合先写出来验证理解。
- 每场会议需要 O(n) 扫描所有房间，当 n 和 m 都很大时会慢。
- 但本题 n ≤ 100，所以暴力法实际上完全能过（10^7 级别）。

---

### 解法2: 双堆模拟 — O(m log n) / O(n) ⭐ 面试首选

**从解法1优化**：解法1每次 O(n) 找最小空闲房间和最早结束房间。用两个堆可以把这两个操作都降到 O(log n)。

```cpp
class Solution {
public:
    int mostBooked(int n, vector<vector<int>>& meetings) {
        sort(meetings.begin(), meetings.end()); // 按开始时间排序
        
        // 空闲房间：小顶堆，按房间号排序
        priority_queue<int, vector<int>, greater<int>> idle;
        // 占用房间：小顶堆，按(结束时间, 房间号)排序
        priority_queue<pair<long long, int>, 
                       vector<pair<long long, int>>, 
                       greater<pair<long long, int>>> busy;
        
        // 初始所有房间都空闲
        for (int i = 0; i < n; i++) idle.push(i);
        
        vector<int> count(n, 0);
        
        for (auto& m : meetings) {
            long long start = m[0], end = m[1];
            long long dur = end - start;
            
            // 步骤1：把所有结束时间 <= start 的房间从 busy 移到 idle
            while (!busy.empty() && busy.top().first <= start) {
                idle.push(busy.top().second);
                busy.pop();
            }
            
            int room;
            if (!idle.empty()) {
                // 步骤2a：有空闲房间 → 取编号最小的
                room = idle.top();
                idle.pop();
                busy.push({start + dur, room});
            } else {
                // 步骤2b：没有空闲房间 → 取最早结束的房间，会议延期
                auto [freeTime, r] = busy.top();
                busy.pop();
                room = r;
                busy.push({freeTime + dur, room}); // 延期后的结束时间
            }
            
            count[room]++;
        }
        
        // 找举办最多会议的最小编号房间
        return max_element(count.begin(), count.end()) - count.begin();
    }
};
```

**为什么双堆是正确的？**
- 空闲堆保证了"编号最小的空闲房间"总在堆顶 → O(log n) 取出
- 占用堆保证了"最早结束的房间"总在堆顶 → O(log n) 取出
- 每个房间在任何时刻只在一个堆里，不会重复分配
- 释放操作：每次处理新会议前，把所有已结束的会议对应的房间归还到空闲堆

## 解法对比

| | 暴力模拟 | 双堆模拟 |
|---|---|---|
| 时间 | O(m·n) | O(m log n) |
| 空间 | O(n) | O(n) |
| 代码复杂度 | 简单 | 中等 |
| 适用场景 | n 很小（≤100） | n 很大时也高效 |
| 面试推荐 | 先说思路 | 必须实现 |

本题 n ≤ 100 很小，暴力法足够。但面试中考察的是堆的使用能力，所以双堆解法是期望答案。

## 易错点

1. **忘记用 `long long`**：
   - ✗ `int freeTime = busy.top().first;` → 多次延期后结束时间会超过 int 范围
   - ✓ `long long freeTime = busy.top().first;`
   - 最坏情况：10^5 个会议每个持续 5×10^5，全部延期到同一房间，结束时间可达 5×10^10

2. **释放条件写错**：
   - ✗ `busy.top().first < start` → 半闭区间 [s, e)，结束时间恰好等于 start 时房间已空闲
   - ✓ `busy.top().first <= start`

3. **延期时结束时间计算错误**：
   - ✗ `busy.push({freeTime + end, room})` → 用了原结束时间
   - ✓ `busy.push({freeTime + dur, room})` → 应该用持续时间(duration)

4. **忘记排序**：
   - 题目说的是"原开始时间更早的会议优先"，所以必须先按 start 排序
   - 题目保证 start 互不相同，所以不需要处理 start 相同的情况

5. **`max_element` 返回的是迭代器**：
   - ✗ `return max_element(count.begin(), count.end());`
   - ✓ `return max_element(count.begin(), count.end()) - count.begin();` → 要减去 begin 得到下标
   - 或用 `distance(count.begin(), max_element(...))`

## 面试追问

**Q1（基础理解）**：暴力法怎么做？复杂度是多少？本题 n ≤ 100 暴力能过吗？
> 每场会议扫描所有房间，O(m·n)。n ≤ 100, m ≤ 10^5，约 10^7 次操作，可以过。但面试需要展示更好的方法。

**Q2（优化）**：每次扫描 n 个房间的瓶颈怎么用堆优化？为什么要两个堆而不是一个？
> 一个堆只能高效取最值。我们需要同时维护两个不同排序标准的集合：空闲房间按编号排、占用房间按结束时间排。所以用两个堆。当房间释放时，从占用堆移到空闲堆。

**Q3（变体）**：如果会议可以取消（给一个 cancel 时间戳数组），怎么处理？
> 需要支持从占用堆中删除特定会议。普通堆不支持删除，可以用**懒删除**（标记删除，pop 时跳过已取消的）或用 `std::set` 代替堆（支持 O(log n) 任意删除）。

**Q4（变体）**：如果要返回每场会议实际分配到的房间编号（而不是最终统计），怎么改？
> 在循环中记录每场会议的 room 即可。双堆逻辑不变，只是额外维护一个结果数组。
