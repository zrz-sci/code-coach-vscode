# 174. 地下城游戏 (Dungeon Game)

## 核心思路

这是一道**反向 DP** 的经典题。与常见的路径 DP（如 LC64 最小路径和）不同，本题要求的是"进入每个房间前的最低血量"，而血量约束是**全程不能 <= 0**。正向 DP 无法同时追踪"路径最小血量"和"路径总和"，因此必须**从终点往起点反推**。

`dp[i][j]` 定义为：进入 `(i,j)` 前，骑士至少需要多少血量才能从 `(i,j)` 活着到达终点。

## 思维链

1. **读完题第一反应** → 像 LC64 一样正向 DP？`dp[i][j]` = 从起点到 `(i,j)` 所需最小初始血量。但这行不通：因为"所需血量"不仅取决于路径总和，还取决于路径上的**最低点**。两条路径，一条总和大但有极低点，另一条总和小但没极低点，后者可能更优。正向 DP 无法在一个状态里同时表达这两个维度。
2. **为什么正向不行？** → 正向 DP 的最优子结构不成立。到达 `(i,j)` 的"最优路径"取决于后面会遇到什么：如果后面有大量补血，前面低点可以靠后面补回来；如果后面全是损血，前面就要多备血。正向无法预见未来。
3. **反向 DP 的直觉** → 从终点 `(m-1, n-1)` 反推：离开公主房间后骑士已经完成任务，至少需要 1 HP。然后逐步往回推，每个房间需要的最低血量 = `max(min(右边需要的, 下面需要的) - 当前房间值, 1)`。
4. **状态转移方程** → `dp[i][j] = max(min(dp[i+1][j], dp[i][j+1]) - dungeon[i][j], 1)`。如果当前房间值为正数（补血），则需要的血量减少；如果为负数（损血），则需要更多血量。但无论如何，进入任何房间前至少需要 1 HP。
5. **空间优化** → 从下往上、从右往左填表，每次只需要当前行和下一行，可以压缩为一维数组。
6. **二分搜索解法** → 二分答案：猜测初始血量 `mid`，然后用正向 DP 验证"以 `mid` 为初始血量能否活着到达终点"。但时间复杂度多一个 log 因子，不如直接反向 DP。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 反向二维 DP | 从终点往起点推 | O(mn) | O(mn) | ⭐ 标准写法 |
| 反向一维 DP（空间优化） | 滚动数组 | O(mn) | O(n) | ⭐ 面试首选 |
| 二分搜索 + 正向验证 | 猜初始血量 | O(mn log K) | O(mn) | 了解即可 |

## 关键提示

1. **为什么不能正向 DP？** 正向 DP 的"最优子结构"在本题中不成立。到达 `(i,j)` 的最优路径取决于之后的路径，而正向无法预见未来。反向 DP 天然解决了这个问题：从终点出发，每一步都能基于"从这里到终点的最优"做决策。
2. **`max(..., 1)` 的含义**：骑士在任何时刻血量都不能 <= 0，所以进入任何房间前至少需要 1 HP。即使当前房间是 +100 的补血房，进入前也至少要 1 HP。
3. **边界初始化**：`dp[m][n-1] = dp[m-1][n] = 1`（虚拟边界，表示公主房间右边或下边出去后至少 1 HP），其余虚拟边界设为 `INT_MAX`（不可到达的方向）。
4. **空间优化时的哨兵**：一维 DP 中 `dp[n]` 作为虚拟边界。第一轮（最后一行）时 `dp[n-1]` 需要初始化为 1，非第一轮时 `dp[n]` 需要重置为 `INT_MAX`。

## 解法详解

### 解法1: 反向二维 DP — O(mn) / O(mn) ⭐

**思考过程**: 既然正向行不通，那就反过来——从终点推回起点。`dp[i][j]` 表示"进入 `(i,j)` 前需要的最低血量"。公主在终点，骑士从终点出发往回推：每个房间需要的血量取决于下一步（右或下）需要的最低值。

```cpp
class Solution {
public:
    int calculateMinimumHP(vector<vector<int>>& dungeon) {
        int m = dungeon.size(), n = dungeon[0].size();
        // dp 多一行一列作为虚拟边界
        vector<vector<int>> dp(m + 1, vector<int>(n + 1, INT_MAX));
        // 公主房间的右边/下边出去后至少需要 1 HP
        dp[m][n - 1] = dp[m - 1][n] = 1;
        
        for (int i = m - 1; i >= 0; i--) {
            for (int j = n - 1; j >= 0; j--) {
                // 下一步取右和下的较小值
                int need = min(dp[i + 1][j], dp[i][j + 1]) - dungeon[i][j];
                // 至少需要 1 HP
                dp[i][j] = max(need, 1);
            }
        }
        return dp[0][0];
    }
};
```

**关键点**:
- `dp` 数组大小为 `(m+1) x (n+1)`，多出的一行一列全部初始化为 `INT_MAX`，表示不可到达。
- 只有 `dp[m][n-1]` 和 `dp[m-1][n]` 设为 1，它们是公主房间的虚拟出口。
- `min(dp[i+1][j], dp[i][j+1])` 表示选择需要血量更少的方向。
- `max(need, 1)` 保证进入任何房间前至少 1 HP。

---

### 解法2: 反向一维 DP（空间优化） — O(mn) / O(n) ⭐ 面试首选

**从解法1优化**: 反向 DP 是从下往上、从右往左填表。第 `i` 行只依赖第 `i+1` 行（`dp[i+1][j]`）和当前行的 `dp[i][j+1]`。所以可以用一维数组滚动。

```
空间优化示意（一维 dp 覆盖过程）:
初始: dp = [INF, INF, 1, INF]  (n=3, 多一个哨兵 dp[3]=INF)

处理第2行 [10, 30, -5]:
  j=2: dp[2] = max(min(dp[2], dp[3]) - (-5), 1) = max(min(1,INF)+5, 1) = 6
  j=1: dp[1] = max(min(dp[1], dp[2]) - 30, 1) = max(min(INF,6)-30, 1) = 1
  j=0: dp[0] = max(min(dp[0], dp[1]) - 10, 1) = max(min(INF,1)-10, 1) = 1
  重置: dp[3] = INF
  dp = [1, 1, 6, INF]

处理第1行 [-5, -10, 1]:
  j=2: dp[2] = max(min(dp[2], dp[3]) - 1, 1) = max(6-1, 1) = 5
  j=1: dp[1] = max(min(dp[1], dp[2]) - (-10), 1) = max(min(1,5)+10, 1) = 11
  j=0: dp[0] = max(min(dp[0], dp[1]) - (-5), 1) = max(min(1,11)+5, 1) = 6
  重置: dp[3] = INF
  dp = [6, 11, 5, INF]

处理第0行 [-2, -3, 3]:
  j=2: dp[2] = max(min(dp[2], dp[3]) - 3, 1) = max(5-3, 1) = 2
  j=1: dp[1] = max(min(dp[1], dp[2]) - (-3), 1) = max(min(11,2)+3, 1) = 5
  j=0: dp[0] = max(min(dp[0], dp[1]) - (-2), 1) = max(min(6,5)+2, 1) = 7

答案: dp[0] = 7 ✓
```

```cpp
class Solution {
public:
    int calculateMinimumHP(vector<vector<int>>& dungeon) {
        int m = dungeon.size(), n = dungeon[0].size();
        // dp[j] 表示进入当前行第j列前需要的最低血量
        vector<int> dp(n + 1, INT_MAX);
        dp[n - 1] = 1; // 公主房间下方的虚拟出口
        
        for (int i = m - 1; i >= 0; i--) {
            for (int j = n - 1; j >= 0; j--) {
                // dp[j] = 下方（上一轮的值）; dp[j+1] = 右方（本轮刚更新的值）
                dp[j] = max(min(dp[j], dp[j + 1]) - dungeon[i][j], 1);
            }
            // 非最后一行时, 重置哨兵
            // (最后一行时 dp[n]=INT_MAX 和 dp[n-1]=1 刚好是正确的初始状态)
            if (i > 0) dp[n] = INT_MAX;
        }
        return dp[0];
    }
};
```

**关键点**:
- 一维 `dp[j]` 在更新前存的是"下一行"的值（即 `dp[i+1][j]`），更新后存的是当前行的值。
- `dp[j+1]` 在本轮中已经被更新过了（因为从右往左遍历），所以它是当前行右边一格的值，正好是我们需要的 `dp[i][j+1]`。
- `dp[n]` 作为哨兵，在处理非最后一行时需要重置为 `INT_MAX`，防止从"第一行处理后残留的有限值"干扰后续。

### 解法3: 二分搜索 + 正向验证 — O(mn log K) / O(mn)

**不同思路**: 二分答案。假设初始血量为 `mid`，用正向 DP 检验"以 `mid` 为起始血量，能否活着到达终点"。

```cpp
class Solution {
public:
    int calculateMinimumHP(vector<vector<int>>& dungeon) {
        int m = dungeon.size(), n = dungeon[0].size();
        int lo = 1, hi = 1; // hi 需要足够大
        // 估算 hi: 最坏情况每个房间损 1000, 路径长 m+n-1
        for (auto& row : dungeon)
            for (int v : row)
                if (v < 0) hi -= v;
        hi = max(hi, 1);
        
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (canSurvive(dungeon, mid, m, n)) hi = mid;
            else lo = mid + 1;
        }
        return lo;
    }
    
private:
    bool canSurvive(vector<vector<int>>& d, int hp, int m, int n) {
        // dp[i][j] = 到达(i,j)后的最大可能血量（如果<=0则不可达）
        vector<vector<int>> dp(m, vector<int>(n, 0));
        dp[0][0] = hp + d[0][0];
        if (dp[0][0] <= 0) return false;
        
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (i == 0 && j == 0) continue;
                int best = 0;
                if (i > 0 && dp[i-1][j] > 0) best = max(best, dp[i-1][j]);
                if (j > 0 && dp[i][j-1] > 0) best = max(best, dp[i][j-1]);
                if (best == 0) { dp[i][j] = 0; continue; } // 不可达
                dp[i][j] = best + d[i][j];
                if (dp[i][j] <= 0) dp[i][j] = 0; // 死了
            }
        }
        return dp[m-1][n-1] > 0;
    }
};
```

**关键点**:
- 这种方法直觉上更简单，但多了一个 log 因子且代码更长。
- `canSurvive` 中正向 DP 追踪"到达每个格子后的最大血量"。选择上/左中血量最大的路径到达，如果到达后血量 <= 0 则标记为不可达。
- 面试中通常不推荐这个方法，因为反向 DP 更优雅且更快。但展示出"你能想到二分+验证的框架"是加分项。

## 解法对比

|  | 反向二维 DP | 反向一维 DP | 二分 + 正向 |
|--|-----------|-----------|------------|
| 时间 | O(mn) | **O(mn)** | O(mn log K) |
| 空间 | O(mn) | **O(n)** | O(mn) |
| 代码量 | 短 | **最短** | 长 |
| 直觉难度 | 中（需理解反向） | 中 | 易（但需估算上界） |
| 面试推荐 | ⭐ 标准 | ⭐ 首选 | 了解框架 |

**面试策略**: 先解释为什么不能正向 DP（这是面试官最想听的），然后写反向一维 DP。如果面试官问"除了 DP 还有别的方法吗？"，提一下二分搜索框架。

## 易错点

1. **尝试用正向 DP 解题**：
   - ✗ `dp[i][j]` = 从起点到 `(i,j)` 的最低初始血量 → 最优子结构不成立
   - ✓ 必须反向：`dp[i][j]` = 从 `(i,j)` 到终点的最低入口血量

2. **忘记 `max(..., 1)`**：
   - ✗ `dp[i][j] = min(dp[i+1][j], dp[i][j+1]) - dungeon[i][j]` → 补血房间可能算出 0 或负数
   - ✓ `dp[i][j] = max(min(dp[i+1][j], dp[i][j+1]) - dungeon[i][j], 1)` → 至少 1 HP

3. **边界初始化错误**：
   - ✗ `dp[m-1][n-1] = max(1 - dungeon[m-1][n-1], 1)` 然后特殊处理最后一行和最后一列
   - ✓ 直接用 `(m+1) x (n+1)` 的 dp 表，虚拟边界统一处理，更不容易出错

4. **空间优化时哨兵未重置**：
   - ✗ `dp[n]` 在第一轮后可能变为有限值，后续行使用了错误的边界
   - ✓ 每行处理完后（非最后一行时）重置 `dp[n] = INT_MAX`

5. **`dungeon[0][0]` 就是正数时误以为答案是 1**：
   - ✗ `dungeon = [[100, -200]]`，起始补 100 但第二格扣 200，答案不是 1 而是 101
   - ✓ 反向 DP 自然处理了这种情况

## 面试追问

**Q1: 为什么不能正向 DP？能给一个具体的反例吗？**
> 考虑 `dungeon = [[1, -3, 3], [0, -2, 0], [-3, -3, -3]]`。正向 DP 如果定义 `dp[i][j]` = 到达 `(i,j)` 所需最小初始血量：到达 `(0,1)` 走上面一步 `(0,0) → (0,1)`，路径和 = 1 + (-3) = -2，最低点是 -2，需要初始 3 HP。但如果后面全是补血房，也许走 `(0,0) → (1,0)` 路径和虽然小但最低点更高，后续更好。正向无法在到达中间点时判断哪条路径更优，因为"更优"取决于后面遇到什么。

**Q2: 能否输出最优路径？怎么做？**
> 在反向 DP 中，每个 `dp[i][j]` 计算时选择了"向右还是向下"。记录这个选择方向到 `choice[i][j]` 数组中。然后从 `(0,0)` 出发，沿 `choice` 路径还原即可。空间多 O(mn)。

**Q3: 这题和 LC64 最小路径和有什么区别？为什么一个正向一个反向？**
> LC64 只关心路径总和最小，`dp[i][j] = min(上, 左) + grid[i][j]` 的最优子结构成立：到达 `(i,j)` 的最小路径和只取决于 `(i-1,j)` 和 `(i,j-1)` 的最小路径和。但本题有"过程约束"——路径上每一步血量都 > 0。这个约束使得正向最优子结构失效。反向 DP 消除了这个问题：从终点出发，每一步需要的血量只取决于下一步需要的血量。
