# 9. 回文数

## 核心思路
判断一个整数正着读和反着读是否相同。本质上是"如何在不转字符串的前提下，比较数字的对称性"。

## 思维链
1. **读完题第一反应**：最直觉的做法是把整数转成字符串，然后用双指针从两头向中间比较——这就是字符串回文的经典做法。
2. **Follow-up 的限制**：题目追问"能否不转字符串？"那就得在数字层面操作。最朴素的想法：把整个数字反转，看反转后是否等于原数。
3. **完整反转的隐患**：反转整个数字可能溢出（如 `2147483647` 反转后超出 int 范围）。虽然这道题负数直接返回 false，正数的回文数反转后一定等于自身不会溢出，但面试中需要能说清楚为什么不会溢出。
4. **更优雅的做法——只反转一半**：如果我们只反转数字的后半部分，和前半部分比较，就完全不用担心溢出。关键问题：怎么知道已经反转了"一半"？答案：当反转的部分 `≥` 剩余的部分时，说明已经到达或超过中点了。
5. **边界快速排除**：负数一定不是回文；末尾是 0 但数字不为 0 的（如 10、120）也不是回文，因为开头不可能是 0。

## 解法概览
| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 转字符串 + 双指针 | 转 string 后首尾比较 | O(n) | O(n) | 能说出即可 |
| 完整反转数字 | 反转整个数字，比较是否相等 | O(n) | O(1) | 能说出即可 |
| 反转一半数字 | 只反转后半部分，和前半部分比较 | O(n) | O(1) | ⭐ 必须写出 |

> n = 数字的位数（最多 10 位）

## 关键提示
1. **负数永远不是回文**：负号在最前面，反过来在最后面，天然不对称。
2. **末尾为 0 的特殊处理**：如果 `x % 10 == 0` 且 `x != 0`，直接返回 false。因为回文数的首位不可能是 0。
3. **怎么判断"已经反转了一半"？** 想想：每次从 x 取出末位追加到 reversed 上，x 在缩小，reversed 在增大，当 `reversed >= x` 时就到中点了。
4. **奇数位数的回文**（如 12321）：反转一半后 reversed 会多出中间那一位（reversed=123, x=12），此时比较 `x == reversed / 10` 即可。

## 解法详解

### 解法1: 转字符串 + 双指针 — O(n) / O(n)
**思考过程**: 回文的定义就是"正读反读一样"。字符串天然支持随机访问，用双指针从两端向中间逐字符比较，最直觉。

```cpp
class Solution {
public:
    bool isPalindrome(int x) {
        string s = to_string(x);  // 负号也会被转入字符串，如 "-121"
        int left = 0, right = s.size() - 1;
        while (left < right) {
            if (s[left] != s[right]) return false;
            left++;
            right--;
        }
        return true;
    }
};
```
**关键点**: 负数转字符串后首字符是 `'-'`，和末尾数字一定不等，自然返回 false，无需额外处理。但额外分配了 O(n) 的字符串空间。

---

### 解法2: 完整反转数字 — O(n) / O(1)
**从解法1优化**: 不想用字符串，那就直接在数字层面把整个数反转，然后比较是否相等。

```cpp
class Solution {
public:
    bool isPalindrome(int x) {
        // 负数不是回文
        if (x < 0) return false;
        
        long reversed = 0;  // 用 long 防止反转过程中溢出
        int original = x;
        while (x > 0) {
            reversed = reversed * 10 + x % 10;  // 取末位追加
            x /= 10;                             // 去掉末位
        }
        return reversed == original;
    }
};
```

```
// 反转 121 的过程:
// x=121, reversed=0
// Step1: reversed = 0*10 + 121%10 = 1,   x = 12
// Step2: reversed = 1*10 + 12%10  = 12,  x = 1
// Step3: reversed = 12*10 + 1%10  = 121, x = 0
// reversed(121) == original(121) → true
```

**关键点**: 
- 用 `long` 存 reversed 防溢出。其实对于回文数而言不会溢出（回文数反转后等于自身），但非回文数在反转过程中可能溢出，如果溢出了反而说明它不是回文。不过用 `long` 更安全、更清晰。
- 需要保存原始值 `original`，因为循环中 `x` 被修改了。

---

### 解法3: 反转一半数字 — O(n) / O(1) ⭐ 面试首选
**从解法2优化**: 完整反转需要用 `long` 防溢出，而且要遍历所有位。如果只反转后半部分，既避免了溢出问题（反转的部分最多和前半部分一样大），又减少了一半的循环次数。

```cpp
class Solution {
public:
    bool isPalindrome(int x) {
        // 特殊情况：负数不是回文；末尾为0且x≠0也不是回文
        if (x < 0 || (x % 10 == 0 && x != 0)) return false;
        
        int reversed_half = 0;
        while (x > reversed_half) {
            // 每次从 x 取出末位，追加到 reversed_half
            reversed_half = reversed_half * 10 + x % 10;
            x /= 10;
        }
        
        // 偶数位: x == reversed_half      (如 1221 → x=12, rev=12)
        // 奇数位: x == reversed_half / 10  (如 12321 → x=12, rev=123, 中间的3不影响)
        return x == reversed_half || x == reversed_half / 10;
    }
};
```

```
// 偶数位示例: x = 1221
// Step0: x=1221,  rev=0
// Step1: rev=0*10+1=1,    x=122     (x > rev? 122>1 ✓ 继续)
// Step2: rev=1*10+2=12,   x=12      (x > rev? 12>12 ✗ 停止)
// 比较: x(12) == rev(12) → true ✓
//
// 奇数位示例: x = 12321
// Step0: x=12321, rev=0
// Step1: rev=0*10+1=1,    x=1232    (x > rev? 1232>1 ✓)
// Step2: rev=1*10+2=12,   x=123     (x > rev? 123>12 ✓)
// Step3: rev=12*10+3=123, x=12      (x > rev? 12>123 ✗ 停止)
// 比较: x(12) == rev/10(12) → true ✓
//
// 非回文示例: x = 123
// Step0: x=123, rev=0
// Step1: rev=3,   x=12    (12>3 ✓)
// Step2: rev=32,  x=1     (1>32 ✗ 停止)
// 比较: 1≠32, 1≠3 → false ✓
```

**关键点**: 
- `while (x > reversed_half)` 是精髓——当反转部分追上或超过剩余部分时，说明已经过了中点。
- 末尾为 0 的提前排除是必需的，否则 10 会进入循环：x=1, rev=0，返回 `1==0` 错误。

## 解法对比
| | 转字符串 | 完整反转 | 反转一半 |
|---|---|---|---|
| 空间 | O(n) 字符串 | O(1) 但需 long | O(1) 且只用 int |
| 溢出风险 | 无 | 需要 long 兜底 | 完全没有 |
| 代码量 | 最少 | 适中 | 适中 |
| 面试评价 | 展示理解 | 合格 | 最佳 |
| 适用场景 | 快速实现 | 不允许字符串转换 | 追求最优 |

**面试首选解法3**：无额外空间、无溢出风险、代码简洁，完美回答 Follow-up。

## 易错点
1. **忘记处理末尾为 0 的情况**
   - ✗ `if (x < 0) return false;` 只排除负数
   - ✓ `if (x < 0 || (x % 10 == 0 && x != 0)) return false;` 还要排除末尾为 0 的非零数
   - 原因：10 → 循环后 x=1, rev=0，`1 != 0` 返回 false 是对的？不！是因为循环条件 `x > reversed_half` 第一次就是 `1 > 0` 为真，进入循环后 rev=0*10+0=0, x=1，然后 `1 > 0` 又为真，rev=0*10+1=1, x=0，退出。x(0)==rev(1)? No, x(0)==rev/10(0)? Yes! 返回 true！所以 **10 会被误判为回文**。

2. **完整反转时忘记保存原始值**
   - ✗ 反转完直接 `return reversed == x;`（此时 x 已经变成 0 了）
   - ✓ 先 `int original = x;` 再循环，最后 `return reversed == original;`

3. **奇数位回文忘记除以 10**
   - ✗ `return x == reversed_half;`（奇数位永远返回 false）
   - ✓ `return x == reversed_half || x == reversed_half / 10;`

## 面试追问
**Q1: 负数为什么一定不是回文？**
负号 `-` 只在数字最前面，反过来就到最后面了，不对称。所以负数直接返回 false。

**Q2: 完整反转数字时，正整数的回文数会溢出吗？**
不会。如果 x 是回文数，那反转后等于 x 自身，而 x 本身就在 int 范围内。但非回文数反转过程可能溢出，所以用 `long` 更安全。或者用解法3，反转一半完全规避溢出。

**Q3: 如果不允许用除法和取模运算，怎么做？**
可以用 `log10(x)` 得到最高位的位数，用 `pow(10, n-1)` 提取最高位，和最低位（用减法和位数推算）比较。或者退回字符串做法。这属于极端约束下的变体，实际面试中罕见。

**Q4: 这道题的思想可以扩展到哪些场景？**
"反转一半"的技巧可用于：判断链表回文（快慢指针找中点 + 反转后半段）、判断数组回文等。核心思想都是"只处理一半，避免全量操作"。
