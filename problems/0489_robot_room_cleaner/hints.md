# 489. 扫地机器人

## 核心思路

这道题本质上是：**在无法看到全局地图的情况下，用回溯（DFS）遍历所有可达的空单元格**。关键难点不在于遍历算法本身，而在于如何在"只有局部感知"的约束下正确管理方向和位置。

## 思维链

1. **读完题第一反应**：这就是一个图/矩阵的遍历问题——需要访问所有可达的空格。如果我有地图，直接 BFS/DFS 就行了。但问题是**我没有地图**，只能通过 API 控制机器人。

2. **核心约束分析**：机器人有"方向"的概念——它面朝某个方向，只能前进、左转、右转。不像普通 DFS 可以随意"跳"到某个邻居，机器人必须通过转向来切换移动方向。而且移动后，机器人的位置和朝向都变了。

3. **怎么确定"在哪"？**：机器人起始位置未知，但我可以自定义一个**相对坐标系**——把起始位置定为 `(0, 0)`，根据移动方向推算相对坐标。用 `set<pair<int,int>>` 记录已访问位置。

4. **怎么做 DFS？**：在当前位置，尝试四个方向。对于每个方向：转到该方向 → 尝试前进 → 如果成功且未访问过就递归 → 递归完**必须回退**到原位置、恢复原方向。

5. **回退怎么做？**：这是最关键的一步！回退 = 掉头（转180°）→ 前进一步 → 再掉头（恢复原来朝向）。这样机器人回到了进入递归前的位置和朝向。

6. **方向管理**：维护一个方向数组 `dirs = {上, 右, 下, 左}`，用一个变量 `d` 表示当前朝向索引。每次右转 `d = (d+1) % 4`。在当前位置，尝试 4 个方向时，每试完一个方向就右转一次，4 次右转后回到原来朝向。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 回溯 DFS + 相对坐标 | 以起点为原点建坐标系，DFS 遍历所有可达格子，每步尝试4方向并回退 | O(N-M) | O(N-M) | ⭐ 必须写出 |

> N = 网格总格子数，M = 障碍物数。实际访问每个空格常数次。

这道题本质上只有一种核心解法（回溯 DFS），因为你无法访问地图，BFS 无法实现（BFS 需要"跳跃"到队列中的节点，但机器人只能逐步移动）。

## 关键提示

1. **相对坐标**：你不知道绝对位置，但可以把起点设为 `(0,0)`，向上走就是 `(row-1, col)`，以此类推。已访问的集合用相对坐标记录。

2. **方向数组与机器人朝向的同步**：定义 `dirs = {(-1,0), (0,1), (1,0), (0,-1)}`（上、右、下、左）。机器人初始朝上。当你需要尝试下一个方向时，调用 `turnRight()` 并将方向索引 `+1`。

3. **回退操作**（最容易出错）：
```
// 回退 = 掉头 + 前进 + 掉头
//
// 状态: 机器人在 B，面朝 →（刚从 A 走到 B）
//
//   A → [B] →        turnRight, turnRight: A ← [B]
//                     move:                 [A] ← B
//                     turnRight, turnRight: [A] → B  (恢复原朝向)
```

4. **循环尝试 4 个方向的技巧**：在当前位置，从当前朝向开始，每次右转一次尝试前进，连续 4 次正好转一圈回到原朝向。

5. **为什么不能用 BFS？**：BFS 需要从队列中取出一个节点后直接"传送"过去处理。机器人无法传送，它必须物理地走过去。DFS + 回溯天然支持"走过去 → 递归 → 走回来"的模式。

## 解法详解

### 解法1: 回溯 DFS + 相对坐标 — O(N-M) / O(N-M) ⭐ 面试首选

**思考过程**：

想象你自己就是这个机器人，你在一个黑暗的房间里，只能感知正前方有没有墙。你会怎么做？

自然的策略是：**走到一个格子，打扫它，然后尝试四个方向，每个方向走到底（递归），走完回来继续尝试下一个方向**。这正是 DFS 回溯。

关键设计决策：
- **坐标系**：以起点为原点，不需要知道绝对位置
- **方向同步**：维护一个方向变量 `d`，和机器人的物理朝向始终一致
- **尝试顺序**：从当前朝向开始，每次右转，连续尝试 4 个方向
- **回退**：递归返回后，掉头走回来，再掉头恢复朝向

```
决策树示意（从 (0,0) 出发，朝上）:

                    (0,0) 朝上
                /     |      \      \
            尝试上  尝试右  尝试下  尝试左
              ↓
          move成功 → 递归到(-1,0)
              ↓
          在(-1,0)再尝试4方向...
              ↓
          全部尝试完 → 回退到(0,0)，恢复朝向
              ↓
          继续尝试右...
```

```
机器人回退操作详解:

假设机器人从 A 走到 B，当前面朝右:

Step 0:  A  [B]→        (在B，朝右)
Step 1:  A  [B]←        turnRight × 2 (掉头)
Step 2: [A]  B           move (回到A)  
Step 3: [A]→ B           turnRight × 2 (恢复原朝向:朝右)

注意: 回退后机器人在A，朝向和进入B之前一样!
```

```
完整 DFS 过程示例:
房间:
  1 1 0
  1 1 1
  0 1 1
起点 (0,0)=相对原点，朝上

  Step1: clean(0,0), 尝试上→墙, 尝试右→(0,1)未访问
  Step2:   move到(0,1), clean(0,1), 尝试上→墙, 尝试右→(0,2)墙
           尝试下→(1,1)未访问
  Step3:     move到(1,1), clean(1,1), ...继续DFS
             ...
           回退到(0,1)
         回退到(0,0)
  Step4: 继续尝试下→(1,0)未访问
  ...直到所有格子都访问过
```

```cpp
/**
 * // This is the robot's control interface.
 * // You should not implement it, or speculate about its implementation
 * class Robot {
 *   public:
 *     // Returns true if the cell in front is open and robot moves into the cell.
 *     // Returns false if the cell in front is obstacle and robot stays in the current cell.
 *     bool move();
 *
 *     // Robot will stay in the same cell after calling turnLeft/turnRight.
 *     // Each turn will be 90 degrees.
 *     void turnLeft();
 *     void turnRight();
 *
 *     // Clean the current cell.
 *     void clean();
 * };
 */

class Solution {
public:
    // 方向数组: 上、右、下、左（与机器人初始朝上对应）
    // 每次 turnRight 就是方向索引 +1
    int dirs[4][2] = {{-1, 0}, {0, 1}, {1, 0}, {0, -1}};
    set<pair<int, int>> visited;
    
    void cleanRoom(Robot& robot) {
        // 起点设为相对坐标 (0, 0)，初始方向为 0（朝上）
        dfs(robot, 0, 0, 0);
    }
    
    void dfs(Robot& robot, int row, int col, int d) {
        // 清扫当前格子，标记已访问
        robot.clean();
        visited.insert({row, col});
        
        // 从当前朝向开始，尝试 4 个方向
        for (int i = 0; i < 4; i++) {
            int newD = (d + i) % 4;
            int newRow = row + dirs[newD][0];
            int newCol = col + dirs[newD][1];
            
            // 如果该方向的格子未访问过，且机器人能走过去
            if (visited.find({newRow, newCol}) == visited.end() && robot.move()) {
                dfs(robot, newRow, newCol, newD);
                // 回退：掉头 → 前进 → 掉头（回到原位，恢复原朝向）
                goBack(robot);
            }
            // 右转一次，准备尝试下一个方向
            robot.turnRight();
        }
        // 4 次 turnRight 后，机器人朝向回到进入时的方向 d
    }
    
    void goBack(Robot& robot) {
        // 掉头（转180度）
        robot.turnRight();
        robot.turnRight();
        // 走回去
        robot.move();
        // 再掉头（恢复原来朝向）
        robot.turnRight();
        robot.turnRight();
    }
};
```

**关键点**：
- `for` 循环中的 4 次 `turnRight` 让机器人转了一整圈，回到进入 `dfs` 时的朝向
- `goBack` 之后机器人的朝向和进入子递归之前一样（因为掉头走回来再掉头 = 净效果为零）
- `newD = (d + i) % 4` 正确计算了每次右转后的实际方向

## 解法对比

| | 回溯 DFS |
|---|---|
| 时间 | O(N-M)，每个空格访问常数次 |
| 空间 | O(N-M)，visited 集合 + 递归栈 |
| 适用场景 | 机器人只能局部感知、逐步移动的场景 |
| 为什么不能BFS | 机器人无法"传送"到队列中的下一个节点 |

## 易错点

1. **方向不同步**：
   - ✗ 在 `dfs` 中用固定的 `{上, 右, 下, 左}` 顺序，而不考虑机器人当前实际朝向
   - ✓ 用 `newD = (d + i) % 4` 配合每次 `turnRight`，保持逻辑方向和物理朝向同步

2. **回退后方向错误**：
   - ✗ 回退只做 `turnRight × 2 + move`，忘了再转回来
   - ✓ 完整的回退是：`turnRight × 2 → move → turnRight × 2`（掉头走回来再掉头）

3. **先 move 再检查 visited**：
   - ✗ `if (!visited.count(...)) { robot.move(); ... }` — 没检查 move 是否成功（可能是墙）
   - ✓ `if (!visited.count(...) && robot.move())` — 两个条件都要满足

4. **忘记在 for 循环体最后 turnRight**：
   - ✗ 只在进入下一方向时转向，导致方向混乱
   - ✓ 每次循环末尾无条件 `turnRight()`，保证 4 次后回到原方向

5. **visited 检查时用绝对坐标**：
   - ✗ 试图获取机器人的绝对坐标（API 不提供）
   - ✓ 用相对坐标 `(row, col)`，起点为 `(0, 0)`

## 面试追问

**Q1: 为什么选 DFS 而不是 BFS？**

> BFS 需要从队列中取出下一个待处理节点后"传送"过去，但机器人只能通过 `move()` 逐步移动。DFS + 回溯天然支持"走过去→处理→走回来"的模式，机器人始终沿着一条路径深入再原路返回。

**Q2: 时间复杂度为什么是 O(N-M)？每个格子不是被尝试了多次吗？**

> 每个空格最多作为"当前格"被 clean 一次。在 DFS 过程中，每个空格作为邻居被检查的次数最多 4 次（从 4 个方向来）。每次检查是 O(1)（查 visited + 可能尝试 move）。回退操作也是 O(1)。所以总操作次数是 O(4(N-M)) = O(N-M)。

**Q3: 如果机器人没有 `turnLeft` API，只有 `turnRight`，算法需要改吗？**

> 不需要！我们的算法本来就只用了 `turnRight`。`turnLeft` 转 1 次 = `turnRight` 转 3 次，所以 `turnRight` 足以实现所有旋转。

**Q4: 如果房间非常大（比如 10^6 个格子），递归栈会溢出吗？怎么处理？**

> 最坏情况下递归深度等于空格数（一条长蛇形路径），确实可能栈溢出。解决方案：
> 1. 系统级增大栈空间
> 2. 将递归改为迭代，用显式栈模拟。但对于这道交互题，迭代实现更复杂，因为需要手动管理"回退到哪"的状态。实际面试中提到这个 concern 并说明 trade-off 就够了。

**Q5: 如果不是所有空格都从起点可达怎么办？**

> 题目保证"所有空单元格都可以从起始位置出发访问到"。如果不保证，那么单个机器人的 DFS 天然只能覆盖连通分量，不可达的区域无法清扫（物理限制）。
