# 946. 验证栈序列

## 核心思路

给定入栈序列 `pushed` 和出栈序列 `popped`，判断 `popped` 是否是合法的出栈顺序。核心方法是 **模拟**：用一个辅助栈，按照 `pushed` 的顺序逐个入栈，每次入栈后检查栈顶是否等于 `popped` 的当前期望值——如果相等就弹出（贪心地尽早弹出）。遍历完 `pushed` 后，如果栈为空，说明 `popped` 序列合法。

## 思维链

1. **读完题第一反应** → 这是一个栈操作的模拟题。给定了 push 和 pop 的序列，需要验证是否存在一种合法的操作顺序。
2. **暴力思路？** → 枚举所有可能的 push/pop 交替顺序？复杂度爆炸（指数级），不可行。
3. **有什么规律？** → 入栈顺序固定（必须按 pushed 顺序），但每次 push 后可以选择 pop 或继续 push。关键观察：**如果栈顶等于 popped 的当前期望值，那么这个 pop 操作必须立即执行**——因为如果不弹出，后续 push 的元素会压在上面，这个元素就永远无法在正确的时机被弹出。
4. **贪心策略** → 每次 push 后，尽可能多地弹出（只要栈顶 == popped[j]，就弹出并移动 j）。这是贪心的：能弹就弹，不弹一定不行。
5. **终止条件** → pushed 全部入栈后，如果栈为空说明 popped 完全匹配，返回 true；否则 false。

```

操作步骤           栈状态 (底→顶)    popped 指针 j    说明
────────────────   ───────────────   ──────────────   ──────────
push(1)            [1]               j=0 (期望4)      1≠4, 不弹
push(2)            [1, 2]            j=0 (期望4)      2≠4, 不弹

                   [1, 2]            pushed 遍历完     栈不为空 ✗
```

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 辅助栈模拟 | 用 stack 模拟 push/pop | O(n) | O(n) | 必须写出 |
| 数组模拟栈 | 用 pushed 数组本身当栈 | O(n) | O(1) | 进阶优化 |

## 关键提示

1. **贪心弹出的正确性**：为什么"能弹就弹"一定是对的？反证法：假设栈顶等于 popped[j]，但我们选择不弹而继续 push。那么后续 push 的元素会压在当前栈顶上面，而 popped[j] 要求这个元素必须先弹出，但它已经被埋住了，矛盾。所以**必须立即弹出**。

2. **为什么只需遍历 pushed 一次？** pushed 的每个元素恰好被 push 一次、最多被 pop 一次。总操作次数 O(2n) = O(n)。

3. **元素互不相同是关键**：题目保证 pushed 中的元素互不相同，所以栈顶和 popped[j] 的比较是确定性的——要么相等（必须弹），要么不等（不能弹）。如果有重复元素，贪心策略可能需要调整。

4. **popped 是 pushed 的排列**：题目保证 popped 是 pushed 的一个排列，所以不需要考虑"popped 中有 pushed 中不存在的元素"的情况。

5. **空间优化思路**：可以复用 pushed 数组作为栈，用一个"栈顶指针"变量来模拟 push/pop，从而将空间降到 O(1)。

## 解法详解

### 解法1: 辅助栈模拟 — O(n) / O(n) -- 面试首选

**思考过程**: 直接模拟栈操作。遍历 pushed，逐个入栈。每次入栈后，检查栈顶是否等于 popped 中下一个要弹出的元素，如果是则弹出。

```cpp
class Solution {
public:
    bool validateStackSequences(vector<int>& pushed, vector<int>& popped) {
        stack<int> stk;
        int j = 0; // popped 的指针，指向下一个期望弹出的元素
        for (int x : pushed) {
            stk.push(x);
            // 贪心: 只要栈顶等于期望弹出值，就弹出
            while (!stk.empty() && stk.top() == popped[j]) {
                stk.pop();
                j++;
            }
        }
        return stk.empty(); // 栈为空说明所有元素都正确弹出
    }
};
```

**关键点**:
- 内层 while 循环可能连续弹出多个元素（如示例2中 push(4) 后连续弹出 4 和 3）。
- `j` 指针只增不减，总共移动 n 次，所以总时间复杂度仍是 O(n)。
- `stk.empty()` 检查必须放在 `stk.top()` 之前（短路求值），否则空栈调用 top() 是未定义行为。

---

### 解法2: 原地模拟（空间优化）— O(n) / O(1)

**从解法1优化**: 观察到 pushed 数组在元素被 push 进辅助栈后就不再需要了。我们可以直接把 pushed 数组当成栈来用，用一个变量 `top` 模拟栈顶指针。

```
原理:
pushed = [1, 2, 3, 4, 5]
当我们"push"到 pushed[i] 时，pushed[0..top] 就是栈的内容。
"pop" 操作只需 top--。
"push" 操作把值写到 pushed[++top]（实际上就是 pushed[i] 本身）。

这样省掉了额外的 stack<int>，空间 O(1)。
```

```cpp
class Solution {
public:
    bool validateStackSequences(vector<int>& pushed, vector<int>& popped) {
        int top = -1; // 栈顶指针，-1 表示空栈
        int j = 0;    // popped 的指针
        for (int x : pushed) {
            pushed[++top] = x; // push: 栈顶指针上移，写入值
            // 贪心弹出: 栈顶等于期望弹出值
            while (top >= 0 && pushed[top] == popped[j]) {
                top--; // pop: 栈顶指针下移
                j++;
            }
        }
        return top == -1; // 栈为空
    }
};
```

**关键点**:
- `pushed[++top] = x` 等价于 `top++; pushed[top] = x;`，利用 pushed 数组的前半部分作为栈。
- `top >= 0` 等价于 `!stk.empty()`。
- **不创建额外数据结构**，空间复杂度 O(1)（不计输入数组）。
- 代价是修改了输入数组 pushed（面试中需说明这一点）。

## 贪心策略正确性证明

```
命题: 如果栈顶 == popped[j]，必须立即弹出。

证明 (反证法):
假设栈顶 s.top() == popped[j]，但我们不弹出，而是继续 push 下一个元素 x。
此时栈变为 [..., s.top(), x]。

由于 popped 要求 popped[j] 在 popped[j+1], popped[j+2], ... 之前弹出，
而 s.top() (= popped[j]) 现在被 x 压在下面了。

要弹出 s.top()，必须先弹出 x。但 popped 序列中 s.top() 在 x 之前
（popped[j] 对应 s.top()，x 一定在更后面），说明 x 应该在 s.top() 
之后才被弹出。矛盾！

因此，当栈顶 == popped[j] 时，必须立即弹出。贪心策略是唯一正确的选择。
```

## 易错点

1. **空栈访问 top()**：
   - ✗ `while (stk.top() == popped[j] && !stk.empty())` → 空栈时先执行 top() 崩溃
   - ✓ `while (!stk.empty() && stk.top() == popped[j])` → 短路求值，空栈不执行 top()

2. **j 越界**：
   - 理论上不会越界（pushed 和 popped 长度相同，且 popped 是排列），但防御性编程可以加 `j < n`。

3. **忘记是 while 不是 if**：
   - ✗ `if (stk.top() == popped[j])` → 只弹一次，漏掉连续弹出的情况
   - ✓ `while (...)` → 循环弹出，直到栈顶不匹配或栈空

4. **原地解法中 top 初值错误**：
   - ✗ `int top = 0;` → 第一次 push 时 `pushed[++top]` 写到 index 1，跳过了 index 0
   - ✓ `int top = -1;` → 第一次 push 时 `pushed[++top]` = `pushed[0]`

5. **混淆入栈顺序和出栈顺序**：
   - 入栈顺序是固定的（必须按 pushed 顺序），出栈顺序是我们要验证的。
   - 不能随意改变 pushed 的遍历顺序。

## 面试追问

**Q1: 贪心为什么是对的？可以不贪心吗？**
> 不能。如果栈顶等于期望弹出值却不弹出，后续 push 的元素会压在上面，导致这个元素无法在正确时机被弹出。见上面的正确性证明。

**Q2: 时间复杂度为什么是 O(n) 而不是 O(n^2)?**
> 虽然有两层循环（外层 for + 内层 while），但每个元素最多被 push 一次、pop 一次。内层 while 的总执行次数不超过 n 次。用摊还分析：n 次 push + 最多 n 次 pop = O(2n) = O(n)。

**Q3: 如果元素可以重复怎么办？**
> 贪心策略仍然正确，因为我们比较的是栈顶的具体值和 popped 的期望值。但需要注意：重复元素意味着有多种合法的 pop 顺序，本题只需要判断给定的 popped 是否合法，贪心模拟仍然适用。

**Q4: 能否用 O(1) 空间且不修改输入？**
> 在不修改输入的前提下，需要额外空间来模拟栈。最优是 O(n)。如果允许修改 pushed（面试中通常可以），则用原地解法 O(1)。
