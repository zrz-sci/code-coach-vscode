# 141. 环形链表

## 核心思路

本质上在问：遍历链表时，是否会走到一个之前已经访问过的节点？也就是说，如何检测"重复访问"。

## 思维链

1. **读完题第一反应**：如果没有环，遍历链表最终会遇到 `nullptr`；如果有环，遍历会无限循环。那问题就是——怎么区分"还没走完"和"已经在绕圈了"？

2. **最朴素的想法**：每访问一个节点，记下来"我来过这里"。如果后面再碰到同一个节点，说明有环。用什么记？**哈希集合**记录访问过的节点指针。

3. **哈希解法的瓶颈**：需要 O(n) 额外空间存储所有访问过的节点。题目 Follow-up 问能否 O(1) 空间？

4. **突破方向**：经典的**快慢指针（Floyd 判圈算法）**。想象两个人在操场跑步，一个快一个慢——如果操场是环形的，快的人一定会追上慢的人（套圈）；如果是直线跑道，快的人先到终点。

5. **为什么快慢指针一定能相遇？** 假设慢指针进入环后，快指针在它前面 k 步。每走一步，快指针多走 1 步，距离缩小 1。所以 k 步之后一定会追上（距离从 k 递减到 0）。

6. **确定步速**：快指针每次走 2 步，慢指针每次走 1 步。这是最简单且一定能相遇的配置。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 哈希集合 | 记录访问过的节点，遇到重复即有环 | O(n) | O(n) | 能说出即可 |
| 快慢指针 | 快指针追慢指针，相遇即有环 | O(n) | O(1) | ⭐ 必须写出 |

## 关键提示

- **提示1**：不要比较节点的值（val 可能重复），要比较**节点指针**（地址唯一标识一个节点）。

- **提示2**：快慢指针中，循环条件应该检查什么？快指针走得快，所以要检查 `fast` 和 `fast->next` 是否为空。

- **提示3**：画出指针的运动过程，感受"距离每轮缩小1"的直觉：

```
// 示例: 3 → 2 → 0 → -4
//            ↑         |
//            └─────────┘
//
// Step0: slow=3, fast=3
// Step1: slow=2, fast=0     (距离: fast在环中领先slow)
// Step2: slow=0, fast=2     (在环中追赶)
// Step3: slow=-4, fast=-4   ← 相遇！有环！
```

- **提示4**：空链表和只有一个节点且无环的链表是边界情况，两种解法都能自然处理。

## 解法详解

### 解法1: 哈希集合 — O(n) / O(n)

**思考过程**：最直觉的方法——"我怎么知道走过重复的路？" 记下走过的每个节点，如果再次遇到就说明有环。用哈希集合（`unordered_set`）存节点指针，查找是 O(1)。

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;
 *     ListNode *next;
 *     ListNode(int x) : val(x), next(NULL) {}
 * };
 */
class Solution {
public:
    bool hasCycle(ListNode *head) {
        unordered_set<ListNode*> visited;
        ListNode* curr = head;
        while (curr != nullptr) {
            // 如果这个节点之前见过，说明绕回来了 → 有环
            if (visited.count(curr)) {
                return true;
            }
            visited.insert(curr);
            curr = curr->next;
        }
        // 走到 nullptr 说明链表有终点，无环
        return false;
    }
};
```

**关键点**：存的是**指针**（节点地址），不是节点的值。两个不同节点可以有相同的 val，但地址一定不同。

---

### 解法2: 快慢指针（Floyd 判圈） — O(n) / O(1) ⭐ 面试首选

**从解法1优化**：解法1的瓶颈是 O(n) 空间。快慢指针利用了一个物理直觉：在环形跑道上，跑得快的人一定会套圈追上跑得慢的人。

**为什么 O(n) 时间就够？**
- 如果无环：快指针先到终点，循环次数 ≤ n/2 = O(n)
- 如果有环：慢指针进入环后，快指针最多绕环一圈就能追上（因为每步距离缩小 1，环长 ≤ n）

```
// 快慢指针运动示意:
//
// 无环情况: 1 → 2 → 3 → 4 → NULL
//   Step0: s=1, f=1
//   Step1: s=2, f=3
//   Step2: s=3, f=NULL → fast到终点，无环
//
// 有环情况: 3 → 2 → 0 → -4 ─┐
//               ↑              |
//               └──────────────┘
//   Step0: s=3,  f=3
//   Step1: s=2,  f=0     (都在往前走)
//   Step2: s=0,  f=2     (fast已经绕进环)
//   Step3: s=-4, f=-4    ← 相遇! 返回true
```

```cpp
class Solution {
public:
    bool hasCycle(ListNode *head) {
        ListNode* slow = head;
        ListNode* fast = head;
        
        // fast 每次走2步, slow 每次走1步
        // 循环条件: fast 和 fast->next 都不为空 (因为fast走两步)
        while (fast != nullptr && fast->next != nullptr) {
            slow = slow->next;        // 慢指针走1步
            fast = fast->next->next;  // 快指针走2步
            
            // 注意: 先移动再判断，避免初始时 slow==fast==head 误判
            if (slow == fast) {
                return true;  // 相遇 → 有环
            }
        }
        
        // fast 走到了终点(nullptr) → 无环
        return false;
    }
};
```

**关键点**：必须**先移动指针，再判断是否相等**。如果先判断再移动，初始时 slow 和 fast 都指向 head，会立刻误判为有环。

**面试策略**：先主动说"可以用哈希集合 O(n) 空间"，然后立刻说"但可以用快慢指针优化到 O(1) 空间"，直接写解法2。

## 易错点

1. **✗ 先判断再移动**：
   ```cpp
   while (...) {
       if (slow == fast) return true;  // ✗ 第一轮就 true 了！
       slow = slow->next;
       fast = fast->next->next;
   }
   ```
   **✓ 先移动再判断**：因为初始时 slow == fast == head，必须先走一步再比较。

2. **✗ 循环条件只检查 fast != nullptr**：
   ```cpp
   while (fast != nullptr) {  // ✗ fast->next 可能为空
       fast = fast->next->next;  // 空指针解引用！
   }
   ```
   **✓ 同时检查 fast 和 fast->next**：`while (fast && fast->next)`，因为 fast 每次要走两步。

3. **✗ 用 val 比较代替指针比较**：
   ```cpp
   if (slow->val == fast->val)  // ✗ 不同节点可以有相同的值！
   ```
   **✓ 用指针比较**：`if (slow == fast)`，比较的是内存地址。

## 面试追问

**Q1（基础理解）**：为什么快慢指针在环中一定会相遇？不会一直错过吗？

> 慢指针进入环后，设快指针在它前面距离 d。每一步快指针多走 1 步，所以距离每轮减少 1（d, d-1, d-2, ..., 1, 0）。d 步后一定距离为 0，即相遇。不存在"跳过"的情况，因为距离是连续递减的。

**Q2（进阶）**：如果不仅要判断有没有环，还要找到**环的入口节点**，怎么做？（即 LeetCode 142）

> 相遇后，让一个指针回到 head，另一个留在相遇点，两者都每次走 1 步，再次相遇的节点就是环入口。数学证明：设头到入口距离 a，入口到相遇点距离 b，相遇点到入口距离 c。fast 走了 a+b+c+b，slow 走了 a+b，且 fast = 2×slow → a = c。

**Q3（变体）**：如果快指针每次走 3 步，慢指针每次走 1 步，还能判环吗？

> 可以，但不如 2:1 简单。每步距离缩小 2，如果环长为奇数，距离序列 d, d-2, d-4, ... 可能跳过 0 到 -1 再到环长-1，需要更多轮。2:1 的配置保证距离严格递减 1，是最简洁可靠的。
