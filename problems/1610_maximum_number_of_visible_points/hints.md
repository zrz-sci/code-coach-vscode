# 1610. 可见点的最大数目

## 核心思路

本质上是：把所有点转化为相对于 location 的**极角**（角度），然后在一个**排序后的角度数组**上找一个宽度为 `angle` 的窗口，使得窗口内包含的点最多。这是一个经典的**排序 + 滑动窗口**问题。

## 思维链

1. **读完题第一反应**：站在 location，转动视野（宽度为 angle 度），问最多能看到多少个点。暴力想法：枚举所有可能的视野起始角度，数每个角度下能看到多少点。但起始角度是连续的，怎么枚举？

2. **关键观察**：最优视野的边界一定"卡"在某个点上。因为如果没有点在边界上，我们可以微调角度而不改变结果。所以只需要枚举每个点作为视野左边界。

3. **角度转化**：用 `atan2(dy, dx)` 把每个点相对于 location 的方向转化为角度（弧度或度数）。与 location 重合的点需要特殊处理——它们无论怎么转都能看到。

4. **环形问题**：角度是环形的（0° 和 360° 相邻）。处理方式：排序后，把整个数组复制一份并每个角度加 360°，拼接到末尾。这样线性滑动窗口就能处理跨 0°/360° 的情况。

5. **滑动窗口**：在排好序（且复制拼接后的）角度数组上，用双指针/滑动窗口，右端 - 左端 ≤ angle 时右指针前进，否则左指针前进。窗口大小的最大值 + 重合点数 = 答案。

6. **复杂度**：计算角度 O(n)，排序 O(n log n)，滑动窗口 O(n)，总体 O(n log n)。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举每个点作为起始边界，遍历所有点计数 | O(n²) | O(n) | 能说出即可 |
| 排序 + 滑动窗口 | 角度排序 + 环形展开 + 双指针 | O(n log n) | O(n) | ⭐ 必须写出 |

## 关键提示

1. **与 location 重合的点要先分离出来**，它们总是可见的，不参与角度计算（`atan2(0,0)` 未定义）。

2. **atan2 返回弧度**，范围是 `(-π, π]`，你可以转成度数 `(-180, 180]` 方便和 `angle` 比较；也可以全程用弧度，把 `angle` 转成弧度。

3. **环形展开是核心技巧**：排序后的角度数组是 `[a₀, a₁, ..., aₙ₋₁]`，拼接 `[a₀+360, a₁+360, ..., aₙ₋₁+360]`，在长度为 2n 的数组上做滑动窗口。

4. **浮点精度**：比较角度差时用 `angles[right] - angles[left] <= angle + 1e-9` 来容忍浮点误差。

5. **视野范围是闭区间**：边界上的点也算可见。

```
// 环形展开示意（角度排序后）:
// 原始: [30, 60, 150, 300]
// 展开: [30, 60, 150, 300, 390, 420, 510, 660]
//                          ↑ 30+360  ↑ 60+360 ...
//
// 如果 angle = 120:
// 窗口 [300, 390] 包含 300° 和 30°(=390-360) → 跨越了0°
```

## 解法详解

### 解法1: 暴力枚举 — O(n²) / O(n)

**思考过程**：对每个非重合点作为视野的起始边界，检查其他所有点是否在 `[该角度, 该角度 + angle]` 的范围内。需要处理环形（跨 360° 的情况）。

```cpp
class Solution {
public:
    int visiblePoints(vector<vector<int>>& points, int angle, vector<int>& location) {
        int same = 0; // 与 location 重合的点
        vector<double> angles;
        
        for (auto& p : points) {
            int dx = p[0] - location[0];
            int dy = p[1] - location[1];
            if (dx == 0 && dy == 0) {
                same++;
                continue;
            }
            // atan2 返回弧度 (-π, π]，转成度数 (-180, 180]
            double deg = atan2(dy, dx) * 180.0 / M_PI;
            if (deg < 0) deg += 360.0; // 统一到 [0, 360)
            angles.push_back(deg);
        }
        
        int n = angles.size();
        int maxVisible = 0;
        
        // 枚举每个点作为视野的左边界
        for (int i = 0; i < n; i++) {
            int count = 0;
            for (int j = 0; j < n; j++) {
                // 计算 angles[j] 是否在 [angles[i], angles[i] + angle] 范围内
                double diff = angles[j] - angles[i];
                if (diff < -1e-9) diff += 360.0; // 处理环形
                if (diff <= angle + 1e-9) {
                    count++;
                }
            }
            maxVisible = max(maxVisible, count);
        }
        
        return maxVisible + same;
    }
};
```

**关键点**：当 n = 10⁵ 时，O(n²) ≈ 10¹⁰，会超时。瓶颈在于对每个起始角度，都要遍历所有点来计数。

---

### 解法2: 排序 + 滑动窗口 — O(n log n) / O(n) ⭐ 面试首选

**从解法1优化**：解法1的瓶颈是"对每个左边界，线性扫描计数"。如果角度排好序，就可以用滑动窗口：左边界右移时，右边界只增不减，每个点最多进出窗口各一次，总共 O(n)。

环形问题的处理：把排序后的角度数组复制一份（每个加 360°）拼在后面。

```
// 滑动窗口示意:
// 角度(排序后): [30, 60, 150, 300 | 390, 420, 510, 660]
//                                   ← 复制+360 →
// angle = 100
//
// left=0(30°):  right扫到 150° 时, 150-30=120 > 100, 停
//               窗口 [30, 60], count=2
// left=1(60°):  right从之前位置继续, 150-60=90 ≤ 100, 继续
//               窗口 [60, 150], count=2
// left=2(150°): right到 300, 300-150=150 > 100, 停
//               窗口 [150], count=1
// left=3(300°): right到 390, 390-300=90 ≤ 100, 继续
//               窗口 [300, 390(=30°)], count=2  ← 跨越了0°!
// ...
// 最大 count + same = 答案
```

```cpp
class Solution {
public:
    int visiblePoints(vector<vector<int>>& points, int angle, vector<int>& location) {
        int same = 0;
        vector<double> angles;
        
        for (auto& p : points) {
            int dx = p[0] - location[0];
            int dy = p[1] - location[1];
            if (dx == 0 && dy == 0) {
                same++;
                continue;
            }
            // atan2 返回 (-π, π]，转成度数
            double deg = atan2(dy, dx) * 180.0 / M_PI;
            if (deg < 0) deg += 360.0; // 归一化到 [0, 360)
            angles.push_back(deg);
        }
        
        // 排序
        sort(angles.begin(), angles.end());
        
        // 环形展开：复制一份并加 360°
        int n = angles.size();
        for (int i = 0; i < n; i++) {
            angles.push_back(angles[i] + 360.0);
        }
        
        // 滑动窗口：找最大的 right - left 使得 angles[right] - angles[left] <= angle
        int maxVisible = 0;
        int right = 0;
        for (int left = 0; left < n; left++) {
            // right 只增不减，因为 left 增大时，右边界不会回退
            while (right < 2 * n && angles[right] - angles[left] <= (double)angle + 1e-9) {
                right++;
            }
            // 窗口内的点数 = right - left
            maxVisible = max(maxVisible, right - left);
        }
        
        return maxVisible + same;
    }
};
```

**关键点**：
- `right` 在整个外循环中只增不减，所以内层 while 总计执行 O(n) 次，不是 O(n²)
- 浮点精度用 `1e-9` 容忍

## 解法对比

| | 暴力枚举 | 排序 + 滑动窗口 |
|---|---|---|
| 时间 | O(n²) | O(n log n) |
| 空间 | O(n) | O(n) |
| 核心操作 | 对每个左边界暴力计数 | 排序后双指针一次扫描 |
| 环形处理 | 计算角度差时取模 | 复制数组 +360° |
| 能否通过 | ✗ n=10⁵ 超时 | ✓ |

选择建议：面试直接写排序 + 滑动窗口。暴力解用于口述"最朴素的想法"。

## 易错点

1. **忘记处理重合点**
   - ✗ 把与 location 重合的点也算 `atan2(0,0)`，结果未定义（C++ 中 `atan2(0,0)` 返回 0，但语义错误）
   - ✓ 先单独计数 `same`，最后加回结果

2. **角度归一化不一致**
   - ✗ 有的角度在 `(-180, 180]`，有的在 `[0, 360)`，混用导致比较错误
   - ✓ 统一用 `if (deg < 0) deg += 360.0` 归一化到 `[0, 360)`

3. **环形展开遗漏**
   - ✗ 只在原始角度数组上滑动窗口，漏掉跨越 0°/360° 的视野
   - ✓ 复制一份加 360° 拼接

4. **浮点精度**
   - ✗ 用 `angles[right] - angles[left] <= angle` 严格比较，浮点误差导致边界上的点被漏掉
   - ✓ 加 `1e-9` 容忍：`<= angle + 1e-9`

5. **right 的初始化位置**
   - ✗ 每次 left 移动时 right 重置为 left，变成 O(n²)
   - ✓ right 声明在循环外，只增不减

## 面试追问

**Q1: 为什么最优视野的边界一定卡在某个点上？**
> 如果视野边界没有卡在任何点上，那么我们可以微调起始角度（左右移动一点点），可见点集合不变。所以最优解一定可以在"某个点恰好在视野左边界上"时取得。这意味着我们只需枚举 n 个离散的起始位置。

**Q2: 能否不转度数，全程用弧度？**
> 可以。把 `angle` 转成弧度 `angle * M_PI / 180.0`，所有比较都在弧度域进行。避免了度数转换的代码，但要注意弧度下 360° = 2π。复制时加 `2 * M_PI` 而不是 360。

**Q3: 如果 angle = 360（或接近 360），需要特殊处理吗？**
> 不需要。当 angle ≥ 360 时，所有点都可见，滑动窗口自然会把所有点包含进来（窗口宽度 360° 覆盖了整个圆）。代码无需特判。

**Q4: 如果有大量查询（不同的 angle 值，同一组 points），如何优化？**
> 角度数组排序只需做一次 O(n log n)。对每个 angle 值，滑动窗口是 O(n) 的。所以 q 次查询总共 O(n log n + q·n)。如果进一步优化，可以对每个左端点预处理右边界（二分查找 `upper_bound`），每次查询 O(n log n) 降到 O(n log n)... 实际上滑动窗口已经是 O(n) 了，很难再优。
