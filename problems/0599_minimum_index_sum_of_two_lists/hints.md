# 599. 两个列表的最小索引总和 (Minimum Index Sum of Two Lists)

## 核心思路
用哈希表存储一个列表的字符串到索引的映射，遍历另一个列表找公共字符串并追踪最小索引和。

## 思维链
1. 需要找两个列表的公共字符串 → 交集问题 → 哈希表
2. 公共字符串可能有多个，需要索引和最小的 → 维护当前最小索引和
3. 把 list1 存入 HashMap<string, index>
4. 遍历 list2，查找 list2[j] 是否在 map 中
5. 如果在，计算 i + j，与当前最小和比较
6. 相等则加入结果，更小则清空结果重新加入

## 解法概览表

| 解法 | 思路 | 时间复杂度 | 空间复杂度 | 难度 |
|------|------|-----------|-----------|------|
| 哈希表 ⭐ | 一个列表建 map，遍历另一个 | O(n+m) | O(n) | Easy |
| 暴力枚举 | 双重循环逐个比较 | O(n*m*L) | O(1) | Easy |

## 关键提示
1. **选较短的列表建 map**: 优化空间
2. **提前终止**: 遍历 list2 时如果 j 已经大于当前最小和，可以跳过（因为 i >= 0）
3. **字符串列表各自唯一**: 不需要考虑同一列表内重复

## 解法详解

### 解法一：哈希表 ⭐
```
map = {} // string -> index
for i, s in list1: map[s] = i
minSum = INT_MAX, result = []
for j, s in list2:
    if s in map:
        sum = map[s] + j
        if sum < minSum:
            minSum = sum
            result = [s]
        elif sum == minSum:
            result.append(s)
return result
```

### 解法二：暴力枚举
双重循环比较每一对，记录最小索引和。时间 O(n*m*L)，L 是字符串比较开销。

## 易错点

| ✗ 错误写法 | ✓ 正确写法 | 原因 |
|-----------|-----------|------|
| 找到一个就返回 | 收集所有最小索引和的结果 | 可能有多个公共字符串索引和相同 |
| minSum 初始化为 0 | minSum 初始化为 INT_MAX | 0 会导致没有结果被收集 |
| 不检查 map.count() | 先检查是否存在再访问 | 不存在的 key 访问会创建默认值 |

## 面试追问

**Q1: 如果列表很大（10^6 量级），如何优化？**
选较短的列表建 map。遍历较长列表时可以提前终止：当 j > minSum 时，后续的 i+j 只会更大（因为 i >= 0），可以 break。

**Q2: 如果不止两个列表，要找三个列表的公共字符串最小索引和呢？**
可以用 map<string, vector<int>> 存储每个字符串在各列表中的索引，遍历所有列表更新索引，最后遍历 map 找出现在所有列表中且索引总和最小的。

**Q3: 字符串列表不唯一（有重复）怎么处理？**
建 map 时只保留第一次出现的索引（最小索引），因为我们要最小索引和。
