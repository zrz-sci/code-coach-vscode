# 814. Binary Tree Pruning - 提示与解析

## 核心思路

本题要求删除二叉树中所有**不包含值为1的节点的子树**。核心方法是**后序遍历（Post-order DFS）**：先递归处理左右子树，再决定当前节点是否需要被剪掉。如果一个节点的左右子树都被剪掉了（变成 null），且该节点自身的值也是0，那么这个节点也应该被剪掉。后序遍历保证了"先处理子树、再处理自身"的正确顺序。

## 思维链

1. **理解剪枝条件**：一个子树被剪掉，当且仅当该子树中不包含任何值为1的节点
2. **选择遍历顺序**：后序遍历（左-右-根）是最自然的选择，因为需要先知道子树的情况
3. **递归返回值**：递归函数返回剪枝后的子树根节点（可能为 null）
4. **剪枝判断**：递归处理完左右子树后，如果左右都为 null 且当前节点值为0，返回 null
5. **根节点也可能被剪**：如果整棵树都是0，应返回 null
6. **边界情况**：空节点直接返回 null

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 适用场景 |
|------|-----------|-----------|---------|
| 后序遍历递归 | O(n) | O(h)，h为树高 | 标准最优解 |
| 迭代后序遍历 | O(n) | O(n) | 避免递归栈溢出 |
| 两遍遍历（先标记再删除） | O(n) | O(n) | 思路分步，更易理解 |

## 关键提示

1. **后序遍历是关键**：必须先处理完子节点，才能判断当前节点是否需要保留。前序或中序无法做到这一点
2. **递归函数的语义**：pruneTree(node) 返回剪枝后的节点。如果整个子树不含1，返回 nullptr
3. **修改指针而非值**：通过将 left/right 设为 nullptr 来"剪掉"子树，不是修改节点值
4. **根节点特殊性**：根节点也可能被剪掉，所以函数返回值可能是 nullptr
5. **节点值只有0和1**：简化了判断逻辑，只需检查 val == 0 且无子节点

## 解法详解

### 解法一：后序遍历递归（推荐）

**递归逻辑**：
```
pruneTree(node):
    if node is null: return null
    
    node.left = pruneTree(node.left)    // 先递归处理左子树
    node.right = pruneTree(node.right)  // 再递归处理右子树
    
    // 后序处理：如果当前节点值为0且左右子树都已被剪掉
    if node.val == 0 and node.left == null and node.right == null:
        return null   // 剪掉当前节点
    
    return node  // 保留当前节点
```

**执行过程示例**（输入 [1,null,0,0,1]）：
1. 根节点1，进入右子树
2. 右子节点0，进入其左子树
3. 左叶子0：val=0且无子节点 -> 返回 null
4. 右叶子1：val=1 -> 保留，返回该节点
5. 回到节点0：val=0，左=null但右!=null -> 保留
6. 回到根1：保留
7. 结果：[1,null,0,null,1]

### 解法二：迭代后序遍历

使用栈模拟后序遍历。需要记录每个节点的父节点，以便在决定剪枝时能修改父节点的指针。实现较复杂，面试中通常不需要。

### 解法三：两遍遍历

- 第一遍（后序）：标记每个节点的子树是否包含1
- 第二遍（前序）：根据标记删除不包含1的子树
- 优点：逻辑分离，每步更简单；缺点：需要额外空间存储标记

## 易错点

1. **忘记处理根节点被剪掉的情况**：根节点也可能是0且无子节点，必须返回 null
2. **先判断再递归（错误顺序）**：如果先判断当前节点再递归子节点，会错过子节点被剪掉后当前节点也该被剪的情况
3. **内存泄漏**：在实际工程中，被剪掉的节点应该被 delete。LeetCode 不检查，但面试中可能被问到
4. **混淆"不包含1"和"值不为1"**：一个值为0的节点如果子树中有1，该节点应该保留
5. **忘记赋值**：`node->left = pruneTree(node->left)` 中赋值号不可省略，否则指针不会被更新

## 面试追问

1. **Q: 如何处理 N 叉树的剪枝？**
   A: 同样后序遍历，遍历所有子节点。递归处理每个子节点后，从 children 列表中移除返回 null 的子节点。最后判断当前节点是否需要剪掉。

2. **Q: 如果树非常深（可能栈溢出），怎么改为迭代？**
   A: 使用显式栈模拟后序遍历。每个栈元素包含节点和一个标志位表示是否已处理子节点。处理完子节点后再判断是否剪枝。

3. **Q: 如果要剪掉不包含偶数的子树怎么办？**
   A: 将判断条件改为 `node->val % 2 != 0 && !left && !right`（奇数且无子节点时剪掉）。核心框架完全一样。

4. **Q: 这个算法能否原地修改？需要额外空间吗？**
   A: 可以原地修改，只需 O(h) 的递归栈空间，h 是树高。不需要额外数据结构。

5. **Q: 时间复杂度能否优于 O(n)？**
   A: 不能，因为必须至少访问每个节点一次来判断其值。
