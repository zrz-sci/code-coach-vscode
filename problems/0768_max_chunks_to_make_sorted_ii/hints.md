# 768. 最多能完成排序的块 II (Max Chunks To Make Sorted II)

## 核心思路

数组可以包含**重复元素**且值域不限于 `[0, n-1]`，这是与第 769 题的关键区别。核心观察是：**在位置 i 处可以分块的充要条件是 `arr[0..i]` 排序后等于最终排序数组的前 `i+1` 个元素**。等价表述为：`arr[0..i]` 中所有元素的**最大值** 小于等于 `arr[i+1..n-1]` 中所有元素的**最小值**。可以用**单调栈**来高效维护分块：栈中每个元素代表一个块的最大值，保持栈单调递增。也可以用**前缀最大值 + 后缀最小值**的预处理方式。

## 思维链

1. **分块条件分析**：在位置 i 处可以切一刀，当且仅当 `max(arr[0..i]) <= min(arr[i+1..n-1])`
2. **前缀 max / 后缀 min**：预处理 `prefixMax[i]` 和 `suffixMin[i]`，如果 `prefixMax[i] <= suffixMin[i+1]`，则可以在位置 i 后切一刀
3. **单调栈方法**：维护一个单调递增栈，栈的大小就是块数。遇到比栈顶小的元素时，说明它需要并入前面的块
4. **与排序数组比较法**：排序数组后逐位比较累计和，如果原数组和排序数组的前缀和相等，可以分块（需要用计数而非简单求和）
5. **处理重复元素**：这是本题比 769 题更难的原因。单调栈和前缀和方法都能正确处理重复值

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 单调栈 | O(n) | O(n) | 最优解，一次遍历 |
| 前缀 max + 后缀 min | O(n) | O(n) | 直观，容易理解分块条件 |
| 排序对比法（计数映射） | O(n log n) | O(n) | 利用排序数组前缀元素集合匹配 |
| 排序对比法（平衡计数） | O(n log n) | O(n) | 用 map 维护差异计数 |

## 关键提示

1. **单调栈核心**：栈中每个元素代表一个块的最大值。遇到 `arr[i] < stack.top()` 时，弹出并合并块，保留被合并块中的最大值
2. **分块的充要条件**：`max(arr[0..i]) <= min(arr[i+1..n-1])` 表示位置 i 是一个合法分割点
3. **与 769 题的区别**：769 题数组是 `[0, n-1]` 的排列，可以直接用 `max == index` 判断；本题有重复值，需要更通用的方法
4. **排序前缀和思路**：如果原数组的前 i 个元素（多重集合）等于目标排序数组的前 i 个元素，则可以在 i 处分块
5. **最后一个位置始终可分**：整个数组排序后一定等于目标，所以最后一个位置必定是分割点

## 解法详解

### 解法一：单调栈（最优解）

**思路**：维护一个单调递增栈。遍历数组，对于每个元素：
- 如果 `arr[i] >= stack.top()`，直接压栈（新开一个块）
- 如果 `arr[i] < stack.top()`，说明当前元素需要归入前面的某个块。弹出栈顶直到 `stack.top() <= arr[i]`，但要记住弹出的最大值（即原来的栈顶），最后将这个最大值压回栈

**关键洞察**：弹出过程就是"合并块"的过程。被合并的块的最大值保留，因为它代表了合并后整个大块的最大值。

**步骤**：
1. 初始化空栈
2. 遍历数组，对每个元素：
   - 记录当前元素 `curMax = arr[i]`（实际上 curMax 取第一个弹出的栈顶）
   - 当栈非空且 `stack.top() > arr[i]` 时，先保存 `curMax = stack.top()`，弹栈
   - 继续弹出所有 `stack.top() > arr[i]` 的元素
   - 将 `curMax` 压栈
3. 返回栈的大小

**时间复杂度**：O(n)，每个元素最多入栈出栈一次  
**空间复杂度**：O(n)

### 解法二：前缀最大值 + 后缀最小值

**思路**：预处理 `prefixMax[i] = max(arr[0..i])` 和 `suffixMin[i] = min(arr[i..n-1])`。位置 i 是分割点当且仅当 `prefixMax[i] <= suffixMin[i+1]`。

**步骤**：
1. 从左到右计算前缀最大值数组
2. 从右到左计算后缀最小值数组
3. 遍历 `[0, n-2]`，统计满足 `prefixMax[i] <= suffixMin[i+1]` 的分割点数量
4. 块数 = 分割点数量 + 1

### 解法三：排序对比法（计数映射）

**思路**：将数组排序得到目标数组。用一个 map 跟踪原数组和排序数组前缀元素的"差异"。当差异为空时（两个前缀的多重集合相同），可以分块。

**关键**：用 nonZero 计数器追踪 map 中非零条目数，当 nonZero == 0 时表示前缀匹配。

## 易错点

1. **单调栈合并时丢失最大值**：弹栈时必须保留最大值（第一个弹出的栈顶），不能只保留当前元素
2. **重复元素处理**：不能简单用 `max == index` 的方式（那是 769 题的解法），本题值可以重复
3. **分割点计数 vs 块数**：分割点数量 + 1 = 块数。最后一个位置天然是分割点
4. **后缀最小值数组边界**：`suffixMin[n-1] = arr[n-1]`，检查时用 `i < n-1`
5. **排序对比法中的前缀和陷阱**：不能简单用 sum 对比（如 `[1,3]` vs `[2,2]` sum 相同但元素不同），需要用计数映射
6. **栈为空时的处理**：第一个元素一定直接入栈，需要处理空栈情况

## 面试追问

1. **Q: 单调栈为什么栈的大小就是答案？**
   A: 栈中每个元素代表一个块的最大值，且保持单调递增。合并操作确保了不存在"后块最小值小于前块最大值"的情况，因此栈大小就是最大分块数

2. **Q: 这道题和 769 题的核心区别是什么？**
   A: 769 题的数组是 `[0, n-1]` 的排列（无重复），可以用 `max(arr[0..i]) == i` 这个简单条件判断分割点。本题有重复值和大值域，需要更通用的方法

3. **Q: 能否用前缀和来判断分割点？**
   A: 不够严谨。前缀和相等不能保证元素集合相同（如 `{1,3}` 和 `{2,2}` 的和都是 4）。需要同时排序后用计数映射比较

4. **Q: 单调栈方法的时间复杂度为什么是 O(n) 而不是 O(n^2)？**
   A: 均摊分析：每个元素最多入栈一次、出栈一次，总操作不超过 2n 次

5. **Q: 如何输出具体的分块方案？**
   A: 单调栈方法中，可以额外记录每个块的起止索引。或用前缀 max/后缀 min 方法，记录所有满足条件的分割点位置
