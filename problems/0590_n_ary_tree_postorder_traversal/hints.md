# 590. N-ary Tree Postorder Traversal - N叉树的后序遍历

## 核心思路

N 叉树的后序遍历要求：**先从左到右依次递归访问每个子节点的子树，最后访问根节点**。递归法很直观，但题目的 Follow-up 要求用迭代法实现。迭代法的经典技巧是**利用前序遍历的变体 + 反转**：先按"根-右-左"顺序收集，最后反转得到"左-右-根"的后序结果。

## 思维链

1. **回顾后序遍历定义**：子节点1的子树 -> 子节点2的子树 -> ... -> 子节点k的子树 -> 根
2. **递归法**：先遍历所有子节点，再记录当前节点值
3. **迭代法（反转技巧）**：
   - 前序遍历是"根-左-右"，如果改为"根-右-左"（子节点从左到右入栈），反转后就是"左-右-根"即后序
4. **迭代法（标记法）**：用 `pair<Node*, bool>` 标记节点是否已展开子节点，实现真正的后序迭代

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 递归 | O(n) | O(h) | 最直观 |
| 迭代 + 反转 | O(n) | O(n) | 最简洁的迭代实现 |
| 迭代 + 标记法 | O(n) | O(n) | 真正的后序迭代，无需反转 |

## 关键提示

1. 后序遍历 = 前序遍历（根-右-左版本）的反转
2. 前序遍历子节点从右到左入栈 -> 出栈从左到右 -> "根-左-右"
3. 前序遍历子节点从左到右入栈 -> 出栈从右到左 -> "根-右-左" -> 反转 = "左-右-根"
4. 递归法中，`result.push_back(node->val)` 放在遍历子节点的**循环之后**
5. 空树需要直接返回空数组

## 解法详解

### 解法一：递归

```
postorder(node):
    if node is null: return
    for child in node.children:   // 先访问所有子树
        postorder(child)
    result.add(node.val)          // 最后访问根
```

**流程示例**（树: 1->[3->[5,6], 2, 4]）：
- 递归 3 -> 递归 5 -> 访问 5 -> 递归 6 -> 访问 6 -> 访问 3
- 递归 2 -> 访问 2
- 递归 4 -> 访问 4
- 访问 1
- 结果: [5, 6, 3, 2, 4, 1]

### 解法二：迭代 + 反转（推荐）

```
stack = [root]
while stack not empty:
    node = stack.pop()
    result.add(node.val)
    // 子节点从左到右入栈（注意: 和前序遍历方向相反）
    for child in node.children:
        stack.push(child)
reverse(result)
```

**核心洞察**：
- 子节点从左到右入栈 -> 出栈顺序从右到左
- 收集顺序为 "根 -> 最右子树 -> ... -> 最左子树"
- 反转后变为 "最左子树 -> ... -> 最右子树 -> 根" = 后序

**流程示例**（树: 1->[3->[5,6], 2, 4]）：
- 栈: [1] -> 弹出 1, 压入 [3, 2, 4] -> result: [1]
- 栈: [3, 2, 4] -> 弹出 4 -> result: [1, 4]
- 栈: [3, 2] -> 弹出 2 -> result: [1, 4, 2]
- 栈: [3] -> 弹出 3, 压入 [5, 6] -> result: [1, 4, 2, 3]
- 栈: [5, 6] -> 弹出 6 -> result: [1, 4, 2, 3, 6]
- 栈: [5] -> 弹出 5 -> result: [1, 4, 2, 3, 6, 5]
- 反转: [5, 6, 3, 2, 4, 1]

### 解法三：迭代 + 标记法（真正后序）

使用 `pair<Node*, bool>` 标记是否已处理过子节点：
```
stack = [(root, false)]
while stack not empty:
    (node, visited) = stack.top(); stack.pop()
    if visited:
        result.add(node.val)
    else:
        stack.push((node, true))      // 根节点标记为待访问
        // 子节点从右到左入栈
        for i from children.size()-1 down to 0:
            stack.push((children[i], false))
```

这种方式不需要反转，是真正按后序顺序访问的迭代实现。

## 易错点

1. **迭代法子节点入栈方向搞混**：反转法需要从左到右入栈（与前序遍历的从右到左相反）
2. **忘记反转**：反转法最后必须 `reverse(result)`
3. **混淆前序和后序**：前序"根-子"，后序"子-根"
4. **root 为空**：直接返回空数组，不要入栈
5. **标记法中标记顺序**：根节点要先 push 再 push 子节点，确保根最后被处理

## 面试追问

1. **为什么"根-右-左"反转就是后序？**
   - 后序是"左-右-根"，将其反转是"根-右-左"，这恰好是修改后的前序遍历
2. **迭代法的反转和标记法各自的优劣？**
   - 反转法代码短但语义不直观（不是真正的后序遍历过程）
   - 标记法语义清晰但代码略长，需要额外的 bool 标记
3. **如何不用额外空间实现后序遍历？**
   - 对 N 叉树来说不像二叉树有 Morris 遍历，通常需要 O(n) 空间
4. **后序遍历有什么实际应用场景？**
   - 文件系统的大小计算（先算子目录大小再算父目录）
   - 表达式树的求值（先算子表达式再算父表达式）
   - 内存释放（先释放子节点再释放父节点）
5. **与 589 前序遍历代码的差异在哪？**
   - 递归法：`push_back` 的位置从循环前移到循环后
   - 迭代法：子节点入栈方向相反 + 最后加一步 reverse
