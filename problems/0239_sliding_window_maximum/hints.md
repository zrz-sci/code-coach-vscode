# 239. 滑动窗口最大值

## 核心思路

本质问题：在一个固定大小为 k 的滑动窗口中，如何**高效维护最大值**？每次窗口滑动一步，只有一个元素进、一个元素出，我们需要一种数据结构能在 O(1) 或 O(log n) 时间内响应这种动态变化。

## 思维链

1. **读完题第一反应**：对每个窗口位置，扫描窗口内 k 个元素取最大值。这是 O(nk) 的暴力解。
2. **暴力解的瓶颈**：每次窗口滑动一步，只变了两个元素（一个出一个进），但我们重新扫描了 k 个元素来找最大值。99% 的工作是重复的。
3. **能不能"记住"之前的最大值？** 如果旧最大值没有滑出窗口，它仍然是候选；如果新进来的元素更大，它就是新的最大值。问题是：**当最大值滑出窗口时，谁是下一个最大值？** 这才是关键瓶颈。
4. **思路A — 堆**：用最大堆维护窗口元素，堆顶就是最大值。新元素入堆 O(log n)，但难点是：滑出的元素可能不在堆顶，标准堆没有高效删除任意元素的方法 → **懒删除**：不急着删，取堆顶时检查它是否还在窗口内，不在就弹掉。
5. **思路B — 单调队列（最优解）**：换个角度想——如果窗口内有元素 `a` 在 `b` 左边且 `a < b`，那 `a` **永远不可能**成为任何包含 `b` 的窗口的最大值。所以 `a` 是"无用"的，可以直接丢掉！维护一个**从大到小**的双端队列（存下标），每次新元素进来，把队尾所有比它小的元素弹掉，因为它们以后再也没用了。队首就是当前窗口的最大值。
6. **验证**：单调队列中每个元素最多进队一次、出队一次，总操作 O(n)，完美！

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力 | 每个窗口扫描 k 个元素 | O(nk) | O(1) | 能说出即可 |
| 最大堆 + 懒删除 | 堆顶取最大值，过期元素懒删除 | O(n log n) | O(n) | 加分项 |

## 关键提示

1. **核心洞察**：如果 `nums[i] >= nums[j]` 且 `i > j`（i 在 j 右边），那么只要 i 在窗口内，j 就永远不可能是答案。所以 j 可以被"淘汰"。
2. **单调队列存什么？** 存**下标**而不是值！因为你需要判断队首元素是否已经滑出窗口（通过比较下标和当前位置的距离是否 > k）。
3. **队列的单调方向**：从队首到队尾**递减**。新元素从队尾进入，进入前把所有 ≤ 它的元素弹出（因为它们以后不可能是最大值了）。
4. **什么时候开始收集结果？** 当窗口形成时，即 `i >= k - 1` 时才开始记录答案。
5. **堆解法的关键**：不需要真的从堆中删除滑出的元素，只需要在取堆顶时检查堆顶下标是否还在窗口内，不在就弹掉（懒删除）。

```
// 单调队列的工作过程 (nums = [1,3,-1,-3,5,3,6,7], k=3):
//
// i=0: deque=[0]           队列值:[1]         窗口未满
// i=1: 3>1,弹0 → deque=[1]  队列值:[3]       窗口未满  
// i=2: -1<3 → deque=[1,2]   队列值:[3,-1]    窗口满 → ans=[3]
// i=3: -3<-1 → deque=[1,2,3] 队列值:[3,-1,-3] 窗口满 → ans=[3,3]
// i=4: 5>-3弹3,5>-1弹2,5>3弹1 → deque=[4] 队列值:[5] → ans=[3,3,5]
// i=5: 3<5 → deque=[4,5]    队列值:[5,3]     → ans=[3,3,5,5]
// i=6: 6>3弹5,6>5弹4 → deque=[6] 队列值:[6]  → ans=[3,3,5,5,6]
// i=7: 7>6弹6 → deque=[7]   队列值:[7]       → ans=[3,3,5,5,6,7]
```

## 解法详解

### 解法1: 暴力法 — O(nk) / O(1)

**思考过程**：最直接的做法——对每个窗口起始位置，遍历窗口内 k 个元素找最大值。

```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> result;
        for (int i = 0; i <= n - k; i++) {
            int maxVal = nums[i];
            for (int j = i + 1; j < i + k; j++) {
                maxVal = max(maxVal, nums[j]);
            }
            result.push_back(maxVal);
        }
        return result;
    }
};
```

**关键点**：n 最大 10^5，k 也可能接近 n，O(nk) 在最坏情况下约 10^10，会超时。但面试中能说出这个暴力解表示你理解了题意。

---

### 解法2: 最大堆 + 懒删除 — O(n log n) / O(n)

**从暴力优化**：暴力解的瓶颈是"每次重新扫描 k 个元素找最大值"。堆能在 O(1) 时间给出最大值，O(log n) 时间插入。难点在于删除滑出窗口的元素——我们用**懒删除**策略：不主动删，取堆顶时发现过期了再弹。

```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> result;
        // 最大堆，存 (值, 下标)，值大的在堆顶
        priority_queue<pair<int, int>> pq;
        
        for (int i = 0; i < n; i++) {
            pq.push({nums[i], i});
            
            // 懒删除：堆顶元素如果已经滑出窗口，弹掉
            // 窗口范围是 [i-k+1, i]，所以下标 < i-k+1 的都过期了
            while (pq.top().second < i - k + 1) {
                pq.pop();
            }
            
            // 窗口形成后开始收集答案
            if (i >= k - 1) {
                result.push_back(pq.top().first);
            }
        }
        return result;
    }
};
```

**关键点**：
- 为什么是 O(n log n) 而不是 O(n log k)？因为懒删除意味着堆中可能积累超过 k 个元素，最坏情况堆的大小为 n（如递增序列，没有元素会被懒删除提前弹出）。
- 懒删除只在查看堆顶时才触发，所以不会影响正确性。

---

### 解法3: 单调队列（双端队列） — O(n) / O(k) ⭐ 面试首选

**核心洞察**：在窗口中，如果 `nums[i] >= nums[j]` 且 `i > j`（i 比 j 更新），那么 j 在 i 之前就会滑出窗口，而且值还不如 i 大，j **永远不可能** 成为任何未来窗口的最大值。所以 j 可以直接淘汰。

这个性质意味着我们只需要维护一个**值递减**的序列。当新元素进来时，所有比它小的旧元素都可以丢掉。这就是**单调递减队列**。

**为什么用双端队列（deque）？**
- **队尾**：新元素从这里进入，进入前把所有 ≤ 它的元素从队尾弹出
- **队首**：最大值在这里取，如果队首元素下标已经滑出窗口就弹掉

```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> result;
        deque<int> dq; // 存下标，对应的值从队首到队尾单调递减
        
        for (int i = 0; i < n; i++) {
            // 1. 移除过期元素：队首下标如果不在窗口 [i-k+1, i] 内，弹出
            while (!dq.empty() && dq.front() < i - k + 1) {
                dq.pop_front();
            }
            
            // 2. 维护单调性：队尾所有 <= nums[i] 的元素都没用了，弹出
            //    为什么是 <=？因为即使相等，新的那个下标更大，存活时间更长
            while (!dq.empty() && nums[dq.back()] <= nums[i]) {
                dq.pop_back();
            }
            
            // 3. 新元素入队
            dq.push_back(i);
            
            // 4. 窗口形成后，队首就是最大值
            if (i >= k - 1) {
                result.push_back(nums[dq.front()]);
            }
        }
        return result;
    }
};
```

**为什么是 O(n)？** 每个元素最多入队一次、出队一次（无论从队首还是队尾弹出），总操作 2n 次，所以是 O(n)。

**关键点**：存下标而不是值！这是因为需要判断队首元素是否过期。

## 解法对比

| | 暴力 | 最大堆+懒删除 | 单调队列 |
|---|---|---|---|
| 时间 | O(nk) | O(n log n) | O(n) |
| 空间 | O(1) | O(n) | O(k) |
| 实现难度 | 简单 | 中等 | 中等 |
| 核心思想 | 逐个扫描 | 堆维护最大值 | 淘汰无用元素 |
| 面试推荐 | ✗ 超时 | ✓ 可以 | ⭐ 最优解 |

**什么时候选哪个：**
- 单调队列是本题的标准解法，面试中 80% 期望你写出来
- 堆解法思路更通用（任何"动态维护极值"的场景都能用），如果一时想不到单调队列，堆是个好的退路
- 暴力解只用来说明你理解题意

## 易错点

1. **队列存值而不存下标**
   - ✗ `deque<int> dq; dq.push_back(nums[i]);` → 无法判断队首是否过期
   - ✓ `deque<int> dq; dq.push_back(i);` → 用 `nums[dq.front()]` 取值，用 `dq.front() < i-k+1` 判断过期

2. **弹出时用 `<` 而不是 `<=`**
   - ✗ `nums[dq.back()] < nums[i]` → 相等的旧元素没弹掉，可能导致过期元素留在队列中影响结果
   - ✓ `nums[dq.back()] <= nums[i]` → 相等时弹掉旧的，保留新的（下标更大，存活更久）

3. **先弹过期元素还是先弹小元素？顺序搞反**
   - 两个操作的顺序不影响正确性（因为过期元素一定在队首，小元素从队尾弹），但建议先弹队首过期元素再弹队尾——逻辑更清晰

4. **结果数组的长度判断错误**
   - 窗口形成的条件是 `i >= k - 1`（即已经有 k 个元素进入），不是 `i >= k`
   - 结果数组长度应为 `n - k + 1`

5. **堆解法忘记懒删除循环**
   - ✗ 只弹一次：`if (pq.top().second < i - k + 1) pq.pop();`
   - ✓ 用 while 循环弹到堆顶合法为止

## 面试追问

**Q1: 暴力解的时间复杂度是多少？瓶颈在哪？**
> O(nk)。瓶颈在于每次窗口移动只变了一个元素，但重新扫描了 k 个元素。

**Q2: 堆能优化到什么程度？还能不能更快？**
> 堆 O(n log n)，每次插入 O(log n)。但堆的瓶颈在于不支持高效删除任意位置的元素，需要懒删除。单调队列利用"旧且小的元素永远不会是答案"这个性质，把总操作降到 O(n)。

**Q3: 单调队列为什么每个元素只操作常数次？如何严格证明 O(n)？**
> 使用**摊还分析**：每个元素最多入队一次（push_back），最多出队一次（从 pop_front 或 pop_back 弹出），所以总操作次数 ≤ 2n。

**Q4: 如果要求滑动窗口的最小值呢？**
> 改变单调队列的方向：维护从队首到队尾**单调递增**的队列，队尾弹出时条件改为 `>=`。

**Q5: 如果窗口大小不固定，而是满足某个条件（如窗口内最大值 - 最小值 ≤ limit）？**
> 这是 LeetCode 1438「绝对差不超过限制的最长连续子数组」。需要**同时维护两个单调队列**：一个递减队列跟踪最大值，一个递增队列跟踪最小值。当 max - min > limit 时收缩左边界。
