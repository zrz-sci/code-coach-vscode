# 454. 四数相加 II

## 核心思路

本题本质上是 **Two Sum 的升级版**：把四个数组的求和问题，通过分组配对，转化为"在哈希表中查找互补值"的问题。

## 思维链

1. **读完题第一反应**：四重循环暴力枚举所有 `(i, j, k, l)` 组合，判断四数之和是否为 0。时间 O(n⁴)，n=200 时约 1.6×10⁹，超时。

2. **暴力解的瓶颈在哪？**：四层嵌套循环，每增加一层就多 ×n 的开销。能否减少循环层数？

3. **关键观察**：`nums1[i] + nums2[j] + nums3[k] + nums4[l] == 0` 等价于 `nums1[i] + nums2[j] == -(nums3[k] + nums4[l])`。也就是说，我们可以把 4 个数组拆成两组，每组两个数组。

4. **怎么利用分组？**：先用 O(n²) 枚举前两个数组的所有和，存到哈希表里（key=和，value=出现次数）。然后 O(n²) 枚举后两个数组的所有和，在哈希表里查找互补值。

5. **为什么这样是对的？**：对于后两个数组的每一对 `(k, l)` 产生的和 `s`，哈希表里 `-(s)` 的出现次数，就是能跟 `(k, l)` 配对形成总和为 0 的 `(i, j)` 的数量。

6. **复杂度飞跃**：从 O(n⁴) → O(n²)，本质就是把"四层循环暴力查找"变成了"两层循环 + 哈希表 O(1) 查找"。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力四重循环 | 枚举所有组合 | O(n⁴) | O(1) | 能说出即可 |
| 三重循环+哈希 | 存一个数组，三重循环查 | O(n³) | O(n) | 能说出即可 |
| **分组哈希** | 2+2分组，哈希表存前两组的和 | **O(n²)** | **O(n²)** | ⭐ 必须写出 |

## 关键提示

1. **Two Sum 的思想扩展**：Two Sum 是在一个数组里找两数之和等于 target，这道题是在四个数组里找四数之和等于 0。能不能把四个数组"折叠"成两组？

2. **为什么 2+2 分组最优？**：分成 1+3 需要 O(n³) 枚举三个数组，分成 2+2 只需 O(n²)。数学上 n² + n² < n³ + n（n 较大时），所以均分最优。

3. **哈希表存什么？**：不是存元素本身，而是存"两个数组元素之和"以及"这个和出现了多少次"。次数很关键——相同的和可能由不同的 (i, j) 对产生。

4. **和 LeetCode 18（四数之和）的区别**：18 题是在**同一个数组**里选 4 个不同元素，需要去重；本题是从**四个独立数组**各选一个，不需要去重，且不能用排序+双指针（因为是四个独立数组）。

5. **数据范围提示**：元素范围 [-2²⁸, 2²⁸]，两数之和最大约 ±2²⁹，在 int 范围内（±2³¹），不会溢出。

## 解法详解

### 解法1: 暴力四重循环 — O(n⁴) / O(1)

**思考过程**: 最直觉的做法，枚举所有四元组。n=200 时约 1.6×10⁹ 次运算，会超时，但帮助理解题意。

```cpp
class Solution {
public:
    int fourSumCount(vector<int>& nums1, vector<int>& nums2,
                     vector<int>& nums3, vector<int>& nums4) {
        int n = nums1.size();
        int count = 0;
        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                for (int k = 0; k < n; k++)
                    for (int l = 0; l < n; l++)
                        if (nums1[i] + nums2[j] + nums3[k] + nums4[l] == 0)
                            count++;
        return count;
    }
};
```

**关键点**: 纯暴力，没有任何优化技巧。瓶颈在于四层嵌套循环，接下来的优化方向就是减少循环层数。

---

### 解法2: 分组哈希 — O(n²) / O(n²) ⭐ 面试首选

**从解法1优化**: 暴力的瓶颈是四层循环。核心洞察是 `a+b+c+d=0` 等价于 `a+b = -(c+d)`，把问题拆成两半：

- **第一步**：O(n²) 枚举 nums1 和 nums2 的所有两数之和，用哈希表记录每个和出现的次数。
- **第二步**：O(n²) 枚举 nums3 和 nums4 的所有两数之和 `s`，在哈希表中查找 `-s` 的出现次数，累加到答案中。

这和 Two Sum 的思路完全一致：先存一半，再查另一半的互补值。

```
示例: nums1=[1,2], nums2=[-2,-1], nums3=[-1,2], nums4=[0,2]

第一步: 枚举 nums1 + nums2 的所有和
  1+(-2)=-1, 1+(-1)=0, 2+(-2)=0, 2+(-1)=1
  哈希表: {-1: 1, 0: 2, 1: 1}

第二步: 枚举 nums3 + nums4 的所有和，查找互补值
  (-1)+0=-1 → 查找 -(-1)=1  → 哈希表[1]=1  → count+=1
  (-1)+2= 1 → 查找 -(1)=-1  → 哈希表[-1]=1 → count+=1
  2+0   = 2 → 查找 -(2)=-2  → 不存在        → count+=0
  2+2   = 4 → 查找 -(4)=-4  → 不存在        → count+=0

最终 count = 2 ✓
```

```cpp
class Solution {
public:
    int fourSumCount(vector<int>& nums1, vector<int>& nums2,
                     vector<int>& nums3, vector<int>& nums4) {
        unordered_map<int, int> sumAB;
        
        // 第一阶段: 枚举前两个数组的所有两数之和，记录次数
        for (int a : nums1)
            for (int b : nums2)
                sumAB[a + b]++;  // 相同的和可能由不同的(i,j)产生，次数要累加
        
        int count = 0;
        
        // 第二阶段: 枚举后两个数组的所有两数之和，在哈希表中查找互补值
        for (int c : nums3)
            for (int d : nums4) {
                int target = -(c + d);  // 需要前两个数组的和等于 -(c+d)
                auto it = sumAB.find(target);
                if (it != sumAB.end())
                    count += it->second;  // 累加次数，不是+1！
            }
        
        return count;
    }
};
```

**关键点**:
- `count += it->second` 而不是 `count++`：因为哈希表里记录的是"有多少对 (i,j) 产生了这个和"，每一对都能和当前的 (k,l) 组成一个合法四元组。
- 使用 `find()` 而不是 `[]` 操作符：`[]` 在 key 不存在时会插入默认值 0，虽然结果正确但会增加哈希表大小、降低性能。

---

### 解法3: 三重循环+哈希（中间态，理解用） — O(n³) / O(n)

**定位**: 这是从暴力到最优解的中间过渡，帮助理解"减少循环层数"的渐进过程。

- 先 O(n) 把 nums4 的值存入哈希表。
- 然后三重循环枚举 nums1、nums2、nums3，在哈希表中查找 `-(a+b+c)`。

```cpp
class Solution {
public:
    int fourSumCount(vector<int>& nums1, vector<int>& nums2,
                     vector<int>& nums3, vector<int>& nums4) {
        // 只存一个数组的值和出现次数
        unordered_map<int, int> mapD;
        for (int d : nums4)
            mapD[d]++;
        
        int count = 0;
        for (int a : nums1)
            for (int b : nums2)
                for (int c : nums3) {
                    int target = -(a + b + c);
                    auto it = mapD.find(target);
                    if (it != mapD.end())
                        count += it->second;
                }
        return count;
    }
};
```

**与解法2的对比**: 分组 1+3 = O(n) + O(n³)，而分组 2+2 = O(n²) + O(n²)。均分分组总是更优的，这就是解法2更好的原因。

## 解法对比

| | 解法1: 暴力 | 解法3: 1+3分组 | 解法2: 2+2分组 |
|---|---|---|---|
| 时间 | O(n⁴) | O(n³) | **O(n²)** |
| 空间 | O(1) | O(n) | O(n²) |
| 核心思想 | 无优化 | 哈希表替代1层循环 | 哈希表替代2层循环 |
| 面试 | 能说出即可 | 过渡思路 | **⭐ 必须掌握** |

**选择策略**: 面试时直接写解法2。如果面试官问"还有没有其他分组方式"，可以提解法3，然后解释为什么 2+2 分组最优（均分原理）。

## 易错点

1. **✗ `count++` → ✓ `count += it->second`**
   ```cpp
   // ✗ 错误: 只算了"存在匹配"，没有计入"有多少对匹配"
   if (sumAB.find(target) != sumAB.end())
       count++;
   
   // ✓ 正确: 哈希表的 value 是出现次数，要累加
   if (sumAB.find(target) != sumAB.end())
       count += sumAB[target];
   ```
   当 nums1=[0,0], nums2=[0,0] 时，和为 0 出现 4 次，不是 1 次。

2. **✗ 用 `sumAB[target]` 查询 → ✓ 用 `sumAB.find(target)`**
   ```cpp
   // ✗ 可以工作但有性能问题: [] 会在 key 不存在时插入 {target, 0}
   count += sumAB[-(c + d)];
   
   // ✓ 更优: find 不会修改哈希表
   auto it = sumAB.find(-(c + d));
   if (it != sumAB.end()) count += it->second;
   ```
   虽然结果相同，但 `[]` 会让哈希表不断膨胀，当 n 较大时影响性能。

3. **忘记考虑重复元素**：本题四个数组完全独立，不存在"不能重复选同一个元素"的限制。`(i,j,k,l)` 中的 i,j,k,l 分别属于不同数组，天然不冲突。

## 面试追问

**Q1: 暴力解的时间复杂度是多少？能过吗？**
A: O(n⁴)，n=200 时约 1.6×10⁹ 次运算，对于 1 秒时限通常会超时。需要优化。

**Q2: 为什么分成 2+2 而不是 1+3 或 3+1？**
A: 分成 k 和 4-k，总复杂度是 O(n^k + n^(4-k))。当 k=2 时取到最小值 O(n²+n²) = O(n²)。这是"均分"的思想——把工作量均匀地分到两半，总开销最小。类似于归并排序每次对半分。

**Q3: 如果不是 4 个数组而是 k 个数组呢？**
A: 同样的思路，把 k 个数组分成两半（各 k/2 个），分别枚举所有 k/2 个数组的元素之和，存入哈希表。时间复杂度 O(n^(k/2))。这其实是 **Meet in the Middle** 算法的经典应用。

**Q4: 这道题和 LeetCode 1 (Two Sum) 有什么关系？**
A: 本质相同！Two Sum 是 a + b = target，用哈希表存 a 查 target-b。本题是 (a+b) + (c+d) = 0，用哈希表存 (a+b) 查 -(c+d)。只是"元素"从单个数变成了两数之和。

## 相关题型

- **LeetCode 1 (Two Sum)** — 本题的基础版。复用"哈希表存互补值"的核心思想，区别在于本题的"元素"是两数之和而非单个数。
- **LeetCode 18 (4Sum)** — 同一个数组选 4 个元素求和为 target。因为是同一数组，需要排序+双指针+去重，思路完全不同。学会本题后做 18 要注意"去重"这个额外约束。
- **LeetCode 15 (3Sum)** — 同一数组选 3 个元素求和为 0。排序+双指针思路。和本题的区别：本题四个独立数组不需去重。
- **Meet in the Middle 思想** — 本题是 MITM 在数组求和问题上的经典应用。遇到"在指数级搜索空间中找目标值"时可以想到此技巧。
