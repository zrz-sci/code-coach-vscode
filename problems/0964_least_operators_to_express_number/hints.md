# LeetCode 964 - Least Operators to Express Number

## 核心思路

将 target 用 x 进制表示，每一"位"对应 x 的某个幂次。对于每一位的系数 r，可以选择：
1. 用 r 个 x^k 相加来凑（正向）
2. 用 (x - r) 个 x^k 相减，同时向高位进位 1（反向）

每个 x^k 需要 k 个乘号（特殊情况：x^0 = x/x 需要 2 个运算符）。用贪心 + DP 的方式，逐位从低到高决定正向/反向凑数，使总运算符最少。

## 思维链

1. **理解运算符计数** - 表达式只能用 x 和四则运算。x 本身是 x^1 (0 个运算符)，x*x 是 x^2 (1 个乘号)，x/x 是 x^0 (1 个除号)。将 x^k 看作一个"单元"，构建 k 个 x^k 需要用 k 个运算符（k >= 1），而 x^0 需要 2 个运算符。
2. **类比进制转换** - 把 target 转为 x 进制，每一位系数 0 <= r < x。每一位系数 r 需要 r 个该幂次单元，每个单元之间用加号连接（r-1 个加号）。
3. **正向 vs 反向** - 对于系数 r，正向花费 = r * cost(k)，其中 cost(k) 代表一个 x^k 单元的运算符数加上加号。反向把 r 改为 (x - r)，向高位进 1。反向花费 = (x - r) * cost(k)。
4. **DP 逐位决策** - 从最低位开始，维护两个状态：当前位选择正向的最小花费 pos，和选择反向（需向上进位）的最小花费 neg。逐位更新直到处理完所有位。
5. **特殊处理** - x = 2 时 target = 1 的情况; 最高位之上可能还有进位，需要额外处理一位。

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|----------|----------|------|
| 记忆化搜索 + x 进制 | O(log_x(target)) | O(log_x(target)) | 递归处理每一位 |
| 迭代 DP（逐位贪心） | O(log_x(target)) | O(1) | 空间最优，推荐 |
| BFS 最短路 | O(target) | O(target) | 暴力，仅适合小范围 |

## 关键提示

1. 一个 x^k (k >= 1) 单元需要 k 个运算符（k-1 个乘号 + 与表达式连接的 1 个加/减号）。
2. 一个 x^0 单元需要 2 个运算符（1 个除号 + 1 个加/减号）。
3. 最终答案需要减去 1，因为最前面的项不需要加/减号来连接。
4. 将 target 逐位除以 x 获得每一位系数，类似进制转换。
5. 每一位有两个选择：正向（花费 r 个单元）或反向（花费 x-r 个单元并进位），取全局最优。
6. 当 x = 2 时要特别注意 x^0 的花费仍然是 2，这使得小系数用反向可能更优。

## 解法详解

### 解法一：迭代 DP（推荐）

**核心思想**：将 target 按 x 进制分解，从低位到高位逐位处理。

每一位的系数 r = target % x，对应幂次 k。

- **正向花费**：需要 r 个 x^k 单元。每个单元花费 k 个运算符（k >= 1 时），加上 r 个加/减号连接。但最低位的第一个项不需要前导加号，这通过最终 ans - 1 处理。
- **反向花费**：需要 (x - r) 个 x^k 单元用减法，同时高位系数 +1。

定义 cost(k) = k（k >= 1）或 2（k = 0），表示一个 x^k 单元的运算符数。

对于第 k 位系数 r：
- 正向：r * cost(k) 个运算符
- 反向：(x - r) * cost(k) 个运算符

用 pos 和 neg 分别跟踪"当前位选正向"和"当前位选反向（进位）"的累计最小花费。

**逐位转移**：
```
新 pos = min(pos + r * cost(k), neg + r * cost(k))       // 上一位不进位/进位，这一位选正向
新 neg = min(pos + (x-r) * cost(k), neg + (x-r-1) * cost(k))  // 注意进位时 r 变成 r+1
```

最后 target 用完后，answer = min(pos, neg + cost(最高位+1)) - 1。

### 解法二：记忆化搜索

把问题看成：用最少运算符凑 target。递归函数 dp(i, target) 表示从 x^i 开始凑剩余 target 的最小运算符数。

每一层递归取 r = target / x^i 的商和余数，尝试正向和反向两种策略，递归处理高位。

用 unordered_map 做记忆化，避免重复计算。

## 易错点

1. **忘记最终减 1** - 表达式最前面的项不需要加/减号，所以总运算符数要减 1。
2. **x^0 花费是 2 不是 0** - x/x = 1 需要一个除号和一个加/减号。
3. **反向进位时系数变化** - 如果上一位选了反向进位，当前位的系数实际上是 r+1 而不是 r。
4. **最高位之上的进位** - 如果最高位选择反向，会产生一个更高位的进位，需要额外处理。
5. **x = 2 的边界** - 由于 x^0 花费高（2），反向在低位可能更优。

## 面试追问

1. **如果允许使用括号，问题会怎么变？** - 括号改变运算顺序，可以用更少的运算符。例如 (x+x)*x 可以替代 x*x+x*x，问题变成表达式树搜索。
2. **如何验证生成的表达式是否正确？** - 可以用逆波兰或直接求值的方式验证，但由于涉及有理数除法，需要用分数类。
3. **如果 x = 1，问题有解吗？** - 不可能。题目保证 x >= 2。
4. **时间复杂度为何是 O(log_x(target))？** - target 的 x 进制位数就是 log_x(target)，每一位处理 O(1)。
5. **这个问题和背包有什么关系？** - 每一位可看作一个"物品"，选择正向/反向是两种"取法"，追求全局最小花费，类似分组背包。
