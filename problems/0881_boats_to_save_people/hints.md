# 881. 救生艇

## 核心思路

**贪心 + 排序 + 双指针**。每艘船最多载两人，且总重量不超过 limit。排序后，尝试将最重的人和最轻的人配对——如果配对成功就一起上船（两个指针都移动），否则最重的人独占一艘船（只移动右指针）。

## 思维链

1. **读完题第一反应**：每艘船最多两人，总重不超过 limit。最少需要多少艘船？→ 尽量让每艘船载两人 → 贪心配对。

2. **贪心策略的直觉**：如果一个很重的人无法和任何人配对（连最轻的人加起来都超限），那他只能独占一艘船。如果他能和最轻的人配对，那这就是最优选择——因为最轻的人对任何人的"帮助"是一样的（他不可能让一个原本装不下两人的船变成能装下），把他和最重的人配对不会浪费。

3. **为什么不贪心配对"最重 + 次重"？** 因为最重和次重可能加起来就超限了，白白浪费两艘船。而最重 + 最轻配对的机会更大。

4. **算法步骤**：
   - 排序
   - 左指针 left 指向最轻，右指针 right 指向最重
   - 如果 `people[left] + people[right] <= limit`：配对成功，`left++, right--`
   - 否则：最重的人独占一船，只 `right--`
   - 无论哪种情况，船数 +1

5. **贪心正确性证明**：假设最优解中最轻的人 A 和某人 X 配对。如果我们把 A 改为和最重的人 B 配对（B 的重量 >= X），而 X 要么独占一船，要么和另一个比 A 更重的人配对。由于 A 是最轻的，A+B <= limit 意味着 A+X <= limit（因为 X <= B），所以交换配对后总船数不会增加。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 排序 + 双指针 | 最重配最轻 | O(n log n) | O(1) | 必须写出 |

## 关键提示

1. **提示1**：每艘船最多**两人**——这是关键约束！如果可以载多人，问题就完全不同了（变成 bin packing）。因为只有两人，所以只需要考虑"一人独占"或"两人配对"。

2. **提示2**：排序后，用双指针从两端向中间靠拢。最轻 + 最重能配对吗？能就一起走，不能就最重的单独走。

3. **提示3**：无论是否配对成功，每次循环 `right--` 且 `boats++`。只有配对成功时才额外 `left++`。

4. **提示4**：为什么这个贪心是对的？**最轻的人是最容易配对成功的**——如果他连最重的人都配不了，那他和谁都配不了（其实不对，他可能和次重的配对）。正确的论证是：如果最轻的人能和最重的人配对，不存在更好的选择（见思维链的证明）。

5. **提示5**：注意 `people[i] <= limit` 是题目保证的，所以每个人至少能独占一船。不存在"某人太重上不了船"的情况。

```
双指针配对过程 (people = [3,2,2,1], limit = 3):

排序后: [1, 2, 2, 3]
         L           R

Round 1: people[L]+people[R] = 1+3 = 4 > 3
         3 单独上船, R--
         boats=1, [1, 2, 2, |3|]
                   L     R

Round 2: people[L]+people[R] = 1+2 = 3 <= 3
         1和2 配对上船, L++, R--
         boats=2, [|1|, 2, |2|, |3|]
                       LR

Round 3: L==R, 2 单独上船
         boats=3

答案: 3 艘船
```

## 解法详解

### 解法: 排序 + 双指针 — O(n log n) / O(1)

**思考过程**：
- 每船最多两人 → 贪心配对
- 排序后双指针：最轻 + 最重尝试配对
- 能配对就都上船（两指针移动），不能就重的人独占（右指针移动）
- 这保证了最优的配对策略

```
// 贪心策略可视化:
//
// 排序后: [1, 2, 2, 3, 3, 5], limit = 5
//          L                 R
//
// 轮次:  配对尝试        结果         船
//  1:    1+5=6 > 5      5单独        [5]
//  2:    1+3=4 <= 5     1,3配对      [1,3]
//  3:    2+3=5 <= 5     2,3配对      [2,3]
//  4:    L>R, 2单独      2单独       [2]
//
// 总计: 4 艘船
```

```cpp
class Solution {
public:
    int numRescueBoats(vector<int>& people, int limit) {
        // 排序: 让最轻和最重的人对齐
        sort(people.begin(), people.end());

        int left = 0, right = people.size() - 1;
        int boats = 0;

        while (left <= right) {
            // 尝试配对最轻和最重的人
            if (people[left] + people[right] <= limit) {
                left++;  // 最轻的人上船了
            }
            // 无论是否配对, 最重的人都上船
            right--;
            boats++;
        }
        return boats;
    }
};
```

**关键点**：
- `left <= right`：当 left == right 时还剩一个人，也需要一艘船
- `left++` 只在配对成功时执行；`right--` 和 `boats++` 每次都执行
- 排序的 O(n log n) 是瓶颈，双指针部分只需 O(n)

## 贪心正确性证明

**命题**：排序后，将最轻的人与最重的人配对（如果可能），得到的总船数是最优的。

**证明（交换论证）**：
- 设最优解为 OPT，我们的贪心解为 G
- 假设在 OPT 中，最轻的人 A (weight = a) 与某人 X (weight = x) 配对
- 在 G 中，A 与最重的人 B (weight = b) 配对（假设 a + b <= limit）
- 因为 b >= x，且 a + b <= limit，所以 a + x <= limit（A 和 X 的配对在 G 中也合法）
- 在 OPT 中，B 可能与某人 Y 配对，或者独占
  - 如果 B 独占：交换后 A-B 配对、X 独占或与 Y 配对，总船数不增加
  - 如果 B 与 Y 配对：交换后 A-B 配对、X-Y 配对（如果合法）或各自独占，总船数不增加
- 因此 G 的船数 <= OPT 的船数，G 是最优的

## 易错点

1. **忘记排序**
   ```cpp
   // 错误: 直接用双指针, 没排序
   // people = [3, 1, 2, 2], limit = 3
   // left=0, right=3: 3+2=5>3, 只能让 2 独占
   // 但其实 1+2 可以配对! 不排序会错过最优配对
   ```

2. **循环条件用 left < right 而非 left <= right**
   ```cpp
   // 错误: while (left < right)  → 漏掉了最后一个人独占的情况
   // 正确: while (left <= right) → left==right 时还有一个人需要一艘船
   ```

3. **配对失败时同时移动两个指针**
   ```cpp
   // 错误: 无论是否配对, 都 left++ 和 right--
   // 正确: 配对失败时只 right-- (最轻的人还要尝试和下一个配对)
   ```

4. **尝试让一艘船载三人或更多**
   ```cpp
   // 错误: 试图找最优的两人/三人组合
   // 题目约束: 每艘船最多两人! 只需考虑单人或双人
   ```

## 面试追问

**Q1: 贪心为什么是对的？能证明吗？**
→ 交换论证法：假设最优解中最轻的人和某个非最重的人配对，我们可以把这个配对换成"最轻+最重"，而不增加总船数。因此我们的贪心策略至少和最优解一样好。

**Q2: 如果每艘船可以载 k 人呢？**
→ 这就变成了 bin packing 问题的变种，NP-hard。k=2 时恰好有 O(n log n) 的贪心解，k>2 需要更复杂的算法（如 First Fit Decreasing 等近似算法）。

**Q3: 如果没有"每船最多两人"的限制，只有重量限制呢？**
→ 这是经典的 bin packing 问题（NP-hard）。最佳近似算法是 First Fit Decreasing (FFD)，保证不超过最优解的 11/9 + 6/9 倍。

**Q4: 时间复杂度能优于 O(n log n) 吗？**
→ 如果权重范围有限（如 limit <= 30000），可以用计数排序 O(n + limit) 代替比较排序。双指针部分已经是 O(n) 了。
