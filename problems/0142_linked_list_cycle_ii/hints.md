# 142. 环形链表 II

## 核心思路

本题本质上在问：**链表中是否有环，如果有，环的入口在哪？** 这是经典的"快慢指针"问题，核心难点不在于检测环（141题已解决），而在于**数学推导出相遇后如何找到环入口**。

## 思维链

1. **读完题第一反应**：怎么知道一个节点"之前访问过"？→ 最朴素的做法是记录访问过的所有节点，用哈希表存。
2. **哈希表解法的代价**：时间 O(n) 已经很好了，但空间也是 O(n)。题目 Follow-up 问能否 O(1) 空间？
3. **想到快慢指针**：141 题用快慢指针判断有没有环（快指针追上慢指针 = 有环）。能不能利用相遇点找到环入口？
4. **关键数学推导**：设链表头到环入口距离为 `a`，环入口到相遇点距离为 `b`，相遇点沿环回到入口距离为 `c`。快指针走了 `a + b + n(b+c)`，慢指针走了 `a + b`。因为快指针速度是慢的2倍：`2(a+b) = a + b + n(b+c)` → `a = (n-1)(b+c) + c`。
5. **推导结论**：`a = c + (n-1)圈`。这意味着从头节点和从相遇点同时出发，每次各走一步，它们一定在**环入口**相遇！
6. **算法成型**：Phase 1 — 快慢指针找相遇点；Phase 2 — 一个从 head 出发，一个从相遇点出发，相遇处就是环入口。

## 解法概览

## 解法详解

### 解法1: 哈希表 — O(n) / O(n)

**思考过程**: 最直觉的想法——遍历链表，记住走过的每个节点。第一个"再次遇到"的节点就是环入口。如果走到 null 都没重复，说明无环。

```cpp
class Solution {
public:
    ListNode *detectCycle(ListNode *head) {
        unordered_set<ListNode*> visited;
        ListNode* curr = head;
        while (curr != nullptr) {
            // 如果当前节点已经访问过，它就是环入口
            if (visited.count(curr)) {
                return curr;
            }
            visited.insert(curr);
            curr = curr->next;
        }
        // 走到 null，无环
        return nullptr;
    }
};
```

**关键点**: 哈希表里存的是**指针（地址）**而不是节点值。两个不同节点可能有相同的值，但地址一定不同。

---

### 解法2: 快慢指针（Floyd 判圈算法）— O(n) / O(1) ⭐ 面试首选

**从解法1优化**: 解法1的瓶颈是 O(n) 空间。Follow-up 要求 O(1) 空间，必须不存储访问过的节点。快慢指针只用两个指针变量就能完成。

**数学推导（这是本题的精华）**:

```
// 设定变量:
//   a = head 到环入口的距离
//   b = 环入口到快慢指针相遇点的距离
//   c = 相遇点沿环方向回到入口的距离
//   环长 L = b + c
//
// Phase 1: 快慢指针相遇
//   慢指针走了: a + b
//   快指针走了: a + b + n*L  (快指针在环里多转了 n 圈, n≥1)
//   快指针速度是慢的2倍: 2(a + b) = a + b + n*L
//   化简: a + b = n*L = n*(b + c)
//   所以: a = n*(b + c) - b = (n-1)*(b+c) + c
//
// 当 n=1 时: a = c
// 当 n>1 时: a = c + (n-1)圈，多走的整圈最终还是回到同一点
//
// 结论: 从 head 走 a 步 = 从相遇点走 c 步 + 若干整圈
//       两者都会到达环入口！
//
// Phase 2: 一个指针从 head 出发，一个从相遇点出发
//         每次各走一步，相遇的地方就是环入口
//
// 图解 Phase 1 (示例1: [3,2,0,-4], pos=1):
//
//   初始:  slow=3, fast=3
//   Step1: slow=2, fast=0     (slow走1步, fast走2步)
//   Step2: slow=0, fast=2     (fast 已经绕进环了)
//   Step3: slow=-4, fast=-4   ← 相遇! (在节点-4处)
//
//          3 → [2] → 0 → -4
//               ↑          |
//               └──────────┘
//                         ↑
//                      相遇点
//
// 图解 Phase 2:
//   ptr1 从 head(3) 出发, ptr2 从相遇点(-4) 出发
//   Step1: ptr1=2, ptr2=2  ← 相遇! 这就是环入口!
```

```cpp
class Solution {
public:
    ListNode *detectCycle(ListNode *head) {
        // Phase 1: 快慢指针找相遇点
        ListNode* slow = head;
        ListNode* fast = head;
        
        while (fast != nullptr && fast->next != nullptr) {
            slow = slow->next;         // 慢指针走1步
            fast = fast->next->next;   // 快指针走2步
            
            if (slow == fast) {
                // 有环！进入 Phase 2
                // Phase 2: 一个从head出发，一个从相遇点出发
                ListNode* ptr1 = head;
                ListNode* ptr2 = slow;  // slow 就是相遇点
                while (ptr1 != ptr2) {
                    ptr1 = ptr1->next;  // 各走一步
                    ptr2 = ptr2->next;
                }
                // ptr1 == ptr2 就是环入口
                return ptr1;
            }
        }
        
        // fast 走到 null，无环
        return nullptr;
    }
};
```

**关键点**: 
- Phase 1 的循环条件是 `fast != nullptr && fast->next != nullptr`（和 141 题完全一致）
- Phase 2 的两个指针**都是每次走一步**，不是快慢指针了！
- 相遇点不一定是环入口，必须经过 Phase 2 才能找到真正的入口

| 时间 | O(n) | O(n) |

| 代码难度 | 简单直观 | 需要理解数学推导 |
| 面试场景 | 作为初始方案提出 | 面试官期望的最终方案 |

**面试策略**: 先说哈希表方案表示理解题意，然后主动提出"可以用 O(1) 空间的快慢指针"，展示你知道 Floyd 算法。

## 易错点

1. **Phase 2 用了快慢指针的速度**:
   - ✗ `ptr1 = ptr1->next; ptr2 = ptr2->next->next;` — Phase 2 不是快慢，是同速！
   - ✓ `ptr1 = ptr1->next; ptr2 = ptr2->next;` — 两个都走一步

2. **Phase 1 判断相遇后直接返回 slow**:
   - ✗ `if (slow == fast) return slow;` — 相遇点不是环入口！
   - ✓ 相遇后还需要 Phase 2 来定位真正的环入口

3. **哈希表存值而不是存指针**:
   - ✗ `unordered_set<int> visited; visited.insert(curr->val);` — 不同节点可能有相同值
   - ✓ `unordered_set<ListNode*> visited; visited.insert(curr);` — 存地址才唯一

4. **Phase 1 循环条件遗漏**:
   - ✗ `while (fast->next != nullptr)` — fast 本身可能为 null
   - ✓ `while (fast != nullptr && fast->next != nullptr)` — 先检查 fast

## 面试追问

**Q1: 这道题和 141 环形链表有什么关系？**
→ 141 只判断有无环（Phase 1），本题在 141 基础上多了 Phase 2 找环入口。代码上，141 在 `slow == fast` 时直接 `return true`，142 在此基础上继续执行 Phase 2。

**Q2: 为什么快指针速度是慢指针的 2 倍，不是 3 倍？**
→ 2倍保证快指针每次比慢指针多走1步，在环内一定会相遇（不会"跳过"）。如果是3倍，当环长为偶数时快指针每次多走2步，可能跳过慢指针。2倍是最简单且正确的选择。

**Q3: 能否求出环的长度？**
→ Phase 1 相遇后，让一个指针原地不动，另一个继续走并计数，再次相遇时的步数就是环长。

**Q4: 如果链表可能有多个环怎么办？（单链表不可能，但如果是图呢？）**
→ 单链表每个节点只有一个 next，所以最多一个环。如果是图，需要 DFS + visited + recursion stack 来找所有环。
