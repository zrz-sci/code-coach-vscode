# 190. 颠倒二进制位

## 核心思路

本质上就是一个**位操作翻转**的问题：将32位整数的二进制位从左到右完全反转。最直觉的做法是逐位取出，放到对称位置上。进阶做法用分治思想（类似归并排序），分层交换相邻bit组。

## 思维链

1. **读完题第一反应** → 把整数的32位二进制表示当成一个"字符串"来翻转。逐位提取最低位，塞到结果的高位上。
2. **暴力解的做法** → 循环32次，每次取 n 的最低位（`n & 1`），左移到结果中，然后 n 右移一位。
3. **有没有更优的？** → 分治法：先交换相邻的1位，再交换相邻的2位组，再4位，再8位，最后16位。整个32位就完全反转了。
4. **Follow-up: 多次调用怎么优化？** → 预计算查找表：把32位拆成4个8位byte，每个byte的翻转结果预存表中，查表拼接即可。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 逐位翻转 | 循环32次，逐位取出放到对称位置 | O(1) | O(1) | ⭐ 必须写出 |
| 分治位操作 | 分层交换相邻bit组 (1→2→4→8→16) | O(1) | O(1) | 加分项 |
| 查找表（Follow-up） | 预计算8位翻转表，拆成4段查表拼接 | O(1) | O(256) | Follow-up 回答 |

## 关键提示

1. **固定循环32次**：不能用 `while (n)` 提前终止，因为高位的0也要参与翻转。例如 `n=1`（二进制 `00...01`），翻转后最高位为1，结果应该是 `2^31`。
2. **结果左移还是n右移？** 每次迭代：结果 `res` 左移1位腾出空间，然后把 n 的最低位加上去，最后 n 右移1位。
3. **分治的mask含义**：`0x55555555 = 0101...0101`（隔一取一），`0x33333333 = 0011...0011`（隔二取二），以此类推。
4. **类型注意**：题目函数签名用的是 `int`（有符号），位操作时要注意不要让符号位干扰。推荐用 `uint32_t` 或转换为无符号处理。

## 解法详解

### 解法1: 逐位翻转 — O(1) / O(1) ⭐ 面试首选

**思考过程**: 把32位二进制想象成一个长度为32的数组，要做的就是逆序。每次从 n 的末尾取一位，放到 res 的末尾，然后 res 左移、n 右移。

```
示例: n = 43261596
二进制: 00000010 10010100 00011110 10011100
翻转后: 00111001 01111000 00101001 01000000
结果:   964176192

过程（简化前4步）:
  第1步: n末位=0, res=0          n右移
  第2步: n末位=0, res=0          n右移
  第3步: n末位=1, res=1          n右移
  第4步: n末位=1, res=11         n右移
  ...循环共32次...
```

```cpp
class Solution {
public:
    int reverseBits(int n) {
        int res = 0;
        for (int i = 0; i < 32; i++) {
            res = (res << 1) | (n & 1);  // res左移腾位，加上n的末位
            n >>= 1;                      // n右移，准备取下一位
        }
        return res;
    }
};
```

**关键点**:
- 必须循环**恰好32次**，不能提前终止。
- `res << 1` 在前，`n & 1` 取末位在后，顺序不能错。

### 解法2: 分治位操作 — O(1) / O(1)

**从不同视角**: 类似归并排序的逆操作——先交换相邻1位，再交换相邻2位组，再4位组，再8位组，最后16位组。5步完成翻转。

```
示例: 8位简化版 abcdefgh → hgfedcba

第1步: 交换相邻1位  → badcfehg
第2步: 交换相邻2位组 → dcbahgfe
第3步: 交换相邻4位组 → hgfedcba ✓
（32位需要5步: 1位→2位→4位→8位→16位）
```

```cpp
class Solution {
public:
    int reverseBits(int n) {
        n = ((n & 0x55555555) << 1)  | ((n >> 1)  & 0x55555555); // 交换相邻1位
        n = ((n & 0x33333333) << 2)  | ((n >> 2)  & 0x33333333); // 交换相邻2位组
        n = ((n & 0x0f0f0f0f) << 4)  | ((n >> 4)  & 0x0f0f0f0f); // 交换相邻4位组
        n = ((n & 0x00ff00ff) << 8)  | ((n >> 8)  & 0x00ff00ff); // 交换相邻8位组
        n = ((n & 0x0000ffff) << 16) | ((n >> 16) & 0x0000ffff); // 交换高低16位
        return n;
    }
};
```

**关键点**:
- 每个mask的模式：`0x55555555 = 01010101...`，`0x33333333 = 00110011...`，`0x0f0f0f0f = 00001111...`
- 这个技巧在 191. Number of 1 Bits 的 popcount 分治解法中也会出现。

### 解法3: 查找表 — Follow-up 最佳答案

**针对多次调用优化**: 预计算所有8位（0~255）的翻转值，查表拼接。

```cpp
class Solution {
    int table[256];
    void buildTable() {
        for (int i = 0; i < 256; i++) {
            int rev = 0, val = i;
            for (int j = 0; j < 8; j++) {
                rev = (rev << 1) | (val & 1);
                val >>= 1;
            }
            table[i] = rev;
        }
    }
public:
    Solution() { buildTable(); }
    int reverseBits(int n) {
        return (table[n & 0xff] << 24)         // 最低8位翻转后放到最高8位
             | (table[(n >> 8) & 0xff] << 16)
             | (table[(n >> 16) & 0xff] << 8)
             | (table[(n >> 24) & 0xff]);       // 最高8位翻转后放到最低8位
    }
};
```

## 易错点

1. **循环次数不足**：
   - ✗ `while (n) { res = (res << 1) | (n & 1); n >>= 1; }` → n=1 时只循环1次，结果是1而不是 2^31
   - ✓ `for (int i = 0; i < 32; i++)` → 固定32次，高位0也参与翻转

2. **res左移位置错误**：
   - ✗ `res |= (n & 1); res <<= 1;` → 最后多左移了一次，结果偏大一倍
   - ✓ `res = (res << 1) | (n & 1);` → 先移再加

3. **有符号右移的陷阱**：
   - ✗ 对负数做 `n >>= 1` 会在高位补1（算术右移），导致死循环或结果错误
   - ✓ 用 `(unsigned)n >> 1` 或者将 n 当作无符号数处理

4. **分治mask写错**：
   - ✗ 把 `0x55555555` 写成 `0x55555` → 只处理了20位，高12位丢失
   - ✓ 确保mask覆盖完整的32位

## 面试追问

**Q1: 逐位翻转的时间复杂度是多少？能优化吗？**
> 严格来说是 O(32) = O(1)。分治法也是 O(1)（5步常数操作），但实际可能更快因为没有循环开销，且更适合硬件并行。

**Q2: Follow-up: 如果这个函数被大量调用，怎么优化？**
> 建查找表。把32位拆成4个字节，每个字节的翻转值预计算存入256大小的数组。每次调用只需4次查表和移位拼接。预处理 O(256)，每次查询 O(1)。

**Q3: 分治法的mask为什么是那些值？能推导吗？**
> 第k步的mask是"每 2^k 位中低 2^(k-1) 位为1，高 2^(k-1) 位为0"的重复模式。比如 k=0: `01` 重复 = `0x55555555`; k=1: `0011` 重复 = `0x33333333`。可以用 `~(~0 << (1 << k))` 生成基本模式再扩展。
