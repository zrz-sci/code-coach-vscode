# 167. 两数之和 II - 输入有序数组

## 核心思路

在一个**已排序**的数组中找两个数使其和为 target。关键是：如何利用"有序"这个条件，把暴力的 O(n²) 降下来？

## 思维链

1. **读完题第一反应**：最朴素的做法就是两层循环，枚举所有 (i, j) 对，检查 `numbers[i] + numbers[j] == target`。这是 O(n²)。

2. **暴力解的瓶颈在哪？** 对于固定的 `numbers[i]`，我们需要在剩余元素中"查找" `target - numbers[i]`。暴力法对每个 i 都线性扫描，查找操作是 O(n)。

3. **怎么突破瓶颈？** 两个方向：
   - 方向 A（二分查找）：数组有序 → 对每个 i，用二分查找 `target - numbers[i]`，查找从 O(n) 降到 O(log n)，总体 O(n log n)。
   - 方向 B（双指针）：数组有序 → 左右指针从两端往中间夹。和太大右指针左移，和太小左指针右移。每个元素最多访问一次，总体 O(n)。

4. **为什么双指针不会漏解？** 因为数组有序，当 `sum > target` 时，右指针右边的所有元素更大，和 left 配对只会更大，所以右指针必须左移。反之同理。这种单调性保证了每次移动都排除了不可能的情况，不会错过答案。

5. **题目约束"常量级额外空间"**：这排除了哈希表解法（O(n) 空间），双指针 O(1) 空间完美满足。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 两层循环 | O(n²) | O(1) | 能说出即可 |
| 二分查找 | 固定一个，二分找另一个 | O(n log n) | O(1) | 加分项 |
| 双指针（对撞指针） | 左右指针向中间夹 | O(n) | O(1) | ⭐ 必须写出 |

## 关键提示

1. **利用有序性**：如果数组无序，你可能会想到哈希表（LeetCode 1. Two Sum 的做法）。但本题数组有序且要求 O(1) 空间，暗示你应该利用"有序"来避免额外空间。

2. **双指针的移动依据**：当前和与 target 的大小关系只有三种，每种情况下只有一个指针该动。想清楚：为什么不能同时移动两个指针？

3. **二分查找的搜索范围**：固定 `numbers[i]` 后，配对元素只能在 `i+1` 到 `n-1` 之间找（不能重复使用同一元素）。

4. **下标从 1 开始**：题目要求返回 1-indexed 的下标，别忘了 +1。

5. **不会有无解的情况**：题目保证恰好有一个答案，所以不需要处理找不到的情况。

```
双指针过程示意 (numbers = [2, 7, 11, 15], target = 9):

  left                right
   ↓                    ↓
  [2,    7,   11,   15]
   sum = 2 + 15 = 17 > 9  → right 左移

  left           right
   ↓               ↓
  [2,    7,   11,   15]
   sum = 2 + 11 = 13 > 9  → right 左移

  left      right
   ↓          ↓
  [2,    7,   11,   15]
   sum = 2 + 7 = 9 == 9   → 找到! 返回 [1, 2]
```

## 解法详解

### 解法1: 暴力枚举 — O(n²) / O(1)

**思考过程**：最直接的想法，枚举所有可能的两数组合，检查和是否等于 target。

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& numbers, int target) {
        int n = numbers.size();
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                if (numbers[i] + numbers[j] == target) {
                    return {i + 1, j + 1}; // 1-indexed
                }
            }
        }
        return {}; // 题目保证有解，不会执行到这里
    }
};
```

**关键点**：这个解法完全没有利用"数组有序"的条件。对于 n = 3×10⁴，O(n²) ≈ 9×10⁸ 次操作，可能超时。

---

### 解法2: 二分查找 — O(n log n) / O(1)

**从解法1优化**：解法1的瓶颈是内层循环——对于每个 `numbers[i]`，线性扫描找配对。数组有序，可以用二分查找将内层从 O(n) 降到 O(log n)。

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& numbers, int target) {
        int n = numbers.size();
        for (int i = 0; i < n; i++) {
            int complement = target - numbers[i];
            // 在 [i+1, n-1] 范围内二分查找 complement
            int lo = i + 1, hi = n - 1;
            while (lo <= hi) {
                int mid = lo + (hi - lo) / 2; // 防溢出写法
                if (numbers[mid] == complement) {
                    return {i + 1, mid + 1}; // 1-indexed
                } else if (numbers[mid] < complement) {
                    lo = mid + 1;
                } else {
                    hi = mid - 1;
                }
            }
        }
        return {};
    }
};
```

**二分搜索空间收缩过程**（numbers = [2, 3, 4], target = 6, i = 0, 找 4）：
```
搜索范围 [3, 4]（索引 1~2）
Round1: lo=1, hi=2, mid=1, numbers[1]=3 < 4 → lo=2
Round2: lo=2, hi=2, mid=2, numbers[2]=4 == 4 → 找到!
```

**关键点**：二分的搜索起点是 `i + 1` 而不是 `0`，因为不能重复使用同一元素，且 j > i。

---

### 解法3: 双指针（对撞指针） — O(n) / O(1) ⭐ 面试首选

**核心洞察**：数组有序 → 最小值在最左，最大值在最右。从两端开始：
- 和太大 → 需要减小，只能让右指针左移（使较大的数变小）
- 和太小 → 需要增大，只能让左指针右移（使较小的数变大）
- 每次移动一个指针，排除一个不可能的候选，所以最多移动 n 次

**为什么不会漏解？**
假设答案是 `(a, b)` 其中 `a = numbers[i*]`, `b = numbers[j*]`。
- 如果 left 还没到 i*，此时 `numbers[left] < a`，所以 `numbers[left] + numbers[right] ≤ a + b = target`（右指针不会越过 j*，因为只有 sum > target 才右移右指针）。
- 对称地，right 不会越过 j*。所以 left 和 right 最终一定会在 (i*, j*) 相遇。

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& numbers, int target) {
        int left = 0, right = numbers.size() - 1;
        while (left < right) {
            int sum = numbers[left] + numbers[right];
            if (sum == target) {
                return {left + 1, right + 1}; // 转成 1-indexed
            } else if (sum < target) {
                left++;  // 和太小，需要更大的左值
            } else {
                right--; // 和太大，需要更小的右值
            }
        }
        return {}; // 题目保证有解
    }
};
```

**关键点**：`while (left < right)` 用 `<` 不是 `<=`，因为两个数不能是同一个元素。

## 解法对比

| | 暴力枚举 | 二分查找 | 双指针 |
|---|---|---|---|
| 时间 | O(n²) | O(n log n) | O(n) |
| 空间 | O(1) | O(1) | O(1) |
| 利用有序性 | ❌ | ✅ 二分加速查找 | ✅ 单调性排除候选 |
| 代码复杂度 | 最简单 | 中等 | 最简单 |
| 面试推荐 | 仅作分析起点 | 展示二分能力 | **首选** |

**什么时候选哪个？**
- 面试直接写双指针，最优且代码最短
- 二分查找适合"固定一个找另一个"的思维模式，在某些变体题中更灵活（比如数组不支持随机移动、只能单向遍历时）

## 易错点

1. **下标偏移忘 +1**
   - ✗ `return {left, right};` — 返回的是 0-indexed
   - ✓ `return {left + 1, right + 1};` — 题目要求 1-indexed

2. **二分查找起点错误**
   - ✗ `int lo = 0;` — 可能找到 i 自身，重复使用同一元素
   - ✓ `int lo = i + 1;` — 配对元素一定在 i 右边

3. **双指针循环条件错误**
   - ✗ `while (left <= right)` — 当 left == right 时是同一个元素，不能配对
   - ✓ `while (left < right)` — 保证是两个不同元素

4. **二分查找中间值溢出**
   - ✗ `int mid = (lo + hi) / 2;` — lo + hi 可能溢出 int
   - ✓ `int mid = lo + (hi - lo) / 2;` — 安全写法（本题数据范围小不会溢出，但养成好习惯）

## 面试追问

**Q1（基础理解）**：为什么双指针不会漏掉正确答案？
> 关键在于有序性。当 `sum > target` 时，对于当前的 right，left 右边所有元素与 right 的和只会更大，所以 right 和当前 left 及其右侧的配对都不可能是答案。因此 right-- 不会错过任何有效配对。left++ 同理。

**Q2（空间约束）**：如果没有 O(1) 空间限制，还有什么解法？
> 可以用哈希表（和 LeetCode 1 一样），边遍历边存，O(n) 时间 O(n) 空间。但本题给了有序条件又限制了空间，就是在考双指针。

**Q3（变体）**：如果要找所有满足条件的配对（可能有多个），双指针怎么改？
> 找到一对后不立即返回，而是记录结果，然后同时 `left++` 和 `right--`（因为固定一端另一端也唯一确定）。如果有重复元素，还需要跳过相同值来去重。这和 LeetCode 15. 三数之和 中的去重逻辑一致。

**Q4（扩展）**：如果是三数之和呢？
> 固定第一个数，问题退化为在剩余部分做两数之和 II。所以三数之和 = 排序 + 枚举第一个数 + 双指针。这就是 LeetCode 15 的做法。

## 相关题型

- **1. 两数之和** — 数组无序，不能用双指针（没有单调性），用哈希表 O(n)/O(n)。本题等于 "如果数组有序且要求 O(1) 空间" 的 follow-up。
- **15. 三数之和** — 复用本题的双指针作为内层，外层多加一层枚举。去重逻辑是额外难点。
- **16. 最接近的三数之和** — 同样的双指针框架，区别是不找精确匹配而是维护最小差值。
- **653. 两数之和 IV - 输入二叉搜索树** — 本题思想搬到 BST 上，用中序遍历得到有序数组再双指针，或直接用双迭代器模拟。
