# 657. 机器人能否返回原点 (Robot Return to Origin)

**难度**: Easy | **标签**: String, Simulation

## 核心思路

机器人在二维平面上从原点 (0, 0) 出发，执行一系列 U/D/L/R 移动。判断最终是否回到原点，等价于判断**水平位移和垂直位移是否都为零**。即 L 和 R 的数量相等，且 U 和 D 的数量相等。

最直接的做法是维护两个计数器（x, y），遍历字符串统计净位移。也可以用字符计数法，分别统计四个方向的出现次数。

## 思维链

1. **建模**：每个移动指令改变坐标——R: x+1, L: x-1, U: y+1, D: y-1
2. **终止条件**：回到原点等价于最终 x == 0 && y == 0
3. **等价条件**：count('L') == count('R') && count('U') == count('D')
4. **一次遍历**：遍历字符串，维护 x, y 两个计数器即可

## 解法概览

| 解法 | 时间复杂度 | 空间复杂度 | 特点 |
|------|-----------|-----------|------|
| 坐标模拟 | O(n) | O(1) | 最直观，推荐 |
| 字符计数 | O(n) | O(1) | 利用 count 函数，代码简洁 |
| 哈希表计数 | O(n) | O(1) | 通用性强，适合方向更多的扩展 |

## 关键提示

1. **两个独立维度**：x 轴（L/R）和 y 轴（U/D）是完全独立的。回到原点需要两个维度都归零
2. **不需要记录路径**：只关心最终位置，不关心中间经过的点。因此只需计数
3. **字符串长度的奇偶性**：如果字符串长度为奇数，不可能回到原点（每步移动 1 个单位，奇数步净位移必为奇数）。这是一个 O(1) 的快速判断
4. **count 方法**：C++ 中可以用 `count(moves.begin(), moves.end(), 'U')` 来计数

## 解法详解

### 解法一：坐标模拟（推荐）

**思路**：维护 (x, y) 坐标，遍历每个字符更新坐标，最后检查是否回到原点。

**步骤**：
1. 初始化 `x = 0, y = 0`
2. 遍历字符串中的每个字符 c：
   - 'U': y++
   - 'D': y--
   - 'L': x--
   - 'R': x++
3. 返回 `x == 0 && y == 0`

**特点**：代码清晰，容易扩展到更多方向（如对角线移动）。

### 解法二：字符计数

**思路**：分别统计四个方向的出现次数，检查对称性。

**步骤**：
1. 统计 'U' 和 'D' 的出现次数
2. 统计 'L' 和 'R' 的出现次数
3. 返回 `countU == countD && countL == countR`

**特点**：可以用 STL 的 `count` 算法，代码更简洁。但遍历了字符串多次（实际影响不大）。

### 解法三：提前剪枝版本

**思路**：在坐标模拟的基础上，先检查字符串长度是否为偶数。

**步骤**：
1. 如果 `moves.size()` 是奇数，直接返回 false
2. 否则执行坐标模拟

**特点**：常数级优化，面试中可以提到展示细节意识。

## 易错点

1. **方向搞反**：U 和 D、L 和 R 的对应关系搞混。建议用 `switch-case` 或 `if-else` 明确写出
2. **只检查一个维度**：忘记同时检查 x 和 y 两个方向都归零
3. **坐标溢出**：字符串长度最大 2*10^4，int 类型完全够用，不会溢出
4. **空字符串处理**：题目约束 `moves.length >= 1`，不需要特殊处理空串
5. **误认为需要模拟路径**：这是一个常见的过度设计错误，只需要关注最终位置

## 面试追问

1. **Q: 如果需要判断机器人是否经过原点（不仅仅是最终回到原点）呢？**
   - A: 需要在每一步移动后都检查 `x == 0 && y == 0`。如果任何中间步骤满足则返回 true。时间复杂度不变，但不能用字符计数法。

2. **Q: 如果增加对角线方向（如 'UL', 'UR', 'DL', 'DR'），如何修改？**
   - A: 每个对角线方向同时改变 x 和 y。仍然维护 (x, y) 坐标即可。但输入格式需要调整（单字符变双字符）。

3. **Q: 如果字符串非常长（10^9），能否不遍历完整字符串？**
   - A: 如果没有任何特殊规律（如周期性），必须遍历整个字符串。但如果移动序列是周期性重复的，可以只分析一个周期。

4. **Q: 能否用数学方法 O(1) 判断？**
   - A: 不能完全 O(1)，因为需要读取输入。但如果预先知道各方向的计数（如外部数据），则可以 O(1) 判断。

5. **Q: 这个思路如何扩展到三维空间？**
   - A: 增加第三个坐标 z，对应两个新方向（如 F/B 表示前后）。最终检查 `x == 0 && y == 0 && z == 0`。
