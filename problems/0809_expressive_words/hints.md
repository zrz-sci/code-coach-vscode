# 809. 情感丰富的文字

## 核心思路

将字符串 `s` 和每个 `word` 都按**连续相同字符分组**，然后逐组对比。一个 word 是 stretchy 的条件：(1) 分组字符顺序完全一致；(2) 每组中 s 的长度 >= word 的长度；(3) 如果 s 的组长度 > word 的组长度，则 s 的组长度必须 >= 3（否则无法通过扩展操作得到）。

## 思维链

1. **读完题第一反应**：需要比较 s 和 word 的字符"组结构"。例如 `"heeellooo"` 分组为 `(h,1)(e,3)(l,2)(o,3)`，`"hello"` 分组为 `(h,1)(e,1)(l,2)(o,1)`。

2. **什么时候一个组匹配？** 对于对应位置的字符组 `(c1, len1)` 和 `(c2, len2)`：
   - 字符必须相同：`c1 == c2`
   - 如果 `len1 == len2`：完全匹配，OK
   - 如果 `len1 > len2`：word 的组被扩展了，但扩展后的长度 `len1` 必须 >= 3
   - 如果 `len1 < len2`：word 的组比 s 还长，不可能通过扩展得到，FAIL

3. **为什么 >= 3？** 题目说"扩展操作是将某组的大小增加到三或更多"。这意味着只有当目标组长度 >= 3 时才能进行扩展。如果 s 中的组长度为 2 而 word 的组长度为 1，那扩展后只有 2 < 3，不符合扩展规则。

4. **双指针实现**：不需要真的建立分组数组，可以用双指针同时遍历 s 和 word，遇到一组相同字符时计算长度并比较。

5. **计数**：对每个 word 判断是否 stretchy，统计个数。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 分组 + 逐组对比 | 将 s 和 word 按连续字符分组，逐组检查 | O(n * (|s| + max|w|)) | O(1) | ⭐ 必须写出 |
| 双指针（不建组） | 双指针在线统计每组长度 | O(n * (|s| + max|w|)) | O(1) | ⭐ 等价写法 |

> 两种写法本质相同，只是一种先分组再比较，另一种边扫边比较。面试中推荐双指针写法，代码更紧凑。

## 关键提示

1. **扩展规则的关键细节**：扩展操作要求目标组大小 >= 3。所以 s 中组长度为 2、word 中组长度为 1 时，**不能**通过扩展得到（因为 2 < 3）。

2. **组数必须相同**：如果 s 有 4 组而 word 有 3 组，直接不匹配。

3. **精确匹配也是合法的**：如果 s 和 word 的某组长度相同，不需要扩展，直接匹配。这时不要求 >= 3。

4. 判断逻辑：
```
对应组 (char_s, len_s) vs (char_w, len_w):
  char_s != char_w          → FAIL
  len_s == len_w            → OK (精确匹配)
  len_s > len_w && len_s>=3 → OK (合法扩展)
  len_s > len_w && len_s<3  → FAIL (组太短,不能扩展)
  len_s < len_w             → FAIL (word比s还长)
```

## 解法详解

### 解法1: 双指针逐组对比 -- O(n * L) / O(1) ⭐ 面试首选

**思考过程**：

双指针同时在 s 和 word 上滑动，每次找出一组连续相同字符，比较字符和长度。

```cpp
class Solution {
public:
    int expressiveWords(string s, vector<string>& words) {
        int count = 0;
        for (const string& word : words) {
            if (isStretchy(s, word)) count++;
        }
        return count;
    }
    
    bool isStretchy(const string& s, const string& w) {
        int i = 0, j = 0;
        int n = s.size(), m = w.size();
        
        while (i < n && j < m) {
            // 字符必须相同
            if (s[i] != w[j]) return false;
            
            // 统计 s 中当前组的长度
            int lenS = 0;
            char ch = s[i];
            while (i < n && s[i] == ch) { i++; lenS++; }
            
            // 统计 w 中当前组的长度
            int lenW = 0;
            while (j < m && w[j] == ch) { j++; lenW++; }
            
            // 判断是否合法
            if (lenS < lenW) return false;        // word 的组更长，不可能
            if (lenS != lenW && lenS < 3) return false; // 扩展了但 <3
        }
        
        // 两个指针都必须走到末尾
        return i == n && j == m;
    }
};
```

**关键点**：
- `lenS < lenW`：s 的组比 word 短，无法匹配。
- `lenS != lenW && lenS < 3`：发生了扩展但结果长度 < 3，不满足扩展规则。
- 最后检查 `i == n && j == m` 确保两个字符串都完整匹配。

## 易错点

1. **忘记 >= 3 的约束**：
   - ✗ 只要 `lenS >= lenW` 就认为合法
   - ✓ 当 `lenS > lenW` 时，还需要 `lenS >= 3`

2. **忘记检查两个指针都到末尾**：
   - ✗ 循环结束后直接返回 true
   - ✓ 必须确认 `i == n && j == m`，否则 s 或 word 可能有剩余未匹配部分

3. **lenS == lenW 时误要求 >= 3**：
   - ✗ 所有情况都要求 `lenS >= 3`
   - ✓ 精确匹配（`lenS == lenW`）时不需要 >= 3，只有扩展时才需要

4. **内层循环忘记边界检查**：
   - ✗ `while (s[i] == ch) { i++; lenS++; }`（i 越界）
   - ✓ `while (i < n && s[i] == ch) { i++; lenS++; }`

## 面试追问

**Q1: 如果扩展规则改为"扩展后的组大小必须 >= 2"而非 >= 3，代码怎么改？**

> 只需把判断条件中的 `lenS < 3` 改为 `lenS < 2` 即可。逻辑框架完全不变。

**Q2: 如果允许"收缩"操作（把 >= 3 的组缩短），怎么判断 word 是否可以通过扩展/收缩变成 s？**

> 收缩和扩展都要求目标长度 >= 3。条件变为：(1) `lenS == lenW`（不操作）；(2) `lenS != lenW && lenS >= 3 && lenW >= 3`（扩展或收缩都合法）；(3) `lenS > lenW && lenS >= 3`（只扩展）。需要根据题意精确定义。

**Q3: 时间复杂度中 L 代表什么？能否优化？**

> L 是 s 和 words 中最长字符串的长度。对于每个 word 都需要 O(|s| + |w|) 的时间。如果 words 数量很大，可以先将 words 预处理为分组表示并排序去重，但不会改变渐进复杂度。
