# 438. 找到字符串中所有字母异位词

## 核心思路

本质上在问：在字符串 `s` 中，所有长度等于 `len(p)` 的子串中，哪些子串的**字符频率**和 `p` 完全相同？这是一个**固定长度滑动窗口 + 频率比较**的经典问题。

## 思维链

1. **读完题第一反应**：对 `s` 中每个长度为 `len(p)` 的子串，判断它是不是 `p` 的异位词。最朴素的方法：截取子串 → 排序 → 和排序后的 `p` 比较。
2. **暴力解的瓶颈**：每个子串排序要 O(m log m)，总共有 n-m+1 个子串，总时间 O(n·m log m)。排序太贵了。
3. **换个判断方式**：异位词的本质是"字符频率相同"。用长度 26 的频率数组代替排序，比较两个频率数组只需 O(26) = O(1)。但每次重新统计子串频率仍然是 O(m)。
4. **关键突破 — 滑动窗口**：相邻的两个子串 `s[i..i+m-1]` 和 `s[i+1..i+m]` 只差一个字符（左边去掉 `s[i]`，右边加上 `s[i+m]`）。用滑动窗口维护频率数组，每次只做 O(1) 的增删操作。
5. **进一步优化**：维护一个 `diff` 变量记录"有多少个字符的频率还不匹配"，这样连 O(26) 的数组比较都省了，每次判断变为 O(1)。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力排序 | 每个子串排序后比较 | O(n·m log m) | O(m) | 能说出即可 |
| 固定窗口 + 频率数组比较 | 滑窗维护频率，每次比较26个字符 | O(26n) | O(1) | ⭐ 必须写出 |
| 固定窗口 + diff 计数 | 滑窗 + 用 diff 变量追踪不匹配数 | O(n) | O(1) | 加分项 |

## 关键提示

1. **异位词 = 字符频率完全相同**。不需要排序，用频率数组（长度26）就够了。
2. **窗口大小是固定的**（等于 `p` 的长度）。这比可变窗口更简单 — 右端扩一步，左端也必须缩一步。
3. **增量更新**：窗口滑动一步只改变两个字符的频率，不需要重新统计整个窗口。
4. **比较优化**：与其每次比较两个长度 26 的数组，不如维护一个"差异计数" `diff`，当 `diff == 0` 时就找到了一个异位词。
5. **滑窗过程可视化**（以 s = "cbaebabacd", p = "abc" 为例）：
```
s:  c b a e b a b a c d
    [c b a]                ← 频率匹配 p! 记录 index=0
      [b a e]              ← 'e' 多了，不匹配
        [a e b]            ← 不匹配
          [e b a]          ← 不匹配
            [b a b]        ← 'b' 多了，不匹配
              [a b a]      ← 'a' 多了，不匹配
                [b a c]    ← 频率匹配 p! 记录 index=6
                  [a c d]  ← 不匹配
```

## 解法详解

### 解法1: 暴力排序 — O(n·m log m) / O(m)

**思考过程**：异位词就是重新排列后相等的字符串。最直接的方法：把 `p` 排序，然后 `s` 中每个长度为 m 的子串也排序，比较是否相等。

```cpp
class Solution {
public:
    vector<int> findAnagrams(string s, string p) {
        vector<int> result;
        int n = s.size(), m = p.size();
        if (n < m) return result;
        
        string sorted_p = p;
        sort(sorted_p.begin(), sorted_p.end());
        
        for (int i = 0; i <= n - m; i++) {
            string sub = s.substr(i, m);
            sort(sub.begin(), sub.end());
            if (sub == sorted_p) {
                result.push_back(i);
            }
        }
        return result;
    }
};
```

**关键点**：这个方法完全正确但效率低。每次 `substr` + `sort` 的开销都是 O(m log m)，而且相邻子串之间的大量重复工作被浪费了。

---

### 解法2: 固定窗口 + 频率数组比较 — O(26·n) / O(1) ⭐ 面试首选

**从解法1优化**：排序的目的只是判断字符频率是否相同。直接用长度 26 的数组统计频率，比较两个数组只需 O(26)。再用滑动窗口避免每次重新统计。

```cpp
class Solution {
public:
    vector<int> findAnagrams(string s, string p) {
        vector<int> result;
        int n = s.size(), m = p.size();
        if (n < m) return result;
        
        vector<int> p_cnt(26, 0), w_cnt(26, 0);
        
        // 统计 p 的频率，同时初始化第一个窗口
        for (int i = 0; i < m; i++) {
            p_cnt[p[i] - 'a']++;
            w_cnt[s[i] - 'a']++;
        }
        if (p_cnt == w_cnt) result.push_back(0);
        
        // 滑动窗口：每次右移一步
        for (int i = m; i < n; i++) {
            w_cnt[s[i] - 'a']++;           // 右端新字符进入窗口
            w_cnt[s[i - m] - 'a']--;       // 左端旧字符离开窗口
            if (p_cnt == w_cnt) {
                result.push_back(i - m + 1);
            }
        }
        return result;
    }
};
```

**关键点**：
- 窗口大小始终是 `m`，所以每次右端 +1 的同时左端也 +1。
- `vector<int>` 的 `==` 运算符会逐元素比较，这里是 26 个元素，视为 O(1)。
- 不需要 `substr`，只在频率数组上做 +1/-1。

---

### 解法3: 固定窗口 + diff 计数 — O(n) / O(1) 加分项

**从解法2优化**：解法2每次滑动后都要比较两个长度26的数组。能否避免？维护一个 `diff` 变量表示"有多少种字符的频率目前不匹配"。当 `diff == 0` 时，窗口就是异位词。

```cpp
class Solution {
public:
    vector<int> findAnagrams(string s, string p) {
        vector<int> result;
        int n = s.size(), m = p.size();
        if (n < m) return result;
        
        // cnt[c] = p中字符c的频率 - 窗口中字符c的频率
        // cnt[c] == 0 表示字符c已经匹配
        vector<int> cnt(26, 0);
        for (char c : p) cnt[c - 'a']++;
        
        int diff = 0;  // 有多少种字符的 cnt 不为 0
        // 初始化：统计 cnt 中非零项的数量
        for (int i = 0; i < 26; i++) {
            if (cnt[i] != 0) diff++;
        }
        
        // 初始化第一个窗口 [0, m-1]
        for (int i = 0; i < m; i++) {
            int idx = s[i] - 'a';
            // 加入窗口前 cnt[idx] 的状态 → 加入后的状态
            if (cnt[idx] == 0) diff++;       // 从匹配变成不匹配
            cnt[idx]--;
            if (cnt[idx] == 0) diff--;       // 变成匹配了
        }
        if (diff == 0) result.push_back(0);
        
        // 滑动
        for (int i = m; i < n; i++) {
            // 右端字符进入窗口
            int r = s[i] - 'a';
            if (cnt[r] == 0) diff++;
            cnt[r]--;
            if (cnt[r] == 0) diff--;
            
            // 左端字符离开窗口
            int l = s[i - m] - 'a';
            if (cnt[l] == 0) diff++;
            cnt[l]++;
            if (cnt[l] == 0) diff--;
            
            if (diff == 0) result.push_back(i - m + 1);
        }
        return result;
    }
};
```

**关键点**：
- `cnt` 数组只有一个，存的是"p的频率 - 窗口的频率"的差值。
- 每次修改 `cnt[x]` 前后检查它是否跨越了 0 这个边界，以此更新 `diff`。
- 当 `diff == 0`，所有 26 个字符的频率差都是 0，即完全匹配。

## 解法对比

| | 暴力排序 | 频率数组比较 | diff 计数 |
|---|---|---|---|
| 核心操作 | 排序+字符串比较 | 滑窗+数组比较 | 滑窗+diff变量 |
| 每步窗口移动 | O(m log m) | O(26) | O(1) |
| 总时间 | O(n·m log m) | O(26n) | O(n) |
| 代码复杂度 | 最简单 | 简单 | 稍复杂 |
| 面试推荐 | ✗ | ✓ 首选 | ✓ 追问时写 |

实际面试中，**解法2**是最佳平衡点：思路清晰、代码简洁、O(26n)在实际中就是 O(n)。解法3是面试官追问"能否真正 O(n)"时的加分项。

## 易错点

1. **忘记 `n < m` 的边界检查**：
   - ✗ 直接开始循环 → 当 `s` 比 `p` 短时越界
   - ✓ 开头 `if (n < m) return {};`

2. **滑窗左端索引算错**：
   - ✗ `w_cnt[s[i - m + 1] - 'a']--` — 减的是新窗口左端
   - ✓ `w_cnt[s[i - m] - 'a']--` — 减的是被移出去的旧左端字符

3. **diff 更新顺序搞反**：
   - ✗ 先改 `cnt[x]`，再检查原值是否为 0
   - ✓ **先检查**原值是否为 0（决定 diff 是否+1），**再改** `cnt[x]`，**再检查**新值是否为 0（决定 diff 是否-1）

4. **起始索引计算**：
   - 滑动循环中 `i` 是窗口右端，起始索引是 `i - m + 1`，不是 `i`

## 面试追问

**Q1: 暴力解的时间复杂度是多少？瓶颈在哪？**
→ O(n·m log m)，瓶颈在于每个子串都要排序。可以用频率数组替代排序把单次比较从 O(m log m) 降到 O(m)，再用滑动窗口把 O(m) 降到 O(1)。

**Q2: 解法2中每次比较26个字符，能否做到真正 O(1)？**
→ 可以。维护 `diff` 变量追踪不匹配的字符种类数。每次窗口滑动只影响2个字符的频率，`diff` 的更新是 O(1)，判断 `diff == 0` 也是 O(1)。这就是解法3。

**Q3: 如果字符集不是 26 个小写字母，而是 Unicode 全集怎么办？**
→ 频率数组换成 `unordered_map`。diff 思路完全不变，只是用哈希表存 `cnt`，当某个 key 的值变为 0 时从 map 中删除。`diff` 就是 map 的 size。

**Q4: 这道题和 LeetCode 567（字符串的排列）有什么关系？**
→ 567 只要求判断是否存在一个异位词子串（返回 bool），438 要求返回所有位置。代码几乎一样，438 只是把 `return true` 换成 `result.push_back(i)`。
