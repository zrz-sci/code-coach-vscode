# 452. 用最少数量的箭引爆气球

## 核心思路

本质上这是一个**区间重叠问题**：找出最少多少组"互相重叠的区间"能覆盖所有区间。每一组重叠的区间可以用一支箭（射在公共重叠区域内）全部引爆。

## 思维链

1. **读完题第一反应**：每个气球是一个区间 `[start, end]`，一支箭射在某个 x 坐标上，能引爆所有包含这个 x 的气球。要用最少的箭。这不就是在问"最少几个点能覆盖所有区间"吗？

2. **暴力怎么做？** 枚举所有可能的射箭组合？这是一个集合覆盖问题，暴力搜索是指数级的，完全不可行。那换个角度——能不能贪心？

3. **贪心的直觉**：如果我们把气球排序，尽量让一支箭射爆尽可能多的气球，是不是就能减少箭的数量？关键问题是：**按什么排序？贪心策略是什么？**

4. **按右端点排序的贪心**：如果按每个气球的**右端点（end）从小到大**排序，那么第一支箭应该射在第一个气球的右端点处——这是能覆盖第一个气球的"最靠右"的位置，这样后续的气球更有可能被这支箭一起引爆。然后跳过所有被这支箭引爆的气球，对下一个未被引爆的气球重复同样的策略。

5. **为什么这个贪心是对的？** 第一个气球无论如何都需要一支箭。把箭射在它的最右端（end），不会比射在更左的位置差——射得越靠右，后续气球的 start 落在这支箭左边的概率越大。这就是"活动选择问题"的经典贪心证明思路。

6. **也可以按左端点排序**：按 start 从小到大排序，维护一个"当前箭能覆盖的最右位置"（即当前重叠区间的交集右端点），遍历时不断缩小这个右端点。当下一个气球的 start 超过这个右端点时，必须射出新箭。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 按右端点排序 + 贪心 | 经典活动选择：每次射在当前最早结束的气球右端点 | O(n log n) | O(log n) | ⭐ 必须写出 |
| 按左端点排序 + 贪心 | 维护重叠区间的交集右端点，断开时加箭 | O(n log n) | O(log n) | ⭐ 必须写出 |

> 两种排序方式本质思路一致，都是 O(n log n)，面试中任选一种即可。但最好能说出两种的区别。

## 关键提示

1. **排序是关键**：无序的区间很难贪心，排序后才能"从左到右扫一遍"解决问题。

2. **按右端点排序时**，贪心策略是"射在当前未被引爆气球中最早结束的那个气球的右端点"。

3. **按左端点排序时**，关键操作是"缩小当前箭能到达的最远位置"：`arrow_end = min(arrow_end, current_balloon_end)`。

4. **边界相切也算引爆**：`[1,2]` 和 `[2,3]` 可以被一支箭在 x=2 处同时引爆，判断用 `<=` 不是 `<`。

5. **数据范围**：坐标可达 `±2^31`，排序时用 lambda 比较而非减法，避免 int 溢出。

```
示例1可视化 (排序前):
气球:  [10----16]  [2----8]  [1---6]  [7----12]

按右端点排序后:
       [1---6]
          [2------8]
                [7----12]
                   [10------16]
       |-----|-----|-----|-----|-----|-----|
       1     4     7    10    13    16

箭1: 射在 x=6 → 引爆 [1,6] 和 [2,8]
箭2: 射在 x=12 → 引爆 [7,12] 和 [10,16]
答案: 2 支箭
```

## 解法详解

### 解法1: 按右端点排序 + 贪心 — O(n log n) / O(log n) ⭐ 面试首选

**思考过程**：这是经典的"活动选择问题"变体。在活动选择问题中，我们按结束时间排序，每次贪心选择最早结束的活动；类比到本题，按气球右端点排序，每次把箭射在当前未爆气球的最右端，尽可能多地覆盖后续气球。

```cpp
class Solution {
public:
    int findMinArrowShots(vector<vector<int>>& points) {
        if (points.empty()) return 0;
        
        // 按右端点从小到大排序
        // 用 a[1] < b[1] 而非减法，避免 int 溢出
        sort(points.begin(), points.end(), [](const vector<int>& a, const vector<int>& b) {
            return a[1] < b[1];
        });
        
        int arrows = 1;                    // 至少需要一支箭
        int arrow_pos = points[0][1];      // 第一支箭射在第一个气球的右端点
        
        for (int i = 1; i < points.size(); i++) {
            // 如果当前气球的起点 > 箭的位置，说明这支箭够不着
            if (points[i][0] > arrow_pos) {
                arrows++;                          // 需要新箭
                arrow_pos = points[i][1];          // 新箭射在这个气球的右端点
            }
            // 否则：当前气球被已有的箭引爆了，不需要额外操作
        }
        
        return arrows;
    }
};
```

**关键点**：
- 排序按**右端点**，不是左端点。
- 判断条件是 `>` 不是 `>=`（题意：边界相切可以引爆）。
- 箭位置只在需要新箭时更新，且一定射在新气球的右端点。

---

### 解法2: 按左端点排序 + 贪心（维护交集） — O(n log n) / O(log n)

**从解法1换个角度**：按左端点排序后，依次遍历气球。维护一个变量 `end` 表示"当前这支箭最远能到的位置"（即当前所有重叠气球的公共区间的右端点）。每遇到一个新气球：
- 如果它和当前区间有交集 → 缩小 `end` 为两者的 `min`
- 如果没有交集 → 必须射出新箭，`end` 重置为新气球的右端点

```cpp
class Solution {
public:
    int findMinArrowShots(vector<vector<int>>& points) {
        if (points.empty()) return 0;
        
        // 按左端点从小到大排序
        sort(points.begin(), points.end(), [](const vector<int>& a, const vector<int>& b) {
            return a[0] < b[0];
        });
        
        int arrows = 1;
        int end = points[0][1];   // 当前箭能到达的最远位置（交集右端点）
        
        for (int i = 1; i < points.size(); i++) {
            if (points[i][0] > end) {
                // 当前气球的起点超过了箭能到达的位置 → 需要新箭
                arrows++;
                end = points[i][1];
            } else {
                // 有交集 → 缩小交集右端点
                // 为什么取 min？因为箭必须在所有重叠气球的公共区域内
                end = min(end, points[i][1]);
            }
        }
        
        return arrows;
    }
};
```

**关键点**：
- 这里多了一步 `end = min(end, points[i][1])`，这是因为按左端点排序时，后面的气球右端点不一定更大。
- 解法1按右端点排序就不需要这步，因为右端点天然递增，箭射在最小的右端点处，后续更大的右端点不会影响。

## 解法对比

| | 按右端点排序 | 按左端点排序 |
|--|------------|------------|
| 排序依据 | `end` 从小到大 | `start` 从小到大 |
| 核心操作 | 只在断开时更新箭位置 | 每步维护交集右端点（取 min） |
| 代码复杂度 | 更简洁（不需要 min） | 略长一行 |
| 本质 | 活动选择问题 | 区间合并思路 |
| 结果 | 完全一致 | 完全一致 |

**面试建议**：按右端点排序的写法更简洁不容易出错，推荐首选。但要能解释为什么按右端点排序是正确的（贪心证明）。

## 易错点

1. **排序比较函数用减法导致溢出**：
   - ✗ `sort(..., [](auto& a, auto& b) { return a[1] - b[1]; });`
     当 `a[1] = INT_MAX, b[1] = INT_MIN` 时溢出！
   - ✓ `sort(..., [](auto& a, auto& b) { return a[1] < b[1]; });`

2. **判断重叠时用 `>=` 还是 `>`**：
   - ✗ `if (points[i][0] >= arrow_pos)` — 这会认为 `[1,2]` 和 `[2,3]` 不能同时引爆
   - ✓ `if (points[i][0] > arrow_pos)` — 边界相切算重叠

3. **按左端点排序时忘记取 min**：
   - ✗ 直接用 `end = points[0][1]` 不更新 — 可能箭位置超出某个短气球的右端
   - ✓ `end = min(end, points[i][1])` — 维护真正的公共重叠区间

4. **初始化 arrows 为 0**：
   - ✗ `int arrows = 0;` 然后从第 0 个气球开始循环 — 逻辑对但需要额外处理空数组
   - ✓ `int arrows = 1;` 从第 1 个气球开始循环 — 更清晰，需要先判空

## 面试追问

**Q1（基础理解）**：为什么要排序？不排序行不行？
> 不排序的话，气球分布杂乱无章，无法用一次线性扫描确定哪些气球可以被同一支箭引爆。排序后相邻区间才有"重叠 or 断开"的清晰判断依据。

**Q2（贪心证明）**：为什么按右端点排序的贪心是正确的？
> 反证法：假设最优解中第一支箭没有射在第一个气球（右端点最小的）的右端点处。那这支箭只可能射在更左的位置（否则不能覆盖第一个气球）。但射在更左的位置只会更少地覆盖后续气球，不会更优。所以射在右端点处至少和最优解一样好。归纳可得整个贪心策略最优。

**Q3（变体）**：如果气球是开区间 `(start, end)` 而非闭区间，代码怎么改？
> 只需把判断条件从 `points[i][0] > arrow_pos` 改为 `points[i][0] >= arrow_pos`。因为边界相切时不再算重叠。

**Q4（关联）**：这道题和"无重叠区间"(LeetCode 435) 有什么关系？
> 完全互补！435 求的是"最少删除多少区间使得剩下的互不重叠"，而本题求的是"最少多少组重叠区间能覆盖全部"。设答案为 `arrows`，则 435 的答案 = `n - arrows`。排序和贪心策略完全一样。

## 相关题型

- **435. 无重叠区间** — 完全互补的问题，复用同样的"按右端点排序 + 贪心"模板，答案 = `n - findMinArrowShots()`。
- **56. 合并区间** — 同样需要排序后扫描，但操作是"合并"而非"计数"。区别：本题维护交集（min），56 维护并集（max）。
- **253. 会议室 II** — 类似的"最少资源数"问题，但用的是扫描线/堆而非贪心，因为会议不能通过一个"点"覆盖。
