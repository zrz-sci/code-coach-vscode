# 945. 使数组唯一的最小增量

## 核心思路

本质上在问：给定一组数，每个数只能增加不能减少，要让所有数互不相同，求最小的总增加量。关键洞察是**排序后，每个数至少要比前一个大1**。

## 思维链

1. **读完题第一反应**：每个重复的数需要被"推"到一个没人占的位置。最朴素做法？对于每个重复元素，一直 +1 直到不重复。
2. **暴力解的瓶颈**：用集合判重，每次 +1 逐步试探，最坏情况一个元素可能要 +n 次，总体 O(n²)。
3. **换个角度看问题**：如果数组排好序了呢？排序后，重复元素一定相邻。而且每个元素的"目标值"至少是前一个元素目标值+1。
4. **贪心策略浮现**：排序后从左到右扫描，维护一个 `need`（当前元素至少应该是多少）。如果 `nums[i] >= need`，不用动；如果 `nums[i] < need`，就把它增加到 `need`，代价是 `need - nums[i]`。
5. **能否不排序？**：可以！用计数数组统计每个值的频次，然后从小到大扫描，把多余的"顺延"到下一个位置，类似桶排序的思想。
6. **复杂度对比**：排序法 O(n log n)，计数法 O(n + max_val)，各有适用场景。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力试探 | 用集合判重，每个重复元素逐步+1 | O(n²) 最坏 | O(n) | 能说出即可 |
| 排序+贪心 | 排序后逐个保证递增 | O(n log n) | O(1) | ⭐ 必须写出 |
| 计数+顺延 | 频次数组，多余元素向后推 | O(n + max_val) | O(max_val) | 加分项 |

## 关键提示

- **提示1**：排序后，问题变得极其简单——你只需要保证每个数严格大于前一个数。
- **提示2**：贪心的正确性：排序后每个数只能增加不能减少，所以让每个重复数增加到"刚好不重复"一定是最优的。
- **提示3**：对于计数法，想象一排桶（0, 1, 2, ...），每个桶最多装1个球，多出来的球顺延到下一个桶。
- **提示4**：注意数据范围——nums[i] 最大 10⁵，但 n 也是 10⁵，所以最终值可能到 2×10⁵。

## 解法详解

### 解法1: 暴力试探 — O(n²) / O(n)

**思考过程**：最直觉的方式——遍历每个元素，如果它已经出现过，就不断+1直到找到没出现过的值。

```cpp
class Solution {
public:
    int minIncrementForUnique(vector<int>& nums) {
        unordered_set<int> seen;
        int moves = 0;
        for (int num : nums) {
            // 如果当前值已被占用，就一直+1直到找到空位
            while (seen.count(num)) {
                num++;
                moves++;
            }
            seen.insert(num);
        }
        return moves;
    }
};
```

**关键点**：这个解法在极端情况下（如全部相同）退化为 O(n²)，因为每个元素都要"爬"很远。但它帮助我们理解题意——每个重复元素需要被"推"到最近的空位。

---

### 解法2: 排序 + 贪心 — O(n log n) / O(1) ⭐ 面试首选

**从解法1优化**：暴力法的瓶颈是"寻找空位"太慢。如果排序后从小到大处理，我们可以直接知道每个元素该放哪——至少比前一个大1。

```
// 示例: nums = [3, 2, 1, 2, 1, 7]
//
// 排序后: [1, 1, 2, 2, 3, 7]
//
// 逐个处理:
//   i=0: nums[0]=1, need=1  → 1 >= 1, 不动, need=2
//   i=1: nums[1]=1, need=2  → 1 < 2,  增加到2, moves += 2-1=1, need=3
//   i=2: nums[2]=2, need=3  → 2 < 3,  增加到3, moves += 3-2=1, need=4
//   i=3: nums[3]=2, need=4  → 2 < 4,  增加到4, moves += 4-2=2, need=5
//   i=4: nums[4]=3, need=5  → 3 < 5,  增加到5, moves += 5-3=2, need=6
//   i=5: nums[5]=7, need=6  → 7 >= 6, 不动, need=8
//
// 总 moves = 1+1+2+2+0 = 6 ✓
```

```cpp
class Solution {
public:
    int minIncrementForUnique(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int moves = 0;
        int need = 0;  // 当前元素至少应该是多少
        
        for (int num : nums) {
            // need 取 num 和 need 的较大值：
            // 如果 num >= need，不用增加，目标就是 num 本身
            // 如果 num < need，必须增加到 need
            need = max(need, num);
            moves += need - num;  // 增加量（可能为0）
            need++;               // 下一个元素至少要比当前大1
        }
        return moves;
    }
};
```

**关键点**：`need` 变量同时起到了"追踪下一个可用位置"的作用。每处理一个元素后，`need` 就是"下一个最小可用值"。

### 解法3: 计数 + 顺延 — O(n + max_val) / O(max_val)

**不同角度**：不排序，而是用计数数组统计频次，然后从小到大扫描。每个位置只能放1个，多余的"顺延"到下一个位置。

```
// 示例: nums = [3, 2, 1, 2, 1, 7]
//
// 计数: count[1]=2, count[2]=2, count[3]=1, count[7]=1
//
// 扫描:
//   val=0: count=0, 无操作
//   val=1: count=2, 留1个, 多1个顺延到val=2, moves += 1 (1→2)
//   val=2: count=2+1=3, 留1个, 多2个顺延到val=3, moves += 2 (两个2→3)
//   val=3: count=1+2=3, 留1个, 多2个顺延到val=4, moves += 2
//   val=4: count=0+2=2, 留1个, 多1个顺延到val=5, moves += 1
//   val=5: count=0+1=1, 留1个, 无多余
//   ...
//   val=7: count=1, 留1个, 无多余
//
// 总 moves = 1+2+2+1 = 6 ✓
```

```cpp
class Solution {
public:
    int minIncrementForUnique(vector<int>& nums) {
        int n = nums.size();
        int maxVal = *max_element(nums.begin(), nums.end());
        // 最终值可能到 maxVal + n（极端情况所有值相同）
        int limit = maxVal + n;
        
        vector<int> count(limit + 1, 0);
        for (int num : nums) {
            count[num]++;
        }
        
        int moves = 0;
        for (int val = 0; val < limit; val++) {
            if (count[val] > 1) {
                int overflow = count[val] - 1;  // 多余的元素个数
                count[val + 1] += overflow;      // 顺延到下一个位置
                moves += overflow;               // 每个多余元素+1
            }
        }
        return moves;
    }
};
```

**关键点**：每个多余元素只 +1 就顺延到下一个位置，如果下一个位置也满了，自然在下一轮继续顺延。这等价于每个元素最终增加了"它被推了多少格"。`moves += overflow` 只计了 +1 这一步，但元素可能被连续推多次，每次推都计了一次，所以总计是正确的。

## 解法对比

| | 排序+贪心 | 计数+顺延 |
|---|---|---|
| 时间 | O(n log n) | O(n + max_val) |
| 空间 | O(1) 原地排序 | O(max_val + n) |
| 适用 | 通用，面试首选 | 值域不太大时更快 |
| 思路直觉 | "每个元素至少比前一个大1" | "桶里多余的球往后推" |
| 代码量 | 最短 | 中等 |

面试推荐：**先说排序贪心**（最好写最好讲），面试官追问"能否更快"时给出计数法。

## 易错点

1. **`need` 更新遗漏**：
   - ✗ `need = num + 1;` — 当 `num < need` 时，应该用 `need` 而不是 `num`
   - ✓ `need = max(need, num) + 1;`（代码中拆成两行：先 `need = max(need, num)`，再 `need++`）

2. **计数数组大小不够**：
   - ✗ `vector<int> count(100001, 0);` — 如果所有元素都是 10⁵，最终值可能到 2×10⁵
   - ✓ `vector<int> count(maxVal + n + 1, 0);`

3. **排序贪心中忘记 moves 加的是差值**：
   - ✗ `moves++;` — 不是每次固定加1，而是加 `need - num` 的差
   - ✓ `moves += need - num;`

4. **暴力解用 `unordered_set` 但忘记更新**：插入的应该是最终值 `num`（已经自增后的），不是原始值。

## 面试追问

**Q1: 暴力解的时间复杂度是多少？能过吗？**
> O(n²) 最坏情况（如 [1,1,1,...,1]），n=10⁵ 会超时。但面试中先说暴力展示理解没问题。

**Q2: 排序贪心为什么是最优的？能不能证明？**
> 排序后，每个元素的目标值是"它自身"和"前一个目标值+1"的较大者。由于只能增加不能减少，这个贪心策略每一步都是局部最优的——让每个元素增加到刚好不冲突的最小值。可以用交换论证：如果存在更优方案，某个元素被增加到了更大的值，那把它换成更小的值不会更差。

**Q3: 如果操作变成"可以+1也可以-1"，怎么做？**
> 这变成了一个经典的中位数问题变体。排序后，让第 i 个元素的目标值为 `sorted[0] + i` 到 `sorted[n-1] + i` 之间选择，可以用数学方法求最优起点。本质上更像"使数组成为等差数列的最小代价"。
