# 1089. 复写零

## 核心思路

本质上是一个**原地（in-place）数组变换**问题：遇到零就复制一份，其余元素右移，超出数组长度的部分丢弃。关键洞察是**从后往前填充**，避免覆盖还未处理的元素。但要从后往前填，首先得知道"最终结果的最后一个元素来源于原数组的哪个位置"——所以需要**两遍扫描**。

## 思维链

1. **读完题第一反应** → 如果可以用额外数组，问题很简单：遍历原数组，非零直接写，零写两个，写满 n 个就停。但题目要求**原地操作 (in-place)**，不能用额外数组。

2. **从前往后能做吗？** → 不行。比如 `[1,0,2,3]`，处理到 `arr[1]=0` 时，如果直接在 `arr[2]` 插入一个0，那原本的 `arr[2]=2` 就被覆盖了，后面所有元素的信息都丢失了。

3. **为什么从后往前可以？** → 如果我们知道最终结果的"最后一个位置"对应原数组的哪个元素，就可以从那个位置开始，往前遍历原数组，往后填充结果。已经被"读取"过的位置被覆盖也没关系——它的值已经被用过了。

4. **如何确定"最后一个保留的元素"？** → 第一遍扫描：从左往右模拟复写过程。维护一个计数器 `zeros` 记录遇到了多少个零。当 `i + zeros >= n` 时，说明从 `arr[0..i]` 复写零后已经占满了整个数组，`arr[i]` 就是最后一个保留的元素。

5. **边界特殊情况** → 如果最后一个保留的元素恰好是 0，但只剩一个格子给它（`i + zeros == n`），那这个 0 只能写一份（不能复写），需要单独处理。

6. **第二遍从后往前填充** → 两个指针：`i` 指向最后一个保留的原始元素，`j` 从 `n-1` 开始。如果 `arr[i] != 0`，写一个；如果 `arr[i] == 0`，写两个。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 额外数组 | 新建数组按规则填充再拷回 | O(n) | O(n) | 不推荐（不满足原地要求） |
| 两遍扫描（从后往前填充） | 先确定边界，再倒序填充 | O(n) | O(1) | 必须掌握 |

## 关键提示

1. **问题转化**：想象你有一根"无限长"的复写结果，然后截取前 n 个元素。第一遍扫描的目的就是找到原数组中哪些元素会出现在这前 n 个结果里。

2. **两遍扫描的核心思路**：
   - 第一遍（正向）：确定原数组中最后一个会"留在结果中"的元素位置 `i`。
   - 第二遍（反向）：从位置 `i` 开始倒着读，从 `n-1` 开始倒着写。

3. **边界处理是关键**：如果第一遍结束时 `i + zeros == n`（刚好多出一格），且 `arr[i] == 0`，说明这个零只能写一份。这是最容易出错的地方。

4. **为什么不需要额外空间**：从后往前填充时，写入的位置 `j` 永远 >= 读取的位置 `i`（因为 `j = i + zeros`，`zeros >= 0`），所以写入不会覆盖还没读到的数据。

5. **与其他"原地操作"题的联系**：这道题和 "88. 合并两个有序数组" 有相同的核心技巧——当从前往后会覆盖数据时，改为从后往前操作。

## 解法详解

### 解法1: 额外数组（理解题意用）— O(n) / O(n)

**思考过程**: 如果不考虑空间限制，先把问题想清楚——直接模拟复写过程。

```cpp
class Solution {
public:
    void duplicateZeros(vector<int>& arr) {
        int n = arr.size();
        vector<int> result;
        for (int x : arr) {
            result.push_back(x);
            if (x == 0) result.push_back(0);
            if (result.size() >= n) break;
        }
        // 截取前 n 个
        for (int i = 0; i < n; i++) {
            arr[i] = result[i];
        }
    }
};
```

**关键点**:
- 这个解法帮助我们理解题意和最终结果的形态。
- 但它用了 O(n) 额外空间，不满足"原地操作"的要求。
- 它的价值：展示了"复写零"操作的本质就是在原数组前部做一次"带零扩展"的截断。

---

### 解法2: 两遍扫描（从后往前填充）— O(n) / O(1)

**从解法1优化**: 要原地操作，关键问题是"从前往后写会覆盖数据"。解决办法：先用第一遍扫描确定边界，然后从后往前填充。

```
示例: arr = [1, 0, 2, 3, 0, 4, 5, 0], n = 8

第一遍扫描 — 找到最后一个保留的元素:
  i=0: arr[0]=1, zeros=0, i+zeros=0 < 8 ✓
  i=1: arr[1]=0, zeros=1, i+zeros=2 < 8 ✓
  i=2: arr[2]=2, zeros=1, i+zeros=3 < 8 ✓
  i=3: arr[3]=3, zeros=1, i+zeros=4 < 8 ✓
  i=4: arr[4]=0, zeros=2, i+zeros=6 < 8 ✓
  i=5: arr[5]=4, zeros=2, i+zeros=7 < 8 ✓
  i=6: arr[6]=5, zeros=2, i+zeros=8 ≥ 8 → 停！

  最后保留的元素: arr[5]=4 (i回退到5)
  等等，更准确地说，循环退出时 i=6, 回退 i--→5

第二遍填充 — 从后往前:
  j=7, i=5: arr[5]=4 → arr[7]=4, j=6
  j=6, i=4: arr[4]=0 → arr[6]=0, arr[5]=0, j=4
  j=4, i=3: arr[3]=3 → arr[4]=3, j=3
  j=3, i=2: arr[2]=2 → arr[3]=2, j=2
  j=2, i=1: arr[1]=0 → arr[2]=0, arr[1]=0, j=0
  j=0, i=0: arr[0]=1 → arr[0]=1, j=-1

  结果: [1, 0, 0, 2, 3, 0, 0, 4] ✓
```

```
边界特例: arr = [8, 4, 5, 0, 0, 0, 0, 7], n = 8

第一遍:
  i=0: 8, zeros=0, 0<8 ✓
  i=1: 4, zeros=0, 1<8 ✓
  i=2: 5, zeros=0, 2<8 ✓
  i=3: 0, zeros=1, 4<8 ✓
  i=4: 0, zeros=2, 6<8 ✓
  i=5: 0, zeros=3, 8≥8 → 停！
  i=5 回退到 i=4... 但 i+zeros=4+3=7 < 8? 不对。

  让我们重新理清: 循环条件是 i+zeros < n, 
  i=5时 5+3=8 == n (不是<n), 刚好等于!
  这意味着 arr[5]=0 是最后一个保留的元素，但 i+zeros==n，
  且 arr[i]=0，这个零只能写一份！

  特殊处理: arr[7]=0, j=6, i=4
  然后正常从后往前填充。

  结果: [8, 4, 5, 0, 0, 0, 0, 0]
```

```cpp
class Solution {
public:
    void duplicateZeros(vector<int>& arr) {
        int n = arr.size();
        int zeros = 0;
        int i = 0;

        // 第一遍: 找最后一个保留在结果中的元素
        for (i = 0; i + zeros < n; i++) {
            if (arr[i] == 0) zeros++;
        }
        i--; // 循环多走了一步，回退

        int j = n - 1;

        // 边界处理: 最后一个保留的元素是0，但只剩一个格子
        if (i + zeros == n && arr[i] == 0) {
            arr[j--] = 0;  // 这个0只写一份
            i--;
        }

        // 第二遍: 从后往前填充
        while (j >= 0) {
            arr[j--] = arr[i];
            if (arr[i] == 0 && j >= 0) {
                arr[j--] = 0;  // 零写两份
            }
            i--;
        }
    }
};
```

**关键点**:
- 第一遍扫描循环条件 `i + zeros < n` 的含义：如果把 `arr[0..i]` 中的每个零都复写一份，产生的结果长度是 `i + 1 + zeros`。当这个长度 >= n 时，说明结果已经填满了原数组。
- `i + zeros == n` 且 `arr[i] == 0` 是特殊边界：这个零的"复写分身"刚好溢出数组，所以只写一份。
- 第二遍中 `j >= i` 始终成立，因为 `j = i + (剩余zeros数)`，所以不会覆盖未读数据。

## 解法对比

|  | 额外数组 | 两遍扫描 |
|--|---------|---------|
| 时间 | O(n) | **O(n)** |
| 空间 | O(n) | **O(1)** |
| 原地操作 | 否 | **是** |
| 实现难度 | 简单 | 中等（边界处理） |
| 面试推荐 | 说思路即可 | 必须能写 |

## 易错点

1. **第一遍循环条件写错**：
   - 错: `for (i = 0; i < n; i++)` — 这只是数零的个数，没有考虑零复写后对"保留范围"的影响。
   - 对: `for (i = 0; i + zeros < n; i++)` — 当 `i + zeros >= n` 时说明复写结果已经填满了数组。

2. **忘记边界特殊处理**：
   - 错: 直接进入第二遍填充，当 `i + zeros == n` 且 `arr[i] == 0` 时，会试图写两个零导致越界。
   - 对: 先检查这个边界条件，手动处理后再进入主循环。

3. **第二遍填充时 j 的溢出检查**：
   - 错: `arr[j--] = 0;` 不检查 `j >= 0` — 当零在最开始时 `j` 可能已经到 -1。
   - 对: `if (arr[i] == 0 && j >= 0)` 先检查 `j` 再写。

4. **忘记 i-- 回退**：
   - 错: 第一遍循环结束后直接使用 `i`。循环退出时 `i` 已经多走了一步。
   - 对: 循环结束后 `i--`。

## 面试追问

**Q1: 为什么不能从前往后原地操作？**
> 从前往后遇到零时需要把后面的元素都右移一位，但右移会覆盖数据。即使逐个移动，总时间也是 O(n²)。而从后往前填充，写入位置始终在读取位置的右边（或相同位置），不会覆盖未读数据。

**Q2: 能否用 O(1) 空间在一遍内完成？**
> 不能。你必须先知道最终结果的边界在哪里（即原数组中哪些元素会被保留），这需要一次完整的扫描。如果边扫描边填充，你不知道要从哪里开始填充。

**Q3: 这道题和"88. 合并两个有序数组"有什么联系？**
> 核心技巧相同——当从前往后操作会覆盖数据时，改为从后往前操作。88题是将两个有序数组合并到 nums1 的末尾空间中，也是从后往前填充。两道题都利用了"写入位置 >= 读取位置"的不变式来保证安全性。

**Q4: 如果允许返回新数组（不要求原地），最简洁的写法是什么？**
> 直接模拟：遍历原数组，非零push一个，零push两个，满了就停。代码只需5行。这个解法的意义是验证你理解了题目的操作本质。

## 相关题型

- **88. 合并两个有序数组** — 相同的"从后往前填充"技巧。nums1 末尾有预留空间，从大到小合并避免覆盖。
- **283. 移动零** — 把所有零移到末尾，非零元素保持顺序。也是双指针原地操作，但更简单（从前往后就行）。
- **26. 删除有序数组中的重复项** — 原地操作的经典题，双指针维护写入位置。
- **27. 移除元素** — 和283类似，原地删除特定值，双指针从前往后即可。
