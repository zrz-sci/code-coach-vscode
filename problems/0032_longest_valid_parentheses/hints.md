# 32. 最长有效括号

## 核心思路

本题本质上是在一个只含 `(` 和 `)` 的字符串中，找到**最长的连续子串**，使得该子串中的括号完全配对。难点在于"连续"——相邻的有效括号段可以合并（如 `()()`），嵌套的有效括号也算（如 `(())`）。

## 思维链

1. **读完题第一反应**：暴力枚举所有子串，检查每个子串是否是有效括号？可以，但 O(n³) 太慢。
2. **暴力的瓶颈**：枚举所有子串是 O(n²)，每次检查有效性又要 O(n)。能不能不枚举子串，而是直接"算"出以每个位置结尾的最长有效括号长度？
3. **DP 的思路浮现**：如果定义 `dp[i]` = 以 `s[i]` 结尾的最长有效括号长度，那么只有 `s[i] == ')'` 时 `dp[i]` 才可能 > 0。关键是怎么从前面的状态推出来。
4. **栈的思路**：括号匹配天然适合栈。经典做法是栈存**索引**而非字符，匹配成功时用当前索引减去栈顶索引得到有效长度。栈底始终保留一个"分界点"（最后一个未匹配的右括号的位置）。
5. **O(1) 空间的巧妙做法**：正反两趟扫描，用两个计数器 `left`/`right` 分别记录左右括号数量。相等时更新答案，某一方超出时归零。正扫漏掉 `(()`，反扫补上。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力枚举 | 枚举所有子串 + 验证 | O(n³) | O(n) | 能说出即可 |
| 动态规划 | dp[i] = 以i结尾的最长有效长度 | O(n) | O(n) | ⭐ 必须写出 |
| 栈 | 栈存索引，匹配时计算长度 | O(n) | O(n) | ⭐ 必须写出 |
| 双向扫描 | 正反两趟计数器 | O(n) | O(1) | 加分项 |

## 关键提示

1. **栈里存什么？** 不存字符，存**索引**。栈底永远放一个"哨兵"——上一个无法匹配的右括号位置（初始为 -1）。匹配时 `当前索引 - 栈顶` 就是有效长度。
2. **DP 的两种 case**：`s[i]=')'` 时，如果 `s[i-1]='('` 直接配对；如果 `s[i-1]=')'` 则要跳过 `dp[i-1]` 长度去找可能配对的 `(`。
3. **为什么需要正反两趟？** 单向扫描只有 `left == right` 时才更新答案，如果 `left` 一直大于 `right`（如 `(()`），永远等不到相等。反向扫描解决这个问题。
4. **连续有效段合并**：`()()` 的长度是 4 不是 2，DP 和栈解法都自然处理了这种合并。

```
示例: ")()())"

索引:  0  1  2  3  4  5
字符:  )  (  )  (  )  )

栈的变化过程（栈存索引，初始 push -1）:
  栈: [-1]
  i=0 ')': 弹出-1, 栈空→push 0   栈: [0]
  i=1 '(': push 1                   栈: [0, 1]
  i=2 ')': 弹出1, ans=2-0=2        栈: [0]
  i=3 '(': push 3                   栈: [0, 3]
  i=4 ')': 弹出3, ans=4-0=4        栈: [0]
  i=5 ')': 弹出0, 栈空→push 5      栈: [5]
  
  答案 = 4
```

## 解法详解

### 解法1: 暴力枚举 — O(n³) / O(n)

**思考过程**：最直觉的做法——枚举所有可能的子串，对每个子串检查是否是有效括号。有效括号的子串长度一定是偶数，所以可以只枚举偶数长度。

```cpp
class Solution {
public:
    int longestValidParentheses(string s) {
        int n = s.size(), ans = 0;
        // 枚举所有可能的起点
        for (int i = 0; i < n; i++) {
            // 只枚举偶数长度的子串
            for (int j = i + 2; j <= n; j += 2) {
                if (isValid(s, i, j)) {
                    ans = max(ans, j - i);
                }
            }
        }
        return ans;
    }
    
    // 检查 s[start..end) 是否是有效括号
    bool isValid(const string& s, int start, int end) {
        int balance = 0;
        for (int i = start; i < end; i++) {
            if (s[i] == '(') balance++;
            else balance--;
            if (balance < 0) return false; // 右括号多了
        }
        return balance == 0;
    }
};
```

**关键点**：这个解法 n=30000 时完全不可行（~2.7×10¹³ 次操作）。但它帮我们理解题意：我们要找的是**连续子串**中最长的有效括号。

### 解法2: 动态规划 — O(n) / O(n) ⭐ 面试首选

**思考过程**：暴力的瓶颈是枚举子串。如果换个视角——对于每个位置 `i`，直接算出以 `s[i]` 结尾的最长有效括号长度，最后取最大值。

**状态定义**：`dp[i]` = 以 `s[i]` 结尾的最长有效括号子串长度。

**关键观察**：
- 如果 `s[i] == '('`，以左括号结尾不可能是有效的，`dp[i] = 0`
- 如果 `s[i] == ')'`，有两种 case：

```
Case 1: s[i-1] == '('
  ...()   → dp[i] = dp[i-2] + 2
  直接配对，再加上前面可能紧邻的有效段

Case 2: s[i-1] == ')'
  ...))   → 需要跳过 dp[i-1] 长度，看 s[i - dp[i-1] - 1] 是否是 '('
  如果是 '('：dp[i] = dp[i-1] + 2 + dp[i - dp[i-1] - 2]
                       ↑内层长度  ↑配对  ↑前面紧邻的有效段
```

```
DP 填表过程示例: s = "()(())"

索引:    0    1    2    3    4    5
字符:    (    )    (    (    )    )
dp:      0    2    0    0    2    6

i=1: s[0]='(' → Case1: dp[1] = dp[-1]+2 = 0+2 = 2
i=4: s[3]='(' → Case1: dp[4] = dp[2]+2 = 0+2 = 2
i=5: s[4]=')' → Case2: 跳过dp[4]=2, 看s[5-2-1]=s[2]='(' ✓
     dp[5] = dp[4]+2+dp[5-2-2] = 2+2+dp[1] = 2+2+2 = 6

答案 = max(dp) = 6
```

```cpp
class Solution {
public:
    int longestValidParentheses(string s) {
        int n = s.size(), ans = 0;
        vector<int> dp(n, 0);
        
        for (int i = 1; i < n; i++) {
            if (s[i] == ')') {
                if (s[i - 1] == '(') {
                    // Case 1: ...() 直接配对
                    dp[i] = (i >= 2 ? dp[i - 2] : 0) + 2;
                } else if (i - dp[i - 1] - 1 >= 0 && s[i - dp[i - 1] - 1] == '(') {
                    // Case 2: ...)) 跳过内层有效段去找配对的 '('
                    dp[i] = dp[i - 1] + 2 
                           + (i - dp[i - 1] - 2 >= 0 ? dp[i - dp[i - 1] - 2] : 0);
                }
                ans = max(ans, dp[i]);
            }
        }
        return ans;
    }
};
```

**关键点**：Case 2 中 `dp[i - dp[i-1] - 2]` 这一项容易遗漏——它处理的是"配对的左括号前面还有紧邻的有效段"的情况，如 `()(())` 中最后一个 `)` 需要把前面的 `()` 也算进来。

### 解法3: 栈 — O(n) / O(n) ⭐ 面试首选

**思考过程**：括号匹配是栈的经典场景。但普通的括号匹配只判断是否有效，这里要求**最长长度**。关键 insight：栈里存**索引**而非字符，栈底维护一个"分界点"（最后一个无法匹配的位置）。

**为什么栈底要有分界点？** 当匹配成功弹出后，`当前索引 - 栈顶` 就是从栈顶下一个位置到当前位置的有效长度。如果栈空了（没有分界点），就不知道有效段从哪里开始。

**算法**：
1. 初始压入 -1 作为哨兵
2. 遇到 `(`：压入索引
3. 遇到 `)`：弹出栈顶
   - 栈空：说明这个 `)` 没有配对，压入当前索引作为新的分界点
   - 栈不空：`当前索引 - 栈顶` = 当前有效长度，更新答案

```cpp
class Solution {
public:
    int longestValidParentheses(string s) {
        int ans = 0;
        stack<int> stk;
        stk.push(-1);  // 哨兵：初始分界点
        
        for (int i = 0; i < (int)s.size(); i++) {
            if (s[i] == '(') {
                stk.push(i);  // 左括号索引入栈
            } else {
                stk.pop();    // 尝试配对
                if (stk.empty()) {
                    stk.push(i);  // 无法配对，更新分界点
                } else {
                    // i - stk.top() = 从分界点/配对点之后到当前的有效长度
                    ans = max(ans, i - stk.top());
                }
            }
        }
        return ans;
    }
};
```

**关键点**：
- 初始 push(-1) 不能忘，否则第一个就匹配成功时（如 `()`），弹出后栈空，无法计算长度。
- `i - stk.top()` 不是 `i - stk.top() + 1`，因为栈顶是"分界点"（不属于有效段），有效段从 `stk.top() + 1` 开始到 `i`。

### 解法4: 双向扫描（计数器）— O(n) / O(1) 加分项

**思考过程**：能不能不用额外空间？观察：如果从左到右扫描，用 `left` 和 `right` 分别计数左右括号数量。当 `left == right` 时，说明当前段有效，长度 = `left + right`。当 `right > left` 时，说明右括号多了，归零重新计数。

**问题**：`(()` 这种情况，`left` 始终 > `right`，永远等不到相等。

**解决**：反方向再扫一遍！从右到左时，`left > right` 归零。

```cpp
class Solution {
public:
    int longestValidParentheses(string s) {
        int n = s.size(), ans = 0;
        
        // 正向扫描：检测 right > left 时重置
        int left = 0, right = 0;
        for (int i = 0; i < n; i++) {
            if (s[i] == '(') left++;
            else right++;
            if (left == right) ans = max(ans, left + right);
            else if (right > left) left = right = 0;  // 右括号多了，无法挽回
        }
        
        // 反向扫描：检测 left > right 时重置
        left = right = 0;
        for (int i = n - 1; i >= 0; i--) {
            if (s[i] == '(') left++;
            else right++;
            if (left == right) ans = max(ans, left + right);
            else if (left > right) left = right = 0;  // 左括号多了，无法挽回
        }
        
        return ans;
    }
};
```

**为什么正反两趟合起来就完备了？**
- 正向扫描能找到所有"右括号不多于左括号"的有效段的最大值
- 但 `(()` 这种"左括号偏多"的情况，正向永远不会 `left == right`
- 反向扫描时，`(()` 变成从右往左看 `)(`，`right` 先增加，然后 `left` 增加到相等时捕获到 `()`
- 两个方向合在一起，不会漏掉任何有效段

## 易错点

1. **DP Case 2 遗漏合并项**
   - ✗ `dp[i] = dp[i-1] + 2`
   - ✓ `dp[i] = dp[i-1] + 2 + dp[i - dp[i-1] - 2]`
   - 为什么：`()(())` 的最后一个 `)` 配对后还需要加上前面紧邻的 `()` 的长度 2

2. **DP 索引越界**
   - ✗ `dp[i] = dp[i-2] + 2` 当 `i == 1` 时 `dp[-1]` 越界
   - ✓ `dp[i] = (i >= 2 ? dp[i-2] : 0) + 2`

3. **栈解法忘记初始哨兵**
   - ✗ 栈初始为空
   - ✓ `stk.push(-1)` 
   - 为什么：`()` 这种情况，弹出后栈空，无法计算 `i - stk.top()`

4. **栈解法长度计算错误**
   - ✗ `ans = max(ans, i - stk.top() + 1)`
   - ✓ `ans = max(ans, i - stk.top())`
   - 为什么：栈顶是分界点（不属于有效段），有效段从 `stk.top() + 1` 到 `i`，长度 = `i - (stk.top() + 1) + 1 = i - stk.top()`

5. **双向扫描只扫一趟**
   - 只正向扫描会漏掉 `(()` → 输出 0 而不是 2
   - 必须正反各一趟

## 面试追问

**Q1: 暴力解的时间复杂度是多少？能优化到什么程度？**
→ 暴力枚举子串 O(n²)，每次验证 O(n)，共 O(n³)。可以优化到 O(n)。

**Q2: 栈解法中为什么要在栈底放 -1？不放行不行？**
→ 不行。-1 是初始分界点。比如 `()`，弹出 `0` 后栈空，如果没有 -1 就无法算出长度 `1 - (-1) = 2`。可以改成不放 -1，但需要额外判断栈空时 `ans = i + 1`，代码更复杂。

**Q3: 能否用 O(1) 空间解决？**
→ 双向扫描法。正向用 left/right 计数器，`left==right` 时更新答案，`right>left` 时重置。单向漏掉左括号偏多的情况，反向扫描补上。

**Q4: 如果把题目改成返回所有最长有效括号子串（可能多个）？**
→ 在任意解法中记录 `ans` 的同时，记录对应的起始位置。每次更新 `ans` 时重置结果集，`ans` 相等时追加结果。
