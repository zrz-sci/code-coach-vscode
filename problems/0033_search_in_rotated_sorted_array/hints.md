# 33. 搜索旋转排序数组

## 核心思路

旋转排序数组被"掰成两段"，每段内部仍然有序。**二分查找的本质不是"数组必须完全有序"，而是"每次能排除一半搜索空间"**。关键在于：先判断哪半边是有序的，再决定 target 在不在那个有序半边里。

## 思维链

1. **读完题第一反应**：线性扫描 O(n) 肯定能找到，但题目要求 O(log n)，这就暗示必须用二分查找。

2. **直接二分行吗？** 标准二分要求整个数组有序，但旋转后不完全有序了。比如 `[4,5,6,7,0,1,2]`，mid=7 时，target=0 在右边，但 target=5 在左边。不能简单用 `nums[mid] < target` 判断方向。

3. **关键观察**：旋转数组虽然整体无序，但一定可以被 mid 分成两半，**其中至少一半是有序的**！
   ```
   [4, 5, 6, 7, 0, 1, 2]
            ↑ mid=7
   左半 [4,5,6,7] 有序 ✓    右半 [0,1,2] 有序 ✓
   
   [6, 7, 0, 1, 2, 4, 5]
            ↑ mid=1
   左半 [6,7,0,1] 无序 ✗    右半 [1,2,4,5] 有序 ✓
   ```

4. **怎么判断哪半边有序？** 比较 `nums[left]` 和 `nums[mid]`：
   - `nums[left] <= nums[mid]` → 左半边有序
   - 否则 → 右半边有序

5. **确定了有序的一半后**，就能精确判断 target 是否在这个有序范围内：
   - 在 → 搜索这半边
   - 不在 → 搜索另一半边

6. **这样每次都能排除一半**，总体 O(log n)。

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 线性扫描 | 遍历找 target | O(n) | O(1) | 能说出即可 |
| 两次二分 | 先找旋转点，再对有序半边二分 | O(log n) | O(1) | 加分项 |
| 一次二分 | 判断有序半边，决定搜索方向 | O(log n) | O(1) | ⭐ 必须写出 |

## 关键提示

1. **画出旋转数组的图形**——它像一个"折线"，有一个断崖。mid 把它切成两半，至少有一半是单调递增的。

```
值 ↑
   |     *
   |   *
   | *           ← 左段（有序）
   |       * 
   |         *   ← 右段（有序）
   +----------→ 索引
         ↑ 断崖
```

2. **判断有序的条件**：`nums[left] <= nums[mid]` 用 `<=` 而不是 `<`，因为 left 可能等于 mid（区间只有1-2个元素时）。

3. **target 在有序半边的判断**需要两个条件同时满足：`nums[left] <= target` **且** `target < nums[mid]`，缺一不可。

4. **思考"先找旋转点"的方法**：如果你能 O(log n) 找到最小值的位置（即 153. 寻找旋转排序数组中的最小值），就把数组分成两段有序数组，再对其中一段做标准二分。

5. **对比 81 题（有重复元素）**：本题元素互不相同，所以 `nums[left] <= nums[mid]` 能可靠判断左半有序。如果有重复，`nums[left] == nums[mid]` 时无法判断，需要特殊处理。

## 解法详解

### 解法1: 线性扫描 — O(n) / O(1)

**思考过程**: 最朴素的想法，直接遍历数组找 target。不满足题目 O(log n) 要求，但作为基础理解和对拍验证很有用。

```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        for (int i = 0; i < nums.size(); i++) {
            if (nums[i] == target) return i;
        }
        return -1;
    }
};
```

**关键点**: 这个解法的"瓶颈"就是没有利用数组的任何结构信息（部分有序），每个元素都要看一遍。

---

### 解法2: 两次二分（先找旋转点，再标准二分） — O(log n) / O(1)

**思考过程**: 既然旋转数组由两段有序数组拼成，我能不能先找到"拼接点"（最小值位置），然后确定 target 在左段还是右段，最后对那一段做标准二分？

```
// 以 [4,5,6,7,0,1,2], target=0 为例：
//
// Step1: 找旋转点 (最小值索引)
// [4, 5, 6, 7, 0, 1, 2]
//  L        M        R    nums[M]=7 > nums[R]=2 → 最小值在右半
//              L  M   R    nums[M]=1 > nums[R]=2? No → 最小值在左半(含M)
//              LM R        nums[M]=0 > nums[R]=2? No → 最小值在左半(含M)
//              LR          L==R → 旋转点 = 4
//
// Step2: target=0, nums[0]=4 → 0 < 4 → target在右段 [0,1,2] 即索引 [4,6]
//
// Step3: 在 [4,6] 上标准二分 → 找到索引 4
```

```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        int n = nums.size();
        
        // ---- 第一步：找旋转点（最小值的索引） ----
        int lo = 0, hi = n - 1;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] > nums[hi]) {
                // mid 比右端大，说明最小值在 mid 右边
                lo = mid + 1;
            } else {
                // mid 比右端小或等，最小值在 mid 或 mid 左边
                hi = mid;
            }
        }
        int pivot = lo; // 最小值索引
        
        // ---- 第二步：确定 target 在哪一段 ----
        if (target >= nums[pivot] && target <= nums[n - 1]) {
            // target 在右段 [pivot, n-1]
            lo = pivot;
            hi = n - 1;
        } else {
            // target 在左段 [0, pivot-1]
            lo = 0;
            hi = pivot - 1;
        }
        
        // ---- 第三步：标准二分查找 ----
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] == target) return mid;
            else if (nums[mid] < target) lo = mid + 1;
            else hi = mid - 1;
        }
        return -1;
    }
};
```

**关键点**: 
- 找旋转点用的是 `nums[mid] > nums[hi]` 而非 `nums[mid] > nums[lo]`，因为后者在数组未旋转时会出错。
- 这个解法逻辑清晰（分两步），面试时如果紧张可以先写这个，容易不出bug。

---

### 解法3: 一次二分（判断有序半边） — O(log n) / O(1) ⭐ 面试首选

**从解法2优化**: 解法2做了两次二分，虽然都是 O(log n) 但逻辑分散。能不能在一次二分中同时完成？关键洞察：**mid 把数组分成两半，至少一半有序，先找到有序的那半边，判断 target 是否在其中。**

```
// 搜索空间收缩过程：nums = [4,5,6,7,0,1,2], target = 0
//
// Round1: L=0, R=6, mid=3
//   [4, 5, 6, 7, 0, 1, 2]
//    L        M        R
//   nums[L]=4 <= nums[M]=7 → 左半 [4,5,6,7] 有序
//   target=0 在 [4,7] 范围内? 4<=0? No → target 不在左半
//   → L = mid+1 = 4
//
// Round2: L=4, R=6, mid=5
//   [4, 5, 6, 7, 0, 1, 2]
//                 L  M  R
//   nums[L]=0 <= nums[M]=1 → 左半 [0,1] 有序
//   target=0 在 [0,1] 范围内? 0<=0 且 0<1? Yes → target 在左半
//   → R = mid-1 = 4
//
// Round3: L=4, R=4, mid=4
//   nums[mid]=0 == target → 返回 4 ✓
```

```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        int left = 0, right = nums.size() - 1;
        
        while (left <= right) {
            int mid = left + (right - left) / 2;
            
            // 找到了，直接返回
            if (nums[mid] == target) return mid;
            
            // 判断哪半边是有序的
            if (nums[left] <= nums[mid]) {
                // 左半边 [left, mid] 有序
                // target 在这个有序范围内吗？
                if (nums[left] <= target && target < nums[mid]) {
                    right = mid - 1;  // 在左半边找
                } else {
                    left = mid + 1;   // 在右半边找
                }
            } else {
                // 右半边 [mid, right] 有序
                // target 在这个有序范围内吗？
                if (nums[mid] < target && target <= nums[right]) {
                    left = mid + 1;   // 在右半边找
                } else {
                    right = mid - 1;  // 在左半边找
                }
            }
        }
        
        return -1;
    }
};
```

**关键点**:
- `nums[left] <= nums[mid]` 中的 `<=` 至关重要，处理 left==mid 的情况（如只剩2个元素）
- 判断 target 在有序半边时需要**双边界条件**，不能只判断一边

## 解法对比

| | 解法1: 线性扫描 | 解法2: 两次二分 | 解法3: 一次二分 |
|---|---|---|---|
| 时间 | O(n) | O(log n) | O(log n) |
| 空间 | O(1) | O(1) | O(1) |
| 思路复杂度 | 最简单 | 分步清晰 | 逻辑集中 |
| 代码量 | 最少 | 最多 | 适中 |
| 面试推荐 | 开场过渡 | 可接受 | **首选** |

- **解法2 vs 解法3**：解法2 更模块化，先定位后查找，每步的逻辑更简单；解法3 一步到位，代码更紧凑。面试中优先写解法3，写不出来再退到解法2。
- 两次二分和一次二分的常数因子差异在实际中几乎无区别，但一次二分展示了更深的理解。

## 易错点

1. **`<=` vs `<` 的混用**
   - ✗ `if (nums[left] < nums[mid])` — 当 left==mid（区间只有1-2个元素）时，会误判左半边不有序
   - ✓ `if (nums[left] <= nums[mid])` — 等号保证单元素区间也被正确判定为"有序"

2. **target 范围判断少了一边**
   - ✗ `if (target < nums[mid]) right = mid - 1;` — 这会把旋转到右边但值更小的 target 错误地留在左半边
   - ✓ `if (nums[left] <= target && target < nums[mid]) right = mid - 1;` — 必须同时约束下界

3. **有序半边的边界取等方向不一致**
   - 左半有序时：`nums[left] <= target` 取等（target 可能就是 left），`target < nums[mid]` 不取等（mid 已经在开头检查过）
   - 右半有序时：`nums[mid] < target` 不取等，`target <= nums[right]` 取等
   - 混淆取等方向会漏掉边界元素

4. **找旋转点时用 `nums[mid] > nums[lo]` 判断**
   - ✗ 当数组完全未旋转（如 `[1,2,3,4,5]`）时，`nums[mid] > nums[lo]` 始终成立，lo 会一直右移，最终得到错误的旋转点
   - ✓ 用 `nums[mid] > nums[hi]` 判断，未旋转时 `nums[mid] < nums[hi]`，hi 左移，最终 lo=0（正确）

## 面试追问

**Q1: 能否先找到旋转点再做二分？两种方式各有什么优劣？**
- 两次二分：逻辑清晰，每次都是标准操作，不容易出错。但需要处理"数组未旋转"的特殊情况。
- 一次二分：代码更简洁，一次遍历搞定，但条件判断需要仔细推敲。面试中推荐一次二分，展示对二分的深刻理解。

**Q2: 如果数组中有重复元素怎么办？（→ LeetCode 81）**
- `nums[left] == nums[mid]` 时无法判断左半边是否有序。例如 `[1,3,1,1,1]` 和 `[1,1,1,3,1]`，left 和 mid 都是1，但有序的半边不同。
- 解决方案：当 `nums[left] == nums[mid]` 时，做 `left++` 跳过一个元素。这使最坏情况退化为 O(n)，但平均仍是 O(log n)。

**Q3: 如果需要找旋转排序数组中的最小值呢？（→ LeetCode 153）**
- 这正是解法2的第一步。用 `nums[mid] > nums[right]` 判断最小值在右半边，否则在左半边（含 mid）。这是标准的"找边界"型二分。

**Q4: 如何在不修改数组的情况下，支持多次查询不同的 target？**
- 预处理一次找到旋转点 O(log n)，之后每次查询只需要做一次标准二分 O(log n)。总共 O(log n + Q·log n)，其中 Q 是查询次数。
