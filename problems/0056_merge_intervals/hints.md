# 56. 合并区间

## 核心思路

本题本质上是：**将一组可能重叠的区间"粘合"成互不重叠的最少区间**。关键观察是——如果区间按起点排序，重叠的区间一定是连续的，只需一次线性扫描就能完成合并。

## 思维链

1. **读完题第一反应**：要找出所有重叠的区间并合并。两个区间什么时候重叠？当一个区间的 start ≤ 另一个区间的 end 时（存在交集）。最朴素的做法是每对区间都检查一遍是否重叠。

2. **暴力解的瓶颈**：两两检查是 O(n²)，而且合并后产生新区间还可能与其他区间重叠，需要反复合并直到稳定，最坏情况更差。核心问题是：**无序的区间让"找谁和谁重叠"变得很困难**。

3. **突破口：排序！** 如果按起点排序，重叠的区间一定是**连续相邻**的。因为排序后 `start[i] ≤ start[i+1]`，区间 i 和 i+1 重叠的充要条件就是 `end[i] ≥ start[i+1]`。这样只需一次线性扫描。

4. **具体做法**：排序后维护一个"当前正在合并的区间"，逐个考察下一个区间：
   - 如果下一个区间的 start ≤ 当前区间的 end → 重叠，合并（取两个 end 的较大值）
   - 否则 → 不重叠，当前区间确定，开始新的区间

5. **图示**：
```
排序前: [1,3] [2,6] [8,10] [15,18]  (恰好已排序)

扫描过程:
|-------|           [1,3]
   |----------|    [2,6]  → start=2 ≤ end=3, 合并为 [1,6]
                |-----|   [8,10] → start=8 > end=6, 不重叠, 输出[1,6]
                            |--------|  [15,18] → start=15 > end=10, 输出[8,10]
最终输出 [8,10], 再输出 [15,18]

结果: [[1,6], [8,10], [15,18]]
```

## 解法概览

| 解法 | 思路 | 时间 | 空间 | 面试 |
|------|------|------|------|------|
| 暴力合并 | 两两检查重叠，反复合并直到稳定 | O(n³) | O(n) | 能说出即可 |
| 排序 + 线性扫描 | 按起点排序，一次遍历合并相邻重叠区间 | O(n log n) | O(n) | ⭐ 必须写出 |

## 关键提示

1. **两个区间重叠的条件**：排序后只需检查 `当前区间的 end ≥ 下一个区间的 start`。
2. **为什么排序有用**：排序保证了起点单调递增，因此如果区间 i 和 i+2 重叠，区间 i 和 i+1 也一定重叠。重叠区间"连成一片"。
3. **合并时取 max(end)**：不能直接取下一个区间的 end，因为可能出现区间包含的情况，如 `[1,10]` 和 `[2,3]`。
4. **只需按起点排序**：起点相同时，end 的顺序不影响正确性（因为合并时取 max）。
5. **ASCII 示意图——包含关系别忘了**：
```
  |--------------|     [1,10]
     |---|             [2,3]   → 合并后仍是 [1,10]，不是 [1,3]！
```

## 解法详解

### 解法1: 暴力合并 — O(n³) / O(n)

**思考过程**: 最直觉的想法——两两检查是否重叠，如果重叠就合并成新区间，然后从头再来，直到没有任何区间重叠为止。

```cpp
class Solution {
public:
    vector<vector<int>> merge(vector<vector<int>>& intervals) {
        vector<vector<int>> merged = intervals;
        
        bool changed = true;
        while (changed) {
            changed = false;
            vector<vector<int>> next;
            vector<bool> used(merged.size(), false);
            
            for (int i = 0; i < merged.size(); i++) {
                if (used[i]) continue;
                vector<int> cur = merged[i];
                for (int j = i + 1; j < merged.size(); j++) {
                    if (used[j]) continue;
                    // 两个区间重叠的条件：互相有交集
                    if (cur[0] <= merged[j][1] && merged[j][0] <= cur[1]) {
                        cur[0] = min(cur[0], merged[j][0]);
                        cur[1] = max(cur[1], merged[j][1]);
                        used[j] = true;
                        changed = true;
                    }
                }
                next.push_back(cur);
            }
            merged = next;
        }
        return merged;
    }
};
```

**关键点**: 
- 两个区间 `[a,b]` 和 `[c,d]` 重叠的通用条件是 `a ≤ d && c ≤ b`（互相交叉）。
- 每轮合并后可能产生新的重叠，需要反复迭代，最坏 O(n) 轮 × 每轮 O(n²) = O(n³)。
- 这个解法的唯一价值是帮助理解题意，面试中不建议写这个。

### 解法2: 排序 + 线性扫描 — O(n log n) / O(n) ⭐ 面试首选

**从解法1优化**: 暴力解的瓶颈是**无序导致必须两两检查**。排序后，重叠区间一定相邻，只需一次线性扫描。

```cpp
class Solution {
public:
    vector<vector<int>> merge(vector<vector<int>>& intervals) {
        // 按起点排序，起点相同时 end 顺序无所谓
        sort(intervals.begin(), intervals.end());
        
        vector<vector<int>> merged;
        
        for (auto& interval : intervals) {
            // 如果结果为空，或者当前区间与上一个不重叠
            // 不重叠条件：当前 start > 上一个 end
            if (merged.empty() || interval[0] > merged.back()[1]) {
                merged.push_back(interval);
            } else {
                // 重叠：合并 —— 扩展上一个区间的右边界
                // 取 max 而不是直接赋值，防止包含关系（如 [1,10] 合并 [2,3]）
                merged.back()[1] = max(merged.back()[1], interval[1]);
            }
        }
        
        return merged;
    }
};
```

**为什么排序后一次扫描就够了？**
- 排序后 `start[0] ≤ start[1] ≤ ... ≤ start[n-1]`
- 如果区间 i 和 i+1 不重叠（`end[i] < start[i+1]`），那么区间 i 和 i+2, i+3, ... 也一定不重叠（因为 `start[i+2] ≥ start[i+1] > end[i]`）
- 所以一旦不重叠，当前合并区间就可以"关闭"了，不会有后面的区间再与它重叠

```
// 完整扫描过程（示例1）:
// 
// 排序后: [1,3], [2,6], [8,10], [15,18]
//
// Step1: merged = []，空 → 加入 [1,3]
//        merged = [[1,3]]
//
// Step2: [2,6]，start=2 ≤ merged.back().end=3 → 重叠
//        合并：end = max(3, 6) = 6
//        merged = [[1,6]]
//
// Step3: [8,10]，start=8 > merged.back().end=6 → 不重叠
//        加入新区间
//        merged = [[1,6], [8,10]]
//
// Step4: [15,18]，start=15 > merged.back().end=10 → 不重叠
//        加入新区间
//        merged = [[1,6], [8,10], [15,18]]
```

## 解法对比

| | 暴力合并 | 排序 + 线性扫描 |
|---|---|---|
| 时间 | O(n³) | O(n log n) |
| 空间 | O(n) | O(n)（结果数组） |
| 核心思想 | 两两检查，反复迭代 | 排序消除无序性，一次扫描 |
| 代码复杂度 | 高（嵌套循环+标记） | 低（排序 + 单层循环） |
| 面试推荐 | ✗ | ✓ |

**选择建议**: 面试只需要写排序解法。暴力解在面试中可以口述"最朴素想法是两两检查"，然后直接过渡到排序优化。

## 易错点

1. **合并时直接赋值 end，而不是取 max**
   - ✗ `merged.back()[1] = interval[1];`
   - ✓ `merged.back()[1] = max(merged.back()[1], interval[1]);`
   - 原因：存在包含关系，如 `[1,10]` 和 `[2,3]`，直接赋值会把 10 变成 3。

2. **重叠判断用 `>=` 还是 `>`**
   - ✗ `interval[0] >= merged.back()[1]` → 这会把 `[1,4]` 和 `[4,5]` 判断为不重叠
   - ✓ `interval[0] > merged.back()[1]` → `[1,4]` 和 `[4,5]` 端点相切也算重叠
   - 题目示例2明确说明 `[1,4]` 和 `[4,5]` 要合并。

3. **忘记排序**
   - 不排序的话，后面可能有起点很小的区间还没处理，`[4,7], [1,4]` 不排序直接扫描会输出两个区间。

4. **按 end 排序而不是按 start**
   - 按 end 排序无法保证重叠区间相邻。如 `[1,5], [2,3], [4,6]` 按 end 排序为 `[2,3], [1,5], [4,6]`，扫描时 `[2,3]` 和 `[1,5]` 看似重叠但逻辑会混乱。

## 面试追问

**Q1（基础理解）**: "两个区间重叠的条件是什么？"
- **A**: 对于 `[a,b]` 和 `[c,d]`，重叠当且仅当 `a ≤ d && c ≤ b`。排序后简化为 `c ≤ b`（因为排序保证 `a ≤ c`）。

**Q2（优化追问）**: "为什么排序后只需一次扫描？能否证明不会漏掉任何重叠？"
- **A**: 排序后起点递增。如果区间 i 的 end < 区间 i+1 的 start，那么对于所有 j > i+1，`start[j] ≥ start[i+1] > end[i]`，所以区间 i 和后面所有区间都不重叠。这保证了重叠区间构成连续段。

**Q3（变体）**: "如果区间是流式输入的（一个一个来），每次插入后都要返回合并结果，怎么做？"
- **A**: 可以用有序数据结构（如 `std::map`）维护已合并的区间。每次插入新区间时，用二分查找定位可能重叠的区间，合并后删除被覆盖的旧区间。单次插入 O(k log n)，k 是被合并的区间数。参见 LeetCode 57（插入区间）。

**Q4（变体）**: "如果不要求合并，只要求判断是否存在任何重叠？"
- **A**: 排序后一次扫描，检查相邻区间是否有 `start[i+1] ≤ end[i]` 即可。O(n log n)。
