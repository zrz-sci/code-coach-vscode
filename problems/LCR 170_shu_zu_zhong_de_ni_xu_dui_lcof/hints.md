# LCR 170. 交易逆序对的总数

## 核心思路

统计数组中所有**逆序对**的数量。逆序对定义：若 `i < j` 且 `record[i] > record[j]`，则 `(i, j)` 是一个逆序对。暴力双循环是 O(n^2)，数据量 50000 会超时。高效解法是利用**归并排序**：在合并两个有序子数组的过程中，可以顺便统计跨越左右两半的逆序对数量。

本质上，逆序对计数 = 归并排序的副产品。

## 思维链

1. **读完题第一反应** → 最直接的做法是双重循环，对每一对 (i, j) 检查是否 record[i] > record[j]。但 O(n^2) 对 n=50000 约 25 亿次操作，超时。
2. **能否用分治？** → 把数组分成左右两半。逆序对可以分为三类：
   - (1) 两个元素都在左半 → 递归解决
   - (2) 两个元素都在右半 → 递归解决
   - (3) 一个在左半、一个在右半（**跨越逆序对**）→ 需要高效统计
3. **关键洞察** → 如果左右两半各自已经排好序，统计跨越逆序对就变得很容易：对于右半的每个元素 `arr[j]`，左半中所有比它大的元素都与它构成逆序对。而左半有序后，这些元素一定是从某个位置 `i` 到左半末尾的连续段，数量就是 `mid - i + 1`。
4. **这不就是归并排序吗？** → 归并排序本身就是"分治 + 合并"，合并时正好做有序数组的 merge。我们只需要在 merge 过程中加一行计数即可。
5. **合并过程中何时计数？** → 当 `arr[i] > arr[j]`（左侧元素大于右侧），说明左侧从 `i` 到 `mid` 的所有元素都比 `arr[j]` 大（因为左侧已排序），逆序对数 += `mid - i + 1`。

## 分治过程图解

```
原始数组: [9, 7, 5, 4, 6]

                    [9, 7, 5, 4, 6]
                   /                \
            [9, 7, 5]              [4, 6]
           /         \            /      \
        [9, 7]       [5]       [4]       [6]
       /      \
     [9]      [7]

合并过程（自底向上）:

第1层合并: [9] + [7]
  i→9, j→7: 9 > 7, 逆序对 += mid-i+1 = 0-0+1 = 1
  合并后: [7, 9]                              计数: 1

第2层合并: [7, 9] + [5]
  i→7, j→5: 7 > 5, 逆序对 += mid-i+1 = 1-0+1 = 2
  i→7, j→(结束)
  合并后: [5, 7, 9]                           计数: 1+2 = 3

第3层合并: [4] + [6]
  i→4, j→6: 4 ≤ 6, 不计数
  合并后: [4, 6]                              计数: 3+0 = 3

第4层合并: [5, 7, 9] + [4, 6]
  i→5, j→4: 5 > 4, 逆序对 += mid-i+1 = 2-0+1 = 3  → 计数=6
  i→5, j→6: 5 ≤ 6, 不计数
  i→7, j→6: 7 > 6, 逆序对 += mid-i+1 = 2-1+1 = 2  → 计数=8
  合并后: [4, 5, 6, 7, 9]                    计数: 8

总逆序对数: 8
验证: (9,7)(9,5)(9,4)(9,6)(7,5)(7,4)(7,6)(5,4) = 8 ✓
```

## 关键提示

1. **核心计数公式**：当 `arr[i] > arr[j]` 时，`cnt += mid - i + 1`。
   - 因为左半已排序，`arr[i], arr[i+1], ..., arr[mid]` 都大于 `arr[j]`
   - 这 `mid - i + 1` 个元素都和 `arr[j]` 构成逆序对

2. **排序不影响计数的正确性**：
   - 归并排序会改变数组顺序，但不影响逆序对计数
   - 因为我们在**合并之前**就完成了计数，此时元素的相对顺序还没改变
   - 排序操作只影响后续合并的效率，不影响已统计的结果

3. **辅助数组预分配**：
   - 在函数外一次性分配 `tmp` 数组，避免每次递归 `new` 内存
   - 频繁内存分配会导致 TLE

4. **归并排序必须是稳定排序**：
   - 当 `arr[i] == arr[j]` 时，应该先放左侧的 `arr[i]`（取 `<=`）
   - 如果先放右侧，会把相等的元素错误地计为逆序对

5. **数据范围注意溢出**：
   - n=50000，最多逆序对数 = n*(n-1)/2 ≈ 12.5 亿，用 int 刚好不溢出（INT_MAX ≈ 21 亿）
   - 但如果 n 更大或需要累加，考虑用 long long

## 解法详解

### 解法1: 暴力双循环 — O(n^2) / O(1) — 超时但理解思路

```cpp
class Solution {
public:
    int reversePairs(vector<int>& record) {
        int n = record.size(), cnt = 0;
        for (int i = 0; i < n; i++)
            for (int j = i + 1; j < n; j++)
                if (record[i] > record[j]) cnt++;
        return cnt;
    }
};
```

**关键点**: n=50000 时 O(n^2) ≈ 1.25 x 10^9，超时。但它明确了问题的定义。

---

### 解法2: 归并排序 — O(n log n) / O(n) -- 面试首选

**从暴力到归并排序的优化思路**:

```
暴力: 对每个 j，扫描所有 i < j 看 record[i] > record[j] 的有几个 → O(n) 每个 j
归并: 合并两个有序子数组时，对每个 j，左侧大于 arr[j] 的元素是一个连续段 → O(1) 统计

关键: 排序让"左侧有多少元素大于 arr[j]"变成了"从 i 到 mid 有几个元素"的简单计算
```

```cpp
class Solution {
public:
    int reversePairs(vector<int>& record) {
        if (record.empty()) return 0;
        vector<int> tmp(record.size());
        return mergeSort(record, tmp, 0, (int)record.size() - 1);
    }
    
    int mergeSort(vector<int>& arr, vector<int>& tmp, int l, int r) {
        if (l >= r) return 0;
        int mid = l + (r - l) / 2;
        // 递归: 左半逆序对 + 右半逆序对
        int cnt = mergeSort(arr, tmp, l, mid) + mergeSort(arr, tmp, mid + 1, r);
        // 合并: 统计跨越逆序对
        int i = l, j = mid + 1, k = l;
        while (i <= mid && j <= r) {
            if (arr[i] <= arr[j]) {
                tmp[k++] = arr[i++];
            } else {
                // arr[i] > arr[j]: 左侧从 i 到 mid 都比 arr[j] 大
                cnt += mid - i + 1;
                tmp[k++] = arr[j++];
            }
        }
        while (i <= mid) tmp[k++] = arr[i++];
        while (j <= r)   tmp[k++] = arr[j++];
        for (int p = l; p <= r; p++) arr[p] = tmp[p];
        return cnt;
    }
};
```

**关键点**:
- `cnt += mid - i + 1` 是唯一多加的一行代码（相比标准归并排序）
- `arr[i] <= arr[j]` 取等号（不是 `<`），确保相等元素先放左侧，不会被误算为逆序对
- `tmp` 数组在外部预分配，避免递归中反复 new

### 解法3: 树状数组 (BIT) — O(n log n) / O(n) — 进阶

**思路**: 从右向左遍历数组，对每个元素统计"它右边有多少比它小的元素"，这就是它贡献的逆序对数。用树状数组（Binary Indexed Tree）高效维护和查询。

```cpp
class Solution {
public:
    int reversePairs(vector<int>& record) {
        if (record.empty()) return 0;
        // 离散化: 将值映射到 [1, n] 范围
        vector<int> sorted_vals(record);
        sort(sorted_vals.begin(), sorted_vals.end());
        sorted_vals.erase(unique(sorted_vals.begin(), sorted_vals.end()), sorted_vals.end());
        int n = sorted_vals.size();
        
        vector<int> bit(n + 1, 0); // 树状数组
        int cnt = 0;
        
        // 从右向左遍历
        for (int k = record.size() - 1; k >= 0; k--) {
            // 找 record[k] 离散化后的位置 (1-indexed)
            int rank = lower_bound(sorted_vals.begin(), sorted_vals.end(), record[k]) 
                       - sorted_vals.begin() + 1;
            // 查询: rank-1 及以下有多少元素 (即右边比 record[k] 小的)
            cnt += query(bit, rank - 1);
            // 更新: 在 rank 位置加 1
            update(bit, rank, n);
        }
        return cnt;
    }
    
    void update(vector<int>& bit, int i, int n) {
        for (; i <= n; i += i & (-i)) bit[i]++;
    }
    
    int query(vector<int>& bit, int i) {
        int s = 0;
        for (; i > 0; i -= i & (-i)) s += bit[i];
        return s;
    }
};
```

## 易错点

1. **等号判断方向错误**：
   - ✗ `if (arr[i] < arr[j])` → 当 arr[i] == arr[j] 时进入 else 分支，把相等元素误算为逆序对
   - ✓ `if (arr[i] <= arr[j])` → 相等时先放左侧，不计数

2. **计数公式写错**：
   - ✗ `cnt += mid - i` → 少算 1 个元素
   - ✗ `cnt += r - j + 1` → 逻辑完全错误
   - ✓ `cnt += mid - i + 1` → 左侧从 i 到 mid 共 mid-i+1 个元素

3. **辅助数组在递归中反复创建**：
   - ✗ 在 mergeSort 内 `vector<int> tmp(r-l+1)` → 每次递归分配内存，O(n log n) 次分配，极慢
   - ✓ 在外部一次分配 `vector<int> tmp(n)` → 传引用复用

4. **忘记拷贝回原数组**：
   - ✗ 合并到 tmp 后不拷贝回 arr → 下次合并时 arr 中的数据没有排序，逻辑错误
   - ✓ `for (int p = l; p <= r; p++) arr[p] = tmp[p];`

5. **递归边界错误**：
   - ✗ `if (l == r)` → 当 l > r 时（空区间）不处理，可能出错
   - ✓ `if (l >= r)` → 空区间和单元素都直接返回 0

## 面试追问

**Q1: 为什么不能用快速排序统计逆序对？**
> 快速排序不稳定，partition 过程中元素的相对顺序被打乱，无法准确统计跨越逆序对。归并排序的 merge 过程保持左右两半的相对顺序，才能正确计数。

**Q2: 能否不排序直接统计？**
> 可以用树状数组或线段树。从右向左遍历，用数据结构维护"右边已遍历元素中比当前元素小的个数"。时间同为 O(n log n)。

**Q3: 如果数据范围很大（值可以到 10^9），树状数组怎么处理？**
> 先离散化：把值映射到 [1, n] 的紧凑范围。用排序 + 去重 + 二分查找实现。

**Q4: 这个问题和"排序需要多少次相邻交换"有什么关系？**
> 等价！将数组排成有序需要的最少相邻交换次数 = 逆序对数。每次相邻交换消除恰好一个逆序对。
