# LeetCode 教学知识库 (Teaching Skills)

> 这个文件是 AI 生成 hints.md 和 reference.cpp 时的 system-level 教学方法论。
> 每次生成都会加载此文件，确保输出的是**教学文档**，而不是答案。

---

## 一、核心教学原则

### 1. 由浅入深，不是直接给最优解
- 先从最直觉的暴力解开始，让人理解"这道题到底在问什么"
- 然后分析暴力解的瓶颈在哪，自然引出优化思路
- 最后给出最优解，此时读者已经理解了为什么要这么做

### 2. 讲"为什么"，不是讲"是什么"
- 错误示范：「用哈希表，时间 O(n)」
- 正确示范：「暴力法需要对每个元素遍历整个数组找配对，瓶颈在查找。哈希表把查找从 O(n) 降到 O(1)，所以总体从 O(n²) 降到 O(n)」

### 3. 每种解法都是完整的
- 每种解法必须有：思路说明 → 为什么能 work → 完整代码 → 复杂度
- 代码注释要解释"为什么这样写"，不是"这行在做什么"

### 4. 对比解法之间的关系
- 递归 vs 迭代：递归是什么，迭代怎么用栈模拟同样的过程
- 暴力 vs 优化：优化到底省在了哪一步
- 不同解法的适用场景：什么时候选哪个

### 5. Follow-up 必须处理
- 如果 LeetCode 题目有 Follow-up（如"能否 O(1) 空间？""如果有大量查询怎么优化？"），必须在 hints.md 中提及，并在 reference.cpp 中给出 Follow-up 解法
- Follow-up 通常是面试追问的重点，不能忽略

### 6. 线性 DP 强制空间优化
- 当 dp[i] 只依赖 dp[i-1]（或 dp[i-1] 和 dp[i-2]）时，必须额外给出滚动变量的空间优化版本
- 二维 DP 如果每行只依赖上一行，必须给出一维滚动数组版本
- 空间优化不是"可选"，而是 DP 教学的必要环节

### 7. 系列题必须串联对比
- 对于系列题（如 Stock I→II→III→IV→Cooldown→Fee，House Robber I→II→III，背包 0/1→完全→多重），必须在 reference.cpp 中显式说明：
  - 和上一题的区别是什么
  - 代码具体改了哪一行/哪个条件
  - 为什么这个改动是正确的
- 这样读者可以系统性理解一类题，而不是每道题孤立地学

### 8. 思维过程可视化
- 回溯题：必须用 ASCII 注释画出决策树（至少画出前 2-3 层），展示选择/撤销的过程
- DP 题：必须用注释说明填表方向和依赖关系（如 dp[i][j] 依赖左、上、左上）
- 二分题：必须在注释中画出搜索空间收缩的过程（至少一个例子）
- 可视化是帮助建立直觉的最有效方式

### 9. 面试追问是递进链，不是独立问题
- 模拟真实面试场景：面试官先问基础理解，再追问优化，最后问变体
- 例如 Two Sum: Q1(暴力能过吗？瓶颈在哪？) → Q2(能否O(1)空间？) → Q3(如果数组有序呢？)
- 每个追问之间有逻辑递进关系，不是随机的3个问题

### 10. 相关题型要说清"复用什么"
- 不是列一个题号就完了，必须说明学会本题后做那道题可以直接复用什么
- ✗ "相关：LeetCode 101 对称二叉树"
- ✓ "101 对称二叉树 — 复用同样的双参数递归框架，区别：100是同侧配对(left,left)，101是交叉配对(left,right)"

### 11. 易错点必须是具体的代码 bug
- ✗ "注意边界条件" "防止溢出" — 这种说了等于没说
- ✓ "递归终止条件漏掉 `!left && !right` 导致对两个null节点返回false"
- ✓ "dp数组初始化时 dp[0]=1 而不是 dp[0]=0，因为空集也算一种方案"
- 每个易错点要具体到代码行为，让人看了能直接避坑

## 二、分类教学方法论

### Array（数组）
**常见解法演进路线：**
1. 暴力枚举 O(n²) → 排序+双指针 O(n log n) → 哈希表 O(n)
2. 暴力子数组 O(n³) → 前缀和 O(n²) → 滑动窗口 O(n)

**必讲要点：**
- 双指针：左右指针（有序数组）vs 快慢指针（链表/原地修改）
- 滑动窗口：什么时候能用（窗口内满足单调性）、怎么维护窗口
- 前缀和：把区间问题转化为两个端点的差

### Two Pointers（双指针）
**必讲要点：**
- 为什么能用双指针：排序后的单调性保证不会漏解
- 去重技巧：跳过相同元素避免重复
- 与二分查找的关系：都是利用有序性缩小搜索范围

### Hash Table（哈希表）
**常见解法演进路线：**
1. 暴力双循环 O(n²) → 哈希表一次遍历 O(n)

**必讲要点：**
- 哈希表的本质：用空间换时间，把"查找"这个操作从 O(n) 变成 O(1)
- 什么时候用 map vs set：需要记录映射关系（索引、次数）用 map，只需存在性用 set
- 边遍历边建表 vs 先建后查：Two Sum 为什么边遍历边查就够了

### Binary Search（二分查找）
**常见解法演进路线：**
1. 线性扫描 O(n) → 二分查找 O(log n)

**必讲要点：**
- 二分的本质：不是"有序数组上查找"，而是"把搜索空间一分为二，每次排除一半"
- 三种模板的区别和适用场景：
  - `left <= right`（找确切值）
  - `left < right`（找边界，收缩区间）
  - `left + 1 < right`（避免死循环，最后检查两端）
- 搜索空间：不一定是数组索引，可以是答案范围（如 Sqrt(x) 在 [0, x] 上二分）
- 上下界移动的判断：mid 属于"可能是答案"还是"一定不是答案"

### Linked List（链表）
**必讲要点：**
- 虚拟头节点(dummy head)：什么时候用（头节点可能被删除/修改时）
- 快慢指针：找中点、检测环、找环入口
- 递归 vs 迭代：链表天然适合递归思考，但迭代更省空间
- 画图：链表题一定要画指针变化的图，否则很容易搞混

### Tree / Binary Tree（树）
**必讲要点 — 每道树的题都要讲两种方式：**

#### 递归 (DFS)
- 树的递归三要素：返回值、终止条件、单层逻辑
- 前序/中序/后序的区别：处理当前节点的时机不同
- 自顶向下 vs 自底向上：传参数下去 vs 收集返回值上来

#### 迭代 (Stack/Queue)
- 用栈模拟递归：为什么栈能模拟递归调用栈
- 前序迭代：根→右→左入栈（出栈顺序就是根→左→右）
- 中序迭代：一路向左入栈，弹出处理，转右子树
- 后序迭代：前序(根左右)的变体，改成根右左再反转
- 层序遍历(BFS)：用队列，逐层处理

#### 共性
- BST 的中序遍历是有序的 — 很多 BST 题本质是利用这个性质
- 高度/深度的区别：深度从上往下数，高度从下往上数

### Binary Search Tree（BST）
**必讲要点：**
- BST 性质：左 < 根 < 右，中序遍历有序
- 利用 BST 性质剪枝：比 root 小往左走，比 root 大往右走
- 验证 BST：不是只比较左右孩子，要维护上下界 [min, max]
- 插入/删除：删除要考虑三种情况（叶子、一个孩子、两个孩子）

### Dynamic Programming（动态规划）
**常见解法演进路线：**
1. 暴力递归(穷举) → 记忆化搜索(自顶向下 DP) → 递推(自底向上 DP) → 空间优化

**必讲要点：**
- 永远从暴力递归开始：先想清楚递归怎么穷举所有可能
- 记忆化：发现重叠子问题后，加 memo 数组缓存
- 转成递推：把递归翻译成 for 循环填表
- 状态定义：dp[i] 或 dp[i][j] 到底代表什么，这是最关键的一步
- 状态转移方程：从哪些子状态推导出当前状态
- 初始化和遍历方向：base case 是什么，填表的方向要保证依赖的状态已经算过
- 空间优化：滚动数组，什么时候能降维

### Backtracking（回溯）
**常见解法演进路线：**
1. 暴力枚举 → 回溯剪枝 → (某些题可以 DP)

**必讲要点：**
- 回溯 = DFS + 撤销选择：做选择 → 递归 → 撤销选择
- 三个关键问题：路径（已做选择）、选择列表（还能做什么）、结束条件
- 去重：排序后跳过相同元素（组合问题常见）
- 剪枝：提前终止不可能的分支，大幅提升效率
- 排列 vs 组合 vs 子集：模板相似但细节不同（是否用 start 控制起点）

### Greedy（贪心）
**必讲要点：**
- 贪心的核心：局部最优 → 全局最优，但要证明为什么贪心策略是对的
- 常见模式：排序后贪心选择、区间问题（按结束时间排序）
- 与 DP 的区别：贪心不回头，DP 考虑所有子问题

### Stack（栈）
**必讲要点：**
- 单调栈：维护一个递增/递减栈，用于"下一个更大/更小元素"问题
- 括号匹配：栈的经典应用
- 表达式求值：操作数栈 + 运算符栈
- 栈模拟递归：前面树的部分已详细说明

### Breadth-First Search（BFS）
**必讲要点：**
- BFS 用队列，逐层扩展，天然适合"最短路径"/"最少步数"问题
- 模板：初始化队列 → while 队列非空 → 取出 → 处理 → 加入邻居
- 层序处理：用 size 变量记录当前层节点数
- 与 DFS 的选择：找最短路径用 BFS，遍历所有路径用 DFS

### Depth-First Search（DFS）
**必讲要点：**
- DFS 用栈或递归，适合"遍历所有可能"/"路径问题"
- 图上 DFS 要标记 visited，避免环
- 树上 DFS 不需要 visited（天然无环）
- 回溯是 DFS 的一种应用

### Sorting（排序）
**必讲要点：**
- 什么时候排序有帮助：消除无序性后可以用双指针/二分
- 排序的代价 O(n log n)：如果整体复杂度已经是 O(n²)，排序不增加开销
- 自定义排序：lambda 比较函数的写法

### Divide and Conquer（分治）
**必讲要点：**
- 分治三步：分解 → 递归解决子问题 → 合并
- 归并排序是分治的典型应用
- 与普通递归的区别：分治把问题分成独立的子问题，合并时做主要工作

### Bit Manipulation（位运算）
**必讲要点：**
- 常用操作：与(&)清零检测、或(|)置位、异或(^)翻转/找不同
- n & (n-1)：消除最低位的 1
- n & (-n)：提取最低位的 1
- 异或性质：a ^ a = 0, a ^ 0 = a

### Sliding Window（滑动窗口）
**必讲要点：**
- 适用条件：连续子数组/子串问题，且窗口满足单调性
- 模板：右指针扩展 → 不满足条件时左指针收缩
- 固定窗口 vs 可变窗口：固定直接滑动，可变需要判断收缩条件
- 窗口内常用辅助：哈希表计数、变量维护当前状态

### Heap / Priority Queue（堆）
**必讲要点：**
- 堆的本质：快速获取最大/最小值，O(log n) 插入和删除
- Top K 问题：小顶堆维护最大的 K 个，大顶堆维护最小的 K 个
- C++ 的 priority_queue：默认大顶堆，小顶堆要用 greater<>

### Trie（前缀树）
**必讲要点：**
- 结构：每个节点包含子节点数组和 isEnd 标志
- 适用场景：前缀匹配、自动补全、词频统计
- 与哈希表的区别：Trie 天然支持前缀查询

### Matrix（矩阵）
**必讲要点：**
- 方向数组：dx[] = {0,0,1,-1}, dy[] = {1,-1,0,0}
- 边界检查：0 <= x < m && 0 <= y < n
- BFS/DFS 在矩阵上的应用：岛屿问题、最短路径

### Design（设计题）
**必讲要点：**
- 数据结构选择的权衡：各操作的时间复杂度要求
- 多种数据结构组合：如 LRU = HashMap + 双向链表

## 三、hints.md 生成规范

### 结构
```
# {id}. {title}

## 核心思路
用 1-2 句话说清楚这道题本质上在解决什么问题。

## 解法概览
| 解法 | 思路 | 时间 | 空间 | 难度 |
|------|------|------|------|------|
| 暴力 | ... | ... | ... | 入门 |

## 关键提示
- 提示1：引导思考方向，不给出答案
- 提示2：点出容易忽略的边界条件
- 提示3：指出暴力解的瓶颈，暗示优化方向

## 相关题型

```

### 原则
- hints.md 是**提示**，帮人想到思路，但不剧透完整解法
- 每个提示是一个"推一下"的力度，不是直接告诉你怎么做

- 最后有对比总结和易错点

## 五、特殊题型教学要求

### 树的题：必须递归 + 迭代两种都给
- 递归版要说清楚三要素（返回值、终止条件、单层逻辑）
- 迭代版要解释栈/队列是怎么模拟递归过程的
- 如果是 BST，要额外讲怎么利用有序性
- **必须用 ASCII 注释画出树的示意图**：
  - 画出题目给定的示例树结构（用 `/` `\` 连线）
  - 用步骤标注展示算法是怎么遍历/操作这棵树的
  - 对于修改类操作（翻转、删除、插入），画出操作前后的对比图
  - 示例格式（在 reference.cpp 的注释中）：
    ```
    //       1          中序遍历过程:
    //      / \         Step1: 入栈1, 向左
    //     2   3        Step2: 入栈2, 向左
    //    / \           Step3: 入栈4, 无左 → 弹出4, 访问4
    //   4   5          Step4: 弹出2, 访问2, 转右
    //                  Step5: 入栈5, 无左 → 弹出5, 访问5
    //                  Step6: 弹出1, 访问1, 转右
    //                  Step7: 入栈3, 无左 → 弹出3, 访问3
    //                  结果: [4, 2, 5, 1, 3]
    ```
  - 对于操作类题目：
    ```
    //  翻转前:        翻转后:
    //       4              4
    //      / \            / \
    //     2   7          7   2
    //    / \ / \        / \ / \
    //   1  3 6  9      9  6 3  1
    ```

### 链表题：必须画指针变化图
- 用 ASCII 注释展示每一步指针的移动过程
- 示例格式：
  ```
  // 反转链表过程:
  // Step1: prev=NULL, curr=1→2→3→NULL
  // Step2: prev=1→NULL, curr=2→3→NULL
  // Step3: prev=2→1→NULL, curr=3→NULL
  // Step4: prev=3→2→1→NULL, curr=NULL → 返回 prev
  ```

### 图/矩阵题：必须画网格扩展过程
- BFS/DFS 在矩阵上的扩展用标记展示：
  ```
  // 岛屿计数 BFS 扩展过程:
  // 原始:    标记后:
  // 1 1 0    ✓ ✓ 0     ← 第1个岛
  // 1 1 0    ✓ ✓ 0
  // 0 0 1    0 0 ✓     ← 第2个岛
  ```

### DP 的题：必须从暴力递归开始
- 先写暴力递归，展示重叠子问题
- 加 memo 变成记忆化搜索
- 翻译成递推
- 如果能空间优化，额外给出优化版
- **必须用注释展示 DP 表的填充过程**：
  ```
  // dp 填表方向 (以 LCS 为例):
  //     "" a b c
  // ""  0  0 0 0
  //  a  0  1 1 1    ← dp[i][j] = dp[i-1][j-1]+1 (匹配)
  //  e  0  1 1 1              或 max(dp[i-1][j], dp[i][j-1]) (不匹配)
  //  c  0  1 1 2
  ```

### 回溯的题：必须画出决策树
- 用 ASCII 注释画出决策树的前 2-3 层
- 展示剪枝前后的区别
- 示例格式：
  ```
  // 组合 [1,2,3] 中选2个的决策树:
  //              []
  //         /    |    \
  //       [1]   [2]   [3]
  //      / \     |
  //   [1,2] [1,3] [2,3]   ← 叶子节点 = 结果
  ```
